# 1457. Теплотрасса

[Timus 1457](https://acm.timus.ru/problem.aspx?space=1&num=1457) · сложность 69 · math

Авторы оригинальной задачи — Никита Рыбак, Дмитрий Ковалёв и Илья Гребнов; Timus Top Coders: Second Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Прямая теплотрасса проходит под N пунктами (1 ≤ N ≤ 1000) в точках P[i]
(0 ≤ P[i] ≤ 10⁶). Усилия на преодоление расстояния пропорциональны его
квадрату. Нужно найти точку теплотрассы, для которой среднее усилие на
путь до пунктов наименьшее, с не менее чем шестью знаками после точки.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N положений.

## Выходные данные

Лучшая точка.

## Проверка

Тесты репозитория сравнивают числовые токены по условию |ответ-эталон| <= 0.0000011·max(1,|эталон|), отклоняют бесконечности и NaN, а нечисловые токены сравнивают точно.

## Примеры

### Пример 1

Ввод:

```
3
7 4 5
```

Вывод:

```
5.333333
```

## Решение

Среднее (x − P[i])² — парабола по x, производная которой 2 (x − среднее)
обращается в ноль в среднем арифметическом положений, так что ответ —
сумма, делённая на N. Сумма не превосходит 10⁹ и помещается в знаковый
32-битный целый тип. `O(N)`.

Подводные камни:

- округление до шести знаков может различаться в разных языках, когда
  среднее оканчивается ровно на пятёрку, как 1/128 (тест 05); принимается
  любой ответ с требуемой точностью.

## Оптимизированные решения

`1457_math_optimized.py`. Читаем байтовый поток и собираем целые числа в один список. Первый элемент — количество позиций N. Начинаем сумму с −N, чтобы учесть заголовок и получить точную сумму координат. Встроенная функция sum обходит список без создания среза. Делим сумму на N и выводим шесть знаков после запятой. Время и дополнительная память — O(N).

Простая версия на CPython в посылке №11286429 получила 0.078 с / 504 КБ. Прежняя реализация на PyPy в посылке №11324843 получила 0.156 с / 248 КБ. Новая версия на CPython в посылке №11328147 получила 0.062 с / 432 КБ.

`1457_math_optimized.rs`. Сохраняется среднее арифметическое, минимизирующее сумму квадратов расстояний. N целых позиций суммируются точно, вещественным остаётся только итоговое деление с шестью дробными знаками. При N<=1000 и позициях<=10^6 сумма не больше10^9 и точно представима в f64. Время O(N), смысл и точность вывода прежние. Позиции суммируются по мере чтения, входная String и вектор значений исключены. Дополнительное состояние O(1); printf выводит одно среднее f64. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1457_math.rs`: время 0.015 s → 0.031 s; память 252 KB → 88 KB.

Оптимизированное решение на Java разбирает числа вручную вместо
`Scanner` и печатает среднее без форматирования: точное значение
округляется в целых числах, `(sum · 10⁶ + N / 2) / N`, и выводятся
целая часть и шесть цифр дробной: 412 КБ вместо 2612 КБ при том же
времени.

## Особенности языков

Для Rust использована выборка от 18 ноября 2026 года. В обеих выборках учитываются посылки других авторов на актуальных компиляторах. Совпадающие результаты делят место.

`1457_math_optimized.py`. В выборке от 18 ноября 2026 года посылка на CPython занимает 3/71 по времени и 23/71 по памяти. При расходе 432 КБ для строгого допуска достаточно места по времени. Звёздочка обозначает отдельную цель — первое место по обеим метрикам.

`1457_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
