# 1493. В одном шаге от счастья

[Timus 1493](https://acm.timus.ru/problem.aspx?space=1&num=1493) · сложность 47 · implementation

Автор оригинальной задачи — Владимир Яковлев; XIII командный чемпионат школьников Свердловской области по программированию, 14 октября 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У билета шестизначный номер, ведущие нули тоже считаются; билет
счастливый, если суммы первых трёх и последних трёх цифр равны. У
данного билета эти суммы отличаются ровно на единицу. Нужно вывести
«Yes», если предыдущий или следующий билет счастливый, и «No» иначе.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Шесть цифр билета.

## Выходные данные

«Yes» или «No».

## Примеры

### Пример 1

Ввод:

```
715068
```

Вывод:

```
Yes
```

### Пример 2

Ввод:

```
445219
```

Вывод:

```
No
```

### Пример 3

Ввод:

```
012200
```

Вывод:

```
Yes
```

## Решение

Проверяем обоих соседей напрямую: берём номер минус один и плюс один,
записываем шестью цифрами и сравниваем суммы половин. Суммы данного
билета различны, так что это не 000000 и не 999999, и оба соседа —
настоящие билеты. Переносы могут менять сразу несколько цифр, поэтому
соседей пересчитываем целиком, а не правим одну цифру. `O(1)`.

Подводные камни:

- номер может начинаться с нулей, и они тоже цифры (тест 03); чтение,
  принимающее ведущий 0 за признак восьмеричной записи, тут ломается;
- перенос или заём через середину меняет обе половины, как при
  переходе от 100000 к 099999 (тесты 06, 08, 09);
- соседи 000000 и 999999 тоже счастливые билеты (тесты 04, 05).

## Оптимизированные решения

Оптимизированные решения (Java, Rust) проверяют тех же двух соседей без
проверки диапазона: билет не 000000 и не 999999, поэтому оба соседа —
билеты. Rust выводит ответ байтовой строкой через `write_all`: 0.031 с
вместо 0.062 с при той же памяти.

Оптимизированное решение на Java разбирает шесть цифр побайтно из
`System.in` вместо `Scanner`: 0.078 с вместо 0.140 с и 308 КБ вместо
1596 КБ.
