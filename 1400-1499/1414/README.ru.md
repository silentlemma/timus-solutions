# 1414. Астрономическая база данных

[Timus 1414](https://acm.timus.ru/problem.aspx?space=1&num=1414) · сложность 430 · sorting, binary_search

## Задача

База названий звёзд вначале содержит одно название «sun». Далее идут
до 10 000 операций, по одной в строке: «+name» добавляет название (его
могут добавить и повторно), «?prefix» запрашивает названия,
начинающиеся с префикса. Аргументы — от 1 до 20 строчных латинских
букв или цифр. На каждый запрос нужно вывести префикс, а затем
подходящие названия в лексикографическом порядке без повторов, каждое
с отступом в два пробела, не больше первых 20.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Операции.

## Выходные данные

Ответы на запросы.

## Примеры

### Пример 1

Ввод:

```
?e
+earth
+egg
?e
+eagle
+earth
?ea
```

Вывод:

```
e
e
  earth
  egg
ea
  eagle
  earth
```

## Решение

Храним названия в упорядоченном множестве. Названия с данным префиксом
образуют непрерывный отрезок в лексикографическом порядке, который
начинается там, куда встал бы сам префикс, поэтому каждый запрос
находит это место двоичным поиском и идёт вперёд, пока название
начинается с префикса и выведено меньше 20 названий. C++, Java и Rust
используют древовидные множества; Go и Python хранят отсортированный
массив и вставляют в него, сдвигая не больше 10 000 ссылок за
добавление. `O(Q log Q)` для древовидных множеств.

Подводные камни:

- «sun» есть в базе с самого начала (тест 02);
- повторные добавления не должны повторяться в ответе (тест 03);
- выводятся только первые 20 названий (тест 04);
- в названиях бывают цифры, они идут раньше букв (тест 12);
- в примере два пробела отступа показаны точками.

## Оптимизированные решения

Новые C++ и Rust сохраняют упорядоченное множество и поиск начала префикса; выводятся первые двадцать различных имён в словарном порядке. Вывод ограничен буфером, все ответы не накапливаются. C++ печатает строки через C stdio. Rust дополняет имена нулями до двадцати байтов и хранит массивы прямо в BTreeSet: ноль меньше любой допустимой цифры или буквы, поэтому обычный словарный порядок, включая собственный префикс, сохраняется. Сравнивается только заданная длина префикса. Полный ответ занимает не больше 21+20·23=481 байта при буфере 512. Память зависит от имён, а не суммарного вывода. Исходные версии сохранены; Go, Java и Python используют подходящие базы и в быстром наборе.

Принятая версия G++ 13.2 x64 заняла 0.125 с при 0.031 с у базовой и использовала 924 KB при 5748 KB у базовой.

Принятая версия Rust 1.75 x64 заняла 0.062 с при 0.031 с у базовой и использовала 292 KB при 6144 KB у базовой.

В прежнем срезе сравнения базовые реализации [1414_sorting.go](1414_sorting.go), [1414_sorting.java](1414_sorting.java), [1414_sorting.py](1414_sorting.py) удовлетворяли критерию включения по топ 15% или первым десяти местам по обеим метрикам. Их измерения сохранены в таблице простых решений.

Сразу записываем каждый запрос по префиксу и его результаты в буфер вывода, не накапливая весь ответ в памяти. Принятая посылка 11324233 заняла 0,125 с и использовала 2 896 КБ. Простая версия заняла 0,156 с и использовала 24264 КБ.
