# 1437. ACM для ГСМ

[Timus 1437](https://acm.timus.ru/problem.aspx?space=1&num=1437) · сложность 493 · bfs

Автор оригинальной задачи — Алексей Лахтин; Седьмое открытое личное первенство УрГУ по спортивному программированию, 25 февраля 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Три канистры вмещают от 0 до 255 литров каждая. Колонка может только
наполнить канистру доверху, бензин можно переливать из одной канистры в
другую, пока первая не опустеет или вторая не наполнится, а проливать
нельзя. Только после всех переливаний некоторые канистры выливаются в
бак. Сколько различных положительных объёмов можно получить в баке?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Три ёмкости, по одной в строке.

## Выходные данные

Количество объёмов.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
0
3
4
```

Вывод:

```
6
```

## Решение

Перебираем все состояния (x, y, z) канистр начиная с пустых: три хода
наполнить канистру и шесть ходов перелить одну канистру в другую. После
любого хода какая-то канистра пуста или полна, поэтому достижимы
не более примерно 3·2·256² из 256³ состояний. Каждое достигнутое
состояние даёт суммы своих непустых подмножеств канистр как объёмы для
бака; считаем различные положительные. Для ёмкостей a, b, c обозначим
P=(a+1)(b+1)(c+1), V=a+b+c+1, S — число достигнутых состояний. С учётом
инициализации флагов время в среднем `O(P)`, а в C++ с упорядоченным
множеством — `O(P + S log V)`.

Подводные камни:

- ноль литров не считается (тесты 01, 03);
- уже полная канистра больше не принимает, поэтому в примере 5 литров
  не получить (тест 01);
- три равные канистры всегда пусты или полны (тест 05).

## Оптимизированные решения

`1437_bfs_optimized.java`. Сохраняется BFS заполнений и переливаний, но тройка кодируется одним int, посещения хранятся битами long, очередь — массивом int. Пусть S=(a+1)(b+1)(c+1), B=S-product(max(0,capacity-1)). После каждого хода канистра пуста или полна, поэтому в очередь попадёт не больше B граничных состояний; нулевое состояние учтено и при нулевых объёмах. Достижимые суммы подмножеств до C=a+b+c отмечаются boolean-массивом вместо HashSet. Исключены копии троек, объектные объёмы и очередь объектов. С инициализацией время O(S), память O(S/64+B+C) ячеек с явной битовой упаковкой; при ёмкостях<=255 индексы помещаются в int. Нулевая сумма в ответ не входит. Буфер ввода256байт.

По сравнению с `1437_bfs.java`: время 0.156 s → 0.109 s; память 20420 KB → 4 004 KB.

C++ и Go сохраняют все исходные переходы наполнения и переливания, но хранят посещённость только на границе параллелепипеда ёмкостей. После хода канистра полна, донор пуст или приёмник полон. Первая пустая/полная канистра задаёт каноническую грань, две остальные координаты — индекс; рёбра и углы получают один бит. При U=256 шесть граней U² требуют 49152 байта битовой карты. Тройка объёмов занимает 24 бита и хранится в uint32; очередь ограничена шестью U² записями (1572864 байта). Множество ответов заменено массивом из 766 флагов. Проверяются все семь сумм подмножеств, ноль исключён; бензин при поиске не сливается. При S посещённых состояниях время O(U²+S), память O(U²), включая инициализацию массивов. Простые версии сохранены; Java, Python и Rust используют подходящие базы.

Принятые базовые реализации [1437_bfs.java](1437_bfs.java), [1437_bfs.py](1437_bfs.py), [1437_bfs.rs](1437_bfs.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1437_bfs_optimized.py`. После наполнения или переливания в каждом не начальном состоянии есть пустой или полный сосуд. В байтовом массиве посещений кодируются только шесть граничных плоскостей вместо всего куба объёмов; переходы BFS прежние. Граница числа состояний O(ab + ac + bc). Самостоятельная программа сбрасывает оба выходных потока перед os._exit(0), чтобы после записи полного ответа не выполнять завершение интерпретатора. Это изменение завершения процесса, а не математического алгоритма; простая версия сохранена.

Accepted #11328684 (Python 3.12 x64): **0.281 s / 2860 KB**. Архивное сравнение: `1437_bfs.py` (Python 3.12 x64) — 0.406 s / 17212 KB (#11286238).

`1437_bfs_optimized.rs`. Алгоритм и типы целых чисел сохранены. Десятичные токены разбираются напрямую вместо универсального строкового парсера; отрицательное значение накапливается со знаком, поэтому минимальное знаковое число остаётся представимым. Хранение ввода и асимптотика алгоритма прежние.

Accepted #11328552 (Rust 1.75 x64): **0.015 s / 3092 KB**. Архивное сравнение: `1437_bfs.rs` (Rust 1.75 x64) — 0.062 s / 3104 KB (#11286240).

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1437_bfs_optimized.java`: место по времени 2/17, по памяти 2/17 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
