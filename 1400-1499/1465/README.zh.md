# 1465. 兵的游戏

[Timus 1465](https://acm.timus.ru/problem.aspx?space=1&num=1465) · 难度 489 · games

原题作者 Alexander Toropov，出自 2006 年 1 月彼得罗扎沃茨克冬季集训的乌拉尔国立大学比赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

在 3 × N（1 ≤ N ≤ 10⁹）的棋盘上，第一横排摆满白兵，第三横排摆满黑兵，中间一排为
空。兵按国际象棋规则走子和吃子，必须吃子，无法走子的一方输。白方先走。双方都采取
最优策略：若白方获胜输出 "White"，否则输出 "Black"。

时间限制：1 秒。内存限制：64 MB。

## 输入

N。

## 输出

"White" 或 "Black"。

## 评测方式

仓库测试比较完整输出文本，仅忽略末尾空白。应保留有意义的空格、换行、大小写及标点。

## 解法

这就是 Dawson 象棋。推到中间一排的兵会受到对方相邻直线上兵的攻击，随后必须进行
的吃子结束时，被推进的那一列及其相邻列都“死”了：那里再也没有兵能走。因此在 n 条
活列组成的一行中，在第 i 列走一步，会留下 i − 2 列和 n − i − 1 列两行独立的部
分；在边上走会使两列死掉，单独的一列自己死掉。这正是八进制游戏 0.137：只有整行
时才能取走一列，取走两列并至多留下一行，或取走三列并留下至多两行。

先手获胜当且仅当 n 的 Grundy 值不为零；一行的值是不在其各步走法值中的最小数，两
行的值用异或合并。用 O(200²) 求出不超过 200 的值。从 n = 52 起它们以 34 为周期重
复，而按八进制游戏的周期性定理，只需验证到 2 · 52 + 34 + 3 即可；因此更大的 N 被
折到 200 以下的最后一个周期中。每个答案 `O(1)`。

注意事项：

- N = 10⁹ 的棋盘无法模拟，只能折叠（测试 12 到 15）；
- 值从 n = 52 起才稳定：14 列与 48 列、34 列与 68 列的胜者不同（测试 07、08、17、18）；
- 在类 C 语言中负数取余为负，所以折叠时减法的顺序必须正确。

## 优化解法

Go 运行时计算与 Accepted 基础版相同的前200个 Grundy 值，沿用相同周期折叠。256项布尔数组替代每次 mex 新建 map。大小≤200 时至多200个动作，mex≤200；字节值 XOR≤255，数组安全。没有存储胜负表，也未引入新周期假设。标准句柄有界 I/O 代替 fmt。固定预处理不依赖 N，查询时间和空间 O(1)。

已通过评测的基础实现 [1465_games.cpp](1465_games.cpp), [1465_games.py](1465_games.py), [1465_games.rs](1465_games.rs) 也满足快速版本的要求：在保存的比较快照中，时间和内存均符合前 15% 或前十名的排名收录规则。直接复用这些源文件，不创建相同副本。星号标记尚未达到该语言目标排名的版本。

`1465_games_optimized.java`. Java 保留简单版本所述的算法和数据结构。固定字节缓冲区与 FastInput 替代 Scanner 及其正则表达式、区域设置处理。整数记号直接解析；需要字符串时仍进行 UTF-8 解码，十进制记号仍显式转换为数值。仅在需要前瞻时保存一个记号，输出算法不变。这样减少通用解析开销；表中列出算法工作量，输入扫描与字节数成正比，并使用有界输入缓冲区。

与 `1465_games.java` 相比：时间 0.140 s → 0.14 s；内存 1720 KB → 668 KB。

`1465_games_bitmask.java`. 生成器枚举每种长度的所有合法走法，将两段剩余棋盘的 Grundy 值异或，再取所有可达值的 mex。它从长度 52 开始验证周期 34，直至满足归纳条件。对于更长的棋盘，给足够长的一段增加或减少 34 列会保留该段的 Grundy 值，因此两个方向上的可达值均相同。长度除以 34 的余数为 4、8、20、24 或 28 时黑方获胜，另外两个黑方获胜的长度是 14 和 34。Java 读取宽度后仅检查掩码中的一位，时间和空间均为 O(1)。 [生成掩码和两个例外长度](1465_games_bitmask_table.py).

在 Java 1.8 上，基础版用时 0.140 s、占用 1720 KB，缓冲输入版用时 0.14 s、占用 668 KB。提交 #11328151 用时 0.093 s、占用 340 KB。与样本中另外 24 位 Java 1.8 作者相比，时间排名为 1/25，内存排名为 1/25，相同成绩并列。
