# 1465. Игра в пешки

[Timus 1465](https://acm.timus.ru/problem.aspx?space=1&num=1465) · сложность 489 · games

Автор оригинальной задачи — Александр Торопов; контест УрГУ на Петрозаводских зимних сборах, январь 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На доске 3 × N (1 ≤ N ≤ 10⁹) первая горизонталь заполнена белыми
пешками, третья — чёрными, средняя пуста. Пешки ходят и бьют по
шахматным правилам, бить обязательно, и проигрывает тот, кто не может
сделать ход. Первыми ходят белые. Оба играют наилучшим образом: нужно
вывести «White», если выигрывают белые, и «Black» иначе.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N.

## Выходные данные

«White» или «Black».

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

Ввод:

```
3
```

Вывод:

```

```

### Пример 2

Ввод:

```

```

Вывод:


### Пример 3

Ввод:

```
5
```

Вывод:

```
White
```

## Решение

Это шахматы Доусона. Пешка, выдвинутая на среднюю горизонталь,
оказывается под ударом пешек противника с соседних вертикалей, и
последующие обязательные взятия кончаются тем, что выдвинутая вертикаль
и её соседи мертвы: ни одна пешка там больше не сможет ходить. Поэтому
ход на вертикали i в ряду из n живых вертикалей оставляет два
независимых ряда из i − 2 и n − i − 1 вертикалей; ход у края убивает две
вертикали, а одиночная вертикаль умирает сама. Это октальная игра
0.137: взять одну вертикаль, только если это весь ряд, взять две,
оставив не больше одного ряда, или взять три, оставив до двух рядов.

Первый игрок выигрывает ровно тогда, когда значение Гранди для n не
ноль; значение ряда — наименьшее число, которого нет среди значений его
ходов, а два ряда объединяются через xor. Значения считаются до 200 за
O(200²). Начиная с n = 52 они повторяются с периодом 34, и по теореме о
периодичности октальных игр это достаточно проверить до
2 · 52 + 34 + 3; поэтому большее N сворачивается в последний период
ниже 200. `O(1)` на ответ.

Подводные камни:

- доску с N = 10⁹ не смоделировать, её можно только свернуть (тесты
  12–15);
- значения устанавливаются только с n = 52: у 14 и 48 вертикалей, как и
  у 34 и 68, победители разные (тесты 07, 08, 17, 18);
- в C-подобных языках остаток от отрицательного числа отрицателен,
  поэтому при сворачивании вычитать нужно в правильном порядке.

## Оптимизированные решения

Go вычисляет те же первые200 значений Гранди и использует тот же периодический переход, что принятая база. Массив 256 логических значений заменяет новый словарь для каждого mex. При размере до200 ходов не более200, поэтому mex≤200; xor байтовых значений не выше255, границы безопасны. Значения вычисляются при запуске, без списка победителей и новой гипотезы периодичности. Ограниченный ввод-вывод дескрипторов заменяет fmt. Предвычисление фиксировано независимо от N: O(1) на запрос и памяти.

Принятые базовые реализации [1465_games.cpp](1465_games.cpp), [1465_games.py](1465_games.py), [1465_games.rs](1465_games.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

`1465_games_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1465_games.java`: время 0.140 s → 0.14 s; память 1720 KB → 668 KB.

`1465_games_bitmask.java`. Генератор вычисляет числа Гранди для каждого размера ряда. Он перебирает допустимые ходы, объединяет значения двух оставшихся частей операцией XOR и находит mex. Генератор проверяет период 34 от длины 52 до начала шага индукции. Для больших рядов можно добавить или убрать 34 клетки в достаточно длинной части с сохранением её числа Гранди. Так значения ходов совпадают в обоих направлениях. Чёрные выигрывают при остатках 4, 8, 20, 24 и 28 по модулю 34 и при двух дополнительных длинах 14 и 34. Java читает ширину и проверяет один бит маски за O(1) времени и памяти. [Генератор маски и двух исключений](1465_games_bitmask_table.py).

На Java 1.8 простая версия получила 0.140 с и 1720 КБ, версия с буфером — 0.14 с и 668 КБ. У посылки №11328151 результат 0.093 с и 340 КБ. В выборке с 24 другими авторами на Java 1.8 это 1/25 по времени и 1/25 по памяти. При равных значениях место общее.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1465_games_optimized.py`. Сохранены 201 бит выигрыша/проигрыша проверенной рекуррентности Гранди, затем применяется прежний период. Соседний 1465_games_table.py заново строит маску по простой рекуррентности; ответы судьи не используются. Самостоятельная программа сбрасывает оба выходных потока перед os._exit(0), чтобы после записи полного ответа не выполнять завершение интерпретатора. Это изменение завершения процесса, а не математического алгоритма; простая версия сохранена.

Accepted #11328554 (Python 3.12 x64): **0.093 s / 672 KB**. Архивное сравнение: `1465_games.py` (Python 3.12 x64) — 0.109 s / 444 KB (#11286512).


`1465_implementation_parsing_optimized.rs`. Размер позиции читается напрямую. Точная рекуррентность Гранди с отметками эпох и установленный период сохранены; готовая таблица ответов не добавляется. Прямой вывод специализирован по реальным типам ответа без универсального выбора формата и временных строк. Фиксированный текст записывается нативно; числовой вывод точно обрабатывает нужные знаковые или беззнаковые значения. Математические решения и архивные простые версии сохранены.

Для этого точного исходника получен собственный Accepted и выполнены единые [рейтинговые критерии](../../RATING_CRITERIA.md). Время и память ниже взяты из одной посылки; повторные измерения судьи могут различаться. Существующие простые и отличающиеся оптимизированные версии сохранены.

Accepted #11329333 (Rust 1.75 x64): **0.031 s / 72 KB**.
