# 1463. Радость населению!

[Timus 1463](https://acm.timus.ru/problem.aspx?space=1&num=1463) · сложность 598 · dp

Автор оригинальной задачи — Александр Торопов, особая благодарность Александру Ипатову; контест УрГУ на Петрозаводских зимних сборах, январь 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть N городов (1 ≤ N ≤ 50000) с радостью A[i] за посещение и K
связей между парами городов с радостью c за перелёт по ним; все значения
— неотрицательные целые до 10000. Между любыми двумя городами не больше
одного маршрута, поэтому связи образуют лес. Нужно найти маршрут по
различным городам, начинающийся где угодно, с наибольшей суммарной
радостью городов и перелётов.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и K, затем радости A[i], затем K строк a, b, c.

## Выходные данные

Наибольшая радость, число городов маршрута и сам маршрут. Принимается
любой лучший маршрут.

## Примеры

### Пример 1

Ввод:

```
2 1
1 1
1 2 1
```

Вывод:

```
3
2
1 2
```

### Пример 2

Ввод:

```
8 7
1 5 4 6 10 1 2 2
1 2 1
2 3 10
2 4 1
4 5 1
4 6 2
6 7 2
6 8 3
```

Вывод:

```
37
4
5 4 2 3
```

## Решение

Маршрут в лесу — это путь в одном дереве, и у каждого пути есть самый
верхний город, если подвесить дерево за корень. Подвесим каждое дерево
за любой город и пройдём города от листьев вверх. Для каждого города v
храним лучший маршрут, начинающийся в v и идущий вниз:
down[v] = A[v] плюс лучшее значение c + down[w] по детям w, вместе с
ребёнком, который его даёт. Лучший маршрут с верхним городом v
соединяет с A[v] два лучших таких значения детей; все значения
неотрицательны, поэтому взять двух детей (или одного, или ни одного)
никогда не вредно. Маршрут восстанавливается спуском по сохранённым
детям вдоль двух выбранных ветвей.

Деревья бывают глубиной в 50000 городов, поэтому обход использует явный
стек вместо рекурсии. `O(N + K)`.

Подводные камни:

- связей может не быть вовсе, а лучший маршрут — один город (тесты 03,
  04, 07, gen5);
- длинная цепь переполняет рекурсию (gen2);
- при нулевых радостях лучший любой маршрут (тест 05).

## Оптимизированные решения

`1463_trees_optimized.cpp`. Сохраняется линейное удаление листьев со степенями, XOR оставшихся соседей и весов и двумя лучшими удалёнными ветвями. Прежние ссылки на детей восстанавливают оптимальный маршрут. Блочные ввод и вывод по 16 КБ заменяют форматированные числовые операции; состояние графа и правила выбора при равенстве не меняются. Читаемая версия со стандартным вводом-выводом 1463_trees.cpp и исходные учебные DFS-версии сохранены со своими метриками. Обе версии удаления листьев требуют O(N+K) времени и O(N) памяти графа плюс фиксированные буферы.

Accepted точного исходника №11326974: 0.015 s / 1448 KB. Сохранённая выборка G++ 13.2 от 2026-11-20: место по времени 1/42, по памяти 1/42.

Читаемая версия со стандартным вводом-выводом `1463_trees.cpp`. Версия C++ последовательно удаляет листья. Для каждого города хранит текущую степень и XOR номеров оставшихся соседей и радостей на оставшихся рейсах. Для листа эти значения определяют единственный оставшийся рейс. Две лучшие уже удалённые ветви позволяют оценить и восстановить маршрут через город. Время O(N + K), дополнительная память O(N). Метрики взяты из посылки 11317012.

В версии Python листья удаляются так же. Каждая удалённая ветвь объединяется с лучшей из уже найденных ветвей у родителя, после чего лучшая ветвь обновляется. Для восстановления маршрута достаточно сохранить начала двух выбранных ветвей. Время O(N + K), дополнительная память O(N). Метрики взяты из посылки 11317010.

Версия Go удаляет листья, храня данные городов в компактном массиве. XOR позволяет получить оставшегося соседа и вес ребра без списков смежности. Посылка 11317154 заняла 0,078 с и 1976 КБ против 0,125 с и 11580 КБ у базы.

Версия Rust удаляет листья, храня данные городов в компактных записях. Оставшегося соседа и вес ребра восстанавливает XOR. Посылка 11317155 заняла 0,015 с и 980 КБ против 0,031 с и 10112 КБ у базы.

Java удаляет листья и восстанавливает оставшегося соседа и вес ребра с помощью XOR. Посылка 11317156 заняла 0,140 с и 1276 КБ против 0,156 с и 3896 КБ у базы.
