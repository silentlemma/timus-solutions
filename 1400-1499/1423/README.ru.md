# 1423. Басня о строке

[Timus 1423](https://acm.timus.ru/problem.aspx?space=1&num=1423) · сложность 170 · strings

Авторы оригинальной задачи — Никита Рыбак, Илья Гребнов и Дмитрий Ковалёв; Timus Top Coders: First Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Строки S и T одной длины N (1 ≤ N ≤ 250 000) состоят из символов с
кодами от 33 до 255. Один циклический сдвиг переносит последний символ
строки в начало. Нужно вывести число X (0 ≤ X < N), такое что X сдвигов
превращают S в T, или −1, если его нет; подходит любое X.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем S, затем T.

## Выходные данные

X или −1.

## Примеры

### Пример 1

Ввод:

```
11
abracadabra
racadabraab
```

Вывод:

```
9
```

В примере 9 сдвигов превращают «abracadabra» в «racadabraab».

## Решение

X сдвигов вправо — это N − X сдвигов влево, а сдвиги S влево на k — это
ровно подстроки длины N строки S + S, начинающиеся в k < N. Поэтому
ищем T в S + S: если вхождение начинается в позиции k, ответ
(N − k) mod N, а если вхождения нет, −1. Поиск — алгоритм
Кнута–Морриса–Пратта с префикс-функцией T по строке S + S без
последнего символа; встроенный поиск по байтам в Python здесь тоже
линейный. `O(N)`.

Подводные камни:

- у периодической S несколько ответов, поэтому тесты проверяет чекер
  (тест 04);
- символы выше 127 нужно читать как байты; некоторые способы чтения их
  декодируют или даже считают код 160 пробелом (тест 05, gen3);
- наивный поиск подстроки может работать квадратично на строках из
  одной повторяющейся буквы (gen2).

## Оптимизированные решения

Оптимизированное решение на C++ хранит префикс-функцию в 18-битных
полях, упакованных в массив 32-битных слов, ведь каждое значение меньше
N ≤ 250 000 < 2^18, и читает поле из двух соседних слов сразу; это стоит
нескольких сдвигов на обращение, зато занимает около 0.56 МБ вместо 1 МБ
для значений `int`. Кроме того, оно проходит S дважды вместо построения
S + S и читает S и T через `scanf` в два статических буфера по
250 001 байту вместо `std::string` с `cin`:
{1423_strings_optimized.cpp}.

Оптимизированное решение на Go хранит префикс-функцию в значениях
`int32` вместо 8-байтовых `int`, ведь каждое значение меньше
N ≤ 250 000, и читает S и T прямо в массивы ровно из N байт через
`io.ReadFull`, полагаясь на то, что обе строки длины N, вместо чтения
всего ввода и разбиения его на поля: {1423_strings_optimized.go}.

Оптимизированное решение на Java читает сырой ввод блоками по 64 КБ и
вырезает из него S и T вручную как массивы `byte`, сравнивая байты,
вместо декодирования строк через `BufferedReader` в массивы `char`,
которые занимают по два байта на символ: {1423_strings_optimized.java}.
