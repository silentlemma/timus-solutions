# 1423. Басня о строке

[Timus 1423](https://acm.timus.ru/problem.aspx?space=1&num=1423) · сложность 170 · strings

Авторы оригинальной задачи — Никита Рыбак, Илья Гребнов и Дмитрий Ковалёв; Timus Top Coders: First Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Строки S и T одной длины N (1 ≤ N ≤ 250 000) состоят из символов с
кодами от 33 до 255. Один циклический сдвиг переносит последний символ
строки в начало. Нужно вывести число X (0 ≤ X < N), такое что X сдвигов
превращают S в T, или −1, если его нет; подходит любое X.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем S, затем T.

## Выходные данные

X или −1.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверка репозитория требует ровно одно целое. Значение-1 принимается ровно когда эталон сообщает об отсутствии сдвига. Иначе подходит любой X из [0,N), если перенос последних X байтов S в начало даёт T; минимальный сдвиг не требуется.

## Примеры

### Пример 1

Ввод:

```
11
abracadabra
racadabraab
```

Вывод:

```
9
```

В примере 9 сдвигов превращают «abracadabra» в «racadabraab».

## Решение

X сдвигов вправо — это N − X сдвигов влево, а сдвиги S влево на k — это
ровно подстроки длины N строки S + S, начинающиеся в k < N. Поэтому
ищем T в S + S: если вхождение начинается в позиции k, ответ
(N − k) mod N, а если вхождения нет, −1. Поиск — алгоритм
Кнута–Морриса–Пратта с префикс-функцией T по строке S + S без
последнего символа; встроенный поиск по байтам в Python здесь тоже
линейный. `O(N)`.

Подводные камни:

- у периодической S несколько ответов, поэтому тесты проверяет чекер
  (тест 04);
- символы выше 127 нужно читать как байты; некоторые способы чтения их
  декодируют или даже считают код 160 пробелом (тест 05, gen3);
- наивный поиск подстроки может работать квадратично на строках из
  одной повторяющейся буквы (gen2).

## Оптимизированные решения

`1423_strings_optimized.py`. Сохраняется точный поиск байтовой подстроки в S+S. Вхождение T со смещением влево p даёт сдвиг вправо (N−p) mod N, отсутствие — −1. Допустим любой правильный сдвиг, включая периодические строки. Бинарный ввод читается и разбивается целиком, поиск выполняется bytes.find, короткий ответ выводится до os._exit(0). Хранятся O(N) байт. Время — линейный ввод/вывод и поиск подстроки рантаймом, без посимвольного цикла Python. Эта CPython-посылка первая по обеим метрикам; её 1592 КБ всё ещё больше 1372 КБ учебной базы.

Точный исходник: Python 3.12 x64 Accepted #11327848: 0.062 s / 1592 KB. Сохранённые места в группе компилятора от 2026-11-20, время затем память: 1/55; 1/55. Строгий допуск учитывает и время, и память при памяти от 1024 КБ: первые десять или топ 15%, равенства делят место, процентный порог округляется вверх. Обе метрики первые, звёздочка не нужна. Сохранённый прежний вариант имеет собственную парную посылку #11325463 (Python 3.12 x64): 0.093 s / 1592 KB; замеры и рантаймы не смешиваются. Все учебные исходники сохранены без изменений.

- `1423_strings_optimized.py`: 0.062 s / 1592 KB; сохранённая учебная база `1423_strings.py`: 0.109 s / 1372 KB.

`1423_strings_optimized.java`. Сохраняются KMP по байтам и ответ в виде правого сдвига. Два слова длины N сразу читаются в конечные байтовые массивы через буфер 4096 байт; полного ввода и декодированных char-массивов нет. Префикс-функция хранится в int, циклический курсор заменяет остаток от деления при просмотре виртуально удвоенного первого слова. Сравнение байтов сохраняет значения 33…255. Время и память O(N); читаемая строковая версия сохранена.

Accepted точного исходника Java 1.8 №11326951: 0.109 с / 1920 КБ. Сохранённое сравнение актуального Java от 2026-11-20: место по времени 2/99, по памяти 1/99. Память не меньше 1024 КБ, поэтому нужны оба строгих рейтинга; оба пройдены.

- `1423_strings_optimized.java`: 0.109 s / 1920 KB; сохранённая учебная база `1423_strings.java`: 0.156 s / 5744 KB; изменение времени -30.1%; изменение памяти -66.6%.

`1423_strings_optimized.rs`. Сохраняются побайтовый КМП и прежний индекс правого сдвига. Длины префиксов хранятся в u32; цепочка s и s без последнего байта заменяет остаток от деления на каждой позиции без выделения удвоенной строки. Байтовые токены сохраняют символы 33…255. Время и память O(N), вывод прямой вместо форматирования Rust.

По сравнению с `1423_strings.rs`: время 0.031 s → 0.031 s; память 3052 KB → 1 804 KB.

Оптимизированное решение на C++ хранит префикс-функцию в 18-битных
полях, упакованных в массив 32-битных слов, ведь каждое значение меньше
N ≤ 250 000 < 2^18, и читает поле из двух соседних слов сразу; это стоит
нескольких сдвигов на обращение, зато занимает около 0.56 МБ вместо 1 МБ
для значений `int`. Кроме того, оно проходит S дважды вместо построения
S + S и читает S и T через `scanf` в два статических буфера по
250 001 байту вместо `std::string` с `cin`:
{1423_strings_optimized.cpp}.

Оптимизированное решение на Go хранит префикс-функцию в значениях
`int32` вместо 8-байтовых `int`, ведь каждое значение меньше
N ≤ 250 000, и читает S и T прямо в массивы ровно из N байт через
`io.ReadFull`, полагаясь на то, что обе строки длины N, вместо чтения
всего ввода и разбиения его на поля: {1423_strings_optimized.go}.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
