# 1450. Российские газопроводы

[Timus 1450](https://acm.timus.ru/problem.aspx?space=1&num=1450) · сложность 149 · dp

Авторы оригинальной задачи — Дмитрий Ковалёв, Илья Гребнов и Никита Рыбак; Timus Top Coders: Second Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Газовая сеть состоит из N станций (2 ≤ N ≤ 500) и M однонаправленных
газопроводов (0 ≤ M ≤ 124750), каждый из A в B с прибыльностью C
(1 ≤ C ≤ 10000); пару станций соединяет не больше одного газопровода, и
в сети нет циклов: если газ может пройти из X в Y, обратно он пройти не
может. Нужно найти самый прибыльный маршрут из станции S в станцию F,
где прибыльность маршрута — сумма по его газопроводам, или вывести
«No solution», если F недостижима.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N и M в первой строке, затем M строк A, B, C, где 1 ≤ A, B ≤ N, затем
S и F в последней строке, где 1 ≤ S, F ≤ N и S ≠ F.

## Выходные данные

Наибольшая прибыльность или «No solution».

## Примеры

### Пример 1

Ввод:

```
6 7
6 5 10
1 4 11
1 2 4
3 1 5
2 4 5
6 3 1
6 1 3
6 4
```

Вывод:

```
17
```

Лучший маршрут в примере — 6, 3, 1, 4.

## Решение

Без циклов самый длинный путь находится простой динамикой. Упорядочим
станции топологически методом Кана: начинаем со станций без входящих
газопроводов и выпускаем станцию, когда все газопроводы в неё уже
рассмотрены. В этом порядке каждая станция окончательно посчитана до
того, как используются её газопроводы, так что best[w] = max(best[v] + C)
по газопроводам v → w, при best[S] = 0, а недостижимые из S станции
остаются пустыми. Ответ — best[F]. `O(N + M)`.

Подводные камни:

- недостижимая F, в том числе когда газопроводы ведут из F в S (тесты
  02, 03, 06);
- самый прибыльный маршрут может содержать больше газопроводов, чем
  прямой (тест 07);
- недостижимые из S станции не должны передавать прибыль дальше, хотя
  упорядочить их всё равно нужно.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает числа вручную из буфера на
4 КБ вместо `scanf` и хранит сеть матрицей 16-битных значений
прибыльности `uint16_t`, около 490 КБ при `N = 500`, вместо `vector` из
`vector` пар. Прибыльность не меньше 1, а пару станций соединяет не
больше одного газопровода, так что нулевая клетка означает отсутствие
газопровода; станция, взятая из очереди, просматривает всю свою строку,
всего `O(N²)`. Лучшая прибыльность маршрута до каждой станции хранится
в `int` вместо `long long`: в маршруте не больше 499 газопроводов, так
что его прибыльность не больше 4 990 000: {1450_dp_optimized.cpp}.

Оптимизированное решение на Go разбирает числа побайтно из
`bufio.Reader` вместо `fmt.Fscan` и хранит сеть матрицей значений
прибыльности `uint16`, около 490 КБ при `N = 500`, вместо срезов
структур с двумя полями `int`. Прибыльность не меньше 1, а пару станций
соединяет не больше одного газопровода, так что нулевая клетка означает
отсутствие газопровода; станция, взятая из очереди, просматривает всю
свою строку, всего `O(N²)`: {1450_dp_optimized.go}.

Оптимизированное решение на Java разбирает числа вручную из буфера на
4 КБ вместо `StreamTokenizer` и хранит сеть матрицей значений
прибыльности `short`, куда помещаются значения до 10 000, вместо трёх
массивов `int` с газопроводами и массивов, группирующих их по станциям.
Прибыльность не меньше 1, а пару станций соединяет не больше одного
газопровода, так что нулевая клетка означает отсутствие газопровода;
станция, взятая из очереди, просматривает всю свою строку, всего
`O(N²)`. Лучшая прибыльность маршрута до каждой станции хранится в `int`
вместо `long`: в маршруте не больше 499 газопроводов, так что его
прибыльность не больше 4 990 000: {1450_dp_optimized.java}.

Оптимизированное решение на Python полагается на построчную раскладку
ввода и читает его по строкам, а не разбивает весь ввод в список. Сеть
хранится по одной строке `array("H")` из беззнаковых 16-битных значений
прибыльности на станцию вместо списков кортежей; прибыльность не меньше
1, а пару станций соединяет не больше одного газопровода, так что
нулевая клетка означает отсутствие газопровода, а станция, взятая из
очереди, просматривает всю свою строку через `enumerate`:
{1450_dp_optimized.py}.

Оптимизированное решение на Rust разбирает числа вручную из буфера на
4 КБ, а не читает весь ввод в `String`, и хранит сеть матрицей значений
прибыльности `u16`, около 490 КБ при `N = 500`, вместо векторов пар
`(usize, i64)`. Прибыльность не меньше 1, а пару станций соединяет не
больше одного газопровода, так что нулевая клетка означает отсутствие
газопровода; станция, взятая из очереди, просматривает всю свою строку,
всего `O(N²)`. Лучшая прибыльность маршрута до каждой станции — простой
`i32` с -1 для недостижимых станций вместо `Option<i64>`: в маршруте не
больше 499 газопроводов, так что его прибыльность не больше 4 990 000:
{1450_dp_optimized.rs}.
