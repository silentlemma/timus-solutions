# 1444. Накормить элефпотама

[Timus 1444](https://acm.timus.ru/problem.aspx?space=1&num=1444) · сложность 262 · geometry

Авторы оригинальной задачи — Екатерина Васильева (идея и текст) и Александр Мироненко, Алексей Лахтин и Ден Расковалов (программирование); Десятый командный чемпионат Урала по спортивному программированию, 24–25 марта 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N тыкв (3 ≤ N ≤ 30000) лежат в различных целых точках с координатами
от −1000 до 1000, не все на одной прямой. Элефпотам начинает у тыквы 1 и
съедает её; после каждой тыквы животное можно направить по прямой к
любой оставшейся тыкве. Наткнувшись на свои следы, элефпотам
останавливается насовсем, поэтому путь не должен касаться сам себя.
Нужно найти наибольшее число тыкв K, которое удастся скормить, и порядок
обхода, начиная с 1.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N, затем координаты тыкв с 1 по N.

## Выходные данные

K, затем номера тыкв в порядке поедания, по одному в строке. Принимается
любой правильный обход.

## Проверка

Принимается любой максимальный обход от первой точки: номера различны, путь не касается и не пересекает себя.

## Примеры

### Пример 1

Ввод:

```
4
0 0
10 10
0 10
10 0
```

Вывод:

```
4
1
3
2
4
```

## Решение

Съесть можно всегда все N тыкв. Отсортируем остальные по углу
направления из тыквы 1, а на одном луче — по расстоянию, ближние
раньше; сравнения используют целочисленные векторные произведения и
потому точны. Обход в этом порядке заметает тыкву 1 веером: каждый шаг
либо уходит дальше по тому же лучу, либо переходит к следующему
направлению, так что путь в каждый момент находится внутри одного узкого
сектора и никогда не возвращается.

Опасно только начало круга. Если два соседних направления отстоят на
пол-оборота или больше, шаг между ними может пройти через тыкву 1 или
пересечь прежние шаги, поэтому круг разрезается сразу после этого
промежутка; такой промежуток не больше одного, ведь не все тыквы лежат
на одной прямой. Без такого промежутка разрезаем круг между любыми
соседними группами различных направлений и начинаем с ближайшей тыквы
следующей группы. Нельзя разделять один луч разрезом: возвращение к
более близким тыквам на нём коснётся начального отрезка. Разрез по
умолчанию в начале угловой сортировки в решениях уже соблюдает это правило.
`O(N log N)`.

Дополнительная память простых версий O(N): записи точек/направлений, сортируемые индексы, при необходимости накопленный вывод и рабочая память сортировки. Версии с чтением всего ввода также хранят I байт; матрицы попарных пересечений нет.

Подводные камни:

- несколько тыкв на одном луче надо есть от ближней к дальней (тесты 03,
  06, gen2);
- при выборе разреза нельзя разделять группу одного луча, даже если
  все угловые промежутки меньше пол-оборота (тест 06);
- промежуток ровно в пол-оборота, когда тыквы лежат по обе стороны от
  тыквы 1 на одной прямой (тесты 03, 09);
- тыква 1 в углу оставляет промежуток больше пол-оборота (тесты 04,
  gen3, gen4).

## Оптимизированные решения

`1444_geometry_optimized.py`. Сохраняются точные упакованные угловые ранги, поля манхэттенского расстояния и номера, сортировка и выбор полукругового разрыва. Построение перенесено в main, чтобы горячий цикл работал с локальными переменными вместо словаря модуля. Границы координат, разделение целых рангов и порядок вывода прежние; float-углы не вводятся. Время O(N log N), память O(N). Новый запуск быстрее, но использует 4100 КБ вместо прежних оптимизированных 3976 КБ; учебные версии сохранены.

Accepted точного исходника CPython 3.12 №11326683: 0.14 с / 4100 КБ. Сравнение, сохранённое 2026-11-20 для актуальных компиляторов семейства: место по времени 2/74, по памяти 1/74. Память не меньше 1024 КБ: требуются оба строгих рейтинга, оба пройдены.

- `1444_geometry_optimized.py`: 0.14 s / 4100 KB; сохранённая учебная база `1444_geometry.py` (Python 3.12 x64): 0.453 s / 11600 KB; изменение времени -69.1%; изменение памяти -64.7%.

Вместо повторных сравнений векторных произведений сортируются точные упакованные целочисленные ключи направлений. Рациональный параметр на основе манхэттеновой длины монотонно обходит окружность. Ограничение координат даёт минимальное расстояние между различными дробями, поэтому масштабирование и взятие целой части не склеивают направления. В ключ входят ранг направления, манхэттенское расстояние |dx|+|dy| и исходный номер; на одном луче ближние точки остаются первыми. Угловой разрыв задаёт тот же циклический разрез, что и простое доказательство. Вещественные углы не вычисляются.

- `1444_geometry_optimized.cpp`: 0.015 s / 320 KB; база `1444_geometry.cpp`: 0.062 s / 444 KB; изменение относительно базы: время -75.8%, память -27.9%.
- `1444_geometry_optimized.go`: 0.031 s / 1188 KB; база `1444_geometry.go`: 0.078 s / 2336 KB; изменение относительно базы: время -60.3%, память -49.1%.
- `1444_geometry_optimized.java`: 0.093 s / 736 KB; база `1444_geometry.java`: 0.187 s / 6232 KB; изменение относительно базы: время -50.3%, память -88.2%.

- `1444_geometry_optimized.rs`: 0.046 s / 1244 KB; база `1444_geometry.rs`: 0.031 s / 2104 KB; изменение относительно базы: время +48.4%, память -40.9%.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1444_implementation_parsing_optimized.rs`. Точный угловой порядок и индексы uint32 сохранены. Обход записывается через единый ограниченный буфер без десятичной строки для каждой вершины и хранения полного вывода. Прямой вывод специализирован по реальным типам ответа без универсального выбора формата и временных строк. Фиксированный текст записывается нативно; числовой вывод точно обрабатывает нужные знаковые или беззнаковые значения. Математические решения и архивные простые версии сохранены.

Accepted #11329201 (Rust 1.75 x64): **0.015 s / 668 KB**. Архивное сравнение: `1444_geometry.rs` (Rust 1.75 x64) — 0.031 s / 2104 KB (#11286291).

## Особенности языков

Действуют единые [критерии](../../RATING_CRITERIA.md), память не сравнивается только строго ниже 1024 КБ. Отдельных правил первого места или улучшения на 30% нет. Для C++/Java/Python обычное сравнение — топ-10 или топ-15%, при 1–10 соперниках точного компилятора — выбранный эталон и допуски джиттера/тика.

Учебные базы `1444_geometry.*` сохранены. C++/Go/Java/Python закрывают `1444_geometry_optimized.*`: время C++ 1/353 при 320 КБ, Java 1/260 при 736 КБ, время/память Python 2/74 и 1/74 при 4100 КБ. Оптимизированная Go 0.031 s / 1188 КБ проходит пределы пяти соперников 0.12535 s / 3459.20 КБ.

Rust закрывает `1444_implementation_parsing_optimized.rs`, Accepted #11329201: 0.015 s / 668 КБ, проходящий предел времени одного соперника 0.078 s без сравнения памяти. Старый `1444_geometry_optimized.rs` сохранён со звёздочкой: 1244 КБ превышают обязательный предел 929.20 КБ. Простая Rust с 2104 КБ тоже его не проходит. Старое место 1/2 само по себе не даёт допуск при замене рейтинга малой выборкой. Прежние парные измерения выше — наблюдения, не альтернативные текущие критерии.

В `1444_implementation_parsing_optimized.rs` только именованы требуемые линтером константы; значения, алгоритм и комментарии прежние. Accepted #11329201 и парные метрики относятся к предыдущим точным байтам.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
