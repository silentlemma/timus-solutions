# 1471. 树上距离

[Timus 1471](https://acm.timus.ru/problem.aspx?space=1&num=1471) · 难度 163 · trees

原题作者 Dmitry Zhukov，出自 2006 年 8 月彼得罗扎沃茨克夏季集训的乌拉尔国立大学与奥廖尔国立技术大学比赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一棵树有 n 个顶点（1 ≤ n ≤ 50000），编号 0 到 n − 1，以及 n − 1 条带权边（权值
0 到 1000）。对 m 个询问（1 ≤ m ≤ 75000）中的每一个，输出两个给定顶点之间路径的
长度。

时间限制：1 秒。内存限制：64 MB。

## 输入

n，然后是形如 u v w 的边，然后是 m 和各对顶点。

## 输出

每行一个距离。

## 样例

### 样例 1

输入:

```
3
1 0 1
2 0 1
3
0 1
0 2
1 2
```

输出:

```
1
1
2
```

## 解法

以顶点 0 为根，记下每个顶点到根的距离。a 与 b 之间的路径先向上走到它们的最近公共
祖先，所以长度为 dist(a) + dist(b) − 2·dist(lca)。公共祖先由欧拉序得到：深度优先
遍历在进入顶点时写下它，并在每个子节点返回后再写一次。在 a 与 b 的首次出现位置之
间，遍历经过它们的公共祖先而不会更高，因此公共祖先就是这一段中深度最小的顶点。对
长度为 2^k 的区间建立最小值稀疏表，用两个相互重叠的查表即可得到答案。建表
`O(n log n)`，每个询问 `O(1)`。

注意事项：

- 50000 个顶点的链对大多数语言的递归来说太深，所以遍历使用自己的栈（gen3）；
- 顶点 0 可能是叶子，边的两个端点顺序任意（测试 03）；
- 只有一个顶点时完全没有边，询问中的两个顶点也可能相同（测试 02）。

## 优化解法

优化的 C++ 解法用重链剖分代替欧拉序来求祖先。从顶点 0 出发的广度优先遍历不用递归
也不用栈就得到各点的父亲、深度和距离；然后按逆序累加子树大小，每个顶点的重儿子是
子树最大的儿子，重边连成链，每个顶点记住所在链的链顶。回答询问时，链顶更深的那个
顶点跳到链顶的父亲，直到两点在同一条链上，两者中较浅的就是祖先。每跳一次都经过一
条轻边，而经过轻边后子树大小至少翻倍，所以每个询问只需 `O(log n)` 次跳跃，而且每
个数组只有 `n` 个元素，而不是 `O(n log n)` 的稀疏表。数字从用 `fread` 反复填充的
4 KB 缓冲区中手工解析：{1471_trees_bfs.cpp}。

优化的 Go 解法保留欧拉序和稀疏表，但从 1 MB 的 `bufio` 读取器中手工解析数字，而
不是用 `fmt.Fscan`；并把每条边两个方向的邻接表压进按各顶点起始偏移索引的扁平数
组，而不是每个顶点一个边结构体切片：{1471_trees_optimized.go}。
