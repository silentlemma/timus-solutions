# 1497. Разрезание квадрата

[Timus 1497](https://acm.timus.ru/problem.aspx?space=1&num=1497) · сложность 304 · implementation

Автор оригинальной задачи — Александр Торопов; XIII командный чемпионат школьников Свердловской области по программированию, 14 октября 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Клетчатый лист N × N (3 ≤ N ≤ 1000) разрезан на чёрный кусок (клетки 1)
и белый кусок (клетки 0), оба связны по сторонам. Куски лежат вместе на
столе. Можно ли отодвинуть один из них далеко от другого, не отрывая
ни один от стола? Нужно вывести «Yes» или «No».

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N строк по N символов 0 и 1.

## Выходные данные

«Yes» или «No».

## Примеры

### Пример 1

Ввод:

```
5
10001
10001
10001
11111
11111
```

Вывод:

```
Yes
```

### Пример 2

Ввод:

```
5
11011
11011
10001
11111
11111
```

Вывод:

```
No
```

## Решение

Отодвинуть один кусок — то же, что отодвинуть другой в обратную
сторону, так что двигать нужно только чёрный кусок. Он может уехать
прямо вверх, когда ни в одном столбце нет белой клетки над чёрной, и
так же вниз, влево и вправо. Сдвиг по диагонали ничего не добавляет:
каждое ребро между кусками должно смотреть от направления движения, и
тогда свободны и оба осевых сдвига, из которых складывается диагональ.
Значит, достаточно проверить четыре направления, по одному проходу по
листу на каждое. `O(N²)`.

Подводные камни:

- кусок, окружённый другим, уйти не может никогда (тест 03, gen2);
- один крючок, даже в одну клетку, сцепляет куски (тесты 05, 07,
  gen4);
- лестничный разрез раздвигается вдоль оси, хотя его рёбра смотрят в
  две стороны (тест 04, gen1).

## Оптимизированные решения

`1497_implementation_optimized.cpp`. Сохраняются четыре флага допустимых направлений. SSE2 сравнивает сразу шестнадцать клеток и превращает блок строки в битовую маску; сдвиг масок обнаруживает горизонтальные переходы, перенос связывает соседние блоки, маски предыдущей строки — вертикальные переходы. Последний неполный блок маскируется, массив строки дополнен так, чтобы каждая векторная загрузка оставалась в его границах. SSE2 входит в целевую x64, инструкции AVX не нужны. Буфер ввода 16 КБ заменяет посимвольный стандартный ввод. Время O(N²), вспомогательная память O(N); ранний отказ сохранён.

Accepted точного исходника №11326995: 0.015 s / 92 KB. Сохранённая выборка G++ 13.2 от 2026-11-20: место по времени 1/46, по памяти 1/46. Учебные исходники сохранены.

C++ и Go проверяют четыре направления за один проход. На горизонтальной паре клеток разных цветов по этой оси допустимо только движение чёрной части от белой. Вертикальная пара так же ограничивает вторую ось. Храним четыре флага и прекращаем проверку, когда все сброшены. Достаточно предыдущей и текущей строк, поэтому память O(N).

Сохранённые принятые базовые реализации [1497_implementation.go](1497_implementation.go), [1497_implementation.java](1497_implementation.java), [1497_implementation.py](1497_implementation.py), [1497_implementation.rs](1497_implementation.rs) также проходят строгий критерий быстрого набора в сохранённой выборке: первые десять мест или топ 15% по требуемым метрикам. Они используются без одинаковых копий; остальные учебные исходники сохранены. Звёздочка обозначает отдельную рейтинговую цель языка.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1497_bitmask_optimized.py`. Каждая двоичная строка просматривается один раз. Поиск в байтах выявляет горизонтальные инверсии, маски столбцов — вертикальные относительно предыдущих строк. Те же четыре направления проверяются за O(n²) времени с O(n) состоянием вместо хранения матрицы. Самостоятельная программа сбрасывает оба выходных потока перед os._exit(0), чтобы после записи полного ответа не выполнять завершение интерпретатора. Это изменение завершения процесса, а не математического алгоритма; простая версия сохранена.

Accepted #11328775 (Python 3.12 x64): **0.093 s / 832 KB**. Архивное сравнение: `1497_implementation.py` (Python 3.12 x64) — 0.109 s / 4276 KB (#11287235).
