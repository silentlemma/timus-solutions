# 1402. Коктейли

[Timus 1402](https://acm.timus.ru/problem.aspx?space=1&num=1402) · сложность 130 · combinatorics

Автор оригинальной задачи — Сергей Пупырев; XII командный чемпионат школьников Свердловской области по программированию, 15 октября 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Коктейль — смесь двух или более из N ≤ 21 напитков, каждый не больше
одного раза, и порядок напитков важен. Нужно посчитать различные
коктейли.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N (1 ≤ N ≤ 21).

## Выходные данные

Количество коктейлей.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
3
```

Вывод:

```
12
```

## Решение

Коктейль из k напитков — упорядоченный выбор k различных напитков, и
таких N·(N − 1)·…·(N − k + 1). Складываем их для k от 2 до N, получая
каждое произведение из предыдущего. `O(N)`.

Подводные камни:

- с одним напитком коктейлей нет вовсе (тест 02);
- при N = 21 ответ около 1,4·10²⁰, больше 64 бит, поэтому решения
  используют 128-битные или длинные числа (тест 07).

Тесты проверяются точным сравнением.

## Оптимизированные решения

`1402_combinatorics_optimized.py`. Сохраняется убывающее факториальное произведение: ways начинается с N, при k=2..N умножается на N-k+1 и добавляется в total. Упорядоченные выборы считаются без таблицы факториалов и пересчёта каждого произведения. При N=1 получается ноль. Время O(N) ограниченных арифметических операций и O(1) ячеек целых при N<=21. Используется та же точная рекуррентность целых Python с байтовым вводом; комбинаторная формула не меняется. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1402_combinatorics.py`: время 0.078 s → 0.125 s; память 388 KB → 244 KB.

`1402_combinatorics_optimized.rs`. Сохраняется убывающее факториальное произведение: ways начинается с N, при k=2..N умножается на N-k+1 и добавляется в total. Упорядоченные выборы считаются без таблицы факториалов и пересчёта каждого произведения. При N=1 получается ноль. Время O(N) ограниченных арифметических операций и O(1) ячеек целых при N<=21. Сохраняется u128, поскольку ответ для21 напитка превышает64 бита. Фиксированные39 байт десятичных цифр вмещают любой u128; консервативная граница21*21! намного меньше его максимума. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1402_combinatorics.rs`: время 0.031 s → 0.062 s; память 232 KB → 56 KB.

Оптимизированное решение на C++ суммирует в том же 128-битном целом, но
записывает цифры с конца в массив фиксированного размера на 23 символа
вместо того, чтобы вставлять каждую в начало `std::string`: при `N ≤ 21`
ответ меньше 21·21! < 10²², так что 22 цифры и завершающий ноль всегда
помещаются. Без `<string>` программа сама ничего не выделяет в куче:
{1402_combinatorics_optimized.cpp}.

Оптимизированное решение на Java читает N побайтно из `System.in` вместо
того, чтобы создавать `Scanner`, чьи регулярные выражения и данные
локали обходятся дороже самих умножений, которых не больше двадцати;
сумма по-прежнему хранится в `BigInteger`:
{1402_combinatorics_optimized.java}.
