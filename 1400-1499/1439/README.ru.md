# 1439. Поединок с И-Так-Понятно-Кем

[Timus 1439](https://acm.timus.ru/problem.aspx?space=1&num=1439) · сложность 428 · binary_search

Авторы оригинальной задачи — Александр Клепинин и Станислав Васильев; Десятый командный чемпионат Урала по спортивному программированию, 24–25 марта 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Комнаты Министерства Магии пронумерованы 1, 2, …, N (1 ≤ N ≤ 10⁹), и
нумерация всегда остаётся без пропусков: когда комнату уничтожают, все
комнаты с бо́льшими номерами сдвигаются на один номер вниз. По порядку
идут M ≤ 10⁵ событий, каждое «D x» (уничтожена комната, у которой
сейчас номер x) или «L x» (Гарри смотрит на дверь, где сейчас номер x).
Уничтожается не более 10⁴ комнат. Для каждого события «L» нужно вывести
номер, который эта комната имела в самом начале.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и M, затем M событий.

## Выходные данные

Исходные номера, по одному в строке.

## Примеры

### Пример 1

Ввод:

```
20 7
L 5
D 5
L 4
L 5
D 5
L 4
L 5
```

Вывод:

```
5
4
6
4
7
```

## Решение

Храним исходные номера уничтоженных комнат в отсортированном массиве g.
Комната с текущим номером x имеет исходный номер x + k, где k — число
уничтоженных комнат ниже неё. Если идти по массиву вверх, комната g[j]
лежит ниже ровно тогда, когда g[j] ≤ x + j, то есть g[j] − j ≤ x; а
g[j] − j не убывает, потому что номера в g различны, так что комнаты
ниже образуют префикс, и его длина k находится двоичным поиском.

Для «L» выводим x + k. Для «D» новый исходный номер x + k встаёт ровно
на позицию k массива: всё до неё меньше, всё после — больше, так что
вставка сохраняет порядок. `O(M log D + D²)` для D уничтоженных комнат,
где каждая вставка сдвигает не более 10⁴ чисел.

Подводные камни:

- один и тот же номер двери, уничтожаемый снова и снова, каждый раз
  скрывает новую комнату (тесты 03, 07, gen3);
- номера доходят до миллиарда, массив на каждую комнату не подходит
  (тесты 05, gen1).

## Оптимизированные решения

Эти реализации сохраняют отсортированный массив уничтоженных комнат и двоичный поиск нужного префикса. Вставка по-прежнему сдвигает элементы, поэтому время остаётся O(M log D + D²). Улучшение состоит в компактном хранении и потоковом вводе-выводе. C++ хранит исходные номера в 32 битах, чего достаточно при N ≤ 10⁹, и резервирует место для 10000 удалений. Go и Rust используют ограниченные буферы; Rust также хранит 32-битные номера и запускается через C runtime. Python освобождает каждую строку ввода после обработки и копит байты вывода вместо всех входных токенов и выходных Python-чисел. Его память — O(D + размер вывода), у остальных новых версий — O(D) и фиксированные буферы. Прежние простые реализации сохранены.

Принятая версия Python 3.12 x64 заняла 0.437 с при 0.421 с у базовой и использовала 2 376 KB при 21004 KB у базовой.

Принятая версия Rust 1.75 x64 заняла 0.046 с при 0.031 с у базовой и использовала 96 KB при 4664 KB у базовой.

Принятые базовые реализации [1439_binary_search.java](1439_binary_search.java) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
