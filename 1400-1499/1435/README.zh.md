# 1435. 财务错误

[Timus 1435](https://acm.timus.ru/problem.aspx?space=1&num=1435) · 难度 989 · math

原题作者 Evgeny Krokhalev，出自 2006 年 2 月 25 日第七届乌拉尔国立大学个人公开赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

从报告中抄下 N 个数（N ≤ 200 000，每个不超过 2³¹ − 1），它们的和与报告中的总数
（不超过 10¹⁶）不一致。抄写错误是某个数的两个相邻数字被交换了；抄本和真实的数都
没有前导零。若和相等，输出 "Input has no error."；若某条记录可由这样的交换解释，
输出 "Error in record #L. Correct number is: K."；否则输出 "Unrecoverable
error."。

时间限制：0.4 秒。内存限制：64 MB。

## 输入

N，N 个抄下的数，然后是报告的总数。

## 输出

三行之一。

## 样例

### 样例 1

输入:

```
3
12
26
45
119
```

输出:

```
Error in record #2. Correct number is: 62.
```

## 解法

交换 10^(i+1) 位上的数字 a 与 10^i 位上的数字 b，使数改变
(b − a)·10^(i+1) + (a − b)·10^i = 9·(b − a)·10^i。所以总数与和之差 D 必须等于
9·c·10^i，且 1 ≤ |c| ≤ 9：把 D 除以 9，去掉因子 10 得到 i，剩下的就是 c。然后把
记录当作字符串扫描，找 10^(i+1) 位与 10^i 位的数字恰好相差 c 的记录，跳过会把 0
换到开头的交换，输出第一条这样的记录，并把两个数字换回来。`O(N)`。

注意事项：

- 真实的数可能超出 32 位，例如 1900000000 应为 9100000000（测试 04）；
- 90 不可能是 09 的抄本，10 也不可能是 01 的抄本（测试 02、06）；
- 总数本身没有抄错（测试 07）；
- 要在 0.4 秒内读完 200 000 个数需要快速输入；各解法一次读入全部内容。
