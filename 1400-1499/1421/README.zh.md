# 1421. 信贷业务

[Timus 1421](https://acm.timus.ru/problem.aspx?space=1&num=1421) · 难度 539 · greedy

原题作者 Ilya Grebnov、Dmitry Kovalioff 与 Nikita Rybak，出自 Timus Top Coders: First Challenge。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

用 0 到 100 的整数填满一个 N × N 矩阵（2 ≤ N ≤ 100），使第 i 行之和为 SR[i]，第
j 列之和为 SC[j]（每个和在 0 到 32 000 之间，两边总和相等）。输出 "YES" 和任意一
个这样的矩阵；若不存在，输出 "NO"。

时间限制：0.25 秒。内存限制：64 MB。

## 输入

N，然后 N 个行和，然后 N 个列和。

## 输出

"NO"，或 "YES" 和矩阵。

## 样例

### 样例 1

输入:

```
4
267 157 188 259
193 320 346 12
```

输出:

```
YES
100 55 100 12
0 70 87 0
0 95 93 0
93 100 66 0
```

## 解法

逐行填写，每次从仍需要最多的列中取。对需要 r 的一行，把所有列的需求向同一水平 L
降低：第 j 列给出 min(100, max(0, SC[j] − L))。给出的总量随 L 增大而减少，所以用
二分查找找到给出量不超过 r 的最小 L，缺少的几个单位从恰好处在水平 L 的列中各取
一个。如果连 L = 0 给出的都少于 r，答案就是 "NO"。

为什么这样不会破坏解：假设存在一个矩阵，但它的第一行使列 j 剩下的需求比列 k 至
少多 2，而这一行本可以从 j 再多取一个、并且从 k 取了一些。那么列 j 的剩余之和大
于列 k 的剩余之和，于是下面某一行在 j 上比在 k 上多。在第一行把一个单位从 k 移到
j，在那一行再移回去，所有和与上下界都保持不变，而剩余需求变得严格更均匀。反复
这样做就得到贪心构造的均衡行，而剩下的问题只依赖于列需求的多重集，所以只要存在
解，贪心就能保住它。`O(N² log S)`。

注意事项：

- 每一行、每一列单独看都放得下，但两行合起来却放不下，所以只按单行单列检查不够
  （测试 06）；
- 任何正确的矩阵都被接受，所以测试使用检查器（测试 01）；
- 某行平均每列需要超过 100 时立即无解（测试 03、08）。

## 优化解法

Rust 保持共同水位贪心与原交换证明。输入/剩余和≤32000 用16位，单格≤100 用字节。N≤100 固定矩阵10000字节、边际和400字节，不分配行向量或逐数字符串。大于100N 的边际立即拒绝，但仍需完整可行性检查；零行跳过。非零行以当前最大剩余列和为二分上界，分配截断贡献及并列余量后立即扣列和。L > 0 时将水位降到 L − 1，每个合适的列多给一单位。L 的最小性保证单位数足够。L = 0 时行和已恰好满足。

对比任意可行矩阵处理本行后的剩余列和与贪心目标。把 L 或 L − 1 限制在各列允许的区间内可知，高于目标的剩余量至少为 L，低于目标的至多为 L − 1。某个后续行在前一列的值必大于后一列。当前行与该行在这两列间反向交换一单位，保持行列和及取值范围，并让剩余量更接近目标。重复即可得到贪心选择的精确剩余向量。

全部列和归零才输出 YES，失败不输出部分矩阵。C 字符 I/O 与 C 入口直接输出有界整数。时间 O(N² log S)，S=max(2, 初始最大列和)，空间 O(N²) 且受固定上限约束。保留简单版，C++/Go/Java/Python 复用已达标基础版。

通过评测的 Rust 1.75 x64 版本耗时 0.062 秒，基础版为 0.031 秒，内存为 84 KB，基础版为 336 KB。
