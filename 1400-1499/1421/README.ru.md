# 1421. Кредитные операции

[Timus 1421](https://acm.timus.ru/problem.aspx?space=1&num=1421) · сложность 539 · greedy

Авторы оригинальной задачи — Илья Гребнов, Дмитрий Ковалёв и Никита Рыбак; Timus Top Coders: First Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Заполнить матрицу N × N (2 ≤ N ≤ 100) целыми числами от 0 до 100 так,
чтобы сумма строки i была SR[i], а столбца j — SC[j] (каждая сумма от 0
до 32 000, итоги равны). Вывести «YES» и любую такую матрицу или «NO»,
если её нет.

Ограничение времени: 0.25 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N сумм строк, затем N сумм столбцов.

## Выходные данные

«NO» или «YES» и матрица.

## Примеры

### Пример 1

Ввод:

```
4
267 157 188 259
193 320 346 12
```

Вывод:

```
YES
100 55 100 12
0 70 87 0
0 95 93 0
93 100 66 0
```

## Решение

Заполняем строки по одной, каждый раз беря кредиты у столбцов, которым
ещё нужно больше всего. Для строки, которой нужно r, опускаем
потребности всех столбцов к общему уровню L: столбец j даёт
min(100, max(0, SC[j] − L)). С ростом L отдаваемая сумма уменьшается,
поэтому двоичный поиск находит наименьшее L, при котором отдаётся не
больше r, а недостающие единицы берутся по одной у столбцов, стоящих
ровно на уровне L. Если даже L = 0 даёт меньше r, ответ «NO».

Почему это не портит решение: пусть матрица существует, но её первая
строка оставляет столбцу j хотя бы на 2 больше, чем столбцу k, хотя
строка могла бы взять ещё единицу из j и что-то даёт k. Тогда остаток
столбца j больше остатка столбца k, и в какой-то нижней строке в j
больше, чем в k. Перенос единицы из k в j в первой строке и обратно в
той строке сохраняет все суммы и границы и делает оставшиеся
потребности строго ровнее. Повторяя это, приходим к сбалансированной
строке, которую строит жадность, а оставшаяся задача зависит лишь от
мультимножества потребностей столбцов, так что жадность сохраняет
решение, если оно есть. `O(N² log S)`.

Подводные камни:

- каждая строка и каждый столбец могут помещаться по отдельности, а
  две строки вместе — нет, так что проверок по отдельным линиям мало
  (тест 06);
- принимается любая правильная матрица, поэтому тесты проверяет чекер
  (тест 01);
- строке, которой нужно больше 100 на столбец, сразу не помочь (тесты
  03, 08).

## Оптимизированные решения

Rust сохраняет тот же жадный алгоритм общего уровня и обменное доказательство. Входные и остаточные суммы до32000 хранятся в16 битах, кредит до100 — в байте. При N≤100 фиксированные массивы занимают10000 байтов под матрицу и400 под суммы, без векторов строк и строк для каждого числа. Сумма строки или столбца выше100N сразу невозможна, но эта проверка не заменяет последующие. Нулевые строки пропускаются. Для ненулевой строки двоичный поиск ограничен текущим максимумом остатка; после основных взносов распределяется остаток среди равных столбцов и суммы сразу уменьшаются. При L > 0 снижение уровня до L − 1 даёт по единице с каждого подходящего столбца. По минимальности L этих единиц хватает. При L = 0 сумма строки уже точна.

Сравним целевые остатки жадного алгоритма с остатками любого допустимого решения после текущей строки. Избыток над целью означает остаток не меньше L, а недостаток — не больше L − 1. Это следует из ограничения уровней L и L − 1 допустимым интервалом столбца. В какой-то следующей строке в столбце с избытком больше единиц, чем в столбце с недостатком. Обменяем единицу между этими столбцами в текущей и следующей строках в противоположных направлениях. Суммы и границы соблюдены, а остатки ближе к целевым. Повторяем до точного жадного вектора.

YES печатается только после обнуления всех остатков, частичной матрицы при отказе нет. Символьный C runtime и точка входа C выводят числа напрямую. Время O(N² log S), S=max(2, наибольшая начальная сумма столбца), память O(N²) в фиксированных пределах. Простые файлы сохранены; C++/Go/Java/Python используют подходящие базы.

Принятая версия Rust 1.75 x64 заняла 0.062 с при 0.031 с у базовой и использовала 84 KB при 336 KB у базовой.

Принятые базовые реализации [1421_greedy.cpp](1421_greedy.cpp), [1421_greedy.go](1421_greedy.go), [1421_greedy.java](1421_greedy.java), [1421_greedy.py](1421_greedy.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
