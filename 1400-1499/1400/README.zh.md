# 1400. 手机符号

[Timus 1400](https://acm.timus.ru/problem.aspx?space=1&num=1400) · 难度 549 · graphs

原题作者 Vladimir Yakovlev，出自 2005 年 10 月 15 日第十二届斯维尔德洛夫斯克州中学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

手机的 N ≤ 256 个附加符号排成 M 列的表格，按行填入，最后一行可能较短。光标
可以向左、右、上、下移动；向左和向右还会越过行首行尾到上一行或下一行，并在表
格两端之间循环，而在第一行向上或向下到不存在的格子时光标不动。选择到达各符号
平均按键次数最少的起始格，输出这个平均值以及每个符号的按键次数。

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 M。

## 输出

"Mean = X"，保留两位小数，然后是 N 个按键次数，每行 M 个。任何最佳起始格都
被接受。

## 样例

### 样例 1

输入:

```
5 3
```

输出:

```
Mean = 1.00
1 0 1
2 1
```

## 解法

按行把格子编号为 0 … N − 1。于是向左、向右就是模 N 的 i − 1 和 i + 1，向上是
i − M（若该格存在），向下是 i + M（若该格存在）；否则光标不动。从每个起始格做
一次广度优先搜索得到全部距离，和最小的起点获胜。`O(N²)`。

注意事项：

- 只有一个符号时答案是 Mean = 0.00 和一个 0（测试 02）；
- 像 13/8 = 1.625 这样的平均值在第二位小数处恰好是中点；解答输出与 C 的
  printf 相同的结果 1.62，所以 Java 用 BigDecimal 对 double 的精确值舍入，
  而不用 String.format（测试 07）；
- 据论坛所说，有超出题面范围的测试，比如 46 列，所以没有任何东西按这些范围
  定死（测试 06）。

测试由检查程序判定：要求平均值最小，且各距离来自某个具有该平均值的起始格。
