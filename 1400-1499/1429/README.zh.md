# 1429. 饼干

[Timus 1429](https://acm.timus.ru/problem.aspx?space=1&num=1429) · 难度 2686 · geometry

原题作者 Nikita Rybak、Ilya Grebnov 与 Dmitry Kovalioff，出自 Timus Top Coders: First Challenge。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

面团擀成以原点为圆心、半径 32 000 的圆，在上面切了 N 个圆形切口（N ≤ 500），每个
切口的圆心（|X|, |Y| ≤ 10 000）和半径（1 ≤ R ≤ 10 000）都是整数，所以它们都远在
面团内部。求面团被分成的块数；块可以带孔，所有切口外剩下的部分也算一块。切口的
不同交点或切点之间的距离至少为 10⁻³。

时间限制：1 秒。内存限制：64 MB。

## 输入

N，然后 N 行 X Y R。

## 输出

块数。

## 样例

### 样例 1

输入:

```
3
-1 0 2
1 0 2
0 0 3
```

输出:

```
6
```

## 解法

切口构成一个平面图：交点和切点是顶点，它们之间的圆弧是边。有 C 个连通分量的平面
图满足欧拉公式 V − E + F = 1 + C，其中 F 也包括外部的面，而这里外部的面就是剩下
的面团，本身也是一块。所以答案是 E − V + C + 1。没有交点的圆算作一个顶点和一条
边，这不改变 E − V，但它单独构成一个分量。

重复的切口算一个，所以先合并相同的圆。两个圆的公共点个数用整数根据 d²、
(r₁ − r₂)² 和 (r₁ + r₂)² 精确判定。交点本身为
p₁ + (m·(dx, dy) ± √K·(−dy, dx)) / (2d²)，其中 m = d² + r₁² − r₂²，
K = 4d²r₁² − m² 是精确的整数，所以只有一次开方和一次除法有舍入。来自不同圆对的
点通过格子大小为 10⁻³ 的网格哈希合并：同一点的不同估计相差远小于 10⁻⁴，而不同的
点至少相距 10⁻³。每个圆上的弧数等于其上不同点的个数，对相交的圆对做并查集得到
C。共 `O(N²)` 对，最多约 250 000 个点。

注意事项：

- 剩下的面团也算，所以一个切口得到 2（测试 01、03）；
- 相同的切口必须合并（测试 06、09）；
- 多个圆可能交于一点，这仍是一个顶点（测试 07、gen4）；
- 相切和几乎相切的圆需要精确的判定和小心的舍入（测试 04、05、08）。

## 各语言说明

- C++ 和 Rust 如上所述用一个网格哈希存放所有点。在 Go、Java 和 Python 中，这张多达 250 000 个点的表超过了 64 MB 的限制，所以它们只保存每个圆上的估计值，并逐个圆合并。一个圆上 s 个估计值组成的一组是位于 s + 1 个圆上的一个点，所以它给顶点数加上 1 / (s + 1)，每个点合计正好加 1。Go 和 Python 为每个圆用一个小的网格哈希合并；Java 把估计值绕圆心的角度排序，同一点的估计值会相邻，因为不同的点在角度上至少相差 10⁻³ / r。
- Python 在 PyPy 下运行：用 CPython 时，这里最大的测试逐圆合并约需 0.8 秒，接近 1 秒的限制。
