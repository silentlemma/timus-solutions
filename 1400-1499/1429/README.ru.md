# 1429. Печенье

[Timus 1429](https://acm.timus.ru/problem.aspx?space=1&num=1429) · сложность 2686 · geometry

Авторы оригинальной задачи — Никита Рыбак, Илья Гребнов и Дмитрий Ковалёв; Timus Top Coders: First Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Тесто раскатано кругом радиуса 32 000 с центром в начале координат, и
в нём сделаны N круговых разрезов (N ≤ 500), у каждого целые центр
(|X|, |Y| ≤ 10 000) и радиус (1 ≤ R ≤ 10 000), так что все они лежат
глубоко внутри теста. Нужно посчитать куски, на которые распадается
тесто; куски могут быть с дырками, а остаток вокруг всех разрезов —
тоже кусок. Различные точки пересечения или касания разрезов отстоят
друг от друга не меньше чем на 10⁻³.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N строк X Y R.

## Выходные данные

Число кусков.

## Примеры

### Пример 1

Ввод:

```
3
-1 0 2
1 0 2
0 0 3
```

Вывод:

```
6
```

## Решение

Разрезы образуют плоский граф: точки пересечения и касания — вершины,
дуги между ними — рёбра. Формула Эйлера для плоского графа из C
компонент связности: V − E + F = 1 + C, где F учитывает и внешнюю
грань, а внешняя грань здесь — остаток теста, тоже кусок. Поэтому ответ
E − V + C + 1. Окружность без пересечений считается одной вершиной и
одним ребром: это не меняет E − V, но даёт свою компоненту.

Повторный разрез — тот же разрез, поэтому равные окружности сначала
объединяются. Число общих точек двух окружностей определяется точно
в целых числах по d², (r₁ − r₂)² и (r₁ + r₂)². Сами точки —
p₁ + (m·(dx, dy) ± √K·(−dy, dx)) / (2d²) при m = d² + r₁² − r₂² и
K = 4d²r₁² − m², где K — точное целое, так что округляются лишь один
корень и одно деление. Точки из разных пар объединяются через
хеш-сетку с клетками 10⁻³: оценки одной точки различаются гораздо
меньше чем на 10⁻⁴, а различные точки отстоят не меньше чем на 10⁻³. У
каждой окружности столько дуг, сколько на ней различных точек, а
система непересекающихся множеств по пересекающимся парам даёт C.
`O(N²)` пар, до примерно 250 000 точек.

Подводные камни:

- остаток теста считается, так что один разрез даёт 2 (тесты 01, 03);
- равные разрезы нужно объединять (тесты 06, 09);
- несколько окружностей могут встречаться в одной точке, и это одна
  вершина (тесты 07, gen4);
- касания и почти касающиеся окружности требуют точных проверок и
  аккуратного округления (тесты 04, 05, 08).

## Особенности языков

- C++ и Rust держат один сеточный хеш всех точек, как описано выше. В Go,
  Java и Python такая таблица до 250 000 точек превышала лимит 64 МБ,
  поэтому они хранят только оценки на каждой окружности и склеивают их
  по окружностям. Группа из s оценок на окружности — это точка на s + 1
  окружностях, поэтому она добавляет 1 / (s + 1) к числу вершин, а
  каждая точка в сумме даёт 1. Go и Python склеивают оценки маленьким
  сеточным хешем на окружность; Java сортирует углы оценок вокруг
  центра, где оценки одной точки идут подряд: разные точки отличаются по
  углу хотя бы на 10⁻³ / r.
- Python запускается под PyPy: склейка по окружностям занимает около
  0,8 с в CPython на самых больших здешних тестах, близко к лимиту 1 с.
