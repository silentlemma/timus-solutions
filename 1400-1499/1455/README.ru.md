# 1455. Свобода слова

[Timus 1455](https://acm.timus.ru/problem.aspx?space=1&num=1455) · сложность 2022 · shortest_paths

Авторы оригинальной задачи — Никита Рыбак, Илья Гребнов и Дмитрий Ковалёв; Timus Top Coders: Second Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В словаре N различных слов (1 ≤ N ≤ 100) из 1–100 малых латинских букв.
После реформы тексты пишутся без разделителей. Нужно найти текст не
длиннее 20000 букв, который делится на слова словаря двумя разными
способами, или вывести «NO», если такого нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N слов.

## Выходные данные

«NO» или «YES» и текст. Принимается любой такой текст.

## Примеры

### Пример 1

Ввод:

```
5
ab
acb
bc
abac
babbc
```

Вывод:

```
YES
abacbabbc
```

Текст «abacbabbc» — это и «abac» + «babbc», и «ab» + «acb» + «ab» +
«bc».

## Решение

Будем читать два разных разбиения одного текста параллельно, в духе
критерия Сардинаса — Паттерсона. В каждый момент одно разбиение опережает
другое на некоторый хвост, и этот хвост всегда — суффикс слова словаря,
так что состояний не больше 100 · 100. Поиск начинается с каждой пары
слов u ≠ v, где u — префикс v, с хвостом «v без u». Из хвоста t слово w,
добавленное к отстающему разбиению, либо точно заканчивается вместе с t —
это замыкает неоднозначный текст; либо длиннее и начинается с t, и тогда
другое разбиение отстаёт на остаток w; либо является префиксом t и
оставляет остаток t.

Стоимость состояния — длина уже написанного текста, она растёт только
когда отстающее разбиение обгоняет. Алгоритм Дейкстры по этим
стоимостям находит кратчайший неоднозначный текст, поэтому если
существует текст в пределах ограничения, найденный тоже в них уложится;
текст восстанавливается по кусочкам назад до начальной пары.
`O(S · N · L log S)` для S состояний и слов длины L.

Подводные камни:

- у одного слова, префиксного или суффиксного кода неоднозначного текста
  нет (тесты 02, 05, 09, gen4, gen5);
- одно разбиение может опережать много шагов подряд, поэтому поиск
  должен следить за хвостами, а не только за парами слов (тесты 03, 07);
- обычный поиск в ширину считает шаги, а не буквы, и может вернуть более
  длинный текст, чем нужно.
