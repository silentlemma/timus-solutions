# 1427. SMS

[Timus 1427](https://acm.timus.ru/problem.aspx?space=1&num=1427) · сложность 364 · greedy

Авторы оригинальной задачи — Дмитрий Ковалёв, Никита Рыбак и Илья Гребнов; Timus Top Coders: First Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Текст длиной до 100 000 символов (латинские буквы, пробелы, цифры и
знаки . , ; : ! ? - ") разбивается на последовательные SMS. Сообщение
только из букв и пробелов может иметь длину до M символов, любое
другое — только до N (1 ≤ N ≤ M ≤ 10 000). Нужно найти наименьшее
число сообщений.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N и M, затем текст отдельной строкой.

## Выходные данные

Наименьшее число сообщений.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
10 15
On the 11-th of February, 2006 the contest "Timus Top Coders: First Challenge" is held!
```

Вывод:

```
8
```

## Решение

Пусть run(i) — число букв и пробелов подряд, начиная с позиции i.
Сообщение, начатое в i, может закончиться где угодно до
i + max(N, min(M, run(i))). Этот самый дальний конец не отступает
назад с ростом i (и i + N, и конец отрезка букв только растут), а при
такой монотонной досягаемости жадность, всегда отправляющая самое
длинное сообщение, оптимальна: любой другой план на каждом шаге
продвигается не дальше. Отрезки букв считаются с конца текста. `O(L)`.

Подводные камни:

- текст может начинаться с пробелов, поэтому вторую строку нужно
  читать целиком, а не после пропуска пробелов (тест 04);
- цифры не считаются буквами (тесты 03, 06);
- сообщение из букв всё равно может быть короче N; длинная форма
  помогает, только когда отрезок букв длиннее N (тест 05).

## Оптимизированные решения

`1427_greedy_optimized.cpp`. Сохраняются потоковый жадный выбор самого длинного допустимого сообщения и признак латинской буквы или пробела. Буфер fread 4 КБ заменяет отдельный вызов ввода с блокировкой для каждого байта. Пропускаются только остаток заголовка и завершающие CR/LF; начальные и конечные пробелы и пунктуация текста сохраняются. Прежние длина и флаг простого текста определяют начало следующего сообщения. Время O(L), фиксированная вспомогательная память; вся строка не хранится.

Accepted точного исходника №11326989: 0.015 s / 88 KB. Сохранённая выборка G++ 13.2 от 2026-11-20: место по времени 1/67, по памяти 1/67. Учебные исходники сохранены.

`1427_greedy_optimized.py`. Сохраняются жадный выбор самого дальнего конца сообщения и семантика Unicode isalpha. Вместо массива длин серий на L позиций просматриваются только буквы и пробелы текущего сообщения до максимальной длины. Каждый просмотренный символ поглощается до следующей итерации, поэтому суммарное сканирование O(L). Сама строка UTF-8 остаётся: O(L) памяти входа и O(1) дополнительного состояния. Удаляются только CR/LF, значимые пробелы и пунктуация сохраняются.

По сравнению с `1427_greedy.py`: время 0.093 s → 0.14 s; память 4392 KB → 1 852 KB.

C++ и Go расширяют текущее сообщение прямо при чтении текста. Храним его длину и признак того, что пока встретились только буквы и пробелы. Если следующий символ превысит применимый лимит, заканчиваем текущее сообщение и начинаем с этого символа следующее. Получаем то же жадное правило за O(L) времени и с O(1) дополнительной памяти.

Сохранённые принятые базовые реализации [1427_greedy.go](1427_greedy.go), [1427_greedy.java](1427_greedy.java), [1427_greedy.rs](1427_greedy.rs) также проходят строгий критерий быстрого набора в сохранённой выборке: первые десять мест или топ 15% по требуемым метрикам. Они используются без одинаковых копий; остальные учебные исходники сохранены. Звёздочка обозначает отдельную рейтинговую цель языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1427_greedy_optimized.py`: место по времени 4/11, по памяти 5/11 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
