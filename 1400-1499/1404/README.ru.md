# 1404. Легко взломать!

[Timus 1404](https://acm.timus.ru/problem.aspx?space=1&num=1404) · сложность 80 · implementation

## Задача

Слово не длиннее 100 строчных латинских букв шифруется так: буквы
заменяются числами от 0 до 25, к первому числу прибавляется 5, к каждому
следующему — новое значение предыдущего, затем все значения берутся по
модулю 26 и снова заменяются буквами. По зашифрованному слову нужно
восстановить исходное.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Зашифрованное слово.

## Выходные данные

Исходное слово.

## Примеры

### Пример 1

Ввод:

```
xbduyr
```

Вывод:

```
secret
```

## Решение

k-е зашифрованное значение — это (k − 1)-е плюс k-я буква, и переход к
модулю 26 это соотношение не портит. Поэтому каждая буква — разность её
кода и предыдущего кода по модулю 26, а перед первым кодом стоит 5.
`O(n)`.

Подводные камни:

- разность может быть отрицательной, её нужно вернуть в 0 … 25 (тест 03,
  где z превращается в e и обратно);
- суммы при шифровании выходят за 25 до взятия остатка, но коды во
  входных данных уже приведены, и этого достаточно.

Тесты получены шифрованием слов и проверяются точным сравнением.

## Оптимизированные решения

`1404_implementation_optimized.py`. Python сохраняет обратный проход с первыми разностями на месте. Идём от последнего зашифрованного байта к первому, чтобы предыдущий шифрованный байт ещё не изменился; каждую разность берём по модулю 26, для первой буквы снимаем начальный сдвиг на пять. Двоичный ввод и bytearray заменяют Unicode-декодирование и обратное кодирование; добавляется перевод строки, байты записываются один раз, выход внутри main обходится без TextIO. Время O(N), память O(N). Списков целых из zip и таблицы ответов нет; учебная версия сохранена.

Accepted точного исходника Python 3.12 x64 №11327543: 0.062 с / 648 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/66, память 47/66. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11324337 (Python 3.12 x64): 0.078 с / 316 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1404_implementation_optimized.py`: 0.062 s / 648 KB; сохранённая учебная база `1404_implementation.py`: 0.078 s / 352 KB.

Оптимизированные решения (C++, Java) расшифровывают буквы по одной по
мере чтения через `getchar` и `System.in.read` вместо `iostream` и
`Scanner`, не сохраняя слово строкой: C++ сразу печатает каждую букву
через `putchar`, Java собирает их в массив из 101 байта и выводит его
одним вызовом. Разность по модулю 26 берётся как
`(code − previous + 26) % 26`, она никогда не отрицательна. C++ занимает
84 КБ вместо 360 КБ, Java — 328 КБ вместо 1612 КБ, в обоих случаях при
том же времени.
