# 1452. Pascal против C++

[Timus 1452](https://acm.timus.ru/problem.aspx?space=1&num=1452) · сложность 607 · hashing

Авторы оригинальной задачи — Илья Гребнов, Дмитрий Ковалёв и Никита Рыбак; Timus Top Coders: Second Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Последовательность состоит из N элементов (2 ≤ N ≤ 2000) — целых чисел
от 0 до 10⁹. Нужно выбрать как можно больше элементов с различными
значениями, образующих последовательные члены возрастающей
арифметической прогрессии; их порядок в последовательности не важен.
Вывести их количество и номера в любом порядке.

Ограничение времени: 0.25 секунды. Ограничение памяти: 16 МБ.

## Входные данные

N, затем N элементов.

## Выходные данные

Количество, затем номера элементов. Принимается любая самая длинная
прогрессия.

## Примеры

### Пример 1

Ввод:

```
6
7 3 2 3 5 9
```

Вывод:

```
4
4 5 1 6
```

## Решение

Важно только множество значений, поэтому храним каждое значение один
раз в хеш-таблице вместе с номером одного элемента, у которого оно
есть, и сортируем различные значения. Любая прогрессия хотя бы из двух
членов задаётся двумя первыми членами x < y с шагом d = y − x. Проходим
её только от настоящего начала, то есть когда x − d отсутствует: дальше
идём по y + d, y + 2d, ..., пока они есть в таблице.

Каждая пара соседних членов максимальной прогрессии попадает ровно в
один проход, а каждая пара (x, y) стоит одного поиска для проверки
начала, так что весь поиск делает O(m²) обращений к таблице для m
различных значений и обходится без таблицы пар: память остаётся O(N),
укладываясь в ограничение в 16 МБ. При единственном различном значении
ответ — один элемент. `O(N + m²)` в среднем.

Подводные камни:

- повторяющиеся значения считаются один раз (тесты 02, 04, 07, gen4);
- прогрессия через все значения требует прохода полной длины
  (gen3);
- таблица всех пар, как в обычной динамике за O(N²), требует больше
  памяти, чем разрешено, при некоторых способах хранения.

## Особенности языков

- Python работает на CPython и отсекает пары. Сначала отбрасываются
  некоторые крайние значения, не являющиеся концами прогрессий из трёх
  членов, а пара x < y проходится только тогда, когда прогрессия от x с
  шагом y − x ещё может обогнать лучшую найденную: её член на такой
  длине должен быть не больше наибольшего значения и найтись в таблице.
  Прежняя версия, проходившая все пары, превышала лимит 0,25 с на тесте
  9 жюри под CPython и на тесте 28 под PyPy.

## Оптимизированные решения

`1452_hashing_optimized.cpp`. Сохраняется точная таблица с открытой адресацией для различных значений и их первых позиций во вводе. Битовый фильтр 8 КБ отмечает бит отпечатка при вставке. Нулевой бит доказывает отсутствие и позволяет пропустить поиск; установленный бит может быть коллизией, поэтому каждое возможное совпадение по-прежнему проверяется по ПОЛНОМУ целочисленному ключу. Отсечение по конечному члену и предшественнику и восстановление прогрессии не меняются. Фиксированный предварительный фильтр сохраняет точный поиск прогрессий.

Accepted точного исходника №11326982: 0.015 s / 168 KB. Сохранённая выборка G++ 13.2 от 2026-11-20: место по времени 1/51, по памяти 1/51. Учебные исходники сохранены.

Оптимизированная версия C++ хранит каждое различное число и индекс его первого появления в хеш-таблице фиксированного размера с открытой адресацией. Разность проверяется, если нужный для нового рекорда член может существовать и у прогрессии нет предыдущего члена во входе. Ответ восстанавливается по первому члену и разности. Метрики взяты из посылки 11326982.

Rust хранит значения и их исходные индексы в отдельных массивах, используя 16-битные числа для индексов. Посылка 11318214 заняла 0,031 с и 292 КБ. Простая версия заняла 0,093 с и 620 КБ.

Java использует хеш-таблицу фиксированного размера с открытой адресацией и пропускает разности, которые не улучшают лучшую прогрессию. Посылка 11318310 заняла 0,187 с и использовала 492 КБ. Простая версия заняла 0,187 с и использовала 924 КБ.

Go использует хеш-таблицу фиксированного размера с открытой адресацией и пропускает разности, которые не улучшают лучшую прогрессию. Посылка 11321984 заняла 0,062 с и использовала 864 КБ. Простая версия заняла 0,125 с и использовала 1376 КБ.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11322326 · Go 1.14 x64 №11322327 · Java 1.8 №11322328 · Python 3.12 x64 №11322330 · Rust 1.75 x64 №11322331.

Оптимизированная версия Python использует битовые маски для значений в плотном диапазоне. На разреженных данных она проверяет наличие необходимого конца прогрессии в хеш-таблице, прежде чем продлить её. Посылка 11322818 заняла 0,109 с и 1884 КБ против 0,140 с и 1608 КБ у простой версии. В публичной таблице Python/PyPy она первая по обеим метрикам.
