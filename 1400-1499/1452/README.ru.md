## Задача

Последовательность состоит из N элементов (2 ≤ N ≤ 2000) — целых чисел
от 0 до 10⁹. Нужно выбрать как можно больше элементов с различными
значениями, образующих последовательные члены возрастающей
арифметической прогрессии; их порядок в последовательности не важен.
Вывести их количество и номера в любом порядке.

Ограничение времени: 0.25 секунды. Ограничение памяти: 16 МБ.

## Входные данные

N, затем N элементов.

## Выходные данные

Количество, затем номера элементов. Принимается любая самая длинная
прогрессия.

## Примеры

### Пример 1

Ввод:

```
6
7 3 2 3 5 9
```

Вывод:

```
4
4 5 1 6
```

## Решение

Важно только множество значений, поэтому храним каждое значение один
раз в хеш-таблице вместе с номером одного элемента, у которого оно
есть, и сортируем различные значения. Любая прогрессия хотя бы из двух
членов задаётся двумя первыми членами x < y с шагом d = y − x. Проходим
её только от настоящего начала, то есть когда x − d отсутствует: дальше
идём по y + d, y + 2d, ..., пока они есть в таблице.

Каждая пара соседних членов максимальной прогрессии попадает ровно в
один проход, а каждая пара (x, y) стоит одного поиска для проверки
начала, так что весь поиск делает O(m²) обращений к таблице для m
различных значений и обходится без таблицы пар: память остаётся O(m),
чего и требует ограничение в 16 МБ. При единственном различном значении
ответ — один элемент. `O(m²)` в среднем.

Подводные камни:

- повторяющиеся значения считаются один раз (тесты 02, 04, 07, gen4);
- прогрессия через все значения — самый медленный случай для проходов
  (gen3);
- таблица всех пар, как в обычной динамике за O(N²), требует больше
  памяти, чем разрешено, в большинстве языков.

## Особенности языков

- Python запускается под PyPy и всё равно превышает лимит 0,25 с на
  тесте 28 жюри (под CPython уже на тесте 9); решение оставлено с
  пометкой TLE: все наши тесты оно проходит, но не претендует на то, что
  успеет на каждом тесте жюри.
