# 1452. Pascal 对 C++

[Timus 1452](https://acm.timus.ru/problem.aspx?space=1&num=1452) · 难度 607 · hashing

原题作者 Ilya Grebnov、Dmitry Kovalioff 与 Nikita Rybak，出自 Timus Top Coders: Second Challenge。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个序列有 N 个元素（2 ≤ N ≤ 2000），都是 0 到 10⁹ 的整数。选出尽可能多的值互不
相同的元素，使它们构成某个递增等差数列的连续项；它们在序列中的顺序无关紧要。输
出个数，以及按任意顺序排列的所选元素编号。

时间限制：0.25 秒。内存限制：16 MB。

## 输入

N，然后是 N 个元素。

## 输出

个数，然后是元素编号。任何一个最长的数列都被接受。

## 样例

### 样例 1

输入:

```
6
7 3 2 3 5 9
```

输出:

```
4
4 5 1 6
```

## 解法

只有值的集合重要，所以把每个值在哈希表中存一次，并记下持有它的某个元素的编号，
再对不同的值排序。任何至少两项的数列都由前两项 x < y 和公差 d = y − x 确定。只
从数列真正的起点出发，即 x − d 不存在时：然后沿着 y + d、y + 2d、……一直走，直
到不在表中为止。

极大数列中每一对相邻项恰好落在一次行走中，而每对 (x, y) 只需一次查表来检查起
点，所以对 m 个不同的值，整个搜索共 O(m²) 次查表，而且不需要成对的表：内存保持
O(N)，符合 16 MB 限制。只有一个不同的值时答案是一个元素。期望时间
`O(N + m²)`。

注意事项：

- 重复的值只算一次（测试 02、04、07、gen4）；
- 贯穿所有值的数列需要一次完整长度的行走（gen3）；
- 像通常 O(N²) 动态规划那样存所有对的表，某些存储方式会超出内存限制。

## 各语言说明

- Python 在 CPython 上运行，并对数对剪枝：先删去部分不是任何三项等差数列端点的极端值；只有当从 x 出发、公差为 y − x 的数列仍可能超过目前最优时才遍历数对 x < y，即它在该长度处的那一项必须不超过最大值并且在表中存在。遍历所有数对的早期版本在 CPython 下于评测第 9 个测试、在 PyPy 下于第 28 个测试超过 0.25 秒的限制。

## 优化解法

`1452_hashing_optimized.cpp`. 保留不同值及其首次输入位置的精确开放寻址表。8 KiB位过滤器在插入时记录指纹位。零位证明不存在，可跳过表查询；置位可能碰撞，因此所有可能命中仍按完整整数键精确验证。端点/前驱剪枝与等差数列重建不变。固定预过滤器保留原本精确的等差数列搜索。

精确源代码 Accepted #11326982：0.015 s / 168 KB。2026-11-20 保存的 G++ 13.2 样本：时间排名 1/51，内存排名 1/51。教学源代码保留。

优化后的 C++ 版本用固定大小的开放寻址哈希表保存每个不同的数及其首次出现的位置。只有当刷新最优答案所需的项可能存在、且输入中不存在该数列的前一项时，才检查这个公差。根据首项和公差还原答案。评测数据来自提交 11326982。

Rust 将数值和原始下标分别存在两个数组中，其中下标使用 16 位整数。提交 11318214 耗时 0.031 秒，使用 292 KB；简单版本耗时 0.093 秒，使用 620 KB。

Java 使用固定大小的开放寻址哈希表，并跳过不能延长最优等差数列的公差。提交 11318310 耗时 0.187 秒，使用 492 KB；简单版本耗时 0.187 秒，使用 924 KB。

Go 使用固定大小的开放寻址哈希表，并跳过不能延长最优等差数列的公差。提交 11321984 耗时 0.062 秒，使用 864 KB；简单版本耗时 0.125 秒，使用 1376 KB。
