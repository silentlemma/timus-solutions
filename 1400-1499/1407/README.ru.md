# 1407. Раз-два, раз-два

[Timus 1407](https://acm.timus.ru/problem.aspx?space=1&num=1407) · сложность 388 · constructive

Автор оригинальной задачи — Сергей Пупырев; XII командный чемпионат школьников Свердловской области по программированию, 15 октября 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для 1 ≤ N ≤ 100 нужно вывести число не длиннее 10 000 цифр, состоящее из
цифр 1 и 2 и делящееся на 2ᴺ, или «No solution», если такого нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

Такое число; подходит любое.

## Примеры

### Пример 1

Ввод:

```
2
```

Вывод:

```
12
```

## Решение

Такое число всегда есть, и ровно из N цифр; строим его справа. Пусть aₖ
из k цифр 1 и 2 делится на 2ᵏ; припишем спереди цифру d:
d·10ᵏ + aₖ = 2ᵏ·(d·5ᵏ + aₖ / 2ᵏ). Поскольку 5ᵏ нечётно, ровно одна из
цифр 1 и 2 делает скобку чётной, и тогда aₖ₊₁ делится на 2ᵏ⁺¹. Начинаем
с пустого числа и повторяем N раз. `O(N²)` в Go/Java, `O(N³)` в Python.

Выбор зависит только от младших N + 1 бит, поэтому C++ и Rust держат
число в 128 битах и позволяют суммам переполняться; Go и Java берут
длинные числа и смотрят на младший единичный бит.

Подводные камни:

- ответ никогда не равен «No solution»;
- 2¹⁰⁰ далеко за пределами 64 бит (тесты 07–09).

Проверены все N от 1 до 100: в числе N цифр 1 и 2, и 2ᴺ его делит.
Тесты проверяются точным сравнением, потому что N-значный ответ
единственный.

## Оптимизированные решения

Go и Rust строят ответ справа налево, храня частичное значение и следующую степень десяти по модулю 2¹²⁸. После k цифр младшие k битов равны нулю, поэтому бит k определяет следующую цифру — единицу или двойку. Важны только младшие N ≤ 100 битов. Go реализует 128-битные операции парой 64-битных слов, Rust использует u128 с арифметикой по модулю. Go читает показатель напрямую из малого переиспользуемого байтового буфера и выводит построенные цифры без преобразования в строки.

Принятая версия Go 1.14 x64 заняла 0.031 с при 0.015 с у базовой и использовала 784 KB при 1140 KB у базовой.

Принятые базовые реализации [1407_constructive.cpp](1407_constructive.cpp), [1407_constructive.java](1407_constructive.java), [1407_constructive.py](1407_constructive.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
