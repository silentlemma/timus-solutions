# 1407. Раз-два, раз-два

[Timus 1407](https://acm.timus.ru/problem.aspx?space=1&num=1407) · сложность 388 · constructive

Автор оригинальной задачи — Сергей Пупырев; XII командный чемпионат школьников Свердловской области по программированию, 15 октября 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для 1 ≤ N ≤ 100 нужно вывести число не длиннее 10 000 цифр, состоящее из
цифр 1 и 2 и делящееся на 2ᴺ, или «No solution», если такого нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

Такое число; подходит любое.

## Проверка

Чекер принимает любое число длиной от 1 до 10000 цифр, состоящее только из 1 и 2 и делящееся на `2^N`. Лишний вывод отклоняется.

## Примеры

### Пример 1

Ввод:

```
2
```

Вывод:

```
12
```

## Решение

Такое число всегда есть, и ровно из N цифр; строим его справа. Пусть aₖ
из k цифр 1 и 2 делится на 2ᵏ; припишем спереди цифру d:
d·10ᵏ + aₖ = 2ᵏ·(d·5ᵏ + aₖ / 2ᵏ). Поскольку 5ᵏ нечётно, ровно одна из
цифр 1 и 2 делает скобку чётной, и тогда aₖ₊₁ делится на 2ᵏ⁺¹. Начинаем
с пустого числа и повторяем N раз. `O(N²)` в Go/Java, `O(N³)` в Python.

Выбор зависит только от младших N + 1 бит, поэтому C++ и Rust держат
число в 128 битах и позволяют суммам переполняться; Go и Java берут
длинные числа и смотрят на младший единичный бит.

Подводные камни:

- ответ никогда не равен «No solution»;
- 2¹⁰⁰ далеко за пределами 64 бит (тесты 07–09).

Ранее для каждого N от 1 до 100 проверялось построение из N цифр с нужной делимостью. Текущие тесты используют семантический проверяющий из раздела «Проверка»: допустим любой ответ из 1..10000 единиц и двоек, кратный 2^N, в том числе более короткий 112 при N=4. Точное совпадение с единственным N-значным построением не требуется.

## Оптимизированные решения

`1407_constructive_optimized.java`. Java сохраняет построение справа налево: после k цифр бит k текущего значения выбирает цифру 2, если равен нулю, иначе 1. В отличие от учебной версии с BigInteger этот файл хранит значение и степень десяти парами long по модулю 2^128. При N<=100 все проверяемые биты сохранены; беззнаковый перенос и умножение на десять через 32-битные половины дают точную модульную арифметику на знаковых словах Java. Цифры сразу записываются в ответ на N+1 байт. В данной области время O(N), хранение ответа O(N), арифметическое состояние O(1); для неограниченного N фиксированной разрядности не обещаем. Учебные исходники сохранены.

Accepted точного исходника Java 1.8 №11327478: 0.093 с / 312 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 5/44, память 1/44. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Место по времени 5/44 проходит единый критерий только по времени; строка без звёздочки верна, отдельной цели первого места нет. Прежний документированный оптимизированный запуск №11324811: 0.125 с / 524 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1407_constructive_optimized.java`: 0.093 s / 312 KB; сохранённая учебная база `1407_constructive.java`: 0.109 s / 1668 KB.

`1407_constructive_optimized.py`. Цифры по-прежнему строятся от младшей к старшей. После k позиций значение кратно 2^k; бит k определяет выбор 1 или 2, поскольку 10^k/2^k нечётно. Исключены две пробные операции остатка. Ответ хранится в bytearray и один раз разворачивается. Целые растут до O(n) бит: работа O(n²) битовых операций, память O(n) бит и цифр; линейное время в фиксированных машинных словах не обещается. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1407_constructive.py`: время 0.078 s → 0.125 s; память 416 KB → 244 KB.

Go и Rust строят ответ справа налево, храня частичное значение и следующую степень десяти по модулю 2¹²⁸. После k цифр младшие k битов равны нулю, поэтому бит k определяет следующую цифру — единицу или двойку. Важны только младшие N ≤ 100 битов. Go реализует 128-битные операции парой 64-битных слов, Rust использует u128 с арифметикой по модулю. Go читает показатель напрямую из малого переиспользуемого байтового буфера и выводит построенные цифры без преобразования в строки.

Принятая версия Go 1.14 x64 заняла 0.031 с при 0.015 с у базовой и использовала 784 KB при 1140 KB у базовой.

Быстрый набор использует проходящие простые C++ и Python и оптимизированную Java. Простая Java сохранена для обучения и не объявляется проходящей: время 15/44 и память 19/44 не проходят. Предыдущий Accepted оптимизированной Java #11327478: 0.093 s / 312 КБ, время 5/44 проходит при сравнении только времени. Одинаковые копии не нужны. Простые учебные строки не являются отдельными целями оптимизации.

## Особенности языков

Действуют единые [критерии](../../RATING_CRITERIA.md): память не сравнивается только строго ниже 1024 КБ; чужие времена меньше 0.015 s исключаются, нижний предел применяется только к нашим. Обычные выборки используют топ-10 или топ-15%, ничьи делят место, порог процента округляется вверх. Исключений за первое место или улучшение на 30% нет. В кэше C++ проходит по времени 1/19. Простая Python проходит 4/27, оптимизированная PyPy с 22/27 не проходит и сохраняет звёздочку. У Go нет соперников на текущем компиляторе, резервное сравнение внутри языка использует два результата Go 1.3; обе версии проходят. Rust аналогично использует три старых соперника, простое/оптимизированное время 4/4 и 1/4 проходят. Исторические парные метрики остаются отдельными наблюдениями.

В `1407_constructive_optimized.java` добавлены только поясняющие комментарии: беззнаковое сравнение переноса через XOR, умножение по 32-битным половинам и выбор цифры по биту k по модулю 2^128. Исполняемый код прежний.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
