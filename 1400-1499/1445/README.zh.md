# 1445. 圣诞礼物

[Timus 1445](https://acm.timus.ru/problem.aspx?space=1&num=1445) · 难度 593 · math

原题作者 Stanislav Vasiliev，出自 2006 年 3 月 24–25 日第十届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

哈利的朋友分成 N 个圈子（1 ≤ N ≤ 500），每个圈子 1 到 500 人。哈利一次见一位朋
友，送出一份礼物并收回一份。送给朋友的礼物可以是事先准备的，也可以是从其他圈子
成员那里收到的，但不能来自同一个圈子。分别求出哈利自己安排见面顺序时，以及顺序
最坏时，最少需要准备多少份礼物。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

N，然后是各圈子的人数。

## 输出

最好情况和最坏情况下准备的礼物数。

## 样例

### 样例 1

输入:

```
4
3 7 3 2
```

输出:

```
1 7
```

## 解法

设最大圈子有 m 人，朋友总数为 S。每次交换都会换回一份礼物，所以哈利手里的礼物数
始终等于准备的份数。最大圈子的 m 个人需要来自圈外的礼物，而来自圈外的礼物总共
只有 S − m 份，所以至少要准备 2m − S 份，并且无论如何至少一份。这么多也足够：若
2m > S，先让最大圈子的 2m − S 人拿到准备好的礼物，之后在该圈子和其他人之间交替。
否则安排朋友的顺序，使相邻两人来自不同圈子，一份礼物就够。

最坏的顺序是最大圈子先来；它的礼物在圈内没用，所以需要 m 份。这也足够：哈利手
里有 m 份礼物，其中来自某个圈子的份数不超过该圈子已见过的人数，所以每个还在等待
的成员都能拿到圈外的礼物。`O(N)`。

注意事项：

- 只有一个圈子时两种情况都要全部事先准备（测试 02、03）；
- 最大圈子不超过其余人数加一时，一份礼物就够（测试 05、06、08）。

## 优化解法

Go 和 Java 只读取一次各组大小，只保留总和与最大值，并直接输出两个答案。

Go 只扫描一遍各组人数，并根据总人数和最大组人数直接求出两个界限。 Go 1.14 x64（提交 11322860）的运行时间从 0.031 秒变为 0.015 秒，内存从 1080 KB 变为 424 KB。

Java 提交 11317352 用时 0.125 秒、使用 376 KB，基础版用时 0.14 秒、使用 1960 KB。

Python 提交 11317966 用时 0.093 秒、使用 344 KB，基础版用时 0.078 秒、使用 480 KB。

Python 逐项转换人数并更新总数和最大值，省去单独的整数列表。
