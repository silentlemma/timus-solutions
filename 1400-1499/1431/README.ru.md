# 1431. Сертификаты

[Timus 1431](https://acm.timus.ru/problem.aspx?space=1&num=1431) · сложность 362 · greedy

Автор оригинальной задачи — Станислав Васильев; Седьмое открытое личное первенство УрГУ по спортивному программированию, 25 февраля 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть N типов дипломов (N ≤ 18), каждого от 1 до 30 штук. Все дипломы
одного типа висят в одном ряду. В ряду висит один тип или два типа,
строго чередующихся, и каждый ряд должен быть симметричен относительно
центра стены. Нужно найти наименьшее число рядов.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем количество дипломов каждого типа.

## Выходные данные

Наименьшее число рядов.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
6
8 15 13 8 14 8
```

Вывод:

```
5
```

## Решение

Ряд из одного типа годится всегда. Два строго чередующихся типа дают
ABAB…, и такой ряд читается одинаково в обе стороны, только если
начинается и кончается одним типом: A B A … B A, то есть количества
отличаются ровно на единицу. Ответ — N минус наибольшее число
непересекающихся пар типов, количества которых отличаются на единицу.

Пары соединяют соседние значения цепочки 1, 2, …, 30. Если идти вверх по
цепочке, ещё не спаренные типы с количеством c теперь могут
спариться только с количеством c + 1, поэтому спарить их сразу как можно
больше никогда не хуже. `O(N + 30)`.

Подводные камни:

- равные количества не могут делить ряд: чередующийся ряд чётной длины
  не симметричен (тест 06);
- в 1, 2, 3, 4 пары — 1–2 и 3–4, а не 2–3 (тест 07);
- у нескольких типов может быть одинаковое количество (тесты 08, 12).

## Оптимизированные решения

`1431_greedy_optimized.py`. Сохраняется жадное сопоставление остатков количества c с количеством c+1 по частотам. Числа читаются блоками 4096 байт, хранятся только 31 частота без всей строки и списка токенов. При V=30 время O(n+V), память O(V+B), где B — размер блока, а длина числового токена ограничена. Сопоставление и формула n-pairs прежние. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1431_greedy.py`: время 0.078 s → 0.156 s; память 420 KB → 256 KB.

Go и Rust хранят частоты количеств от одного до 30 в байтовых массивах. На каждом количестве составляется максимум пар с оставшимися типами предыдущего количества. Каждая пара уменьшает ответ на одну строку. Дальше передаётся только остаток без пары, поэтому не нужны отсортированный список или граф паросочетания. Обе версии используют фиксированные байтовые буферы для ввода и десятичного вывода. Go обращается напрямую к дескрипторам стандартного ввода и вывода, Rust использует библиотеку времени исполнения C.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 56 KB при 220 KB у базовой.

Принятые базовые реализации [1431_greedy.cpp](1431_greedy.cpp), [1431_greedy.java](1431_greedy.java), [1431_greedy.py](1431_greedy.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

`1431_greedy_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1431_greedy.java`: время 0.156 s → 0.109 s; память 1644 KB → 440 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1431_greedy_optimized.java`: место по времени 8/13, по памяти 2/13 в этой сопоставимой выборке.

`1431_greedy_optimized.py`: место по времени 32/36, по памяти 1/36 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
