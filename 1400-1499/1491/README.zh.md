# 1491. 闭区间加法后的各位置总量

[Timus 1491](https://acm.timus.ru/problem.aspx?space=1&num=1491) · 难度 203 · prefix_sums

原题作者 Alexander Toropov，出自 2006 年 10 月 14 日第十三届斯维尔德洛夫斯克州中学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `2 ≤ N ≤ 100000` 个初始总量为零的位置。操作 0 向闭区间 `a..b`
每处增加 `c` 枚金币，随后每个 `i = 1..N` 再有一个操作。
每次满足 `1 ≤ a ≤ b ≤ N`、`1 ≤ c ≤ 10000`；第 `i` 个操作不包含
自身位置（`a_i > i` 或 `b_i < i`），操作 0 无此限制。
求最终各总量；任何位置都不扣除赠送成本。时间限制 1 秒，内存限制 64 MB。

## 输入

`N`，随后初始三元组 `a b c`，再按顺序给出另外 `N` 个三元组。

## 输出

按位置顺序输出 `N` 个总量，以空格分隔。

## 评测方式

实际紧凑 Python 程序通过 812 个输入：800 个合法小实例使用直接
逐接收者加金币的独立参考，另有 12 个边界或极限实例按独立已知总量比较。
包括 `N = 2, 1023, 1024, 1025, 2048, 100000`、十亿总量和大负差分。
各赠送操作按题意不包含赠送者自身。合法最大总量为 `N × 10000`，
因为某位置不会收到自身赠送；上面较宽松的界也覆盖所有中间单元。
五份实际候选还分别在 Docker 中通过仓库 14 个输入，并取得各自的 Accepted。
812 次参考检查是 Python 执行，不是每种语言各执行 812 次。


输出:

```

```

```

```

## 解法

建立 `N + 2` 个零元素的差分数组。对全部 `N + 1` 次操作，
在 `a` 加 `c`，在 `b + 1` 减 `c`，再求位置 `1..N` 的前缀和。

对单次操作，前缀 `j` 在 `j ≥ a` 时贡献 `+c`，在 `j ≥ b + 1`
时再贡献 `−c`，恰在 `a ≤ j ≤ b` 内为 `c`，外部为零。
将各操作恒等式相加即得正确性。`N + 1` 单元允许区间结束于 `N`，
但不输出该单元；不能遗漏初始操作。不能赠送给自己的限制不改变加法计算。

输入输出数字长度有界时，时间、辅助空间均 `O(N)`。
易读原生语言基线用 64 位差分单元，Python 用普通整数列表。
五份原 Accepted 源码逐字节保留。

## 优化解法

所有操作金额总和 `S` 至多为
`(N + 1) × 10000 ≤ 1000010000 < 2^31`。一次操作对某个差分单元
最多改变自身金额，所以中间单元也都在 `[-S,S]`。运行前缀和是当前
有效正金额之和，位于 `[0,S]`。有符号 32 位足够保存单元和累加器，
包括很大的负端点差分。

用 32 位数组代替原生 64 位单元或 Python 对象列表，测试 ABI 下数组占
`4 × (N + 2)` 字节。C++、Java 用固定 4 KiB 输入输出缓冲和十字节
临时数字数组，足以表示上述上界。Go 将输入缓冲从 1 MiB 缩为 4 KiB，
保留缓冲输出。Rust 流式读取锁定输入、缓冲输出，不再保存全部输入及答案字符串。
Python 用 `array("i")`、逐行流式读入，每组输出至多 1024 个数字字符串。
整组结束后，若还有数字就输出空格，否则换行；不足一组的尾部也换行。
因此组间不会丢失分隔符。

时间、空间仍为 `O(N)`，这是同一差分算法的实现和内存优化，故后缀
`_optimized`。每份发布源码均有各自精确字节的 Accepted，且至少节省
30% 内存。内存更小不代表记录时间更低，下面同时列出两项。

相对同语言原基线的实测变化：

- C++: 0.187 s / 980 KB → 0.046 s / 516 KB; 内存减少 47.3%.
- Go: 0.031 s / 4540 KB → 0.031 s / 2972 KB; 内存减少 34.5%.
- Java: 0.109 s / 8872 KB → 0.125 s / 852 KB; 内存减少 90.4%.
- Python: 0.328 s / 35944 KB → 0.250 s / 1236 KB; 内存减少 96.6%.
- Rust: 0.046 s / 9428 KB → 0.062 s / 584 KB; 内存减少 93.8%.
