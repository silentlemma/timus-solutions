# 1491. Нереальная история

[Timus 1491](https://acm.timus.ru/problem.aspx?space=1&num=1491) · сложность 205 · prefix_sums

Автор оригинальной задачи — Александр Торопов; XIII командный чемпионат школьников Свердловской области по программированию, 14 октября 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N рыцарей (2 ≤ N ≤ 100000) пронумерованы от 1 до N. Король называет a,
b и c, и каждый рыцарь с номером от a до b получает c монет; затем каждый
рыцарь называет свою тройку a_i, b_i, c_i с тем же действием
(1 ≤ a ≤ b ≤ N, 1 ≤ c ≤ 10000). Нужно вывести, сколько монет получил
каждый рыцарь.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, тройка короля, затем N троек рыцарей.

## Выходные данные

N сумм через пробел.

## Примеры

### Пример 1

Ввод:

```
4
2 3 2
2 4 1
3 4 1
1 2 1
1 1 1
```

Вывод:

```
2 4 4 2
```

### Пример 2

Ввод:

```
7
1 7 1
2 3 4
3 5 3
1 2 1
5 7 4
2 4 10
3 4 2
1 6 3
```

Вывод:

```
5 19 23 19 11 8 5
```

## Решение

N + 1 прибавлений на отрезках длиной до 10⁵ по одному — это слишком
медленно. Разностный массив записывает подарок c рыцарям a..b как +c в
позиции a и −c в позиции b + 1; затем текущая сумма по массиву даёт
итог каждого рыцаря. `O(N)`.

Подводные камни:

- тройка короля — ещё один подарок, так что всего их N + 1 (тесты 01,
  02);
- итог может дойти до 100001 · 10000 ≈ 10⁹, близко к пределу 32 бит,
  поэтому суммы хранятся в 64 битах (gen2);
- условия о местах самих рыцарей ничего не меняют в вычислениях (все
  тесты).
