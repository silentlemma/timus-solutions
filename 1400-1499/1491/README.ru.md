# 1491. Итоги прибавлений на отрезках

[Timus 1491](https://acm.timus.ru/problem.aspx?space=1&num=1491) · сложность 203 · prefix_sums

Автор оригинальной задачи — Александр Торопов; XIII командный чемпионат школьников Свердловской области по программированию, 14 октября 2006 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `2 ≤ N ≤ 100000` позиций с нулевыми начальными суммами.
Операция 0 добавляет по `c` монет позициям `a..b` включительно, затем
идёт ещё по операции для каждого `i = 1..N`. Везде `1 ≤ a ≤ b ≤ N`,
`1 ≤ c ≤ 10000`. Операция `i` не включает собственную позицию
(`a_i > i` или `b_i < i`); операция 0 свободна от этого ограничения.
Найдите конечные суммы. Ни с одной позиции стоимость подарка не списывается.
Лимит времени — 1 секунда, памяти — 64 МБ.

## Входные данные

`N`, начальная тройка `a b c`, затем `N` остальных троек по порядку.

## Выходные данные

`N` итоговых сумм по порядку позиций, через пробел.

## Проверка

Реальный Python с компактным массивом прошёл 812 входов: 800 малых
корректных экземпляров с прямым прибавлением каждого подарка каждому
получателю и 12 граничных/максимальных с независимо известными суммами.
Есть `N = 2, 1023, 1024, 1025, 2048, 100000`, итог в миллиард монет
и большие отрицательные разности. Подарки исключают самих дарителей,
как требует условие. Максимальный допустимый итог — `N × 10000`,
поскольку собственный подарок позиция не получает; более свободная
граница выше также покрывает промежуточные ячейки. Все пять реальных
кандидатов дополнительно прошли по 14 входов репозитория в Docker
и получили собственные Accepted. 812 эталонных проверок запускались
на Python, а не по 812 раз на каждом языке.

## Решение

Создаём нулевой массив разностей из `N + 2` ячеек. Для каждой
из `N + 1` операций прибавляем `c` в `a` и вычитаем `c` в `b + 1`.
Префиксные суммы на позициях `1..N` дают ответ.

Вклад одной операции в префикс `j` равен `+c`, когда `j ≥ a`,
и дополнительно `−c`, когда `j ≥ b + 1`. Получается ровно `c` внутри
`a ≤ j ≤ b` и ноль снаружи. Суммирование этих равенств доказывает
алгоритм для всех операций. Ячейка `N + 1` позволяет закончить отрезок
в `N`, но сама не выводится. Начальную операцию нельзя забыть;
запрет подарка самому себе не меняет арифметику прибавлений.

Время и дополнительная память — `O(N)` при ограниченной длине чисел
ввода и вывода. В понятных нативных базах ячейки 64-битные, Python
использует обычные списки целых. Все пять исходных Accepted-файлов
сохранены побайтово.

## Оптимизированные решения

Сумма всех величин операций `S` не больше
`(N + 1) × 10000 ≤ 1000010000 < 2^31`. Одна операция изменяет конкретную
ячейку разностей не больше чем на свою величину, поэтому даже
промежуточные ячейки лежат в `[-S,S]`. Текущая префиксная сумма складывает
положительные активные операции и лежит в `[0,S]`. Знаковых 32 бит
хватает и ячейкам, и накопителю, включая большие отрицательные разности.

Используем 32-битные массивы вместо нативных 64-битных ячеек или списков
объектов Python. На проверенной ABI среды массив занимает `4 × (N + 2)`
байт. C++ и Java читают и пишут фиксированными буферами по 4 КиБ;
временные десятибайтовые массивы цифр вмещают указанную границу.
Go уменьшает входной буфер с 1 МиБ до 4 КиБ, сохраняя буферизованный
вывод. Rust читает заблокированный поток и пишет через буфер, не храня
весь вход и все строки ответа. Python использует `array("i")`, читает
указанные входные строки потоком и выводит группы до 1024 строк чисел.
После полной группы пишет пробел, если числа ещё будут, иначе перевод
строки; неполная последняя группа тоже заканчивается переводом строки.
Разделители на границах групп не теряются.

Время и память остаются `O(N)`. Это оптимизация реализации и памяти
того же массива разностей, поэтому суффикс — `_optimized`.
У каждого файла собственный Accepted точного исходника и не менее 30%
выигрыша памяти. Меньший расход памяти не гарантирует меньшее записанное
время; ниже приведены обе метрики.

Измеренные изменения относительно исходной базы того же языка:

- C++: 0.187 s / 980 KB → 0.046 s / 516 KB; уменьшение памяти 47.3%.
- Go: 0.031 s / 4540 KB → 0.031 s / 2972 KB; уменьшение памяти 34.5%.
- Java: 0.109 s / 8872 KB → 0.125 s / 852 KB; уменьшение памяти 90.4%.
- Python: 0.328 s / 35944 KB → 0.250 s / 1236 KB; уменьшение памяти 96.6%.
- Rust: 0.046 s / 9428 KB → 0.062 s / 584 KB; уменьшение памяти 93.8%.

## Особенности языков

По ранее принятому профилю сравнения для C++ нужны топ 15% или первые 10 мест одновременно по времени и памяти; для Go, Java, Python/PyPy и Rust — первое место по обеим метрикам. Равные результаты делят место, пустые выборки учитываются отдельно.

- Java: 1 / 1; 4 / 4; цель достигнута.
- Python: 10 / 1; 20 / 20; рейтинговая цель ещё открыта.
