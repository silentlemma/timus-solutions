# 2115. 至多交换一次使队列有序

[Timus 2115](https://acm.timus.ru/problem.aspx?space=1&num=2115) · 难度 228 · sorting

原题作者 Ivan Smirnov，出自 2019 年大学学术中学生信息学奥林匹克。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定 `1≤n≤100000` 个高度 `0≤a[i]≤10⁹`，判断它是否已不递减或不递增；
否则找两个不同位置交换，使任一顺序成立，或证明一次交换不够。允许相等高度。
时间限制 1 秒，内存 256 MB。

## 输入

首行 n，第二行按原顺序给出 n 个高度。

## 输出

若已经任一方向单调，输出 `Nothing to do here`。否则可行时输出 `Yes`，
下一行给两个不同的从 1 开始的位置，交换后满足任一顺序；任意合法交换均可。
若不存在，输出 `No hope`。

## 评测方式

检查必需判定，或执行所给不同的从 1 开始的位置交换，验证任一方向单调；
允许不同正确交换。五份选定程序各在目标环境通过 15 个仓库输入及 100 个额外输入。
重读全部 500 份额外输出和退出码，用独立排序目标检查器验证，不用逆序边界规则。
所选精确 Python 另在主机运行 10876 次：长度 1..8 的全部 9840 个
`{0,1,10⁹}` 数组、1000 随机、重复端点和长度 99999/100000 构造，含长单行、
多行词和 EOF。这些主机次数不计为原生运行。五份快速源码和三份格式化修订各有
对应精确字节的 Accepted。

## 样例

### 样例 1

输入：

```
3
150 160 170
```

输出：

```
Nothing to do here
```

### 样例 2

输入：

```
4
140 160 150 170
```

输出：

```
Yes
2 3
```

## 解法

基础版排序副本得到不递减目标，再反转得到不递增目标。若原数组等于任一目标，
无需操作。否则逐个目标找不同位置：一次交换只改两处，故必须恰有两个差异 i,j，且
`a[i]=target[j]`、`a[j]=target[i]`。这也充分，因为其余位置已相同。尝试两目标
即完备。时间 `O(n log n)`，数组 `O(n)`，另计保留的输入。

五份排序算法都保留。Go、Python 字节不变；C++、Java、Rust 只采用仓库格式器
的精确输出，各有新的独立 Accepted。格式化前字节保存在本地发布备份；表中指标
属于实际源码字节。

## 优化解法

`two_pointers` 不排序、不建目标副本。先考虑不递减：找到首个逆序
`a[p]>a[p+1]`，从 p 沿相等值向左扩展至 l；找到最后逆序 `a[q-1]>a[q]`，
从 q 沿相等值向右扩展至 r。交换 l,r 并完整检查。失败后恢复数组，再令
direction=−1、比较 `direction*a[i]` 来处理不递增。值在 `[-10⁹,10⁹]`，
不溢出有符号 32 位。原数组已单调时先输出无须操作的指定短语。

端点为何必要？若交换 i<j 可修好递增序列，原端点值为 H>L，未变的中间值都在
L、H 之间。首个逆序在从 i 开始的 H 连续段右端；该段不能延到 i 前，否则未变
的 H 会大于交换后的 L。因此首逆序向左扩展恰找回 i。末逆序在于 j 结束的 L
连续段左端；该段不能延到 j 后，否则换来的 H 会大于后继 L。因此向右扩展找回 j。
任何可行交换都必须是所试端点；完整检查证明充分，两方向都失败才无解。不能忽略
相等段，如 `1,2,2,1`。

只有常数次全扫描，时间 `O(n)`，数组外搜索状态 `O(1)`，序列用 `O(n)` 单元。
Go、Rust 还保留全部输入，Python split 可暂留整行词；必须计入这些空间，不能
称整个程序常数空间。C++ 用字节缓冲加一个 32 位向量，Java 一个 int 数组，
Python `array('i')` 代替装箱整数列表。不构建排序或反转目标。

相对当前同语言 Accepted 排序基础版：C++ 时间 0.109→0.015 s（少 86.2%），
内存 2532→520 KB（少 79.5%）。Go 时间 0.140→0.046 s（少 67.1%），
内存 5696→4052 KB 只少 28.9%，故按时间准入。Java 内存 3644→848 KB
少 76.7%。Rust 内存 3504→2140 KB 少 38.9%；0.062→0.046 s 仅一个
计时单位，不作加速证据。Python 内存 15740→8564 KB 少 45.6%，但时间
0.140→0.203 s 反而多 45.0%；按内存准入，保留未达排名目标的星号。

## 各语言说明

线性方法是不同算法，命名 `two_pointers`，与简单 `sorting` 并存。C++、
Python 选择更强的009批次 Accepted 修订，先前002同名候选只留在本地快照、
报告中，不建公开重复文件。

C++、Java、Go、Rust 达当前目标；Go、Rust 无符合条件的其他作者，只有形式
覆盖，不证明竞争优势。CPython 3.12 在样本中内存第一、时间第17，保留星号。
有新格式化 Accepted 的原生基础版，比较均用新指标，绝不把旧指标贴到新字节。
覆盖完整范围，含 n=1、全相等、零及 10⁹。
