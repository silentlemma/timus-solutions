# 2123. 每种快速增长的砝码各两个时凑出质量的方法数

[Timus 2123](https://acm.timus.ru/problem.aspx?space=1&num=2123) · 难度 1026 · dp

原题作者 Alexey Danilyuk，出自 2018 年夏季彼得罗扎沃茨克集训营 t.me/umnik_team 专场。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n 种砝码，质量为 a₁ … aₙ，每种至少是前一种的两倍重，每种各有两个。求恰好凑出质量 W 的方法数；若某种砝码使用的个数不同，则方法不同。时间限制 4 秒，内存限制 256 MB。

## 输入

n 和 W（1 ≤ n ≤ 60，0 ≤ W ≤ 4 · 10¹⁸），然后是 a₁ … aₙ，满足 1 ≤ a₁、2aᵢ ≤ aᵢ₊₁ 且 aₙ ≤ 10¹⁸。

## 输出

方法数。

## 样例

### 样例 1

输入：

```
5 100
2 5 10 21 49
```

输出：

```
3
```

## 解法

把第 i 种砝码的个数写成 1 + xᵢ，其中 xᵢ ∈ {−1, 0, 1}。设 S 为所有质量之和，一种方法就是满足 Σ xᵢ aᵢ = W − S 的一组 xᵢ。把所有符号取反，就把某个值的解变成其相反数的解，所以只需统计 r = |W − S| 的表示数（W > 2S 时没有）。

从最重的一种往下处理，维护可达的余数及其方法数。在使用第 i 种之前，余数 r 必须能由第 1 … i 种覆盖，所以 r ≤ Sᵢ，即 a₁ … aᵢ 之和。选择 xᵢ 把 r 变成 r 或 r − aᵢ，由同样的符号对称性可以把 r − aᵢ 换成 |r − aᵢ|；r + aᵢ 永远不够小，因为更轻的各种砝码之和小于 aᵢ。在这样的增长条件下，只有全部 xᵢ = 0 才得到 0，所以余数 0 就是一种方法，直接计入答案。

C++、Go、Java 和 Rust 的实现保持余数有序。不选时保持顺序，r > aᵢ 时的 r − aᵢ 也保持顺序，而 r ≤ aᵢ 时的 aᵢ − r 使顺序反转，所以下一层的列表是三路有序流的归并，相同余数相加。每种砝码至少把余数上界减半，至多把方法数翻倍，所以余数和它的计数可以一起放进一个 64 位字。余数个数可能像斐波那契数那样增长，但受 Sᵢ + 1 限制，能够满足限制。

样例中的三种方法是 2 · 5 + 2 · 10 + 21 + 49、2 + 2 · 49 和 2 · 2 + 5 + 2 · 21 + 49。

## 各语言说明

Python 解答先将质量和目标除以各质量的最大公约数；目标不能整除时直接返回 0。一般分支将原目标的剩余质量存成按质量分块的位集，方法数存成二进制位平面，每步减去 0、aᵢ 或 2aᵢ，并舍弃 [0, 2Sᵢ₋₁] 以外的余数。每块有 2048 或 8192 位。设 B 为占用块数的最大值，C 为计数位平面数的最大值，考虑每次位平面加法中的进位传播，可得保守时间上界 O(n B C²)，空间为 O(B C + n)。

若最轻的 p 种构成精确的倍增链 u, 2u, 4u, …，且 p ≥ 28、k = n − p ≤ 32，Python 则改为递归处理后缀，使用上文取绝对值后的余数。剩余前缀的方法数通过 Stern 双原子序列的超二进制表示数在 O(p) 时间内计算。相同递归状态没有记忆化，因此这一分支的时间为 O(n + p 2^k)，空间为 O(n)，不能用 O(n R) 限制时间。

陷阱：[测试 16](tests/16.in) 检查纯倍增链上的大计数，但即使不同余数很少，短后缀也可能产生大量重复计算。审计中的 60 种砝码反例为：先取 0 ≤ i < 28 的 2^i，再取 0 ≤ j < 32 的 (2^28 + 1)2^j，W = 768614339088919210。答案 62338921 正确，却产生 11405773 次递归调用，归并后的每层最多只有三个余数。O(n R) 适用于其余四个实现，不能作为 Python 快捷分支的上界。
