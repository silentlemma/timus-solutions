# 2186. Наименьший поворот, направляющий достаточно лучей в круг

[Timus 2186](https://acm.timus.ru/problem.aspx?space=1&num=2186) · сложность 1765 · geometry, sorting

Автор оригинальной задачи — Артём Кутузов; Уральская командная олимпиада по программированию 2024.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Из начала координат выходят n лучей в различных направлениях (xᵢ, yᵢ),
а круг радиуса r с центром (a, b) лежит в стороне от начала. Лучи вместе
поворачивают против часовой стрелки на угол α, затем делают k выстрелов,
каждый из луча, выбранного равновероятно и независимо; выстрел попадает,
если его луч задевает круг, граница тоже считается. Для каждой из q
вероятностей pᵢ найдите наименьший α из [0, 360), дающий попадание с
вероятностью не меньше pᵢ, или −1. Принимаются ответы с точностью 10⁻³.
Ограничения: 2 секунды и 256 МБ.

## Входные данные

n, k и q, 1 ≤ n ≤ 10⁵, 1 ≤ k ≤ 10, 1 ≤ q ≤ 10⁵, затем n направлений с
координатами до 10⁹, затем a, b и r, затем pᵢ не более чем с пятью
знаками после запятой.

## Выходные данные

Угол в градусах для каждого запроса или −1.

## Примеры

### Пример 1

Ввод:

```
6 2 5
5 -5
3 0
-3 -2
-3 -1
-3 0
-4 -1
4 2 2
0.3 0.5 0.75 0.8 0.9
```

Вывод:

```
0.0000000000
45.0000000000
165.9637565321
180.0000000000
-1
```

## Решение

Если круг задевают c лучей, вероятность попадания равна
1 − ((n − c) / n)ᵏ и растёт с c, так что каждый запрос спрашивает
наименьший поворот, при котором попадающих лучей не меньше некоторого c.

Из начала координат круг виден как дуга направлений от нижней
касательной до верхней шириной 2 · asin(r / √(a² + b²)). С ростом α лучи
входят в эту дугу через нижнюю касательную. Поэтому число попаданий
растёт только при α = 0 или в момент, когда какой-то луч доходит до
нижней касательной, и тогда попадают лучи, чьи направления лежат в
пределах ширины дуги после него. Лучи сортируются по углу, окно двух
указателей по удвоенному списку даёт это число для каждого луча, а
наименьший α для каждого числа, сделанный монотонным суффиксным
минимумом, отвечает на все числа.

Направления точно на касательной решают, попадает ли луч, поэтому
всякий раз, когда вещественные числа близки к равенству, проверка
повторяется в целых: край окна сравнивает угол между двумя лучами с
шириной дуги через скалярное и векторное произведения, а вход в дугу вблизи
α = 0 считается нулевым, если только луч не строго внутри дуги —
тогда угол входа чуть меньше полного оборота.

У вероятностей пять знаков после запятой, так что каждое число c
получает уровень ⌊10⁵ · (1 − ((n − c) / n)ᵏ)⌋, посчитанный в
вещественных числах и подтверждённый в целых рядом с точкой сетки, а
запрос p в C++, Go и Python становится двоичным поиском первого уровня
не меньше 10⁵ p; Java и Rust заранее вычисляют ответы для всей сетки.

В примере k = 2 и n = 6. Луч (3, 0) касается круга при α = 0, что уже
даёт 1 − (5/6)² ≥ 0.3, а для 0.9 нужны пять лучей из шести, которых
дуга одновременно не вмещает.

Сортировка и окно занимают O(n log n), а запросы O(q log n), либо O(q)
в Java и Rust после подготовки таблицы за O(n + 10⁵).
