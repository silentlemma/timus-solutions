# 2109. Общий предок отрезка подряд идущих вершин

[Timus 2109](https://acm.timus.ru/problem.aspx?space=1&num=2109) · сложность 533 · trees, dp

Автор оригинальной задачи — Владимир Лесков; Чемпионат УрФУ среди юниоров 2016.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано дерево из n вершин с корнем 1. Маршрут [L, R] идёт из L в L + 1,
затем в L + 2 и так далее до R, всегда по путям дерева. Для каждого из q
маршрутов выведите посещённую вершину, ближайшую к корню. Ограничения:
4 секунды и 300 МБ.

## Входные данные

n, 1 ≤ n ≤ 2 · 10⁵, n − 1 ребро, затем q, 0 ≤ q ≤ 10⁶, и маршруты
L ≤ R.

## Выходные данные

Ответ для каждого маршрута, по одному в строке.

## Примеры

### Пример 1

Ввод:

```
7
1 2
1 3
2 4
2 5
2 6
3 7
3
4 6
3 4
5 7
```

Вывод:

```
2
1
1
```

### Пример 2

Ввод:

```
7
1 3
3 5
5 6
7 5
1 4
2 4
3
4 5
5 6
6 7
```

Вывод:

```
1
5
5
```

## Решение

Маршрут проходит ровно минимальное поддерево, соединяющее L, L + 1, …, R,
а ближайшая к корню вершина этого поддерева — наименьший общий предок
всего отрезка. Этот предок — самый высокий из попарных предков
LCA(i, i + 1) при L ≤ i < R: каждый из них лежит в его поддереве, а путь
между двумя вершинами в разных дочерних ветвях обязан пройти через него.

Поэтому c(i) = LCA(i, i + 1) для всех i считается один раз, офлайн,
методом Тарьяна: при обходе в глубину законченная вершина сливается с
родителем, а при входе в вершину v представитель уже посещённого соседа
i ± 1 и есть их общий предок. Среди предков одной вершины самый высокий
имеет наименьший номер в прямом порядке обхода, так что хранится этот
номер для c(i), и каждый маршрут отвечается запросом минимума на отрезке
по разреженной таблице за O(1). Для L = R ответ — сама L.

Обход итеративный, ведь дерево может быть путём из 2 · 10⁵ вершин. Общее
время — O(n log n + q).

В первом примере маршрут 4 → 5 → 6 остаётся ниже вершины 2, а маршруты
3 → 4 и 5 → 6 → 7 проходят через корень.

Учебная версия C++ находит глубины и родителей обходом в ширину. Затем строит таблицу предков на расстояниях 1, 2, 4 и далее. Для LCA(i, i + 1) сначала поднимаем более глубокую вершину до уровня второй. Если вершины совпали, это LCA. Иначе поднимаем обе самыми длинными прыжками, после которых они ещё различны, и берём их родителя. Для LCA соседних пар строим дерево отрезков с минимумом по глубине. Запрос [L, R] берёт минимум по парам с началом от L до R − 1. При L = R ответ равен L. Время O((n + q) log(n + 1)), память O(n log(n + 1)).

## Оптимизированные решения

Go и CPython сохраняют итеративную подготовку LCA соседних номеров через Тарьяна/DSU и sparse table минимумов времени входа. Завершённое поддерево при выходе указывает на ближайшего активного предка, поэтому запрос уже посещённого соседнего номера находит LCA. Пусть a — наименьший общий предок городов [L, R]. При L < R он является LCA некоторой соседней пары. Если a входит в диапазон, подойдёт пара с ним. Иначе последовательность городов переходит из одного дочернего поддерева a в другое. Все LCA соседних пар лежат в поддереве a, поэтому минимальный номер входа принадлежит a. Новые версии хранят головы, рёбра, родителей, представителей, времена, порядок и RMQ в 32-битных массивах. Знаковый 32-битный стек хранит события входа и выхода. Нулевое время означает непосещённую вершину, для RMQ позиции переводятся к нулевой нумерации. Временные массивы графа и DFS больше не нужны перед построением RMQ. Числа читаются потоком, ответы выводятся порциями. При L = R сразу выводим L. При q = 0 пропускаем DFS и построение таблицы. Go вычисляет уровень таблицы через bits.Len. Python читает блоки по 65 536 байт, переносит незаконченный токен в следующий блок и выводит по 8192 ответа. Строки разреженной таблицы хранятся в array I. Индексы рёбер не больше 399 998, модуль события не больше 200 000. Время O(n log n + q), память O(n log n). Для C++, Java и Rust быстрыми служат базовые версии.

Принятая версия Python 3.12 x64 заняла 2.984 с при 2.875 с у базовой и использовала 19 348 KB при 222288 KB у базовой.

Принятые базовые реализации [2109_trees_dp.cpp](2109_trees_dp.cpp), [2109_trees_dp.java](2109_trees_dp.java), [2109_trees_dp.rs](2109_trees_dp.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
