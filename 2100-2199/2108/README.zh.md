# 2108. 按愿望规则闭包手办集合

[Timus 2108](https://acm.timus.ru/problem.aspx?space=1&num=2108) · 难度 461 · bitmask

原题作者 Kirill Borozdin，出自 2016 年乌拉尔联邦大学青少年锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n 个收藏手办。m 个愿望中的每一个是说：一旦拥有集合 A 中的所有手办，就还想要集合 B 中的所有手办。从已经拥有的手办出发，求满足所有愿望的最小集合，也就是不断满足愿望直到不再想要新东西时得到的集合。时间限制 0.9 秒，内存限制 64 MB。

## 输入

n 和 m（1 ≤ n ≤ 1000，0 ≤ m ≤ 4000），然后 m 行，每行是用 n 个 0 和 1 组成的字符串表示的集合 A 和 B，最后是同样格式的已有集合。

## 输出

同样格式的最终集合。

## 样例

### 样例 1

输入：

```
6 4
111000 101000
110000 111000
010000 100000
000010 000001
010100
```

输出：

```
111100
```

## 解法

满足所有愿望且包含已有手办的集合，必须包含任何一条愿望链能到达的手办，而恰好由这些手办组成的集合满足所有愿望。所以反复扫描愿望：A 包含在已有集合中的愿望加入 B。一轮扫描没有新增就结束，其他每轮至少新增一个手办，所以至多 n + 1 轮。

集合用 64 位字的位集表示："A 包含在已有集合中" 就是 A AND NOT owned = 0，加入 B 是一次 OR，都是 n / 64 次字操作。总工作量 O(n · m · n / 64)，约 6 · 10⁷ 次字操作。

样例中已有手办 2 和 4 使第三个愿望生效，加入 1；然后第二个愿望加入 3，结果为 111100。

## 各语言说明

Python 解答把问题转置，因为当愿望链按相反顺序给出时，逐轮扫描在 Python 中太慢。对每个手办，用一个大整数表示需要它的愿望集合（A 字符串矩阵的一列）。一棵建在手办上的线段树维护所有尚缺手办的这些集合的并，这恰好就是尚未生效的愿望集合。每一轮执行所有新生效的愿望，并把新获得手办对应的叶子清零。每个愿望至多执行一次，每个手办的叶子至多清零一次。

设 w 为 Python 大整数每个数位的位数，N = ceil(n / w)，M = ceil(m / w)，L = 1 + ceil(log2 n)。m > 0 时，时间复杂度为 O(nm + (nL + m)M + nN)：读取及转置需要 O(nm)，线段树更新和就绪检查需要 O(nLM)，枚举生效愿望需要 O(mM)，枚举新增手办需要 O(nN)。合并结果集合需要 O(mN)，已包含在 O(nm) 中。m = 0 时，时间为 O(n)。

易错点（测试 15，空结果）：即使愿望没有增加手办，也仍需处理。在 Python 中，枚举置位并非每位常数时间：`mask & -mask` 和 `mask ^= low` 都要扫描整数数位。当 n = 1、m = 4000 且所有愿望都是 A = B = 0 时，答案仍为 0，但枚举生效愿望需要 Θ(m² / w) 次数位操作。因此，反复扫描的 O(n^2 m / 64) 上界不适用于 Python 解答。
