# 2197. Кратчайший повторяющийся префикс строки при перезаписи блоков

[Timus 2197](https://acm.timus.ru/problem.aspx?space=1&num=2197) · сложность 1669 · hashing, fenwick

Автор оригинальной задачи — Константин Рычков; Квалификационный тур Уральского регионального чемпионата ICPC 2024.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Строка S длины N печатается несколькими копиями одного из её
префиксов, а печать префикса длины l один раз занимает l² секунд. Q раз
образец t_k из фиксированного набора перезаписывает S с позиции p.
Выведите наименьшее время печати для исходной строки и после каждой
перезаписи. Ограничения: 3 секунды и 256 МБ.

## Входные данные

N, M и Q, 1 ≤ N ≤ 2 · 10⁵, 0 ≤ M, Q ≤ 2 · 10⁵, затем S, затем M
образцов общей длиной до 10⁶, затем перезаписи p k.

## Выходные данные

Q + 1 значение времени.

## Примеры

### Пример 1

Ввод:

```
4 3 3
abab
be
ebb
ee
3 1
1 2
2 3
```

Вывод:

```
8
16
16
4
```

## Решение

Печать N / l копий префикса длины l занимает N · l секунд, так что
нужна наименьшая длина l, которая делит N и порождает S.

Длины, которые делят N и порождают S, замкнуты относительно gcd, так что
наименьшая из них делит все остальные. Начиная с l = N, решение пытается
делить l на каждый простой делитель N, пока более короткий префикс всё
ещё порождает S; что остаётся — наименьший период. Префикс длины c
проверяется сравнением хеша S с хешем префикса, повторённого N / c раз,
— геометрической суммой h(prefix) · (B^N − 1) / (B^c − 1), которая
сравнивается после умножения на знаменатель. Для двух модулей при каждом
запуске независимо выбираются случайные основания от 257 до модуль − 2.
Если хотя бы для одного основания B^N = 1 по соответствующему модулю,
выбор повторяется; поскольку c делит N, знаменатель B^c − 1 тоже ненулевой.
Равенство хешей — вероятностная проверка, а не точное сравнение строк.

Ловушка: фиксированные общедоступные основания позволяют специально
строить коллизии. В тестах 17 и 18 непостоянные строки простой длины 17
имеют те же хеши, что и постоянная строка, при прежних параметрах, даже
при равных суммах кодов символов. Ответ равен 289, а не 17. Одни и те же
случайные основания используются для проверки периодов, кеша ответов
и проверки неизменяющих перезаписей; вероятность коллизии остаётся ненулевой.

Трудная часть — хешировать строку, которая меняется длинными
перезаписями. Весь текст, который вообще может появиться, — S и все
образцы — складывается в одну строку-источник с префиксными хешами.
Текущая S — список фрагментов, каждый из которых указывает на кусок
источника и хранит свой хеш, уже сдвинутый на свою позицию в S, в дереве
Фенвика по позиции начала. Перезапись режет фрагменты на двух своих
концах, выбрасывает те, что внутри, и добавляет один фрагмент для
образца, так что каждая перезапись создаёт лишь постоянное число
фрагментов. Хеш префикса — префиксная сумма Фенвика по целым
фрагментам плюс хеш части последнего фрагмента, прочитанный из
источника. Ответы ещё и запоминаются по хешу всей строки.

В примере у «abab» период 2, так что время 4 · 2 = 8, а у «eeee» период
1, и время 4.

Пусть L — суммарная длина словаря. Каждый ответ требует O(log N)
проверок кандидатов с учётом повторного удаления одного простого
множителя; каждая проверка стоит O(log N). Перезапись стоит O(log N)
на созданный или удалённый фрагмент; всего создаётся O(N + Q) фрагментов.
С учётом ввода и предобработки ожидаемое общее время равно
O(L + (N + Q + 1) log² N), память — O(L + N + Q); log N считается не меньше 1.

## Особенности языков

- Python также пропускает периоды, у которых число копий не делит сумму
  кодов символов: повторение префикса повторяет и эту сумму. В таблице
  сохранены опубликованные измерения под PyPy; для версии со случайными
  основаниями они не повторялись. CPython 3.12 и PyPy 3.10 для локальной
  проверки были недоступны.
