# 2118. 把前缀码比特串切成无法解码的片段

[Timus 2118](https://acm.timus.ru/problem.aspx?space=1&num=2118) · 难度 1382 · greedy, strings

原题作者 Alexey Danilyuk，出自 2018 年夏季彼得罗扎沃茨克集训营 t.me/umnik_team 专场。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一条由 k 个字母组成的字母表上的消息用二进制前缀码编码，得到比特串 T。把 T 切成尽可能多的片段，使得任何片段都不能用同一套码解码，或者报告无法做到。时间限制 1 秒，内存限制 64 MB。

## 输入

k（1 ≤ k ≤ 52），由 A–Z a–z 中前 k 个字母组成、长度至多 10⁶ 的消息，然后是 k 个码字，每个长度不超过 k。

## 输出

最多的片段数，或者 −1。

## 样例

### 样例 1

输入：

```
3
CACB
011
1
001
```

输出：

```
2
```

### 样例 2

输入：

```
3
ACBABCAACABCAACC
0
10
110
```

输出：

```
-1
```

## 解法

用前缀码解码是确定的：每个位置至多有一个码字匹配。答案取决于长度为 1 的码字。

- 没有：单个比特永远无法解码，所以每个比特都是一个片段，答案是 T 的长度。
- 0 和 1 都是：任何串都能解码，答案为 −1。
- 恰好一个，记为 g，另一个比特记为 b。那么其他所有码字都以 b 开头。只由 g 组成的片段可以解码，所以每个片段都含有 b，片段数不超过 b 的个数。

在最后一种情况下，片段 g…g b 永远无法解码：g 逐个解码，而最后的 b 单独不是码字。设 p 为 T 中最后一个这样的位置：没有任何码字是从 p 开始的后缀的前缀。之后的每个后缀都以某个码字开头，由归纳法可以解码，所以最后一个片段不能从 p 之后开始；而从 p 开始的后缀本身无法解码。在 p 之前每个 b 之后都切一刀，剩下的作为最后一个片段，得到（p 之前 b 的个数）+ 1 个片段，这是最多的。如果不存在这样的 p，或者 T 中根本没有 b，答案为 −1。

T 可能有 5 · 10⁷ 个比特，所以不构造它。用反转码字的 Aho–Corasick 自动机从末尾扫描后缀：当某个码字是已读后缀的前缀时，状态为接受态。从某个状态读入一整个字母的转移只逐比特计算一次并缓存，所以扫描代价为 O(|s|) 加上每个状态 O(k²)，状态数不超过 k²。

第一个样例中 T = 0010110011，g = 1。后缀 0011 以码字 001 开头，但后缀 010110011 不以任何码字开头，所以 p 是第二个比特，它前面有一个 0，答案为 2。
