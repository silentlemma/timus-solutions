# 2104. Складывание двусторонней полоски до одного цвета

[Timus 2104](https://acm.timus.ru/problem.aspx?space=1&num=2104) · сложность 375 · games

Автор оригинальной задачи — Никита Сивухин; Чемпионат УрФУ среди юниоров 2016.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У полоски 1 × n клетки окрашены в цвета A и B с обеих сторон. Алиса и
Боб ходят по очереди, первой Алиса; ход складывает полоску пополам
(только при чётной длине) внутрь или наружу. Если после хода полоска с
обеих сторон одного цвета, то A означает победу Алисы, а B — Боба,
независимо от того, кто сложил. Если ходящий не может сложить и никто не
выиграл, это ничья. Кто победит при лучшей игре? Ограничения: 2 секунды
и 64 МБ.

## Входные данные

n ≤ 5·10⁵, затем две стороны строками из A и B.

## Выходные данные

`Alice`, `Bob` или `Draw`.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
4
BBAA
BABB
```

Вывод:

```
Bob
```

### Пример 2

Ввод:

```
3
AAA
BBB
```

Вывод:

```
Draw
```

### Пример 3

Ввод:

```
2
AA
BB
```

Вывод:

```
Alice
```

## Решение

Сгиб кладёт правую половину поверх левой или под неё. В одном случае
снаружи оказываются левая половина верхней стороны и перевёрнутая правая
половина верхней стороны, в другом — перевёрнутая правая половина нижней
стороны и левая половина нижней стороны. Грани, оказавшиеся внутри,
больше не видны. Значит, у каждой позиции не больше двух ходов, каждый
делит длину пополам, и в игре не больше log₂ n ≈ 19 уровней.

Хватает обычного минимакса по этому дереву: после каждого сгиба
проверяем, одного ли цвета новая полоска; иначе рекурсивно ходит другой
игрок, а нечётная длина — ничья. Алиса берёт лучший для себя результат,
Боб — лучший для себя, и перебор останавливается, как только ход
выигрывает. На уровне k не больше 2ᵏ полосок длины n / 2ᵏ, так что работа
O(n log n).

В первом примере оба сгиба Алисы оставляют полоски, которые Боб
складывает в B/B, поэтому выигрывает Боб.

## Оптимизированные решения

`2104_games_optimized.java`. Сохраняются прежний минимакс складок и исходы Alice/Draw/Bob, но видимая сторона задаётся номером исходной стороны, началом, направлением±1 и длиной. Два массива префиксных количеств позволяют за O(1) проверить, полностью ли новые стороны цвета A или B, без подстрок, разворотов и повторных проходов. Каждая ветка уменьшает длину вдвое: худшее число узлов O(n), глубина стека O(log n), построение префиксов O(n). Общая память O(n). Нечётная текущая длина по-прежнему даёт ничью до новой складки; один цвет побеждает только после складки, семантика игры и ранние отсечения минимакса сохранены.

По сравнению с `2104_games.java`: время 0.125 s → 0.125 s; память 14 904 KB → 5 032 KB.

Версии C++, Go и Rust представляют сторону срезом исходной полоски и признаком обратного порядка. При сгибе берём два подсреза и меняем ориентацию одного из них. Две видимые половины вместе содержат ровно клетки выбранной стороны, поэтому одноцветность проверяется одним проходом по этой стороне. Минимакс занимает O(n log n) времени и O(log n) памяти стека сверх входных данных.

Принятая версия Rust 1.75 x64 заняла 0.046 с при 0.015 с у базовой и использовала 1 152 KB при 2132 KB у базовой.

Принятые базовые реализации [2104_games.java](2104_games.java), [2104_games.py](2104_games.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`2104_games_optimized.java`: место по времени 5/27, по памяти 1/27 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
