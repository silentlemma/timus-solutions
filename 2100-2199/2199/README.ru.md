# 2199. Два дня на отрезке с суммой изменений, ближайшей к нулю

[Timus 2199](https://acm.timus.ru/problem.aspx?space=1&num=2199) · сложность 1123 · sqrt_decomposition, sorting

Автор оригинальной задачи — Вадим Баринов; Квалификационный тур Уральского регионального чемпионата ICPC 2024.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Массив d из N целых получает Q запросов [l, r]: назовите две различные
позиции i, j на отрезке с наименьшим |dᵢ + dⱼ|, любые, если лучших
несколько. Ограничения: 3 секунды и 256 МБ.

## Входные данные

N и Q, 2 ≤ N ≤ 30 000, 1 ≤ Q ≤ 30 000, затем d с |dᵢ| ≤ 10⁹, затем запросы с 1 ≤ l < r ≤ N.

## Выходные данные

Две позиции для каждого запроса.

## Примеры

### Пример 1

Ввод:

```
6 4
17 11 -1 -4 20 -24
1 2
3 4
2 3
1 6
```

Вывод:

```
1 2
3 4
2 3
5 6
```

## Решение

Упорядочим элементы по модулю. Хотя бы одна оптимальная пара состоит
из соседей в этом порядке. Рассмотрим a, c, b с |a| ≤ |c| ≤ |b|.
Если a и b одного знака, (a, c) не хуже (a, b). Иначе, если знак c
совпадает со знаком b, не хуже пара (a, c); если со знаком a — пара
(c, b). Нулю можно приписать любой знак. Повторяя замену, получим
оптимальную пару соседей, поэтому при вставке достаточно проверить
предшественника и последователя.

Запросы обрабатываются офлайн, группами по блоку левого конца. Внутри
блока из B дней запросы сортируются по правому концу. Основная часть
правее блока только растёт. C++, Java и Rust хранят занятые ранги по
модулю в упорядоченных множествах, Go — в дереве Фенвика со счётчиками
и поиском по порядковому номеру. Поиск и обновление стоят O(log N).
Для запроса, пересекающего границу блока, сравниваются лучшая пара
основной части, заранее вычисленная лучшая пара суффикса блока и
перекрёстные пары: для каждого элемента суффикса ищутся соседние ранги
в основной части. Суффикс в неё не вставляется. Запросы целиком внутри
блока используют временное множество, очищаемое после каждого запроса.

В компилируемых версиях применяются две оценки. Префиксная таблица
находит пару с глобально минимальной суммой по модулю, если такая пара
есть в запросе. Кроме того, элемент можно пропустить, если даже его
лучший партнёр во всём массиве не улучшает текущий ответ. Эти оценки
ускоряют работу на практике, но не меняют оценку худшего случая.

Python использует то же разбиение на блоки с другой предобработкой,
без этих двух отсечений. Вставка элементов в порядок по модулю
равносильна удалению из полного порядка в обратной последовательности.
Связный список позволяет заранее записать соседей в момент вставки
для растущей основной части и суффиксов блока. Запрос целиком внутри
блока просматривает порядок по модулю, отбирая дни по своим границам.
Для перекрёстных пар каждому значению x из края нужен элемент основной
части, ближайший к −x. Обратное удаление в числовом порядке даёт интервал
отражённых значений, для которых новый элемент становится строго ближе;
при равных расстояниях сохраняется прежний партнёр. Двоичные поиски
находят границы интервала среди отражённых значений края. Присваивания
применяются в порядке появления к дереву над группами по 16 элементов
края, с отдельными обновлениями на концах. Побеждает последняя временная
метка, и запрос читает партнёров своего суффикса.

В примере весь массив даёт |20 − 24| = 4 в днях 5 и 6.

При 1 ≤ B ≤ N и B примерно N / √Q компилируемые версии работают за
O(N log N + Q log Q + (N²/B + QB) log N), Python — за
O(N log N + Q log Q + (N²/B) log(B+1) + QB). Все пять используют
O(N + Q) дополнительной памяти. В таблице B обозначает длину блока.

Ловушки: Q может быть равно 1 (тесты 02–04); эти корректные тесты не
требуют замены. Соседство относится к порядку по модулю, а не к датам
(тест 06), причём соседней должна быть лишь одна оптимальная пара.
Операции множества и дерева Фенвика имеют логарифмическую стоимость,
а не постоянную стоимость битовых операций.
