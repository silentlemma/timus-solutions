# 2199. Два дня на отрезке с суммой изменений, ближайшей к нулю

[Timus 2199](https://acm.timus.ru/problem.aspx?space=1&num=2199) · сложность 1265 · sqrt_decomposition, sorting

Автор оригинальной задачи — Вадим Баринов; Квалификационный тур Уральского регионального чемпионата ICPC 2024.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Массив d из N целых получает Q запросов [l, r]: назовите две различные
позиции i, j на отрезке с наименьшим |dᵢ + dⱼ|, любые, если лучших
несколько. Ограничения: 3 секунды и 256 МБ.

## Входные данные

N и Q, 2 ≤ N, Q ≤ 30 000, затем d с |dᵢ| ≤ 10⁹, затем запросы.

## Выходные данные

Две позиции для каждого запроса.

## Примеры

### Пример 1

Ввод:

```
6 4
17 11 -1 -4 20 -24
1 2
3 4
2 3
1 6
```

Вывод:

```
1 2
3 4
2 3
5 6
```

## Решение

Упорядочим элементы по модулю. Лучшая пара любого множества — два
соседа в этом порядке: если для a и b есть элемент c с
|a| ≤ |c| ≤ |b| между ними, то замена b на c или a на c не увеличивает
|a + b|, ведь знак c совпадает со знаком a или b. Значит, множеству
нужны для каждого элемента лишь предшественник и последователь в этом
порядке.

Запросы обрабатываются офлайн, группами по блоку левого конца, в духе
алгоритма Мо без удалений. Внутри блока запросы отсортированы по правому
концу, и часть отрезка правее блока только растёт; её элементы хранятся
в битсете по рангам модуля, так что новый элемент находит двух соседей
битовыми операциями и обновляет лучшую пару. Немногие дни между левым
концом и границей блока добавляются поверх этого для каждого запроса и
затем убираются, а их собственные пары подготовлены один раз на блок.

Две дешёвые оценки отсекают большую часть работы. Наименьшее
|dᵢ + dⱼ| по всему массиву известно заранее, и запрос, содержащий
достигающую его пару, отвечается сразу по префиксной таблице. А элемент,
лучший партнёр которого во всём массиве не может побить текущий ответ,
вставлять вообще не нужно.

Версия на Python обходится без поиска по битсету. Добавлять элементы по
одному в порядок по модулю — то же, что удалять их из полного порядка в
обратном порядке, поэтому связный список по этому порядку, удаляемый с
конца, даёт каждому элементу его соседей в момент появления. Для
немногих дней левее блока запросу нужен для каждого такого дня x
появившийся элемент y, ближайший к −x. Появившись, y становится
ближайшим ровно для значений −x между серединами отрезков до его
соседей в порядке по значению, и эти интервалы тоже находятся удалением
с конца. Интервалы применяются в порядке появления к дереву над
группами по 16 таких дней, побеждает последний, и запрос читает
сохранённого партнёра каждого своего дня.

В примере весь массив даёт |20 − 24| = 4 в днях 5 и 6.

С блоками примерно по N / √Q дней это O((N + Q)√N) битовых шагов.
