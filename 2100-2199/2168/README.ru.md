# 2168. Покрытие строки непересекающимися кусками с бордером

[Timus 2168](https://acm.timus.ru/problem.aspx?space=1&num=2168) · сложность 2963 · dp, strings

Автор оригинальной задачи — Вадим Баринов; Уральская командная олимпиада по программированию 2022.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Ряд из N рун — строка из строчных латинских букв. Один ход поднимает
непрерывный отрезок рун, которые все ещё лежат на месте, если
какой-то собственный префикс отрезка совпадает с его суффиксом той же
длины (у отрезка есть бордер, как у abcdab или aa, но не у abc или a).
Найдите наибольшее число рун, которое можно поднять. Ограничения:
2 секунды и 256 МБ.

## Входные данные

N, 1 ≤ N ≤ 10⁵, затем строка.

## Выходные данные

Наибольшее число поднятых рун.

## Примеры

### Пример 1

Ввод:

```
6
abcdab
```

Вывод:

```
6
```

### Пример 2

Ввод:

```
7
abcdabd
```

Вывод:

```
6
```

### Пример 3

Ввод:

```
6
abacdc
```

Вывод:

```
6
```

## Решение

Поднятые отрезки — непересекающиеся отрезки исходной строки, так что
пусть f(i) — наименьшее число оставленных рун среди первых i, а ответ
равен N − f(N). Отрезок [l, e] имеет бордер длины L ровно тогда, когда
текст с позиции l встречается снова в некоторой p > l с
LCP(l, p) ≥ L и e = p + L − 1. Значит, начало l и более позднее
совпадение p позволяют каждому концу из p … p + LCP(l, p) − 1
унаследовать f(l), а иначе f(i + 1) = f(i) + 1.

Два факта делают это небольшим.

- **Остаётся не больше 26 рун.** Идём слева направо: руна, чья буква
  ещё встретится, начинает отрезок до последнего вхождения этой буквы,
  а руна, чья буква больше не встречается, пропускается. Каждая буква
  пропускается не больше раза, так что f принимает только значения
  0 … 26.
- **Для одной буквы важны только начала с убывающей стоимостью.**
  Возьмём начала l₁ < l₂ с одной буквой c и f(l₁) ≤ f(l₂) и отрезок
  [l₂, e] с бордером длины L, найденным в p. Если L = 1, то s[p] = c и
  [l₁, p] — отрезок с бордером c, который уже достигает e со стоимостью
  f(l₁). Если L ≥ 2, отрезок [l₁, l₂] даёт f(l₂ + 1) ≤ f(l₁), а у
  [l₂ + 1, e] есть бордер длины L − 1, найденный в p + 1. Повторяя
  рассуждение для более короткого бордера, приходим к L = 1, так что l₂
  никогда не нужно.

Поэтому для каждой буквы хранится стек начал со строго убывающей
стоимостью, не больше 27 штук. В позиции p решение просматривает стек
буквы s[p] от самого нового начала, получает LCP(l, p) из суффиксного
массива минимумом на отрезке массива LCP (разреженная таблица в Python,
дерево отрезков в остальных языках) и запоминает для каждой стоимости k самый
дальний конец, которого достигает отрезок стоимости k. Более старое
начало полезно, только если его LCP длиннее, ведь его стоимость выше.
Затем f(p + 1) — наименьшая стоимость, чей запомненный конец покрывает
p, или f(p) + 1.

В третьем примере отрезки aba и cdc поднимают все шесть рун.

Ловушка (тест 32): более дешёвое позднее начало не должно заменять более
раннее начало с той же буквой: у раннего может быть более длинный полезный бордер.

В C++, Go, Java и Rust сортировка подсчётом по парам рангов строит
суффиксный массив за O(N log N), а дерево отрезков строится за O(N).
Просмотр делает не больше 27 запросов LCP на позицию, каждый за O(log N),
поэтому добавляет O(27 N log N); итого O(N log N) времени и O(N) памяти.
Python использует сортировку сравнениями в O(log N) раундах удвоения,
что даёт оценку O(N log² N) времени для суффиксного массива. Разреженная
таблица строится за O(N log N) времени и памяти и отвечает на запрос LCP
за O(1), поэтому просмотр добавляет O(27 N). Общая оценка — O(N log² N)
времени и O(N log N) памяти.
