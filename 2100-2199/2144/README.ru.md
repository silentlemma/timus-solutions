# 2144. Порядок запечатанных коробок для одного отсортированного ряда

[Timus 2144](https://acm.timus.ru/problem.aspx?space=1&num=2144) · сложность 221 · sorting

Автор оригинальной задачи — Иван Смирнов; Уральская командная олимпиада по программированию 2019.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть n коробок, в каждой — фиксированный ряд размеров фигурок, который
нельзя ни переставить, ни развернуть. Определите, можно ли расставить
коробки в таком порядке, чтобы все размеры вместе шли по неубыванию.
Ограничения: 0.5 секунды и 256 МБ.

## Входные данные

n, 1 ≤ n ≤ 100, затем для каждой коробки kᵢ, 1 ≤ kᵢ ≤ 100, и её
размеры, 1 ≤ aᵢⱼ ≤ 10⁴.

## Выходные данные

YES или NO.

## Проверка

Вывод сравнивается полностью, включая пробелы и переводы строк.

## Примеры

### Пример 1

Ввод:

```
3
2 1 2
3 7 7 7
1 5
```

Вывод:

```
YES
```

### Пример 2

Ввод:

```
2
2 1 3
1 2
```

Вывод:

```
NO
```

## Решение

Каждая коробка должна быть неубывающей внутри. После этого важны только
её первый размер f и последний размер l, и в правильном порядке l
каждой коробки не больше f следующей.

В любом правильном порядке первые размеры не убывают, ведь f ≤ l ≤ f
следующей коробки. Среди коробок с одинаковым первым размером f у всех,
кроме последней, l ≤ f, то есть l = f. Поэтому сортировка коробок по
(f, l) даёт правильный порядок, если он вообще есть, и достаточно
проверить соседей в этом порядке. Работа — O(Σ kᵢ + n log n).

В первом примере коробки (1, 2), (5, 5) и (7, 7) подходят в этом
порядке; во втором (1, 3) и (2, 2) пересекаются.

## Оптимизированные решения

Содержимое каждой коробки читается потоково, внутреннее нарушение порядка обнаруживается сразу. Для допустимой коробки достаточно двух крайних значений. Ограниченные концы упаковываются в одно целое: обычная числовая сортировка даёт нужный лексикографический порядок интервалов. Концы восстанавливаются для той же проверки соседних интервалов, что и в простом доказательстве. Java использует примитивные ключи вместо объектов и компаратора, Python не хранит полный ввод и временные пары концов.

- `2144_sorting_optimized.java`: 0.109 s / 2064 KB; база `2144_sorting.java`: 0.187 s / 6916 KB; изменение относительно базы: время -41.7%, память -70.2%.
- `2144_sorting_optimized.py`: 0.078 s / 420 KB; база `2144_sorting.py`: 0.093 s / 1040 KB; изменение относительно базы: время -16.1%, память -59.6%.

`2144_sorting_optimized.rs`. Каждая коробка читается за один проход с проверкой соседних размеров и сохранением только первого и последнего. n пар концов сортируются на месте неустойчивой лексикографической сортировкой, затем проверяются соседние коробки. В отличие от базы, не создаётся отдельный вектор всех размеров коробки и не сохраняется декодированный ввод. Доказательство порядка прежнее. Время O(Σk+n log n), память O(n). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `2144_sorting.rs`: время 0.015 s → 0.015 s; память 320 KB → 76 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2144_sorting_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
