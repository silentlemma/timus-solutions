# 2119. Вес поддерева, натянутого на меняющееся множество вершин

[Timus 2119](https://acm.timus.ru/problem.aspx?space=1&num=2119) · сложность 780 · trees, fenwick

Автор оригинальной задачи — Алексей Данилюк; Петрозаводск лето 2018. t.me/umnik_team Contest.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано дерево со взвешенными рёбрами и изначально пустое множество вершин
A. Каждый запрос добавляет вершину в A или удаляет её оттуда. После
каждого запроса выведите суммарный вес наименьшего поддерева, содержащего
все вершины A (0, если A пусто). Ограничения: 5 секунд и 256 МБ.

## Входные данные

n, 1 ≤ n ≤ 3 · 10⁵, n − 1 ребро «u v w» с 0 ≤ w ≤ 10⁹, затем q,
1 ≤ q ≤ 3 · 10⁵, и запросы «+ v» или «− v». Вершину добавляют, только
когда её нет в A, и удаляют, только когда она там есть.

## Выходные данные

Вес после каждого запроса, по одному в строке.

## Примеры

### Пример 1

Ввод:

```
5
1 2 1
2 3 10
3 4 100
3 5 1000
8
+ 2
+ 5
+ 4
- 5
+ 1
- 4
- 2
- 1
```

Вывод:

```
0
1010
1110
110
111
1
0
0
```

## Решение

Упорядочим вершины A по номеру в прямом порядке обхода в глубину:
v₁, v₂, …, vₖ. Обход v₁ → v₂ → … → vₖ → v₁ по путям дерева проходит
каждое ребро натянутого поддерева ровно дважды, как замкнутый обход
вокруг поддерева, поэтому вес — половина
d(v₁, v₂) + … + d(vₖ, v₁). Когда v вставляется между циклическими
соседями a и b в этом порядке, сумма растёт на
d(a, v) + d(v, b) − d(a, b); удаление вычитает столько же.

Соседей даёт дерево Фенвика по позициям прямого обхода, отмечающее
элементы A: число отмеченных позиций до v даёт ранг a, а спуск по дереву
находит элемент с данным рангом, с переходом через оба конца. Расстояния
считаются через взвешенные глубины, d(u, v) = D(u) + D(v) − 2 D(LCA).
При u ≠ v и tin(u) < tin(v) LCA — та вершина, чей номер в прямом
порядке наименьший среди родителей вершин на позициях
tin(u) + 1 … tin(v). Разреженная таблица по этим номерам родителей
отвечает за O(1).

Обход итеративный, потому что дерево может быть путём. Веса достигают
3 · 10¹⁴, так что суммы нужны в 64-битных целых. Общее время —
O((n + q) log n).

В примере после «+ 2», «+ 5» и «+ 4» поддерево — это 2 – 3 – 4 и 3 – 5
весом 10 + 100 + 1000 = 1110.
