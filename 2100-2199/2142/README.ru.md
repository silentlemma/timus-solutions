# 2142. Оплата красной, синей и любой маны двойными землями

[Timus 2142](https://acm.timus.ru/problem.aspx?space=1&num=2142) · сложность 127 · greedy

Автор оригинальной задачи — Валентин Зуев; Уральская командная олимпиада по программированию 2019.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть A красных, B синих и C двойных земель; каждая даёт одну ману, а
двойная — красную или синюю по выбору. Заклинанию нужны X красной маны,
Y синей и ещё Z любого цвета. Определите, хватит ли земель. Ограничения:
1 секунда и 256 МБ.

## Входные данные

A, B, C, затем X, Y, Z, все от 0 до 10⁹.

## Выходные данные

«It is a kind of magic», если заклинание можно оплатить, иначе «There
are no miracles in life».

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
3 3 1
2 2 1
```

Вывод:

```
It is a kind of magic
```

### Пример 2

Ввод:

```
5 6 5
6 5 6
```

Вывод:

```
There are no miracles in life
```

## Решение

Красные земли должны в первую очередь платить за красную ману, а синие —
за синюю, ведь любая земля может оплатить часть любого цвета. Что они
не покрывают, max(0, X − A) + max(0, Y − B), должно прийти от двойных
земель. После этого каждая оставшаяся земля любого вида может оплатить Z
маны любого цвета, так что второе условие — A + B + C ≥ X + Y + Z. Оба
вместе необходимы и достаточны. Суммы доходят до 3 · 10⁹, больше
32-битных целых.

Ловушка (тест 02, второй пример): покрыть оба цвета недостаточно.
Для красной маны нужна 6 − 5 = 1 двойная земля, но всего 16 земель против
17 маны.

## Оптимизированные решения

`2142_greedy_optimized.go`. Сохраняются две необходимые и достаточные проверки маны: двойные земли покрывают max(0,X-A)+max(0,Y-B), а всего земель хватает на X+Y+Z. После оплаты цветных дефицитов любая оставшаяся земля даёт бесцветную ману. Обе фразы ответа точны, включая полностью нулевой случай. Суммы достигают3·10^9, поэтому в Go везде int64, в Python точные целые. Время и состояние O(1); байтовый ввод и прямой вывод заменяют базовые обёртки. Переносимые os.Stdin.Read/os.Stdout.Write и прямое преобразование целых используют фиксированные буферы ввода и вывода по 4096 байт. Частичная запись обрабатывается до повторного использования буфера. Исходный простой вариант с Accepted сохранён.

По сравнению с `2142_greedy.go`: время 0.031 s → 0.031 s; память 1088 KB → 860 KB.

После оплаты цветных дефицитов любая оставшаяся земля даёт бесцветную ману. Обе фразы ответа точны, включая полностью нулевой случай. Суммы достигают3·10^9, поэтому в Go везде int64, в Python точные целые. Время и состояние O(1); байтовый ввод и прямой вывод заменяют базовые обёртки. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `2142_greedy.py`: время 0.078 s → 0.125 s; память 416 KB → 208 KB.

Оптимизированное решение на Java читает шесть чисел побайтно из
`System.in` вместо того, чтобы создавать `Scanner`, чьи регулярные
выражения и данные локали — главная статья расходов программы с двумя
сравнениями; суммы по-прежнему считаются в `long`, ведь они достигают
3 · 10⁹: {2142_greedy_optimized.java}.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2142_greedy_optimized.go`: место по времени 5/12, по памяти 3/12 в этой сопоставимой выборке.

`2142_greedy_optimized.py`: место по времени 66/79, по памяти 1/79 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
