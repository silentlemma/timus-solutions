# 2102. Ровно двадцать простых множителей

[Timus 2102](https://acm.timus.ru/problem.aspx?space=1&num=2102) · сложность 147 · number_theory

Автор оригинальной задачи — Владимир Лесков; Чемпионат УрФУ среди юниоров 2016.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Определите, равна ли сумма показателей в разложении n на простые
ровно 20, то есть является ли n произведением ровно 20 простых с учётом
кратности. Ограничения: 2 секунды и 64 МБ.

## Входные данные

n, 1 ≤ n ≤ 10¹⁸.

## Выходные данные

`Yes` или `No`.

## Примеры

### Пример 1

Ввод:

```
2
```

Вывод:

```
No
```

### Пример 2

Ввод:

```
1048576
```

Вывод:

```
Yes
```

### Пример 3

Ввод:

```
10000000000
```

Вывод:

```
Yes
```

## Решение

Делим n на каждое d от 2 до B = 2·10⁶, пока d² ≤ n, и считаем
отделённые простые множители. Если цикл остановился, потому что d²
превзошло остаток, то остаток — 1 или простое и добавляет 0 или 1. Иначе
остаток не меньше B² = 4·10¹², так что отделённая часть не больше
10¹⁸ / B², меньше 2¹⁸, то есть множителей пока меньше 18; у остатка нет
делителей меньше B и он не больше 10¹⁸ < B³, поэтому добавляет не больше
двух. Сумма не может достичь 20, и ответ No. Время работы — O(min(sqrt n, B)).

В третьем примере 10¹⁰ = 2¹⁰ · 5¹⁰ имеет 20 простых множителей.

## Оптимизированные решения

`2102_number_theory_optimized.java`. Сохраняется проверка ровно 20 простых множителей. Удаляются двойки и тройки, затем перебираются делители 6k-1/6k+1; enough проверяет минимальное произведение оставшихся множителей, выполняя деление до умножения во избежание переполнения. Когда не хватает не более двух множителей, квадрат может дать ровно два только при простом корне. Math.sqrt даёт лишь кандидата, который принимается после точного long-сравнения root*root==n; пропущенный квадрат безопасно обрабатывает прежний перебор. Уже удалено хотя бы 18 множителей: остаток не больше 10^18/2^18, проверка простоты корня требует делителей меньше 1400, а обычный перебор ограничен 1953125. Единственный long читается побайтно, ответ выводится постоянными байтами. Без таблицы ответов и вероятностной простоты. Фактический Java-код прошёл 315488 точных проверок множителей и 100000 сравнений границы произведения без переполнения. Учебный перебор сохранён.

Пока нужны более двух множителей, нижняя оценка умножается в беззнаковой 128-битной арифметике с остановкой сразу после превышения остатка. Перед умножением оценка не больше 10^18, делитель — порядка 10^9, поэтому промежуточное значение помещается в 128 бит. Для последних двух множителей действует прежняя граница по квадрату. ctz не получает ноль; ответ по-прежнему означает ровно двадцать простых множителей с кратностями.

### Измеренный выигрыш

Каждая сохранённая оптимизированная версия имеет Accepted. Она проходит по первым десяти местам или топ 15% одновременно по времени и памяти, по топ 30% по обеим метрикам с улучшением места базы хотя бы по одной из них либо по сокращению времени или памяти минимум на 30% относительно базы на том же языке. Отрицательное сокращение означает рост расхода. Звёздочка относится к отдельной рейтинговой цели языка.
