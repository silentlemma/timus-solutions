# 2124. Порядок подгруппы, порождённой отрезком, при умножении на отрезке

[Timus 2124](https://acm.timus.ru/problem.aspx?space=1&num=2124) · сложность 1303 · number_theory, segment_tree

Автор оригинальной задачи — Алексей Данилюк; Петрозаводск лето 2018. t.me/umnik_team Contest.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Всё происходит в мультипликативной группе по простому модулю p. К
массиву из n вычетов приходят q запросов: умножить каждый элемент
[l, r] на x или вывести порядок подгруппы, порождённой элементами
[l, r]. Ограничения: 4 секунды и 256 МБ.

## Входные данные

p, n и q, 2 ≤ p < 10⁹ простое, 1 ≤ n, q ≤ 10⁵, массив, 1 ≤ aᵢ < p, и
запросы «1 l r x» и «2 l r», где 1 ≤ l ≤ r ≤ n и 1 ≤ x < p.

## Выходные данные

Ответ на каждый запрос второго типа.

## Примеры

### Пример 1

Ввод:

```
17 3 7
10 16 2
2 2 3
2 1 2
2 2 2
1 1 2 3
2 1 1
2 3 3
2 1 3
```

Вывод:

```
8
16
2
4
8
16
```

## Решение

Группа циклическая порядка m = p − 1. Для образующей g элемент gᵉ
порождает подгруппу индекса gcd(e, m), а множество порождает подгруппу,
индекс которой — НОД индексов его элементов; порядок равен m, делённому
на этот индекс. Индекс одного элемента a равен m / ord(a), а ord(a)
находится по простым делителям m: начиная с m, делим на простое q, пока
a в степени текущего порядка, делённого на q, всё ещё равно 1.
Дискретный логарифм не нужен.

Умножение на отрезке меняет много элементов, поэтому хранятся отношения
bᵢ = aᵢ / aᵢ₋₁ (b₁ = a₁). Умножение [l, r] на x умножает b_l на x и
b_{r+1} на x⁻¹ — два точечных изменения. Элементы a_l, a_{l+1}, …, a_r
порождают ту же подгруппу, что a_l, b_{l+1}, …, b_r, ведь каждое из этих
множеств выражается через другое. Поэтому:

- дерево отрезков хранит НОД индексов отношений и даёт НОД по
  b_{l+1} … b_r;
- дерево Фенвика хранит множители граничных изменений; произведение на
  префиксе, умноженное на исходное a_l, даёт текущее a_l.

Запрос считает индекс a_l, берёт НОД с деревом и выводит m, делённое на
него. В C++, Go, Java и Rust каждое изменение или запрос использует
O(log n) операций с деревьями и O(log² p) модульных операций для порядков
и обратных. Факторизация перебором стоит O(sqrt p), а вычисление начальных
индексов отношений — O(n log² p). Обратные берутся по малой теореме Ферма.

Резервная ветка Python вычисляет индексы отношений лениво и кеширует в
каждой вершине проекцию НОД на проверенный делитель. Поэтому один запрос
может посетить O(n) вершин, и оценка на запрос для остальных версий здесь
не подходит. Между сбросами проверенный делитель растёт по делимости не
более O(log p) раз. Изменение сбрасывает O(log n) вершин, а вычисление
некешированной проекции стоит O(log² p). Это даёт консервативную суммарную
амортизированную оценку в таблице. S — стоимость
поиска первообразного корня и построения таблиц логарифмов в Python;
для резервной ветки S = 0.

Ловушка: тест 11 проверяет степень простого (p = 257), а тест 13 — восемь
различных простых делителей; оба случая важны при выборе ветки Python.
Это не гарантирует логарифмическое время ленивого запроса: при
p = 999999503, n = 100000 и всех элементах 1 первый запрос `2 1 100000`
верно выводит 1, но выполняет O(n) отложенной работы с деревом.

В примере p = 17 и m = 16. Элемент 16 = −1 имеет порядок 2, а 10 и 16
вместе порождают подгруппу порядка 16 — всю группу.

## Особенности языков

- Python использует дискретные логарифмы, если каждая примарная компонента
  помещается в таблицу или разбивается на два разряда с таблицами не более
  min(65536, n + q) элементов. Взаимно простые компоненты могут делить одну
  таблицу; логарифмы объединяются по китайской теореме об остатках.
  Умножение на отрезке становится сложением показателей с деревом отрезков
  для НОД и аддитивным деревом Фенвика. Иначе используется описанная выше
  ленивая резервная ветка с индексами отношений.
