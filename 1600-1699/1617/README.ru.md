# 1617. Ползуны

[Timus 1617](https://acm.timus.ru/problem.aspx?space=1&num=1617) · сложность 65 · implementation

Автор оригинальной задачи — Владимир Яковлев; XII чемпионат Урала по спортивному программированию, 29 марта 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В депо n колёсных пар (1 ≤ n ≤ 150), у каждой целый диаметр от 600 до
700 мм. Вагону нужны четыре колёсные пары одного диаметра. Сколько
вагонов можно оснастить?

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

n, затем n диаметров.

## Выходные данные

Число вагонов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
9
689
690
690
689
689
690
689
688
688
```

Вывод:

```
1
```

## Решение

Посчитаем пары каждого диаметра. Диаметр, у которого c пар, оснащает
⌊c / 4⌋ вагонов, а разные диаметры друг на друга не влияют, поэтому
ответ — сумма по всем диаметрам. `O(n)`.

Подводные камни:

- оставшиеся пары разных диаметров нельзя объединять (тест 01);
- восемь пар одного размера оснащают два вагона, а не один (тест 03).

## Оптимизированные решения

Оптимизированное решение на Java читает ввод блоками по 1 КБ и разбирает
его вручную вместо `Scanner`, а диаметры, от 600 до 700, считает в
обычном массиве из 101 счётчика со сдвигом на 600: 0.109 с вместо
0.140 с и 336 КБ вместо 1680 КБ.

`1617_implementation_optimized.py`. Counter заменён списком 101 частоты с индексом diameter-600, что обосновано диапазоном 600..700. Суммируется frequency//4, поскольку смешивать диаметры нельзя. Итератор байтовых токенов исключает декодированный текст и ключи хеш-таблицы, но сами токены ввода остаются: суммарная память O(N+101), а не потоковая O(1). Время O(N+101). Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1617_implementation.py`: время 0.093 s → 0.125 s; память 368 KB → 244 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1617_implementation_optimized.py`: место по времени 88/104, по памяти 1/104 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
