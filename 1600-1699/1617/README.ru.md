# 1617. Ползуны

[Timus 1617](https://acm.timus.ru/problem.aspx?space=1&num=1617) · сложность 65 · implementation

Автор оригинальной задачи — Владимир Яковлев; XII чемпионат Урала по спортивному программированию, 29 марта 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В депо n колёсных пар (1 ≤ n ≤ 150), у каждой целый диаметр от 600 до
700 мм. Вагону нужны четыре колёсные пары одного диаметра. Сколько
вагонов можно оснастить?

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

n, затем n диаметров.

## Выходные данные

Число вагонов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
9
689
690
690
689
689
690
689
688
688
```

Вывод:

```
1
```

## Решение

Посчитаем пары каждого диаметра. Диаметр, у которого c пар, оснащает
⌊c / 4⌋ вагонов, а разные диаметры друг на друга не влияют, поэтому
ответ — сумма по всем диаметрам. `O(n)`.

Подводные камни:

- оставшиеся пары разных диаметров нельзя объединять (тест 01);
- восемь пар одного размера оснащают два вагона, а не один (тест 03).

## Оптимизированные решения

`1617_implementation_optimized.py`. Сохраняются 101 частота диаметров 600..700 и сумма floor(frequency/4). Бинарный ввод читается напрямую, короткий числовой ответ целиком выводится os.write перед os._exit(0). split сохраняет токены ввода: память O(I+101), где I — байты ввода, это не потоковая константная память. O(N+101) арифметики, обрабатываются все заявленные пары колёс. Учебная Counter-версия сохранена.

Accepted точного исходника Python 3.12 x64 №11327789: 0.062 с / 660 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/104, память 90/104. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11325072: 0.125 с / 244 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1617_implementation_optimized.py`: 0.062 s / 660 KB; сохранённая учебная база `1617_implementation.py`: 0.093 s / 368 KB.

`1617_implementation_optimized.java`. Сохраняется группировка одинаковых диаметров 600..700 за один проход. Байт на диаметр хранит только остаток по модулю четыре: при достижении четырёх он сбрасывается и считается вагон. Между чтениями остаток не больше трёх, знакового byte достаточно; итоговый проход по частотам не нужен. O(N) времени и 101 байт состояния групп. Все числовые поля, нужные вычислению, потребляются до вывода. Один массив 256 байт сначала служит вводу, затем выводу; перед знаковым int резервируются двенадцать байт, разворачиваются только новые цифры. Убраны отдельные массивы ввода, вывода и цифр, нужные алгоритму данные не перезаписываются. Разбор и вывод линейны по потреблённым байтам, буфер фиксирован.

Accepted точного исходника Java 1.8 №11327764: 0.078 с / 368 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/221, память 6/221. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303764: 0.109 с / 336 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1617_implementation_optimized.java`: 0.078 s / 368 KB; сохранённая учебная база `1617_implementation.java`: 0.14 s / 1680 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
