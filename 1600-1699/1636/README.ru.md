# 1636. Штрафное время

[Timus 1636](https://acm.timus.ru/problem.aspx?space=1&num=1636) · сложность 61 · implementation

Автор оригинальной задачи — Алексей Самсонов; XIII открытый командный чемпионат УрГУ по программированию.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Команды QXX и ZZZ решили все десять задач; QXX победила со штрафным
временем T1 против T2 у ZZZ. Каждая штрафная попытка добавляет
20 минут. По числу штрафных попыток ZZZ на каждой задаче нужно решить,
победила бы ZZZ без них. При равном времени команды упорядочиваются по
названию, так что ZZZ всё равно была бы второй.

## Входные данные

В первой строке T1 и T2 (250 ≤ T1 ≤ T2 ≤ 2400), затем десять чисел
штрафных попыток ZZZ.

## Выходные данные

`Dirty debug :(`, если попытки стоили ZZZ первого места, иначе
`No chance.`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
290 420
0 0 0 2 1 0 2 0 1 0
```

Вывод:

```
No chance.
```

### Пример 2

Ввод:

```
300 719
0 0 0 0 0 0 21 0 0 0
```

Вывод:

```
Dirty debug :(
```

## Решение

Вычесть из T2 по 20 минут за каждую штрафную попытку. ZZZ победила бы
только со строго меньшим временем, чем T1, ведь при равенстве первой
по алфавиту идёт QXX. `O(1)`.

Подводные камни:

- равное чистое время — всё равно поражение (тест 03), на минуту
  меньше — победа (тест 04);
- ответы кончаются точкой и грустным смайликом, и то и другое входит в
  ожидаемый текст.

Ответы совпадают с независимой принятой реализацией на 100 случайных
тестах.

## Оптимизированные решения

Оптимизированное решение на Java разбирает числа побайтно из `System.in`
вместо `Scanner`: 368 КБ вместо 1600 КБ при том же времени.

`1636_implementation_optimized.py`. Сохраняется строгое сравнение T2-20*sum(rejections)<T1; равенство по-прежнему даёт No chance. Целые байтовые токены читаются через map, оставшиеся десять счётчиков непосредственно потребляются sum, без отдельного списка целых attempts и декодированного ввода. Работа O(P) при P=10 счётчиках; память токенов парсера остаётся. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1636_implementation.py`: время 0.078 s → 0.109 s; память 428 KB → 216 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1636_implementation_optimized.py`: место по времени 62/80, по памяти 1/80 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
