# 1663. 霍比特人，或去而复返 2

[Timus 1663](https://acm.timus.ru/problem.aspx?space=1&num=1663) · 难度 3048 · dp

原题作者 Alexander Ipatov，出自 2008 年 1 月彼得罗扎沃茨克冬季集训的 Ural SU Contest。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

旅程从城市 1 出发，恰好经过 N 个城市各一次后回到城市 1。从城市 B 进入城市 A 需付 P_A · ⌊1000 / P_B⌋，
其中 P 为人口。输出一条最便宜的路线，从城市 1 开始；任何一条最便宜的都可以。

## 输入

N（2 ≤ N ≤ 1000），然后是各城市人口 P₁ … P_N（1 ≤ Pᵢ ≤ 1000）。

## 输出

按路线顺序给出 N 个城市。

## 样例

### 样例 1

输入：

```
4
10 3 5 4
```

输出：

```
1 4 2 3
```

## 解法

记 q_B = ⌊1000 / P_B⌋，则从 B 到 A 的一步花费 q_B · P_A。按人口排序城市：沿这个顺序 P 只增不减，q 只减不增。
对这种乘积形式的花费，总有一条最便宜的路线是金字塔形的：它沿递增的城市序列从最小的城市爬到最大的城市，再经过
其余城市下降回来。

因此排序后每个城市要么在上升路径上，要么在下降路径上。处理完城市 0 到 m 后，其中一条路径止于城市 m，只有另一条
路径的端点 j 有关。计入各自的公共偏移后，up[j] 表示上升路径止于 m 时的最小花费，down[j] 表示下降路径止于 m 时的最小花费。把
城市 m + 1 接到已经止于 m 的路径上，j 不变，所有元素加上同一个值，所以每个数组只保存一个公共偏移；把它接到另一
条路径上，就得到 j = m 的唯一新元素，是对所有 j 取最小值。最后一个城市把两条路径连起来。每一步记录产生新元素的
j，从最佳终态往回走即可把每个城市分到路径上。`O(N²)`。

易错点：

- 路线必须从城市 1 开始，而它不一定是最小的，所以要把找到的环旋转；
- 过路费是整数除法，许多城市的 q 相同（测试 06 和 gen4 中的大城市）；
- 只有两个城市时只有一条路线。

金字塔形这一点已在 400 个最多 9 个城市的随机输入上由穷举所有路线验证，在 60 个最多 1000 个城市的随机输入上，
路线花费与一个独立的已通过实现一致。检查器比较路线花费。
