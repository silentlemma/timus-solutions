# 1608. 2008 幸运票

[Timus 1608](https://acm.timus.ru/problem.aspx?space=1&num=1608) · 难度 1032 · math

原题作者 Sergey Pupyrev，出自 2008 年 3 月 29 日第十二届乌拉尔竞技编程锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

票号依次为 1, 2, 3, …，没有前导零。若票号 d₁d₂…dₙ 中任意两个对称位置的数字都不相同，即 i ≠ n + 1 − i 时
dᵢ ≠ dₙ₊₁₋ᵢ，则为幸运票。求从 a 到 b（1 ≤ a ≤ b ≤ 10¹⁸）的幸运票张数。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

a 和 b。

## 输出

幸运票的张数。

## 样例

### 样例 1

输入:

```
1 10
```

输出:

```
10
```

### 样例 2

输入:

```
100 2000
```

输出:

```
1620
```

## 解法

计算不超过 n 的幸运票数 f(n)，输出 f(b) − f(a − 1)。

各位数字分成对称的数对，长度为奇数时还有中间一位。固定若干前导数字后，其余数字逐对计数：两位都已固定的数对必须不同
（否则为 0）；只固定了左边一位的数对，右边一位有 9 种选择；两位都自由的数对有 10·9 = 90 种；自由的中间位有 10 种。
前缀总是从左边固定，所以不会出现只固定右边一位的数对。

f(n) 把所有更短的数按首位 1 到 9 累加，再把与 n 等长且小于 n 的数，按首次比 n 小的位置及该位放的更小数字累加；
若 n 本身是幸运票再加一。最多 19 位，只需几千步。

计数已与逐个检验不超过 300000 的所有数对照。

注意事项：

- 首位不能是 0，统计更短的数时也是如此；
- 奇数长度的中间位没有配对，总是自由的；
- 到 10¹⁸ 的计数约为 3.9·10¹⁷，可用 64 位整数存放，但 a − 1 可能为 0，此时计数为 0。
