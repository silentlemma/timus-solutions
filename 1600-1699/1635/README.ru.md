# 1635. Мнемоника и палиндромы

[Timus 1635](https://acm.timus.ru/problem.aspx?space=1&num=1635) · сложность 202 · dp

## Задача

Разбить строку из строчных букв на наименьшее число палиндромов и
вывести их количество и сами куски по порядку. Подходит любое
оптимальное разбиение.

## Входные данные

Одна непустая строка из строчных латинских букв длиной не больше 4000.

## Выходные данные

Наименьшее число палиндромов, затем куски оптимального разбиения через
пробел.

## Примеры

### Пример 1

Ввод:

```
pasoib
```

Вывод:

```
6
p a s o i b
```

### Пример 2

Ввод:

```
zzzqxx
```

Вывод:

```
3
zzz q xx
```

### Пример 3

Ввод:

```
wasitacatisaw
```

Вывод:

```
1
wasitacatisaw
```

## Решение

Пусть `d[j]` — минимум частей для первых `j` букв, `d[0]=0`.
Каждый палиндром `s[l..r]` даёт переход
`d[r+1] = min(d[r+1], d[l]+1)`. Сохраняем начало `l`, восстанавливаем
части от конца и разворачиваем для вывода. У любого разбиения есть
последний палиндром, поэтому переходы рассматривают все варианты.

Базы C++, Go, Java и Rust расширяют нечётные и чётные палиндромы вокруг
`2n−1` центров слева направо. Порядок корректен: все части, заканчивающиеся
до `l`, имеют центр строго раньше `l`, а центр текущего палиндрома не раньше
`l`. Значит, используемое `d[l]` уже окончательно. В худшем случае
`O(n²)` времени и `O(n)` памяти вместе с восстановлением; квадратная
матрица палиндромов не нужна.

Существующая база Python хранит начала палиндромов в битовых масках целых.
Для правого конца `i` сдвигаем прежние начала вправо на один, пересекаем
с позициями буквы `s[i]`, добавляем одиночную букву `i` и, при равенстве
двух последних букв, начало `i−1`. Это точная рекуррентность по внутреннему
палиндрому с отдельно добавленными длинами один и два.

При добавлении буквы минимум меняется не более чем на один. Верхняя
граница следует из добавления одиночной буквы. Для нижней удалим последнюю
букву последнего палиндрома оптимального разбиения: его остаток — первая
буква и палиндромная середина, то есть не более двух частей вместо одной.
Поэтому `d[i+1]` равно `d[i]−1`, `d[i]` или `d[i]+1`. Маска `level[v]`
хранит прежние длины префиксов с минимумом `v`. По порядку пересекаем
начала с уровнями `d[i]−2` и `d[i]−1`; если оба пусты, одиночная буква
оптимальна. Младший бит непустого пересечения даёт корректного предка.

При `w` битах в разряде длинного целого требуется `O(n²/w+n)` операций
над разрядами. Маски уровней в сумме могут занимать `O(n²)` бит плюс
`O(n)` индексов и объектов: даже маске с одним установленным битом нужна
память до его позиции. Это отдельная оценка, а не линейная память
машинного DP; размер разряда не предполагается равным 64.

## Оптимизированные решения

Новый C++ сохраняет то же расширение центров и DP, поэтому имеет суффикс
`_optimized`. Сначала проверяем, не является ли вся строка палиндромом:
одна часть заведомо оптимальна, ответ находится за `O(n)`. Иначе остаётся
худшая оценка `O(n²)`. При `n≤4000` количества, значение `n+1` для
инициализации, индексы префиксов и концы восстановленных частей помещаются
в беззнаковые 16-битные ячейки. Статические массивы хранят вход, минимум,
предков и концы. `fwrite` выводит срезы без создания строк-подстрок
и вектора строк; stdio заменяет iostream. Весь Accepted-процесс занимает
140 КБ против 676 КБ неизменённой базы, экономия 79,3%. Время у обеих
версий 0,015 с, измеренное ускорение не заявлено. Обе версии сохранены.

## Проверка

Проверяющий алгоритм должен проверить число частей, палиндромность,
совпадение их конкатенации с исходной строкой и минимальность количества.
Оптимальные разбиения могут различаться. Фактический новый C++ прошёл
693 дополнительных входа: все 510 непустых двоичных строк до длины восемь,
180 случайных строк и три строки длины 4000 с доказанными ответами
1, 2 и 4000. Малые ответы считались независимым DP с проверкой каждого
суффикса разворотом, без расширения центров. Большие случаи — одна буква,
чередование `ab` и повторение `abcd`: в последнем нет палиндромов длины
два и три, а значит и более длинных. Решение также прошло все 15 входов
репозитория в Docker и получило Accepted для точных байтов. 693 проверки —
реальные запуски C++, а не запуски нового Python-кандидата.

## Особенности языков

Все пять прежних Accepted-исходников сохранены побайтово. Новый C++
сравнивается со своей C++-базой. Снимок использует согласованный профиль:
C++ — одновременно топ 15% или первые десять мест по обеим метрикам;
другие семейства — первое место по обеим. Пустая выборка конкурентов
даёт формальное покрытие, не доказательство превосходства. Допущенная
версия с недобором рейтинга получает звёздочку и переведённое пояснение.
