# 1677. 键盘前的猴子

[Timus 1677](https://acm.timus.ru/problem.aspx?space=1&num=1677) · 难度 1540 · strings

原题作者 Igor Chevdar，出自 2008 年 8 月彼得罗扎沃茨克夏季集训的 Ural SU Contest。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

猴子每秒等概率地敲出前 N 个字母之一。求给定单词在敲出的文本中出现所需秒数的期望，向下取整。

## 输入

N（1 ≤ N ≤ 26），然后是单词：取自前 N 个字母的小写字母，至多 30000 个。

## 输出

期望时间，向下取整（它本来就是整数）。

## 样例

### 样例 1

输入：

```
2
aa
```

输出：

```
6
```

### 样例 2

输入：

```
2
ba
```

输出：

```
4
```

## 解法

答案是对所有使单词前 k 个字母等于后 k 个字母（即单词的边界）的 k 求 N^k 之和，包括整个单词。对 N = 2 的 aa
是 2 + 4 = 6，对 ba 只是 4。

下注的论证说明了原因。每秒之前来一位带一枚硬币的新赌徒，以返还赌注 N 倍的公平规则全押下一个字母是单词的第一个字母；
赢了就全押第二个字母，依此类推。游戏是公平的，所以在单词第一次出现时，赌徒们的总奖金减去带来的硬币，期望为零。
此时仍在游戏中的恰好是从单词某个边界开始的赌徒，长度为 k 的边界对应持有 N^k，而每一秒带来一枚硬币。所以期望
时间等于 N^k 之和。

边界由前缀函数得到：单词的最长边界、它的最长边界，依此类推。N > 1 时，这个和用 N 进制表示只有数字 0 和 1。多数实现用 Horner
法则从最高位往下构造，Java 则累加逐次计算的幂；它最多约有 42 500 位十进制数字。数的运算为 `O(L²)` 次单元操作，边界为 `O(L)`。

易错点：

- 答案是一个巨大的精确整数（测试 05），需要高精度运算；浮点数在这里没用；
- N = 1 时时间就是单词的长度（测试 03）。

对所有长度不超过 5、字母数不超过 3 的单词，答案与精确求解期望方程的结果一致，也与一个独立的已通过实现一致。

## 各语言说明

- C++ 和 Rust 自己用以 10⁹ 为基的单元做运算：每一步乘以 N 再加一位数字。
- Python 用 sys.set_int_max_str_digits(0) 解除把巨大整数转换为文本的限制。
