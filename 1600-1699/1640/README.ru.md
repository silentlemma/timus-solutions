# 1640. Кольцо холода

[Timus 1640](https://acm.timus.ru/problem.aspx?space=1&num=1640) · сложность 178 · geometry

Автор оригинальной задачи — Дмитрий Иванков (подготовка — Александр Ипатов); осеннее первенство школьников, октябрь 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Демоны стоят в n точках решётки. Сандро может телепортироваться в любую
точку, где нет демона, и создать вокруг неё ледяное кольцо радиусом не
больше 10000. Кольцо должно убить хотя бы одного демона (лежащего на
окружности), а все оставшиеся в живых демоны должны оказаться внутри.
Нужно вывести центр и радиус.

## Входные данные

n (1 ≤ n ≤ 100), затем координаты демонов — целые числа не больше 1000
по модулю, отсчитанные от текущего положения Сандро. Все демоны в разных
точках, ни один не стоит там, где Сандро.

## Выходные данные

Центр и радиус с точностью 10⁻⁹. Подходит любой правильный ответ.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверка репозитория требует ровно три конечных числа x,y,r при 0<=r<=10000+1e-6. Центр отстоит от каждого демона минимум на 1e-6, все демоны находятся не дальше r+1e-6, хотя бы одно расстояние отличается от r не более чем на 1e-6. Это допуск проверки репозитория; условие отдельно требует точность 1e-9.

## Решение

Телепортироваться не нужно. В точке, где стоит Сандро, демона нет, а
окружность вокруг неё через самого дальнего демона убивает его и
охватывает всех остальных. Её радиус не больше 1000 · √2, что далеко от
10000. `O(n)`.

Подводные камни:

- центр не должен совпадать с демоном, так что центр наименьшей
  охватывающей окружности годится не всегда; начальная точка — всегда;
- правильных ответов много, поэтому чекер принимает любую окружность,
  удовлетворяющую правилам.

## Оптимизированные решения

Оптимизированное решение на Java печатает ту же окружность, но читает
числа вручную из блоков байтов по 4 КБ вместо `Scanner`, регулярные
выражения которого требуют времени и памяти на подготовку:
{1640_geometry_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1640_geometry_optimized.java`: сокращение времени +33.57%; сокращение
  памяти +54.92%; база: `1640_geometry.java`.

`1640_geometry_optimized.rs`. Сохраняется центр в начале координат, где по условию нет демона. Целые координаты читаются по паре, max(x*x+y*y) точно считается в i64, один квадратный корень извлекается в конце вместо hypot для каждой точки. При модулях координат до 1000 квадраты заведомо помещаются. Радиус выводится с десятью знаками после точки. Время O(n), дополнительное состояние O(1), без вектора всего вещественного ввода. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1640_geometry.rs`: время 0.062 s → 0.031 s; память 268 KB → 96 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1640_geometry_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
