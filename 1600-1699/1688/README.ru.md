# 1688. Team.GOV!

Автор оригинальной задачи — Александр Ипатов; X открытое личное первенство УрГУ, 28 февраля 2009 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Трое членов команды заказывают одно и то же, а платит за всех один из
них. Ещё один участник может уйти, как только заплаченные за него
деньги — треть каждого счёта — превысят n. По счетам в порядке походов
определить, после какого похода это случится.

## Входные данные

n и m (1 ≤ n ≤ 2 · 10⁹; 0 ≤ m ≤ 3000), затем m счетов — целые от 1 до
2 · 10⁶.

## Выходные данные

«Free after x times.» для первого такого похода x или «Team.GOV!», если
этого не случится.

## Примеры

### Пример 1

Ввод:

```
1666 5
2000
1024
900
1156
1200
```

Вывод:

```
Free after 4 times.
```

### Пример 2

Ввод:

```
3000 5
2000
1024
900
1156
1200
```

Вывод:

```
Team.GOV!
```

## Решение

Храним сумму счетов. Доля total / 3 превышает n ровно тогда, когда
total > 3n, — так обходимся без дробей; останавливаемся на первом
походе, где это выполнено. `O(m)`.

Подводные камни:

- 3n доходит до 6 · 10⁹, как и сумма: нужны 64-битные целые (тест 06);
- доли, равной n, недостаточно, сравнение строгое (тесты 04 и 06).

Ответы совпадают с независимой принятой реализацией.

## Оптимизированные решения

Оптимизированное решение на Java разбирает числа побайтно из буфера на
4 КБ, который оно заново заполняет из `System.in`, вместо того чтобы
сначала копировать весь ввод в `StringBuilder`, а затем ещё в одну
строку для разбивки на токены. Оно читает все m счетов, даже когда ответ
уже известен, и держит сумму и 3n в `long`, ведь оба значения могут
достигать 6 · 10⁹: {1688_implementation_optimized.java}.

Оптимизированное решение на Python берёт токены построчно из генератора
по `sys.stdin.buffer` вместо того, чтобы читать весь ввод и превращать
его в список до 3002 целых; текущая сумма считается так же, как в
простом решении: {1688_implementation_optimized.py}.

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.
