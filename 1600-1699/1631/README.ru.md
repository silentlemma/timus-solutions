# 1631. Пьяный король 2

[Timus 1631](https://acm.timus.ru/problem.aspx?space=1&num=1631) · сложность 493 · math

Автор оригинальной задачи — Игорь Чевдарь; XIII открытый командный чемпионат УрГУ по программированию.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Король обходит шахматную доску m × n с нечётными сторонами: начинает и
заканчивает в углу, каждую клетку, кроме первой, посещает ровно один
раз, не пересекает свой путь и, будучи пьяным, никогда не делает два
хода подряд в одном направлении. Нужно найти длину кратчайшего такого
обхода, считая между центрами клеток (прямой ход — 1, диагональный — √2).

## Входные данные

Одна строка с m и n (6 < m, n < 500, оба нечётные).

## Выходные данные

Длина кратчайшего обхода с точностью 10⁻⁹.

## Примеры

### Пример 1

Ввод:

```
7 7
```

Вывод:

```
55.213203435596425732025330863145
```

## Решение

В обходе mn ходов. Если D из них диагональные, длина равна
mn + D·(√2−1), поэтому нужно минимизировать D. Принятые программы
вычисляют формулу с D=m+n+1 за постоянное время и память.

Почему диагоналей не может быть меньше? Разобьём клетки по чётности
строки и столбца: A — чётная/чётный, B — чётная/нечётный,
C — нечётная/чётный, D₀ — нечётная/нечётный. При нечётных размерах
|A|−|D₀|=(m+n)/2. Шахматный цвет A∪D₀ содержит на одну клетку больше B∪C.

Пусть x — число диагоналей B–C, y — число диагоналей A–D₀.
Ортогональные ходы соединяют два цвета и сокращаются при вычитании
сумм степеней. Каждая диагональ даёт два конца своему цвету, откуда
y−x=1. Если вычесть сумму степеней D₀ из суммы степеней A,
диагонали A–D₀ тоже сократятся. Останется разность m+n между
числами концов ортогональных рёбер в A и в D₀.

Посчитаем эту разность на других концах, в B∪C. Без диагонали
у клетки должен быть один горизонтальный и один вертикальный ход:
два по одной оси означали бы ход прямо или повторное посещение.
Тогда один сосед лежит в A, другой — в D₀, вклад равен нулю.
При одной диагонали вклад не больше единицы, при двух — снова ноль.
Клеток с одной диагональю не больше 2x, поэтому m+n≤2x и
x+y=2x+1≥m+n+1.

В примере 7×7 оценка достигается с 15 диагоналями. Разрежем обход
между строками 3 и 4 при нумерации с нуля. Разрез пересекают только
вертикальные рёбра в столбцах 1, 2, 4 и 6. Вставим две строки и заменим
эти рёбра ходами `↓←↓→↓`, `↓→↓←↓`, `↓→↙↓` и `↓↙→↓` соответственно.
Они покрывают 14 новых клеток, а две диагонали лежат в разных квадратах.
На концах каждого пути направление остаётся вертикальным. Верхний разрез
сохраняет те же пересечения, поэтому вставку можно повторять для любой
нечётной высоты при ширине семь. Транспонирование меняет стороны местами.
Для расширения сначала отразим пример слева направо. Вставим четыре
столбца после столбца 4. Два ребра этого разреза начинаются слева
в (2,4) и (5,4). Заменим их ходами `↗↑→↘↑→↓→` и
`↘→↑←↑→↑←↑→↑↘→↓←↓→↙↓→↑↘`, сохранив правые концы со сдвигом на четыре.
Эти пути покрывают весь новый блок и добавляют четыре диагонали.
Стыки позволяют повторять вставку на том же разрезе. На разрезе
между строками первые три столбца сохраняют два крайних вертикальных
ребра, а в каждой следующей паре столбцов ровно одно такое ребро.
Прежняя двухстрочная вставка работает по этим блокам, с отражением
пути в паре при необходимости. Получаем оптимум, когда хотя бы одна
сторона даёт остаток 3 при делении на 4.
[Рисунок из условия](https://sp.urfu.ru/usu/okt_08/USU_champ_08.pdf#page=4)

На максимальном размере точности binary64 хватает для 10⁻⁹;
десятичный разделитель должен быть точкой при любой локали.

### Обе стороны дают остаток 1 при делении на 4

Начнём с обхода 9×9. Посещаем клетки по номерам и возвращаемся из 81 в 1. В нём 19 диагоналей.

```text
 1 81 79 78 75 74 72 70 69
 3  2 80 77 76 51 73 71 68
 4  5 45 46 49 50 52 67 66
 6 43 44 47 48 54 53 64 65
 7 42 41 39 38 55 56 63 62
 9  8 40 37 35 34 57 61 60
10 11 19 20 36 33 32 58 59
12 15 18 21 23 24 27 31 30
13 14 16 17 22 25 26 28 29
```

Для четырёхстрочных вставок пути перечислены в порядке входов. Для входов 0 и 1 используем `↓↘←↓→↙↓` / `↓→↓→↑→↓↙→↓←↖↓←↓`. Для входов 0 и 3 используем `↓→↙↓↘←↓` / `↓→↓←↖↓←↓→↓↗→↓←↓`. Каждая вставка покрывает четыре новых ряда по пять клеток, добавляет четыре диагонали и сохраняет вертикальные ходы на концах. В паре столбцов с одним входом дважды повторяем двухстрочный U-образный путь.

Сначала расширяем доску по разрезу после столбца 4. Его горизонтальные рёбра лежат в строках 0, 2, 5 и 7. На строки 2–6 переносим вставку со входами 0 и 3, меняя строки и столбцы местами. Так же транспонируем пути для пар строк 0–1 и 7–8. Этот разрез сохраняется. Каждая вставка даёт по одному вертикальному ребру в каждой новой паре столбцов на разрезе после строки 3. Затем по этому разрезу увеличиваем высоту. Для первых пяти столбцов берём вставку со входами 0 и 1, для остальных пар берём парные пути. Каждые четыре новых ряда или столбца добавляют четыре диагонали. Две стартовые доски покрывают все допустимые размеры.

## Оптимизированные решения

Варианты Go и Java вычисляют ту же формулу mn + (m+n+1)(√2−1). Меняется только ввод-вывод: Go разбирает два числа через фиксированные буферы64байта и выводит целую и двенадцатизначную дробную части напрямую, без fmt, strconv и хранения всего ввода; Java читает два числа напрямую и печатает double без Scanner, Locale и String.format. Go выводит двенадцать знаков после точки; Double.toString в Java сохраняет достаточное число значащих цифр. Независимая проверка с 60 значащими цифрами включает все допустимые квадраты и доски 7×n; она проверяет вычисления, а не доказывает заново формулу обхода. Время и память O(1). Обычные исходники сохранены; C++, Python и Rust используют подходящие базы.

Принятые базовые реализации [1631_math.cpp](1631_math.cpp), [1631_math.py](1631_math.py), [1631_math.rs](1631_math.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
