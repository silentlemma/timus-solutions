# 1626. Мешающий отрезок

[Timus 1626](https://acm.timus.ru/problem.aspx?space=1&num=1626) · сложность 6623 · geometry

Оригинальная задача — SPbSU ITMO Contest, Петрозаводские сборы, зима 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У простого многоугольника N вершин (3 ≤ N ≤ 800, целые координаты по
модулю не больше 10⁴, никакие три подряд идущие вершины не лежат на одной
прямой), и отрезок S лежит строго внутри него. Триангуляции здесь
используют только вершины многоугольника, и ни одна вершина не может
лежать на стороне треугольника, кроме его собственных углов. Найдите
треугольник какой-нибудь триангуляции, содержащий S строго внутри, и
выведите номера трёх его вершин, или `Impossible`. Принимается любой
такой треугольник.

Ограничение времени: 5 секунд. Ограничение памяти: 64 МБ.

## Входные данные

N, вершины по порядку, затем концы S.

## Выходные данные

Три номера вершин или `Impossible`.

## Примеры

### Пример 1

Ввод:

```
3
0 0
0 3
4 3
1 2 2 2
```

Вывод:

```
1 2 3
```

### Пример 2

Ввод:

```
4
0 0
2 0
2 3
0 3
1 1 1 2
```

Вывод:

```
Impossible
```

## Решение

Треугольник входит в какую-нибудь триангуляцию ровно тогда, когда его
стороны — рёбра многоугольника или диагонали (внутри многоугольника, не
касаются других вершин) и внутри него нет вершин: остальная часть
многоугольника тогда распадается на меньшие многоугольники, которые
можно триангулировать. Значит, нужно найти такой треугольник вокруг S.

Всё делается битовыми множествами из N вершин. После ориентации
многоугольника против часовой стрелки для каждой пары a < b хранится
множество вершин строго слева от прямой a → b. Пара i, j — диагональ,
если j лежит внутри внутреннего угла при i, а i — внутри угла при j,
если ни одно ребро не пересекает отрезок собственно и на открытом
отрезке нет вершин. У возможных пересекающих рёбер различаются признаки
«строго слева» у концов относительно i → j (множество слева xor само
себя с циклическим сдвигом на единицу), а у i и j — относительно прямой
ребра; точно проверяются только эти кандидаты.

Затем для каждой диагонали или ребра a → b, у которых оба конца S строго
слева, третьи вершины k — общие соседи a и b, при которых оба конца S
остаются внутри треугольника, тоже пересечение битовых множеств.
Треугольник a, b, k пуст, если у трёх множеств «слева» нет общих вершин,
кроме его углов. Первый такой треугольник — ответ. `O(N³)` времени.

Python строит множества «слева» иначе: вокруг каждой вершины остальные
сортируются по углу, так что каждое множество — круговой отрезок этого
порядка и получается из префиксных битовых множеств за `O(1)`
операций с длинными числами, а ближайшая вершина в каждом направлении
отмечает, на каких отрезках нет других вершин. Хранятся только
множества текущей вершины, поэтому пустоту треугольника проверяют по
углам: ни одно ребро многоугольника в углу не должно смотреть внутрь
треугольника. Граница не может пересечь стороны, значит, она целиком
снаружи, а с ней и все вершины. В таблице w — число бит в разряде
длинного числа.

Подводные камни:

- вершина может лежать ровно на предполагаемой диагонали (тесты 03, 04);
- в прямоугольнике обе диагонали могут пересекать S (второй пример);
- треугольник примера можно вывести с углами в любом порядке, поэтому
  чекер проверяет каждое условие.

Ответы проходят чекер на всех тестах, а независимая принятая реализация
выносит тот же вердикт на каждом сгенерированном многоугольнике.

## Особенности языков

- Python запускается под PyPy: CPython тратит около 2,4 с на самых
  больших наших тестах при лимите 5 с, это слишком близко для жюри, а
  PyPy — около 0,9 с. PyPy освобождает короткоживущие битовые маски
  только при сборке мусора, поэтому решение вызывает сборщик каждые
  64 строки; без этого один мусор превышал лимит 64 МБ.
- Java строит множества «слева» в арифметике int, которую позволяют
  координаты до 10⁴; это вдвое ускоряет её.
