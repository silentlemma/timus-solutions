# 1691. 算法复杂度

[Timus 1691](https://acm.timus.ru/problem.aspx?space=1&num=1691) · 难度 2798 · graphs

原题作者 Ivan Burmistrov，出自 2009 年 2 月彼得罗扎沃茨克冬季集训的 Ural SU Contest。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

在没有重边（允许自环）的有向图中，设 F(N) 为从 s 到 t 长度为 N 的路径数。
求最小的 k ≥ 0，使得对某个常数 C 和所有 N ≥ 1 有 F(N) ≤ C · Nᵏ；若 F 增长快于任何多项式，输出 −1。

## 输入

n, m, s, t（1 ≤ n, m ≤ 100000），然后是 m 条弧。

## 输出

k 或 −1。

## 样例

### 样例 1

输入：

```
2 3 1 2
1 1
1 2
2 2
```

输出：

```
1
```

### 样例 2

输入：

```
3 6 1 2
1 2
2 1
1 3
3 1
2 3
3 2
```

输出：

```
-1
```

## 解法

只有位于某条 s 到 t 路径上的顶点才有意义：从 s 可达且能到达 t 的顶点。若 t 不可达，F 为零，k = 0。
这些顶点构成完整的强连通分量，因为与这样的顶点同在一个环上的点也位于 s 和 t 之间。

弧数多于顶点数的分量含有经过同一顶点的两个不同的环，路径可以按指数多种顺序绕行，答案为 −1。
否则每个分量要么是单个顶点（可能带自环），要么是一个简单环，弧数等于顶点数。
经过 c ≥ 1 个简单环的路径把多余的长度分配到这些环上，约有 N^(c − 1) 种方式。
所以 F(N) ≤ C · N^(c − 1)，并且在合适的等差数列 N 上能达到这个阶。
因此 k = max(0, c − 1)，其中 c 是一条 s 到 t 路径上最多的含环分量数。

Kosaraju 算法给分量编号，使分量之间的弧都从小编号指向大编号。按这个顺序扫一遍，
把含环分量的权记为 1，按最长路求出 c。所有遍历都使用显式栈。`O(n + m)`。

注意事项：

- 含两个环但到不了 t（或从 s 到不了）的分量无关紧要（测试 07）；
- 路径上只有一个环时 F 有界，所以 k = 0 而不是 1（测试 08）；
- 自环是长度为 1 的环，且允许 s = t（测试 04）；
- 递归深度会达到 10⁵，所以遍历使用自己的栈。

答案与一个独立的已通过实现一致；在 121 个很小的图上，也与精确计算到 N = 3000 的 F(N) 的增长一致。
