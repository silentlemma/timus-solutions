# 1605. Дьявольская последовательность

[Timus 1605](https://acm.timus.ru/problem.aspx?space=1&num=1605) · сложность 606 · math

Автор оригинальной задачи — Александр Ипатов; IX открытое личное первенство УрГУ, 1 марта 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

x₀ = 0, x₁ = 1 и xₙ = (xₙ₋₁ + xₙ₋₂)/2. Для 2 ≤ n ≤ 100000 нужно
определить, со скольких шестёрок после запятой начинается десятичная
запись xₙ. Например, x₁₀ = 0.666015625 начинается с трёх.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

n.

## Выходные данные

Количество начальных шестёрок.

## Примеры

### Пример 1

Ввод:

```
10
```

Вывод:

```
3
```

## Решение

У рекурренты характеристические корни 1 и −1/2, а начальные значения
дают xₙ = 2/3 − (−1)ⁿ·(2/3)·2⁻ⁿ. Поскольку 2/3 = 0.666…, всё решают
расстояние от xₙ до 2/3 и сторона.

Число начинается хотя бы с k шестёрок, когда лежит в [0.6…6, 0.6…6 + 10⁻ᵏ)
с k шестёрками, то есть между 2/3 − (2/3)·10⁻ᵏ и 2/3 + (1/3)·10⁻ᵏ. При
чётном n xₙ меньше 2/3 на (2/3)·2⁻ⁿ, так что k шестёрок сохраняются,
пока 10ᵏ ≤ 2ⁿ. При нечётном n xₙ больше на ту же величину, так что они
сохраняются, пока 2·10ᵏ < 2ⁿ, то есть 10ᵏ ≤ 2ⁿ⁻¹ (равенство при n ≥ 2
невозможно). В обоих случаях ответ — ⌊m·log₁₀ 2⌋ при m = n или n − 1, на
единицу меньше числа десятичных цифр 2ᵐ: `O(1)`.

Формула сверена с десятичной записью точных дробей при n < 200 и с
числом цифр 2ᵐ.

Подводные камни:

- сторона важна: у x₃ = 0.75 нет ведущих шестёрок, а у x₄ = 0.625 одна, так что
  нечётным n нужно 2ⁿ⁻¹ вместо 2ⁿ;
- m·log₁₀ 2 может подходить близко к целому, но при n до 10⁵ не ближе
  1,5·10⁻⁵ (n = 28738), что гораздо больше ошибки округления double
  (тесты 08–10);
- моделирование xₙ в вещественных числах теряет отличие от 2/3 уже
  примерно через 50 шагов, задолго до n = 100000.

## Оптимизированные решения

Java использует целочисленную арифметику и приближение log₁₀ 2 с фиксированной точкой. Приближение даёт точное округление вниз для каждого допустимого входа. Посылка 11318297 заняла 0,109 с и использовала 316 КБ.

Приближение отбрасывает цифры log₁₀ 2 после 12-го знака. При умножении на m ≤ 10⁵ ошибка меньше 10⁻⁷, что меньше указанного выше расстояния до ближайшего целого.

Python использует целочисленную арифметику и приближение log₁₀ 2 с фиксированной точкой. Приближение даёт точное округление вниз для каждого допустимого входа. Посылка 11318410 заняла 0,078 с и использовала 404 КБ.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11321853 · Go 1.14 x64 №11322280 · Java 1.8 №11322281 · Python 3.12 x64 №11322282 · Rust 1.75 x64 №11322283.

Go использует приближение логарифма с фиксированной точкой, сохраняющее целую часть на всём диапазоне входа. Ответ записывается в тот же буфер. Go 1.14 x64, посылка 11322854. Время 0,031 → 0,031 с, память 1060 → 284 КБ.

Rust читает десятичное число как масштабированное целое и вычисляет целую часть целочисленной арифметикой. Rust 1.75 x64, посылка 11323310. Время 0,015 → 0,031 с, память 244 → 48 КБ.
