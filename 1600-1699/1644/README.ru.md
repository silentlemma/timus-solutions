# 1644. Куча орехов

[Timus 1644](https://acm.timus.ru/problem.aspx?space=1&num=1644) · сложность 100 · implementation

Автор оригинальной задачи — Алексей Самсонов; осеннее первенство школьников, октябрь 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В каждом из n экспериментов Попугай съедал от 3 до 9 орехов и
записывал, остался ли голодным или наелся. Сытость монотонна: от
большего числа орехов голоднее не станешь. Известно, что десяти орехов
всегда хватает, а двух никогда. Нужно найти наименьшее число орехов,
которого наверняка хватит, или сообщить, что записи противоречат друг
другу.

## Входные данные

n (0 ≤ n ≤ 100), затем n строк: число орехов и `hungry` или
`satisfied`.

## Выходные данные

Наименьшее число орехов, которого наверняка хватит, или `Inconsistent`.

## Примеры

### Пример 1

Ввод:

```
4
4 hungry
7 satisfied
5 hungry
8 satisfied
```

Вывод:

```
7
```

### Пример 2

Ввод:

```
2
6 hungry
5 satisfied
```

Вывод:

```
Inconsistent
```

## Решение

Возьмём наибольшее «голодное» количество, начиная с 2, и наименьшее
«сытое», начиная с 10. Записи согласуются с монотонным порогом ровно
тогда, когда второе больше; тогда ответ — наименьшее «сытое» количество,
ведь меньшее никогда не давало сытости. Иначе `Inconsistent`. `O(n)`.

Подводные камни:

- без записей ответ 10 (тест 03), и только с «голодными» записями ответ
  тоже 10 (тест 04);
- одно и то же количество, записанное двумя способами, — противоречие
  (тест 06).

Ответы совпадают с независимой принятой реализацией на 180 случайных
наборах записей.

## Оптимизированные решения

Оптимизированное решение на Java разбирает числа вручную из небольшого
буфера вместо `Scanner` и различает два слова по первой букве, `h` или
`s`, пропуская остальные: 400 КБ вместо 1708 КБ при том же времени.

Оптимизированное решение на C++ читает через `scanf` в небольшой массив
`char` вместо `iostream` и `std::string` и различает два слова по первой
букве: 128 КБ вместо 388 КБ при том же времени.
