# 1641. Дежурства

[Timus 1641](https://acm.timus.ru/problem.aspx?space=1&num=1641) · сложность 511 · constructive

Автор оригинальной задачи — Павел Атнашев; осеннее первенство школьников, октябрь 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый из n учеников отвечает за один из k кабинетов, и за каждый
кабинет должен кто-то отвечать. В каждый из m дней дежурят два ученика,
отвечающие за разные кабинеты. Никакая пара не дежурит дважды, и каждый
ученик должен подежурить хотя бы раз. Нужно вывести такой план; известно,
что он существует.

## Входные данные

n, k и m (2 ≤ k ≤ n ≤ 100).

## Выходные данные

n строк с кабинетом каждого ученика, затем m строк с дежурной парой
каждого дня. Подходит любой правильный план.

## Примеры

### Пример 1

Ввод:

```
5 3 4
```

Вывод:

```
1
2
1
2
3
1 2
3 4
3 5
4 5
```

### Пример 2

Ввод:

```
4 2 4
```

Вывод:

```
1
2
1
2
1 2
3 4
1 4
2 3
```

## Решение

На языке графов: разбить учеников на k непустых групп и выбрать m
различных рёбер между разными группами, покрывающих всех учеников.
Чтобы покрыть n учеников, нужно не меньше ⌈n/2⌉ рёбер, а всего рёбер не
больше, чем в полном k-дольном графе. Их больше всего при максимально
ровных группах, так что раздача кабинетов по кругу, ученику i кабинет
i mod k, не хуже любого другого разбиения; раз план существует, m
помещается.

При раздаче по кругу у учеников i и i + 1 всегда разные кабинеты, так
что пары (0, 1), (2, 3), … покрывают всех за ⌈n/2⌉ дней; лишний
последний ученик встаёт в пару с учеником 0 или с учеником 1, если у 0
тот же кабинет. Остальные дни занимают любые неиспользованные пары из
разных кабинетов по порядку. `O(n² log n)` в C++; `O(n²)` в остальных.

Подводные камни:

- сначала важно покрыть всех: если заполнять дни просто по порядку, их
  могут целиком занять первые ученики (тест 07);
- при k = n у каждого кабинета по одному ученику и разрешены все пары
  (тест 06).

Чекер принимает любой правильный план; планы программы проходят его на
всех 1866 допустимых входах с n ≤ 12.

## Оптимизированные решения

C++ и Java сохраняют равномерное назначение кабинетов i mod k. При размерах кабинетов sᵢ число пар из разных кабинетов равно (n²−Σsᵢ²)/2. Если в одном кабинете хотя бы на два ученика больше, чем в другом, перевод одного из большего кабинета в меньший уменьшает Σsᵢ². Поэтому равномерное назначение позволяет набрать любое допустимое m. Сначала выводим непересекающиеся пары соседних индексов; при нечётном n последний ученик соединяется с нулевым или первым из другого кабинета. Эти ceil(n/2) пар покрывают всех, и меньше дней невозможно. Затем перебираем неупорядоченные межгрупповые пары, пропуская начальные по формулам индексов, до m дней. Не нужны множество или матрица использованных пар, массив кабинетов и список всех дней. В Java фиксированный буфер на 8192 байта заменяет растущий StringBuilder, ввод Java обходится без Scanner. Худшее время O(n²), дополнительная память O(1). Простые версии сохранены; Go, Python и Rust используют подходящие базы.

Принятые базовые реализации [1641_constructive.go](1641_constructive.go), [1641_constructive.py](1641_constructive.py), [1641_constructive.rs](1641_constructive.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
