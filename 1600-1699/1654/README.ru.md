# 1654. Шифровка

[Timus 1654](https://acm.timus.ru/problem.aspx?space=1&num=1654) · сложность 60 · implementation

Автор оригинальной задачи — Владимир Яковлев (идея — Александр Клепинин); четвертьфинал Восточного подрегиона NEERC 2008.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Текст без двух одинаковых соседних букв зашифровали, много раз вставив в
любое место пару одинаковых букв. Нужно удалить все вставленные пары и
вывести исходный текст.

## Входные данные

Одна строка до 200000 строчных латинских букв.

## Выходные данные

Восстановленный текст (возможно, пустой).

## Примеры

### Пример 1

Ввод:

```
wwstdaadierfflitzzz
```

Вывод:

```
stierlitz
```

## Решение

Удаление пары одинаковых соседей похоже на сокращение x · x = 1 в группе,
где каждая буква обратна сама себе, и такие сокращения всегда приводят к
одному и тому же тексту в любом порядке. В исходном тексте одинаковых
соседей нет, так что это и есть сокращённая форма.

Стек вычисляет её за один проход: буква, равная вершине стека, сокращает
её, любая другая кладётся в стек. `O(n)`.

Подводные камни:

- удаление пар может свести вместе новые одинаковые буквы (`abba`
  исчезает целиком, тест 04), так что одного прохода слева направо без
  стека мало;
- три одинаковые буквы оставляют одну (тест 06);
- ответ может быть пустой строкой (тесты 02, 04).

Ответы совпадают с независимой принятой реализацией на 60 случайных
тестах.

## Оптимизированные решения

Оптимизированные решения не хранят текст отдельно от стека. C++ и Java
читают ввод небольшими блоками и кладут буквы прямо в стек
фиксированного размера на 200 000 байт; Rust читает ввод байтами и
использует как стек уже обработанное начало, поскольку стек никогда не
длиннее прочитанной части. Все выводят стек одним блоком байтов. При том
же времени C++ занимает 284 КБ вместо 988 КБ, Java — 660 КБ вместо
3828 КБ, Rust — 396 КБ вместо 936 КБ.

Оптимизированное решение на Python читает текст блоками по 4 КБ и идёт
по нему байтами, пропуская всё, что не строчная буква, поэтому строка
целиком не хранится: 820 КБ вместо 1424 КБ при том же времени.
