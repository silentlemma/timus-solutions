# 1642. Одномерный лабиринт

[Timus 1642](https://acm.timus.ru/problem.aspx?space=1&num=1642) · сложность 96 · implementation

Автор оригинальной задачи — Даниил Айзенштейн; осеннее первенство школьников, октябрь 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Человек стоит в точке 0 на прямой с препятствиями и выходом в точке x,
идёт в выбранном направлении, сразу выходит, достигнув выхода, и
разворачивается у каждого препятствия. Для обоих начальных направлений,
вперёд (в сторону роста) и назад, нужно найти пройденное до выхода
расстояние или сообщить, что выход недостижим.

## Входные данные

n и x (0 ≤ n ≤ 100), затем n различных координат препятствий. Все
координаты ненулевые, не больше 1000 по модулю, и ни одно препятствие
не стоит в точке выхода. В любом направлении путь встречает выход или
препятствие.

## Выходные данные

Два расстояния, сначала для движения вперёд, или `Impossible`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
3 -2
-10 -4 2
```

Вывод:

```
6 2
```

### Пример 2

Ввод:

```
3 -2
10 -1 2
```

Вывод:

```
Impossible
```

## Решение

Важны только ближайшие препятствия: left — наибольшее меньше 0 (или −∞,
если его нет) и right — наименьшее больше 0 (или +∞, если его нет).
Выход достижим ровно тогда, когда left < x < right; иначе `Impossible`.
Тогда в обоих направлениях путь прямой или с одним крюком:

- x > 0: вперёд x; назад до left и обратно, 2 · |left| + x;
- x < 0: вперёд до right и обратно, 2 · right + |x|; назад |x|.

Нужное для крюка препятствие существует по обещанию условия. `O(n)`.

Подводные камни:

- препятствие между началом и выходом закрывает оба направления, так
  что один ответ на оба (второй пример, тест 06);
- со стороны выхода препятствий может не быть вовсе.

Ответы совпадают с независимой принятой реализацией на 300 случайных
прямых.

## Оптимизированные решения

`1642_implementation_optimized.py`. Сохраняются ближайшие отрицательное/положительное препятствия и прежние формулы выхода. Целые читаются потоком вместо хранения стен и повторных проходов списков. Используется обещанное препятствие со стороны от выхода, Impossible прежний. PyPy сбрасывает ответ перед os._exit(0). Время O(n), постоянное геометрическое состояние плюс ограниченные буферы токенов; измеренное время выше, память ниже.

По сравнению с `1642_implementation.py`: время 0.093 s → 0.156 s; память 504 KB → 252 KB.

Оптимизированное решение на Java разбирает числа вместе со знаками
вручную из небольшого буфера вместо `Scanner`: 436 КБ вместо 1688 КБ
при том же времени. Остальное то же.

`1642_implementation_optimized.cpp`. Ближайшая преграда с каждой стороны находится за один проход ввода, затем применяются прежние условия достижимости и формулы двух расстояний. Ручной побайтовый разбор и вывод C заменяют форматированное преобразование целых, промежуточные значения знаковые 64-битные. Список преград не хранится: O(n) времени и O(1) явного рабочего состояния.

По сравнению с `1642_implementation.cpp`: время 0.031 s → 0.015 s; память 124 KB → 72 KB.

`1642_implementation_optimized.rs`. Обе границы ближайших преград обновляются при чтении очередного препятствия, без сбора ввода и двух проходов по вектору. Формулы расстояний не меняются. Числовой ввод-вывод через среду C и две границы дают O(n) времени и O(1) дополнительной памяти.

По сравнению с `1642_implementation.rs`: время 0.031 s → 0.015 s; память 228 KB → 48 KB.
