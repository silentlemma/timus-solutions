# 1694. Слова-убийцы

[Timus 1694](https://acm.timus.ru/problem.aspx?space=1&num=1694) · сложность 2933 · backtracking

Автор оригинальной задачи — Алексей Самсонов; Ural SU Contest, Петрозаводские зимние сборы, февраль 2009 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Слово-убийца состоит только из первых m латинских букв, является
k-повтором (k копий одного слова подряд), и никакое его собственное
подслово не является k-повтором. Посчитать слова-убийцы длины не
больше n.

## Входные данные

m, k, n (1 ≤ m ≤ 18; 2 ≤ k ≤ 5; 1 ≤ n ≤ 22).

## Выходные данные

Количество слов-убийц.

## Примеры

### Пример 1

Ввод:

```
3 2 4
```

Вывод:

```
9
```

## Решение

Слово-убийца — это wᵏ для слова w длины L ≤ n / k, не больше 11.
Подходит ли wᵏ, зависит не от того, какие буквы использует w, а только
от их расположения. Поэтому перебираем w, нумеруя буквы в порядке
первого появления (0, затем 0 или 1 и так далее). Шаблон с d разными
буквами соответствует m(m − 1)⋯(m − d + 1) словам.

Любое подслово w — подслово wᵏ, поэтому префикс w, который уже
заканчивается k-повтором, отбрасывается вместе со всеми продолжениями.
Для каждого оставшегося w проверяем само wᵏ. Раз в w нет k-повторов, а
wᵏ имеет период L, смотреть нужно только окна, которые начинаются в
первой копии w и выходят за неё. Слово w, степень которого не
подходит, всё равно продолжается, потому что более длинное w может
подойти: (010)² содержит 00, а (0102)² годится.

Количества шаблонов по длине и числу букв суммируются с убывающими
степенями m. Перебор посещает около 10⁵ шаблонов при k = 2 и n = 22 и
гораздо меньше при больших k. Наибольший ответ, 3.5 · 10¹³, помещается
в 64 бита.

Подводные камни:

- всё слово не является собственным подсловом, так что само wᵏ
  допустимо;
- нельзя останавливаться на w, степень которого не подходит (тест 06
  с тремя буквами это требует);
- при n < k слов нет вовсе (тест 07).

Решение на Python отправляется под PyPy: локальный запуск CPython
занимает около 0.6 с при k = 2 и n = 22, слишком близко к пределу в 1 с.

Ответы совпадают с подсчётом по всем словам при малых m и n и с
независимой принятой реализацией на 120 наборах параметров.
