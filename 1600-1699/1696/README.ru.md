# 1696. Зарплата для роботов

[Timus 1696](https://acm.timus.ru/problem.aspx?space=1&num=1696) · сложность 872 · dp

Автор оригинальной задачи — Игорь Чевдарь; Ural SU Contest, Петрозаводские зимние сборы, февраль 2009 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n роботов с рангами 1..n каждый месяц получают зарплату от 1 до k.
Выплата запрещена, если есть роботы a, b, c, ранги которых убывают от a
к c, а зарплаты возрастают от a к c; выплаты не могут повторяться.
Месяцы в году нумеруются 1..p. В какой месяц у бухгалтера закончатся
выплаты?

## Входные данные

n, k, p (1 ≤ n ≤ 1000; 1 ≤ k ≤ 200; 2 ≤ p ≤ 10⁹).

## Выходные данные

Номер этого месяца в его году.

## Примеры

### Пример 1

Ввод:

```
3 3 20
```

Вывод:

```
7
```

## Решение

Выпишем зарплаты в порядке рангов. Запрещённый узор — строго убывающая
подпоследовательность длины три. Если допустимых выплат C, бухгалтер
ржавеет в месяц C + 1 от начала, так что ответ — (C mod p) + 1.

Считаем последовательности по одному рангу. Состояние: a — наибольшая
зарплата до сих пор, b — наибольшая зарплата, перед которой была
бо́льшая (0, если такой нет). Новая зарплата z допустима ровно при
z ≥ b, ведь z < b завершила бы убывающую тройку. Если z < a, состояние
становится (a, z), иначе (z, b). Оба перехода — префиксные суммы: новое
(a, c) собирает все старые (a, b) с b ≤ c вдоль строки, а новое (z, b) —
все старые (a, b) с a ≤ z вдоль столбца. Итого `O(n · k²)` по модулю p.

Подводные камни:

- месяц равен (C mod p) + 1, поэтому кратное p число даёт месяц 1
  (тест 10);
- равные зарплаты не образуют запрещённую тройку, только строго
  возрастающие;
- количества с самого начала хранятся по модулю p, ведь само C
  астрономически велико.

Решение на Python отправляется под PyPy: локальный запуск CPython
занимает около 3 с при n = 1000 и k = 200, больше предела в 2 с.

Ответы совпадают с подсчётом по всем последовательностям зарплат при
n ≤ 6 и k ≤ 5 и с независимой принятой реализацией.
