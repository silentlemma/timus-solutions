# 1658. Сумма цифр

[Timus 1658](https://acm.timus.ru/problem.aspx?space=1&num=1658) · сложность 203 · dp

Автор оригинальной задачи — Владимир Яковлев (идея — Станислав Васильев); четвертьфинал Восточного подрегиона NEERC 2008.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для каждого из t запросов по сумме s₁ цифр положительного целого числа и
сумме s₂ их квадратов нужно вывести наименьшее такое число или
`No solution`, если среди чисел не длиннее 100 цифр его нет.

## Входные данные

t (не больше 10000), затем t пар s₁ s₂ (1 ≤ s₁, s₂ ≤ 10000).

## Выходные данные

Наименьшее число для каждого запроса или `No solution`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4
9 81
12 9
6 10
7 9
```

Вывод:

```
9
No solution
1122
111112
```

## Решение

У наименьшего числа меньше всего цифр, а среди таких оно — наименьшая
строка. Нулей в нём не бывает: ноль добавляет цифру, не меняя ни одной
суммы, так что число не было бы кратчайшим. При не более чем 100 цифрах
суммы не превосходят 900 и 8100, так что для больших запросов ответа нет.

Кроме Python, таблица наименьшего числа ненулевых цифр для каждой пары (s₁, s₂) до
900 × 8100 заполняется за один проход: каждая клетка на единицу больше
лучшей из клеток, получаемых вычитанием цифры d и d². Ответ строится
жадно: первая цифра — наименьшая d, после которой остатку нужно ровно на
одну цифру меньше, и так далее. Цифры получаются отсортированными, так
что каждый поиск можно начинать с предыдущей цифры. `O(S₁ · S₂ · 9)` на
таблицу и `O(100)` на запрос.

Подводные камни:

- в таблице 7,3 миллиона клеток, поэтому она хранится в байтах;
- сумма квадратов меньше суммы цифр или больше её девятикратной
  невозможна; таблица учитывает это без особых случаев;
- s₁ = 900 и s₂ = 8100 — это сто девяток, на цифру больше уже слишком
  длинно (тест 02).

Ответы совпадают с независимой принятой реализацией на 80 000 запросах.

## Оптимизированные решения

DP по двум моментам цифр хранит только достижимые по границам и паритету состояния вместо прямоугольной таблицы с невозможными суммами. Границы сбалансированных и максимально крупных цифр задают сжатые строки; значения по-прежнему означают минимальное число цифр, восстановление следует допустимым переходам. Python с битовыми множествами объединяет переходы точными сдвигами и OR, без вещественной арифметики. Нормализация убирает нулевое заполнение, не теряя допустимых состояний. Готовая таблица ответов не вводится.

Здесь C — число допустимых сжатых состояний, T — число запросов, K — граница числа цифр; множитель 9 соответствует ненулевым цифрам.
