# 1658. 数字之和

[Timus 1658](https://acm.timus.ru/problem.aspx?space=1&num=1658) · 难度 203 · dp

原题作者 Vladimir Yakovlev（创意来自 Stanislav Vasilyev），出自 NEERC 2008 东部分区四分之一决赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

t 个询问，每个给出某正整数各位数字之和 s₁ 和各位数字平方和 s₂，输出满足条件的最小整数；若不超过 100 位的
数中没有，输出 `No solution`。

## 输入

t（不超过 10000），然后 t 对 s₁ s₂（1 ≤ s₁, s₂ ≤ 10000）。

## 输出

每个询问的最小数，或 `No solution`。

## 评测方式

按词元比较输出，多余空白不影响结果。

## 样例

### 样例 1

输入：

```
4
9 81
12 9
6 10
7 9
```

输出：

```
9
No solution
1122
111112
```

## 解法

最小的数位数最少，位数相同时是最小的字符串。它不含 0：0 多占一位却不改变任何一个和，所以就不是最短的。
最多 100 位时两个和分别不超过 900 和 8100，更大的询问无解。

除 Python 外，对 900 × 8100 以内的每一对 (s₁, s₂)，最少非零数字个数的表格一遍即可填好：每格等于减去某个数字 d 及 d²
后到达的最佳格子加一。然后贪心构造答案：第一位取最小的 d，使剩余部分恰好少一位，依此类推。得到的数字是
有序的，所以每次搜索可以从上一位数字开始。建表 `O(S₁ · S₂ · 9)`，每个询问 `O(100)`。

易错点：

- 表格有 730 万格，所以用字节存储；
- 平方和小于数字和或大于其九倍都不可能；表格无需特殊处理即可反映这一点；
- s₁ = 900、s₂ = 8100 是一百个 9，再多一位就太长了（测试 02）。

在 80 000 个询问上，答案与一个独立的已通过实现一致。

## 优化解法

数字矩 DP 只保存满足界限和奇偶性的状态，不分配含大量不可能和的矩形表。均衡数字及最大平方和界限确定压缩行；状态仍表示所需最少数字数目，按合法数字转移恢复。Python 位集用精确移位与 OR 批量处理转移，不用浮点数。归一化去除零填充而不丢失可行状态，不引入预存答案表。

C 是可行压缩状态数，T 是询问数，K 是数字长度上限，因子 9 对应非零数字。
