# 1665. Финансовая пирамида декана

[Timus 1665](https://acm.timus.ru/problem.aspx?space=1&num=1665) · сложность 440 · number_theory

Автор оригинальной задачи — Алексей Самсонов; Ural SU Contest, Петрозаводские зимние сборы, январь 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

К вечеру первого дня на столе лежит одно заявление. Каждый следующий
день число заявлений умножается на целый множитель — 2 или нечётное
число больше 1, — возможно, каждый день разный. Деньги выплачивают
только в чётный день и только если вечером на столе ровно N заявлений.
Для каждого N нужно решить, возможно ли это.

## Входные данные

T (1 ≤ T ≤ 100), затем T чисел N (1 ≤ N ≤ 2²⁵ − 1).

## Выходные данные

`YES` или `NO` для каждого N.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4
4
7
6
30
```

Вывод:

```
NO
YES
NO
YES
```

## Решение

В день d число заявлений — произведение d − 1 множителей, а d должен
быть чётным, так что вопрос в том, раскладывается ли N в произведение
нечётного числа множителей, каждый из которых 2 или нечётное число
больше 1. Запишем N = 2ᵃ · r, r нечётное. Множитель двойку в N вносит
только множитель 2, поэтому таких множителей ровно a, а нечётные дают в
произведении r.

- Если r = 1, множителей ровно a: `YES`, когда a нечётно (N = 1 — это
  первый день, выплаты не будет).
- Если a чётно и r > 1, a двоек и само r дают a + 1 множителей —
  нечётное число: `YES`.
- Если a нечётно, r нужно разбить на чётное число нечётных множителей
  больше 1, а это возможно ровно тогда, когда r не простое (два
  множителя или больше при необходимости): `YES` для составного r,
  `NO` для простого.

Простота проверяется делением на нечётные числа до √r, это не больше
примерно 2900 делителей. `O(T · √N)`.

Подводные камни:

- N = 1 и N = 2ᵃ с чётным a — `NO`; 2ᵃ с нечётным a — `YES` (тест 02);
- степень двойки с нечётным показателем, умноженная на простое, — `NO`
  (6 в примере, 2²³ · 3 в тесте 03).

Ответы совпадают с полным перебором последовательностей множителей для
всех N до 3000 и с независимой принятой реализацией.

## Оптимизированные решения

`1665_number_theory_optimized.java`. Сохраняется классификация по чётности числа множителей. Степень двойки считается numberOfTrailingZeros, нечётная часть получается сдвигом. Чистые степени двойки, чётный показатель и делимость на3 обрабатываются отдельно; пробные делители нужны лишь в оставшемся случае нечётной части. Колесо6k-1/6k+1 проверяется шагами2,4 с условием divisor<=odd/divisor вместо квадрата делителя. Это прежнее решение, не вероятностный тест простоты. Для положительных N<=2^25-1 худшее время O(T sqrt N), состояние O(1) плюс байтовые буферы. Ответы выводятся сразу, без общего StringBuilder.

По сравнению с `1665_number_theory.java`: время 0.14 s → 0.093 s; память 420 KB → 508 KB.

Новый Go сохраняет классификацию по чётности числа множителей, но один раз просеивает нечётные простые для всей пачки. Проверка простоты нужна только при нечётной степени двойки, то есть хотя бы один множитель 2 уже удалён. Остаток меньше 2²⁴, его корень меньше R=4096; у составного остатка обязательно есть делитель в подготовленном списке. Условие p²≤остаток включает квадраты простых. Чистые степени двойки обработаны отдельно; одна заявка первого дня по-прежнему даёт NO. Решето и список 16-битных простых занимают O(R), работа O(R log log R+T·π(R)). Стандартные дескрипторы заменяют fmt. Все обычные исходники сохранены; остальные четыре подходящие базы также закрывают быстрый набор.

Принятые базовые реализации [1665_number_theory.cpp](1665_number_theory.cpp), [1665_number_theory.java](1665_number_theory.java), [1665_number_theory.py](1665_number_theory.py), [1665_number_theory.rs](1665_number_theory.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
