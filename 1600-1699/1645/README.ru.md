# 1645. Лыжная гонка

[Timus 1645](https://acm.timus.ru/problem.aspx?space=1&num=1645) · сложность 200 · fenwick

Авторы оригинальной задачи — Евгений Курпилянский и Алексей Самсонов; осеннее первенство школьников, октябрь 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Лыжники 1…n стартуют друг за другом с интервалом 30 секунд, а итоговая
таблица упорядочивает их по собственному времени. Известен только
порядок финиша. Для каждого лыжника нужно найти самое высокое и самое
низкое возможное место.

## Входные данные

n (1 ≤ n ≤ 2000), затем лыжники в порядке финиша.

## Выходные данные

Для каждого лыжника i — самое высокое и самое низкое возможное место.

## Примеры

### Пример 1

Ввод:

```
6
3 5 1 4 2 6
```

Вывод:

```
3 6
4 6
1 4
2 5
1 3
1 6
```

## Решение

Номер лыжника задаёт порядок старта с интервалом 30 секунд. Относительно
лыжника `i` стартовавший позже, но финишировавший раньше наверняка быстрее;
стартовавший раньше, но финишировавший позже наверняка медленнее. Два
других порядка допускают оба сравнения. Значит, лучшее место равно
`1 + число заведомо более быстрых`, худшее — `n − число заведомо более медленных`.

Докажем достижимость границ одновременно для всех неопределённых
соперников выбранного лыжника. Для лучшего места соберём все прежние
финиши непосредственно перед его финишем, в интервале короче 30 секунд,
а последующие отодвинем более чем на `30n` секунд. Тогда стартовавшие
раньше и финишировавшие раньше окажутся медленнее; стартовавшие позже
и финишировавшие позже — тоже. Для худшего места прежние финиши
отодвигаем более чем на `30n` секунд назад, а последующие собираем
сразу после выбранного в интервале короче 30 секунд. Все неопределённые
соперники станут быстрее. Внутри групп сохраняем строгий порядок финиша;
общая большая прибавка ко всем финишам делает длительности положительными.
Можно выбрать их различными. Конструкция отдельная для каждого лыжника
и границы: одновременное достижение крайних мест всеми лыжниками в одной
гонке не требуется.

Пусть `p=place[i]`, а `e` — число стартовавших и финишировавших раньше
лыжника `i`. Заведомо быстрее `p−1−e` человек, заведомо медленнее —
`i−1−e`. Ответ: `p−e` и `n−i+e+1`.

Обрабатываем лыжников в порядке старта. Дерево Фенвика хранит позиции
финиша ровно прежних стартовавших. Сумма на префиксе до `p−1` даёт `e`;
выводим две границы и лишь затем добавляем `p`. Инвариант и индукция
доказывают правильность всех подсчётов. Время `O(n log n)`, память `O(n)`.
При `n≤2000` индексы и счётчики помещаются в машинное целое. Если порядок
финиша совпал со стартовым, любое место возможно; обратный порядок
определяет места однозначно.

## Проверка

Сравниваются две целочисленные границы для каждого лыжника в порядке
старта. Формулы проверены 10078 точными конструкциями времён гонки:
обе границы для каждого выбранного лыжника во всех перестановках до шести
участников. Длительности положительные и различные, порядок финиша
сохранён: проверена именно достижимость, а не только необходимые
попарные сравнения. Отдельно оба фактических отформатированных C++/Rust
прошли 996 дополнительных входов против прямого подсчёта пар: все 873
перестановки до шести участников, 120 случайных гонок и три максимальные.
Каждый также прошёл 13 входов репозитория в Docker и получил собственный
Accepted для точных байтов. Конструкции времён — математические проверки,
а не 10078 запусков каждой машинной программы.

## Особенности языков

Во всех пяти языках сохранён тот же алгоритм Фенвика. C++ и Rust
изменены ровно форматтером и заново проверены судьёй; в таблице стоят
метрики этих новых Accepted. Исходные байты сохранены в локальной
резервной копии ревизии. Go, Java и Python побайтово совпадают с принятым
архивом. Форматирование не называется оптимизацией, одинаковый
оптимизированный файл не создаётся.

В сохранённом снимке от 2 ноября 2026 года все текущие базы достигли
согласованной рейтинговой цели: C++ — одновременно топ 15% или первые
десять мест по двум метрикам, остальные семейства — первое место по обеим.
Пустая отфильтрованная выборка даёт формальное покрытие, не доказательство
превосходства. Отдельные более простые кандидаты с перебором пар ещё
ждут проверки судьёй и не включены сюда как Accepted.
