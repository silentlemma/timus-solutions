# 1600. Аэропорт

[Timus 1600](https://acm.timus.ru/problem.aspx?space=1&num=1600) · сложность 552 · geometry

Автор оригинальной задачи — Владимир Яковлев; IX открытое личное первенство УрГУ, 1 марта 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

До 500 объектов летят в пространстве прямолинейно с постоянной
скоростью; все начинают дальше друг от друга, чем критическое расстояние
d. Нужно найти первый момент, когда какая-то пара сблизится до
расстояния d, и вывести `ALARM!`, а затем время с тремя знаками и пару,
или `OK`, если этого не случится. Если в этот момент сблизились
несколько пар, можно вывести любую.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

n и d, затем положение и скорость каждого объекта, шесть чисел.

## Выходные данные

`OK` или `ALARM!`, а затем время и номера двух объектов.

## Примеры

### Пример 1

Ввод:

```
2 1.0
1.0 1.0 -1.0 0.0 0.0 10.0
0.0 0.0 4.0 2.0 0.0 0.0
```

Вывод:

```
ALARM!
0.500 1 2
```

## Решение

С точки зрения одного объекта пары другой движется по прямой p + v·t, где
p и v — разности положений и скоростей. Расстояние равно d, когда
|p + v·t|² = d², то есть квадратное уравнение
(v·v)t² + 2(p·v)t + (p·p − d²) = 0. При равных скоростях или
отрицательном дискриминанте пара не сближается. Иначе меньший корень —
момент, когда расстояние впервые становится d; так как все пары
начинают поодаль, отрицательный корень значит, что они разлетаются.
Самый ранний момент по всем парам и есть ответ: `O(n²)`, около 125000
пар.

Тесты проверяет чекер, который принимает любую пару, сблизившуюся в
нужный момент, с учётом округления до трёх знаков. Времена сверены с
бисекцией по расстоянию до момента наибольшего сближения.

Подводные камни:

- пара, которая лишь касается расстояния d в момент наибольшего
  сближения, всё равно вызывает тревогу: дискриминант тогда ровно 0
  (тест 04);
- при крошечной относительной скорости время бывает большим, почти
  10⁶ секунд в тесте 07, так что заранее его ограничивать нельзя;
- с половинным дискриминантом, b = p·v и b² − a·c, не нужно таскать
  множитель 4.

Простая версия на C++ приводит десятичные данные к целым числам и вычисляет знак дискриминанта точно. Простая версия на Java приводит десятичные данные к целым числам и вычисляет знак дискриминанта точно.

Простая версия на Rust приводит десятичные данные к целым числам и вычисляет знак дискриминанта точно.

## Оптимизированные решения

`1600_geometry_optimized.cpp`. Сохраняются перебор всех пар, точное отсечение на сетке сотых, устойчивая формула векторного произведения, быстрый double и quad-перепроверка около касания. Меняется только разбор scanf на fread-читатель 4096 байт и токены до 127 символов; они поступают в тот же десятичный парсер. Точность и допуск столкновений не ослабляются. O(N²) обработки пар, O(N) объектов и фиксированный ввод. Простая версия и обе Python-альтернативы времени/памяти сохранены. Новая пара C++ — 0.015 с/264 КБ, прежняя — 0.031 с/256 КБ.

Точный исходник: G++ 13.2 x64 Accepted #11327842: 0.015 s / 264 KB. Сохранённые места в группе компилятора от 2026-11-20, время затем память: 1/46; 5/46. Строгий допуск учитывает только время при памяти меньше 1024 КБ: первые десять или топ 15%, равенства делят место, процентный порог округляется вверх. Отдельная цель C++ по обеим метрикам пройдена, звёздочка не нужна. Сохранённый прежний вариант имеет собственную парную посылку #11321905 (G++ 13.2 x64): 0.031 s / 256 KB; замеры и рантаймы не смешиваются. Все учебные исходники сохранены без изменений.

- `1600_geometry_optimized.cpp`: 0.015 s / 264 KB; сохранённая учебная база `1600_geometry.cpp`: 0.328 s / 664 KB.

Python сортирует объекты по координате x и отбрасывает пары, которые по этой оси не могут сблизиться до критического расстояния. После обнаружения сближения целая верхняя граница его времени ограничивает перебор. Знак дискриминанта для оставшихся пар вычисляется точно. Python 3.12 x64, посылка 11322507. Время 0,203 → 0,078 с, память 1492 → 1084 КБ.

Версия Python с меньшим расходом памяти перебирает все пары и пропускает те, которые удаляются друг от друга. Формула времени входа `c / (−b + √(b² − ac))` позволяет избежать вычитания близких чисел. Посылка 11316939 заняла 0,156 с и использовала 764 КБ. Версия с сортировкой по x проверяет меньше пар и заняла 0,078 с при 1084 КБ. По сравнению с простой версией перебор пар экономит 48,8% памяти, а сортировка по x сокращает время на 61,6%.

Посылка Java №11321903 заняла 0,125 с и использовала 1780 КБ. Текущая простая версия заняла 0,281 с и использовала 7020 КБ.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11322335 · Go 1.14 x64 №11322334 · Java 1.8 №11322333 · Python 3.12 x64 №11322332 · Rust 1.75 x64 №11322336.

Go пропускает удаляющиеся пары. Для пар вблизи касания дискриминант пересчитывается из исходных десятичных чисел рациональной арифметикой, после чего применяется устойчивая формула времени сближения.

Историческое описание и замеры прежней ревизии: C++ вычисляет минимальное расстояние через векторное произведение и перепроверяет случаи вблизи касания в четверной точности.

Rust приводит десятичный ввод к целым числам. Если каждое значение после масштабирования не превосходит по модулю 500 000 000, дискриминант точно вычисляется в 128-битных целых. Для остальных входов используется длинная арифметика.
