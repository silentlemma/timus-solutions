# 1607. Такси

[Timus 1607](https://acm.timus.ru/problem.aspx?space=1&num=1607) · сложность 46 · implementation

Автор оригинальной задачи — Денис Мусин; IX открытое личное первенство УрГУ, 1 марта 2008 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Петя торгуется с таксистом. Петя начинает с a и каждый раз повышает
цену на b; таксист начинает с c и каждый раз снижает на d; говорят по
очереди, первым Петя. Никто не называет цену за чужой ценой: таксист
соглашается с Петиной ценой вместо того, чтобы просить меньше, и Петя
соглашается с ценой таксиста вместо того, чтобы предложить больше.
Сколько заплатит Петя? Все числа от 1 до 10000.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

a, b, c и d.

## Выходные данные

Цена поездки.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
150 50 1000 100
```

Вывод:

```
450
```

## Решение

Разыграем торг. Если a уже не меньше c, таксист соглашается. Иначе Петя
повышает на b; если это дошло до цены таксиста, Петя с ней соглашается.
Потом таксист снижает на d; если это дошло до Петиного предложения,
таксист соглашается с ним. Разрыв за раунд сокращается хотя бы на 2,
так что раундов не больше примерно 5000: `O(max(1, c - a))`. Результаты
сверены с независимой реализацией на 800 случайных входах.

Подводные камни:

- та сторона, что перешла бы чужую цену, уступает по чужой цене, так что
  ответ — всегда реально названная цена (тесты 04 и 05);
- Петя может начать выше цены таксиста; тогда торга нет, и Петя платит
  a (тест 02).

## Оптимизированные решения

`1607_math.java`. Попеременные предложения заменены точной формулой за константное время. При a>=c ответ a; иначе q=(c-a-1)//(b+d) полных раундов ещё сохраняют разрыв, а соглашение равно min(a+(q+1)*b,c-q*d). Вычитание единицы исключает равенство при пересечении из пропущенных раундов. Произведения не превышают 19999 при ограничениях ввода. O(1) арифметики и памяти, побайтный ввод и буферный десятичный вывод. Имя math отличает алгоритм от сохранённых implementation-версий моделирования. Сравнение проводится с буквальными переговорами, без вещественных приближений.

Точный исходник: Java 1.8 Accepted #11327420: 0.109 s / 348 KB. Сохранённые места в группе компилятора от 2026-11-20, время затем память: 48/411; 4/411. Строгий допуск учитывает только время при памяти меньше 1024 КБ: первые десять или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка — первого места по обеим метрикам. Сохранённый прежний вариант имеет собственную парную посылку #11303763 (Java 1.8): 0.125 s / 316 KB; замеры и рантаймы не смешиваются. Все учебные исходники сохранены без изменений.

- `1607_math.java`: 0.109 s / 348 KB; сохранённая учебная база `1607_implementation.java` (Java 1.8): 0.14 s / 1600 KB.

`1607_math.py` используется побайтово без изменений, без второго исходника и нового алгоритма. Accepted точного исходника на CPython 3.12 №11327029: 0.078 с / 692 КБ. Сохранённая выборка актуальных компиляторов семейства Python от 2026-11-20: место по времени 4/97, по памяти 62/97. Поскольку здесь меньше 1024 КБ, строгий критерий первых десяти мест или топ 15% учитывает только время; звёздочка сохраняет отдельную рейтинговую цель языка. У того же файла есть прежний Accepted на PyPy 3.10 №11324835: 0.156 с / 200 КБ. Это парные замеры разных запусков: CPython даёт выбранный результат по времени и рейтингу, PyPy расходует меньше памяти. Прежние замечания об экономии памяти в этом разделе относятся к этому замеру PyPy, а не к строке CPython. Все учебные исходники сохранены без изменений.

Оптимизированное решение на Java разбирает числа побайтно из `System.in`
вместо `Scanner`: 316 КБ вместо 1600 КБ при том же времени.

`1607_math.py`. Пошаговый торг заменяется формулой. При a>=c возвращаем a. Иначе q=(c-a-1)//(b+d) — число полных раундов, после которых стороны ещё не сошлись; следующее предложение или ответ даёт min(a+(q+1)*b,c-q*d). Положительные b,d обеспечивают допустимость деления. Это вариант math, исходник с симуляцией сохраняется отдельно. O(1) времени и памяти ограниченной целочисленной арифметики. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1607_implementation.py`: время 0.093 s → 0.156 s; память 416 KB → 200 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Прежнее сравнение PyPy: `1607_math.py`: место по времени 97/97, по памяти 1/97 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
