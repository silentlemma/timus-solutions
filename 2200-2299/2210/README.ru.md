# 2210. Больше всего денег за T дней работы и покупок предприятий

[Timus 2210](https://acm.timus.ru/problem.aspx?space=1&num=2210) · сложность 1161 · dp

Автор оригинальной задачи — Валентин Зуев; Вузовско-академическая олимпиада по информатике 2023.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый день игрок либо работает за 1 монету, либо покупает одно
предприятие одного из N видов, которое стоит Aᵢ и приносит Bᵢ монет в
день начиная со следующего дня; затем выплачивается доход с купленных
раньше предприятий. Для каждой из Q длительностей T найдите наибольшее
число монет после T дней, если начать с нуля. Ограничения: 2 секунды и
256 МБ.

## Входные данные

N, 1 ≤ N ≤ 100, затем пары Aᵢ, Bᵢ от 1 до 100, затем Q,
1 ≤ Q ≤ 5 · 10⁴, и длительности 1 ≤ T ≤ 10⁸.

## Выходные данные

Наибольшая сумма для каждого T.

## Примеры

### Пример 1

Ввод:

```
1
1 100
1
5
```

Вывод:

```
401
```

### Пример 2

Ввод:

```
2
1 1
4 10
1
8
```

Вывод:

```
42
```

## Решение

Важны только виды, приносящие больше любого более дешёвого вида, так что
они образуют список с растущими ценой и доходом, который кончается самым
дорогим видом с ценой C и доходом I.

Состояние — (доход, деньги). За день можно работать или купить
доступный вид, а состояние, у которого и доход, и деньги не больше, чем
у другого, отбрасывается, так что каждый день остаётся короткая лесенка
состояний. Динамика идёт по дням с двумя выходами:

- **Дальше только работать.** Состояние (r, m) в день d, которое дальше
  только работает, заканчивает с m + (r + 1)(T − d) — прямая по T.
  Каждое состояние добавляет такую прямую.
- **Богатые состояния.** Когда и доход, и деньги не меньше C, деньги
  больше ничего не ограничивают, и покупать как можно раньше не хуже.
  Тогда каждый оставшийся день независимо выбирает лучшее из работы
  (1 монета) и покупки вида, больше всего приносящего за оставшиеся
  k дней, — Bk − A. Начиная с C + 1 оставшегося дня это всегда верхний
  вид, Ik − C, так что после фиксированного начала сумма — квадратичная
  функция T, у которой часть с T² одинакова для всех богатых состояний.
  Если её убрать, у каждого богатого состояния остаётся одна прямая.

Небогатые состояния продолжают работать или покупать, и цикл кончается,
когда все состояния стали богатыми, — в худших случаях это занимает
несколько сотен дней. Небольшие T до
этого момента берутся из таблицы, а большие — как лучшее значение по
прямым работы и по прямым богатых состояний, каждые из которых хранятся
верхней выпуклой оболочкой с двоичным поиском.

В первом примере (тест 01) оптимальные действия — работать, купить,
работать, купить, работать. После каждого дня остаётся 1, 0, 101, 200,
401 монета. Ловушка — слишком ранняя покупка: при нулевой начальной
сумме купить в первый день нельзя, а новое предприятие приносит доход
только со следующего дня.

Динамика держит не больше C + 2I + 1 ≤ 301 состояния в день несколько
сотен дней, а каждый запрос стоит O(log).
