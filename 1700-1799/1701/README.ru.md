# 1701. Остап и партнёры

[Timus 1701](https://acm.timus.ru/problem.aspx?space=1&num=1701) · сложность 639 · dsu

Автор оригинальной задачи — Дмитрий Иванков; XIII чемпионат Урала по спортивному программированию, 4 апреля 2009 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В блокноте записаны утверждения «сотрудник i получает на d больше
сотрудника j». Сотрудник 0, Василий, получает 0, и никто больше не
получает больше 10⁹ (или меньше 0). Найти зарплаты, подходящие под все
утверждения, или номер первого утверждения, которое не удаётся
выполнить вместе с предыдущими.

## Входные данные

n и m (1 ≤ n, m ≤ 50000), затем m утверждений i j d
(0 ≤ i, j < n; |d| ≤ 20000).

## Выходные данные

Possible и n зарплат или «Impossible after i statements». Подходят любые
верные зарплаты.

## Примеры

### Пример 1

Ввод:

```
5 6
3 4 1200
4 1 -5500
2 3 4300
3 0 8200
0 4 -7000
2 1 0
```

Вывод:

```
Possible
0
12500
12500
8200
7000
```

### Пример 2

Ввод:

```
3 5
1 2 5
0 2 0
1 0 -5
1 2 5
2 2 0
```

Вывод:

```
Impossible after 3 statements
```

### Пример 3

Ввод:

```
3 2
1 0 871
1 2 903
```

Вывод:

```
Impossible after 2 statements
```

## Решение

Обрабатываем утверждения по порядку системой непересекающихся множеств
с весами. Каждый сотрудник хранит разницу между своей зарплатой и
зарплатой родителя, так что после сжатия пути
salary(x) = salary(root) + offset(x). Каждое множество также хранит
диапазон значений, которые может принять зарплата его корня, чтобы все
его зарплаты оставались в 0 … 10⁹. Множество Василия начинается с
единственного значения 0.

Утверждение salary(i) − salary(j) = d внутри одного множества должно
согласоваться со смещениями. Между двумя множествами оно задаёт
salary(rⱼ) = salary(rᵢ) + shift. Диапазон объединённого корня — старый
диапазон, пересечённый с диапазоном другого корня, сдвинутым на
−shift, и пустой диапазон означает, что утверждение всё ломает. В
конце каждый корень берёт наименьшее значение своего диапазона, а все
зарплаты следуют из смещений. `O((n + m) α(n))`.

Подводные камни:

- утверждение может противоречить только границам, а не другим
  утверждениям: в третьем примере второе утверждение делает зарплату
  отрицательной;
- утверждение может сравнивать сотрудника с ним самим, и тогда d должно
  быть 0 (тест 05);
- верхняя граница здесь никогда не срабатывает: |d| ≤ 20000 и не больше
  49999 связей держат любую разницу ниже 10⁹, а нижняя срабатывает;
- поиск корня сжимает пути без рекурсии; объединение по размеру
  сохраняет небольшую глубину деревьев.

Чекер проверяет 0 у Василия, диапазоны и каждое утверждение или точную
строку Impossible; независимая принятая реализация проходит его на тех
же тестах.

## Оптимизированные решения

Версия C++ хранит одну запись на сотрудника. У корня поле родителя содержит размер компоненты со знаком минус, у остальных — индекс родителя. Сжатие пути накапливает разность зарплат до корня, а объединение по размеру ограничивает глубину рекурсии. Байтовый буфер читает сравнения без создания строк для чисел. Время O((n + m) α(n)), память O(n). Метрики взяты из посылки 11316975.

Версия Python читает утверждения построчно и при поиске корня поднимает вершину к деду, сохраняя разность зарплат. В памяти остаются данные компонент и зарплаты для вывода. Память O(n). Метрики взяты из посылки 11317043.

Rust читает по одному сравнению и переиспользует буфер строки. Запись системы непересекающихся множеств хранит родителя или отрицательный размер, смещение до родителя и допустимый диапазон зарплаты для корня. Посылка 11317269 заняла 0,046 с и 992 КБ против 0,031 с и 5152 КБ у базы.

Go разбирает сравнения побайтово из буфера. Взвешенная система непересекающихся множеств хранит четыре 32-битных числа на сотрудника и выводит зарплаты через переиспользуемый буфер цифр. Посылка 11317271 заняла 0,015 с и 1712 КБ против 0,109 с и 5968 КБ у базы.

Java разбирает сравнения из байтового буфера и хранит данные системы непересекающихся множеств в четырёх целочисленных массивах. Для вывода зарплат переиспользуется буфер цифр. Посылка 11317272 заняла 0,125 с и 1320 КБ против 0,14 с и 6400 КБ у базы.
