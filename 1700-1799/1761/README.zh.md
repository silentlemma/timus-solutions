# 1761. 二进制回文

[Timus 1761](https://acm.timus.ru/problem.aspx?space=1&num=1761) · 难度 1091 · strings

原题作者 Ilya Zvigintsev，出自 2010 年 3 月 13 日第十一届乌拉尔国立大学公开个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

把 1 到 n 的二进制表示依次连写。求所得 0/1 串中最长回文子串的长度。

## 输入

二进制形式的 n（1 ≤ n ≤ 2¹⁰⁰⁰⁰⁰⁰），即至多一百万零一位。

## 输出

最长回文的长度。

## 样例

### 样例 1

输入：

```
101
```

输出：

```
5
```

### 样例 2

输入：

```
10100
```

输出：

```
11
```

## 解法

设 n 有 k 位二进制数字。三个相邻的 k 位数组成一个回文：2^(k−1) + 5 = 1 0…0 101，然后 2^(k−1) + 6 = 1 0…0 110，
再取 2^(k−1) + 7 = 1 0…0 111 的前 k − 2 位，即 1 0…0 1，其中每个 0…0 有 k − 4 个零。
连写得到的 1 0…0 1011 0…0 1101 0…0 1 正反读相同，共 3k − 2 位。只要 n 达到 2^(k−1) + 7 它就出现，
这等价于最高位之后、最后三位之前某处有 1，或者最后三位全是 1。否则，短一位的同样模式给出 3(k − 1) − 2。

不存在更长的回文在这里是验证而非证明的：用 Manacher 算法在整个串上求出的最长回文，对所有不超过 300 的 n 与公式一致；
又因为添加数字只会让它变长，对 6 到 20 的每个 k，在答案相同的每段 n 的两端也与公式一致。n 小于 32 时这一模式还不成立，串很短，可以直接搜索。
全部工作就是读入数字：`O(k)`。

n = 39 = 100111 时串以 100101 100110 100111 结尾，1001011001101001 就是长为 16 = 3·6 − 2 的回文。

注意事项：

- n 至多一百万零一位，所以从不把它转成数；
- 从 3k − 5 跳到 3k − 2 发生在 2^(k−1) + 7，而不是 2^(k−1)；
- 小于 32 时公式不成立，例如 n = 20 的答案是 11 而不是 10。
- 上界限制的是数值：一百万零一位的合法输入只能是 1 后接一百万个 0。
  因此测试 gen5、gen6 和 gen7 使用一百万位，使阈值附近及随机用例都满足限制。

生成器原先为测试 gen5、gen6 和 gen7 生成了超出范围的输入。位数减少一位后仍保留这些测试的目的；
解法及其 `O(k)` 复杂度不变。
