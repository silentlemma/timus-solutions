# 1761. Двоичный палиндром

[Timus 1761](https://acm.timus.ru/problem.aspx?space=1&num=1761) · сложность 1091 · strings

Автор оригинальной задачи — Илья Звигинцев; XI открытое личное первенство УрГУ, 13 марта 2010 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Выписать подряд числа от 1 до n в двоичной записи. Найти длину самого
длинного палиндрома в получившейся строке из нулей и единиц.

## Входные данные

n в двоичной записи (1 ≤ n ≤ 2¹⁰⁰⁰⁰⁰⁰), то есть до миллиона и одной
цифры.

## Выходные данные

Длина самого длинного палиндрома.

## Примеры

### Пример 1

Ввод:

```
101
```

Вывод:

```
5
```

### Пример 2

Ввод:

```
10100
```

Вывод:

```
11
```

## Решение

Пусть в n k двоичных цифр. Три подряд числа из k цифр дают палиндром:
2^(k−1) + 5 = 1 0…0 101, затем 2^(k−1) + 6 = 1 0…0 110, затем первые
k − 2 цифры числа 2^(k−1) + 7 = 1 0…0 111, то есть 1 0…0 1, где в каждом
0…0 по k − 4 нуля. Выписанная строка 1 0…0 1011 0…0 1101 0…0 1 читается
одинаково в обе стороны и имеет 3k − 2 цифры. Она есть, как только n
доходит до 2^(k−1) + 7, а это так, если после старшей цифры где-то до
трёх последних встречается единица или эти три цифры все единицы.
Иначе тот же узор на одну длину короче даёт 3(k − 1) − 2.

Что длиннее не бывает, здесь проверено, а не доказано: самый длинный
палиндром, найденный алгоритмом Манакера по всей строке, совпадает с
формулой для всех n до 300, а поскольку добавление чисел может только
удлинить его, — и на обоих концах каждого отрезка n с одним ответом для
всех k от 6 до 20. До 32 узор ещё не работает, и строка достаточно
коротка для прямого поиска. Вся работа — прочитать цифры: `O(k)`.

При n = 39 = 100111 строка заканчивается на 100101 100110 100111, и
1001011001101001 — палиндром из 16 = 3·6 − 2 цифр.

Подводные камни:

- в n до миллиона и одной цифры, поэтому оно никогда не превращается в число;
- скачок с 3k − 5 до 3k − 2 происходит на 2^(k−1) + 7, а не на 2^(k−1);
- до 32 формула не работает, например при n = 20 ответ 11, а не 10.
- ограничение числовое: из записей длиной миллион и одна цифра допустима
  только единица с миллионом нулей. Поэтому тесты gen5, gen6 и gen7
  используют миллион цифр, сохраняя пороговые и случайные случаи в пределах ограничения.

Раньше генератор создавал недопустимые входы для тестов gen5, gen6 и gen7.
Уменьшение длины на одну цифру сохраняет их назначение;
алгоритм решений и его сложность `O(k)` не изменились.
