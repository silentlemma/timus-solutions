## Задача

n записей переписаны в одном и том же порядке в два блокнота: по a на
страницу в первом и по b во втором. Посчитать пары записей, которые в
первом блокноте на одной странице, а во втором — на разных.

## Входные данные

a, b и n (1 ≤ a, b ≤ n ≤ 25 000 000).

## Выходные данные

Число таких пар.

## Примеры

### Пример 1

Ввод:

```
3 4 10
```

Вывод:

```
4
```

### Пример 2

Ввод:

```
2 4 10
```

Вывод:

```
0
```

## Решение

Ответ — пары на одной странице первого блокнота, n div a полных страниц
по C(a, 2) пар плюс C(n mod a, 2), минус пары на одной странице обоих.
Границы страниц обоих блокнотов режут ряд на куски, и пары на одной
странице обоих — это сумма C(len, 2) по кускам.

Эта сумма берётся по страницам блокнота с большими страницами: каждую
такую страницу меньшие режут на начало, несколько целых малых страниц и
хвост, что стоит O(1) на большую страницу. Границы страниц обоих
блокнотов повторяются каждые L = lcm(a, b) записей, поэтому при L ≤ n
сумма за один период умножается на n div L и добавляется остаток. В
любом случае обходится не больше примерно √n больших страниц: при L ≤ n
их в периоде L / max(a, b) = min(a, b) / gcd(a, b), не больше √L, а при
L > n выполнено max(a, b) > √n. Итого `O(√n)`.

В первом примере страницы по 3 дают по 3 пары, всего 9, а границы в 3,
4, 6, 8 и 9 режут ряд на куски из 3, 1, 2, 2, 1 и 1 записей с 5 парами:
9 − 5 = 4.

Подводные камни:

- ответ доходит примерно до 3·10¹⁴, больше 32 бит;
- обход всех n записей слишком медленный в некоторых языках, а обход
  всех страниц меньшего размера — когда они совсем маленькие;
- lcm(a, b) доходит до 6·10¹⁴, поэтому считается как a / gcd · b в 64
  битах.

Ответы совпадают с попарным подсчётом на 300 маленьких случаях, с
линейным подсчётом на 60 побольше и с независимой принятой реализацией
на 100 случаях до предельных значений.
