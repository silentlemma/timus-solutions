# 1741. 社交狂人

[Timus 1741](https://acm.timus.ru/problem.aspx?space=1&num=1741) · 难度 289 · dp

原题作者 Alex Samsonov（由 Marina Mukhacheva 准备），出自第十四届乌拉尔国立大学公开团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

需要把版本 1 的正版客户端升级到版本 n。每个更新把版本 x 升到版本 y > x，并有一定大小。
盗版更新会让客户端永远变成盗版；破解更新可以装在任何客户端上；正版更新只能装在仍是正版的客户端上。
求更新的最小总大小，或者报告无法到达版本 n。

## 输入

n 和 m（2 ≤ n ≤ 10⁴，1 ≤ m ≤ 10⁴），然后是 m 个更新 `x y d s`（1 ≤ x < y ≤ n，1 ≤ d ≤ 10⁶），
其中 s 为 `Pirated`、`Cracked` 或 `Licensed`。

## 输出

`Online` 和最小总大小，或者 `Offline`。

## 评测方式

按词元比较输出，多余空白不影响结果。

## 样例

### 样例 1

输入：

```
3 4
1 3 10 Licensed
1 2 2 Pirated
2 3 3 Licensed
2 3 6 Cracked
```

输出：

```
Online
8
```

### 样例 2

输入：

```
3 1
1 2 10 Licensed
```

输出：

```
Offline
```

## 解法

更新只会提高版本，所以可以按版本递增的顺序处理，每个版本都在所有通向它的版本之后处理。
状态是版本以及客户端仍是正版还是已经盗版。从每个已到达的状态出发，盗版更新通向目标版本的盗版状态，
破解更新保持状态，正版更新只能从正版状态出发。答案是版本 n 的两个值中较小者。`O(n + m)`。

样例 1 中盗版的 1 → 2（大小 2）加破解的 2 → 3（大小 6）得 8，比正版的 1 → 3（大小 10）便宜；
正版的 2 → 3（大小 3）不能接在盗版更新之后。

注意事项：

- 总和可达约 10¹⁰，超过 32 位能存的范围；
- 破解更新让正版客户端保持正版；
- 版本 n 最终是否正版无关紧要。

在 200 个随机数据上，答案与一个独立的已通过实现（最短路搜索）一致。

## 优化解法

`1741_dp_optimized.go`. 保留 DAG 双状态 DP：零表示仍有许可，一表示盗版。每条更新都指向更大版本，因此递增处理；P 进入状态一，C 保持状态，状态一不能使用 L。用扁平链式前向星数组保存边：端点和链接 int32，类型 byte，权重 int64，替代嵌套的带填充结构切片。路径总大小可能超 32 位，故代价保持 int64。三个规定单词首字母互异，解析首字母即可区分，但仍消费整个记号。含初始化的时间和空间均为 O(n+m)。 可移植的 os.Stdin.Read/os.Stdout.Write 与直接整数转换使用各 4096 字节的固定输入输出缓冲区。重复使用输出缓冲区前会处理部分写入。保留原有简单 Accepted 版本。

与 `1741_dp.go` 相比：时间 0.046 s → 0.031 s；内存 3284 KB → 1 184 KB。

保留按递增版本处理的 DAG DP，状态为正版或盗版。扁平边数组代替逐顶点容器及边对象。盗版更新把两状态的较小值只转入盗版；破解更新分别保持状态，正版更新仅接受正版。每条更新只按类型分支一次。路径费用用 64 位，顶点编号和边字段可紧凑存储。不需要优先队列或 Dijkstra。
