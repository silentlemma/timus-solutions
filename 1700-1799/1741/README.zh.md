# 1741. 社交狂人

[Timus 1741](https://acm.timus.ru/problem.aspx?space=1&num=1741) · 难度 289 · dp

原题作者 Alex Samsonov（由 Marina Mukhacheva 准备），出自第十四届乌拉尔国立大学公开团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

需要把版本 1 的正版客户端升级到版本 n。每个更新把版本 x 升到版本 y > x，并有一定大小。
盗版更新会让客户端永远变成盗版；破解更新可以装在任何客户端上；正版更新只能装在仍是正版的客户端上。
求更新的最小总大小，或者报告无法到达版本 n。

## 输入

n 和 m（2 ≤ n ≤ 10⁴，1 ≤ m ≤ 10⁴），然后是 m 个更新 `x y d s`（1 ≤ x < y ≤ n，1 ≤ d ≤ 10⁶），
其中 s 为 `Pirated`、`Cracked` 或 `Licensed`。

## 输出

`Online` 和最小总大小，或者 `Offline`。

## 样例

### 样例 1

输入：

```
3 4
1 3 10 Licensed
1 2 2 Pirated
2 3 3 Licensed
2 3 6 Cracked
```

输出：

```
Online
8
```

### 样例 2

输入：

```
3 1
1 2 10 Licensed
```

输出：

```
Offline
```

## 解法

更新只会提高版本，所以可以按版本递增的顺序处理，每个版本都在所有通向它的版本之后处理。
状态是版本以及客户端仍是正版还是已经盗版。从每个已到达的状态出发，盗版更新通向目标版本的盗版状态，
破解更新保持状态，正版更新只能从正版状态出发。答案是版本 n 的两个值中较小者。`O(n + m)`。

样例 1 中盗版的 1 → 2（大小 2）加破解的 2 → 3（大小 6）得 8，比正版的 1 → 3（大小 10）便宜；
正版的 2 → 3（大小 3）不能接在盗版更新之后。

注意事项：

- 总和可达约 10¹⁰，超过 32 位能存的范围；
- 破解更新让正版客户端保持正版；
- 版本 n 最终是否正版无关紧要。

在 200 个随机数据上，答案与一个独立的已通过实现（最短路搜索）一致。
