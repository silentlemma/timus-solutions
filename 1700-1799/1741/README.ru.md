# 1741. Монстр общения

## Задача

Лицензионный клиент версии 1 нужно довести до версии n. Каждое
обновление переводит версию x в версию y > x и имеет размер. Пиратское
обновление навсегда делает клиент пиратским; взломанное ставится на
любой клиент; лицензионное — только на клиент, который ещё
лицензионный. Найти наименьший суммарный размер обновлений или
сообщить, что версии n не достичь.

## Входные данные

n и m (2 ≤ n ≤ 10⁴, 1 ≤ m ≤ 10⁴), затем m обновлений `x y d s`
(1 ≤ x < y ≤ n, 1 ≤ d ≤ 10⁶), где s — `Pirated`, `Cracked` или
`Licensed`.

## Выходные данные

`Online` и наименьший суммарный размер или `Offline`.

## Примеры

### Пример 1

Ввод:

```
3 4
1 3 10 Licensed
1 2 2 Pirated
2 3 3 Licensed
2 3 6 Cracked
```

Вывод:

```
Online
8
```

### Пример 2

Ввод:

```
3 1
1 2 10 Licensed
```

Вывод:

```
Offline
```

## Решение

Обновления только повышают версию, поэтому версии можно обрабатывать по
возрастанию, каждую после всего, что к ней ведёт. Состояние — версия и
то, лицензионный ли ещё клиент или уже пиратский. Из каждого
достигнутого состояния пиратское обновление ведёт в пиратское
состояние своей цели, взломанное сохраняет состояние, а лицензионное
допустимо только из лицензионного. Ответ — меньшее из двух значений у
версии n. `O(n + m)`.

В первом примере пиратское 1 → 2 за 2 и взломанное 2 → 3 за 6 дают 8,
дешевле лицензионного 1 → 3 за 10; лицензионное 2 → 3 за 3 не может идти
после пиратского.

Подводные камни:

- сумма доходит примерно до 10¹⁰, больше, чем вмещают 32 бита;
- взломанное обновление оставляет лицензионный клиент лицензионным;
- неважно, будет ли версия n лицензионной.

Ответы совпадают с независимой принятой реализацией — поиском
кратчайшего пути — на 200 случайных наборах.
