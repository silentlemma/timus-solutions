# 1712. Шифровальная решётка

[Timus 1712](https://acm.timus.ru/problem.aspx?space=1&num=1712) · сложность 86 · implementation

Автор оригинальной задачи — Алексей Самсонов, подготовка — Александр Ипатов; NEERC 2009, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В решётке 4 × 4 вырезаны четыре окошка. Положенная на листок 4 × 4,
она открывает четыре клетки, и в них по порядку чтения пишутся
очередные четыре буквы пароля из 16 букв. Затем решётку поворачивают на
90° по часовой стрелке, и так четыре раза, так что в каждую клетку
попадает ровно одна буква. По решётке в начальном положении и
заполненному листку восстановить пароль.

## Входные данные

Четыре строки решётки, X — окошко, . — бумага, затем четыре строки
листка: латинские буквы обоих регистров.

## Выходные данные

Пароль из 16 букв.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
....
X..X
.X..
...X
Pwoo
Khaa
smrs
odbk
```

Вывод:

```
KamkohobPassword
```

## Решение

Повторим запись. В каждом из четырёх положений соберём буквы под
окошками по строкам и слева направо, затем повернём решётку. Поворот по
часовой стрелке переводит клетку (r, c) в (c, 3 − r), так что в
повёрнутой решётке в (r, c) стоит то, что в старой было в (3 − c, r).
`O(1)`.

Подводные камни:

- в одном положении буквы идут в порядке чтения окошек, а не в том
  порядке, в каком они были найдены в предыдущем положении;
- поворот по часовой стрелке: поворот в другую сторону читает те же
  клетки в другом порядке (в тесте 04 все четыре окошка в одном углу);
- во входе нет пробелов, так что чтение словами работает в любом языке.

Ответы совпадают с независимой принятой реализацией на 300 случайных
правильных решётках.

## Оптимизированные решения

`1712_implementation_optimized.java`. Отверстия решётки кодируются 16-битной маской. Извлечение младшего установленного бита посещает только отверстия в построчном порядке; поворот (r,c) в (c,3-r) вычисляется целыми позициями битов. Четыре допустимых поворота покрывают все шестнадцать клеток и сохраняют порядок пароля. Ввод 64 байта пропускает пробелы, ответ 17 байт включает перевод строки. Для фиксированных 4x4 время и память O(1), таблицы перестановок или ответов нет. Учебный обход решётки сохранён.

Accepted точного исходника Java 1.8 №11327758: 0.093 с / 384 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 4/90, память 7/90. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303503: 0.109 с / 348 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1712_implementation_optimized.java`: 0.093 s / 384 KB; сохранённая учебная база `1712_implementation.java`: 0.14 s / 1568 KB.

`1712_implementation_optimized.py`. Сохраняются четыре поворота решётки по часовой стрелке, но вращаются только координаты отверстий (r,c)->(c,3-r), а не создаются четыре строки решётки на каждом шаге. Перед чтением отверстия сортируются для построчного порядка, байты пароля собираются в bytearray. При фиксированном поле 4×4 время и память ограничены константой; обещание корректной решётки прежнее. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1712_implementation.py`: время 0.078 s → 0.14 s; память 492 KB → 256 KB.

Историческое описание и замеры прежней ревизии: Оптимизированные решения (C++, Java) читают оба квадрата посимвольно в
массивы фиксированного размера 4 × 4, а не словами, и печатают буквы
пароля по мере нахождения (C++) или собирают их в массив из 17 байт
(Java). Java к тому же переиспользует один массив для повёрнутой
решётки, а не выделяет новый на каждый поворот. C++: 84 КБ вместо 348 КБ
при том же времени; Java: 0.109 с вместо 0.140 с и 348 КБ вместо
1568 КБ.

`1712_implementation_optimized.rs`. Решётка и лист представлены фиксированными массивами 4×4. Байты читаются напрямую, видимые клетки каждой ориентации выводятся построчно, маска поворачивается через ещё один фиксированный массив. Четыре ориентации поля фиксированного размера требуют O(1) времени и памяти, без вложенных Vec и накопленного ответа. Rust использует среду выполнения C для ввода-вывода, без целых декодированных строк String и форматирования Rust. Простой принятый исходник сохранён без изменений.

По сравнению с `1712_implementation.rs`: время 0.031 s → 0.046 s; память 236 KB → 52 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1712_implementation_optimized.py`: место по времени 36/43, по памяти 1/43 в этой сопоставимой выборке.

`1712_implementation_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
