# 1740. А олени лучше!

## Задача

Путь до избирательного участка — l км. Олени могут бежать как угодно,
лишь бы любой отрезок длиной k км занимал ровно h часов. Найти
наименьшее и наибольшее возможное время на весь путь.

## Входные данные

Целые l, k и h (1 ≤ k ≤ l ≤ 1000, 1 ≤ h ≤ 1000).

## Выходные данные

Наименьшее и наибольшее время с погрешностью не более 10⁻⁵.

## Проверка

Тесты репозитория сравнивают числовые токены по условию |ответ-эталон| <= 1e-5·max(1,|эталон|), отклоняют бесконечности и NaN, а нечисловые токены сравнивают точно.

## Примеры

### Пример 1

Ввод:

```
30 10 1
```

Вывод:

```
3.00000000 3.00000000
```

## Решение

Пусть t(x) — время, за которое достигается километр x. Любой отрезок в
k км занимает h часов, поэтому t(x + k) = t(x) + h: t растёт на h за
каждые k км плюс часть, повторяющаяся через каждые k км. При l = nk + r
весь путь занимает nh + t(r), а t(r) лежит между t(0) = 0 и t(k) = h.
Олени могут почти не тратить времени на первые r км каждого отрезка или
тратить на них почти всё, поэтому ответы — nh и, если r > 0, (n + 1)h.
`O(1)`.

В примере 30 км — три отрезка по 10 км, в любом случае 3 часа.

Подводные камни:

- если k делит l, оба ответа совпадают;
- времена целые; код выводит их с восемью знаками после запятой.

## Оптимизированные решения

`1740_math_optimized.java`. Сохраняются l=qk+r и точные целые границы qh и (q+[r>0])h. Три целых разбираются через буфер 1024 байта вместо StreamTokenizer и символьного декодирования. Вывод дописывает восемь десятичных нулей без преобразования в float, сохраняя требуемые значения. O(1) арифметики и дополнительной памяти; учебная реализация сохранена.

Accepted точного исходника Java 1.8 №11326958: 0.093 с / 368 КБ. Сохранённое сравнение актуального Java от 2026-11-20: место по времени 4/90, по памяти 1/90. При памяти меньше 1024 КБ строгий критерий учитывает только время.

- `1740_math_optimized.java`: 0.093 s / 368 KB; сохранённая учебная база `1740_math.java`: 0.14 s / 1792 KB; изменение времени -33.6%; изменение памяти -79.5%.

Оптимизированное решение на C++ читает три числа через `scanf` вместо
`std::cin`, так что в программе вовсе нет машинерии `iostream`;
вычисление и вывод те же: {1740_math_optimized.cpp}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1740_math_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +72.28%; база: `1740_math.cpp`.

`1740_math_optimized.py`. Сохраняется разложение по периодам l=q*k+r. Минимальное время равно q*h, максимальное — (q+[r!=0])*h. Оба результата целые и выводятся целочисленными токенами вместо преобразования во float и восьми дробных знаков. Числовая проверка принимает эквивалентные значения. При ограничениях условия произведения не больше 10^6, время и состояние O(1). Частное и остаток получаются divmod, операция десятичного форматирования исключена. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1740_math.py`: время 0.078 s → 0.125 s; память 384 KB → 188 KB.

`1740_math_optimized.rs`. Сохраняется разложение по периодам l=q*k+r. Минимальное время равно q*h, максимальное — (q+[r!=0])*h. Оба результата целые и выводятся целочисленными токенами вместо преобразования во float и восьми дробных знаков. Числовая проверка принимает эквивалентные значения. При ограничениях условия произведения не больше 10^6, время и состояние O(1). Используются частное и остаток i64 и ручной вывод целых вместо f64 и форматирования вещественных чисел Rust. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1740_math.rs`: время 0.046 s → 0.015 s; память 252 KB → 48 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1740_math_optimized.py`: место по времени 22/29, по памяти 1/29 в этой сопоставимой выборке.

`1740_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
