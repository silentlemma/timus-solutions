## Задача

Путь до избирательного участка — l км. Олени могут бежать как угодно,
лишь бы любой отрезок длиной k км занимал ровно h часов. Найти
наименьшее и наибольшее возможное время на весь путь.

## Входные данные

Целые l, k и h (1 ≤ k ≤ l ≤ 1000, 1 ≤ h ≤ 1000).

## Выходные данные

Наименьшее и наибольшее время с погрешностью не более 10⁻⁵.

## Примеры

### Пример 1

Ввод:

```
30 10 1
```

Вывод:

```
3.00000000 3.00000000
```

## Решение

Пусть t(x) — время, за которое достигается километр x. Любой отрезок в
k км занимает h часов, поэтому t(x + k) = t(x) + h: t растёт на h за
каждые k км плюс часть, повторяющаяся через каждые k км. При l = nk + r
весь путь занимает nh + t(r), а t(r) лежит между t(0) = 0 и t(k) = h.
Олени могут почти не тратить времени на первые r км каждого отрезка или
тратить на них почти всё, поэтому ответы — nh и, если r > 0, (n + 1)h.
`O(1)`.

В примере 30 км — три отрезка по 10 км, в любом случае 3 часа.

Подводные камни:

- если k делит l, оба ответа совпадают;
- времена целые; код выводит их с восемью знаками после запятой.

## Оптимизированные решения

Оптимизированное решение на C++ читает три числа через `scanf` вместо
`std::cin`, так что в программе вовсе нет машинерии `iostream`;
вычисление и вывод те же: {1740_math_optimized.cpp}.

Оптимизированное решение на Java читает числа через `StreamTokenizer`
вместо `Scanner` и вовсе не форматирует числа с плавающей точкой: оба
ответа — целые числа не больше 1000 · 1000 = 10⁶, поэтому оно считает их
в `int` и дописывает к каждому `.00000000` вместо вызова `printf` с
`%.8f`, чей форматировщик и данные локали обходятся дороже всей
остальной программы: {1740_math_optimized.java}.
