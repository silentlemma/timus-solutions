# 1723. Книга Сандро

[Timus 1723](https://acm.timus.ru/problem.aspx?space=1&num=1723) · сложность 62 · strings

Автор оригинальной задачи — Иван Бурмистров (подготовка — Ольга Соболева); Уральская региональная командная олимпиада по программированию 2009.

## Задача

Каждая подстрока данного слова — заклинание, а его сила — число его
вхождений в слово, считая перекрывающиеся. Вывести самое сильное
заклинание.

## Входные данные

Непустое слово не длиннее 50 строчных латинских букв.

## Выходные данные

Любое самое сильное заклинание.

## Примеры

### Пример 1

Ввод:

```
tebidohtebidoh
```

Вывод:

```
tebidoh
```

## Решение

Каждое вхождение заклинания начинается с вхождения его первой буквы, и
разные вхождения начинаются в разных местах. Поэтому никакое заклинание
не сильнее своей первой буквы, и самая частая буква — самое сильное
заклинание. `O(n)`.

В примере каждая буква встречается дважды, так что `t` не слабее
`tebidoh`.

Подводные камни:

- вхождения могут перекрываться: `aba` встречается в `abababa` три
  раза, но `a` — четыре;
- подходит любое самое сильное заклинание, поэтому тесты используют
  проверяющую программу.

Проверяющая программа считает вхождения ответа с перекрытиями и
сравнивает их с ожидаемым ответом. Самая частая буква совпадает с
полным перебором всех подстрок на 300 случайных словах.

## Оптимизированные решения

`1723_strings_optimized.java`. Сохраняются подсчёт 26 строчных букв и выбор любой самой частой: она является сильнейшим заклинанием. Длина слова не больше пятидесяти, поэтому знаковые byte-счётчики не переполняются. Максимум обновляется при чтении; буква и перевод строки выводятся двумя байтами. Без хранения слова, Scanner и итогового прохода по частотам. O(N) времени, 26 байтов частот и константное состояние; другая буква с той же частотой допустима.

Accepted точного исходника Java 1.8 №11327830: 0.109 с / 308 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 36/246, память 1/246. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303774: 0.14 с / 348 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1723_strings_optimized.java`: 0.109 s / 308 KB; сохранённая учебная база `1723_strings.java`: 0.125 s / 1556 KB.

Оптимизированное решение на C++ считает буквы по мере чтения через
`getchar`, не сохраняя строку: 84 КБ вместо 352 КБ.

Считаем вхождения каждой строчной буквы встроенным методом подсчёта байтов и берём первую с максимальной частотой. Принятая посылка 11302183 заняла 0,078 с и использовала 392 КБ. Простая версия заняла 0,078 с и использовала 404 КБ.
