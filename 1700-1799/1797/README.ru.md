## Задача

В каждом контесте либо x, либо y задач. Размер тома правильный, если
несколько контестов (хотя бы один) вместе содержат ровно столько
задач. Посчитать правильные размеры от l до r. Случаев до 100.

## Входные данные

Число случаев, затем x, y, l, r для каждого (1 ≤ x, y, l, r ≤ 10¹⁸,
l ≤ r).

## Выходные данные

Для каждого случая — число правильных размеров.

## Примеры

### Пример 1

Ввод:

```
1
4 5 7 13
```

Вывод:

```
5
```

## Решение

Считаем размеры a·x + b·y (a, b ≥ 0, не оба нули) до границы N; ответ —
счёт до r минус счёт до l − 1. Деление x, y и N на g = gcd(x, y) делает
x и y взаимно простыми. Тогда у каждого достижимого размера ровно одна
запись с 0 ≤ b < x, поэтому счёт до N — это сумма по b от 0 до
B = min(x − 1, ⌊N/y⌋) величин ⌊(N − b·y)/x⌋ + 1, минус один за ноль.
Замена i = B − b даёт счёт B + Σ ⌊(y·i + (N − y·B))/x⌋ по i от 0
до B — сумму целых частей, которую евклидово сведение считает за
O(log max(x, y)) шагов: выносим целые части наклона и сдвига, затем
меняем ролями наклон и модуль. При этих границах все промежуточные
вычисления помещаются в 64 бита, хотя для наклон × число + сдвиг код
использует более широкую арифметику. `O(log max(x, y))` на случай.

В примере из четвёрок и пятёрок складываются 8, 9, 10, 12 и 13, а 7 и
11 — нет.

Подводные камни:

- у x и y может быть общий делитель, и тогда считаются только его
  кратные;
- B и диапазон доходят до 10¹⁸, так что сумму по b нельзя пройти
  почленно;
- сумма целых частей использует широкую арифметику: решение на Java
  использует BigInteger, на Go — bits.Mul64 и bits.Div64;
- ноль, пустой набор контестов, размером не считается.

Ответы совпадают с прямым подсчётом достижимых размеров на 3000
маленьких случаях и с независимой принятой реализацией на 4500
больших, включая общие делители, размеры 1 и равные размеры.
