# 1708. Сумма цифр 2

[Timus 1708](https://acm.timus.ru/problem.aspx?space=1&num=1708) · сложность 11130 · math

Автор оригинальной задачи — Владимир Яковлев; XIII чемпионат Урала по спортивному программированию, 4 апреля 2009 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Назовём положительное число в системе с основанием b наименьшим, если
никакое меньшее число не имеет той же суммы цифр и той же суммы
квадратов цифр. Нужно описать все наименьшие числа самым коротким
списком шаблонов. Шаблон состоит из цифр и звёздочек, а звёздочка
разрешает предыдущей цифре повторяться сколько угодно раз, в том числе
ни разу. Каждое число, подходящее под шаблон, должно быть наименьшим, и
каждое наименьшее число должно подходить под какой-то шаблон.

## Входные данные

Основание b, 2 ≤ b ≤ 36.

## Выходные данные

Шаблоны, отсортированные как строки, по одному в строке, с цифрами
1 … 9, A, B, … и без лишних частей: 12*3, а не 12*2*3. Шаблон может
подходить и под пустую строку.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
1*2*
112*3*
12*3*
2*3*
```

## Решение

Обе суммы не зависят от порядка цифр, поэтому в наименьшем числе нет
нулей и цифры не убывают: это мультимножество цифр 1 … b − 1, вектор
количеств. Из двух векторов с равными суммами меньше тот, в котором
меньше цифр. При равной длине смотрим на первую цифру, количества
которой различаются: меньше вектор, где её копий больше. Сравнение
зависит только от разности векторов, так что добавление одних и тех же
цифр к обоим его не меняет.

Если вычеркнуть из наименьшего числа цифры, снова получится наименьшее,
поэтому наименьшие векторы — ровно те, что не лежат выше ни одного из
минимальных ненаименьших векторов; ниже они называются запрещёнными.
Чтобы их найти, для каждой пары (сумма, сумма квадратов), достижимой не
более чем 15 цифрами, вычислим её наименьший вектор. Будем дописывать
цифры по возрастанию и хранить для пары только лучшее слово: по
замечанию выше лучшее остаётся лучшим после любого продолжения.
Запрещённый вектор без своей наибольшей цифры наименьший, значит, он
получается дописыванием одной цифры в конец наименьшего слова.
Удлинённое слово запрещено, если оно не наименьшее для своей пары, а
каждое слово на одну цифру короче — наименьшее. Для основания 36
получается около 720000 пар и 25000 запрещённых векторов. Ни один не
длиннее 15 цифр, и поднятие предела до 17 не находит новых.

Шаблоны строятся рекурсией по последней цифре. Пусть G — множество
запрещённых векторов над цифрами 1 … n, а t — наибольшее количество
цифры n в G. При k < t копиях префикс должен избегать векторов из G, где
копий не больше k, с удалённой цифрой n и оставленными лишь минимальными.
При t копиях и больше префикс должен избегать их всех, и этот случай
становится звёздочкой. Значит, шаблоны — это шаблоны случая со
звёздочкой с дописанным n*, и для каждого k < t шаблоны его случая с
дописанными k копиями. Шаблоны префиксов, которые и так всё избегают,
там отбрасываются: их покрывает звёздочка. Эти множества растут с k.
Так как в G только минимальные векторы, новичок никогда не лежит выше
старого, поэтому каждый шаг лишь выкидывает старые векторы, лежащие
выше какого-то новичка. Одни и те же множества встречаются часто, так
что результаты запоминаются. Шаблоны хранятся в боре из узлов
(родитель, количество), а результат одного множества — несколько
отрезков подряд идущих узлов. Для основания 36 выходит около 2,1
миллиона узлов и 47062 шаблона.

Подводные камни:

- ограничение памяти 64 МБ: наименьшие слова хранятся компактно в
  хеш-таблице с открытой адресацией, которая освобождается до построения
  шаблонов;
- самая частая проверка — лежит ли вектор выше одного из многих других:
  другие сгруппированы по множествам ненулевых количеств, и проверяются
  только группы внутри множества проверяемого вектора;
- у основания 2 единственный шаблон 1*, а основание 36 выводит около
  325 КБ;
- решение на Python под PyPy тратит здесь на основание 36 около 16 с и
  несколько сотен МБ. Оно проходит все здешние тесты и оставлено с
  пометкой TLE, без утверждения, что укладывается в ограничения жюри;
- решение на Java тратит здесь около 1,5 с, но на тесте 30 жюри не
  укладывается во время, поэтому тоже оставлено с пометкой TLE. Чтобы
  уложиться там в память, его хеш-таблица заполняется до трёх четвертей.

Для каждого основания от 2 до 36 вывод в точности совпадает с выводом
независимой принятой реализации.
