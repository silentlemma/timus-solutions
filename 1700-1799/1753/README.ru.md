# 1753. Книжная полка

[Timus 1753](https://acm.timus.ru/problem.aspx?space=1&num=1753) · сложность 335 · geometry

Автор оригинальной задачи — Дмитрий Иванков; XI открытое личное первенство УрГУ, 13 марта 2010 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У полки длины L по краям бортики высоты h. У левого бортика вертикально
стоит книга высоты H. Её нижний край тянут вправо по полке, а боком
книга продолжает опираться на верх левого бортика, пока не ляжет
плашмя. Толщина у всего нулевая. Найти, насколько далеко влево от
левого бортика заходит середина книги.

## Входные данные

Целые h, H и L (1 ≤ h < H < L ≤ 1000).

## Выходные данные

Наибольшее смещение середины книги влево от бортика с погрешностью не
более 10⁻⁵.

## Проверка

Тесты репозитория сравнивают числовые токены по условию |ответ-эталон| <= 1e-5·max(1,|эталон|), отклоняют бесконечности и NaN, а нечисловые токены сравнивают точно.

## Примеры

### Пример 1

Ввод:

```
7 120 200
```

Вывод:

```
39.850361
```

## Решение

Поместим верх левого бортика в (0, h), а нижний край книги в (x, 0).
Книга лежит на прямой от нижнего края через верх бортика, этот отрезок
имеет длину r = √(x² + h²), поэтому её середина на расстоянии H/2 от
нижнего края находится на горизонтали x(1 − H / 2r). Смещение влево
равно f(x) = x(H / 2r − 1).

Производная равна H·h² / 2r³ − 1, поэтому f растёт, пока r³ < H·h²/2,
и убывает после, а лучший момент — r = ∛(H·h²/2). Такое r никогда не
больше H, так что книга в этот момент ещё опирается на бортик. Если это
r не больше h, что бывает ровно при H ≤ 2h, середина никогда не
выходит за бортик и ответ 0; иначе x = √(r² − h²) и ответ f(x). L роли
не играет: книга всегда помещается на полке. `O(1)`.

В примере r = ∛2940 ≈ 14,33, x ≈ 12,50, и смещение около 39,85.

Подводные камни:

- книга не длиннее двух бортиков даёт 0, а не отрицательное смещение;
- бортик слева, поэтому движение нижнего края вправо сдвигает середину
  влево, только пока книга стоит круто.

Формула совпадает с перебором 200001 положения нижнего края на 100
случайных входах и с независимой принятой реализацией ещё на 300.

## Оптимизированные решения

`1753_geometry_optimized.java`. Java сохраняет аналитический оптимум. При расстоянии основания x и r=hypot(x,h) смещение равно x*(H/(2*r)-1), его производная — H*h*h/(2*r^3)-1. Поэтому при H<=2*h максимум нулевой; иначе r=cbrt(H*h*h/2) и x=sqrt(r*r-h*h) задают точку максимума. В ней x<H<L, поэтому длина полки не ограничивает ответ и её можно не разбирать. Прежние вычисления double через cbrt/sqrt не меняются. Double.toString выводит десятичную запись с точным обратным восстановлением double без инициализации Formatter и Locale. Время и дополнительная память O(1), включая фиксированный буфер ввода на 1024 байта; учебная версия с плавающей точкой сохранена.

Accepted точного исходника Java 1.8 №11327331: 0.109 с / 572 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 10/37, память 4/37. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11324797: 0.125 с / 984 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1753_geometry_optimized.java`: 0.109 s / 572 KB; сохранённая учебная база `1753_geometry.java`: 0.109 s / 1816 KB.

Go и Rust переписывают ту же формулу оптимума через отношение q = cbrt(H/(2h)). При H ≤ 2h смещение равно нулю. Иначе берут f = (q−1)(q+1) и вычисляют h·f·sqrt(f). Общий множитель считается один раз, а вычитание двух больших квадратов длин не требуется. Результат сразу выводится с шестью знаками после точки. Обе версии используют фиксированные байтовые буферы и округляют до миллионных перед записью десятичных цифр. Go обращается напрямую к стандартным дескрипторам. Rust запускается через C main и передаёт буферы через библиотеку C.

Принятые базовые реализации [1753_geometry.cpp](1753_geometry.cpp), [1753_geometry.java](1753_geometry.java), [1753_geometry.py](1753_geometry.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
