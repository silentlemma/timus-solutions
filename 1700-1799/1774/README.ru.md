# 1774. Парикмахер армии магов

[Timus 1774](https://acm.timus.ru/problem.aspx?space=1&num=1774) · сложность 519 · matching

Автор оригинальной задачи — Магаз Асанов; XV Открытый командный чемпионат УрГУ по программированию.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n человек нужно побрить по два раза, в две разные целые минуты своего
пребывания: человек i приходит в минуту tᵢ и остаётся sᵢ минут, так что
допустимы минуты с tᵢ по tᵢ + sᵢ − 1. В одну минуту можно побрить не
больше k человек. Определить, можно ли побрить всех, и указать по две
минуты для каждого.

## Входные данные

n и k (1 ≤ n, k ≤ 100), затем tᵢ и sᵢ для каждого (0 ≤ tᵢ ≤ 1000,
2 ≤ sᵢ ≤ 1000).

## Выходные данные

`No` либо `Yes` и для каждого человека две минуты pᵢ < qᵢ. Подходит
любое подходящее расписание.

## Примеры

### Пример 1

Ввод:

```
3 2
1 3
1 3
1 3
```

Вывод:

```
Yes
1 2
1 3
2 3
```

### Пример 2

Ввод:

```
2 1
1 3
1 3
```

Вывод:

```
No
```

## Решение

Это задача о потоке: каждый человек отдаёт 2 бритья, каждая минута
принимает не больше k, и человек может отдать в каждую минуту своего
пребывания не больше одного бритья. Минуты между двумя соседними
моментами прихода или ухода видят одних и тех же людей, поэтому
сливаются в блоки: блок из L минут принимает не больше k·L бритий и не
больше min(L, 2) от одного человека. Блоков не больше 2n + 1, сеть
маленькая, и алгоритм Диница находит максимальный поток; всех можно
побрить ровно тогда, когда он равен 2n.

Внутри блока бритья раздаются по его минутам по кругу, бритья каждого
человека подряд. Поэтому два бритья одного человека в одном блоке
попадают в разные минуты, ведь L ≥ 2, когда человек отдаёт туда два, и
ни одна минута не получает больше k, так как блок вмещает не больше
k·L. В сети O(n²) рёбер и не больше 2n бритий, каждое находится по
пути за O(n²), итого `O(n³)`.

В первом примере трое делят минуты 1—3 при k = 2: шесть бритий
заполняют шесть мест, и раздача по кругу даёт 1 2, 3 1, 2 3, то есть
каждую пару минут по разу.

Подводные камни:

- два бритья одного человека должны быть в разные минуты, а простой
  подсчёт по блокам этого не заметит;
- последняя допустимая минута — tᵢ + sᵢ − 1, а не tᵢ + sᵢ;
- расписание не единственное, поэтому чекер проверяет окна и загрузку
  каждой минуты.

Ответы совпадают с перебором всех пар минут на 300 случайных случаях до
5 человек и с независимой принятой реализацией, проверенные в обе
стороны, на 100 случаях до 100 человек.

Учебная версия C++ создаёт вершину для каждой минуты от 0 до 1999. Источник передаёт каждому магу две единицы. Ребро ёмкости один связывает мага с каждой минутой его пребывания, а каждая минута передаёт стоку не больше k единиц. Целочисленный поток 2n задаёт каждому магу ровно две различные допустимые минуты. Обходом в глубину ищем увеличивающие пути и добавляем по единице. Если пути больше нет, поток максимален. Выбранные минуты читаем прямо по насыщенным рёбрам от мага к минуте. При E=n+2000+Σsᵢ прямых рёбрах время O(nE), память O(E).

## Оптимизированные решения

C++, Go, Java и Rust сохраняют исходную модель Диница со сжатием по концам интервалов и циклическое восстановление расписания. Ребро теперь содержит три 16-битных поля для конца, следующего ребра и ёмкости. Списки заменены массивом голов. Концов не больше 2n, поэтому блоков B≤2n−1 и вершин не больше 301. Остаточных записей с двумя фиктивными не больше 2(nB+n+B+1)≤40 400, что помещается в 16-битный индекс. Ёмкость интервал–сток ограничиваем общим спросом 2n≤200. Полное расписание использует всего 2n единиц, поэтому ограничение сохраняет допустимость и ограничивает остаточные ёмкости. Сначала считаем рёбра человек–интервал для точного выделения памяти. Буферы BFS, уровней и текущих рёбер переиспользуются. Два времени человека восстанавливаются по обратным ёмкостям его рёбер, без отдельных ссылок и динамических списков ответов. Таблица на 2001 момент заменяет сортировку и множества границ. В блоке из L минут человек получает не больше min(L,2) последовательных мест при циклической выдаче, поэтому его минуты различны. Всего выдаётся не больше kL мест, значит, на минуту приходится не больше k. Время O(n³), память O(n²). Простые исходники сохранены; Python использует подходящую базу.

Принятые базовые реализации [1774_matching.py](1774_matching.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
