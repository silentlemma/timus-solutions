## Задача

Сложность числа — количество его делителей. Для каждого данного n найти
самое сложное число от 1 до n, при равенстве наименьшее, и его
сложность.

## Входные данные

t (1 ≤ t ≤ 100), затем t чисел n (1 ≤ n ≤ 10¹⁸).

## Выходные данные

Для каждого n — число и количество его делителей.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
5
1
10
100
1000
10000
```

Вывод:

```
1 1
6 4
60 12
840 32
7560 64
```

## Решение

Число делителей p₁^a₁ · p₂^a₂ · … равно (a₁ + 1)(a₂ + 1)… и зависит
только от показателей. Если поставить наибольшие показатели на
наименьшие простые, получится наименьшее число с этими показателями,
поэтому ответ всегда имеет вид 2^a · 3^b · 5^c · … с a ≥ b ≥ c ≥ … на
подряд идущих простых. Таких чисел до 10¹⁸ лишь несколько десятков
тысяч, и простые нужны только до 53: 2 · 3 · … · 53 уже больше 10¹⁸.

Перечислим их все перебором показателей, отсортируем и пройдём вверх,
храня лучшее на данный момент: число заменяет лучшее только при строго
большем числе делителей, так что при равенстве остаётся меньшее. Каждый
запрос — двоичный поиск последнего числа списка, не превосходящего n.
`O(K log K + t log K)` при K = 32 749 чисел в списке.

При n = 100 ответ 60 = 2² · 3 · 5 с 3 · 2 · 2 = 12 делителями.

Подводные камни:

- умножение около 10¹⁸ может переполнить 64 бита; проверяйте
  границу делением перед умножением;
- при равенстве побеждает меньшее число: у 2 и 3 по два делителя.

Ответы совпадают с решетом количества делителей на 100 случайных
запросах до 20 000 и с независимой принятой реализацией на 30 случайных
тестах до 10¹⁸ и около чисел-рекордсменов.

## Оптимизированные решения

Невозрастающие показатели простых перебираются лишь до наибольшей запрошенной границы. Поддерживается недоминируемая граница по возрастанию значения со строго возрастающим числом делителей. Предшественник с не меньшим числом делителей делает новый вариант бесполезным; иначе удаляются последующие записи с не большим числом. Так сохраняются все возможные лучшие ответы и меньшее значение при равенстве. Запросы ищут по компактной границе вместо хранения и сортировки всех кандидатов и отдельных префиксных ответов.
