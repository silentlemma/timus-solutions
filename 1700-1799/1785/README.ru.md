# 1785. Трудности локализации

[Timus 1785](https://acm.timus.ru/problem.aspx?space=1&num=1785) · сложность 16 · implementation

Оригинальная задача — фольклор; Уральская региональная командная олимпиада по программированию 2010.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Игра называет размер армии словом вместо числа: 1–4 — "few", 5–9 —
"several", 10–19 — "pack", 20–49 — "lots", 50–99 — "horde", 100–249 —
"throng", 250–499 — "swarm", 500–999 — "zounds", 1000 и больше —
"legion". Вывести слово для заданного числа монстров.

## Входные данные

n (1 ≤ n ≤ 2000).

## Выходные данные

Слово для n.

## Примеры

### Пример 1

Ввод:

```
7
```

Вывод:

```
several
```

### Пример 2

Ввод:

```
40
```

Вывод:

```
lots
```

## Решение

Храним нижние границы диапазонов от большей к меньшей — 1000, 500,
250, 100, 50, 20, 10, 5, 1 — рядом с их словами. Пропускаем границы,
которые больше n; первая не большая даёт слово. `O(1)`.

В примерах 7 проходит границы от 1000 до 10 и останавливается на 5 —
"several"; 40 останавливается на 20 — "lots".

Подводные камни:

- граница относится к большему слову: 5 — "several", 1000 — "legion";
- все n от 1000 до 2000 — "legion".

Ответы совпадают с независимой принятой реализацией на всех n от 1 до
2000.

## Оптимизированные решения

Оптимизированное решение на C++ ищет слово в той же таблице, но читает
через `scanf` и печатает через `puts` вместо `iostream`: 116 КБ вместо
376 КБ при том же времени.

Оптимизированное решение на Java разбирает числа побайтно из `System.in`
вместо `Scanner`: 0.093 с вместо 0.125 с и 340 КБ вместо 1600 КБ.
