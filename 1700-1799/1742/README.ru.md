# 1742. Тим-билдинг

[Timus 1742](https://acm.timus.ru/problem.aspx?space=1&num=1742) · сложность 312 · graphs

Автор оригинальной задачи — Артём Рипатти; контест УГАТУ, Петрозаводские летние сборы, август 2009 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый из n программистов называет коллегу, которого считает
сильнейшим, возможно себя. Группы формируются по одной: берём любого
программиста не из группы, затем добавляем названного последним
добавленным коллегу, пока тот свободен. Найти наименьшее и наибольшее
число групп, которое так может получиться.

## Входные данные

n (1 ≤ n ≤ 10⁵), затем номер, названный каждым программистом.

## Выходные данные

Наименьшее и наибольшее число групп.

## Примеры

### Пример 1

Ввод:

```
4
2
3
4
2
```

Вывод:

```
1 2
```

## Решение

Названные номера образуют граф, где из каждого программиста выходит
одна стрелка: деревья, ведущие в циклы. Группа — это проход по
стрелкам.

- Наименьшее: программист, которого никто не назвал, может быть только
  в группе, которая с него начинается, как и цикл, в который никто
  снаружи не указывает; если начинать с них, каждый проход идёт, пока не
  встретит группу, так что каждый из них даёт ровно одну группу, и
  больше ничего не нужно.
- Наибольшее: войдя в цикл, проход обходит его целиком, поэтому каждый
  цикл — в лучшем случае одна группа. Если сначала взять циклы, а затем
  остальных от циклов наружу, каждый другой программист может
  образовать группу сам.

Значит, ответы — (программисты, которых никто не назвал) + (циклы, в
которые никто не указывает) и (программисты вне циклов) + (циклы).
Проход по стрелкам от каждого нового программиста с пометкой пути
находит каждый цикл один раз. `O(n)`.

В примере 2 → 3 → 4 → 2 — цикл, и 1 указывает в него: начав с 1,
забираем всех, а начав на цикле, оставляем 1 одного.

Подводные камни:

- программист, назвавший себя, — цикл из одного;
- цикл, на котором висит дерево, не требует для минимума своей группы;
- проходы нужно делать циклом, а не рекурсией, так как цепочка может
  быть длиной 10⁵.

Ответы совпадают с перебором всех порядков выбора на 300 случайных
графах до 8 программистов и с независимой принятой реализацией на
больших тестах.

## Оптимизированные решения

Компактные версии считают входящие рёбра только до двух. Ноль отмечает начало группы, а цикл изолирован, если у каждой его вершины счётчик равен единице. Один байт на вершину хранит состояние «не посещена», «в текущем обходе» или «обработана». После подсчёта найденного цикла повторяем проход по тем же стрелкам, чтобы отметить вершины обработанными. Каждую вершину посещаем лишь константное число раз, и отдельный массив вершин обхода не нужен.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 2 088 KB при 5148 KB у базовой.

Принятые базовые реализации [1742_graphs.java](1742_graphs.java), [1742_graphs.py](1742_graphs.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
