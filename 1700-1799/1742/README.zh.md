# 1742. 团队建设

[Timus 1742](https://acm.timus.ru/problem.aspx?space=1&num=1742) · 难度 312 · graphs

原题作者 Artyom Ripatti，出自 2009 年 8 月彼得罗扎沃茨克夏季集训的乌法国立航空技术大学专场。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

n 名程序员每人说出自己认为最强的同事（可能是自己）。小组逐个组建：任选一名尚未分组的程序员，
然后只要最后加入者所说的同事还空闲，就把他加入。求这样能得到的最少和最多小组数。

## 输入

n（1 ≤ n ≤ 10⁵），然后是每名程序员说出的编号。

## 输出

最少和最多的小组数。

## 样例

### 样例 1

输入：

```
4
2
3
4
2
```

输出：

```
1 2
```

## 解法

这些编号构成一个每个程序员恰有一条出边的图：通向环的树。一个小组就是沿箭头走的一条路径。

- 最少：没人说出的程序员只能在以他开头的小组里，没有外部指向的环也是如此；从这些起点出发，每条路径一直走到遇到已有小组为止，
  所以每个起点恰好给出一个小组，其他都不需要。
- 最多：路径一旦进入环就会绕完整个环，所以每个环最多一个小组。先处理环，再从环向外处理其他人，其余每个程序员都可以单独成组。

所以答案为（没人说出的程序员数）+（没有外部指向的环数），以及（不在环上的程序员数）+（环数）。
从每个新程序员沿箭头走并标记路径，可以把每个环恰好找一次。`O(n)`。

样例中 2 → 3 → 4 → 2 是一个环，1 指向它：从 1 开始会带上所有人，而从环上开始则让 1 单独一组。

注意事项：

- 说出自己的程序员是长度为 1 的环；
- 挂着树的环在求最小值时不需要单独的小组；
- 路径要用循环而不是递归来走，因为链长可达 10⁵。

在 300 个最多 8 名程序员的随机图上，答案与穷举所有选择顺序一致；在大测试上与一个独立的已通过实现一致。

## 优化解法

紧凑版本的入边计数最多记到二。零表示起点，环上每个顶点的计数都为一时，该环才孤立。每个顶点用一个字节记录未访问、在当前路径上或已完成。统计发现的环后再沿原来的箭头走一遍，把路径标为已完成。每个顶点只访问常数次，无需单独保存路径上的顶点。

通过评测的 Rust 1.75 x64 版本耗时 0.031 秒，基础版为 0.015 秒，内存为 2 088 KB，基础版为 5148 KB。
