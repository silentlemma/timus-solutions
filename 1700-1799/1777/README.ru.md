# 1777. Племя аниндилъяква

[Timus 1777](https://acm.timus.ru/problem.aspx?space=1&num=1777) · сложность 128 · simulation

Автор оригинальной задачи — Иван Бурмистров; XV Открытый командный чемпионат УрГУ по программированию.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На поляне лежат три кучи камней разного размера. Каждый человек по
очереди находит две кучи с наименьшей разницей размеров и приносит
новую кучу ровно такого размера; все кучи остаются. Вопросы
прекращаются на человеке, который найдёт две равные кучи. Скольких
людей спросят?

## Входные данные

Три различных размера x₁, x₂, x₃ (1 ≤ xᵢ ≤ 10¹⁸).

## Выходные данные

Число опрошенных.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
11 5 9
```

Вывод:

```
3
```

## Решение

Процесс моделируется как есть: отсортировать кучи, взять наименьшую
разницу соседей, остановиться, если она 0, иначе добавить кучу такого
размера. Наименьшая разница сокращается примерно как числа в алгоритме
Евклида, поэтому процесс короткий: самый длинный найденный, из трёх
подряд идущих чисел Фибоначчи около 10¹⁸, опрашивает 85 человек, а
выборка из 10 000 равномерно случайных допустимых троек дала в среднем
3,7 человека (медиана 3). `O(s² log s)` при s шагах.

В примере разницы 2, 4 и 6: первый приносит кучу из 2, второй снова
видит 9 и 11 и приносит ещё 2, а третий указывает на две кучи по 2.

Подводные камни:

- человек, нашедший равные кучи, тоже считается;
- новая куча может повторить старый размер, и тогда всё кончится на
  следующем человеке;
- размеры до 10¹⁸ требуют 64-битных чисел.
- короткие случайные прогоны не определяют худший случай: в тесте 08
  опрашивают 85 человек.

Ответы совпадают с независимой принятой реализацией на 90 случайных
тройках, в том числе на тройках чисел Фибоначчи.

## Оптимизированные решения

`1777_simulation_optimized.java`. Сохраняется точная сжатая симуляция куч. Для двух меньших куч a≤b и положительного минимального разрыва g≤b−a<b: при g<a имеем b−g≥a−g и следующий разрыв min(g,a−g); иначе g−a≤g и разрыв min(g−a,b−g). Убраны только лишние модуль и минимум; обновления куч и подсчёт людей прежние. O(s) времени для s шагов симуляции и O(1) дополнительной памяти, без утверждения константного числа шагов.

Accepted точного исходника Java 1.8 №11327759: 0.109 с / 404 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 8/77, память 1/77. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11304426: 0.14 с / 440 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1777_simulation_optimized.java`: 0.109 s / 404 KB; сохранённая учебная база `1777_simulation.java`: 0.14 s / 1704 KB.

Оптимизированное решение на C++ не хранит список куч: только две
наименьшие кучи a < b и текущую наименьшую разность g. Новая куча g не
больше b − a, то есть меньше b, и в отсортированном порядке её соседями
могут быть только a и b. Все старые разности остаются, поэтому следующая
наименьшая разность — наименьшее из g, |g − a| и b − g, а двумя
наименьшими кучами становятся g и a или a и g. Каждый шаг занимает
`O(1)` времени, а весь прогон — `O(1)` памяти вместо сортировки
растущего вектора; все значения помещаются в `long long`, ведь они не
больше 10¹⁸: {1777_simulation_optimized.cpp}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1777_simulation_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +47.92%; база: `1777_simulation.cpp`.

`1777_simulation_optimized.rs`. Все кучи хранятся в одном отсортированном динамическом векторе. После просмотра соседних разностей новый минимальный размер ищется двоичным поиском и вставляется на место, без полной сортировки на каждом шаге. Если такой размер уже есть, сразу учитывается следующий человек, обнаруживающий равенство. Динамическая ёмкость не опирается на экспериментальный предел числа куч. При s шагах просмотры и сдвиги вставки суммарно требуют O(s²), память O(s). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1777_simulation.rs`: время 0.046 s → 0.031 s; память 252 KB → 76 KB.

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1777_simulation_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
