# 1777. Племя аниндилъяква

[Timus 1777](https://acm.timus.ru/problem.aspx?space=1&num=1777) · сложность 128 · simulation

Автор оригинальной задачи — Иван Бурмистров; XV Открытый командный чемпионат УрГУ по программированию.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На поляне лежат три кучи камней разного размера. Каждый человек по
очереди находит две кучи с наименьшей разницей размеров и приносит
новую кучу ровно такого размера; все кучи остаются. Вопросы
прекращаются на человеке, который найдёт две равные кучи. Скольких
людей спросят?

## Входные данные

Три различных размера x₁, x₂, x₃ (1 ≤ xᵢ ≤ 10¹⁸).

## Выходные данные

Число опрошенных.

## Примеры

### Пример 1

Ввод:

```
11 5 9
```

Вывод:

```
3
```

## Решение

Процесс моделируется как есть: отсортировать кучи, взять наименьшую
разницу соседей, остановиться, если она 0, иначе добавить кучу такого
размера. Наименьшая разница сокращается примерно как числа в алгоритме
Евклида, поэтому процесс короткий: самый длинный найденный, из трёх
подряд идущих чисел Фибоначчи около 10¹⁸, опрашивает 85 человек, а
выборка из 10 000 равномерно случайных допустимых троек дала в среднем
3,7 человека (медиана 3). `O(s² log s)` при s шагах.

В примере разницы 2, 4 и 6: первый приносит кучу из 2, второй снова
видит 9 и 11 и приносит ещё 2, а третий указывает на две кучи по 2.

Подводные камни:

- человек, нашедший равные кучи, тоже считается;
- новая куча может повторить старый размер, и тогда всё кончится на
  следующем человеке;
- размеры до 10¹⁸ требуют 64-битных чисел.
- короткие случайные прогоны не определяют худший случай: в тесте 08
  опрашивают 85 человек.

Ответы совпадают с независимой принятой реализацией на 90 случайных
тройках, в том числе на тройках чисел Фибоначчи.

## Оптимизированные решения

Оптимизированное решение на C++ не хранит список куч: только две
наименьшие кучи a < b и текущую наименьшую разность g. Новая куча g не
больше b − a, то есть меньше b, и в отсортированном порядке её соседями
могут быть только a и b. Все старые разности остаются, поэтому следующая
наименьшая разность — наименьшее из g, |g − a| и b − g, а двумя
наименьшими кучами становятся g и a или a и g. Каждый шаг занимает
`O(1)` времени, а весь прогон — `O(1)` памяти вместо сортировки
растущего вектора; все значения помещаются в `long long`, ведь они не
больше 10¹⁸: {1777_simulation_optimized.cpp}.

Оптимизированное решение на Java читает три размера побайтно из
`System.in` вместо того, чтобы создавать `Scanner`, чьи регулярные
выражения и данные локали обходятся дороже короткой симуляции, которая
осталась прежней: {1777_simulation_optimized.java}.
