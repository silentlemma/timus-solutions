# 1781. 整洁的代码

[Timus 1781](https://acm.timus.ru/problem.aspx?space=1&num=1781) · 难度 2067 · graphs

原题作者 Alex Samsonov，出自第十五届乌拉尔国立大学公开团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一张 n × n 的 0/1 表说明依次举行的 n 场比赛各使用哪些机房。机房 i 在第 i 场比赛后立即打扫，之后不能再用，所以第 i 场比赛不能使用 j < i 的机房 j。
一次操作交换第 i、j 行，再交换第 i、j 列。在至多 200 次操作内使表符合要求，或报告不可能。

## 输入

n（2 ≤ n ≤ 100），然后是这张表。

## 输出

操作次数和各对 i、j，或者 −1。任何符合要求的答案都可以。

## 样例

### 样例 1

输入：

```
3
0 0 0
1 1 0
1 1 0
```

输出：

```
1
1 3
```

### 样例 2

输入：

```
3
1 1 1
1 1 0
1 0 0
```

输出：

```
-1
```

## 解法

同时交换行和列只是对比赛和机房做相同的重新编号，而且任何重新编号都能达到。当对角线外的所有 1 都在对角线上方时表就符合要求，
即使用机房 b ≠ a 的比赛 a 排在比赛 b 之前。这些就是图的边 a → b，合适的编号就是它的拓扑序；若图中有环，就无论如何都不行，答案为 −1。

按顺序把各场比赛依次放到第 1、2、… 位，每次至多把当前位置上的比赛与需要的比赛交换一次，所以至多用 n − 1 ≤ 99 次操作。`O(n²)`。

样例 1 中比赛 2 和 3 都使用机房 1，所以比赛 1 必须排在两者之后；交换 1 和 3 把它放到最后。

注意事项：

- 比赛可以使用自己的机房，这些对角线上的 1 不产生顺序要求；
- 每次操作同样地交换行和列，所以这是重新编号，而不是随意移动行；
- 答案不唯一，所以检查器重放这些交换。

在 300 张最多 5 个机房的随机表上，有无解与枚举所有重新编号的结果一致；在 100 张最多 100 个机房的随机表上，这些交换都通过了检查器，一个独立的已通过实现的交换也是如此。
