# 1731. Укроп

[Timus 1731](https://acm.timus.ru/problem.aspx?space=1&num=1731) · сложность 106 · constructive

## Задача

Подобрать массы n ящиков укропа первого сорта и m ящиков второго сорта
— различные целые положительные числа не больше 10⁹ — так, чтобы
никаким способом нельзя было подарить двум соседям по ящику каждого
сорта с равными суммарными массами.

## Входные данные

n и m (2 ≤ n, m ≤ 50).

## Выходные данные

n масс первого сорта в одной строке и m масс второго сорта в следующей.
Подходят любые подходящие массы.

## Примеры

### Пример 1

Ввод:

```
2 3
```

Вывод:

```
1 2
5 10 12
```

## Решение

Два подарка a + b и a′ + b′ не имеют общих ящиков, а две суммы с общим
ящиком и так различны, потому что все массы разные. Значит, условие
означает, что все n·m сумм a_i + b_j различны.

Возьмём a_i = i при i = 1..n и b_j = (j + 1)·n + 1 при j = 0..m − 1.
Тогда a_i + b_j = (j + 1)·n + 1 + i, и, поскольку i пробегает 1..n,
сумма определяет и i, и j — как число в системе счисления по основанию
n определяет последнюю цифру и остальное. Все массы различны, наибольшая
меньше 3000. `O(n + m)`.

Для примера получаются 1 2 и 3 5 7 с суммами 4, 6, 8, 5, 7, 9.

Подводные камни:

- ответ существует всегда, так что «It is a lie!» не выводится никогда;
- второй сорт не должен повторять массы первого, поэтому он начинается
  выше n.

Проверяющая программа проверяет количество, диапазон, различность и то,
что все суммы разные.

## Оптимизированные решения

Оптимизированное решение на C++ читает n и m через `scanf` вместо
`std::cin`, так что программа вовсе не подключает `iostream`; массы
печатаются так же: {1731_constructive_optimized.cpp}.

Оптимизированное решение на Java читает n и m по цифрам прямо из
`System.in` вместо создания `Scanner`, подготовка которого стоит больше
всей остальной программы; вывод строится так же:
{1731_constructive_optimized.java}.
