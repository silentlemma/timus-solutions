# 1731. Укроп

[Timus 1731](https://acm.timus.ru/problem.aspx?space=1&num=1731) · сложность 106 · constructive

Автор оригинальной задачи — Евгений Курпилянский (подготовка — София Техажева); Уральская региональная командная олимпиада по программированию 2009.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Подобрать массы n ящиков укропа первого сорта и m ящиков второго сорта
— различные целые положительные числа не больше 10⁹ — так, чтобы
никаким способом нельзя было подарить двум соседям по ящику каждого
сорта с равными суммарными массами.

## Входные данные

n и m (2 ≤ n, m ≤ 50).

## Выходные данные

n масс первого сорта в одной строке и m масс второго сорта в следующей.
Подходят любые подходящие массы.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверка репозитория требует ровно две строки с n и m целыми массами. Все n+m масс различны и входят в [1,10^9], все n*m попарных сумм различны. Конструкция существует всегда, сообщение о невозможности не принимается.

## Примеры

### Пример 1

Ввод:

```
2 3
```

Вывод:

```
1 2
5 10 12
```

## Решение

Два подарка a + b и a′ + b′ не имеют общих ящиков, а две суммы с общим
ящиком и так различны, потому что все массы разные. Значит, условие
означает, что все n·m сумм a_i + b_j различны.

Возьмём a_i = i при i = 1..n и b_j = (j + 1)·n + 1 при j = 0..m − 1.
Тогда a_i + b_j = (j + 1)·n + 1 + i, и, поскольку i пробегает 1..n,
сумма определяет и i, и j — как число в системе счисления по основанию
n определяет последнюю цифру и остальное. Все массы различны, наибольшая
меньше 3000. `O(n + m)`.

Для примера получаются 1 2 и 3 5 7 с суммами 4, 6, 8, 5, 7, 9.

Подводные камни:

- ответ существует всегда, так что «It is a lie!» не выводится никогда;
- второй сорт не должен повторять массы первого, поэтому он начинается
  выше n.

Проверяющая программа проверяет количество, диапазон, различность и то,
что все суммы разные.

## Оптимизированные решения

Оптимизированное решение на C++ читает n и m через `scanf` вместо
`std::cin`, так что программа вовсе не подключает `iostream`; массы
печатаются так же: {1731_constructive_optimized.cpp}.

Оптимизированное решение на Java читает n и m по цифрам прямо из
`System.in` вместо создания `Scanner`, подготовка которого стоит больше
всей остальной программы; вывод строится так же:
{1731_constructive_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1731_constructive_optimized.cpp`: сокращение времени +0.00%;
  сокращение памяти +67.02%; база: `1731_constructive.cpp`.

- `1731_constructive_optimized.java`: сокращение времени +45.61%;
  сокращение памяти +76.20%; база: `1731_constructive.java`.

`1731_constructive_optimized.py`. Сохраняются массы 1..n первого вида и j*n+1 при j=1..m второго. Первая группа меньше второй, суммы с соседними массами второго вида образуют непересекающиеся интервалы по n значений, поэтому каждая сумма подарка уникальна. При n,m<=50 любая масса не больше 2501. Две требуемые строки выводятся за O(n+m) операций с ограниченными числами. Каждая строка ответа по-прежнему строится склейкой; первая использует map(str,range(...)). Строки требуют O(n+m) пиковой памяти, это не потоковый вывод с постоянной памятью. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1731_constructive.py`: время 0.093 s → 0.125 s; память 416 KB → 208 KB.

`1731_constructive_optimized.rs`. Сохраняются массы 1..n первого вида и j*n+1 при j=1..m второго. Первая группа меньше второй, суммы с соседними массами второго вида образуют непересекающиеся интервалы по n значений, поэтому каждая сумма подарка уникальна. При n,m<=50 любая масса не больше 2501. Две требуемые строки выводятся за O(n+m) операций с ограниченными числами. Каждая масса выводится при генерации, без двух Vec<String> и склейки строк. Дополнительное состояние O(1). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1731_constructive.rs`: время 0.046 s → 0.031 s; память 220 KB → 56 KB.

Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
