# 1727. Магические числа Знайки

[Timus 1727](https://acm.timus.ru/problem.aspx?space=1&num=1727) · сложность 202 · greedy

Автор оригинальной задачи — Иван Бурмистров; Уральская региональная командная олимпиада по программированию 2009.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Найти набор различных целых положительных чисел меньше 10⁵, цифры
которых в сумме дают n, или вывести −1, если такого нет.

## Входные данные

n (0 < n < 10⁵).

## Выходные данные

Размер набора и затем его числа или −1. Подходит любой подходящий
набор.

## Проверка

Нужен конструктивный проверяющий модуль, а не совпадение с одним
примером. Проверяем заявленный размер, положительные числа меньше
100000, отсутствие повторов и точную сумму всех десятичных цифр.
Каждый из пяти новых исходников прошёл 13 архивных входов в Docker
и получил собственный Accepted с точным SHA. Форматированная C++-база
отдельно прошла все 13 входов. Новый Python также реально выполнен
на 265 входах; отдельная модель префикса и остатка проверена для всех
99999 допустимых целей. Это проверки модели, а не 99999 запусков каждого
языка. Значения 1, 9, 45, 46 и 99999 покрывают добор цифрами и обе фазы.

## Примеры

### Пример 1

Ввод:

```
17
```

Вывод:

```
3
7 12 43
```

## Решение

Пусть `s(x)` — сумма десятичных цифр, `L=100000`. Понятные жадные базы
сначала строят `s(i)=s(i//10)+i%10` для всех `i<L`, затем идут от `L−1`
вниз и берут число, если сумма его цифр помещается в остаток цели.
Каждое значение просматривается один раз: выбранные числа различны и
допустимы. Время и вспомогательная таблица — `O(L)`; отдельно хранится
вывод размера `O(q)`, где `q` — число выбранных значений.

Почему остаток всегда обнуляется? У каждого числа от 90000 до 99999
сумма цифр не больше 45, а по всему блоку она равна
`9·10000+4·45·1000=270000`. Если после блока остаток всё ещё не меньше
45, все числа блока подошли бы. Но из исходного `n<100000` нельзя вычесть
270000, сохранив неотрицательность. Значит, ещё в блоке остаток стал
меньше 45 и дальше не возрастает. При достижении пока не использованных
цифр `9,8,…,1` ими жадно набирается любой остаток от 0 до 45.
Инвариант перед цифрой `d`: `remainder≤d(d+1)/2`; если `d` подходит,
вычитаем её, сохраняя границу для `d−1`. В конце остаток нулевой.
Поэтому ответ −1 не нужен.

Все пять простых алгоритмов сохранены. В C++ изменилось лишь точное
репозиторное форматирование, для которого получен отдельный Accepted
с новыми метриками. Другие четыре файла побайтово прежние; старые байты
C++ сохранены в резервной копии.

## Оптимизированные решения

Новая конструкция убирает полную таблицу сумм цифр и длинный проход.
Пока остаток больше 45, берём подряд числа от 99999 вниз, считая сумму
цифр каждого по необходимости. В пятизначном числе она не превосходит
45, поэтому очередное число точно помещается. Граница 270000 доказывает,
что фаза заканчивается ещё до 90000, далеко от однозначных чисел.
Остаток добираем различными цифрами от 9 до 1. Диапазоны двух фаз не
пересекаются; инвариант остатка доказывает точную сумму. Подходит любой
такой набор, минимальное число элементов не требуется.

При `D` цифрах большого числа и `q` элементах вывода время —
`O(qD+D)`, память вывода — `O(q)`; здесь `D=5`, то есть время `O(q)`.
Предварительной таблицы `O(L)` нет. Это другая конструкция с именем
`constructive`, а не дублирующий `_optimized` для прежнего прохода.
Все пять версий подтвердили порог 30% по памяти относительно текущей
базы на том же языке. Записанное время Python выросло с 0,093 до 0,109 с:
допуск именно по памяти. Разница Rust 0,046→0,031 с — один тик таймера,
поэтому доказательством ускорения она не считается.

Измеренная экономия памяти: C++ 66.4%, Go 43.9%, Java 61.9%, Python 43.0%, Rust 76.6%.

## Особенности языков

Метрики Accepted в таблицах относятся к точным байтам исходников.
Сравнения используют текущие простые базы, включая заново принятый C++.
Рейтинговый срез от 2 ноября 2026 года применяет установленные фильтры
компиляторов и других авторов: для C++ нужны верхние 15% или первые десять
мест по обоим показателям, для остальных семейств — первое место по обоим.
Звёздочка отмечает допустимую улучшенную версию, пока не достигшую этой
цели. Отсутствие конкурентов означает формальное покрытие, но не
доказанное превосходство.
