# 1779. Великая команда

[Timus 1779](https://acm.timus.ru/problem.aspx?space=1&num=1779) · сложность 344 · constructive

Автор оригинальной задачи — Иван Бурмистров; XV Открытый командный чемпионат УрГУ по программированию.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Построить граф дружбы на n студентах, в котором никакие три студента не
имеют одинакового числа друзей, или сообщить, что такого нет.

## Входные данные

n (3 ≤ n ≤ 200).

## Выходные данные

Число пар друзей и сами пары или −1, если подходящего графа нет.
Подходит любой подходящий граф.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
2
1 3
3 4
```

## Решение

Соединим студентов i и j, когда i + j > n. Тогда студент i дружит с i
студентами n − i + 1, …, n, кроме себя, если он среди них, то есть при
2i > n. Значит, у студента i i друзей при i ≤ n/2 и i − 1 при i > n/2:
числа идут 1, 2, … до середины и дальше после неё, и только одно число,
серединное, общее у двух студентов. Поэтому граф существует всегда и −1
не выводится никогда. `O(n²)`.

Для четырёх студентов получаются пары 1–4, 2–3, 2–4 и 3–4 с 1, 2, 2 и 3
друзьями — это подходит так же, как ответ из примера.

Подводные камни:

- n − 1 друзей и 0 друзей не бывают одновременно, поэтому числа от 0 до
  n − 1 не могут быть все разными, и двое студентов обязаны их
  разделить;
- граф может быть плотным, около n²/4 пар, так что вывод большой;
- ответ не единственный, поэтому чекер сам считает друзей.

Построение проходит чекер для всех n от 3 до 200, как и независимая
принятая реализация.

## Оптимизированные решения

Go и Rust сразу выводят число пар floor(n/2) · ceil(n/2), затем перебирают i < j с условием i + j > n. Каждая пара сразу записывается через буфер фиксированного размера, поэтому дополнительная память постоянна.

Принятая версия Go 1.14 x64 заняла 0.031 с при 0.015 с у базовой и использовала 912 KB при 2140 KB у базовой.

Принятые базовые реализации [1779_constructive.cpp](1779_constructive.cpp), [1779_constructive.java](1779_constructive.java), [1779_constructive.py](1779_constructive.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
