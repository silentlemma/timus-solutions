# 1756. Полтора землекопа

[Timus 1756](https://acm.timus.ru/problem.aspx?space=1&num=1756) · сложность 179 · math

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

m землекопов роют траншею ровно за d₁ дней, если все работают каждый
день. Составить график, сколько землекопов работает в каждый из d₂
дней, чтобы та же траншея была вырыта ровно за d₂ дней при наименьшем
числе нанятых землекопов. Дни, когда никто не работает, допускаются.

## Входные данные

m, d₁ и d₂ (1 ≤ m, d₁, d₂ ≤ 10000).

## Выходные данные

d₂ чисел — сколько землекопов работает в каждый день. Подходит любой
лучший график.

## Примеры

### Пример 1

Ввод:

```
3 1 2
```

Вывод:

```
1 2
```

## Решение

Траншея требует W = m·d₁ землекопо-дней. Нанять нужно столько
землекопов, сколько их работает в самый загруженный день, а d₂ дней по
не более чем k землекопов дают не более k·d₂ землекопо-дней, поэтому
нужно хотя бы ⌈W / d₂⌉ землекопов. Этого и достаточно: при
W = q·d₂ + r ставим q землекопов на d₂ − r дней и q + 1 на остальные r.
`O(d₂)`.

В примере W = 3 на 2 дня: один день 1 землекоп, другой — 2, так что
нанимаются два землекопа, а не полтора.

Подводные камни:

- m·d₁ доходит до 10⁸ — в 32 бита помещается, но об этом стоит
  помнить;
- при W < d₂ в некоторые дни никто не работает;
- дневные числа должны давать в сумме ровно W, а не просто не меньше.

Графики проходят чекер, проверяющий сумму и самый загруженный день, на
маленьких, случайных и предельных входах; независимая принятая
реализация выводит те же дни в другом порядке.

## Оптимизированные решения

Оптимизированное решение на Java читает три числа вручную вместо
`Scanner`, один раз форматирует два возможных дневных числа и пишет их
байты через `BufferedOutputStream`, а не собирает всю строку до
10000 чисел в `StringBuilder`: {1756_math_optimized.java}.

Оптимизированное решение на Python один раз форматирует два возможных
дневных числа и собирает строку повторением двух строк, а не создаёт
список до 10000 целых, переводя каждое в строку:
{1756_math_optimized.py}.

Оптимизированное решение на Rust один раз форматирует два возможных
дневных числа и пишет их сразу в `BufWriter`, а не создаёт до
10000 строк, чтобы склеить их в ещё одну: {1756_math_optimized.rs}.
