# 1793. Тарелки 2

[Timus 1793](https://acm.timus.ru/problem.aspx?space=1&num=1793) · сложность 403 · geometry

Автор оригинальной задачи — София Техажева; Уральская региональная командная олимпиада по программированию 2010.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У подноса дно a × b и вертикальные бортики высоты d. Две тарелки —
усечённые конусы одной высоты h, у каждой радиус дна и больший радиус
верха. Можно ли поставить обе тарелки так, чтобы их донышки целиком
лежали на подносе?

## Входные данные

a, b и d; затем радиусы дна и верха каждой тарелки; затем h. Все числа
целые, от 1 до 1000.

## Выходные данные

"YES", если тарелки можно поставить, иначе "NO".

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
10 10 10
1 2
1 2
5
```

Вывод:

```
YES
```

### Пример 2

Ввод:

```
8 4 1
1 2
1 3
1
```

Вывод:

```
NO
```

## Решение

Тарелка расширяется кверху, поэтому внутри бортиков она шире всего на
высоте min(d, h), где её радиус w = r + (R − r)·min(d, h)/h. Выше
бортиков она может нависать над краем. Значит, центр каждой тарелки
должен быть не ближе w к каждой стороне, для чего нужно 2w ≤ a и
2w ≤ b. Две тарелки одной высоты дальше всего друг от друга внизу и
ближе всего вверху, поэтому их центры должны отстоять хотя бы на
R₁ + R₂. Центры дальше всего друг от друга в противоположных углах
своих допустимых прямоугольников: на a − w₁ − w₂ вдоль одной стороны и
на b − w₁ − w₂ вдоль другой. Умножение всего на h оставляет числа
целыми, а сравнение квадратов расстояний обходится без корней, так что
проверка точна. `O(1)`.

В первом примере бортики выше тарелок, поэтому w = 2 у обеих; центры
можно развести на 6 вдоль каждой стороны, всего примерно на 8,49, а
нужно лишь 4.

Подводные камни:

- при низких бортиках верх тарелки может быть шире подноса;
- тарелки сталкиваются верхами, а не на высоте бортиков;
- касающиеся тарелки помещаются, и проверка в плавающей точке может
  здесь ошибиться.

Ответы совпадают с независимой принятой реализацией на 600 случайных
случаях, среди них тарелки, касающиеся точно по диагонали 3-4-5.

## Оптимизированные решения

`1793_geometry_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1793_geometry.java`: время 0.156 s → 0.109 s; память 1592 KB → 504 KB.

C++ и Go сохраняют ту же точную проверку с масштабированными радиусами. Сначала проверяют, помещается ли каждая тарелка вдоль короткой стороны подноса на высоте борта. Затем сравнивают квадрат расстояния между противоположными допустимыми углами с квадратом суммы верхних радиусов. Итоговые произведения вычисляются в знаковой 64-битной арифметике, ответ выводится постоянной строкой YES или NO. Go читает восемь положительных целых через фиксированный байтовый буфер без токенов сканера и преобразований строк. Он обращается прямо к стандартным дескрипторам, повторяет прерванные вызовы и завершает частичные записи.

Принятые базовые реализации [1793_geometry.java](1793_geometry.java), [1793_geometry.py](1793_geometry.py), [1793_geometry.rs](1793_geometry.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`1793_geometry_optimized.java`: место по времени 8/31, по памяти 3/31 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
