## Задача

У каждого объекта есть набор ассоциаций. Для каждой из нескольких
групп объектов вывести общие для всех них ассоциации по алфавиту или
«No solution.», если таких нет.

## Входные данные

n (2 ≤ n ≤ 1000) строк «имя: ассоциация ассоциация …», затем m
(1 ≤ m ≤ 1000) строк — группы хотя бы из двух имён объектов. Слова из
строчных латинских букв, строки не длиннее 250 символов.

## Выходные данные

По строке на группу.

## Примеры

### Пример 1

Ввод:

```
6
whale: big black water animal
penguin: black white ice beak
piano: keyboard black white wire
jackboot: leather heel black
train: rail wheel black
rose: red green thorn
3
whale penguin piano jackboot train
penguin piano
jackboot rose
```

Вывод:

```
black
black white
No solution.
```

## Решение

Храним ассоциации каждого объекта как множество по его имени. Для
группы пересекаем множества её членов и выводим результат по порядку
или «No solution.», если он пуст. Все строки короткие; на группу нужно
`O(L²)` проверок в множествах.
`O((n + m · L) · L log(n + L))` для строк длины L.

Подводные камни:

- ассоциация может быть указана у объекта дважды, но выводится один
  раз (тест 02);
- в группе один объект может быть назван дважды (тест 03);
- у объекта может не быть ассоциаций вовсе, тогда строка кончается
  сразу после двоеточия.

Ответы совпадают с независимой принятой реализацией.

## Оптимизированные решения

C++/Go интернируют ассоциации в общие целые ID и хранят для объекта отсортированный список без повторов. Запрос копирует самый короткий список, пересекает остальные двумя индексами, затем сортирует сохранившиеся написания для вывода. Исходные списки не меняются; повторы членов группы и ассоциаций результата не меняют. Python читает определения потоком во frozenset интернированных строк и пересекает копию самого маленького множества. Ответы выводятся потоком. T — символы входа, A — максимум ассоциаций, K — размер группы, W — длина слова: пересечения ID стоят O(KA), сортировка написаний O(A log A·W), хеширование имеет обычные ожидаемые оценки. Написания разделяются между объектами, весь ввод и вывод не накапливаются. Простые множества сохранены; Java/Rust используют подходящие базы.

Принятая версия Go 1.14 x64 заняла 0.062 с при 0.765 с у базовой и использовала 10 348 KB при 8908 KB у базовой.

В прежнем срезе сравнения базовые реализации [1700_implementation.java](1700_implementation.java), [1700_implementation.rs](1700_implementation.rs) удовлетворяли критерию включения по топ 15% или первым десяти местам по обеим метрикам. Их измерения сохранены в таблице простых решений.

Храним ассоциации в отсортированных массивах и пересекаем их двумя указателями. Ответы выводим по мере обработки запросов. Принятая посылка 11324225 заняла 0,250 с и использовала 8 536 КБ. Простая версия заняла 0,437 с и использовала 12376 КБ.
