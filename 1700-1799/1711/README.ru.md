# 1711. Кодовые имена

[Timus 1711](https://acm.timus.ru/problem.aspx?space=1&num=1711) · сложность 135 · greedy

Автор оригинальной задачи — Алексей Самсонов, подготовка — Игорь Чевдарь; NEERC 2009, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У каждой из n задач есть три варианта кодового имени, и задачи в
комплекте идут в алфавитном порядке имён. Нужно выбрать по имени для
каждой задачи так, чтобы задачи шли в заданном порядке, или сообщить,
что это невозможно.

## Входные данные

n (1 ≤ n ≤ 16), затем n строк с тремя именами каждой задачи: строчные
латинские буквы, не больше 20, все имена различны. В последней строке —
требуемый порядок, перестановка чисел 1 … n.

## Выходные данные

Выбранные имена в требуемом порядке, по одному в строке, или
IMPOSSIBLE. Подходит любой правильный выбор.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверка репозитория принимает IMPOSSIBLE ровно когда таков сохранённый эталон. Иначе нужны ровно n токенов имён, каждый предложен соответствующей задаче в заданном порядке, имена строго возрастают. Годится любой выбор, переводы строк не сравниваются.

## Решение

Идём по требуемому порядку и даём каждой задаче наименьшее из её имён,
которое идёт после предыдущего выбранного. Если такого нет, ответ —
IMPOSSIBLE.

Такой жадный выбор безопасен. Пусть правильный выбор существует;
сравним его с жадным задача за задачей. По индукции жадное имя никогда
не идёт позже правильного: правильное имя следующей задачи идёт после
правильного предыдущего, а значит, и после жадного предыдущего. Поэтому
оно — кандидат, и жадный выбор не больше него. Значит, жадный проход
никогда не застрянет. `O(n)` сравнений коротких строк.

Подводные камни:

- имена сравниваются как строки, и префикс идёт раньше: «code» перед
  «codenames»;
- строка порядка перечисляет номера задач по их местам в комплекте, а
  не место каждой задачи;
- подходит любой правильный ответ, поэтому тесты используют
  проверяющую программу.

Проверяющая программа убеждается, что каждое имя принадлежит своей
задаче и что имена возрастают. Ответы совпадают с независимой принятой
реализацией на 600 случайных комплектах.

## Оптимизированные решения

`1711_greedy_optimized.java`. Сохраняем жадное правило выбора минимального допустимого имени. Читаем ASCII-байты непосредственно из существующего потока System.in, храним по три имени на задачу в одном плоском массиве байтов с отдельными длинами и перебираем кандидатов вместо сортировки массивов String. Сравниваем общий префикс, затем длины: порядок собственных префиксов сохраняется. Полный ответ собираем в массиве байтов и выводим обычным System.out.write со сбросом буфера; если продолжение невозможно, частичный ответ отбрасывается. Для B байтов входа и длины имени L<=20 время O(B+nL), дополнительная память O(nL). Три дополнительных запуска совершенно одинакового исходника дали (0.125 s, 384 KB), (0.093 s, 340 KB) и (0.125 s, 336 KB). В таблице указана реальная средняя посылка: относительно сохранённой простой Java-версии время снижено на 33.57%, память — на 34.11%. Разброс показан явно; время 0.093 s не объединяется с 336 KB из третьей посылки.

По сравнению с `1711_greedy.java`: время 0.140 s → 0.093 s; память 516 KB → 340 KB.

`1711_greedy_optimized.py`. Сохраняется жадный выбор наименьшего из трёх имён, строго большего предыдущего. Три байтовые строки просматриваются напрямую вместо сортировки троек и списка подходящих имён; порядок потребляется токенами без отдельного списка числовых ID. Вывод собирается одним bytearray, при поздней неудаче заменяется на IMPOSSIBLE, поэтому частичный ответ не печатается. Имена состоят из строчных ASCII-букв, L<=20, байтовый порядок совпадает с лексикографическим. При B байтах ввода время O(B+nL), память O(B+nL), а не константная. Вывод сбрасывается перед os._exit(0). Измеренное время улучшено с0.093 до0.062секунды, память выросла с492 до776КБ; допуск обеспечивает время, экономия памяти не заявляется.

По сравнению с `1711_greedy.py`: время 0.093 s → 0.062 s; память 492 KB → 776 KB.

Оптимизированное решение на C++ читает через `scanf` в массив
фиксированного размера на 16 × 3 имени по 21 байту, которого хватает при
n ≤ 16 и 20 буквах с завершающим нулём, вместо вектора векторов
`std::string`, читаемых через `iostream`. Вместо сортировки трёх имён
задачи оно просматривает их через `strcmp` в поисках наименьшего после
предыдущего выбора, запоминает только указатели на выбранные имена и
печатает их через `puts`: {1711_greedy_optimized.cpp}.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1711_greedy_optimized.go`. Алгоритм и обработка границ сохранены. Вместо сканирования и печати через fmt используются разбор токенов и чисел и повторно используемый выходной буфер. Ввод целиком хранится в байтовом буфере: это обмен памяти под ввод на меньшие накладные расходы универсального ввода-вывода.

Accepted #11328588 (Go 1.14 x64): **0.031 s / 976 KB**. Архивное сравнение: `1711_greedy.go` (Go 1.14 x64) — 0.062 s / 1148 KB (#11289207).


`1711_greedy_parsing_optimized.rs`. Допустимые 16 записей, по три имени длиной не более 20 байт, хранятся фиксированно на стеке. Имена читаются ограниченными токенами, точный выбор минимального имени выше предыдущего сохранён, ограниченный ответ записывается один раз. Ввод, имена и ответ не требуют кучи.

Для этого точного исходника получен собственный Accepted и выполнены единые [рейтинговые критерии](../../RATING_CRITERIA.md). Время и память ниже взяты из одной посылки; повторные измерения судьи могут различаться. Существующие простые и отличающиеся оптимизированные версии сохранены.

Accepted #11329353 (Rust 1.75 x64): **0.015 s / 60 KB**.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
