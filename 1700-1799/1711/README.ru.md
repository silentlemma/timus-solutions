# 1711. Кодовые имена

[Timus 1711](https://acm.timus.ru/problem.aspx?space=1&num=1711) · сложность 135 · greedy

Автор оригинальной задачи — Алексей Самсонов, подготовка — Игорь Чевдарь; NEERC 2009, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У каждой из n задач есть три варианта кодового имени, и задачи в
комплекте идут в алфавитном порядке имён. Нужно выбрать по имени для
каждой задачи так, чтобы задачи шли в заданном порядке, или сообщить,
что это невозможно.

## Входные данные

n (1 ≤ n ≤ 16), затем n строк с тремя именами каждой задачи: строчные
латинские буквы, не больше 20, все имена различны. В последней строке —
требуемый порядок, перестановка чисел 1 … n.

## Выходные данные

Выбранные имена в требуемом порядке, по одному в строке, или
IMPOSSIBLE. Подходит любой правильный выбор.

## Примеры

### Пример 1

Ввод:

```
11
cipher grille kamkohob
names codenames codes
newtests rejudge timus
size volume summit
watchmen braineater twosides
solution random yesorno
keywords subversion commands
bosses shooting shaitan
game strategy playgame
mnemonic palindromes bestname
eligibility rectangle rules
2 1 7 10 9 6 11 3 8 4 5
```

Вывод:

```
codenames
grille
keywords
mnemonic
playgame
random
rectangle
rejudge
shaitan
volume
watchmen
```

### Пример 2

Ввод:

```
3
problems in the
first sample are
ordered not randomly
1 2 3
```

Вывод:

```
IMPOSSIBLE
```

## Решение

Идём по требуемому порядку и даём каждой задаче наименьшее из её имён,
которое идёт после предыдущего выбранного. Если такого нет, ответ —
IMPOSSIBLE.

Такой жадный выбор безопасен. Пусть правильный выбор существует;
сравним его с жадным задача за задачей. По индукции жадное имя никогда
не идёт позже правильного: правильное имя следующей задачи идёт после
правильного предыдущего, а значит, и после жадного предыдущего. Поэтому
оно — кандидат, и жадный выбор не больше него. Значит, жадный проход
никогда не застрянет. `O(n)` сравнений коротких строк.

Подводные камни:

- имена сравниваются как строки, и префикс идёт раньше: «code» перед
  «codenames»;
- строка порядка перечисляет номера задач по их местам в комплекте, а
  не место каждой задачи;
- подходит любой правильный ответ, поэтому тесты используют
  проверяющую программу.

Проверяющая программа убеждается, что каждое имя принадлежит своей
задаче и что имена возрастают. Ответы совпадают с независимой принятой
реализацией на 600 случайных комплектах.

## Оптимизированные решения

Оптимизированное решение на C++ читает через `scanf` в массив
фиксированного размера на 16 × 3 имени по 21 байту, которого хватает при
n ≤ 16 и 20 буквах с завершающим нулём, вместо вектора векторов
`std::string`, читаемых через `iostream`. Вместо сортировки трёх имён
задачи оно просматривает их через `strcmp` в поисках наименьшего после
предыдущего выбора, запоминает только указатели на выбранные имена и
печатает их через `puts`: {1711_greedy_optimized.cpp}.
