# 1792. Код Хэмминга

[Timus 1792](https://acm.timus.ru/problem.aspx?space=1&num=1792) · сложность 84 · implementation

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Четыре пересекающихся круга содержат по биту, а три лепестка — общие
части трёх кругов — содержат чётность суммы по кругам, которые их
накрывают. В порядке рисунка из условия лепесток j лежит во всех
кругах, кроме круга j, а четвёртый круг накрывает все три лепестка.
Изменено не более одного из семи битов. Восстановить правильный код.

## Входные данные

Семь битов: четыре круга, затем три лепестка.

## Выходные данные

Семь битов правильного кода, отличающегося от входа не более чем в
одном месте.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны. Выводятся семь восстановленных битов в исходном порядке.

## Примеры

### Пример 1

Ввод:

```
0 1 0 1 1 0 1
```

Вывод:

```
0 1 0 0 1 0 1
```

### Пример 2

Ввод:

```
1 1 1 1 1 1 1
```

Вывод:

```
1 1 1 1 1 1 1
```

## Решение

Проверяем слово как есть: лепесток j должен равняться сумме кругов,
кроме круга j, по модулю 2. Если проверка не прошла, по очереди меняем
каждый из семи битов и оставляем первую замену, после которой слово
правильное. Два правильных слова всегда отличаются хотя бы в трёх
местах, поэтому ответ единственный. `O(1)`.

В первом примере неверны все три лепестка, а под всеми ними лежит
только четвёртый круг; замена в нём 1 на 0 делает лепестки равными
1, 0, 1, как и записано.

Подводные камни:

- изменённым битом может быть сам лепесток, а не круг;
- слово может уже быть правильным, тогда оно выводится без изменений.

Все 128 возможных входов дают тот же ответ, что и независимая принятая
реализация.

## Оптимизированные решения

`1792_bitmask.py`. Три проверки чётности декодируются как синдром вместо построения и проверки восьми семибитных кандидатов. Один бит синдрома указывает на контрольный бит, синдром 7 — на бит данных 3, остальные двухбитные синдромы — на другой бит данных по отсутствующей проверке. При обещанной не более чем одной ошибке нужный бит инвертируется; нулевой синдром ничего не меняет. Этот другой метод bitmask получает отдельное имя; простой перебор кандидатов сохранён. Для семи бит оба метода имеют постоянный размер. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1792_implementation.py`: время 0.093 s → 0.14 s; память 464 KB → 264 KB.

Оптимизированные решения (C++, Java) читают семь битов как отдельные
символы через `getchar` и `System.in.read` вместо `iostream` и `Scanner`
и выводят ответ посимвольно (C++) или одним массивом байтов (Java).
Перебор одиночных изменений тот же. C++: 84 КБ вместо 396 КБ при том же
времени; Java: 0.109 с вместо 0.156 с и 380 КБ вместо 1604 КБ.

`1792_bitmask.rs`. Вместо перебора исправлений используется трёхбитный синдром проверок чётности. Ошибочный бит меняет ровно столбец своих проверок; семь столбцов — различные ненулевые трёхбитные комбинации. Нулевой синдром не требует изменения, иначе переворачивается единственный бит с этим столбцом. При не более чем одной ошибке все проверки восстанавливаются. Один фиксированный семибайтовый массив заменяет клоны кандидатов; время и память O(1). Rust использует среду выполнения C для ввода-вывода, без целых декодированных строк String и форматирования Rust. Простой принятый исходник сохранён без изменений.

По сравнению с `1792_implementation.rs`: время 0.046 s → 0.046 s; память 228 KB → 60 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1792_bitmask.py`: место по времени 63/69, по памяти 2/69 в этой сопоставимой выборке.

`1792_bitmask.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
