# 1786. Биография Сандро

[Timus 1786](https://acm.timus.ru/problem.aspx?space=1&num=1786) · сложность 110 · strings

Автор оригинальной задачи — Ольга Соболева; Уральская региональная командная олимпиада по программированию 2010.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Текст из латинских букв нужно изменить так, чтобы в нём встретилось
слово "Sandro". Замена буквы на другую букву того же регистра стоит
5 монет, смена регистра буквы — тоже 5. Найти наименьшую стоимость.

## Входные данные

Текст длиной от 6 до 200 букв.

## Выходные данные

Наименьшее число монет.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
MyNameIsAlexander
```

Вывод:

```
20
```

## Решение

Перебираем все места для шести букв имени. Буква стоит 5, если у неё
неверный регистр, и ещё 5, если это не та буква, так что буква,
неверная в обоих смыслах, стоит 10. Складываем шесть стоимостей в
каждом месте и берём наименьшую сумму. Сам перебор занимает `O(n)` времени,
но Python в каждой позиции копирует суффикс `text[start:]`, поэтому эта
реализация работает за `O(n^2)`. Все реализации используют `O(n)` памяти
с учётом входной строки; максимальная длина входа — всего 200.

В примере лучшее место — "xander": x нужна другая буква и заглавный
регистр — 10, а замены e → r и r → o стоят по 5, всего 20.

Подводные камни:

- неверная буква неверного регистра оплачивается дважды;
- в тесте 03, `sANDRO`, неверен регистр всех шести букв, поэтому стоимость — 30;
- имя может начинаться с самой первой буквы или кончаться самой
  последней.

Ответы Python совпадают с независимым оракулом на графе допустимых операций
на 2 000 случайных коротких текстах, 592 направленных проверках, всех 8
сохранённых тестах и 64 сгенерированных тестах.

## Оптимизированные решения

`1786_strings_optimized.py`. Сохраняется стоимость смены ASCII-буквы и её регистра на шесть букв Sandro. Для каждой позиции строится таблица из 256 байтов, весь текст переводится в шесть выровненных потоков стоимости, затем суммируются столбцы по шесть значений. Исключены повторные копии суффикса text[start:], из-за которых простой исходник квадратичен по копируемым символам, и вызовы Python-функции для каждой буквы. При фиксированных шести буквах время O(L), память потоков O(L), не константа. Принудительного выхода интерпретатора здесь нет. Собственный Accepted допускается по рейтингу даже без 30% выигрыша измерений.

По сравнению с `1786_strings.py`: время 0.109 s → 0.078 s; память 408 KB → 400 KB.

Оптимизированное решение на C++ читает текст через `scanf` в буфер на
201 байт, которого хватает на 200 букв и завершающий ноль, вместо
`std::cin` и `std::string`, а раз в тексте только латинские буквы,
регистр определяется сравнением с `'Z'`, а буква переводится в нижний
регистр прибавлением `'a' − 'A'` вместо вызовов `isupper` и `tolower`:
{1786_strings_optimized.cpp}.

Оптимизированное решение на Java читает текст посимвольно прямо из
`System.in` вместо создания `Scanner`, а раз в тексте только латинские
буквы, регистр определяется сравнением с `'Z'`, а буква переводится в
нижний регистр прибавлением `'a' − 'A'` вместо вызовов
`Character.isUpperCase` и `Character.toLowerCase`:
{1786_strings_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и проходит рейтинговый критерий
либо критерий сокращения ресурса.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1786_strings_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +68.42%; база: `1786_strings.cpp`.

- `1786_strings_optimized.java`: сокращение времени +28.44%; сокращение
  памяти +75.13%; база: `1786_strings.java`.

`1786_strings_optimized.rs`. В кольце хранятся только шесть последних букв. Для каждого полного окна суммируются независимые стоимости смены регистра и смены буквы без учёта регистра до Sandro. Шесть сравнений на позицию дают O(N) времени и O(1) памяти без хранения текста и создания срезов. Rust использует среду выполнения C для ввода-вывода, без целых декодированных строк String и форматирования Rust. Простой принятый исходник сохранён без изменений.

По сравнению с `1786_strings.rs`: время 0.031 s → 0.062 s; память 216 KB → 64 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1786_strings_optimized.py`: место по времени 2/32, по памяти 7/32 в этой сопоставимой выборке.

`1786_strings_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
