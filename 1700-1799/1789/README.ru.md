# 1789. В поисках Додекаэдра

[Timus 1789](https://acm.timus.ru/problem.aspx?space=1&num=1789) · сложность 220 · constructive

Автор оригинальной задачи — Михаил Рубинчик; Уральская региональная командная олимпиада по программированию 2010.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Артефакт стоит на одном из n постаментов в ряд, на остальных —
копии. Каждый ход касаются одного постамента. Если артефакт там, он
найден; если нет, артефакт переходит на соседний постамент, левый или
правый, на свой выбор. Вывести не более 1000 касаний, которые найдут
артефакт, где бы он ни стоял сначала и как бы ни двигался.

## Входные данные

n (2 ≤ n ≤ 100).

## Выходные данные

Число касаний, затем номера постаментов по порядку.

## Проверка

Проверяется последовательность не более чем из 1000 касаний с номерами 1..N; после каждого неуспешного касания распространяются все возможные положения предмета, и в итоге ни одно не должно сохраниться. Допустима любая последовательность с этой гарантией. Новый точный исходник Python прошёл 13 тестов репозитория на PyPy 3.10. Также 99 сравнений потоковой конструкции со списками для всех N=2..100. Остальные сохранённые варианты имеют собственные проверки целевой среды и точные Accepted. Вывод сравнивается по правилам проверяющего модуля задачи.

## Примеры

### Пример 1

Ввод:

```
3
```

Вывод:

```
2
2 2
```

## Решение

После каждого неудачного касания артефакт сдвигается, поэтому чётность его
постамента меняется каждый ход. Касаемся 2, 3, …, n − 1. Если при
первом касании артефакт стоит на чётном постаменте, то на каждом ходу
он имеет ту же чётность, что и тронутый, и стоит не левее, поэтому
перепрыгнуть его не может и будет пойман не позже чем на n − 1. Иначе
после этих n − 2 касаний его чётность совпадает с чётностью n − 1, и
касания n − 1, n − 2, …, 2 так же выметают его справа. При n > 2
постаменты 1 и n не трогаем: артефакт оттуда обязан шагнуть внутрь.
Всего 2(n − 2) касаний. При n = 2 середины нет вовсе, и подходит
двойное касание постамента 1. `O(n)`.

В примере оба прохода — одно касание постамента 2: артефакт на 2
пойман сразу, а с 1 или 3 он обязан перейти на 2.

Подводные камни:

- один проход слева пропускает артефакт с другой чётностью — он просто
  проскальзывает мимо;
- при n > 2 касаться крайних постаментов бесполезно: артефакт не
  может на них остаться;
- n = 2 требует отдельного ответа, формула даёт ноль касаний.

Чекер следит за множеством постаментов, где артефакт ещё может быть, и
требует, чтобы оно опустело. Проходят все n от 2 до 100, а полный
перебор таких множеств при n до 12 подтверждает, что более короткой
последовательности нет.

## Оптимизированные решения

`1789_constructive_optimized.java`. Сохраняются два прохода по тумбам: 2..N−1, затем N−1..2, и ответ 1,1 при N=2. Конструкция требует O(N) времени и фиксированных дополнительных буферов. Все числовые поля, нужные вычислению, потребляются до вывода. Один массив 256 байт сначала служит вводу, затем выводу; перед знаковым int резервируются двенадцать байт, разворачиваются только новые цифры. Убраны отдельные массивы ввода, вывода и цифр, нужные алгоритму данные не перезаписываются. Разбор и вывод линейны по потреблённым байтам, буфер фиксирован.

Accepted точного исходника Java 1.8 №11327766: 0.078 с / 368 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/35, память 1/35. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Обе метрики на первом месте: отдельная цель языка также пройдена, звёздочка не нужна. Прежний документированный оптимизированный запуск №11324970: 0.109 с / 504 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

Историческое описание и замеры прежней ревизии: `1789_constructive_optimized.java`. Сохраняются два прохода по классам чётности: 2..n-1 и n-1..2, а при n=2 — специальный ответ 1,1. Число касаний заранее равно 2(n-2), номера выводятся по мере проходов. ## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1789_constructive_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
