# 1757. 金条

[Timus 1757](https://acm.timus.ru/problem.aspx?space=1&num=1757) · 难度 2343 · binary_search

原题作者 Vassily Burnin，出自 2010 年 3 月 13 日第十一届乌拉尔国立大学公开个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n 根金条；第 i 根重 mᵢ 克，成色为 pᵢ（每千克合金中金的克数）。可以取任意金条的任意部分。铸造一根重 m 克、成色为 p 的金条，或者报告做不到。

## 输入

n、m 和 p（1 ≤ n ≤ 1000，1 ≤ m ≤ 10⁶，0 ≤ p ≤ 1000），然后是每根金条的 mᵢ 和 pᵢ（1 ≤ mᵢ ≤ 1000，0 ≤ pᵢ ≤ 1000）。

## 输出

`NO`，或者 `YES` 以及从每根金条取的克数 xᵢ，满足 |Σxᵢ − m| < 10⁻⁶ 且 |Σxᵢpᵢ/1000 − mp/1000| < 10⁻⁶。任何符合要求的取法都可以。

## 样例

### 样例 1

输入：

```
4 150 750
100 1000
150 585
100 750
100 0
```

输出：

```
YES
75.000000000
0.000000000
50.000000000
25.000000000
```

### 样例 2

输入：

```
1 100 1000
200 0
```

输出：

```
NO
```

## 解法

把金条按成色从低到高排成一行，共 M 克，考虑从 s 开始的长 m 克的窗口。窗口中的金量 G(s) 随 s 右移不减（窗口丢掉较差的金属、纳入较好的），并且连续变化。
任意 m 克的选择所含的金不少于 s = 0 时的窗口，也不多于 s = M − m 时的窗口。所以当且仅当 M ≥ m 且 G(0) ≤ m·p ≤ G(M − m) 时可以铸造，两个边界都用整数计算。

若可以，对 s 二分查找使 G(s) = m·p，各部分就是窗口与金条的重叠：窗口内的整根金条，加上两端至多两根被切开的金条。
G(s) 只需扫一遍金条，或在重量和金量的前缀和上二分，所以总复杂度为 `O(n log n + K·n)`，K = 100 次区间折半。被切开的金条少，也使输出各部分的舍入误差远低于 10⁻⁶。

样例 1 中金条按顺序成色为 0、585、750、1000。s = 0 时窗口含 100 克成色 0 和 50 克成色 585，共 29.25 克金；最远端含 50 克成色 750 和 100 克成色 1000，共 137.5 克。
订单需要 112.5 克，所以窗口停在中间：约 30.12 克 585 的金条、整根 750 的金条和约 19.88 克 1000 的金条。这是与样例不同的另一个合法答案。

注意事项：

- 订单比整个仓库还重时，任何成色都做不到；
- 是否可行的判断不能依赖浮点数：边界 G(0) 和 G(M − m) 是整数和；
- 按比例混合许多金条会使每一部分都是长小数，1000 个舍入后的部分可能吃掉 10⁻⁶ 余量的大部分。

在 500 个随机仓库上（许多成色恰在边界或刚越过边界），哪些订单可行的判断与一个独立的已通过实现一致，并且每个答案都通过了检查两个条件和金条重量的检查器。
