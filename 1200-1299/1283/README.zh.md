# 1283. 小矮人

[Timus 1283](https://acm.timus.ru/problem.aspx?space=1&num=1283) · 难度 116 · math

原题作者 Leonid Volkov（由 Ivan Dashkevich 准备），出自 2004 年乌拉尔国立大学个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

小矮人有 G 单位黄金，银行每年收取 p% 作为手续费（1 ≤ p ≤ 99），所以黄金每年变
为原来的 (100 − p)/100。当黄金不超过 L 时，小矮人就失去了活下去的意义。G 和 L 都
是不超过 2³¹ − 1 的整数。还剩几年？

时间限制：1 秒。内存限制：64 MB。

## 输入

G、L 和 p。

## 输出

年数。

## 样例

### 样例 1

输入：

```
19 10 50
```

输出：

```
1
```

### 样例 2

输入：

```
1000 1 1
```

输出：

```
688
```

## 解法

k 年后黄金恰好是 G · ((100 − p)/100)^k，答案是使它不超过 L 的最小 k。用整数表示，检验条件为

```text
G · (100 − p)^k ≤ L · 100^k
```

所以每年把两边分别乘以 100 − p 和 100，直到左边不再更大。当 G = 2³¹ − 1、L = 1、p = 1 时
循环最多执行约 2140 次，数字增长到几千位。Y 年时为 `O(Y²)` 次数位运算。

上述循环次数的估计假设 G 和 L 都为正数，而题面没有给出它们的下界：当 G > 0、
L = 0 时，经过任意有限年数，黄金仍为正数，不存在有限答案。

注意事项：

- 黄金可能恰好落在上限上，而浮点数会错过它：300 · 0.81 算出来是 243.00000000000003，
  L = 243 时多算一年（测试 05）；ln(9801/10000) / ln(0.99) 向上取整得到三年而不是两年
  （测试 06）；
- 若黄金已经不超过 L，答案为 0（测试 03、04）。

## 优化解法

优化的 Java 解法把两边各存为一个以 10⁹ 为基数的数位数组，就地相乘，只在出现新数
位时才扩大数组，而不是每年创建两个新的 `BigInteger` 对象；一个数位乘以不超过 100
的数再加上进位，仍小于 10¹¹，放得进 `long`。G、L 和 p 直接从 `System.in` 逐位读
入 `int`（它们不超过 2³¹ − 1，放得下），而不是创建 `Scanner`：
