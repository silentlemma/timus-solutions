# 1283. 小矮人

[Timus 1283](https://acm.timus.ru/problem.aspx?space=1&num=1283) · 难度 116 · math

原题作者 Leonid Volkov（由 Ivan Dashkevich 准备），出自 2004 年乌拉尔国立大学个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

小矮人有 G 单位黄金，银行每年收取 p% 作为手续费（1 ≤ p ≤ 99），所以黄金每年变
为原来的 (100 − p)/100。当黄金不超过 L 时，小矮人就失去了活下去的意义。G 和 L 都
是不超过 2³¹ − 1 的整数。还剩几年？

时间限制：1 秒。内存限制：64 MB。

## 输入

G、L 和 p。

## 输出

年数。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
81 64 20
```

输出：

```
2
```

### 样例 2

输入：

```
625 256 20
```

输出：

```
4
```

## 解法

k 年后黄金恰好是 G · ((100 − p)/100)^k，答案是使它不超过 L 的最小 k。用整数表示，检验条件为

```text
G · (100 − p)^k ≤ L · 100^k
```

所以每年把两边分别乘以 100 − p 和 100，直到左边不再更大。当 G = 2³¹ − 1、L = 1、p = 1 时
循环最多执行约 2140 次，数字增长到几千位。对 `Y` 年和有界的正初始输入，每个乘积
含 `O(Y+1)` 个数字或固定基数的数肢。因此简单版本需要 `O((Y+1)²)` 次数位
操作和 `O(Y+1)` 个同时存活的辅助数字/数肢，包括乘法临时值。`+1` 也涵盖
立即返回零年的情况。输入和缓冲区另计：Rust 保留输入字符串，Python 保留输入行，
其他简单版本使用有界 scanner/stdio 缓冲区。规定格式中只有三个有界整数。

上述循环次数的估计假设 G 和 L 都为正数，而题面没有给出它们的下界：当 G > 0、
L = 0 时，经过任意有限年数，黄金仍为正数，不存在有限答案。

注意事项：

- 黄金可能恰好落在上限上，而浮点数会错过它：300 · 0.81 算出来是 243.00000000000003，
  L = 243 时多算一年（测试 05）；ln(9801/10000) / ln(0.99) 向上取整得到三年而不是两年
  （测试 06）；
- 若黄金已经不超过 L，答案为 0（测试 03、04）。

## 优化解法

`1283_binary_search_math.py`. 通过倍增括界及精确整数幂二分，找首年 Y 满足 G(100−p)^Y≤L100^Y。无需对数、gcd/math 导入或逐年大整数乘循环。G≤L 含零立即处理，保留精确相等边界。操作数 D 位、乘法 M(D) 下保守 O(log²(Y+2)·M(D)) 时间、O(D) 存储。搜索算法独立名，保留简单逐年版。

与 `1283_math.py` 相比：时间 0.078 s → 0.125 s；内存 480 KB → 264 KB。

优化的 Java 解法把两边各存为一个以 10⁹ 为基数的数位数组，就地相乘，只在出现新数
位时才扩大数组，而不是每年创建两个新的 `BigInteger` 对象；一个数位乘以不超过 100
的数再加上进位，仍小于 10¹¹，放得进 `long`。G、L 和 p 直接从 `System.in` 逐位读
入 `int`（它们不超过 2³¹ − 1，放得下），而不是创建 `Scanner`：
[1283_math_optimized.java](1283_math_optimized.java)。

- `1283_math_optimized.java`: 时间降低 +0.00%; 内存降低 +93.57%; 基础版本: `1283_math.java`.

`1283_math_optimized.rs`. 保留 G*(100-p)^Y 与 L*100^Y 的精确比较，但先用最大公约数约分 G/L 和 (100-p)/100。检查乘法成功时两个乘积保存在 u128 中；溢出时，把两个尚未相乘的原值一起转成 10^9 进制 u32 数位，继续精确计算。G<=L 时在约分前返回零。不用对数、浮点数或 epsilon 决定终止边界。设年数 Y、最多 D 个数位，时间 O((Y+1)·D)，空间 O(D)；窄数位与原生整数快路径降低开销。 Rust 版本通过 C 运行库读写，不保留解码后的输入 String，也不构造格式化的输出 String。保留简单版本及其 Accepted。

与 `1283_math.rs` 相比：时间 0.015 s → 0.031 s；内存 232 KB → 68 KB。
