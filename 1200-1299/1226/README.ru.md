# 1226. Каждое слово задом наперёд

[Timus 1226](https://acm.timus.ru/problem.aspx?space=1&num=1226) · сложность 114 · strings

Оригинальная задача — четвертьфинал ACM ICPC 2002–2003, центральный регион России, Рыбинск, октябрь 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Условие оставляет преобразование угадать по примеру: текст до 1000 строк
длиной до 255 печатных символов нужно воспроизвести, записав буквы каждого слова
в обратном порядке. Слово — максимальная последовательность латинских
букв, заглавных или строчных; все остальные символы остаются на месте.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Текст.

## Выходные данные

Текст, в котором каждое слово перевёрнуто.

## Примеры

### Пример 1

Ввод:

```
This is an example of a simple test. If you did not 
understand the ciphering algorithm yet, then write the 
letters of each word in the reverse order. By the way, 
"reversing" the text twice restores the original text.
```

Вывод:

```
sihT si na elpmaxe fo a elpmis tset. fI uoy did ton 
dnatsrednu eht gnirehpic mhtirogla tey, neht etirw eht 
srettel fo hcae drow ni eht esrever redro. yB eht yaw, 
"gnisrever" eht txet eciwt serotser eht lanigiro txet.
```

## Решение

Идём по тексту: как только начинается последовательность букв, находим
её конец и переворачиваем её. Цифры, знаки препинания, пробелы и
переводы строк не трогаются, так что текст сохраняет точное
расположение. `O(L)` для `L` символов.

Тонкие места:

- строки могут кончаться пробелами, и они должны остаться, поэтому текст
  не разбивается на слова и не склеивается обратно;
- слово кончается на любом не-букве, в том числе на цифре или
  подчёркивании: `abc123` превращается в `cba123`;
- у последней строки может не быть перевода строки, и добавлять его
  нельзя.

Вывод сверен посимвольно с ожидаемым текстом на всех тестах, включая
1000 строк случайных печатных символов.

## Оптимизированные решения

Оптимизированное решение на C++ читает текст через `getchar` и хранит
только текущее слово в буфере на 255 байт, которого хватает, ведь слово
не переходит через строку, а в строке не больше 255 символов; слово
печатается задом наперёд, как только его заканчивает не-буква, вместо
того чтобы собирать весь текст в `std::string`:
{1226_strings_optimized.cpp}.

Оптимизированное решение на Java читает весь ввод байтами блоками по
64 КБ и переворачивает последовательности букв на месте в этом массиве
байтов, вместо декодирования символов через reader и writer и создания
строки для каждого слова: {1226_strings_optimized.java}.

Оптимизированное решение на Python обрабатывает по одной строке в
`bytearray` и переворачивает последовательности букв срезами, вместо
импорта модуля регулярных выражений и замены по всему тексту; слово не
переходит через строку, так что это безопасно. Так тратится меньше
памяти, но цикл по каждому символу идёт на Python и стоит времени:
{1226_strings_optimized.py}.

## Особенности языков

В срезе рейтинга от 31 октября 2026 года следующие базовые реализации
уже достигают целей по времени и памяти. Сохраняются их существующие
файлы в базовом наборе; для достижения рейтинговой цели на этих языках
дополнительная реализация не требуется.

- [1226_strings.rs](1226_strings.rs).

- Python переворачивает каждое совпадение регулярного выражения над
  сырыми байтами; C++, Go и Rust читают весь ввод и переворачивают
  последовательности букв на месте; Java читает текст посимвольно в
  кодировке Latin-1, которая сохраняет каждый байт как есть, и печатает
  слово перевёрнутым, когда его заканчивает не-буква.
