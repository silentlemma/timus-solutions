# 1296. Гиперпереход

[Timus 1296](https://acm.timus.ru/problem.aspx?space=1&num=1296) · сложность 60 · dp

Автор оригинальной задачи — Ден Расковалов; IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дана последовательность из N ≤ 60 000 целых чисел от −30 000 до 30 000.
Нужно найти наибольшую сумму непрерывного отрезка. Пустой отрезок
разрешён и даёт 0.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N чисел по одному в строке. N может быть равно 0.

## Выходные данные

Наибольшая сумма.

## Проверка

Сравнение токенов (`judging: tokens` в `tests/tests.json`). Ответ —
одно целое число; пробелы вокруг него не влияют на результат.

## Примеры

### Пример 1

Ввод:

```
8
-8
12
-3
9
-20
7
6
-2
```

Вывод:

```
18
```

### Пример 2

Ввод:

```
4
-9
-2
-7
-4
```

Вывод:

```
0
```

## Решение

Это задача о максимальном подмассиве, которая решается алгоритмом
Кадане за один проход. Храним `ending` — наибольшую сумму отрезка,
оканчивающегося на текущем числе, причём пустой отрезок тоже считается.
Каждое новое число p либо продлевает этот отрезок, либо, если сумма
стала бы отрицательной, его лучше не брать:

ending = max(ending + p, 0).

Ответ — наибольшее значение, которое принимает `ending`; оно начинается
с 0 для пустого отрезка. Читаем целое число со знаком, прибавляем его к
`ending`, заменяем отрицательное `ending` на 0 и обновляем `best`.
Время — `O(N)`, дополнительная память — `O(1)`; простые решения на
Python и Rust буферизуют вход, используя `O(N)` памяти.

Тонкие места:

- если все числа отрицательны, ответ — 0, а не наибольшее число
  (тест 02);
- N = 0 допустимо (тест 03);
- явный плюс допустим: в Java его нужно пропустить перед чтением
  числового токена, чтобы `+0` читалось как 0 (тест 09);
- сумма доходит до 60 000 · 30 000 = 1,8 · 10⁹, близко к пределу 32
  бит, поэтому решения используют 64 бита (тест gen2).

Независимый оракул пар префиксов методом разделяй и властвуй проверяет
все готовые и сгенерированные ответы. Он сверен с перебором всех
отрезков на всех малых последовательностях и 1500 случайных с фиксированным
seed. Обе настоящие Python main отдельно запускаются на хосте.

## Оптимизированные решения

Оптимизированное решение на Python читает числа построчно, по одному в
строке, вместо разбиения всего ввода и сравнивает текущие суммы напрямую
вместо вызова `max()`: 0.078 с вместо 0.125 с и 388 КБ вместо 4788 КБ.
Оптимизированное решение на Rust читает числа построчно через буфер на
1 КБ вместо чтения всего ввода в строку. Парные Accepted: база
#11297982 `0.031 s / 1260 KB`, быстрая #11303736 `0.015 s / 228 KB`:
снизились и время, и память. Это замеры записанных точных байтов,
а не переносимая гарантия времени выполнения.

## Особенности языков

- Все языки хранят лишь две текущие суммы, `best` и `ending`.
- C++, Go и Java, а также оптимизированные решения на Python и Rust
  используют `O(1)` общей памяти; простые решения на Python и Rust —
  `O(N)` общей памяти из-за буферизации входа.

Читаем числа из буфера блоками и обновляем максимум суммы отрезка при поступлении каждого числа. Принятая посылка 11302135 заняла 0,015 с и использовала 100 КБ. Простая версия заняла 0,046 с и использовала 132 КБ.

Комментарии быстрых Python и Rust теперь правильно называют вход
значениями последовательности, а не ценами. Изменены только эти
комментарии, алгоритмы и остальные содержательные комментарии сохранены. Строки Accepted #11303735 и #11303736 относятся к прежним точным байтам.

Пусть I — размер входа, H — длина самой длинной строки. Арифметика
хранит две текущие суммы, но построчное чтение также хранит строку:
быстрый Rust использует `O(1024+H)`, Python — `O(B+H)` с буферами B.
При одном ограниченном числе в строке это константа; произвольное
дополнение пробелами увеличило бы H. Простые Python/Rust хранят I.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
