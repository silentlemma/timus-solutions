# 1296. Гиперпереход

[Timus 1296](https://acm.timus.ru/problem.aspx?space=1&num=1296) · сложность 60 · dp

Автор оригинальной задачи — Ден Расковалов; IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дана последовательность из N ≤ 60 000 целых чисел от −30 000 до 30 000.
Нужно найти наибольшую сумму непрерывного отрезка. Пустой отрезок
разрешён и даёт 0.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N чисел по одному в строке. N может быть равно 0.

## Выходные данные

Наибольшая сумма.

## Примеры

### Пример 1

Ввод:

```
10
31
-41
59
26
-53
58
97
-93
-23
84
```

Вывод:

```
187
```

### Пример 2

Ввод:

```
3
-1
-5
-6
```

Вывод:

```
0
```

## Решение

Это задача о максимальном подмассиве, которая решается алгоритмом
Кадане за один проход. Храним `ending` — наибольшую сумму отрезка,
оканчивающегося на текущем числе, причём пустой отрезок тоже считается.
Каждое новое число p либо продлевает этот отрезок, либо, если сумма
стала бы отрицательной, его лучше не брать:

ending = max(ending + p, 0).

Ответ — наибольшее значение, которое принимает `ending`; оно начинается
с 0 для пустого отрезка. Читаем целое число со знаком, прибавляем его
к `ending`, заменяем отрицательное `ending` на 0 и обновляем `best`.
Время — `O(N)`, дополнительная память — `O(1)`; Python и Rust
буферизуют вход, используя `O(N)` памяти.

Тонкие места:

- если все числа отрицательны, ответ — 0, а не наибольшее число
  (тест 02);
- N = 0 допустимо (тест 03);
- явный плюс допустим: в Java его нужно пропустить перед чтением
  числового токена, чтобы `+0` читалось как 0 (тест 09);
- сумма доходит до 60 000 · 30 000 = 1,8 · 10⁹, близко к пределу 32
  бит, поэтому решения используют 64 бита (тест gen2).

Ответы сравнивались с перебором всех отрезков на 1500 случайных
последовательностях.

## Особенности языков

- Все языки хранят лишь две текущие суммы, `best` и `ending`.
- C++, Go и Java используют `O(1)` общей памяти; Python и Rust —
  `O(N)` общей памяти из-за буферизации входа.
