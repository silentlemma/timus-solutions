# 1248. Сложение чисел с 19 значащими цифрами

[Timus 1248](https://acm.timus.ru/problem.aspx?space=1&num=1248) · сложность 659 · math

Автор оригинальной задачи — Александр Клепинин; личное первенство УрГУ, 1 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Сложить до 1000 чисел, записанных в экспоненциальной форме с 19
значащими цифрами каждое, все от 10⁻¹⁰⁰ до 10¹⁰⁰, и вывести сумму в
экспоненциальной форме с 19 верными значащими цифрами.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N чисел по одному в строке.

## Выходные данные

Сумма в виде `d.ddddddddddddddddddeE`.

## Примеры

### Пример 1

Ввод:

```
2
1.5e3
1.5e-3
```

Вывод:

```
1.500001500000000000e3
```

## Решение

Double хранит лишь 15–17 цифр, и даже 80-битный long double теряет
малые слагаемые рядом с большими, поэтому сумма считается точно. Каждое
входное число — целое кратное 10⁻³⁰⁰ (19 цифр ниже 10⁻¹⁰⁰ доходят
примерно до 10⁻¹¹⁹), так что после умножения на 10³⁰⁰ оно становится
точным целым: цифры мантиссы, умноженные на степень десяти. Целые
складываются точно, сумма обрезается до 19 старших цифр с округлением
остатка вверх от половины и выводится с порядком
`(число цифр − 1) − 300`. Если округление превращает 19 цифр в 10¹⁹,
мантисса становится единицей с нулями, а порядок растёт на единицу.
`O(N · L)` при L ≈ 400 цифр.

Тонкие места:

- малые числа влияют только на цифры после 19-й, но всё же могут сдвинуть
  её округлением: тест 04 стоит ровно на половине, тест 05 — чуть ниже;
- сумма двух чисел меньше 10¹⁰⁰ может дойти до 2·10¹⁰⁰, а округление —
  перенестись в новую степень десяти (тест 03);
- порядок выводится как есть, `e3` и `e-100`, без плюса и ведущих нулей.

## Особенности языков

- Python использует свои точные целые, Go — `math/big`; Java складывает
  `BigDecimal` и округляет через `MathContext(19, HALF_UP)`; C++ и Rust
  хранят по одной знаковой сумме цифр на каждую степень десяти и
  разносят переносы в конце.
