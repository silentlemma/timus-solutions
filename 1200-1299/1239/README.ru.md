# 1239. Один луч через как можно больше шаров

[Timus 1239](https://acm.timus.ru/problem.aspx?space=1&num=1239) · сложность 3015 · geometry

Автор оригинальной задачи — Роман Елизаров; полуфинал ACM ICPC Северо-Восточной Европы 2002–2003.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Пушка в начале координат стреляет одним лучом в октант x, y, z ≥ 0.
Есть N привидений (0 ≤ N ≤ 100) — шаров с целыми центрами (X, Y, Z),
1 ≤ X, Y, Z ≤ 10 000, и целым радиусом 1 ≤ R ≤ min(X, Y, Z); луч убивает
каждое привидение, которого касается, хотя бы в одной точке. Найти
наибольшее число убитых одним лучом привидений и их номера.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем каждое привидение в виде `X Y Z R`.

## Выходные данные

Максимальное число привидений, затем их номера в любом порядке.

## Проверка

Лучших групп может быть несколько, поэтому чекер принимает любую: число
должно совпадать с максимальным числом, номера — быть различными, и
должен существовать луч, касающийся всех перечисленных привидений. Чекер
ищет такой луч в 50-значной десятичной арифметике.

## Решение

Из пушки привидение с центром C видно как круговой конус: луч вдоль d
касается его ровно тогда, когда `d·C ≥ L·|d|`, где `L = √(|C|² − R²)` —
длина касательной из начала координат. На сфере направлений каждое
привидение — шапочка, и нужна точка, покрытая наибольшим числом шапочек.

Шапочки, содержащие лучшую точку, пересекаются по выпуклой области. Либо
эта область — одна шапочка, и тогда её центр лежит во всех, либо у неё
есть угол, где контуры двух шапочек пересекаются или касаются. Поэтому
достаточно перебрать направления на центры и точки встречи двух контуров,
`O(N²)` кандидатов, и для каждого посчитать содержащие его шапочки.
`O(N³)`.

При det > 0 контуры шапочек i и j встречаются в единичных векторах
`d = (a·C_i + b·C_j ± c·C_i×C_j)` с `d·C_i = L_i` и `d·C_j = L_j`.
Обозначив `g = C_i·C_j` и `det = |C_i|²|C_j|² − g²`,

```text
a·det = L_i|C_j|² − L_j·g,   b·det = L_j|C_i|² − L_i·g,   c² = Q / det²,
Q = det − L_i²|C_j|² − L_j²|C_i|² + 2g·L_i·L_j
```

Вся трудность — в точности: первый пример работает только потому, что два
конуса касаются в точности, а касания достаточно. Поэтому всё, что можно
решить в целых числах, решается в них:

- центр шапочки i лежит в шапочке k, когда `(C_i·C_k)² ≥ L_k²·|C_i|²` —
  всё целое;
- контуры встречаются при Q ≥ 0, где Q — целое число плюс
  `2g·√(L_i²L_j²)`; его знак получается сравнением квадратов в 128-битных
  целых, так что касание даёт ровно Q = 0 и одну точку;
- когда Q, `a·det` и `b·det` — разности почти равных чисел, они
  вычисляются через сопряжённое, `x − y = (x² − y²)/(x + y)`, с точным
  числителем.

Только последняя проверка — лежит ли точка-кандидат в третьей шапочке —
использует относительный допуск 10⁻⁹.

Тонкие места:

- одинаковые конусы у масштабированных привидений, вроде
  `(1200, 1200, 3900, 300)` и `(2400, 2400, 7800, 600)`, имеют совпадающие
  контуры (det = 0), поэтому пара пропускается; точки с
  другими шапочками всё равно учитывают обе (тест 09);
- чуть более тонкая копия должна промахнуться мимо точки касания
  (тест 08);
- без привидений ответ — 0 и пустой список.

Ответы сравнивались с тем же перебором в 80-значной десятичной арифметике
на 600 случайных маленьких случаях, многие из которых составлены из
масштабированных и отражённых копий.

## Особенности языков

- C++ и Rust используют 128-битные целые для точных знаков, Go —
  `math/big`, Java — `BigInteger`; целые Python и так точны.
