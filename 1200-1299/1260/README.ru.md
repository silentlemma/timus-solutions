# 1260. Фотограф-зануда

[Timus 1260](https://acm.timus.ru/problem.aspx?space=1&num=1260) · сложность 112 · dp

Автор оригинальной задачи — Александр Ипатов; открытое командное соревнование школьников Свердловской области по программированию, 11 октября 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N студентов в возрасте 1, 2, …, N лет (1 ≤ N ≤ 55) садятся в ряд.
Однолетний сидит с левого края, а возрасты любых двух соседей
отличаются не больше чем на 2. Сколько существует таких рядов?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N.

## Выходные данные

Число рядов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
4
```

## Решение

Пусть a(k) — число рядов для возрастов 1..k. Посмотрим, кто сидит
вторым:

- возраст 2: остальное — ряд из 2..k, начинающийся с 2, та же задача со
  сдвигом на единицу, a(k − 1) способов;
- возраст 3, затем 2: следующим обязан быть 4, а остальное — ряд из 4..k,
  начинающийся с 4, a(k − 3) способов;
- возраст 3, а 2 позже: соседями 2 могут быть только 1, 3 и 4, а 1 и 3
  уже сидят рядом друг с другом, поэтому 2 сидит с правого края рядом с
  4. Это вынуждает зигзаг 1, 3, 5, … вверх по нечётным возрастам и назад
  вниз по чётным до 4, 2: ровно один ряд.

Итак, a(k) = a(k − 1) + a(k − 3) + 1, где a(1) = a(2) = 1 и a(3) = 2.
Если продолжить правило назад, получится a(0) = 0 и a(−1) = −1, и цикл
можно начинать с k = 1 без особых случаев. a(55) = 1 388 937 263 ещё
помещается в 32 бита, но C++, Go, Java и Rust используют 64-битные
целые, а Python — свои целые произвольной точности. `O(N)`.

Тонкие места:

- третий случай легко упустить: при N = 5 это ряд 1, 3, 5, 4, 2
  (тест 05);
- при N = 1 и N = 2 ряд ровно один (тесты 02, 03).

Рекуррента сравнивалась с перебором всех перестановок для N до 10.

## Оптимизированные решения

`1260_dp_optimized.py`. Сохраняются a(k)=a(k-1)+a(k-3)+1 и начальное состояние (-1,0,1). Три накопителя остаются без дополнительной таблицы: на каждом шаге все три прежних значения сдвигаются одновременно. Время O(N), три ячейки ограниченных целых. При N<=55 количество помещается в знаковые64 бита; достаточно консервативной границы a(N)<2^N. Читается один байтовый токен, рекуррентность выполняется без вызова функции-обёртки. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1260_dp.py`: время 0.109 s → 0.125 s; память 404 KB → 200 KB.

`1260_dp_optimized.rs`. Сохраняются a(k)=a(k-1)+a(k-3)+1 и начальное состояние (-1,0,1). Три накопителя остаются без дополнительной таблицы: на каждом шаге все три прежних значения сдвигаются одновременно. Время O(N), три ячейки ограниченных целых. При N<=55 количество помещается в знаковые64 бита; достаточно консервативной границы a(N)<2^N. Используются накопители i64 и прямой вывод результата, без декодированного ввода и форматирования Rust. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1260_dp.rs`: время 0.015 s → 0.031 s; память 232 KB → 56 KB.

Оптимизированное решение на Java читает единственное число N по цифрам
прямо из `System.in` вместо создания `Scanner`, подготовка которого
обходится гораздо дороже самой рекуррентности, не более 54 шагов;
вычисление то же: {1260_dp_optimized.java}.
