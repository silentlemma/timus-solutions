# 1294. Марсианские спутники

[Timus 1294](https://acm.timus.ru/problem.aspx?space=1&num=1294) · сложность 317 · geometry

Автор оригинальной задачи — Владимир Яковлев; IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Четыре спутника A, B, C и D лежат на одной круговой орбите в этом
порядке. Известны расстояния AD, AC, BD и BC в тысячах километров
(целые числа от 1 до 10 000); радиус орбиты неизвестен. Нужно найти
расстояние CD в километрах, округлённое до целого, или сообщить, что
однозначно его определить нельзя.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

AD, AC, BD и BC.

## Выходные данные

`Distance is X km.` или `Impossible.`

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
50 40 40 14
```

Вывод:

```
Distance is 30000 km.
```

## Обновление принятых посылок

Исправление пробельного ввода Python имеет Accepted точного исходника
#11330228 (`0.093 s / 424 KB`) в таблице. Прежние измерения исторические.
Сохранённые численные сравнения подтверждают C++, Go, Java и Python;
у Rust есть Accepted, но нет сопоставимого рейтингового эталона.
Учебные и отличающиеся быстрые реализации сохранены.

## Решение

Обозначим a = AD, b = AC, c = BD, d = BC и x = CD. Точки A и B лежат на
одной дуге, отсекаемой хордой CD, поэтому видят её под одним и тем же
вписанным углом t. Теорема косинусов в треугольниках ACD и BCD даёт

x² = a² + b² − 2ab cos t = c² + d² − 2cd cos t —

два уравнения относительно x² и cos t. Отсюда

cos t = (a² + b² − c² − d²) / (2 (ab − cd)),

x² = (ab (c² + d²) − cd (a² + b²)) / (ab − cd).

- Если ab = cd, уравнения либо противоречат друг другу, либо ничего не
  говорят об t. Во втором случае, например у равнобокой трапеции, CD
  действительно может принимать много значений (тест 02). В любом
  случае ответ — `Impossible.` (тесты 02 и 03).
- Если |a² + b² − c² − d²| ≥ 2 |ab − cd|, невырожденного треугольника
  нет: равенство тоже недопустимо, поскольку три различные точки
  окружности не могут лежать на одной прямой (тесты 04 и 07).
- По теореме Птолемея для заданного порядка вершин AB · CD = bc − ad > 0.
  При bc ≤ ad ответ — `Impossible.` (тесты 05 и 07). Вместе со строгой
  границей для косинуса эта проверка гарантирует нужный порядок
  восстановленных точек.
- Иначе x = 1000 · √x² километров с округлением.

Все проверки существования делаются в точных 64-битных целых
(исходные произведения меньше 2 · 10¹⁶). Приведём числитель и знаменатель
к положительным значениям. Вещественный квадратный корень даёт оценку
целой части m расстояния в километрах; округляем вверх точно тогда, когда
(2m + 1)² ≤ floor(4 · 1000² · num / den). Чтобы избежать переполнения,
вычисляем правую часть как s · (num div den) + (s · (num mod den)) div den,
где s = 4 · 1000². Новые промежуточные значения меньше 2 · 10¹⁵.
Время и дополнительная память — `O(1)`.

Исправленные проверки существования и округлённые ответы проверяются
независимым восстановлением AB, строгими неравенствами треугольника
и порядком точек, затем всеми четырьмя хордами и общей окружностью
в рациональных координатах. Дополнительно проверены Птолемей и точное
округление. Неизменённая Python main совпадает на всех 20736 четвёрках
из `[1, 12]` и 1000 случайных входах полного диапазона с фиксированным seed.

Тонкие места:

- входные данные в тысячах километров, ответ — в километрах (тест 01);
- AD · AC = BD · BC не всегда означает противоречивые данные: иногда
  это означает много ответов (тесты 02 и 03);
- одного косинуса в [−1, 1] недостаточно: нужно исключить вырожденные
  треугольники и проверить порядок вершин (тест 07).

## Оптимизированные решения

`1294_geometry_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1294_geometry.java`: время 0.109 s → 0.093 s; память 1 600 KB → 452 KB.

Rust после проверки единственности геометрического ответа представляет квадрат длины хорды дробью с целыми числителем и знаменателем. Дробь масштабируется для удвоенного расстояния в километрах с разделением частного и остатка перед умножением. Приближение квадратного корня уточняется целочисленными сравнениями квадратов. Его целая часть определяет итоговое округление без форматирования вещественного числа. Ввод и весь ответ помещаются в фиксированные байтовые буферы. Rust читает и пишет через библиотеку времени исполнения C.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 56 KB при 220 KB у базовой.

Сохранённый аудит точных исходников допускает простые C++ и Python без
дубликатов быстрых файлов. Простая Go #11325573 (`0.015 s / 1080 KB`)
превышает порог памяти малой группы 1016.60 КБ; быстрая #11328935
(`0.015 s / 804 KB`) проходит только по времени. Простая Java #11325554
не проходит нужный рейтинг памяти; быстрая #11325015 с 452 КБ проходит
обычный рейтинг времени. Эти простые файлы сохранены для обучения.
Оба Rust имеют подтверждённый Accepted, но в сохранённом аудите нет
допустимого чужого эталона: численный рейтинг неизвестен, а не доказанно
провален. Прежнее общее утверждение о допуске базовых файлов устарело.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1294_geometry_parsing_implementation_optimized.go`. Разбор токенов и числовой вывод специализированы по реально используемым типам; неиспользуемые универсальные ветви удалены, алгоритм и комментарии сохранены. Вместо полного ввода хранится пополняемый буфер на 8192 байта. Значение токенов и обработка частичного чтения и EOF сохранены.

Accepted #11328935 (Go 1.14 x64): **0.015 s / 804 KB**. Архивное сравнение: `1294_geometry.go` (Go 1.14 x64) — 0.015 s / 1080 KB (#11325573).

## Особенности языков

Общие [рейтинговые критерии](../../RATING_CRITERIA.md) одинаковы для языков:
обычные топ-10 или топ-15% по нужным метрикам, заменяемые эталоном при
1–10 допустимых соперниках того же компилятора. Ниже 1024 КБ нужно только
время. Чужие времена быстрее `0.015 s` исключаются; до этого порога
поднимается только наше время для сравнения. Исходные измерения Accepted,
включая C++ `0.001 s`, сохранены. Нет ограничения по ID/дате, отдельного
первого места или допуска только за улучшение на 30%.

Места быстрой Java от 18 ноября 2026 года (время 5/20, память 2/20)
исторические; сохранённый обычный рейтинг времени по-прежнему её допускает.
Python проходит порог времени `0.093 s` по девяти соперникам компилятора.
Сохранённая звёздочка Rust означает неизвестный численный рейтинг; отдельно привязанное качественное ревью уже одобряет оптимизированный Rust по сравнению с C++-эталоном. Она не
доказывает провал более медленной версии Rust с меньшей памятью.

В текущей быстрой Go исправлен комментарий: `fastFormatted` поддерживает
только `%d` для int/int64 с необязательным выравниванием. Используется
фиксированный формат `Distance is %d km.\n`; преобразований символов,
строк и десятичных дробей нет. Строгий линтер также требует вынести вместимость токена
128 в `inlineTokenBytes`; после подстановки константы исполняемые токены
и алгоритм совпадают.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
