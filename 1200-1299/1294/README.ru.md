# 1294. Марсианские спутники

[Timus 1294](https://acm.timus.ru/problem.aspx?space=1&num=1294) · сложность 317 · geometry

Автор оригинальной задачи — Владимир Яковлев; IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Четыре спутника A, B, C и D лежат на одной круговой орбите в этом
порядке. Известны расстояния AD, AC, BD и BC в тысячах километров
(целые числа от 1 до 10 000); радиус орбиты неизвестен. Нужно найти
расстояние CD в километрах, округлённое до целого, или сообщить, что
однозначно его определить нельзя.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

AD, AC, BD и BC.

## Выходные данные

`Distance is X km.` или `Impossible.`

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
4 7 5 7
```

Вывод:

```
Distance is 5385 km.
```

## Решение

Обозначим a = AD, b = AC, c = BD, d = BC и x = CD. Точки A и B лежат на
одной дуге, отсекаемой хордой CD, поэтому видят её под одним и тем же
вписанным углом t. Теорема косинусов в треугольниках ACD и BCD даёт

x² = a² + b² − 2ab cos t = c² + d² − 2cd cos t —

два уравнения относительно x² и cos t. Отсюда

cos t = (a² + b² − c² − d²) / (2 (ab − cd)),

x² = (ab (c² + d²) − cd (a² + b²)) / (ab − cd).

- Если ab = cd, уравнения либо противоречат друг другу, либо ничего не
  говорят об t. Во втором случае, например у равнобокой трапеции, CD
  действительно может принимать много значений (тест 02). В любом
  случае ответ — `Impossible.` (тесты 02 и 03).
- Если |a² + b² − c² − d²| ≥ 2 |ab − cd|, невырожденного треугольника
  нет: равенство тоже недопустимо, поскольку три различные точки
  окружности не могут лежать на одной прямой (тесты 04 и 07).
- По теореме Птолемея для заданного порядка вершин AB · CD = bc − ad > 0.
  При bc ≤ ad ответ — `Impossible.` (тесты 05 и 07). Вместе со строгой
  границей для косинуса эта проверка гарантирует нужный порядок
  восстановленных точек.
- Иначе x = 1000 · √x² километров с округлением.

Все проверки существования делаются в точных 64-битных целых
(исходные произведения меньше 2 · 10¹⁶). Приведём числитель и знаменатель
к положительным значениям. Вещественный квадратный корень даёт оценку
целой части m расстояния в километрах; округляем вверх точно тогда, когда
(2m + 1)² ≤ floor(4 · 1000² · num / den). Чтобы избежать переполнения,
вычисляем правую часть как s · (num div den) + (s · (num mod den)) div den,
где s = 4 · 1000². Новые промежуточные значения меньше 2 · 10¹⁵.
Время и дополнительная память — `O(1)`.

Исправленные проверки существования и округлённые ответы проверяются
независимым точным оракулом на основе теоремы Птолемея, противоположных
углов и строгих неравенств треугольника.

Тонкие места:

- входные данные в тысячах километров, ответ — в километрах (тест 01);
- AD · AC = BD · BC не всегда означает противоречивые данные: иногда
  это означает много ответов (тесты 02 и 03);
- одного косинуса в [−1, 1] недостаточно: нужно исключить вырожденные
  треугольники и проверить порядок вершин (тест 07).

## Оптимизированные решения

`1294_geometry_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1294_geometry.java`: время 0.109 s → 0.093 s; память 1 600 KB → 452 KB.

Rust после проверки единственности геометрического ответа представляет квадрат длины хорды дробью с целыми числителем и знаменателем. Дробь масштабируется для удвоенного расстояния в километрах с разделением частного и остатка перед умножением. Приближение квадратного корня уточняется целочисленными сравнениями квадратов. Его целая часть определяет итоговое округление без форматирования вещественного числа. Ввод и весь ответ помещаются в фиксированные байтовые буферы. Rust читает и пишет через библиотеку времени исполнения C.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 56 KB при 220 KB у базовой.

Принятые базовые реализации [1294_geometry.cpp](1294_geometry.cpp), [1294_geometry.go](1294_geometry.go), [1294_geometry.java](1294_geometry.java), [1294_geometry.py](1294_geometry.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`1294_geometry_optimized.java`: место по времени 5/20, по памяти 2/20 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
