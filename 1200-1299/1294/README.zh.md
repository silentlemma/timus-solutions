# 1294. 火星卫星

[Timus 1294](https://acm.timus.ru/problem.aspx?space=1&num=1294) · 难度 317 · geometry

原题作者 Vladimir Yakovlev，出自 2004 年 3 月 13 日第九届中学生公开团体程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

四颗卫星 A、B、C、D 按此顺序位于同一圆形轨道上。已知距离 AD、AC、BD、BC，单位为千公里（1 到
10 000 的整数）；轨道半径未知。求 CD 的距离（公里，四舍五入到整数），或者报告它不能唯一确定。

时间限制：1 秒。内存限制：64 MB。

## 输入

AD、AC、BD 和 BC。

## 输出

`Distance is X km.` 或 `Impossible.`

## 评测方式

仓库测试比较完整输出文本，仅忽略末尾空白。应保留有意义的空格、换行、大小写及标点。

## 样例

### 样例 1

输入：

```
50 40 40 14
```

输出：

```
Distance is 30000 km.
```

## 解法

记 a = AD，b = AC，c = BD，d = BC，x = CD。点 A 和 B 位于弦 CD 截出的同一段弧上，所以它们看 CD
的圆周角相同，记为 t。在三角形 ACD 和 BCD 中用余弦定理得

x² = a² + b² − 2ab cos t = c² + d² − 2cd cos t，

这是关于 x² 和 cos t 的两个方程。由此

cos t = (a² + b² − c² − d²) / (2 (ab − cd))，

x² = (ab (c² + d²) − cd (a² + b²)) / (ab − cd)。

- 若 ab = cd，两个方程要么矛盾，要么对 t 没有任何约束。后一种情况（例如等腰梯形）下 CD 确实可以
  取很多值（测试 02）。两种情况的答案都是 `Impossible.`（测试 02 和 03）。
- 若 |a² + b² − c² − d²| ≥ 2 |ab − cd|，则不存在非退化三角形。等号也不允许，因为圆上三个不同的点
  不可能共线（测试 04 和 07）。
- 对于给定的顶点顺序，托勒密定理要求 AB · CD = bc − ad > 0。因此 bc ≤ ad 时输出
  `Impossible.`（测试 05 和 07）。结合严格的余弦界限，这项检查保证重建的点具有正确顺序。
- 否则 x = 1000 · √x² 公里，四舍五入。

所有可行性检查都用精确的 64 位整数完成（原始乘积小于 2 · 10¹⁶）。先将分子和分母化为正数。
用浮点平方根估计公里数的整数部分 m，再精确判断是否向上舍入：
(2m + 1)² ≤ floor(4 · 1000² · num / den)。为避免溢出，将右侧计算为
s · (num div den) + (s · (num mod den)) div den，其中 s = 4 · 1000²。
新的中间值均小于 2 · 10¹⁵。时间和额外空间均为 `O(1)`。

先独立重建 AB，检查严格三角不等式及循环点序，再以有理坐标验证全部四条已知
弦和共同圆；另验托勒密关系和精确舍入。未改动的 Python main 在 `[1, 12]` 的
全部 20736 个四元组及 1000 个固定种子全范围输入上均一致。

注意事项：

- 输入单位是千公里，答案单位是公里（测试 01）；
- AD · AC = BD · BC 并不总是意味着数据矛盾，有时意味着答案有很多个（测试 02 和 03）；
- 余弦在 [−1, 1] 内并不足以保证轨道有效：还要排除退化三角形并检查顶点顺序（测试 07）。

## 优化解法

`1294_geometry_optimized.java`. Java 保留简单版本所述的算法和数据结构。固定字节缓冲区与 FastInput 替代 Scanner 及其正则表达式、区域设置处理。整数记号直接解析；需要字符串时仍进行 UTF-8 解码，十进制记号仍显式转换为数值。仅在需要前瞻时保存一个记号，输出算法不变。这样减少通用解析开销；表中列出算法工作量，输入扫描与字节数成正比，并使用有界输入缓冲区。

与 `1294_geometry.java` 相比：时间 0.109 s → 0.093 s；内存 1 600 KB → 452 KB。

Rust 检查几何条件是否能唯一确定答案后，将弦长平方分解为整数分子和分母。先拆分商和余数再缩放，得到以千米计的两倍距离的平方。用整数平方比较修正浮点平方根估计，其整数部分决定最终舍入，无需浮点格式化。固定字节缓冲区保存输入和完整输出。Rust 通过 C 运行库读写。

通过评测的 Rust 1.75 x64 版本耗时 0.031 秒，基础版为 0.015 秒，内存为 56 KB，基础版为 220 KB。

保存的精确源码审计接纳简单 C++ 和 Python，无需复制快速文件。简单 Go
#11325573（`0.015 s / 1080 KB`）超出稀疏内存上限 1016.60 KB；优化
#11328935（`0.015 s / 804 KB`）通过只比较时间的规则。简单 Java
#11325554 未满足所需内存排名，优化 #11325015 在 452 KB 下通过普通时间
排名，简单文件仍用于教学。两个 Rust 均有精确 Accepted，但已存审计没有
有效对手参考，数值排名未知，并非证实失败。此前基础文件普遍达标的说法已过时。
