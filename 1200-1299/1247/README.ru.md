# 1247. Ни один отрезок не тяжелее своей длины плюс N

[Timus 1247](https://acm.timus.ru/problem.aspx?space=1&num=1247) · сложность 240 · bitmask, dp, prefix_sums

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны положительные `S, N ≤ 30000` и `S` целых чисел `0 ≤ A_i ≤ 100`. ГАРАНТИРОВАНО `sum(A_i) = S + N`. Определите, для каждого ли непустого непрерывного отрезка верно `A_i + … + A_j ≤ (j − i + 1) + N`. Лимит времени: 0,5 секунды. Память: 64 МБ.

## Входные данные

`S N`, затем `S` строк по одному элементу последовательности.

## Выходные данные

Выведите `YES` заглавными буквами, если условие верно для всех отрезков, иначе `NO`.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Решение

Вычтем единицу из каждого элемента и обозначим `p_0 = 0`,
`p_i = sum(A_1 − 1, …, A_i − 1)`. По гарантии о сумме `p_S = N`.
Для отрезка условие превращается в `p_j − p_(i−1) ≤ N`.

Необходимость: каждый префикс является отрезком, значит `p_i ≤ N`.
Каждый суффикс после префикса тоже является отрезком: `N − p_i ≤ N`,
откуда `p_i ≥ 0`. Достаточность: если все префиксы лежат в `[0, N]`,
любая разность для отрезка не превосходит `N − 0 = N`. Поэтому достаточно
потоковой проверки `0 ≤ p_i ≤ N`. Префикс выше `N` уже нарушает условие,
а отрицательный префикс делает оставшийся суффикс слишком тяжёлым.
Можно сразу закончить с `NO`. Доказательство использует обещанную общую
сумму; на произвольный вход без этой гарантии оно не распространяется.

Пять программ `prefix_sums` — предпочитаемые простые версии: `O(S)`
времени и один текущий префикс, `O(1)` состояния алгоритма. Rust хранит
текст входа; этот буфер добавляется к состоянию сканирования.
Все прежние Accepted-исходники сохранены побайтово. В них общий Kadane
хранит наибольшую сумму с концом в текущей позиции:
`ending = max(0, ending + A_i − 1)` и сравнивает максимум с `N`.
Это тоже `O(S)`, причём алгоритму не требуется гарантия об общей сумме.

## Оптимизированные решения

Сохраняем старые варианты динамики и пять более простых потоковых префиксных баз; сравниваем с последними. По гарантии суммы S+N условие равносильно нахождению всех p_i=sum(A_1..A_i)-i в[0,N]. C++ сохраняет этот алгоритм с ограниченным буфером чтения 4096 байт и прямым выводом. Python использует итераторы на C: накопление исходных сумм, вычитание возрастающих позиций, затем деление вниз на N+1. При N>0 целое p даёт p//(N+1)==0 ровно при 0<=p<=N, в том числе для отрицательных p. any находит первый ненулевой результат без Python-цикла и сохранения последовательности. Время O(S), рабочая память O(1). Python сравнивается с текущей потоковой базой 0,109 с/328 КБ, не со старой динамикой 1312 КБ.

- `1247_prefix_sums_optimized.cpp`: 0.015 s / 64 KB; база `1247_prefix_sums.cpp`: 0.031 s / 104 KB; изменение относительно базы: время -51.6%, память -38.5%.
- `1247_prefix_sums_optimized.py`: 0.078 s / 416 KB; база `1247_prefix_sums.py`: 0.109 s / 328 KB; изменение относительно базы: время -28.4%, память +26.8%.
