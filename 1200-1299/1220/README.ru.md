# 1220. Тысяча стеков в трёх четвертях мегабайта

## Задача

Выполнить до `10⁵` операций над 1000 стеков: `PUSH A B` кладёт число
`B ≤ 10⁹` в стек `A`, а `POP A` снимает вершину стека `A` и выводит её.
Каждый `POP` находит свой стек непустым. Ограничение памяти — всего
0,75 МБ.

Ограничение времени: 0.5 секунды. Ограничение памяти: 0.75 МБ.

## Входные данные

`N`, затем операции, по одной в строке.

## Выходные данные

Значение каждого `POP`, по одному в строке, по порядку.

## Примеры

### Пример 1

Ввод:

```
7
PUSH 1 100
PUSH 1 200
PUSH 2 300
PUSH 2 400
POP 2
POP 1
POP 2
```

Вывод:

```
400
200
300
```

## Решение

Хранить каждое значение с указателем на лежащее под ним заняло бы около
600 КБ на `10⁵` значений — слишком близко к пределу вместе с самой
программой, а отдельный массив на стек тратил бы место на пустые.

Поэтому каждый стек — цепочка блоков по 10 значений, новейший блок
первым, и каждый блок помнит следующий, более старый блок того же стека.
Размер стека говорит, насколько заполнен его новейший блок, так что
счётчик в блоке не нужен: при добавлении в полный блок (или в пустой
стек) берётся блок из списка свободных, а снятие, опустошившее новейший
блок, возвращает его туда. Частично заполненным может быть только
новейший блок стека, поэтому одновременно занято не больше
`10⁵/10 + 1000` блоков, всего около 460 КБ. Маленькие фиксированные
буферы для чтения и записи делают ввод и вывод быстрыми без лишней
памяти. `O(N)`.

Тонкие места:

- одна только библиотека потоков C++ заметно расходует память, поэтому
  программа читает и пишет через `fread` и `fwrite`;
- блок нужно возвращать, как только он опустел, иначе стек, который
  много раз растёт и уменьшается, исчерпает запас;
- 16-битных номеров блоков хватает: блоков меньше 32 768.

Вывод сверен с простой симуляцией на списках на всех тестах, включая
100 000 операций разных видов.
