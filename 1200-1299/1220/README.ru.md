# 1220. Тысяча стеков в трёх четвертях мегабайта

[Timus 1220](https://acm.timus.ru/problem.aspx?space=1&num=1220) · сложность 281 · implementation

Автор оригинальной задачи — Павел Атнашев; VII студенческое соревнование по программированию УрГУ.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Выполнить до `10⁵` операций над 1000 стеков: `PUSH A B` кладёт число
`B ≤ 10⁹` в стек `A`, а `POP A` снимает вершину стека `A` и выводит её.
Каждый `POP` находит свой стек непустым. Ограничение памяти — всего
0,75 МБ.

Ограничение времени: 0.5 секунды. Ограничение памяти: 0.75 МБ.

## Входные данные

`N`, затем операции, по одной в строке.

## Выходные данные

Значение каждого `POP`, по одному в строке, по порядку.

## Проверка

Сравниваются точные токены ответа, пробельное оформление несущественно.

- `1220_implementation_optimized.rs` (Rust 1.75 x64): 13 тестов репозитория; 8 дополнительных сравнений точного исходника.

## Примеры

### Пример 1

Ввод:

```
7
PUSH 1 100
PUSH 1 200
PUSH 2 300
PUSH 2 400
POP 2
POP 1
POP 2
```

Вывод:

```
400
200
300
```

## Решение

Хранить каждое значение с 32-битной ссылкой на лежащее под ним заняло бы
около 800 КБ на `10⁵` значений — уже больше предела памяти, а
отдельный массив на стек тратил бы место на пустые.

Поэтому каждый стек — цепочка блоков по 10 значений, новейший блок
первым, и каждый блок помнит следующий, более старый блок того же стека.
Размер стека говорит, насколько заполнен его новейший блок, так что
счётчик в блоке не нужен: при добавлении в полный блок (или в пустой
стек) берётся блок из списка свободных, а снятие, опустошившее новейший
блок, возвращает его туда. Частично заполненным может быть только
новейший блок стека, поэтому одновременно занято не больше
`10⁵/10 + 1000` блоков, всего около 460 КБ. Маленькие фиксированные
буферы для чтения и записи делают ввод и вывод быстрыми без лишней
памяти. `O(N)`.

Тонкие места:

- одна только библиотека потоков C++ заметно расходует память, поэтому
  программа читает и пишет через `fread` и `fwrite`;
- блок нужно возвращать, как только он опустел, иначе стек, который
  много раз растёт и уменьшается, исчерпает запас;
- 16-битных номеров блоков хватает: блоков меньше 32 768.

Вывод сверен с простой симуляцией на списках на всех тестах, включая
100 000 операций разных видов.

## Оптимизированные решения

Здесь судья поддерживает только C++ и Rust; обе простые версии сохраняются. Компактный Rust реализует те же LIFO-стеки, но связывает блоки по восемь значений вместо отдельных расширяемых выделений для стеков. Число не больше10^9<2^30, поэтому восемь значений занимают30байт. Ссылка u16 указывает на предыдущий блок; опустевшие блоки возвращаются в свободный список и используются снова. Частичных верхних блоков не больше1000, полные содержат по восемь живых значений: достаточно100000/8+1000+1слотов с индексами u16. Операция затрагивает ограниченное окно из четырёх/пяти байт, сохраняя соседние ячейки. Статические массивы и ограниченный ввод-вывод через C ABI исключают кучу и ненужный запуск. Время O(Q), память O(Q+S), S=1000. Точный исходник прошёл13тестов репозитория и8независимых стрессов, включая100000операций и переиспользование блоков.

- `1220_implementation_optimized.rs`: 0.031 s / 436 KB; база `1220_implementation.rs`: 0.031 s / 672 KB; изменение относительно базы: время -0.0%, память -35.1%.

## Особенности языков

Сохранённые срезы: 1–2 ноября 2026 года. Цель C++ — топ 15% либо первые 10 мест одновременно по времени и памяти; других семейств — первое место по обеим метрикам. Ничьи делят место. Пустые выборки дают только формальное покрытие.

Используется сохранённый профиль текущих компиляторов; исключены собственный автор и старые строки со временем меньше 0,015 с. Для семейств кроме C++ дополнительно требуется ID посылки ≥10770000; память C++ сравнивается по первым 1000 подходящим строкам. Собственные времена меньше 0,015 с считаются 0,015 с. Порог ID — фиксированное правило сравнения, а не точный календарный фильтр.
