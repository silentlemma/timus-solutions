# 1220. 四分之三兆字节里的一千个栈

[Timus 1220](https://acm.timus.ru/problem.aspx?space=1&num=1220) · 难度 281 · implementation

原题作者 Pavel Atnashev，出自第七届乌拉尔国立大学大学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

在 1000 个栈上执行最多 `10⁵` 次操作：`PUSH A B` 把数 `B ≤ 10⁹` 压入栈 `A`，
`POP A` 弹出栈 `A` 的顶部并输出。每次 `POP` 时对应的栈都不为空。内存限制只有
0.75 MB。

时间限制：0.5 秒。内存限制：0.75 MB。

## 输入

`N`，然后每行一个操作。

## 输出

按顺序每行输出一次 `POP` 得到的值。

## 评测方式

精确比较答案词元，空白排版无关。

- `1220_implementation_optimized.rs` (Rust 1.75 x64): 13个仓库测试; 8个额外精确源码比较.

## 样例

### 样例 1

输入：

```
7
PUSH 1 100
PUSH 1 200
PUSH 2 300
PUSH 2 400
POP 2
POP 1
POP 2
```

输出：

```
400
200
300
```

## 解法

如果每个压入的值都带一个指向下面那个值的 32 位链接，`10⁵` 个值约需 800 KB，已超过
内存限制；而每个栈单独开一个数组又会在空栈上浪费空间。

所以每个栈都是由若干块组成的链，每块 10 个值，最新的块在前，每块记住同一个栈中
下一个较旧的块。栈的大小就说明了最新的块装了多少，所以块里不需要计数器：向已满
的块（或空栈）压入时从空闲表取一块，弹出使最新的块变空时把它还回去。每个栈只有
最新的块可能半满，所以任何时候最多使用 `10⁵/10 + 1000` 块，总共约 460 KB。用于
读写的小型固定缓冲区让输入输出既快又不占多少内存。`O(N)`。

注意事项：

- 仅 C++ 流库本身就要占用不少内存，所以程序用 `fread` 和 `fwrite` 读写；
- 块一变空就必须归还，否则一个反复增长又缩小的栈会耗尽块池；
- 块的编号用 16 位就够了，因为块少于 32,768 个。

输出已在所有测试上与基于列表的简单模拟比对，其中包括多种类型的 100,000 次操作。

## 优化解法

本题评测仅支持C++和Rust，保留两种教学源码。紧凑Rust仍实现普通LIFO，但每八个值组成链块，避免各栈可扩容分配。值<=10^9<2^30，八值共30字节。u16链接指向前块，空块归还自由链后复用。至多1000个顶块不满，满块各含八个活值，因此100000/8+1000+1槽足够，u16索引可表示。压入/弹出只访问有界四/五字节窗口，不改邻格。固定全局存储、有界C ABI输入输出避免堆和未用启动设施。Q次操作O(Q)，S=1000栈时空间O(Q+S)。精确源码通过13个仓库测试及8个独立压力输入，包含100000次操作和块复用。

- `1220_implementation_optimized.rs`: 0.031 s / 436 KB; 基础 `1220_implementation.rs`: 0.031 s / 672 KB; 相对变化: 时间 -0.0%, 内存 -35.1%.
