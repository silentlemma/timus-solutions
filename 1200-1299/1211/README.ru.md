# 1211. Показания без круга и с одним признанием

[Timus 1211](https://acm.timus.ru/problem.aspx?space=1&num=1211) · сложность 311 · graphs

Автор оригинальной задачи — Леонид Волков; USU Open Collegiate Programming Contest, октябрь 2002 года, Junior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый из `N ≤ 25000` детей либо признаётся, что разбил кружку
(записано как 0), либо называет виновным ребёнка. Показания
выглядят непротиворечивыми, если признался ровно один ребёнок и нет группы
детей, указывающих друг на друга по кругу. Ответить `YES` или `NO` для
каждого из не более чем 16 тестов.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

В первой строке целое `1 ≤ T ≤ 16`. Каждый тест занимает две строки: целое `1 ≤ N ≤ 25000`, затем N целых `0 ≤ a_i ≤ N`. Позиция i относится к ребёнку i: 0 означает признание, положительное значение — номер названного ребёнка от 1, в том числе самого i.

## Выходные данные

`YES` или `NO` для каждого теста, по одному в строке.

Ввод:

```
5
1
0
1
1
5

6

4

```

Вывод:

```
YES

YES
```

## Решение

Каждый ребёнок, кроме признавшегося, указывает ровно на одного ребёнка,
так что показания образуют граф, где из каждой вершины выходит не больше
одного ребра. При ровно одном признании круга нет тогда и только тогда,
когда, идя по обвинениям от любого ребёнка, всегда приходим к
признавшемуся.

Идём по очереди от каждого ребёнка, отмечая детей на текущем пути. Путь
останавливается на признавшемся или на ребёнке, про которого уже
известно, что он туда ведёт; тогда туда ведёт и каждый ребёнок на пути.
Если же путь наткнулся на ребёнка, отмеченного на текущем пути, обвинения
идут по кругу. Каждый ребёнок проходится один раз. `O(N)` на тест.

Тонкие места:

- ребёнок, назвавший самого себя, — круг из одного;
- ни одного признания или два — уже `NO`;
- цепочки бывают длиной 25000, поэтому обход — цикл, а не рекурсия.

Ответы сверены с отдельно написанным решением на 200 файлах по 16
случайных тестов всех видов.

Алгоритм обхода цепочек использует `O(N)` рабочей памяти на тест: обвинения, состояния и текущий путь. Время по всем T тестам — `O(Σ N_i)`. Пусть I — байты всего ввода, H — самая длинная строка. Простая Python хранит все разбитые токены, Rust — всю String, поэтому память `O(I + max N_i + T)`. C++ и Go читают потоком с ограниченными буферами, для графа требуется `O(max N_i)`. Java также хранит текущую строку и T слов ответа: `O(max N_i + H + T)` плюс библиотечные буферы. Быстрая Rust хранит ограниченный буфер/токен, обвинения, состояния, путь и T слов ответа: `O(max N_i + T + B)`, B — фиксированный буфер. DSU обрабатывает обвинения при чтении за амортизированное `O(N α(N))` на тест; фактические статические массивы из 25001 знакового 16-битного элемента и буферы используют `O(M + B)` памяти при M=25000 даже для малого теста. Индексы до 25000 и отрицательные размеры компонент до −25000 помещаются в знаковые 16 бит.

## Оптимизированные решения

Версии C++ и Go обрабатывают обвинения по мере чтения с помощью системы непересекающихся множеств. Обвинение между уже связанными вершинами замыкает неориентированный цикл. Из каждой вершины выходит не более одного обвинения, поэтому каждая вершина цикла даёт ровно одно его ребро и цикл оказывается ориентированным. Сюда же относятся самообвинение и два встречных обвинения. Требуется одно признание и отсутствие циклов. Знаковая 16-битная ячейка хранит индекс родителя или отрицательный размер компоненты.

Кэш аудита точных исходников применяет общие [рейтинговые критерии](../../RATING_CRITERIA.md). Простые Java и Python проходят и используются без дубликатов. Обе Go проходят по выборке всего того же языка: соперников точного компилятора нет. Быстрый набор C++ покрывает `1211_dsu.cpp`, Rust — `1211_graphs_implementation_optimized.rs` (№11328956, 0.031 с / 580 КБ). Простая Rust №11283644 за 0.031 с / 5212 КБ не проходит обязательную память, простая C++ — время; обе остаются содержательными учебными без звёздочек. Ниже 1024 КБ сравнивается только время; проходящим Go/Java/Python выше этой границы нужны обе метрики. Отдельной цели первого места нет.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1211_graphs_implementation_optimized.rs`. Токены читаются через ограниченный нативный байтовый буфер; короткие хранятся внутри объекта, дополнительная память выделяется только длинным. Десятичный разбор сохраняет знаковые границы без хранения всего командного ввода. Точка входа C напрямую вызывает решение и сбрасывает вывод Rust перед возвратом; архивная реализация с обычной точкой входа сохранена.

## Проверка

В `tests/tests.json` задан `tokens`: ровно T токенов YES/NO сравниваются в порядке тестов без учёта пробелов и переводов строк. Обычно результат печатается по одному на строке. Собственный пример содержит одного признавшегося, самозацикливание, сливающиеся пути к признанию, отдельный цикл и два признания. Другие тесты проверяют длинные цепочки, поздние циклы, максимальные размеры и сброс состояний.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
