# 1214. Как отменить странную процедуру

[Timus 1214](https://acm.timus.ru/problem.aspx?space=1&num=1214) · сложность 103 · math

Автор оригинальной задачи — Анатолий Углов; USU Open Collegiate Programming Contest, октябрь 2002 года, Junior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Процедура принимает два целых `x` и `y`. Если оба положительны, она
`x + y` раз выполняет тело цикла: `y ← x² + y`, затем `x ← x² + y`, затем
`y ← ⌊√(x − y)⌋`, затем `2y` раз вычитает `y` из `x`; в конце она
печатает `x` и `y`. По напечатанному, оба от `−32000` до `32000`,
восстановить вход. Переполнений не бывает.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Напечатанные `x` и `y`.

## Выходные данные

Входные `x` и `y`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4 7
```

Вывод:

```
7 4
```

## Решение

Проследим один виток цикла от `(x, y)`. Сначала `y` становится
`x² + y`, затем `x` становится `2x² + y`. Их разность — `x²`, поэтому
новое `y` равно `x`. Вычитание его `2x` раз отнимает `2x²` от `2x² + y` и
оставляет `y`. Значит, каждый виток просто меняет числа местами, а сумма
`x + y`, задающая число витков, не меняется. После `x + y` витков числа
переставлены ровно тогда, когда сумма нечётна.

Итак, процедура меняет числа местами, если оба положительны и их сумма
нечётна, и ничего не меняет иначе. Это преобразование обратно самому
себе: применяем то же правило к напечатанной паре. `O(1)`.

Тонкие места:

- при нуле или отрицательном числе цикл не выполняется вовсе, и пара
  печатается без изменений;
- чётность определяет сумма, а не сами числа.

Запуск процедуры на всех парах от `−3` до `15` и отмена результата каждый
раз возвращали исходную пару.

## Оптимизированные решения

`1214_math_optimized.java`. Сохраняется та же инволюция: переставить числа ровно тогда, когда оба положительны и имеют разную чётность. Значения в пределах ±32000, модули безопасны в int. Ввод буфером 64 байта; y, затем x записываются справа налево в ответ 32 байта со знаками, пробелом и переводом строки. Убраны общий форматтер long и отдельный массив цифр. Полный ответ записывается и сбрасывается перед System.exit(0). Арифметика и состояние константны для этих границ. Учебная версия сохранена. Новая пара 0.093 с/436 КБ требует больше памяти, чем прежняя 0.109 с/384 КБ; строгий допуск следует из рейтинга, а не заявленного выигрыша ресурсов 30%.

Accepted точного Java 1.8 №11327866: 0.093 с / 436 КБ. В сохранённом сравнении от 2026-11-20 время 5/75, память 4/75. Ниже 1024 КБ он проходит общий критерий только по времени, без отдельного первого места и звёздочки. Прежняя быстрая №11303725 за 0.109 с / 384 КБ — отдельная историческая пара, не подтверждение текущего файла. Простая Java сохранена без изменений.

- `1214_math_optimized.java`: 0.093 s / 436 KB; сохранённая учебная база `1214_math.java`: 0.125 s / 1584 KB.

`1214_math_optimized.py`. Сохраняется та же инволюция: два значения меняются местами ровно тогда, когда оба положительны и сумма нечётна. При нуле или отрицательном значении обмена нет. Модули напечатанных значений не больше 32000, сумма безопасно помещается в i64. Время и состояние арифметики O(1). Разбираются байтовые токены вместо декодированной строки; нечётность проверяется битовой операцией, без симуляции процедуры. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1214_math.py`: время 0.078 s → 0.125 s; память 444 KB → 204 KB.

`1214_math_optimized.rs`. Сохраняется та же инволюция: два значения меняются местами ровно тогда, когда оба положительны и сумма нечётна. При нуле или отрицательном значении обмена нет. Модули напечатанных значений не больше 32000, сумма безопасно помещается в i64. Время и состояние арифметики O(1). Читаются только два знаковых целых, без декодированной строки и вектора разобранных значений. Математическое преобразование прежнее. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1214_math.rs`: время 0.046 s → 0.046 s; память 212 KB → 60 KB.

## Особенности языков

К сохранённым точным исходникам применяются общие [рейтинговые критерии](../../RATING_CRITERIA.md). Проходят простая C++, быстрые Go/Java, простая CPython и обе Rust. Простая Go за 0.015 с / 1068 КБ не проходит обязательную память, быстрая Go за 0.031 с / 948 КБ проходит только по времени: ускорение здесь не заявляется. Простая Java не достигает численного порога; содержательные простые версии остаются учебными без звёздочек. Ниже 1024 КБ нужно только время, выше — обе метрики. Go использует применимое сравнение с эталоном точного компилятора, Rust — выборку всего того же языка. Нет отдельного допуска по отсутствию соперников, первому месту или выигрышу 30%.

Сохранённое сравнение PyPy от 2026-11-18 историческое: №11324914 за 0.125 с / 204 КБ имела место 29/40 по времени и 1/40 по памяти. Она всё ещё не проходит время и сохраняет маркер, несмотря на меньшую память. Простая CPython №11283658 за 0.078 с / 444 КБ покрывает быстрый Python. Текущие пары замеров сохранены в таблицах; старые срезы не являются новыми живыми рейтингами или гарантиями между запусками.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
