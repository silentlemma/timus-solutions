# 1280. Топологическая сортировка

[Timus 1280](https://acm.timus.ru/problem.aspx?space=1&num=1280) · сложность 140 · graphs

Авторы оригинальной задачи — Сергей Волченков, Владимир Пинаев и Михаил Копачёв; четвертьфинал ACM ICPC 2003–2004, центральный регион России, Рыбинск, 15–16 октября 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть 1 ≤ N ≤ 1000 предметов и 0 ≤ M ≤ 100 000 правил «s u»: предмет s
нужно изучить раньше предмета u. Согласуется ли заданный порядок всех N
предметов со всеми правилами?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и M, M правил, затем порядок N предметов. Предметы пронумерованы от 1
до N.

## Выходные данные

`YES` или `NO`.

## Примеры

### Пример 1

Ввод:

```
5 6
1 3
1 4
3 5
5 2
4 2
1 2
1 3 4 5 2
```

Вывод:

```
YES
```

### Пример 2

Ввод:

```
5 6
1 3
1 4
3 5
5 2
4 2
1 2
1 2 4 5 3
```

Вывод:

```
NO
```

## Решение

Ничего сортировать не нужно: запомним место каждого предмета в
заданном порядке и проверим, что каждое правило идёт вперёд, то есть s
стоит раньше u. Если в правилах есть цикл, какое-то правило на нём при
любом порядке идёт назад, так что проверка и так скажет `NO`, как и
требует условие. `O(N + M)`.

Тонкие места:

- для `NO` достаточно одного нарушенного правила; порядок в тесте 02
  нарушает три правила: 3 → 5, 5 → 2 и 4 → 2;
- правило может вести от предмета к нему же, и его не выполнит никакой
  порядок (тест 04);
- правила могут повторяться (тест 07);
- без правил годится любой порядок (тест 06).

## Оптимизированные решения

Оптимизированное решение на C++ разбирает числа вручную из буфера на
4 КБ вместо `scanf` и хранит правила битовой матрицей, по строке
`std::bitset` на предмет, вместо двух массивов `int` на число правил до
100 000. При `N ≤ 1000` матрица занимает около 125 КБ, а повторённые
правила попадают в один бит. Проверка затем перебирает все `N²` пар
предметов, не больше миллиона битов: {1280_graphs_optimized.cpp}.

Оптимизированное решение на Go разбирает числа побайтно из
`bufio.Reader` вместо `fmt.Fscan` и хранит концы правил в двух срезах
`uint16`, куда помещаются номера предметов до 1000, вместо срезов `int`,
вчетверо больших: {1280_graphs_optimized.go}.

Оптимизированное решение на Java разбирает числа вручную из буфера на
4 КБ вместо `StreamTokenizer` и хранит правила битовой матрицей в
массиве `long`, `N` строк по `⌈N / 64⌉` слов, около 125 КБ при
`N ≤ 1000`, вместо двух массивов `int` на число правил до 100 000.
Проверка затем перебирает все `N²` пар предметов:
{1280_graphs_optimized.java}.

Оптимизированное решение на Python читает ввод кусками по 8 КБ и
преобразует токены кусок за куском, а не разбивает весь ввод сразу, и
хранит концы правил в `array("H")` из беззнаковых 16-битных чисел, куда
помещаются номера предметов до 1000, вместо списка кортежей:
{1280_graphs_optimized.py}.

Оптимизированное решение на Rust разбирает числа вручную из буфера на
4 КБ, а не читает весь ввод в `String`, и хранит правила парами
`(u16, u16)`, куда помещаются номера предметов до 1000, вместо пар
`(usize, usize)`, вчетверо больших: {1280_graphs_optimized.rs}.
