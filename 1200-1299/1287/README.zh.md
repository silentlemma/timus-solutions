# 1287. 火星运河

[Timus 1287](https://acm.timus.ru/problem.aspx?space=1&num=1287) · 难度 383 · dp

原题作者 Alexander Mironenko（由 Igor Goldberg 准备），出自 2004 年乌拉尔国立大学个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一块 N × N 的田（N ≤ 1400）种着两种谷物 `s` 和 `S`，每格一种。求沿行、列或任一条对角线的
最长同字母直线连续段。输出最长连续段更长的那个字母，相等则输出 `?`，再输出该长度。

时间限制：1 秒。内存限制：64 MB。

## 输入

N，然后 N 行，每行 N 个字母。

## 输出

获胜的字母或 `?`，然后是最长连续段的长度。

## 样例

### 样例 1

输入：

```
3
SsS
sSs
SsS
```

输出：

```
S
3
```

### 样例 2

输入：

```
2
sS
Ss
```

输出：

```
?
2
```

## 解法

逐行扫描。对每个格子记录在四个方向上以它结尾的连续段长度：来自左边、上边、左上和右上。
若邻格字母相同，则等于邻格的长度加一，否则为 1。只需要上一行，并在扫描中记录每个字母的
最长连续段。动态规划需要 `O(N²)` 时间和 `O(N)` 状态空间；总内存取决于输入的存储方式（见下文）。

注意事项：

- 来自右上的对角线容易被忘掉（测试 06）；
- 最长连续段相等时输出 `?`（测试 02）；
- 田里有近两百万个格子，所以读入要快。

在 1200 块边长不超过十二格的随机田和全部 530 块边长为一至三格的田上，
与从每个格子出发逐一走完每条连续段的结果比较过。

## 优化解法

C++ 用 SSE2 每次更新八列的竖直和斜向连续段。比较字母得到掩码，只在字母相等的位置保留旧长度。水平连续段单独扫描。Go 把长度和字母打包到一个 16 位整数中，原地更新三个数组，并暂存下一列所需的左上角旧值。两者均用 O(N²) 时间和 O(N) 空间。

已通过评测的基础实现 [1287_dp.java](1287_dp.java), [1287_dp.py](1287_dp.py), [1287_dp.rs](1287_dp.rs) 也满足快速版本的要求：在保存的比较快照中，时间和内存均符合前 15% 或前十名的排名收录规则。直接复用这些源文件，不创建相同副本。星号标记尚未达到该语言目标排名的版本。

## 各语言说明

以下说明针对基础实现。

- C++、Go、Java 和 Rust 为前后两行各保存三个连续段数组，并用一个标量记录横向连续段。
  C++、Go 和 Java 的总内存为 `O(N)`；Rust 保留全部输入，总内存为 `O(N²)`。
- Python 逐格处理会太慢。它把行、列和两条方向的对角线都做成字节串：对角线就是逐行错开
  一格后的列，由 `zip` 完成转置。然后对 k 二分，用 `bytes.find` 判断文本中是否出现 k 个
  相同字母连续。点号分隔符和填充可防止连续段跨越不同直线或超出田的边界。
  构造文本需要 `O(N²)` 时间和内存；二分查找的最坏时间为 `O(N² log N)`，总内存为 `O(N²)`。
