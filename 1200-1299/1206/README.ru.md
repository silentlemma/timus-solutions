# 1206. Пары чисел, суммы цифр которых складываются

[Timus 1206](https://acm.timus.ru/problem.aspx?space=1&num=1206) · сложность 124 · combinatorics

Автор оригинальной задачи — Леонид Волков; командное соревнование УрГУ, март 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Пусть `S(N)` — сумма цифр `N`. Для `2 ≤ K ≤ 50` посчитать упорядоченные
пары `K`-значных чисел `A` и `B` без ведущих нулей, для которых
`S(A + B) = S(A) + S(B)`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`K`.

## Выходные данные

Число пар.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
5989500
```

## Решение

Каждый перенос при сложении превращает 10 в одном разряде в 1 в
следующем и уменьшает сумму цифр на 9. Значит, равенство выполняется
ровно тогда, когда переносов нет, то есть цифры в каждом разряде дают в
сумме не больше 9. Тогда разряды независимы. В старшем разряде обе цифры
от 1 до 9, это `8 + 7 + … + 1 = 36` пар; в каждом из остальных `K − 1`
разрядов цифры от 0 до 9, это `10 + 9 + … + 1 = 55` пар. Ответ —
`36 · 55^(K−1)`, число до 87 цифр. `O(K²)` при умножении столбиком.

Результату нужно O(K) десятичных цифр или битов с постоянным множителем. Простые C++/Rust хранят растущие векторы цифр, Rust ещё создаёт выходной String длины O(K); Go/Java/Python хранят длинные целые и десятичный вывод: O(K) живых значений/вывода плюс рабочая память арифметики и входные буферы. Школьное время O(K²) — консервативная модель арифметики/преобразования, не утверждение о K повторных умножениях встроенного возведения. Быстрая Java выделяет ровно 2K ячеек цифр и O(K) байтов ответа; быстрая C++ резервирует фиксированные 100 ячеек на стеке при K ≤ 50. Неравенство 36·55^(K−1) < 100^K даёт не более 2K цифр; при K=2 и K=3 граница достигается.

Тонкие места:

- ответ выходит за 64 бита уже при `K = 12`;
- старшие цифры не могут быть нулём, поэтому для них пар другое число.

Формула проверена перебором всех пар для `K = 2` и `K = 3`, и каждое `K`
сверено с отдельно написанным решением.

## Оптимизированные решения

`1206_combinatorics_optimized.java`. Сохраняется формула подсчёта без переносов 36*55^(K-1). При K<=50 достаточно не более 100 десятичных цифр: массив умножается на 55 K-1 раз во время работы, затем выводятся байты. Меняется представление арифметики, а не комбинаторное доказательство; готовые ответы не хранятся. Консервативно O(K²) операций над цифрами и O(K) памяти вместо инициализации BigInteger; простая формула с BigInteger сохранена.

Исторический Accepted точного Java 1.8 №11327341: 0.109 с / 308 КБ; сохранённое сравнение от 2026-11-20: время 14/141, память 1/141. Ниже 1024 КБ он проходит общий критерий времени, без отдельного первого места или маркера. Прежний №11304422 — отдельная историческая пара 0.125 с / 448 КБ. Сейчас изменён только комментарий границы: не «меньше 2K», а «не более 2K»; остальной исполняемый текст идентичен.

- `1206_combinatorics_optimized.java`: 0.109 s / 308 KB; сохранённая учебная база `1206_combinatorics.java`: 0.14 s / 1748 KB.

Выбранный Accepted точного `1206_combinatorics_optimized.py` на CPython 3.12 №11327017: 0.078 с / 612 КБ; сохранённые места от 2026-11-20: время 2/76, память 60/76. Ниже 1024 КБ проходит только время. Относительно текущей базы №11283600, 0.109 с / 416 КБ, время ниже на 28.44%, память выше на 47.12%: выигрыша 30% ни по одной метрике нет. Исторический PyPy 3.10 №11324911 — отдельная пара 0.140 с / 252 КБ; дальнейшее сравнение экономии памяти относится к нему, не выбранной строке CPython.

Оптимизированное решение на C++ так же умножает десятичные цифры на 55,
но в массиве фиксированного размера на 100 элементов на стеке вместо
растущего `std::vector`: при `K ≤ 50` ответ `36 · 55^(K−1)` меньше
`100^K` и содержит не больше 100 цифр (на деле не больше 87). Без
`<vector>` в программе вовсе нет кода контейнеров:
{1206_combinatorics_optimized.cpp}.

### Измеренный выигрыш

Это исторические различия между парными запусками Accepted, не универсальный допуск за выигрыш 30%. Простые исходники сохранены; отрицательное сокращение означает рост расхода. Текущий допуск определяется общей рейтинговой политикой.

- `1206_combinatorics_optimized.cpp`: сокращение времени +0.00%;
  сокращение памяти +46.81%; база: `1206_combinatorics.cpp`.

`1206_combinatorics_optimized.py`. Сохраняются точная формула 36*55^(K-1) и длинные целые Python. Базовый оператор ** и здешний pow уже выполняют целочисленное возведение в степень; нового алгоритма подсчёта нет. Консервативная граница при школьной арифметике с переводом в десятичную запись — O(K²) времени и O(K) бит ответа. Изменённая реализация читает единственный токен и завершается без функциональной обёртки и обычной очистки. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Исторический Accepted на PyPy показывает экономию памяти; выбранный текущий Accepted на CPython, наоборот, обменивает рост памяти на меньшее измеренное время. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1206_combinatorics.py`: время 0.109 s → 0.14 s; память 416 KB → 252 KB.

## Особенности языков

Действуют общие [рейтинговые критерии](../../RATING_CRITERIA.md) и кэш точных исходников. Обе C++, Go, Rust и привязанные к посылкам быстрые Java/Python проходят численные критерии. Простые Java/Python не проходят и остаются учебными без звёздочек. Ниже 1024 КБ учитывается время; Go с 1200 КБ нужны обе метрики и сравнение с двумя соперниками точной версии. Rust использует эталон с одним соперником. Нет отдельного первого места, допуска по выигрышу 30% или подмены текущего рейтинга старым местом PyPy.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
