# 1206. Пары чисел, суммы цифр которых складываются

[Timus 1206](https://acm.timus.ru/problem.aspx?space=1&num=1206) · сложность 124 · combinatorics

## Задача

Пусть `S(N)` — сумма цифр `N`. Для `2 ≤ K ≤ 50` посчитать упорядоченные
пары `K`-значных чисел `A` и `B` без ведущих нулей, для которых
`S(A + B) = S(A) + S(B)`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`K`.

## Выходные данные

Число пар.

## Примеры

### Пример 1

Ввод:

```
2
```

Вывод:

```
1980
```

## Решение

Каждый перенос при сложении превращает 10 в одном разряде в 1 в
следующем и уменьшает сумму цифр на 9. Значит, равенство выполняется
ровно тогда, когда переносов нет, то есть цифры в каждом разряде дают в
сумме не больше 9. Тогда разряды независимы. В старшем разряде обе цифры
от 1 до 9, это `8 + 7 + … + 1 = 36` пар; в каждом из остальных `K − 1`
разрядов цифры от 0 до 9, это `10 + 9 + … + 1 = 55` пар. Ответ —
`36 · 55^(K−1)`, число до 87 цифр. `O(K²)` при умножении столбиком.

Тонкие места:

- ответ выходит за 64 бита уже при `K = 12`;
- старшие цифры не могут быть нулём, поэтому для них пар другое число.

Формула проверена перебором всех пар для `K = 2` и `K = 3`, и каждое `K`
сверено с отдельно написанным решением.

## Оптимизированные решения

Оптимизированное решение на C++ так же умножает десятичные цифры на 55,
но в массиве фиксированного размера на 100 элементов на стеке вместо
растущего `std::vector`: при `K ≤ 50` ответ `36 · 55^(K−1)` меньше
`100^K` и содержит не больше 100 цифр (на деле не больше 87). Без
`<vector>` в программе вовсе нет кода контейнеров:
{1206_combinatorics_optimized.cpp}.

Оптимизированное решение на Java читает `K` побайтно из `System.in`
вместо того, чтобы создавать `Scanner`, чьи регулярные выражения и
данные локали обходятся дороже самого возведения в степень; ответ
по-прежнему считается через `BigInteger`:
{1206_combinatorics_optimized.java}.
