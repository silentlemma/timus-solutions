# 1210. Самый дешёвый подъём по уровням планет

[Timus 1210](https://acm.timus.ru/problem.aspx?space=1&num=1210) · сложность 169 · dp

Автор оригинальной задачи — Леонид Волков; USU Open Collegiate Programming Contest, октябрь 2002 года, Junior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Планеты расположены на уровнях от 0 до `N`, `0 < N < 30`, не больше 30
на уровне, и на уровне 0 одна планета — дом путешественника. Переходы
ведут только с планеты одного уровня на планеты следующего, и каждый
стоит целое число от `−32768` до `32767`; отрицательная стоимость
значит, что охраняющий переход дух доплачивает путешественнику. Найти
самый дешёвый маршрут от дома до любой планеты уровня `N`; он может быть
отрицательным. Маршрут заведомо существует.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` блоков, разделённых строками `*`. Блок `i` начинается с
числа `K_i` планет на уровне `i`, пронумерованных от 1 до `K_i`; затем
для каждой из них по порядку строка пар «планета уровня `i − 1`,
стоимость», завершённая `0`.

## Выходные данные

Наименьшая суммарная стоимость.

## Примеры

### Пример 1

Ввод:

```
3
2
1 15 0
1 5 0
*
3
1 -5 2 10 0
1 3 0
2 40 0
*
2
1 1 2 5 3 -5 0
2 -19 3 -20 0
```

Вывод:

```
-1
```

## Решение

Карта слоистая, и каждый переход поднимается на уровень, так что циклов
нет и отрицательные стоимости не мешают: самый дешёвый путь до планеты —
самый дешёвый путь до одной из планет, ведущих к ней, плюс этот переход.
Храним наименьшую стоимость для каждой планеты текущего уровня, начиная с
0 для дома, и строим стоимости следующего уровня по входящим переходам из
его блока. Ответ — наименьшая стоимость на уровне `N`. `O(L)` для `L`
переходов.

Тонкие места:

- у планеты может не быть входящих переходов вовсе или быть только
  переходы с недостижимых планет; такая планета должна остаться
  недостижимой, а не передавать дальше щедрый переход с неё;
- строки `*` — только разделители, при чтении чисел их можно пропускать;
- сумма по модулю меньше `30 · 32768`, так что 32-битных целых хватает.

Ответы сверены с отдельно написанным решением на 300 случайных картах,
половина из них с недостижимыми планетами.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает числа со знаком вручную из
буфера на 4 КБ, который пополняется через `fread`, пропуская разделители
`*` вместе с прочими символами, не входящими в числа, вместо того чтобы
читать каждый токен в `std::string` и переводить его через `std::stoi`;
печатает оно через `printf`, так что `iostream` не используется вовсе.
Метка недостижимой планеты у него — 1 000 000, это больше стоимости
любого маршрута, ведь в маршруте меньше 30 связей, каждая по модулю не
больше 32 768: {1210_dp_optimized.cpp}.

Оптимизированное решение на Java читает ввод блоками по 4 КБ и разбирает
числа со знаком вручную, пропуская разделители `*`, вместо того чтобы
резать строки ввода на подстроки через `StringTokenizer`, а минимум
находит простым циклом вместо `Arrays.stream`. Метка недостижимой
планеты у него — 1 000 000, это больше стоимости любого маршрута, ведь в
маршруте меньше 30 связей, каждая по модулю не больше 32 768:
{1210_dp_optimized.java}.

Оптимизированное решение на Python читает ввод кусками по 4 КБ и
разбивает каждый кусок на токены, перенося в следующий кусок только
незаконченный токен, вместо того чтобы читать и разбивать весь ввод
сразу, так что ввод никогда не лежит в памяти целиком; токены `*`
отбрасываются по ходу: {1210_dp_optimized.py}.

Оптимизированное решение на Rust разбирает числа со знаком вручную из
буфера на 4 КБ, который пополняется из стандартного ввода, пропуская
разделители `*`, вместо чтения всего ввода в `String`, так что, кроме
стоимостей двух уровней, в памяти лежит лишь этот буфер. Метка
недостижимой планеты у него — 1 000 000, это больше стоимости любого
маршрута, ведь в маршруте меньше 30 связей, каждая по модулю не больше
32 768: {1210_dp_optimized.rs}.
