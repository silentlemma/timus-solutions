# 1210. 逐层攀升行星的最低花费

[Timus 1210](https://acm.timus.ru/problem.aspx?space=1&num=1210) · 难度 169 · dp

原题作者 Leonid Volkov，出自 2002 年 10 月 USU Open Collegiate Programming Contest（Junior Session）。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

行星分布在第 0 层到第 `N` 层（`0 < N < 30`），每层最多 30 颗，第 0 层只有一颗，
即旅行者的家。通道只从某一层的行星通往下一层的行星，每条通道的花费是 `−32768` 到
`32767` 之间的整数；负的花费表示守护通道的精灵会倒贴给旅行者。求从家到第 `N` 层
任意一颗行星的最便宜路线，结果可能为负。保证至少存在一条路线。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N`，然后是 `N` 个块，块之间用只含 `*` 的行分隔。第 `i` 块以第 `i` 层的行星数
`K_i` 开头，这些行星编号为 1 到 `K_i`；接着按编号顺序每颗行星一行，列出若干对
“第 `i − 1` 层的行星、花费”，以 `0` 结尾。

## 输出

最小的总花费。

## 样例

### 样例 1

输入：

```
3
2
1 15 0
1 5 0
*
3
1 -5 2 10 0
1 3 0
2 40 0
*
2
1 1 2 5 3 -5 0
2 -19 3 -20 0
```

输出：

```
-1
```

## 解法

地图是分层的，每条通道都上升一层，所以没有环，负花费也无妨：到某颗行星的最便宜
路线，就是到某颗连向它的行星的最便宜路线再加上这条通道。为当前层的每颗行星记录
最小花费，家为 0，再根据下一层块中列出的入边算出下一层的花费。答案是第 `N` 层的
最小花费。`L` 为通道数时为 `O(L)`。

注意事项：

- 一颗行星可能根本没有入边，或者只有来自不可达行星的入边；这样的行星必须保持
  不可达，而不能把它后面的慷慨通道传递下去；
- `*` 行只是分隔符，读数时可以跳过；
- 总和的绝对值小于 `30 · 32768`，32 位整数就够了。

答案已在 300 张随机地图上与另一份独立解答比对，其中一半含有不可达的行星。

## 优化解法

优化的 C++ 解法从用 `fread` 反复填充的 4 KB 缓冲区中手工解析带符号的数，把分隔符
`*` 和其他不属于数的字符一起跳过，而不是把每个记号读进 `std::string` 再用
`std::stoi` 转换；输出用 `printf`，因此完全不用 `iostream`。它用 1 000 000
标记不可达的星球，这比任何路线的代价都大，因为一条路线少于 30 条连接，每条的绝对
值不超过 32 768：{1210_dp_optimized.cpp}。

优化的 Java 解法按 4 KB 分块读入并手工解析带符号的数，跳过分隔符 `*`，而不是用
`StringTokenizer` 把各行切成字符串；最小值用普通循环求出，而不是
`Arrays.stream`。它用 1 000 000 标记不可达的星球，这比任何路线的代价都大，因为一
条路线少于 30 条连接，每条的绝对值不超过 32 768：{1210_dp_optimized.java}。

优化的 Python 解法按 4 KB 分块读入，把每块切分成记号，只把未读完的记号带到下一
块，而不是一次读入并切分整个输入，因此整个输入从不同时留在内存中；记号 `*` 随
读随丢：{1210_dp_optimized.py}。

优化的 Rust 解法从标准输入反复填充的 4 KB 缓冲区中手工解析带符号的数，跳过分隔符
`*`，而不是把整个输入读进 `String`，因此除了两层的代价，内存中只有这个缓冲区。
它用 1 000 000 标记不可达的星球，这比任何路线的代价都大，因为一条路线少于 30 条
连接，每条的绝对值不超过 32 768：{1210_dp_optimized.rs}。
