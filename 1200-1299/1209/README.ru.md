# 1209. Цифры записанных подряд 1, 10, 100, 1000

[Timus 1209](https://acm.timus.ru/problem.aspx?space=1&num=1209) · сложность 34 · math

Автор оригинальной задачи — Алексей Лахтин; USU Open Collegiate Programming Contest, октябрь 2002 года, Junior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Степени десятки записаны подряд: `110100100010000…`. Для до 65535
позиций `1 ≤ K < 2³¹` вывести цифру на каждой позиции.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` позиций.

## Выходные данные

`N` цифр через пробел.

## Примеры

### Пример 1

Ввод:

```
4
3
14
7
6
```

Вывод:

```
0 0 1 0
```

## Решение

`m`-я записанная степень — это `10^(m−1)`, она занимает `m` цифр, поэтому
начинается с позиции `1 + (1 + 2 + … + (m − 1)) = 1 + m(m − 1)/2`, и
именно там стоит её единственная 1. На позиции `K` стоит 1 ровно тогда,
когда `K − 1 = m(m − 1)/2` для некоторого `m`, то есть когда
`8(K − 1) + 1 = (2m − 1)²` — точный квадрат. `O(1)` на позицию.

Тонкие места:

- `8(K − 1) + 1` доходит примерно до `1.7·10¹⁰`, больше 32 бит;
- корень в плавающей точке может ошибиться на единицу около больших
  квадратов, поэтому его надо поправить точными целочисленными
  проверками.

Ответы сверены с отдельно написанным решением на всех позициях от 1 до
65535, на случайных позициях и на позициях рядом с единицами.

## Оптимизированные решения

`1209_math_optimized.py`. Сохраняется точная проверка isqrt: позиция K выбрана тогда и только тогда, когда 8*(K-1)+1 — полный квадрат. Ввод теперь идёт блоками по 4096 байт с переносом неполного токена. Цифра с разделителем добавляется в bytearray одним вызовом, сброс — при 4096 байтах; все запросы и ответы не накапливаются. Финальный перевод строки корректен и при точно заполненном блоке. При ограниченных целых O(Q) арифметических операций и ограниченные буферы, без вещественного округления и таблицы ответов. Прямой вывод и os._exit(0) находятся внутри main.

Accepted точного исходника Python 3.12 x64 №11327504: 0.125 с / 748 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 7/209, память 23/209. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11326663 (Python 3.12 x64): 0.156 с / 1076 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1209_math_optimized.py`: 0.125 s / 748 KB; сохранённая учебная база `1209_math.py`: 0.125 s / 6556 KB.

Accepted точного исходника CPython 3.12 №11326663: 0.156 с / 1076 КБ. Сохранённая выборка актуальных компиляторов от 2026-11-20: место по времени 21/209, по памяти 32/209. Обе обязательные метрики проходят строгий критерий первых десяти мест или топ 15%, процентная граница округляется вверх. Звёздочка относится к отдельной цели Python — первому месту по обеим метрикам.

Прежняя документированная оптимизированная посылка №11303724 (Python 3.12 x64) имела 0.218 с / 492 КБ. У текущего запуска CPython 3.12 зафиксированы меньшее время и большая память. Это разные парные измерения судьи; сравнение включает выбор интерпретатора и разброс запусков. Сохранённая простая версия быстрее: 0.125 с; эта версия выбирает меньшую память.

Оптимизированные решения (C++, Rust) разбирают номера позиций вручную и
выводят каждый ответ двумя байтами, цифрой и разделителем, а не собирают
ответы в строку: C++ через `getchar` и `putchar`, Rust из входного
буфера в 1 КБ в `BufWriter`. Проверка та же. C++ — 0.031 с вместо
0.062 с и 84 КБ вместо 388 КБ; Rust — 188 КБ вместо 3160 КБ при том же
времени.

## Особенности языков

- Python использует точный `math.isqrt`; остальные языки поправляют
  корень в плавающей точке целочисленными сравнениями.
