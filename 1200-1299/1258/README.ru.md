# 1258. Бильярд

## Задача

Программист ходит по прямым внутри кабинета W × D (2 ≤ W, D ≤ 1000),
отражаясь от стен, как бильярдный шар. Начало и конец — целые точки
строго внутри кабинета, а удары о стены перечислены по порядку: L, R,
F, B — левая (x = 0), правая (x = W), передняя (y = 0) и задняя
(y = D) стены, не более 1000 ударов, ни одного в угол. Найти длину
пути, округлённую до четырёх знаков после точки.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

W и D, затем x0 y0, затем x1 y1, затем строка ударов (возможно, пустая).

## Выходные данные

Длина пути.

## Примеры

### Пример 1

Ввод:

```
10 20
9 1
1 19
FLRLRB
```

Вывод:

```
52.8015
```

## Решение

Вместо того чтобы поворачивать идущего, будем отражать кабинет при
каждом ударе: путь превращается в один отрезок, а его горизонтальная и
вертикальная протяжённости складываются по отдельности.

По x важны только удары L и R, и они обязаны чередоваться. Если их нет,
протяжённость равна |x1 − x0|. Иначе сначала путь идёт до первой боковой
стены (x0 для L, W − x0 для R), между каждыми двумя соседними боковыми
ударами пересекает кабинет шириной W и от последней боковой стены идёт к
концу (x1 для L, W − x1 для R):

```text
dx = first + (k − 1) · W + last
```

То же самое с F, B и D даёт dy, а ответ равен √(dx² + dy²). Порядок, в
котором перемежаются боковые и передние/задние удары, на длину не
влияет. `O(K)` для K ударов.

Тонкие места:

- строка ударов может быть пустой или вовсе отсутствовать (тест 02);
- первый удар по оси может прийтись на любую из двух стен (тесты 03, 06);
- dx и dy доходят примерно до 10⁶, так что dx² + dy² требует 64 бит
  (тест 08).

Ответы сравнивались на 200 случаях с длиной прямого отрезка, по которому
строился каждый случайный тест (его пересечения с отражённой сеткой
дают удары).
