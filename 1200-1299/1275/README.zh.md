# 1275. 圆桌骑士

[Timus 1275](https://acm.timus.ru/problem.aspx?space=1&num=1275) · 难度 2249 · math

原题作者 Sergey Volchenkov、Vladimir Pinaev 和 Michael Kopachev，出自 2003 年 10 月 15–16 日在雷宾斯克举行的 ACM ICPC 2003–2004 俄罗斯中部赛区四分之一决赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

N 名骑士（2 ≤ N ≤ 1000）围坐在圆桌旁，每人面前有若干酒杯。仆人每来一次，要么给相隔 K
个座位的两名骑士各送来一只酒杯，要么从这两名骑士那里各拿走一只。最终每名骑士都必须有 F 只
酒杯，而且仆人不能拿走不存在的酒杯。求来回次数最少的方案；若不存在，输出 −1。初始数量和 F
都在 0 到 1000 之间，最优方案不超过 30 000 次。

时间限制：0.1 秒。内存限制：0.5 MB。题面只允许 C、C++ 和 Pascal，提交表单还提供 Rust。

## 输入

N、K 和 F，然后是 N 个酒杯数。

## 输出

次数 M，以及形如 `i j +` 或 `i j -` 的每一次；或 −1。

## 评测方式

最优方案可能有很多，所以评测程序接受任意一个：次数必须是最小可能值，每次服务的两名骑士
必须相隔 K 个座位，任何骑士的酒杯都不能被拿到负数，最终每人都有 F 只。

## 样例

### 样例 1

输入：

```
3 1 4
1 2 3
```

输出：

```
3
1 2 +
1 2 +
3 1 +
```

## 解法

设 x_i 为对 (i, i + K) 这一对的带符号次数：正数表示送来，负数表示拿走。同一对上既送又拿
只会浪费次数。骑士 i 属于 (i, i + K) 和 (i − K, i) 两对，所以 x_(i−K) + x_i 必须等于 F 减去
该骑士的酒杯数。

骑士分成 gcd(N, K) 个环 i, i + K, i + 2K, …，每个环长 L = N / gcd(N, K)，各环分别求解。令
第一个未知数为 t，每条规则依次确定下一个，得到符号交替的 x_j = ±t + c_j。最后一条规则把环
闭合：

- L 为奇数时得到 2t = r：恰有一个解，r 为奇数时无解；
- L 为偶数时 t 被消去：r ≠ 0 时无解，否则任意 t 都可以。次数 Σ |t − p_j|（其中
  p_j = ∓c_j）在 t 取这些点的中位数时最小。

先输出所有送来酒杯的次数，再输出拿走的。这样每名骑士的酒杯先只增后只减，数量始终非负，
最终等于 F ≥ 0。

注意事项：

- 在偶数环上，让第一对不被服务的方案可能不是最优；最好的次数由中位数决定（测试 gen3）；
- 如果 `-` 出现在它所依赖的 `+` 之前，就可能拿走一只还不存在的酒杯；
- N = 2K 时，(i, i + K) 与 (i + K, i) 是同一对，两名骑士所需的变化必须相同（测试 07）；
- 内存限制不允许任何笨重的东西：仅 C++ 流库就占用太多，所以程序使用 `scanf` 和 `printf`。

在 400 个最多五名骑士的随机数据上，与枚举所有方案得到的最少次数比较过。

## 各语言说明

- 题面只允许 C、C++ 和 Pascal，但 Timus 的提交表单还提供 Rust 1.75，所以给出 C++ 和 Rust 解答；Go、Python 和 Java 无法提交。
- C++ 用 `int` 存储酒杯数的变化量和带符号次数，t 和总次数使用 `long long`；Rust 用 `i64`
  存储这些变化量、带符号次数和 t，总次数为 `u64`。Rust 自行实现输入输出，各使用固定的
  4096 字节缓冲区，代替 `scanf` 和 `printf`。
