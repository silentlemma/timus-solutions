# 1297. Палиндромы

[Timus 1297](https://acm.timus.ru/problem.aspx?space=1&num=1297) · сложность 82 · strings, greedy

## Задача

Дана строка не длиннее 1000 латинских букв. Нужно вывести её самую
длинную подстроку, которая читается одинаково в обоих направлениях;
если таких несколько — самую левую. Заглавные и строчные буквы
различаются.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Строка.

## Выходные данные

Самая длинная подстрока-палиндром.

## Примеры

### Пример 1

Ввод:

```
Kazak
```

Вывод:

```
aza
```

## Решение

У каждого палиндрома есть центр: буква для нечётной длины и промежуток
между двумя буквами для чётной. В строке из n букв 2n − 1 центров. От
каждого расширяемся наружу, пока буквы с обеих сторон совпадают.
Расширение доходит до самого длинного палиндрома вокруг центра, а более
короткие начинаются правее, поэтому никогда не выигрывают.

Лучший палиндром — самый длинный, а среди равных — с наименьшим
началом. `O(n²)` в худшем случае (строка из одной буквы), всего около
500 000 сравнений при n = 1000.

Алгоритм Манакера справился бы за `O(n)`, но при таком размере он не
нужен.

Тонкие места:

- буквы сравниваются точно, так что `K` и `k` различны (тесты 01, 04 и
  10);
- если все буквы различны, ответ — первая буква (тест 03);
  отсутствие равных соседних букв исключает палиндромы чётной длины,
  но нечётные, например `aba`, всё ещё возможны (тест 06);
- при равенстве длин выбирается самый левый палиндром (тесты 05 и 06);
- палиндромам чётной длины нужны свои центры (тесты 05 и 08).

Ответы сравнивались с перебором всех подстрок на 300 случайных
строках.

## Оптимизированные решения

Оптимизированное решение на C++ читает буквы по одной через `getchar`, а
не всю строку сразу, в массив фиксированного размера на не больше чем
1000 букв до первого пробельного символа. Ответ оно выводит прямо из
этого массива, не строя строку: 92 КБ вместо 364 КБ при том же времени.
Оптимизированное решение на Rust читает и пишет буквы байтами, без
строки UTF-8 посередине: 0.015 с вместо 0.046 с и 208 КБ вместо 244 КБ.
Поиск от каждого центра тот же.

**Наращивание лучшего палиндрома** (Python). Палиндром, кончающийся на
следующей букве, не более чем на 2 длиннее лучшего найденного: если
отрезать ему концы, останется палиндром, кончающийся на букву раньше.
Поэтому для каждой буквы проверяются только два кандидата длины best + 2
и best + 1, кончающихся на ней, — сравнением среза с его разворотом,
которое Python выполняет на C: 0.109 с вместо 0.171 с, хотя память
растёт с 452 КБ до 464 КБ.

## Особенности языков

- Простые решения читают строку целиком, а лишние пробельные символы,
  например `\r` в конце, отбрасываются перед поиском.
