# 1223. Наименьшее число бросков яиц, находящее критический этаж

[Timus 1223](https://acm.timus.ru/problem.aspx?space=1&num=1223) · сложность 292 · dp

Оригинальная задача — фольклор, предложена Александром Клепининым; VII студенческое соревнование по программированию УрГУ.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `f` этажей с номерами от 1 до `f` и `e` одинаковых яиц,
где `1 ≤ e, f ≤ 1000`. Неизвестное `E` лежит в `0..f`: яйцо выдерживает
падение с любого этажа не выше `E` и разбивается выше него. Если яйцо
разбилось на первом этаже, то `E = 0`; если уцелело на этаже `f`, то `E = f`.

Найдите наименьшее число бросков, определяющее `E` в худшем случае.
Уцелевшие яйца можно использовать повторно. Запросов не больше 1000;
пара `0 0` завершает ввод и запросом не является.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

По запросу в строке: число яиц и число этажей.

## Выходные данные

Для каждого запроса — наименьшее число бросков в худшем случае.

## Проверка

Целочисленные токены сравниваются в порядке запросов; для `0 0`
ответ не выводится. Каждый из пяти новых учебных исходников прошёл
13 архивных входов в Docker и получил собственный Accepted точного SHA.
Новый учебный Python реально проверен на 21000 запросах пачками не более
1000: все этажи1..1000 при яйцах1..20 и 1000 случайных запросов до1000
яиц. Независимый эталон использует замкнутую сумму `Σ C(d,i)` и двоичный
поиск, а не прямую или обратную ДП. Это запуски Python, не 21000 запусков
каждого машинного языка. Важны одно яйцо, один этаж, десять и1000 яиц,
точные границы ёмкости, 1000 запросов и завершающий нулевой запрос.

## Примеры

### Пример 1

Ввод:

```
1 10
2 5
0 0
```

Вывод:

```
10
3
```

## Решение

Новые учебные версии используют прямую минимаксную рекуррентность.
Пусть `D(e,f)` — минимум бросков в худшем случае при `e` яйцах и `f`
этажах. Для нуля этажей ответ ноль, `D(1,f)=f`. Первый бросок с этажа
`x`: разбившееся яйцо оставляет `x−1` этажей и на одно яйцо меньше,
уцелевшее — `f−x` этажей с прежним числом яиц. Поэтому
`D(e,f)=1+min₁≤ₓ≤f max(D(e−1,x−1),D(e,f−x))`. У любой стратегии есть
первый этаж и оба возможных исхода, что доказывает нижнюю границу.
Выбрав лучший этаж и оптимально продолжая каждую ветвь, достигаем её.

Считаем по возрастанию яиц и этажей: первое слагаемое уже в предыдущей
строке, второе — для меньшего числа этажей. Возможных порогов `F+1`,
исход каждого опыта двоичный, значит нужно хотя бы `ceil(log₂(F+1))`
бросков. С десятью яйцами обычный двоичный поиск достигает этой границы
при `F≤1000`: не более десяти бросков, по одному потерянному яйцу на
бросок. Дополнительные яйца не помогают. Ограничение десятью строками
доказано, а не подобрано.

При `E=10`, `F=1000` подготовка требует `O(EF²)` времени и `O(EF)`
целых ячеек, запрос — `O(1)`. Все пять новых исходников получили
собственные Accepted и выбраны учебными базами. Простой Python работает
в PyPy 3.10. Все пять прежних исходников побайтово сохранены;
дублирующих optimized-копий нет.

## Оптимизированные решения

Прежний алгоритм `dp` решает обратную задачу. Пусть `R(d,e)` —
сколько этажей можно различить за `d` бросков с `e` яйцами. Первый бросок
делит задачу на ветвь разбившегося яйца, свой этаж и ветвь уцелевшего:
`R(d,e)=R(d−1,e−1)+1+R(d−1,e)`, нулевые границы. Такое разбиение
необходимо и достижимо по тому же рассуждению о дереве решений.
Первое `d` с `R(d,e)≥f` в точности равно `D(e,f)`.

Увеличиваем `d` и заполняем ответ для этажа при первом достижении его
ёмкости. Ёмкости безопасно ограничивать F: большие значения одинаковы
для всех запросов, обновление монотонно. Проходов не больше F, ведь
одно яйцо различает d этажей, а каждая ячейка ответа записывается один
раз. Получаем подготовку `O(EF)`, память `O(EF)`, запрос `O(1)`.
Слагаемые после ограничения не больше F, сумма не больше
`2F+1=2001`, что безопасно для используемых машинных целых.

По правилу 30% оптимизированным сейчас называется только прежний Python:
CPython 0,078 с / 812 КБ против учебного PyPy 0,265 с / 2916 КБ;
экономия времени 70,6%, памяти 72,2%. Это другой алгоритм, сохраняющий
прежнее имя `dp`. Прежний Java быстрее лишь на 28,4% и расходует больше
памяти — это алгоритмическая альтернатива. C++/Go/Rust тоже не достигают
30% относительно новых баз; они сохранены без ярлыка оптимизации.
Новая простая Java уже достигает рейтинговой цели.
