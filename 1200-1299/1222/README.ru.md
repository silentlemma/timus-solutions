# 1222. Наибольшее произведение чисел с заданной суммой

[Timus 1222](https://acm.timus.ru/problem.aspx?space=1&num=1222) · сложность 144 · math

Оригинальная задача — фольклор, предложена Леонидом Волковым; VII студенческое соревнование по программированию УрГУ.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У стаи орлов всего `1 ≤ N ≤ 3000` голов, а её IQ равен произведению
числа голов её орлов. Найти наибольший возможный IQ, то есть наибольшее
произведение натуральных чисел с суммой `N`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Наибольшее произведение.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
7
```

Вывод:

```
12
```

## Решение

Слагаемое 4 и больше можно разбить на 2 и остаток, не уменьшив
произведение, а слагаемое 5 и больше так его увеличивает
(`2(k − 2) > k` при `k > 4`), слагаемое же 1 только тратит голову. Значит,
в оптимальном разбиении только двойки, тройки и четвёрки, а 4 — то же,
что 2 + 2. Три двойки хуже двух троек (`8 < 9`), так что двоек не больше
двух. Остаётся: одни тройки, когда `N` делится на 3, ещё одна двойка при
остатке 2 и две двойки (или одна четвёрка) вместо тройки при остатке 1.
При `N` до 3 лучше всего один орёл. В произведении до 478 цифр. `O(N²)`
операций с цифрами для многократного умножения на 3.

Ответ содержит O(N) цифр/битов. Растущие векторы цифр, длинные целые и десятичный вывод используют O(N) живой памяти значений/вывода плюс рабочую память библиотечной арифметики; быстрая C++ вместо этого резервирует фиксированный массив 1000 цифр. Для повторных малых умножений консервативная оценка O(N²) операций над цифрами. Библиотечная степень использует более крупные умножения; общая граница не означает N повторных умножений встроенной степени.

Тонкие места:

- `N = 1` даёт 1, а `N = 4` даёт 4;
- остаток 1 нельзя оставлять множителем 1;
- ответ далеко за пределами 64 бит.

Ответы проверены перебором всех разбиений для каждого `N` до 59 и сверены
с отдельно написанным решением на всех тестах.

## Оптимизированные решения

`1222_math_optimized.java`. Сохраняется оптимальное разбиение на тройки с заменой остатка один множителем четыре; N<4 обрабатывается отдельно. То же произведение вычисляется в блоках по основанию 10^9 с множителями до 3^18 во время работы, без BigInteger и готовых ответов. Каждое промежуточное long меньше 10^9*3^18<2^63. При выводе младшие блоки дополняются до девяти цифр. Консервативно O(N²) арифметической работы и O(N) памяти; простая математическая версия сохранена.

Accepted точного Java 1.8 №11327402: 0.093 с / 348 КБ. Сохранённые места от 2026-11-20: время 12/136, память 2/136. Ниже 1024 КБ проходит только время, без отдельного первого места и звёздочки. Прежняя быстрая №11304486 за 0.125 с / 484 КБ — отдельная историческая пара, не подтверждение текущего файла. Простой алгоритм Java сохранён; правка только комментария отмечена ниже.

- `1222_math_optimized.java`: 0.093 s / 348 KB; сохранённая учебная база `1222_math.java`: 0.093 s / 1708 KB.

`1222_math_optimized.rs`. Сохраняется оптимальное разбиение на тройки с четвёркой при остатке один. В разряде u32 хранятся девять десятичных цифр вместо одной; девятизначные группы с нулями выводятся напрямую без десятичной String. Умножение на три помещается в u32: 3*(10^9-1)+2<2^32. Повторные малые умножения всё ещё требуют O(n²) разрядной работы и O(n) цифр памяти; выигрыш даёт компактное представление, а не другая асимптотика. Простая версия с десятичными разрядами сохранена.

По сравнению с `1222_math.rs`: время 0.031 s → 0.015 s; память 208 KB → 64 KB.

Оптимизированное решение на C++ умножает глобальный массив постоянного
размера из 1000 десятичных цифр вместо `std::vector`, растущего вместе с
произведением, так что программе не нужна динамическая память; при
`N ≤ 3000` в произведении не больше 478 цифр: {1222_math_optimized.cpp}.

## Особенности языков

К сохранённым точным исходникам применяются общие [рейтинговые критерии](../../RATING_CRITERIA.md). Проходят обе C++, Go, базовая CPython, быстрая Java и обе Rust. Простая Java не проходит обязательную память; PyPy не проходит время и сохраняет маркер. Ниже 1024 КБ учитывается только время; Go с 1184 КБ нужны обе метрики и эталон точного компилятора. Rust использует выборку всего того же языка: обе пары 0.031 с / 208 КБ и 0.015 с / 64 КБ проходят численно, не по пустой таблице или исключению экономии памяти. Прежние места PyPy 19/61 по времени, 3/61 по памяти исторические, не текущая цель первого места.

Сейчас исправлен только комментарий доказательства в `1222_math.cpp`, `1222_math_optimized.cpp`, `1222_math.go`, `1222_math.java`, `1222_math.py` и `1222_math.rs`: разбиение части больше 4 строго улучшает произведение, 4=2+2 даёт равенство. Исполняемый текст и все остальные комментарии не изменены. Посылки в таблицах и допуск выше относятся к историческим точным байтам.
