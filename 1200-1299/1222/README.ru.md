# 1222. Наибольшее произведение чисел с заданной суммой

[Timus 1222](https://acm.timus.ru/problem.aspx?space=1&num=1222) · сложность 144 · math

Оригинальная задача — фольклор, предложена Леонидом Волковым; VII студенческое соревнование по программированию УрГУ.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У стаи орлов всего `1 ≤ N ≤ 3000` голов, а её IQ равен произведению
числа голов её орлов. Найти наибольший возможный IQ, то есть наибольшее
произведение натуральных чисел с суммой `N`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Наибольшее произведение.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
5
```

Вывод:

```
6
```

## Решение

Слагаемое 4 и больше можно разбить на 2 и остаток, не уменьшив
произведение, а слагаемое 5 и больше так его увеличивает
(`2(k − 2) > k` при `k > 4`), слагаемое же 1 только тратит голову. Значит,
в оптимальном разбиении только двойки, тройки и четвёрки, а 4 — то же,
что 2 + 2. Три двойки хуже двух троек (`8 < 9`), так что двоек не больше
двух. Остаётся: одни тройки, когда `N` делится на 3, ещё одна двойка при
остатке 2 и две двойки (или одна четвёрка) вместо тройки при остатке 1.
При `N` до 3 лучше всего один орёл. В произведении до 478 цифр. `O(N²)`
операций с цифрами для многократного умножения на 3.

Тонкие места:

- `N = 1` даёт 1, а `N = 4` даёт 4;
- остаток 1 нельзя оставлять множителем 1;
- ответ далеко за пределами 64 бит.

Ответы проверены перебором всех разбиений для каждого `N` до 59 и сверены
с отдельно написанным решением на всех тестах.

## Оптимизированные решения

`1222_math_optimized.rs`. Сохраняется оптимальное разбиение на тройки с четвёркой при остатке один. В разряде u32 хранятся девять десятичных цифр вместо одной; девятизначные группы с нулями выводятся напрямую без десятичной String. Умножение на три помещается в u32: 3*(10^9-1)+2<2^32. Повторные малые умножения всё ещё требуют O(n²) разрядной работы и O(n) цифр памяти; выигрыш даёт компактное представление, а не другая асимптотика. Простая версия с десятичными разрядами сохранена.

По сравнению с `1222_math.rs`: время 0.031 s → 0.015 s; память 208 KB → 64 KB.

Оптимизированное решение на C++ умножает глобальный массив постоянного
размера из 1000 десятичных цифр вместо `std::vector`, растущего вместе с
произведением, так что программе не нужна динамическая память; при
`N ≤ 3000` в произведении не больше 478 цифр: {1222_math_optimized.cpp}.

Оптимизированное решение на Java читает единственное число побайтно
через `System.in.read`, а не создаёт `Scanner`, так что JVM не загружает
сканер и его регулярные выражения; степень через `BigInteger` та же:
{1222_math_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1222_math_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +45.83%; база: `1222_math.cpp`.

- `1222_math_optimized.java`: сокращение времени -34.41%; сокращение
  памяти +71.66%; база: `1222_math.java`.

`1222_math_optimized.py`. Сохраняется разбиение максимального произведения на тройки: N<4 обрабатывается отдельно, остаток один заменяется четвёркой. Точный результат прежний; pow и базовый ** равнозначны как целочисленное возведение в степень. Ответ занимает O(N) бит, консервативная граница школьной арифметики и десятичного вывода — O(N²) времени и O(N) бит. Измеренное улучшение относится к реализации самостоятельной программы. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1222_math.py`: время 0.078 s → 0.109 s; память 396 KB → 248 KB.

Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
