# 1298. Обойти все клетки ходами коня

[Timus 1298](https://acm.timus.ru/problem.aspx?space=1&num=1298) · сложность 234 · backtracking

Оригинальная задача — фольклор (подготовил Ден Расковалов); IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На доске N × N (1 ≤ N ≤ 8) нужно найти обход конём: путь из ходов
коня, проходящий через каждую клетку ровно один раз. Вывести клетки по
порядку — буква столбца и номер строки — или `IMPOSSIBLE`, если обхода
нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

N² клеток по одной в строке или `IMPOSSIBLE`.

## Проверка

Проверяем ответ как свидетельство: ровно N² различных клеток внутри
доски, каждый переход — ход коня. Допустимы разные обходы; сравнивать их
текст или предполагать одинаковый порядок равных кандидатов нельзя.
Обе новые программы прошли восемь входов репозитория в Java 8 и CPython
3.12: покрыт весь диапазон значений N=1..8. Все 16 фактических выводов
и кодов завершения заново независимо проверены. Для `IMPOSSIBLE`
отдельный обычный поиск перебрал все начала и пути при N≤4, всего
30102 рекурсивных вызова, без симметрий, порядка степеней и отсечения
изолированных вершин. У обоих исходников есть собственный Accepted
для точных байтов.

## Решение

Считаем клетки вершинами графа, а допустимые ходы коня — рёбрами.
Пусть `V=N²`. Простые версии запускают поиск в глубину с возвратом из
каждой начальной клетки. Отмечаем текущую клетку, добавляем её в путь,
пробуем всех непосещённых соседей. При неудаче снимаем отметку и удаляем
клетку из пути. Путь из V вершин является обходом. Если все ветви из всех
начал неудачны, обхода нет. Полнота не зависит от порядка ходов.

Правило Варнсдорфа первым пробует соседа с меньшим числом свободных
продолжений. Оно меняет лишь порядок, не отбрасывая ветви. Часто ответ
находится быстро, но полиномиальная оценка не гарантируется. Грубая
верхняя граница — `O(V·8^V)` времени и `O(V)` памяти: у вершины не более
восьми соседей, глубина рекурсии не больше V. Весь допустимый диапазон
мал (`V≤64`) и явно проверен ниже.

При N=1 ответ — одна клетка a1. Для N=2,3,4 полный обычный перебор
доказывает отсутствие обхода. Для N=5,6,7,8 фактический вывод содержит
полный обход. Замыкать его не нужно, начинать можно с любой клетки.
Практическое поведение эвристики не является доказательством асимптотики.

## Оптимизированные решения

Два файла `_optimized` сохраняют тот же полный поиск с порядком
Варнсдорфа, но хранят соседей и непосещённые клетки битовыми масками.
Номер `(столбец,строка)` равен `столбец*N+строка`. Кандидаты —
`adjacency[v] & remaining`; степень продолжения — число единиц в
`adjacency[w] & remaining`. Упорядочить нужно не более восьми ходов.

Два корректных отсечения уменьшают поиск. Отражения относительно обеих
осей и транспонирование сохраняют ходы коня. Отражением переводим начало
в расстояния до ближайших краёв, затем переставляем координаты так,
чтобы столбец≤строка. В каждой орбите начал есть представитель
`0≤столбец≤строка<ceil(N/2)`; достаточно перебрать только их.
Кроме того, при более чем одной оставшейся вершине изолированная вершина
в порождённом ими графе делает продолжение невозможным: путь через все
оставшиеся вершины не сможет связать её с другой оставшейся вершиной.
Для единственной оставшейся клетки это отсечение не применяется.

Python использует целые маски и `bit_count`, устраняя повторное создание
координатных кортежей и списков свободных соседей. Java использует `long`
и примитивные массивы кандидатов и степеней для каждой глубины вместо
ArrayList, отдельных массивов координат каждого хода, компараторов и
Scanner. При N=8 нужны все 64 бита: полная маска Java явно равна `-1L`,
поскольку сдвиг long на 64 фактически означал бы сдвиг на ноль.
Знаковый бит 63 не мешает подсчёту единиц и поиску младшей единицы.

Отсечения сохраняют полноту, но не дают полиномиальной гарантии. Грубая
граница с учётом проверки изолированных вершин — `O(V²·8^V)` времени.
При V≤64 маски и рабочие массивы глубин занимают `O(V)` слов или объектов
ограниченного размера, глубина не больше V. При обобщении на большие
доски пришлось бы учитывать переменный размер длинных целых. Готовых
обходов и ответов в исходниках нет.

Accepted точных байтов Python: 0,062 против 0,171 с, ускорение 63,7%,
но 636 против 544 КБ, расход памяти выше на 16,9%. Java: 396 против
7116 КБ, экономия 94,4%; время 0,125 против 0,156 с, меньше на 19,9%.
Оба варианта проходят критерий по одной из метрик. Все пять простых
исходников сохранены побайтово.

## Особенности языков

Пять прежних реализаций сохраняют понятный поиск по координатам и
свои принятые обходы. Две масочные версии могут выводить другой
допустимый порядок. В таблице указан фактически принятый интерпретатор:
новая Python-версия получила Accepted в CPython 3.12, не в PyPy.

Обе новые версии допущены по выигрышу, но ещё не занимают первое место
хотя бы по одной метрике, поэтому у обеих строк стоит звёздочка. База
C++ уже проходит согласованное правило топ 15% либо первых десяти мест
по обеим метрикам. Для Go и Rust в отфильтрованном снимке нет допустимых
чужих посылок: это формальное покрытие, не доказательство превосходства.
Сравнения идут со своей простой базой на том же языке; искусственных
оптимизированных копий нет.
