# 1298. Обойти все клетки ходами коня

[Timus 1298](https://acm.timus.ru/problem.aspx?space=1&num=1298) · сложность 234 · backtracking

Оригинальная задача — фольклор (подготовил Ден Расковалов); IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На доске N × N (1 ≤ N ≤ 8) нужно найти обход конём: путь из ходов
коня, проходящий через каждую клетку ровно один раз. Вывести клетки по
порядку — буква столбца и номер строки — или `IMPOSSIBLE`, если обхода
нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

N² клеток по одной в строке или `IMPOSSIBLE`.

## Проверка

Вывод проверяется как свидетельство, а не сравнением обходов: ровно N²
различных клеток внутри доски, по одной в строке, каждый соседний
переход — ход коня. Все восемь исходников запускаются при каждом
N=1..8: проверены 64 настоящих вывода и коды завершения. Для IMPOSSIBLE
независимый простой перебор проходит все старты и пути при N=2,3,4
без симметрий, сортировки степеней и отсечения изолированных вершин. Обход одной клетки и обходы N=5..8 проверены напрямую.

## Решение

Считаем клетки вершинами графа, а допустимые ходы коня — рёбрами.
Пусть `V=N²`. Простые версии запускают поиск в глубину с возвратом из
каждой начальной клетки. Отмечаем текущую клетку, добавляем её в путь,
пробуем всех непосещённых соседей. При неудаче снимаем отметку и удаляем
клетку из пути. Путь из V вершин является обходом. Если все ветви из всех
начал неудачны, обхода нет. Полнота не зависит от порядка ходов.

Правило Варнсдорфа первым пробует соседа с меньшим числом свободных
продолжений. Оно меняет лишь порядок, не отбрасывая ветви. Часто ответ
находится быстро, но полиномиальная оценка не гарантируется. Грубая
верхняя граница — `O(V·8^V)` времени и `O(V)` памяти: у вершины не более
восьми соседей, глубина рекурсии не больше V. Весь допустимый диапазон
мал (`V≤64`) и явно проверен ниже.

При N=1 ответ — одна клетка a1. Для N=2,3,4 полный обычный перебор
доказывает отсутствие обхода. Для N=5,6,7,8 фактический вывод содержит
полный обход. Замыкать его не нужно, начинать можно с любой клетки.
Практическое поведение эвристики не является доказательством асимптотики.

## Оптимизированные решения

`1298_backtracking_optimized.java`. Сохраняются полный перебор с порядком Варнсдорфа и представители симметрий. Степени активных вершин обновляются при удалении текущей вершины; маска изолированных вершин делает прежний тест невозможности константным. Неудачная ветвь восстанавливает ровно изменённые степени соседей и сохранённую маску. Стабильный порядок ходов и исключение для последней вершины сохранены; ограничения поиска нет. Грубая экспоненциальная оценка остаётся O(V²·8^V), память O(V) ограниченных машинных слов при V=N²≤64. Готовые обходы не хранятся.

Accepted точного исходника Java 1.8 #11327756 — `0.078 s / 376 KB`,
сохранённые места от 20 ноября 2026 года: время 1/26, память 2/26.
Ниже 1024 КБ нужно только время, поэтому версия проходит. В текущей
строке нет звёздочки и отдельной языковой цели первого места по обеим
метрикам тоже нет. Прежний запуск #11308542 (`0.125 s / 396 KB`) —
отдельная историческая пара; учебные исходники сохранены.

- `1298_backtracking_optimized.java`: 0.078 s / 376 KB; сохранённая учебная база `1298_backtracking.java`: 0.156 s / 7116 KB.

Два файла `_optimized` сохраняют тот же полный поиск с порядком
Варнсдорфа, но хранят соседей и непосещённые клетки битовыми масками.
Номер `(столбец,строка)` равен `столбец*N+строка`. Кандидаты —
`adjacency[v] & remaining`; степень продолжения — число единиц в
`adjacency[w] & remaining`. Упорядочить нужно не более восьми ходов.

Два корректных отсечения уменьшают поиск. Отражения относительно обеих
осей и транспонирование сохраняют ходы коня. Отражением переводим начало
в расстояния до ближайших краёв, затем переставляем координаты так,
чтобы столбец≤строка. В каждой орбите начал есть представитель
`0≤столбец≤строка<ceil(N/2)`; достаточно перебрать только их.
Кроме того, при более чем одной оставшейся вершине изолированная вершина
в порождённом ими графе делает продолжение невозможным: путь через все
оставшиеся вершины не сможет связать её с другой оставшейся вершиной.
Для единственной оставшейся клетки это отсечение не применяется.

Историческое описание и замеры прежней ревизии: Python использует целые маски и `bit_count`, устраняя повторное создание
координатных кортежей и списков свободных соседей. Java использует `long`
и примитивные массивы кандидатов и степеней для каждой глубины вместо
ArrayList, отдельных массивов координат каждого хода, компараторов и
Scanner. При N=8 нужны все 64 бита: полная маска Java явно равна `-1L`,
поскольку сдвиг long на 64 фактически означал бы сдвиг на ноль.
Знаковый бит 63 не мешает подсчёту единиц и поиску младшей единицы.

Отсечения сохраняют полноту, но не дают полиномиальной гарантии. Грубая
граница с учётом проверки изолированных вершин — `O(V²·8^V)` времени.
При V≤64 маски и рабочие массивы глубин занимают `O(V)` слов или объектов
ограниченного размера, глубина не больше V. При обобщении на большие
доски пришлось бы учитывать переменный размер длинных целых. Готовых
обходов и ответов в исходниках нет.

Историческое описание и замеры прежней ревизии: Accepted точных байтов Python: 0,062 против 0,171 с, ускорение 63,7%,
но 636 против 544 КБ, расход памяти выше на 16,9%. Java: 396 против
7116 КБ, экономия 94,4%; время 0,125 против 0,156 с, меньше на 19,9%.
Оба варианта проходят критерий по одной из метрик. Все пять простых
исходников сохранены побайтово.

## Особенности языков

Действуют общие [рейтинговые критерии](../../RATING_CRITERIA.md): обычные
топ-10 или топ-15% по нужным метрикам, заменяемые эталоном при 1–10
допустимых соперниках того же компилятора. Ниже 1024 КБ нужно только
время. Чужие времена быстрее `0.015 s` исключаются; снизу ограничивается
лишь наше время сравнения. Ничьи делят место, процентная отсечка
округляется вверх. Нет отдельного первого места, отсечения по ID/дате
или допуска только за улучшение на 30%. В текущих таблицах звёздочек нет.

Замороженный аудит точных исходников допускает простую C++ по обычному
рейтингу времени и быструю Java с местом времени 1/26. Быстрая CPython
#11308531 (`0.062 s / 636 KB`) проходит порог `0.093 s` по девяти
соперникам. У Go два соперника: выбранная #11330229 (`0.015 s / 780 KB`)
проходит порог `0.062 s`; база Go с 4468 КБ превышает порог памяти
1127.00 КБ. У Rust один соперник и пройден порог времени `0.031 s`.
Прежнее утверждение об отсутствии соперников Go/Rust устарело. Простые
Java и Python сохранены для обучения, хотя нужные сравнения не пройдены.
Все алгоритмы поиска, комментарии и ячейки Accepted сохранены.

Координатные простые поиски остаются полными. Масочные версии могут
печатать другой правильный обход. Для быстрой Python таблица выбирает
CPython 3.12; искусственные дубликаты быстрых файлов не нужны.

Строгий линтер требует имён для числа ходов Go8, границы невозможных
досок4 и буфера цифр24. Текущий файл только выделяет эти константы;
подстановка значений в точности возвращает байты прежнего Accepted. #11330229 и его измерения относятся к той версии.
