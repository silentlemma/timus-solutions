# 1298. 用马步走遍所有格子

[Timus 1298](https://acm.timus.ru/problem.aspx?space=1&num=1298) · 难度 234 · backtracking

原题为民间流传的题目（由 Den Raskovalov 准备），出自 2004 年 3 月 13 日第九届中学生公开团体程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

在 N × N 的棋盘上（1 ≤ N ≤ 8）找一条马的周游路线：由马步组成、恰好经过每个格子一次的路径。按顺序
输出各格（列用字母，行用数字）；若不存在周游，输出 `IMPOSSIBLE`。

时间限制：1 秒。内存限制：64 MB。

## 输入

数 N。

## 输出

N² 个格子，每行一个，或 `IMPOSSIBLE`。

## 评测方式

按见证验证输出：恰有 N² 个互不相同、位于棋盘内的格子，每个相邻位移均为
马步。不同正确路径都允许，不比较文本或假定相同的平局顺序。两份新程序各在
Java 8、CPython 3.12 下通过八个仓库输入，覆盖全部允许的 N=1..8。重新独立
检查全部 16 份实际输出及退出码。无解的 N≤4 由另一普通搜索枚举所有起点和路径，
共 30102 次递归，不用对称、度数顺序或孤立点剪枝。两份源码都有精确字节的
独立 Accepted 提交。

## 解法

把每个格子看作顶点，合法马步看作边，令 `V=N²`。基础版从每个起点做
深度优先回溯：标记当前格子并加入路径，尝试所有未访问邻居；分支失败后撤销标记
并移出路径。包含 V 个顶点的路径即所求。所有起点的所有分支都失败才输出无解，
因此完备性与尝试顺序无关。

Warnsdorff 规则先尝试后续未访问邻居更少的格子，只改变顺序，不省略分支。
实践中常很快找到路径，但不保证多项式时间。粗略最坏上界为 `O(V·8^V)` 时间、
`O(V)` 空间：每格最多八个邻居，递归深度不超过 V。允许范围很小（`V≤64`），
下面逐一验证了全部 N 值。

N=1 的答案为 a1；N=2,3,4 的无解由普通完整枚举证明。N=5,6,7,8 的实际
输出提供了完整路径。不要求闭合，起点任意。不能把启发式的实测表现当成渐近证明。

## 优化解法

两份 `_optimized` 保留同一完整 Warnsdorff 顺序回溯，用位掩码保存邻居
和未访问格子。编号 `(列,行)` 为 `列*N+行`；候选为 `adjacency[v] & remaining`，
候选 w 的后续度数为 `adjacency[w] & remaining` 的置位数。最多排序八个候选。

两个可靠缩减减少搜索。水平、垂直反射及转置都保持马步。先把起点反射为到最近边界
的距离，再转置使列≤行；每个起点轨道在 `0≤列≤行<ceil(N/2)` 中有代表，
只枚举这些代表仍完备。此外，若剩余顶点多于一个且其诱导子图存在孤立点，覆盖所有
剩余顶点的路径无法把它与另一剩余顶点连接，故该分支无解。仅剩一个顶点时不剪枝。

Python 使用整数掩码和 `bit_count`，避免重复构造坐标元组及空闲邻居列表。
Java 用 long 掩码及按深度保存的基本类型候选、度数数组，避免 ArrayList、每步
坐标数组、比较器对象及 Scanner。N=8 需要全部 64 位，Java 显式用 `-1L` 作
完整掩码，因为 long 左移 64 实际等于左移零。有符号的第 63 位不影响置位计数或
最低置位位置提取。

这些缩减保持完备，不保证多项式复杂度。包含每次孤立点扫描的粗略上界为
`O(V²·8^V)` 时间。V≤64 时，掩码和每层工作空间占 `O(V)` 个有限大小的字或
对象，深度至多 V；推广到更大棋盘还必须计入变长整数掩码的成本。源码不存现成路径
或答案。

精确源码的 Accepted：Python 从 0.171 降至 0.062 s，快 63.7%，但内存
从 544 增至 636 KB，多 16.9%；Java 从 7116 降至 396 KB，少 94.4%，
时间从 0.156 降至 0.125 s，少 19.9%。两者各有一项满足准入条件，五份简单
源码全部逐字节保留。
