# 1246. В какую сторону обходят многоугольник

[Timus 1246](https://acm.timus.ru/problem.aspx?space=1&num=1246) · сложность 333 · geometry

Автор оригинальной задачи — Евгений Кобзев; личное первенство УрГУ, 1 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Собака привязана к столбу внутри участка, обнесённого забором, — простого
многоугольника из N вершин (3 ≤ N ≤ 200 000, целые координаты по модулю
до 50 000). Бегун бегает круг за кругом вдоль забора, проходя вершины в
данном порядке, а собака гоняется за бегуном внутри. В какую сторону
намотается трос на столб: по часовой стрелке (`cw`) или против (`ccw`)?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N вершин в порядке обхода бегуном.

## Выходные данные

`cw` или `ccw`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4
0 0
0 1
1 1
1 0
```

Вывод:

```
cw
```

## Решение

Собака следует за бегуном вдоль внутренней стороны участка, так что трос
наматывается в ту сторону, в которую бегун обходит многоугольник. Это
знак удвоенной ориентированной площади многоугольника по формуле шнурования,
`Σ (x_i·y_{i+1} − x_{i+1}·y_i)`: положительный при обходе против часовой
стрелки и отрицательный по часовой. Многоугольник простой и не вырожден,
так что сумма никогда не равна нулю. `O(N)`.

Тонкие места:

- многоугольник не обязательно выпуклый, так что поворот в одной
  вершине ничего не говорит; решает только площадь целиком (тесты 04 и
  05);
- каждое слагаемое доходит до 5·10⁹, больше 32 бит, поэтому нужны
  64-битные целые или целые произвольной точности.

## Оптимизированные решения

C++ и Rust накапливают удвоенную ориентированную площадь во время чтения вершин. Они хранят первую и предыдущую точки, по одному разу добавляют векторное произведение для каждого ребра и замыкают многоугольник. Произведения и сумма хранятся в знаковых 64-битных числах. Буфер ввода и геометрические данные занимают постоянный объём памяти.

Принятые базовые реализации [1246_geometry.go](1246_geometry.go), [1246_geometry.java](1246_geometry.java), [1246_geometry.py](1246_geometry.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

`1246_geometry_optimized.py`. Сохраняется определение ориентации по формуле площади, но очередное ребро добавляется при чтении следующей вершины, в конце замыкается ребро от последней к первой. Хранятся лишь первая и предыдущая вершины и точная знаковая удвоенная площадь; положительная означает ccw, иначе cw как в базе. Разбор блоками по 65536 байт переносит разорванный числовой токен, заменяя список всех входных целых, срезы координат и циклические копии. При B байтах ввода и N вершинах время O(B+N), память — ограниченные блоки парсера и постоянное состояние арифметики при данных пределах. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1246_geometry.py`: время 0.218 s → 0.187 s; память 41236 KB → 10 140 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1246_geometry_optimized.py`: место по времени 2/22, по памяти 7/22 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
