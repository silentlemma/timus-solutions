# 1264. 工作日常

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个函数统计 0 到 M 的每个值在 N 个元素的数组中出现了几次，写法是对每个元素和每个值各写
一行 `if`（0 ≤ N, M ≤ 40 000）。写一行要一秒。写完整个函数需要多少秒？

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 M。

## 输出

秒数。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
3 1
```

输出：

```
6
```

## 解法

有 N 个元素、M + 1 个值，所以答案是 N · (M + 1)。`O(1)`。

注意事项：

- 值从 0 到 M，共 M + 1 个，而不是 M 个；
- 答案可达 40 000 · 40 001 = 1 600 040 000，接近 32 位有符号整数的上限；C++、Go、Java 和 Rust 使用 64 位
  （测试 05）；
- N = 0 时无论 M 为多少答案都是 0（测试 02、03）。

## 优化解法

`1264_math_optimized.go`. 保留直接计数 N*(M+1)，涵盖零元素及 M+1 个取值中的零，不模拟数组。N,M<=40000 时乘积至多1600040000；Go 保持 int64，Python 用精确整数。数字字节输入和直接输出降低运行开销，时间及额外状态仍为 O(1)。 可移植的 os.Stdin.Read/os.Stdout.Write 与直接整数转换使用各 4096 字节的固定输入输出缓冲区。重复使用输出缓冲区前会处理部分写入。保留原有简单 Accepted 版本。

与 `1264_math.go` 相比：时间 0.031 s → 0.015 s；内存 1060 KB → 796 KB。

`1264_math_optimized.py`. 保留直接计数 N*(M+1)，涵盖零元素及 M+1 个取值中的零，不模拟数组。N,M<=40000 时乘积至多1600040000；Go 保持 int64，Python 用精确整数。数字字节输入和直接输出降低运行开销，时间及额外状态仍为 O(1)。 独立评测程序在 os._exit(0) 前显式刷新 stdout，跳过常规解释器清理。其自身 Accepted 记录证明内存收益。单独改变退出方式不改进渐近复杂度，运行环境收益也不保证跨平台成立。简单版本保持不变。

与 `1264_math.py` 相比：时间 0.093 s → 0.109 s；内存 320 KB → 208 KB。

优化的 Java 解法直接从 `System.in` 逐字节解析两个数，而不是使用 `Scanner`：
296 KB，而不是 1552 KB，但时间从 0.109 s 增加到 0.140 s。
