# 1208. Больше всего легендарных команд без общих участников

[Timus 1208](https://acm.timus.ru/problem.aspx?space=1&num=1208) · сложность 210 · bitmask, dp

Автор оригинальной задачи — Леонид Волков; командное соревнование УрГУ, март 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Выберите наибольшее подмножество `1 ≤ K ≤ 18` команд без общего
участника у двух выбранных команд. В каждой команде три различных имени
длиной до 20 строчных латинских букв; имя может встречаться в нескольких
командах. Лимит времени — 0,5 секунды, памяти — 64 МБ.

## Входные данные

`K`, затем три имени каждой команды, до 20 строчных букв.

## Выходные данные

Наибольшее число команд, которые могут участвовать.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Примеры

### Пример 1

Ввод:

```
7
gerostratos scorpio shamgshamg
zaitsev silverberg cousteau
zaitsev petersen shamgshamg
clipper petersen shamgshamg
clipper bakirelli vasiliadi
silverberg atn dolly
knuth dijkstra bellman
```

Вывод:

```
4
```

## Решение

Две команды конфликтуют, если множества участников пересекаются.
Для команды `i` храним маску конфликтующих команд `clash[i]`, включая
её саму. В оставшемся множестве `S` возьмём младшую команду `i`.
Любой допустимый набор либо не включает её, либо включает и исключает
всех её соперников по участникам:

`best(S) = max(best(S без i), 1 + best(S без clash[i]))`.

Два варианта покрывают все возможности, ответ для пустого множества —
ноль. Обе новые маски численно меньше, потому что сбрасывают бит `i`;
нативные базы заполняют таблицу по возрастанию маски. Python вычисляет
ту же рекуррентность лениво через `lru_cache`, посещая не обязательно
все маски. При ограниченной длине имён время — `O(2^K + K²)`, память
таблицы или кэша — до `O(2^K)`. Все пять исходных Accepted-баз сохранены
побайтово. Общие имена в разных столбцах тоже создают конфликт;
одинаковую команду из двух строк нельзя выбрать дважды.

## Оптимизированные решения

**C++, Go, Java, Rust.** Новый алгоритм обходит дерево включения/исключения без хранения
ответа для каждой маски. Состояние — оставшаяся маска и число уже выбранных
команд; в маске только команды, совместимые с выбранными. Храним лучший
найденный допустимый ответ. `selected + popcount(mask)` — верхняя граница
даже при конфликтах внутри остатка; если она не улучшает ответ, ветвь
можно безопасно отсечь.

Иначе выбираем оставшуюся команду с наибольшим числом конфликтов в маске,
включая её саму. Если максимум не больше единицы, конфликтующих пар нет:
можно взять весь остаток и достичь верхней границы. Иначе сначала
включаем выбранную команду с удалением всей её маски конфликтов, затем
исключаем только её. Эти ветви разбивают все допустимые продолжения.
Первое включение может улучшить ответ до ветви исключения; максимальная
степень — эвристика, а не условие корректности. В каждой ветви уходит
хотя бы одна команда, поэтому глубина не больше `K ≤ 18`.

Худшее время — `O(K 2^K + K²)`: выбор очередной команды просматривает
до `K` битов в каждом узле. Рабочая память поиска — `O(K)` на маски
и рекурсию, помимо входных имён; экспоненциальной таблицы нет. Маски
помещаются в 32 бита. Поисковый алгоритм меняется, поэтому имена —
`backtracking_bitmask`, без дублирующего суффикса `_optimized`.
Все четыре опубликованные версии проходят по памяти. У Java записано
большее время, 0,125 с против 0,109 с, но памяти меньше на 83,3%.
Один тик сам по себе не является надёжным подтверждением изменения CPU.

**Python/PyPy.** Сохраняем понятный алгоритм независимого множества с мемоизацией полных масок. Новый вариант делит не более 18 команд на половины по 9. Для каждого подмножества левой половины считаем оптимум: пропустить младшую команду либо взять её и удалить конфликты. Справа рекурсивно пропускаем или берём команду, удаляя её конфликты справа и несовместимые команды слева. В листе оптимум для разрешённой левой маски берётся из таблицы. Каждому совместимому набору соответствует одна правая ветвь и оптимальное допустимое левое подмножество — отсюда корректность. Имена сравниваются точно, вероятностного хеширования нет. Время O(K²+2^ceil(K/2)), память O(2^floor(K/2)+K).

- `1208_backtracking_bitmask.cpp`: 0.015 s / 176 KB; база `1208_bitmask.cpp`: 0.015 s / 976 KB; изменение относительно базы: время -0.0%, память -82.0%.
- `1208_backtracking_bitmask.go`: 0.031 s / 1104 KB; база `1208_bitmask.go`: 0.062 s / 3204 KB; изменение относительно базы: время -50.0%, память -65.5%.
- `1208_backtracking_bitmask.java`: 0.125 s / 448 KB; база `1208_bitmask.java`: 0.109 s / 2688 KB; изменение относительно базы: время +14.7%, память -83.3%.
- `1208_backtracking_bitmask.rs`: 0.015 s / 224 KB; база `1208_bitmask.rs`: 0.046 s / 684 KB; изменение относительно базы: время -67.4%, память -67.3%.
- `1208_bitmask_dp.py`: 0.125 s / 296 KB; база `1208_bitmask.py`: 0.078 s / 456 KB; изменение относительно базы: время +60.3%, память -35.1%.

## Особенности языков

Сохранённые срезы: 1–2 ноября 2026 года. Цель C++ — топ 15% либо первые 10 мест одновременно по времени и памяти; других семейств — первое место по обеим метрикам. Ничьи делят место. Пустые выборки дают только формальное покрытие.

Используется сохранённый профиль текущих компиляторов; исключены собственный автор и старые строки со временем меньше 0,015 с. Для семейств кроме C++ дополнительно требуется ID посылки ≥10770000; память C++ сравнивается по первым 1000 подходящим строкам. Собственные времена меньше 0,015 с считаются 0,015 с. Порог ID — фиксированное правило сравнения, а не точный календарный фильтр.
