# 1208. Больше всего легендарных команд без общих участников

[Timus 1208](https://acm.timus.ru/problem.aspx?space=1&num=1208) · сложность 214 · bitmask

Автор оригинальной задачи — Леонид Волков; командное соревнование УрГУ, март 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `K ≤ 18` легендарных команд по три программиста, и некоторые
программисты были в нескольких из них. Программист может играть только за
одну команду, поэтому нужно найти наибольшее число команд, которые могут
участвовать вместе, то есть без программиста, входящего в две из них.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`K`, затем три имени каждой команды, до 20 строчных букв.

## Выходные данные

Наибольшее число команд, которые могут участвовать.

## Примеры

### Пример 1

Ввод:

```
7
gerostratos scorpio shamgshamg
zaitsev silverberg cousteau
zaitsev petersen shamgshamg
clipper petersen shamgshamg
clipper bakirelli vasiliadi
silverberg atn dolly
knuth dijkstra bellman
```

Вывод:

```
4
```

## Решение

Две команды конфликтуют, если у них общий участник, а ответ — наибольшее
множество команд без конфликтов между ними. Для каждой команды храним
битовую маску команд, с которыми она конфликтует, включая её саму. Для
множества команд, заданного маской, смотрим на его младшую команду: либо
она не играет, и остаётся множество без неё, либо играет, и остаётся
множество без неё и без всех команд, с которыми она конфликтует. Поэтому

`best(S) = max(best(S без i), 1 + best(S минус clash(i)))`, где `i` —
младшая команда в `S`.

Оба меньших множества — меньшие числа, так что таблицу можно заполнить
для всех `2^K` масок по возрастанию. `O(2^K + K²)`.

Тонкие места:

- команда конфликтует сама с собой, что убирает её, когда её берут;
- один программист может быть во многих командах, так что конфликты не
  только между соседями по списку.

Ответы сверены с отдельно написанным решением на 200 случайных входах и
на командах из пулов от 3 до 1000 программистов.

## Особенности языков

- Python вычисляет ту же рекурсию лениво через `functools.lru_cache`,
  посещая только реально возникающие множества; остальные языки
  заполняют всю таблицу.
