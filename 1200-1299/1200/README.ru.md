# 1200. Сколько делать рогов и копыт

[Timus 1200](https://acm.timus.ru/problem.aspx?space=1&num=1200) · сложность 257 · math

Автор оригинальной задачи — Магаз Асанов; командное соревнование УрГУ, март 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый рог приносит `A` рублей, каждое копыто — `B` рублей,
`-10000 ≤ A, B ≤ 10000` с двумя знаками после точки. Продать можно не
больше `K ≤ 10000` изделий всего, а рэкетиры берут квадрат количества
изделий каждого вида. Выбрать `x` рогов и `y` копыт с `x + y ≤ K`, чтобы
максимизировать `A·x + B·y − x² − y²`; среди лучших планов взять тот, где
меньше рогов, затем меньше копыт.

Ограничение времени: 0.25 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`A` и `B`, затем `K`.

## Выходные данные

Наибольшая прибыль с двумя знаками после точки, затем `x` и `y`.

## Примеры

### Пример 1

Ввод:

```
34.20 61.70
45
```

Вывод:

```
1239.50
16 29
```

## Решение

Переведём две цены в целые копейки `a,b`. Прибыль равна
`P(x,y)=a·x+b·y−100(x²+y²)`, где `x,y≥0` целые, `x+y≤K`.
Можно ничего не выпускать, поэтому оптимум неотрицателен.

Простой алгоритм перебирает рога `x=0..K`. При фиксированном `x`
прибыль от копыт — вогнутая парабола с вершиной `b/200`, ограниченная
отрезком `0≤y≤K−x`. Проверяем два соседних целых у вершины после
ограничения этим отрезком; при отрицательной вершине лучше ноль.
Перебраны все допустимые `x` и лучший `y` для каждого, значит найден
глобальный оптимум. Идём по `x` и двум вариантам `y` по возрастанию,
обновляем ответ только при строго большей прибыли: равенство оставляет
меньше рогов, затем меньше копыт. Все пять принятых простых версий
соблюдают это правило. Время `O(K)`, постоянное число рабочих переменных
плюс ограниченный ввод и вывод.

Оценки прибыли считаются в целых копейках, без сравнения вещественных
результатов. Базы округляют считанную цену с двумя десятичными знаками
после умножения на 100. При `|A|,|B|≤10000` ошибка двоичного представления
намного меньше половины копейки, поэтому начальный перевод безопасен.
Дальше арифметика целая. При `K≤10000` абсолютные промежуточные выражения
не превосходят `2·10¹⁰`, а максимальная прибыль — `5·10⁹` копеек;
машинным языкам нужны знаковые 64-битные оценки, а не 32-битные.

## Оптимизированные решения

Прибыль — разделимая вогнутая квадратичная функция на целочисленном треугольнике. Внутренний оптимум округляет две независимые вершины; если эти варианты нарушают мощность, оптимум лежит на границе. Подстановка равенства мощности даёт вогнутую функцию одной переменной: достаточно соседних целых у вершины и концов отрезка. Java явно проверяет этот постоянный набор, Python сразу выполняет эквивалентную проекцию с правилом равенства. Оценки считаются в точных целых копейках; при равенстве выбираются меньшие рога, затем копыта. Линейный перебор заменён другим геометрическим алгоритмом постоянного размера.

- `1200_math_geometry.java`: 0.109 s / 868 KB; база `1200_math.java`: 0.140 s / 2096 KB; изменение относительно базы: время -22.1%, память -58.6%.
- `1200_math_geometry.py`: 0.125 s / 284 KB; база `1200_math.py`: 0.093 s / 488 KB; изменение относительно базы: время +34.4%, память -41.8%.

## Проверка

Сравниваем прибыль в точных копейках и оба количества; правило
равенства обязательно. Фактический Java-кандидат прошёл 13 входов
репозитория в Docker и получил Accepted точных байтов. Python-реализация
метода постоянного набора точек независимо сверена полным перебором
на 8400 малых допустимых треугольниках и 400 дополнительных случаях
нулевой мощности вне входного ограничения `K≥1`. Всего 8800 запусков
Python, а не 8800 запусков Java. Важны отрицательные цены, нулевой выпуск,
неиспользованная мощность, активная диагональ и полуцелые вершины,
дающие одинаковые прибыли.
