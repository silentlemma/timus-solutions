# 1252. Сортировка камней перестановками через K

[Timus 1252](https://acm.timus.ru/problem.aspx?space=1&num=1252) · сложность 397 · number_theory

Автор оригинальной задачи — Алексей Лахтин; открытое командное первенство УрГУ, 15 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N камней (1 ≤ N ≤ 130 000) разного веса стоят в ряд. Два камня можно
поменять местами, если между ними ровно K других камней. Найти
наибольшее K (0 ≤ K < N), при котором ряд можно отсортировать по весу —
по возрастанию или по убыванию.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N весов по одному в строке. Каждый вес — целое число от 1 до
130 000 включительно.

## Выходные данные

Наибольшее такое K.

## Примеры

### Пример 1

Ввод:

```
5
30
21
56
40
17
```

Вывод:

```
1
```

## Решение

Перестановка с K камнями между ними сдвигает оба камня на d = K + 1
мест, так что камень остаётся в своём классе позиций по модулю d, а
внутри класса любой порядок получается перестановками соседей по классу.
Поэтому отсортировать можно ровно тогда, когда d делит расстояние каждого
камня от его места до места в отсортированном ряду.

Значит, для возрастающего и для убывающего порядка найдём НОД g этих
расстояний. Наибольшее d, делящее g, — само g, и оно меньше N, так что
K = g − 1; если ряд уже стоит в этом порядке, g = 0 и годится любое K,
так что K = N − 1. Ответ — большее из двух. `O(N log N)` на сортировку.

Тонкие места:

- убывающий порядок тоже считается (тест 04), и два порядка могут дать
  разные K;
- отсортированный ряд допускает наибольшее K = N − 1, хотя тогда
  никакая перестановка вообще невозможна (тесты 03 и gen4).

Правило сравнивалось с перебором всех достижимых порядков для каждого K
на 300 случайных рядах до 7 камней.

## Оптимизированные решения

C++, Java и Rust используют таблицу с индексом по весу. Веса различны, поэтому каждая ячейка хранит исходную позицию камня или ноль. Проход по занятым ячейкам в порядке веса даёт ранг r по возрастанию и N + 1 − r по убыванию. Оба НОД обновляются за один проход. W — размер таблицы весов.

Принятые базовые реализации [1252_number_theory.go](1252_number_theory.go), [1252_number_theory.py](1252_number_theory.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
