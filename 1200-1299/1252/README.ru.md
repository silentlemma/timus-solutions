# 1252. Сортировка камней перестановками через K

[Timus 1252](https://acm.timus.ru/problem.aspx?space=1&num=1252) · сложность 397 · number_theory

Автор оригинальной задачи — Алексей Лахтин; открытое командное первенство УрГУ, 15 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N камней (1 ≤ N ≤ 130 000) разного веса стоят в ряд. Два камня можно
поменять местами, если между ними ровно K других камней. Найти
наибольшее K (0 ≤ K < N), при котором ряд можно отсортировать по весу —
по возрастанию или по убыванию.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N весов по одному в строке. Каждый вес — целое число от 1 до
130 000 включительно.

## Выходные данные

Наибольшее такое K.

## Проверка

В `tests/tests.json` задан точный `tokens`: один десятичный K из 0..N−1. Окружающие пробелы/переводы строк не важны; лишние токены или иное написание числа отклоняются. Разрешены возрастание и убывание; уже отсортированный ряд допускает N−1 даже без возможных перестановок такой дальности.

## Примеры

### Пример 1

Ввод:

```
6
40
50
60
10
20
30
```

Вывод:

```
2
```

## Решение

Перестановка с K камнями между ними сдвигает оба камня на d = K + 1
мест, так что камень остаётся в своём классе позиций по модулю d, а
внутри класса любой порядок получается перестановками соседей по классу.
Поэтому отсортировать можно ровно тогда, когда d делит расстояние каждого
камня от его места до места в отсортированном ряду.

Значит, для возрастающего и для убывающего порядка найдём НОД g этих
расстояний. Наибольшее d, делящее g, — само g, и оно меньше N, так что
K = g − 1; если ряд уже стоит в этом порядке, g = 0 и годится любое K,
так что K = N − 1. Ответ — большее из двух. `O(N log N)` на сортировку.

Тонкие места:

- убывающий порядок тоже считается (тест 04), и два порядка могут дать
  разные K;
- отсортированный ряд допускает наибольшее K = N − 1, хотя тогда
  никакая перестановка вообще невозможна (тесты 03 и gen4).

Правило сравнивалось с перебором всех достижимых порядков для каждого K
на 300 случайных рядах до 7 камней.

Простые C++/Go хранят веса и отсортированные исходные индексы, Java один упакованный long[N]; O(N) памяти массивов вместе с возможным рабочим местом сортировки. Python дополнительно хранит весь ввод, целые/срезы и индексы, Rust ввод и векторы чисел/индексов: O(I+N). Быстрые нативные версии имеют полную таблицу 130001 позиций, O(W) при W=130000, независимо от меньшего занятого диапазона, без второго массива камней. Буферы ввода: 16384 байта C++, 4096 Java, ограниченный заблокированный stdin Rust. Общая работа НОД до O(N log N), инициализация/сканирование таблицы добавляет O(W), чтение O(I).

## Оптимизированные решения

Три быстрые нативные версии заменяют сортировку нулевой таблицей вес→исходная позиция благодаря различным ограниченным весам. Запоминают минимальный/максимальный вес и сканируют этот интервал, пропуская нули; ранг даёт позиции обоих порядков. C++/Rust прекращают работу, когда оба НОД равны 1: НОД 1 остаётся 1 при новых значениях, поэтому d>1 невозможен в обоих порядках и ответ K=0 окончателен. Java проходит весь интервал. C++ использует собственный fread-парсер, Java 4096 байт, Rust заблокированный байтовый ввод. Консервативное время O(I+W+N log N), память O(W+B) при ограниченном вводе B.

Кэш точных исходников подтверждает базу Go 4012 КБ по применимому редкому эталону точного компилятора и обеим метрикам, не по обычному топ 10/топ 15%. Python 13612 КБ проходит обе обычные таблицы. Базы Java 1596 КБ и Rust 3652 КБ проходят обе; быстрые Java 972 КБ, C++ 604 КБ и Rust 712 КБ требуют только время при памяти меньше 1024 КБ. Простая C++ остаётся учебной, хотя обязательные метрики не проходит. Общие [критерии](../../RATING_CRITERIA.md) без отдельных первого места или улучшения 30%. Новые комментарии быстрых C++/Rust требуют Accepted точных байтов, исторические числовые замеры не подменяют его.

В `1252_sorting.cpp` (историческая#11310440,0.015 с/604 КБ) и `1252_sorting.rs` (историческая#11310439,0.015 с/712 КБ) добавлены только объяснения раннего выхода. Простые версии и неизменённая быстрая Java доступны.
