# 1293. Эния

[Timus 1293](https://acm.timus.ru/problem.aspx?space=1&num=1293) · сложность 14 · math

Автор оригинальной задачи — Ден Расковалов; IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N прямоугольных панелей размером A на B метров нужно обработать с
обеих сторон, а на один квадратный метр уходит один нанограмм состава
(1 ≤ N, A, B ≤ 100). Сколько нанограммов нужно?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, A и B в одной строке.

## Выходные данные

Число нанограммов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
5 2 3
```

Вывод:

```
60
```

## Решение

У каждой панели две стороны по A · B квадратных метров, поэтому ответ
равен 2 · N · A · B. `O(1)`.

Тонкие места:

- считаются обе стороны: без множителя 2 на примере получится 30
  вместо 60 (тест 01);
- наибольший ответ — 2 000 000, он с запасом помещается в 32 бита
  (тест 03).

## Оптимизированные решения

`1293_math_optimized.go`. Сохраняется площадь двух сторон панелей2*N*A*B. Все три входных значения не больше100, результат не больше2000000, вещественное преобразование не нужно. Три числа читаются напрямую вместо форматированных сканеров или декодированного ввода и вектора значений в Rust. Время и состояние ограниченной арифметики O(1), учебные формулы сохранены без изменений. Переносимые os.Stdin.Read/os.Stdout.Write и прямое преобразование целых используют фиксированные буферы ввода и вывода по 4096 байт. Частичная запись обрабатывается до повторного использования буфера. Исходный простой вариант с Accepted сохранён.

По сравнению с `1293_math.go`: время 0.031 s → 0.031 s; память 1152 KB → 796 KB.

Три числа читаются напрямую вместо форматированных сканеров или декодированного ввода и вектора значений в Rust. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

Оптимизированное решение на Java разбирает три числа побайтно из
`System.in` вместо `Scanner`: 312 КБ вместо 1596 КБ при том же времени.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1293_math_optimized.go`: место по времени 22/32, по памяти 1/32 в этой сопоставимой выборке.

`1293_math_optimized.py`: место по времени 935/1017, по памяти 3/1017 в этой сопоставимой выборке.

`1293_math_optimized.rs`: место по времени 1/12, по памяти 1/12 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
