# 1244. Каких карт не хватает в колоде, по её весу

[Timus 1244](https://acm.timus.ru/problem.aspx?space=1&num=1244) · сложность 254 · dp

Автор оригинальной задачи — Александр Петров; личное первенство УрГУ, 1 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Полная колода состоит из `N` пронумерованных карт, `2 ≤ N ≤ 100`,
с целыми весами `1 ≤ w_i ≤ 1000` миллиграммов. Обозначим их сумму через
`T`. Оставшиеся карты весят целое `W`, `0 < W < T`. Нужно найти номера
отсутствующих карт: вывести их по возрастанию, если множество единственно,
`-1`, если вариантов несколько, и `0`, если решений нет. Карты одного
веса различаются номерами. Лимит времени: 0,5 секунды. Память: 64 МБ.

## Входные данные

W, затем N, затем N весов карт.

## Выходные данные

Недостающие карты, -1 или 0.

## Проверка

Целые числа сравниваются как разделённые пробелами или переводами строк токены. Для единственного ответа номера отсутствующих карт идут по возрастанию; иначе выводится один токен `0` или `-1`.

## Примеры

### Пример 1

Ввод:

```
270
4
100
110
170
200
```

Вывод:

```
2 4
```

### Пример 2

Ввод:

```
270
4
100
110
160
170
```

Вывод:

```
-1
```

### Пример 3

Ввод:

```
270
4
100
120
160
180
```

Вывод:

```
0
```

## Решение

Оставшиеся в колоде карты образуют набор общего веса W, а недостающие —
всё остальное. Поэтому посчитаем наборы карт веса W, но только до 2,
потому что важно лишь это: `ways[i][s]` — число наборов из первых i
карт веса s, ограниченное двойкой, и
`ways[i][s] = min(2, ways[i−1][s] + ways[i−1][s − w_i])`. Тогда
`ways[N][W]` равно 0, 2 (вывести -1) или ровно 1.

Для единственного набора пойдём назад от последней карты с s = W: карта
i отсутствует ровно тогда, когда первые i − 1 карт уже сами дают s,
`ways[i−1][s] = 1`; иначе она в колоде, и s уменьшается на её вес.
Единственность означает, что выполняется только одно из двух.
`O(N·W)` при W < 100 000.

Тонкие места:

- одинаковые карты — разные карты: при двух картах веса 1 и W = 1
  недоставать может любая, так что ответ -1 (тест 04);
- недоставать может несколько карт, вплоть до всех, кроме одной
  (тест 08).

Ответы сравнивались с перебором всех подмножеств на 1500 случайных
маленьких колодах.

## Оптимизированные решения

Дополнение множества задаёт биекцию между оставшимися картами веса
`W` и отсутствующими веса `T−W`. Будем считать подмножества для
`S = min(W,T−W)`, а при необходимости дополним выбранные номера до всей
колоды. Отсутствие решения, единственность и неоднозначность сохраняются;
при этом `S ≤ 50000`.

Четыре нативные версии обновляют одну строку насыщенных счётчиков по
убыванию суммы. При первом достижении суммы запоминается номер её
последней карты; этот предок больше не меняется. Предыдущая сумма была
достижима до обработки данной карты. Благодаря убывающему обходу и
положительным весам номера карт вдоль цепочки строго убывают, карта не
повторяется. Если итоговое множество единственно, эта цепочка его и даёт.
Счётчики принимают только `0,1,2`, номера предков не больше 100.
Время — `O(N·S)`, память — `O(S+N)`.

Python сохраняет битсет достижимости для каждого префикса, но битсет сумм
с хотя бы двумя представлениями хранит лишь для текущего шага. Старую
неоднозначность переносим с новой картой и без неё; пересечение старой
достижимости с её сдвигом также означает два разных множества. Единственный
ответ восстанавливается по префиксам достижимости. Обнаружив два способа
набрать `S`, можно сразу вывести `-1`: последующие карты разрешено не брать,
поэтому оба свидетельства сохранятся.

Пусть `C` — максимальный вес карты, `w` — число битов в разряде большого
целого, `B = ceil((S+C+1)/w)`, `B_W = ceil((W+C+1)/w)`. Консервативная
оценка времени и памяти оптимизированного Python — `O(N·B)` машинных слов;
в простой версии префиксные битсеты соответствуют `B_W`. Слагаемое `C`
учитывает временный сдвиг до маскирования. Все простые исходники сохранены
без изменений.

Измеренное сокращение памяти относительно неизменённых принятых простых исходников: C++ — 98.1%, Go — 90.3%, Java — 95.6%, Python — 80.2%, Rust — 97.7%. Все пять проходят порог по памяти. Разница времени в один тик не считается надёжным ускорением. Рейтинговый срез — 2 ноября 2026 года; отмеченные звёздочкой версии можно оптимизировать дальше.
