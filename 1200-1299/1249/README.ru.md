# 1249. Все ли тёмные области — прямоугольники?

[Timus 1249](https://acm.timus.ru/problem.aspx?space=1&num=1249) · сложность 221 · implementation

Авторы оригинальной задачи — Никита Шамгунов и Леонид Волков; открытое командное первенство УрГУ, 15 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано бинарное изображение `N × M`, не более 3000 строк и 3000 столбцов. Определите, является ли каждая компонента единиц, связанных по стороне, заполненным прямоугольником со сторонами вдоль осей. Касание только углом связности не создаёт. Лимит времени: 2,5 секунды. Память: 4 МБ.

## Входные данные

`N M`, затем `N` строк по `M` нулей и единиц, разделённых пробелами.

## Выходные данные

Выведите `Yes`, если каждая компонента — заполненный прямоугольник, иначе `No`.

## Проверка

Сравнение по токенам: `Yes` или `No` с указанным регистром. Форматирование пробелов несущественно.

## Примеры

### Пример 1

Ввод:

```
2 2
0 1
1 1
```

Вывод:

```
No
```

### Пример 2

Ввод:

```
3 3
0 0 1
1 1 0
1 1 0
```

Вывод:

```
Yes
```

## Решение

В окне 2 × 2 с ровно тремя тёмными клетками все три принадлежат одной
компоненте, которая не может быть заполненным прямоугольником. Обратно,
у границы связной по сторонам компоненты, не заполняющей прямоугольник,
есть внутренний угол, в том числе вокруг отверстия. Он даёт такое окно
с тремя тёмными клетками. Достаточно запрещать именно эти окна.

Храним только соседние строки и проверяем окно при поступлении его
последней клетки. Простые нативные версии явно проверяют четыре клетки;
простая Python-версия представляет строки целыми числами и проверяет
нечётность вместе с наличием хотя бы двух единиц. Ввод занимает `O(N M)`
времени, строки — `O(M)` памяти. Всё изображение или текст входа хранить
нельзя из-за лимита памяти. Компоненты, касающиеся углами, остаются разными.
Все пять исходных Accepted-версий сохранены побайтово.

## Оптимизированные решения

Для соседних строк `B = previous AND current` отмечает полностью тёмные
вертикальные столбцы, а `S = previous XOR current` — столбцы с одной
единицей. Запрещённое окно — полный столбец рядом с одиночным, поэтому
`(B AND (S >> 1)) OR (S AND (B >> 1))` проверяет оба порядка.

Python так факторизует прежнее выражение из четырёх клеток и удаляет
пробельные символы строки одной трансляцией. C++ упаковывает столбцы
в 64-битные слова, использует ограниченный буфер ввода, проверяет слово
параллельно и отдельно проверяет пару на границе слов. Хранятся предыдущая
упакованная строка и текущее слово. Логическая проверка строки в C++
занимает `O(ceil(M/64))`, чтение всего входа остаётся `O(N M)`, а строки
занимают `O(M/64)` слов. Python хранит `O(M)` бит и текущую строку входа.

C++: 0,531 с / 208 КБ → 0,078 с / 128 КБ, выигрыш 85,3% по времени
и 38,5% по памяти. Python: 0,218 с / 1532 КБ → 0,125 с / 3684 КБ,
выигрыш 42,7% по времени, но измеренный пик памяти вырос. Python проходит
критерий только по времени; у обеих версий есть собственный Accepted.
Эти замеры не означают улучшения каждого ресурса.

## Особенности языков

Python-кандидат проверен на 75 254 малых изображениях независимым
обходом компонент с проверкой ограничивающего прямоугольника, включая
все бинарные изображения с каждой стороной не более четырёх. Обе реальные
программы прошли 14 тестовых входов репозитория в Docker, в том числе
3000 × 3000. Дополнительно проверены все четыре положения отсутствующего
угла и диагональные касания на границах машинных слов в C++ и Python.

Рейтинговый срез — 2 ноября 2026 года. C++ достиг цели: место 5 по времени
и 1 по памяти среди 61 отфильтрованной посылки других авторов. У Python
места 1 и 2 против одной посылки, поэтому остаётся звёздочка. Исходная Java
первая по обеим метрикам против четырёх посылок. Сравнительные выборки Go
и Rust пусты: формальное покрытие не доказывает конкурентного превосходства.
