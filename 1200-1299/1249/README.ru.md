# 1249. Все ли тёмные области — прямоугольники?

[Timus 1249](https://acm.timus.ru/problem.aspx?space=1&num=1249) · сложность 221 · implementation

Авторы оригинальной задачи — Никита Шамгунов и Леонид Волков; открытое командное первенство УрГУ, 15 марта 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано бинарное изображение `N × M`, не более 3000 строк и 3000 столбцов. Определите, является ли каждая компонента единиц, связанных по стороне, заполненным прямоугольником со сторонами вдоль осей. Касание только углом связности не создаёт. Лимит времени: 2,5 секунды. Память: 4 МБ.

## Входные данные

`N M`, затем `N` строк по `M` нулей и единиц, разделённых пробелами.

## Выходные данные

Выведите `Yes`, если каждая компонента — заполненный прямоугольник, иначе `No`.

## Проверка

Сравнение по токенам: `Yes` или `No` с указанным регистром. Форматирование пробелов несущественно.

## Примеры

### Пример 1

Ввод:

```
2 3
1 1 1
1 0 1
```

Вывод:

```
No
```

### Пример 2

Ввод:

```
3 4
1 1 0 1
1 1 0 1
0 0 0 1
```

Вывод:

```
Yes
```

## Решение

В окне 2 × 2 с ровно тремя тёмными клетками все три принадлежат одной
компоненте, которая не может быть заполненным прямоугольником. Обратно,
у границы связной по сторонам компоненты, не заполняющей прямоугольник,
есть внутренний угол, в том числе вокруг отверстия. Он даёт такое окно
с тремя тёмными клетками. Достаточно запрещать именно эти окна.

Храним соседние строки и проверяем каждое окно 2×2 при чтении последней клетки. Нативные простые версии явно проверяют клетки, Python представляет строку целой битовой маской. Чтение O(NM), состояние O(M) элементов либо O(M) бит Python плюс текущая строка. Максимальное 3000×3000 изображение по байту на пиксель требует 9000000 байт, больше 4 МиБ. Малые изображения помещаются; даже максимальная упакованная битовая карта может поместиться. Поэтому невозможность хранения всей картинки не безусловна: потоковый ввод устраняет худший расход неупакованного представления. Контакт углами не соединяет компоненты.

В пяти файлах ниже изменён только неточный комментарий о памяти; исполняемый код и содержательные пояснения сохранены. Строки таблиц сохраняют исторические пары Accepted.

`1249_implementation.cpp` (#11283966); `1249_implementation.go` (#11283967); `1249_implementation.java` (#11283977); `1249_implementation.rs` (#11283979); `1249_implementation_parsing_optimized.go` (#11329324).

## Оптимизированные решения

`1249_implementation_optimized.rs`. Сохраняется запрет окна 2×2 с суммой три. Две строки заменены одной байтовой строкой и сохранёнными левой/верхней левой клетками; столбец обновляется после проверки окна. Ранний No и итоговый Yes прежние. Время O(NM), память O(M).

По сравнению с `1249_implementation.rs`: время 0.031 s → 0.625 s; память 224 KB → 68 KB.

Для соседних строк `B = previous AND current` отмечает полностью тёмные
вертикальные столбцы, а `S = previous XOR current` — столбцы с одной
единицей. Запрещённое окно — полный столбец рядом с одиночным, поэтому
`(B AND (S >> 1)) OR (S AND (B >> 1))` проверяет оба порядка.

Python так факторизует прежнее выражение из четырёх клеток и удаляет
пробельные символы строки одной трансляцией. C++ упаковывает столбцы
в 64-битные слова, использует ограниченный буфер ввода, проверяет слово
параллельно и отдельно проверяет пару на границе слов. Хранятся предыдущая
упакованная строка и текущее слово. Логическая проверка строки в C++
занимает `O(ceil(M/64))`, чтение всего входа остаётся `O(N M)`, а строки
занимают `O(M/64)` слов. Python хранит `O(M)` бит и текущую строку входа.

Сохранены пары: C++ 0.531 с/208 КБ→0.078 с/128 КБ (время ниже 85.3%, память 38.5%); Python 0.218 с/1532 КБ→0.125 с/3684 КБ (время ниже 42.7%, память выше). Быстрая Python не допускается только по времени: 3684 КБ≥1024, память обязательна. Точный эталон допускает 2060.8 КБ, поэтому память не проходит даже при проходящем времени; звёздочка остаётся. Неизменённая простая Python 1532 КБ проходит обе метрики и закрывает язык. Отдельного допуска по ускорению нет.

`1249_implementation_parsing_optimized.go` разбирает размеры целыми и прямо декодирует блоки ввода в текущую строку, затем сравнивает окна с предыдущей. Буфер 8192 байта, пополнение/EOF учтены, убран вызов байтового помощника на пиксель. fastPrint поддерживает только строки и пишет фиксированные Yes/No с переводом через переиспользуемый буфер. Числового преобразования вывода нет; числовые функции относятся к вводу. Геометрия сохранена.

Следующая пара Accepted Go относится к исходнику до правки комментария. Пара замеров, простые и отдельные версии сохранены.

Accepted #11329324 (Go 1.14 x64): **0.031 s / 820 KB**.

## Особенности языков

Python-кандидат проверен на 75 254 малых изображениях независимым
обходом компонент с проверкой ограничивающего прямоугольника, включая
все бинарные изображения с каждой стороной не более четырёх. Обе реальные
программы прошли 14 тестовых входов репозитория в Docker, в том числе
3000 × 3000. Дополнительно проверены все четыре положения отсутствующего
угла и диагональные касания на границах машинных слов в C++ и Python.

Старые места фильтрованного среза 2 ноября заменены текущим кэшем и общими [критериями](../../RATING_CRITERIA.md): быстрая C++ и простая Java проходят только время; Go-парсер исторически проходит время по второму из двух соперников точного компилятора, простая Go не проходит время. Обе Rust проходят по выборке всего языка, не из пустой таблицы. Простая C++ остаётся учебной. Числовой допуск исторического хеша не заменяет новый Accepted изменённых байтов.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
