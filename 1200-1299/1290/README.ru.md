# 1290. Саботаж

[Timus 1290](https://acm.timus.ru/problem.aspx?space=1&num=1290) · сложность 80 · sorting

Оригинальная задача — фольклор (подготовил Ден Расковалов); IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Медленная функция получает N ≤ 25 000 целых положительных чисел, каждое
не больше 25 000. Она печатает, сколько из них не меньше 1, затем
сколько больше 1, больше 2 и так далее, останавливаясь перед первым 0.
Напечатанные числа снова читаются как массив, и тот же шаг выполняется
ещё раз; второй список и есть результат. Нужно получить его быстро.

Для 4 1 6 первый список — 3 2 2 2 1 1, второй — 6 4 1.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N чисел, по одному в строке. N может быть равно 0.

## Выходные данные

Числа результата, по одному в строке.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
3
4
1
6
```

Вывод:

```
6
4
1
```

## Решение

Представим числа рядами клеток: число p — ряд из p клеток, все ряды
выровнены по левому краю. j-е напечатанное число считает ряды,
доходящие до столбца j, то есть первый список — длины столбцов:
картинка, повёрнутая набок (сопряжённое разбиение). Второй поворот
возвращает ряды, от самого длинного к самому короткому.

Значит, функция просто сортирует массив по убыванию. Значения не больше
25 000, поэтому хватает сортировки подсчётом: посчитать каждое значение
и вывести значения от 25 000 до 1, каждое столько раз, сколько оно
встретилось. `O(N + 25 000)`.

Тонкие места:

- при N = 0 вывод пустой (тест 02);
- равные числа возвращаются все (тесты 04 и 06).

Равносильность проверялась прямой симуляцией двух шагов на 200
случайных массивах.

## Оптимизированные решения

Оптимизированные решения (C++, Python) хранят те же счётчики, но
16-битными числами, поскольку значение встречается не больше 25 000 раз,
и форматируют строку каждого значения один раз, а затем повторяют её
столько раз, сколько встречается значение. C++ разбирает числа вручную
из блоков по 8 КБ вместо `scanf`; Python читает блоки по 4 КБ через
генератор, а не разбивает весь ввод, и хранит счётчики в `array("H")`.
C++: 156 КБ вместо 280 КБ при том же времени; Python: 0.078 с вместо
0.109 с и 880 КБ вместо 4732 КБ.

`1290_sorting_optimized.rs`. Сортировка подсчётом сохранена, но используется фиксированный массив M+1 счётчиков u16 при M=25000 вместо счётчиков usize и сохранённой входной String. Частота не больше N<=25000, поэтому u16 достаточно. Все M значений просматриваются по убыванию и выводятся с нужной кратностью; при N=0 вывод пустой. Время O(N+M), явная память счётчиков 50002 байта плюс постоянное состояние. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1290_sorting.rs`: время 0.015 s → 0.015 s; память 724 KB → 100 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1290_sorting_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
