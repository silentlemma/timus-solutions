# 1292. 火星太空基地

[Timus 1292](https://acm.timus.ru/problem.aspx?space=1&num=1292) · 难度 380 · math

原题作者 Denis Musin，出自 2004 年 3 月 13 日第九届中学生公开团体程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

设 F(x) 为 x 的各位十进制数字的立方和，例如 F(12) = 9。太空基地沿一条航线分布：第一个基地距
航线端点 K，若基地 i 之前的间隔为 x，则它之后的间隔为 F(x)。密钥 K 是 3 的倍数。

飞船位于基地 N − 1 和 N 之间，距基地 N − 1 为 L。对 2 ≤ T ≤ 33 333 个询问（2 ≤ N ≤ 33 333，
3 ≤ K ≤ 33 333），输出飞船到基地 N 的距离。

时间限制：1 秒。内存限制：64 MB。

## 输入

T，然后 T 行，每行 N、K、L，其中 `L ≥ 1`。飞船位于所给两基地之间，L 是它在该间隔内的偏移。

## 输出

T 行距离。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
2
3 12 100
16 12558 152
```

输出：

```
629
1
```

## 解法

把航线端点看作基地 0，基地 N 之前的间隔就是对 K 施加 N − 1 次 F，答案为这个间隔减去 L。自编样例
可以验证：12 → 9 → 729，729 − 100 = 629。

每个询问最多施加 33 332 次 F，对 33 333 个询问来说太慢，但这条链几乎立刻就稳定下来。因为
d³ ≡ d (mod 3)，F 保持数字和模 3 的余数，所以 3 的倍数仍是 3 的倍数。F(153) = 1 + 125 + 27
= 153，逐一检查 33 333 以内所有 3 的倍数可知，每个数最多 14 步就到达 153（最慢的是 12 558）。
因此不断施加 F，直到做完 N − 1 步或值变成 153。`O(T · 14 · 位数)`。

注意事项：

- 基地 N 之前的间隔需要 N − 1 步而不是 N − 2 步：第一个基地已经距端点 K（测试 01）；
- 链可能恰好在到达 153 之前截止（测试 03）；
- 间隔可能远大于 K，例如 F(99) = 1458（测试 05）。

以独立的函数复合（二进制倍增）核对全部固定和生成答案，不在 153 处停止。
另行穷举全部 11111 个有效密钥，确认最多十四步的收敛界。

## 优化解法

`1292_math_optimized.py`. 保留反复求数字立方和，直到 N-1 步或不动点 153。预计算十个立方，查询及输出按 4096 字节块处理，不保存全部查询和答案。题定 K<=33333 且为三的倍数，已穷举验证最多十四步收敛；在该固定范围总时间 O(Q)、缓冲空间 O(B)。中间值不再变化也结束循环。数字立方和的每一步都使用精确整数运算。

与 `1292_math.py` 相比：时间 0.265 s → 0.125 s；内存 7972 KB → 3 344 KB。

优化 C++ 和 Go 逐个处理查询，直到指定步数或不动点 153，并使用有界输出缓冲区。Go 用十项表查每位数字的立方。C++ 合并两个三位块的预计算立方和，船的位置偏移及减法结果使用有符号 64 位整数。Go 也使用有符号 64 位偏移，并通过字节缓冲区直接读写数字，不为每个数字分配字符串。辅助空间为常数。

简单 Java 已满足保存的普通时间和内存排名，可直接复用为快速解而不复制文件。
简单 Python 和 Rust 保留用于教学：Python 超出稀疏比较的时间上限，Rust
超出内存上限。各自单独的优化文件提供达标结果。两个 Go 和优化 C++ 也
达标；简单 C++ 保留以便理解。此前声称全部基础文件均获准的说法已过时。

采用统一[排名标准](../../RATING_CRITERIA.md)，没有按语言另设第一名要求或
按改善 30% 单独准入。普通比较要求所需指标位于前十名或前 15%。同编译器
有 1–10 个有效对手时，稀疏参考比较取代名次准入。内存小于 1024 KB 时只
比较时间。排除快于 `0.015 s` 的对手；只把自己的时间提升到该下限。原始
Accepted 配对测量（包括 `0.001 s`）保持不变，不设日期或提交 ID 门槛。

2026 年 11 月 18 日的 PyPy 名次（时间 1/19、内存 5/19）为历史记录。绑定
精确源码的冻结审计按九个同编译器对手的参考值接纳优化 PyPy #11325483：
`0.125 s / 3344 KB`，上限为 `0.19665 s / 7672.80 KB`。基础 CPython
#11284592 的 `0.265 s` 超过其 `0.21505 s` 上限。基础 Rust #11284596
使用 2124 KB，超出其 1904.40 KB 上限；优化 Rust #11328962 使用 144 KB，
按时间达标。

令 `I`、`Z` 为输入输出字节数，`B` 为固定缓冲区。简单 C++、Go 流式处理，
辅助空间 `O(B)`。Java 保留输出，占 `O(Z+B)`；简单 Python 保留输入记号和
答案，占 `O(I+T+Z)`；简单 Rust 保留输入，占 `O(I+B)`。优化 C++/Go 使用
固定表和缓冲区，优化 Rust 对规定短数字采用有界缓冲和内联记号，均占 `O(B)`。
优化 Python 至多保留一块记号及输出，在规定数字长度下也占 `O(B)`。此前
Python 描述中的 `Q = T`。若允许任意长度 S 的记号，Python 未完成记号和
Rust spill 存储还需 `O(S)`。
