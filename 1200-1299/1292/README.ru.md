# 1292. Марсианские космобазы

[Timus 1292](https://acm.timus.ru/problem.aspx?space=1&num=1292) · сложность 380 · math

Автор оригинальной задачи — Денис Мусин; IX открытое командное соревнование школьников по программированию, 13 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Пусть F(x) — сумма кубов десятичных цифр x, так что F(12) = 9.
Космобазы стоят вдоль пути: первая на расстоянии K от конца пути, а
если промежуток перед базой i равен x, то промежуток после неё равен
F(x). Ключ K кратен 3.

Корабль находится между базами N − 1 и N на расстоянии L от базы N − 1.
Для каждого из 2 ≤ T ≤ 33 333 запросов с 2 ≤ N ≤ 33 333 и 3 ≤ K ≤ 33 333
нужно вывести расстояние от корабля до базы N.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

T, затем T строк с N, K и L, где `L ≥ 1`. Корабль находится между
указанными базами, а L — его смещение внутри этого промежутка.

## Выходные данные

T строк с расстояниями.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
2
3 12 100
16 12558 152
```

Вывод:

```
629
1
```

## Решение

Если считать конец пути базой 0, промежуток перед базой N — это F,
применённая N − 1 раз к K, а ответ — этот промежуток минус L. Наш пример
это подтверждает: 12 → 9 → 729, и 729 − 100 = 629.

Применять F до 33 332 раз на запрос при 33 333 запросах слишком долго,
но цепочка почти сразу устанавливается. Так как d³ ≡ d (mod 3), F
сохраняет остаток суммы цифр по модулю 3, и кратные 3 остаются
кратными 3. F(153) = 1 + 125 + 27 = 153, а проверка всех кратных 3 до
33 333 показывает, что каждое из них доходит до 153 не более чем за 14
шагов (дольше всех — 12 558). Поэтому F применяется, пока не сделано
N − 1 шагов или значение не стало 153. `O(T · 14 · цифры)`.

Тонкие места:

- промежуток перед базой N — это N − 1 шагов, а не N − 2: первая база
  уже стоит на расстоянии K от конца (тест 01);
- цепочка может оборваться прямо перед 153 (тест 03);
- промежуток может быть намного больше K, например F(99) = 1458
  (тест 05).

Все готовые и сгенерированные ответы сверены независимой композицией
функций (двоичным подъёмом), без остановки на 153. Отдельная полная
проверка всех 11111 допустимых ключей подтверждает границу 14 шагов.

## Оптимизированные решения

`1292_math_optimized.py`. Сохраняется повторная сумма кубов цифр до N-1 шагов либо неподвижной точки 153. Десять кубов предвычисляются, запросы и вывод идут блоками 4096 байт без хранения всех запросов и ответов. Для обещанных кратных трём K<=33333 ранее проверенная конечная граница сходимости — четырнадцать шагов; при этих фиксированных границах время O(Q), память буфера O(B). Неизменившееся промежуточное значение тоже завершает цикл. Все преобразования суммы кубов цифр выполняются в точной целочисленной арифметике.

По сравнению с `1292_math.py`: время 0.265 s → 0.125 s; память 7972 KB → 3 344 KB.

Быстрые C++ и Go обрабатывают запрос до нужного шага или неподвижной точки 153 и выводят ответы через ограниченный буфер. Go берёт куб каждой цифры из таблицы на десять элементов. C++ складывает две готовые суммы кубов для трёхзначных блоков. Смещение корабля и результат вычитания в C++ хранятся в знаковых 64-битных числах. Go также хранит смещения в знаковых 64-битных числах, читает и выводит числа через байтовые буферы без создания отдельной строки для каждого числа. Дополнительная память постоянна.

Простая Java уже проходит сохранённый обычный рейтинг по времени и
памяти и используется как быстрая без дублирования файла. Простые
Python и Rust сохранены для обучения: Python превышает порог времени
малой группы, Rust — её порог памяти. Их отдельные быстрые файлы
дают проходящие результаты. Обе Go и быстрая C++ также проходят;
простая C++ сохранена ради ясности. Прежнее утверждение о допуске
всех базовых файлов устарело.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1292_math_implementation_optimized.rs`. Токены читаются через ограниченный нативный байтовый буфер; короткие хранятся внутри объекта, дополнительная память выделяется только длинным. Десятичный разбор сохраняет знаковые границы без хранения всего командного ввода. Точка входа C напрямую вызывает решение и сбрасывает вывод Rust перед возвратом; архивная реализация с обычной точкой входа сохранена.

Accepted #11328962 (Rust 1.75 x64): **0.015 s / 144 KB**. Архивное сравнение: `1292_math.rs` (Rust 1.75 x64) — 0.001 s / 2124 KB (#11284596).

В текущем быстром Rust только вынесена вместимость токена 32 в
`INLINE_TOKEN_BYTES` по требованию строгого линтера; алгоритм и
комментарии сохранены. #11328962 и измерения относятся к прежним
точным байтам.

## Особенности языков

Действуют общие [рейтинговые критерии](../../RATING_CRITERIA.md), без
отдельного требования первого места для языков или допуска за улучшение
на 30%. Обычный рейтинг требует топ-10 или топ-15% по нужным метрикам.
При 1–10 допустимых соперниках того же компилятора место заменяет
сравнение с эталоном малой группы. Ниже 1024 КБ учитывается только время.
Чужие времена быстрее `0.015 s` исключаются; до этого порога поднимается
только наше время. Исходные пары Accepted, включая `0.001 s`, сохранены.
Ограничений по дате или ID нет.

Места PyPy от 18 ноября 2026 года (время 1/19, память 5/19) исторические.
Замороженный аудит с привязкой к исходникам допускает быстрый PyPy
#11325483 по эталону девяти соперников того же компилятора:
`0.125 s / 3344 KB` при порогах `0.19665 s / 7672.80 KB`. Базовый
CPython #11284592 с `0.265 s` превышает свой порог `0.21505 s`. Базовый
Rust #11284596 с 2124 КБ превышает свой порог 1904.40 КБ; быстрый
Rust #11328962 использует 144 КБ и проходит по времени.

Пусть `I` и `Z` — размеры входа/вывода в байтах, `B` — фиксированные
буферы. Простые C++ и Go работают потоково с памятью `O(B)`. Java
хранит вывод: `O(Z+B)`; простой Python хранит входные токены и ответы:
`O(I+T+Z)`; простой Rust хранит вход: `O(I+B)`. Быстрые C++/Go
используют фиксированные таблицы и буферы; быстрый Rust — ограниченные
буферы и встроенные токены для заданных коротких чисел: `O(B)`. Быстрый
Python хранит не более блока токенов и блока вывода, то есть `O(B)` при
обещанной длине чисел. В раннем описании Python `Q = T`. При произвольной
длине токена S незавершённый токен Python и spill Rust добавили бы `O(S)`.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
