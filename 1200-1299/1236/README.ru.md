# 1236. Восстановление ключа XOR по сдвинутому сообщению

[Timus 1236](https://acm.timus.ru/problem.aspx?space=1&num=1236) · сложность 499 · math

Автор оригинальной задачи — Елена Крючкова; полуфинал ACM ICPC Северо-Восточной Европы 2002–2003.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Сообщения шифруются побайтно как `E[i] = K[i] xor C[i]` с секретным
ключом K. Один и тот же открытый текст из N байт (1 ≤ N ≤ 10 000)
отправили дважды: как есть и с одним пробелом (байт 32) в начале. По
обоим зашифрованным сообщениям восстановить первые N + 1 байт ключа.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Две строки шестнадцатеричных цифр: зашифрованное сообщение из N байт,
затем из N + 1 байта.

## Выходные данные

N + 1 байт ключа в том же шестнадцатеричном виде.

## Примеры

### Пример 1

Ввод:

```
05262C5269143F314C2A69651A264B
610728413B63072C52222169720B425E
```

Вывод:

```
41434D2049435043204E454552432732
```

## Решение

Обозначим зашифрованные сообщения S (короткое) и L (длинное). Длинный
текст начинается с известного пробела, поэтому `K[0] = L[0] xor 32`.
Дальше байт i + 1 длинного сообщения и байт i короткого скрывают один и
тот же открытый байт C[i]:

```text
C[i] = S[i] xor K[i],   K[i+1] = L[i+1] xor C[i] = L[i+1] xor S[i] xor K[i]
```

Каждый байт ключа даёт следующий, так что один проход восстанавливает
все N + 1. `O(N)`.

Тонкие места:

- каждый байт выводится двумя заглавными цифрами, с ведущим нулём, если
  он меньше 16 (тест gen3).

## Оптимизированные решения

Обозначим открытый текст P, ключ K, короткий шифротекст S и длинный L. Начальный пробел даёт `K[0] = L[0] XOR пробел`. Для позиции i верны `S[i] = P[i] XOR K[i]` и `L[i+1] = P[i] XOR K[i+1]`. При XOR этих выражений P[i] сокращается, поэтому `K[i+1] = K[i] XOR S[i] XOR L[i+1]`. Каждый байт ключа выводится сразу после восстановления. C++, Go, Java и Rust хранят короткий шифротекст в массиве на 10000 байт и используют блоки ввода и вывода по 4096 байт. Java читает знаковые байты как беззнаковые с маской 255. Один проход занимает O(N) времени. Python использует базовую реализацию.

Принятая версия Java 1.8 заняла 0.125 с при 0.109 с у базовой и использовала 408 KB при 1756 KB у базовой.

Принятая версия Rust 1.75 x64 заняла 0.046 с при 0.015 с у базовой и использовала 208 KB при 368 KB у базовой.

Принятые базовые реализации [1236_math.py](1236_math.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Исходные Go/Python используют библиотечный hex; новые C++/Go/Java/Rust разбирают цифры и потоково вычисляют рекуррентность. Java раскрывает байты маской255. Python сохраняет исходный библиотечный вариант.
