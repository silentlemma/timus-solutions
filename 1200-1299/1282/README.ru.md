# 1282. Дерево игры

[Timus 1282](https://acm.timus.ru/problem.aspx?space=1&num=1282) · сложность 338 · games

Авторы оригинальной задачи — Сергей Волченков, Владимир Пинаев и Михаил Копачёв; четвертьфинал ACM ICPC 2003–2004, центральный регион России, Рыбинск, 15–16 октября 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Игра двух игроков задана деревом из 1 < N ≤ 1000 вершин с корнем в вершине
1. Игроки ходят по очереди, первый — в корне, спускаясь к одному из
детей. В каждом листе записан итог: +1, если выиграл первый игрок, −1,
если второй, 0 при ничьей. Какой итог получится при наилучшей игре обоих?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем для вершин 2…N либо `N предок` для внутренней вершины, либо
`L предок итог` для листа.

## Выходные данные

`+1`, `-1` или `0`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
7
N 1
N 1
L 2 -1
L 2 +1
L 3 +1
L 3 +1
```

Вывод:

```
+1
```

### Пример 2

Ввод:

```
7
N 1
N 1
L 2 -1
L 2 +1
L 3 +1
L 3 0
```

Вывод:

```
0
```

### Пример 3

Ввод:

```
18
N 1
N 1
N 2
L 2 +1
N 3
L 3 +1
L 3 +1
L 4 -1
L 4 +1
N 4
N 6
L 6 -1
L 6 -1
L 11 -1
L 11 +1
L 12 +1
L 12 -1
```

Вывод:

```
+1
```

## Решение

Это минимакс. Первый игрок ходит в вершинах чётной глубины и выбирает
наибольшее значение среди детей, второй — на нечётной и выбирает
наименьшее. Вершина может быть описана раньше своего предка, поэтому
значения считаются не в порядке входа: обход в ширину от корня даёт
все глубины, а проход по этому порядку в обратную сторону посещает всех
детей раньше родителя. `O(N)`.

Тонкие места:

- предок может быть описан после потомка (тест 05);
- цепочка из 1000 вершин сделала бы наивную рекурсию глубокой (тест 06);
- итоги записываются как `+1`, со знаком плюс, и во входе, и в ответе.

Ответы сравнивались с обычным рекурсивным минимаксом на 149
сгенерированных деревьях.

## Оптимизированные решения

`1282_games_optimized.java`. Сохраняется восходящий минимакс: максимум на чётной глубине, минимум на нечётной. Дети хранятся плоскими first/next, от корня строится один примитивный порядок обхода. Вместо полных глубин нужна лишь чётность, результаты -1,0,+1 хранятся байтами. Обратный обход считает детей раньше родителей, стек рекурсии не нужен даже для цепочки. Числовой ввод напрямую принимает токен +1. Время и память O(N), без вложенных списков объектов детей, объектных элементов порядка и полного декодированного ввода.

По сравнению с `1282_games.java`: время 0.140 s → 0.109 s; память 1656 KB → 680 KB.

Go считает дерево от листьев, храня результат для каждого из двух возможных игроков на ходе. Результат ребёнка при ходе второго игрока участвует в максимуме родителя, а при ходе первого — в минимуме. Узел готов после последнего ребёнка. Тогда его счётчик детей превращается в ссылку следующего элемента стека готовых узлов, поэтому отдельные стек и списки смежности не нужны.

Принятые базовые реализации [1282_games.cpp](1282_games.cpp), [1282_games.java](1282_games.java), [1282_games.py](1282_games.py), [1282_games.rs](1282_games.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1282_games_optimized.java`: место по времени 8/25, по памяти 2/25 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
