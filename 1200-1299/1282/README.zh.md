# 1282. 博弈树

[Timus 1282](https://acm.timus.ru/problem.aspx?space=1&num=1282) · 难度 338 · games

原题作者 Sergey Volchenkov、Vladimir Pinaev 和 Michael Kopachev，出自 2003 年 10 月 15–16 日在雷宾斯克举行的 ACM ICPC 2003–2004 俄罗斯中部赛区四分之一决赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个双人游戏由一棵以 1 号节点为根、共 1 < N ≤ 1000 个节点的树给出。双方轮流走，先手从根开始，
每步走到一个子节点。每个叶子记录结果：+1 表示先手胜，−1 表示后手胜，0 表示平局。双方都采取
最佳策略时结果如何？

时间限制：1 秒。内存限制：64 MB。

## 输入

N，然后对节点 2 到 N，内部节点为 `N 父节点`，叶子为 `L 父节点 结果`。

## 输出

`+1`、`-1` 或 `0`。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
7
N 1
N 1
L 2 -1
L 2 +1
L 3 +1
L 3 +1
```

输出：

```
+1
```

### 样例 2

输入：

```
7
N 1
N 1
L 2 -1
L 2 +1
L 3 +1
L 3 0
```

输出：

```
0
```

### 样例 3

输入：

```
18
N 1
N 1
N 2
L 2 +1
N 3
L 3 +1
L 3 +1
L 4 -1
L 4 +1
N 4
N 6
L 6 -1
L 6 -1
L 11 -1
L 11 +1
L 12 +1
L 12 -1
```

输出：

```
+1
```

## 解法

这就是极小化极大。先手在偶数深度的节点行动，取子节点中的最大值；后手在奇数深度行动，取
最小值。节点可能在父节点之前给出，所以不能按输入顺序计算：从根做一次广度优先遍历得到所有
深度，倒序走这个顺序就能保证子节点先于父节点处理。`O(N)`。

注意事项：

- 父节点可能出现在子节点之后（测试 05）；
- 1000 个节点的链会让朴素递归很深（测试 06）；
- 结果写作带加号的 `+1`，输入输出都是如此。

在 149 棵生成的树上与普通的递归极小化极大比较过。

## 优化解法

`1282_games_optimized.java`. 保留自底向上极大极小：偶深度取最大，奇深度取最小。以 first/next 扁平保存孩子，根起一次基本类型遍历序；只存深度奇偶，结果 -1,0,+1 存 byte。逆序保证先子后父，即使链也不需递归栈。数字读取可直接接受 +1。时间、空间 O(N)，去掉嵌套装箱孩子列表、装箱遍历序及完整解码输入。

与 `1282_games.java` 相比：时间 0.140 s → 0.109 s；内存 1656 KB → 680 KB。

Go 从叶子向上求值，为两种可能的当前玩家分别保存结果。子节点在第二名玩家回合的结果参与父节点的最大值，第一名玩家回合的结果参与最小值。最后一个子节点处理完后，该节点就绪，其子节点计数器改存就绪栈的下一链接，因此无需单独的栈或邻接表。
