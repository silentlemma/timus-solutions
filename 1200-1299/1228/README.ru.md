# 1228. Границы массива по множителям индексов

[Timus 1228](https://acm.timus.ru/problem.aspx?space=1&num=1228) · сложность 109 · math

Оригинальная задача — четвертьфинал ACM ICPC 2002–2003, центральный регион России, Рыбинск, октябрь 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`n`-мерный массив `array[0..k1, 0..k2, …, 0..kn]`, `n ≤ 20`, хранится так,
что быстрее всех меняется последний индекс, поэтому элемент
`X[i1, …, in]` имеет номер `1 + D1·i1 + … + Dn·in` при некоторых
множителях `Di`. По множителям и общему числу элементов `s` найти верхние
границы `k1, …, kn`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` (`1 ≤ n ≤ 20`) и `s` (`1 ≤ s < 2³¹ − 1`), затем `D1, …, Dn`.

## Выходные данные

`k1, …, kn` (`0 < ki ≤ 1000`) через пробелы или переводы строк.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4 180
90
18
6
1
```

Вывод:

```
1 4 2 5
```

## Решение

Увеличение индекса `i` на единицу пропускает целый блок последующих
размерностей, так что `D(i−1) = Di · (ki + 1)`, а весь массив — один блок
первой размерности: `s = D1 · (k1 + 1)`. Если поставить `s` перед
множителями, каждая граница на единицу меньше частного двух соседей:
`k1 = s/D1 − 1` и `ki = D(i−1)/Di − 1`. `O(n)`.

Арифметика ограниченных целых множителей занимает O(n) времени. Простые C++/Go/Java хранят n+1 размеров, O(n) ячеек; простые Python/Rust также сохраняют весь ввод, разобранные целые и строки ответа, O(I+n) памяти при I байтах ввода. Быстрые C++/Rust выводят отношения сразу, O(1) арифметического состояния плюс буферы. Быстрая Java хранит скалярный ввод, но собирает ответ StringBuilder, O(n) вывода. Быстрая Python хранит блок 65536 байт/токены и n строк ответа, O(n+B+T) при блоке B и самом длинном токене T. Быстрая Go сохраняет массив размеров и весь ввод, O(I+n): замена I/O не убрала массив.

Тонкие места:

- последний множитель всегда 1, а первая граница получается из `s`, а не
  из множителя;
- произведения меньше `2³¹ − 1`, поэтому для вычислений достаточно
  32-битных знаковых целых.

Границы проверены перемножением `ki + 1` в `s` на 59 сгенерированных
массивах и сверены с отдельно написанным решением на всех тестах.

## Оптимизированные решения

Оптимизированное решение на C++ читает множители по одному и хранит
только предыдущий, печатая каждую границу, как только приходит её
делитель, вместо того чтобы держать `s` и все множители в `std::vector`:
{1228_math_optimized.cpp}.

Оптимизированное решение на Java разбирает числа по цифрам прямо из
`System.in` вместо создания `Scanner` и хранит только предыдущий
множитель вместо массива всех множителей: {1228_math_optimized.java}.

`1228_math_optimized.py`. Сохраняется восстановление по соседним отношениям: начинаем с полного размера s, для очередного множителя выводим previous/current-1. Последний множитель обрабатывается так же; допустимый ввод обеспечивает точные положительные отношения. Выполняется O(n) делений ограниченных целых. Разбор блоками по 65536 байт переносит между чтениями только незаконченный токен, без всего декодированного ввода и массива входных целых. Однако список строк ответа и его склейка сохраняются: O(n) памяти вывода плюс ограниченная память парсера при заданной длине токенов. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1228_math.py`: время 0.078 s → 0.109 s; память 424 KB → 212 KB.

`1228_math_optimized.rs`. Сохраняется восстановление по соседним отношениям: начинаем с полного размера s, для очередного множителя выводим previous/current-1. Последний множитель обрабатывается так же; допустимый ввод обеспечивает точные положительные отношения. Выполняется O(n) делений ограниченных целых. Каждое отношение сразу читается и выводится, хранятся только предыдущий и текущий коэффициенты. Вектор ввода, строки отдельных ответов и склеенный вывод не нужны: O(1) дополнительного состояния. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1228_math.rs`: время 0.015 s → 0.015 s; память 216 KB → 52 KB.

## Особенности языков

Кэш точных исходников и общие [рейтинговые критерии](../../RATING_CRITERIA.md) подтверждают обе C++, быстрые Go/Java, простую CPython и обе исторические Rust. Простые Go/Java остаются учебными без звёздочек. PyPy за 0.109 с / 212 КБ всё ещё не проходит время и сохраняет маркер; исторические места 21/32 по времени и 1/32 по памяти не создают отдельной цели первого места. Проходящие быстрые Go/Java ниже 1024 КБ, нужно только время. Простая Go с 1136 КБ не проходит обязательную память эталона, несмотря на меньшее исходное время. Rust использует выборку всего того же языка и проходит численно, не по пустой таблице или исключению экономии памяти. Пары неизменённых исходников сохранены; правке комментария Rust ниже нужен отдельный Accepted.

Сейчас исправлен только незавершённый комментарий в `1228_math.rs`. Полное соотношение: множитель, умноженный на размер своей размерности, равен предыдущему множителю или полному размеру для первой размерности. Обратная замена двух строк точно восстанавливает прежние байты, исполняемый текст и другие комментарии сохранены. База №11283740 за 0.015 с / 216 КБ относится к историческому точному исходнику.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
