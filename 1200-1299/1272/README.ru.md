# 1272. Метро не в Екатеринбурге

[Timus 1272](https://acm.timus.ru/problem.aspx?space=1&num=1272) · сложность 144 · dsu

Автор оригинальной задачи — Магаз Асанов (подготовил Игорь Гольдберг); чемпионат Уральского государственного университета, 25 октября 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Город стоит на 1 ≤ N ≤ 10 000 островах, соединённых 0 ≤ K ≤ 12 000
тоннелями и 0 ≤ M ≤ 12 000 мостами, и вместе они связывают все острова.
Метро должно связать все острова, используя часть этих переходов и как
можно меньше мостов. Сколько мостов понадобится?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, K и M, затем K тоннелей и M мостов, каждый — два номера островов
от 1 до N.

## Выходные данные

Наименьшее число мостов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
6 3 4
1 2
2 3
4 5
1 3
3 4
4 6
5 6
```

Вывод:

```
2
```

## Решение

Тоннели ничего не стоят, поэтому берём их все: они разбивают острова на
уже связные группы. Каждый мост объединяет не больше двух групп в одну,
а раз вся сеть связна, мосты всегда можно выбрать так, чтобы объединять
группы по одной. Значит, ответ — число групп по тоннелям минус один; его
считает система непересекающихся множеств по тоннелям, а концы мостов
игнорируются. `O((N + K) log N)`.

Тонкие места:

- мосты не важны — важно лишь, что они связывают группы, а это обещано
  условием;
- тоннели могут повторяться или вести с острова на него же (тест 05);
- при одном острове или если всё связывают одни тоннели, ответ 0
  (тесты 02, 04).

## Оптимизированные решения

`1272_dsu_optimized.py`. Сохраняются объединение по размеру и сжатие путей через вершину. Полная сеть связна по условию, поэтому минимум платных мостов равен числу компонент тоннелей минус один; концы мостов на этот счёт не влияют. При одной вершине или отсутствии тоннелей возвращается N−1 без выделения DSU. При достижении одной компоненты работа завершается. Нужные токены читаются блоками 1024 байта; остаток мостов не разбирается. O(N+K·α(N)) времени алгоритма в худшем случае, O(N) памяти DSU и ограниченные буферы; ранние выходы дешевле.

Accepted точного исходника Python 3.12 x64 №11327776: 0.078 с / 784 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 3/99, память 2/99. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11304489: 0.109 с / 1076 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1272_dsu_optimized.py`: 0.078 s / 784 KB; сохранённая учебная база `1272_dsu.py`: 0.093 s / 3328 KB.

`1272_dsu_optimized.java`. Сохраняется DSU компонент туннелей: начинаем с N групп, уменьшаем число лишь при объединении разных корней, выводим groups-1. Обещание связности всех переходов гарантирует достаточность такого числа мостов. Как и в базе, нужны только концы туннелей; записи мостов не требуется хранить или дочитывать после определения ответа. Сохраняются объединение без рангов и сокращение пути пополам: меняется ввод, а не алгоритм связности. Память O(N); прямая консервативная худшая граница O(N+K·N), не больше N родительских ссылок на find. Байтовый ввод заменяет StreamTokenizer.

По сравнению с `1272_dsu.java`: время 0.140 s → 0.109 s; память 488 KB → 512 KB.

Оптимизированное решение на C++ разбирает числа вручную из буфера на
4 КБ вместо `scanf` и хранит родителей в глобальном массиве постоянного
размера из 10 001 клетки, которого хватает при `N ≤ 10 000`, вместо
`std::vector`. Кроме того, оно дочитывает мосты до конца, а простое
решение их не читает: {1272_dsu_optimized.cpp}.

Оптимизированное решение на Go разбирает числа побайтно из
`bufio.Reader` вместо `fmt.Fscan` и хранит родителей в `uint16`, куда
помещаются номера островов до 10 000, вместо `int`. Кроме того, оно
дочитывает мосты до конца, а простое решение их не читает:
{1272_dsu_optimized.go}.

Оптимизированное решение на Rust разбирает числа вручную из буфера на
4 КБ, пополняемого со стандартного ввода, а не читает весь ввод в
`String`, так что в памяти остаются только родители и буфер:
{1272_dsu_optimized.rs}.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1272_dsu_optimized.java`: место по времени 6/90, по памяти 2/90 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
