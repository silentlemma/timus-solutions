# 1272. Метро не в Екатеринбурге

[Timus 1272](https://acm.timus.ru/problem.aspx?space=1&num=1272) · сложность 144 · dsu

Автор оригинальной задачи — Магаз Асанов (подготовил Игорь Гольдберг); чемпионат Уральского государственного университета, 25 октября 2003 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Город стоит на 1 ≤ N ≤ 10 000 островах, соединённых 0 ≤ K ≤ 12 000
тоннелями и 0 ≤ M ≤ 12 000 мостами, и вместе они связывают все острова.
Метро должно связать все острова, используя часть этих переходов и как
можно меньше мостов. Сколько мостов понадобится?

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, K и M, затем K тоннелей и M мостов, каждый — два номера островов
от 1 до N.

## Выходные данные

Наименьшее число мостов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
7 4 4
1 2
2 3
4 5
6 7
1 3
2 4
5 6
6 7
```

Вывод:

```
2
```

## Решение

Тоннели ничего не стоят, поэтому берём их все: они разбивают острова на
уже связные группы. Каждый мост объединяет не больше двух групп в одну,
а раз вся сеть связна, мосты всегда можно выбрать так, чтобы объединять
группы по одной. Значит, ответ — число групп по тоннелям минус один; его
считает система непересекающихся множеств по тоннелям, а концы мостов
игнорируются. `O((N+K)log(N+1))`.

Тонкие места:

- мосты не важны — важно лишь, что они связывают группы, а это обещано
  условием;
- тоннели могут повторяться или вести с острова на него же (тест 05);
- при одном острове или если всё связывают одни тоннели, ответ 0
  (тесты 02, 04).

Все простые и быстрые нативные файлы связывают корни без рангов и сокращают путь пополам (path halving). Логарифмическая оценка DSU амортизированная и допускает произвольное связывание ([Тарьян–ван Лёвен, леммы 7–8](https://doi.org/10.1145/62.2160)); отдельный find может быть линейным. Обратная функция Аккермана для них не заявляется. Пусть Iᶜ — реально потреблённые байты с ограниченным упреждающим чтением. Время O((N+K)log(N+1)+Iᶜ). Простые C++/Go/Java разбирают лишь тоннели, Python/Rust читают весь файл. Быстрые C++/Go/Rust дочитывают мосты, Java/Python нужен префикс. Вклад M учитывается через потреблённый ввод.

Простые C++/Go/Java: N+1 родителей и ограниченный читатель B, O(N+B). Python хранит полный разбитый ввод, Rust весь String: O(N+I). Быстрая Go хранит N+1 uint16, Rust/Java нативных родителей и ограниченные буферы, O(N+B). C++ резервирует 10001 ячейку независимо отN: O(W+B), W=10000. Быстрая Python хранит отрицательные размеры корней/родителей и 1024-байтовые блоки: O(N+B); при n=1 либо k=0 DSU не выделяется. Потоковые версии не хранят список мостов.

## Оптимизированные решения

`1272_dsu_optimized.py` объединяет по размеру и расщепляет путь (path splitting). Сохраняет старого родителя next_vertex, перенаправляет текущую вершину к деду, затем переходит к старому родителю; halving перешёл бы к новому. Отрицательные корни содержат размеры. Связность полной сети даёт components−1 без чтения мостов; при одной компоненте выход, при n=1 либо k=0 ответ N−1 без DSU. Нужные токены читаются блоками 1024. Работа DSU O(N+K·α(N)) амортизированно плюс потреблённый ввод, память O(N+B). Документация не меняет алгоритм.

Историческая Accepted точного Python 3.12 №11327776:0.078 с / 784 КБ. Срез 2026-11-20 время 3/99, память 2/99: при памяти меньше 1024 КБ нужно лишь время, без отдельного первого места. Прежняя №11304489 — другая историческая пара 0.109 с / 1076 КБ.

- `1272_dsu_optimized.py`: 0.078 s / 784 KB; сохранённая учебная база `1272_dsu.py`: 0.093 s / 3328 KB.

`1272_dsu_optimized.java` сохраняет связывание без рангов и halving, заменяя StreamTokenizer фиксированным байтовым вводом. После тоннелей суффикс мостов не разбирается. Работа DSU имеет ту же амортизированную логарифмическую оценку; O(N+K·N) лишь более грубая оценка отдельных find, не другой алгоритм. Память O(N+B). Исторические пары Java сохранены: база 0.140 с / 488 КБ, быстрый ввод 0.109 с / 512 КБ.

По сравнению с `1272_dsu.java`: время 0.140 s → 0.109 s; память 488 KB → 512 KB.

Оптимизированное решение на C++ разбирает числа вручную из буфера на
4 КБ вместо `scanf` и хранит родителей в глобальном массиве постоянного
размера из 10 001 клетки, которого хватает при `N ≤ 10 000`, вместо
`std::vector`. Кроме того, оно дочитывает мосты до конца, а простое
решение их не читает: [1272_dsu_optimized.cpp](1272_dsu_optimized.cpp).

Оптимизированное решение на Go разбирает числа побайтно из
`bufio.Reader` вместо `fmt.Fscan` и хранит родителей в `uint16`, куда
помещаются номера островов до 10 000, вместо `int`. Кроме того, оно
дочитывает мосты до конца, а простое решение их не читает:
[1272_dsu_optimized.go](1272_dsu_optimized.go).

Оптимизированное решение на Rust разбирает числа вручную из буфера на
4 КБ, пополняемого со стандартного ввода, а не читает весь ввод в
`String`, так что в памяти остаются только родители и буфер:
[1272_dsu_optimized.rs](1272_dsu_optimized.rs).

## Особенности языков

Кэш точных исходников: быстрые C++/Java/Python проходят обычное время, обе Rust обычное время, обе Go редкий эталон точного компилятора (база 1428 КБ требует обе метрики, быстрая 916 КБ только время). Простые C++/Java/Python сравнения не проходят, но остаются учебными. [Общие критерии](../../RATING_CRITERIA.md) одинаковы для всех, при памяти меньше 1024 КБ лишь время. Прежние места Java 6/90 время,2/90 память обозначены историческими, не отдельным допуском. Все девять хешей с новыми комментариями требуют новых Accepted точных байтов; быстрая Java не менялась.

Во всех девяти файлах исправлено «каждый мост соединяет две компоненты»: мост может быть внутренним, но связная полная сеть даёт достаточно межкомпонентных мостов. Менялись лишь эти объясняющие строки; исполняемый код, простые версии и прочие содержательные комментарии сохранены. ID/время/память таблиц — прежние парные Accepted.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
