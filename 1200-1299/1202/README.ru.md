# 1202. Кратчайший путь через цепочку прямоугольников

[Timus 1202](https://acm.timus.ru/problem.aspx?space=1&num=1202) · сложность 442 · greedy

Автор оригинальной задачи — Леонид Волков; командное соревнование УрГУ, март 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Менее `10⁵` прямоугольников на клетчатой бумаге образуют цепочку слева
направо: у первого левый нижний угол в `(0, 0)`, каждый начинается там,
где по горизонтали кончается предыдущий, и каждая сторона длиной от 2 до
100 клеток. Там, где соседи соприкасаются, их общая граница исчезает.
Путник идёт по линиям сетки от `(1, 1)` до точки на клетку внутри
правого верхнего угла последнего прямоугольника, не может идти по
границам прямоугольников и переходит из прямоугольника в следующий
только через исчезнувшую часть границы. Найти длину кратчайшего пути или
`-1`, если пути нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n`, затем каждый прямоугольник как `x1 y1 x2 y2` — левый нижний и
правый верхний углы.

## Выходные данные

Длина кратчайшего пути или `-1`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
2
0 0 3 5
3 1 5 7
```

Вывод:

```
8
```

## Решение

Путь должен попасть из `x = 1` в `x = x2 − 1` последнего прямоугольника,
и это всегда можно сделать, ни разу не шагая влево, так что
горизонтальная часть фиксирована. Между прямоугольниками `i` и `i + 1`
путь пересекает прямую `x = x2ᵢ` на целой высоте строго внутри обоих
прямоугольников, то есть в `[max(y1) + 1, min(y2) − 1]`; если этот
диапазон пуст, пути нет. Внутри прямоугольника высоту можно менять как
угодно по внутренней вертикальной линии, поэтому вертикальная длина —
суммарное изменение высоты между стартом, выбранными высотами переходов
и целью.

Чтобы её минимизировать, двигаемся только по необходимости: держим
текущую высоту и на каждой границе загоняем её в допустимый диапазон. По
индукции самый дешёвый способ оказаться на высоте `h` после границы `i`
стоит жадную сумму плюс `|h − жадная высота|`, так что жадный выбор
никогда не хуже. `O(n)`.

Тонкие места:

- прямоугольники, соприкасающиеся меньше чем на две единицы или только
  углом, не оставляют перехода вовсе;
- прямоугольники могут заходить ниже нуля;
- при одном прямоугольнике ответ — просто расстояние от `(1, 1)` до цели,
  а для прямоугольника 2×2 это 0.

Ответы сверены с отдельно написанным решением на 400 случайных цепочках и
на всех тестах.

## Оптимизированные решения

`1202_greedy_optimized.py`. Сохраняется жадное ограничение высоты ближайшей точкой пересечения соседних прямоугольников. Четыре координаты читаются блоками 4096 байт; остаются только предыдущий вертикальный интервал, текущая высота и сумма перемещений. Убраны и список чисел входа, и копии прямоугольников. Пустое пересечение сразу даёт -1, иначе используются правая и верхняя границы последнего прямоугольника. Время O(n), память O(B) при ограниченных координатных токенах и блоке B. Полный ответ сбрасывается до выхода интерпретатора.

По сравнению с `1202_greedy.py`: время 0.328 s → 0.203 s; память 39384 KB → 6 920 KB.

Новые C++ и Go сохраняют ту же проекцию высоты на интервал каждого общего борта. Для неё уже достаточно предыдущего прямоугольника, текущей высоты и суммы вертикальных перемещений; список прямоугольников не добавляется. C++ заменяет повторный scanf буфером 8192 байта, Go заменяет bufio/fmt ограниченным вводом-выводом через стандартные дескрипторы. Отрицательные координаты разбираются явно, координаты и длины на целевых платформах вычисляются в 64 битах. Пустой интервал сразу даёт −1. Время O(n), дополнительная память ограничена. Все обычные исходники сохранены; Java, Python и Rust закрывают быстрый набор уже подходящими базами.

Принятые базовые реализации [1202_greedy.java](1202_greedy.java), [1202_greedy.py](1202_greedy.py), [1202_greedy.rs](1202_greedy.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1202_greedy_optimized.py`: место по времени 3/15, по памяти 8/15 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
