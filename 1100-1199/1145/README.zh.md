# 1145. 树形迷宫中两格之间的最长路径

[Timus 1145](https://acm.timus.ru/problem.aspx?space=1&num=1145) · 难度 353 · bfs

原题来自 Timus，未注明作者和出处。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个 `n × m` 的迷宫（`3 ≤ n, m ≤ 820`）由空格（`.`）和墙（`#`）组成；只能在
有公共边的空格之间移动，任意两个空格之间恰有一条路径。线将系在两个事先
未知的空格之间。求一根最短的线，使它对任意两个空格都够长，也就是所有这些
路径中最长的一条。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

`n`（宽度）和 `m`（高度），然后是 `m` 行、每行 `n` 个字符。

## 输出

线的长度，以格子边长为单位。

## 样例

### 样例 1

输入：

```
7 6
#######
#.#.###
#.#.###
#.#.#.#
#.....#
#######
```

输出：

```
8
```

## 解法

空格及其公共边构成一棵树，答案就是这棵树的直径。两次广度优先搜索即可求
出：从任一空格出发，最远的格子 `u` 是某条最长路径的端点；再从 `u` 出发，
最远的格子是另一端，它的距离就是答案。

为什么第一次搜索会落在端点上：设 `a … b` 是一条最长路径，`u` 是离起点 `s`
最远的格子。从 `s` 到 `u` 的路径会与路径 `a … b`（或通往它的路）相遇；如果
`u` 离相遇点不比 `a` 或 `b` 远，那么其中之一离 `s` 就会比 `u` 更远。所以把
`a … b` 的一端换成 `u`，得到的路径不会更短。

给网格加一圈墙，这样每个格子在数组中都有四个邻居，格子编号为
`r·(n + 2) + c`。一次搜索为 `O(n·m)`。

注意事项：

- 迷宫最多有 672400 个格子，所以搜索用一维数组和显式队列，不用递归；
- 第一个数是宽度，第二个是高度；
- 空格可能位于迷宫边缘，外加的一圈墙解决了这个问题。

答案已在 120 个小型随机迷宫上与从每个空格出发的广度优先搜索比对，同时验证
了空格构成一棵树。

## 各语言说明

- 所有语言都在加了边框的一维网格上做同样的两次搜索。
- 在我们的运行中，Python 在最大的迷宫上约需四分之一秒，但在 Timus 的
  CPython 3.12 下，它在第 9 个测试上超出 0.5 秒的限制（0.515 秒）；同一文件在
  PyPy 3.10 下以 0.218 秒通过，所以 Python 解法只能在 PyPy 下通过。
