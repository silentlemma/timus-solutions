# 1145. Самый длинный путь между двумя клетками лабиринта-дерева

[Timus 1145](https://acm.timus.ru/problem.aspx?space=1&num=1145) · сложность 353 · bfs

Оригинальная задача с Timus; автор и источник не указаны.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В лабиринте из `n × m` клеток, `3 ≤ n, m ≤ 820`, есть свободные клетки
(`.`) и стены (`#`); ходить можно между свободными клетками с общей
стороной, и между любыми двумя свободными клетками ровно один путь. Нить
привяжут между двумя свободными клетками, заранее неизвестными. Найти
самую короткую нить, которой хватит для любых двух свободных клеток, то
есть самый длинный из всех этих путей.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`n` (ширина) и `m` (высота), затем `m` строк по `n` символов.

## Выходные данные

Длина нити в сторонах клеток.

## Примеры

### Пример 1

Ввод:

```
7 6
#######
#.#.###
#.#.###
#.#.#.#
#.....#
#######
```

Вывод:

```
8
```

## Решение

Свободные клетки с общими сторонами образуют дерево, и ответ — диаметр
этого дерева. Его находят два поиска в ширину: из любой свободной клетки
самая дальняя клетка `u` — конец какого-то самого длинного пути; из `u`
самая дальняя клетка — другой конец, и расстояние до неё — ответ.

Почему первый поиск попадает в конец: пусть `a … b` — самый длинный путь,
а `u` — самая дальняя клетка от старта `s`. Путь из `s` в `u` встречает
путь `a … b` (или дорогу к нему), и если бы `u` не была хотя бы так же
далеко от этой точки встречи, как `a` или `b`, одна из них была бы дальше
от `s`, чем `u`. Значит, замена одного конца `a … b` на `u` даёт путь не
короче.

К сетке добавляется рамка из стен, так что у каждой клетки в массиве
четыре соседа, а клетки нумеруются как `r·(n + 2) + c`. Поиск — `O(n·m)`.

Тонкие места:

- в лабиринте до 672400 клеток, поэтому поиск идёт по плоскому массиву с
  явной очередью, без рекурсии;
- первое число — ширина, второе — высота;
- свободные клетки могут лежать на краю лабиринта, это решает рамка из
  стен.

Ответы сверены с поиском в ширину из каждой свободной клетки на 120
маленьких случайных лабиринтах, который заодно проверил, что свободные
клетки образуют дерево.

## Особенности языков

- Во всех языках одни и те же два поиска по плоской сетке с рамкой.
- Python в наших запусках тратит около четверти секунды на самых больших
  лабиринтах, но под CPython 3.12 на Timus превышает лимит 0,5 с на
  тесте 9 (0,515 с); тот же файл принимается под PyPy 3.10 за 0,218 с,
  так что решение на Python проходит только под PyPy.
