# 1150. Сколько раз каждая цифра встречается в номерах страниц от 1 до N

[Timus 1150](https://acm.timus.ru/problem.aspx?space=1&num=1150) · сложность 249 · math

Автор оригинальной задачи — Евгений Брызгалов; командный чемпионат Урала по программированию, Пермь, апрель 2001 года, английский тур.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Страницы пронумерованы от 1 до `N`, `N < 10⁹`. Посчитать, сколько раз
пишется каждая цифра от 0 до 9.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Десять строк: количество нулей, единиц, …, девяток.

## Проверка

Сравниваются десять точных целых количеств в порядке цифр 0..9; пробелы несущественны. Новый точный исходник Python прошёл 12 тестов репозитория на PyPy 3.10. Остальные сохранённые варианты имеют собственные проверки целевой среды и точные Accepted. Вывод сравнивается по правилам проверяющего модуля задачи.

## Примеры

### Пример 1

Ввод:

```
12
```

Вывод:

```
1
5
2
1
1
1
1
1
1
1
```

## Решение

Каждый десятичный разряд считаем отдельно. Для разряда с весом `p` (1, 10,
100, …) разобьём `N` на часть выше него, `high = N / (10p)`, цифру `cur` в
нём и часть ниже, `low = N mod p`. Рассмотрим числа от 1 до `N` по их части
выше этого разряда:

- за каждой верхней частью от `0` до `high − 1` идут все `10p` нижних
  окончаний, так что для каждой из них каждая цифра встречается в этом
  разряде `p` раз;
- при верхней части, равной `high`, цифра `d < cur` встречается ещё `p`
  раз, `d = cur` — ещё `low + 1` раз (для окончаний от `0` до `low`), а
  большие цифры не встречаются вовсе.

С нулями иначе: ноль в этом разряде пишется, только если выше стоит
ненулевая цифра, так что верхняя часть `0` не считается. Это даёт
`(high − 1)·p` для полных верхних частей начиная с 1, а затем `p` или
`low + 1`, как выше, и всё это только при `high > 0`. Разрядов не больше
девяти. `O(log N)`.

Тонкие места:

- ведущие нули не пишутся, поэтому для нулей нужно отдельное правило;
- при `N = 999999999` количества доходят до `9·10⁸`, это ещё 32 бита;
- само `N` тоже входит.

Ответы сверены с выписыванием всех чисел для всех `N` до 3000 и многих
до 30000, а также с поразрядным подсчётом по десятичной записи `N` на всех
тестах.

## Оптимизированные решения

`1150_math_optimized.go`. Сохраняются подсчёт цифр по старшей/текущей/младшей части и поправка ведущих нулей. Умножение разряда защищено; сравнение через limit/place/radix исключает переполнение. Время O(log N), память постоянна, перебора всех чисел нет. Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1150_math.go`: время 0.031 s → 0.015 s; память 1084 KB → 292 KB.

`1150_math_optimized.rs`. Сохраняются позиционные формулы high/current/low и поправка, исключающая ведущие нули. Прямой числовой ввод и десять строк целых заменяют стандартные текстовые средства; десять счётчиков и сам алгоритм прежние. Время O(log(N+1)), память O(1) при числовых границах условия. Наглядная версия с формулами сохранена рядом с измеренно более компактной реализацией.

По сравнению с `1150_math.rs`: время 0.015 s → 0.046 s; память 236 KB → 40 KB.

Позиционный подсчёт не изменён: для каждого десятичного разряда N делится на старшие цифры, текущую цифру и младшие цифры. Ненулевая цифра получает полные циклы и неполный остаток; у нуля исключается блок ведущих нулей. Хранятся десять счётчиков, вес разряда умножается на десять. Компактные файлы уменьшают накладные расходы ввода-вывода, а не вводят другую формулу подсчёта. У Python собственный Accepted на PyPy: более высокое время обменивается на меньшую память; понятные версии сохранены.

- `1150_math_optimized.java`: 0.078 s / 320 KB; база `1150_math.java`: 0.109 s / 1568 KB; изменение относительно базы: время -28.4%, память -79.6%.
- `1150_math_optimized.py`: 0.140 s / 316 KB; база `1150_math.py`: 0.062 s / 460 KB; изменение относительно базы: время +125.8%, память -31.3%.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1150_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
