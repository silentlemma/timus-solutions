# 1190. Может ли надпись на шоколадке с несколькими долями быть честной

[Timus 1190](https://acm.timus.ru/problem.aspx?space=1&num=1190) · сложность 338 · greedy

Автор оригинальной задачи — Леонид Волков; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На обёртке перечислены `N ≤ 5000` продуктов в порядке невозрастания
долей; у некоторых доля указана, в сотых долях процента. Каждая настоящая
доля — целое число от 1 до 10000 сотых, и все они в сумме дают ровно
100%. Определить, существуют ли настоящие доли, согласные с порядком и со
всеми указанными значениями.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем для каждого продукта его название, `0` или `1` и доля.

`1 ≤ N ≤ 5000`. Названия различны, содержат от 1 до 16 английских букв,
дефисов или подчёркиваний и не содержат других символов. Указанные доли —
целые числа от 1 до 10000; гарантируется, что они идут в порядке
невозрастания, в том числе через продукты с неизвестными долями.

## Выходные данные

`YES` или `NO`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4
Water 0
Cocoa-butter 0
Cocoa-powder 1 4000
Lecithin 0
```

Вывод:

```
NO
```

## Решение

По условию указанные доли уже идут в порядке невозрастания;
два прохода ниже опираются на эту гарантию.

Поскольку доли вниз по списку не растут, продукт без указанной доли не
меньше ближайшей указанной доли ниже него (или 1, если её нет) и не
больше последней указанной доли выше него (или 10000). Указанные доли
фиксированы. Если взять все доли наименьшими, получится допустимый
невозрастающий список с наименьшей суммой, а если наибольшими — с
наибольшей.

Достижима и любая сумма между ними: начиная с наименьшего списка,
поднимаем первую долю по единице до её максимума, затем вторую и так
далее; список всё время остаётся невозрастающим, а сумма растёт на единицу
за шаг. Значит, ответ `YES` ровно тогда, когда наименьшая сумма не больше
10000, а наибольшая не меньше 10000. `O(N)`.

Тонкие места:

- неизвестная доля всё равно не меньше 1, и это может вытолкнуть
  наименьшую сумму за 100% (тест `06`);
- возрастающие указанные доли нарушают входные ограничения и не могут
  служить контрпримером к методу двух проходов;
- если выше нет указанных долей, неизвестная доля может быть до 100%, а не
  только до первой указанной;
- надпись вообще без указанных долей всегда честна: `N ≤ 5000` долей по
  меньшей мере 1 помещаются в 10000.

Ответы сверены с точным динамическим оракулом на 2000 случайных надписях и
всех шести сохранённых тестах; сгенерированные случаи также проверены.

## Оптимизированные решения

`1190_greedy_optimized.java`. Java сохраняет проверку минимальной и максимальной возможной суммы, но завершает блок неизвестных долей при чтении следующей напечатанной. Она задаёт нижнюю границу, предыдущая известная доля — верхнюю, изначально 10000. Для хвоста нижняя граница равна единице. Любая целая сумма между границами достигается невозрастающим набором, поэтому условие low<=10000<=high точно. Имена пропускаются без создания строк; вместо массива долей длины N хранятся только позиция и значение последней известной доли и две суммы long. При ограниченной длине имён время O(N), дополнительная память O(1) с фиксированным буфером ввода на 1024 байта.

Accepted точного исходника Java 1.8 №11327329: 0.109 с / 476 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 5/28, память 1/28. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11324799: 0.14 с / 1308 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1190_greedy_optimized.java`: 0.109 s / 476 KB; сохранённая учебная база `1190_greedy.java`: 0.171 s / 6296 KB.

C++ и Go обрабатывают каждую серию неизвестных долей ингредиентов сразу при чтении следующей указанной доли. Она задаёт нижнюю границу серии, а предыдущая указанная доля — верхнюю. Для последней серии нижняя граница равна единице. Хранятся только длина серии, предыдущая доля и две границы общей суммы, поэтому дополнительная память постоянна.

Принятые базовые реализации [1190_greedy.java](1190_greedy.java), [1190_greedy.py](1190_greedy.py), [1190_greedy.rs](1190_greedy.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.


`1190_greedy_parsing_optimized.go`. Разбор специализируется на неотрицательных числовых токенах, ввод читается блоками по 32 КиБ. Сохранены нижняя и верхняя суммы для серий неизвестных долей; при превышении нижней суммой 10000 сразу возвращается NO. Перед явным завершением процесса вывод полностью записывается.

Для этого точного исходника получен собственный Accepted и выполнены единые [рейтинговые критерии](../../RATING_CRITERIA.md). Время и память ниже взяты из одной посылки; повторные измерения судьи могут различаться. Существующие простые и отличающиеся оптимизированные версии сохранены.

Accepted #11329530 (Go 1.14 x64): **0.015 s / 392 KB**.
