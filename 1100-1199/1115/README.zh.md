# 1115. 把长度分配到总长给定的各行

[Timus 1115](https://acm.timus.ru/problem.aspx?space=1&num=1115) · 难度 409 · backtracking

原题出自保加利亚 IOI 国家队第一次选拔赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `N < 100` 个物品，长度为 1 到 100 的整数，以及 `M` 行（`1 < M < 10`），每行长度给定。把所有物品分到各行，使每行中物品长度之和恰好等于该行长度；每行至少一个物品。已知存在这样的分法。输出任意一种。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N M`，然后是 `N` 行物品长度，再是 `M` 行各行的长度。

## 输出

按输入顺序，每行输出两行：该行的物品数和它们的长度。

## 评测方式

接受任何一个正确的分法。检查程序验证每行之和等于其长度，并且用到的物品恰好是给定的那些。

## 样例

### 样例 1

输入：

```
5 2
4
10
2
5
3
11
13
```

输出：

```
3
5 4 2
2
10 3
```

## 解法

这是精确的多路划分，一般来说是难题，因此解法使用带剪枝的回溯搜索。最初按行长从短到长填充，物品按长度递减尝试。这只是一种启发式策略：短行的填法不一定更少。最后一行取走所有剩余物品。相同长度在每个位置只试一次，因为相同物品可以互换。

填充一行之前，位集 `reach[k]` 记录从位置 `k` 起的空闲物品能凑出的和，从后往前构造：
`reach[k] = reach[k+1] | reach[k+1] << len`。只要任意未填充行的目标不可达，就立即剪枝。只有当当前行的剩余部分能用后面的物品凑齐时，才选择该物品。

固定的搜索顺序仍可能在互不兼容的行填法上耗时过长。前 128 次尝试各允许 256 次子集搜索调用，达到限制后撤销所有分配，并重新排列行和不同物品长度的尝试顺序。相同长度仍放在一起。所有语言使用相同的固定初始状态和整数生成器，因此输出一致。如果这些尝试都失败，最后进行一次不限制调用次数的完整搜索；达到预算并不表示无解。输出时保留行的原始输入编号。

设物品总长为 `S`，位集的字宽为 `W`，保守的最坏时间复杂度为 `O(M^N * N^2 * ceil(S/W))`，辅助空间为 `O(M * N * ceil(S/W))` 个字。重启并未消除指数级最坏情况，实测速度不能保证所有合法输入都同样快。

注意事项：

- 若按所有顺序尝试相同物品，在长度大量重复的数据上搜索会爆炸；
- 没有子集和检查时，不可达的当前行或后续行仍会留在搜索中；
- 测试 **07** 揭示固定的最短行优先顺序会导致数百万次调用；短行的填法不一定最少（物品 `[1,1,2,5]`、目标 `[2,2,5]` 中，长度 2 有两种填法，长度 5 只有一种）；
- 中断尝试时必须撤销所有分配，最后一次搜索必须取消调用次数限制；
- 各行必须按输入顺序输出，尽管填充顺序不同。

Python 解法通过了全部 7 个保存的测试、全部 5 个指定生成用例、与独立精确判定程序核对的 1,500 个小规模随机用例，以及 406 个大规模或边界用例。

- C++ 使用 `std::bitset`；Go、Java 和 Rust 用 64 位字数组保存和，并手写移位或运算；Python 用大整数作位集。
