# 1115. 把长度分配到总长给定的各行

[Timus 1115](https://acm.timus.ru/problem.aspx?space=1&num=1115) · 难度 415 · backtracking

原题出自保加利亚 IOI 国家队第一次选拔赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `N < 100` 个物品，长度为 1 到 100 的整数，以及 `M` 行（`1 < M < 10`），每行长度给定。把所有物品分到各行，使每行中物品长度之和恰好等于该行长度；每行至少一个物品。已知存在这样的分法。输出任意一种。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N M`，然后是 `N` 行物品长度，再是 `M` 行各行的长度。

## 输出

按输入顺序，每行输出两行：该行的物品数和它们的长度。

## 评测方式

接受任何一个正确的分法。检查程序验证每行之和等于其长度，并且用到的物品恰好是给定的那些。

## 样例

### 样例 1

输入：

```
5 2
4
10
2
5
3
11
13
```

输出：

```
3
5 4 2
2
10 3
```

## 解法

这是精确的多路划分，一般来说是难题，所以解法用强剪枝的回溯搜索。各行逐一填充，从最短的开始，因为短行的填法最少；最后一行直接取走剩下的全部物品。在一行内按长度从大到小尝试物品，且相同长度在每个位置只试一次，因为相同的物品可以互换。

关键的剪枝是子集和表。填充一行之前，位集 `reach[k]` 记录从位置 `k` 起的空闲物品能凑出的和（从后往前构造：
`reach[k] = reach[k+1] | reach[k+1] << len`）。只有当剩余部分还能用其后的物品凑齐时才取这个物品，所以单独一行永远不会走进死胡同；只有行与行之间的相互影响才会导致回溯。在随机数据以及长度几乎相等、部分填法很多的数据上，每个用例都远在时限之内完成。

注意事项：

- 若按所有顺序尝试相同物品，在长度大量重复的数据上搜索会爆炸；
- 没有子集和检查时，即使一行的剩余部分已无法凑成也会被继续搜索；
- 各行必须按输入顺序输出，尽管填充顺序不同。

答案在所有测试以及 120 组随机数据（至多 99 个物品、9 行，包括长度几乎相等和大多相同的情况）上都用检查程序验证过。
