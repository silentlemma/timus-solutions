# 1115. Разбиение длин по рядам заданной общей длины

[Timus 1115](https://acm.timus.ru/problem.aspx?space=1&num=1115) · сложность 409 · backtracking

Оригинальная задача — первое отборочное соревнование в болгарскую команду на IOI.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `N < 100` предметов с целыми длинами от 1 до 100 и `M` рядов
(`1 < M < 10`) заданных длин. Разложить все предметы по рядам так, чтобы
длины в каждом ряду в сумме давали ровно длину ряда; в каждом ряду хотя
бы один предмет. Известно, что разбиение существует. Вывести любое.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N M`, затем `N` строк с длинами предметов, затем `M` строк с длинами
рядов.

## Выходные данные

Для каждого ряда в порядке ввода две строки: число предметов в нём и их
длины.

## Проверка

Подходит любое правильное разбиение. Проверяющая программа убеждается,
что каждый ряд в сумме даёт свою длину и что использованы ровно данные
предметы.

## Примеры

### Пример 1

Ввод:

```
5 2
4
10
2
5
3
11
13
```

Вывод:

```
3
5 4 2
2
10 3
```

## Решение

Это точное разбиение на несколько частей, в общем случае трудная задача,
поэтому решения используют перебор с отсечениями. Сначала ряды заполняются
от коротких к длинным, а предметы перебираются по убыванию длины. Это лишь
эвристика: у короткого ряда не обязательно меньше заполнений. Последний
ряд забирает все оставшиеся предметы. Равные длины пробуются на каждом
месте только один раз, ведь равные предметы взаимозаменяемы.

Перед заполнением ряда битсет `reach[k]` хранит суммы, которые могут дать
свободные предметы с позиции `k` до конца. Он строится с конца:
`reach[k] = reach[k+1] | reach[k+1] << len`. Если длина любого ещё не
заполненного ряда недостижима, ветка сразу отсекается. Предмет берётся,
только если остаток текущего ряда можно добрать предметами после него.

Фиксированный порядок перебора всё равно может слишком долго перебирать
несовместимые заполнения рядов. Каждая из первых 128 попыток допускает
256 вызовов поиска подмножества, затем все назначения отменяются,
перемешиваются ряды и порядок различных длин предметов. Равные длины
остаются рядом. Во всех языках используется один и тот же целочисленный
генератор с фиксированным начальным состоянием, поэтому ответы совпадают.
Если эти попытки не помогли, последний поиск без ограничения числа вызовов
полностью перебирает варианты: исчерпание бюджета не означает отсутствия
разбиения. Для вывода сохраняются исходные номера рядов.

При суммарной длине предметов `S` и ширине слова битсета `W` консервативная
оценка времени в худшем случае — `O(M^N * N^2 * ceil(S/W))`, дополнительной
памяти — `O(M * N * ceil(S/W))` слов. Перезапуски не устраняют
экспоненциальный худший случай; измеренная скорость не гарантирует такую
же скорость на каждом допустимом входе.

Тонкие места:

- перебор равных предметов во всех порядках взрывается на наборах с
  многими одинаковыми длинами;
- без проверки сумм в поиске остаются недостижимые текущие и будущие ряды;
- тест **07** вызывает миллионы обращений при фиксированном порядке от
  коротких рядов к длинным; короткие ряды не обязательно имеют меньше
  заполнений (предметы `[1,1,2,5]`, длины рядов `[2,2,5]`: для 2 есть
  два заполнения, для 5 — одно);
- прерванная попытка должна отменить все назначения, а последний поиск
  должен работать без ограничения числа вызовов;
- ряды нужно выводить в порядке ввода, хотя заполняются они в другом.

Решение на Python проверено на всех 7 сохранённых тестах, всех 5
заданных случаях генератора, 1 500 небольших случайных случаях с
независимым точным оракулом и 406 больших или граничных случаях.

## Оптимизированные решения

Версия C++ выделяет только нужное для текущей таблицы сумм число 64-битных слов. Если суммарная длина свободных кораблей U, подмножество длины T для будущего ряда существует тогда и только тогда, когда существует подмножество длины U − T. Проверяем меньшее значение. Для текущего ряда сохраняем полную целевую сумму, чтобы восстановить выбранные корабли. Последний поиск без ограничения на число вызовов сохраняет полноту.

Принятые базовые реализации [1115_backtracking.go](1115_backtracking.go), [1115_backtracking.java](1115_backtracking.java), [1115_backtracking.py](1115_backtracking.py), [1115_backtracking.rs](1115_backtracking.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- C++ использует `std::bitset`; Go, Java и Rust хранят суммы в массивах
  64-битных слов с написанным вручную сдвигом с «или»; Python использует
  длинные целые как битсеты.
