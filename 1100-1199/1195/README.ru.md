# 1195. Кто выиграет недоигранную партию в крестики-нолики

[Timus 1195](https://acm.timus.ru/problem.aspx?space=1&num=1195) · сложность 260 · games

Авторы оригинальной задачи — Леонид Волков и Олег Кац; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На доске 3×3 для крестиков-ноликов ровно три крестика и три нолика, и ни
одна линия ещё не заполнена; крестики ходили первыми, значит, сейчас их
ход. Найти исход при наилучшей игре обеих сторон.

Победная линия — три одинаковых символа в одной строке, одном столбце или любой из двух диагоналей.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Три строки из `X`, `O` и `#` для пустой клетки.

## Выходные данные

`Crosses win`, `Ouths win` или `Draw`.

## Проверка

Проверяющий репозитория требует одну строку ответа и сравнивает токены внутри неё. Пробелы внутри строки нормализуются, но перенос слов на другую строку неравнозначен. Допустимые ответы: `Crosses win`, `Ouths win`, `Draw`.

- `1195_games_optimized.cpp` (G++ 13.2 x64): 15 тестов репозитория; 1372 дополнительных сравнений точного исходника.

- `1195_games_optimized.java` (Java 1.8): 15 тестов репозитория; 1372 дополнительных сравнений точного исходника.

- `1195_games_optimized.py` (PyPy 3.10 x64): 15 тестов репозитория; 1372 дополнительных сравнений точного исходника.

## Решение

Свободны только три клетки, так что во всём дереве игры не больше
`3·2·1` вариантов. Его решает простой минимакс: ходящая сторона пробует
каждую пустую клетку; ход, заполняющий линию, выигрывает, иначе исход
противоположен лучшему исходу соперника из полученной позиции; полная
доска — ничья. `O(1)`.

Тонкие места:

- ходят всегда крестики, потому что обе стороны сделали по три хода;
- проверять заполненную линию нужно для только что поставленного знака, а
  не для обоих;
- ответ для ноликов пишется `Ouths win`.

Ответы сверены с отдельно написанным решением на всех 1372 досках с тремя
крестиками, тремя ноликами и без заполненной линии.

## Оптимизированные решения

`1195_games_optimized.java`. Java сохраняет тот же точный негамакс глубиной три хода. Две девятибитные маски представляют фигуры; маски строк, столбцов и диагоналей определяют победу, выигрышный ход сразу завершает поиск. Во входе всегда три пустые клетки, поэтому таблица мемоизации не нужна. Буфер ввода на 64 байта заменяет отдельные обращения к потоку; три строки ответа сохранены. На фиксированном поле время и дополнительная память O(1). Все 1372 допустимые позиции с шестью фигурами сверены с независимым решателем на обычной доске.

Accepted точного Java 1.8 №11327339: 0.093 с / 372 КБ; сохранённое сравнение от 2026-11-20: время 3/25, память 2/25. Ниже 1024 КБ он проходит общий критерий времени, без отдельной цели первого места или маркера. Прежний №11309258 — отдельная историческая пара 0.109 с / 352 КБ; её память нельзя подставлять вместо текущих 372 КБ.

- `1195_games_optimized.java`: 0.093 s / 372 KB; сохранённая учебная база `1195_games.java`: 0.109 s / 1544 KB.

`1195_games_optimized.rs`. Сохраняется негамакс для позиции после шести ходов. Две девятибитные маски заменяют изменяемый вектор поля, восемь выигрышных масок — сравнения троек, выигрышный ход сразу завершает поиск. Мемоизация и новые правила не вводятся. При E пустых клетках худший поиск O(E!), стек O(E); поле фиксировано 3×3. Побайтовые ввод и вывод сохраняют точные строки Crosses/Draw/Ouths.

По сравнению с `1195_games.rs`: время 0.046 s → 0.015 s; память 212 KB → 56 KB.

Сохраняются полный минимакс и восемь выигрышных линий. В легальном вводе по три крестика и нолика без готовой победы, свободны только три клетки: таблица всех досок не нужна. Перебираем ход; если он завершил линию, сразу получаем победу, иначе меняем знак результата соперника и выбираем максимум. Полная доска даёт ничью. Нативные версии с изменяемой доской восстанавливают клетку перед каждым ранним выходом. Python держит две девятибитные маски и маску свободных клеток с тем же деревом игры. Прямой небольшой ввод-вывод убирает тяжёлые сканеры и потоки. Поиск глубины три имеет O(1); новый Python независимо проверен на всех1372легальных досках с шестью знаками.

- `1195_games_optimized.cpp`: 0.015 s / 100 KB; база `1195_games.cpp`: 0.015 s / 352 KB; изменение относительно базы: время -0.0%, память -71.6%.

- `1195_games_optimized.py`: 0.125 s / 280 KB; база `1195_games.py`: 0.078 s / 528 KB; изменение относительно базы: время +60.3%, память -47.0%.

## Особенности языков

Действуют общие [рейтинговые критерии](../../RATING_CRITERIA.md). Кэш точных исходников подтверждает обе C++, Go, быструю Java, простую Python и обе Rust. Простая Java не проходит численный порог, но остаётся учебной без звёздочки; быстрая PyPy не проходит время и сохраняет маркер. Ниже 1024 КБ учитывается только время. Go с 1084 КБ проходит обе метрики относительно одного соперника точной версии. У Rust нет точных соперников: применяется обычное сравнение всех версий языка с одним соперником другого компилятора, а не вывод по одной экономии памяти. Нет отдельных требований первого места или выигрыша 30%. Чужие времена ниже 0.015 с исключаются, свои меньшие ограничиваются снизу лишь при сравнении.

При этом ревью в `1195_games.py` изменён только комментарий о результате относительно текущего игрока; исполняемое AST и простой алгоритм прежние. В таблице сохранены исторический Accepted №11283478 и его парные метрики.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
