# 1153. Восстановление N по сумме 1 + 2 + … + N длиной до 600 цифр

[Timus 1153](https://acm.timus.ru/problem.aspx?space=1&num=1153) · сложность 332 · math

Автор оригинальной задачи — Евгений Брызгалов; командный чемпионат Урала по программированию, Пермь, апрель 2001 года, английский тур.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Компьютер сложил целые числа от 1 до `N`, `0 < N < 10³⁰⁰`, и выдал сумму
`S`, но `N` потеряно. По `S`, которое всегда является такой суммой, найти
`N`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`S`.

## Выходные данные

`N`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
28
```

Вывод:

```
7
```

## Решение

`S = N(N + 1)/2`, поэтому `8S + 1 = 4N² + 4N + 1 = (2N + 1)²` — точный
квадрат, и `N = (√(8S + 1) − 1) / 2`. Трудность только в размере: в `S`
до 600 цифр, так что корень требует длинной арифметики.

Школьный способ извлечения корня столбиком идёт цифра за цифрой и требует
только умножения на малые числа, сложения, сравнения и вычитания.
Разобьём `8S + 1` на пары цифр справа. Храним уже найденную часть корня
`r` и остаток. Для каждой следующей пары приписываем её к остатку
(умножаем на 100 и прибавляем), затем находим наибольшую цифру `x`, при
которой `(20r + x)·x` не больше остатка, вычитаем это произведение и
приписываем `x` к корню. После последней пары корень равен `2N + 1`;
вычитаем единицу и делим пополам, начиная со старшей цифры. При примерно
300 парах и не больше девяти попыток на каждую над числами из 600 цифр
это несколько миллионов действий с цифрами.

Тонкие места:

- ни `S`, ни `N` не помещаются ни в какое машинное целое;
- у `8S + 1` может быть нечётное число цифр; ведущий ноль выравнивает пары;
- `N = 1` даёт `S = 1`, а корень из `9` равен `3`.

Ответы проверены на всех тестах обратным вычислением `N(N + 1)/2` в целых
числах Python.

## Оптимизированные решения

Обе версии обращают то же тождество 8S + 1 = (2N + 1)² через точный целочисленный квадратный корень. Go хранит десятичные цифры в фиксированных массивах и сносит их парами. Для префикса корня r выбирает наибольшую цифру x, для которой (20r + x)x не превышает остаток, вычитает этот вклад и дописывает x. Затем вычитает единицу и делит корень пополам. Это O(L²) времени и O(L) памяти без универсальной длинной арифметики и временных строк. Python начинает со степени двойки выше корня и выполняет целочисленные шаги Ньютона, пока приближения убывают. Для L цифр входа O(L² log(L+1)) даёт верхнюю оценку при квадратичном делении.

Принятые базовые реализации [1153_math.cpp](1153_math.cpp), [1153_math.java](1153_math.java), [1153_math.rs](1153_math.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

`1153_math_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером. Для Java здесь используется та же консервативная оценка, что у уже имеющегося варианта Ньютона на Python: O(L² log(L+1)) при квадратичном делении больших целых, где L — длина десятичного ввода. Старт выше корня даёт O(log(L+1)) шагов Ньютона; каждый делит числа из O(L) цифр. Оценка уточняется и для неизменённого простого Java-кода, и для новой версии с заменённым вводом.

По сравнению с `1153_math.java`: время 0.140 s → 0.125 s; память 1676 KB → 736 KB.

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1153_math_implementation_optimized.rs`. Точка входа C напрямую вызывает решение и сбрасывает вывод Rust перед возвратом; архивная реализация с обычной точкой входа сохранена.

Accepted #11328983 (Rust 1.75 x64): **0.031 s / 356 KB**. Архивное сравнение: `1153_math.rs` (Rust 1.75 x64) — 0.046 s / 456 KB (#11280829).


`1153_math_binary_search_parsing_optimized.go`. Корень из 8S+1 вычисляется точной десятичной арифметикой в фиксированных массивах. Следующая цифра корня находится двоичным поиском вместо перебора от девяти вниз; сравнение и вычитание остатка остаются точными. Из корня вычитается единица, затем он делится на два. Байтовый ввод-вывод исключает инициализацию math/big и выделение строк токенов. Для L цифр время O(L²), хранение ограничено пределом ввода в 600 цифр.

Для этого точного исходника получен собственный Accepted и выполнены единые [рейтинговые критерии](../../RATING_CRITERIA.md). Время и память ниже взяты из одной посылки; повторные измерения судьи могут различаться. Существующие простые и отличающиеся оптимизированные версии сохранены.

Accepted #11329520 (Go 1.14 x64): **0.015 s / 312 KB**.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- Python использует `math.isqrt` на встроенных целых, а Go — `big.Int.Sqrt`.
- В Java 8 нет `BigInteger.sqrt`, поэтому там работает метод Ньютона,
  `x ← (x + D/x)/2`, начиная со степени двойки выше корня.
- В стандартных библиотеках C++ и Rust нет длинных целых, и там корень
  извлекается столбиком по десятичным цифрам.
