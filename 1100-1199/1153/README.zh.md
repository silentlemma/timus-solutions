# 1153. 由最多 600 位的和 1 + 2 + … + N 还原 N

[Timus 1153](https://acm.timus.ru/problem.aspx?space=1&num=1153) · 难度 332 · math

原题作者 Evgeny Bryzgalov，出自 2001 年 4 月在彼尔姆举行的乌拉尔团体程序设计锦标赛英语轮。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一台计算机把 1 到 `N`（`0 < N < 10³⁰⁰`）的整数相加并输出和 `S`，但 `N` 丢失
了。已知 `S`（它总是这样的和），求 `N`。

时间限制：1 秒。内存限制：64 MB。

## 输入

`S`。

## 输出

`N`。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
28
```

输出：

```
7
```

## 解法

`S = N(N + 1)/2`，所以 `8S + 1 = 4N² + 4N + 1 = (2N + 1)²` 是完全平方数，
`N = (√(8S + 1) − 1) / 2`。唯一的困难在于规模：`S` 最多 600 位，开方需要
大整数。

学校里学的竖式开方逐位进行，只需要乘以小数、加法、比较和减法。把 `8S + 1`
从右往左每两位分成一组。记录已求出的根 `r` 和余数。对每一组，把它接到余数
后面（乘以 100 再加上），然后找出使 `(20r + x)·x` 不超过余数的最大数字 `x`，
减去这个乘积，并把 `x` 接到根后面。处理完最后一组后，根就是 `2N + 1`；减一
后从最高位开始除以 2。约 300 组、每组最多试九次、数字长 600 位，总共只有
几百万次数字运算。

注意事项：

- `S` 和 `N` 都放不进任何机器整数；
- `8S + 1` 的位数可能是奇数，前面补一个零就能对齐分组；
- `N = 1` 时 `S = 1`，`9` 的平方根是 `3`。

答案已在所有测试上用 Python 整数反算 `N(N + 1)/2` 验证。

## 优化解法

两个版本都用精确整数平方根反解同一恒等式 8S + 1 = (2N + 1)²。Go 使用固定十进制数组，每次取下一对数字。对于根前缀 r，选择满足 (20r + x)x 不超过余数的最大数字 x，减去该部分并把 x 追加到根。最后减一并除以二。时间为 O(L²)，空间为 O(L)，无需通用大整数或临时字符串。Python 从根上方的一个二次幂开始，执行整数牛顿迭代，直到近似值不再下降。若输入有 L 位，采用平方复杂度除法时，O(L² log(L+1)) 是保守上界。

已通过评测的基础实现 [1153_math.cpp](1153_math.cpp), [1153_math.java](1153_math.java), [1153_math.rs](1153_math.rs) 也满足快速版本的要求：在保存的比较快照中，时间和内存均符合前 15% 或前十名的排名收录规则。直接复用这些源文件，不创建相同副本。星号标记尚未达到该语言目标排名的版本。

`1153_math_optimized.java`. Java 保留简单版本所述的算法和数据结构。固定字节缓冲区与 FastInput 替代 Scanner 及其正则表达式、区域设置处理。整数记号直接解析；需要字符串时仍进行 UTF-8 解码，十进制记号仍显式转换为数值。仅在需要前瞻时保存一个记号，输出算法不变。这样减少通用解析开销；表中列出算法工作量，输入扫描与字节数成正比，并使用有界输入缓冲区。 该 Java 实现采用与现有 Python 牛顿版本相同的保守界：在大整数除法为二次复杂度时为 O(L² log(L+1))，L 是十进制输入长度。从平方根上方开始，需 O(log(L+1)) 次牛顿迭代，每次对 O(L) 位整数作除法。此处同时澄清未修改的简单 Java 代码和仅替换输入的新版本的复杂度。

## 各语言说明

以下说明针对基础实现。

- Python 对内置整数使用 `math.isqrt`，Go 使用 `big.Int.Sqrt`。
- Java 8 没有 `BigInteger.sqrt`，所以用牛顿法 `x ← (x + D/x)/2`，从大于根的
  2 的幂开始。
- C++ 和 Rust 的标准库没有大整数，因此对十进制数字做竖式开方。
