# 1140. Кратчайший путь обратно в центр шестиугольной сетки после прогулки

[Timus 1140](https://acm.timus.ru/problem.aspx?space=1&num=1140) · сложность 383 · geometry

Оригинальная задача — четвертьфинал, центральный регион России, Рыбинск, 17–18 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Болото разбито на шестиугольные клетки, и три из шести направлений между
соседними клетками названы `X`, `Y` и `Z`, причём `Y` лежит между `X` и
`Z`. Студент начинает в центральной клетке и проходит до 32000 прямых
отрезков, каждый задан направлением и ненулевой длиной со знаком;
отрицательная длина означает обратное направление. Студент никогда не
отходит от центра больше чем на 100 клеток. Нужно описать путь обратно в
центр через наименьшее число клеток в том же формате.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` (`1 ≤ n ≤ 32000`), затем `n` строк с буквой направления и длиной со знаком.

## Выходные данные

Число отрезков `m ≥ 0` обратного пути, затем сами отрезки.

## Проверка

Принимается любой кратчайший путь. Проверяющая программа смотрит формат,
что путь заканчивается в центре и что его общая длина равна
шестиугольному расстоянию от последней клетки.

## Примеры

### Пример 1

Ввод:

```
4
Z -2
Y 3
Z 3
X -1
```

Вывод:

```
2
Y -2
Z -2
```

## Решение

На шестиугольной сетке среднее направление — сумма двух других: шаг по
`Y` приводит в ту же клетку, что шаг по `X` и затем шаг по `Z`. Поэтому
сложим длины по направлениям и запишем конец прогулки как `a·X + b·Z`, где
`a = X + Y` и `b = Z + Y`. Обратный путь с `m` шагами по `Y` требует ещё
`a − m` шагов по `X` и `b − m` по `Z` в обратную сторону и содержит
`|a − m| + |m| + |b − m|` шагов. Сумма расстояний от `m` до точек `a`, `0`
и `b` минимальна в их медиане, так что берём `m` равным медиане `a`, `0`
и `b` и выводим ненулевые из `X −(a − m)`, `Y −m`, `Z −(b − m)`. `O(n)`.

Геометрическое состояние — три суммы и до трёх кандидатов отрезков
обратно: O(1) ограниченных числовых слов без рекурсии у всех версий.
Простые C++/Go/Java читают постепенно, храня только ограниченные
буферы и это состояние. Простой Python хранит полный ввод и токены
split, Rust — входной String: дополнительно O(I) байтов. Быстрые
Go/Rust не сохраняют полный ввод; для Rust это отличие от базы.
Быстрый Python хранит блок 4096 байтов, части split и незаконченный
токен: O(4096+T) при максимальной длине токена T вместо O(I). Чтение
I байтов добавляет O(I) времени к O(n) геометрических обновлений.

Тонкие места:

- когда `a` и `b` одного знака, часть пути идёт по `Y`; когда знаки
  разные, `m = 0` и `Y` не нужен;
- отрезки нулевой длины запрещены, поэтому они выбрасываются, и ответ
  может состоять из `0` отрезков;
- во входе должен быть хотя бы один отрезок, даже если маршрут заканчивается
  в центре (тест 03); в режиме 1 генератор использует пару взаимно обратных
  отрезков, если малый запрошенный размер иначе дал бы пустой маршрут;
- кратчайших путей может быть несколько, принимается любой.

Ответы проверены проверяющей программой на всех тестах и на 1200 случайных
прогулках; формула расстояния в проверке сверена с поиском в ширину по
всем клеткам в пределах 100 от центра.

## Оптимизированные решения

Обе быстрые нативные версии сохраняют формулу медианы. Go меняет
map[string]int на массив трёх целых, sort.Ints трёх значений — на
явное ограничение нуля, fmt.Fscan — на Scanner/ScanWords и
strconv.Atoi, форматированные строки fmt — на небольшой байтовый
буфер вывода. База уже хранила только три суммы. Rust меняет
read_to_string и общий разбор токенов на stdin.lock().bytes() и
прямой разбор знакового числа, суммы — на массив трёх i32. Его база
уже находила медиану через min/max; clamp — та же операция
постоянного размера, не новая геометрия. Нулевые длины по-прежнему
не выводятся, обе простые версии сохранены.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 188 KB при 344 KB у базовой.

Кэш точных исходников подтверждает повторно используемые C++/Java
только по времени ниже 1 МиБ. Простой Python 0.125 s/776 КБ не
проходит эталон времени малой выборки; отдельная версия
0.062 s/828 КБ закрывает Python. Простой Go проходит обе метрики
малой выборки, быстрый Go — только время; обе Rust проходят
обычные места времени ниже 1 МиБ. Действуют общие
[рейтинговые критерии](../../RATING_CRITERIA.md); учебные исходники
без звёздочек, одинаковые быстрые копии не создаются.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1140_geometry_implementation_optimized.py`. Полный текстовый ввод/
split заменён блоками os.read с переносом лишь незаконченного
токена между блоками. Как база, версия собирает три суммы
направлений в словаре, затем вычисляет две оси и сортирует (a,0,b)
для медианы, а не накапливает две оси напрямую. Байтовые ключи
и os._exit после сброса полного вывода — изменения реализации;
геометрия и простой файл сохранены.

Accepted #11329035 (Python 3.12 x64): **0.062 s / 828 KB**. Архивное сравнение: `1140_geometry.py` (Python 3.12 x64) — 0.125 s / 776 KB (#11279441).

Текущая быстрая Python-редакция только именует прежний ASCII-порог
пробела 32 в разборе блоков. Формула медианы, числовые значения,
простой исходник и содержательные комментарии сохранены.
