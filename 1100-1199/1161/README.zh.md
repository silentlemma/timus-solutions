# 1161. 按两倍几何平均合并生物后的最小结果

[Timus 1161](https://acm.timus.ru/problem.aspx?space=1&num=1161) · 难度 93 · greedy

原题作者 Nick Durov，出自 2001 年 ACM ICPC 东北欧区域赛北部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`N ≤ 100` 个生物的重量是 1 到 10000 之间的整数。两个生物可以合并成一个重量为
`2·√(m₁·m₂)` 的生物，合并一直进行到只剩一个。求最终重量的最小可能值，保留两位小
数。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N`，然后是 `N` 个重量。

## 输出

最小的最终重量。

## 评测方式

仓库测试按 |实际值-参考值| <= 0.011·max(1,|参考值|) 比较数值记号，拒绝非有限值，并精确比较非数值记号。

## 样例

### 样例 1

输入：

```
2
72
50
```

输出：

```
120.00
```

### 样例 2

输入：

```
3
72
30
50
```

输出：

```
120.00
```

## 解法

先合并最重的两个，再把结果与次重的合并，依此类推直到最轻的。无论按什么顺序
合并，每个重量最后都处在若干层嵌套的平方根里：被合并 `k` 次的重量以它的
`2^k` 次方根进入结果，再乘以只与合并结构有关的常数。最重的重量被开方次数最多
时结果最小，而从最重往下的链恰好做到这一点，把最大的重量放在最深的位置。
排序加一遍扫描：`O(N log N)`。

注意事项：

- 只有一个生物时，答案就是它的重量；
- 顺序很重要：先合并轻的可能得到更重的结果；
- 重量永远不超过 40000，远在双精度范围之内。

答案已在 150 个最多七个生物的随机群体上，与枚举所有合并顺序的结果比对。

## 优化解法

优化的 C++ 解法把最多 100 个重量放在定长数组里，而不是 `vector`，因此不需要
在堆上分配内存：136 KB，而不是 216 KB。排序和取整方法不变。

优化的 Java 解法按 4 KB 分块读入并手工解析数字，而不是使用 `Scanner`；取整也不用
`BigDecimal`。`double` 恰好是小于 `2^53` 的整数尾数除以 `2^shift`。每次合并的结
果最多为 `2·√(x·10000)`，所以总重量始终小于 40000，移位量在 37 到 52 之间；尾数
的 100 倍小于 `100·2^53`，仍能放进 `long`。因此总重量的 100 倍是两个 `long` 之比
的精确分数，代码像 `printf` 一样按“五成双”取整：0.093 s，而不是 0.140 s；444 KB，
而不是 1912 KB。

`1161_greedy_optimized.rs`. 保留重量降序贪心和 f64 递推 total=2*sqrt(total*weight)。原地不稳定排序避免稳定排序的临时缓冲区，printf 输出两位小数而不使用 Rust 格式化。重量向量仍需 O(N) 空间，时间仍为 O(N log N)。 Rust 版本通过 C 运行库读写，不保留解码后的输入 String，也不构造格式化的输出 String。保留简单版本及其 Accepted。

与 `1161_greedy.rs` 相比：时间 0.015 s → 0.046 s；内存 248 KB → 104 KB。
