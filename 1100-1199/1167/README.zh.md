# 1167. 把一排黑白马分进马厩使不满意度最小

[Timus 1167](https://acm.timus.ru/problem.aspx?space=1&num=1167) · 难度 136 · dp

原题作者 Mugurel Ionut Andreica，出自 2001 年 12 月的 Romanian Open Contest（罗马尼亚公开赛）。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`N ≤ 500` 匹马排成一排，每匹是黑色或白色。把这一排恰好分成 `K` 个非空的连续段
（`1 ≤ K ≤ N`），每段进一个马厩。有 `i` 匹黑马和 `j` 匹白马的马厩不满意度为
`i·j`。求最小的总不满意度。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N` 和 `K`，然后是 `N` 个颜色：`1` 表示黑色，`0` 表示白色。

## 输出

最小的总不满意度。

## 样例

### 样例 1

输入：

```
6 3
1
1
0
1
0
1
```

输出：

```
2
```

## 解法

设 `best[s][i]` 为前 `i` 匹马分进 `s` 个马厩的最小不满意度。最后一个马厩装的是
某段马 `j..i−1`，所以 `best[s][i] = min_j best[s−1][j] + cost(j, i)`，其中代价是
黑马数乘白马数，可由黑马的前缀和得到。总共 `O(K·N²)`，在上限时约两千万步：
编译型语言没问题，Python 则太慢。

这个代价有一个有用的性质。对 `a ≤ b ≤ c ≤ d`，记 `x`、`y`、`z` 为 `a..b`、
`b..c`、`c..d` 三段，则
`cost(a, d) + cost(b, c) − cost(a, c) − cost(b, d) = Bx·Wz + Bz·Wx ≥ 0`，其中
`B` 和 `W` 是黑马和白马的数量。根据这个四边形不等式，随着 `i` 增大，最优的最后
分割点不会左移。于是每一层用分治来填：先求中间的 `i` 的最优分割点，然后左半部分
只在它左侧（含）搜索，右半部分只在它右侧（含）搜索。每层 `O(N log N)`，总共
`O(K·N log N)`。

注意事项：

- 所有马厩都必须用上，所以 `best[s][i]` 只在 `i ≥ s` 时存在；
- 还没有马厩时只有 `best[0][0] = 0` 可行，其余起点都必须视为不可达。

答案已在 400 个不超过 40 匹马的随机输入和所有测试上，与朴素的 `O(K·N²)` 递推
比对。

## 优化解法

优化的 C++ 解法把前缀计数和两层状态放在 501 个元素的固定 `int` 数组里（因为
`N ≤ 500`，这就够了），而不是向量；每处理完一个马厩就交换两层的指针，而不是新建
一层再复制回去：{1167_dp_optimized.cpp}。

优化的 Go 解法只分配一次两层状态，每处理完一个马厩就交换它们，而不是每个马厩新建
一个切片。重复使用的那一层里留下的旧值没有影响，因为第 `s` 层只读取从 `s − 1` 开
始的位置，而这些位置刚被上一层写过。这样垃圾回收器就没有东西可回收：
{1167_dp_optimized.go}。

优化的 Java 解法只分配一次两层状态，每处理完一个马厩就交换它们，而不是每个马厩新
建一个数组。重复使用的那一层里留下的旧值没有影响，因为第 `s` 层只读取从 `s − 1`
开始的位置，而这些位置刚被上一层写过。这样循环中不再分配内存：
{1167_dp_optimized.java}。

优化的 Python 解法减少解释器的工作量。如果 `K` 不小于同色连续段的个数，就直接输
出 0：每段各占一个马厩，再把段继续拆开不增加代价，直到恰好有 `K` 个马厩，因为
`K ≤ N`，这总能做到。第一层是只有一个马厩时的代价，直接算出。第 `s` 层只填到位置
`N − K + s`，因为后面每个马厩都至少需要一匹马。代价计算直接写进最内层循环，空区
间也不再压入栈中：{1167_dp_optimized.py}。
