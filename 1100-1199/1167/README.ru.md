# 1167. Разбиение ряда чёрных и белых лошадей по конюшням с наименьшим недовольством

[Timus 1167](https://acm.timus.ru/problem.aspx?space=1&num=1167) · сложность 136 · dp

Автор оригинальной задачи — Mugurel Ionut Andreica; Romanian Open Contest, декабрь 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N ≤ 500` лошадей, чёрных или белых, стоят в ряд. Нужно разбить ряд
ровно на `K` непустых отрезков подряд (`1 ≤ K ≤ N`), по одному на
конюшню. Конюшня с `i` чёрными и `j` белыми лошадьми имеет недовольство
`i·j`. Найти наименьшее возможное суммарное недовольство.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `K`, затем `N` цветов: `1` — чёрная, `0` — белая.

## Выходные данные

Наименьшее суммарное недовольство.

## Примеры

### Пример 1

Ввод:

```
6 3
1
1
0
1
0
1
```

Вывод:

```
2
```

## Решение

Пусть `best[s][i]` — наименьшее недовольство первых `i` лошадей в `s`
конюшнях. Последняя конюшня берёт каких-то лошадей `j..i−1`, поэтому
`best[s][i] = min по j от best[s−1][j] + cost(j, i)`, где стоимость —
число чёрных на число белых, оно берётся из префиксных сумм чёрных. Всего
это `O(K·N²)`, около 20 миллионов шагов на пределе: для компилируемых
языков нормально, а для Python медленно.

У стоимости есть полезное свойство. Для `a ≤ b ≤ c ≤ d` обозначим через
`x`, `y`, `z` куски `a..b`, `b..c`, `c..d`; тогда
`cost(a, d) + cost(b, c) − cost(a, c) − cost(b, d) = Bx·Wz + Bz·Wx ≥ 0`,
где `B` и `W` — числа чёрных и белых. По этому неравенству четырёхугольника
лучшее последнее разбиение не сдвигается влево при росте `i`. Поэтому
каждый слой заполняется методом «разделяй и властвуй»: находим лучшее
разбиение для среднего `i`, затем левая половина ищет только разбиения не
правее него, а правая — только не левее. Каждый слой стоит `O(N log N)`,
все вместе — `O(K·N log N)`.

Тонкие места:

- все конюшни должны быть заняты, так что `best[s][i]` есть только при
  `i ≥ s`;
- без конюшен возможно только `best[0][0] = 0`, а всё остальное должно
  считаться недостижимым.

Ответы сверены с простой рекуррентой за `O(K·N²)` на 400 случайных входах
до 40 лошадей и на всех тестах.

## Оптимизированные решения

Оптимизированное решение на C++ хранит префиксные суммы и два слоя в
массивах `int` фиксированного размера на 501 элемент, которых хватает
при `N ≤ 500`, вместо векторов, и меняет местами указатели на слои
вместо того, чтобы после каждой конюшни заводить новый слой и копировать
его обратно: {1167_dp_optimized.cpp}.

Оптимизированное решение на Go выделяет два слоя один раз и меняет их
местами после каждой конюшни вместо нового среза на каждую конюшню.
Старые значения в повторно используемом слое не мешают, ведь слой `s`
читает только позиции начиная с `s − 1`, а их только что записал
предыдущий слой. Сборщику мусора тогда нечего собирать:
{1167_dp_optimized.go}.

Оптимизированное решение на Java выделяет два слоя один раз и меняет их
местами после каждой конюшни вместо нового массива на каждую конюшню.
Старые значения в повторно используемом слое не мешают, ведь слой `s`
читает только позиции начиная с `s − 1`, а их только что записал
предыдущий слой. Цикл тогда вообще не выделяет память:
{1167_dp_optimized.java}.

Оптимизированное решение на Python сокращает работу интерпретатора. Если
`K` не меньше числа одноцветных отрезков, оно сразу выводит 0: каждый
отрезок получает свою конюшню, а дробить отрезки дальше можно бесплатно,
пока конюшен не станет ровно `K`, что возможно, поскольку `K ≤ N`.
Первый слой — стоимость одной конюшни, она считается напрямую. Слой `s`
заполняет только позиции до `N − K + s`, ведь каждой следующей конюшне
нужна хотя бы одна лошадь. Стоимость подставлена прямо во внутренний
цикл, а пустые диапазоны не кладутся в стек: {1167_dp_optimized.py}.
