# 1160. 连通所有集线器并使最长的电缆尽可能短

[Timus 1160](https://acm.timus.ru/problem.aspx?space=1&num=1160) · 难度 140 · dsu

原题作者 Andrew Stankevich，出自 2001 年 ACM ICPC 东北欧区域赛北部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`2 ≤ N ≤ 1000` 个集线器可以用 `1 ≤ M ≤ 15000` 条给定长度的可选电缆相连。选出
一些电缆，使每个集线器都能直接或经由其他集线器连到其余所有集线器，并使所选电缆
中最长的那条尽可能短。输出这个长度，然后输出电缆数和这些电缆。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N` 和 `M`，然后 `M` 行，每行是两个集线器（编号为 1 到 `N`）和一个长度，长度是 1
到 10⁶ 之间的整数。

## 输出

最长电缆的长度、电缆数 `P`，然后是 `P` 对集线器。

## 评测方式

只要方案用可选电缆连通所有集线器，且其最长电缆是可能的最小值，就被接受。
检查程序自己通过对长度二分并检查连通性求出这个最小长度，并验证输出的长度和
方案。

## 样例

### 样例 1

输入：

```
4 6
1 2 1
1 3 1
1 4 2
2 3 1
3 4 1
2 4 1
```

输出：

```
1
3
1 2
1 3
3 4
```

## 解法

Kruskal 算法从最短的电缆开始构造生成树，若电缆两端已经连通就跳过，用并查集来
判断。它构造的是最小生成树，而最小生成树同时使最长边最小：当 Kruskal 算法加入
最后一条、也是最长的边 `e` 时，比 `e` 短的电缆让集线器至少分成两组，所以任何
连通方案都需要一条不短于 `e` 的电缆。答案就是最后加入的边的长度，树的 `N − 1`
条电缆就是一个合法方案。`O(M log M)`（Go 为 `O(M log² M)`）。

注意事项：

- 方案不必是树，任何最长电缆最小的方案都被接受；
- 必须连到每个集线器，所以答案取 Kruskal 最后加入的边，而不是最后考察的边；
- 长度相等无需特殊处理。

答案已用检查程序在所有测试和 60 个随机网络上验证。

## 优化解法

优化的 C++ 解法从 4 KB 缓冲区中手工解析数字，而不是用 `scanf`，并把电缆存放在固
定大小的 8 字节记录数组中：长度用 `int`，两个集线器用 `uint16_t`，足以容纳不超过
1000 的编号。它用 `std::sort` 原地排序，而不是需要临时副本的
`std::stable_sort`；选够 `N − 1` 条电缆后就停止 Kruskal 算法，并用 `printf` 输
出，而不是先把输出拼成字符串：{1160_dsu_optimized.cpp}。

优化的 Java 解法从 4 KB 缓冲区中手工解析数字，而不是用 `StreamTokenizer`，并把每
条电缆打包成一个 `long`：两个集线器各占 10 位，足以容纳不超过 1000 的编号，长度
（不超过 10⁶）放在它们上面。对普通 `long` 数组排序就能按长度排好电缆，既不需要每
条电缆一个数组，也不需要比较器；选够 `N − 1` 条电缆后 Kruskal 算法即停止：
{1160_dsu_optimized.java}。

优化的 Python 解法按 8 KB 分块读入，逐块转换其中的词，而不是一次切分整个输入。它
把每条电缆打包成一个整数，长度放在两个 10 位的集线器编号（编号不超过 1000）上
面，这样普通的 `sort` 就能按长度排序，无需元组或键函数；选够 `N − 1` 条电缆后
Kruskal 算法即停止：{1160_dsu_optimized.py}。

优化的 Rust 解法从 4 KB 缓冲区中手工解析数字，而不是把整个输入读进 `String`。每
条电缆是一个 8 字节的元组，由 `u32` 长度和两个 `u16` 集线器组成，而不是三个
`usize` 值；排序用不需要额外缓冲区的 `sort_unstable`，选够 `N − 1` 条电缆后
Kruskal 算法即停止，输出经由 `BufWriter`：{1160_dsu_optimized.rs}。
