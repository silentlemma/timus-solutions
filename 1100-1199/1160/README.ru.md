# 1160. Соединение всех хабов так, чтобы самый длинный кабель был как можно короче

[Timus 1160](https://acm.timus.ru/problem.aspx?space=1&num=1160) · сложность 140 · dsu

Автор оригинальной задачи — Андрей Станкевич; северный подрегион полуфинала ACM ICPC Северо-Восточной Европы 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`2 ≤ N ≤ 1000` хабов можно соединить `1 ≤ M ≤ 15000` возможными
кабелями данной длины. Выбрать кабели, которые связывают каждый хаб с
каждым, напрямую или через другие, так, чтобы самый длинный выбранный
кабель был как можно короче. Вывести эту длину, затем число кабелей и
сами кабели.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `M`, затем `M` строк с двумя хабами, пронумерованными от 1 до
`N`, и длиной — целым числом от 1 до 10⁶.

## Выходные данные

Длина самого длинного кабеля, число кабелей `P`, затем `P` пар хабов.

## Проверка

Принимается любой план, который связывает все хабы возможными кабелями и
у которого самый длинный кабель наименьший из возможных. Проверяющая
программа сама находит эту наименьшую длину двоичным поиском по длинам с
проверкой связности и сверяет выведенные длину и план.

## Примеры

### Пример 1

Ввод:

```
4 6
1 2 1
1 3 1
1 4 2
2 3 1
3 4 1
2 4 1
```

Вывод:

```
1
3
1 2
1 3
3 4
```

## Решение

Алгоритм Краскала строит остовное дерево начиная с самых коротких
кабелей и пропускает кабель, концы которого уже связаны; это определяет
система непересекающихся множеств. Построенное дерево — минимальное
остовное, а минимальное остовное дерево минимизирует и самое длинное
ребро: когда алгоритм Краскала добавляет последнее, самое длинное ребро
`e`, кабели короче `e` оставляют хабы хотя бы в двух отдельных группах, так
что любому связному плану нужен кабель не короче `e`. Ответ — длина
последнего взятого ребра, а `N − 1` кабелей дерева — подходящий план.
`O(M log M)` (в Go — `O(M log² M)`).

Тонкие места:

- план не обязан быть деревом, и принимается любой план с наименьшим
  самым длинным кабелем;
- нужно достичь каждого хаба, поэтому ответ даёт последнее взятое
  Краскалом ребро, а не последнее рассмотренное;
- равные длины не требуют особой обработки.

Ответы проверены проверяющей программой на всех тестах и на 60 случайных
сетях.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает числа вручную из буфера на
4 КБ вместо `scanf` и хранит кабели в массиве постоянного размера из
8-байтовых записей: длина в `int`, а два хаба в `uint16_t`, куда
помещаются номера до 1000. Оно сортирует их на месте через `std::sort`
вместо `std::stable_sort`, которому нужна временная копия, останавливает
алгоритм Краскала после `N − 1` кабелей и печатает через `printf`, а не
собирает вывод в строку: {1160_dsu_optimized.cpp}.

Оптимизированное решение на Java разбирает числа вручную из буфера на
4 КБ вместо `StreamTokenizer` и упаковывает каждый кабель в один `long`:
два хаба по 10 бит, чего хватает для номеров до 1000, а над ними длина,
до 10⁶. Сортировка простого массива `long` упорядочивает кабели по длине
без массива на каждый кабель и без компаратора, а алгоритм Краскала
останавливается после `N − 1` кабелей: {1160_dsu_optimized.java}.

Оптимизированное решение на Python читает ввод кусками по 8 КБ и
преобразует токены кусок за куском, а не разбивает весь ввод сразу.
Каждый кабель упакован в одно целое: длина над двумя 10-битными номерами
хабов (номера не больше 1000), так что обычный `sort` упорядочивает
кабели по длине без кортежей и функции-ключа, а алгоритм Краскала
останавливается после `N − 1` кабелей: {1160_dsu_optimized.py}.

Оптимизированное решение на Rust разбирает числа вручную из буфера на
4 КБ, а не читает весь ввод в `String`. Кабель — 8-байтовый кортеж из
длины `u32` и двух хабов `u16` вместо трёх значений `usize`, сортировка
— `sort_unstable`, которой не нужен дополнительный буфер, алгоритм
Краскала останавливается после `N − 1` кабелей, а вывод идёт через
`BufWriter`: {1160_dsu_optimized.rs}.
