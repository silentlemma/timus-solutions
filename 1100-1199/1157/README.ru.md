# 1157. Наименьшее число плиток, дающее N прямоугольников, если на K плиток меньше давали M

[Timus 1157](https://acm.timus.ru/problem.aspx?space=1&num=1157) · сложность 200 · number_theory

Оригинальная задача — командный чемпионат Урала по программированию, Пермь, апрель 2001 года, английский тур.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Мальчик выкладывает все свои квадратные плитки в прямоугольники. По `M`,
`N` и `K` (`M, N ≤ 50`, `K ≤ 9999`) найти наименьшее число плиток `L`,
такое что из `L` плиток можно сложить ровно `N` разных прямоугольников, а
из `L − K` плиток — ровно `M`. Если такого `L` не больше 10000 нет, вывести
`0`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`M`, `N` и `K`.

## Выходные данные

Наименьшее `L` или `0`.

## Проверка

Все количества плиток `1..10000` независимо разложены на простые
множители; число делителей получено из показателей степеней. Так построена
эталонная таблица форм; её максимум — 32 прямоугольника. Реальный кандидат
Python проверен на 125 запросах: пример, отсутствующие количества форм,
`K = 9999`; ответ — первое совпадение в независимой таблице. Каждая из
пяти реальных программ также прошла 13 входов репозитория в Docker.
Это не исчерпывающая проверка всех входных троек. Затем все пять
кандидатов получили собственные Accepted.

## Примеры

### Пример 1

Ввод:

```
2 3 1
```

Вывод:

```
16
```

## Решение

Для `x` плиток каждая неупорядоченная пара делителей `a × b = x`,
`a ≤ b`, задаёт один прямоугольник; поворот не создаёт новую форму.
Пусть `d[x]` — число делителей. Сопоставив делителю частное, получаем
`shapes[x] = (d[x] + 1) // 2`: у квадрата средний делитель парный сам себе.

Простое решето увеличивает `d[x]` у каждого кратного каждого делителя
`1..B`, где `B = 10000`. Так каждый делитель учитывается ровно один раз.
Перебираем `L` по возрастанию от `K + 1` до `B` и проверяем оба требуемых
количества форм. Первое совпадение минимально; если его нет, выводим `0`.
Начало с `K + 1` обеспечивает `L − K ≥ 1`. Это обосновывает и подсчёт,
и выбор ответа. Время — `O(B log B)`, дополнительная память — `O(B)`.
Все пять исходных Accepted-файлов сохранены побайтово. Python создаёт
второй список количеств форм; нативные базовые версии вычисляют их
из таблицы делителей по мере надобности.

## Оптимизированные решения

Считаем неупорядоченные пары делителей сразу. Для каждой меньшей
стороны `a = 1..floor(sqrt(B))` увеличиваем ячейки `a², a² + a, …, B`.
Это ровно произведения `a × b` с `b ≥ a`. У любого прямоугольника есть
единственная меньшая сторона, поэтому он учтён один раз; квадрат тоже
учитывается один раз. Прежний возрастающий поиск даёт тот же ответ.

Достаточно одного байта на счётчик: у любого `x ≤ B` возможны не более
`floor(sqrt(x)) ≤ 100` меньших сторон. Поэтому не переполняется даже
знаковый `byte` Java. Таблица занимает `10001` байт без заголовка объекта,
ввода-вывода и среды выполнения. Время остаётся `O(B log B)`, память —
`O(B)`, но увеличений меньше, а хранение компактнее. Java также заменяет
`Scanner` на `StreamTokenizer`; Rust разбирает три входных числа без
сбора числового вектора. Это разные реализации того же подхода решетом
пар делителей, поэтому используется суффикс `_optimized`.

Относительно исходной базы на том же языке память C++ уменьшается
216 → 120 КБ (44,4%), Python — 712 → 428 КБ (39,9%), Java —
1620 → 420 КБ (74,1%). Записанное время C++ и Python не меняется;
Java также ускоряется 0,125 → 0,078 с (37,6%). Rust проходит по времени:
0,046 → 0,015 с (67,4%); память уменьшается лишь на 25,3%, 300 → 224 КБ.
У каждой опубликованной версии есть собственный Accepted точного исходника.

Кандидат Go тоже получил Accepted, но память уменьшается только на 8,2%,
1172 → 1076 КБ, а изменение 0,031 → 0,015 с составляет один тик таймера.
Один тик не подтверждает устойчивого ускорения, поэтому кандидат
не добавлен как оптимизированный исходник. Исходная база Go сохранена.

## Особенности языков

Рейтинговый срез — 2 ноября 2026 года. У оптимизированного C++ места
1 по времени и 2 по памяти против 73 отфильтрованных посылок других авторов;
цель достигнута. У Python места 2 и 2 против 16 посылок, у Java — 1 и 2
против пяти. По принятому более строгому профилю для языков кроме C++, где
нужно первое место по обеим метрикам, у этих двух остаются звёздочки,
несмотря на подтверждённый выигрыш. Выборки Go и Rust пусты: формальное
покрытие не доказывает конкурентного превосходства. Рейтинг и критерий
включения с выигрышем 30% учитываются раздельно.
