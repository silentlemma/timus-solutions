# 1119. 带有若干对角捷径的网格上的最短路线

[Timus 1119](https://acm.timus.ru/problem.aspx?space=1&num=1119) · 难度 70 · dp

原题作者 Leonid Volkov，出自 2001 年 10 月 USU Open Collegiate Programming Contest（Junior Session）。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

网格由 `N × M` 个边长 100 米的正方形街区组成（`0 < N, M ≤ 1000`）。路线从街区 `(1, 1)` 的西南角出发，沿街道只向北或向东走，到达街区
`(N, M)` 的东北角；给定的 `K ≤ 100` 个街区还可以沿从西南到东北的对角线穿过。求最短路线的长度，四舍五入到整米。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

`N M`，然后是 `K`，再是 `K` 行 `x y`，表示可以穿过的街区。

## 输出

最短长度（米），四舍五入。

## 评测方式

输出按记号逐个比较；多余的空白字符无关紧要。

## 样例

### 样例 1

输入：

```
3 2
3
1 1
3 2
1 2
```

输出：

```
383
```

## 解法

路线只向北和向东走，所以它用到的对角线构成一条两个坐标都严格递增的街区链，而任何这样的链都能走到。每条对角线把两条边（200 米）换成 `100√2`
米，所以最优路线使用最长的链。把街区排序，用最长上升子序列的平方复杂度动态规划求最长链；若有 `L` 条对角线，长度为
`100·(N + M − 2L) + 100√2·L`。`O(K²)`。

注意事项：

- 同一行或同一列的两个街区不能同时使用：链必须在两个坐标上都严格递增；
- 输入中的街区可能重复；
- 长度永远不会恰好位于两个整数正中间，因为当 `L > 0` 时 `100√2·L` 是无理数，所以普通的四舍五入是安全的。

答案经过验证：与一个对网格全部 `(N + 1)(M + 1)` 个路口做的动态规划（从西、从南或沿对角线到达）比对，覆盖所有测试和 60 个随机网格。

## 优化解法

优化的 C++ 解法把街区和链长存放在长度固定为 100 的数组中，而不是 `vector`，
并且不调用 `std::round`，直接用 `printf("%.0f")` 输出长度：长度永远不会恰好落在
两个整数正中间，因为 `L > 0` 时 `100√2·L` 是无理数。算法相同；内存为
148 KB，而不是 212 KB，时间不变。

优化的 Java 解法按 1 KB 分块读入并手工解析，而不是使用 `Scanner`；每个格子存成一
个数 `x · 1001 + y`，因此直接对 `int` 排序就能给坐标对排序，不需要比较器：
0.078 s，而不是 0.187 s；408 KB，而不是 3928 KB。
