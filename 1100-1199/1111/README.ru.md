# 1111. Сортировка квадратов по расстоянию до точки

[Timus 1111](https://acm.timus.ru/problem.aspx?space=1&num=1111) · сложность 383 · geometry

Оригинальная задача с Timus; автор и источник не указаны.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `n` закрашенных квадратов (`1 ≤ n ≤ 50`), каждый задан двумя
противоположными вершинами с целыми координатами из `(−9999, 9999)`;
квадраты могут быть повёрнуты под любым углом, а квадрат может
вырождаться в точку. Расстояние от точки `P` до квадрата — длина
кратчайшего отрезка от `P` до точки квадрата, так что оно равно 0, когда
`P` внутри. Вывести номера квадратов по возрастанию расстояния, при
равенстве — сначала меньший номер.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`n`, затем `n` строк `x1 y1 x2 y2` с двумя противоположными вершинами,
затем строка `x y` с точкой `P`.

## Выходные данные

Номера квадратов (с 1) в отсортированном порядке через пробел.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
2
0 0 1 1
0 3 1 4
0 0
```

Вывод:

```
1 2
```

## Решение

Посмотрим на каждый квадрат из его центра `C`, где
`D = (x2 − x1, y2 − y1)` — диагональ. Его стороны идут вдоль `D`,
повёрнутой на `±45°`, то есть вдоль `D ± D⊥`, где `D⊥` — `D`, повёрнутая
на `90°`. С удвоенным смещением `q = 2P − (x1 + x2, y1 + y2)`, целым,
проекции `q` на два направления сторон равны `s1 = |q · (D + D⊥)|` и
`s2 = |q · (D − D⊥)|`, и `P` внутри ровно тогда, когда обе не больше
`h = |D|²`. Снаружи избытки `a = max(0, s1 − h)` и `b = max(0, s2 − h)`
дают квадрат расстояния `(a² + b²) / (8h)`, а у квадрата-точки он равен
`|q|² / 4`.

Так каждый квадрат расстояния — точная дробь из целых, и два из них
сравниваются перекрёстным умножением, а при равенстве — по исходному
номеру. Точку `P` читаем и все выражения с ней вычисляем целыми
произвольной точности; фиксированной разрядности достаточно только для
ограниченных координат вершин и знаменателей. Сортировка делает
`O(n log n)` сравнений. Пусть `L` — максимальная десятичная длина
координаты `P` (не менее 1). При умножении столбиком верхняя оценка
времени — `O(n L² + n log n L)`, рабочей памяти — `O(n L)`.
Размер знаменателей ограничен.

Тонкие места:

- равенства часты — из-за симметричных квадратов и из-за `P` внутри
  нескольких из них, поэтому сравнение должно быть точным: в плавающей
  точке два равных расстояния могут упорядочиться как угодно;
- ограничение координат вершин не распространяется на `P`. В тесте
  `09` два расстояния равны, но числитель для квадрата равен `2^64`:
  расширять тип только при сравнении уже поздно. Даже 128 бит не
  хватит для любого допустимого `P`, поэтому чтение, проекции,
  возведение в квадрат и сравнение требуют произвольной точности;
- заданные вершины противоположные, а не соседние, и любая диагональ в
  любом направлении описывает один и тот же квадрат.

Ответы проверены отдельным точным вычислением с дробями: четыре вершины
строятся явно, принадлежность проверяется векторными произведениями, а
расстояние — наименьшее до четырёх сторон как отрезков. Сотни случайных
наборов, многие с равенствами, совпали.

## Оптимизированные решения

C++, Go и Rust сохраняют точные дроби квадратов расстояний и сортируют перекрёстным умножением, разрешая равенство по входному номеру. Буферы произведений при сравнении используются повторно. C++ и Rust также читают координаты запроса без ограничения длины сразу группами по девять десятичных цифр, совпадающими с разрядами основания 10⁹. Go хранит длинные целые со знаком в 30-битных блоках, читает координаты запроса напрямую из байтов и сортирует номера слиянием. Буферы арифметики и сравнения используются повторно. Rust разбирает байтовые токены, хранит координаты квадратов и номера в фиксированных массивах и выводит ответ одним фиксированным байтовым буфером. Для ввода и вывода Rust использует библиотеку времени исполнения C.

Принятая версия Go 1.14 x64 заняла 0.031 с при 0.015 с у базовой и использовала 800 KB при 1288 KB у базовой.

Принятые базовые реализации [1111_geometry.java](1111_geometry.java), [1111_geometry.py](1111_geometry.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

- Базовые C++ и Rust используют собственную знаковую арифметику по блокам. Базовая версия Go использует `math/big.Int` и `sort.Slice` с явным сравнением номеров при равенстве.
- Оптимизированная Go использует 30-битные блоки, читает координаты напрямую из байтов и сортирует номера слиянием с переиспользованием произведений сравнения.
- Java использует `BigInteger`, Python — собственные целые с отключённым ограничением длины десятичного ввода. Все версии сравнивают точные дроби квадратов расстояний, затем входные номера.
