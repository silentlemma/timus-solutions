# 1111. 按到一点的距离给正方形排序

[Timus 1111](https://acm.timus.ru/problem.aspx?space=1&num=1111) · 难度 383 · geometry

原题来自 Timus，未注明作者和出处。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `n` 个实心正方形（`1 ≤ n ≤ 50`），每个由两个相对顶点给出，坐标为 `(−9999, 9999)`
内的整数；正方形可以旋转任意角度，也可能退化成一个点。点 `P` 到正方形的距离是从 `P` 到正方形上一点的最短线段长度，所以 `P`
在内部时距离为 0。按距离输出正方形的编号，距离相同时编号小的在前。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

`n`，然后是 `n` 行 `x1 y1 x2 y2`，给出两个相对顶点，最后一行 `x y` 是 `P`。

## 输出

按排序后的顺序输出正方形编号（从 1 开始），用空格分隔。

## 评测方式

输出按记号逐个比较；多余的空白字符无关紧要。

## 样例

### 样例 1

输入：

```
2
0 0 1 1
0 3 1 4
0 0
```

输出：

```
1 2
```

## 解法

从每个正方形的中心 `C` 看它，`D = (x2 − x1, y2 − y1)` 是对角线。它的边沿着 `D` 旋转 `±45°` 的方向，即沿 `D ± D⊥`，其中
`D⊥` 是 `D` 旋转 `90°`。取加倍的偏移 `q = 2P − (x1 + x2, y1 + y2)`（全为整数），`q` 在两个边方向上的投影为
`s1 = |q · (D + D⊥)|` 和 `s2 = |q · (D − D⊥)|`，当且仅当两者都不超过 `h = |D|²` 时 `P` 在内部。在外部时，超出量
`a = max(0, s1 − h)` 与 `b = max(0, s2 − h)` 给出距离的平方 `(a² + b²) / (8h)`；退化为点的正方形则为 `|q|² / 4`。

于是每个距离平方都是整数构成的精确分数，两个分数通过交叉相乘比较，相等时比较原编号。读取 `P` 及计算所有涉及它的表达式时均使用任意精度整数；只有有界的顶点坐标和分母使用固定位宽整数。排序需要 `O(n log n)` 次比较。令 `L` 为 `P` 坐标的最大十进制长度（至少为 1），按普通竖式乘法估算，时间上界为 `O(n L² + n log n L)`，工作空间为 `O(n L)`。分母的大小有界。

注意事项：

- 距离相等很常见，来自对称的正方形以及 `P` 同时位于多个正方形内部，所以比较必须精确：浮点数可能把两个相等的距离排成任意顺序；
- 顶点坐标的限制不适用于 `P`。测试 `09` 的两个距离相等，但正方形的分子为 `2^64`，仅在最终比较时扩展位宽已经太迟。即使 128 位也不能覆盖所有合法的 `P`，因此读取、投影、平方及比较都必须支持任意精度；
- 给出的是相对顶点而不是相邻顶点，任一条对角线、任一方向都描述同一个正方形。

答案经过验证：与一个独立的分数精确计算比对，它显式构造四个顶点，用叉积判断包含关系，并取到四条边（作为线段）的最小距离。数百组随机数据（其中很多有相等距离）结果一致。

## 语言说明

- C++ 和 Rust 使用简短的有符号多字整数实现；Go 使用 `math/big.Int`，Java 使用 `BigInteger`，Python 使用自带整数并关闭十进制输入长度限制。所有版本使用相同的投影公式，比较精确分数后再比较原编号。
- Go 使用 `sort.Slice` 并显式用编号打破平局，避免 `sort.SliceStable` 的额外交换。
