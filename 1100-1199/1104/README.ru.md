# 1104. Наименьшее основание, в котором число делится на основание минус один

[Timus 1104](https://acm.timus.ru/problem.aspx?space=1&num=1104) · сложность 95 · number_theory

Автор оригинальной задачи — Игорь Гольдберг; Tetrahedron Team Contest, май 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Число записано цифрами `0`–`9` и буквами `A`–`Z` (`A` = 10, …, `Z` = 35),
их не больше `10^6`. Найти наименьшее основание `k`, `2 ≤ k ≤ 36`, в
котором эта строка — правильная запись числа, делящегося на `k − 1`.
Если такого нет, вывести `No solution.`

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Одна строка с цифрами.

## Выходные данные

`k` в десятичной записи или `No solution.`

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
A1A
```

Вывод:

```
22
```

## Решение

Так как `k ≡ 1 (mod k − 1)`, любая степень `k` даёт остаток 1 по модулю
`k − 1`, и число в системе с основанием `k` имеет тот же остаток, что и
сумма его цифр, — то же правило, что признак делимости на 9 в десятичной
системе. Поэтому один раз считаем сумму цифр `S` и наибольшую цифру `m`,
затем перебираем `k` от `max(m + 1, 2)` до 36 и выводим первое, для
которого `k − 1` делит `S`. `O(L)` для `L` цифр.

Тонкие места:

- основание должно быть больше любой цифры, поэтому перебор начинается с
  `m + 1`;
- в основании 2 всё делится на 1, так что у числа из нулей и единиц ответ
  всегда 2, в том числе у одиночного `0`;
- сумма цифр не больше `35 · 10^6` и помещается в 32 бита.

Ответы проверены переводом всей строки в каждое основание длинными целыми
Python и прямым взятием остатка.

## Оптимизированные решения

`1104_number_theory_optimized.go`. Сохраняется проверка по сумме цифр: в основании b число сравнимо с суммой цифр по модулю b-1. Входной токен просматривается один раз с накоплением суммы и наибольшей цифры; начальный максимум один обеспечивает первое основание не меньше двух. Основания greatest+1..36 проверяются по возрастанию, выводится первое подходящее либо точно No solution. Обе новые версии читают байты без сохранения строки числа, Rust также исключает вектор цифр. При L<=10^6 сумма не больше35·10^6 и помещается в знаковые32 бита. Время O(L+36), O(1) дополнительного состояния плюс фиксированные буферы среды. Переносимые os.Stdin.Read/os.Stdout.Write и прямое преобразование целых используют фиксированные буферы ввода и вывода по 4096 байт. Частичная запись обрабатывается до повторного использования буфера. Исходный простой вариант с Accepted сохранён.

По сравнению с `1104_number_theory.go`: время 0.031 s → 0.031 s; память 6608 KB → 812 KB.

Входной токен просматривается один раз с накоплением суммы и наибольшей цифры; начальный максимум один обеспечивает первое основание не меньше двух. Основания greatest+1..36 проверяются по возрастанию, выводится первое подходящее либо точно No solution. Обе новые версии читают байты без сохранения строки числа, Rust также исключает вектор цифр. При L<=10^6 сумма не больше35·10^6 и помещается в знаковые32 бита. Время O(L+36), O(1) дополнительного состояния плюс фиксированные буферы среды. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1104_number_theory.rs`: время 0.015 s → 0.031 s; память 7048 KB → 60 KB.

Оптимизированные решения (C++, Java, Python) вообще не хранят строку из
`10^6` цифр: они читают ввод кусками по 4 КБ (в Python — по 64 КБ) и
складывают цифры по ходу, поэтому памяти нужно мало при любой длине. Python
переводит целый кусок в значения цифр сразу через `bytes.translate` и
складывает его через `sum`, без цикла по символам на Python. C++:
0.015 с вместо 0.093 с и 96 КБ вместо 2640 КБ; Java: 372 КБ вместо
5448 КБ при том же времени; Python: 0.109 с вместо 0.265 с и 588 КБ
вместо 17808 КБ.
