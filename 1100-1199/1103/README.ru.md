# 1103. Окружность через три карандаша, делящая остальные пополам

[Timus 1103](https://acm.timus.ru/problem.aspx?space=1&num=1103) · сложность 504 · geometry

Автор оригинальной задачи — Катя Овечкина; Tetrahedron Team Contest, май 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` карандашей стоят в целых точках (`N` нечётно, `3 ≤ N ≤ 5000`,
координаты по модулю не больше `10^8`). Никакие три не лежат на одной
прямой, никакие четыре — на одной окружности. Нужно выбрать три
карандаша так, чтобы внутри окружности через них оказалось ровно
`(N − 3) / 2` остальных карандашей и столько же снаружи. Если такой
окружности нет, вывести `No solution`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк `x y`.

## Выходные данные

Координаты трёх карандашей, по одному карандашу в строке.

## Проверка

Подходит любая правильная окружность. Проверяющая программа убеждается,
что три точки — разные карандаши, и считает карандаши внутри и снаружи
окружности точным целочисленным определителем.

## Примеры

### Пример 1

Ввод:

```
7
0 0
1 0
2 -1
2 1
1 1
0 2
-3 -1
```

Вывод:

```
-3 -1
2 -1
1 1
```

## Решение

Решение есть всегда. Возьмём `A` — самый нижний карандаш (из самых
нижних самый левый) — и `B`, его соседа по выпуклой оболочке, выбранного
так, что все остальные карандаши лежат слева от прямой `AB`. Тогда любая
окружность через `A` и `B` делит эту полуплоскость одинаково: карандаш
`P` внутри окружности через `A`, `B` и `C` ровно тогда, когда он видит
отрезок `AB` под большим углом, чем `C`. Все углы `APB` меньше 180° и,
поскольку никакие четыре карандаша не лежат на одной окружности, все
различны. Отсортируем остальные `N − 2` карандаша по этому углу и
возьмём средний как `C`: `(N − 3) / 2` карандашей видят `AB` под большим
углом и лежат внутри, столько же — под меньшим и лежат снаружи.
`O(N log N)`.

Углы сравниваются без плавающей точки. Котангенс угла равен
`dot / cross`, где `dot = (A − P)·(B − P)`, а `cross` — удвоенная ориентированная
площадь `P`, `A`, `B`, положительная для каждого `P`. У большего угла
котангенс меньше, поэтому `P` идёт раньше `Q`, когда
`dot_P · cross_Q > dot_Q · cross_P`.

Тонкие места:

- координаты доходят до `10^8`, поэтому `dot` и `cross` ограничены
  по модулю `8 · 10^16` и `4 · 10^16`, а их произведения — `3.2 · 10^33`, далеко за 64 бита;
- сравнивать углы через `atan2` рискованно: два далёких карандаша могут
  видеть `AB` под углами, разница которых меньше ошибки округления;
- `B` должен быть соседом `A` по оболочке; для произвольной второй точки
  карандаши по разные стороны от `AB` не упорядочиваются одним углом.

Ответы проверены точным определителем «точка в окружности» на всех
тестах, включая случайные наборы из тысяч карандашей на всём диапазоне
координат.

## Оптимизированные решения

Go сохраняет ребро оболочки AB и упорядочивает остальные точки по возрастанию угла, поэтому больший котангенс идёт первым. Векторные произведения положительны. Сначала сравниваются знаки скалярных произведений, ноль считается неотрицательным. При одинаковых знаках math/bits.Mul64 даёт старшее и младшее слова точных модулей произведений. Сравнение начинается со старшего слова, а для двух отрицательных знаков порядок обращается. Координаты и произведения хранятся в одном массиве. Для каждого разбиения опорный элемент выбирается как медиана трёх точек. Если оставшийся отрезок убывает геометрически, работа занимает O(N). После максимум 2·bit_length(N−2) разбиений оставшийся отрезок сортируется. В худшем случае время O(N log N), память O(N). Для остальных языков подходят базовые версии.

Принятые базовые реализации [1103_geometry.cpp](1103_geometry.cpp), [1103_geometry.java](1103_geometry.java), [1103_geometry.py](1103_geometry.py), [1103_geometry.rs](1103_geometry.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

C++/Rust используют нативные128-битные произведения и выбор медианы. Исходные Go и Java сортируют длинными целыми; новый Go использует точные128-битные произведения из двух разрядов и выбор с ограничением глубины. Python сохраняет точную целочисленную реализацию.
