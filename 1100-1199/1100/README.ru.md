# 1100. Таблица результатов в том порядке, что дала бы сортировка пузырьком

[Timus 1100](https://acm.timus.ru/problem.aspx?space=1&num=1100) · сложность 44 · sorting

Автор оригинальной задачи — Павел Атнашев; Tetrahedron Team Contest, май 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` команд (`1 < N ≤ 150 000`) заданы парами из уникального номера
(`1 ≤ ID ≤ 10^7`) и числа решённых задач `M` (`0 ≤ M ≤ 100`). Старая
программа сортировала их пузырьком, меняя соседей, пока
`A[i] < A[i+1]` по `M`. Выведите такую же таблицу, но быстро.

Ограничение времени: 1 секунда. Ограничение памяти: 16 МБ.

## Входные данные

`N`, затем `N` строк с `ID` и `M`.

## Выходные данные

`N` строк с `ID` и `M` в порядке, который даёт сортировка пузырьком.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
8
1 2
16 3
11 2
20 3
3 5
26 4
7 1
22 4
```

Вывод:

```
3 5
26 4
22 4
16 3
20 3
1 2
11 2
7 1
```

## Решение

Сортировка пузырьком меняет только соседей с разным счётом, поэтому две
команды с одинаковым `M` никогда не обгоняют друг друга: результат —
устойчивая сортировка по убыванию `M`. Так как `M` принимает всего 101
значение, это делает сортировка подсчётом за один проход: кладём каждую
команду в корзину её счёта в порядке ввода, затем выводим корзины от 100
до 0. `O(N)`.

Подводные камни:

- неустойчивая сортировка перемешивает команды с одинаковым счётом, и
  ответ меняется;
- ограничение памяти — 16 МБ, поэтому команды хранятся компактно, а в
  Python ввод читается построчно и вывод пишется частями;
- 150 000 строк вывода требуют буферизации.

Ответы сверены с самой сортировкой пузырьком для таблиц до 300 команд и
с устойчивой сортировкой из библиотеки для больших таблиц.

## Особенности языков

- Python хранит номера в корзинах `array("i")`, по четыре байта на номер.
- Java делает устойчивую сортировку подсчётом с префиксными суммами по
  счёту вместо списков.
