# 1133. Член последовательности фибоначчиевого типа по двум другим членам

[Timus 1133](https://acm.timus.ru/problem.aspx?space=1&num=1133) · сложность 225 · number_theory

Оригинальная задача — четвертьфинал, центральный регион России, Рыбинск, 17–18 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Целочисленная последовательность, бесконечная в обе стороны, удовлетворяет
`F(k + 2) = F(k + 1) + F(k)` для всех `k`. По `F(i)` и `F(j)` при `i ≠ j`
найти `F(n)`. Все индексы лежат в `[−1000, 1000]`, и каждый член от
наименьшего до наибольшего из `i, j, n` не превосходит `2·10⁹` по модулю.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Пять целых чисел: `i`, `F(i)`, `j`, `F(j)`, `n`.

## Выходные данные

`F(n)`.

## Проверка

Ответ сравнивается как один целочисленный токен. Фактический новый
Python-исходник сверён с независимой прямой и обратной целочисленной
рекуррентностью на 2500 допустимых сгенерированных запросах и 100 нулевых.
Проверены переставленные и отрицательные индексы, запрос вне промежутка
и полный размах 2000. Оба новых исполняемых решения отдельно прошли
все 13 входов репозитория в Docker и имеют Accepted для точных байтов.
2600 дифференциальных проверок — запуски Python, не 2600 запусков Java.

## Примеры

### Пример 1

Ввод:

```
3 5 -1 4 5
```

Вывод:

```
12
```

## Решение

Упорядочим известные члены по индексам: `i < j`, `D=j−i`.
Пусть `H(0)=0, H(1)=1` — обычные числа Фибоначчи. Повторная подстановка
даёт `F(j)=H(D−1)·F(i)+H(D)·F(i+1)`. При `D≥1` число `H(D)>0`, поэтому
следующий член однозначно находится точным целочисленным делением.
Затем идём к нужному индексу вперёд сложением или назад по формуле
`F(k−1)=F(k+1)−F(k)`. Это доказывает корректность восстановления
и единственность ответа при гарантированном существовании последовательности.

Новые файлы `math` на Python, Go и Java используют длинные целые напрямую.
Им не нужны выбранное простое число, обратный элемент и доказательство
обратимости знаменателя. Для этих трёх языков это основная учебная версия.
При `W=max(i,j,n)−min(i,j,n)` выполняется `O(W)` операций с длинными
числами; коэффициенты занимают `O(W)` бит. Консервативная битовая оценка
времени — `O(W²)`, дополнительная память живых чисел — `O(W)` бит при
фиксированной границе входных значений. Это не `O(W)` операций постоянной
стоимости над машинными целыми.

Сохранённые файлы `number_theory` считают то же выражение по модулю
простого `P=4294967291`. Оно больше числа `4·10⁹+1` возможных ответов;
остаток выше `P/2` означает отрицательное значение. Все нужные числа
Фибоначчи с индексами от 1 до 2000 ненулевые по модулю `P` — это проверено
точной рекуррентностью, поэтому обращение по Ферма допустимо. Произведение
остатков помещается в беззнаковые 64 бита. Получаем `O(W)` времени над
машинными числами и постоянную числовую память; C++ и Rust обходятся
без внешних библиотек длинной арифметики.

Пять значений читаются как токены, независимо от переводов строк. Индексы
бывают отрицательными, соседними, переставленными и вне промежутка между
известными членами. Нулевая последовательность допустима даже на самых
далёких индексах. Точные и модульные реализации сверены с независимыми
рекуррентностями, включая длинные нулевые диапазоны и выход за заданный
промежуток.

## Оптимизированные решения

Неизменённый модульный Go — другой, оптимизированный алгоритм относительно
основной прямой Go-базы с длинными целыми: 1064 КБ вместо 1544 КБ,
экономия 31,1%. Время 0,015 с против 0,031 с отличается на один тик,
поэтому надёжное ускорение не заявлено. Прежние модульные Java/Python
сохранены как принятые математические альтернативы без названия
«оптимизированные».

Новые `math_optimized` на Java и Python сохраняют прямую точную арифметику
и добавляют доказанный ранний выход. Если оба известных члена нулевые,
из формулы восстановления и `H(D) > 0` следует нулевой соседний член.
Сложение вперёд и вычитание назад тогда дают нулевую последовательность
на всех целых индексах. Можно сразу вернуть ноль, не строя большие
коэффициенты Фибоначчи. Для остальных входов алгоритм прежний:
консервативно `O(W²)` битового времени и `O(W)` живых бит; в нулевом
случае арифметическая работа постоянна. Это частный случай той же
рекуррентности, без таблицы готовых ответов.

Сравниваем с основными базами `math`, а не со старыми модульными файлами.
Java Accepted занимает 536 КБ против 828 КБ: экономия 35,3%; время
0,093 с против 0,109 с — один тик, не надёжное доказательство ускорения.
Python явно запускается на PyPy 3.10: 256 КБ против 436 КБ базы CPython,
экономия 41,3%, но 0,140 с против 0,078 с — на 79,5% больше времени.
Сравнение внутри согласованного семейства Python включает смену
интерпретатора и не отделяет её эффект от раннего выхода. Обе версии
допущены по памяти, измеренной судьёй. Понятные прямые базы сохраняются.

## Особенности языков

Python использует встроенные целые, Go — `math/big`, Java — `BigInteger`.
C++ и Rust сохраняют принятые модульные реализации со стандартными
беззнаковыми числами. Модульная альтернатива Java применяет
`Long.remainderUnsigned` к переполненному 64-битному произведению.
Все входные значения точно представляются используемым токенизатором Java.

Сохранённый снимок от 2 ноября 2026 года использует согласованный
профиль: C++ — одновременно топ 15% или первые десять мест по двум
метрикам, остальные семейства — первое место по обеим. Допущенные версии
с недобором цели помечены звёздочкой. Пустые выборки конкурентов Go/Rust
дают формальное покрытие, а не доказательство превосходства.
