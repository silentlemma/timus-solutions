# 1133. 由两项求类斐波那契数列的另一项

[Timus 1133](https://acm.timus.ru/problem.aspx?space=1&num=1133) · 难度 224 · number_theory

原题出自 2001 年 10 月 17–18 日在雷宾斯克举行的俄罗斯中部赛区四分之一决赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个向两端无限延伸的整数数列对所有 `k` 满足 `F(k + 2) = F(k + 1) + F(k)`。
已知 `F(i)` 和 `F(j)`（`i ≠ j`），求 `F(n)`。所有下标都在 `[−1000, 1000]`
内，并且从 `i, j, n` 中最小的到最大的下标之间每一项的绝对值都不超过
`2·10⁹`。

时间限制：1 秒。内存限制：64 MB。

## 输入

五个整数：`i`、`F(i)`、`j`、`F(j)`、`n`。

## 输出

`F(n)`。

## 样例

### 样例 1

输入：

```
3 5 -1 4 5
```

输出：

```
12
```

## 解法

设 `i < j`（否则交换两对）。每一项都是 `F(i)` 与 `F(i + 1)` 的固定整数
组合：`F(j) = A·F(i) + B·F(i + 1)`，其中 `A`、`B` 是斐波那契数，把系数对从
`(1, 0)` 和 `(0, 1)` 出发推进 `j − i` 步即可得到。于是未知的
`F(i + 1) = (F(j) − A·F(i)) / B`，然后用 `F(k − 1) = F(k + 1) − F(k)` 从 `i`
向前或向后走到 `n`。

难点在于大小：`B` 可能是第 2000 个斐波那契数，远超 64 位，而答案很小。
所以所有运算都在素数 `P = 4294967291` 下取模进行。它大于 `4·10⁹ + 1` 个
可能的答案，因此 `F(n)` 的余数唯一确定它：大于 `P / 2` 的余数表示负值。
它小于 `2³²`，所以两个余数的乘积能放进无符号 64 位整数。除法就是乘以
`B^(P−2)`；这之所以可行，是因为下标 1 到 2000 的斐波那契数都不能被 `P`
整除（已直接验证）。与下标范围宽度 `W` 成线性：最多 4000 步。

注意事项：

- 虽然所有输入和答案都很小，中间值 `A` 和 `B` 却非常大，普通 64 位运算会
  溢出；
- `n` 可能在 `i` 到 `j` 的区间之外，任意一侧都可能；
- 给出的两个下标可能以任意顺序出现；
- 全零数列允许下标相距 2000，所以最多要走 2000 步。

答案已在所有测试和 200 个随机询问上与精确的大整数计算比对，同时验证了
输入满足 `2·10⁹` 的限制。

## 各语言说明

- 所有语言使用相同的模数和遍历。
- Java 没有无符号 64 位类型，但 `Long.remainderUnsigned` 能正确地对溢出
  回绕后的乘积取模。
