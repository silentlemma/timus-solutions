# 1110. Все вычеты, N-я степень которых даёт остаток Y

[Timus 1110](https://acm.timus.ru/problem.aspx?space=1&num=1110) · сложность 53 · bruteforce

Оригинальная задача — Болгарская национальная олимпиада по информатике, первый день.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `N`, `M` и `Y` (`0 < N < 999`, `1 < M < 999`, `0 < Y < 999`). Найти
все целые `X` из `[0, M − 1]`, для которых `X^N mod M = Y`.

Все три входных значения N, M и Y — целые числа.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N M Y` в одной строке.

## Выходные данные

Все такие `X` по возрастанию через пробел или `-1`, если их нет.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
2 6 4
```

Вывод:

```
2 4
```

## Решение

Кандидатов меньше тысячи, поэтому перебираем каждый `X` и считаем
`X^N mod M` быстрым возведением в степень, беря остаток по `M` после
каждого умножения. `O(M log N)`.

При быстром возведении result*b^e сравнимо с исходным X^N по модулю
M. Умножение result при нечётном показателе, затем возведение b
в квадрат и деление e пополам сохраняют инвариант. При e=0 получен
точный остаток. Каждый X от 0 до M-1 проверяется ровно один раз,
поэтому оставлены все и только корни, уже по возрастанию. Пустой
результат обосновывает -1. При N=1 работа на кандидата постоянная.

Функция степени использует O(1) арифметических слов. Простой C++
хранит O(M) целых корней; Go/Rust — строки корней и объединённый
ответ, Java — построитель ответа. Простой Python хранит целые корни
и форматированный вывод. При P байтах вывода это O(M+P); здесь корень
имеет не больше трёх цифр, поэтому O(M). Полный сохранённый ввод
добавляет I байтов в Python/Rust и быстром Go. Быстрый C++ выводит
корни сразу с O(1) состоянием; Java хранит O(M) флагов/байтов вывода;
быстрые Python/Go по-прежнему хранят строки корней и общий ответ.
Фиксированные библиотечные буферы учитываются отдельно.

Тонкие места:

- `Y` может быть равен `M` или больше; остаток таким не бывает, и тогда
  ответ `-1`;
- само `X^N` астрономически велико: остаток берётся на каждом шаге, а
  произведения остаются меньше `M²` и помещаются в 32 бита;
- при `N = 1` ответ — одно `Y`, если `Y < M`.

Ответы проверены простым повторным умножением, `N` умножений для каждого
`X`.

## Оптимизированные решения

`1110_bruteforce_optimized.java`. Java сохраняет полный поиск модульных корней быстрым возведением в степень, но объединяет x и M-x: при чётном N их степени равны, при нечётном противоположны по модулю M. Одно возведение проверяет оба остатка; ноль обрабатывается отдельно, при Y>=M корней нет. Булев массив отмечает корни, затем ограниченный байтовый буфер выводит их по возрастанию либо -1. При M<999 каждому корню нужно не более трёх десятичных цифр, поэтому достаточно 4*M байт ответа. Время O(M log N), дополнительная память O(M). Сохранён прямой разбор целых; таблицы ответов и другого теоретико-числового алгоритма нет.

Accepted точного исходника Java 1.8 №11327344: 0.078 с / 304 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/228, память 1/228. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Применимый критерий времени выполнен; отдельной цели языка нет, строка остаётся без звёздочки. Прежний документированный оптимизированный запуск №11303558: 0.109 с / 412 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1110_bruteforce_optimized.java`: 0.078 s / 304 KB; сохранённая учебная база `1110_bruteforce.java`: 0.109 s / 1568 KB.

`1110_bruteforce_optimized.py`. Обе Python-версии уже используют
трёхаргументный pow и один объединённый ответ. Быстрая сразу хранит
строки корней вместо списка целых с преобразованием при печати,
читает через stdin.buffer, пишет без конечного перевода строки,
явно сбрасывает вывод и вызывает os._exit(0). Проверки корней и
возрастающий порядок прежние, пустой список по-прежнему даёт -1.
Меняется обработка вывода и завершения, а не алгоритм перебора.

Accepted точного исходника CPython 3.12 №11327010: 0.062 с / 656 КБ. Сравнение, сохранённое 2026-11-20 для актуальных компиляторов семейства: место по времени 4/147, по памяти 118/147. При памяти меньше 1024 КБ строгий критерий учитывает только время.

- `1110_bruteforce_optimized.py`: 0.062 s / 656 KB; сохранённая учебная база `1110_bruteforce.py` (Python 3.12 x64): 0.078 s / 352 KB; изменение времени -20.5%; изменение памяти +86.4%.

Оптимизированное решение на C++ печатает каждый корень сразу, как только
он найден, а не собирает корни в вектор: 128 КБ вместо 196 КБ при том же
времени.
