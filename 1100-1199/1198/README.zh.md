# 1198. 哪些参议员能独自让法案通过

[Timus 1198](https://acm.timus.ru/problem.aspx?space=1&num=1198) · 难度 489 · graphs

原题作者：Nikita Rybak。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`N ≤ 2000` 名参议员每人都握有其中一些人的把柄。想通过某项法案的参议员会给自己
握有把柄的每个人打电话，请他们支持法案，并让他们也照样去打电话。所有参议员都
支持时法案才能通过。求出所有能这样独自让法案通过的参议员。

时间限制：1.5 秒。内存限制：96 MB。

## 输入

`N`，然后每名参议员一行，列出其握有把柄的参议员，以 `0` 结尾。

## 输出

在一行中按升序输出这些参议员的编号，最后是 `0`；没有的话只输出 `0`。

## 样例

### 样例 1

输入：

```
5
3 2 0
0
4 5 0
1 5 0
2 0
```

输出：

```
1 3 4 0
```

## 解法

从每名参议员向其握有把柄的每个人连一条边；答案就是能到达所有顶点的那些顶点。

从每个尚未标记的顶点出发做一次搜索，每次搜索只标记未标记的顶点。之前标记过的
顶点都到不了后面某次搜索的起点，否则起点早就被标记了，所以最后一次搜索的起点
位于一个没有其他强连通分量能进入的强连通分量中。如果这个起点不能到达所有人，
那么谁都不能：能到达所有人的顶点必然能到达起点，因而和它在同一个分量里。如果
能，答案恰好是能到达起点的那些顶点，沿反向边再搜索一次即可求出。`O(N + M)`（Python 为 `O(N² + M)`），
`M` 是把柄记录的条数，最多约 `4·10⁶`。

注意事项：

- 输入可能接近 20 MB，读入慢的代价比图上的计算还大；
- `4·10⁶` 条邻接记录要紧凑地存成平坦数组里的 32 位整数，才能稳稳地留在内存
  限制以内；
- 参议员可能出现在自己的列表里，也可能在同一列表里出现两次；
- 没有符合条件的人时，只输出一个 `0`。

答案已在 300 个随机小图和所有测试上与另一份基于位集传递闭包的独立解答比对。

C++ 教学版只存一个布尔邻接矩阵。正向搜索读一行，反向搜索读同一矩阵的一列。重复边只会再次设置同一个元素。先正向验证最后一次搜索的根，再反向找出所有能到达该根的顶点。每轮每个顶点最多入队一次，扫描 N 个元素。时间 O(N² + M)，空间 O(N²)。

## 优化解法

C++、Go、Rust 用 64 位字压缩正反邻接行；重复边和自环只重复置位。搜索时与未访问掩码相交，入队前清位，因此每点仅入队一次。保留最后一次搜索的根作为候选，验证它可达全图，再从它搜索反图。有万能起点时最后根必可达全图；验证后另一点万能当且仅当能到该根，所以反图搜索恰好给出答案。三次遍历合计 O(N⌈N/64⌉) 字，读入 O(M)。N=2000 两矩阵共 1024000 字节，无须存数百万独立边；队列 ID 适合 16 位。保留普通 CSR 文件；Java/Python 复用符合标准的基础版。

已通过评测的基础实现 [1198_graphs.java](1198_graphs.java), [1198_graphs.py](1198_graphs.py) 也满足快速版本的要求：在保存的比较快照中，时间和内存均符合前 15% 或前十名的排名收录规则。直接复用这些源文件，不创建相同副本。星号标记尚未达到该语言目标排名的版本。

## 各语言说明

以下说明针对基础实现。

- C++、Go、Java 和 Rust 都把两个图存成带偏移量的平坦数组，反向图通过计数
  构建。
- Python 把每名参议员的列表存成一个大整数，每名参议员占一个字节，通过
  `bytearray` 填充，这样逐条记录的工作都在内置函数中完成；搜索时每名参议员
  只需几次整集合运算，反向图则通过对各行做 `zip` 得到。输入一次性整体读入，
  在这里比逐行读取快得多。
