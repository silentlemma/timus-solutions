# 1155. Удаление частиц из вершин куба парами

[Timus 1155](https://acm.timus.ru/problem.aspx?space=1&num=1155) · сложность 171 · constructive

Оригинальная задача — командный чемпионат Урала по программированию, Пермь, апрель 2001 года, английский тур.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Восемь камер `A`–`H` стоят в вершинах куба (`A B C D` вокруг одной
грани, `E F G H` над ними в том же порядке), в каждой от 0 до 100
частиц. Одно действие создаёт или уничтожает две частицы в двух соседних
камерах, по одной в каждой. Вывести не больше 1000 действий, после
которых все камеры пусты, или `IMPOSSIBLE`.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Одна строка с восемью целыми числами от 0 до 100 — для `A`–`H` по порядку.

## Выходные данные

По действию в строке: две камеры и `+` или `-`; или `IMPOSSIBLE`.

## Проверка

Принимается любая подходящая последовательность. Проверяющая программа
повторяет действия: каждое должно соединять соседние камеры, ни одна
камера не может уйти ниже нуля, действий не больше 1000, и в конце все
камеры пусты. `IMPOSSIBLE` должно выводиться ровно тогда, когда суммы
двух сторон (см. ниже) различны.

## Примеры

### Пример 1

Ввод:

```
1 0 1 0 3 1 0 0
```

Вывод:

```
EF-
AE-
BA+
CB-
AE-
```

### Пример 2

Ввод:

```
0 1 0 1 2 3 2 2
```

Вывод:

```
IMPOSSIBLE
```

## Решение

Раскрасим вершины как шахматную доску: `A C F H` на одной стороне и
`B D E G` на другой. Каждое ребро соединяет стороны, поэтому каждое
действие меняет суммы обеих сторон на одно и то же, и их разность не
меняется. Если разность не ноль, ответ `IMPOSSIBLE`.

Иначе сначала один раз проходим двенадцать рёбер и уничтожаем на каждом
столько пар, сколько позволяют оба конца. Числа только убывают, так что
после этого у каждого ребра один конец пуст. Вершина, в которой ещё есть
частицы, имеет всех трёх соседей пустыми, а противоположная вершина —
единственная из другой стороны, не соседняя с ней, — держит все частицы
своей стороны. Раз суммы равны, остаётся по `k` частиц в двух
противоположных вершинах `u` и `w`. Между ними три ребра, `u x y w`, и
тройка «создать на `x y`, уничтожить на `u x`, уничтожить на `y w`»
убирает по одной из каждой. Первый проход занимает не больше 400
действий, остаток — не больше `3·100`, так что предел 1000 не достигается.

Тонкие места:

- пару можно уничтожить, только если в обеих камерах есть частица,
  поэтому в каждой тройке создание идёт первым;
- если все числа нулевые, не нужно ни одного действия (тест 03);
- все восемь чисел должны быть в одной строке; переносы между ними
  нарушают формат входа, а Python читает только первую строку;
- `IMPOSSIBLE` зависит только от сумм двух сторон, а не от распределения
  частиц.

Ответы проверены проверяющей программой на всех 13 сохранённых и
сгенерированных тестах. Независимый оракул и повторение действий подтвердили
ответы на 3000 малых случайных входах и 374 граничных случаях;
максимум — 500 действий.

`std::map`, читает через `scanf` вместо `iostream` и печатает каждую
операцию через `printf` сразу, а не собирает весь вывод в строку:

Оптимизированное решение на Java печатает те же операции, но хранит
количества и трёх соседей каждой вершины в массивах фиксированного
размера, индексированных буквой вершины, вместо словарей с упакованными
символами и списков, созданных лямбдами, и читает восемь чисел побайтно
блоками по 4 КБ вместо `Scanner`: {1155_constructive_optimized.java}.

Оптимизированное решение на Rust печатает те же операции, но хранит
количества и трёх соседей каждой вершины в массивах фиксированного

каждую операцию сразу в `BufWriter`, а не собирает весь вывод в строку:
{1155_constructive_optimized.rs}.
