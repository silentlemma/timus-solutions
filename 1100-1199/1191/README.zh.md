# 1191. 警察能否抓住不断换乘电车的小偷

[Timus 1191](https://acm.timus.ru/problem.aspx?space=1&num=1191) · 难度 249 · dp, math

原题作者 Leonid Volkov，出自 2002 年 3 月 2 日第五届中学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

小偷比警察领先 `L` 分钟，两人跑得一样快。在 `N` 个车站中的每一个，小偷都等一条
线路的电车（每 `Ki` 分钟一班，相位未知），坐到下一站；警察跟到同一站，坐同一线路
的下一班电车，若发现小偷还在等车就将其逮捕。所有电车速度相同。判断警察是否有
可能在 `N` 段乘车结束前抓住小偷。

时间限制：1 秒。内存限制：64 MB。

## 输入

`L` 和 `N`，然后是 `K1 … KN`，都是小于 100 的正整数。

## 输出

若有可能抓住，输出 `YES`，否则输出 `NO`。

## 评测方式

精确比较答案词元。每个新源码有完整目标环境检查、独立数学比较及哈希绑定的自身Accepted；保留简单版本的各自测量。

## 解法

设警察到站比小偷晚 `g`，发车间隔为 `K`。小偷等待 `w`，`0≤w<K`。
若 `g<K`，选择 `g<w<K` 即可让警察在小偷仍等待时赶到；若 `g≥K` 则本站抓不到。

未抓到时，警察比小偷晚整数个班次出发，间隔为 `K·ceil((g−w)/K)`。
写成 `g=qK+r`、`0≤r<K`，由 `w<K` 得出下界 `qK`。取 `w=r+(K−r)/2`
严格位于 `r` 与 `K` 之间，正好达到下界，不涉及到站与发车同时发生的约定。
相同乘车时间保留出发间隔，成为下一站到达间隔。

因此最佳下一状态为 `g−g%K`，零代表可能抓获。映射随 `g` 不减，所以较小
且可达的间隔不会损害后续机会。按路线归纳证明，逐次选择最小值当且仅当某个
合法时刻表允许抓获时得到零；遇零输出 YES，否则乘完 `N` 辆后输出 NO。
`g=K` 仍是 `K`，不能抓；间隔一不会减少正整数差。

时间 `O(N)`。C++/Go/Java 流式处理只需常量算术状态；旧 Python/Rust
保留 `O(N)` 输入 token。输入均为 1..99，除数为正，最小差不增，整数取模安全精确。

## 优化解法

**Java.** 新增 Java 保留相同取模递推及提前返回，只把 `Scanner` 换成
`InputStreamReader` 上的 `StreamTokenizer`。最多 101 个整数 token 不需
Scanner 的模式解析；这里小整数均可被 tokenizer 数值字段精确表示。
同算法的实现优化使用 `_optimized`。精确源码 Accepted 为 0.125 s、408 KB，
原 Java 为 0.125 s、1636 KB，内存减少 75.1%，时间未变。两版均保留；
不是递推或解释器变化带来的差异。

**Python/PyPy.** 保留正向模拟作为教学解。新算法逆向处理：最终正间隔的最小值为1。正向映射是k*floor(gap/k)，所以要保留至少needed，之前至少需ceil(needed/k)*k。依次逆向更新该阈值；它不会减小，因此一旦needed>L，就不可能保留正间隔，能够追上。否则L可通过全部站点而不被追上。整数输入列表从末尾弹出，不生成逆序切片。时间O(N)，输入存储O(N)；实测优势是内存而非耗时。
