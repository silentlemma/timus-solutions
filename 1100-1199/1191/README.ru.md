# 1191. Может ли полицейский догнать вора, пересаживающегося с трамвая на трамвай

[Timus 1191](https://acm.timus.ru/problem.aspx?space=1&num=1191) · сложность 249 · dp, math

Автор оригинальной задачи — Леонид Волков; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Вор опережает полицейского на `L` минут, бегут они с одной скоростью. На
каждой из `N` остановок вор ждёт трамвая маршрута, который ходит каждые
`Ki` минут с неизвестным сдвигом, и едет на нём до следующей остановки;
полицейский прибегает на ту же остановку и садится на следующий трамвай
того же маршрута, арестовывая вора, если застаёт его ещё ждущим. Все
трамваи едут с одной скоростью. Определить, может ли полицейский поймать
вора до того, как закончатся `N` поездок.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`L` и `N`, затем `K1 … KN`, все целые положительные меньше 100.

## Выходные данные

`YES`, если поимка возможна, иначе `NO`.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Решение

Пусть `g` — отставание полицейского при прибытии на остановку,
`K` — интервал трамваев. Вор ждёт время `w`, `0≤w<K`. При `g<K` можно
выбрать `g<w<K`: полицейский застанет вора ожидающим, поймать его возможно.
При `g≥K` на этой остановке поймать нельзя.

Иначе полицейский уезжает на целое число трамваев позже вора; разрыв
отправлений равен `K·ceil((g−w)/K)`. Запишем `g=qK+r`, `0≤r<K`.
Из `w<K` следует нижняя граница `qK`. Выбор `w=r+(K−r)/2` строго между
`r` и `K` достигает этой границы и не требует совпадения прибытия
полицейского с отправлением трамвая. Одинаковые времена поездки
сохраняют разрыв отправлений при прибытии на следующую остановку.

Лучшее следующее состояние — `g−g%K`; ноль означает возможность ареста.
Отображение не убывает по `g`, поэтому меньшее достижимое отставание
никогда не ухудшает шанс на последующих остановках. Индукция по маршрутам
доказывает: последовательность минимумов обнаружит арест тогда и только
тогда, когда он возможен при каком-либо допустимом расписании.
При нуле выводим YES, иначе после всех `N` трамваев — NO. Равенство
`g=K` оставляет `K`, а не даёт арест. Интервал один не уменьшает
положительное целочисленное отставание.

Время `O(N)`. Потоковые C++/Go/Java используют постоянную арифметическую
память; прежние Python/Rust сохраняют `O(N)` входных токенов. Все входные
числа от 1 до 99, делители положительны, минимальный разрыв не растёт:
обычное целочисленное взятие остатка безопасно и точно.

## Оптимизированные решения

**Java.** Добавленный Java сохраняет ту же арифметику и ранний выход. Вместо
`Scanner` использует `StreamTokenizer` над `InputStreamReader`: для максимум
101 целочисленного токена не нужен шаблонный разбор Scanner. Числа этого
диапазона точно представляются числовым полем токенизатора. Это та же
идея с другой реализацией, поэтому суффикс `_optimized`.

**Python/PyPy.** Прямую симуляцию остановок сохраняем как учебное решение. Новый алгоритм идёт назад: минимальный положительный конечный отрыв равен 1. Перед интервалом k для сохранения отрыва needed нужен как минимум ceil(needed/k)*k, поскольку прямое преобразование равно k*floor(gap/k). Заменяем needed этим порогом и просматриваем интервалы в обратном порядке. Порог не уменьшается, поэтому needed>L уже доказывает невозможность положительного конечного отрыва: поимка возможна. Иначе исходный L переживает все остановки и поимка невозможна. Список целых расходуется с конца без обратного среза. Время O(N), хранение ввода O(N); измеренный выигрыш относится к памяти, не к времени.
