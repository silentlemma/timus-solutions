# 1194. Сколько рукопожатий, когда компания расходится по домам

[Timus 1194](https://acm.timus.ru/problem.aspx?space=1&num=1194) · сложность 84 · math

Автор оригинальной задачи — Леонид Волков; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N ≤ 20000` хоббитов, среди которых `K` супружеских пар, вместе уходят с
вечеринки. На каждом перекрёстке группа делится на меньшие, и каждый
пожимает руку каждому, с кем расстаётся. Группы делятся, пока каждая не
станет одним хоббитом или супружеской парой. Разбиения заданы; посчитать
все рукопожатия.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `K`, затем для каждого разбиения номер группы, число новых групп и
номер и численность каждой из них.

## Выходные данные

Число рукопожатий.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
3 0
1 2 2 2 3 1
2 2 4 1 5 1
```

Вывод:

```
3
```

## Решение

Любые два хоббита, кроме супругов, пожимают руки ровно один раз — на том
разбиении, где они впервые оказываются в разных группах. Не расстаются
только супружеские пары, которые уходят домой вместе. Значит, ответ —
`N·(N − 1)/2 − K`, а описание разбиений не важно. `O(1)`, не считая
чтения первой строки.

Тонкие места:

- строки с разбиениями можно вообще не читать, но решение, которое
  складывает разведённые пары по каждому разбиению, получает то же число;
- `N·(N − 1)/2` доходит примерно до `2·10⁸`, что ещё помещается в 32 бита,
  хотя 64-битная арифметика здесь ничего не стоит.

Ответы сверены с отдельно написанным решением, считающим рукопожатия по
разбиениям, на 200 случайных компаниях и на всех тестах.

## Оптимизированные решения

`1194_math_optimized.java`. Сохраняется точная формула int n*(n-1)/2-married. Как и раньше, записи иерархии не влияют на ответ и после двух чисел заголовка не разбираются. Все числовые поля, нужные вычислению, потребляются до вывода. Один массив 256 байт сначала служит вводу, затем выводу; перед знаковым int резервируются двенадцать байт, разворачиваются только новые цифры. Убраны отдельные массивы ввода, вывода и цифр, нужные алгоритму данные не перезаписываются. Разбор и вывод линейны по потреблённым байтам, буфер фиксирован.

Accepted точного исходника Java 1.8 №11327761: 0.093 с / 356 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 10/106, память 3/106. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303576: 0.125 с / 308 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1194_math_optimized.java`: 0.093 s / 356 KB; сохранённая учебная база `1194_math.java`: 0.125 s / 1552 KB.

`1194_math_optimized.py` используется побайтово без изменений, без второго исходника и нового алгоритма. Accepted точного исходника на CPython 3.12 №11327016: 0.078 с / 652 КБ. Сохранённая выборка актуальных компиляторов семейства Python от 2026-11-20: место по времени 4/39, по памяти 24/39. Поскольку здесь меньше 1024 КБ, строгий критерий первых десяти мест или топ 15% учитывает только время; звёздочка сохраняет отдельную рейтинговую цель языка. У того же файла есть прежний Accepted на PyPy 3.10 №11324849: 0.125 с / 220 КБ. Это парные замеры разных запусков: CPython даёт выбранный результат по времени и рейтингу, PyPy расходует меньше памяти. Прежние замечания об экономии памяти в этом разделе относятся к этому замеру PyPy, а не к строке CPython. Все учебные исходники сохранены без изменений.

`1194_math_optimized.go`. Сохраняется число неупорядоченных пар хоббитов h(h−1)/2 за вычетом заданных пар. Нужны только скалярные вычисления и постоянная дополнительная память. Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1194_math.go`: время 0.015 s → 0.015 s; память 1064 KB → 280 KB.

`1194_math_optimized.cpp`. Сохраняется формула N(N-1)/2-K: каждая пара, кроме супружеской, разделяется ровно один раз независимо от описаний разбиений. Читаются лишь два числа заголовка, ответ выводится явным побайтовым преобразованием C вместо форматированного чтения и печати целых. Алгоритм и дополнительное состояние имеют постоянный размер.

По сравнению с `1194_math.cpp`: время 0.031 s → 0.015 s; память 128 KB → 80 KB.

`1194_math_optimized.py`. Читается только предусмотренная условием первая строка с N и K в виде байтов. Журнал разбиений остаётся непрочитанным: инвариант количества пар от него не зависит. Выводится N(N-1)/2-K, вывод явно сбрасывается, процесс завершается без обычной очистки интерпретатора. Строка всего ввода и список всех токенов не хранятся.

По сравнению с `1194_math.py`: время 0.093 s → 0.125 s; память 328 KB → 220 KB.

`1194_math_optimized.rs`. Тот же инвариант количества пар используется при чтении лишь двух знаковых целых через среду C. Описания разбиений не требуют хранения или обработки. Ручной десятичный вывод убирает форматирование Rust и целые строки ввода-вывода; при заданных границах чисел время и дополнительное состояние O(1).

По сравнению с `1194_math.rs`: время 0.015 s → 0.015 s; память 208 KB → 48 KB.
