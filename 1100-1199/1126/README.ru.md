# 1126. Максимум каждого окна из M подряд идущих показаний

[Timus 1126](https://acm.timus.ru/problem.aspx?space=1&num=1126) · сложность 92 · two_pointers

Автор оригинальной задачи — Александр Мироненко; VI студенческое соревнование по программированию УрГУ, 21 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны ширина окна `M` (`2 ≤ M ≤ 14000`) и `N` показаний
(`M ≤ N ≤ 25000`, каждое от 0 до 100000), оканчивающихся числом `-1`.
Вывести максимум показаний `1..M`, затем `2..M+1` и так далее до
последнего полного окна.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`M`, затем показания по одному в строке, затем `-1`.

## Выходные данные

`N − M + 1` максимумов окон, по одному в строке.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3
10
11
10
0
0
0
1
2
3
2
-1
```

Вывод:

```
11
11
10
0
1
2
3
3
```

## Решение

Храним двустороннюю очередь индексов, значения которых убывают от начала
к концу. Новое показание сначала убирает с конца все индексы, значение
которых не больше его собственного, — они уже не увеличат максимум, пока
новое в окне; затем встаёт в конец. Начало уходит, когда выпадает из
окна. Начало очереди всегда — максимум текущего окна. Каждый индекс
входит и выходит не более одного раза, так что весь проход — `O(N)`; пересчёт каждого
окна стоил бы `O(N·M)`, до примерно 156 миллионов шагов.

Тонкие места:

- показания заканчиваются числом `-1`, а не задаются количеством;
- из равных показаний с конца можно убрать все, кроме самого нового,
  которое уйдёт из окна последним;
- при `M = N` окно одно.

Ответы проверены прямым вычислением максимума каждого окна на всех
тестах.

## Оптимизированные решения

Оптимизированные решения (C++, Java) не хранят показания: каждое попадает
в дек вместе со своим номером сразу при чтении, а максимум полного окна
печатается немедленно. C++ читает через `getchar`; Java вручную разбирает
байтовый буфер, держит дек в кольцевом буфере из `M` ячеек — больше в окне
не бывает — и пишет числа через байтовый буфер. C++: 224 КБ вместо
776 КБ при том же времени; Java: 0.109 с вместо 0.156 с и 624 КБ вместо
2332 КБ.

Оптимизированные решения на Python и Rust тоже не хранят показания, а
держат только окно. Python держит его в кольцевом буфере из двух `array`
вместо дека и выводит ответы пачками по 256 строк: 668 КБ вместо 3448 КБ
при том же времени. Rust разбирает числа вручную из буфера на 4 КБ
вместо чтения всего ввода в строку и выводит каждый ответ через
буферизованный вывод, как только он известен: 332 КБ вместо 1192 КБ при
том же времени.

## Особенности языков

- В простых решениях Go и Java хранят очередь в массиве с движущимся
  началом; C++, Rust и Python используют библиотечные деки.
