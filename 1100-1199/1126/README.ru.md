# 1126. Максимум каждого окна из M подряд идущих показаний

[Timus 1126](https://acm.timus.ru/problem.aspx?space=1&num=1126) · сложность 92 · two_pointers

Автор оригинальной задачи — Александр Мироненко; VI студенческое соревнование по программированию УрГУ, 21 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны ширина окна `M` (`2 ≤ M ≤ 14000`) и `N` показаний
(`M ≤ N ≤ 25000`, каждое от 0 до 100000), оканчивающихся числом `-1`.
Вывести максимум показаний `1..M`, затем `2..M+1` и так далее до
последнего полного окна.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`M`, затем показания по одному в строке, затем `-1`.

## Выходные данные

`N − M + 1` максимумов окон, по одному в строке.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3
10
11
10
0
0
0
1
2
3
2
-1
```

Вывод:

```
11
11
10
0
1
2
3
3
```

## Решение

Храним двустороннюю очередь индексов, значения которых убывают от начала
к концу. Новое показание сначала убирает с конца все индексы, значение
которых не больше его собственного, — они уже не увеличат максимум, пока
новое в окне; затем встаёт в конец. Начало уходит, когда выпадает из
окна. Начало очереди всегда — максимум текущего окна. Каждый индекс
входит и выходит не более одного раза, так что весь проход — `O(N)`; пересчёт каждого
окна стоил бы `O(N·M)`, до примерно 156 миллионов шагов.

Тонкие места:

- показания заканчиваются числом `-1`, а не задаются количеством;
- из равных показаний с конца можно убрать все, кроме самого нового,
  которое уйдёт из окна последним;
- при `M = N` окно одно.

Ответы проверены прямым вычислением максимума каждого окна на всех
тестах.

## Оптимизированные решения

`1126_two_pointers_optimized.py`. Монотонная очередь сохраняется, но элемент кодируется одним целым (value<<15)|index: при N<=25000 достаточно 15 бит индекса. Порядок целых сначала сравнивает значение, затем возраст, поэтому новое равное значение вытесняет старое. Устаревшая голова удаляется, худшие хвосты отбрасываются, максимум извлекается через >>15. Каждый элемент добавляется и удаляется не более раза: O(N) амортизированного времени, O(M) элементов. Ввод по 4096 байт сохраняет неполный токен; вывод порциями по 512 ответов ограничивает временную память. Прямой вывод и os._exit(0) внутри main исключают обычную финализацию. Учебная версия с парами сохранена.

Accepted точного исходника Python 3.12 x64 №11327503: 0.093 с / 1452 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 2/54, память 2/54. При памяти от 1024 КБ строгий допуск требует порога и по времени, и по памяти: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11326680 (Python 3.12 x64): 0.109 с / 2152 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1126_two_pointers_optimized.py`: 0.093 s / 1452 KB; сохранённая учебная база `1126_two_pointers.py`: 0.14 s / 3448 KB.

Accepted точного исходника CPython 3.12 №11326680: 0.109 с / 2152 КБ. Сохранённая выборка актуальных компиляторов от 2026-11-20: место по времени 6/54, по памяти 4/54. Обе обязательные метрики проходят строгий критерий первых десяти мест или топ 15%, процентная граница округляется вверх. Звёздочка относится к отдельной цели Python — первому месту по обеим метрикам.

Прежняя документированная оптимизированная посылка №11303710 (Python 3.12 x64) имела 0.125 с / 668 КБ. У текущего запуска CPython 3.12 зафиксированы меньшее время и большая память. Это разные парные измерения судьи; сравнение включает выбор интерпретатора и разброс запусков. Разница с прежним оптимизированным запуском 0.016 с — один тик таймера; выбор обоснован сохранёнными рейтингами.

Оптимизированные решения (C++, Java) не хранят показания: каждое попадает
в дек вместе со своим номером сразу при чтении, а максимум полного окна
печатается немедленно. C++ читает через `getchar`; Java вручную разбирает
байтовый буфер, держит дек в кольцевом буфере из `M` ячеек — больше в окне
не бывает — и пишет числа через байтовый буфер. C++: 224 КБ вместо
776 КБ при том же времени; Java: 0.109 с вместо 0.156 с и 624 КБ вместо
2332 КБ.

Rust разбирает числа вручную из буфера на 4 КБ
вместо чтения всего ввода в строку и выводит каждый ответ через
буферизованный вывод, как только он известен: 332 КБ вместо 1192 КБ при
том же времени.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1126_two_pointers_parsing_implementation_optimized.go`. Разбор токенов и числовой вывод специализированы по реально используемым типам; неиспользуемые универсальные ветви удалены, алгоритм и комментарии сохранены. Вместо полного ввода хранится пополняемый буфер на 8192 байта. Значение токенов и обработка частичного чтения и EOF сохранены.

Accepted #11328910 (Go 1.14 x64): **0.031 s / 2344 KB**. Архивное сравнение: `1126_two_pointers.go` (Go 1.14 x64) — 0.062 s / 2896 KB (#11279328).

## Особенности языков

- В простых решениях Go и Java хранят очередь в массиве с движущимся
  началом; C++, Rust и Python используют библиотечные деки.
