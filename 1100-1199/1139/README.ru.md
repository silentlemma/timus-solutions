# 1139. Сколько кварталов пересекает полёт по диагонали над сеткой улиц

[Timus 1139](https://acm.timus.ru/problem.aspx?space=1&num=1139) · сложность 78 · number_theory

Оригинальная задача — четвертьфинал, центральный регион России, Рыбинск, 17–18 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` авеню и `M` улиц, `1 < N, M < 32000`, делят город на квадратные
кварталы. Вертолёт летит по прямой из юго-западного угла в
северо-восточный. Посчитать кварталы, над которыми он пролетел; квартал —
открытая внутренность своего квадрата, так что касание угла не считается.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `M`.

## Выходные данные

Число кварталов.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
4 3
```

Вывод:

```
4
```

### Пример 2

Ввод:

```
3 3
```

Вывод:

```
2
```

## Решение

Кварталы образуют сетку `a × b`, где `a = N − 1` и `b = M − 1`, а полёт —
её диагональ. Он сначала входит в один квартал, и каждый раз, когда
пересекает линию сетки, попадает в новый квартал. Он пересекает `a − 1`
внутренних вертикальных и `b − 1` внутренних горизонтальных линий, но во
внутреннем углу сетки пересекает по одной линии каждого вида
одновременно и попадает только в один новый квартал. Диагональ проходит
через точки `(k·a/g, k·b/g)`, так что встречает ровно `g − 1` внутренних
углов, где `g = gcd(a, b)`. Всего
`1 + (a − 1) + (b − 1) − (g − 1) = a + b − gcd(a, b)`. `O(log min(a, b))`.

Тонкие места:

- во входе количества линий, а не кварталов: из каждого вычитается
  единица;
- в квадратной сетке диагональ проходит через все углы на своём пути и
  пересекает только `a` кварталов;
- при одном ряде или столбце полёт пересекает все его кварталы.

Ответы сверены с подсчётом кварталов под диагональю по столбцам, с точными
округлениями вниз и вверх, для всех `N, M ≤ 40` и на всех тестах.

## Оптимизированные решения

`1139_number_theory_optimized.py`. Сохраняется формула пересечения сетки a+b-gcd(a,b), где a=N-1,b=M-1. НОД считается итеративным алгоритмом Евклида по остаткам. Поправка на пересечения углов прежняя; O(log min(N,M)) шагов с ограниченными целыми и O(1) дополнительного состояния. Это не новый геометрический алгоритм. Цикл НОД встроен вместо импорта math.gcd, два байтовых токена разбираются напрямую. Измеренный выигрыш относится к памяти судьи, а не к скорости Python-цикла по сравнению с нативной библиотекой. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1139_number_theory.py`: время 0.078 s → 0.125 s; память 400 KB → 220 KB.

`1139_number_theory_optimized.rs`. Сохраняется формула пересечения сетки a+b-gcd(a,b), где a=N-1,b=M-1. НОД считается итеративным алгоритмом Евклида по остаткам. Поправка на пересечения углов прежняя; O(log min(N,M)) шагов с ограниченными целыми и O(1) дополнительного состояния. Это не новый геометрический алгоритм. Итеративный цикл заменяет рекурсивный НОД, прямой числовой ввод-вывод исключает сохранённую входную String. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1139_number_theory.rs`: время 0.015 s → 0.031 s; память 248 KB → 56 KB.

Оптимизированное решение на Java читает два числа побайтно через
`System.in.read` вместо `Scanner` и считает НОД в цикле, а не рекурсией.
Формула та же; решению нужно 360 КБ вместо 1592 КБ при том же времени.
