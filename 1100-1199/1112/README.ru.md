# 1112. Как можно больше отрезков без общих внутренних точек

[Timus 1112](https://acm.timus.ru/problem.aspx?space=1&num=1112) · сложность 165 · greedy

Оригинальная задача — Болгарская национальная олимпиада по информатике, второй день.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На прямой даны `N` отрезков (`1 ≤ N ≤ 99`), отрезок `i` — от `A_i` до
`B_i`, целые `−999 ≤ A_i < B_i ≤ 999`. Убрать как можно меньше отрезков
так, чтобы никакие два оставшихся не имели общей внутренней точки; концы
могут касаться. Вывести оставшиеся отрезки.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк `A_i B_i`.

## Выходные данные

Число `P` оставленных отрезков, затем `P` строк `A B` по возрастанию левых
концов. Подходит любой оптимальный ответ.

## Проверка

Подходит любой оптимальный ответ. Проверяющая программа находит
наибольшее возможное число отрезков квадратичной динамикой и убеждается,
что вывод оставляет столько же, берёт их из входа, перечисляет по левым
концам и не содержит двух перекрывающихся.

## Примеры

### Пример 1

Ввод:

```
3
3 6
1 3
2 5
```

Вывод:

```
2
1 3
3 6
```

## Решение

Это задача о выборе заявок. Отсортируем отрезки по правым концам и будем
брать каждый, который начинается не раньше правого конца последнего
взятого. Отрезок, который кончается первым, всегда входит в какой-то
оптимальный ответ: в любом оптимальном наборе отрезок с самым левым
правым концом можно заменить на него, не создав перекрытия. Повторяя
рассуждение для остальных, получаем правильность жадного выбора.
Оставленные отрезки не пересекаются, поэтому их порядок по правым концам
совпадает с порядком по левым. `O(N log N)`.

Тонкие места:

- касающиеся отрезки (один кончается там, где начинается следующий) не
  имеют общей внутренней точки и могут остаться оба;
- сортировка по левому концу или по длине с жадным выбором даёт неверные
  ответы: длинный отрезок, начинающийся первым, может закрыть несколько
  коротких;
- отрезки могут повторяться; каждая копия — отдельный отрезок, но остаться
  может не больше одной.

Ответы проверены проверяющей программой на всех тестах и на 150 случайных
наборах, в том числе с цепочками касающихся, повторяющимися и вложенными
отрезками.

## Оптимизированные решения

`1112_greedy_optimized.py`. Сохраняются жадный выбор по раннему концу и допустимость касания концов. Кортежи (конец,начало) сортируются напрямую вместо отдельного входного списка и key-функции. Выбранные отрезки уплотняются в префикс того же списка и выводятся без второго списка и объединённой строки. Время O(n log n), память O(n). При равных концах возможен другой допустимый оптимум, проверенный конструктивным чекером. Вывод сбрасывается перед прямым завершением PyPy.

По сравнению с `1112_greedy.py`: время 0.078 s → 0.125 s; память 460 KB → 272 KB.

Оптимизированное решение на C++ хранит отрезки в одном глобальном
массиве из 99 пар, ведь `N ≤ 99`, вместо двух `vector`, и записывает
оставленные отрезки в начало того же массива: оставленный отрезок
занимает место лишь уже просмотренного. Память в куче не выделяется:
{1112_greedy_optimized.cpp}.

Оптимизированное решение на Java читает ввод блоками по 4 КБ и разбирает
числа со знаком вручную вместо `Scanner`, хранит концы в двух массивах
`int` вместо отдельного массива на каждый отрезок и сортирует их
вставками, что при `N ≤ 99` дёшево и не требует компаратора; оставленные
отрезки записываются в начало тех же массивов:
{1112_greedy_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1112_greedy_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +41.67%; база: `1112_greedy.cpp`.

- `1112_greedy_optimized.java`: сокращение времени +40.38%; сокращение
  памяти +89.45%; база: `1112_greedy.java`.

`1112_greedy_optimized.rs`. Сохраняется жадный выбор по раннему правому концу; касание концами допустимо. Единственный вектор отрезков сортируется sort_unstable_by_key, выбранные отрезки уплотняются в уже просмотренный префикс. Отдельные вектор ответа и строковый построитель не нужны. Равные правые концы могут менять порядок: принимается любой оптимальный допустимый набор. Время O(N log N), память O(N). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1112_greedy.rs`: время 0.015 s → 0.031 s; память 232 KB → 64 KB.
