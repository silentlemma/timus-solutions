# 1182. Две команды взаимных знакомых, как можно более равные

[Timus 1182](https://acm.timus.ru/problem.aspx?space=1&num=1182) · сложность 507 · graphs

Авторы оригинальной задачи — Владимир Котов и Роман Елизаров; полуфинал ACM ICPC Северо-Восточной Европы 2001–2002.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`2 ≤ N ≤ 100` человек перечисляют, кого они знают; знакомство не
обязательно взаимное. Разбить всех на две непустые команды так, чтобы в
каждой команде каждый знал каждого, а размеры команд были как можно
ближе, или сообщить, что разбиения нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем для каждого человека список тех, кого он знает, кончающийся 0.

## Выходные данные

`No solution` или две строки, в каждой размер команды и её члены.

## Проверка

Принимается любое разбиение, в котором обе команды непусты, покрывают
всех, состоят из взаимно знакомых и отличаются по размеру как можно
меньше; лучшую разницу проверяющая программа берёт из сохранённого
ответа.

## Примеры

### Пример 1

Ввод:

```
5
3 4 5 0
1 3 5 0
2 1 4 5 0
2 3 5 0
1 2 3 4 0
```

Вывод:

```
No solution
```

### Пример 2

Ввод:

```
5
2 3 5 0
1 4 5 3 0
1 2 5 0
1 2 3 0
4 3 2 1 0
```

Вывод:

```
3 1 3 5
2 2 4
```

## Решение

Назовём двоих незнакомыми, если хотя бы один не знает другого. Незнакомые
должны быть в разных командах, значит, граф незнакомств должен быть
двудольным, что проверяет раскраска обходом в ширину; нечётный цикл
означает `No solution`. У каждой компоненты связности этого графа две
доли, и они должны попасть в разные команды, в любом из двух вариантов.
Люди из разных компонент знают друг друга взаимно, так что любое
сочетание выборов допустимо.

Остаётся рюкзак: `reach[k][s]` говорит, могут ли первые `k` компонент
дать первой команде ровно `s` человек, и запоминает выбранную долю.
Берём достижимое `s`, ближайшее к `N/2`, и обратным ходом собираем
команды. `O(N²)`.

Тонкие места:

- знакомство во входе одностороннее, поэтому пара считается знакомой,
  только если оба указали друг друга;
- компонента из одного человека может пойти в любую команду, это и
  позволяет выровнять размеры;
- обе команды автоматически непусты: у компоненты с незнакомыми обе доли
  непусты, а одиночек рюкзак распределяет.

Ответы сверены с отдельно написанным решением на 300 случайных группах
до 41 человека, двенадцать из которых без решения, и каждое выведенное
разбиение прошло проверяющую программу.

## Оптимизированные решения

Go и Rust сохраняют двудольность графа несовместимости и выбор ориентаций компонент. Пара несовместима, если отсутствует хотя бы одно направление знакомства. Строка хранится двумя 64-битными словами в Go или u128 в Rust. BFS пересекает строку с маской своего цвета для обнаружения конфликта и перебирает только непосещённых соседей по младшему биту. Компонента хранит две маски участников и размеры a,b. Достижимость обновляется как (old<<a)|(old<<b), одна маска истории сохраняется на компоненту. Перестановкой команд можно добиться, чтобы размер первой команды s был не больше floor(N/2). Разность размеров равна N−2s, поэтому выбираем максимальное достижимое s≥1. Если его нет, двух непустых команд не получится. Ориентации восстанавливаем по истории. При N≤100 размеры помещаются в 128 бит. Время O(N²), основная работа — ввод и проверка пар; маски заменяют булевы и целочисленные матрицы. Простые версии сохранены; остальные семейства используют подходящие базы.

Принятые базовые реализации [1182_graphs.cpp](1182_graphs.cpp), [1182_graphs.java](1182_graphs.java), [1182_graphs.py](1182_graphs.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Исходные версии используют матрицу знакомств и скалярный рюкзак. Новые Go/Rust используют упакованные строки и историю достижимости; Go явно обрабатывает сдвиг через64 бита, Rust использует u128. Восстановление сохраняет участников компонент и исключает пустые команды.
