# 1180. Кто выиграет, если камни берут степенями двойки

[Timus 1180](https://acm.timus.ru/problem.aspx?space=1&num=1180) · сложность 89 · games

Автор оригинальной задачи — Дмитрий Филимоненков; третье личное первенство УрГУ по программированию, Екатеринбург, 16 февраля 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В кучке `N ≤ 10²⁵⁰` камней. Двое по очереди берут из неё степень двойки
(1, 2, 4, 8, …) камней; кто взял последний камень, тот выиграл. Сказать,
кто выигрывает при правильной игре, а если первый — наименьшее число
камней, которое он может взять первым ходом, сохранив выигрыш.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, до 251 цифры.

## Выходные данные

`2` либо `1` и наименьший выигрывающий первый ход.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
8
```

Вывод:

```
1
2
```

## Решение

Ни одна степень двойки не делится на 3, поэтому из кучки, кратной 3,
любой ход оставляет некратную 3. Из любой другой кучки взятие 1 или 2
камней — остатка по модулю 3 — оставляет кратную 3. Ноль кратен 3, так что
игрок, всегда оставляющий кратную 3 кучку, берёт последний камень. Второй
выигрывает ровно тогда, когда `N` делится на 3; иначе выигрывает первый, а
наименьший выигрывающий ход — `N mod 3`, ведь никакой другой ход в 1 или 2
камня не оставляет кратную 3. `N mod 3` — это сумма цифр по модулю 3.
`O(цифр)`.

Тонкие места:

- в `N` до 251 цифры, так что 64-битного целого не хватит;
- выигрывающий ход должен быть наименьшим, а 1 и 2 — степени двойки, так
  что это и есть сам остаток.

Ответы проверены прямым перебором игры для всех `N` до 399.

## Оптимизированные решения

Оптимизированные решения (C++, Java) складывают цифры по одной по мере
чтения через `getchar` и `System.in.read`, не сохраняя число строкой, и
выводят короткий ответ побайтно. C++: 88 КБ вместо 384 КБ при том же
времени; Java: 0.093 с вместо 0.125 с и 328 КБ вместо 1568 КБ.

`1180_games_optimized.py`. Сохраняется классификация игры со степенями двойки по остатку N на три. Нулевой остаток проигрывает; иначе снятие остатка, одного или двух камней, — наименьший выигрышный ход. D десятичных цифр обрабатываются без преобразования всего огромного числа в целое. Коды байтов цифр суммируются напрямую: ASCII-ноль равен 48 и делится на три, поэтому остаток прежний. Байтовая строка по-прежнему хранится: O(D) времени и O(D) памяти ввода. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1180_games.py`: время 0.078 s → 0.125 s; память 400 KB → 236 KB.

`1180_games_optimized.rs`. Сохраняется классификация игры со степенями двойки по остатку N на три. Нулевой остаток проигрывает; иначе снятие остатка, одного или двух камней, — наименьший выигрышный ход. D десятичных цифр обрабатываются без преобразования всего огромного числа в целое. Ограниченный остаток обновляется для каждой входящей цифры, строка ввода не сохраняется. Время O(D), дополнительное состояние O(1). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1180_games.rs`: время 0.015 s → 0.031 s; память 212 KB → 56 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1180_games_optimized.py`: место по времени 64/77, по памяти 3/77 в этой сопоставимой выборке.

`1180_games_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
