# 1129. Покраска дверей: с одной стороны зелёная, с другой оранжевая, и в каждой комнате почти поровну

[Timus 1129](https://acm.timus.ru/problem.aspx?space=1&num=1129) · сложность 378 · graphs

Автор оригинальной задачи — Магаз Асанов; VI студенческое соревнование по программированию УрГУ, 21 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В здании `N ≤ 100` комнат, соединённых дверями; между двумя комнатами
может быть несколько дверей. Каждая дверь с одной стороны зелёная, с
другой оранжевая. Нужно покрасить двери так, чтобы в каждой комнате
число зелёных и оранжевых сторон дверей отличалось не больше чем на
единицу. Если это невозможно, вывести `Impossible`.

Ограничение времени: 0,25 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк: число дверей комнаты и номера комнат, куда они
ведут, по возрастанию.

## Выходные данные

`N` строк: цвета дверей каждой комнаты в порядке ввода, `G` — зелёный,
`Y` — оранжевый, или слово `Impossible`.

## Проверка

Принимается любая подходящая раскраска. Проверяющая программа смотрит,
что у каждой комнаты по одному цвету на каждую дверь, что в каждой
комнате цвета уравновешены с точностью до одного и что для каждой пары
комнат двери между ними зелёные ровно с одной стороны. Двери между одними
и теми же комнатами неотличимы, поэтому считаются зелёные метки по паре,
а не отдельные двери.

## Примеры

### Пример 1

Ввод:

```
5
3 2 3 4
3 1 3 5
4 1 2 4 5
3 1 3 5
3 2 3 4
```

Вывод:

```
G Y G
Y G Y
G Y Y G
Y G G
G Y Y
```

## Решение

Комнаты — вершины, двери — рёбра. Каждую пару параллельных дверей код
заменяет петлёй в каждой комнате. Покрасить дверь в зелёный в комнате `u`
и в оранжевый в комнате `v` — то же самое, что направить ребро из `u` в
`v`, так что нужна ориентация, где у каждой вершины полустепени исхода и
захода отличаются не больше чем на единицу. Такая ориентация есть
всегда. Добавим фиктивную вершину и соединим её лишним ребром с каждой
вершиной нечётной степени; таких вершин чётное число, так что теперь все
степени чётные. Тогда у каждой компоненты связности есть эйлеров цикл, и
обход по нему выходит из каждой вершины столько же раз, сколько входит.
Направим каждое ребро по ходу обхода и выбросим лишние рёбра: вершина
теряет не больше одного ребра, поэтому её два счёта отличаются не больше
чем на единицу. Для `D` дверей ожидаемое время — `O(N + D)` с хеш-таблицами,
`O(N + D log D)` с упорядоченным словарём C++.

Тонкие места:

- ответ `Impossible` не бывает никогда;
- дверь упоминается в строках обеих своих комнат; упоминания каждой пары
  комнат связываются попарно в порядке просмотра. Двери между одними
  комнатами взаимозаменяемы;
- цикл обходится явным стеком с указателем на следующее неиспользованное
  ребро у каждой вершины, так что каждое ребро просматривается константное
  число раз;
- для комнаты без дверей выводится пустая строка.

Ответы проверены проверяющей программой на всех тестах и на случайных
зданиях с большим числом повторяющихся дверей между одними комнатами.

## Оптимизированные решения

`1129_graphs_optimized.py`. Сохраняются точное сокращение противоположных параллельных пар и эйлерова ориентация остатка после присоединения нечётных комнат к фиктивной. Соседи комнаты отсортированы, поэтому itertools.groupby считает равные серии в нативном коде. Остаточные соседи хранятся битовыми целыми, младшее доступное ребро удаляется XOR, цвета разворачиваются по исходным кратностям; пары дверей в ту же комнату сбалансированы. Отпечатков ответов нет. Для N комнат, D упоминаний и B=ceil(N/w) разрядов целого: O(D+N²B) работы и O(N²+максимальная степень строки) памяти с построчным вводом/выводом. При N<=100 битовые наборы занимают несколько разрядов. Учебные графовые версии сохранены. Здесь w — число битов разряда длинного целого Python.

Accepted точного исходника CPython 3.12 №11327005: 0.078 с / 752 КБ. Сравнение, сохранённое 2026-11-20 для актуальных компиляторов семейства: место по времени 1/83, по памяти 1/83. При памяти меньше 1024 КБ строгий критерий учитывает только время.

- `1129_graphs_optimized.py`: 0.078 s / 752 KB; сохранённая учебная база `1129_graphs.py` (Python 3.12 x64): 0.078 s / 2560 KB; изменение времени +0.0%; изменение памяти -70.6%.

`1129_graphs_optimized.java`. Сохраняется ориентация эйлеровым обходом после виртуального соединения нечётных комнат с фиктивной. D упоминаний сторон дверей хранятся плоско со смещениями комнат, исходными позициями и индексами пар. Сортируются long-ключи (неупорядоченная пара комнат,исходная позиция): параллельные двери связывают две половины упоминаний в порядке позиций, петли спариваются подряд. При N<=100 ключ пары меньше10000 и отделён от младших32 бит позиции. Настоящие рёбра получают противоположные G/Y, виртуальные только выравнивают чётность и не выводятся. Примитивный стек и байтовые цвета заменяют объектную смежность, хеш-очереди и построитель всего ответа. Память O(N+D). При стоимости примитивной сортировки S(D) остальная работа O(N+D); обычно Java8 даёт O(D log D), но консервативно допускается худшее O(D²), без строгого обещания логарифмической границы.

По сравнению с `1129_graphs.java`: время 0.156 s → 0.109 s; память 3876 KB → 832 KB.

C++ и Python считают двери для каждой пары комнат. Противоположные направления двух параллельных дверей уравновешиваются в обеих комнатах, поэтому в остаточном графе между комнатами не более одного ребра. После добавления фиктивных рёбер все степени чётны. Идём по неиспользованным рёбрам до замыкания обхода и ориентируем их по ходу. C++ просматривает матрицу монотонными указателями; Python обходит остаточные битовые целые, как описано выше. Обе версии разворачивают исходные кратности в порядке входа.

Сохранённые принятые базы [1129_graphs.go](1129_graphs.go), [1129_graphs.rs](1129_graphs.rs) также проходят строгий критерий первых десяти мест или топ 15% по требуемым метрикам в сохранённом сравнении. Они используются без одинаковых исходников. Остальные учебные версии сохранены; звёздочка означает отдельную рейтинговую цель языка.
