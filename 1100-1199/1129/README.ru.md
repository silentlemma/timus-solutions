# 1129. Покраска дверей: с одной стороны зелёная, с другой оранжевая, и в каждой комнате поровну

[Timus 1129](https://acm.timus.ru/problem.aspx?space=1&num=1129) · сложность 406 · graphs

Автор оригинальной задачи — Магаз Асанов; VI студенческое соревнование по программированию УрГУ, 21 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В здании `N ≤ 100` комнат, соединённых дверями; между двумя комнатами
может быть несколько дверей. Каждая дверь с одной стороны зелёная, с
другой оранжевая. Нужно покрасить двери так, чтобы в каждой комнате
число зелёных и оранжевых сторон дверей отличалось не больше чем на
единицу. Если это невозможно, вывести `Impossible`.

Ограничение времени: 0,25 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк: число дверей комнаты и номера комнат, куда они
ведут, по возрастанию.

## Выходные данные

`N` строк: цвета дверей каждой комнаты в порядке ввода, `G` — зелёный,
`Y` — оранжевый, или слово `Impossible`.

## Проверка

Принимается любая подходящая раскраска. Проверяющая программа смотрит,
что у каждой комнаты по одному цвету на каждую дверь, что в каждой
комнате цвета уравновешены с точностью до одного и что для каждой пары
комнат двери между ними зелёные ровно с одной стороны. Двери между одними
и теми же комнатами неотличимы, поэтому считаются зелёные метки по паре,
а не отдельные двери.

## Примеры

### Пример 1

Ввод:

```
5
3 2 3 4
3 1 3 5
4 1 2 4 5
3 1 3 5
3 2 3 4
```

Вывод:

```
G Y G
Y G Y
G Y Y G
Y G G
G Y Y
```

## Решение

Комнаты — вершины, двери — рёбра. Покрасить дверь в зелёный в комнате `u`
и в оранжевый в комнате `v` — то же самое, что направить ребро из `u` в
`v`, так что нужна ориентация, где у каждой вершины полустепени исхода и
захода отличаются не больше чем на единицу. Такая ориентация есть
всегда. Добавим фиктивную вершину и соединим её лишним ребром с каждой
вершиной нечётной степени; таких вершин чётное число, так что теперь все
степени чётные. Тогда у каждой компоненты связности есть эйлеров цикл, и
обход по нему выходит из каждой вершины столько же раз, сколько входит.
Направим каждое ребро по ходу обхода и выбросим лишние рёбра: вершина
теряет не больше одного ребра, поэтому её два счёта отличаются не больше
чем на единицу. `O(N + D)` для `D` дверей плюс стоимость словаря, который
связывает упоминания дверей.

Тонкие места:

- ответ `Impossible` не бывает никогда;
- дверь упоминается в строках обеих своих комнат, и упоминания надо
  связать: `k`-е упоминание `v` в комнате `u` идёт в пару с `k`-м
  упоминанием `u` в комнате `v`; двери между одними комнатами
  взаимозаменяемы, так что подходит любое согласованное разбиение на пары;
- цикл обходится явным стеком с указателем на следующее неиспользованное
  ребро у каждой вершины, так что каждое ребро просматривается константное
  число раз;
- для комнаты без дверей выводится пустая строка.

Ответы проверены проверяющей программой на всех тестах и на случайных
зданиях с большим числом повторяющихся дверей между одними комнатами.

## Особенности языков

- Во всех языках один и тот же обход с явным стеком.
- В Python упоминания связываются списками по паре комнат; при
  нескольких тысячах дверей операции с очередями дёшевы.
