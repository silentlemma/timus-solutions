# 1129. 给门涂色：一面绿一面橙，并让每个房间两种颜色均衡

[Timus 1129](https://acm.timus.ru/problem.aspx?space=1&num=1129) · 难度 378 · graphs

原题作者 Magaz Asanov，出自 2001 年 10 月 21 日第六届乌拉尔国立大学大学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一栋楼有 `N ≤ 100` 个房间，由门相连；两个房间之间可以有多扇门。每扇门
一面涂绿色，另一面涂橙色。要求涂色后每个房间里绿色门面与橙色门面的数量
相差不超过一。若无法做到，输出 `Impossible`。

时间限制：0.25 秒。内存限制：64 MB。

## 输入

`N`，然后 `N` 行：某个房间的门数，然后按递增顺序给出这些门通向的房间
编号。

## 输出

`N` 行：按输入顺序给出每个房间各扇门的颜色，`G` 表示绿色，`Y` 表示橙色；
或者输出单词 `Impossible`。

## 评测方式

任何合法的涂色都被接受。检查程序验证：每个房间对列出的每扇门给出一种
颜色；每个房间的两种颜色数量相差不超过一；对每一对房间，它们之间的门恰好
在一面是绿色。同一对房间之间的门彼此无法区分，因此检查程序按房间对统计
绿色标记，而不是逐扇门匹配。

## 样例

### 样例 1

输入：

```
5
3 2 3 4
3 1 3 5
4 1 2 4 5
3 1 3 5
3 2 3 4
```

输出：

```
G Y G
Y G Y
G Y Y G
Y G G
G Y Y
```

## 解法

把房间看作顶点，门看作边。代码把每对平行门替换为两个房间各一个自环。
门在房间 `u` 一面涂绿、在房间 `v` 一面涂橙，
等价于把边定向为从 `u` 指向 `v`，所以题目要求一种定向，使每个顶点的出度
与入度相差不超过一。这样的定向总是存在。增加一个虚拟顶点，向每个奇度
顶点连一条额外的边；奇度顶点有偶数个，于是所有度数都变成偶数。这样每个
连通部分都有欧拉回路，沿回路行走时离开每个顶点的次数等于进入的次数。
把每条边按行走方向定向，再删去额外的边：每个顶点最多失去一条边，所以它的
出度与入度相差不超过一。对 `D` 扇门，使用哈希映射的期望时间为
`O(N + D)`，C++ 使用有序映射，为 `O(N + D log D)`。

五个简单源码与优化 Rust 按行扫描，为每个无序房间对配对连续
出现的门侧，并非配对相对房间的第 k 次出现。不同房间间有 m 扇门时，
各房间产生 floor(m/2) 个自环，m 为奇数时再有一条连接边。
每个自环将两位置涂为 G/Y，局部平衡；连接边处理奇数余项。
各房间原始位置数不变，每对房间的 2m 个位置恰有 m 个绿色，
满足检查器。平行门没有独立身份，因此允许这种人工配对。
自门的门侧在同一行内配对。优化 Java 明确配对两端半区；
优化 C++/Python 消去偶数重数，只定向残余图。

注意事项：

- 答案永远不会是 `Impossible`；
- 一扇门会出现在它两侧房间的行里；每对房间的提及按扫描顺序两两配对。
  同一对房间之间的门可以互换；
- 回路用显式栈遍历，每个顶点保存指向下一条未用边的指针，因此每条边只被
  查看常数次；
- 没有门的房间输出一个空行。

答案已用检查程序在所有测试以及许多同一对房间之间有大量重复门的随机楼房
上验证。

## 优化解法

`1129_graphs_optimized.py`. 保留反向平行门对的精确抵消，以及把奇度房间接到虚拟房间后对剩余图作 Euler 定向。邻居有序，因此 itertools.groupby 以原生代码统计相同段。Python 用整数位集保存残余邻居，XOR 移除最低可用边，再按原重数展开颜色；自门配对仍平衡。不使用答案指纹。N 房间、D 门提及、B=ceil(N/w) 个整数位段时，工作 O(D+N²B)，空间 O(N²+最大行度数)，含逐行输入输出。N<=100 时位集仅少数位段，保留教学图实现。 其中 w 为 Python 大整数每个位段的位数。

精确源代码 CPython 3.12 Accepted #11327005：0.078 s / 752 KB。2026-11-20 保存的当前语言族编译器组比较：时间排名 1/83，内存排名 1/83。低于 1024 KB，严格收录只看时间。

- `1129_graphs_optimized.py`: 0.078 s / 752 KB; 保留的教学基础版 `1129_graphs.py` (Python 3.12 x64): 0.078 s / 2560 KB; 时间变化 +0.0%; 内存变化 -70.6%.

`1129_graphs_optimized.java`. 保留把奇度房间虚连到虚拟房间后的欧拉行走定向。扁平保存 D 个门侧出现项、房间偏移、原位置和配对下标。排序 long 键（无序房间对，原槽位）：平行门按槽位配对两个端点半组，自环出现项依次两两配对。N<=100 使房间对键小于10000，与低32位槽位分开。真实边标相反 G/Y，虚边只平衡奇偶、不输出。基本类型栈及字节颜色替代对象邻接、哈希队列和完整输出构造器。空间 O(N+D)。设基本类型排序代价 S(D)，其余配对、遍历、输出为 O(N+D)；Java8 通常 O(D log D)，保守允许最坏 O(D²)，不声称严格对数保证。

与 `1129_graphs.java` 相比：时间 0.156 s → 0.109 s；内存 3876 KB → 832 KB。

C++ 和 Python 统计每对房间之间的门数。两扇平行门取相反方向时，在两端都抵消，因此剩余图中每对房间最多有一条真实边。添加虚拟边后各点度数均为偶数。沿未用边走到回路闭合，按走过的方向定向。C++ 以单调游标扫描邻接矩阵；Python 按上述方式遍历残余整数位集。两者均按原重数和输入顺序展开输出。

此前精确源码缓存确认简单 Go 通过适用小样本两项。简单 Rust
不合格：1172 KB 需要比较内存而未通过；884 KB 优化 Rust 仅按
时间合格。简单 C++/Java/Python 也未过所需指标，相应优化版均
低于 1 MiB，仅按时间合格。保留全部教学版，不加目标星号；
使用统一标准，不另设语言第一名目标。

当前五个简单源码与优化 Rust 已修正配对说明注释；优化 Rust
另将原有 32 字节内联记号容量命名。可执行算法、
