# 1138. Самая длинная цепочка работ, где каждая прибавка — целое число процентов

[Timus 1138](https://acm.timus.ru/problem.aspx?space=1&num=1138) · сложность 204 · dp

Оригинальная задача — четвертьфинал, центральный регион России, Рыбинск, 17–18 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Первая зарплата программиста была ровно `s`, каждая следующая —
положительное целое число, больше предыдущей на целое число процентов, а
последняя не больше `n`, при `1 ≤ n, s ≤ 10000`. Найти наибольшее
возможное число работ, считая первую.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` и `s`.

## Выходные данные

Наибольшее число работ.

## Проверка

Сравнивается один целочисленный токен. У сохранённых машинных добавлений по 380 дополнительных запусков: 320 малых точных переборов путей и 60 граничных регрессий. Для новой учебной Python-ревизии сохранены 7730 исполнений против буквального графа зарплат, 7260 сравнений множеств переходов, 12 тестов репозитория и 169 дополнительных проверок на PyPy, включая максимальный n. Эти числа относятся к разным проверкам, а не ко всем машинным языкам.

## Примеры

### Пример 1

Ввод:

```
10 2
```

Вывод:

```
5
```

## Решение

Пусть `jobs[a]` — максимальное число работ от начальной зарплаты `s` до `a`.
Повышение до `b>a` допустимо тогда и только тогда, когда `100(b−a)` делится
на `a`. Четыре учебные машинные версии перебирают все большие целые `b`
и обновляют `jobs[b] = max(jobs[b], jobs[a]+1)` при допустимом повышении.
Изначально задано только `jobs[s]=1`. Зарплаты строго растут: возрастающий
порядок топологический, поэтому индукция доказывает DP для самого длинного
пути. Время `O(n²)`, память `O(n)`.

Принятый учебный Python перебирает другое: для каждого достижимого `a`
все целые положительные проценты `p≤floor(100(n−a)/a)`. Если `a*p % 100 == 0`,
обновляется зарплата `a+a*p/100`. Каждому допустимому переходу соответствует
ровно один такой процент, поэтому доказательство DP то же; рассуждение
через НОД не требуется. Верхняя оценка — `O(P n log n)` проверок при `P=100`,
память `O(n)`. Это не квадратичный перебор пар. Версия принята на PyPy 3.10.
Ранний Python с перебором пар получил TLE и не публикуется.

При `s>n` ответ ноль; при `s≤n` учитываем первую работу. Повышение строго
положительно, недостижимые зарплаты пропускаем. Произведения не больше
миллиона, число работ не больше 10000: достаточно машинных 32-битных целых.

## Оптимизированные решения

Положим `P=100`, `g=gcd(a,P)`. Числа `a/g` и `P/g` взаимно просты,
поэтому `a | P(b−a)` равносильно `(a/g) | (b−a)`. Допустимые зарплаты —
в точности `a+a/g, a+2a/g, …`. Перечисляем только их вместо проверки всех
зарплат или процентов. Доказательство DP в топологическом порядке сохраняется.
Из зарплаты `a` не более `Pn/a` обновлений: всего `O(P n log n+n log P)`
времени с вычислением НОД и `O(n)` памяти. Дополнительный Java заранее
вычисляет `gcd(r,100)` для 100 остатков и использует StreamTokenizer
вместо Scanner.

Все пять прежних программ с НОД сохранены. Их алгоритм отличается от прямых
учебных переборов, поэтому прежние имена `dp` остаются. Дополнительный
Java `_optimized` сохраняет алгоритм с НОД. Ниже каждая версия сравнивается
с фактической предпочитаемой базой того же языка. Сравнение Python включает
