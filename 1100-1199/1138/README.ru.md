# 1138. Самая длинная цепочка работ, где каждая прибавка — целое число процентов

[Timus 1138](https://acm.timus.ru/problem.aspx?space=1&num=1138) · сложность 203 · dp

Оригинальная задача — четвертьфинал, центральный регион России, Рыбинск, 17–18 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Первая зарплата программиста была ровно `s`, каждая следующая —
положительное целое число, больше предыдущей на целое число процентов, а
последняя не больше `n`, при `1 ≤ n, s ≤ 10000`. Найти наибольшее
возможное число работ, считая первую.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` и `s`.

## Выходные данные

Наибольшее число работ.

## Примеры

### Пример 1

Ввод:

```
10 2
```

Вывод:

```
5
```

## Решение

Прибавка от зарплаты `a` до `b > a` составляет `100·(b − a) / a`
процентов, и это целое число ровно тогда, когда `a` делит `100·(b − a)`.
При `g = gcd(a, 100)` это значит, что `a / g` делит `b − a`, так что из `a`
достижимы зарплаты `a + a/g, a + 2a/g, …`. Пусть `jobs[a]` — длина самой
длинной цепочки от `s` до `a`, `jobs[s] = 1`. Зарплаты только растут,
поэтому, идя вверх от `s` и передавая `jobs[a] + 1` каждому достижимому
`b ≤ n`, мы заполняем таблицу по порядку; ответ — её наибольшее значение.
Шаг `a/g` не меньше `a/100`, так что всего передач в худшем случае около
`100·n·ln n`, а на деле гораздо меньше.

Тонкие места:

- прибавка должна быть положительной, так что `b > a`;
- при `n = s` работа одна;
- если `s > n`, не подходит ни одна цепочка и ответ `0`;
- работа с `a / gcd(a, 100)` избавляет от перебора всех процентов.

Ответы сверены с проверкой всех пар зарплат на всех тестах и на 300
случайных входах до 400.
