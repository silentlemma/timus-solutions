# 1138. 每次加薪都是整数百分比的最长工作序列

[Timus 1138](https://acm.timus.ru/problem.aspx?space=1&num=1138) · 难度 203 · dp

原题出自 2001 年 10 月 17–18 日在雷宾斯克举行的俄罗斯中部赛区四分之一决赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一位程序员的第一份工资恰好是 `s`，之后每份工资都是正整数，并比前一份
高出整数个百分点，最后一份不超过 `n`，`1 ≤ n, s ≤ 10000`。求最多可能有
多少份工作（包括第一份）。

时间限制：1 秒。内存限制：64 MB。

## 输入

`n` 和 `s`。

## 输出

最多的工作数。

## 样例

### 样例 1

输入：

```
10 2
```

输出：

```
5
```

## 解法

工资从 `a` 涨到 `b > a`，涨幅为 `100·(b − a) / a` 个百分点；它是整数当且仅当
`a` 整除 `100·(b − a)`。令 `g = gcd(a, 100)`，这等价于 `a / g` 整除 `b − a`，
所以从 `a` 能到达的工资是 `a + a/g, a + 2a/g, …`。设 `jobs[a]` 为从 `s` 出发、
以 `a` 结尾的最长序列长度，`jobs[s] = 1`。工资只会增长，所以从 `s` 往上
处理，把 `jobs[a] + 1` 推给每个可到达的 `b ≤ n`，表就按顺序填好了；答案是
表中的最大值。步长 `a/g` 至少为 `a/100`，所以最坏情况下推送总数约为
`100·n·ln n`，实际上要少得多。

注意事项：

- 涨幅必须为正，所以 `b > a`；
- `n = s` 时只有一份工作；
- 若 `s > n`，没有任何序列满足条件，答案为 `0`；
- 使用 `a / gcd(a, 100)` 可以避免枚举每个百分比。

答案已在所有测试以及 300 个不超过 400 的随机输入上与逐对检查工资的结果
比对。
