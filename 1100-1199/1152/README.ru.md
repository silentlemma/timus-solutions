# 1152. Наименьший урон от монстров на балкончиках вокруг зала

[Timus 1152](https://acm.timus.ru/problem.aspx?space=1&num=1152) · сложность 155 · bitmask

Автор оригинальной задачи — Евгений Брызгалов; командный чемпионат Урала по программированию, Пермь, апрель 2001 года, английский тур.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` балкончиков, `3 ≤ N ≤ 20`, стоят по кругу, на каждом от 1 до 100
монстров. Один залп уничтожает три соседних балкончика (`N`-й соседствует
с первым). После каждого залпа каждый оставшийся в живых монстр наносит
одну единицу урона. Залпы продолжаются, пока монстры не кончатся. Найти
наименьший общий урон.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем количества монстров на балкончиках.

## Выходные данные

Наименьший общий урон.

## Примеры

### Пример 1

Ввод:

```
7
3 4 2 2 1 4 1
```

Вывод:

```
9
```

## Решение

Состояние — множество ещё занятых балкончиков, маска из `N` битов. Из
состояния залп по балкончику `i` очищает `i − 1`, `i` и `i + 1` и
оставляет множество `rest`; он стоит количество монстров в `rest`, а
дальше следует лучшая игра из `rest`. Значит, при `damage(∅) = 0`

`damage(mask) = min по залпам, которые во что-то попадают, alive(rest) + damage(rest)`.

Важны только состояния, достижимые из полного круга: их очищенные части —
объединения отрезков из трёх соседей, и при `N = 20` их всего 15126.
Рекурсия с запоминанием посещает только их, по `N` залпов на каждое.
Рекурсивных переходов не больше `N − 2` (`N − 1` активных вызовов):
первый залп очищает три балкончика, а каждый следующий полезный залп —
хотя бы один. Залпы, не задевающие ни одного занятого балкончика,
пропускаются: они никогда не помогают. При `S` достижимых состояниях
вычисление `alive(rest)` за `O(N)` даёт `O(S·N²)` времени на рекурсию.

Тонкие места:

- круг замкнут, так что залп по первому балкончику очищает и `N`-й;
- урон после последнего залпа равен нулю — никого не осталось;
- порядок залпов важен, потому что большие группы выгодно убирать рано;
- перекрывающиеся залпы могут очищать лишь один новый балкончик. В тесте
  07 залпы с центрами 1, 2 и 3 образуют ветвь из трёх переходов, хотя
  оптимальный ответ равен 2; `⌈N / 3⌉` не ограничивает глубину рекурсии.

Ответы сверены с таблицей снизу вверх по всем `2^N` подмножествам на 120
случайных входах до 13 балкончиков и на всех тестах с 20.

## Оптимизированные решения

Оптимизированное решение на C++ запоминает для каждого состояния сумму
оставшегося урона и числа живых в нём монстров, так что сумма живых
считается один раз на состояние, а не на каждый переход, всего `O(S·N)`
времени; ответ — значение для полного круга минус все монстры. Кэш —
`unordered_map` только с достижимыми состояниями вместо массива на все
`2^N` масок: {1152_bitmask_optimized.cpp}.

Оптимизированное решение на Go запоминает для каждого состояния сумму
оставшегося урона и числа живых в нём монстров, так что сумма живых
считается один раз на состояние, а не на каждый переход, всего `O(S·N)`
времени; ответ — значение для полного круга минус все монстры. Кэш —
`map` только с достижимыми состояниями вместо среза на все `2^N` масок:
{1152_bitmask_optimized.go}.

Оптимизированное решение на Java запоминает для каждого состояния сумму
оставшегося урона и числа живых в нём монстров, так что сумма живых
считается один раз на состояние, а не на каждый переход, всего `O(S·N)`
времени; ответ — значение для полного круга минус все монстры. Вместо
массива на все `2^N` масок кэш — хеш-таблица с открытой адресацией в
двух массивах `int`, которая удваивается по мере заполнения, поэтому
хранит только достижимые состояния и не упаковывает ключи в объекты;
ввод читается через `StreamTokenizer` вместо `Scanner`:
{1152_bitmask_optimized.java}.

Оптимизированное решение на Python хранит достижимые состояния в обычном
словаре вместо `lru_cache` и запоминает для каждого состояния сумму
оставшегося урона и числа живых в нём монстров, так что сумма живых
считается один раз на состояние, а не на каждый переход, всего `O(S·N)`
времени; ответ — значение для полного круга минус все монстры:
{1152_bitmask_optimized.py}.

## Особенности языков

- Во всех языках запоминается одна и та же рекурсия; Python хранит
  значения в кэше по маске, остальные — в массиве из `2^N` элементов.
- Python использует `O(S + N)` памяти. Остальные языки инициализируют все
  `2^N` элементов, поэтому общее время — `O(2^N + S·N²)`, а память —
  `O(2^N + N)`.
