# 1144. 尽可能均匀地把金箱分给将军们

[Timus 1144](https://acm.timus.ru/problem.aspx?space=1&num=1144) · 难度 1972 · greedy

原题作者：HNT。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

把 `N ≤ 10000` 个价值在 1 到 1000 之间的箱子分给 `M ≤ N`、`M ≤ 1000` 位
将军，每个箱子整个归一位将军。要让最富与最穷的将军之间的差距尽可能小。
差距不超过给定的 `K` 即被接受。输出差距，然后输出每位将军的箱子。

时间限制：1 秒。内存限制：4 MB。

## 输入

`N`、`M` 和 `K`，然后是 `N` 个价值。

## 输出

差距，然后 `M` 行，每行是一位将军的箱子编号。

## 评测方式

差距不超过 `K` 的任何分法都被接受。检查程序验证每个箱子恰好分出一次、输出
的差距是真实差距，并且不超过 `K`。大测试中的 `K` 取本搜索达到的差距；其中
为 `1` 的情形也是最优的，因为总和不能被 `M` 整除。

## 样例

### 样例 1

输入：

```
10 3 4
12 95 16 37 59 50 47 3 41 95
```

输出：

```
4
1 2 7
3 4 8 10
5 6 9
```

## 解法

把数分成 `M` 组使各组和相等是 NP 困难问题，所以这里用启发式：一个好的初始
解，加上局部搜索，一旦差距不超过 `K` 就停止。

初始解用经典的“先大后小”规则：从价值最高的箱子往下，把每个箱子交给目前
金子最少的将军，用堆来找。

然后只要差距大于 `K`，就对最富的将军 `hi`、最穷的将军 `lo`（差距为 `d`）
反复执行：

1. **移动或交换。** 把价值 `v` 的箱子从 `hi` 移给 `lo`，两人的差距变为
   `|d − 2v|`；把 `hi` 的箱子 `a` 与 `lo` 的箱子 `b` 交换，差距变为
   `|d − 2(a − b)|`。每位将军的箱子保持有序，所以二分查找能找到最接近
   `d/2` 的箱子，以及对每个不同的价值 `a` 最接近 `a − d/2` 的箱子 `b`。若最好
   的变动能缩小这两人的差距，就执行它。
2. 若 `hi` 与 `lo` 之间没有这样的变动，就在 `hi` 与其他每位将军之间（从最穷
   的开始）以及其他每位将军（从最富的开始）与 `lo` 之间尝试同样的操作。
3. **精确划分。** 若任何单次移动或交换都没用，就把两位将军的箱子合在一起，
   用以位集表示的子集和表尽可能均匀地重新划分；每个箱子一行，以便还原划分。
   只有当表小于 400 万位（约半兆字节）时才这样做。
4. 若都无效，搜索结束。

每次变动都缩小两位将军的差距，既不抬高较富者也不压低较穷者，所以各将军
金额的平方和每次都严格减小，搜索必然结束；轮数上限保证时间安全。在每位
将军箱子很多的随机测试中，差距能降到 `1`，当总和不能被 `M` 整除时这是最优
的。每位将军只有一两个箱子时差距会更大，其中一部分是无法避免的。

注意事项：

- 4 MB 的内存限制不允许很大的子集和表，所以每次精确划分前都检查表的大小；
- 每位将军至少保留一个箱子：移动从不让 `hi` 变空，会让一方变空的划分被
  放弃；
- 输出的差距必须等于所输出分法的真实差距。

答案已用检查程序在所有测试上验证；五种语言输出完全相同的分法。

## 各语言说明

- 所有语言按相同顺序执行相同步骤，因此结果完全一致。
- Go、Java 和 Rust 把一个箱子存成一个整数：价值左移 14 位再加上编号，其
  排序方式与二元组相同。
- Java 全部使用基本类型数组，子集和表复用同一个缓冲区，也不用 lambda：在
  4 MB 的限制下，装箱的数字、短命的表以及 Java 8 为 lambda 加载的机制会让堆
  超出限制。
