# 1142. Число упорядочений N объектов с возможными равенствами

[Timus 1142](https://acm.timus.ru/problem.aspx?space=1&num=1142) · сложность 155 · combinatorics

Оригинальная задача с Timus; автор и источник не указаны.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Между любыми двумя из `N` сравнимых объектов выполняется одно из `a = b`,
`a < b`, `b < a`. Посчитать различные способы упорядочить `N` объектов в
этом смысле, с возможными равенствами: для трёх объектов их 13, от
`a = b = c` до `c < b < a`. Ответить для нескольких `N` от 2 до 10; ввод
заканчивается числом `-1`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Значения `N` по одному в строке, затем `-1`.

## Выходные данные

Количество для каждого `N`, по одному в строке.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
2
3
-1
```

Вывод:

```
3
13
```

## Решение

Упорядочение с равенствами — это последовательность групп равных
объектов, строго возрастающих. Посмотрим на первую группу: это любое
непустое множество из `k` объектов, выбираемое `C(n, k)` способами, а
оставшиеся `n − k` объектов образуют своё упорядочение с равенствами.
Значит, при `a(0) = 1`

`a(n) = Σ_{k=1..n} C(n, k)·a(n − k)`.

Это упорядоченные числа Белла (числа Фубини) 1, 1, 3, 13, 75, 541, …;
наибольшее нужное `a(10) = 102247563` помещается в 32 бита. Таблица
строится один раз с треугольником Паскаля, а каждый запрос — просто
обращение к ней. `O(10²)` на построение.

Тонкие места:

- количества запросов во входе нет, читаем до `-1`;
- одно и то же `N` может спрашиваться несколько раз.

Значения сверены с независимой формулой `a(n) = Σ k!·S(n, k)` через
числа Стирлинга второго рода, а для `n ≤ 6` — с перечислением всех
упорядочений.

## Оптимизированные решения

`1142_combinatorics_optimized.go`. Рекуррентная формула и полная матрица Паскаля 11×11 сохранены. Ответы для L=10 вычисляются заранее, Q запросов читаются до отрицательного маркера или EOF. В этой Go-версии меняются накладные расходы ввода-вывода, а не комбинаторный алгоритм или хранение таблиц. Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1142_combinatorics.go`: время 0.001 s → 0.015 s; память 1084 KB → 272 KB.

`1142_combinatorics_optimized.py`. Рекуррентный подсчёт слабых порядков сохраняется, но C(n,k) получается последовательно как choose*(n-k+1)//k без хранения треугольника Паскаля. Остаются L+1 ответов при L=10, предвычисление занимает O(L²). Python всё ещё хранит токены входа и собранный вывод, поэтому общая память O(L+I+O) для размеров входа и вывода I,O. Первый отрицательный запрос завершает обработку. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1142_combinatorics.py`: время 0.031 s → 0.125 s; память 436 KB → 220 KB.

`1142_combinatorics_optimized.rs`. Рекуррентность слабых порядков сохраняется, биномиальные коэффициенты считаются последовательно без матрицы Паскаля 11×11. Хранятся одиннадцать счётчиков u64; запросы читаются до отрицательного числа либо EOF, вывод идёт байтами через среду C без строк полного входа и вывода. При L=10 и Q запросах время O(L²+Q), дополнительная память O(L). Учебная версия с таблицей Паскаля сохранена.

По сравнению с `1142_combinatorics.rs`: время 0.001 s → 0.001 s; память 220 KB → 44 KB.

`1142_combinatorics_optimized.java`. Сохраняется рекуррентная формула упорядоченных разбиений. Числа читаются из байтового буфера 1 КБ, хранится только ways[0..L], L=10; биномиальный коэффициент вычисляется последовательно умножением, без матрицы Паскаля. Исключены StreamTokenizer, BufferedReader и PrintWriter. Ответы собираются в StringBuilder до отрицательного запроса или EOF и выводятся вместе. Для Q запросов время O(L²+Q), память O(L+Q), включая буфер ответа; память вывода не константна. Простая версия сохранена.

Accepted точного исходника №11326631: 0.046 s / 336 KB. В сохранённой выборке Java 1.8 от 2026-11-20: место по времени 3/44, по памяти 2/44. Звёздочка по-прежнему относится к отдельной рейтинговой цели языка.
