# 1134. Проверка, возможны ли числа, прочитанные с карт, на которых написано k − 1 и k

[Timus 1134](https://acm.timus.ru/problem.aspx?space=1&num=1134) · сложность 197 · greedy

Оригинальная задача — четвертьфинал, центральный регион России, Рыбинск, 17–18 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `n ≤ 1000` карт; на карте `k` с одной стороны написано `k − 1`, с
другой — `k`. Ребёнок взял `m ≤ n` разных карт в каком-то порядке и прочёл
одну сторону каждой. По `m` прочитанным числам определить, могли ли они
получиться при каком-то выборе карт и сторон.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` и `m`, затем `m` чисел, каждое от `0` до `n`.

## Выходные данные

`YES`, если такое прочтение возможно, иначе `NO`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
5 4
2 0 1 2
```

Вывод:

```
NO
```

## Решение

Вопрос в том, можно ли дать каждому прочтению свою карту. Число `x` есть
на картах `x` и `x + 1` (`0` только на карте 1, `n` только на карте `n`),
так что каждое прочтение может взять одну из двух соседних карт.
Подсчитаем прочтения каждого числа и пойдём вверх от `0`. Прочтения `x`
сначала берут карту `x`, потом карту `x + 1`. Брать сначала нижнюю карту
безопасно: на карте `x` только `x − 1` и `x`, все прочтения `x − 1` уже
размещены, так что дальше она никому не нужна. Если какому-то прочтению
`x` не досталось ни одной из его карт, распределения нет. `O(n + m)`.

Тонкие места:

- `0` и `n` есть только на одной карте каждое;
- одно и то же число может быть прочитано несколько раз, но при ответе
  `YES` не больше двух;
- прочтения идут в произвольном порядке, важны только их количества.

Ответы сверены с паросочетанием Куна на всех тестах и на 400 случайных
случаях.

## Оптимизированные решения

Жадное назначение меньшей допустимой карты не меняется. Байтовый счётчик каждого значения заменяет отдельные массивы частот и занятости; одно состояние занятости переносит границу между соседними вариантами. Требования обрабатываются по значениям, каждый раз расходуется наименьшая ещё допустимая карта, оставляя большие последующим требованиям. Сторожевое состояние убирает ветвления на концах. Фактический интерпретатор Python и измеренная экономия указаны в таблицах.

- `1134_greedy_optimized.py`: 0.140 s / 288 KB; база `1134_greedy.py`: 0.078 s / 492 KB; изменение относительно базы: время +79.5%, память -41.5%.
