# 1131. 用 K 根线把程序复制到 N 台电脑，每根线每小时复制一份

[Timus 1131](https://acm.timus.ru/problem.aspx?space=1&num=1131) · 难度 77 · math

原题作者 Stanislav Vasiliev 和 Alexander Mironenko，出自 2001 年 10 月 21 日第六届乌拉尔国立大学大学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

程序在 `N` 台电脑中的一台上。一小时内，已有程序的电脑可以通过一根线把它
复制到另一台电脑上，一共有 `K` 根线。求所有 `N` 台电脑都有程序所需的最少
小时数，`1 ≤ N, K ≤ 10⁹`。

时间限制：0.25 秒。内存限制：64 MB。

## 输入

一行中的 `N` 和 `K`。

## 输出

最少的小时数。

## 样例

### 样例 1

输入：

```
8 3
```

输出：

```
4
```

## 解法

一小时内有 `min(have, K, N − have)` 台新电脑得到程序，其中 `have` 是已经
有程序的电脑数；每小时尽可能多地复制显然最优。当 `have < min(N, K)` 时，
将 `have` 翻倍并累计一小时。如果此时 `have ≥ N`，所有剩余电脑都能在这一
小时内得到程序，循环结束；计数器可能超过 `N`，但不影响答案。这个阶段最多
需要 30 小时。否则，当 `have ≥ K` 时，每小时最多增加 `K` 台，所以剩下的
`N − have` 台还需要 `⌈(N − have) / K⌉` 小时。`O(log min(N, K))`。

注意事项：

- `N = 1` 时不需要时间；
- `K = 1` 且 `N = 10⁹` 时答案接近 `10⁹`，所以翻倍之后的小时数必须用除法
  计算，不能逐小时累加；
- 最后一小时得到程序的电脑可能少于 `K` 台（测试 11），所以除法需要向上取整；
- 翻倍计数器可能超过 `N`（测试 05），但最多达到 `2³⁰`；使用 64 位整数安全，
  不过有符号 32 位整数也已足够。

答案已在所有测试上与按小时数二分查找的结果比对，并对所有 `N < 200`、
`K < 70` 与逐小时模拟比对。
