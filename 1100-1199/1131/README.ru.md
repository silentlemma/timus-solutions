# 1131. Копирование программы на N компьютеров по K шнурам, по одной копии на шнур в час

[Timus 1131](https://acm.timus.ru/problem.aspx?space=1&num=1131) · сложность 77 · math

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Программа есть на одном из `N` компьютеров. За час компьютер, на котором
она есть, может скопировать её на один другой компьютер по шнуру, а шнуров
всего `K`. Найти наименьшее число часов, за которое программа окажется на
всех `N` компьютерах, при `1 ≤ N, K ≤ 10⁹`.

Ограничение времени: 0,25 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `K` в одной строке.

## Выходные данные

Наименьшее число часов.

## Примеры

### Пример 1

Ввод:

```
8 3
```

Вывод:

```
4
```

## Решение

За час программу получают `min(have, K, N − have)` новых компьютеров, где
`have` — число компьютеров, на которых она уже есть; копировать каждый час
как можно больше, очевидно, выгоднее всего. Пока `have < min(N, K)`,
удваиваем `have` и прибавляем час. Если получилось `have ≥ N`, за этот час
программу могут получить все оставшиеся компьютеры, и цикл завершается;
счётчик может превысить `N`, но это не меняет ответ. Этот этап занимает не
больше 30 часов. Иначе, когда `have ≥ K`, каждый час добавляется до `K`
компьютеров, так что оставшимся `N − have` компьютерам нужно ещё
`⌈(N − have) / K⌉` часов.
`O(log min(N, K))`.

Тонкие места:

- при `N = 1` часов не нужно;
- при `K = 1` и `N = 10⁹` ответ почти `10⁹`, поэтому часы после удвоения
  считаются делением, а не по одному;
- за последний час программу могут получить меньше `K` компьютеров
  (тест 11), поэтому деление округляется вверх;
- счётчик при удвоении может превысить `N` (тест 05), но не `2³⁰`;
  64-битные целые безопасны, хотя достаточно и знаковых 32-битных.

Ответы сверены с двоичным поиском по числу часов на всех тестах и с
почасовой симуляцией для всех `N < 200` и `K < 70`.
