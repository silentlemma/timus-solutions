# 1114. Раскладка до A и B одинаковых шаров двух цветов по N коробкам

[Timus 1114](https://acm.timus.ru/problem.aspx?space=1&num=1114) · сложность 194 · combinatorics, math

Оригинальная задача — первое отборочное соревнование в болгарскую команду на IOI.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В ряд стоят `N` коробок (`1 ≤ N ≤ 20`), есть `A` одинаковых красных и
`B` одинаковых синих шаров (`0 ≤ A, B ≤ 15`). В каждую коробку можно
положить сколько угодно шаров любых цветов, коробки могут оставаться
пустыми, а шары — неиспользованными. Посчитать число различных раскладок.

Ограничение времени: 0,6 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N A B` в одной строке.

## Выходные данные

Число раскладок.

## Проверка

Сравнивается один точный целочисленный токен. Новый Python исполнен на всех 5120 допустимых тройках и 12 тестах репозитория на CPython 3.12 и PyPy 3.10; дополнительно каждый интерпретатор выполнил 12 отдельных процессов на тестах репозитория. Ожидаемые ответы сверены независимой DP распределения по одной коробке с суммированием всех разрешённых использованных количеств каждого цвета. Проверены нулевые количества и максимальный ответ выше знаковых 64 бит. Для сохранённого Java отдельно есть привязанная к исходнику проверка коэффициентов и беззнакового произведения на всех 5120 тройках.

## Примеры

### Пример 1

Ввод:

```
2 1 1
```

Вывод:

```
9
```

## Решение

Цвета независимы. Расстановка не более `A` красных шаров в `N`
различимых коробках однозначно продолжается до расстановки ровно `A`
шаров в `N + 1` коробках: неиспользованные кладём в дополнительную.
Обратное отображение удаляет эту коробку. По методу «звёзды и перегородки»
получаем `C(N + A,N)`. Независимый выбор двух цветов даёт ответ
`C(N + A,N) × C(N + B,N)`.

Понятные базы C++, Go, Java и Rust строят треугольник Паскаля с
`TOP = 40` и делают два обращения к таблице. Время и память — `O(TOP²)`;
нужные индексы не больше 35. Python дважды вызывает `math.comb`, без
таблицы. При фиксированных ограничениях все эти программы имеют `O(1)`
относительно размеров допустимого входа. Все пять исходных Accepted-файлов
сохранены.

Нужные коэффициенты не превосходят `C(35,15) = 3247943160 < 2^32`;
это не значит, что любая ячейка большей таблицы Паскаля помещается в 32 бита.
Максимальный ответ `10549134770590785600` превышает знаковые 64 бита,
но меньше `2^64`. C++, Go и Rust используют беззнаковое произведение;
Java сохраняет младшие 64 бита и выводит `Long.toUnsignedString`.
В Python целые не ограничены машинным словом.

## Оптимизированные решения

Java вычисляет каждый биномиальный коэффициент по произведению: после шага i значение r=C(N+i,i), следующее деление точное. Произведение перед делением не больше 35*C(35,15)=113678010600 и помещается в знаковый long. Итог может превышать знаковые 64 бита, но меньше 2^64: Java сохраняет младшие 64 бита и выводит Long.toUnsignedString. Таблица Паскаля не нужна, все понятные базы сохранены.

Java включена по экономии памяти 77,4%; разница времени в один тик не доказывает ускорение.

Оптимизированный Python сохраняет формулу «звёзды и перегородки» и короткую базу с math.comb. Он читает текст из существующего стандартного потока, импортирует только потоки из sys и вычисляет каждый коэффициент точными последовательными умножениями и делениями. После шага i коэффициент равен C(N+i,i), поэтому деление на i точное. Каждый множитель не больше C(35,15)=3247943160; произведение перед делением не больше 113678010600. Два готовых коэффициента перемножаются лишь один раз, затем записывается точная десятичная строка. Большое целое Python вмещает максимальный ответ 10549134770590785600, превышающий знаковые 64 бита. Не нужны таблица Паскаля и импорт math. Время — O(A+B) шагов с ограниченным размером чисел при данных условиях.

Собственный Accepted 11309624 на PyPy 3.10 x64: 0,125 с и 240 КБ против неизменённой базы CPython 3.12 с 0,078 с и 372 КБ. Измеренная экономия памяти 35,5%, время хуже на 60,3%. Версия включена только по выигрышу памяти, недобор рейтинга отмечен звёздочкой. Это две реальные посылки с указанными интерпретаторами, метрики между ними не переносились.

- `1114_combinatorics_math.java`: 0.093 s / 372 KB; база `1114_combinatorics.java`: 0.109 s / 1648 KB; изменение относительно базы: время -14.7%, память -77.4%.
- `1114_combinatorics_optimized.py`: 0.125 s / 240 KB; база `1114_combinatorics.py`: 0.078 s / 372 KB; изменение относительно базы: время +60.3%, память -35.5%.
