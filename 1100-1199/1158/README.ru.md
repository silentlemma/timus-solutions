# 1158. Подсчёт предложений длины M, не содержащих запрещённых слов

[Timus 1158](https://acm.timus.ru/problem.aspx?space=1&num=1158) · сложность 500 · strings

Автор оригинальной задачи — Николай Дуров; северный подрегион полуфинала ACM ICPC Северо-Восточной Европы 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В алфавите `N ≤ 50` букв, а предложение — любая строка ровно из `M ≤ 50`
букв. Даны `P ≤ 10` запрещённых слов длиной до 10 букв; предложение
запрещено, если содержит одно из них как подстроку. Посчитать
незапрещённые предложения. Буквами могут быть любые символы с кодами
больше 32, в том числе больше 127.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, `M` и `P`, затем `N` букв одной строкой, затем `P` слов.

## Выходные данные

Число разрешённых предложений.

## Примеры

### Пример 1

Ввод:

```
3 3 3
QWE
QQ
WEE
Q
```

Вывод:

```
7
```

## Решение

Строим автомат Ахо — Корасик для запрещённых слов: бор с суффиксными
ссылками, дополненный так, что у каждого состояния есть переход по каждой
букве. Состояние соответствует самому длинному концу уже прочитанного
текста, который является префиксом какого-то слова; оно плохое, если в нём
заканчивается слово — само или через суффиксные ссылки. Предложение
разрешено ровно тогда, когда при его чтении автомат ни разу не попадает в
плохое состояние.

Значит, считаем пути: `ways[s]` — число разрешённых начал текущей длины,
заканчивающихся в состоянии `s`. Начинаем с одного пустого начала в корне
и делаем `M` шагов, каждый раз передавая `ways[s]` по всем `N` переходам,
которые не ведут в плохое состояние. Ответ — сумма по всем состояниям. При
`S ≤ 101` состояниях подсчёт занимает `O(M·S·N)` сложений — около 5000 на шаг.

Тонкие места:

- число доходит до `50⁵⁰ ≈ 8,9·10⁸⁴`, так что нужна длинная арифметика;
- слово, содержащее другое слово, плохо уже на более коротком, и это
  переносят суффиксные ссылки;
- буквы — произвольные байты, возможно больше 127, поэтому ввод читается
  как байты, а не декодируется как текст;
- одно и то же слово может быть дано дважды.

Ответы сверены с перебором всех предложений на 200 маленьких случайных
входах; в тестах буквы больше 127 хранятся как символы Latin-1 в UTF-8, а
программа запуска передаёт их решениям одиночными байтами.

Учебная версия Python хранит состояние как собственный префикс запрещённого слова. После добавления буквы переход отбрасывается, если новое окончание совпало с запрещённым словом. Иначе выбирается самый длинный суффикс из сохранённых префиксов, включая пустой. Любой более короткий префикс, который может закончить слово, уже является суффиксом текущего состояния. Поэтому прямые проверки дают те же переходы, что и суффиксные ссылки. При P запрещённых словах длины до L построение таблицы занимает O(SN(P+S)L) времени. Подсчёт требует O(MSN) сложений.

## Оптимизированные решения

Go и Rust сохраняют Ахо–Корасик и точный подсчёт. Состояний максимум 1+10·10=101, букв 50: ID переходов помещаются в байт, очередь BFS фиксирована. Сначала распространяем запреты по суффиксным ссылкам и достраиваем все переходы; затем безопасные буквы с одинаковой целью объединяем в ребро с кратностью. Два переиспользуемых слоя DP прибавляют число·кратность по ребру. Ответ не больше 50⁵⁰<10⁸⁵: десять разрядов по основанию 10⁹ точны, произведение разряда на кратность≤50 помещается в uint64. Нули и унаследованные запреты учитываются. Байты выше 127 читаются как буквы алфавита. Пусть W — суммарная длина запрещённых слов, S — число состояний, N — размер алфавита, E — число сгруппированных рёбер, D≤10 — число разрядов. Построение и группировка занимают O(W+S(S+N)) времени: для каждой строки сканируются счётчики целей. Очистка, проверка и обновление слоёв требуют O(M(S+E)D) времени. Память O(SN+SD), ввод и вывод блочные. Для C++, Java и Python подходят базовые версии.

Принятые базовые реализации [1158_strings.cpp](1158_strings.cpp), [1158_strings.java](1158_strings.java), [1158_strings.py](1158_strings.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Исходные Go/Python/Java используют длинные целые, исходные C++/Rust — динамические разряды по девять цифр. Новые Go/Rust используют два фиксированных слоя по десять разрядов и байтовый автомат, сохраняя исходные Latin-1 байты. Модуля и таблицы ответов нет.
