# 1162. Можно ли цепочкой обменов валют с комиссиями увеличить капитал

[Timus 1162](https://acm.timus.ru/problem.aspx?space=1&num=1162) · сложность 185 · shortest_paths

Автор оригинальной задачи — Николай Дуров; северный подрегион полуфинала ACM ICPC Северо-Восточной Европы 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `N ≤ 100` валют и `M ≤ 100` обменных пунктов, каждый работает между
двумя валютами в обе стороны со своими курсом и комиссией для каждого
направления: обмен суммы `x` даёт `(x − комиссия)·курс`, и сумма никогда не
может стать отрицательной. Имея `V` единиц валюты `S`, определить, есть ли
последовательность обменов, которая кончается в валюте `S` с суммой больше
`V`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, `M`, `S` и `V`, затем `M` строк с двумя валютами, курсом и комиссией
в каждую сторону.

`1 ≤ S ≤ N ≤ 100`, `1 ≤ M ≤ 100`, `0 ≤ V ≤ 1000`.
Курсы лежат в `[0.01, 100]`, комиссии — в `[0, 100]`; они заданы не более
чем с двумя дробными цифрами. Число дробных цифр в `V` не ограничено.
Для любой последовательности, использующей каждый обменный пункт не
более одного раза, отношение конечной суммы к начальной меньше `10000`.

## Выходные данные

`YES` или `NO`.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Решение

Вершины — валюты, рёбра — направления обмена. Допустимый обмен
превращает `x` в `(x−fee)·rate`, если `x≥fee`. Пять понятных баз используют
синхронный Беллман—Форд: `best[c]` — максимальная достижимая сумма после
не более `j` обменов, а проход `j+1` читает только этот массив и пишет
в отдельный следующий. Положительные курсы делают любой суффикс
монотонным: больший капитал не ухудшает допустимое продолжение. Поэтому
достаточно максимума на валюту. Недостижимость отличаем от нулевой суммы.

Арифметика точная. Пусть `P=max(2, число дробных знаков V)`, начальный
знаменатель `D=10^P`, а курс и комиссия записаны целыми сотыми `R,C`.
Если числитель `x<C·D/100`, обмен пропускаем. Иначе следующий числитель
равен `(x−C·D/100)·R`, знаменатель — `100D`. Сохранённые суммы и исходный
капитал на каждом проходе тоже умножаем на 100. Дробные знаки исходного
капитала не отбрасываются; вещественной арифметики и epsilon нет.

Отвечаем YES, как только сумма в `S` выросла. Проход без улучшений —
неподвижная точка, значит ответ NO. Улучшение на проходе `N` обнаруживает
выгодный цикл: если все повторяющиеся участки улучшающего маршрута не
увеличивали капитал при входе, их удаление сохраняло бы допустимость
и не ухудшало монотонный суффикс. Остался бы простой путь длины не более
`N−1`, противоречие. Цикл задаёт `A·x−B`, где `B≥0`; строгий выигрыш при
`x≥0` требует `A>1`, поэтому повторение неограниченно наращивает деньги.
У каждого пункта есть обратный положительный курс: накопив достаточно,
можно оплатить возврат к `S` и превысить `V`. Нулевой капитал не растёт.

После `N` проходов числа имеют `O(P+N)` десятичных разрядов. Релаксации
и копирование состояний требуют `O(N(N+M)(P+N))` разрядного времени;
консервативная граница с разбором десятичного ввода —
`O(P²+N(N+M)(P+N))`. Живые состояния занимают `O(N(P+N))` разрядов плюс
`O(M)` рёбер фиксированного размера. Базы C++/Rust хранят разряды по
основанию 100, Go использует `big.Int`, Java — `BigInteger`, Python —
длинные целые. В базах изменены только имена существующих ролей числа
100 и форматирование. Каждая получила собственный Accepted точного SHA;
все пять прежних файлов сохранены в резервных копиях. Алгоритмы прежние.

## Оптимизированные решения

**C++, Go, Java.** Три оптимизированные версии сохраняют тот же точный алгоритм Якоби
и суффикс `_optimized`. Сначала оставляют неориентированную компоненту
`S`: пункты работают в обе стороны, другие компоненты недоступны.
При `C` оставшихся вершинах хватает `C` проходов. Это структурное
сокращение, а не утверждение доступности любых комиссий.

Go повторно использует собственные буферы `big.Int` и рабочие значения;
копирует через `Set`, без поверхностного присваивания структуры.
C++ и Java хранят неотрицательные числа по основанию `10^9`, разбирают
по девять цифр и повторно используют ёмкость и рабочие буферы вместо
коротких разрядов или неизменяемых промежуточных объектов. При нулевой
комиссии вычитание стоимости не нужно. Рёбра читают только предыдущий
проход; повторное использование памяти не превращает алгоритм
в релаксации на месте.

При `B=10^9` разряд меньше `B`, множитель курса/комиссии не больше 10000.
Произведение с переносом меньше `B·10000=10^13`, что помещается
в C++ `uint64_t` и Java `long`. Вычитание выполняется только при
достаточном капитале; заём равен 0 или 1 и помещается в выбранные типы.
Умножение числа самого в себя сначала читает старый разряд, затем пишет
новый; разные буферы владеют своей памятью. Учтены нули, степени основания
и длинные цепочки заёмов. Асимптотика прежняя; уменьшаются число разрядов,
выделений памяти и обрабатываемых вершин.

**Python/PyPy.** Python сохраняет точный синхронный Беллман—Форд и запас 100^N: при не более N обменах деление на 100 не теряет цифры. Исходные десятичные числа переводятся блоками не длиннее 1000 цифр, поэтому длинный ввод не упирается в ограничение одного преобразования. Кортежи рёбер хранят заранее вычисленные точные комиссии. После каждых восьми строк обменников удаляются мёртвые объекты разбора: меняется только время жизни памяти, не суммы и не достижимость. Это обмен времени сборки на пик памяти. Все пять понятных точных версий сохраняются. O(NM) точных релаксаций, O(N+M) числовых записей и отдельно измеряемые расходы сборки.
