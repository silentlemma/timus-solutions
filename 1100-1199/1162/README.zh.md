# 1162. 一系列带手续费的货币兑换能否让钱变多

[Timus 1162](https://acm.timus.ru/problem.aspx?space=1&num=1162) · 难度 185 · shortest_paths

原题作者 Nick Durov，出自 2001 年 ACM ICPC 东北欧区域赛北部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `N ≤ 100` 种货币和 `M ≤ 100` 个兑换点，每个兑换点在两种货币之间双向兑换，
每个方向有各自的汇率和手续费：兑换 `x` 得到 `(x − 手续费)·汇率`，金额任何时候
都不能为负。初始持有 `V` 单位的货币 `S`，判断是否存在一系列兑换，最后回到货币
`S` 且金额大于 `V`。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N`、`M`、`S` 和 `V`，然后 `M` 行，每行是两种货币以及两个方向的汇率和手续费。

`1 ≤ S ≤ N ≤ 100`，`1 ≤ M ≤ 100`，`0 ≤ V ≤ 1000`。
汇率范围为 `[0.01, 100]`，手续费范围为 `[0, 100]`，两者最多有两位小数。
`V` 的小数位数没有限制。任意不重复使用兑换点的兑换序列，其最终金额与初始
金额之比小于 `10000`。

## 输出

`YES` 或 `NO`。

## 样例

### 样例 1

输入：

```
3 2 1 10.0
1 2 1.0 1.0 1.0 1.0
2 3 1.1 1.0 1.1 1.0
```

输出：

```
NO
```

### 样例 2

输入：

```
3 2 1 20.0
1 2 1.0 1.0 1.0 1.0
2 3 1.1 1.0 1.1 1.0
```

输出：

```
YES
```

## 解法

将货币看作顶点，每个兑换方向看作一条边。使用 Bellman–Ford，令 `best[c]`
表示货币 `c` 的最大可达金额。初始只有 `S` 可达，金额为 `V`。每轮读取旧数组，
写入新数组，因此第 `k` 轮结束时包含至多 `k` 次兑换的最优结果。先扣手续费，
再乘汇率；金额不足以支付手续费时跳过该兑换。

使用精确整数代替浮点数。设 `P` 为 2 与 `V` 小数位数的较大值，初始公分母为
`D = 10^P`。汇率和手续费均乘以 100 后存储。对于金额分子 `x`、汇率 `R`、
手续费 `C`，下一轮的分子是 `(x − C·(D/100))·R`，分母是 `100·D`。
保留的金额和初始金额也乘以 100，然后更新 `D`。这样所有可支付性和增益比较
都完全精确，不会丢失任何小数位。

如果没有可达的增益环，删掉两次访问同一顶点之间的片段不会减少金额，因此
至多 `N − 1` 次兑换的简单路径已经足够。第 `N` 轮仍有改进就证明存在可达的
增益环。由于汇率为正且手续费非负，该环的乘数大于 1，反复兑换会使金额
无限增长。每个兑换点都双向工作，最终一定付得起返回 `S` 的费用。此时或
`best[S] > V` 时输出 `YES`；某轮没有改进则输出 `NO`。

共有 `O(N·M)` 次松弛，并复制 `O(N²)` 个数组元素。整数有 `O(P+N)` 位，
所以精确计算的时间复杂度为 `O(N·(N+M)·(P+N))`，空间复杂度为
`O(N·(P+N)+M)`。

注意事项：

- 手续费先扣，且以源货币收取；零金额合法，必须区别零金额与不可达状态；
- 获利可能需要经过远离 `S` 的环；
- 测试 **08** 中 `0.000000001` 可以翻倍，绝对容差却会隐藏这笔利润；直接
  去掉浮点比较的容差又可能把舍入误差当成获利。必须精确读取 `V`，不能将其
  四舍五入到两位小数。

已验证全部 8 个固定测试、101 个生成用例、2500 个随机输入以及 600 个盈亏
临界点或微小偏差用例。随机用例通过精确分数穷举简单路径和闭环独立核对。
