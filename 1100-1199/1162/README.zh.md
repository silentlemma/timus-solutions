# 1162. 一系列带手续费的货币兑换能否让钱变多

[Timus 1162](https://acm.timus.ru/problem.aspx?space=1&num=1162) · 难度 197 · shortest_paths

原题作者 Nick Durov，出自 2001 年 ACM ICPC 东北欧区域赛北部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `N ≤ 100` 种货币和 `M ≤ 100` 个兑换点，每个兑换点在两种货币之间双向兑换，
每个方向有各自的汇率和手续费：兑换 `x` 得到 `(x − 手续费)·汇率`，金额任何时候
都不能为负。初始持有 `V` 单位的货币 `S`，判断是否存在一系列兑换，最后回到货币
`S` 且金额大于 `V`。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N`、`M`、`S` 和 `V`，然后 `M` 行，每行是两种货币以及两个方向的汇率和手续费。

## 输出

`YES` 或 `NO`。

## 样例

### 样例 1

输入：

```
3 2 1 10.0
1 2 1.0 1.0 1.0 1.0
2 3 1.1 1.0 1.1 1.0
```

输出：

```
NO
```

### 样例 2

输入：

```
3 2 1 20.0
1 2 1.0 1.0 1.0 1.0
2 3 1.1 1.0 1.1 1.0
```

输出：

```
YES
```

## 解法

把货币看作顶点，兑换点的每个方向看作一条边。设 `best[c]` 为能持有的货币 `c`
的最大金额，初始 `best[S] = V`。Bellman–Ford 松弛
`best[b] = max(best[b], (best[a] − 手续费)·汇率)`（仅当 `best[a] ≥ 手续费` 时
允许）一遍遍改进这些金额。每一步关于金额都是递增的，所以钱多永远不会更差。

若不存在增益环，最佳金额都由简单路径达到，简单路径最多 `N − 1` 次兑换，届时
各遍不再改变任何值。因此若经过 `N` 遍后仍有改变，就能到达一个增益环；反复
绕环可以让任何手续费都变得微不足道，而且由于每个兑换点都是双向的，总能回到
`S`，所以答案为 `YES`。一旦 `best[S]` 超过 `V`，答案也是 `YES`。否则为 `NO`。
`O(N·M)`。

注意事项：

- 手续费先扣，且以源货币收取；金额少于手续费时不能兑换；
- 获利可能需要绕道经过远离 `S` 的环；
- 双精度数比较时用一个很小的容差，以免舍入误差看起来像获利。

答案已在所有测试和 150 个随机输入上，与用精确分数做同样松弛、遍数多十倍的
结果比对。
