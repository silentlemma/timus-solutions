# 1120. Самая длинная серия последовательных натуральных чисел с данной суммой

[Timus 1120](https://acm.timus.ru/problem.aspx?space=1&num=1120) · сложность 87 · math

Автор оригинальной задачи — Леонид Волков; USU Open Collegiate Programming Contest, октябрь 2001 года, Junior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано `1 ≤ S ≤ 10^9`. Найти натуральные `A` и `N`, для которых
`S = A + (A + 1) + … + (A + N − 1)`, а `N` как можно больше.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`S`.

## Выходные данные

`A N`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
14
```

Вывод:

```
2 4
```

## Решение

Сумма серии равна `N·A + N(N − 1)/2`, поэтому при данном `N` начало
`A = (S − N(N − 1)/2) / N` должно быть натуральным. `A ≥ 1` означает
`N(N + 1)/2 ≤ S`, так что `N` не больше примерно `√(2S) ≈ 44721`.
Перебираем `N` вниз от этой границы и останавливаемся на первом, при
котором деление нацело; `N = 1` подходит всегда. `O(√S)`.

Тонкие места:

- квадратный корень может округлиться вверх: начинать с `⌊√(2S)⌋` и
  уменьшать `N`, пока `N(N + 1)/2 > S`;
- `N(N + 1)/2` при `N ≈ 44721` около `10^9` и помещается в 32 бита, но
  решения на C++, Go, Java и Rust используют 64-битные целые, а Python —
  целые произвольной точности;
- у степени двойки нет нечётных делителей больше 1, поэтому подходит
  только `N = 1` (тест 08).

Ответы проверены перебором всех начал и длин для `S ≤ 3000`, а для
больших `S` — через делители: серия длины `N` существует ровно тогда,
когда `N` делит `2S`, а `2S/N − N + 1` положительно и чётно.

## Оптимизированные решения

`1120_number_theory.py`. Вместо просмотра всех длин прогрессии факторизуется нечётная часть S и перебираются её делители. Каждый нечётный делитель даёт длины d и2S/d; условие length(length+1)≤2S обеспечивает положительное начало, затем выбирается максимум. Используются пробные нечётные делители, короткий рекурсивный генератор и точные целые. Необязательный PyPy JIT отключён для короткого сканирования, вывод сбрасывается перед прямым завершением. Консервативно O(√S+τ(S)) арифметических операций и O(log S) состояния множителей/рекурсии; простой перебор длин сохранён.

По сравнению с `1120_math.py`: время 0.078 s → 0.109 s; память 444 KB → 308 KB.

Оптимизированное решение на Java разбирает число побайтно из `System.in`
вместо `Scanner` и пересчитывает остаток для следующей, более короткой
длины за O(1): 368 КБ вместо 1640 КБ при том же времени.

`1120_math_optimized.rs`. Наибольшая длина с N(N+1)/2<=S находится целочисленным двоичным поиском; далее длины перебираются вниз до делимости S-N(N-1)/2 на N. Корень с плавающей точкой исключён, убывающий поиск сохранён. При S<=10^9 все произведения двоичного поиска помещаются в i64. Время O(log S+√S)=O(√S), дополнительная память O(1). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1120_math.rs`: время 0.046 s → 0.031 s; память 220 KB → 56 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1120_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
