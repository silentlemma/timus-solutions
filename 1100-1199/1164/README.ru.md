# 1164. Какие буквы останутся после поиска всех слов филворда

[Timus 1164](https://acm.timus.ru/problem.aspx?space=1&num=1164) · сложность 207 · strings

Автор оригинальной задачи — Alex Selivanov; северный подрегион полуфинала ACM ICPC Северо-Восточной Европы 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В сетке `N×M` из заглавных букв (`2 ≤ N, M ≤ 10`) спрятаны `P ≤ 100`
слов. Каждое слово занимает путь из соседних по стороне клеток, и ни одна
клетка не принадлежит двум словам или дважды одному слову. Правильная
расстановка всегда существует. Вывести в алфавитном порядке буквы клеток,
не занятых ни одним словом.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, `M` и `P`, затем `N` строк сетки, затем `P` слов.

## Выходные данные

Оставшиеся буквы по порядку в одной строке.

## Проверка

Точно сравнивается строка оставшихся заглавных букв; пустому остатку соответствует пустой вывод. Новый точный исходник Python прошёл 11 тестов репозитория на PyPy 3.10. Остальные сохранённые варианты имеют собственные проверки целевой среды и точные Accepted. Вывод сравнивается по правилам проверяющего модуля задачи.

## Примеры

### Пример 1

Ввод:

```
3 3 2
EBG
GEE
EGE
BEG
GEE
```

Вывод:

```
EEG
```

## Решение

Искать пути не нужно. Для каждой буквы `c` пусть `G[c]` — число
её клеток в сетке, а `U[c]` — количество в перечисленных словах. Любое
допустимое размещение использует ровно `U[c]` различных клеток с буквой
`c`: путь не повторяет клетки, разные слова не пересекаются. Поэтому
после любого размещения остаётся ровно `G[c] − U[c]` копий буквы,
независимо от геометрии. Гарантия существования размещения обеспечивает
неотрицательность разностей.

Считаем буквы сетки, вычитаем буквы слов с учётом повторений и выводим
каждую букву от `A` до `Z` оставшееся число раз. Получается ровно нужное
мультимножество в отсортированном порядке. Повторяющиеся слова расходуют
свои буквы отдельно. Если заняты все клетки, выводим пустую строку.
Из гарантии также следует суммарная длина слов `W ≤ N M ≤ 100`,
поэтому и длина каждого слова не превосходит 100.

Время — `O(N M + W + 26)`. Нативные базы хранят 26 счётчиков, понятная
база Python использует `Counter`. С учётом хранимого ввода и вывода
для всех версий подходит оценка памяти `O(N M + W)`; потоковые версии
хранят меньше входа. Все пять исходных Accepted-файлов сохранены побайтово.

## Оптимизированные решения

Все размещения расходуют один и тот же набор букв с кратностями. Сохраняются понятные счётчики и компактный C++-вариант. Python для каждой из 26 заглавных букв считает вхождения в поле и объединённых словах, затем выводит положительную разность в алфавитном порядке. Постоянный множитель размера алфавита сохраняет линейное время. Не нужны импорт Counter и отдельные словари частот, но строки ввода остаются в памяти. Существующие текстовые потоки и прямая запись результата убирают дополнительные обёртки ввода. Подтверждён выигрыш только памяти; ухудшение времени приведено ниже.

- `1164_strings_optimized.cpp`: 0.015 s / 104 KB; база `1164_strings.cpp`: 0.015 s / 380 KB; изменение относительно базы: время -0.0%, память -72.6%.
- `1164_strings_optimized.py`: 0.109 s / 260 KB; база `1164_strings.py`: 0.078 s / 436 KB; изменение относительно базы: время +39.7%, память -40.4%.

## Особенности языков

Сохранённые срезы: 1–2 ноября 2026 года. Цель C++ — топ 15% либо первые 10 мест одновременно по времени и памяти; других семейств — первое место по обеим метрикам. Ничьи делят место. Пустые выборки дают только формальное покрытие.

Используется сохранённый профиль текущих компиляторов; исключены собственный автор и старые строки со временем меньше 0,015 с. Для семейств кроме C++ дополнительно требуется ID посылки ≥10770000; память C++ сравнивается по первым 1000 подходящим строкам. Собственные времена меньше 0,015 с считаются 0,015 с.
