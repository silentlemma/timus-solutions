# 1164. Какие буквы останутся после поиска всех слов филворда

[Timus 1164](https://acm.timus.ru/problem.aspx?space=1&num=1164) · сложность 207 · strings

Автор оригинальной задачи — Alex Selivanov; северный подрегион полуфинала ACM ICPC Северо-Восточной Европы 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В сетке `N×M` из заглавных букв (`2 ≤ N, M ≤ 10`) спрятаны `P ≤ 100`
слов. Каждое слово занимает путь из соседних по стороне клеток, и ни одна
клетка не принадлежит двум словам или дважды одному слову. Правильная
расстановка всегда существует. Вывести в алфавитном порядке буквы клеток,
не занятых ни одним словом.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, `M` и `P`, затем `N` строк сетки, затем `P` слов.

## Выходные данные

Оставшиеся буквы по порядку в одной строке.

## Проверка

Точно сравнивается строка оставшихся заглавных букв; пустому остатку соответствует пустой вывод. Новый точный исходник Python прошёл 11 тестов репозитория на PyPy 3.10. Остальные сохранённые варианты имеют собственные проверки целевой среды и точные Accepted. Вывод сравнивается по правилам проверяющего модуля задачи.

## Примеры

### Пример 1

Ввод:

```
3 3 2
EBG
GEE
EGE
BEG
GEE
```

Вывод:

```
EEG
```

## Решение

Искать пути не нужно. Для каждой буквы `c` пусть `G[c]` — число
её клеток в сетке, а `U[c]` — количество в перечисленных словах. Любое
допустимое размещение использует ровно `U[c]` различных клеток с буквой
`c`: путь не повторяет клетки, разные слова не пересекаются. Поэтому
после любого размещения остаётся ровно `G[c] − U[c]` копий буквы,
независимо от геометрии. Гарантия существования размещения обеспечивает
неотрицательность разностей.

Считаем буквы сетки, вычитаем буквы слов с учётом повторений и выводим
каждую букву от `A` до `Z` оставшееся число раз. Получается ровно нужное
мультимножество в отсортированном порядке. Повторяющиеся слова расходуют
свои буквы отдельно. Если заняты все клетки, выводим пустую строку.
Из гарантии также следует суммарная длина слов `W ≤ N M ≤ 100`,
поэтому и длина каждого слова не превосходит 100.

Время — `O(N M + W + 26)`. Нативные базы хранят 26 счётчиков, понятная
база Python использует `Counter`. С учётом хранимого ввода и вывода
для всех версий подходит оценка памяти `O(N M + W)`; потоковые версии
хранят меньше входа. Все пять исходных Accepted-файлов сохранены побайтово.

## Оптимизированные решения

`1164_strings_optimized.java`. Java сохраняет 26 балансов букв: прибавить буквы поля, вычесть буквы всех слов и вывести положительные остатки по алфавиту. Любое допустимое размещение расходует одно и то же мультимножество, поэтому поиск путей не нужен. countLetters считает заглавные байты токена прямо в пополняемом буфере на 1024 байта, без строк слов, декодирования UTF-8 и массивов символов. Ответ по-прежнему собирается через StringBuilder. Для W букв слов и A букв ответа время O(N*M+W+A); дополнительная память O(A+26) плюс фиксированный буфер ввода. Учебные версии сохранены.

Accepted точного исходника Java 1.8 №11327328: 0.093 с / 456 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 4/32, память 2/32. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11324785: 0.109 с / 500 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1164_strings_optimized.java`: 0.093 s / 456 KB; сохранённая учебная база `1164_strings.java`: 0.109 s / 1640 KB.

`1164_strings_optimized.rs`. Сохраняются 26 балансов букв: буквы поля добавляются, буквы слов вычитаются. Строки и слова читаются напрямую, оставшиеся буквы выводятся по алфавиту без хранения входного текста и строки ответа. Время O(I+A) для I байт входа и A букв ответа; память постоянного алфавита.

По сравнению с `1164_strings.rs`: время 0.015 s → 0.015 s; память 220 KB → 60 KB.

Все размещения расходуют один и тот же набор букв с кратностями. Сохраняются понятные счётчики и компактный C++-вариант. Python для каждой из 26 заглавных букв считает вхождения в поле и объединённых словах, затем выводит положительную разность в алфавитном порядке. Постоянный множитель размера алфавита сохраняет линейное время. Не нужны импорт Counter и отдельные словари частот, но строки ввода остаются в памяти. Существующие текстовые потоки и прямая запись результата убирают дополнительные обёртки ввода. Подтверждён выигрыш только памяти; ухудшение времени приведено ниже.

- `1164_strings_optimized.cpp`: 0.015 s / 104 KB; база `1164_strings.cpp`: 0.015 s / 380 KB; изменение относительно базы: время -0.0%, память -72.6%.
- `1164_strings_optimized.py`: 0.109 s / 260 KB; база `1164_strings.py`: 0.078 s / 436 KB; изменение относительно базы: время +39.7%, память -40.4%.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1164_strings_optimized.go`. Алгоритм и обработка границ сохранены. Вместо сканирования и печати через fmt используются разбор токенов и чисел и повторно используемый выходной буфер. Ввод целиком хранится в байтовом буфере: это обмен памяти под ввод на меньшие накладные расходы универсального ввода-вывода.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
