# 1143. 经过凸多边形所有顶点的最短路径

[Timus 1143](https://acm.timus.ru/problem.aspx?space=1&num=1143) · 难度 589 · dp

原题出自越南 IOI 国家队选拔赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`N ≤ 200` 个营地位于凸多边形的顶点上，按逆时针顺序给出实数坐标。求从任意
营地出发、经过所有营地的最短路径长度，保留三位小数输出。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N`，然后 `N` 行顶点坐标。

## 输出

最短路径的长度，保留三位小数。

## 样例

### 样例 1

输入：

```
4
50.0 1.0
5.0 1.0
0.0 0.0
45.0 0.0
```

输出：

```
50.211
```

## 解法

最短路径不会自交：如果它的两条线段相交，把它们之间的部分反转，就能用两条
总长更短的线段替换它们（三角不等式）。对凸位置的点，这推出一个很强的结论：
任何时刻已访问的顶点构成多边形的一段弧，而路径停在弧的一端。否则路径就得
越过这段弧到另一侧，之后的某条线段会与之前的线段相交。

所以状态是一段弧 `(i, length)` 以及路径所在的那一端。弧可以从任一端向任一
侧增加一个顶点，共四种转移。令 `at[i]` 和 `at_end[i]` 为从顶点 `i` 开始的弧
上、停在弧的第一个或最后一个顶点的最短路径。从所有长度为 1、代价为 0 的弧
开始，扩展到长度 `N`，取最小值。时间 `O(N²)`，每个长度 `O(N)` 内存。

注意事项：

- 绕多边形一圈并不总是最优：在细长的多边形里，路径会在两条长边之间来回
  折返；
- `N = 1` 时答案为 `0.000`；
- 弧会跨过顶点列表的末尾，所以下标要对 `N` 取模；
- 答案必须恰好保留三位小数。

答案已在 120 个最多 11 个顶点的随机多边形上（包括细长椭圆和挤在短弧上的
顶点）与不依赖凸性的 Held–Karp 全子集搜索比对。

## 各语言说明

- 所有语言都用同样的弧上动态规划，每个长度两个数组。
- Java 用 `Locale.US` 格式化答案，保证小数点是点号。

## 优化解法

Go 版本原地更新两个弧段动态规划数组。每轮先保存第一对值，以便处理最后一个状态时仍能读取上一轮的数据。提交 11317228 耗时 0.046 秒，使用 948 KB；基础版耗时 0.031 秒，使用 1856 KB。

Python 提交 11318126 耗时 0.125 秒，使用 736 KB。简单版本耗时 0.156 s，使用 2176 KB。

预先计算相邻顶点之间的距离，供所有弧长复用。原地更新两个动态规划数组，同时保存首项供跨过多边形起点的最后一段弧使用。

Java 提交 11318129 耗时 0.125 秒，使用 1560 KB。简单版本耗时 0.156 s，使用 1804 KB。

**简单版本的 Timus 提交记录**

G++ 13.2 x64 №11321852 · Go 1.14 x64 №11322217 · Java 1.8 №11322218 · Python 3.12 x64 №11322219 · Rust 1.75 x64 №11322220.

C++ 将环复制一遍，预计算相邻点间距离，再原地更新弧段两端的代价。 G++ 13.2 x64（提交 11322408）的运行时间从 0.015 秒变为 0.015 秒，内存从 228 KB 变为 148 KB。

Rust 原地更新两行环形区间代价，并在每轮扫描前保存跨越边界的值。 Rust 1.75 x64（提交 11323271）的运行时间从 0.031 秒变为 0.046 秒，内存从 288 KB 变为 144 KB。
