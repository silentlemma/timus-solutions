# 1127. Самая высокая башня из кубиков с одноцветными боковыми гранями

[Timus 1127](https://acm.timus.ru/problem.aspx?space=1&num=1127) · сложность 323 · bruteforce

Автор оригинальной задачи — Екатерина Васильева; VI студенческое соревнование по программированию УрГУ, 21 октября 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `N` кубиков (`1 < N ≤ 1000`); у каждой грани кубика есть цвет (одна
из 10 букв), и все шесть граней кубика разного цвета. Грани даны в
порядке: передняя, правая, левая, задняя, верхняя, нижняя. Поставить друг
на друга как можно больше кубиков, повернув каждый как угодно, так чтобы
каждая из четырёх боковых сторон башни была одного цвета. Вывести высоту.

Ограничение времени: 0,4 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк по шесть букв-цветов.

## Выходные данные

Наибольшая высота.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4
GYVABW
AOCGYV
CABVGO
OVYWGA
```

Вывод:

```
3
```

## Решение

Башня задаётся кольцом цветов своих боковых сторон: передняя, правая,
задняя, левая. Кубик подходит к кольцу, если одна из его 24 ориентаций
показывает ровно это кольцо. Так как его шесть цветов различны, каждое
кольцо кубик показывает не более чем в одной ориентации, поэтому подсчёт
для каждого кольца кубиков, которые могут его показать, даёт высоту
самой высокой башни с этим кольцом. 24 ориентации строятся один раз из
двух поворотов на четверть — вокруг вертикальной оси и вокруг оси
«лево-право» — как перестановки шести позиций граней. `O(24·N)`.

Тонкие места:

- повороты должны быть вращениями, а не отражениями: поворот на четверть
  переводит переднюю грань вправо, правую назад и так далее, сохраняя
  ориентацию;
- зеркальное отражение кубика всё равно подходит: перевёрнутое вокруг
  оси «перед-зад», оно показывает то же кольцо боковых граней, лишь верх
  и низ меняются местами, а они не важны;
- при фиксированной ориентации цвета верхней и нижней граней не важны.

Ответы проверены отдельным построением 24 вращений как знаковых матриц
перестановок с определителем +1, действующих на нормали граней, на всех
тестах.

## Оптимизированные решения

`1127_bruteforce_optimized.java`. Сохраняются24 собственных вращения куба и максимум одинаковых упорядоченных колец боковых граней. Вращения генерируются в фиксированных примитивных массивах, десять символов цвета получают ID0..9, четыре боковых ID упаковываются в десятичный ключ. Один int[10000] заменяет HashMap строк колец, счётчики-объекты и множества вращений. Шесть цветов каждого куба различны, поэтому его24 кольца различны и прямой инкремент не считает куб дважды для одного кольца. Время O(24*N+10000), включая обнуление таблицы; память —10000 целых счётчиков, фиксированные вращения/цвета и байтовый ввод, независимо от N.

По сравнению с `1127_bruteforce.java`: время 0.171 s → 0.093 s; память 6664 KB → 576 KB.

Go и Rust считают три боковых кольца, выбирая каждую пару противоположных граней верхом и низом. Все шесть цветов кубика различны, поэтому у кольца единственный наименьший цвет. Поворачиваем кольцо к нему и выбираем меньшее направление обхода для объединения равнозначных колец. Четыре цвета кодируются в системе счисления с основанием C = 10, а частоты хранятся в плоском массиве 16-битных счётчиков.

Принятая версия Go 1.14 x64 заняла 0.046 с при 0.031 с у базовой и использовала 896 KB при 1344 KB у базовой.

Принятые базовые реализации [1127_bruteforce.cpp](1127_bruteforce.cpp), [1127_bruteforce.java](1127_bruteforce.java), [1127_bruteforce.py](1127_bruteforce.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1127_bruteforce_optimized.java`: место по времени 1/31, по памяти 1/31 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
