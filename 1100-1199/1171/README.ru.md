# 1171. Путь вниз по космической станции с лучшим количеством еды в день

[Timus 1171](https://acm.timus.ru/problem.aspx?space=1&num=1171) · сложность 1265 · dp

Автор оригинальной задачи — Mugurel Ionut Andreica; Romanian Open Contest, декабрь 2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В станции `N ≤ 16` уровней, каждый — сетка `4×4` комнат с едой от 1 до
255, в некоторых комнатах есть дверь в ту же комнату уровнем ниже.
Начиная в заданной комнате верхнего уровня, космонавт делает один шаг в
день (север, восток, юг, запад или вниз через дверь), не заходит в
комнату дважды, не поднимается и должен закончить на уровне 1. Каждая
посещённая комната даёт свою еду. Максимизировать собранную еду, делённую
на число дней, то есть на число посещённых комнат, и вывести такой путь.

Ограничение времени: 1 секунда. Ограничение памяти: 4 МБ.

## Входные данные

`N`, затем для каждого уровня сверху вниз четыре строки еды и четыре
строки дверей, затем строка и столбец начальной комнаты.

## Выходные данные

Лучшее отношение с четырьмя знаками после запятой, число ходов и, если они
есть, сами ходы буквами `N`, `E`, `S`, `W` и `D`.

## Проверка

Принимается любой путь, который допустим, кончается на уровне 1 и
достигает лучшего отношения; проверяющая программа повторяет ходы.

0 0 0 0

Вывод:

```

```

## Решение

Внутри одного уровня путь — простой путь в сетке `4×4`, а их всего
28 512. Для каждого уровня обход в глубину по всем им записывает
`best[s][e][k]` — наибольшую еду на пути из `k` комнат от `s` до `e`.

Отношение максимизируется методом Динкельбаха. Для текущего отношения
`num/den` ищем путь с наибольшим `den·еда − num·комнаты`. Это простая
динамика снизу вверх: ценность входа на уровень в комнату `s` — лучшее по
выходам `e` (дверям, а на уровне 1 любым комнатам) и длинам `k` значение
`den·best[s][e][k] − num·k` плюс ценность входа на следующий уровень в
`e`. Если лучший путь даёт больше нуля, его собственное отношение выше, и
оно становится новым `num/den`; когда больше нуля не даёт ничего,
отношение оптимально. Всё это целочисленная арифметика, так что остановка
точная. Каждый раунд стоит `O(N·16³)`, а раундов немного.

В конце путь восстанавливается: на каждом уровне второй обход ищет путь
от его начала до его конца с записанными длиной и едой.

Тонкие места:

- путь должен дойти до уровня 1, поэтому на верхних уровнях путь по
  уровню может кончаться только в комнатах с дверью, а на уровне 1 — в
  любой;
- дни — это посещённые комнаты, на одну больше, чем ходов, и на одном
  уровне с богатой стартовой комнатой ходов может не быть совсем;
- ограничение памяти 4 МБ, поэтому сами пути не хранятся, только лучшая
  еда для каждого начала, конца и длины.

Отношения сверены с отдельно написанным решением на 300 случайных
станциях от 1 до 16 уровней, и каждый выведенный путь прошёл проверяющую
программу.
