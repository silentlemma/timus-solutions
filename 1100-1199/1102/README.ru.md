# 1102. Разбиение строки на слова странного диалога

[Timus 1102](https://acm.timus.ru/problem.aspx?space=1&num=1102) · сложность 176 · strings

Автор оригинальной задачи — Катя Овечкина; Tetrahedron Team Contest, май 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Диалог — любая последовательность слов `out`, `output`, `puton`, `in`,
`input` и `one`, записанная без пробелов. Для каждой из `N` строк
(`N ≤ 1000`, строчные латинские буквы, всего `≤ 4 · 10^6` букв) выведите
`YES`, если это диалог, и `NO` иначе.

Ограничение времени: 1 секунда. Ограничение памяти: 16 МБ.

## Входные данные

`N` (`1 ≤ N ≤ 1000`), затем `N` непустых строк из строчных латинских
букв.

## Выходные данные

`YES` или `NO` для каждой строки.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
puton
inonputin
oneputonininputoutoutput
oneininputwooutoutput
outpu
utput
```

Вывод:

```
YES
NO
YES
NO
NO
NO
```

## Решение

При чтении вперёд слова неудобно перекрываются: `out` — начало `output`,
`in` — начало `input`, а `output` + `one` читается как `out` + `puton` +
`e`. При чтении назад они превращаются в `tuo`, `tuptuo`, `notup`, `ni`,
`tupni` и `eno`, и ни одно из них не является началом другого. Значит, в
каждой точке может заканчиваться не больше одного слова, и жадное
отрезание слов с конца строки по одному либо съедает всю строку, либо
доказывает, что разбиения нет. `O(L)` для `L` букв.

Подводные камни:

- жадность вперёд, всегда берущая самое длинное слово, ошибается:
  `outputon` — это `out` + `puton`, а если сначала взять `output`,
  останется `on`;
- строки длинные, а ограничение памяти всего 16 МБ, поэтому копий всего
  ввода нужно избегать.

Ответы сверены с динамикой по префиксам вперёд — на всех диалогах до трёх
слов, на почти диалогах и на случайных испорченных строках.

## Оптимизированные решения

Оптимизированное решение на C++ распознаёт диалоги конечным автоматом
вместо отрезания слов с конца. Шесть слов, всего 24 буквы, образуют бор
не больше чем из 25 вершин, так что множество вершин бора помещается в
32-битную маску. Состояние — множество вершин, до которых дошли читаемые
сейчас слова, причём корень означает ещё и то, что прочитанный префикс
разбивается на целые слова; немногие такие множества, достижимые из
корня, находятся один раз в начале и получают таблицу переходов. Дальше
каждая буква стоит одного обращения к таблице, строка нигде не хранится,
а ответ `YES`, если в конце строки корень входит в множество. Вместо
чтения строки длиной до четырёх миллионов букв в `string` через `cin`
ввод читается блоками по 4 КБ: {1102_parsing.cpp}.

Оптимизированное решение на Go распознаёт диалоги конечным автоматом
вместо отрезания слов с конца. Шесть слов, всего 24 буквы, образуют бор
не больше чем из 25 вершин, так что множество вершин бора помещается в
32-битную маску. Состояние — множество вершин, до которых дошли читаемые
сейчас слова, причём корень означает ещё и то, что прочитанный префикс
разбивается на целые слова; немногие такие множества, достижимые из
корня, находятся один раз в начале и получают таблицу переходов. Дальше
каждая буква, взятая прямо из буферизованного ввода, стоит одного
обращения к таблице, строка не хранится как `string`, а ответ `YES`,
если в конце строки корень входит в множество: {1102_parsing.go}.

Оптимизированное решение на Java с динамикой читает ввод побайтно из
буферизованного потока и идёт по строке вперёд: `good[i]` говорит,
разбиваются ли первые `i` букв на слова, и истинно, если на букве `i`
заканчивается одно из шести слов, а перед этим словом `good` истинно.
Слово длиной не больше шести букв, поэтому в кольцевом буфере хранятся
только последние семь букв и значений, и строка нигде не хранится, тогда
как простое решение на Java читает каждую строку в массив из четырёх
миллионов символов: {1102_dp.java}.

Оптимизированное решение на Java с автоматом распознаёт диалоги конечным
автоматом вместо отрезания слов с конца. Шесть слов, всего 24 буквы,
образуют бор не больше чем из 25 вершин, так что множество вершин бора
помещается в 32-битную маску. Состояние — множество вершин, до которых
дошли читаемые сейчас слова, причём корень означает ещё и то, что
прочитанный префикс разбивается на целые слова; немногие такие
множества, достижимые из корня, находятся один раз в начале и получают
таблицу переходов. Дальше каждый байт, прочитанный блоками по 4 КБ,
стоит одного обращения к таблице, а ответ `YES`, если в конце строки
корень входит в множество. Строка нигде не хранится, тогда как простое
решение на Java читает каждую строку в массив из четырёх миллионов
символов: {1102_parsing.java}.

Оптимизированное решение на Rust распознаёт диалоги конечным автоматом
вместо отрезания слов с конца. Шесть слов, всего 24 буквы, образуют бор
не больше чем из 25 вершин, так что множество вершин бора помещается в
32-битную маску. Состояние — множество вершин, до которых дошли читаемые
сейчас слова, причём корень означает ещё и то, что прочитанный префикс
разбивается на целые слова; немногие такие множества, достижимые из
корня, находятся один раз в начале и получают таблицу переходов. Дальше
каждая буква стоит одного обращения к таблице прямо в блоках входного
буфера, а ответ `YES`, если в конце строки корень входит в множество. Ни

## Особенности языков

- Python сопоставляет перевёрнутую строку с регулярным выражением
  `(?:tuo|tuptuo|notup|ni|tupni|eno)*+`; притяжательный `*+` не хранит
  состояний для отката, и это безопасно, потому что разбиение
  единственно.
- Java читает каждую строку посимвольно в один массив `char`,
  рассчитанный на четыре миллиона букв всего ввода, 8 МБ: `readLine`
  сделал бы ещё и временные копии длинной строки, а они не помещаются в
  16 МБ.
