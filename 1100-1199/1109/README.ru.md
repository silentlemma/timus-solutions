# 1109. Наименьшее число рёбер, касающихся всех вершин двудольного графа

[Timus 1109](https://acm.timus.ru/problem.aspx?space=1&num=1109) · сложность 249 · matching

Оригинальная задача — Болгарская национальная олимпиада по информатике, первый день.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Двудольный граф имеет `M` вершин слева и `N` справа (`M, N ≤ 1000`) и
`K` рёбер, каждое соединяет левую вершину с правой; у каждой вершины есть
хотя бы одно ребро. Найти наименьшее число рёбер, такое что каждая
вершина — конец хотя бы одного выбранного ребра.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`M N K`, затем `K` строк `a b`: ребро между левой вершиной `a` и правой
вершиной `b`. Рёбра могут повторяться.

## Выходные данные

Наименьшее число рёбер.

## Проверка

Сравнивается один целочисленный токен. Фактический Python-кандидат
сверен с независимым перебором паросочетаний на всех 46312 двудольных графах
без изолированных вершин с долями до четырёх. Для 327 графов до 3×3 ответ
также проверен прямым перебором подмножеств рёберного покрытия, без формулы
через паросочетание. Все шесть реальных кандидатов отдельно прошли по
82 дополнительных графа и 12 входов репозитория в Docker, затем получили
собственные Accepted для точных исходников.

Дополнительные случаи: чередующаяся цепь на 1000 вершинах доли, миллион
различных рёбер, блоки с дефицитом по Холлу, повторы, границы 63/64/65 бит.
Python также проверен на 16 разрывах числа/пары между блоками и последнем
токене без завершающего пробела. 46312 запусков относятся только к Python,
не к каждому машинному файлу. Четыре стресс-входа CPython локально дали
до 0,194 с процессорного времени и 17240 КБ RSS, при лимите 0,5 с/64 МБ;
локальный RSS не является метрикой памяти судьи.

## Решение

Представим делегатов вершинами двудольного графа, разрешённые звонки —
рёбрами. По гарантии у каждой вершины есть сосед. Максимальное паросочетание
размера `q` покрывает `2q` вершин. Для каждой оставшейся добавим любое
инцидентное ребро. Две непокрытые вершины не соседствуют, иначе паросочетание
увеличилось бы. Получаем рёберное покрытие размера `M+N−q`.

Для нижней границы возьмём произвольное рёберное покрытие с `c` компонентами.
В нём не менее `M+N−c` рёбер. По одному ребру из каждой компоненты образуют
паросочетание размера `c`, значит `c≤q`. Любое покрытие имеет не менее
`M+N−q` рёбер, поэтому это точный ответ. Гарантия отсутствия изолированных
вершин необходима.

Основной учебный C++ использует DFS Куна. Сначала строим любое жадное
паросочетание, затем для каждой изначально свободной левой вершины ищем
увеличивающий путь, помечая посещённые правые вершины номером поиска.
Жадное паросочетание уже максимально на множестве покрытых им левых
вершин. Добавление одной свободной левой вершины увеличивает оптимум
не более чем на один; новый увеличивающий путь обязан начинаться в ней.
При успехе переворачиваем путь, при неудаче оптимум не меняется. Индукция
доказывает максимальность после всех вершин. Более короткий алгоритм
проверен на C++; о непроверенных портах утверждений нет.
Время `O(M(V+K))`, память `O(V+K)`, `V=M+N`, включая инициализацию.

Все пять прежних Accepted-версий со слоями BFS и DFS сохраняются. Поиск
идёт до отсутствия увеличивающих путей, что через симметрическую разность
доказывает максимальность. Но длина найденного пути не всегда кратчайшая:
для строк `[1,2,3]`, `[2,3]`, `[1]` Python может взять путь из пяти рёбер
при наличии пути из трёх. Для этих реализаций используем безопасную оценку
`O(L(V+K))`: текущие указатели рёбер и не более `L=min(M,N)` успешных фаз,
без предположения о строгой оценке Хопкрофта–Карпа по кратчайшим путям.
Память — `O(V+K)`.

## Оптимизированные решения

Новый алгоритм хранит по битовой строке соседей для левой вершины;
левой выбираем меньшую долю `L=min(M,N)`, правой — `R=max(M,N)`.
Для новой левой вершины BFS ищет чередующийся путь. Сначала пересекаем
соседей со свободными правыми вершинами: найденная вершина завершает поиск.
Иначе все соседи заняты: каждую ещё не посещённую правую вершину отмечаем,
сохраняем левого предка и ставим в очередь её единственного партнёра.
В очереди не более `L` вершин. По предкам и прежним парам переворачиваем
путь до свободного корня. Если свободный конец недостижим, увеличивающего
пути нет. Та же индукция по добавленным левым вершинам доказывает максимум.

Повторы рёбер устанавливают тот же бит. Неиспользуемые биты последнего
машинного слова не встречаются в строках смежности и не дают ложных вершин.
При `B=ceil(R/w)` консервативно `O(K+L²B+LR)` операций над словами,
`O(LB+V)` слов памяти плюс ограниченные буферы ввода. У машинных реализаций
слово 64-битное, у Python — разряды длинного целого. Если свободного соседа
нет, извлекаются не более `L` занятых правых вершин; это ограничивает
и повторную работу с длинными целыми Python.

Python сначала строит изменяемые байтовые строки, затем по разу превращает
их в целые: не копирует широкую маску на каждом ребре. Блоки ввода по
65536 байт сохраняют незавершённое число и половину пары между блоками;
машинные версии используют буферы по 4096 байт. Выводится одно число.
Алгоритм отличается от DFS и прежнего поиска по слоям, поэтому имя отдельное.

Все пять допущены по памяти: C++ 280 КБ против НОВОЙ простой базы 496 КБ
(−43,5%), Go 1292/2512 (−48,6%), Java 680/1264 (−46,2%), Python 3868/8516
(−54,6%), Rust 356/1820 (−80,4%). C++ 0,031→0,015 с — один тик,
надёжное ускорение не заявлено. Python: 0,140 против 0,093 с, на 50,5%
больше записанного времени. У Java/Go/Rust время тоже выше на один тик.
Это экономия памяти с явно указанным компромиссом по времени.

## Особенности языков

Новый DFS C++ — основная простая база; прежний C++ со слоями оставлен
дополнительным Accepted-алгоритмом. Остальные языки сохраняют прежние
простые базы. Все быстрые версии сравниваются с ТЕКУЩЕЙ базой своего языка,
включая новый Accepted C++. Python остаётся на CPython 3.12.

Снимок от 2 ноября 2026 года: быстрый C++ — 1/1 против 74 отфильтрованных
чужих записей. Java — 3/1 против шести, Python — 11/12 против 25;
обе версии помечены звёздочками, улучшение возможно. Выборки Go/Rust пусты,
покрытие формальное. Для C++ цель — топ 15% или первые десять мест по двум
метрикам, для других семейств — первое место по обеим. Допущенная экономия
памяти ниже рейтинговой цели остаётся допустимой со звёздочкой.
