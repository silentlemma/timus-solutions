# 1109. 覆盖二分图所有顶点的最少边数

[Timus 1109](https://acm.timus.ru/problem.aspx?space=1&num=1109) · 难度 249 · matching

原题出自保加利亚全国信息学奥林匹克竞赛第一天。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个二分图左侧有 `M` 个顶点，右侧有 `N` 个顶点（`M, N ≤ 1000`），共 `K` 条边，每条边连接一个左顶点和一个右顶点；每个顶点至少有一条边。求最少选多少条边，才能使每个顶点都是至少一条所选边的端点。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

`M N K`，然后是 `K` 行 `a b`：左顶点 `a` 与右顶点 `b` 之间的一条边。边可能重复。

## 输出

最少的边数。

## 评测方式

按一个整数 token 比较。实际 Python 与独立子集匹配枚举对照了两侧至多
四个顶点、无孤立点的全部 46312 个图。327 个至多 3×3 的图还直接枚举边覆盖
子集，不假定匹配公式。六个实际候选分别通过 Docker 中 82 个额外图形及 12 个
仓库输入，且各自取得精确源码 Accepted。

额外图形包括每侧最多 1000 点的交替链、百万条不同边、Hall 缺陷块、重复边及
63/64/65 位边界。Python 还检查 16 个数字或端点对的分块边界及末 token 无
空白结束。46312 次只执行 Python，不是每个原生程序执行这么多次。
四个 CPython 压力输入本地最高 0.194 CPU 秒、17240 KB RSS，符合 0.5 秒及
64 MB 限制；本地 RSS 不等于评测内存。

## 样例

### 样例 1

输入：

```
3 2 4
1 1
2 1
3 1
3 2
```

输出：

```
3
```

## 解法

把两国代表作为二分图顶点，允许通话作为边。题目保证每个顶点有邻居。
最大匹配大小为 `q` 时，其边覆盖 `2q` 个顶点；给每个未覆盖顶点加一条邻接边。
两个未匹配顶点不可能相邻，否则可增大匹配。因此得到 `M+N−q` 条边的边覆盖。

任意边覆盖若有 `c` 个连通分量，至少有 `M+N−c` 条边；每个分量取一条边
得到大小 `c` 的匹配，故 `c≤q`。任何覆盖至少有 `M+N−q` 条边，证明答案。
无孤立点保证不可缺少。

首选教学 C++ 是 Kuhn DFS：先任意贪心匹配，再从每个原本自由的左顶点找
增广路，右顶点用搜索轮次标记。初始匹配在其覆盖的左顶点子集上已最大；
添加一个自由左顶点使最优值至多增一，新增广路必须从它出发。成功翻转后增一，
失败则最优值不变。归纳证明最终最大匹配。此较短实现已在 C++ 验证，不宣称
未经验证的其他语言也能通过。`V=M+N`，时间 `O(M(V+K))`，空间 `O(V+K)`。

五份旧 Accepted 分层 BFS/DFS 源码全部保留。没有增广路时由对称差证明最大，
但成功路径不总是最短：邻接行 `[1,2,3]`、`[2,3]`、`[1]` 可使 Python
选五条边的路，而存在三条边的路。这里采用安全界 `O(L(V+K))`：当前边指针
加至多 `L=min(M,N)` 个成功阶段，不套用严格最短路 Hopcroft–Karp 的更强界。
空间为 `O(V+K)`。

## 优化解法

新算法给每个左顶点存邻居位集，把较小侧设为 `L=min(M,N)`，另一侧
`R=max(M,N)`。对新左根做交替路 BFS；先与自由右顶点位集相交，非空即完成。
否则邻居均已匹配：每个未访问右顶点仅访问一次，记录左前驱，把其唯一左匹配
伙伴入队。队列至多 `L` 项；沿前驱及旧匹配翻转至自由根。若找不到自由端点，
就无增广路。与教学算法相同的逐顶点归纳证明最大性。

重复边只设置已有位；末字中的多余位不会出现在邻接位集中，不产生虚假顶点。
令 `B=ceil(R/w)`，保守时间 `O(K+L²B+LR)` 字操作，空间 `O(LB+V)` 字加
有界输入缓冲。原生字为 64 位，Python 用大整数分块；无自由邻居时至多提取
`L` 个已匹配右顶点，也限制 Python 反复大整数操作的工作量。

Python 先用可变字节行建图，再每行转整数一次，避免逐边复制宽整数。
65536 字节分块保留跨块的未完数字及半对端点；原生输入缓冲为 4096 字节。
只输出一个整数。算法不同于 DFS 及旧分层搜索，故采用不同方法名。

五版按内存准入：C++ 280 KB 对新的简单 C++ 496 KB，节省 43.5%；
Go 1292/2512，48.6%；Java 680/1264，46.2%；Python 3868/8516，54.6%；
Rust 356/1820，80.4%。C++ 0.031→0.015 s 仅一刻度，不宣称可靠加速。
Python 0.140 对 0.093 s，记录时间多 50.5%；Java/Go/Rust 也各高一个刻度。
这是带明确时间取舍的内存优化。
