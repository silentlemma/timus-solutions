# 1193. 口试要提前多久开始才能让所有人按时结束

[Timus 1193](https://acm.timus.ru/problem.aspx?space=1&num=1193) · 难度 181 · greedy

原题作者 Anatoly Uglov，出自 2002 年 3 月 2 日第五届中学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`N ≤ 40` 名学生在口试开始时拿到题目。学生 `i` 准备 `T1` 分钟（各不相同），然后
回答 `T2` 分钟；同一时间只能有一人回答，按准备完成的先后顺序进行，准备好时若有人
正在回答就排队等候。每名学生必须在计划开始时间之后 `T3` 分钟内结束。求口试至少
要提前多少分钟开始，才能让所有人按时结束。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

`N`（`1 ≤ N ≤ 40`），然后对每名学生给出 `T1 T2 T3`，满足 `0 ≤ T1 ≤ T3 ≤ 600`、
`1 ≤ T2 ≤ 240`。所有 `T1` 互不相同。

## 输出

分钟数；不需要提前时输出 0。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
3
100 10 120
70 40 150
99 15 400
```

输出：

```
15
```

### 样例 2

输入：

```
2
100 10 110
80 15 100
```

输出：

```
0
```

## 解法

提前 `s` 分钟开始，会把一切都平移 `s`：排队顺序和每段等待都不变，只是相对于开始
时刻而言，截止时间都晚了 `s` 分钟。所以只需按 `T1` 的顺序模拟一次口试：每次回答
在学生准备好或上一位回答结束时开始，取两者中较晚者。答案就是最大的迟到量（结束
时间减去 `T3`），没人迟到则为 0。排序需要 `O(N log N)`。

注意事项：

- 队列按准备完成的时间排序，而不是按输入顺序；
- 学生准备好时若没人在回答就立即开始，所以学生之间老师可能空闲；
- 提前量不能为负：如果所有人都早有余裕，答案是 0。

答案已在 300 场随机口试和所有测试上与另一份用二分查找提前量的独立解答比对。

## 优化解法

`1193_greedy_sorting.java`. 相同的就绪顺序考试模拟用直接寻址替代比较排序：T1 是 0..600 中互不相同的整数。T1 槽存 (T2<<10)|T3；T2≥1 使零可标空，T3≤600 容于十位。按时间扫描非空槽，更新 finish=max(finish,T1)+T2 及最大迟到。O(N+601) 时间、601 个整数槽及 256 字节输出缓冲。不同排序实现命名 greedy_sorting；保留易懂排序和旧优化版。

精确源码：Java 1.8 Accepted #11327835: 0.078 s / 356 KB。2026-11-20 保存的编译器组排名，时间然后内存：1/42; 1/42。严格收录采用低于 1024 KB 只看时间：前十或前 15%，同值共享名次，百分比向上取整。两项第一，无需星号。保留的旧版本有自己的配对指标 #11307308 (Java 1.8): 0.125 s / 376 KB，不混合测量或运行时。教学源码保持不变。

- `1193_greedy_sorting.java`: 0.078 s / 356 KB; 保留教学版 `1193_greedy.java` (Java 1.8): 0.14 s / 3776 KB.

优化的 C++ 解法把学生存在有 40 条记录的静态数组中（因为 `N ≤ 40`，这已足够），而
不是存在堆上分配的元组向量里；排序和模拟都不变：{1193_greedy_optimized.cpp}。

优化的 Java 解法按 4 KB 分块逐字节读数，而不是用 `Scanner`，并把学生存在三个
`int` 数组中，每读入一个就用插入法放到正确位置，而不是用 lambda 比较器对三元组数
组排序。学生最多 40 个，平方级的插入排序几乎不花时间：
{1193_greedy_optimized.java}。
