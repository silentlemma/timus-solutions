# 1193. На сколько раньше начать устный зачёт, чтобы все успели

[Timus 1193](https://acm.timus.ru/problem.aspx?space=1&num=1193) · сложность 181 · greedy

Автор оригинальной задачи — Анатолий Углов; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N ≤ 40` студентов получают вопросы в начале устного зачёта. Студент `i`
готовится `T1` минут (у всех по-разному), затем отвечает `T2` минут; отвечают
по одному, в порядке окончания подготовки, а подготовившийся, пока кто-то
отвечает, встаёт в очередь. Каждый должен закончить не позже `T3` минут
от запланированного начала. Найти наименьшее число минут, на которое
нужно начать зачёт раньше, чтобы все успели.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` (`1 ≤ N ≤ 40`), затем `T1 T2 T3` для каждого студента, где
`0 ≤ T1 ≤ T3 ≤ 600` и `1 ≤ T2 ≤ 240`. Все значения `T1` различны.

## Выходные данные

Число минут, 0 если сдвиг не нужен.

## Примеры

### Пример 1

Ввод:

```
3
100 10 120
70 40 150
99 15 400
```

Вывод:

```
15
```

### Пример 2

Ввод:

```
2
100 10 110
80 15 100
```

Вывод:

```
0
```

## Решение

Начало раньше на `s` минут сдвигает всё на `s`: порядок очереди и все
ожидания не меняются, сдвигаются только сроки — на `s` минут позже
относительно начала. Поэтому моделируем зачёт один раз в порядке `T1`:
каждый ответ начинается, когда студент готов или когда кончается
предыдущий ответ, смотря что позже. Ответ — наибольшее опоздание, время
окончания минус `T3`, или 0, если никто не опаздывает. `O(N log N)` на
сортировку.

Тонкие места:

- очередь упорядочена по окончанию подготовки, а не по порядку во входе;
- студент, готовый, когда никто не отвечает, начинает сразу, так что
  между студентами преподаватель может простаивать;
- сдвиг не бывает отрицательным: если все успевают с запасом, ответ 0.

Ответы сверены с отдельно написанным решением, которое ищет сдвиг
двоичным поиском, на 300 случайных зачётах и на всех тестах.

## Оптимизированные решения

Оптимизированное решение на C++ хранит студентов в статическом массиве
из 40 записей, чего хватает, так как `N ≤ 40`, вместо вектора кортежей в
куче; сортировка и моделирование те же: {1193_greedy_optimized.cpp}.

Оптимизированное решение на Java читает числа побайтно блоками по 4 КБ
вместо `Scanner` и хранит студентов в трёх массивах `int`, ставя каждого
на место вставкой сразу при чтении, вместо сортировки массива троек
компаратором-лямбдой. Студентов не больше 40, так что квадратичная
сортировка вставками ничего не стоит: {1193_greedy_optimized.java}.
