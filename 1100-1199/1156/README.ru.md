# 1156. Разбиение 2N задач на два тура, чтобы похожие задачи оказались в разных

[Timus 1156](https://acm.timus.ru/problem.aspx?space=1&num=1156) · сложность 320 · graphs

Автор оригинальной задачи — Евгений Брызгалов; командный чемпионат Урала по программированию, Пермь, апрель 2001 года, английский тур.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`2N` задач, `N ≤ 50`, нужно разбить на два тура по `N` задач. `M ≤ 100`
пар задач похожи и не должны попасть в один тур. Вывести оба тура или
`IMPOSSIBLE`.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `M`, затем `M` пар похожих задач.

## Выходные данные

Две строки с `N` задачами каждого тура или `IMPOSSIBLE`.

## Проверка

Принимается любое подходящее разбиение. Проверяющая программа смотрит,
что в двух строках по `N` задач и вместе все задачи от 1 до `2N`, что
никакая похожая пара не делит тур и что `IMPOSSIBLE` выводится, только
когда разбиения нет.

## Примеры

### Пример 1

Ввод:

```
2 3
1 3
2 1
4 3
```

Вывод:

```
1 4
2 3
```

## Решение

Соединим похожие задачи рёбрами. Внутри компоненты связности тур одной
задачи определяет туры всех остальных: соседи чередуются. Значит, каждую
компоненту нужно раскрасить в два цвета, и нечётный цикл делает разбиение
невозможным. Компонента с классами размеров `a` и `b` отдаёт первому туру
либо `a`, либо `b` задач, а задачи без похожих — это компоненты размера
`(1, 0)`.

Остаётся для каждой компоненты выбрать, какой класс идёт в первый тур,
так чтобы в нём оказалось ровно `N` задач. Это сумма подмножеств по
компонентам: `reach[k]` хранит размеры, которые могут дать первые `k`
компонент, а обратный проход от `N` восстанавливает выбор. Компонент не
больше `2N = 100`, размеры до `N`, так что таблица крошечная.

Тонкие места:

- одной раскраски мало: размеры классов ещё должны дать в сумме `N`;
- задача, похожая сама на себя, делает разбиение невозможным;
- пара может быть дана дважды;
- задачи тура можно выводить в любом порядке; здесь они по возрастанию.

Ответы проверены проверяющей программой на всех тестах, а возможность
разбиения сверена с перебором всех выборов `N` задач на 200 случайных
входах до 14 задач.

## Оптимизированные решения

C++ и Rust хранят смежность в плоских массивах и раскрашивают компоненты поиском в ширину. Каждая строка динамики суммы размеров занимает одно 64-битное слово, поскольку в раунде не больше 50 задач. Сдвиги предыдущей строки на размеры двух долей дают следующую строку. Сохранённые слова позволяют восстановить выбор доли в каждой компоненте, проверяя достижимость размера в предыдущей строке. Вершин не больше 100, направленных рёбер — 200, поэтому Rust хранит номера и ссылки смежности в байтах. Rust запускается через C main и передаёт фиксированные байтовые буферы через библиотеку C, завершая частичные записи.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 64 KB при 244 KB у базовой.

Принятые базовые реализации [1156_graphs.go](1156_graphs.go), [1156_graphs.java](1156_graphs.java), [1156_graphs.py](1156_graphs.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- Во всех языках раскраска идёт поиском в глубину с явным стеком и
  заполняется одна и та же таблица суммы подмножеств; Python хранит
  каждую строку как множество.
