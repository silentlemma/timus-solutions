# 1196. Сколько дат из списка студента есть у преподавателя

[Timus 1196](https://acm.timus.ru/problem.aspx?space=1&num=1196) · сложность 52 · binary_search, hashing

Оригинальная задача — фольклор; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У преподавателя отсортированный список из `1 ≤ N ≤ 15000` годов, а
студент выписывает `1 ≤ M ≤ 10⁶` годов в любом порядке; в обоих списках
года могут повторяться, каждый год от 1 до `10⁹`. Посчитать записи из
списка студента, которые есть и в списке преподавателя.

Ограничение времени: 1.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и года преподавателя, по одному в строке, затем `M` и года студента.

## Выходные данные

Число совпадающих записей.

## Проверка

Тесты репозитория точно сравнивают целочисленный токен ответа; пробельные символы и переводы строк между токенами игнорируются. Конкретное оформление окружающих пробелов не требуется.

## Примеры

### Пример 1

Ввод:

```
2
1054
1492
4
1492
65536
1492
100
```

Вывод:

```
2
```

## Решение

Список преподавателя уже отсортирован, поэтому каждый год студента ищется
двоичным поиском; каждое совпадение засчитывается, включая повторы со
стороны студента, а повторы со стороны преподавателя ничего не меняют.
`O(N + M log(N + 1))`. При миллионе чисел на вход быстрое чтение важнее самих
поисков.

Двоичный поиск требует O(N + M log(N + 1)) времени, включая N = 1; чтение дополнительно стоит O(I) при I байтах входа. C++/Go/Java хранят O(N) дат преподавателя и фиксированные входные буферы; быстрая Rust делает то же с буфером 65536 байтов. Простая Rust дополнительно сохраняет весь входной String длины O(I). Python требует O(U + L) памяти для U различных дат преподавателя и текущей строки максимальной длины L байтов, U ≤ N. Обе Python-версии обрабатывают даты студента потоком, не сохраняя M запросов; ожидаемое время хеш-множества O(N + M) плюс чтение. Это не гарантия худшего случая при коллизиях.

Тонкие места:

- год, записанный студентом дважды, засчитывается дважды;
- во входе около миллиона строк, так что медленное построчное чтение в
  некоторых языках может не уложиться во время.

Ответы сверены с отдельно написанным решением, использующим хеш-таблицу,
на всех тестах.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает до миллиона чисел вручную из
блоков по 64 КБ, прочитанных `fread`, вместо вызова `scanf` для каждого:
0.046 с вместо 0.687 с при почти той же памяти (260 КБ против 256 КБ).
Двоичный поиск тот же.

Оптимизированное решение на Go разбирает даты вручную, читая ввод через
буфер на 4 КБ, вместо сканера слов с буфером на 1 МБ, хранит их как
`int32` и ищет собственным двоичным поиском: 0.062 с вместо 0.171 с и
996 КБ вместо 5576 КБ. Оптимизированное решение на Rust разбирает даты
вручную из буфера на 64 КБ вместо чтения всего ввода в строку и хранит
их как `u32`: 320 КБ вместо 9300 КБ; парное время растёт с 0.031 с до 0.046 с.
Оптимизированное решение на Python опирается на то, что в каждой строке
одна дата: оно преобразует строки как есть и считает известные даты
через `map` вместо цикла на Python: 0.343 с вместо 0.687 с и 1324 КБ
вместо 1456 КБ.

## Особенности языков

Действуют общие [рейтинговые критерии](../../RATING_CRITERIA.md) и аудит кэша точных исходников. Все быстрые версии проходят, простая Rust тоже. Остальные базы остаются учебными без звёздочек, даже если численные пороги не выполнены. Ниже 1024 КБ учитывается только время. Обе строки Python и простые Go/Rust занимают не менее 1024 КБ, им нужны обе метрики; быстрая Python и простая Rust проходят обе. Go и Rust используют эталонное сравнение при 7 и 4 соперниках точной версии соответственно, с допуском одного отображаемого тика по времени. Нет отдельного требования первого места или выигрыша 30%.

В `1196_binary_search_optimized.java` добавлен только поясняющий комментарий о входном буфере; исполняемая программа не меняется. Строка №11302071 и 0.218 с / 420 КБ остаётся исторической парой Accepted.

- Python складывает года преподавателя в множество; остальные языки
  ищут двоичным поиском в отсортированном массиве.
- Python читает года студента по одной строке. Если разбить весь ввод
  сразу, в памяти одновременно окажется миллион маленьких строк, около
  62 МБ, и такая версия превысила лимит 64 МБ на тесте 8.

Читаем годы напрямую из буфера байтов и ищем их в отсортированном массиве примитивов. Принятая посылка 11302071 заняла 0,218 с и использовала 420 КБ. Простая версия заняла 0,328 с и использовала 592 КБ.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
