# 1196. Сколько дат из списка студента есть у преподавателя

[Timus 1196](https://acm.timus.ru/problem.aspx?space=1&num=1196) · сложность 52 · binary_search, hashing

Оригинальная задача — фольклор; пятое командное первенство школьников по программированию, 2 марта 2002 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У преподавателя отсортированный список из `1 ≤ N ≤ 15000` годов, а
студент выписывает `1 ≤ M ≤ 10⁶` годов в любом порядке; в обоих списках
года могут повторяться, каждый год от 1 до `10⁹`. Посчитать записи из
списка студента, которые есть и в списке преподавателя.

Ограничение времени: 1.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и года преподавателя, по одному в строке, затем `M` и года студента.

## Выходные данные

Число совпадающих записей.

## Примеры

### Пример 1

Ввод:

```
2
1054
1492
4
1492
65536
1492
100
```

Вывод:

```
2
```

## Решение

Список преподавателя уже отсортирован, поэтому каждый год студента ищется
двоичным поиском; каждое совпадение засчитывается, включая повторы со
стороны студента, а повторы со стороны преподавателя ничего не меняют.
`O(N + M log N)`. При миллионе чисел на вход быстрое чтение важнее самих
поисков.

Тонкие места:

- год, записанный студентом дважды, засчитывается дважды;
- во входе около миллиона строк, так что медленное построчное чтение в
  некоторых языках может не уложиться во время.

Ответы сверены с отдельно написанным решением, использующим хеш-таблицу,
на всех тестах.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает до миллиона чисел вручную из
блоков по 64 КБ, прочитанных `fread`, вместо вызова `scanf` для каждого:
0.046 с вместо 0.687 с при почти той же памяти (260 КБ против 256 КБ).
Двоичный поиск тот же.

Оптимизированное решение на Go разбирает даты вручную, читая ввод через
буфер на 4 КБ, вместо сканера слов с буфером на 1 МБ, хранит их как
`int32` и ищет собственным двоичным поиском: 0.062 с вместо 0.171 с и
996 КБ вместо 5576 КБ. Оптимизированное решение на Rust разбирает даты
вручную из буфера на 64 КБ вместо чтения всего ввода в строку и хранит
их как `u32`: 320 КБ вместо 9300 КБ при том же времени.
Оптимизированное решение на Python опирается на то, что в каждой строке
одна дата: оно преобразует строки как есть и считает известные даты
через `map` вместо цикла на Python: 0.343 с вместо 0.687 с и 1324 КБ
вместо 1456 КБ.

## Особенности языков

- Python складывает года преподавателя в множество; остальные языки
  ищут двоичным поиском в отсортированном массиве.
- Python читает года студента по одной строке. Если разбить весь ввод
  сразу, в памяти одновременно окажется миллион маленьких строк, около
  62 МБ, и такая версия превысила лимит 64 МБ на тесте 8.
