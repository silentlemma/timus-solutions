# 1148. K-я в лексикографическом порядке башня, где соседние уровни отличаются на кирпич

[Timus 1148](https://acm.timus.ru/problem.aspx?space=1&num=1148) · сложность 1730 · dp

Оригинальная задача с Timus; автор и источник не указаны.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В башне `H ≤ 60` уровней; в нижнем `M ≤ 10` кирпичей, а в каждом
следующем ровно на один кирпич больше или меньше, чем в уровне под ним,
и никогда не ноль. Рассмотрим все такие башни, на которые уходит не
больше `N ≤ 32767` кирпичей, записанные как список ширин уровней снизу
вверх и упорядоченные лексикографически. Вывести, сколько их, затем
башню с каждым данным номером `K`, считая с 1.

Ограничение времени: 1 секунда. Ограничение памяти: 4 МБ.

## Входные данные

`N`, `H` и `M`, затем числа `K` по одному в строке, в конце `-1`.

## Выходные данные

Число башен, затем ширины каждой запрошенной башни.

## Примеры

### Пример 1

Ввод:

```
22 5 4
1
10
-1
```

Вывод:

```
10
4 3 2 1 2
4 5 4 5 4
```

## Решение

Пусть `count(n, h, m)` — число башен из `h` уровней, нижний из которых
содержит `m` кирпичей, на которые уходит не больше `n` кирпичей. Оно равно
`0` при `m = 0` или `m > n`, `1` при `h = 1`, а иначе

`count(n, h, m) = count(n − m, h − 1, m − 1) + count(n − m, h − 1, m + 1)`.

Ответ на первый вопрос — `count(N, H, M)`, не больше `2^59`, что
помещается в 64 бита. `K`-я башня считывается уровень за уровнем: в
лексикографическом порядке сначала идёт более узкое продолжение, так что
если `K` не больше числа башен, продолжающихся шириной `m − 1`, берём её;
иначе вычитаем это число и продолжаем шириной `m + 1`.

Трудность — в памяти. Башне из `h` уровней, начинающейся с `m`, никогда не
нужно больше `m·h + h(h − 1)/2` кирпичей, так что `n` можно обрезать до
этого значения, а на данной высоте встречаются только ширины одной
чётности в пределах `M ± (H − h)`. Даже так полная таблица по
`(n, h, m)` заняла бы десятки мегабайт. Поэтому значения хранятся только
для каждой четвёртой высоты — около 245 тысяч 64-битных чисел, или 2 МБ, —
а три высоты между ними пересчитываются простой рекурсией, что стоит не
больше `2⁴ = 16` обращений к следующей хранимой высоте на хранимое
значение. Хранимое значение вычисляется один раз, когда оно впервые
понадобится.

Тонкие места:

- число башен доходит примерно до `4,7·10¹⁷`, так что нужны 64-битные
  целые;
- уровень из одного кирпича не может сузиться до нуля;
- `n`, большее, чем могла бы использовать любая башня, обрезается — это
  держит таблицу маленькой и делает хранимые значения общими;
- при `M > N` башен нет вовсе.

Ответы сверены с перечислением всех башен по порядку на 200 случайных
входах до 14 уровней, а большие тесты — с восстановлением башни по номеру
при запоминании всех состояний.
