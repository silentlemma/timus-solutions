# 1148. 相邻层相差一块砖的塔中，字典序第 K 座塔

[Timus 1148](https://acm.timus.ru/problem.aspx?space=1&num=1148) · 难度 1730 · dp

原题来自 Timus，未注明作者和出处。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一座塔有 `H ≤ 60` 层；最底层有 `M ≤ 10` 块砖，每往上一层恰好比下面一层多
一块或少一块，且不能为零。考虑所有用砖不超过 `N ≤ 32767` 块的这种塔，把它们
写成从下到上的各层宽度列表，并按字典序排列。输出塔的总数，然后输出每个给定
编号 `K`（从 1 开始）对应的塔。

时间限制：1 秒。内存限制：4 MB。

## 输入

`N`、`H` 和 `M`，然后每行一个数 `K`，以 `-1` 结尾。

## 输出

塔的总数，然后是每座被询问的塔的各层宽度。

## 样例

### 样例 1

输入：

```
22 5 4
1
10
-1
```

输出：

```
10
4 3 2 1 2
4 5 4 5 4
```

## 解法

设 `count(n, h, m)` 为共 `h` 层、最底层有 `m` 块砖、总用砖不超过 `n` 块的塔的
数目。当 `m = 0` 或 `m > n` 时它为 `0`，`h = 1` 时为 `1`，否则

`count(n, h, m) = count(n − m, h − 1, m − 1) + count(n − m, h − 1, m + 1)`。

第一个问题的答案是 `count(N, H, M)`，至多 `2^59`，在 64 位范围内。第 `K` 座塔
逐层读出：字典序中较窄的延续在前，所以若 `K` 不超过以 `m − 1` 延续的塔数，就
选它；否则减去这个数，以 `m + 1` 继续。

难点在于内存。从 `m` 开始的 `h` 层塔用砖永远不超过 `m·h + h(h − 1)/2`，所以
`n` 可以截断到这个值；并且在给定高度上只会出现一种奇偶性、范围在
`M ± (H − h)` 内的宽度。即便如此，关于 `(n, h, m)` 的完整表仍需几十兆字节。
因此只为每隔四层的高度保存计数——约 24.5 万个 64 位数，即 2 MB——中间的
三层用普通递归重新计算，每个保存值最多访问下一个保存高度的 `2⁴ = 16` 个
值。每个保存值只在第一次需要时计算一次。

注意事项：

- 塔数可达约 `4.7·10¹⁷`，需要 64 位整数；
- 一块砖的层不能缩到零；
- 超过任何塔可能用到的 `n` 会被截断，这使表保持较小并让保存值可以共用；
- `M > N` 时一座塔也没有。

答案已在 200 个最多 14 层的随机输入上与按顺序列出所有塔的结果比对，大测试
则与记忆所有状态的按编号还原比对。

## 各语言说明

- 所有语言都保存同样的稀疏表，并在其各层之间递归。
