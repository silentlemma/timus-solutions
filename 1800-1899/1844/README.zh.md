# 1844. 法师军团的统帅

[Timus 1844](https://acm.timus.ru/problem.aspx?space=1&num=1844) · 难度 1557 · dp

原题作者 Evgeny Kurpilyansky，出自 2010 年 8 月彼得罗扎沃茨克夏季集训的 Ural SU Contest。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

两位导师 Sandro 和 Zagamius 在各自的办公室面试法师。每人都按固定的计划执行"召见法师 a"和"放走法师 a"的步骤。
一个法师只能在一个办公室里，所以当法师在另一位导师那里时，召见要等待；两人都能行动时，任何一人都可以先走。判断两位导师是否可能永远互相等待。

## 输入

t（1 ≤ t ≤ 10）组测试。每组以 n、m、k（1 ≤ n, m, k ≤ 1000）开始：Sandro 和 Zagamius 计划的长度以及法师人数。
然后是 Sandro 的 n 步和 Zagamius 的 m 步，每步为 "+ a" 或 "- a"（1 ≤ a ≤ k）。没有人召见已在自己办公室的法师，也不放走不在那里的法师，最后两个办公室都是空的。

## 输出

对每组测试，若两个计划一定能完成，输出 ":-)"；若导师可能卡住，输出 ":-("。

## 样例

### 样例 1

输入：

```
2
4 4 2
+ 1
+ 2
- 2
- 1
+ 1
+ 2
- 2
- 1
4 4 2
+ 1
+ 2
- 1
- 2
+ 2
+ 1
- 2
- 1
```

输出：

```
:-)
:-(
```

## 解法

一个时刻就是格子 (i, j)：Sandro 做了 i 步，Zagamius 做了 j 步。若两个办公室同时有同一个法师，称该格子被占用。
一步被阻塞，当且仅当它会走进被占用的格子：只有召见能让两个办公室共有一个法师，而这恰好发生在对方正拥有该法师时。
所以可能出现的时刻，就是从 (0, 0) 出发、经由空闲格子向下或向右可以到达的格子；若这样的某个格子（(n, m) 除外）两个邻居都被占用或不存在，导师就可能卡住。
最后一行和最后一列不会卡住，因为已完成的导师不再拥有任何法师。

哪些格子被占用。固定一行时 Sandro 的法师集合是固定的；沿着这一行走，统计两个办公室共有的法师数，当 Zagamius 召见或放走 Sandro 拥有的法师时加一或减一。
知道被占用的格子后，扫描一遍网格即可标出可达格子并检查每个是否是死路。`O(t·n·m)`。

Python 版本做同样的事，但把每行存成以 j 为下标的位掩码。每个法师有一个掩码，表示 Zagamius 拥有他的那些列；一行中被占用的格子是 Sandro 拥有的法师的掩码之并，借助行上的线段树放到 Sandro 拥有每个法师的那段行上。
在一行内，Zagamius 从每个从上方进入的格子向右走，直到下一个被占用的格子；用被占用格子的掩码减去这些起点，就能把每段空闲区间从第一个起点开始翻转，于是只需几次大整数运算就填满这一行。

在样例的第二组测试中，Sandro 召见法师 1，同时 Zagamius 召见法师 2。此时 Sandro 等法师 2，Zagamius 等法师 1。

注意事项：

- 只有召见会等待，所以死路要求两位导师都正要召见对方拥有的法师；
- 同一个法师可能被多次召见，所以关键是拥有他的时间段，而不是法师本身。

在一百五十个各含十组测试的随机文件上，答案与一个独立的已通过实现一致。
