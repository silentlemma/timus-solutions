# 1826. 雷区

[Timus 1826](https://acm.timus.ru/problem.aspx?space=1&num=1826) · 难度 309 · greedy

原题作者 Dmitry Teryaev，出自 2011 年 3 月 19 日第十二届乌拉尔国立大学公开个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

n 人的侦察小组带着唯一的探雷器穿越雷区：两人一起过去，然后一人把探雷器送回，如此反复。
每人都有自己的通过时间，两人同行的速度取决于较慢的那位。求全组通过的最少总时间。

## 输入

n（2 ≤ n ≤ 100），然后是 n 个通过时间，均为不超过 600 的正整数。

## 输出

最少的总时间。

## 样例

### 样例 1

输入：

```
4
1
10
5
2
```

输出：

```
17
```

## 解法

这就是过桥与手电筒问题。把时间排序为 a ≤ b ≤ … ≤ y ≤ z。当等待的人多于三人时，用以下两种方式之一把最慢的两人送过去，取较便宜者：

- 最快的人分别护送他们：z + a + y + a = 2a + y + z；
- 最快的两人过去，a 返回，最慢的两人一起过去，b 返回：b + a + z + b = a + 2b + z。

两种方式之后最快的两人都回到起点，剩下的人少了两个。三个人需要 a + b + c（a 护送另两人），两个人需要较慢者的时间。
交换论证表明，总有某个最优方案以这种方式送走最慢的两人。算法的时间复杂度为 `O(n log n)`，
但 Python 实现每轮用 `times[:-2]` 复制剩余列表，因此时间复杂度为 `O(n^2)`。
五种实现的峰值空间复杂度均为 `O(n)`。

在样例 (1, 2, 5, 10) 中，配对花费 1 + 2·2 + 10 = 15，而护送花费 2 + 5 + 10 = 17，最后两人花 2：共 17。

注意事项：

- 总是由最快者护送并非最优：1, 2, 5, 10 将需要 19；
- 当第二快的人也很慢时，总是让慢者配对同样不是最优；
- 每一轮都要重新选择；
- Python 列表切片会复制元素：测试 07 中 n = 100，共复制
  98 + 96 + … + 2 = 2450 个元素，因此排序并非该实现的主要渐近时间开销。

在至多 7 人的小组上，答案与对所有状态的 Dijkstra 搜索一致，并在随机小组上与一个独立的已通过实现一致。

## 优化解法

Go 和 Rust 在固定大小的数组中排序过河时间，每步送走剩余最慢的两人。设最快两人的时间为 a、b，剩余最慢两人为 y、z，则增加 z + min(2a+y, a+2b)。剩两人时增加 b，剩三人时增加 a+b+c。两个版本都用 16 位保存输入时间。Go 使用原地堆排序，Rust 用 32 位累加总时间。两个版本都用固定字节缓冲区进行输入和十进制输出。Go 直接访问标准输入和输出句柄，Rust 通过 C 运行库读写。
