# 1881. Длинное условие задачи

[Timus 1881](https://acm.timus.ru/problem.aspx?space=1&num=1881) · сложность 62 · simulation

Автор оригинальной задачи — Фёдор Фоминых; Уральская региональная командная олимпиада по программированию 2011.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На странице h строк по w символов. Слова в строке разделяются одним
пробелом, а слово, не помещающееся в текущую строку, начинает новую;
слова не переносятся. Сколько страниц займёт текст из n слов?

## Входные данные

h, w и n (1 ≤ h, w ≤ 100, 1 ≤ n ≤ 10 000), затем n слов, по одному в
строке, каждое не длиннее w; их суммарная длина не больше 10 000.
Слова непустые и состоят только из прописных и строчных английских
букв и знаков препинания `.,!?`.

## Выходные данные

Количество страниц.

## Примеры

### Пример 1

Ввод:

```
3 5 6
To
be
or
not
to
be
```

Вывод:

```
2
```

## Решение

Заполняем строки жадно. Храним число занятых символов в текущей
строке; слову нужна его длина плюс один пробел, если оно не первое в
строке. Если не помещается, начинаем с него новую строку. Начальное
значение −1 избавляет первое слово строки от пробела. Ответ — число
строк, делённое на h с округлением вверх. `O(n)`.

В примере строки такие: «To be», «or», «not» и «to be»: «or not» и
«not to» длиннее на один символ. Четыре строки при трёх строках на
странице занимают две страницы.

Подводные камни:

- слово, ровно заполняющее остаток строки вместе с пробелом, ещё
  помещается;
- пробел ставится только между словами, никогда в начале строки;
- число страниц округляется вверх.

Ответы совпадают с независимой принятой реализацией на 100 случайных
текстах.

## Оптимизированные решения

`1881_simulation_optimized.java`. Java сохраняет жадный перенос целых слов. Длины считаются непосредственно в общем буфере ввода на 1024 байта, включая слова через границу заполнений и конец файла, без создания строк слов. Хранятся только занятая ширина и число строк: не поместившееся слово начинает следующую строку, число страниц равно ceil(lines/height). Целый ответ выводится через фиксированные байтовые буферы. Для B байт ввода время O(B), дополнительная память O(1); массив слов и склеенный текст не хранятся. Независимые проверки строили настоящие строки и охватывали точное заполнение, длинные слова, границы буфера и отсутствие финального перевода строки.

Accepted точного исходника Java 1.8 №11327457: 0.109 с / 356 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 21/202, память 1/202. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303783: 0.125 с / 408 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1881_simulation_optimized.java`: 0.109 s / 356 KB; сохранённая учебная база `1881_simulation.java`: 0.109 s / 1336 KB.

Оптимизированное решение на C++ вообще не хранит слова: оно читает
каждое слово посимвольно через `getchar` и запоминает только его длину,
а больше для разбиения на строки ничего не нужно. Оно занимает 128 КБ
вместо 404 КБ при том же времени.

Читаем слова построчно и учитываем только их длины при размещении на страницах. Принятая посылка 11303784 заняла 0,093 с и использовала 488 КБ. Простая версия заняла 0,078 с и использовала 656 КБ. Зафиксированное время выше, чем у простой версии.
