# 1822. Война Уго II

Автор оригинальной задачи — Кирилл Бутин; XII открытое личное первенство УрГУ, 19 марта 2011 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дворяне королевства образуют дерево под королём, дворянином 1. Приказ с
числом x спускается от короля вниз. Дворянин без вассалов сразу
собирает войска за tᵢ дней. Дворянин с вассалами ждёт, пока будут
готовы хотя бы x% непосредственных вассалов, затем собирает войска за
tᵢ дней. Король выступает, как только готовы хотя бы x% его
непосредственных вассалов. Найти наибольшее x, при котором король
выступит не позже чем через t дней.

## Входные данные

n и t (1 ≤ n ≤ 10⁴, 0 ≤ t ≤ 10⁶), затем для дворян 2, …, n сюзерен pᵢ
и число дней tᵢ (0 ≤ tᵢ ≤ 100).

## Выходные данные

Наибольшее x с абсолютной погрешностью не больше 10⁻⁴.

## Примеры

### Пример 1

Ввод:

```
6 3
1 2
2 2
2 1
1 2
1 4
```

Вывод:

```
50.00000000
```

## Решение

При фиксированном x дворянин с c вассалами ждёт ⌈x·c/100⌉ из них, то
есть ⌈x·c/100⌉-й по величине день готовности, и готов ещё через tᵢ
дней; один проход от листьев вверх даёт день короля. Большее x никого
не ускоряет, так что допустимые x образуют отрезок [0, X].

Внутри него важны только величины ⌈x·c/100⌉, а они меняются лишь в
дробях m/c, где c — число непосредственных вассалов. Значит, само X
равно 100·m/c для какой-то такой дроби. Собираем дроби для всех
различных c, сортируем их и двоичным поиском находим последнюю, которую
король успевает, проверяя каждую точно в целых числах. C++, Go, Java и
Rust сортируют перекрёстным умножением; Python — по значению m/c с
плавающей точкой. Различные дроби отличаются хотя бы на 1/9999², поэтому
при этих ограничениях такая сортировка безопасна. Округляем 100·m/c до
восьми знаков целочисленно, при равенстве округляя вверх, и выводим целую
часть и дробную часть с ведущими нулями через точку. Все пять языков
дают одинаковый вывод с погрешностью не больше 5·10⁻⁹.
Дробей не больше 2n, так что всего `O(n log² n)`.

В примере при x = 50 дворянин 2 ждёт одного из вассалов 3 и 4, готового
в день 1, и сам готов в день 3. Вассалы короля готовы в дни 3, 2 и 4,
так что второй из них появляется в день 3 — вовремя. Любое x больше 50
заставляет дворянина 2 ждать обоих. Король ждёт двоих из 4, 2, 4 при
x ≤ 200/3, а иначе всех троих (например, при 75%). В обоих случаях
король выступает в день 4, слишком поздно.

Подводные камни:

- x — доля непосредственных вассалов с округлением вверх: при 3
  вассалах уже 34% требуют двоих;
- номер сюзерена может быть больше номеров вассалов, поэтому порядок
  обработки берётся из обхода от короля;
- сам король не тратит дней на сбор;
- десятичный разделитель должен быть точкой независимо от локали:
  тест 10 выявляет запятую в Java при русской локали, поэтому форматтер
  явно использует `Locale.US`;
- если у короля нет вассалов, он выступает сразу и ответ равен 100.
