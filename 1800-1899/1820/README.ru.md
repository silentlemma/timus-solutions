# 1820. Уральские бифштексы

[Timus 1820](https://acm.timus.ru/problem.aspx?space=1&num=1820) · сложность 25 · math

Автор оригинальной задачи — Магаз Асанов; XII открытое личное первенство УрГУ, 19 марта 2011 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Повар должен прожарить обе стороны n бифштексов, по минуте на сторону,
на сковороде, где помещается не больше k бифштексов одновременно. Найти
наименьшее число минут.

## Входные данные

n и k (1 ≤ n, k ≤ 1000).

## Выходные данные

Наименьшее число минут.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
3 2
```

Вывод:

```
3
```

## Решение

Сторон 2n, и за минуту жарится не больше k из них, так что нужно хотя
бы ⌈2n/k⌉ минут; а две стороны одного бифштекса нельзя жарить в одну
минуту, так что нужно хотя бы 2. Ответ — max(2, ⌈2n/k⌉), и он
достижим: выпишем стороны как лицо 1, …, лицо n, оборот 1, …, оборот n
и каждую минуту жарим следующие k из них. При n ≥ k две стороны
бифштекса стоят в списке на расстоянии n и никогда не попадают в одну
минуту; при n < k обе стороны и так укладываются в две минуты. `O(1)`.

В примере: лица 1 и 2, затем оборот 1 с лицом 3, затем обороты 2 и 3 —
три минуты.

Подводные камни:

- жарить целые партии по k бифштексов по две минуты — значит терять
  место на сковороде: 3 бифштекса на сковороде на 2 жарятся 3 минуты,
  а не 4;
- при k ≥ 2n оценка ⌈2n/k⌉ равна 1, но бифштексу всё равно нужны две
  минуты.

## Оптимизированные решения

Оптимизированное решение на Java разбирает числа побайтно из `System.in`
вместо `Scanner`: 348 КБ вместо 1608 КБ при том же времени.

`1820_math_optimized.cpp`. Сохраняется max(2,ceil(2N/K)): одному стейку нужны две разные минуты, за минуту помещаются не более K из 2N сторон. Явное побайтовое преобразование C заменяет форматированное чтение и печать целых; округление вверх вычисляется точно в знаковых 64-битных промежуточных значениях. Время и дополнительное состояние O(1).

По сравнению с `1820_math.cpp`: время 0.031 s → 0.015 s; память 124 KB → 72 KB.

`1820_math_optimized.go`. Сохраняются та же оценка времени жарки и её достижимость. Переносимые байтовые потоки os.File и ограниченные буферы заменяют fmt, округление вверх использует int64. Хранятся лишь два входных значения и ответ, поэтому алгоритм требует O(1) времени и фиксированной дополнительной памяти.

По сравнению с `1820_math.go`: время 0.046 s → 0.031 s; память 1076 KB → 808 KB.

`1820_math_optimized.py`. Та же точная формула жарки вычисляется по байтовым токенам, без декодированной строки всего ввода и обёртки main. Напечатанный ответ сбрасывается перед завершением без обычной очистки интерпретатора. При заданных ограниченных целых время и дополнительная память O(1).

По сравнению с `1820_math.py`: время 0.093 s → 0.125 s; память 348 KB → 216 KB.
