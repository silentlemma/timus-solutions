## Задача

Император Адриан приносит в жертву стадо из n баранов, n нечётно, деля
его поровну между некоторым числом богов. Теон Смирнский хочет, чтобы
это число было нечётным и имело нечётное число положительных делителей.
Найти наибольшее такое число богов.

## Входные данные

Нечётное целое n (1 ≤ n ≤ 10¹⁸ − 1).

## Выходные данные

Наибольшее подходящее число богов.

## Примеры

### Пример 1

Ввод:

```
45
```

Вывод:

```
9
```

## Решение

У числа нечётное число делителей ровно тогда, когда оно — полный
квадрат: делители разбиваются на пары k и m/k, и только у квадрата есть
делитель в паре с самим собой. Все делители нечётного n нечётны, так
что ответ — наибольший квадрат, делящий n, то есть произведение
p^(2⌊e/2⌋) по степеням простых p^e в разложении n.

Выделяем нечётные простые p, пока p³ ≤ n, причём n по ходу уменьшается.
Остаток не имеет простых делителей до своего кубического корня, так что
это 1, простое, произведение двух простых или квадрат простого, и
только последний добавляет квадрат: проверяем точным целым квадратным
корнем. Перебор делителей занимает не больше 10⁶ шагов, а решение на
Python пробует только простые из решета. `O(n^(1/3))`.

В примере 45 = 3²·5, так что ответ 9.

Подводные камни:

- большой простой делитель в квадрате, например (10⁹ − 63)², остаётся
  после перебора и всё равно должен быть распознан;
- вещественный квадратный корень числа около 10¹⁸ может ошибиться на
  единицу; поправляйте его целыми проверками.

Ответы совпадают с прямым перебором на сотне маленьких чисел и с
независимой принятой реализацией на больших простых, произведениях
двух больших простых, квадратах больших простых и произведениях многих
маленьких простых.

## Оптимизированные решения

`1854_number_theory_optimized.py`. Сохраняется точное разложение для наибольшего квадратного делителя нечётного входа. Сначала удаляются все множители три, затем проверяются только делители 6k-1 и 6k+1. После удаления простой степени точный isqrt позволяет сразу вернуть квадратный остаток; после цикла до кубического корня вклад даёт только квадратный остаток. Решета и таблицы готовых ответов нет. O(n^(1/3)) пробных делений и постоянное арифметическое состояние при n<10^18; читаемая Python-версия с решетом сохранена.

Accepted точного исходника PyPy 3.10 x64 №11327061: 0.125 с / 1068 КБ. Сохранённое сравнение актуальных компиляторов семейства Python от 2026-11-20: время 2/23, память 7/23; оба строгих критерия первой десятки пройдены. Память не меньше 1024 КБ: требуются и время, и память. Отдельная цель первого места по обеим метрикам не достигнута, звёздочка остаётся. Прежний документированный оптимизированный запуск CPython 3.12 №11314964: 0.203 с / 392 КБ. У выбранного PyPy меньше зафиксированное время, но больше память; это независимые парные замеры разных интерпретаторов, не чистый эффект алгоритма и не смешанные минимумы. Текущий Accepted сохранённой простой версии CPython №11327562: 0.171 с / 1928 КБ. Дополнительная копия исходника и повторная отправка не нужны.

Собственные Accepted после изменения только форматирования: `1854_number_theory.java` #11327560, `1854_number_theory.cpp` #11327561, `1854_number_theory.py` #11327562. Алгоритмы простых версий и все остальные исходники сохранены.

Новые Go, Python и Rust сохраняют пробные деления до кубического корня уменьшающегося числа и выделение квадратных степеней. Полный квадрат на входе или в остатке после удаления множителя можно сразу вернуть: весь остаток — свой наибольший квадратный делитель. Python обходится без решета на миллион элементов, отдельно удаляет множитель три и перебирает только делители 6k±1; арифметическое состояние постоянно. Число проб остаётся O(n^(1/3)); составной пробный делитель не разделит остаток после удаления всех меньших простых множителей. Python использует точный isqrt, Go и Rust — целочисленный двоичный корень с границей 10⁹. Даже следующая проверка куба при 1000001 помещается в знаковые 64 бита, а накопленный квадратный множитель делит исходное n. Go использует стандартные дескрипторы, Rust — точку входа C и ограниченный посимвольный ввод-вывод. Все старые исходники, включая Python с решетом, сохранены; C++ и Java закрывают быстрый набор своими подходящими базами.

Сохранённые принятые базы [1854_number_theory.cpp](1854_number_theory.cpp), [1854_number_theory.java](1854_number_theory.java) также проходят строгий допуск первых десяти мест или топ 15% по требуемым метрикам в сохранённом сравнении. Они используются без одинаковых оптимизированных копий. Текущие точные парные замеры приведены в таблице, звёздочка означает отдельную цель языка. Форматирование не меняет алгоритм, ему не приписывается ускорение.
