# 1821. Биатлон

[Timus 1821](https://acm.timus.ru/problem.aspx?space=1&num=1821) · сложность 178 · sorting

Авторы оригинальной задачи — Александр Ипатов и Алексей Самсонов; XII открытое личное первенство УрГУ, 19 марта 2011 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В гонке с раздельным стартом биатлонисты стартуют по одному с
интервалом 30 секунд. Табло показывает спортсмена с лучшим временем
среди уже финишировавших. По списку спортсменов в порядке старта с их
временем прохождения дистанции перечислить всех, кто появлялся на
табло.

## Входные данные

n (1 ≤ n ≤ 100), затем n строк: непустая фамилия (до 20 английских
букв, первая заглавная, остальные строчные) и время «mm:ss.d».
Все фамилии различны. Никакие двое не финишируют одновременно и
не показывают одинаковое время.

## Выходные данные

Число спортсменов, которые были лидерами в момент своего финиша, затем
их фамилии в лексикографическом порядке, по одной в строке.

## Примеры

### Пример 1

Ввод:

```
6
Zaitseva 21:38.2
Hauswald 21:21.0
Boulygina 22:04.4
Henkel 22:06.1
Wilhelm 21:11.1
Jonsson 22:05.8
```

Вывод:

```
3
Hauswald
Wilhelm
Zaitseva
```

## Решение

Считаем в десятых долях секунды. Спортсмен i (с нуля) стартует в 300·i
и финиширует в 300·i плюс время прохождения. Сортируем спортсменов по
моменту финиша и проигрываем гонку: спортсмен попадает на табло, если
его время лучше всех уже показанных. Собранные фамилии сортируем и
выводим. `O(n log n)`.

В примере финиши идут в порядке Zaitseva (12982), Hauswald (13110),
Boulygina (13844), Wilhelm (13911), Henkel (14161), Jonsson (14758) в
десятых; лучшее время улучшается у Zaitseva, Hauswald и Wilhelm.

Подводные камни:

- порядок финиша не совпадает с порядком старта, поэтому сортировать
  надо по моменту финиша, а не по времени прохождения;
- табло показывает лучшее время на данный момент, а не первого
  финишировавшего;
- при сравнении моментов финиша учитывайте сдвиг старта: в тесте 06
  Late финиширует в 6000 десятых, а Early — в 6601, поэтому лидирует
  только Late;
- ответ упорядочен по фамилии, а не по порядку смены табло.

## Оптимизированные решения

Оптимизированное решение на C++ читает каждого лыжника одним `scanf`,
который сразу делит время по `:` и `.`, вместо `iostream` и подстрок,
преобразуемых через `stoi`, и хранит лыжников в статическом массиве из
100 записей с именем на 21 байт, чего хватает, так как `n ≤ 100`, а в
фамилии не больше 20 букв, вместо вектора кортежей с `std::string`.
Табло хранит указатели на имена, отсортированные через `strcmp`:
{1821_sorting_optimized.cpp}.

Оптимизированное решение на Java читает строки через `BufferedReader` и
`StringTokenizer`, который заодно делит время по `:` и `.`, вместо
`Scanner` и подстрок, и сортирует массив записей, реализующих
`Comparable`, вместо упакованных индексов `Integer` с
компаратором-лямбдой: {1821_sorting_optimized.java}.
