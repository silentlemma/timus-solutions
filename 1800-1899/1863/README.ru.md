# 1863. Мирный атом

## Задача

Стержни реактора могут стоять на любой глубине от 0 до n мм и начинали
на глубине s. В логе записаны k перемещений стержней, но только их
длины, а не направление — вверх или вниз; стержни никогда не выходили
за пределы [0, n]. Найти наименьшую и наибольшую глубину, на которой
стержни могут быть сейчас.

## Входные данные

n, s и k (0 ≤ s ≤ n ≤ 10⁹, n > 0, 1 ≤ k ≤ 40), затем k длин
перемещений. Некоторый выбор направлений оставляет стержни в пределах.

## Выходные данные

Наименьшая и наибольшая возможная конечная глубина.

## Примеры

### Пример 1

Ввод:

```
10 3 3
4 5 1
```

Вывод:

```
1 3
```

## Решение

Перебор всех 2⁴⁰ направлений слишком долог, поэтому разделим лог
пополам. Для первой половины храним множество глубин, достижимых без
выхода из [0, n], расширяя его перемещение за перемещением и сливая
равные глубины; в нём не больше 2²⁰ элементов.

Для второй половины переберём все выборы направлений поиском в глубину,
следя за тремя числами: суммарным сдвигом t и наименьшей и наибольшей
частичными суммами low и high. Начав с глубины x, вторая половина
остаётся в пределах ровно тогда, когда x + low ≥ 0 и x + high ≤ n, так
что x должно лежать в [−low, n − high], а заканчивается она в x + t.
Выбор отсекается, как только high − low превышает n: никакое x уже не
подойдёт. На каждом законченном выборе двоичным поиском по
отсортированным глубинам первой половины находим наименьшее и
наибольшее x в этом отрезке; они дают наименьшую и наибольшую конечную
глубину для этого выбора. `O(2^(k/2)·k)`.

В примере первое перемещение ведёт из 3 в 7 (−4 ушло бы ниже 0), затем
7 ± 5 даёт 2 или 12, где в пределах только 2; последнее перемещение на
1 заканчивается в 1 или 3.

Подводные камни:

- пределы должны соблюдаться после каждого перемещения, а не только в
  конце, поэтому второй половине нужны её частичные экстремумы, а не
  только сумма;
- хранить все 2²⁰ выборов второй половины по три числа слишком
  затратно для 64 МБ; поиску в глубину память не нужна;
- решение на Python работает на PyPy, хранит значения, достижимые каждой
  половиной, в отсортированных 32-битных массивах вместо хеш-множеств и
  отсекает перебор арифметическими оценками и симметрией: у судьи 11 МБ,
  тогда как прежняя версия с множествами занимала 70 МБ на тесте 10.

Ответы совпадают с прослеживанием множества достижимых глубин через
весь лог на трёхстах коротких логах и с независимой принятой
реализацией на логах из 40 перемещений.
