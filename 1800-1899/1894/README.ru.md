# 1894. Нелётная погода

[Timus 1894](https://acm.timus.ru/problem.aspx?space=1&num=1894) · сложность 1405 · geometry

Автор оригинальной задачи — Даниил Айзенштейн; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны положения двух невырожденных строго выпуклых многоугольников
60 секунд назад. Многоугольник A неподвижен, а B переносится без
вращения со скоростью ровно 1 метр в секунду в неизвестном постоянном
направлении. На снимке B покрывает хотя бы одну внутреннюю точку A.

Найдите минимальное возможное время ожидания от текущего момента
до разделения многоугольников среди всех постоянных направлений
движения. Если при каком-то направлении они уже могли разделиться,
ответ равен 0. Ограничения: 2 секунды и 64 МБ.

## Входные данные

Первая строка содержит числа вершин n и m многоугольников A и B:
3 ≤ n, m ≤ 50 000. Следующие n строк задают вершины A, затем m строк
задают вершины B. Оба списка идут против часовой стрелки.
Координаты целые, заданы в метрах и не превосходят 10⁸ по модулю.

## Выходные данные

Выведите минимальное оставшееся время в секундах.

## Проверка

Абсолютная или относительная погрешность не должна превышать 10⁻⁶.

## Примеры

### Пример 1

Ввод:

```
4 4
400 400
600 400
600 600
400 600
0 0
1000 0
1000 1000
0 1000
```

Вывод:

```
540.0
```

## Решение

Пусть K = A + (−B) — разность Минковского: множество всех векторов
a − b для точек a из A и b из B. После переноса B на вектор v
многоугольники пересекаются тогда и только тогда, когда v принадлежит K.
Начальное пересечение гарантирует, что начало координат строго внутри K.

Для единичного направления u смещение через t секунд равно t·u.
Разделение означает выход из K вдоль этого луча. Минимальная длина
выхода по всем направлениям равна расстоянию r от начала координат
до границы K: любой выход достигает границы, а ближайшая граничная
точка задаёт направление с этим порогом разделения. Скорость равна 1,
снимок сделан 60 секунд назад, поэтому ответ — max(0, r − 60).

Построим K за линейное время. Изменим знаки координат всех вершин B;
порядок против часовой стрелки сохраняется. Циклически сдвинем каждый
список так, чтобы первым стал минимум по y, а при равенстве — по x.
Направления рёбер после этого уже идут по углу. Сливаем два списка
рёбер, выбирая меньшее направление, а при одинаковом направлении
прибавляя оба вектора. Начинаем с суммы первых вершин и получаем
границу K против часовой стрелки.

Для соседних вершин p и q многоугольника K расстояние от начала
координат до прямой их ребра равно cross(p, q) / hypot(q − p).
Числитель положителен, поскольку начало координат внутри. Берём
минимум по рёбрам. Это также расстояние до границы многоугольника:
круг с центром в начале координат и радиусом, равным минимальному
расстоянию до прямых, лежит во всех задающих полуплоскостях. Поэтому
его точка касания ближайшей прямой принадлежит соответствующему ребру.

При слиянии можно сразу учитывать каждое новое ребро, не сохраняя K
целиком. Чтение, слияние и просмотр занимают `O(n + m)` времени;
входные массивы требуют `O(n + m)` памяти.

В примере K — квадрат [−600, 600] × [−600, 600]. Ближайшая граница
находится в 600 метрах от начала координат, поэтому минимальное
оставшееся время равно 600 − 60 = 540 секунд.

Подводные камни:

- вычесть прошедшие 60 секунд и ограничить ответ снизу нулём;
- изменить знаки координат B, не разворачивая порядок вершин;
- сливать рёбра одинакового направления одновременно;
- вычислять векторные произведения точно в знаковых 64-битных числах
  до вещественного деления; целые Python уже имеют нужную точность;
- не возводить векторное произведение в квадрат в 64-битном типе:
  возможно переполнение;
- отрицательные координаты допустимы; нужны знаковые типы и `hypot`.

Среди тестов есть тонкий многоугольник, на котором теряется точность, и
многоугольники по 50 000 вершин; ответы также отдельно проверены на 128
тестах.

## Особенности языков

Векторные произведения для направлений рёбер и числителя расстояния
вычисляются целочисленно: C++ использует `long long`, Go — `int64`,
Java — `long`, Rust — `i64`; целые Python имеют произвольную точность.
Переход к вещественным числам нужен лишь для гипотенузы и деления:
так почти параллельные координаты не теряют знак или малую разность
больших произведений.

Все версии выводят десять знаков после точки. Java явно выбирает
`Locale.US`, чтобы десятичным разделителем была точка.
