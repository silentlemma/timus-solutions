# 1885. Комфорт пассажиров

[Timus 1885](https://acm.timus.ru/problem.aspx?space=1&num=1885) · сложность 186 · math

Автор оригинальной задачи — Денис Дублённых; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Самолёт должен набрать высоту h метров за первые t секунд и дальше её
держать. Он поднимается не быстрее v метров в секунду и не может
снижаться до набора h. Уши у пассажиров заложены ровно тогда, когда
самолёт поднимается быстрее x метров в секунду. Найдите наименьшее и
наибольшее возможное время с заложенными ушами.

## Входные данные

h, t, v, x (5000 ≤ h ≤ 12 000, 50 ≤ t ≤ 1200, 1 ≤ x < v ≤ 100,
h ≤ t·v).

## Выходные данные

Наименьшее и наибольшее время, каждое с абсолютной или относительной погрешностью не больше 10⁻⁶.

## Проверка

Сравниваются два числа с абсолютным либо относительным допуском 1e-6. Новый Python прошёл 6953 проверки целевой среды, включая граничные тесты репозитория; аналитическая граница округления доказывает точность для всех входов.

## Примеры

### Пример 1

Ввод:

```
10000 500 50 10
```

Вывод:

```
125.0 500.0
```

## Решение

Наименьшее: каждая секунда на скорости x или меньше бесплатна и даёт не
больше x метров. Если t·x ≥ h, самолёт поднимается со скоростью x, и
уши не закладывает вовсе. Иначе нужно подниматься со скоростью x все
секунды, кроме τ, а τ секунд — со скоростью v, где τ·v + (t − τ)·x = h,
то есть τ = (h − t·x)/(v − x). Любая скорость ниже v только удлиняет
быстрые секунды.

Наибольшее: уши закладывает только при подъёме, так что не больше t
секунд и не больше h/x секунд. Подъём
со скоростью чуть выше x приближается к последней границе, а если h/x > t,
самолёт все t секунд поднимается со скоростью h/t > x. Ответ —
min(t, h/x). `O(1)`.

В примере t·x = 5000 < 10 000, так что нужно 5000/40 = 125 секунд на
50 м/с, а подъём на h/t = 20 > 10 м/с все 500 секунд держит уши
заложенными всё время.

Подводные камни:

- наибольшее время — предел: ровно на скорости x уши не закладывает,
  а на любой большей — да, так что ответ min(t, h/x);
- при t·x ≥ h наименьшее время равно 0;
- подъём медленнее x бесплатен, так что смесь медленных скоростей
  никогда не лучше подъёма со скоростью x.

Ответы совпадают с независимой принятой реализацией на всех тестах.

## Оптимизированные решения

`1885_math_optimized.java`. Java сохраняет формулы минимума и верхнего предела max(0,h-t*x)/(v-x) и min(t,h/x), используя точные целые числители и знаменатели. Деление столбиком сразу выводит двенадцать дробных знаков в буфер на 64 байта без преобразования double, Locale.US и общего форматирования. Погрешность усечения меньше 1e-12 и укладывается в допуск 1e-6. Условие x<v делает первый знаменатель положительным; знаменатели не больше 99, остаток после умножения на десять меньше 1000, каждый ответ не больше t<=1200, поэтому оба результата помещаются в буфер. Фиксированные ограничения и двенадцать знаков дают O(1) времени и дополнительной памяти. Учебные версии с плавающей точкой и отдельная реализация Rust не меняются.

Accepted точного исходника Java 1.8 №11327530: 0.078 с / 336 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 2/41, память 1/41. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11324784: 0.125 с / 976 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1885_math_optimized.java`: 0.078 s / 336 KB; сохранённая учебная база `1885_math.java`: 0.109 s / 1788 KB.

`1885_math_optimized.rs`. Полностью сохраняются формулы экстремумов max(0,h-t*x)/(v-x) и min(t,h/x), вычисления double и шесть знаков после точки. Rust читает четыре double проверяемыми вызовами C scanf и выводит printf, без String ввода, вектора чисел и средств форматирования Rust. Постоянные форматы C согласованы с указателями f64 и аргументами double; переменных форматных строк нет. Это улучшение ввода-вывода и среды, а не новый математический алгоритм; время и вспомогательная память O(1). Условие x<v даёт положительный знаменатель, действует прежний числовой допуск 1e-6.

По сравнению с `1885_math.rs`: время 0.046 s → 0.046 s; память 248 KB → 104 KB.

Сохраняются формулы минимума и супремума учебных версий. Числители вычисляются точно, неотрицательное деление округляется до шести знаков с масштабом `S=10^6`: `floor((a*S+floor(b/2))/b)`. Ошибка не больше половины последнего знака, `0,5·10^-6`, что укладывается в допуск. Минимум ограничивается нулём, максимум — t. Целые части и дополненные нулями дробные поля выводятся напрямую, без вещественной конвертации, общего процентного форматтера и склейки результата. Все промежуточные значения при данных ограничениях помещаются в знаковые 64 бита; Python принят на PyPy 3.10. Меняется реализация арифметики и вывода, математический ответ тот же. Короткие вещественные базы сохранены. Время и дополнительная память постоянны.

- `1885_math_optimized.py`: 0.109 s / 272 KB; база `1885_math.py`: 0.078 s / 392 KB; изменение относительно базы: время +39.7%, память -30.6%.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1885_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
