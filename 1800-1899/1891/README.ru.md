# 1891. Язык Ocean

[Timus 1891](https://acm.timus.ru/problem.aspx?space=1&num=1891) · сложность 711 · parsing

Автор оригинальной задачи — Алексей Самсонов; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Проверьте типы в последовательности объявлений переменных. Доступны
типы `int`, `real` и `string`. Каждое объявление инициализирует новую
переменную результатом вызова функции. Указанный тип — один из этих
трёх либо `auto`, принимающий тип результата функции.

Имена функций могут повторяться. Вызов выбирает функцию по имени
и упорядоченному списку типов аргументов, включая их количество.
Аргументы — переменные, объявленные в предыдущих строках. Типы должны
совпадать точно, неявных преобразований нет. Имена функций и переменных
принадлежат разным пространствам имён, поэтому могут совпадать.

Найдите первое ошибочное объявление. Внутри строки проверяйте ошибки
в следующем порядке приоритета:

- `Double declaration`: переменная с таким именем уже объявлена;
- `Unknown variable`: хотя бы один аргумент ещё не объявлен;
- `No such function`: нет функции с нужным именем и типами аргументов;
- `Invalid initialization`: явно указанный тип не совпадает с типом результата.

Если вся программа верна, перечислите выведенные типы переменных
`auto` в порядке объявления. Ограничения: 1 секунда и 64 МБ.

## Входные данные

Сначала задано число заголовков функций f, где 1 ≤ f ≤ 100.
Следующие f строк имеют вид `name(type, ..., type) : type`;
список параметров может быть пустым. Нет двух заголовков с одинаковыми
именем и упорядоченным списком типов параметров одновременно.

Затем задано число объявлений n, где 1 ≤ n ≤ 100. Следующие n строк
имеют вид `type variable = name(argument, ..., argument)`, где `type`
может также быть `auto`, а аргументы — имена переменных. В каждом
заголовке и вызове не больше 10 аргументов.

Имена состоят из 1–20 букв. В именах переменных допустимы только
строчные английские буквы; имена функций могут содержать и прописные
английские буквы и различаются по регистру. Слова `int`, `real`,
`string` и `auto` не могут быть именами. Пробелы расставлены как
в примерах; синтаксис корректен, проверять нужно только перечисленные
смысловые ошибки.

## Выходные данные

При ошибке выведите `Error on line k: message`, где k — номер
объявления, начиная с 1, а message — точный текст ошибки из списка.
В этом случае типы не выводятся даже для предыдущих верных строк.

Иначе для каждой переменной `auto` выведите `name : type` в порядке
объявления. Если объявлений `auto` нет, вывод пустой.

## Проверка

Ответы сравниваются по последовательностям токенов.

## Примеры

### Пример 1

Ввод:

```
2
ReadInt() : int
IntToReal(int) : real
3
auto a = ReadInt()
auto b = IntToReal(a)
int c = ReadInt()
```

Вывод:

```
a : int
b : real
```

### Пример 2

Ввод:

```
1
ReadInt() : int
2
int x = ReadInt()
int x = ReadInt()
```

Вывод:

```
Error on line 2: Double declaration
```

### Пример 3

Ввод:

```
3
ReadInt() : int
ReadReal() : real
SumRealInt(real, int) : real
4
auto x = ReadInt()
auto y = ReadReal()
real z = SumRealInt(y, x)
real q = SumRealInt(x, y)
```

Вывод:

```
Error on line 4: No such function
```

## Решение

Разберём заголовки и сохраним отображение сигнатуры функции в тип
результата. Сигнатура состоит из имени и упорядоченного списка типов
параметров; пустой список означает функцию без параметров. Отдельно
храним отображение имён объявленных переменных в их типы. Знаки
пунктуации разделяют поля и не могут встретиться внутри имени.

Обрабатываем объявления по порядку. Сначала проверяем, не занято ли
новое имя. Только затем ищем все аргументы: любой неизвестный аргумент
даёт `Unknown variable` ещё до поиска функции. По типам аргументов
строим сигнатуру и ищем её в таблице функций. Если функция найдена,
сравниваем тип результата с явно указанным типом либо используем его
как выведенный тип для `auto`.

Добавляем переменную лишь после успешного прохождения всех проверок.
Для `auto` также сохраняем имя и тип в списке вывода. Печатаем этот
список только после успешной проверки всей программы; если позже
нашлась ошибка, выводим только её.

Перед каждой строкой таблица переменных содержит в точности типы,
установленные предыдущими верными объявлениями. Поэтому поиск
аргументов использует именно допустимые переменные. Поиск сигнатуры
точно реализует правило выбора перегрузки, а сравнение типа результата
проверяет инициализацию. Выполняя эти действия в нужном порядке,
получаем приоритетную ошибку в первой неверной строке.

Пусть L — общая длина входа. С хеш-таблицами разбор, построение
сигнатур и поиск занимают ожидаемое время `O(L)` и память `O(L)`.

В первом примере `a` получает тип `int`, а `b` — `real`; явно
объявленная `c` в вывод не попадает. Во втором примере `x` повторно
объявлена в строке объявлений 2. В третьем `SumRealInt(y, x)` подходит
к `(real, int)`, а `(int, real)` в строке 4 не подходит. Хотя типы
`x` и `y` были выведены раньше, печатать их нельзя: в программе ошибка.

Подводные камни:

- учитывать порядок аргументов и регистр имени функции;
- отсутствие функции не важнее неизвестного аргумента;
- проверять повторное объявление до разбора правой части;
- новая переменная ещё не может ссылаться на себя;
- `auto` превращается в конкретный тип и не входит в сигнатуру вызова;
- `int` не преобразуется в `real` неявно;
- функции без аргументов и пустой вывод корректной программы допустимы.

Ответы совпадают с отдельным интерпретатором правил на 237 тестах, где
есть и корректные программы, и все четыре вида ошибок.
