# 1878. Кубик Рубинчика

## Задача

Головоломка состоит из четырёх прозрачных слоёв 4 × 4 на общей оси. На
каждом слое четыре цветных квадратика, по одному каждого из четырёх
цветов, расположенные так, что поворот слоя на четверть оборота
переводит каждый в следующую четверть. Четыре квадратика каждого слоя
образуют орбиту этого поворота. У всех слоёв одинаковый циклический
порядок цветов по часовой стрелке с точностью до поворота, как на
[исходной схеме слоёв](https://acm.timus.ru/image/get.aspx/a394d0eb-f9d5-4bc2-846a-74ef972e9e4b).
Сверху слои заполняют сетку
4 × 4. Головоломка собрана, когда каждая четверть 2 × 2 одного цвета.
Ход — поворот одного слоя на 90° в любую сторону. По виду сверху
найдите наименьшее число ходов до сборки.

## Входные данные

Четыре строки по четыре цвета от 1 до 4 — вид сверху.

## Выходные данные

Наименьшее число ходов.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
2 1 2 3
1 1 2 2
4 4 3 3
1 4 3 4
```

Вывод:

```
1
```

## Решение

У всех слоёв одинаковый циклический порядок цветов, поэтому совмещение
квадратиков цвета 1 совмещает и остальные цвета.
На каждом слое ровно один квадратик цвета 1, и он задаёт ориентацию
слоя — свою четверть. Занумеруем четверти в том порядке, в каком их
обходит квадратик при повороте (левая верхняя, правая верхняя, правая
нижняя, левая нижняя). Головоломка собрана, когда все четыре квадратика
цвета 1 в одной четверти t. Слою, чей квадратик в четверти p, нужно
min(d, 4 − d) ходов, где d = (p − t) mod 4. Перебираем все четыре t и
берём самое дешёвое. `O(1)`.

В примере три квадратика цвета 1 в левой верхней четверти и один в
левой нижней, на четверть оборота дальше: один ход.

Подводные камни:

- совмещать только цвет 1 можно благодаря общему циклическому порядку
  цветов (как в тесте 01); одного квадратика каждого цвета на слое
  для этого недостаточно;
- в собранном состоянии цвет 1 может быть в любой четверти: кубик
  может оказаться повёрнут целиком;
- слой, развёрнутый на пол-оборота, стоит два хода в любую сторону;
- четверти надо нумеровать по кругу, а не по строкам, иначе расстояния
  будут неверны.

Решение на Python совпадает с независимым поиском в ширину по поворотам
физических слоёв на всех 1536 разрешимых полях, включая все соответствия
между числами и цветами.

## Оптимизированные решения

`1878_math_optimized.java`. Сохраняются четыре счётчика квадрантов и точное выражение 4−max(|a−d|,|b−c|) для фиксированного поля 4×4. O(1) времени и памяти. Все числовые поля, нужные вычислению, потребляются до вывода. Один массив 256 байт сначала служит вводу, затем выводу; перед знаковым int резервируются двенадцать байт, разворачиваются только новые цифры. Убраны отдельные массивы ввода, вывода и цифр, нужные алгоритму данные не перезаписываются. Разбор и вывод линейны по потреблённым байтам, буфер фиксирован.

Точный исходник: Java 1.8 Accepted #11327768: 0.093 s / 368 KB. Сохранённые места в группе компилятора от 2026-11-20, время затем память: 4/31; 2/31. Строгий допуск учитывает только время при памяти меньше 1024 КБ: первые десять или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка — первого места по обеим метрикам. Сохранённый прежний вариант имеет собственную парную посылку #11308562 (Java 1.8): 0.109 s / 440 KB; замеры и рантаймы не смешиваются. Все учебные исходники сохранены без изменений.

- `1878_math_optimized.java`: 0.093 s / 368 KB; сохранённая учебная база `1878_implementation.java` (Java 1.8): 0.14 s / 1668 KB.

`1878_implementation_optimized.go`. Сохраняется проверка стоимости поворотов к четырём целевым квадрантам. Шестнадцать клеток сразу превращаются в четыре счётчика; индекс квадранта по часовой стрелке вычисляется арифметически, сами клетки не сохраняются. Расстояния по кругу и равенства прежние. Для поля 4×4 время и память постоянны. Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1878_implementation.go`: время 0.031 s → 0.015 s; память 1084 KB → 292 KB.

`1878_implementation_optimized.rs`. Сохраняется проверка четырёх целевых квадрантов по стоимости поворотов. Шестнадцать клеток сразу превращаются в четыре счётчика u8 белых, каждый не больше четырёх; индекс квадранта по часовой стрелке получается арифметически без массива клеток и таблицы соответствия. Число выводится напрямую. Для фиксированной задачи 4×4 время и память постоянны; кратчайшее расстояние по кругу и равенства прежние.

По сравнению с `1878_implementation.rs`: время 0.046 s → 0.031 s; память 208 KB → 60 KB.

Формула дисбаланса фиксированного поля заменяет перебор целевых цветов и циклы модульных расстояний. Подсчитываем один цвет в каждом квадранте в порядке строк, сравниваем дисбалансы противоположных квадрантов и берём соответствующее дополнение. Существенен циклический порядок цветов на физической схеме; произвольная перестановка квадрантов неэквивалентна. Размер поля фиксирован, поэтому память и число операций постоянны относительно параметров входа.

- `1878_math.java`: 0.109 s / 440 KB; база `1878_implementation.java`: 0.140 s / 1668 KB; изменение относительно базы: время -22.1%, память -73.6%.
- `1878_math.py`: 0.125 s / 288 KB; база `1878_implementation.py`: 0.093 s / 432 KB; изменение относительно базы: время +34.4%, память -33.3%.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1878_implementation_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
