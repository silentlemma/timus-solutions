# 1807. Патроны для Максима

[Timus 1807](https://acm.timus.ru/problem.aspx?space=1&num=1807) · сложность 1479 · number_theory

Автор оригинальной задачи — Даниил Айзенштейн (идея — Алексей Самсонов); NEERC 2010, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n патронов принесли не менее чем в двух одинаковых ящиках, по меньшей
мере по 100 в каждом. Разложить их по двум или более карманам так,
чтобы НОД количеств в карманах был наибольшим, а среди таких
раскладок — наибольшим НОК. Вывести любую лучшую раскладку.

## Входные данные

n (200 ≤ n ≤ 10⁹).

## Выходные данные

Количества патронов в карманах.

## Примеры

### Пример 1

Ввод:

```
200
```

Вывод:

```
100 100
```

### Пример 2

Ввод:

```
625
```

Вывод:

```
375 250
```

## Решение

Пусть p — наименьший простой делитель n; n составное, так что
p ≤ 31622. НОД g хотя бы двух карманов делит n и оставляет n/g ≥ 2,
поэтому наибольший НОД равен n/p. Каждая лучшая раскладка — это n/p,
умноженное на части с суммой p, а её НОК — n/p, умноженное на НОК
частей. Среди частей с суммой p наибольший НОК дают степени различных
простых, дополненные единицами, — это функция Ландау. Её находит
рюкзак: для каждого простого q выбираем не больше одной степени q,
меньшей p, с весом, равным степени, и ценностью, равной её логарифму,
и максимизируем ценность при весе не больше p. Таблица выбора для
каждого простого восстанавливает части. Полный перебор по всем простым
один раз показал, что лучшему выбору для любого простого p < 31623 не
нужны простые больше 700, так что участвуют только простые меньше 1000.
Части меньше p, поэтому карманов всегда хотя бы два.
`O(p · π(1000))`.

Во втором примере p = 5 и n/p = 125; 5 = 2 + 3 даёт НОК 6, наибольший
возможный, так что в карманах 250 и 375.

Подводные камни:

- при чётном n p = 2, и единственная раскладка — две половины;
- само p не может быть одной частью: карманов нужно хотя бы два;
- НОК вырастает за пределы любых целых типов, поэтому сравниваются
  логарифмы.

Чекер сравнивает точный НОК с НОК ожидаемого ответа и проверяет сумму,
НОД и число карманов. Ответы совпадают с независимой принятой
реализацией на квадратах всех простых от 11 до 400, на квадрате
наибольшего простого меньше 31623 и на случайных количествах.
