# 1803. Винтовки белочехов

[Timus 1803](https://acm.timus.ru/problem.aspx?space=1&num=1803) · сложность 716 · math

Автор оригинальной задачи — Виктор Камашев; NEERC 2010, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Винтовка i стоит i-е число Фибоначчи рублей (1, 1, 2, 3, …). Купюры
достоинством в степени k, и каждая винтовка оплачивается наименьшим
числом купюр. Упорядочить винтовки по числу уплаченных купюр, при
равенстве — по номеру винтовки.

## Входные данные

k и n (2 ≤ k ≤ 10, 3 ≤ n ≤ 50000).

## Выходные данные

Номера винтовок в нужном порядке.

## Примеры

### Пример 1

Ввод:

```
10 8
```

Вывод:

```
1 2 3 4 8 7 5 6
```

## Решение

Наименьшее число купюр для суммы — это сумма её цифр в системе по
основанию k, так что число купюр равно сумме цифр числа Фибоначчи.
В F(50000) около 10⁴ десятичных цифр, поэтому числа складываются
одно из другого прямо в системе по основанию k. Компилируемые решения
хранят разряды по основанию k^m — наибольшей степени k, не
превосходящей миллиона. Таблица даёт сумму цифр каждого разряда, так
что одно сложение сразу даёт следующее число и его сумму цифр. Затем
устойчивая сортировка по сумме цифр даёт порядок. `O(n² / log B)` для
разрядов по основанию B.

Решение на Python хранит каждую цифру по основанию k в 4-битном поле
одного большого целого. Поле одного слагаемого содержит цифру + 16 − k, поэтому оно
переполняется ровно тогда, когда цифра по основанию k даёт перенос, и
обычное сложение целых передаёт переносы дальше. Поля, давшие
перенос, находятся по исключающему или слагаемых и суммы и снова
получают смещение. Число единиц в четырёх битовых плоскостях полей
даёт сумму цифр. При k = 2 сумма цифр — просто число единиц.

В примере цены 1, 1, 2, 3, 5, 8, 13, 21 с суммами цифр 1, 1, 2, 3, 5,
8, 4, 3, что даёт 1 2 3 4 8 7 5 6.

Подводные камни:

- в числах тысячи цифр, далеко за пределами 64 бит;
- при равном числе купюр винтовки идут по возрастанию номеров;
- перевод больших чисел в текст в Python слишком медленный для 50000
  чисел.

Ответы совпадают с независимой принятой реализацией для каждого
основания на наибольшем числе винтовок и на многих меньших.

## Оптимизированные решения

В основаниях 2, 4 и 8 сумма цифр получается подсчётом битов. В остальных основаниях для сумм цифр блоков используются байтовые таблицы.

`1803_math_optimized.cpp`. Сохраняются сложение чисел Фибоначчи по блокам и выбор меньшего индекса при равенстве. Каждое основание специализируется при компиляции. В обычных основаниях блок делится на две части; таблица сумм цифр строится во время работы и занимает не больше 4096 байтов вместо таблицы для всех значений блока. Для оснований 2/4/8 используются 60-битные блоки и подсчёт битовых плоскостей; аппаратный POPCNT вызывается только после проверки CPU, иначе работает программная ветка. Нормализация беззнаковым заёмом точна: основание блока меньше половины диапазона беззнакового типа, промежуточная сумма меньше удвоенного основания. Таблица содержит вычисленные суммы цифр, не готовые ответы. При размере таблицы T и основании блока B время O(T+n²/log B+n log n), память O(T+n); все учебные исходники сохранены.

Accepted точного исходника G++ 13.2 x64 №11326993: 0.171 с / 620 КБ. В сохранённой выборке актуальных компиляторов от 2026-11-20 место по времени 10/45, по памяти 2/45: обе цели первых десяти мест пройдены, звёздочка не нужна. При памяти меньше 1024 КБ строгий допуск также учитывает только время. Ранее документированная C++-посылка №11320151 использовала 1380 КБ за 0.14 с: новый запуск экономнее по памяти, но его зафиксированное время выше. Это две разные принятые посылки; в таблице указаны только парные измерения №11326993.

- `1803_math_optimized.cpp`: 0.171 s / 620 KB; сохранённая учебная база `1803_math.cpp`: 0.375 s / 4728 KB.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1803_math_implementation_optimized.rs`. Для оснований, не являющихся степенями двойки, предел основания блоков уменьшен с миллиона до 200000; выбирается наибольшая степень системы счисления в этом пределе. Таблица сумм цифр становится меньше ценой большего числа блоков. Точные суммы, рекуррентность и ветвь степеней двойки сохранены. Токены читаются через ограниченный нативный байтовый буфер; короткие хранятся внутри объекта, дополнительная память выделяется только длинным. Десятичный разбор сохраняет знаковые границы без хранения всего командного ввода.

Accepted #11328979 (Rust 1.75 x64): **0.125 s / 732 KB**. Архивное сравнение: `1803_math_optimized.rs` (Rust 1.75 x64) — 0.187 s / 1420 KB (#11320179).
