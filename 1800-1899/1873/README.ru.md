# 1873. Летопись GOV

[Timus 1873](https://acm.timus.ru/problem.aspx?space=1&num=1873) · сложность 365 · implementation

Автор оригинальной задачи — Михаил Рубинчик; Уральская региональная командная олимпиада по программированию 2011.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Условие подробно рассказывает историю команды Alarm, позже Team.GOV,
контест за контестом, со всеми сменами состава. Игроки занумерованы от
0 до 13. По номеру игрока выведите, сколько контестов этот игрок
сыграл за команду. Игровой тур последнего чемпионата Урала не
считается.

## Входные данные

Номер игрока от 0 до 13.

## Выходные данные

Число контестов, сыгранных игроком за команду.

## Примеры

### Пример 1

Ввод:

```
1
```

Вывод:

```
21
```

### Пример 2

Ввод:

```
11
```

Вывод:

```
0
```

## Решение

Вся работа — внимательно прочитать историю; программа лишь смотрит в
таблицу. Контесты и составы по порядку:

| Контесты | Игроки |
| --- | --- |
| Alarm: УрГУ, четвертьфинал, полуфинал, Урал, Татарстан | 0, 1, 2 |
| чемпионат УрГУ, осень 2008 | 1, 2 |
| четвертьфинал | 1, 2, 3 |
| полуфинал | 1, 2, 4 |
| отбор на чемпионат Урала | 1, 2, 5 |
| чемпионат Урала | 1, 5 |
| четвертьфинал, чемпионат УрГУ, полуфинал | 1, 2, 6 |
| Битва поколений | 1, 6, 7 |
| отбор на чемпионат Урала | 5, 6 |
| чемпионат Урала | 1, 5, 6 |
| чемпионат УрГУ, четвертьфинал, Всесибирская олимпиада, полуфинал | 1, 8, 9 |
| последний чемпионат Урала | 1, 3, 10 |
| SWERC | 1, 12, 13 |

Сумма даёт 5, 21, 12, 2, 1, 4, 6, 1, 4, 4, 1, 0, 1, 1 контестов для
игроков от 0 до 13. `O(1)`.

Подводные камни:

- игрок 11 участвовал только в игровом туре, так что ответ 0;
- некоторые контесты играли вдвоём: чемпионат УрГУ 2008 года без
  игрока 3, чемпионат Урала без игрока 2 и отбор без игрока 1;
- контест SWERC из конца истории тоже считается.

Таблица совпадает с независимой принятой реализацией для всех
четырнадцати игроков.

## Оптимизированные решения

Go и Python сохраняют ту же таблицу числа соревнований на четырнадцать участников. Go читает номер прямо через фиксированный байтовый буфер и переиспользует его для ответа. Go использует syscall.Read и syscall.Write со стандартными дескрипторами, повторяет прерванные вызовы и дописывает частичную запись. Версия для PyPy читает номер и выводит готовый байтовый ответ через небуферизованные двоичные потоки, без текстового форматирования.

Принятая версия PyPy 3.10 x64 заняла 0.14 с при 0.078 с у базовой и использовала 208 KB при 388 KB у базовой.

Принятые базовые реализации [1873_implementation.cpp](1873_implementation.cpp), [1873_implementation.java](1873_implementation.java), [1873_implementation.rs](1873_implementation.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
