# 1895. 机上牛排

[Timus 1895](https://acm.timus.ru/problem.aspx?space=1&num=1895) · 难度 2082 · dp

原题作者 Alex Samsonov，出自 NEERC 2011 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

在最多同时处理 k 个订单的设备上安排 n 个订单。每个订单需要两个
独立且连续的一分钟步骤，两步之间可以暂停。订单 i 必须不晚于 tᵢ
完成，且不能早于 max(0, tᵢ − x) 开始。

所有步骤的开始时刻必须是非负整数。最小化至少有一个步骤执行的分钟
数量，并构造安排。空闲间隔不计入目标。时间限制为 1 秒，内存为 64 MB。

## 输入

第一行为 x、k，满足 2 ≤ x ≤ 1000，1 ≤ k ≤ 50。
第二行为 n，1 ≤ n ≤ 50。第三行为非递减的 t₁, …, tₙ，
其中 2 ≤ tᵢ ≤ 1000。

## 输出

若无解，输出 `-1`。否则先输出最少工作分钟数，再按输入顺序输出 n 对
步骤开始时刻。订单 i 的 aᵢ、bᵢ 必须满足
max(0, tᵢ − x) ≤ aᵢ < bᵢ，且 bᵢ + 1 ≤ tᵢ。任一时刻最多开始 k 个
步骤。任意最优安排均可。

## 评测方式

检查器验证时间窗口、每对步骤的先后关系、容量，以及声明的工作分钟数
是否等于不同开始时刻的数量。该数量还必须等于最优值；仅合法但非最优
的安排不能通过。

## 解法

记 rᵢ = max(0, tᵢ − x)。rᵢ 和截止时刻 tᵢ 都不递减。可以假设第一步
按订单编号执行，第二步也如此。证明方法是分别排序所有第一步开始时刻
a₁ ≤ … ≤ aₙ 和第二步开始时刻 b₁ ≤ … ≤ bₙ，再将各自第 i 项分配给
订单 i。释放时刻有序保证 aᵢ ≥ rᵢ，截止时刻有序保证 bᵢ + 1 ≤ tᵢ。
原安排中，最早的 i 个第二步都有各自的第一步严格早于 bᵢ，因此
aᵢ < bᵢ。每分钟执行的步骤总数保持不变。

按已工作分钟数 c 进行动态规划。状态 (c, i, j) 保存完成 i 个第一步、
j 个第二步后，最后一个工作分钟的最早开始时刻。初始状态 (0, 0, 0)
的时刻为 −1。对于相同计数，只保留最早时刻即可：更早结束的前缀可以
原样执行较晚前缀的任何后续安排，不会违反窗口或容量。

选择 p 个新的第一步，0 ≤ p ≤ min(k, n − i)。将剩余容量用于
q = min(k − p, i − j) 个旧订单的第二步。跳过 p + q = 0。只有此前
已经开始的订单才能执行第二步，所以一个订单不会在同一分钟完成两步。
新时刻至少是前一时刻加 1；若 p > 0，还要至少为 rᵢ₊ₚ。若 q > 0，
该分钟结束时必须不晚于这些第二步中最早的截止时刻 tⱼ₊₁。用所得时刻
更新 (c + 1, i + p, j + q) 的最小值。

总取最大的 q 是安全的。可用空余容量立即完成更多旧订单，再删除其未来
的第二步。它们完成得更早，其余操作时刻不变。因此较小的 q 不会带来
更优的后续安排。

如果下一个未完成订单已经来不及，则丢弃状态。最后工作开始于 s 时，
已经完成第一步的订单最早在 s + 2 完成；尚未开始的订单最早在 s + 3
完成。这些都是必要条件，不会排除可行安排。

第一个到达 (n, n) 的层数就是最少工作分钟数。保存前驱和所选分钟，
恢复每个订单的两次开始时刻。如果直到 2n 层都未到达目标，则输出 −1，
因为任何安排至多占用 2n 个不同分钟。

总状态数为 `O(n³)`，每个状态至多 k + 1 个转移。时间为 `O(n³k)`，
用于恢复安排的空间为 `O(n³)`。

第一个样例中，订单 1 必须占用分钟 0 和 1。订单 3 与订单 2 的可用窗口
只重叠一分钟，因此它们总共至少还需三个工作分钟；给出的安排正好用了
五分钟。第二个样例有八个步骤，容量为 2，至少需要四分钟，3、4、5、6
即可。第三个样例只有分钟 0 和 1 可用，容量为 1，无法安排四个步骤。

注意事项：

- 在 tᵢ 开始的步骤完成得太晚；
- 同一订单的两步必须占用不同分钟；
- 将负的释放时刻截为零；
- 目标是被占用的分钟数，不是最早到最晚时刻的跨度；
- 贪心填满旧分钟可能阻碍更优的重新分配。

带网络流检验的穷举在 408 个小测试上确认了最优值，另有 19 个刁钻的安排用来检验评测程序。

## 各语言说明

各版本都将 `(i, j)` 编码为 `i·(n+1)+j`，只遍历当前层的活跃状态。
时间层和前驱层都会保留，以便恢复安排。

Python 用有符号短整数数组 `array("h")` 保存这两类层：状态编码至多为
`51²−1 = 2600`，时间无穷大标记至多为 1001，因此包括 −1 在内的存储值
均可容纳。编译语言版本使用普通整数数组或向量；Java 使用带缓冲输入的
`StreamTokenizer`。
