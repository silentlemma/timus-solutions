# 1895. Бифштексы на борту

[Timus 1895](https://acm.timus.ru/problem.aspx?space=1&num=1895) · сложность 2082 · dp

Автор оригинальной задачи — Алексей Самсонов; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Распределите n заказов на оборудовании, которое одновременно обрабатывает
не более k заказов. Каждому нужны два отдельных непрерывных этапа по
одной минуте; между ними можно делать паузу. Заказ i должен закончиться
не позже tᵢ и не может начаться раньше max(0, tᵢ − x).

Начала этапов — неотрицательные целые числа. Минимизируйте число минут,
когда выполняется хотя бы один этап, и постройте расписание. Промежутки
простоя не учитываются. Ограничения: 1 секунда и 64 МБ.

## Входные данные

Первая строка содержит x и k: 2 ≤ x ≤ 1000; 1 ≤ k ≤ 50.
Вторая строка содержит n: 1 ≤ n ≤ 50. В третьей даны t₁, …, tₙ
по неубыванию: 2 ≤ tᵢ ≤ 1000.

## Выходные данные

Если расписания нет, выведите `-1`. Иначе выведите минимальное число
занятых минут и затем n пар времён начала этапов в порядке ввода.
Для заказа i пара aᵢ, bᵢ должна удовлетворять
max(0, tᵢ − x) ≤ aᵢ < bᵢ и bᵢ + 1 ≤ tᵢ. В одну минуту может начинаться
не больше k этапов. Подходит любое оптимальное расписание.

## Проверка

Чекер проверяет временные окна, порядок двух этапов, вместимость
и равенство заявленного числа занятых минут числу различных времён
начала. Это число должно быть оптимальным: допустимое, но неоптимальное
расписание не принимается.

## Решение

Обозначим rᵢ = max(0, tᵢ − x). И rᵢ, и сроки tᵢ не убывают.
Можно считать, что первые этапы идут по номерам заказов, и вторые —
тоже. Для доказательства отдельно отсортируем начала первых этапов
a₁ ≤ … ≤ aₙ и вторых b₁ ≤ … ≤ bₙ, а заказу i назначим i-е времена.
Из упорядоченности нижних границ следует aᵢ ≥ rᵢ, а из сроков —
bᵢ + 1 ≤ tᵢ. Первым i вторым этапам в исходном расписании
предшествуют i первых этапов строго раньше bᵢ, значит aᵢ < bᵢ.
Число этапов в каждую минуту при переназначении не меняется.

Динамика идёт по числу c занятых минут. В состоянии (c, i, j)
храним самое раннее последнее время начала при i выполненных первых
этапах и j вторых. Начальное состояние (0, 0, 0) имеет время −1.
Достаточно самого раннего времени: такой префикс может повторить
продолжение более позднего с теми же количествами этапов, не нарушая
окон и вместимости.

Выбираем p новых первых этапов: 0 ≤ p ≤ min(k, n − i). Остаток
вместимости заполняем q = min(k − p, i − j) вторыми этапами уже
начатых заказов. Пропускаем p + q = 0. Оба этапа одного заказа
не попадут в одну минуту. Новое начало — предыдущее время плюс 1,
увеличенное до rᵢ₊ₚ при p > 0. Если q > 0, окончание не должно
превышать tⱼ₊₁ — ближайший срок среди этих вторых этапов. Обновляем
состояние (c + 1, i + p, j + q) минимумом полученного времени.

Максимальное q безопасно. Свободной вместимостью можно завершить
больше уже начатых заказов сейчас, а их вторые этапы удалить из
будущего расписания. Эти заказы завершаются раньше, остальные операции
сохраняют времена. Поэтому меньшее q не даёт лучшего продолжения.

Отбрасываем состояние, если следующему незавершённому заказу уже
не хватает времени. После последнего начала в s заказ с выполненным
первым этапом не закончится раньше s + 2, а ещё не начатый — раньше
s + 3. Это необходимые условия, не исключающие допустимое расписание.

Первый слой, достигший (n, n), даёт минимум занятых минут. Сохраняем
предков и выбранные минуты, чтобы восстановить оба начала каждого
заказа. Если цель не достигнута до слоя 2n включительно, выводим −1:
любое расписание использует не больше 2n занятых минут.

Всего `O(n³)` состояний по всем слоям, из каждого не больше k + 1
переходов. Время — `O(n³k)`, память с восстановлением — `O(n³)`.

В первом примере заказ 1 вынуждает занять минуты 0 и 1. Заказ 3
может разделить с заказом 2 не больше одной минуты их работы,
поэтому им вместе нужны ещё хотя бы три занятые минуты. Вывод
использует ровно пять. Во втором примере восемь этапов при вместимости
2 требуют хотя бы четырёх минут; подходят 3, 4, 5 и 6. В третьем
доступны только минуты 0 и 1, куда не помещаются четыре этапа
при вместимости 1.

Подводные камни:

- этап, начавшийся в tᵢ, завершится слишком поздно;
- два этапа одного заказа занимают разные минуты;
- отрицательные нижние границы нужно заменить нулём;
- минимизируется число занятых минут, а не промежуток от первой до последней;
- жадное заполнение старых минут может помешать лучшему переназначению.

Полный перебор с проверкой потоком подтверждает оптимум на 408 малых
тестах, а 19 каверзных расписаний проверяют проверяющую программу.

## Особенности языков

Во всех версиях пара `(i, j)` кодируется как `i·(n+1)+j`,
а переходы перебирают только активные состояния слоя. Слои времён
и предков сохраняются для восстановления.

Python хранит оба вида слоёв в массивах коротких знаковых чисел
`array("h")`: код состояния не больше `51²−1 = 2600`, а маркер
бесконечности по времени не больше 1001, поэтому все сохраняемые
значения, включая −1, помещаются. Компилируемые версии используют
обычные целочисленные массивы или векторы; Java читает данные через
`StreamTokenizer` с буферизацией.
