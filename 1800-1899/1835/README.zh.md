# 1835. 沼泽医生

[Timus 1835](https://acm.timus.ru/problem.aspx?space=1&num=1835) · 难度 3124 · strings

原题作者 Alexey Samsonov（由 Dmitry Ivankov 和 Ivan Burmistrov 准备），出自 2011 年 4 月第十五届乌拉尔竞技编程公开锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

地址由用户名和域名以 "@" 连接而成，两者都是由小写字母和点组成的非空字符串，不以点开头或结尾，也不含两个连续的点。统计文本中作为子串出现的不同地址的个数。

## 输入

文本，至多 10⁶ 字节，由编码 32 到 126 的字符和换行组成。

## 输出

文本中不同地址的个数。

## 样例

### 样例 1

输入：

```
a.b@c.d
b@c.de.
@qq
q@.q
```

输出：

```
5
```

## 解法

一个字符串是否是地址只取决于字符串本身，而与它出现的位置无关。所以经典的不同子串计数方法加上一个过滤条件即可：建立后缀数组，以及每个后缀与排序后前一个后缀的 LCP。
一个后缀的前缀在这个顺序中更早出现，当且仅当它不长于这个 LCP；所以只统计长于 LCP 的地址前缀，每个不同的地址恰好在以它开头的第一个后缀处计数一次。

对以字母开头的后缀，其地址前缀由它之后、在同一段字母和点中的第一个 "@" 决定。用户名不能越过最后一个 ".." 向左延伸，"@" 两侧必须是字母，域名在下一个 ".."、"@" 或其他字符之前的某个字母处结束。
这些都对每个 "@" 预先算好，所以每个后缀只需用前缀和加上一段区间内的字母个数。

后缀数组用循环倍增加计数排序构建，字母表共 30 个符号，其他所有字符共用一个编码；LCP 用 Kasai 算法求出。`O(n log n)`。

在样例中，地址是 a.b@c、a.b@c.d、b@c、b@c.d 和 b@c.de；b@c 和 b@c.d 各出现两次，但只计一次。

注意事项：

- 同一个地址可能出现多次，所以按出现次数计数会多算；
- "a..b@c" 仍然包含地址 b@c，但不包含 a..b@c 和 .b@c；
- 两段各 5·10⁵ 个字母之间的一个 "@" 会产生约 2.5·10¹¹ 个地址，需要 64 位整数；
- 对 10⁶ 个字符建后缀数组，CPython 太慢；Python 版本在 PyPy 上运行，并使用紧凑的数组。

答案在数百个短随机文本上与逐个检查所有子串的结果一致，并在一兆字节的文本上与一个独立的已通过实现一致。
