# 1889. Объявление в аэропорту

[Timus 1889](https://acm.timus.ru/problem.aspx?space=1&num=1889) · сложность 308 · bruteforce

Автор оригинальной задачи — Денис Дублённых; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Игорь услышал n фраз объявления и знает язык некоторых из них;
остальные — «unknown». Объявление прочитали на нескольких языках, на
каждом не больше одного раза и с одинаковым числом фраз. На скольких
языках его могли прочитать? Перечислите все варианты по возрастанию
или выведите «Igor is wrong.», если вариантов нет.

## Входные данные

n (2 ≤ n ≤ 1000), затем n строк с названием языка (от 4 до 20 строчных
букв) или «unknown»; хотя бы одна фраза известна.

## Выходные данные

Все возможные числа языков по возрастанию или «Igor is wrong.».

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
6
english
unknown
unknown
unknown
german
unknown
```

Вывод:

```
2 3 6
```

### Пример 2

Ввод:

```
4
english
french
unknown
english
```

Вывод:

```
Igor is wrong.
```

### Пример 3

Ввод:

```
3
zulu
zulu
zulu
```

Вывод:

```
1
```

## Решение

Если объявление прочитано на k языках, то k делит n, и фразы
разбиваются на k подряд идущих блоков по n/k, по блоку на язык. Для
каждого делителя k проверяем две вещи. Известные фразы блока должны
быть на одном языке. Ни один язык не может встретиться в двух разных
блоках. Блоки без известных фраз могут быть на любом новом языке.
С хеш-множествами ожидаемое время — `O(n·d(n))`, с упорядоченным
множеством в C++ — `O(n·d(n)·log n)`.

В первом примере один блок содержал бы и английский, и немецкий, так
что 1 не подходит. Для 2 блоки — «english ? ?» и «? german ?», для 3 —
пары, где английский в первой, а немецкий в третьей, а 6 здесь всегда
возможно: ответ 2 3 6.

Подводные камни:

- один и тот же язык в двух блоках запрещает k, как в третьем примере
  для 3 языков;
- блок из одних неизвестных фраз допустим;
- строка вывода — «Igor is wrong.» с точкой.

Ответы совпадают с независимой принятой реализацией на 125 случайных
объявлениях.

## Оптимизированные решения

`1889_bruteforce_optimized.java`. По-прежнему проверяются лишь делители k числа n и согласованность каждого блока. Известным языкам один раз присваиваются положительные целые ID, ноль означает unknown. Массив меток поколений не допускает один известный язык в двух блоках, заменяя новый HashSet и повторные сравнения строк для каждого делителя. Внутри блока остаётся не более одного известного ID; неизвестным блокам можно назначить различные неиспользованные языки. k перебираются по возрастанию, фраза ошибки сохранена точно. При tau(n) делителях и длине имени до20 ожидаемое время O(n·tau(n)), память O(n); хеширование имеет ожидаемую, не гарантированную худшую стоимость. Это тот же перебор с компактными данными и буфером256байт.

По сравнению с `1889_bruteforce.java`: время 0.125 s → 0.109 s; память 684 KB → 708 KB.

Go объединяет известные фразы в последовательные группы языков, сохраняя имя и номера первой и последней фразы. Таблица с открытой адресацией отклоняет язык, который повторяется после другого известного языка. Для каждого делителя n проверяется, что группа лежит в одном блоке, а разные группы занимают разные блоки. Здесь d(n) — число делителей n. Коллизии хеша могут дать квадратичное время построения групп в худшем случае. Для ввода-вывода служат фиксированные байтовые буферы; имена точно сравниваются в 20-байтовых массивах даже при коллизиях хеша.

Принятые базовые реализации [1889_bruteforce.cpp](1889_bruteforce.cpp), [1889_bruteforce.java](1889_bruteforce.java), [1889_bruteforce.py](1889_bruteforce.py), [1889_bruteforce.rs](1889_bruteforce.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1889_trees_parsing_optimized.rs`. Имена языков нумеруются точным упорядоченным деревом вместо случайного хеширования; перебор делителей и проверки блоков по эпохам сохранены.

Accepted #11329230 (Rust 1.75 x64): **0.015 s / 136 KB**. Архивное сравнение: `1889_bruteforce.rs` (Rust 1.75 x64) — 0.046 s / 448 KB (#11325666).

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`1889_bruteforce_optimized.java`: место по времени 6/22, по памяти 1/22 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
