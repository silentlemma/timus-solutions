# 1848. 打苍蝇

[Timus 1848](https://acm.timus.ru/problem.aspx?space=1&num=1848) · 难度 4255 · geometry

原题作者 Denis Dublennykh，出自 2010 年 8 月彼得罗扎沃茨克夏季集训的 Ural SU Contest。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

n 只苍蝇停在墙上互不相同的点。m 个朋友用苍蝇拍拍墙，留下的痕迹是互无公共点的简单多边形。苍蝇若在痕迹内部或边界上就被打死。统计每个苍蝇拍打死的苍蝇数。

## 输入

n（1 ≤ n ≤ 10⁵）和苍蝇的坐标，然后是 m（1 ≤ m ≤ 30 000）和各个痕迹，每个痕迹给出顶点数和按逆时针顺序排列的顶点。顶点总数不超过 10⁵，所有坐标都是绝对值不超过 10⁷ 的整数。

## 输出

按输入顺序输出每个苍蝇拍打死的苍蝇数。

## 样例

### 样例 1

输入：

```
3
0 0
1 1
4 4
3
3 -2 -2 -3 -3 -2 -3
3 0 0 2 0 1 1
3 3 0 5 0 4 6
```

输出：

```
0
2
1
```

## 解法

痕迹互不相交，所以没有一个在另一个内部；不在任何边界上的苍蝇位于某个痕迹内部，当且仅当它正上方最近的边是这个痕迹的边，并且内部在这条边的下方。逆时针多边形的内部在每条边的左侧，所以从右向左走的边，其内部在下方。

在 C++、Go、Java 和 Rust 中，一条竖直扫描线从左向右移动，按从下到上的顺序保存与它相交的边。为了避开顶点，在 x 处的苍蝇按 x 稍右一点的位置来查询：从 x₁ 到 x₂（x₁ < x₂）的边在 x₁ ≤ x < x₂ 时有效，并且在每一列中先移除结束的边，再加入开始的边。
停在顶点上的苍蝇也算在内部，所以顶点存放在映射中；竖直的边不进入扫描，按 x 存为排好序的区间。其他位于边界上的苍蝇都落在某条有效边上。

边互不相交，所以两条有效边只需一次方向测试就能排序：取左端点更靠右的那条，用这个端点对另一条边所在直线做测试；若端点恰在直线上，说明两条边从同一个痕迹的公共顶点出发，此时由另一个端点决定。
苍蝇按长度为零的边以同样方式比较。方向测试中各乘积的绝对值不超过 4·10¹⁴。第一条不在苍蝇下方的有效边，要么经过苍蝇，要么是它上方最近的边。
这些边在 C++、Java 和 Rust 中存放在平衡搜索树中，在 Go 中存放在 treap 中：对 V 个顶点，复杂度为 `O((n + V) log(n + V))`（Go 为期望复杂度）。Python 在 PyPy 上按 (x, y) 顺序扫描，包含竖直边和顶点，使用有序桶：桶大小固定时，最坏复杂度为 `O(n log(n + V) + V²)`。Python 版本把边和坐标存放在扁平整数数组中，在评测上占用 25 MB；使用元组和字典的早期版本在评测的第 11 个测试上占用 70 MB。

在样例中，苍蝇 (0, 0) 和 (1, 1) 是第二个三角形的顶点。在 x = 4 稍右处，(4, 4) 上方最近的边是第三个三角形从 (5, 0) 到 (4, 6) 的边，它从右向左走，所以这只苍蝇也在内部。

注意事项：

- 与顶点在同一竖线上的苍蝇：在 x 稍右处查询，避免了尖角两条边之间的平局；
- C++、Go、Java 和 Rust 要在扫描之外单独检查竖直边和顶点；
- 若边从上往下给出，可能迫使插入发生在最底部，普通的有序列表会因此花费平方时间。

在最多 30 000 个痕迹的随机墙面上，苍蝇位于网格、顶点和边上，计数结果与逐个检查每只苍蝇与附近痕迹的直接方法一致，也与一个独立的已通过实现一致。
