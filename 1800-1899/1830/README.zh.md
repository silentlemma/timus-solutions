# 1830. NatOS 的帮助系统

[Timus 1830](https://acm.timus.ru/problem.aspx?space=1&num=1830) · 难度 951 · math

原题作者 Evgeny Kurpilyansky（创意来自 Stanislav Vasiliev），出自 2011 年 4 月第十五届乌拉尔竞技编程公开锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

帮助系统有页面 1, …, n。F1 打开或关闭页面 1。除最后一页外，每页都有打开或关闭下一页的按钮，但只有最不详细的打开页面（编号最小的那页）可见可用。
求把一组打开的页面变成另一组所需的最少按键次数。

## 输入

n（1 ≤ n ≤ 50），然后是初始和目标集合，各为 n 个 0 和 1 组成的字符串，第 i 个字符表示页面 i 是否打开。

## 输出

最少的按键次数。

## 样例

### 样例 1

输入：

```
3
111
000
```

输出：

```
5
```

## 解法

这就是九连环。任何状态下至多有两种走法：切换页面 1，或者切换第一个打开页面之后紧挨着的那一页。把页面 i 看作一个二进制字的第 i − 1 位。
这正是反射格雷码的两种步：每隔一步翻转第 0 位，否则翻转最低的 1 位之上紧邻的那一位。
因此全部 2ⁿ 个状态按格雷码顺序排在一条路径上，一个状态在路径上的位置就是它的字按格雷码解码的结果：该字与它所有右移结果的异或。答案是两个位置之差的绝对值。`O(n)`。

在样例中 111 是字 7，它的位置为 7 xor 3 xor 1 = 5，而 000 位于 0：五次按键。

注意事项：

- 第一个字符是页面 1，即最低位，所以字符串要倒着读；
- 答案可达 2⁵⁰ − 1，需要 64 位整数；
- 在 2⁵⁰ 个状态上做广度优先搜索毫无希望。

答案在 n 不超过 9 时与广度优先搜索一致，并在至多 50 页的随机数据上与一个独立的已通过实现一致。
