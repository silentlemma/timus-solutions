## Задача

Пусть F₀ = F₁ = 1 и Fᵢ = i·Fᵢ₋₁·Fᵢ₋₂. Найти число делителей Fₙ по
модулю 10⁹ + 7.

## Входные данные

n (1 ≤ n ≤ 10⁶).

## Выходные данные

Число делителей Fₙ по модулю 10⁹ + 7.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
3
```

Вывод:

```
4
```

## Решение

Каждый шаг один раз домножает на i и повторяет два предыдущих
произведения, так что множитель k входит в Fₙ ровно fib(n − k + 1) раз,
где fib(1) = fib(2) = 1: один раз в F_k, один раз в F_{k+1}, дважды в
F_{k+2} и далее по правилу Фибоначчи. Значит, Fₙ = Π k^fib(n−k+1) по
k = 1 … n.

Число делителей равно Π (e_p + 1) по простым p, где e_p — показатель p
в Fₙ. Число k вносит v_p(k), умноженное на свой вес fib(n − k + 1), а
v_p(k) считает, сколько из p, p², p³, … делят k, так что e_p — сумма
весов всех кратных p, p² и так далее. Важен только e_p по модулю
10⁹ + 7, поэтому веса тоже хранятся по модулю. Обход кратных каждой
степени простого занимает около n·ln ln n шагов; решение на Python
суммирует каждую прогрессию одним срезом. `O(n log log n)`.

В примере F₃ = 3·F₂·F₁ = 3·2·1 = 6, у которого делители 1, 2, 3 и 6.

Подводные камни:

- показатели огромны, но ответу они нужны только по модулю 10⁹ + 7;
- степень простого, перешедшая n, должна остановить цикл до
  переполнения;
- решение на Python работает на PyPy.

Ответы совпадают с прямым разложением Fₙ при n до 14 и с независимой
принятой реализацией до 10⁶.

## Оптимизированные решения

`1860_number_theory_optimized.java`. Сохраняется формула числа делителей по показателям простых modulo10^9+7. Остатки Фибоначчи хранятся в int[] вместо long[]: даже сумма двух остатков до сокращения меньше2^31. Вес берётся как fib[n-multiple+1], отдельная копия long[] weight исключена. Суммы показателей и произведения ответа остаются long, показатели сокращаются после прохода очередной степени простого. Решето и вклады степеней прежние. Время O(n log log n), память O(n) с меньшим числом байт на индекс. На входе один байтовый числовой токен, n=1 по-прежнему даёт один делитель.

По сравнению с `1860_number_theory.java`: время 0.187 s → 0.125 s; память 18 412 KB → 8 368 KB.

Новые C++, Go и Rust сохраняют сумму по степеням простых, но хранят только один массив Фибоначчи uint32: вес k берётся как fib[n−k+1], без второго 64-битного массива. Сумма двух остатков меньше 2·MOD, поэтому достаточно условного вычитания. Битовое сито нечётных занимает около n/16 байтов, простое2 обработано отдельно. Для одного простого суммируется до n весов, сумма uint64 меньше n·MOD≤10¹⁵; модуль берётся один раз. Модульное произведение тоже помещается в uint64. Перед умножением степени проверяем power>n/p. Время O(n log log n), память O(n): около4n байтов весов вместо двух массивов по8n. Базы сохранены; Java/Python используют подходящие базы.

Принятые базовые реализации [1860_number_theory.java](1860_number_theory.java), [1860_number_theory.py](1860_number_theory.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`1860_number_theory_optimized.java`: место по времени 3/16, по памяти 5/16 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
