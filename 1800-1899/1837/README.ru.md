# 1837. Число Исенбаева

[Timus 1837](https://acm.timus.ru/problem.aspx?space=1&num=1837) · сложность 60 · bfs

Оригинальная задача — фольклор; XV открытый чемпионат Урала по спортивному программированию, апрель 2011 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Число Исенбаева равно 0 у самого Владислава Исенбаева, 1 у
однокомандников Исенбаева, 2 у их однокомандников, не игравших с
Исенбаевым, и так далее. По составам команд вывести число каждого
участника или «undefined», если цепочки команд до Исенбаева нет.

## Входные данные

n (1 ≤ n ≤ 100), затем n команд по три фамилии (заглавная буква, затем
строчные, не длиннее 20 букв). Фамилия Исенбаева — «Isenbaev».

## Выходные данные

Каждый участник со своим числом, по алфавиту фамилий.

## Примеры

### Пример 1

Ввод:

```
7
Isenbaev Oparin Toropov
Ayzenshteyn Oparin Samsonov
Ayzenshteyn Chevdar Samsonov
Fominykh Isenbaev Oparin
Dublennykh Fominykh Ivankov
Burmistrov Dublennykh Kurpilyanskiy
Cormen Leiserson Rivest
```

Вывод:

```
Ayzenshteyn 2
Burmistrov 3
Chevdar 3
Cormen undefined
Dublennykh 2
Fominykh 1
Isenbaev 0
Ivankov 2
Kurpilyanskiy 3
Leiserson undefined
Oparin 1
Rivest undefined
Samsonov 2
Toropov 1
```

## Решение

Соединим в графе каждых двух членов одной команды. Число — это
расстояние от Исенбаева, найденное поиском в ширину; не достигнутые им
участники получают undefined. Выводим фамилии в отсортированном
порядке. При не более чем 300 участниках подойдёт любой способ.
`O(n log n)` на сортировку.

В примере Oparin играл с Исенбаевым (1), Ayzenshteyn — с Oparin (2),
Chevdar — с Ayzenshteyn (3), а команда Cormen отрезана.

Подводные камни:

- Исенбаева может не быть во входных данных; тогда у всех undefined;
- одна и та же команда может встретиться дважды;
- фамилии сравниваются как обычные строки, все начинаются с заглавной.

## Оптимизированные решения

Оптимизированные решения на C++, Java и Rust выполняют тот же поиск в
ширину, но по номерам, а не по именам. Каждое имя получает номер при
первой встрече; номера хранятся в упорядоченном словаре, чтобы вывод
оставался отсортированным, а товарищи по командам и расстояния — это
обычные массивы с этими номерами в качестве индексов; очередь тоже
массив. C++ читает имена через `scanf` в буфер на 21 байт, Java читает
их побайтно и хранит товарищей связными списками в массивах `int`, а
Rust печатает через `BufWriter`. C++ занимает 252 КБ вместо 552 КБ при
том же времени; Rust — 264 КБ вместо 468 КБ при том же времени; Java —
0.109 с вместо 0.171 с и 656 КБ вместо 4192 КБ.

Оптимизированное решение на Go читает имена сканером слов с буфером на
1 КБ вместо `fmt.Fscan` и нумерует их в хеш-таблице, поэтому граф хранит
`int`, а не строки, а перед выводом сортирует имена: 964 КБ вместо
1420 КБ при том же времени.
