# 1897. Алиса и Боб и строка

[Timus 1897](https://acm.timus.ru/problem.aspx?space=1&num=1897) · сложность 5381 · suffix_structures

Автор оригинальной задачи — Александр Кульков; Петрозаводск, лето 2018, Moscow IPT Contest.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Позиция игры — подстрока t фиксированной строки s, возможно пустая.
За ход к t приписывают по одной строчной букве слева и справа так,
чтобы результат оставался подстрокой s. Невозможность хода означает
поражение; оба участника выбирают оптимально.

Найдите k-ю лексикографически строку среди различных начальных позиций,
выигрышных для делающего ход. Пустая строка идёт первой, а собственный
префикс — раньше продолжений. Разные вхождения одной подстроки
считаются одним вариантом. Ограничения: 1 секунда и 256 МБ.

## Входные данные

Первая строка содержит s из строчных английских букв:
1 ≤ |s| ≤ 100 000. Вторая содержит k: 1 ≤ k ≤ 10¹⁰.

## Выходные данные

Выведите искомую строку либо `no solution`, если выигрышных вариантов
меньше k. Пустую строку обозначьте `-`.

## Проверка

Ответы сравниваются по последовательностям токенов.

## Примеры

### Пример 1

Ввод:

## Решение

### Сжать игру по центрам

Ход добавляет две буквы, сохраняя центр вхождения и чётность длины.
Для чётного вхождения c — промежуток перед позицией c, для нечётного —
позиция центральной буквы. При чётности e, равной 0 или 1, и радиусе d
подстрока начинается в c − d и имеет длину 2d + e.

Для каждого центра читаем пары букв изнутри наружу и строим бор этих
последовательностей. Один корень задаёт пустую строку, нечётные корни
группируются по центральной букве. Совпадающие префиксы задают одинаковые
подстроки, а ход игры — один шаг бора. Отмечаем терминал там, где
очередной центр достигает границы исходной строки.

Сжимаем пути, оставляя корни, ветвления и все терминалы, даже с одним
ребёнком. Таких узлов `O(n)`, поскольку последовательностей центров
тоже `O(n)`. Терминальное вхождение не даёт дополнительного хода
и не требует остановиться: другие вхождения ещё могут продолжаться.
Отметки сохраняют места изменения множества вхождений.

Для быстрого построения подготовим суффиксные массивы и запросы
минимума LCP для s и обратной строки. Общий префикс двух центральных
последовательностей равен минимуму совпадений слева наружу и справа
наружу, ограниченному доступными радиусами. При необходимости
сравниваем следующие пары букв. Так центры сортируются с константным
сравнением, а сжатый бор строится по LCP соседей стеком глубин.

### Вычислить исходы рёбер

Позиция выигрышна, если из неё есть ход в проигрышную. Пусть ребро
идёт от радиуса L до R, а исход ребёнка равен W(R). Внутри ребра
есть единственное продолжение, поэтому
W(d) = W(R) XOR ((R − d) mod 2) при L < d ≤ R. Явные узлы вычисляем
снизу вверх по первым позициям исходящих рёбер.

### Назначить каждой строке суффикс

Назначим подстроку тому вхождению, у которого суффикс начала имеет
минимальный ранг суффиксного массива. В порядке массива эти владельцы
дают обычные блоки новых префиксов: длины больше LCP с предыдущим
суффиксом. Внутри блока возрастание длины совпадает с лексикографическим
порядком.

Внутри сжатого ребра множество центров не меняется. Каждый шаг
приписывает всем вхождениям одинаковую букву слева и сохраняет порядок
их суффиксов. Поэтому один центр-представитель c владеет всем ребром.
Представителей находим снизу вверх: на радиусе узла сравниваем его
терминальные центры с представителями дочерних групп.

Ребро L < d ≤ R даёт начала p = c − d на отрезке
[c − R, c − L − 1]. Исход чередуется с радиусом, поэтому выигрышные
строки прибавляют по 1 к каждому второму началу этого отрезка.
Используем отдельные разностные массивы для чётных и нечётных позиций.
Выигрышный нечётный корень добавляет свою односимвольную строку
в позицию представителя. Пустой корень учитываем отдельно.

Префиксные суммы дают число выигрышных строк каждого суффикса.
Идём по суффиксному массиву и находим блок с позицией k. Для выбранного
начала p ещё раз просматриваем рёбра: каждое даёт не больше одного
радиуса d = c − p и длины 2d + e. Оставляем выигрышные варианты,
добавляем подходящую односимвольную позицию, сортируем длины и выбираем
оставшийся номер.

Каждая различная подстрока имеет ровно одну позицию бора и одного
владельца-суффикс. Чётность ребра даёт её исход, прибавления учитывают
её один раз, а порядок владельцев и длин — лексикографический.
Поэтому выбранная строка имеет нужный номер.

Удвоение суффиксного массива с сортировкой подсчётом, подготовка LCP
и сортировка центральных путей занимают `O(n log n)`. Сжатая игра
и подсчёт владельцев линейны; сортировка длин выбранного владельца
требует не больше `O(n log n)`. Итоговое время и память разреженных
таблиц — `O(n log n)`.

В первом примере выигрывают пустая строка, `a`, `b` и `ba`, третья —
`b`. Во втором пустая позиция может перейти в терминальную `rn`
и потому выигрышна. В третьем выигрывают только пустая строка и `b`,
то есть вариантов меньше десяти.

Подводные камни:

- один ход увеличивает радиус на 1, а длину на 2;
- при сжатии сохранять все терминалы, даже с одним ребёнком;
- граничное вхождение не запрещает продолжения остальных;
- владелец выбирается по рангу суффикса, а не по позиции в тексте;
- считать строки, а не вхождения, используя 64-битные счётчики;
- выигрышная пустая строка идёт раньше всех непустых.

## Особенности языков

Короткие центральные префиксы упакованы в целые ключи, чтобы сократить
сравнения. C++, Go, Java и Rust хранят таблицы LCP в массивах
примитивных типов.

Решение на Python работает на PyPy и идёт другим путём — через
суффиксный автомат обратной строки s, обращённые суффиксные ссылки которого
образуют суффиксное дерево исходной s и дают лексикографический порядок. Строка,
встречающаяся один раз, может расти, только пока её вхождение не упрётся
в ближний конец s, так что её исход определяется чётностью; для
повторяющихся строк исходы длин каждого состояния автомата хранятся в
битсетах суммарно линейного размера, с общими сериями для сильно
повторяющихся строк. Затем выигрышные строки подсчитываются вниз по
суффиксному дереву, чтобы найти k-ю. У судьи решение тратит 0,69 с из
1 с; прежние версии, с деревьями центров и затем с первым автоматом,
превышали лимит времени на тестах 73 и 107 жюри.

Ответы совпадают с полным перебором игры на 25 534 запросах рангов.
