# 1890. Деньги из воздуха

[Timus 1890](https://acm.timus.ru/problem.aspx?space=1&num=1890) · сложность 464 · fenwick

Автор оригинальной задачи — Дмитрий Иванков; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано корневое дерево из n сотрудников с номерами от 0 до n − 1;
корень имеет номер 0. В каждой вершине задана целая неотрицательная
зарплата. Последовательно выполните q условных обновлений:

- `employee x y z`: если текущая зарплата в вершине x строго меньше y,
  увеличить её на z;
- `department x y z`: если текущая средняя зарплата в поддереве x
  строго меньше y, увеличить на z каждую зарплату этого поддерева,
  включая вершину x.

Найдите все итоговые зарплаты. Дерево не меняется. Ограничения:
1 секунда и 64 МБ.

## Входные данные

Первая строка содержит n, q и начальную зарплату s₀ корня:
1 ≤ n, q ≤ 50 000; 0 ≤ s₀ ≤ 10⁹.

Для каждого i от 1 до n − 1 следующая строка задаёт родителя pᵢ
и начальную зарплату sᵢ: 0 ≤ pᵢ < i; 0 ≤ sᵢ ≤ 10⁹.

Следующие q строк содержат обновления в указанном выше формате,
где 0 ≤ x < n и 1 ≤ y, z ≤ 10⁹.

## Выходные данные

Выведите n итоговых зарплат, каждую с новой строки, по возрастанию
номеров вершин.

## Проверка

Ответы сравниваются по последовательностям целочисленных токенов.

## Примеры

### Пример 1

Ввод:

```
4 3 1
0 10
0 10
1 10
employee 2 15 1
employee 3 5 1
department 0 10 1
```

Вывод:

```
2
11
12
11
```

## Решение

Расположим вершины в порядке обхода в глубину, записывая вершину до
её потомков. Пусть tin[x] — позиция вершины x, а size[x] — размер её
поддерева. Всё поддерево занимает ровно отрезок
[tin[x], tin[x] + size[x]).

Номер родителя меньше номеров потомков, поэтому размеры поддеревьев
можно найти, прибавляя их родителям по убыванию номеров вершин.
Затем переберём вершины по возрастанию номеров. Родитель выделяет
ребёнку x очередной блок длины size[x] после своей позиции и блоков,
уже выделенных предыдущим детям. Так позиции обхода строятся за
`O(n)` без рекурсии.

Храним зарплаты в этом порядке в двух деревьях Фенвика, позволяющих
прибавлять число на отрезке и находить сумму на отрезке. Для этого
обозначим через dᵢ разность соседних зарплат, с индексацией от 1;
d₁ равно первой зарплате. Первое дерево хранит dᵢ, второе —
(i − 1)dᵢ. Если их префиксные суммы
до k равны B₁(k) и B₂(k), то сумма первых k зарплат равна
k·B₁(k) − B₂(k). Прибавление z на отрезке меняет только две граничные
разности, поэтому в каждом дереве нужны лишь два точечных обновления.
Сумма на отрезке получается разностью двух префиксных сумм.

Для `employee` запрашиваем одноэлементный отрезок вершины x. Для
`department` запрашиваем всё поддерево; пусть его сумма равна S.
Среднюю сравниваем точно: S < y·size[x]. Деление и вещественные числа
не нужны. Если соответствующее строгое неравенство выполнено,
прибавляем z на том же отрезке; иначе ничего не меняем.

Отрезки обхода выбирают в точности нужных сотрудников. Формула для
деревьев Фенвика возвращает текущую сумму после всех предыдущих
обновлений, поэтому и проверка условия, и прибавление соответствуют
операции. В конце обратим построение первого дерева Фенвика:
по убыванию индексов вычтем каждый элемент из его родителя в дереве
Фенвика. После этого элементы содержат текущие разности dᵢ.
Префиксные суммы восстанавливают все зарплаты за линейное время;
выводим их в порядке исходных номеров вершин.

Каждый запрос или прибавление занимает `O(log n)`. Начальные деревья
Фенвика строятся передачей каждого элемента своему родителю по
возрастанию индексов. Построение и восстановление ответа линейны,
поэтому время составляет `O(n + q log n)`, память деревьев — `O(n)`.

В примере зарплата сотрудника 2 меняется с 10 на 11. У сотрудника 3
остаётся 10, поскольку 10 не меньше 5. Теперь сумма всего дерева
равна 32, а среднее — 8, что меньше 10. Последнее обновление
прибавляет 1 ко всем зарплатам: получаются 2, 11, 12 и 11.

Подводные камни:

- равенство порогу не приводит к обновлению;
- поддерево включает корень и всех потомков;
- номера вершин одного поддерева не обязаны идти подряд;
- для зарплат, сумм, взвешенных разностей и произведений вроде
  y·size[x] нужны знаковые 64-битные числа; целые Python уже подходят;
- выводить нужно по номерам вершин, а не по позициям обхода.

## Особенности языков

Используйте буферизованный ввод и вывод. В языках с фиксированными
типами элементы деревьев Фенвика должны быть 64-битными;
для индексов достаточно обычных целых чисел.

Ответы совпадают с переборной симуляцией на 160 малых случайных тестах и
с независимой принятой реализацией на 37 сгенерированных.
