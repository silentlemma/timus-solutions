# 1869. Новогодний круиз

[Timus 1869](https://acm.timus.ru/problem.aspx?space=1&num=1869) · сложность 239 · prefix_sums, simulation

Автор оригинальной задачи — Денис Дублённых; Открытый командный чемпионат УрФУ по программированию, 2011 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Поезд идёт из Владивостока (станция 1) в Москву (станция n) с
остановками на станциях 1, …, n и затем тем же путём обратно. aᵢⱼ
человек купили билеты от станции i до станции j: при i < j они едут
поездом туда, при i > j — обратно. В каждом вагоне 36 мест. Сколько
вагонов нужно, чтобы всем хватило мест?

## Входные данные

n (2 ≤ n ≤ 100), затем матрица n × n из aᵢⱼ (0 ≤ aᵢⱼ ≤ 1000, aᵢᵢ = 0).

## Выходные данные

Наименьшее число вагонов.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Примеры

### Пример 1

Ввод:

```
3
0 180 180
0 0 180
360 0 0
```

Вывод:

```
10
```

## Решение

Поезд должен вмещать наибольшее число людей, едущих одновременно, на
любом перегоне в любую сторону. Для каждого направления прибавим aᵢⱼ
на станции с меньшим номером и вычтем на станции с большим. Накопленная
сумма этих изменений по порядку станций — загрузка каждого перегона. Ответ
— наибольшая загрузка, делённая на 36 с округлением вверх. `O(n²)`.

В примере поездом туда на обоих перегонах едут 360 человек (180 от
станции 1 до 3 вместе со 180 от 1 до 2 или от 2 до 3), и 360 едут
обратно всю дорогу: 10 вагонов.

Подводные камни:

- два направления — разные рейсы, их загрузки складывать нельзя;
- деление округляется вверх: 37 людям нужны два вагона;
- если билетов нет совсем, ответ 0.

Ответы совпадают с независимой принятой реализацией на 150 случайных
матрицах.

## Оптимизированные решения

Пять прямых симуляций прибавляют каждый билет ко всем пересекаемым перегонам за O(N³) времени и O(N) памяти. Они служат учебными базами наряду с исходными матричными решениями. Оптимизированный Python читает по строке на станцию. Суммы правых суффиксов дают вклад в перегоны прямого направления, а суммы левых префиксов дают вклад в обратное. Каждый вектор упакован в целое с 32-битными полями. Сдвиг на одно поле и деление на 2^32−1 образуют суффиксные суммы, а умножение на число из единиц в этой системе счисления с усечением даёт префиксные суммы. Значение поля не превышает 1000N², поэтому переносов между полями нет. Ответ равен наибольшей загрузке в обоих направлениях, делённой на 36 с округлением вверх. Время O(N²), рабочая память O(N). Версия ускорилась и использует больше памяти, чем прямая симуляция.

- `1869_prefix_sums_optimized.py`: 0.062 s / 468 KB; база `1869_simulation.py`: 0.093 s / 396 KB; изменение относительно базы: время -33.3%, память +18.2%.
