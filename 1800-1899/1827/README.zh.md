# 1827. 土著战争

[Timus 1827](https://acm.timus.ru/problem.aspx?space=1&num=1827) · 难度 1191 · hashing

原题作者 Dmitry Ivankov，出自 2011 年 3 月 19 日第十二届乌拉尔国立大学公开个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

土著用夜空中的星星数来区分日子。他们的书把每场战争记为 x（第一天的星星数）、y（最后一天的星星数）和 d（持续天数）。
已知最近 n 天中每天（i 天前）看到的星星数，标出所有可能有某场记录的战争正在进行的日子。

## 输入

n（2 ≤ n ≤ 10⁵），然后是 a₁, …, aₙ，其中 aᵢ 是 i 天前的星星数（0 ≤ aᵢ ≤ 2·10⁸），然后是 m（1 ≤ m ≤ 10⁵）和 m 行 x, y, d（0 ≤ x, y ≤ 2·10⁸，2 ≤ d ≤ 50）。

## 输出

由 n 个数字组成的字符串：若 i 天前可能在打仗，第 i 位为 1，否则为 0。

## 样例

### 样例 1

输入：

```
6
6 5 4 3 2 1
3
2 4 3
4 5 2
1 6 5
```

输出：

```
011110
```

## 解法

在 k 天前结束、持续 d 天的战争开始于 k + d − 1 天前，因此它恰好在位置 k + d − 1 的 a 等于 x 且位置 k 的 a 等于 y 时成立。
长度不超过 50，所以对书中出现的每个长度 d，把这些战争的 (x, y) 放进哈希集合，再扫过所有 k，查询 (k + d − 1 处的 a, k 处的 a)。
每次命中覆盖第 k … k + d − 1 天：对每个 k 记录在该处结束的战争覆盖到的最早一天，再扫一遍，把位于当前最大值以内的日子都标出。
总共至多 49·n 次查询，`O(50·n + m)`。

Python 用对两个错开的列表做 `map`，一次完成同一长度的所有查询，把命中打包成大整数位掩码，再用 O(log d) 次移位和按位或把它扩展到 d 天。

在样例中，战争 (2, 4, 3) 对应 5 到 3 天前，(4, 5, 2) 对应 3 到 2 天前，而 (1, 6, 5) 需要 2 天前有 6 颗星星。

注意事项：

- 战争的第一天离现在更远，所以 x 要与更大的“天前”数匹配；
- 若所有数都相同，每场战争处处匹配，因此按第一天的星星数逐个位置查找战争是平方级的；
- 一场战争可能比整个记录还长。

在数百个随机记录和全规模测试上，答案都与一个独立的已通过实现一致。
