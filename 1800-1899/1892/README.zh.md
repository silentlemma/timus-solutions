# 1892. 科利佐沃的早晨

[Timus 1892](https://acm.timus.ru/problem.aspx?space=1&num=1892) · 难度 885 · simulation

原题作者 Denis Dublennykh，出自 NEERC 2011 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

为同一条跑道上的起飞和降落两个先进先出队列安排时间。每架飞机加入
相应队列的时刻已知，并在获得许可后立即开始操作。安全间隔从操作
开始时刻计算：

| 较早的操作开始 | 较晚的操作开始 | 最小间隔 |
| --- | --- | --- |
| 起飞 | 起飞 | t₁ |
| 起飞 | 降落 | t₂ |
| 降落 | 起飞 | t₃ |
| 降落 | 降落 | t₄ |

只要还有飞机排队等待降落，就不能起飞，即使该降落还在等待安全间隔。
如果一架飞机恰在可以起飞的时刻加入降落队列，也应优先降落。
求每次操作的开始时刻。

时间限制为 1 秒，内存限制为 64 MB。

## 输入

第一行是以秒计的 t₁、t₂、t₃、t₄，满足 30 ≤ tᵢ ≤ 500，
max(t₁, t₄) ≤ min(t₂, t₃)。

接着给出起飞数量 n，1 ≤ n ≤ 50，以及 n 个加入起飞队列的时刻。
然后给出降落数量 m，1 ≤ m ≤ 50，以及 m 个加入降落队列的时刻。

所有时刻采用 `hh:mm:ss` 格式，范围为 `06:00:00` 到 `10:00:00`，
包含端点。每个列表内严格递增，不同列表中的时刻可以相同。

## 输出

先输出 n 个起飞开始时刻，再输出 m 个降落开始时刻，各组内保持输入
顺序。采用 `hh:mm:ss` 格式，每个字段两位数字。开始时刻可以晚于
`10:00:00`。

## 评测方式

输出按记号逐一比较。

## 样例

### 样例 1

输入：

```
60 60 60 60
2
07:01:00
07:01:30
2
07:00:00
07:02:10
```

输出：

```
07:01:00
07:02:00
07:00:00
07:03:00
```

## 解法

把时刻转换成秒。用两个指针分别指向两个队列中第一架尚未处理的飞机，
并保存最近一次起飞的开始时刻 D 和降落的开始时刻 A。如果某类操作
尚未发生，则不考虑该类操作带来的限制。

对下一架起飞机，计算满足安全间隔的最早开始时刻
d = max(加入队列时刻, D + t₁, A + t₃)。将 d 与下一架降落飞机加入
队列的时刻 a 比较，而不是与它真正可以降落的时刻比较。若 a ≤ d，
先在 max(a, D + t₂, A + t₄) 处理降落并更新 A；否则在 d 处理起飞
并更新 D。一个队列耗尽后，按相同的安全限制继续处理另一个队列。

该选择是必然的：下一次起飞不可能早于 d。若 a ≤ d，则到 d 时已有
飞机等待降落，即使降落还需继续等待安全间隔，也会阻止起飞。若 a > d，
则 d 时没有飞机排队降落，所以立即起飞。选定队列后，其第一架飞机在
加入队列的时刻和安全限制所给下界的最大值开始操作。只需保存每类操作
最近的开始时刻，因为更早的同类操作只会给出更弱的下界。重复此步骤
即可得到要求的安排。

每步处理一架飞机，时间为 `O(n + m)`。保存输入列表和分组答案所需
空间为 `O(n + m)`。

样例中第一次降落开始于 `07:00:00`，两次起飞开始于 `07:01:00` 和
`07:02:00`，此时第二架降落飞机尚未到达。它在 `07:02:10` 加入队列，
但上次起飞使其必须等到 `07:03:00` 才能降落。输出先列出起飞，
再列出降落，不是所有操作的时间顺序。

注意事项：

- 与 d 比较的是加入降落队列的时刻，相等时也应优先降落；
- 排队等待降落的飞机在实际可降落之前就会阻止起飞；
- 分别保存最近一次起飞和降落的开始时刻；
- 安全间隔从操作开始计算，而不是从结束计算；
- 保持队列顺序，并按输入顺序分两组输出。

答案在 179 个测试上与逐秒模拟一致，在 700 个小测试上与穷举一致，在 56 个生成测试上与另一份独立的已通过实现一致。

## 各语言说明

五种实现使用相同的整数秒模拟。C++、Java、Rust 用有符号 32 位整数
保存时间，Go 使用 `int`，Python 使用整数类型。最多 100 次操作、每次
安全间隔不超过 500 秒，这些类型足够。初始负哨兵要求使用有符号类型。

Python 读取字节记号，Java 使用缓冲逐行输入。各版本都为时钟字段补前导
零，并保留晚于最后允许到达时刻的结果，不会在 `10:00:00` 截断答案。
