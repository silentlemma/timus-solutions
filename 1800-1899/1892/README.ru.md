# 1892. Утро в Кольцово

[Timus 1892](https://acm.timus.ru/problem.aspx?space=1&num=1892) · сложность 886 · simulation

Автор оригинальной задачи — Денис Дублённых; NEERC 2011, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Найдите расписание двух очередей к одной полосе: на взлёт и на посадку.
Внутри каждой очереди сохраняется порядок прибытия. Время постановки
каждого самолёта в очередь известно; операция начинается сразу, как
только разрешена. Минимальные интервалы отсчитываются между началами:

| Предыдущее начало | Следующее начало | Минимальный интервал |
| --- | --- | --- |
| взлёт | взлёт | t₁ |
| взлёт | посадка | t₂ |
| посадка | взлёт | t₃ |
| посадка | посадка | t₄ |

Взлёт запрещён, пока в очереди на посадку есть самолёт, даже если
посадка ещё ждёт окончания безопасного интервала. Постановка на
посадку ровно в момент возможного взлёта тоже даёт посадке приоритет.
Определите время начала каждой операции.

Ограничения: 1 секунда и 64 МБ.

## Входные данные

Первая строка содержит t₁, t₂, t₃ и t₄ в секундах:
30 ≤ tᵢ ≤ 500; max(t₁, t₄) ≤ min(t₂, t₃).

Затем задано число взлётов n, где 1 ≤ n ≤ 50, и n времён постановки
в очередь на взлёт. Далее задано число посадок m, где 1 ≤ m ≤ 50,
и m времён постановки в очередь на посадку.

Каждое время имеет формат `hh:mm:ss` и лежит от `06:00:00` до
`10:00:00` включительно. Каждый список строго возрастает; времена
из разных списков могут совпадать.

## Выходные данные

Выведите сначала n времён начала взлётов, затем m времён начала посадок,
сохраняя порядок ввода внутри каждой группы. Формат — `hh:mm:ss`,
по две цифры на поле. Операции могут начаться позже `10:00:00`.

## Проверка

Ответы сравниваются по последовательностям токенов.

## Примеры

### Пример 1

Ввод:

```
60 60 60 60
2
07:01:00
07:01:30
2
07:00:00
07:02:10
```

Вывод:

```
07:01:00
07:02:00
07:00:00
07:03:00
```

## Решение

Переведём время в секунды. Храним указатели на первые необработанные
самолёты двух очередей, последнее начало взлёта D и посадки A.
Если операции данного вида ещё не было, ограничение от неё отсутствует.

Для следующего взлёта найдём самое раннее время с учётом безопасности:
d = max(время прибытия, D + t₁, A + t₃). Сравниваем d именно со
временем a постановки следующего самолёта в очередь на посадку,
а не с возможным временем самой посадки. Если a ≤ d, сначала
обрабатываем посадку в max(a, D + t₂, A + t₄) и обновляем A.
Иначе взлёт начинается в d, обновляем D. Если одна очередь закончилась,
обрабатываем другую с теми же ограничениями безопасности.

Выбор вынужденный. Раньше d следующий взлёт невозможен. Если a ≤ d,
к этому моменту самолёт уже ждёт посадки и запрещает взлёты, даже
если безопасный интервал до посадки закончится позже. Если a > d,
в момент d очередь на посадку пуста, поэтому взлёт начинается сразу.
Выбрав очередь, запускаем её первый самолёт в максимум времени
прибытия и необходимых интервалов. Достаточно последнего начала
каждого вида: более ранние операции того же вида дают более слабые
нижние границы. Повторение шага строит требуемое расписание.

Каждый шаг обрабатывает один самолёт, поэтому время — `O(n + m)`.
Входные списки и ответы по группам требуют `O(n + m)` памяти.

В примере первая посадка начинается в `07:00:00`. Взлёты происходят
в `07:01:00` и `07:02:00`: второй самолёт на посадку ещё не прибыл.
Он встаёт в очередь в `07:02:10`, но после последнего взлёта посадка
возможна лишь в `07:03:00`. В выводе сначала идут взлёты, затем
посадки, а не общая хронологическая последовательность.

Подводные камни:

- сравнивать с d время постановки на посадку, включая равенство;
- ожидающая посадка запрещает взлёт ещё до разрешённого времени посадки;
- хранить отдельно последние начала взлёта и посадки;
- отсчитывать интервалы от начала, а не от завершения операции;
- сохранять порядок очередей и выводить две группы в порядке ввода.

Ответы совпадают с посекундной симуляцией на 179 тестах, с полным
перебором на 700 малых и с независимой принятой реализацией на 56
сгенерированных.

## Особенности языков

Во всех пяти версиях одинаковая симуляция с целым числом секунд.
C++, Java и Rust хранят время в знаковых 32-битных числах, Go — в `int`,
Python — в своём целом типе. Этого достаточно для не более 100 операций
с интервалами не больше 500 секунд. Начальный отрицательный маркер
требует знакового типа.

Python читает байтовые токены, Java использует буферизованный построчный
ввод. Во всех версиях поля времени дополняются ведущими нулями; результат
может быть позже последнего допустимого времени прибытия и не обрезается
по `10:00:00`.
