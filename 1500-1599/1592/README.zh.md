# 1592. 中国钟表

[Timus 1592](https://acm.timus.ru/problem.aspx?space=1&num=1592) · 难度 588 · math

原题作者 Andrey Demidov，出自 2007 年 10 月 27 日在叶卡捷琳堡举行的 ACM ICPC 2007–2008 NEERC 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n ≤ 50000 只 12 小时表盘的钟，每只显示时间 h:mm:ss。指针只能向前拨，费力程度是指针移动的总时间。
选一个时间设到所有钟上，使总费力最小。

时间限制：1 秒。内存限制：64 MB。

## 输入

n，然后是每只钟的时间，格式为 h:mm:ss，1 ≤ h ≤ 12。

## 输出

选定的时间，格式相同。

## 样例

### 样例 1

输入:

```
3
11:30:00
12:10:01
6:10:18
```

输出:

```
12:10:01
```

## 解法

从 12 点起按秒计时，时间就是 0 到 43199 之间的数 t。把钟从时间 a 拨到 t 需要指针移动 (t − a) mod 43200 秒。
对目标 t，显示时间不超过 t 的钟花费 t − a，显示更晚时间的钟要多转一整圈，所以总和为
n·t − Σa + 43200·(时间晚于 t 的钟数)。把 t 往回移到最近的钟面时间不会增加总费力，所以最优目标必是某只钟的时间。
排序后让 t 依次取各钟时间，用一个指针维护计数：`O(n log n)`。

题目没有说多个同样好的时间时输出哪个；解答输出从 12 点起算最早的那个。结果已在小数据上与枚举全部 43200 个时间的做法对照。

注意事项：

- 12 点是表盘的起点，对应 0 秒，答案为 0 秒时输出 12:00:00；
- 总费力可达约 50000·43200 ≈ 2·10⁹，超出 32 位整数；
- 分和秒输出两位，小时不带前导零。

## 优化解法

优化版 C++ 统计表盘每一秒对应的手表数量。按顺序遍历有手表的秒数，就能维护初始时间严格晚于当前目标的手表数量 later。目标为 t 时比较 N·t + D·later，其中 D = 43,200；初始时间之和对所有目标相同。时间复杂度为 O(N + D)，额外空间为 O(D)。评测数据来自提交 11316963。

Java 版本沿用同样的扫描方法，使用固定长度的 16 位计数数组，从输入缓冲区直接解析时间字段。额外空间为 O(D)。评测数据来自提交 11317056。

Rust 版本沿用同样的扫描方法，使用固定长度的 16 位计数数组，从输入缓冲区直接解析时间字段。额外空间为 O(D)。评测数据来自提交 11317053。

Go 版本沿用同样的扫描方法，使用固定长度的 16 位计数数组，从输入缓冲区直接解析时间字段。额外空间为 O(D)。评测数据来自提交 11317046。

Python 版本沿用同样的扫描方法，使用紧凑的 16 位计数数组并逐行读取手表时间，额外空间为 O(D)。评测数据来自提交 11317035。
