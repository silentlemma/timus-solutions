# 1592. Китайские часы

[Timus 1592](https://acm.timus.ru/problem.aspx?space=1&num=1592) · сложность 588 · math

Автор оригинальной задачи — Андрей Демидов; ACM ICPC 2007–2008, NEERC, Восточный подрегион, Екатеринбург, 27 октября 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть n ≤ 50000 часов с 12-часовым циферблатом, каждые показывают время
h:mm:ss. Стрелки можно крутить только вперёд, и усилие — это суммарное
время, на которое сдвигаются стрелки. Нужно выбрать одно время для всех
часов с наименьшим суммарным усилием.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

n, затем время на каждых часах в виде h:mm:ss, где 1 ≤ h ≤ 12.

## Выходные данные

Выбранное время в том же формате.

## Примеры

### Пример 1

Ввод:

```
3
11:30:00
12:10:01
6:10:18
```

Вывод:

```
12:10:01
```

## Решение

Будем считать секунды от 12 часов, так что время — это число t от 0 до
43199. Перевод часов со времени a на время t стоит (t − a) mod 43200
секунд движения стрелок. Для цели t часы, показывающие не больше t,
стоят t − a, а часы с более поздним временем — на полный оборот больше,
так что сумма равна n·t − Σa + 43200·(число часов после t). Сдвиг t назад
до ближайшего времени на часах не увеличивает суммарное усилие,
поэтому лучшая цель — одно из времён на часах. После сортировки
указатель поддерживает количество, пока t проходит по временам часов:
`O(n log n)`.

Условие не говорит, какое время выводить, если одинаково хороших
несколько; решения выводят самое раннее, считая от 12 часов. Результаты
сверены с перебором всех 43200 времён на маленьких входах.

Подводные камни:

- 12 часов — начало циферблата: это 0 секунд, и ответ 0 секунд
  выводится как 12:00:00;
- суммарное усилие доходит примерно до 50000·43200 ≈ 2·10⁹, больше
  32-битных чисел;
- минуты и секунды выводятся двумя цифрами, а час — без ведущего нуля.

## Оптимизированные решения

Оптимизированная версия C++ считает часы на каждой секунде циферблата. При обходе занятых секунд по порядку поддерживаем число часов, показывающих время строго позже текущей цели. Для цели t сравниваем N·t + D·later, где D = 43 200, а later — это число часов. Сумма исходных показаний одинакова для всех целей. Время O(N + D), дополнительная память O(D). Метрики взяты из посылки 11316963.

Версия Java использует тот же обход с фиксированным массивом 16-битных счётчиков и читает поля времени прямо из буфера. Дополнительная память составляет O(D). Метрики взяты из посылки 11317056.

Версия Rust использует тот же обход с фиксированным массивом 16-битных счётчиков и читает поля времени прямо из буфера. Дополнительная память составляет O(D). Метрики взяты из посылки 11317053.

Версия Go использует тот же обход с фиксированным массивом 16-битных счётчиков и читает поля времени прямо из буфера. Дополнительная память составляет O(D). Метрики взяты из посылки 11317046.

Версия Python использует тот же обход с компактным массивом 16-битных счётчиков. Показания читаются построчно, поэтому дополнительная память составляет O(D). Метрики взяты из посылки 11317035.
