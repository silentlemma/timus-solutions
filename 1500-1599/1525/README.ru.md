# 1525. Путь

[Timus 1525](https://acm.timus.ru/problem.aspx?space=1&num=1525) · сложность 376 · implementation

Автор оригинальной задачи — Дмитрий Гозман; Dmitry Gozman Contest 1 на Петрозаводских зимних сборах, январь 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Робот стоит в неизвестной клетке коробки n × m × k (1 ≤ n, m, k ≤ 10⁵) и
выполняет программу не длиннее 10⁵ ходов: 'l' и 'r' по ширине, 'd' и
'u' по высоте, 'b' и 'f' по длине. Ход, выводящий из коробки,
пропускается. Нужно посчитать клетки, в которых робот может оказаться в
конце.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

n, m и k, затем программа в одной строке.

## Выходные данные

Число возможных конечных клеток.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
1 1 1
uuuur
```

Вывод:

```
1
```

### Пример 2

Ввод:

```
2 2 2
ulf
```

Вывод:

```
1
```

### Пример 3

Ввод:

```
13 14 15
uudlbdrruffbr
```

Вывод:

```
1560
```

## Решение

Три оси не влияют друг на друга, поэтому ответ — произведение
количеств по каждой оси. На одной оси ход сдвигает каждое начало на
единицу или оставляет его у стены, так что два соседних начала
остаются по порядку и не дальше единицы друг от друга. Значит, концы
всех начал заполняют весь отрезок между концами крайних начал 1 и L, и
ось даёт f(L) − f(1) + 1. Моделируем только эти два начала. `O(len)`.

Подводные камни:

- число доходит примерно до 10¹⁵ и требует 64 бит (тест 04, gen1);
- программа может быть пустой, тогда подходит любая клетка (тест 05);
- достаточно длинная серия одинаковых ходов прижимает все начала к стене
  (тесты 01, 06).

## Оптимизированные решения

`1525_implementation_optimized.java`. Сохраняется образ отрезка возможных положений по каждой оси, но три пары концов обновляются за один проход по байтам программы. Команда ограничивает оба конца своей оси, другие оси неизменны. Пустая программа сохраняет исходные отрезки. Перемножаются три итоговые длины; максимум 10^15 помещается в long. Время O(L) при L байтах программы/ввода, хранятся девять long и фиксированный входной буфер; целая String программы и три повторных прохода исключены. Последнее число по-прежнему выводит println.

По сравнению с `1525_implementation.java`: время 0.140 s → 0.093 s; память 2212 KB → 496 KB.

На каждой оси храним смещение s без учёта стен и его минимум lo и максимум hi на префиксах, включая нулевой. При координатах от 0 до L − 1 границы достижимого интервала равны s − lo и L − 1 + s − hi, пока они не встретились. Новый минимум прижимает первую границу к нулю, новый максимум — вторую к L − 1. После встречи границы уже не разойдутся. Число позиций равно max(1, L − (hi − lo)). Перемножаем три результата после одного прохода.

Принятые базовые реализации [1525_implementation.java](1525_implementation.java) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1525_implementation_optimized.java`: место по времени 1/15, по памяти 1/15 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
