# 1572. Екатеринозаводский колодец

[Timus 1572](https://acm.timus.ru/problem.aspx?space=1&num=1572) · сложность 146 · geometry

Авторы оригинальной задачи — Александр Ипатов и Алексей Самсонов; XIV открытое командное первенство школьников Свердловской области по программированию, октябрь 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Отверстие колодца и до 100 крышек от люков — каждое круг (тип 1, размер —
радиус), квадрат (тип 2) или равносторонний треугольник (тип 3, размер —
сторона) с целыми размерами 1 … 100. Плоскую крышку можно как угодно
поворачивать и перемещать в пространстве. Нужно посчитать крышки,
которые можно закинуть в колодец.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Тип и размер колодца, затем N (1 ≤ N ≤ 100) и тип и размер каждой
крышки.

## Выходные данные

Число крышек, которые пролезут.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
2 10
3
3 20
1 5
2 11
```

Вывод:

```
2
```

### Пример 2

Ввод:

```

2

```

Вывод:

```

```

## Решение

Крышка, поставленная вертикально и опускаемая прямо вниз, пересекает
плоскость отверстия по параллельным хордам, так что она проходит, когда в
каком-то направлении её самая длинная хорда помещается в отверстие.
Лучшее направление даёт для круга диаметр 2r, для квадрата сторону a, а
для треугольника высоту a·√3/2 (хорды, параллельные высоте). Отверстие
вмещает отрезки до своего самого длинного: диаметр круга 2R, диагональ
квадрата A·√2 и сторону треугольника A.

Если возвести все эти длины в квадрат и умножить на 4, получатся целые
числа: 16r², 4a² и 3a² для крышек, 16R², 8A² и 4A² для колодца, так что
сравнение точное, и крышка, которая лишь касается краёв, проходит.
`O(N)`. Ответы совпадают с независимой программой для каждой пары колодца
и крышки любой формы и размера.

Подводные камни:

- размер круга — радиус, а не диаметр;
- треугольник проходит высотой, а не стороной, так что треугольник со
  стороной 16 ещё входит в квадратный колодец со стороной 10 (тест 06);
- равные размеры проходят: квадрат со стороной 10 проходит в круг
  радиуса 5 (второй пример), так что вещественные сравнения требуют
  аккуратности.

## Оптимизированные решения

`1572_geometry_optimized.py`. Сохраняются точные сравнения квадратов хорд по коэффициентам форм NARROWEST/WIDEST, включая равенство. Каждый люк читается, проверяется его масштабированный целый квадрат и отбрасывается вместо хранения списка. Время O(n), постоянное геометрическое состояние плюс буферы токенов. Единственный ответ сбрасывается перед прямым завершением PyPy; простое геометрическое объяснение сохранено.

По сравнению с `1572_geometry.py`: время 0.093 s → 0.14 s; память 384 KB → 264 KB.

`1572_geometry_optimized.rs`. Сохраняется точное сравнение квадратов хорд по коэффициентам фигур NARROWEST и WIDEST, включая равенство. Каждая крышка читается, её масштабированный квадрат u64 сравнивается с отверстием и больше не хранится; полный вектор входа убран. Вывод прямой вместо форматирования. Время O(n), память O(1); наглядное геометрическое обоснование и базовый исходник сохранены.

По сравнению с `1572_geometry.rs`: время 0.031 s → 0.046 s; память 228 KB → 60 KB.

Оптимизированное решение на Java разбирает числа вручную из буфера на
4 КБ, заполняемого из `System.in`, а не создаёт `Scanner`, так что JVM
не загружает сканер и его регулярные выражения; сравнение квадратов длин
то же: {1572_geometry_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1572_geometry_optimized.java`: сокращение времени +44.29%; сокращение
  памяти +80.86%; база: `1572_geometry.java`.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1572_geometry_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
