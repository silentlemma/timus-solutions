# 1571. Переводчики

[Timus 1571](https://acm.timus.ru/problem.aspx?space=1&num=1571) · сложность 451 · constructive

Автор оригинальной задачи — Сергей Пупырев; XII чемпионат УрГУ по программированию, 6 октября 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждая из N ≤ 100 строительных бригад говорит на одном языке.
Переводчик знает любые два языка. Любые две бригады должны иметь
возможность поговорить, и никакая другая бригада не должна понимать их
разговор. Нужно вывести наименьшее число переводчиков с их языками в
виде `язык1-язык2` или `Impossible`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем язык каждой бригады.

## Выходные данные

Число переводчиков и пары их языков или `Impossible`. Принимается любой
лучший набор.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверяются минимальное число переводчиков и пары разных языков с именами из строчных букв длиной до десяти. Между языками любых двух команд должен быть путь через языки, на которых не говорит никакая другая команда. Impossible должен соответствовать ожидаемой невозможности.

## Примеры

### Пример 1

Ввод:

```
3
russian
french
german
```

Вывод:

```
3
russian-english
english-german
english-french
```

## Решение

Если у двух бригад общий язык, то третья бригада, если она есть, не
сможет поговорить с первой так, чтобы вторая не поняла; если бригад
всего две, никто не нужен. Иначе пусть все k языков различны. Одной
бригаде никто не нужен, двум нужен один переводчик для их двух языков.

При k ≥ 3 разговор, проходящий через язык другой бригады, этой бригадой
подслушивается, так что между любыми двумя бригадами переводчики должны
образовывать цепочку, внутренние языки которой не знает ни одна бригада.
Если бы переводчики использовали только языки бригад, они образовали бы
связный граф на этих k языках, а с k − 1 рёбрами это было бы дерево, в
котором какая-то цепочка проходит через третий язык. Значит, нужно k
переводчиков, и k хватает: язык каждой бригады в паре с языком, которого
никто не знает, например english. Если какая-то бригада говорит на
english, средний язык — первое свободное имя из одной или двух букв:
языки в ответе тоже должны быть не длиннее десяти букв, а 100 бригад
не могут занять все 702 таких имени. `O(N log N)` в C++; в остальных
языках в среднем `O(N)`.

Подводные камни:

- двум бригадам одного языка никто не нужен, а для трёх бригад с
  повторяющимся языком задача невыполнима (тесты 03, 05);
- какая-то бригада сама может говорить на english, поэтому средний язык
  не должна знать ни одна бригада (тесты 06, 08);
- принимаются и другие ответы, например треугольник прямых пар для трёх
  бригад, так что чекер проверяет конфиденциальность.

## Оптимизированные решения

`1571_constructive_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1571_constructive.java`: время 0.156 s → 0.078 s; память 1712 KB → 668 KB.

`1571_constructive_optimized.py`. Сохраняются случаи совпадающих языков и минимальная звезда через язык, которого не знает ни одна команда. Одно- и двухбуквенные имена генерируются по одному вместо выделения всех 702 и импорта string. При n<=100 свободное имя гарантировано. Языки остаются байтами, рёбра выводятся отдельно; текстовое количество сбрасывается перед байтовыми рёбрами. Полные токены входа и множество языков сохраняются: память O(I), не константа. Время O(n) при ограниченных именах и фиксированном алфавите; простая строковая версия остаётся.

По сравнению с `1571_constructive.py`: время 0.078 s → 0.125 s; память 548 KB → 212 KB.

Новые C++, Go и Rust сортируют ограниченную таблицу не более 100 имён по 11 байтов с завершающим нулём. Равные соседние имена выявляют повторы. При трёх и более различных командах отмечаем занятые одно- и двухбуквенные имена и выбираем свободное среди 26+26²: 100 команд не займут их все. Соединяем каждую команду с этим неизвестным остальным языком. Сохраняются исходная конструкция и оптимальное число переводчиков; множества, хеш-таблицы и временные списки заменены ограниченным хранилищем. Сортировка занимает O(N log N) при длине имени до десяти; это не асимптотическое улучшение хеш-баз. C++/Rust используют C runtime, Go — стандартные дескрипторы. Простые файлы сохранены; Java/Python повторно используют подходящие базы без копий.

Принятые базовые реализации [1571_constructive.java](1571_constructive.java), [1571_constructive.py](1571_constructive.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`1571_constructive_optimized.java`: место по времени 1/18, по памяти 4/18 в этой сопоставимой выборке.

`1571_constructive_optimized.py`: место по времени 18/18, по памяти 1/18 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
