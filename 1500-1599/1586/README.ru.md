# 1586. Трипростые числа

[Timus 1586](https://acm.timus.ru/problem.aspx?space=1&num=1586) · сложность 144 · dp

Автор оригинальной задачи — Денис Мусин; ACM ICPC 2007–2008, NEERC, Восточный подрегион, Екатеринбург, 27 октября 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Число трипростое, если любые три подряд идущие цифры образуют
трёхзначное простое число. Нужно посчитать n-значные трипростые числа
(3 ≤ n ≤ 10000) по модулю 10⁹ + 9.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

n.

## Выходные данные

Количество по модулю 10⁹ + 9.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
204
```

## Решение

Может ли идти следующая цифра, зависит только от двух последних цифр,
так что числа считаются по ним. При n = 3 каждое трёхзначное простое
считается один раз под своими двумя последними цифрами. Каждая следующая
цифра c приписывается к числу, оканчивающемуся на ab, ровно тогда, когда
abc — трёхзначное простое, и новое число оканчивается на bc. 143
трёхзначных простых дают 143 перехода на цифру: `O(143·n)`. Результаты
сверены с проверкой всех чисел не длиннее шести цифр.

Подводные камни:

- трёхзначное простое не может начинаться с 0, так что ни одно окно не
  может начинаться с нулевой цифры; подсчёт по самим простым это
  учитывает;
- количество быстро растёт и берётся по модулю 10⁹ + 9, а не 10⁹ + 7.

## Оптимизированные решения

Оптимизированное решение на C++ один раз записывает в массивы
постоянного размера начальную и конечную пары цифр каждого перехода по
простому числу, а не вычисляет `p / 10` и `p % 100` заново на каждой
цифре, и переиспользует два массива счётчиков вместо нового `vector` на
каждую цифру. Счётчики хранятся в `int` вместо `long long`, а каждое
сложение приводится одним условным вычитанием вместо `%`: два остатка
меньше 10⁹ + 9 в сумме меньше 2³¹: {1586_dp_optimized.cpp}.

Оптимизированное решение на Go один раз записывает в массивы постоянного
размера начальную и конечную пары цифр каждого перехода по простому
числу и переиспользует два массива счётчиков вместо нового среза на
каждую цифру; каждое сложение приводится одним условным вычитанием
вместо `%`: {1586_dp_optimized.go}.

Оптимизированное решение на Java читает `n` побайтно через
`System.in.read` вместо `Scanner`, хранит начальную и конечную пары цифр
каждого перехода в массивах `int`, а не перебирает список упакованных
простых `Integer`, и меняет местами два массива счётчиков вместо нового
массива на каждую цифру. Счётчики хранятся в `int` вместо `long`, а
каждое сложение приводится одним условным вычитанием вместо `%`: два
остатка меньше 10⁹ + 9 в сумме меньше 2³¹: {1586_dp_optimized.java}.

При `n = 3` оптимизированное решение на Python выводит число трёхзначных
простых, 143. При `n ≥ 4` оно возводит матрицу переходов в степень, а не
проходит по всем `n` цифрам. Начиная с четвёртой цифры обе последние
цифры завершают трёхзначное простое число, поэтому каждая из них — 1, 3,
7 или 9, и остаётся только 16 пар; матрица 16 × 16 считает простые
числа, ведущие из одной пары в другую. Счётчики для четырёх цифр,
умноженные на эту матрицу в степени `n − 4`, которая вычисляется
повторным возведением в квадрат, не более 14 раз при `n ≤ 10000`, дают
ответ, всего `O(16³ log n)`: {1586_dp_matrix.py}.
