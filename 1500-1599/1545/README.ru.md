# 1545. Иероглифы

[Timus 1545](https://acm.timus.ru/problem.aspx?space=1&num=1545) · сложность 50 · implementation

Автор оригинальной задачи — Евгений Крохалев; XI командный студенческий чемпионат Урала по программированию, Екатеринбург, 21 апреля 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В справочнике N ≤ 1000 иероглифов, каждый записан двумя строчными
буквами. По введённой букве нужно вывести иероглифы, которые с неё
начинаются.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, N двухбуквенных записей, затем буква.

## Выходные данные

Подходящие записи, по одной в строке, в любом порядке; ничего, если их
нет.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверка репозитория разбивает вывод на токены и сравнивает отсортированные списки с сохранением кратностей. Совпавшие записи допустимы в любом порядке, повторы должны сохраняться.

## Примеры

### Пример 1

Ввод:

```
6
na
no
ni
ki
ka
ku
k
```

Вывод:

```
ka
ki
ku
```

## Решение

Сравним первую букву каждой записи с введённой и выведем совпадения в
порядке справочника. `O(N)`.

Подводные камни:

- если совпадений нет, вывод пуст (тесты 02, 05);
- запись, встречающаяся дважды, выводится дважды (тест 03);
- буква должна стоять первой: совпадение на втором месте не считается
  (тест 05).

## Оптимизированные решения

Оптимизированное решение на C++ хранит двухбуквенные записи не в
`std::string`, а в локальном массиве трёхбайтовых C-строк, читая их
через `scanf("%2s")` и печатая через `puts`: 120 КБ вместо 392 КБ при
том же времени.

Каждый иероглиф — две буквы. Оптимизированное решение на Java хранит их
в байтовых массивах, заполняемых из блоков по 256 байт, и выводит ответ
из одного байтового массива, без `Scanner` и без строк: 392 КБ вместо
1804 КБ при том же времени. Оптимизированное решение на Rust хранит
каждый иероглиф парой байтов и выводит через `BufWriter` с небольшим
буфером: 0.015 с вместо 0.046 с и 196 КБ вместо 236 КБ.

`1545_implementation_optimized.py`. Сохраняются фильтрация словаря, порядок и повторы записей. Сырые байты разделяются на токены, однобуквенный префикс проверяется startswith, совпавшие записи соединяются как bytes. Декодированный словарь и отдельный список текстовых совпадений не сохраняются, но токены, ссылки среза и склеенный ответ всё равно требуют O(N) памяти при длине записи два. Время O(N). Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1545_implementation.py`: время 0.062 s → 0.14 s; память 460 KB → 216 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1545_implementation_optimized.py`: место по времени 168/175, по памяти 2/175 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
