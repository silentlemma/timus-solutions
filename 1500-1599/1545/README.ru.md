# 1545. Иероглифы

[Timus 1545](https://acm.timus.ru/problem.aspx?space=1&num=1545) · сложность 50 · implementation

Автор оригинальной задачи — Евгений Крохалев; XI командный студенческий чемпионат Урала по программированию, Екатеринбург, 21 апреля 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В справочнике N ≤ 1000 иероглифов, каждый записан двумя строчными
буквами. По введённой букве нужно вывести иероглифы, которые с неё
начинаются.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, N двухбуквенных записей, затем буква.

## Выходные данные

Подходящие записи, по одной в строке, в любом порядке; ничего, если их
нет.

## Примеры

### Пример 1

Ввод:

```
6
na
no
ni
ki
ka
ku
k
```

Вывод:

```
ka
ki
ku
```

## Решение

Сравним первую букву каждой записи с введённой и выведем совпадения в
порядке справочника. `O(N)`.

Подводные камни:

- если совпадений нет, вывод пуст (тесты 02, 05);
- запись, встречающаяся дважды, выводится дважды (тест 03);
- буква должна стоять первой: совпадение на втором месте не считается
  (тест 05).

## Оптимизированные решения

Оптимизированное решение на C++ хранит двухбуквенные записи не в
`std::string`, а в локальном массиве трёхбайтовых C-строк, читая их
через `scanf("%2s")` и печатая через `puts`: 120 КБ вместо 392 КБ при
том же времени.

Каждый иероглиф — две буквы. Оптимизированное решение на Java хранит их
в байтовых массивах, заполняемых из блоков по 256 байт, и выводит ответ
из одного байтового массива, без `Scanner` и без строк: 392 КБ вместо
1804 КБ при том же времени. Оптимизированное решение на Rust хранит
каждый иероглиф парой байтов и выводит через `BufWriter` с небольшим
буфером: 0.015 с вместо 0.046 с и 196 КБ вместо 236 КБ.
