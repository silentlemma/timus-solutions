# 1576. Телефонные тарифы

[Timus 1576](https://acm.timus.ru/problem.aspx?space=1&num=1576) · сложность 147 · implementation

Оригинальная задача — фольклор; XIV открытое командное первенство школьников Свердловской области по программированию, октябрь 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Три тарифа: базовый — абонентская плата N1 и C1 за минуту;
комбинированный — плата N2, включающая T минут, и C2 за каждую минуту
сверх T; безлимитный — плата N3. Звонки не дольше 6 секунд бесплатны, а
более долгие округляются вверх до целых минут. По списку из не более чем
1000 звонков в виде mm:ss нужно вывести месячный счёт по каждому тарифу.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N1 и C1, затем N2, T и C2, затем N3 — все целые от 1 до 1000, — затем
K (1 ≤ K ≤ 1000) и K длительностей звонков в виде mm:ss, где
0 ≤ mm, ss ≤ 59.

## Выходные данные

Три строки в формате примеров.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
135 1
220 10 1
300
5
00:05
00:10
09:59
07:00
01:01
```

Вывод:

```
Basic:     155
Combined:  230
Unlimited: 300
```

### Пример 2

Ввод:

```
10 2
100 1 1
1000
1
03:00
```

Вывод:

```
Basic:     16
Combined:  102
Unlimited: 1000
```

## Решение

Сложим оплачиваемые минуты: звонок длиной s секунд ничего не добавляет
при s ≤ 6, а иначе добавляет ⌈s / 60⌉. При M минутах счета равны
N1 + C1·M, N2 + C2·max(0, M − T) и N3. Они меньше 7·10⁷. `O(K)`.

Подводные камни:

- звонок ровно в 6 секунд бесплатен, в 7 секунд стоит целую минуту, а
  звонок ровно в минуту стоит одну (тест 03);
- комбинированный тариф ничего не добавляет, пока минуты укладываются в
  T, так что перерасход не бывает отрицательным;
- подписи выровнены по ширине: после `Basic:` пять пробелов, после
  `Combined:` два, после `Unlimited:` один.

## Оптимизированные решения

`1576_implementation_optimized.java`. Java читает звонок mm:ss как два целых числа без разбиения строки. Звонки не дольше шести секунд бесплатны; иначе оплачиваемые минуты равны mm+(ss>0). Хранится только их сумма. Те же три формулы тарифов вычисляются в int: не более 1000 звонков по 60 оплачиваемых минут и параметры тарифов до 1000 ограничивают максимальный счёт числом 60001000. Повторно используемые буферы ввода и вывода по 1024 байта выводят точные подписи, пробелы и числа без конкатенации StringBuilder. Время O(K), дополнительная память O(1). Все 3600 пар минут и секунд проверены по округлению длительности в секундах.

Accepted точного исходника Java 1.8 №11327448: 0.078 с / 356 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/54, память 1/54. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Обе метрики на первом месте: отдельная цель языка также пройдена, звёздочка не нужна. Прежний документированный оптимизированный запуск №11304530: 0.125 с / 376 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1576_implementation_optimized.java`: 0.078 s / 356 KB; сохранённая учебная база `1576_implementation.java`: 0.109 s / 2244 KB.

`1576_implementation_optimized.rs`. Сохраняются бесплатные звонки до шести секунд включительно и округление каждого платного до полной минуты. k длительностей mm:ss читаются напрямую: числовой разбор потребляет двоеточие между полями, без поиска и разбиения строковых токенов. Накапливаются только платные минуты; три формулы, подписи и пробелы выравнивания прежние. Время O(k), память O(1), правила тарификации не меняются.

По сравнению с `1576_implementation.rs`: время 0.015 s → 0.015 s; память 232 KB → 52 KB.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1576_implementation_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
