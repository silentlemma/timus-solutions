# 1570. 高处用餐

[Timus 1570](https://acm.timus.ru/problem.aspx?space=1&num=1570) · 难度 896 · dp

原题作者 Vladimir Yakovlev，出自 2007 年 10 月 6 日第十二届乌拉尔国立大学程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

菜单上有 N ≤ 100 道菜，每道菜价格为 1 … 10000 卢布，饱腹度在 0.1 到 10 之间（小数点后至多三位），即能喂饱的
人数。可以点任意份数的任意菜，使饱腹度之和至少为 M ≤ 20 且花费最少；在这样的点法中选不同菜品最多的一种。
输出花费以及各道菜和份数。

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 M，然后每道菜：名称、价格和饱腹度。

## 输出

花费，然后每行一道菜及其份数。任何最优的点法都被接受。

## 样例

### 样例 1

输入:

```
4 6
pizza 320 2.4
turkey 1050 3.5
lasagna 150 0.9
pasta 75 0.45
```

输出:

```
865
pizza 2
lasagna 1
pasta 1
```

## 解法

饱腹度按千分之一精确读入，所以目标是 T = 1000·M，任何不小于 T 的总和都算作 T。对这些总和做完全背包，对每个
总和保存最小花费，花费相同时保存最多的不同菜品数，二者合成一个数 花费·128 − 菜品数，越小越好。

不同菜品数不能按份数相加，所以菜是一道一道加入的。对每道菜，含有它的点法从“在不含它的点法上加第一份”开始
（多一道菜），然后再加更多份（不增加菜品数）；在这些点法和不含这道菜的点法中保留最好的。每一步都记下来源，
因此可以从总和 T 出发逐道菜倒推出点法。耗时 O(N·T)，约 2·10⁶ 步。结果已在 300 个随机小菜单上与枚举所有份数
的做法对照。

注意事项：

- 更便宜的点法可能超过 M，所以大于 T 的总和必须允许（测试 03：200 份小菜）；
- 花费相同时比较的是不同菜品数，而不是份数（样例及测试 04、05）；
- 饱腹度可能不带小数点（测试 04）；
- Python 在 PyPy 下运行：最大的测试在 CPython 下约需 0.8 秒（限制为 1 秒），在 PyPy 下约 0.1 秒。
