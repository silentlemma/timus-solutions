# 1574. Математики и скобки

[Timus 1574](https://acm.timus.ru/problem.aspx?space=1&num=1574) · сложность 353 · strings

Автор оригинальной задачи — Александр Торопов; XIV открытое командное первенство школьников Свердловской области по программированию, октябрь 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дана непустая строка из не более чем 100000 скобок. Нужно посчитать циклические
сдвиги на 0 … n − 1 символов, превращающие её в правильную скобочную
последовательность. Сдвиги на разное число символов считаются отдельно,
даже если дают одну и ту же строку.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Строка скобок.

## Выходные данные

Число таких сдвигов.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
)(()
```

Вывод:

```
1
```

### Пример 2

Ввод:

```
)()(
```

Вывод:

```
2
```

### Пример 3

Ввод:

```
()
```

Вывод:

```
1
```

## Решение

Если открывающих и закрывающих скобок разное число, ни один сдвиг не
подходит. Иначе возьмём баланс после каждого префикса: открывающие минус
закрывающие. Сдвиг, начинающийся сразу после позиции i, меняет каждый
баланс на −p(i), где p(i) — баланс в этом месте, поэтому он не уходит
ниже нуля ровно тогда, когда p(i) — наименьший из всех балансов. Ответ —
число префиксов с балансом, равным этому минимуму. `O(n)`.

Подводные камни:

- строка вроде `)()(` даёт одну и ту же правильную строку двумя разными
  сдвигами, и оба считаются (второй пример);
- сдвиг на ноль тоже считается (третий пример);
- у несбалансированной строки ответ 0, даже если какой-то сдвиг держит
  все балансы неотрицательными (тесты 04, 05).

## Оптимизированные решения

`1574_strings_optimized.java`. Число вхождений минимального баланса префикса считается на ходу; при ненулевом итоговом балансе ответ ноль. У сбалансированной строки минимум неположителен, поэтому lowest=0 без подсчёта пустого префикса даёт прежнее число циклических сдвигов. Java читает байты скобок напрямую, не сохраняя строку, и использует фиксированную память ввода. Python убирает список всех префиксных сумм, но целиком читает байтовую строку: общая память остаётся O(n), вспомогательная память Java — O(1). Время обеих O(n). Python сбрасывает вывод перед os._exit(0); это изменение завершения среды не меняет асимптотику.

По сравнению с `1574_strings.java`: время 0.125 s → 0.125 s; память 1196 KB → 480 KB.

`1574_strings_optimized.py`. Число вхождений минимального баланса префикса считается на ходу; при ненулевом итоговом балансе ответ ноль. У сбалансированной строки минимум неположителен, поэтому lowest=0 без подсчёта пустого префикса даёт прежнее число циклических сдвигов. Java читает байты скобок напрямую, не сохраняя строку, и использует фиксированную память ввода. Python убирает список всех префиксных сумм, но целиком читает байтовую строку: общая память остаётся O(n), вспомогательная память Java — O(1). Время обеих O(n). Python сбрасывает вывод перед os._exit(0); это изменение завершения среды не меняет асимптотику.

По сравнению с `1574_strings.py`: время 0.093 s → 0.14 s; память 5252 KB → 1 412 KB.

Версии C++, Go и Rust считают вхождения минимального баланса префикса прямо при чтении. При появлении нового минимума счётчик сбрасывается до единицы. Учитываются префиксы длин от 1 до n. При нулевом итоговом балансе полный префикс заменяет пустой: оба соответствуют одному и тому же циклическому разрезу. C++ использует буферизованный стандартный ввод, Go читает блоками фиксированного размера, Rust читает из буфера стандартного ввода. Время O(n), дополнительная память O(1).

Принятые базовые реализации [1574_strings.java](1574_strings.java), [1574_strings.py](1574_strings.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1574_strings_optimized.java`: место по времени 13/22, по памяти 2/22 в этой сопоставимой выборке.

`1574_strings_optimized.py`: место по времени 28/45, по памяти 25/45 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
