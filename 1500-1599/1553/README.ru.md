# 1553. Пещеры и туннели

[Timus 1553](https://acm.timus.ru/problem.aspx?space=1&num=1553) · сложность 282 · trees

Оригинальная задача — Novosibirsk SU Contest, Петрозаводские сборы, сентябрь 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N ≤ 100000 пещер образуют дерево. У каждой пещеры есть уровень радиации,
сначала 0. Нужно ответить на Q ≤ 100000 запросов: «I U V» увеличивает
уровень пещеры U на V ≤ 10000, а «G U V» спрашивает наибольший уровень
на пути от U до V.

Ограничение времени: 3 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N, N − 1 туннель, Q и запросы.

## Выходные данные

Ответ на каждый запрос G, по одному в строке.

## Проверка

Ответы запросов сравниваются по порядку. Новый Java прошёл 106 запусков: 100 случайных малых деревьев с буквальным BFS путей, цепь из 100000 вершин со 100000 операциями, звезду из 99999 вершин и 4 теста репозитория. Проверены нулевые увеличения и значения до 10^9.

## Примеры

### Пример 1

Ввод:

```
4
1 2
2 3
2 4
6
I 1 1
G 1 1
G 3 4
I 2 3
G 1 1
G 3 4
```

Вывод:

```
1
0
1
3
```

## Решение

Тяжёлые пути: подвесим дерево за пещеру 1, и пусть каждая пещера
продолжает свою цепочку в ребёнка с самым большим поддеревом. Любой путь
от пещеры вверх к корню пересекает не больше ⌊log₂ N⌋ + 1 цепочек, потому что
каждое лёгкое ребро хотя бы вдвое уменьшает размер поддерева при спуске. Выложим
цепочки одну за другой, чтобы каждая занимала подряд идущие места, и
будем хранить дерево отрезков максимумов по местам.

Увеличение меняет один лист и максимумы над ним. Запрос пути
поднимается от того конца, у которого голова цепочки глубже, беря
максимум по куску этой цепочки, пока оба конца не окажутся в одной
цепочке, и завершается куском между ними. Дерево строится без рекурсии,
по порядку обхода в ширину, ведь путь из 100000 пещер переполнил бы
рекурсивный обход. `O((N + Q) log² N)`.

Подводные камни:

- запрос от пещеры к ней самой — это её уровень (тесты 01, 02, 03);
- увеличения на 0 допустимы (тест 04);
- уровень не больше 10⁹ (10⁵ увеличений по 10⁴) и помещается в знаковые
  32 бита; учебные версии на компилируемых языках сохраняют 64-битные значения,
  компактные используют 32 бита, учебный Python — целые Python;
- путь может разбиться на две цепочки, если пещера 1 внутренняя: в gen2
  цепочки из 52487 и 47513 пещер, а не одна из 100000 пещер.

## Оптимизированные решения

Сохраняются итеративное heavy-light разложение и максимумы на путях. Компактные C++/Python используют плоские массивы графа и состояний, 32-битные максимумы и ограниченные буферы. После не более 100000 увеличений не более чем на 10000 значение не превышает 10^9 и помещается в знаковые 32 бита. Неотрицательные увеличения позволяют прекратить подъём, если максимум предка не меняется.

Java дополнительно переиспользует память после конца прежнего назначения: головы списков смежности становятся тяжёлыми детьми после обхода; размеры поддеревьев — позициями вершин; порядок обхода — головами цепей. Корни цепей после этого перебираются по номерам вершин, а не по перезаписанному порядку. После нумерации цепей массив концов рёбер из 2N ячеек очищается и становится деревом отрезков. Родители и глубины для запросов сохраняются. Удаляются три выделения по N ячеек и отдельное дерево из 2N без пересечения живых назначений. Подготовка `O(N)`, обновление `O(log N)`, запрос `O(log² N)`, память `O(N)`. Все понятные HLD-базы сохранены.

- `1553_trees_optimized.cpp`: 0.046 s / 5200 KB; база `1553_trees.cpp`: 0.390 s / 9584 KB; изменение относительно базы: время -88.2%, память -45.7%.
- `1553_trees_optimized.java`: 0.187 s / 6968 KB; база `1553_trees.java`: 0.203 s / 10684 KB; изменение относительно базы: время -7.9%, память -34.8%.

## Особенности языков

Сохранённые срезы: 1–2 ноября 2026 года. Цель C++ — топ 15% либо первые 10 мест одновременно по времени и памяти; других семейств — первое место по обеим метрикам. Ничьи делят место. Пустые выборки дают только формальное покрытие.

Используется сохранённый профиль текущих компиляторов; исключены собственный автор и старые строки со временем меньше 0,015 с. Для семейств кроме C++ дополнительно требуется ID посылки ≥10770000; память C++ сравнивается по первым 1000 подходящим строкам. Собственные времена меньше 0,015 с считаются 0,015 с. Порог ID — фиксированное правило сравнения, а не точный календарный фильтр.
