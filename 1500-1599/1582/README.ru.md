# 1582. Букмекеры

[Timus 1582](https://acm.timus.ru/problem.aspx?space=1&num=1582) · сложность 123 · math

Автор оригинальной задачи — Сергей Пупырев, подготовка — Владимир Яковлев; ACM ICPC 2007–2008, NEERC, Восточный подрегион, Екатеринбург, 27 октября 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У матча три исхода с лучшими коэффициентами k₁, k₂ и k₃ (0.01 … 100):
ставка x на верный исход приносит k·x, неверная — ничего. Нужно
распределить ставки на общую сумму 1000 фунтов по трём исходам так,
чтобы в худшем случае получить как можно больше, и вывести эту сумму,
округлённую до целого.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

k₁, k₂ и k₃.

## Выходные данные

Гарантированная выплата, округлённая.

## Примеры

### Пример 1

Ввод:

```
3.5 3.5 3.5
```

Вывод:

```
1167
```

### Пример 2

Ввод:

```
1.25 10.0 5.75
```

Вывод:

```
931
```

## Решение

Поставим xᵢ на исход i, x₁ + x₂ + x₃ = 1000; исход i приносит kᵢ·xᵢ.
Чтобы гарантировать выплату P, каждый исход должен приносить не меньше
P, то есть xᵢ ≥ P / kᵢ, и сложение трёх неравенств даёт
1000 ≥ P·(1/k₁ + 1/k₂ + 1/k₃). Ставки xᵢ = P / kᵢ достигают этой
границы, поэтому наибольшая гарантированная выплата равна

P = 1000 / (1/k₁ + 1/k₂ + 1/k₃).

Читаем каждую десятичную дробь точно как a / 10ˢ. Начиная с N = 1 и
D = 0, для каждого коэффициента обновляем D = D·a + N·10ˢ, затем
N = N·a. Теперь P = 1000·N / D. Используем длинные целые числа и
двоичным поиском находим наибольшее целое m, для которого
2·1000·N ≥ (2m − 1)·D: точные половины округляются вверх без ошибок
вещественной арифметики. Ответ не превосходит ⌊1000·100 / 3⌋, поэтому
число шагов поиска постоянно. Для L десятичных цифр во входе (после
раскрытия экспоненты, если она есть) время — `O(L^2)`, память — `O(L)`.

Подводные камни:

- при всех коэффициентах больше 3 гарантированная выплата больше ставки,
  как в первом примере;
- точная половина округляется вверх: коэффициенты 2, 10 и 25 дают
  1562.5 и ответ 1563, а `printf("%.0f")` округлил бы к чётному и вывел
  1562 (тест 08);
- двоичная арифметика может превратить точную половину в чуть меньшее
  число: коэффициенты 0.02, 0.02 и 0.03 дают ровно 7.5 и ответ 8
  (тест 10). Число знаков после запятой не ограничено, поэтому нужна
  точная арифметика, а не добавление эпсилон.

## Оптимизированные решения

Оптимизированное решение на Java читает три коэффициента через
`BufferedReader` и `StringTokenizer` вместо `Scanner` с его
регулярными выражениями и данными локали. Арифметика остаётся точной,
коэффициенты по-прежнему попадают в `BigDecimal`, а сравнения идут в
`BigInteger`, так что дешевле становится только чтение ввода:
{1582_math_optimized.java}.
