# 1506. Столбцы чисел

[Timus 1506](https://acm.timus.ru/problem.aspx?space=1&num=1506) · сложность 134 · implementation

Автор оригинальной задачи — Станислав Васильев; четвертьфинал XXXI ACM ICPC, Екатеринбург, 2006 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно напечатать N чисел от 0 до 999 (1 ≤ N ≤ 100) в K столбцов
(1 ≤ K ≤ N) с наименьшим числом строк. Все столбцы одной высоты, кроме
последнего, который может быть короче. Числа заполняют первый столбец
сверху вниз, затем второй и так далее. Каждое число выровнено по
правому краю в поле из 4 символов, концевых пробелов в строках нет.
Гарантируется, что таблица ровно с K непустыми столбцами существует.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и K, затем N чисел.

## Выходные данные

Таблица.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются. В частности, сохраняются выравнивание таблицы и ведущие пробелы в каждом поле.

## Примеры

### Пример 1

Ввод:

```
7 3
1 2 30 40 50 600 700
```

Вывод:

```
   1  40 700
   2  50
  30 600
```

## Решение

Наименьшее число строк — H = ⌈N / K⌉. Любая допустимая высота h
удовлетворяет h ≥ H и (K − 1)·h < N. Поэтому из гарантии существования
следует (K − 1)·H < N: при высоте H последний столбец непуст.
В столбце c стоят числа с
индексами от c·H до c·H + H − 1, поэтому строка r состоит из
существующих чисел c·H + r для c = 0, 1, …; они кончаются на первом
исчерпанном столбце, а это может быть только последний. Каждое число
печатаем в поле из 4 символов и на этом заканчиваем строку. `O(N)`.

Подводные камни:

- числа идут вниз по столбцам, а не вдоль строк (тест 01);
- каждое число занимает 4 символа, и первое тоже, поэтому каждая
  строка начинается с пробелов (тест 01);
- если последний столбец короче, нижние строки заканчиваются на число
  раньше, без концевых пробелов (тест 06);
- гарантия существования существенна: последний столбец содержит хотя
  бы одно число (тест 06); не любая пара с 1 ≤ K ≤ N допустима;
- при K = N получается одна строка, при K = 1 — один столбец
  (тесты 03, 04).

## Оптимизированные решения

`1506_implementation_optimized.py` используется побайтово без изменений, без второго исходника и нового алгоритма. Accepted точного исходника на CPython 3.12 №11327027: 0.046 с / 720 КБ. Сохранённая выборка актуальных компиляторов семейства Python от 2026-11-20: место по времени 1/291, по памяти 285/291. Поскольку здесь меньше 1024 КБ, строгий критерий первых десяти мест или топ 15% учитывает только время; звёздочка сохраняет отдельную рейтинговую цель языка. У того же файла есть прежний Accepted на PyPy 3.10 №11325476: 0.125 с / 248 КБ. Это парные замеры разных запусков: CPython даёт выбранный результат по времени и рейтингу, PyPy расходует меньше памяти. Прежние замечания об экономии памяти в этом разделе относятся к этому замеру PyPy, а не к строке CPython. Все учебные исходники сохранены без изменений.

`1506_implementation_optimized.py`. Сохраняются height=ceil(n/k) и заполнение по столбцам. Числа разбираются один раз, индексы row,row+height,... обходятся напрямую; каждая строка выводится отдельно с выравниванием вправо в поле ширины четыре. Убраны список всех готовых строк и срез строковых чисел. Массив числового входа остаётся: время и память O(n). Ведущие пробелы и переводы строк значимы. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1506_implementation.py`: время 0.093 s → 0.125 s; память 460 KB → 248 KB.

Оптимизированное решение на C++ хранит числа в массиве фиксированного
размера на 100 `int` на стеке вместо `std::vector`, ведь N ≤ 100, так
что программа ничего не выделяет в куче:
{1506_implementation_optimized.cpp}.

Оптимизированное решение на Java дополняет ячейки само: переводит число
в строку через `Integer.toString` и ставит перед ним пробелы до
4 символов вместо вызова `String.format`, который для каждой ячейки
создаёт новый форматировщик и разбирает шаблон. В числе до 999 не больше
трёх цифр, так что перед каждой ячейкой встаёт хотя бы один пробел:
{1506_implementation_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1506_implementation_optimized.cpp`: сокращение времени +0.00%;
  сокращение памяти +48.98%; база: `1506_implementation.cpp`.

- `1506_implementation_optimized.java`: сокращение времени +14.68%;
  сокращение памяти +56.56%; база: `1506_implementation.java`.

`1506_implementation_optimized.rs`. Не более 100 значений хранятся в одном фиксированном массиве u16, выбираются по индексу столбца и строки, нужные пробелы выводятся напрямую. Нет строк для отдельных чисел, склеенных строк таблицы и построителя всего ответа. Время O(N), память ограничена фиксированным массивом и состоянием вывода числа. Rust использует среду выполнения C для ввода-вывода, без целых декодированных строк String и форматирования Rust. Простой принятый исходник сохранён без изменений.

По сравнению с `1506_implementation.rs`: время 0.015 s → 0.031 s; память 252 KB → 52 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Прежнее сравнение PyPy: `1506_implementation_optimized.py`: место по времени 279/291, по памяти 2/291 в этой сопоставимой выборке.

`1506_implementation_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
