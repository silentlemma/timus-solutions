# 1506. Столбцы чисел

## Задача

Нужно напечатать N чисел от 0 до 999 (1 ≤ N ≤ 100) в K столбцов
(1 ≤ K ≤ N) с наименьшим числом строк. Все столбцы одной высоты, кроме
последнего, который может быть короче. Числа заполняют первый столбец
сверху вниз, затем второй и так далее. Каждое число выровнено по
правому краю в поле из 4 символов, концевых пробелов в строках нет.
Гарантируется, что таблица ровно с K непустыми столбцами существует.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и K, затем N чисел.

## Выходные данные

Таблица.

## Примеры

### Пример 1

Ввод:

```
7 3
1 2 30 40 50 600 700
```

Вывод:

```
   1  40 700
   2  50
  30 600
```

## Решение

Наименьшее число строк — H = ⌈N / K⌉. Любая допустимая высота h
удовлетворяет h ≥ H и (K − 1)·h < N. Поэтому из гарантии существования
следует (K − 1)·H < N: при высоте H последний столбец непуст.
В столбце c стоят числа с
индексами от c·H до c·H + H − 1, поэтому строка r состоит из
существующих чисел c·H + r для c = 0, 1, …; они кончаются на первом
исчерпанном столбце, а это может быть только последний. Каждое число
печатаем в поле из 4 символов и на этом заканчиваем строку. `O(N)`.

Подводные камни:

- числа идут вниз по столбцам, а не вдоль строк (тест 01);
- каждое число занимает 4 символа, и первое тоже, поэтому каждая
  строка начинается с пробелов (тест 01);
- если последний столбец короче, нижние строки заканчиваются на число
  раньше, без концевых пробелов (тест 06);
- гарантия существования существенна: последний столбец содержит хотя
  бы одно число (тест 06); не любая пара с 1 ≤ K ≤ N допустима;
- при K = N получается одна строка, при K = 1 — один столбец
  (тесты 03, 04).

## Оптимизированные решения

Оптимизированное решение на C++ хранит числа в массиве фиксированного
размера на 100 `int` на стеке вместо `std::vector`, ведь N ≤ 100, так
что программа ничего не выделяет в куче:
{1506_implementation_optimized.cpp}.

Оптимизированное решение на Java дополняет ячейки само: переводит число
в строку через `Integer.toString` и ставит перед ним пробелы до
4 символов вместо вызова `String.format`, который для каждой ячейки
создаёт новый форматировщик и разбирает шаблон. В числе до 999 не больше
трёх цифр, так что перед каждой ячейкой встаёт хотя бы один пробел:
{1506_implementation_optimized.java}.
