# 1515. Финансовая реформа

[Timus 1515](https://acm.timus.ru/problem.aspx?space=1&num=1515) · сложность 215 · greedy

Авторы оригинальной задачи — Илья Гребнов, Никита Рыбак и Дмитрий Ковалёв; Timus Top Coders: Third Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть по одной банкноте каждого из N номиналов (1 ≤ N ≤ 100), данных в
порядке возрастания, каждый от 1 до 10⁶. Нужно найти наименьшее
положительное число, которое не является суммой каких-то из этих
банкнот; одна банкнота тоже считается суммой.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N номиналов в порядке возрастания.

## Выходные данные

Наименьшее число, которое не набирается никаким набором банкнот.

## Проверка

Сравниваются точные целые токены. Новые исходники имеют собственные полные проверки целевой среды и Accepted; прежние опубликованные базы сохраняют свои собственные Accepted, а не старые архивные метрики.

## Примеры

### Пример 1

Ввод:

```
5
1 2 4 9 100
```

Вывод:

```
8
```

## Решение

Идём по номиналам в порядке возрастания и храним reach — наибольшее
число, такое что любую сумму от 1 до reach можно набрать. Если
следующий номинал d не больше reach + 1, то набирается и любая сумма до
reach + d: суммы до reach — как раньше, а большие — как d плюс сумма до
reach. Если d > reach + 1, то reach + 1 набрать нельзя: взятые номиналы
дают в сумме лишь reach, а любой другой номинал сам по себе больше
reach + 1. Ответ — reach + 1. Вход уже отсортирован, поэтому дополнительная сортировка не нужна.
Время — `O(N)`, жадный алгоритм хранит `O(1)` дополнительного состояния.
C++, Go и Java читают номиналы потоком; Python и Rust также сохраняют
входные данные, занимая `O(N)` памяти.

Подводные камни:

- заданный порядок возрастания важен для жадного доказательства;
  повторная сортировка не нужна (в тестах 05, 06 N = 100);
- без банкноты в 1 ответ равен 1 (тесты 03, 06);
- ответ может быть больше любого номинала, вплоть до суммы всех плюс
  один (тесты 04, 05, gen2);
- первый пропуск заканчивает проход, и никакой следующий номинал его
  не закроет: при 1 и 3 нельзя набрать 2 (тест 07).

## Оптимизированные решения

Все пять учебных версий используют линейный жадный проход по уже отсортированному вводу. Если достижимы все суммы до `reach`, купюра номиналом не выше `reach + 1` расширяет этот диапазон до `reach + note`. Купюра большего номинала оставляет первый пропуск недостижимым, поэтому проход на ней заканчивается. Компактная версия на Python сохраняет тот же инвариант и сразу выводит ответ. Посылка на PyPy получила Accepted и использовала 244 КБ против 352 КБ у принятой учебной версии, на 30,7% меньше. Время выросло с 0,093 до 0,125 с.

- `1515_greedy_optimized.py`: 0.125 s / 244 KB; база `1515_greedy.py`: 0.093 s / 352 KB; изменение относительно базы: время +34.4%, память -30.7%.
