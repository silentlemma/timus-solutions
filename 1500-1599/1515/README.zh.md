# 1515. 财政改革

[Timus 1515](https://acm.timus.ru/problem.aspx?space=1&num=1515) · 难度 215 · greedy

原题作者 Ilya Grebnov、Nikita Rybak 与 Dmitry Kovalioff，出自 Timus Top Coders: Third Challenge。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

N 种面值（1 ≤ N ≤ 100）的钞票各有一张，按递增顺序给出，每种在 1 到 10⁶ 之间。求不能
由其中某些钞票相加得到的最小正整数；单独一张钞票也算一种和。

时间限制：1 秒。内存限制：64 MB。

## 输入

N，然后是按递增顺序的 N 个面值。

## 输出

任何一组钞票都凑不出的最小数。

## 评测方式

精确比较整数词元。新源码各有完整目标环境测试及自身Accepted；保留的已发布基础使用其自身Accepted，不借用旧存档测量。

## 样例

### 样例 1

输入:

```
5
1 2 4 9 100
```

输出:

```
8
```

## 解法

按递增顺序处理面值，维护 reach：1 到 reach 的每个数都能凑出的最大数。如果下一个面
值 d 不超过 reach + 1，那么 reach + d 以内的每个数也都能凑出：不超过 reach 的照旧，
更大的用 d 加上一个不超过 reach 的和。如果 d > reach + 1，reach + 1 就凑不出：已处
理的面值总和只有 reach，而其他每个面值本身就大于 reach + 1。答案是 reach + 1。
输入已按递增顺序给出，无须再次排序。时间为 `O(N)`，贪心只维护 `O(1)` 的额外状态。C++、Go 和 Java 流式读取面值；Python 和 Rust 还保存输入，因此使用 `O(N)` 内存。

注意事项：

- 输入的递增顺序是贪心证明的前提，无须再次排序（测试 05、06 的 N = 100）；
- 没有面值为 1 的钞票时答案是 1（测试 03、06）；
- 答案可以比所有面值都大，最大为全部面值之和加一（测试 04、05、gen2）；
- 第一个空缺出现时就可以停止，后面的面值都填不上它：有 1 和 3 时凑不出 2（测试
  07）。

## 优化解法

五种教学版本均对已经排好序的输入进行线性贪心扫描。若不超过 `reach` 的金额都能凑出，面额不超过 `reach + 1` 的纸币可把该范围扩展到 `reach + note`。若下一张纸币面额更大，第一个缺口无法填补，因此扫描在此结束。精简的 Python 版本保留这一不变量并直接输出答案。通过评测的 PyPy 提交使用 244 KB，教学版使用 352 KB，内存减少 30.7%。耗时从 0.093 秒升至 0.125 秒。

- `1515_greedy_optimized.py`: 0.125 s / 244 KB; 基础 `1515_greedy.py`: 0.093 s / 352 KB; 相对变化: 时间 +34.4%, 内存 -30.7%.
