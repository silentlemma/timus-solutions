# 1535. Хоббит, или Туда и обратно

[Timus 1535](https://acm.timus.ru/problem.aspx?space=1&num=1535) · сложность 497 · constructive

Автор оригинальной задачи — Александр Ипатов; Восьмое открытое личное первенство УрГУ, 3 марта 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Бильбо выходит из города 1, по разу посещает каждый из городов 2 … N и
возвращается в город 1 (2 ≤ N ≤ 50000). Вход в город P из города Q
стоит P·Q золотых. Нужно вывести порядок посещения с наименьшей
суммарной платой и порядок с наибольшей.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N.

## Выходные данные

Две строки по N чисел, начиная с 1: самый дешёвый порядок и самый
дорогой. Подходят любые оптимальные порядки.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
1 4 2 3
1 3 4 2
```

## Решение

Стоимость циклического порядка — сумма произведений соседей,
включая замыкающее ребро к городу 1. Положим D(i,j)=N²−ij.
Матрица неотрицательна и симметрична. При i<j<k<l

(Dᵢⱼ+Dₖₗ)−(Dᵢₖ+Dⱼₗ)=(k−j)(i−l)<0,

(Dᵢₖ+Dⱼₗ)−(Dᵢₗ+Dⱼₖ)=(j−i)(k−l)<0.

Это неравенства Супника. Минимальный D-цикл перечисляет нечётные метки
по возрастанию, затем чётные по убыванию. Максимальный D-цикл состоит
из двух чередующихся ветвей. Стоимость D-цикла равна N³ минус исходная
сумма произведений, поэтому первый цикл максимизирует эту сумму,
а второй минимизирует. [Теоремы об экстремальных циклах](https://doi.org/10.1016/S0166-218X(99)00148-1)

Для максимальной суммы выводим 1, 3, 5, … по возрастанию, затем чётные
по убыванию до 2. Для минимума начинаем с N и берём q=⌊(N−1)/2⌋.
При k=1…q одна ветвь берёт aₖ=k+1 для нечётного k и N−k для
чётного; другая — bₖ=k для нечётного и N−k+1 для чётного.
Соединяем N,a₁,…,a_q, единственную неиспользованную середину
при чётном N, затем b_q,…,b₁. Середина при чётном N равна 2⌊N/4⌋+1.
Поворачиваем цикл к началу в 1. Обратное чтение даёт максимальный
D-цикл 1, N−1, 3, N−3, …, N−2, 2, N и доказывает минимум исходной
стоимости. При N=2 и N=3
единственный неориентированный набор рёбер даёт ответ сразу.

Простые программы хранят ветви и поворачивают собранный цикл за O(N)
времени и с O(N) дополнительной памяти. Быстрые версии
вычисляют те же индексы напрямую и используют ограниченные буферы.

Обе строки начинаются с 1. Учитываем замыкающее ребро в стоимости
и выводим каждый город один раз.

## Оптимизированные решения

C++, Go и Rust вычисляют прежний цикл по индексам вместо хранения посещённости, двух ветвей, цикла, поворота и строк. Пусть q=⌊(N−1)/2⌋. Выводим 1,N, затем aₖ=k+1 при нечётном k и N−k при чётном, k=1…q. Для чётного N>2 единственная неиспользованная середина равна 2⌊N/4⌋+1. Завершаем bₖ=k при нечётном k и N−k+1 при чётном в порядке k=q…2: b₁=1 уже стоит первым. При N=2 ответ 1,2. Это прежняя конструкция двух ветвей без их хранения. Максимальный порядок по-прежнему выводит нечётные вверх, чётные вниз. Блок 8192 байта даёт время O(N) и дополнительную память O(1). Простые исходники сохранены; Java/Python используют подходящие базы. Независимая точная DP по подмножествам проверяет оба оптимума до N=14 как регрессионные тесты; общее обоснование дано сведением к теоремам Супника в простом решении.

Принятая версия Rust 1.75 x64 заняла 0.046 с при 0.031 с у базовой и использовала 232 KB при 4376 KB у базовой.

Принятые базовые реализации [1535_constructive.java](1535_constructive.java), [1535_constructive.py](1535_constructive.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
