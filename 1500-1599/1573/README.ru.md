# 1573. Алхимия

[Timus 1573](https://acm.timus.ru/problem.aspx?space=1&num=1573) · сложность 108 · math

Автор оригинальной задачи — Александр Ипатов; XIV открытое командное первенство школьников Свердловской области по программированию, октябрь 2007 года.

## Задача

У Сандро три мешка разных реагентов: B синих, R красных и Y жёлтых
(по 1 … 100). Для зелья нужно по одному реагенту каждого цвета из
рецепта, все цвета разные. Нужно посчитать наборы реагентов, из которых
можно сделать зелье.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

B, R и Y, затем положительное K и K различных цветов рецепта (Blue, Red
или Yellow).

## Выходные данные

Число способов.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
2 3 5
3
Red
Yellow
Blue
```

Вывод:

```
30
```

## Решение

Каждый цвет рецепта берёт один реагент из своего мешка, и выборы
независимы, так что ответ — произведение размеров мешков, названных в
рецепте. Он не больше 100³ = 10⁶. `O(K)`.

Подводные камни:

- мешки во входе идут как синий, красный, жёлтый, а рецепт в примере
  начинается с красного;
- считаются только цвета из рецепта (тесты 02, 03).

## Оптимизированные решения

`1573_math_optimized.java`. Сохраняется произведение независимых вариантов из различных требуемых мешков. Первые буквы B/R/Y однозначно задают обещанные Blue/Red/Yellow; остальные символы пропускаются без строк рецепта. Буфер ввода 1024 байта и прямой числовой вывод уменьшают накладные расходы. Не более трёх множителей до 100 помещаются в int; O(K) работы для K цветов и фиксированная дополнительная память. Комбинаторное доказательство и простая версия сохранены.

Accepted точного исходника Java 1.8 №11327456: 0.093 с / 344 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 12/82, память 2/82. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11304267: 0.109 с / 328 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1573_math_optimized.java`: 0.093 s / 344 KB; сохранённая учебная база `1573_math.java`: 0.125 s / 1628 KB.

Оптимизированное решение на C++ читает через `scanf` вместо `iostream` и
выбирает мешок по первой букве цвета, ведь Blue, Red и Yellow начинаются
с разных букв, вместо поиска названия в `std::map` со строковыми
ключами. Цвет читается в буфер на 7 байт, которого хватает для самого
длинного названия, Yellow, а произведение хранится в `int`, которого
хватает, ведь оно не больше 10⁶: {1573_math_optimized.cpp}.

Оптимизированное решение на Rust держит размеры трёх мешков в трёх
переменных и выбирает нужный через `match` по названию цвета вместо
построения `HashMap`: {1573_math_optimized.rs}.

Каждая оптимизированная версия имеет Accepted и сокращает время или

Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1573_math_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +69.23%; база: `1573_math.cpp`.

- `1573_math_optimized.rs`: сокращение времени -206.67%; сокращение
  памяти +45.10%; база: `1573_math.rs`.

`1573_math_optimized.py`. Сохраняется произведение количеств реагентов для разных цветов рецепта. Три байтовых ASCII-имени Blue, Red, Yellow сопоставляются целым количествам напрямую, без декодирования ввода и текстовых ключей. Выполняется O(K) умножений, хранится O(K) токенов, при K<=3 и произведении не больше 10^6. Меняются представление и накладные расходы, а не комбинаторное правило. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1573_math.py`: время 0.078 s → 0.109 s; память 452 KB → 232 KB.
