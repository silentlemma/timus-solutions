# 1573. Алхимия

## Задача

У Сандро три мешка разных реагентов: B синих, R красных и Y жёлтых
(по 1 … 100). Для зелья нужно по одному реагенту каждого цвета из
рецепта, все цвета разные. Нужно посчитать наборы реагентов, из которых
можно сделать зелье.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

B, R и Y, затем положительное K и K различных цветов рецепта (Blue, Red
или Yellow).

## Выходные данные

Число способов.

## Примеры

### Пример 1

Ввод:

```
2 3 5
3
Red
Yellow
Blue
```

Вывод:

```
30
```

## Решение

Каждый цвет рецепта берёт один реагент из своего мешка, и выборы
независимы, так что ответ — произведение размеров мешков, названных в
рецепте. Он не больше 100³ = 10⁶. `O(K)`.

Подводные камни:

- мешки во входе идут как синий, красный, жёлтый, а рецепт в примере
  начинается с красного;
- считаются только цвета из рецепта (тесты 02, 03).

## Оптимизированные решения

Оптимизированное решение на C++ читает через `scanf` вместо `iostream` и
выбирает мешок по первой букве цвета, ведь Blue, Red и Yellow начинаются
с разных букв, вместо поиска названия в `std::map` со строковыми
ключами. Цвет читается в буфер на 7 байт, которого хватает для самого
длинного названия, Yellow, а произведение хранится в `int`, которого
хватает, ведь оно не больше 10⁶: {1573_math_optimized.cpp}.

Оптимизированное решение на Java разбирает числа по цифрам прямо из
`System.in` вместо создания `Scanner` и выбирает мешок по первой букве
цвета, пропуская остаток слова, ведь Blue, Red и Yellow начинаются с
разных букв, вместо поиска названия в `HashMap` с упакованными
значениями `Long`. Произведение хранится в `int`, которого хватает, ведь
оно не больше 10⁶: {1573_math_optimized.java}.

Оптимизированное решение на Rust держит размеры трёх мешков в трёх
переменных и выбирает нужный через `match` по названию цвета вместо
построения `HashMap`: {1573_math_optimized.rs}.
