# 1599. Число оборотов

[Timus 1599](https://acm.timus.ru/problem.aspx?space=1&num=1599) · сложность 1732 · geometry

Автор оригинальной задачи — Владимир Яковлев.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Замкнутая железная дорога идёт через n узлов (3 ≤ n ≤ 5000) по прямым
путям, которые могут пересекаться и накладываться. Для каждой из m точек
наблюдения (1 ≤ m ≤ 5000) нужно вывести `EDGE`, если точка лежит на пути, а
иначе — сколько полных оборотов против часовой стрелки сделает тот, кто
следит за поездом за один его круг: число оборотов кривой вокруг точки.
Координаты — целые числа до 10⁹ по модулю.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

В первой строке задано n, затем в n строках — координаты узлов x y
в порядке движения. Пути соединяют соседние узлы, а последний — с
первым. Далее задано m, затем в m строках — координаты точек наблюдения x y.

## Выходные данные

Для каждой точки в отдельной строке вывести `EDGE` или число оборотов
со знаком: положительное против часовой стрелки, отрицательное — по часовой.

## Примеры

### Пример 1

Ввод:

```
8
-2 -2
-5 1
-2 4
1 3
-2 0
-3 1
-2 2
1 1
3
-2 1
0 0
1 2
```

Вывод:

```
-2
EDGE
0
```

## Решение

Посмотрим вдоль луча из точки вправо. Каждый раз, когда поезд пересекает
его вверх, он проходит мимо точки против часовой стрелки, а вниз — по
часовой. Значит, число оборотов — это число путей, пересекающих луч
вверх, минус пересекающих его вниз. Путь из a в b пересекает луч вверх,
если a.y ≤ p.y < b.y и точка лежит слева от него, то есть
cross(b − a, p − a) > 0, и вниз, если b.y ≤ p.y < a.y и точка справа.
Если учитывать нижний конец каждого пути, но не верхний, пересечение
через узел считается один раз; при касании вклады сокращаются или оба
не учитываются. Горизонтальные пути не вносят вклад в сумму оборотов.

Точка лежит на пути, если векторное произведение равно 0 и точка внутри
ограничивающего прямоугольника пути. Для каждой точки перебираем пути,
проверяя это условие перед подсчётом пересечений; при совпадении
останавливаемся и выводим `EDGE`. Иначе после перебора выводим сумму.
Время в худшем случае — `O(n·m)`, не более 2,5·10⁷ проверок путей
только в целых числах.

Результаты сверены с суммированием углов поворота через atan2 на
небольших маршрутах, включая маршруты через строки точек и маршруты туда
и обратно.

Подводные камни:

- модуль векторного произведения не превышает (2·10⁹)² = 4·10¹⁸, что
  меньше максимума знакового 64-битного целого 2⁶³ − 1; 32 бит недостаточно;
- в узлах на луче пересечения считаются один раз, а касания дают
  нулевой суммарный вклад; это обеспечивают полуоткрытые проверки по y,
  а горизонтальные пути важны только для `EDGE`;
- проходы одного пути в противоположных направлениях сокращаются в
  сумме оборотов, а пути нулевой длины дают нулевой вклад; в обоих
  случаях всё равно нужна проверка `EDGE`.

## Особенности языков

- Python запускается в PyPy, заранее строит кортежи рёбер и использует
  целые произвольной точности. C++, Go, Java и Rust получают следующий
  конец пути по индексу и выполняют геометрические вычисления в
  знаковых 64-битных целых.
- Java читает числа через `StreamTokenizer` как double, где все
  допустимые целые координаты представляются точно, затем переводит
  их в `long` перед геометрическими вычислениями.
