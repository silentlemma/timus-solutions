# 1517. Самая длинная общая подстрока

[Timus 1517](https://acm.timus.ru/problem.aspx?space=1&num=1517) · сложность 240 · suffix_structures

Авторы оригинальной задачи — Илья Гребнов, Никита Рыбак и Дмитрий Ковалёв; Timus Top Coders: Third Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны две строки из заглавных латинских букв длины `N` каждая, `1 ≤ N ≤ 100000`. Выведите любую самую длинную строку, входящую в обе как непрерывная подстрока. Если общей буквы нет, выведите пустую строку. Лимит времени: 2 секунды. Память: 64 МБ.

## Входные данные

Число `N`, затем первая и вторая строки на отдельных строках ввода.

## Выходные данные

Одна наибольшая общая подстрока; при нулевой длине — пустая строка.

## Проверка

Принимается любая наибольшая общая подстрока. Проверяются вхождение в обе строки и максимальность длины; при нескольких ответах совпадение с примером не требуется.

## Примеры

### Пример 1

Ввод:

```
28
VOTEFORTHEGREATALBANIAFORYOU
CHOOSETHEGREATALBANIANFUTURE
```

Вывод:

```
THEGREATALBANIA
```

## Решение

Построим суффиксный автомат первой строки. Состояние объединяет подстроки
с одинаковыми позициями окончаний и хранит максимальную длину, суффиксную
ссылку и переходы по буквам. При расширении создаётся новое состояние;
если переход ведёт в класс с избыточной длиной, класс разделяется клоном,
а затронутые переходы перенаправляются.

Просматриваем вторую строку, поддерживая наибольший суффикс уже прочитанного
префикса, встречающийся в первой строке. Если перехода нет, идём по
суффиксным ссылкам и уменьшаем длину, пока переход не появится или не будет
достигнут корень. Если переход существует, выполняем его. Максимальная
длина и позиция её окончания задают ответ. Каждая общая подстрока является
суффиксом некоторого просмотренного префикса, поэтому найденный максимум
оптимален. Переход по ссылке уменьшает длину, чтение буквы увеличивает её
не более чем на один; суммарный просмотр линеен.

Состояний и переходов `O(N)`. При фиксированном алфавите из 26 букв
построение и поиск требуют `O(N)` времени и памяти. Простые нативные версии
хранят полные строки переходов, Python — словари. Все пять понятных
исходников сохранены без изменений.

## Оптимизированные решения

`1517_suffix_structures_optimized.py`. Сохраняется суффиксный автомат, но для не более 2N+1 состояний выделяется плотная строка из 26 знаковых 32-битных индексов переходов; длины и суффиксные ссылки также в упакованных массивах. Клон копирует свою строку до перенаправления ссылок. Исчезают поиск по списку рёбер и словари Python, зато резервируются все 26 переходов состояния. Вторая строка сканируется с откатами по суффиксным ссылкам; выводится любая наибольшая общая подстрока. При длинах N и M время O(26N+M), состояние O(26N) плюс две входные строки. Учебная версия со словарями сохранена.

Accepted точного исходника PyPy 3.10 №11326700: 0.234 с / 25000 КБ. Сохранённая выборка актуальных компиляторов от 2026-11-20: место по времени 1/32, по памяти 9/32. Обе обязательные метрики проходят строгий критерий первых десяти мест или топ 15%, процентная граница округляется вверх. Звёздочка относится к отдельной цели Python — первому месту по обеим метрикам.

Прежняя документированная оптимизированная посылка №11308173 (Python 3.12 x64) имела 1.312 с / 9736 КБ. У текущего запуска PyPy 3.10 зафиксированы меньшее время и большая память. Это разные парные измерения судьи; сравнение включает выбор интерпретатора и разброс запусков.

- `1517_suffix_structures_optimized.py`: 0.234 s / 25000 KB; сохранённая учебная база `1517_suffix_structures.py` (Python 3.12 x64): 0.5 s / 56240 KB.

Оптимизированные C++, Go, Java и Rust хранят разреженные массивы переходов: голову у состояния, букву, конец и индекс следующего ребра у дуги. Поиск просматривает до 26 рёбер; клон копирует собственный список до перенаправлений. При N<=100000 индексы и длины помещаются в 32 бита. Для этих четырёх версий работа и память O(N) при фиксированном алфавите с меньшей константой памяти. Их прежние Accepted и сравнение от 2 ноября 2026 года сохранены в таблице; у Go записано 0.078 с против 0.046 с базы — компромисс времени и памяти.

Зафиксированное сокращение памяти относительно баз таблицы: C++ 82.9%, Go 70.6%, Java 81.1%, Python 55.5%, Rust 81.0%.
