# 1517. Самая длинная общая подстрока

[Timus 1517](https://acm.timus.ru/problem.aspx?space=1&num=1517) · сложность 240 · suffix_structures

Авторы оригинальной задачи — Илья Гребнов, Никита Рыбак и Дмитрий Ковалёв; Timus Top Coders: Third Challenge.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны две строки из заглавных латинских букв длины `N` каждая, `1 ≤ N ≤ 100000`. Выведите любую самую длинную строку, входящую в обе как непрерывная подстрока. Если общей буквы нет, выведите пустую строку. Лимит времени: 2 секунды. Память: 64 МБ.

## Входные данные

Число `N`, затем первая и вторая строки на отдельных строках ввода.

## Выходные данные

Одна наибольшая общая подстрока; при нулевой длине — пустая строка.

## Проверка

Принимается любая наибольшая общая подстрока. Проверяются вхождение в обе строки и максимальность длины; при нескольких ответах совпадение с примером не требуется.

## Примеры

### Пример 1

Ввод:

```
28
VOTEFORTHEGREATALBANIAFORYOU
CHOOSETHEGREATALBANIANFUTURE
```

Вывод:

```
THEGREATALBANIA
```

## Решение

Построим суффиксный автомат первой строки. Состояние объединяет подстроки
с одинаковыми позициями окончаний и хранит максимальную длину, суффиксную
ссылку и переходы по буквам. При расширении создаётся новое состояние;
если переход ведёт в класс с избыточной длиной, класс разделяется клоном,
а затронутые переходы перенаправляются.

Просматриваем вторую строку, поддерживая наибольший суффикс уже прочитанного
префикса, встречающийся в первой строке. Если перехода нет, идём по
суффиксным ссылкам и уменьшаем длину, пока переход не появится или не будет
достигнут корень. Если переход существует, выполняем его. Максимальная
длина и позиция её окончания задают ответ. Каждая общая подстрока является
суффиксом некоторого просмотренного префикса, поэтому найденный максимум
оптимален. Переход по ссылке уменьшает длину, чтение буквы увеличивает её
не более чем на один; суммарный просмотр линеен.

Состояний и переходов `O(N)`. При фиксированном алфавите из 26 букв
построение и поиск требуют `O(N)` времени и памяти. Простые нативные версии
хранят полные строки переходов, Python — словари. Все пять понятных
исходников сохранены без изменений.

## Оптимизированные решения

Оптимизированные программы хранят только существующие переходы в плоских
массивах: у состояния есть индекс головы списка, у ребра — буква, конец
и индекс следующего ребра. Поиск просматривает не более 26 рёбер.
Клон получает собственную копию списка, чтобы последующие перенаправления
не меняли исходное состояние. При `N ≤ 100000` индексы и длины помещаются
в 32 бита; Python использует упакованные целочисленные массивы и bytearray
для букв.

Полные строки из 26 переходов и объекты словарей больше не нужны;
инвариант суффиксного автомата сохраняется. Время остаётся `O(N)` для
фиксированного алфавита, но поиск перехода имеет большую константу.
Память — `O(N)` с гораздо меньшей константой. Это прежде всего экономия памяти.

Измеренное сокращение памяти относительно неизменённых принятых баз: C++ — 82.9%, Go — 70.6%, Java — 81.1%, Python — 82.7%, Rust — 81.0%. Все пять проходят порог по памяти. Python медленнее: 1,312 с против 0,500 с, зато память снижена с 56240 до 9736 КБ. Go также медленнее: 0,078 с против 0,046 с. Это принятый компромисс времени и памяти, а не универсальное ускорение. Рейтинговый срез — 2 ноября 2026 года; звёздочка означает недостигнутую рейтинговую цель.

## Особенности языков

Python проверен на 5760 парах против независимой квадратичной DP наибольшей
общей подстроки. Разреженный граф дополнительно проверен на строках длины
100000 над алфавитами из 1, 2 и 26 букв. Каждая из пяти реальных программ
перед отправкой прошла 13 тестовых входов репозитория в Docker.
Локальные проверки дополняют отдельные подтверждённые посылки Accepted.
