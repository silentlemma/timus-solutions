# 1511. 税务操作

[Timus 1511](https://acm.timus.ru/problem.aspx?space=1&num=1511) · 难度 1212 · dp

原题作者 Nikita Rybak、Ilya Grebnov 与 Dmitry Kovalioff，出自 Timus Top Coders: Third Challenge。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一份报税单写着三个正整数 A、B、C（都小于 10¹⁰⁰⁰），但 A + B ≠ C。可以把一个数字换成
另一个数字，罚款为两个数字之差的绝对值；数的长度不能改变，首位也不能变成 0。求使
A + B = C 的最小总罚款，无解时输出 -1。

时间限制：1 秒。内存限制：64 MB。

## 输入

A、B、C，各占一行。

## 输出

最小总罚款，或 -1。

## 样例

### 样例 1

输入:

```
123
554
345
```

输出:

```
8
```

## 解法

A 和 B 不能比 C 长，否则它们的和也会更长。否则就像竖式加法那样从最低位逐列相加，以
进位为状态：cost[carry] 表示已处理各列的最便宜改法，且向上传出这个进位。在每一列枚举
A 的数字 x 和 B 的数字 y（超出数的长度只能是 0，首位不能是 0）；于是 C 的数字为
(x + y + carry) mod 10，在 C 的首位不能为 0，罚款是三个差之和。答案是处理完 C 的最
后一列后的 cost[0]。每列至多 2 · 100 个转移，`O(len(C))`，常数为 200。

注意事项：

- 首位不能变成 0，所以 1 + 1 = 1 只能把 C 改成 2（测试 02）；
- C 比 A 短，或比任何和都长两位，答案为 -1（测试 03、04、gen3）；
- C 多一位时，A 和 B 的最高几列必须产生进位（测试 06、gen2）；
- 数最多有 1000 位，所以按数字串处理（gen1、gen5）。
