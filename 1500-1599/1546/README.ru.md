# 1546. Сортировка по-японски

[Timus 1546](https://acm.timus.ru/problem.aspx?space=1&num=1546) · сложность 887 · sorting

Автор оригинальной задачи — Владимир Яковлев; XI командный студенческий чемпионат Урала по программированию, Екатеринбург, 21 апреля 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно отсортировать строки из строчных букв и цифр (всего не больше 100
КБ) в «японском» порядке, где числа внутри строк сравниваются по
значению: photox2 идёт раньше photox10. Условие не излагает правила
полностью; оно предлагает программу, сортирующую небольшие входы.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Строки, по одной в строке.

## Выходные данные

Те же строки в японском порядке.

## Примеры

### Пример 1

Ввод:

```
photox10
photox1
photo2
photox2
```

Вывод:

```
photo2
photox1
photox2
photox10
```

## Решение

Правила — это естественная сортировка, как в файловом менеджере, а
подробности ниже совпадают с программой из условия в том виде, в каком
её выводы приводятся на форуме судьи:

- строка разбивается на буквы и максимальные отрезки цифр;
- сравнение идёт по кускам: число раньше буквы, числа сравниваются по
  значению (по длине без ведущих нулей, затем по цифрам, ведь они бывают
  очень длинными), буквы по коду;
- строка, которая кончается раньше, идёт первой;
- только если все куски равны, сравниваются ведущие нули чисел, отрезок
  за отрезком, и больше нулей идёт раньше: 000 < 00 < 0, a001 < a01 и
  01w01 < 01w1.

Каждая строка получает ключ: список кусков и список нулей со знаком
минус; устойчивая сортировка по ключу делает остальное.
`O(L log n)` для общей длины L.

Подводные камни:

- нули только разрешают ничьи: z001pp00 идёт после z0pp01 (тест 02);
- строка из нулей — это число, и 000 идёт раньше 0 (тест 03);
- числа бывают больше 64 бит (тест 04);
- цифры раньше букв: 1, 2, 10, a, a1, aa (тест 06).
