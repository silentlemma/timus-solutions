# 1555. Найди сокровище!

[Timus 1555](https://acm.timus.ru/problem.aspx?space=1&num=1555) · сложность 7392 · games

Оригинальная задача — Novosibirsk SU Contest, Петрозаводские сборы, сентябрь 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Двое ходят по очереди в лабиринте N × N (2 ≤ N ≤ 6, не больше 30 стен; у
клетки может быть стена с любой стороны, так что между соседями бывает
две стены). Ход — шаг на свободную соседнюю клетку не через стену,
пропуск или выстрел единственной ракетой игрока: на север, восток, юг,
запад или вниз. Ракета летит, пока не покинет поле, не ударит в стену
(та разрушается) или в другого игрока (тот погибает); ракета, пущенная
вниз, убивает стрелявшего. Погибший проигрывает; игрок, наступивший на
сундук, может ещё выиграть, покинув поле. Без сундука покидать поле
нельзя. Оба играют оптимально.
Выведите `Draw` либо `Win` или `Lose` для первого игрока с числом
ходов (первый игрок его уменьшает, второй увеличивает) и первый ход
первого игрока: `M` или `S` с направлением по цифровой клавиатуре (8 —
север, 6 — восток, 2 — юг, 4 — запад, 5 — пропуск или вниз).

Ограничение времени: 5 секунд. Ограничение памяти: 64 МБ.

## Входные данные

N, затем 3N строк по 3N символов: каждая клетка — квадрат 3 × 3 со
стенами `-` и `|` в серединах сторон и `1`, `2`, `*` или пробелом в
центре. Цифры обозначают игроков, а `*` — сундук; каждый из символов
`1`, `2` и `*` встречается ровно один раз. Север находится сверху.
Только в примерах пробелы для наглядности заменены точками.

## Выходные данные

`Draw` в одной строке либо `Win`/`Lose` и число ходов через пробел в
первой строке, а первый ход — во второй. В записи хода `M` означает
перемещение (или пропуск), а `S` — выстрел.

## Примеры

### Пример 1

Ввод:

```
3
.-..-..-.
|1....|2|
.........
.........
|*|.....|
.........
.........
|.......|
.-..-..-.
```

Вывод:

```
Win 5
M2
```

### Пример 2

Ввод:

```
2
.-..-.
|2..*|
.-....
.-....
|1||.|
.-..-.
```

Вывод:

```
Lose 1
S5
```

## Решение

Ретроградный анализ. Позиция — две клетки, кто держит сундук и чей
ход; сверх того каждая ракета либо заряжена, либо улетела за поле, либо
потрачена на стену w. Выстрел, не завершающий игру, ведёт только в
состояния ракет с меньшим числом заряженных, поэтому состояния ракет
решаются от «ни одной заряженной» до «обе заряжены», и каждое — граф
игры не более чем из 7 560 позиций, выстрелы из которого, не завершающие
игру, ведут в уже
решённые позиции.

Внутри состояния ракет результаты получаются обратной индукцией:
позиция выиграна, как только один ход выигрывает для ходящего,
проиграна, когда проигрывают все ходы, а оставшиеся неразрешёнными
позиции — ничья.
Число ходов затем считается проходом в духе Дейкстры с кучей (корзинами
в Python): позиция первого игрока берёт наименьшее число ходов среди
ходов, сохраняющих
результат, позиция второго — наибольшее, когда все такие ходы известны.
Первый ход — лучший по результату, затем по числу ходов, затем в
порядке M8, M6, M2, M4, M5, S8, S6, S2, S4, S5. Для W стен
S = W + 2 ≤ 32 — число состояний одной ракеты, а P = 6N²(N² − 1) —
число позиций для пары состояний ракет. Время четырёх компилируемых
решений — `O(S² · P log P)`, решения на Python — `O(S² · P)`.

Подводные камни:

- первый игрок уменьшает число ходов, даже проигрывая: во втором
  примере первый игрок сразу стреляет вниз (`Lose 1`);
- из двух стен между соседями ракета разрушает только первую
  встреченную, и разрушенная стена больше не появляется (тест 08);
- ракета, улетевшая за поле, просто тратится;
- с сундуком игрок покидает поле только через сторону без стены;
- позиции, оставшиеся неразрешёнными после ретроградного анализа, —
  ничья (тест 03).

Ответы сравнивались с независимой принятой реализацией на здешних
тестах и на 40 случайных лабиринтах, среди них поля 6 × 6 с 30 стенами.

## Особенности языков

- Решение на Python работает под PyPy и получило Accepted под PyPy
  3.10 x64 за 3,515 с при лимите 5 с, использовав 48 720 КБ. Прямой
  перенос работал около 20 с, поэтому оно устроено иначе, чем
  остальные четыре:
  - состояние ракет — это у кого ещё есть ракета и какие стены
    разрушены, так что состояния, различающиеся лишь тем, кто разрушил
    стену или какая ракета вылетела из лабиринта, делят одну таблицу
    (около 530 вместо примерно тысячи);
  - без ракет важны только открытые шаги и выходы, и состояния с
    одинаковыми шагами и выходами тоже делят таблицу;
  - ходы, не зависящие от стен, строятся один раз, каждый шаг вместе
    со стороной, через которую он идёт, так что состоянию остаётся
    отметить открытые стороны;
  - число ходов считается по списку корзин вместо кучи, потому что
    оно только растёт, а выигранные и проигранные позиции проходятся
    вместе за один раз.
- Остальные четыре решения хранят ходы и предшественников позиций в плоских
  массивах, общих для всех состояний ракет: выделение их заново для
  каждого из примерно тысячи состояний замедляло решения до двух раз.
