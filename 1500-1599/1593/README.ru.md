# 1593. Квадратная страна. Версия 2

[Timus 1593](https://acm.timus.ru/problem.aspx?space=1&num=1593) · сложность 725 · math

Оригинальную задачу подготовил Фёдор Меньшиков, особая благодарность Святославу Демидову.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Землю продают квадратными участками с положительной целой стороной, участок со
стороной a стоит a². Нужно потратить ровно N ≤ 10¹⁵ на как можно меньшее
число участков и вывести, сколько их понадобится. Это
[задача 1073](../../1000-1099/1073/README.ru.md) с гораздо большим N.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Положительное целое N, 1 ≤ N ≤ 10¹⁵.

## Выходные данные

Наименьшее число квадратов, дающих в сумме N.

## Примеры

### Пример 1

Ввод:

```
344
```

Вывод:

```
3
```

## Решение

По теореме Лагранжа любое N — сумма четырёх квадратов, так что ответ от
1 до 4, а какой именно, говорят классические теоремы:

- 1, если N — точный квадрат;
- 2, если каждое простое вида 4k + 3 входит в N в чётной степени
  (теорема Ферма о суммах двух квадратов);
- 4, если N = 4ᵃ(8b + 7) после удаления всех множителей 4 (теорема
  Лежандра о трёх квадратах);
- иначе 3.

Разложение N нужно только для проверки на два квадрата. В C++, Go, Java
и Rust хватает пробного деления на нечётные числа до √N, их не больше
примерно 1,6·10⁷; то, что останется в конце, — 1 или простое. В Python
такой цикл слишком медленный, поэтому малые делители до 1000 снимаются
пробным делением, а остаток раскладывается ρ-методом Полларда с тестом
Миллера — Рабина по первым двенадцати простым основаниям, который точен
далеко за пределами 10¹⁵.

Для Python сложность — ожидаемая оценка рандомизированного ρ-метода;
повторные попытки не дают детерминированной верхней границы времени.

Ответы сверены с динамикой по всем N до 20000.

Подводные камни:

- с квадратным корнем нужна аккуратность: вещественный корень числа
  около 10¹⁵ может ошибиться на единицу, поэтому он поправляется целыми
  шагами;
- произведение двух простых около √N, оба вида 4k + 3, не имеет малых
  делителей и даёт остаток 1 по модулю 4, так что остановить пробное
  деление на кубическом корне и угадывать остаток нельзя (тест 06);
- множитель, оставшийся после пробного деления, тоже нужно проверить:
  если N само простое вида 4k + 3, ничто не делит его до √N (тест 08);
  простое 2 не мешает никогда, так как 2 = 1 + 1.
- сгенерированные данные тоже должны удовлетворять N ≤ 10¹⁵: в режиме 2
  генератора нужно ограничить поиск простых, а в режиме 4 учесть +7 до
  умножения на 4ᵃ. Эти ошибки границ не затрагивают сохранённые номерные тесты.
