# 1534. Гондорский футбол

[Timus 1534](https://acm.timus.ru/problem.aspx?space=1&num=1534) · сложность 585 · math

Автор оригинальной задачи — Сергей Пупырев; Восьмое открытое личное первенство УрГУ, 3 марта 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Команда сыграла N матчей, забив всего K мячей и пропустив L
(0 ≤ K, L ≤ 10⁹, 1 ≤ N ≤ 10⁹). Победа даёт 3 очка, ничья — 1,
поражение — 0. Нужно найти наибольшее и наименьшее число очков, которое
могло быть у команды.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

K, L и N в одной строке.

## Выходные данные

Наибольшее и наименьшее число очков.

## Примеры

### Пример 1

Ввод:

```
3 2 2
```

Вывод:

```
4 3
```

### Пример 2

Ввод:

```
3 1 2
```

Вывод:

```
6 3
```

### Пример 3

Ввод:

```
3 0 4
```

Вывод:

```
10 6
```

### Пример 4

Ввод:

```
3 0 1
```

Вывод:

```
3 3
```

## Решение

При W победах и R поражениях у команды 3W + (N − W − R) = N + 2W − R
очков. Разделим голы каждого матча на равную часть, забитую обеими
сторонами, и разницу: равные части дают какое-то X ≥ 0 с обеих сторон,
разницы побед — K − X, разницы поражений — L − X, и каждой победе или
поражению нужна разница хотя бы в один гол. Равную часть можно
положить в любой матч. Значит, W побед и R поражений возможны ровно
тогда, когда

- W = R = 0 и K = L;
- R = 0, W ≥ 1 и K − L ≥ W (все L уходят в равную часть);
- W = 0, R ≥ 1 и L − K ≥ R;
- W ≥ 1, R ≥ 1, W ≤ K и R ≤ L, причём всегда W + R ≤ N.

Остаётся максимизировать и минимизировать N + 2W − R в каждом случае:
при d = K − L без поражений получается не больше N + 2·min(d, N) и не
меньше N + 2 (или N при d = 0); при d < 0 без побед — не больше N − 1
и не меньше N − min(−d, N); с победами и поражениями вместе — не больше
N − 1 + 2·min(K, N − 1) и не меньше N + 2 − min(L, N − 1), для этого
нужны K, L ≥ 1 и N ≥ 2. Ответ — лучшее по подходящим случаям. Значения
доходят до 3·10⁹, поэтому нужны 64-битные числа. `O(1)`.

Подводные камни:

- минимум может сочетать победы и поражения: в примере 1 победа и
  поражение дают 3 очка, меньше, чем победа и ничья;
- команда, забившая, но не пропустившая ни одного мяча, хотя бы раз
  победила, так что минимум — N + 2, а не N (тесты 03, 10);
- 1:1 в единственном матче — только ничья (тест 09);
- 3·10⁹ − 3 не помещается в 32-битные числа (тест 06).

## Оптимизированные решения

Java считывает три числа в буфер фиксированного размера и применяет те же формулы для очков. Посылка 11318275 заняла 0,109 с и использовала 480 КБ.

Rust вычисляет границы очков по формулам и записывает оба целых числа в фиксированный буфер. Rust 1.75 x64, посылка 11323307. Время 0,031 → 0,046 с, память 216 → 48 КБ.

Версия на Python вычисляет минимум и максимум очков напрямую. Если обе команды забивали, она также рассматривает случай, когда один матч оставляют под противоположный исход. Python 3.12 x64, посылка 11320787. Время 0,093 → 0,093 с, память 488 → 484 КБ.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11321851 · Go 1.14 x64 №11322271 · Java 1.8 №11322272 · Python 3.12 x64 №11322274 · Rust 1.75 x64 №11322276.

Go читает три целых числа в фиксированный буфер и выводит обе суммы очков за одну запись. Go 1.14 x64, посылка 11322414. Время 0,031 → 0,046 с, память 1152 → 796 КБ.
