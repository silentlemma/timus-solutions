# 1551. Турнир по сумо

[Timus 1551](https://acm.timus.ru/problem.aspx?space=1&num=1551) · сложность 257 · math, sorting

Автор оригинальной задачи — Сергей Пупырев; XI командный студенческий чемпионат Урала по программированию, Екатеринбург, 21 апреля 2007 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В турнире на выбывание 2ᴺ сумоистов (1 ≤ N ≤ 10) и N раундов; каждый
сумоист представляет префектуру. Организаторы выбирают начальную сетку.
Нужно найти наибольшее K, такое, что при некоторой сетке при любых
исходах поединков есть хотя бы K раундов, в которых не встречаются
двое из одной префектуры.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем 2ᴺ строк с именем сумоиста и префектурой.
Оба поля содержат от 1 до 30 латинских букв.

## Выходные данные

K.

## Проверка

Сравнивается один целочисленный токен. Новый Python прошёл 168 распределений против независимого хеш-подсчёта: регистр, поля длины 30, различные/одинаковые префектуры и до 1024 борцов.

## Примеры

### Пример 1

Ввод:

```
3
Homasho Ishikawa
Tamakasuga Tokyo
Futeno Tochigi
Takekaze Tokyo
Kasugao Yamaguchi
Kotoshogiku Ishikawa
Kotomitsuki Tokyo
Miyabiyama Shizuoka
```

Вывод:

```
1
```

## Решение

В раунде r сетка сводит пары блоков по 2^(r−1) сумоистов, и раз из блока
может выйти любой, раунд r безопасен ровно тогда, когда у двух половин
каждого блока из 2^r нет общей префектуры.

Возьмём самую большую префектуру с c сумоистами и выберем исходы так,
чтобы они побеждали всех соперников из других префектур. Её участники
выбывают только при встречах друг с другом, причём за небезопасный
раунд их число уменьшается не более чем вдвое. Чтобы из c остался один,
нужно хотя бы ⌈log₂ c⌉ небезопасных раундов, поэтому K ≤ N − ⌈log₂ c⌉.

Эта граница достигается: при k = ⌈log₂ c⌉ для наибольшего c отсортируем
сумоистов по префектуре и раздадим по кругу в 2ᵏ блоков верхних k
уровней. В префектуре не больше 2ᵏ сумоистов, поэтому они попадут в
разные блоки; внутри блока все из разных префектур, так что первые N − k
раундов безопасны. Значит, ответ — N − ⌈log₂ c⌉. Подсчитываем участников
по префектурам, находим максимум и увеличиваем k от нуля, пока 2ᵏ < c;
выводим N − k. Полный перебор сеток и исходов совпал на всех 29 наборах
численностей при N ≤ 3 и 1200 случайных входах. `O(2ᴺ log 2ᴺ)` на подсчёт.

Подводные камни:

- при одной префектуре безопасных раундов нет (тесты 02, 04);
- c = 4 требует лишь двух небезопасных раундов, c = 5 — трёх (тесты 06,
  07);
- префектуры сравниваются как записаны, Tokyo и tokyo различны (тест
  08).
- имена сумоистов не влияют на подсчёт; оба поля всё равно должны
  содержать 1–30 латинских букв без цифровых суффиксов (тесты 04–07).

## Оптимизированные решения

Ответ по-прежнему определяется наибольшей частотой префектуры c: `N−ceil(log2 c)`. Компактные C++/Java отбрасывают имена борцов при чтении и сразу поддерживают максимальную частоту. В C++ остаётся упорядоченная map, в Java — hash map с ограниченным байтовым вводом. Python хранит только строки префектур, сортирует их и находит максимальную длину одинакового блока. Каждое имя образует ровно один непрерывный блок, его длина равна частоте. Убираются импорт Counter, сохранённые токены имён и отдельные записи хеш-таблицы. Python обменивает ожидаемо линейное хеширование на сортировку `O(M log M)`, `M=2^N`, уменьшая измеренную память; ускорение не заявляется. Сравниваются полные строки с учётом регистра, вероятностных отпечатков нет. `bit_length(c−1)` точно вычисляет округление логарифма вверх. Все простые версии, включая Counter, сохранены.
