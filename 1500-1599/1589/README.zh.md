# 1589. 推箱子

[Timus 1589](https://acm.timus.ru/problem.aspx?space=1&num=1589) · 难度 14456 · bidirectional

原题作者 Stanislav Vasiliev 与 Sergey Pupyrev，出自 2007 年 10 月 27 日在叶卡捷琳堡举行的 ACM ICPC 2007–2008 NEERC 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个不超过 8 × 8 的推箱子关卡：墙 `#`、目标 `.`、箱子 `$`（在目标上为
`*`）和玩家 `@`（在目标上为 `+`）。玩家在空格上行走，走进箱子时可以一次
推动一个箱子，但不能拉。输出一个让所有箱子都到达目标的方案：移动
`u`、`d`、`l`、`r`，推箱子的移动用大写，总数不超过 10 000。解一定存在，
任何合法方案都被接受。

时间限制：5 秒。内存限制：64 MB。

## 输入

逐行给出关卡；各行长度可以不同，墙外可以有空格。

## 输出

一行方案。

## 样例

### 样例 1

输入:

```
########
#@  $ .#
########
```

输出:

```
rrRR
```

### 样例 2

输入:

```
######
##   .#
#@  ###
#   * #
#   $ #
#     #
#######
```

输出:

```
dddrrrruLdlUUUluRR
```

## 解法

搜索以推动为单位，而不是以步为单位。状态是箱子集合加上玩家能走到的
区域（用其中编号最小的格子表示）；两者合成一个 64 位键，区域通过位掩码
扩张求得。

两个最佳优先搜索在中间相遇：从起点推，以及从已解局面（箱子在目标上，
玩家在任一空闲区域）拉。它们共用一张有 2²² 个槽位的开放寻址表
（Java 和 Python 为 2²¹），被两边都找到的状态把方案的两半连起来。
每个搜索按 `g + 3h` 取状态，h 是单个箱子的推动距离之和：正向到最近目标，
反向从最近箱子起始格出发。箱子与可达目标或起始格之间的匹配能发现无法
全部归位的箱子。开放列表是穿过表格串起来的桶，其存储量受表大小限制。

大部分工作在于剪掉死局：

- 死格：单个箱子无法到达目标（正向），或无法从箱子起始格到达（反向）；
- 冻结的箱子（仅正向）：两条轴都被任意一侧的墙或冻结箱子、或两侧的死格
  阻塞，且冻结的一组箱子中有箱子不在目标上；
- 围栏（仅正向）：玩家进不去某个区域，而周围箱子的所有推动都朝里且能
  立即执行时，只尝试这些推动；未完成的区域若没有潜在的边界推动，就是死的；
- 小子集：对每组二到四个箱子有一张表，由只含这些箱子的搜索建成，说明
  仅凭它们是否还能解开（对拉的搜索：能否从起点到达）。所查子集都包含
  被移动箱子：所有二元组、三元组，以及其余箱子都在它三行三列以内的四元组。

方案按每个键记录的移动复原，推动之间的步子由广度优先行走给出。
表中 P 为预处理时间，S 为存储状态数，B 为箱子数，F 和 H 分别为冻结检查
和哈希表操作的最大开销。

易错点：

- 箱子可能已经都在目标上：输出空行（测试 03）；
- 玩家可能从目标上出发（`+`），行可能以空格开头（测试 04）；
- 目标上的箱子若忽略其他箱子仍与玩家被墙隔开，就永远不会动，
  会被排除在搜索之外（测试 05）。

方案在这里的测试和约 1 500 个生成的关卡上检查过；在这些检查中，一份
独立的已通过实现解出的随机关卡，这些解法也全部解出了。

## 各语言说明

- Go 插入新状态时复用首次查表找到的空槽，并直接由箱子的格子编号算出小子集的序号：最初的版本比 C++ 慢约 1.4 倍，在评测第 92 个测试上 4.6 秒后放弃，而 C++ 用 2.2 秒解出。Go 的搜索最多进行到 4.85 秒。

- Java 用 2²¹ 个键的表，使 JVM 能放进 64 MB，并做了与 Go 相同的加速。它在找到玩家区域时一次标记整个区域，用位运算构造子集表，并把掩码直接存进键中，这使评测第 92 个测试从超过 5 秒降到 4.34 秒。

- Python 把状态存在紧凑数组中并在 PyPy 下运行；CPython 慢好几倍。它在这里的测试上约需 0.5 秒，却在评测第 62 个测试上超过 5 秒的限制，该测试要重得多：C++ 在第 92 个测试上需要 2.2 秒。我们尝试过三种不同的 Python 搜索：这个双向搜索；加上最佳优先重启和箱子到目标的最小代价指派的同一搜索（第 55 个测试）；以及按该指派的贪心搜索，配合死格、冻结箱子、围栏以及箱子对和三元组的表（第 56 个测试）。在相同状态数下，PyPy 上的 Python 约比 C++ 慢 35 倍，所以要通过需要访问少得多状态的搜索。因此保留并标为 TLE：它通过了这里的全部测试，但不保证在评测的每个测试上都不超时。
