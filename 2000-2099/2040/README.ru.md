# 2040. Новые значения палиндромов после каждой буквы

[Timus 2040](https://acm.timus.ru/problem.aspx?space=1&num=2040) · сложность 861 · strings

Автор оригинальной задачи — Михаил Рубинчик (Подготовка —  Кирилл Бороздин); Ural FU Dandelion contest. Petrozavodsk training camp. Summer 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для каждого непустого префикса слова нужно определить, сколько новых
различных непустых подстрок-палиндромов появилось после добавления
последней буквы. Равные строки на разных позициях считаются одним
значением; число вхождений не требуется.

## Входные данные

Одно слово только из строчных букв `a` и `b`, длина `1≤n≤5000000`. Время
— 0,5 секунды, память — 100 МБ. В официальном примечании гарантируется
достаточно быстрое решение на C++, но такой гарантии для других языков,
включая Java, нет.

## Выходные данные

Ровно `n` цифр подряд без пробелов. Цифра `i` равна разности количеств
различных непустых палиндромов в префиксах длины `i` и `i-1`. Первая
цифра равна `1`. Ниже доказывается, что каждая цифра — `0` или `1`.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
abbbba
```

```
111111
```

Поочерёдно добавляются новые значения `a`, `b`, `bb`, `bbb`, `bbbb` и
`abbbba`, поэтому все шесть цифр равны единице. Это не свойство любого
двоичного слова: для `aababbaa` ответ `11111110`; последняя буква нового
значения не создаёт.

## Решение

### Не более одного нового палиндрома

Новая подстрока обязана заканчиваться на новой позиции. Пусть возникли
два разных новых палиндромных суффикса `U,V`, где `|U|>|V|`. Палиндром
`V` как суффикс палиндрома `U` одновременно является его префиксом. Это
вхождение заканчивается раньше, что противоречит новизне `V`. Значит,
новое значение не более одно, и им может быть только наибольший
палиндромный суффикс. Всего различных непустых палиндромов не больше
`n`.

### Двоичное дерево палиндромов

Вершина обозначает один палиндром. Хранятся длина, суффиксная ссылка на
наибольший собственный палиндромный суффикс и два перехода: буква `c`
ведёт из `P` в `cPc`. Есть корни длины ноль и искусственной длины минус
один. Искусственный корень позволяет получить палиндром длины один, а
его ссылка на себя завершает поиск расширения. Вершина ноль —
искусственный корень, вершина один — пустой; ноль в переходе означает
отсутствие ребра, настоящие палиндромы нумеруются с двух.

Пусть `last` — наибольший палиндромный суффикс обработанного префикса.
При добавлении `c` на позиции `p` идём по ссылкам от `last`, пока для
вершины `P` не выполняются `p-1-length(P)≥0` и равенство буквы на этой
позиции букве `c`. Искусственный корень всегда подходит. Кандидаты идут
по убыванию длины, поэтому первое совпадение даёт новый наибольший
суффикс `cPc`.

Если соответствующий переход уже есть, такое значение встречалось:
выводим ноль и используем готовую вершину. Иначе создаём ровно одну
вершину длины `length(P)+2`, записываем переход и выводим единицу. Для
длины один ссылка ведёт в пустой корень. Для большей длины выполняем
такой же поиск от `link(P)`; переход по `c` из найденного кандидата
становится новой суффиксной ссылкой. Внутренность любого собственного
палиндромного суффикса является собственным палиндромным суффиксом `P`,
поэтому поиск находит наибольший. Целевая вершина уже существует, иначе
на шаге появилось бы два новых палиндрома.

Внутренность каждого палиндрома встречалась до его последней буквы.
Вместе с единственностью записи `cPc` это доказывает, что переходы точно
соответствуют ранее встречавшимся значениям. По индукции оба поиска
сохраняют наибольший суффикс и правильные ссылки. Создание вершины
эквивалентно появлению нового значения, следовательно, цифры являются
ответом.

### Почему оба поиска линейны суммарно

Пусть `F_i` — длина наибольшего палиндромного суффикса после `i` букв,
`F_0=0`. Первый поиск начинается с `F_(i-1)` и заканчивается на `F_i-2`.
Каждый переход уменьшает длину хотя бы на единицу; число переходов не
больше `F_(i-1)+2-F_i`. Телескопическая сумма не превосходит `2n`.

Для второго поиска обозначим через `G_i` длину наибольшего собственного
палиндромного суффикса текущего наибольшего, положив `G_0=-1`.
Внутренность собственного суффикса `W` длины хотя бы два является
палиндромным суффиксом предыдущего префикса. Из `|W|<F_i≤F_(i-1)+2`
следует, что эта внутренность — собственный суффикс старого наибольшего,
поэтому `G_i≤G_(i-1)+2`. Для длин ноль и один неравенство также верно.
Второй поиск начинается с длины не больше `G_(i-1)` и заканчивается на
`G_i-2`, значит, его стоимость не больше `G_(i-1)+2-G_i`. Если поиск не
нужен, нулевая стоимость также ограничена этим неотрицательным
выражением. Сумма снова `O(n)`. При двух переходах за постоянное время
вся работа дерева, включая создание вершин, занимает `O(n)`.

### Представление и ресурсы

C++ использует четыре 32-битных поля на вершину, а не четыре
машинных индекса. При `n=5000000` буфер вершин занимает до
`16(n+2)=80000032` байт; дополнительно учитываются ввод, вывод и среда
исполнения. Python хранит четыре типизированных массива, а не миллионы
объектов, и записывает выходной bytearray без дополнительной полной
копии.

В Java четыре беззнаковых трёхбайтовых поля занимают `12(n+2)` байт. Все
номера вершин и `length+1` меньше `2^23`; длина плюс один кодирует
искусственный корень нулём. Выход хранится в исходных байтах: бит со
значением четыре отсутствует в ASCII `a` и `b`. Его устанавливают при
создании нового палиндрома, маскируют при последующих сравнениях букв и
лишь после обработки всего слова превращают отметки в `0`/`1` на месте.
Исходные буквы после этого уже не нужны. Записывается только диапазон
настоящего слова, без пробелов и неиспользованной ёмкости буфера.

Дерево, вход и ответ занимают O(n) памяти; Java резервирует
фиксированный входной буфер на 5 000 002 байта. Ответ читается и пишется
целой строкой байтов, без форматирования миллионов отдельных чисел.

Решение на Python запускается под PyPy: под CPython 3.12 оно превышает
ограничение времени на 9-м тесте судьи, а под PyPy 3.10 принимается за
0.375 с и 92 МБ из 100 МБ. Go и Rust читают слово в один буфер
фиксированного размера, отмечают в нём ответ, как и остальные, и держат
дерево в четырёх массивах 32-битных целых, всего около 85 МБ; их прежние
версии у судьи не компилировались.

Считаются различные значения, а не вхождения; пустой палиндром исключён.
Новая вершина создаёт одну цифру ответа, повторное вхождение — нет.
Второй поиск начинается с суффиксной ссылки родителя. Логическая длина
искусственного корня равна минус единице; при упаковке используется
явное смещение. Не нужны 64-битные индексы в каждом поле, полная
UTF-16-копия слова и лишняя копия выхода Python. Малые примеры из единиц
не заменяют тесты с нулями и длинными спусками по ссылкам.
