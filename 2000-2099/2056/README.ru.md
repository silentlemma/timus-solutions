# 2056. Определить вид стипендии

[Timus 2056](https://acm.timus.ru/problem.aspx?space=1&num=2056) · difficulty 41 · implementation

Задача из фольклора; XIX Открытый чемпионат Урала по спортивному программированию (апрель, 2015).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Студент сдал n экзаменов с оценками от 3 до 5. Определите стипендию:
`None`, если есть хотя бы одна 3, иначе `Named`, если все оценки 5,
иначе `High`, если средний балл не меньше 4.5, и `Common` во всех
остальных случаях. Ограничения: 1 секунда и 64 МБ.

## Входные данные

Число экзаменов n, 1 ≤ n ≤ 10, и затем n строк по одной оценке.

## Выходные данные

Одно слово с учётом регистра.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3
5
5
4
```

```
High
```

```
3
3
3
3
```

```
None
```

В первом примере сумма равна четырнадцати, и `2·14≥9·3`, поэтому среднее
выше 4,5. Троек нет, но есть четвёрка, следовательно ответ `High`. Во
втором примере присутствуют тройки; первое правило сразу определяет
`None`.

## Решение

Читаем оценки, храня их сумму S и минимум. Затем применяем правила по
порядку: любая тройка даёт `None`; все пятёрки — `Named`; средний балл
не меньше 4.5 — `High`, это проверяется в целых числах как 2S ≥ 9n; всё
остальное — `Common`. `O(n)`.

Подводные камни:

- тройка важнее любого среднего;
- все пятёрки — это `Named`, а не `High`;
- порог 4.5 включается: одна четвёрка и одна пятёрка дают `High`.

## Оптимизированные решения

`2056_implementation_optimized.py`. Каждая оценка разбирается как число; остаются признак наличия 3 и количество четвёрок. Для оценок 3,4,5 порог среднего 4.5 при отсутствии троек равносилен условию удвоенное число четвёрок не больше n. Все четыре названия стипендии сохранены. Не нужны обновления минимума и суммы на каждой оценке; в отличие от отклонённого опыта с байтовым написанием знаки плюс и ведущие нули разбираются численно. Время O(n), память для токенов O(I); простая версия через среднее сохранена. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `2056_implementation.py`: время 0.078 s → 0.125 s; память 472 KB → 228 KB.

Оптимизированное решение на C++ читает через `scanf` и печатает через
`puts` вместо `iostream` и `std::string`: 116 КБ вместо 420 КБ при том
же времени.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2056_implementation_optimized.py`: место по времени 272/297, по памяти 1/297 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
