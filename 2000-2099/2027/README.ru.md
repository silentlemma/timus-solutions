# 2027. Исполнение сетки с регистрами

[Timus 2027](https://acm.timus.ru/problem.aspx?space=1&num=2027) · сложность 541 · simulation

Автор оригинальной задачи — Кирилл Бороздин; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Исполните прямоугольную сетку команд. Есть текущий целочисленный регистр
и 26 регистров памяти `A`…`Z`; изначально все равны нулю. Указатель
начинает в левом верхнем углу и смотрит вправо. За такт сначала
выполняется команда клетки, потом указатель сдвигается на одну клетку в
полученном направлении. Переноса через край нет.

| Команда | Действие до перемещения |
| --- | --- |
| `^`, `>`, `v`, `<` | Задать направление вверх, вправо, вниз, влево соответственно. |
| `.` | Ничего не менять. |
| `A`…`Z` | Поменять местами текущий регистр и указанный регистр памяти. |
| `?` | Перезаписать текущий регистр следующим входным числом; после конца всегда повторять последнее. |
| `!` | Вывести текущее значение, затем обнулить текущий регистр. |
| `+`, `-` | Увеличить или уменьшить текущее значение на единицу. |
| `@` | При нуле повернуть против часовой стрелки, иначе по часовой, в том числе при отрицательном числе. |
| `#` | Немедленно закончить без перемещения. |

После команды выход текущего значения за `[-100000,100000]` даёт
`OVERFLOW ERROR`. Последующий выход указателя за сетку даёт `RUNTIME
ERROR`. Если выполнены 1000000 тактов без завершения и этих ошибок,
возникает `TIME LIMIT EXCEEDED`. Ранее выведенные числа сохраняются.
Команда и переполнение проверяются до движения, а оба вида ошибок — до
лимита тактов. Завершение на такте 1000000 успешно.

Размеры: `1 ≤ H,W ≤ 100`. Входных чисел `1 ≤ N ≤ 100000`, их модули не
больше 100000. Неиспользованные входные числа допустимы. Ограничения: 2
секунды и 64 МБ.

## Входные данные

Даны `H W`, затем `H` строк по `W` команд из таблицы. Далее `N` и `N`
целых чисел, по одному на строку.

## Выходные данные

Каждое выполненное `!` выводит число в отдельной строке. При ошибке
добавляется строка с точным сообщением. Обычное завершение ничего не
добавляет; вывод может быть пустым.

## Проверка

Ответы сравниваются по токенам.

## Решение

Каждое целое читаем как десятичный токен: пропускаем необязательный знак
`+` или `-`, накапливаем цифры и применяем знак. Так разбираем размеры,
количество входных чисел и сами числа перед симуляцией.

Достаточно прямой симуляции: храним координаты, направление, текущее
значение, память, курсор ввода и буфер вывода. Направления кодируем по
часовой стрелке: вправо, вниз, влево, вверх. `@` прибавляет единицу по
модулю четырёх при ненулевом значении и вычитает при нуле. Курсор после
последнего чтения остаётся на последнем индексе.

На каждом из не более 1000000 тактов выполняем команду. При `#` сразу
возвращаем результат. Иначе проверяем переполнение, перемещаем указатель
и проверяем границы. Первая ошибка немедленно завершает исполнение. Если
цикл исчерпан, добавляем сообщение о лимите. Буфер сохраняет ранее
выведенные значения. Обнаруживать цикл не требуется: повторение позиции
ещё не разрешает отбросить множество будущих команд вывода.

Корректность доказывается индукцией по тактам. Начальные регистры,
указатель, направление, непрочитанный ввод и пустой вывод соответствуют
определению машины. Каждая команда выполняет заданное обновление: обмен
сохраняет оба значения, чтение берёт следующее число или повторяет
последнее, вывод предшествует обнулению. Направление меняется до
движения. Поэтому состояние и префикс вывода после такта совпадают с
машиной. Проверки в нужных фазах находят ту же первую ошибку, `#`
останавливает до движения. После миллионного полного такта остаётся
только ошибка лимита. Значит, весь вывод, включая конечное сообщение,
совпадает.

В первом примере цикл переносит единицы через `A` и выводит 5. Во втором
выводится ноль, регистр очищается и указатель зацикливается без
достижения завершения, поэтому добавляется сообщение лимита. В третьем
единственное входное число читается дважды: второе чтение повторяет 1,
затем число выводится и программа завершается.

При `S ≤ 1000000` исполненных тактах и длине вывода `B` время равно
`O(HW + N + S + B)`. Память с буферизацией — `O(HW + N + B)`; регистры и
указатель требуют константную память. Потоковый вывод убрал бы член `B`,
но обязан сохранить все числа, выведенные до ошибки.

Подводные камни:

- Принимайте явный `+` у целых чисел, включая количество. В тесте `028`
  записано `+1`; обработка знака как цифры делает количество отрицательным.
- Буква регистра меняет значения местами; `!` обнуляет текущее значение.
- После конца ввода повторяется последнее число; лишние входные числа не ошибка.
- Отрицательное значение в `@` означает поворот по часовой стрелке.
- Нельзя переносить указатель через край или двигаться после `#`;
  переполнение важнее выхода.
- Сначала выполните миллионную команду и движение, затем проверяйте лимит.
- Сохраняйте большой вывод; немедленное завершение не обязано печатать
  перевод строки.

## Особенности языков

Обычного знакового целого достаточно и для значения, и для обнаружения
переполнения на один шаг. C++ использует строковый буфер, Go —
`strings.Builder`, Java — `StringBuilder`, Rust — `String`, Python —
`StringIO` вместо почти миллиона отдельных строк с числами. Все варианты
буферизуют ввод и не сокращают полный лимит тактов.
