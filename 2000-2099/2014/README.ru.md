# 2014. Кредитный баланс при нарушенном порядке операций

## Задача

Наличные и кредитный баланс изначально нулевые. Доход увеличивает
наличные. Расход сначала оплачивается ими, а нехватка уменьшает
кредитный баланс. Поздний доход остаётся наличными и не погашает кредит.
Сообщения об операциях приходят в произвольном порядке, но содержат
время самих операций. После каждого сообщения пересчитайте кредитный
баланс по уже известным операциям в хронологическом порядке. Ответ —
ноль или отрицательная сумма долга.

## Входные данные

Сначала `n`, `1 ≤ n ≤ 100 000`. Далее `n` строк: сумма `−c` или `+c`, `1
≤ c ≤ 50 000`, и момент `dd.MM hh:mm`. Все моменты различны и относятся
к одному невисокосному году. Строки следуют в порядке получения
сообщений. Лимит времени 1 секунда, памяти 64 МБ.

## Выходные данные

После каждого сообщения выведите текущий восстановленный кредитный
баланс, всего `n` целых чисел по строкам. Не берите модуль долга.
Единственные целые ответы сравниваются по токенам.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
5
-1000 10.09 21:00
+500 09.09 14:00
+1000 02.09 00:00
-1000 17.09 21:00
+500 18.09 13:00
```

```
-1000
-500
0
-500
-500
```

Первый известный расход даёт −1000. Сообщение о более раннем доходе
меняет оценку на −500, затем ещё один ранний доход полностью убирает
долг. Следующий расход даёт −500. Последний доход произошёл после
нехватки: он увеличивает наличные, оставляя долг −500.

## Решение

Пусть `S` — сумма хронологического префикса, `D` — минимум таких сумм с
учётом пустого префикса ноль. Кредитный баланс равен `D`, наличные —
`S−D`. Изначально равенства верны. Доход увеличивает `S` и наличные, не
уменьшая минимум. Расход, на который хватает наличных, сохраняет `D`.
При нехватке новая сумма `S` становится меньше `D`: наличные исчерпаны,
новый баланс равен этой меньшей сумме. Индукция доказывает равенства;
нужен минимум префикса.

Считываем все моменты и сортируем индексы событий по времени: месяц,
день, час, минута. Сортировка исходных строк с днём впереди неверна.
Каждому событию назначаем ранг и строим на рангах нулевое дерево
отрезков. Ещё не полученные операции имеют нулевой вклад: знание
координат не использует будущие суммы. В порядке поступления задаём
листу сумму операции и выводим минимум префикса в корне.

Узел хранит сумму `S` и минимум префикса `P` с пустым префиксом. Для
левой части A и правой B объединение такое: `S=A.S+B.S`,
`P=min(A.P,A.S+B.P)`. Любой префикс заканчивается внутри A либо содержит
всю A и префикс B, поэтому формула точна. Лист со значением `v` хранит
`(v,min(0,v))`, неизвестный или дополняющий лист — `(0,0)`. Индукция по
дереву доказывает правильность всех сводок. После обновления корень
описывает ровно известную хронологическую последовательность, а
доказанная связь наличных и кредита даёт правильный ответ.

Сортировка и обновления требуют `O(n log n)` времени; итеративное дерево
и входные массивы — `O(n)` памяти. Модуль суммы и долга может достигать
`100 000·50 000=5 000 000 000`, нужны 64-битные целые. Альтернатива —
прибавление суммы операции ко всему суффиксу префиксных балансов с
поддержкой их глобального минимума.

## Особенности языков

Порядок сообщений не равен порядку операций. Поздний доход не погашает
кредит, а заново найденный ранний доход меняет его оценку. Учитывайте
нулевой префикс, выводите отрицательный долг и сравнивайте месяц раньше
дня. Уникальность моментов позволяет присваивать значение листу. Python
использует массив рангов и два списка дерева и запускается под PyPy: под
CPython 3.12 решение превышает ограничение времени на 15-м тесте судьи,
а под PyPy 3.10 принимается за 0.39 с. C++, Go, Java и Rust используют
широкие суммы. Java сортирует примитивные упакованные пары момента и
индекса в long-массиве, без объектов Integer; сама упаковка тоже
64-битная. Парсеры учитывают оба знака и разделители даты и времени.
