# 2014. 乱序交易报告下的信用余额

[Timus 2014](https://acm.timus.ru/problem.aspx?space=1&num=2014) · 难度 547 · segment_tree

原题作者 Nick Burlakov（由 Olga Soboleva 整理），出自 NEERC 2014 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

现金与信用余额最初为零。收入增加现金；支出先用现金，不足部分降低信用余额。后来的收入保留为现金，不偿还信用欠款。交易报告乱序到达，但包含实际发生时刻。每收到一份报告，仅用目前已知报告按发生时间重算信用余额，输出零或负的欠款余额。

## 输入

先给 `n`，`1 ≤ n ≤ 100,000`。随后每行给带符号金额 `−c` 或 `+c`，`1 ≤ c ≤ 50,000`，以及时间 `dd.MM hh:mm`。所有时刻互异，属于同一个非闰年。输入顺序是报告收到顺序。时间限制 1 秒，内存 64 MB。

## 输出

每份报告后输出当前重建的信用余额，共 `n` 行整数。不对欠款取绝对值。唯一整数答案按标记比较。

## 评测方式

按记号逐个比较输出。

## 样例

```
5
-1000 10.09 21:00
+500 09.09 14:00
+1000 02.09 00:00
-1000 17.09 21:00
+500 18.09 13:00
```

```
-1000
-500
0
-500
-500
```

首先只有一笔支出，余额为 −1000。得知更早收入后修正为 −500，再得知另一笔早收入后归零。下一笔支出使其为 −500。最后的收入发生在现金不足之后，因此只增加现金，信用余额仍为 −500。

## 解法

设按时间累计的金额和为 `S`，截至目前的最小前缀和（包括空前缀零）为 `D`。信用余额等于 `D`，现金等于 `S−D`。初始成立。收入提高 `S` 与现金，不降低最小值；现金足够的支出不改变 `D`。若现金不足，新 `S` 小于旧 `D`，现金耗尽且信用余额变成这个更小值。由归纳证明，答案就是最小前缀和。

先读全部时刻，按月、日、小时、分钟排序事件下标并压缩为排名。不能直接按日开头的原始字符串排序。在排名上建立全零线段树；未来报告的叶子保持零，预读坐标不使用未来金额。按收到顺序，把对应叶子赋为交易金额，输出根的最小前缀和。

节点保存总和 `S` 和含空前缀的最小前缀 `P`。左段 A 接右段 B 时，`S=A.S+B.S`，`P=min(A.P,A.S+B.P)`。任意前缀要么止于 A 内，要么含完整 A 与 B 的一个前缀，所以合并准确。值为 `v` 的叶子存 `(v,min(0,v))`，未收到及填充叶子存 `(0,0)`。按树结构归纳，每个摘要都正确；根恰好描述当前已知的时间序列，结合现金/信用恒等式，输出正确。

排序与全部更新耗时 `O(n log n)`，迭代树和输入数组用空间 `O(n)`。总和与欠款的绝对值可达 `100,000·50,000=5,000,000,000`，必须使用 64 位整数。另一种办法是对时间前缀余额做后缀加法，并维护全局最小值。

## 各语言说明

收到顺序不同于发生顺序；晚收入不还款，新发现的早收入却可能修正欠款。保留零前缀、负的输出符号，并让月先于日参与比较。时刻唯一，所以叶子可以直接赋值。Python 使用排名数组及两份树列表，在 PyPy 下运行：在 CPython 3.12 下它在评测的第 15 个测试上超时，而在 PyPy 3.10 下以 0.39 秒通过。C++、Go、Java、Rust 使用宽整数。Java 将时间键与事件下标打包进原生 long 数组排序，不使用装箱对象；打包运算也必须是 64 位。输入解析处理正负号及日期时间分隔符。
