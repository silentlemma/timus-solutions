# 2093. 积雪减速道路上的最快路线

[Timus 2093](https://acm.timus.ru/problem.aspx?space=1&num=2093) · 难度 1369 · dijkstra

原题作者 Denis Dublennykh，出自 2014 年乌拉尔联邦大学公开个人赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

n 个路口由 m 条道路连接，正常通行时间为 tᵢ。从时刻 0 开始下雪；在道路上次清扫（或下雪开始）后 T 分钟驶入，通行时间为 min(⌈(1 + T/100) tᵢ⌉, 100500 tᵢ)。每条道路有清扫时间表，清扫期间封闭，而且通行必须在下次清扫开始前结束。可以在路口等待。求在时刻 0 从路口 1 出发最早何时到达路口 n。时间限制 2 秒，内存限制 64 MB。

## 输入

n 和 m（至多 10⁵），m 条道路 aᵢ bᵢ tᵢ（tᵢ ≤ 10⁶），然后是 k ≤ 10⁵ 次清扫 pᵢ sᵢ fᵢ（道路及封闭区间，时刻至多 10⁹；同一道路的清扫互不重叠）。

## 输出

最早到达时刻。

## 样例

### 样例 1

输入：

```
4 3
1 2 10
2 3 10
3 4 10
1
2 10 15
```

输出：

```
38
```

## 解法

固定一条道路和到达其起点的时刻。在两次清扫之间，越晚出发只会遇到越多的雪，所以每个开放区间内最好的出发时刻是最早的那个。后一个区间开始于一次清扫之后，而那次清扫开始时，较早的出发本可以已经结束，所以第一个“最早出发仍能在下次清扫前结束”的区间给出最早到达；最后一次清扫之后道路总能通行。这个到达函数随到达时刻不减，因此可以对到达时刻使用 Dijkstra 算法：取出路口时，扫描每条道路排好序的清扫来松弛它。每条道路至多松弛两次，因此扫描耗时 O(m + k)，堆操作耗时 O((n + m) log n)。清扫时间表排序耗时 O(k log k)，总时间复杂度为 O((n + m) log n + k log k)。通行时间用整数计算并带上 100500 tᵢ 的上限。

一个陷阱是漏算排序成本：测试 gen7（生成器 `5 7`）只有两个路口和一条道路，却有 100000 条未排序的清扫记录，因此排序成本不能计入 O(k log n)。

样例中第一条道路用 10 分钟；第二条在 10 到 15 清扫，所以 15 驶入、25 驶出；第三条已下了 25 分钟雪，需要 ⌈1.25 · 10⌉ = 13 分钟，38 到达。
