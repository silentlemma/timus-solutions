# 2061. Подсчёт богатых двоичных слов

[Timus 2061](https://acm.timus.ru/problem.aspx?space=1&num=2061) · сложность 3176 · strings, bruteforce

Автор оригинальной задачи — Михаил Рубинчик; Палиндромный контест, 11 июля 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Слово длины n называется богатым, если среди его подстрок ровно n
различных непустых палиндромов. Для каждой длины i от 1 до n посчитайте
богатые слова длины i над двухбуквенным алфавитом. Ограничения:
1 секунда и 64 МБ.

## Входные данные

Одно целое число n, 1 ≤ n ≤ 61.

## Выходные данные

n строк: количество богатых двоичных слов длины 1, 2, …, n.

## Проверка

Ответы сравниваются по токенам.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
2
4
8
16
```

## Решение

У входа всего 61 возможное значение, а ответы растут примерно до
3·10¹² — слишком много слов, чтобы перечислить их за секунду. Поэтому
ответы вычисляются один раз заранее, а программы печатают первые n из
таблицы. Интересно здесь то, как таблица вычисляется.

Приписывание буквы к слову добавляет не больше одного нового различного
палиндрома: новый палиндром — суффикс, и если бы новыми были два
суффикса `U` и `V`, `|U| > |V|`, то `V` как палиндромный суффикс
палиндрома `U` был бы и его префиксом, то есть встречался бы раньше.
Значит, в слове длины L не больше L различных палиндромов, и ровно L
их только тогда, когда каждая буква добавила новый. Поэтому любой
префикс богатого слова богат, и богатые слова образуют дерево, где
каждое слово — богатое слово плюс одна буква.

Это дерево обходится поиском в глубину. Для текущего слова поддерживается
дерево палиндромов: по вершине на каждый различный палиндром, суффиксная
ссылка на наибольший собственный палиндромный суффикс и переходы
`c: P → cPc`. Чтобы попробовать букву c, идём по суффиксным ссылкам от
наибольшего палиндромного суффикса, пока буква перед ним не станет
равна c; найденный палиндром с c по краям — новый наибольший
палиндромный суффикс. Если такая вершина уже есть, слово с c не богатое
и ветка отсекается; иначе вершина создаётся, поиск идёт глубже, а при
возврате вершина и переход удаляются. Каждый шаг стоит не больше O(L),
глубина не больше 61, памяти нужно совсем мало.

Замена двух букв друг на друга переводит богатые слова в богатые,
поэтому поиск начинается с буквы 0, а все количества удваиваются.
Слова длины 20, начинающиеся с 0, делят работу на независимые части для
нескольких потоков. Весь поиск проходит около 10¹³ слов и занимает около
полутора часов на 22 потоках. Его результаты совпадают с последовательностью
A216264 из OEIS для всех длин до 60.
[2061_strings_bruteforce_table.py](2061_strings_bruteforce_table.py) — тот
же перебор на Python: для всех 61 длины он слишком медленный, но первые
значения проверяет за секунды.

В примере богаты все 16 слов длины 4; первые небогатые слова появляются
при длине 8, например 00101100.

## Особенности языков

Наибольшее количество, 2 966 632 985 826, требует 64-битных целых.
Каждая программа хранит таблицу как константу и печатает первые n её
элементов.
