# 2004. Кратчайшая строка со всеми двоичными словами

[Timus 2004](https://acm.timus.ru/problem.aspx?space=1&num=2004) · сложность 761 · graphs, greedy

Автор оригинальной задачи — Илья Кучумов; Уральская региональная командная олимпиада по программированию 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для каждого числа от 0 до `2^n−1` берётся запись ровно из `n` бит с
ведущими нулями. Она делится на старшую часть длины `ceil(n/2)` и
младшую длины `floor(n/2)`. Младшая часть переносится перед старшей без
изменения порядка внутри частей. Требуется кратчайшая двоичная строка,
содержащая все полученные слова как непрерывные подстроки. Подходит
любой оптимальный ответ.

## Входные данные

Одно целое `n`, `1 ≤ n ≤ 20`. Время 0,5 секунды, память 64 МБ.

## Выходные данные

Одна двоичная строка минимальной длины. Ведущие нули существенны.

## Проверка

Проверяющая программа убеждается, что ответ — двоичная строка длины 2ⁿ +
n − 1, содержащая все слова длины n; принимается любая такая строка.

## Примеры

```
1
```

```
10
```

При `n=1` нужны слова 0 и 1. Как ответ `10` из примера, так и вывод
программы `01` минимальны.

## Решение

Перестановка двух частей обратима: результат делится после первых
`floor(n/2)` бит, затем части меняются обратно. Поэтому и при чётном, и
при нечётном `n` получаются в точности все `2^n` двоичных слов.
Вычислять саму функцию не нужно.

В строке длины `L` всего `L−n+1` окон длины `n`. Для покрытия `2^n`
различных слов необходимо `L≥2^n+n−1`. Построим строку, достигающую этой
границы.

Вершинами ориентированного графа сделаем слова длины `n−1`. Каждое слово
длины `n` задаёт ребро из своего префикса в суффикс с меткой последнего
бита. У каждой вершины по два входящих и исходящих ребра. При `n=1` есть
одна вершина, пустое слово, и две петли. Эйлеров обход задаёт все слова
по одному с перекрытием соседних рёбер.

Начинаем с `n` нулей, использовав нулевую петлю в нулевой вершине. Затем
предпочитаем дописать 1, если новое слово длины `n` ещё не использовано;
иначе дописываем 0. Использованные слова отмечаются в байтовом массиве.
Текущее окно поддерживается сдвигом и маской. Всего дописываем `2^n−1`
символов.

Почему жадный обход использует все рёбра без возвратов? В вершине,
отличной от начальной, застрять нельзя: использованных входящих рёбер на
одно больше исходящих, а полные степени равны. Поэтому ранняя остановка
замкнула бы обход в нуле. Неиспользованные рёбра тогда сбалансированы в
каждой вершине. Если в ненулевой вершине осталось исходящее ребро, её
нулевое ребро ещё не использовано, поскольку единичное предпочитается.
По балансу конец этого нулевого ребра тоже имеет неиспользованный выход.
Повторное дописывание нуля не позднее чем за `n−1` шагов приводит в
нулевую вершину, что противоречит остановке в ней. Первоначальная
нулевая петля — единственное исключение из порядка предпочтения,
расположенное именно в начале. Значит, использованы все рёбра, все окна
различны и нижняя граница достигнута.

Время `O(2^n+n)`, память `O(2^n+n)` вместе с выводом и отметками.
Максимальный ответ содержит 1 048 595 бит. Список преобразованных слов и
рекурсивный стек не нужны.

Ответ — линейная строка, поэтому к циклу из `2^n` рёбер добавляются
`n−1` символов перекрытия. Нулевое слово отмечается до цикла. Индекс
определяется последними `n` битами с маской `2^n−1`. Случай `n=1`
обрабатывается общим кодом. Нельзя сравнивать допустимые ответы с одной
фиксированной строкой.

## Особенности языков

C++ резервирует строку, Go использует `strings.Builder`, Java заполняет
массив символов, Rust — вектор байтов, Python — байтовый массив с прямой
записью в вывод. Индексы и сдвиги укладываются в знаковые 32-битные
целые при `n≤20`. Ресурсы измеряются для каждой полной программы на
максимальном входе.
