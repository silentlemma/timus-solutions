# 2028. Генерация программы суммы в сетке

[Timus 2028](https://acm.timus.ru/problem.aspx?space=1&num=2028) · сложность 880 · constructive

Автор оригинальной задачи — Кирилл Бороздин; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Выведите фиксированную программу на описанном ниже языке сетки. Получив
одно число `n`, она для любого `1 ≤ n ≤ 100` должна вывести ровно одно
число `1+2+…+n` и нормально завершиться. Подходит любая корректная
программа. Сам генератор числа `n` не получает: его единственный ввод —
строка `Good luck!`, которую можно игнорировать. Ограничения генератора:
1 секунда и 64 МБ.

Выводимая программа — сетка `H×W`, где `1 ≤ H,W ≤ 100`. Есть текущий
регистр и 26 регистров `A`…`Z`, изначально нулевые. Указатель начинает в
левом верхнем углу, направление вправо. За такт сначала выполняется
команда, затем делается шаг в полученном направлении, без переноса через
край.

| Команда | Значение |
| --- | --- |
| `^`, `>`, `v`, `<` | Направление вверх, вправо, вниз, влево соответственно. |
| `.` | Ничего не менять. |
| `A`…`Z` | Обменять текущий регистр с указанным регистром памяти. |
| `?` | Прочитать число в текущий регистр; после единственного входа повторять `n`. |
| `!` | Вывести текущее значение и обнулить его. |
| `+`, `-` | Увеличить или уменьшить текущее значение на единицу. |
| `@` | При нуле повернуть против часовой стрелки, при любом ненулевом — по часовой. |
| `#` | Немедленно закончить без движения. |

Модуль текущего значения больше 100000 даёт `OVERFLOW ERROR` до движения. Выход
за сетку даёт `RUNTIME ERROR`. Если выполнены 1000000 тактов без завершения и
предыдущих ошибок, возникает `TIME LIMIT EXCEEDED`. Выводимая программа должна
избежать всех ошибок; правильного числа перед ошибкой недостаточно.

## Входные данные

Единственная строка `Good luck!` относится к генератору. Отдельный ввод
исполняемой программы — одно целое `n`.

## Выходные данные

Сначала `H W`, затем ровно `H` строк команд длины `W`. Разрешены только команды
из таблицы. Программа должна решать задачу для каждого допустимого `n`.

## Проверка

Проверяющая программа запускает напечатанную программу для каждого n от
1 до 100 и принимает её, если каждый запуск ровно один раз печатает
правильную сумму и нормально останавливается. Программа из официального
примера лишь показывает формат и не является верным ответом, поэтому
сохранённый вывод примера помечен `format_only` и не проверяется.

## Примеры

```
Good luck!
```

```
4 6
?A?v>v
>..>@A
-...A!
^A.+<#
```
Этот официальный пример показывает только формат вывода. Программа в нём задачу
не решает: при целевом входе 1 получается 2 вместо 1. Наши генераторы выводят
корректную программу ниже; совпадение с иллюстрацией не требуется.

## Решение

```text
6 11
>?v........
.>>.......v
..@A+AB+B-<
..B........
..-........
.^@A!#.....
```
Регистр `A` хранит сумму, `B` — временный счётчик. Текущий регистр
содержит внешний счётчик `q`, изначально `n`. Для `q = n,n-1,…,1`
прибавляем к `A` ровно `q` единиц, восстанавливаем `q` из `B` и
уменьшаем его. При нуле переносим `A` в текущий регистр, выводим и
завершаемся.

Внутренний макрос `-B+BA+A` уменьшает текущее значение на один, увеличивает `B`
через обмен, прибавление и обратный обмен, затем так же увеличивает `A`.
После `j` итераций текущее значение равно `q-j`, `B=j`, `A=old_sum+j`.
При `j=q` получаем ноль, `B=q` и сумму, увеличенную на `q`. Выход `B-`
восстанавливает `q`, обнуляет `B` и оставляет в текущем регистре `q-1`.

При нумерации с нуля внутренний `@` стоит в `(2,2)`, вход в него
направлен влево. При ненуле указатель поворачивает вверх во внутренний
прямоугольник, при нуле — вниз к `B-`. Тело проходится справа налево,
поэтому в строке оно записано наоборот. Внешний `@` в `(5,2)`
достигается движением вниз: неноль поворачивает влево к `^` и коридору
возврата через `(1,1)` и `(1,2)`, ноль — вправо к `A!#`. Чтение в
`(0,1)` выполняется один раз.

Внешний инвариант: текущий регистр равен `q`, `B=0`, а `A` содержит сумму уже
обработанных значений от `n` до `q+1`. Внутренний инвариант доказывает, что
итерация добавляет ровно `q` и восстанавливает внешний инвариант для `q-1`.
При `q=0` сумма равна `1+…+n`; единственный вывод выполняется на последнем
выходе, за ним следует нормальное завершение. Все значения лежат от 0 до 5050,
путь целиком внутри сетки 6×11.

Пусть `S=n(n+1)/2`. Начало занимает три такта, каждая прибавленная единица — 18,
переходы между внешними итерациями — восемь, последний выход — шесть. Итого
`3+18S+8(n-1)+6 = 18S+8n+1`, максимум 91701 при `n=100`, меньше миллиона.

Генератор печатает фиксированную сетку из 66 клеток, поэтому его время и
память — `O(1)`. Выданная программа работает за `O(n²)` времени с `O(1)`
регистрами. Это разные этапы исполнения: вычисленная генератором формула
сама по себе не даёт программу сетки, работающую с целевым вводом.

Подводные камни:

- Сохраните официальный пример формата, но не считайте его правильным решением.
- Ввод генератора — не `n`; все значения обрабатывает напечатанная программа.
- Буквы памяти меняют значения местами; макрос обязан восстанавливать
  текущий счётчик.
- Учтите направление подхода к обоим `@` и обратную запись внутреннего тела.
- Нужен один верный вывод и нормальное завершение; ошибка после вывода
  тоже недопустима.

## Особенности языков

Все пять генераторов выводят одинаковые строки команд с именованными константами
высоты и ширины и могут не читать вход. Фиксированный вывод — сама требуемая
конструкция: её циклы работают для всех целевых значений. Точки — настоящие
пустые команды, поэтому ширину строк и направления нужно сохранить точно.
