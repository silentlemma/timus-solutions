# 2033. 按出现次数和最低报价选择型号

[Timus 2033](https://acm.timus.ru/problem.aspx?space=1&num=2033) · 难度 104 · hashing

原题作者 Ilya Kuchumov，出自 2014 年乌拉尔地区中学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

恰有六条购买记录，每条包含人名、设备型号及价格。选择出现记录数最多的型号；
次数相同时，选择该型号观测到的最低价格更低者。两项都相同则任意最优型号均可。
人名可能重复，每条记录仍独立计数，不能按人名去重。

人名为 1–20 个小写英文字母，型号为 1–20 个小写英文字母或数字。
价格为 1 至 `1000000` 的整数，时间 1 秒，内存 64 MB。

## 输入

恰好六个描述，每个占三行：人名、型号、价格。没有前置记录数。

## 输出

一个最优型号名，保留原字符串及可能的前导零。

## 评测方式

检查器接受任何出现次数最多、并在这些型号中价格最低的型号。

## 解法

用型号字符串作哈希表键，保存出现次数和最低价格。读取人名但不把它作为键。
首次出现时以零次数、当前价格建立项，再增加次数并更新最低价。
最后遍历各项，优先较大次数，再较低价格。程序对完全平局额外选择字典序较小者，
只为输出稳定；题目接受全部最优型号。

处理任意输入前缀后，各项恰好记录该前缀中型号的出现数和最低价。
初始化及加一、取最小保持不变量，六条后得到准确得分。最终扫描时当前答案始终是
已扫描项中的最优，依次比较两项标准保持此性质，所以扫描完成后全局最优。

样例 `nexus4` 出现三次、最低 12000；`htc` 两次、最低 9500；
`kurtka` 一次、20000。次数优先，故 `nexus4` 胜过价格更低的少数型号。

对 `k` 条记录，期望哈希时间 `O(k)`、空间 `O(k)`，单词长度最多 20。
本题固定 `k=6`，实际时间、空间均为有界常数，不假设更多记录。

注意事项：

- 计数记录而非不同人名。
- 型号价格取最小值，不取总和、平均、最后值或最大值。
- 次数比价格更优先。
- 首次价格从当前记录初始化，不能保留默认零。
- 全数字型号仍是字符串，要保留前导零。

## 优化解法

优化的 C++ 解法不用哈希表：记录只有六条，所以把每条记录与全部六条比较，统计同一
型号的记录数并取其最低价格，一共 36 次比较，再按同样的平局规则选出最好的记录。名
称用 `scanf` 读入长度固定为 21 字节的数组（足够容纳 20 个字符和结尾的零），而不
是使用 `std::string` 和 `iostream`：{2033_bruteforce.cpp}。

优化的 Rust 解法不用哈希表：记录只有六条，所以把每条记录与全部六条比较，统计同一
型号的记录数并取其最低价格，一共 36 次比较，再按同样的平局规则选出最好的记录。六
个型号保持为输入文本的切片，存放在定长数组中，而不是复制到 `HashMap` 里：
{2033_bruteforce.rs}。
