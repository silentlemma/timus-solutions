# 2018. 限制连续段长度的序列计数

[Timus 2018](https://acm.timus.ru/problem.aspx?space=1&num=2018) · 难度 102 · dp, prefix_sums

原题作者 Olga Soboleva（由 Alex Samsonov 整理），出自 NEERC 2014 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

统计由 1、2 构成的长度为 `n` 的序列。连续的 1 至多有 `a` 个，连续的 2
至多有 `b` 个。某个位置不同就视为不同序列。答案对 `1,000,000,007` 取模。
约束为 `1 ≤ a,b ≤ 300`、`max(a,b)+1 ≤ n ≤ 50,000`。
时间限制 2 秒，内存限制 64 MB。

## 输入

唯一一行包含 `n a b`。

## 输出

输出合法序列数量对 `1,000,000,007` 取模的结果。

## 评测方式

按记号逐个比较输出。

## 样例

```
3 2 1
```

```
4
```

## 解法

设 `A_i` 为长度 `i`、以 1 结尾的合法前缀数，`B_i` 为以 2 结尾的数量。
人为设 `A_0 = B_0 = 1`，各自代表第一段之前的空前缀。对于正长度，
按最后一个极大连续段拆分：

- `A_i = sum(B_(i−r), 1 ≤ r ≤ min(a,i))`。
- `B_i = sum(A_(i−r), 1 ≤ r ≤ min(b,i))`。

去掉最后一段后，前缀为空或以相反符号结尾。反过来，给这样的前缀追加
长度合法的一段，必然得到合法序列。最后一段唯一，所以不会重复或遗漏。
两种末尾符号互斥，答案就是 `(A_n + B_n) mod 1,000,000,007`。

不必每次重新加至多 300 项。在处理长度 `i` 之前维护
`S_A = sum(B_j, max(0,i−a) ≤ j < i)` 和
`S_B = sum(A_j, max(0,i−b) ≤ j < i)`，初值均为一。
当前两和分别就是 `A_i`、`B_i`，应先同时保存，再更新。
下步的 `S_A` 加入 `B_i`，若 `i ≥ a` 则减去 `B_(i−a)`；
`S_B` 加入 `A_i`，若 `i ≥ b` 则减去 `A_(i−b)`。
更新后取模，并把减法结果规范为非负余数。这恰好移动窗口边界，
保持上述不变式，由归纳法可知计算结果满足递推。

过期值只来自最近一段历史。`B` 用大小 `a+1` 的环形缓冲，`A` 用大小
`b+1` 的缓冲。先读出过期项，再写入当前项。被覆盖的旧项已不在窗口中，
额外一个位置也保证新项与本次过期项不会占用同一格。
注意 `A` 缓冲由 **b** 决定，因为它用于计算以 2 结尾的序列。
时间 `O(n)`，空间 `O(a+b)`，最多保存 602 个计数。

样例中的合法序列为 `112`、`121`、`211`、`212`。
`b=1` 禁止相邻的 `22`，而 `111` 超过 `a=2`，故答案是四。

注意事项：

- 人为的空前缀在两种递推中各出现一次，然后按正常窗口规则过期。
- 修改窗口之前先保存两个当前计数，避免混用新旧值。
- 在 `i=a`、`i=b` 时就要删除过期项，并注意使用相反末尾类型。
- 加模数后的中间结果可能接近三个模数，必须使用足够宽的整数。
- 减法余数要规范为非负，不能把两个空边界状态当成实际答案。

## 各语言说明

五种版本都使用两个环形缓冲和滑动和。C++、Go、Java 用有符号 64 位计数，
Rust 用 `u64`，Python 用任意精度整数和非负取模。无需递归或大型动态规划表。
