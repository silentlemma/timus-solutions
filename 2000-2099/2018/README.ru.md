# 2018. Подсчёт последовательностей с ограниченными сериями

[Timus 2018](https://acm.timus.ru/problem.aspx?space=1&num=2018) · сложность 102 · dp, prefix_sums

Автор оригинальной задачи — Ольга Соболева; подготовка — Алексей Самсонов. NEERC 2014, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно посчитать последовательности длины `n` из символов 1 и 2.
Подряд может идти не более `a` единиц и не более `b` двоек.
Последовательности различаются, если хотя бы в одной позиции стоят разные
символы. Ответ требуется по модулю `1 000 000 007`.

Ограничения: `1 ≤ a,b ≤ 300`, `max(a,b)+1 ≤ n ≤ 50 000`.
Лимиты: 2 секунды, 64 МБ.

## Входные данные

Единственная строка содержит `n a b`.

## Выходные данные

Выведите количество допустимых последовательностей по модулю `1 000 000 007`.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3 2 1
```

```
4
```

## Решение

Пусть one[i] — число допустимых последовательностей длины i, которые
кончаются серией единиц, а two[i] — серией двоек. Последовательность,
которая кончается серией из r единиц, 1 ≤ r ≤ a, — это
последовательность длины i − r, кончающаяся двойками, и затем сама
серия; пустая последовательность считается по разу с каждой стороны,
one[0] = two[0] = 1. Поэтому

- one[i] = two[i − 1] + two[i − 2] + … + two[max(0, i − a)],
- two[i] = one[i − 1] + … + one[max(0, i − b)],

а ответ — one[n] + two[n] по модулю 10⁹ + 7. Каждая сумма — разность
двух префиксных сумм одного массива, поэтому каждая длина обходится в
`O(1)`, всего `O(n)`.

В примере n = 3, a = 2, b = 1 подходят 112, 121, 211 и 212: в 22 серия
двоек длиннее b, в 111 серия единиц длиннее a.

Подводные камни:

- пустая последовательность входит в каждую сумму один раз и никогда не
  считается ответом;
- разность двух префиксных сумм по модулю 10⁹ + 7 может быть
  отрицательной.

## Оптимизированные решения

Оптимизированное решение на Java хранит только те значения, которые ещё
нужны суммам: последние a + 1 значений two и последние b + 1 значений
one, в кольцевых буферах, вместе с двумя суммами окон, которые
сдвигаются на шаг для каждой длины, а не берутся из префиксных сумм. Оно
также разбирает три числа вручную вместо `Scanner`: 0.093 с вместо
0.125 с и 408 КБ вместо 3140 КБ.

## Особенности языков

- В Python `%` и так даёт неотрицательный остаток; C++, Go и Java
  прибавляют модуль и снова берут остаток, а Rust использует
  `rem_euclid`.
