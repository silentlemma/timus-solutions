# 2018. Подсчёт последовательностей с ограниченными сериями

[Timus 2018](https://acm.timus.ru/problem.aspx?space=1&num=2018) · сложность 102 · dp, prefix_sums

Автор оригинальной задачи — Ольга Соболева; подготовка — Алексей Самсонов. NEERC 2014, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно посчитать последовательности длины `n` из символов 1 и 2.
Подряд может идти не более `a` единиц и не более `b` двоек.
Последовательности различаются, если хотя бы в одной позиции стоят разные
символы. Ответ требуется по модулю `1 000 000 007`.

Ограничения: `1 ≤ a,b ≤ 300`, `max(a,b)+1 ≤ n ≤ 50 000`.
Лимиты: 2 секунды, 64 МБ.

## Входные данные

Единственная строка содержит `n a b`.

## Выходные данные

Выведите количество допустимых последовательностей по модулю `1 000 000 007`.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3 2 1
```

```
4
```

## Решение

Обозначим через `A_i` число допустимых префиксов длины `i`, оканчивающихся
единицей, через `B_i` — двойкой. Введём служебные значения `A_0 = B_0 = 1`:
каждое представляет пустой префикс перед первой серией противоположного типа.
При `i > 0` отделим последнюю максимальную серию:

- `A_i = sum(B_(i−r), 1 ≤ r ≤ min(a,i))`.
- `B_i = sum(A_(i−r), 1 ≤ r ≤ min(b,i))`.

Оставшийся префикс пуст либо оканчивается другим символом. Обратно, добавление
серии допустимой длины к такому префиксу даёт правильную последовательность.
Последняя серия определяется однозначно, поэтому пропусков и повторного
счёта нет. Ответ равен `(A_n + B_n) mod 1 000 000 007`, поскольку последние
символы двух классов различны.

Чтобы не суммировать до 300 слагаемых на каждом шаге, поддерживаем скользящие
суммы. Перед обработкой длины `i` это
`S_A = sum(B_j, max(0,i−a) ≤ j < i)` и
`S_B = sum(A_j, max(0,i−b) ≤ j < i)`; изначально обе равны единице.
Их текущие значения и есть `A_i`, `B_i`. Сначала сохраняем оба значения.
Для следующего шага добавляем `B_i` к `S_A`, а при `i ≥ a` вычитаем
`B_(i−a)`. Аналогично добавляем `A_i` к `S_B` и при `i ≥ b` вычитаем
`A_(i−b)`. Остатки после вычитания приводим к неотрицательным.
Эти операции точно сдвигают границы окон, поэтому сохраняют инвариант;
индукцией получаем требуемую динамику.

Истёкшие значения нужны лишь из недавнего прошлого. Храним `B` в кольцевом
буфере размера `a+1`, а `A` — размера `b+1`. Сначала читаем выбывающие
элементы, затем записываем новые. Перезаписываемое значение уже не входит
в окно, а дополнительная ячейка отделяет новый элемент от выбывающего.
Размер буфера `A` определяется именно **b**, поскольку эти значения входят
в сумму для двоек. Время `O(n)`, память `O(a+b)`, не более 602 счётчиков.

В примере допустимы `112`, `121`, `211`, `212`. Пара `22` запрещена
условием `b=1`, а `111` превышает `a=2`, поэтому ответ равен четырём.

Подводные камни:

- Служебный пустой префикс участвует в каждой сумме один раз и затем
  выбывает как обычный.
- Оба текущих значения получайте из старых сумм до их изменения.
- Вычитание начинается при равенстве `i=a` или `i=b`; не перепутайте тип
  окончания.
- Промежуточная сумма с добавленным модулем может приближаться к трём
  модулям: нужен широкий тип.
- Нормализуйте отрицательный остаток; два служебных пустых состояния не
  являются готовым ответом.

## Особенности языков

Во всех версиях используются два кольцевых буфера и скользящие суммы.
C++, Go и Java хранят счётчики в знаковом 64-битном типе, Rust — в `u64`,
Python использует целые числа и неотрицательный остаток. Рекурсия и большая
таблица динамики не нужны.
