# 2001. Математики и ягоды

[Timus 2001](https://acm.timus.ru/problem.aspx?space=1&num=2001) · сложность 22 · math

## Задача

Две корзины взвешивают трижды. Сначала каждая содержит собственные
ягоды. Затем всё содержимое второй пересыпают в первую и снова
взвешивают обе. Наконец все ягоды из первой пересыпают во вторую и
повторяют измерения. Найти первоначальные массы ягод, учитывая
неизменную массу самих корзин.

## Входные данные

Три пары `a1 b1`, `a2 b2`, `a3 b3` в порядке измерений. Каждое показание
целое от 0 до 10000. Данные соответствуют описанным пересыпаниям.
Лимиты: 0,5 секунды и 64 МБ.

## Выходные данные

Первоначальная масса ягод в первой и второй корзине именно в таком порядке.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
1 2
2 1
0 3
```

```
1 1
```

Первая корзина пуста на последнем измерении, поэтому её масса 0. Вторая
пуста на среднем измерении и весит 1. Вычитая их из первоначальных
показаний 1 и 2, получаем 1 и 1.

## Решение

Пусть пустые корзины весят c и d, а ягоды — x и y. Первое взвешивание
даёт a1 = c + x и b1 = d + y. После того как вторую корзину высыпали в
первую, b2 = d; после того как первую высыпали во вторую, a3 = c.
Значит, x = a1 − a3 и y = b1 − b2; показания a2 и b3 не нужны. `O(1)`.

## Оптимизированные решения

`2001_math_optimized.java`. Сохраняются две точные разности a1−a3 и b1−b2 после чтения всех шести значений. O(1) арифметики и фиксированные буферы. Все числовые поля, нужные вычислению, потребляются до вывода. Один массив 256 байт сначала служит вводу, затем выводу; перед знаковым int резервируются двенадцать байт, разворачиваются только новые цифры. Убраны отдельные массивы ввода, вывода и цифр, нужные алгоритму данные не перезаписываются. Разбор и вывод линейны по потреблённым байтам, буфер фиксирован.

Accepted точного исходника Java 1.8 №11327769: 0.078 с / 364 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 3/1109, память 7/1109. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303655: 0.125 с / 344 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `2001_math_optimized.java`: 0.078 s / 364 KB; сохранённая учебная база `2001_math.java`: 0.156 s / 1608 KB.

Историческое описание и замеры прежней ревизии: Оптимизированные решения (C++, Java) вычисляют те же две разности. C++
пропускает показания a2 и b3 через `%*d` в `scanf` вместо `iostream`:
124 КБ вместо 396 КБ при том же времени. Java разбирает числа вручную из
`System.in` вместо `Scanner`: 0.125 с вместо 0.156 с и 344 КБ вместо
1608 КБ.

Читаем шесть чисел через буфер байтов и напрямую выводим две разности. Принятая посылка 11301801 заняла 0,015 с и использовала 916 КБ. Простая версия заняла 0,031 с и использовала 1088 КБ.

Читаем шесть чисел из байтов и используем только четыре, которые нужны для двух разностей. Принятая посылка 11301805 заняла 0,078 с и использовала 364 КБ. Простая версия заняла 0,093 с и использовала 384 КБ.
