# 2043. Змейка с пополнением запаса у южной границы

[Timus 2043](https://acm.timus.ru/problem.aspx?space=1&num=2043) · difficulty 4144 · math

Автор оригинальной задачи — Илья Кучумов (Подготовка — Кирилл Бороздин); Ural FU Dandelion contest. Petrozavodsk training camp. Summer 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть прямоугольник из `n` столбцов с запада на восток и `m` строк с юга
на север. Клетки обрабатываются вертикальной змейкой: из юго-западной
клетки сначала идём на север, затем на одну клетку восточнее, проходим
следующий столбец на юг и продолжаем чередование. Начальная клетка не
требует шага; переход в соседнюю по стороне клетку стоит один шаг.

Изначально имеется запас `k` единиц, обработка клетки расходует одну.
После каждых `k` обработанных клеток, кроме последней, нужно пройти
строго на юг до нижней клетки текущего столбца, сделать шаг наружу,
пополнить запас, вернуться в ту же нижнюю клетку и кратчайшим
манхэттенским путём дойти до следующей клетки змейки. Выход и возврат
стоят два шага. Движение за пополнением не продвигает порядок обработки
и не расходует запас. После последней клетки сразу останавливаемся.
Найдите общее число шагов по модулю `1000000007`.

## Входные данные

Сначала дано `1≤t≤10`. В следующих `t` строках находятся `n,m,k`:
`1≤n,m≤10^12`, `1≤k≤10^18`, `min(n,m)≤10^6`. Поэтому площадь
`N=nm≤10^18`. Ширина и высота играют разные роли: переставлять их
нельзя. Лимиты — 4 секунды и 64 МБ.

## Выходные данные

Для каждого случая выведите целое число по модулю `1000000007` в
отдельной строке. Ответы сравниваются по целым токенам.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
1
5 3 5
```

```
20
```

В прямоугольнике `15` клеток, обычная змейка требует `14` шагов.
Пополнения нужны после клеток `5` и `10`. В первый раз текущая и
следующая высоты над южной строкой равны `1` и `0`: вместо одного шага
тратится `1+2+0=3`, добавка `2`. Во второй раз высоты `2` и `1` дают
добавку `2+2+1-1=4`. Итого `14+2+4=20`; после клетки `15` пополнения
нет.

## Решение

### Добавка от одного пополнения

Используем координаты от нуля с южной высотой ноль. После клетки с
порядковым номером `j` текущая позиция — `(x,y)`, следующая — `(u,v)`.
Маршрут пополнения стоит `y+2+v+|u-x|` вместо обычного одного шага.
Добавка всегда чётна; её половину обозначим `f(j)`. Число пополнений
`F=(N-1)//k`, ответ `N-1+2Σ f(ik)` при `1≤i≤F`. Граница `N-1` исключает
пополнение в последней клетке, даже если `k` делит `N`.

Пусть `j=qm+r`, `0≤r<m`. При `r>0` в идущем вверх столбце `f(j)=r`, а в
идущем вниз `f(j)=m-r`; направление определяется чётностью `q`. При
`r=0` нечётное `q` соответствует верхнему переходу с `f=m`, чётное —
нижнему с `f=1`. Поэтому при `P=2m` и `z=j mod P` имеем
`f(j)=min(z,P-z)`, но для `z=0` значение равно `1`, а не нулю.

### Суммирование по столбцам

Для столбца `c` от нуля берём кратные `k` номера в
`(cm,min((c+1)m,N-1)]`. Их множители идут от `a=cm//k+1` до
`b=min((c+1)m,N-1)//k`. При `a>b` вклад нулевой; иначе `C=b-a+1`.

При движении вверх половины добавок образуют арифметическую прогрессию
от `ak-cm` до `bk-cm`. При движении вниз — от `(c+1)m-ak` до
`(c+1)m-bk`. Сумма равна `C(first+last)/2`. Если нисходящая прогрессия
закончилась нулём, добавляем единицу за нижний переход. Интервалы
номеров разбивают все пополнения без повторов, что доказывает метод за
`O(n)`.

### Короткий префикс периода остатков

Пусть `g=gcd(k,2m)`, `L=2m/g`. Остатки `ki` имеют период `L` и за полный
период посещают `0,g,2g,...,(L-1)g` ровно по разу. Для `h=L//2` сумма
двух сторон треугольной функции равна `g h(L-h)` и при чётном, и при
нечётном `L`. За нулевой остаток нужна ещё единица: полный период даёт
`C=g h(L-h)+1`.

Запишем `F=qL+r`. Полные периоды дают `qC`. Для ненулевых индексов
периода `f(ki)=f(k(L-i))`, поэтому `prefix(r)+prefix(L-r-1)=C-1`.
Достаточно вычислить `W=min(r,L-r-1)` первых слагаемых; при более
коротком противоположном префиксе вычитаем его из `C-1`. Остаток
увеличиваем на `k mod 2m` и при необходимости один раз вычитаем `2m`. В
собственном префиксе периода нуля нет: его особая единица уже учтена
полным периодом и формулой дополнения.

Имеем `W≤floor((L-1)/2)≤m/g≤m`. При `n<W` выбираем столбцы, иначе
остатки. Число итераций не больше `min(n,m)≤10^6`. Разбиение пополнений
доказывает первый способ, перестановка остатков и симметрия — второй;
выбор любого сохраняет правильность.

### Короткий период полных столбцов в Python

Python дополнительно группирует полные столбцы по `T=2k/gcd(m,k)`. Сдвиг
`c` на `T` сохраняет чётность и `cm mod k`, поэтому полный вклад
повторяется. `T` чётно и `k` делит `Tm`. Вызов `columns(T,m,k)`
исключает последнее нижнее пополнение, так что для полного цикла
добавляем единицу. Неполную группу из `R` столбцов восстанавливаем так
же: возвращаем исключённое конечное пополнение только если `k` делит
`Rm`; его половина добавки равна `m` для нечётного `R` и единице для
чётного. После объединения циклов и остатка вычитаем пополнение
последней клетки всего поля, если `k` делит `N`.

Ускорение применяется только при `2T<min(n,W)`. Цикл и его неполный
префикс обходят меньше `2T` столбцов, поэтому исходная оценка числа
итераций не ухудшается. Вычисления точны по модулю ответа.

На один случай требуется `O(min(n,m)+log(max(k,m)))` времени и `O(1)`
дополнительной арифметической памяти. Логарифмическую часть дают НОД. Во
всём вводе не больше десяти случаев.

Площадь, используемые произведения номеров и сумма выбранного короткого
префикса помещаются в 64 бита: последняя не превосходит `m·10^6≤10^18`.
Полные суммы прогрессий и циклов могут иметь порядок `10^30`. C++ и Rust
используют промежуточные 128-битные значения. Go, Java и Python перед
модульным умножением делят один чётный множитель прогрессии на два;
произведение приведённых множителей меньше `MOD²<2^63`. Go и Java также
заранее приводят множители полного цикла. Это сохраняет остаток и
исключает переполнение.

Нельзя поворачивать поле, пополняться после последней клетки или считать
начальный шаг. Нулевой остаток треугольной функции стоит единицу. Длина
противоположного префикса — `L-r-1`, с исключением особой единицы конца
периода. Сохраняйте поправку верхнего и нижнего перехода. Перед
модульным умножением делите чётный множитель прогрессии. Само поле и все
пополнения перечислять нельзя.

## Особенности языков

Везде используются целочисленный НОД и скалярные циклы. C++ и Rust
сохраняют точные большие суммы в 128 битах; Go 1.14 и Java 8 ведут
модульные 64-битные суммы. В Java буферный ввод чисел. Python использует
дополнительный период столбцов и ограниченное модульное накопление;
выбран PyPy 3.10. Буферы содержат лишь ввод и ответы максимум десяти
случаев.
