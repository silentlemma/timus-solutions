# 2011. Не меньше шести различных перестановок

[Timus 2011](https://acm.timus.ru/problem.aspx?space=1&num=2011) · сложность 103 · combinatorics

Автор оригинальной задачи — Алексей Кунгурцев; Уральская региональная командная олимпиада по программированию 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `n` символов трёх возможных типов. Все символы нужно расположить в
слово длины `n`; одинаковые символы неразличимы. Определите, существует
ли хотя бы шесть разных слов. Каждый имеющийся символ используется ровно
один раз.

## Входные данные

В первой строке дано `n`, `1 ≤ n ≤ 100`. Во второй — `n` целых чисел от
1 до 3, обозначающих типы символов. Лимит времени 0,5 секунды, памяти 64
МБ.

## Выходные данные

Выведите `Yes`, если разных слов не меньше шести, иначе `No`. Регистр
важен. Единственный ответ сравнивается по токенам.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
6
1 2 2 3 3 3
```

```
Yes
```

Кратности типов равны 1, 2 и 3. Число разных слов `6!/(1!·2!·3!)=60`,
поэтому ответ `Yes`.

## Решение

Кусочки одного вида одинаковы, поэтому из k кусочков, среди которых
c₁, c₂, c₃ каждого вида, получается k!/(c₁!·c₂!·c₃!) разных слов. Читаем
кусочки по одному и храним это число для прочитанных: когда приходит
k-й кусочек и его вид теперь встречается c раз, число умножается на k и
делится на c нацело. Как только число достигает 6, ответ `Yes`:
оставшиеся кусочки, дописанные в одном и том же порядке, оставят слова
разными. Если 6 так и не набирается, ответ `No`. `O(n)`.

Перед каждым шагом число не больше 5, поэтому 5 · 100 помещается в
любой целый тип; умножать надо до деления.

Подводные камни:

- ровно шесть слов — это уже `Yes`;
- полные факториалы считать нельзя: они переполняются.

## Оптимизированные решения

`2011_combinatorics_optimized.py` используется побайтово без изменений, без второго исходника и нового алгоритма. Accepted точного исходника на CPython 3.12 №11327046: 0.078 с / 732 КБ. Сохранённая выборка актуальных компиляторов семейства Python от 2026-11-20: место по времени 1/52, по памяти 41/52. Поскольку здесь меньше 1024 КБ, строгий критерий первых десяти мест или топ 15% учитывает только время; звёздочка сохраняет отдельную рейтинговую цель языка. У того же файла есть прежний Accepted на PyPy 3.10 №11325480: 0.156 с / 264 КБ. Это парные замеры разных запусков: CPython даёт выбранный результат по времени и рейтингу, PyPy расходует меньше памяти. Прежние замечания об экономии памяти в этом разделе относятся к этому замеру PyPy, а не к строке CPython. Все учебные исходники сохранены без изменений.

`2011_combinatorics_optimized.py`. Сохраняются точная мультиномиальная рекуррентность ways=ways*length/count[value] и остановка при шести вариантах. Блоки 4096 байт разбираются сразу в три частоты без построения всего списка чисел до раннего выхода. Число перестановок при добавлении элемента не уменьшается, поэтому непрочитанный хвост не отменяет успех. Худшее время O(n), память O(B) при ограниченных токенах и размере блока B. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `2011_combinatorics.py`: время 0.109 s → 0.156 s; память 516 KB → 264 KB.

`2011_combinatorics_optimized.java`. Сохраняется инкрементальное мультиномиальное число ways=ways*length/count[newType] с остановкой при достижении шести. Добавление символа не уменьшает число вариантов, поэтому после Yes непрочитанный хвост не нужен. Java оставляет прежнюю раннюю остановку, заменяя Scanner. Rust исключает всю String ввода и вектор разобранных значений, читая типы напрямую. Хранятся лишь три счётчика: время в худшем случае O(n), вспомогательная память O(1). Перед обновлением ways<=5, при n<=100 произведение не больше 500 и помещается в обычные целые; факториалы и длинная арифметика не нужны. Порог >=6 и регистр Yes/No сохранены.

По сравнению с `2011_combinatorics.java`: время 0.125 s → 0.109 s; память 1668 KB → 496 KB.
