# 2005. 五站路线的最短合法顺序

[Timus 2005](https://acm.timus.ru/problem.aspx?space=1&num=2005) · 难度 94 · bruteforce

原题作者 Mikhail Rubinchik. (Prepared by Oleg Merkurev)，出自 2013 年乌拉尔地区中学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

恰好访问五个地点各一次，从 1 出发，在 5 结束。地点 3 不能是倒数第二站。已知每对地点的距离，求总距离最小的合法路线及其长度。允许任意最优路线。

## 输入

一个 5 行 5 列的整数距离矩阵。每项为 0 到 10000，对角线为零，距离对称并满足三角不等式 `d[i][j]≤d[i][k]+d[k][j]`。时间限制 0.5 秒，内存 64 MB。

## 输出

第一行输出最小总距离。第二行按访问顺序输出五个地点编号，以空格分隔。相同最优长度可任选一个路线。

## 评测方式

检查器确认路线合法、输出的长度确实是其长度并且最优；任何最优路线都被接受。

## 样例

```
0 2600 3800 2600 2500
2600 0 5300 3900 4400
3800 5300 0 1900 4500
2600 3900 1900 0 3700
2500 4400 4500 3700 0
```

```
13500
1 2 3 4 5
```

所示路线长度为 `2600+5300+1900+3700=13500`，倒数第二站为 4，满足约束。

## 解法

点 1 在最前，点 5 在最后，所以只有点 2、3、4 的顺序可变：共六种顺序，其中 3 紧挨
在 5 之前的两种是禁止的。尝试其余四种，把每条路线的四段距离相加，取最短的。
`O(1)`。

注意事项：

- 这条规则针对的是最后一站之前的那一站；
- 一条路线的长度在 0 到 40 000 之间，所以最小值要从“尚无”开始，而不是从 0 或 10 000 开始。

## 优化解法

`2005_bruteforce_optimized.py`. 保留穷举路线，但 5×5 费用矩阵用平表，选取不同 a,b 属于 1,2,3 后令第三中间点为 6-a-b，排除结束前为点 2 的情形。仍按原顺序考察同样四条合法路线，并列最优有效。去掉排列元组及矩阵行复制；固定五点下时间、空间为常数。 Accepted 行标明实际评测运行时及成对时间/内存。先 flush 输出，再以 os._exit(0) 跳过解释器清理；实测内存收益属于该运行时，不代表渐近加速。

与 `2005_bruteforce.py` 相比：时间 0.093 s → 0.109 s；内存 432 KB → 212 KB。

`2005_bruteforce_optimized.rs`. 保留五点穷举，输入直接填固定 25 格 i64 费用数组，第三中间点为 6-a-b，去掉冗余第三循环及解析输入向量。直接输出五个顶点，不分配格式化字符串。四条可行路线及平局顺序不变，费用运算范围更宽。时间、空间有常数界。

与 `2005_bruteforce.rs` 相比：时间 0.031 s → 0.015 s；内存 236 KB → 48 KB。

`2005_bruteforce_optimized.java`. Java 保留简单版本所述的算法和数据结构。固定字节缓冲区与 FastInput 替代 Scanner 及其正则表达式、区域设置处理。整数记号直接解析；需要字符串时仍进行 UTF-8 解码，十进制记号仍显式转换为数值。仅在需要前瞻时保存一个记号，输出算法不变。这样减少通用解析开销；表中列出算法工作量，输入扫描与字节数成正比，并使用有界输入缓冲区。

与 `2005_bruteforce.java` 相比：时间 0.125 s → 0.125 s；内存 1616 KB → 496 KB。
