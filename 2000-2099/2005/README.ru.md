# 2005. Кратчайший допустимый маршрут по пяти точкам

[Timus 2005](https://acm.timus.ru/problem.aspx?space=1&num=2005) · сложность 94 · bruteforce

Автор оригинальной задачи — Михаил Рубинчик; подготовка — Олег Меркурьев. Уральская региональная командная олимпиада по программированию 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно посетить пять точек ровно по одному разу, начав в 1 и закончив в
5. Точка 3 не может быть предпоследней. По расстояниям между всеми
парами найдите маршрут минимальной суммарной длины и эту длину. Подходит
любой оптимальный допустимый маршрут.

## Входные данные

Целочисленная матрица расстояний 5 на 5. Значения от 0 до 10000, на
диагонали нули, матрица симметрична и выполняется неравенство
треугольника: `d[i][j]≤d[i][k]+d[k][j]`. Время 0,5 секунды, память 64
МБ.

## Выходные данные

Первая строка — минимальная суммарная длина. Вторая — пять номеров точек
в порядке посещения через пробел. При равенстве длин можно выбрать любой
оптимум.

## Проверка

Проверяющая программа убеждается, что маршрут допустим, напечатанная
длина — его длина и он оптимален; принимается любой оптимальный маршрут.

## Примеры

```
0 2600 3800 2600 2500
2600 0 5300 3900 4400
3800 5300 0 1900 4500
2600 3900 1900 0 3700
2500 4400 4500 3700 0
```

```
13500
1 2 3 4 5
```

Длина показанного маршрута равна `2600+5300+1900+3700=13500`.
Предпоследняя точка 4 удовлетворяет ограничению.

## Решение

Точка 1 первая, точка 5 последняя, поэтому меняется только порядок
точек 2, 3 и 4: шесть порядков, из которых два, где 3 стоит прямо перед
5, запрещены. Перебираем остальные четыре, складываем четыре расстояния
каждого маршрута и берём кратчайший. `O(1)`.

Подводные камни:

- правило касается остановки прямо перед последней;
- маршрут стоит от 0 до 40 000, поэтому минимум начинается с «пока
  ничего», а не с 0 или 10 000.

## Оптимизированные решения

`2005_bruteforce_optimized.py`. Полный перебор маршрутов сохраняется, но матрица 5×5 хранится плоско, а третья промежуточная вершина получается как 6-a-b после выбора различных a,b из 1,2,3. Вершина 2 непосредственно перед финишем запрещается. Те же четыре допустимых маршрута идут в прежнем порядке, равные оптимумы остаются корректными. Убраны кортежи перестановок и копии строк матрицы; при пяти точках время и память постоянны. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `2005_bruteforce.py`: время 0.093 s → 0.109 s; память 432 KB → 212 KB.

`2005_bruteforce_optimized.rs`. Сохраняется перебор маршрутов на пяти точках, но ввод сразу заполняет массив из 25 стоимостей i64, третья промежуточная вершина равна 6-a-b. Убраны лишний третий цикл и вектор разобранного входа. Пять вершин выводятся напрямую без форматированных строк. Сохранены те же четыре маршрута и порядок равных оптимумов, арифметика стоимости расширена. Время и память ограничены константой.

По сравнению с `2005_bruteforce.rs`: время 0.031 s → 0.015 s; память 236 KB → 48 KB.

`2005_bruteforce_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `2005_bruteforce.java`: время 0.125 s → 0.125 s; память 1616 KB → 496 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2005_bruteforce_optimized.java`: место по времени 106/170, по памяти 13/170 в этой сопоставимой выборке.

`2005_bruteforce_optimized.py`: место по времени 33/50, по памяти 1/50 в этой сопоставимой выборке.

`2005_bruteforce_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
