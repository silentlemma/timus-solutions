# 2098. Заплатить наличными или переплатить за страховку

[Timus 2098](https://acm.timus.ru/problem.aspx?space=1&num=2098) · сложность 325 · math

Автор оригинальной задачи — Денис Дублённых; Открытое личное первенство УрФУ по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

После мелкой аварии водитель может заплатить b рублей наличными или
оформить её и дать заплатить страховой. Страховка стоит c сейчас и
дорожает на d каждый год, так что следующие k лет стоят c + d, c + 2d,
…, c + kd; после оформленной аварии эти k платежей на p процентов выше.
Скажите, какой вариант дешевле (при равенстве — Insurance), и на
сколько. Ограничения: 1 секунда и 64 МБ.

## Входные данные

b (до 10⁵), затем c и d (до 10⁴), затем k и p (до 100).

## Выходные данные

`Cash` или `Insurance`, затем выгода с абсолютной или относительной
погрешностью не больше 10⁻⁶.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
10000
5000 1000
3 50
```

Вывод:

```
Cash
500.00
```

### Пример 2

Ввод:

```
15000
2500 1000
4 25
```

Вывод:

```
Insurance
10000.00
```

## Решение

Оба варианта платят обычную страховку S = k·c + d·k(k + 1)/2 за
следующие k лет. Наличные добавляют b, оформление — S·p/100. Сравнение
100·b с S·p оставляет всё в целых (не больше примерно 5·10⁹), а их
разность по модулю, делённая на 100, — выгода, она печатается точно с двумя
знаками.

В первом примере S = 21000, так что оформление стоит на 10500 больше, а
наличные — на 10000: Cash, выгода 500.

## Оптимизированные решения

`2098_math_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `2098_math.java`: время 0.125 s → 0.093 s; память 1 716 KB → 904 KB.

Rust сравнивает 100b с целочисленной надбавкой p·k·(2c+d(k+1))/2. Модуль разности уже равен экономии в сотых, поэтому выводятся целая часть и две дробные цифры. При равенстве выбирается Insurance. Все вычисления используют 64-битные целые и обходятся без форматирования вещественных чисел. Ввод и весь ответ помещаются в фиксированные байтовые буферы. Rust читает и пишет через библиотеку времени исполнения C.

Принятые базовые реализации [2098_math.cpp](2098_math.cpp), [2098_math.go](2098_math.go), [2098_math.java](2098_math.java), [2098_math.py](2098_math.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`2098_math_optimized.java`: место по времени 3/32, по памяти 9/32 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
