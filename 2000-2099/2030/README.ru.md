# 2030. Рассылка значений соседям дерева

[Timus 2030](https://acm.timus.ru/problem.aspx?space=1&num=2030) · сложность 517 · dfs

Автор оригинальной задачи — Никита Сивухин; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано связное неориентированное дерево из `n` вершин с номерами от 1 до `n`.
Изначально в вершине `v` записано целое `a[v]`. Запросы выполняются по порядку:

- `1 v`: прибавить текущее значение вершины `v` к значению каждого её соседа.
  Значение самой вершины `v` остаётся прежним.
- `2 v`: вывести текущее значение в `v` по модулю `P = 1000000007`.

Значение источника фиксируется до начала рассылки; сосед получает прибавку,
а не замену своего значения. Все предыдущие рассылки учитываются в следующих.
Ограничения: `1 ≤ n,m ≤ 100000`, `0 ≤ a[v] ≤ 1000000000`, 2 секунды, 64 МБ.

## Входные данные

Сначала дано `n`, затем строка из `n` начальных значений. В следующих
`n-1` строках даны концы рёбер `x y`: `1 ≤ x,y ≤ n`, `x ≠ y`. Связность
гарантирована. Далее записаны число `m` и `m` пар `t v`, где `t` равно 1
или 2, `1 ≤ v ≤ n`.

## Выходные данные

Для каждого запроса второго типа вывести отдельной строкой остаток из `[0,P-1]`.
Если таких запросов нет, вывод пуст. В дереве из одной вершины рассылка ничего
не меняет.

## Проверка

Ответы сравниваются по токенам.

## Решение

Укореним дерево в вершине 1 итеративным обходом. У любой вершины среди соседей
есть единственный родитель, если вершина не корень, и некоторое число детей.
Разделим рассылку на одну прибавку родителю и общую отложенную прибавку детям.

Храним `direct[v]`, изначально `a[v]`, и `broadcast[v]`, изначально
ноль. `broadcast[v]` — сумма значений, которые когда-либо рассылала сама
вершина `v`. `direct[v]` содержит начальное значение и все прибавки от
рассылок детей. Поддерживаем инвариант: для некорневой вершины `value(v)
= direct[v] + broadcast[parent[v]] (mod P)`, а для корня —
`direct[root]`.

При любом запросе сначала вычисляем `delta = value(v)`. Запрос второго типа
выводит это число. При рассылке прибавляем `delta` к `broadcast[v]` и, если
есть родитель, к `direct[parent[v]]`. Все суммы берём по модулю `P`.
Обход соседей во время запросов не требуется.

### Доказательство

Вначале рассылок нет и инвариант даёт начальные значения. Пусть он
выполнен перед рассылкой. Значение каждого ребёнка `v` включает
`broadcast[v]`, поэтому изменение единственного общего поля прибавляет
каждому ребёнку ровно `delta`. Родитель получает такую же прибавку в
собственное поле `direct`. Источник читает свои `direct` и `broadcast`
родителя: оба поля не изменились, поэтому источник не увеличивается. Для
остальных вершин не изменилось ни одно поле их формулы. Следовательно,
выполнено в точности требуемое действие и инвариант сохранён. Запросы
чтения выводят значение инварианта и ничего не меняют; индукция
доказывает все ответы. Сокращение по модулю корректно, поскольку
используются только сложения.

В первом примере первые четыре чтения дают единицы. Рассылка вершины 1
увеличивает только вершины 2 и 3 до двух; в вершинах 1 и 4 остаются
единицы. Во втором примере чередующиеся рассылки по единственному ребру
дают запрошенные значения `1,1,2,3,5,8,13,21`.

Обход занимает `O(n)`, каждый запрос — `O(1)`, суммарно `O(n+m)`
времени. Дерево, родители и массивы значений требуют `O(n)` рабочей
памяти. Python хранит до `O(m)` строк вывода, Rust также сохраняет вход:
с учётом буферов это `O(n+m)`. C++, Go и Java обрабатывают запросы и
вывод потоково.

Подводные камни:

- Источник не получает собственную прибавку: петель в дереве нет.
- Текущее значение источника вычисляется до изменения полей.
- Нужна сумма рассылок родителя, а не текущее значение родителя.
- Корень обрабатывается отдельно, без фиктивной прибавки от самого себя.
- На цепочке из 100000 вершин нужен итеративный обход.
- При отсутствии чтений нельзя печатать лишний ноль.

## Особенности языков

После каждого сложения поля нормализуются; сумма двух остатков не больше
`2000000012`, поэтому помещается даже в Java `int`. В C++, Go и Rust
значения хранятся в более широком типе. Достаточно одного условного
вычитания модуля. Java использует примитивные массивы смежности и
байтовый ввод. Python читает построчно и освобождает временную смежность
после итеративного построения родителей. Рекурсия, порог степени и
логарифмические структуры не нужны.
