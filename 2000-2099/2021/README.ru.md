# 2021. Как отложить очевидную победу

[Timus 2021](https://acm.timus.ru/problem.aspx?space=1&num=2021) · сложность 462 · sorting

Автор оригинальной задачи — Олег Долгоруков; NEERC 2014, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В двух командах по `n` участников, каждому заранее известен целый результат
от 0 до 6 очков. Нужно устроить `n` раундов, по одному участнику каждой
команды в раунде, использовав всех ровно один раз. Оба результата раунда
объявляются одновременно. Побеждает команда с большей итоговой суммой,
а при равенстве получается ничья. Зрители заранее знают лишь границы очков.

Выберите порядки так, чтобы как можно позже наступил первый раунд, после
которого по объявленным результатам можно гарантировать победу команды.
После `k` раундов при `r=n−k` оставшихся и разности очков `d` победа
гарантирована ровно при `|d| > 6r`. При равенстве ещё возможна ничья.
Если победитель не определён раньше, весь исход становится известен после
последнего раунда, включая случай итоговой ничьей.

Ограничения: `2 ≤ n ≤ 1000`, результат каждого участника от 0 до 6.
Лимиты: 1 секунда, 64 МБ.

## Входные данные

Первая строка содержит `n`, вторая — `n` очков первой команды, третья —
`n` очков второй. В каждой команде участники независимо пронумерованы
от 1 до `n` в порядке ввода.

## Выходные данные

Выведите `n` строк, в каждой — номера участников первой и второй команды
данного раунда. Каждый номер должен встретиться один раз в своём столбце.
Допустим любой глобально оптимальный порядок.

## Проверка

Проверяющая программа сверяет обе перестановки, проигрывает счёт и
принимает любые порядки, при которых первый решающий раунд наступает как
можно позже.

## Примеры

```
5
0 1 4 3 6
6 5 1 3 0
```

```
5 1
1 5
4 4
2 3
3 2
```

## Решение

Сравним **итоговые суммы**, которые не зависят от перестановок. Если первая
команда побеждает, поставим её участников по возрастанию очков, а вторую
команду — по убыванию. Если побеждает вторая, направления меняются местами.
При равных суммах годятся любые порядки; используем возрастание обеих команд.
Совместим полученные списки по позициям, сохранив исходные номера.

Докажем оптимальность для итоговой разности `D>0` в пользу первой
команды. После любого префикса при `r` оставшихся раундах обозначим
через `R` разность, которую дадут фактически оставшиеся участники. Один
раунд добавляет от −6 до 6, поэтому `R≤6r` и `d=D−R≥D−6r>−6r`. Будущая
проигравшая команда не может получить гарантированную победу ни при
каком порядке этих участников. Значение имеет только верхний порог
`d>6r`.

Для каждой длины префикса `k` возрастание первой команды даёт наименьшую
возможную сумму её `k` первых результатов, а убывание второй — наибольшую
сумму соперника. Их сочетание минимизирует `d(k)` среди **всех** порядков
сразу для каждого `k`. Если в этом порядке победа впервые гарантирована
в раунде `k<n`, в любом другом порядке разность в этом раунде не меньше,
поэтому победа там уже определена. Отложить её дольше нельзя. Если дошли
до последнего раунда, достигнута максимально возможная задержка.
Для победы второй команды доказательство симметрично.

При `D=0` любой префикс даёт `d=−R`, значит, `|d|≤6r`. Ни один порядок
не гарантирует победителя до раскрытия итоговой ничьей, так что любой оптимален.
Даже большой временный отрыв будущей проигравшей команды безопасен:
реальные оставшиеся очки не позволяют превысить порог определённости.

В примере итоговые суммы равны 14 и 15. Показанные первые четыре пары
приносят командам одинаковые очки, а последняя — 4 и 5. Победитель
определяется лишь в пятом раунде, что оптимально.

Сортировка двух массивов номеров занимает `O(n log n)` времени и `O(n)`
памяти. Модули сумм и разностей не больше 6000, обычного целого типа достаточно.

Подводные камни:

- Направления сортировки определяются итоговыми суммами, а не текущим отрывом.
- Сравнение `|d| > 6r` строгое: равенство ещё допускает ничью.
- Очки пары объявляются вместе; каждый участник используется один раз в
  своей команде.
- Выводятся исходные номера с единицы, а не очки или позиции после сортировки.
- Принимайте любой оптимальный порядок, в том числе произвольный при
  равных итогах.

## Особенности языков

Во всех версиях номера сортируются по `(очки, номер)`, затем порядок
будущей проигравшей команды разворачивается. Второй ключ лишь делает
вывод определённым. C++ и Go используют сортировку сравнением, Python —
ключи, Rust — ключи-кортежи, Java 8 — объектный массив номеров с компаратором.
