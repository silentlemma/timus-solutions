# 2021. 尽量推迟胜负确定的时刻

[Timus 2021](https://acm.timus.ru/problem.aspx?space=1&num=2021) · 难度 462 · sorting

原题作者 Oleg Dolgorukov，出自 NEERC 2014 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

两队各有 `n` 名参与者，每人预定得到 0 至 6 的整数分数。安排 `n` 轮，
每轮每队各出一人，每人恰好出场一次。每轮两人的分数同时公布。最终总分
较高的队获胜，相等则平局。观众事先只知道分数范围。

选择两队顺序，使观众能够保证某队获胜的第一轮尽量晚。完成 `k` 轮、
剩余 `r=n−k` 轮、当前分差为 `d` 时，只有 `|d| > 6r` 才能保证胜利。
等号仍允许平局。若此前没有保证胜者，最终一轮后全部结果明确，包括平局。

`2 ≤ n ≤ 1,000`，个人得分为 0 至 6。时间限制 1 秒，内存限制 64 MB。

## 输入

第一行是 `n`，第二、三行分别给出两队各 `n` 个分数。
每队按输入顺序独立从 1 至 `n` 编号。

## 输出

输出 `n` 行，每行是本轮第一队和第二队的编号。两列各为完整排列。
可以输出任意全局最优顺序。

## 评测方式

检查器核对两个排列，重放比分，接受任何使第一个已确定胜负的轮次尽可能晚的顺序。

## 样例

```
5
0 1 4 3 6
6 5 1 3 0
```

```
5 1
1 5
4 4
2 3
3 2
```

## 解法

先比较不受顺序影响的**最终总分**。若第一队获胜，将第一队按分数升序，
第二队降序；若第二队获胜，交换方向。总分相等时任意顺序均可，程序
让两队都升序。保留原编号，将两条有序列表按位置配对。

设第一队最终领先 `D>0`。任意前缀后剩余 `r` 轮，实际剩余参与者会增加
分差 `R`。每轮差值在 −6 至 6，因此 `R≤6r`，有 `d=D−R≥D−6r>−6r`。
最终输的一队不可能在任何排列中提前得到保证胜利，所以只需考虑上界 `d>6r`。

对每个前缀长度 `k`，第一队升序取得其最小的 `k` 人分数和，第二队降序
取得对方最大的 `k` 人分数和。因此这个方案对**每一个** `k` 同时把
`d(k)` 降到所有顺序中的最小值。若本方案在 `k<n` 时首次保证胜利，
其他方案在同一轮的分差不小，必然已确定胜利，无法拖得更晚。若直到
最终轮才确定，已达到最大可能延迟。第二队获胜的情形完全对称。

若 `D=0`，任何前缀都有 `d=−R`，所以 `|d|≤6r`。没有任何顺序能在
最后平局公布前保证胜者，故任意顺序最优。最终输的一队即使暂时领先
很多，也不会过早保证胜利：实际剩余得分的范围排除了这种情况。

样例两队总分为 14、15。给出的前四轮两队分别同分，最后一轮为 4 对 5，
直到第五轮才确定获胜队，已经最优。

排序两个编号数组耗时 `O(n log n)`，空间 `O(n)`。
总分和分差绝对值至多 6,000，普通整数足够。

注意事项：

- 根据最终总分决定排序方向，不能根据当前分差改变规则。
- 必须用严格比较 `|d| > 6r`，等号仍可能平局。
- 两人的分数同时公布，每队每个编号只能使用一次。
- 输出从 1 开始的原始编号，不是分数或排序后的位置。
- 接受任意最优顺序，尤其总分相等时所有顺序都合法最优。

## 各语言说明

五种实现均按 `(分数, 编号)` 排序并反转最终输队的顺序。编号作为第二
关键字仅用于确定性输出。C++、Go 使用比较排序，Python 使用排序键，
Rust 使用元组键，Java 8 使用带比较器的装箱编号数组。
