# 2041. Порядок со строгими ограничениями соседей

[Timus 2041](https://acm.timus.ru/problem.aspx?space=1&num=2041) · difficulty 2106 · greedy, dsu

Автор оригинальной задачи — Олег Меркурьев; Ural FU Dandelion contest. Petrozavodsk training camp. Summer 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `n` пронумерованных объектов с внутренним объёмом `a_i` и внешним
объёмом `b_i`. Нужно упорядочить все объекты так, чтобы для каждой
соседней пары `u,v` выполнялось строгое неравенство `b_u>a_v`. Условие
относится только к соседним парам. Определите возможность такого порядка
и постройте его.

## Входные данные

Первая строка содержит `2≤n≤100000`. В следующих `n` строках записаны
`a_i,b_i`, причём `1≤a_i≤b_i≤1000000`. Равенство внутреннего и внешнего
объёмов разрешено. Исходные номера идут от `1` до `n`. Лимит времени — 1
секунда, памяти — 64 МБ.

## Выходные данные

Если порядка нет, выведите `No`. Иначе выведите `Yes` и перестановку
всех `n` исходных номеров. Подходит любой допустимый порядок.

## Проверка

Проверяется любая полная перестановка: диапазон и уникальность номеров,
число токенов и каждое строгое неравенство соседей. Для `No` проверяющий
скрипт независимо считает точечные объекты и строго пересекающие объём
интервалы, как описано ниже. Совпадение с одной фиксированной
перестановкой не требуется.

## Примеры

```
3
1 5
2 2
6 7
```

```
Yes
3 1 2
```

```
3
2 2
2 2
3 4
```

```
No
```

В первом примере порядок `3,1,2` даёт `7>1` и `5>2`. Программы могут
вывести `3,2,1` — это тоже верно. Во втором примере между двумя `(2,2)`
нужен переход к внешнему объёму больше `2`; объект `(3,4)` не может идти
непосредственно после `(2,2)` и такой переход не обеспечивает.

## Решение

### Максимальный допустимый внутренний объём

Пусть `B` — внешний объём последнего выбранного объекта; сначала
`B=max(b_i)+1`. Среди оставшихся выбираем максимальное `a_i<B`, а при
равном `a_i` — максимальное `b_i`. Добавляем исходный номер, заменяем
`B` на `b_i` и удаляем выбранный объект. При совпадении обеих величин
номер неважен; реализации выбирают наибольший. Если допустимых объектов
больше нет, а не все использованы, ответ `No`.

Приоритет внешнего объёма важен: для `(2,2),(2,3)` сначала нужен второй
объект. Выбор точки первым ошибочно завёл бы алгоритм в тупик.

### Почему остановка означает невозможность

Назовём `a<b` интервалом, а `(x,x)` — точкой в `x`. Каждый
неиспользованный интервал всегда остаётся допустимым. Если допустимый
интервал `v` не выбран, выбранный `u` имеет `a_u≥a_v`. При строгом
неравенстве `b_u≥a_u>a_v`. При равенстве дополнительный приоритет даёт
`b_u≥b_v>a_v`. Значит, `v` допустим и на следующем шаге. Вначале
допустимы все, поэтому индукция доказывает утверждение. При остановке
остаются только точки.

Для фиксированного `x` обозначим число точек `(x,x)` через `K(x)`, а
число интервалов `a<x<b` через `T(x)`. Для любого допустимого порядка
необходимо `K(x)≤T(x)+1`. Между последовательными появлениями точки `x`
внешний объём должен впервые перейти от значения не больше `x` к
значению больше `x`. Первый осуществляющий это объект имеет `b>x`, а
допустимое предыдущее ребро требует `a<x`. Поэтому каждому из `K(x)-1`
непересекающихся промежутков нужен свой строго пересекающий `x`
интервал.

Пусть жадный алгоритм остановился, а точка `x` осталась. Когда `B>x`,
эта точка допустима, поэтому выбранное внутреннее значение не меньше
`x`. Такая фаза не может опустить `B` ниже `x` и заканчивается только
выбором точки в `x`, после чего `B=x`. Пересекающий `x` интервал в этой
фазе не выбирается: его внутренний объём меньше `x`. Каждый такой
интервал выбирается при `B≤x` и начинает новую фазу `B>x`. При остановке
`B≤x`, а все интервалы уже использованы по инварианту. Итак, одна
начальная фаза и `T(x)` новых закончились выбором `T(x)+1` точек в `x`.
Ещё хотя бы одна осталась, откуда `K(x)>T(x)+1`. Нарушено необходимое
условие любого порядка.

Успешный жадный проход допустим по построению, а неуспешный даёт
доказательство невозможности. Тем самым доказана и достаточность
отдельных неравенств для всех `x`. Нельзя заменять их общим
паросочетанием точечных классов и интервалов: один интервал способен
помочь нескольким различным объёмам в одном порядке.

### Предшественник с удалениями

Сортируем тройки `(a,b,номер)` по возрастанию. Их позиции — `1..n`,
позиция `0` служит сторожем. Двоичный поиск первой позиции с `a≥B` даёт
число `c` позиций с `a<B`. Нужна наибольшая ещё доступная позиция не
больше `c`; порядок сортировки обеспечивает оба приоритета.

Используем систему непересекающихся множеств с делением пути пополам,
объединением по рангу и минимальной позицией `best` в корне. Вначале
позиции одиночны. Удаляя доступную `p`, объединяем её компоненту с
компонентой `p-1`. Компоненты — непрерывные отрезки `[l,r]`: все позиции
`(l,r]` удалены, а `l` ещё доступна либо равна сторожу. Поэтому
`best[find(c)]` — в точности искомый предшественник. Сам номер корня
может быть удалён; ответом является сохранённый минимум, а не корень.
Нулевой ответ означает отсутствие допустимого объекта. Все поиски
итеративны.

Сортировка и `n` двоичных поисков требуют `O(n log n)`, сбалансированные
операции DSU добавляют `O(n α(n))`. Итого время `O(n log n)`, память
`O(n)` вместе с ответом. Дерево Фенвика по доступным отсортированным
позициям даёт альтернативную реализацию за `O(n log n)`.

Неравенство соседей строгое, хотя во входе разрешено `a=b`. При равных
внутренних объёмах сначала сравнивается внешний объём и только потом
номер. Номер корня DSU сам по себе не является предшественником: нужен
сохранённый минимум. Запас переходов проверяется отдельно для каждого
точечного объёма, поскольку один интервал может помогать нескольким
классам. Допустимый вывод может отличаться от порядка в примере.

## Особенности языков

C++, Go и Rust хранят тройки и массивы DSU напрямую. Go использует
совместимую с 1.14 сортировку и буферный ввод-вывод. В Rust двоичный
поиск итеративен, вывод буферизован. В Java 8 применены байтовый буфер
ввода, массивы троек, байтовые ранги и StringBuilder. Python читает пары
построчно, использует отсортированные тройки, `bisect_left` и bytearray
рангов; итеративное деление пути не расходует стек рекурсии. Везде
сохраняются исходные номера от единицы, а двоичный поиск исключает
равенство `a=B`.
