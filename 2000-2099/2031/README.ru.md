# 2031. Ряд, превращающийся в последовательные числа

[Timus 2031](https://acm.timus.ru/problem.aspx?space=1&num=2031) · сложность 88 · bruteforce

Автор оригинальной задачи — Никита Сивухин; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Построить ряд из `n` десятичных чисел, который после поворота всего ряда на 180
градусов становится возрастающим отрезком последовательных положительных целых.
Каждое напечатанное число состоит ровно из двух цифр: однозначные дополняются
ведущим нулём. Поворот меняет порядок чисел и порядок цифр внутри каждого числа.
Цифры `0`, `1`, `8` переходят в себя, `6` и `9` — друг в друга. Остальные
цифры становятся нечитаемыми и не подходят.

Ограничение: `1 ≤ n ≤ 99`. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Одно целое `n` — количество чисел в требуемом ряду.

## Выходные данные

Любой подходящий ряд из `n` двухзначных записей через пробел. При
отсутствии решения вывести в точности `Glupenky Pierre`. После
переворота все числа должны быть положительными: `00` недопустимо. В
остальных записях ведущие нули сохраняются.

## Проверка

Проверяющая программа переворачивает напечатанный ряд и убеждается, что
получается отрезок подряд идущих положительных чисел из двух читаемых
цифр каждое; ответ о невозможности принимается, только если такого
отрезка нет. Принимается любой подходящий ряд.

## Примеры

```
2
```

```
11 01
```

```
99
```

```
Glupenky Pierre
```

## Решение

Вверх ногами читаются только цифры 0, 1, 6, 8 и 9, поэтому после
поворота могут получиться лишь числа от 1 до 99, составленные из них.
Идём по 1 … 99, считаем текущую серию подряд идущих читаемых чисел и
останавливаемся, когда она достигает n на некотором числе r. Тогда
выводим r, r − 1, …, r − n + 1 вверх ногами: у каждого числа сначала
повёрнутая цифра единиц, затем повёрнутая цифра десятков, так что
повёрнутый ряд читает серию по возрастанию. Если ни одна серия не
достаточно длинная, ответ `Glupenky Pierre`. `O(100 + n)`.

Читаемые числа: 1, 6, 8, 9, 10, 11, 16, 18, 19, 60, 61, 66, 68, 69, 80,
81, 86, 88, 89, 90, 91, 96, 98, 99; самые длинные серии, 8–11 и 88–91,
содержат по четыре числа, так что ответ есть только при n ≤ 4.

Подводные камни:

- при повороте 6 и 9 меняются местами;
- ведущий ноль сохраняется: 01 вверх ногами — это 10;
- 00 превратилось бы в 0, а оно не положительное.

## Оптимизированные решения

`2031_bruteforce_optimized.py`. Сохраняются перебор целей 1..99 и заданная карта перевёрнутых цифр. После первого отрезка из n подходящих целей метки выводятся в обратном порядке целей, иначе сохраняется точное сообщение Glupenky Pierre. Алгоритм поиска прежний. В Python меняются только ввод и организация выполнения; простая функция сохранена. Время O(99+n), вывод ограничен фиксированным двузначным диапазоном. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `2031_bruteforce.py`: время 0.078 s → 0.14 s; память 420 KB → 232 KB.

`2031_bruteforce_optimized.rs`. Сохраняются поиск отрезка в 1..99 и точная карта перевёрнутых цифр. Каждая двухбайтовая метка выводится через среду C напрямую без строки ответа; единственное число читается без сохранения текста входа. Сохранены обратный порядок целей, метки с ведущим нулём и точная фраза ошибки. Время O(99+n), дополнительная память O(1); простая версия со String остаётся.

По сравнению с `2031_bruteforce.rs`: время 0.015 s → 0.015 s; память 204 KB → 56 KB.

Оптимизированное решение на C++ читает `n` через `getchar` и печатает
цифры по одной через `putchar`, без `iostream` и без сборки строки:
88 КБ вместо 368 КБ при том же времени.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`2031_bruteforce_optimized.go`. Алгоритм и обработка границ сохранены. Вместо сканирования и печати через fmt используются разбор токенов и чисел и повторно используемый выходной буфер. Ввод целиком хранится в байтовом буфере: это обмен памяти под ввод на меньшие накладные расходы универсального ввода-вывода.

Accepted #11328623 (Go 1.14 x64): **0.015 s / 944 KB**. Архивное сравнение: `2031_bruteforce.go` (Go 1.14 x64) — 0.031 s / 1152 KB (#11303665).

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2031_bruteforce_optimized.py`: место по времени 44/46, по памяти 3/46 в этой сопоставимой выборке.

`2031_bruteforce_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
