# 2031. 旋转后得到连续整数的一行数

[Timus 2031](https://acm.timus.ru/problem.aspx?space=1&num=2031) · 难度 88 · bruteforce

原题作者 Nikita Sivukhin，出自 2014 年乌拉尔地区中学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

构造一行 `n` 个十进制数，使整行旋转 180 度后成为递增的连续正整数段。
每个输出数恰有两位，一位数必须补前导零。旋转既反转整行数的顺序，也反转每个数的数字顺序。
`0`、`1`、`8` 旋转后不变，`6` 与 `9` 互换，其他数字不可读，不能使用。

限制：`1 ≤ n ≤ 99`，1 秒，64 MB。

## 输入

一个整数 `n`，表示所需行中的数目。

## 输出

输出任意合法的 `n` 个两位数，以空格分隔。无解则精确输出 `Glupenky Pierre`。
旋转后的数必须为正，因此 `00` 不合法；其他两位表示中的前导零必须保留。

## 评测方式

检查器把输出的一行旋转过来，确认得到的是连续的正整数，每个数都由两位可读数字组成；只有不存在这样的连续段时才接受“无解”的回答。任何合法的一行都被接受。

## 样例

```
2
```

```
11 01
```

```
99
```

```
Glupenky Pierre
```

## 解法

先寻找旋转后的目标。每个目标在 1 至 99 内，其两位数字（含可能的前导零）都属于
`0,1,6,8,9`。按整数递增扫描，维护当前连续可读数字段的长度；不可读数将长度清零。
在整数 `r` 处长度达到 `n` 时，就找到区间 `[r-n+1,r]`。

构造原行时从 `r` 递减到 `r-n+1`。每个目标先输出个位的旋转数字，再输出十位的
旋转数字。以字符拼接确保宽度为二。若扫描结束仍没有足够长的段，则声明无解。

### 正确性

旋转映射是对合，应用两次恢复每个可读数字。构造行恰为目标区间的逆旋转。
整行反转恢复目标的递增顺序，单词内反转与数字映射恢复各目标的两位数字，因此结果
正好是选定的连续正整数。

反过来，任意合法输出旋转后一定是在 `[1,99]` 内、数字可读的连续正整数区间。
完整扫描会依次经过该区间的所有整数，当前长度必然达到 `n`。所以扫描失败严格证明无解。

所有可读的正目标为
`1,6,8,9,10,11,16,18,19,60,61,66,68,69,80,81,86,88,89,90,91,96,98,99`。
最长连续段是 `[8,11]` 和 `[88,91]`，长度都是四，因此仅长度一至四可行；程序自行寻找段，
无需硬写此阈值。

首例 `11 01` 旋转为 `10 11`；程序也可以输出 `60 80`，旋转为 `08 09`，同样合法。
第二例要求 99 个数，超过最大连续段长，应输出指定短语。

最多扫描 99 个整数，成功时输出 `n` 个词：时间 `O(100+n)`、扫描状态 `O(1)`、输出缓冲
`O(n)`。固定两位范围使枚举工作为常数。

注意事项：

- 同时反转整行单词顺序及每个词的数字顺序。
- `6` 与 `9` 必须互换，只反转字符不够。
- 前导零属于固定两位表示。
- 目标区间不能包含零。
- 合法的另一个区间不必与样例标记相同。

## 各语言说明

所有实现拼接映射后的数字字符，不把旋转结果先转为整数，以保留前导零。不可读数字用标记
表示。Rust 用 `r-offset` 构造递减目标，找到的段保证 `r ≥ n`，故无符号减法安全。
无需大整数或浮点数。
