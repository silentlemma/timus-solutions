# 2052. Посчитать неподвижные позиции после сортировки по сумме цифр

[Timus 2052](https://acm.timus.ru/problem.aspx?space=1&num=2052) · difficulty 1485 · dp, binary_search

Автор оригинальной задачи — Александр Ипатов; подготовка — Булат Зайнуллин. XIX Открытый чемпионат Урала по спортивному программированию (апрель, 2015).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Числа 1, …, n сортируют по сумме десятичных цифр, при равенстве — по
значению. Посчитайте числа, которые остались на своём месте.
Ограничения: 1 секунда и 64 МБ.

## Входные данные

Одно целое число n, 2 ≤ n ≤ 10⁹.

## Выходные данные

Количество позиций, которые не изменились.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
19
```

```
3
```

Для девятнадцати получается порядок
`1,10,2,11,3,12,4,13,5,14,6,15,7,16,8,17,9,18,19`. На месте остались
ровно `1,18,19`, поэтому ответ три. Суммы их цифр — один, девять и
десять.

## Решение

### Формула позиции после сортировки

Пусть `C(b,s)` — количество положительных чисел не больше `b` с суммой
цифр `s`. Обозначим `L_s=sum_{t<s} C(n,t)`. Группа суммы `s` занимает
позиции `[L_s+1,L_s+C(n,s)]`. Если сумма цифр `x` равна `s`, то его
новая позиция `rank(x)=L_s+C(x,s)`. Сначала идут меньшие суммы цифр,
затем числа той же группы вплоть до `x` включительно, поскольку внутри
группы порядок числовой. Позиция сохраняется ровно при `x-C(x,s)=L_s`.

### Не более одного совпадения на сумму цифр

Пусть члены одной группы по возрастанию — `x_1<x_2<…`. Их новые позиции
— `L_s+j`. У соседних целых чисел суммы цифр различаются: прибавление
единицы меняет сумму на `1-9k`, где `k` — число конечных девяток, и это
не ноль. Значит, `x_{j+1}≥x_j+2`, поэтому `x_j-j` строго возрастает.
Равенство `L_s` возможно не более одного раза. Достаточно найти одного
кандидата для каждой суммы цифр.

Функция `F_s(b)=b-C(b,s)` не убывает: при увеличении `b` на единицу
счётчик увеличивается на ноль или один. В интервале позиций группы
двоичным поиском ищем **последнее** число с `F_s(b)≤L_s`; пустые группы
пропускаем. Проверяем, что кандидат внутри интервала, имеет сумму цифр
`s` и удовлетворяет точному равенству. Тогда увеличиваем ответ на один.

Полнота следует так. Любое неподвижное число находится внутри интервала
позиций своей группы и удовлетворяет предикату. Следующее за ним число
имеет другую сумму цифр, поэтому `F_s` сразу становится `L_s+1`, если
интервал поиска ещё не закончился. Из монотонности дальше подходящих
чисел нет. Значит, существующее неподвижное число обязательно будет
найдено. Финальные проверки гарантируют правильность каждого учтённого
кандидата.

### Точный подсчёт за линейное число цифр

Пусть `D` — число цифр `n`, `S=9D`. Предвычислим `W_l(q)` — количество
десятичных строк длины `l` с суммой `q`, разрешая ведущие нули. Имеем
`W_0(0)=1` и `W_l(q)=sum_{a=0..9} W_{l-1}(q-a)`. Строку удобно считать
скользящим окном. Храним префиксы `P_l(q)=sum_{r≤q} W_l(r)`: при
отрицательном индексе значение ноль, выше возможной суммы — `10^l`.
Нужны длины до `D-1`.

Для подсчёта чисел до `b` просматриваем его цифры слева направо,
поддерживая оставшуюся сумму `q`. Если текущая цифра `d` и справа ещё
`l` цифр, меньшие варианты `a=0,…,d-1` оставляют хвосту суммы `q-a`. Их
количество равно `P_l(q)-P_l(q-d)`. Прибавляем его, вычитаем `d` из `q`
и продолжаем по равному префиксу. При отрицательной оставшейся сумме
завершаем; в конце само `b` добавляется ровно при `q=0`. Меньшие по
длине числа имеют единственное представление с ведущими нулями.
Запрашиваются только положительные суммы `s≥1`, поэтому ноль
автоматически исключён из рангов. Получаем `C(b,s)` за `O(D)` без
перебора чисел.

Перебираем `s=1,…,S`, вычисляем размер группы, выполняем поиск и
накапливаем `L_s`. Все счётчики и позиции целые; свободных цифр в
таблицах здесь не больше девяти, 64-битных чисел достаточно с запасом.

Позиции нумеруются от единицы, `x` включается в `C(x,s)`. Нули допустимы
в цифровых хвостах, но само число ноль не входит в группы. Важны пустые
группы и переносы через девятки. Предикат монотонен только при
фиксированной сумме цифр: вся перестановка не является монотонным
числовым порядком. Ищется последний подходящий кандидат с обязательной
проверкой его суммы цифр; соседнее число вне группы может удовлетворять
тому же неравенству. Добавлять не больше единицы позволяет доказанная
уникальность.

## Особенности языков

Предвычисление занимает `O(D·S)` времени и памяти. Не более `S` поисков
по `O(log n)` шагов с подсчётом за `O(D)` дают итоговое время
`O(D·S·(1+log n))` и дополнительную память `O(D·S)`. Здесь `D≤10,S≤90`.
Полная перестановка не строится.

Все пять версий используют одни префиксы количества хвостов и поиск по
интервалам групп. В C++/Go/Java/Rust счётчики 64-битные, в Python —
точные целые. Десятичные строки используются только для не более десяти
цифр запроса, не для перебора всех чисел.
