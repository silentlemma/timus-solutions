# 2084. Порядок задач, гасящих долг

[Timus 2084](https://acm.timus.ru/problem.aspx?space=1&num=2084) · сложность 3114 · dp, sorting

Автор оригинальной задачи — Никита Бурлаков.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Долг вначале равен X. Каждая из N задач сначала уменьшает долг на aᵢ (не
ниже нуля), а затем приносит max(0, bᵢ − D), где D — долг в этот момент.
Найдите порядок задач с наибольшей суммой и выведите его. Ограничения:
2 секунды и 256 МБ.

## Входные данные

X и N, 0 ≤ X ≤ 100, 1 ≤ N ≤ 200, затем a₁ … a_N (от 0 до 100) и
b₁ … b_N (от 0 до 10⁶).

## Выходные данные

Наибольшая сумма, затем порядок задач, который её даёт. Подходит любой
такой порядок.

## Проверка

Проверяющая программа сравнивает сумму и воспроизводит выведенный
порядок.

## Примеры

### Пример 1

Ввод:

```
5 3
0 1 5
5 1 0
```

Вывод:

```
6
3 2 1
```

### Пример 2

Ввод:

```
4 4
3 0 1 2
7 8 2 3
```

Вывод:

```
19
1 4 3 2
```

## Решение

Долг никогда не больше X, поэтому задача с b > X всегда приносит на
b − X больше, чем та же задача с b = X; эта часть прибавляется в конце, и
дальше все b не больше X. Обозначим rᵢ суммарную починку до задачи i
включительно. Тогда долг равен X − min(X, rᵢ), и задача приносит
max(0, min(X, rᵢ) − (X − bᵢ)).

Возьмём лучший порядок и назовём брошенными задачи, которые ничего не
приносят. Перенос их в начало только увеличивает починку, которую видят
остальные, так что брошенные задачи можно делать первыми. Каждая
остальная приносит min(X, rᵢ) − (X − bᵢ), и сумма вторых частей от
порядка не зависит. Первые части — префиксные суммы починок с отсечкой на X, которые
максимальны в каждой позиции, если задачи идут по убыванию a. Обратно,
для любого набора брошенных задач такой порядок приносит не меньше
формулы, ведь реальная задача не приносит меньше нуля. Значит, ответ —
лучшее значение формулы по всем наборам брошенных задач.

Отсортируем задачи по возрастанию a. Если оставленные задачи идут после
брошенных по убыванию, задача k видит брошенные задачи перед ней в
отсортированном списке и все задачи от k дальше. Поэтому DP по
отсортированному списку хранит s — починку брошенных задач до сих пор
(с отсечкой на X, больше ничего не меняет): оставленная задача приносит
min(X, s + suffix_k) − (X − b_k), брошенная добавляет свою a к s.
Сохранённые выборы дают порядок: сначала брошенные, затем оставленные по
убыванию a. DP занимает O(N · (X + 1)), плюс сортировка.

В первом примере третья задача сначала чинит все 5 единиц, затем вторая
и первая приносят 1 и 5: всего 6.
