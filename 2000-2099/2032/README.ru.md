# 2032. Размещение трёх длин на целочисленной решётке

[Timus 2032](https://acm.timus.ru/problem.aspx?space=1&num=2032) · сложность 788 · geometry

Автор оригинальной задачи — Алексей Данилюк; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

По трём положительным целым длинам найти три целочисленные точки, попарные
расстояния между которыми в точности равны данным длинам в любом порядке.
Длины не больше `10000000`, неравенство треугольника гарантировано.
Модуль каждой координаты не больше `100000000`. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Одна строка с тремя длинами сторон.

## Выходные данные

Любые три пары целых координат через пробельные символы либо `-1`, если
размещения на решётке нет. Порядок вершин произвольный.

## Проверка

Проверяющая программа точно сравнивает три квадрата расстояний и
проверяет ограничение на координаты; `-1` принимается, только если
целочисленного треугольника нет. Принимается любое подходящее
расположение.

## Примеры

```
4 3 5
```

```
0 0
3 4
3 0
```

```
10 17 21
```

```
0 0
0 21
-8 15
```

```
100 100 100
```

```
-1
```

## Решение

Упорядочим длины `r ≤ b ≤ a`. Положим `A=(0,0)`, `B=(x,y)`, `C=(u,v)`,
где `|B|=r`, `|C|=b`, `|C-B|=a`. Скалярное произведение
`D=(r²+b²-a²)/2` должно быть целым: нечётный числитель сразу исключает ответ.
Векторное произведение — целое `K`, причём `K²=r²b²-D²`. Отрицательное
значение или неполный квадрат исключаются точным целочисленным корнем.
Значение `D` может быть отрицательным.

Для каждой целой точки `B` окружности радиуса `r` решаем систему:
`u=(Dx-Ky)/r²`, `v=(Dy+Kx)/r²`. Оба деления должны быть точными.

Переберём все `B` первой четверти, начиная с осей. Деление ненулевых
катетов на НОД `t` даёт примитивную пифагорову тройку с гипотенузой
`d=r/t`, делителем `r`. По параметризации Евклида катеты равны
`m²-k²,2mk`, где `m²+k²=d`, `m>k≥1`, параметры взаимно просты и разной
чётности. Разложим `r` пробными делителями и построим все делители. Для
нечётного `d≥5` проверим `m` от `floor(sqrt(d/2))+1` до
`floor(sqrt(d-1))`, возьмём `k=isqrt(d-m²)` и точно проверим квадрат,
НОД и чётность. Умножим катеты на `r/d` и проверим оба порядка координат
сразу, без хранения окружности.

Для полноты возьмём любое размещение на решётке и перенесём вершину в начало.
При необходимости отразим весь треугольник, сделав векторное произведение
неотрицательным, затем повернём всю фигуру на кратный 90 градусам угол,
поместив `B` в замкнутую первую четверть. Целочисленность сохраняется.
Оси или полная параметризация примитивных троек перечислят эту `B`,
а линейная система восстановит единственную `C`. Поэтому исчерпание
кандидатов доказывает невозможность. Полный квадрат `K²` — необходимая
предварительная проверка, не замена полного поиска.

Корректность найденного ответа следует из
`|C|²=(D²+K²)/r²=b²` и `|C-B|²=b²+r²-2D=a²`.
Делимость обеспечивает целые координаты. Их модули не больше расстояний
`r,b≤10000000` от начала, что удовлетворяет границам вывода.

В первом примере квадраты расстояний `25,9,16` дают длины `5,3,4`.
Во втором `441,289,100` дают `21,17,10`; отрицательные координаты допустимы.
Для равностороннего со стороной 100 имеем `D=5000` и `K²=75000000`,
не являющийся полным квадратом: отсюда последний отказ.

Пусть `d(r)` — число делителей, `M` — наибольшая входная сторона.
Получаем `O(d(r) sqrt(r))` попыток. Точные двоичные корни, включая
корень большого векторного произведения, дают общую верхнюю оценку
`O(d(r) sqrt(r) log(M+1))` времени и `O(d(r))` памяти. Все промежуточные
значения, включая границы поиска корня, помещаются в знаковые 128 бит.

Подводные камни:

- Сторону не всегда можно расположить вдоль оси.
- Нужны все делители, оба порядка катетов, НОД и чётность.
- Деления и корни нельзя округлять.
- Произведение `D` и координаты бывают отрицательными.
- Произведения достигают `10^28`: тип расширяется до умножения.

## Особенности языков

C++ использует знаковый `__int128`, Rust — `i128` и точные двоичные корни.
Go применяет `math/big.Int.Sqrt`; Java 8 — `BigInteger` и целочисленную
итерацию Ньютона, поскольку встроенного корня в этой версии нет.
Малые двоичные корни в этих двух языках работают со значениями до `10000000`.
Python использует точные целые и `math.isqrt`. Вещественная геометрия не нужна.
