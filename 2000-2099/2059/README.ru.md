# 2059. Сравнение частот палиндромов

[Timus 2059](https://acm.timus.ru/problem.aspx?space=1&num=2059) · difficulty 1486 · strings

Автор оригинальной задачи — Михаил Рубинчик; Палиндромный контест, 11 июля 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для двух слов A и B рассмотрите все различные палиндромы, встречающиеся
хотя бы в одном из них. Посчитайте палиндромы, которые чаще встречаются
в A, которые встречаются одинаково часто, и которые чаще встречаются в
B. Вхождения могут перекрываться, регистр важен. Ограничения: 1 секунда
и 64 МБ.

## Входные данные

Число тестов T, затем для каждого теста две строки с A и B. Каждое слово
непусто и не длиннее 200 000 символов; весь вход не больше 8 МБ.

## Выходные данные

Для теста i — строка `Case #i: x y z` с тремя числами.

## Проверка

Проверяющая программа сравнивает три числа каждого теста; пробелы между
ними не важны.

## Примеры

```
3
abacab
abccab
faultydogeuniversity
hasnopalindromeatall
abbacabbaccab
youmayexpectedstrongsamplesbutnow
```

```
Case #1: 4 1 2
Case #2: 8 3 9
Case #3: 13 0 15
```

В первой паре `a,aba,aca,bacab` чаще встречаются в `abacab`; `b`
встречается дважды в каждом слове; `c` и `cc` чаще встречаются в
`abccab`. Получаем `4 1 2`. Во второй паре объединение содержит 20
палиндромов с распределением `8+3+9`, в третьей — 28 с распределением
`13+0+15`. Перекрытия важны: `aaaa` содержит `aa` три раза, а сравнение
`aaaa` с `aaa` даёт `4 0 0`.

## Решение

### Общее дерево палиндромов

Настоящие вершины дерева палиндромов представляют различные палиндромные
строки. Два служебных корня имеют длины `−1` и `0`. Переход по символу
`c` расширяет `P` до `cPc`; из нечётного корня получается одна буква
`c`. Вершина хранит длину, ссылку `link` на максимальный собственный
палиндромный суффикс и разреженный список детей.

Просматриваем `A` слева направо. От прежнего максимального палиндромного
суффикса идём по ссылкам, пока новая буква не сможет окружить найденный
палиндром. Используем соответствующий переход, создавая его при
отсутствии. Ссылку новой вершины ищем аналогично, начиная со ссылки её
родителя. Перед обращением к предшествующему символу проверяем левую
границу текущего слова.

Затем просматриваем `B` с теми же вершинами и переходами, но начинаем
активный суффикс с пустого корня и используем границу `B`. Совпадающие
палиндромы получают общие вершины, а через границу слов ничего не
возникает. У каждой вершины два счётчика, сначала нулевые. На каждой
позиции увеличиваем только счётчик текущего максимального суффикса для
просматриваемого слова.

### Восстановление всех частот

Обрабатываем настоящие вершины в порядке убывания номера создания.
Добавляем оба счётчика `v` в соответствующие счётчики `link[v]`. Затем
сравниваем два счётчика `v` и увеличиваем одну из величин `x,y,z`.
Служебные корни не классифицируем.

Внутренний палиндром и две равные внешние буквы однозначно определяют
строку перехода. Поэтому общая вершина соответствует одному различному
палиндрому, а не одному вхождению. На позиции новым бывает только
максимальный палиндромный суффикс: каждый более короткий уже встречался
раньше как его префикс. Следовательно, вершин не больше `|A|+|B|+2`, а
собственный суффикс новой вершины имеет меньший номер.

Зафиксируем конец вхождения. Все палиндромы, заканчивающиеся в нём,
встречаются ровно по одному разу в цепочке суффиксных ссылок от
максимального. Изначально ставим одну отметку только в начале этой
цепочки. Перенос счётчиков доставляет её каждому предку один раз,
поэтому вершина получает ровно по отметке на каждый конец вхождения
своего палиндрома. Разные концы различаются даже при перекрытии.
Убывание номеров обрабатывает каждого потомка раньше предка, поскольку
ссылки ведут к более старым вершинам. Это доказывает оба счётчика.
Каждая настоящая вершина появилась хотя бы в одном слове, значит, равные
количества положительны. Классификация даёт требуемое число различных
строк.

### Несколько тестов и реализация

Память массивов используем повторно. Обнуляем головы списков и счётчики
двух корней, а при выдаче номера новой вершине инициализируем её поля,
включая список детей и оба счётчика. Старые недостижимые ячейки не
влияют на новое дерево. Пара одиночных букв — базовый случай: равные
дают `0 1 0`, разные — `1 0 1`.

При алфавите размера `σ` поиск перехода просматривает не больше `σ`
детей. Время на пару — `O(σ(|A|+|B|))`: суммарные проходы по суффиксным
ссылкам линейны по амортизации уменьшением длины, поскольку расширение
увеличивает соответствующие длины не больше чем на два. Перенос частот
тоже линейный. Для фиксированного байтового алфавита это `O(|A|+|B|)`.
Живых вершин `O(|A|+|B|)`. Компилируемые версии один раз выделяют
максимум `400002` ячейки, Python наращивает массивы до наибольшей
встреченной пары. Начальная инициализация не повторяется на каждом малом
тесте. Все количества помещаются в знаковые 32 бита.

C++ и Python читают слова по строкам; Go и Java хранят вход в буфере не
больше 8 МиБ, Rust также сохраняет вход. Вывод буферизуется
ограниченными блоками, поэтому почти два миллиона малых тестов не
создают список всех ответов в памяти. Python использует упакованные
массивы и переиспользует их.

Нельзя строить несвязанные деревья и сравнивать номера вершин: между
разными деревьями номер не обозначает одну и ту же строку. При переходе
к `B` сбрасываем активный суффикс. Помечаем только максимальный суффикс:
одновременное увеличение всей цепочки и последующий перенос удвоят
подсчёт. Соблюдаем обратный топологический порядок, исключаем пустые
корни, считаем перекрытия и сравниваем частоты, а не только наличие. При
повторном использовании номера сбрасываем оба счётчика. Учитываем общий
вход 8 МБ, а не только длину одного слова.
