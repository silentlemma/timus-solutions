# 2042. Палиндромы ограниченной длины при присваиваниях подстроке

[Timus 2042](https://acm.timus.ru/problem.aspx?space=1&num=2042) · difficulty 3245 · strings, segment_tree

Автор оригинальной задачи — Никита Сивухин; Ural FU Dandelion contest. Petrozavodsk training camp. Summer 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Поддерживается строка из строчных латинских букв. Обновление заменяет
все символы заданного включительного отрезка одной буквой. Запрос
подсчёта требует число вхождений палиндромных подстрок длины не больше
фиксированного `k`, целиком лежащих в его отрезке. Одинаковые слова на
разных позициях считаются отдельно.

## Входные данные

В первой строке находятся исходная строка и `k`: `1≤n≤100000`, `1≤k≤50`.
Далее дано `1≤m≤100000` операций. Операция `1 l r c` присваивает
строчную букву `c` всем позициям `l..r`. Операция `2 l r` запрашивает
число вхождений на этом отрезке. Нумерация начинается с единицы,
`1≤l≤r≤n`. Длина строки и `k` не меняются. Лимиты: 3 секунды, 64 МБ.

## Выходные данные

На каждый запрос подсчёта выведите отдельное целое число в порядке
операций. Если таких запросов нет, вывод пуст. Ответы сравниваются по
целым токенам. Считаются пары концов подстроки, а не различные значения
палиндромов. Каждый ответ не превосходит `nk≤5000000`.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
abacaba 4
3
2 1 3
1 1 3 c
2 1 4
```

```
4
10
```

Первые три буквы вначале образуют `aba`: три отдельные буквы и палиндром
длины три дают `4` вхождения. После присваивания `c` позициям `1..3`
первые четыре буквы — `cccc`. Все `4+3+2+1=10` подстрок этого отрезка
имеют длину не больше `4` и являются палиндромами.

## Решение

### Счётчик для каждого центра

Далее используем индексы от нуля. Обозначим `O=(k+1)//2`, `E=k//2`.
Величина `odd[i]` — радиус нечётного палиндрома с центром в символе `i`,
включая центр и с ограничением `O`. Величина `even[i]` — радиус чётного
палиндрома с центром непосредственно перед `i`, ограниченный `E`. Радиус
`d` соответствует `d` положительным длинам этой чётности. Поэтому
`p[i]=odd[i]+even[i]` считает все допустимые вхождения с данным индексом
центра.

Радиусы находим алгоритмом Манакера. Ограничение радиуса не нарушает
зеркальную инициализацию: радиус меньше предела точен до известной
правой границы, а достигнутый предел уже является максимальным
допустимым ответом. Новые успешные сравнения двигают правую границу,
поэтому каждый из двух проходов линеен.

Первое ленивое дерево отрезков присваивает символы и извлекает короткое
окно. Второе хранит суммы `p`, поддерживает присваивание константы и
заменяет короткий непрерывный участок явно вычисленными значениями за
один обход. Отдельное точечное обновление для каждого центра добавило бы
лишний логарифм.

### Обновляем только границы присваивания

Сначала присваиваем символы в `[l,r]`. Радиус меняется лишь тогда, когда
его максимальное разрешённое окно пересекает обновление. Поэтому все
затронутые центры лежат в `A=[l-O+1,r+E]` после обрезки границами
строки. Для центров `I=[l+E,r-O+1]` оба максимальных окна целиком
находятся внутри присваивания. Все их подстроки постоянны, значит, там
можно лениво установить `p=k`.

Остаток `A` состоит не более чем из двух частей, по `k-1` центров в
каждой. Если `I` пуст, пересчитываем всё обрезанное `A` один раз:
условные граничные части могут пересекаться. Для центров `[u,v]`
извлекаем символы `[u-E,v+O-1]`, обрезаем глобальными границами,
вычисляем ограниченные радиусы и заменяем только требуемые центры. Окно
содержит каждый возможный палиндром допустимой длины с этими центрами,
поэтому его края ничего не теряют. Длина окна — `O(k)` даже при длинном
присваивании.

### Ответ на запрос

Если `r-l+1<k`, извлекаем весь запрошенный отрезок и суммируем его
локальные радиусы. Иначе центры `[l+E,r-O+1]` полностью обеспечены
символами внутри запроса: берём сумму хранимых `p`. Остаются центры
`l..l+E-1` и `r-O+2..r`.

Для левой части нужны первые `k-1` символов запроса и только первые `E`
центров этого окна. Для правой — последние `k-1` символов и только
последние `O-1` центров. Эти окна содержат все подходящие палиндромы и
сами ограничивают их концами запроса. Внутренняя и две краевые части
разбивают индексы центров, а у каждого вхождения единственные центр и
чётность. Поэтому каждое требуемое вхождение учитывается ровно один раз,
а выходящие за запрос не учитываются. При `k=1` обе краевые части пусты
и остаются одиночные буквы.

### Доказательство и оценки

После правильного начального построения присваивание восстанавливает
каждый изменившийся центр и сохраняет остальные. Индукция по операциям
даёт верность хранимых значений, а разбиение центров доказывает ответы.
Короткое окно и его замена требуют `O(k+log n)`, длинная постоянная
середина — ленивого присваивания. Всего время `O(n+m(k+log n))`, память
`O(n)`.

Python поддерживает другой инвариант: `s[i]` и `e[i]` — числа допустимых
палиндромов, начинающихся и заканчивающихся в позиции `i`. В описании
этой версии отрезки полуоткрытые. При проходе хранится маска размером с
машинное слово: бит `d` означает палиндром длины `d+1`, заканчивающийся
в текущей позиции. Предыдущую маску сдвигаем на два бита, добавляем
кандидатов длины один и два и пересекаем с маской позиций, содержащих
текущую букву. В последней бит `d` установлен ровно тогда, когда символ
на `d` позиций левее совпадает с текущим. Поэтому длинный кандидат
остаётся ровно тогда, когда его внутренняя подстрока — палиндром, а
крайние буквы равны. Длины больше `k` отбрасываем; небольшая таблица
числа единичных битов даёт `e[i]`. Историю каждой буквы сдвигаем на
расстояние от её предыдущего появления. Проход по перевёрнутому окну
даёт `s[i]`.

В однородном окне счётчик равен `min(k,t)`, где `t` — число доступных
символов в направлении соответствующего края. Для коротких окон из двух
или трёх максимальных серий одинаковых букв счётчики тоже вычисляются
напрямую, начиная с вхождений внутри каждой серии. В окне из двух серий
нет палиндрома, содержащего обе буквы. В случае трёх серий палиндром с
разными буквами обязан содержать всю среднюю серию и поровну букв из
совпадающих крайних серий. Добавляем ровно те расширения, которые
помещаются в обе крайние серии и укладываются в предел длины. В
остальных случаях применяется проход с масками. Ограниченные точные кэши
сохраняют короткие байтовые строки и неизменяемые счётчики либо ответы
на запросы; повторное использование результата не влияет на точность.

Если длина запроса меньше `k-1`, любая его подстрока уже удовлетворяет
ограничению. Число подстрок внутри каждой серии даёт треугольное число;
затем симметрично расширяем палиндром вокруг каждой серии целиком. У
любого палиндрома с разными буквами есть единственная такая центральная
серия, поэтому каждое вхождение учитывается один раз. Если работа на
расширения превышает линейный порог, частичную сумму отбрасываем и
выполняем проход с масками. Так подсчёт короткого запроса остаётся
линейным.

Символы и счётчики хранятся в bytearray, разбитых на блоки фиксированной
длины; над суммами блоков построено ленивое дерево отрезков. Суммы
счётчиков начал и концов занимают отдельные поля одного целого числа.
Каждое поле вмещает максимально возможную сумму, поэтому при сложении
переноса между полями нет. Присваивание помечает целые блоки новой
буквой и временно устанавливает оба счётчика в `k`. Перед чтением
символов или частичной правкой помеченный блок восстанавливается явно.
Там, где все допустимые длины помещаются внутри закрашенной серии,
значение `k` точно. Остальные затронутые счётчики пересчитываются в
окнах длины `O(k)` у её краёв; пересекающиеся окна объединяются.
Изменившийся палиндром обязательно пересекает присваивание и имеет длину
не больше `k`, поэтому окна содержат все необходимые символы, а
остальные счётчики остаются верными. Суммы обновляются только для
пересчитанных блоков.

Для запроса `[l,r)` длины не меньше `k-1` ответ равен
`sum(e[0:r])-sum(s[0:l])`; обе префиксные суммы берутся из дерева. Любой
допустимый палиндром с началом левее `l` заканчивается раньше `r`,
поскольку его длина не больше `k`. Вычитание убирает ровно те вхождения,
которые выходят за левый край запроса; оставшиеся целиком лежат внутри.
Для всей строки ответом служит готовая общая сумма.

Присваивания откладываются до запроса, которому нужны хранимые счётчики.
Перед первым таким запросом накопленные изменения применяются к
символам, после чего счётчики строятся один раз. В следующих пакетах
можно отбросить присваивание, целиком перекрытое более поздними: для
следующего ещё не отвеченного запроса важно только итоговое состояние
строки. При обратном проходе покрытие накапливается лишь для длинных
присваиваний: игнорирование коротких может оставить лишнюю запись, но не
удалить нужную. Большие пакеты коротких присваиваний сначала меняют
символы в исходном порядке, отсекая уже совпадающие с новой буквой
префиксы и суффиксы. Реальное изменение `[l,r)` затрагивает счётчики
концов только в `[l,r+k-1)`, а начал — только в `[l-k+1,r)` после
обрезки границами строки. Эти отрезки сортируются, близкие объединяются,
а для пересчёта добавляется нужный контекст из `k-1` символов. Каждый
объединённый участок пересчитывается один раз по итоговой строке. Даже
при перекрывающихся присваиваниях это точно, поскольку все пересчёты
используют окончательные символы. Остальные пакеты обрабатываются
отдельными граничными пересчётами. Присваивания после последнего запроса
обрабатывать не нужно.

Для некоторых запросов пересчёт вообще не нужен. Помимо последнего
закрашенного отрезка, Python хранит один заведомо однородный участок:
объединяет пересекающиеся или соседние присваивания той же буквы либо
выбирает новый отрезок или сохранившуюся однородную часть. Эти действия
сохраняют гарантию равенства всех символов выбранного участка. Для
запроса внутри любого из двух известных однородных отрезков ответ равен
`dL-d(d-1)/2`, где `L` — длина запроса, `d=min(k,L)`: суммируем `L-j+1`
вхождений для каждой длины `j` от единицы до `d`. При `k=1` эта формула
верна для любого запроса независимо от символов. Такие ответы не требуют
применения отложенных присваиваний.

Оценка Python учитывает и работу вне дерева. Пусть `B` — фиксированная
длина блока, не меньшая `k`. Одно присваивание может записать `O(n/B)`
меток блоков и пересчитать `O(B+k)` символов; пути в дереве требуют
`O(log n)`. При фильтрации пакета поддержание объединения уже перекрытых
отрезков также может затронуть `O(n/B+1)` частей при фиксированных
порогах реализации. Сортировки затронутых отрезков суммарно занимают не
больше `O(m log m)` для всех пакетов. Консервативная общая оценка
времени — `O(n+m(n/B+B+k+log n+log m))`. Символы, счётчики и деревья
занимают `O(n)` памяти; с буфером ввода, отложенными присваиваниями и
ответами общий расход равен `O(n+m)`. Эти затраты отличаются от
приведённой выше оценки для счётчиков по центрам.

Чётный центр расположен перед `i`. Обрезайте глобальные окна,
объединяйте пересекающиеся части пересчёта и различайте радиус и длину.
Считайте вхождения, включая все одиночные буквы. Учитывайте `k>n` и
пустой вывод. Перед частичной правкой блока восстановите его отложенное
значение. Не заменяйте единый короткий обход на `k` точечных обновлений
дерева.

## Особенности языков

C++, Go и Rust используют плоские массивы и рекурсию логарифмической
глубины. Rust обрезает левые границы и пустую середину насыщающей
арифметикой. Go 1.14 использует собственный разбор чисел и буферный
вывод. Java 8 повторно использует короткие буферы символов, радиусов и
замен, ограничивая выделения памяти. В Python используются маски
палиндромов по концам, ленивое дерево над блоками и отложенный пересчёт
границ. Счётчики помещаются в знаковые 32 бита; Rust хранит суммы в
беззнаковых 32-битных числах. Вводимые индексы преобразуются один раз.

Текущее решение на Python работает под PyPy и получило Accepted на Timus
под PyPy 3.10 x64 за 2,39 с при лимите 3 с, использовав 26 300 КБ.
Предыдущие версии превышали лимит времени на тесте 9 под CPython и на
тестах 14 и 17 под PyPy.
