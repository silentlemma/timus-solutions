# 2060. Количество соседних палиндромных вхождений

[Timus 2060](https://acm.timus.ru/problem.aspx?space=1&num=2060) · difficulty 650 · strings

Автор оригинальной задачи — Михаил Рубинчик; Палиндромный контест, 11 июля 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Посчитайте пары соседних непустых палиндромов в строке: тройки 0 ≤ i ≤ j
< k < n, у которых s[i..j] и s[j+1..k] — палиндромы. Одинаковые тексты в
разных местах считаются отдельно. Ограничения: 1 секунда и 64 МБ.

## Входные данные

Одна строка из 1–300 000 строчных латинских букв.

## Выходные данные

Точное количество.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
abaa
```

```
5
```

Для `abaa` количества палиндромов, заканчивающихся в позициях, равны
`E=[1,1,2,2]`, а начинающихся — `S=[2,1,2,1]`. Три внутренние границы
дают `1·1`, `1·2` и `2·1`, всего пять. Первая учитывает `a|b`, хотя эти
части не покрывают всё слово; последняя учитывает `a|a` и `aba|a`.

## Решение

### Независимый выбор у каждой границы

Пусть `E[j]` — число непустых палиндромных вхождений с концом в `j`,
`S[j]` — с началом в `j`. Для границы `j|j+1` независимо выбираем левое
вхождение из `E[j]` и правое из `S[j+1]`. Их положения определяют одну
допустимую тройку. Обратно, каждая тройка однозначно задаёт такую
границу и два выбора. Ответ равен `sum(E[j]·S[j+1])` по `0≤j<n−1`.
Учитываются позиции, а не различные тексты палиндромов.

### Радиусы Манакера задают отрезки концов

Для нечётного центра `c` радиус `r≥1` включает центральную букву и
описывает длины `1,3,…,2r−1`. Их концы по одному проходят отрезок
`[c,c+r−1]`, а начала — `[c−r+1,c]`. Для чётного центра перед `c` радиус
`r≥0` даёт концы `[c,c+r−1]` и начала `[c−r,c−1]`. Нулевой чётный радиус
ничего не добавляет.

Оба семейства радиусов вычисляет Манакер. Храним палиндромное окно с
самой правой границей. Внутри окна переносим известный зеркальный
радиус, обрезанный правой границей, затем расширяем, пока обе позиции
существуют и буквы равны. Вне окна начинаем с единицы для нечётных
центров и нуля для чётных. Отражение доказывает перенесённую часть,
сравнения — максимальное дальнейшее расширение. На центр приходится не
больше одного неудачного сравнения; успешные новые сравнения продвигают
правую границу. Каждый проход занимает `O(n)`.

Каждый отрезок концов или начал добавляем в разностный массив за `O(1)`:
для включительного `[l,r]` увеличиваем ячейку `l` и уменьшаем `r+1`.
После обработки центров префиксные суммы двух массивов дают точно `E` и
`S`. У любого палиндромного вхождения единственные центр, чётность и
радиус, поэтому оно один раз добавляется к своему началу и концу. Ничего
не теряется и не удваивается; формула по границам завершает
доказательство.

### Память и размер целых

Массив радиусов общий для двух проходов; между ними окно сбрасывается.
При вычислении чётного центра `c` текущее окно создано раньше, в `q<c`,
поэтому зеркальный индекс `2q−c<c`. Он обращается к уже перезаписанному
чётному префиксу массива, а не к старому нечётному значению. Разностные
массивы имеют `n+1` ячейку для вычитания в `n`; настоящие счётчики
относятся только к `0..n−1`.

Каждый счётчик не больше `n`, достаточно знаковых 32 бит. Однако
произведение двух счётчиков может выйти за этот диапазон, а ответ
достигает `n(n−1)(n+1)/6`: всего существует `C(n+1,3)` троек индексов, и
все они допустимы в строке одинаковых букв. При `n=300000` получается
`4499999999950000`. C++, Go, Java и Rust приводят множитель к знаковым
64 битам до умножения; Python считает точно.

## Особенности языков

Два прохода Манакера, разностные обновления, префиксные суммы и итоговое
суммирование требуют `O(n)` времени и `O(n)` памяти. Все версии
итеративные и сравнивают буквы точно. Python использует CPython 3.12 и
три упакованных массива знаковых 32-битных чисел, остальные —
целочисленные массивы или векторы. Вводится одно слово, выводится одно
число.

Нельзя учитывать только максимальный палиндром у позиции. Нужны
одиночные буквы и обе чётности; пустой чётный палиндром не учитывается.
Для чётного центра отрезок начал заканчивается в `c−1`, а не в `c`.
Умножаем `E[j]` на `S[j+1]`, не на `S[j]`, и берём только внутренние
границы. Не объединяем одинаковые тексты и не требуем покрытия всей
строки. Для одной буквы ответ ноль. Приводим тип до умножения, а не
после переполнения 32-битного произведения.

Решение на Python запускается под PyPy: под CPython 3.12 оно превышает
ограничение времени на 49-м тесте судьи, а под PyPy 3.10 принимается за
0.234 с.
