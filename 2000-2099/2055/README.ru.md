# 2055. Связная сеть с минимальным разбросом цен

[Timus 2055](https://acm.timus.ru/problem.aspx?space=1&num=2055) · difficulty 1470 · trees, dsu, two_pointers

Автор оригинальной задачи — Никита Бурлаков; XIX Открытый чемпионат Урала по спортивному программированию (апрель, 2015).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Связный мультиграф имеет n вершин и m дорог с ценами. Оставьте остовное
дерево, чтобы убрать как можно больше дорог, а среди остовных деревьев
минимизируйте разность наибольшей и наименьшей оставленной цены.
Ограничения: 1.5 секунды и 128 МБ.

## Входные данные

В первой строке n и m, 2 ≤ n ≤ 50 000, n − 1 ≤ m ≤ 50 000. В каждой из
следующих m строк дорога `a b c`: два разных конца и цена 1 ≤ c ≤ 10⁹.
Параллельные дороги различны.

## Выходные данные

Номера оставленных дорог в одной строке в любом порядке.

## Проверка

Проверяющая программа убеждается, что дороги образуют остовное дерево и
что разброс цен оптимален; принимается любое оптимальное дерево.

## Примеры

```
3 3
1 2 1
2 3 3
3 1 4
```

```
2 3
```

```
4 5
1 2 1
2 3 1
1 3 2
1 4 2
2 4 1
```

```
1 2 5
```

В первом примере три возможных дерева имеют разбросы `3−1=2`, `4−1=3` и
`4−3=1`. Дороги 2 и 3 дают минимум один. Во втором дороги 1, 2 и 5
соединяют все четыре вершины и стоят одинаково, поэтому достигают
абсолютного минимума — нуля.

## Решение

### Максимальный остовный лес каждого префикса

Связному графу необходимо хотя бы `n−1` ребро, а остовное дерево
достигает этой границы. Поэтому первая цель требует именно дерева.
Отсортируем дороги по цене, разрешая равенства по концам и исходному
номеру, и присвоим различные ранги `0,…,m−1`. Для каждого обработанного
префикса поддерживаем остовный лес с максимальной суммой рангов.

Обычная DSU хранит связность всего обработанного графа. Если новая
дорога соединяет разные компоненты, включим её и объединим компоненты.
Иначе она замыкает цикл в текущем лесу: удалим ребро минимального ранга
на пути между концами и добавим новое. Его ранг больше всех прежних.
Массив активности отмечает оставленные ранги; указатель на первый
активный ранг только движется вперёд, поскольку удалённые ранги не
возвращаются. Суммарно его продвижение занимает `O(m)`.

Когда оставлено `n−1` ребро, лес становится деревом. Новое ребро
обязательно входит в него и имеет максимальную цену. Запомним лучший
разброс и соответствующий интервал рангов. При нуле можно закончить. В
конце запустим новую DSU только на сохранённом интервале и выберем `n−1`
соединяющих рёбер. Полное дерево при каждом улучшении копировать не
нужно.

### Динамический лес и повторное использование узла ребра

Link-cut tree представляет отдельным узлом каждую вершину и каждое
оставленное ребро. Ключ вершины — заведомо большой `m+1`, ключ ребра —
текущий ранг. Каждое вспомогательное splay-дерево хранит узел
минимального ключа. Перед вращениями итеративный splay проталкивает
отложенные развороты. Операции `makeroot(u); access(v)` выставляют весь
путь `u–v` во внутреннем порядке дерева, и минимум пути доступен через
агрегат.

У узла ребра физическая степень два. После выставления пути поднимем его
минимальное ребро `e` в корень splay. Слева находится путь `u…a`, справа
`b…v`; старое ребро соединяло `a,b`. Развернём **оба** поддерева и
заменим ключ `e` новым рангом. Порядок станет `a…u,e,v…b`: старое ребро
исчезло, а тот же узел теперь соединяет новые концы `u,v`. Все остальные
рёбра и виртуальные ветви сохраняются. Разворот не меняет агрегат
минимума; после смены ключа пересчитаем `e`. Это изменение топологии, а
не просто цены старого ребра.

Новый узел ребра выделяется только при объединении компонент обычной
DSU. Таких объединений не более `n−1`, поэтому достаточно не более `2n`
ячеек с учётом неиспользуемого нуля. Индекс переиспользованного узла уже
не равен рангу дороги: ранг берётся из ключа. Все операции пути
амортизированно занимают `O(log n)`.

### Почему полученный диапазон оптимален

Обновление сохраняет максимальный лес. При соединении прежних компонент
новое ребро — единственное доступное пересечение между ними. Внутри
компоненты обозначим прежнее максимальное дерево `T`, новое ребро `e`,
минимум его цикла `f`. Конкурирующее дерево без `e` не лучше `T+e−f`.
Если оно содержит `e`, удалим его: какое-то ребро `g` прежнего пути
пересекает полученный разрез. Замена `e` на `g` даёт дерево старого
префикса с суммой рангов не больше `T`. Поскольку `rank(g)≥rank(f)`,
сумма конкурента не больше `T+e−f`. Значит, лес остаётся максимальным.

Максимальное дерево также максимизирует минимальную цену своего
префикса. Иначе удалим его слишком дешёвое ребро. Дерево, у которого все
цены выше, пересекает этот разрез более дорогим и более ранговым ребром.
Замена увеличивает сумму рангов — противоречие. Разрешение равных цен не
мешает: строго большему весу всегда соответствует строго больший ранг.

Возьмём глобально оптимальное дерево и префикс, заканчивающийся его
наибольшим рангом. У поддерживаемого дерева максимум цены не выше,
минимум не ниже, значит разброс не больше оптимального. Все
рассмотренные деревья допустимы, поэтому лучший найденный разброс в
точности оптимален. Сохранённый интервал связен; любое восстановленное
внутри него дерево имеет разброс не больше оптимума, а строго меньше
иметь не может. Восстановление также корректно.

## Особенности языков

Сортировка занимает `O(m log m)`, динамические обновления —
амортизированно `O(m log n)`, восстановление — `O(m)`. Итого `O(m log
m+m log n)` времени, `O(n+m)` памяти. DSU и массивы леса занимают
`O(n)`, список дорог и активность — `O(m)`. Суммы рангов нужны лишь в
доказательстве и не вычисляются. Цены и разности укладываются в знаковый
32-битный тип.

C++, Go, Java и Rust используют итеративные splay и DSU, буферизованный
ввод и то же переиспользование узлов, реализованное отдельными
функциями. Рекурсивный обход графа и линейный поиск минимума пути не
нужны.

Не путать связность префикса в обычной DSU с удалениями из текущего
дерева. Равные цены — отдельные ранги; сохранять исходные номера,
сравнивать ключи, а не номера переиспользованных узлов. Проталкивать
развороты перед splay, разворачивать обе части при замене ребра и
пересчитывать минимум после изменения ключа. Оценивать только полные
деревья. Минимальная сумма цен и минимальный разброс — разные цели; один
обычный Краскал решает только первую.

Python обходится без дерева link-cut. Он ведёт два указателя по дорогам,
отсортированным по цене: правый добавляет дороги в DSU с откатом, а пока
окно связывает граф, левый убирает его самую дешёвую дорогу. Самую
старую дорогу DSU напрямую убрать не может, поэтому окно хранится как
очередь из двух логических стеков с общей историей отката. Если последняя
запись относится к заднему стеку, откатываем записи, пока из обоих стеков
не удалено поровну или передний стек не исчерпан. Если в переднем стеке
остались записи, восстанавливаем удалённые задние записи в исходном
порядке; иначе откатываем оставшуюся историю и разворачиваем задний стек
в передний. В обоих случаях удалённые передние записи восстанавливаем
последними, чтобы самая старая дорога оказалась сверху.
Каждая дорога переносится всего `O(log m)` раз. Ловушка (тест `edge_04`):
перебалансировка нужна и при непустом переднем стеке, если более новые
записи заднего стека мешают откату самой старой дороги. Связное окно с
минимальным разбросом цен даёт ответ, а Краскал по его дорогам строит дерево.
`O(m log m log n)` при объединении по размеру и без сжатия путей.
Решение работает на CPython, у судьи 1,34 с из 1,5 с; прежняя версия с
лесом splay превышала лимит времени на 11-м тесте судьи даже под PyPy.
