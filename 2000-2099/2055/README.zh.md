# 2055. 保留价格跨度最小的连通道路

[Timus 2055](https://acm.timus.ru/problem.aspx?space=1&num=2055) · difficulty 1470 · trees, dsu, two_pointers

原题作者 Nikita Burlakov，出自 2015 年乌拉尔体育编程锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个连通多重图有 n 个顶点和 m 条带价格的道路。保留一棵生成树，以删去尽可能多的道路；在所有生成树中，使保留道路的最高价与最低价之差最小。时间限制 1.5 秒，内存限制 128 MB。

## 输入

第一行是 n 和 m，2 ≤ n ≤ 50 000，n − 1 ≤ m ≤ 50 000。接下来 m 行每行一条道路 `a b c`：两个不同的端点和价格 1 ≤ c ≤ 10⁹。平行的道路彼此不同。

## 输出

在一行中以任意顺序输出保留道路的编号。

## 评测方式

检查器确认这些道路构成生成树，并且价格差最优；任何最优的树都被接受。

## 样例

```
3 3
1 2 1
2 3 3
3 1 4
```

```
2 3
```

```
4 5
1 2 1
2 3 1
1 3 2
1 4 2
2 4 1
```

```
1 2 5
```

第一个示例的三棵树跨度分别是 `3−1=2`、`4−1=3`、`4−3=1`，道路 2、3 达到最小值一。第二个示例中道路 1、2、5 连通四个顶点，价格都为一，因此跨度为绝对下界零。

## 解法

### 维护每个前缀的最大生成森林

连通图至少保留 `n−1` 条边，生成树恰好达到，因此第一目标要求一棵树。按价格、端点、原编号排序，为道路赋予唯一秩 `0,…,m−1`，并维护已处理前缀中秩和最大的生成森林。

普通并查集只记录整个已处理图的连通性。新边若连接不同分量，就加入森林并合并分量；否则形成一个环，删除原端点路径上秩最小的边，再加入秩比所有旧边都大的新边。用布尔数组记录保留秩，指针向右越过被删除秩，得到最小价格。删除秩不会重新出现，所以指针总开销为 `O(m)`。

森林边数达到 `n−1` 后就是树。最新边必被保留，价格也是最大值；记录最小跨度及其秩区间。跨度为零即可结束。最后用新的并查集扫描保存区间，任取 `n−1` 条合并不同分量的边，无需每次改善都复制整棵树。

### 动态森林与边节点复用

Link-cut tree 将顶点和每条保留边分别表示为节点。顶点键为哨兵 `m+1`，边键为当前秩；辅助 splay 树保存最小键节点。迭代 splay 在旋转前下传路径翻转标记。`makeroot(u); access(v)` 按中序暴露整条 `u–v` 路径，通过聚合值找到最小边。

边节点的实际度为二。暴露路径后，将最小边节点 `e` splay 到根：左子树是 `u…a`，右子树是 `b…v`，旧边连接 `a,b`。将**两个**子树都翻转，把 `e` 的键更新为新秩，中序就变成 `a…u,e,v…b`。旧边被删除，复用节点现在恰好连接新端点 `u,v`，其余边和所有虚分支均保留。翻转不改变最小值；改键后重新汇总 `e`。这改变了拓扑，而不仅是旧边权。

只在普通并查集合并分量时分配新边节点，最多 `n−1` 次，连同未用零号槽在内至多 `2n` 个数组槽位即可。复用后节点下标不再等于边秩，必须读取键。所有路径操作摊还 `O(log n)`。

### 最优性证明

更新始终维护最大森林。连接旧分量时，新边是它们之间唯一新出现的连接。对于同一分量，设旧最大树为 `T`，新边为 `e`，环上最小边为 `f`。不含 `e` 的竞争树不优于 `T+e−f`。若竞争树含 `e`，删除它得到一个割，旧端点路径上有边 `g` 跨越此割；以 `g` 替换 `e` 得到旧前缀树，秩和不超过 `T`。又因 `rank(g)≥rank(f)`，竞争树秩和不超过 `T+e−f`，更新正确。

最大树还最大化当前前缀的最小价格。否则删除其过便宜的边，所有边价格都更高的竞争树必用更高价格、更大秩的边跨割，替换会增加秩和，矛盾。价格相等时任意一致的秩细化都不影响严格价格比较。

取全局最优树，考察以其最大秩边结束的前缀。维护树的最高价不更高、最低价不更低，跨度不超过最优值；所有记录树又都合法，因此记录最小值恰为最优值。保存区间连通，其中任何重建树的跨度至多为最优值，也不可能更小，故重建同样正确。

## 各语言说明

排序 `O(m log m)`，动态更新摊还 `O(m log n)`，重建 `O(m)`，合计 `O(m log m+m log n)` 时间、`O(n+m)` 空间。并查集和森林数组占 `O(n)`，边列表与活动数组占 `O(m)`。秩和只用于证明，程序不计算它；价格和差值均适合有符号 32 位整数。

C++、Go、Java 和 Rust 采用迭代 splay、并查集和缓冲输入，并用独立辅助函数执行相同节点复用。无需图递归或线性扫描路径。

普通并查集维护前缀连通性，不执行森林删边。相同价格仍是不同秩；保存原编号，并比较键而非复用节点下标。splay 前下传翻转，替换时两边都翻转，修改键后更新聚合。只评估完整树。最小总价与最小跨度不同，直接 Kruskal 只解决前者。

Python 不使用 link-cut 树。它在按价格排序的道路上移动两个指针：右指针把道路加入可回滚的并查集，只要窗口使图连通，左指针就移除其中最便宜的道路。并查集不能直接删除最早加入的道路，所以窗口保存为两个逻辑栈共享一份回滚历史的队列。如果最新记录属于后栈，就回滚记录，直到两个栈各被移除相同数量的记录，或前栈耗尽。若前栈仍有记录，则按原顺序恢复移除的后栈记录；否则回滚剩余历史，将后栈翻转为前栈。两种情况下，最后都恢复移除的前栈记录，让最早的道路位于栈顶。每条道路总共只被移动 `O(log m)` 次。陷阱（测试 `edge_04`）：即使前栈非空，也可能需要重新平衡，因为较新的后栈记录会阻碍回滚最早的道路。价格跨度最小的连通窗口给出答案，再对其道路运行 Kruskal 构造树。按大小合并且不做路径压缩时为 `O(m log m log n)`。它在 CPython 上运行，评测用时 1.34 秒（限制 1.5 秒）；使用 splay 森林的早期版本即使在 PyPy 下也在评测的第 11 个测试上超时。
