# 2024. Выбор целых цветовых групп

[Timus 2024](https://acm.timus.ru/problem.aspx?space=1&num=2024) · сложность 339 · sorting, combinatorics

Автор оригинальной задачи — Никита Сивухин; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `n` различных объектов, номера которых совпадают с позициями в
строке. Строчная латинская буква задаёт цвет объекта. Нужно выбрать
подмножество, содержащее не более `k` различных цветов, и найти
максимальный размер и число подмножеств такого размера. Подмножества
различны, если некоторый номер входит только в одно из них. Перестановка
объектов или выбор названий отсутствующих цветов нового подмножества не
создаёт.

Ограничения: `1 ≤ n ≤ 100000`, `1 ≤ k ≤ 26`, цвета от `a` до `z`. Время
— 1 секунда, память — 64 МБ. Количество требуется точно, без взятия по
модулю.

## Входные данные

Первая строка содержит строку цветов длины `n`; отдельно число `n` не дано.
Во второй строке записано `k`.

## Выходные данные

Два целых числа через пробел: максимальный размер подмножества и количество
подмножеств, достигающих этого размера.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
abcde
1
```

```
1 5
```

```
ababac
2
```

```
5 1
```

## Решение

Подсчитаем частоты всех 26 цветов и отсортируем по убыванию, включая нули.
Максимальный размер — сумма первых `k` частот. Обозначим через `b` частоту
на позиции `k` в этом порядке.

Если `b = 0`, встречающихся цветов меньше `k`. Можно взять все объекты,
и такое подмножество ровно одно. Выбор разных отсутствующих цветов не
меняет набор номеров.

Иначе пусть `g` частот строго больше `b`, а `t` частот равны `b`. В
оптимальном наборе обязательны все `g` больших групп и ровно `r = k-g`
из `t` равных граничных. Поэтому число вариантов равно `C(t,r)`.

Почему достаточно целых групп? Если цвет уже выбран, любой пропущенный объект
этого цвета можно добавить, увеличив размер без увеличения числа цветов. Такой
неполный набор не оптимален. Если разрешено добавить ещё цвет, любая непустая
группа улучшает размер. Значит, выбираются `k` самых частых непустых групп либо
все непустые группы, когда их меньше `k`.

Замена выбранной меньшей группы на невыбранную большую строго
увеличивает размер. Отсюда все группы выше границы `b` обязательны, все
ниже исключены; остаётся выбрать только равные положительные группы на
границе. Любые `r` таких групп дают одну и ту же сумму. Разные выборы
меняют номера объектов, поскольку группы непустые. Внутри выбранной
группы вариантов больше нет: нужно взять все объекты.

Сочетание вычисляем с `q = min(r,t-r)`: начинаем с `ways = 1` и
выполняем `ways = ways * (t-i+1) / i` для `i = 1..q`. Деление всегда
точное: очередное значение равно `C(t,i)`. Умножение выполняем в широком
целом типе, без факториалов. Максимальный ответ — `C(26,13) = 10400600`,
но `26!` не помещается в 64 бита.

В первом примере пять частот равны единице, поэтому один объект можно выбрать
пятью способами. Во втором частоты равны 3, 2 и 1; группы размеров 3 и 2 дают
размер 5 и определены однозначно.

При алфавите размера `σ` время — `O(n + σ log σ)`, память для частот —
`O(σ)`. Здесь `σ = 26`, поэтому время — `O(n)`. Программы буферизуют
входную строку: общая дополнительная память — `O(n + σ)`, то есть `O(n)`
при фиксированном алфавите. Альтернатива — рюкзак по целым группам с
ограничением числа цветов за `O(σk)` после подсчёта; такой алгоритм
удобен для независимой проверки.

Подводные камни:

- Ограничено число различных цветов, а не количество объектов.
- Объекты одного цвета различны по номерам, но оптимальная выбранная
  группа целая.
- Считайте подмножества, а не перестановки. Нулевые частоты не дают
  новых вариантов.
- Учитывайте равенство частот на границе, в том числе при `k = 1` и `k = 26`.
- Для точного количества не нужны факториалы и вещественная арифметика.

## Особенности языков

C++, Go и Rust используют 64-битный тип для сочетания, Java — `long`, Python —
точные целые. Суммы частот помещаются в обычный целый тип. Java сортирует по
возрастанию и берёт последние `k` элементов; остальные программы — первые `k`
после сортировки по убыванию. Go применяет `fmt.Fscan` с буферизованным вводом,
поэтому строка из 100000 символов не упирается в стандартный лимит Scanner.
В CPython используется тот же линейный проход.
