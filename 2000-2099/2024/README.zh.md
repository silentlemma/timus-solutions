# 2024. 选择完整的颜色组

[Timus 2024](https://acm.timus.ru/problem.aspx?space=1&num=2024) · 难度 340 · sorting, combinatorics

原题作者 Nikita Sivukhin，出自 2014 年乌拉尔地区中学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

字符串的每个位置代表一个不同对象，该位置的小写字母表示颜色。选择一个至多包含 `k` 种颜色的子集，
求最大对象数量及达到最大数量的不同子集个数。两个子集不同，当且仅当某个对象下标只属于其中一个。
改变顺序或选择不存在的颜色名称，不会产生新的对象子集。

限制：`1 ≤ n ≤ 100000`、`1 ≤ k ≤ 26`，颜色为 `a` 至 `z`。时间 1 秒，内存 64 MB。
计数要求精确整数，没有取模。

## 输入

第一行是长度为 `n` 的颜色字符串，不单独给出 `n`。第二行是 `k`。

## 输出

输出两个以空格分隔的整数：最大子集大小，以及达到这个大小的子集个数。

## 评测方式

按记号逐个比较输出。

## 样例

```
abcde
1
```

```
1 5
```

```
ababac
2
```

```
5 1
```

## 解法

统计全部 26 种颜色的频数，包含零频数，并按降序排序。前 `k` 个频数之和就是最大大小。
令 `b` 为排序后第 `k` 个频数。

若 `b = 0`，实际出现的颜色不足 `k` 种，可以选中全部对象，而这样的子集只有一个。
选择不同的缺失颜色不会改变对象下标集合。

否则，设严格大于 `b` 的频数有 `g` 个，等于 `b` 的有 `t` 个。最优子集必须选择全部
`g` 个较大组，再从 `t` 个边界组中选择 `r = k-g` 个，因此方案数为 `C(t,r)`。

为什么可以只考虑完整颜色组？如果已选某个颜色，却漏掉该颜色的一个对象，补上这个对象会增加大小，
而不会增加颜色种数，所以原子集不可能最优。若还允许增加颜色，加入任意剩余非空组也能改进大小。
因此应选频数最大的 `k` 个非空组；实际组数不足 `k` 时全选。

如果选中了较小组却未选较大组，交换两组会严格增大大小。所以高于边界 `b` 的组全部必选，
低于边界的全部排除，只有相同正频数的边界组可以选择。任意 `r` 个边界组的总大小相同。
这些组非空，不同选择一定对应不同的对象下标集合；颜色确定后必须包含组内全部对象，没有组内额外选择。

计算组合数时取 `q = min(r,t-r)`，初始化 `ways = 1`，对 `i = 1..q` 执行
`ways = ways * (t-i+1) / i`。每步结果都是 `C(t,i)`，所以整除没有误差。
乘法使用宽整数，不能先算阶乘：最终答案至多 `C(26,13) = 10400600`，但 `26!` 超出 64 位。

第一个样例的五个频数均为一，选一个对象有五种方案。第二个样例的频数是 3、2、1，
选择大小为 3 和 2 的两个组得到 5，且选择唯一。

设字母表大小为 `σ`，时间为 `O(n + σ log σ)`，频数空间为 `O(σ)`。
本题 `σ = 26`，所以时间为 `O(n)`。程序缓存输入字符串，总额外空间为 `O(n + σ)`，
固定字母表下为 `O(n)`。也可以在完整组上做限制组数的背包，统计后用 `O(σk)` 工作，适合独立验证。

注意事项：

- 限制的是颜色种数，而非对象个数。
- 同色对象下标仍不同，但最优选择必须包含所选组的全部对象。
- 计数的是子集而非排列；零频数不增加方案。
- 正确处理边界相同频数，以及 `k = 1`、`k = 26`。
- 不要使用阶乘或浮点数计算精确方案数。

## 各语言说明

C++、Go、Rust 用 64 位整数计算组合数，Java 用 `long`，Python 的整数保持精确。
频数之和用普通整数即可。Java 按升序排序并取最后 `k` 项，其余版本按降序取前 `k` 项。
Go 使用带缓冲读取器的 `fmt.Fscan`，可读入 100000 字符的单个 token，不受 Scanner 默认长度上限影响。
CPython 使用相同的线性扫描。
