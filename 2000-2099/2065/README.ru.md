# 2065. Мало различных сумм на отрезках

[Timus 2065](https://acm.timus.ru/problem.aspx?space=1&num=2065) · сложность 318 · constructive

Автор оригинальной задачи — Никита Сивухин; подготовка — Алексей Данилюк и Никита Сивухин. Уральская региональная командная олимпиада по программированию 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Постройте массив из n целых чисел, в котором не меньше k различных
значений, так чтобы суммы его отрезков принимали как можно меньше
различных значений. Все числа по модулю не больше 10⁶. Ограничения:
1 секунда и 64 МБ.

## Входные данные

Два целых числа n и k, 1 ≤ k ≤ n ≤ 500.

## Выходные данные

n целых чисел в одной строке. Принимается любой оптимальный массив.

## Проверка

Проверяющая программа сверяет значения и число различных значений и
считает различные суммы отрезков, которых должно быть ровно k.

## Примеры

### Пример 1

Ввод:

```
1 1
```

Вывод:

```
-987654
```

### Пример 2

Ввод:

```
3 2
```

Вывод:

```
0 7 0
```

## Решение

Каждый отдельный элемент — это отрезок, поэтому у массива с k
различными значениями не меньше k различных сумм отрезков. Эта оценка
всегда достижима: возьмём n − k + 1 нулей, а за ними 1, −1, 2, −2, 3, …,
пока чисел не станет n. Нули и k − 1 остальных чисел дают ровно k
различных значений.

Сумма отрезка — разность двух префиксных сумм. Префиксные суммы этого
массива — 0, …, 0, 1, 0, 2, 0, 3, …: нули чередуются с 1, 2, …, m, где
m — наибольшее использованное число. Если массив кончается на −m,
разности более ранней и более поздней префиксных сумм покрывают ровно
−m, …, m, то есть 2m + 1 = k значений. Если он кончается на m,
префиксная сумма m стоит последней, поэтому −m не получается, и суммы —
это −(m − 1), …, m, снова 2m = k значений. Значит, массив оптимален, а
ответ строится за O(n).

Во втором примере массив 0 0 1 имеет значения 0 и 1 и суммы отрезков 0
и 1, по два, как и ответ из примера 0 7 0.

## Оптимизированные решения

Go и Rust выводят ту же конструкцию из n−k+1 нулей и хвоста 1, −1, 2, −2 и так далее до общей длины n. Go формирует ответ в фиксированном буфере для n ≤ 500 и напрямую обращается к дескрипторам ввода и вывода, Rust использует ограниченный буфер вывода. Промежуточный массив чисел или список строковых представлений не строится.

Принятые базовые реализации [2065_constructive.cpp](2065_constructive.cpp), [2065_constructive.java](2065_constructive.java), [2065_constructive.py](2065_constructive.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
