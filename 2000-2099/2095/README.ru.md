# 2095. Подсчёт дней, которые оставляет повторное решето

## Задача

Дни нумеруются 1, 2, 3, … Каждый второй день — отчёт; из оставшихся
дней каждый третий — отчёт; из оставшихся — каждый четвёртый, и так
бесконечно. Дни, которые никогда не убираются, спокойные. Посчитайте
спокойные дни на [l; r]. Ограничения: 1 секунда и 64 МБ.

## Входные данные

l и r, 1 ≤ l ≤ r ≤ 10⁹.

## Выходные данные

Число спокойных дней от l до r.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Примеры

### Пример 1

Ввод:

```
1 10
```

Вывод:

```
3
```

## Решение

Пусть f(n) — число спокойных дней среди первых n. Удаления всегда
берут позиции в списке оставшихся дней, поэтому среди первых c
оставшихся дней шаг k убирает ровно ⌊c / k⌋, а оставшиеся дни среди
первых n остаются префиксом списка. Значит, f(n) находится как
c ← c − ⌊c / k⌋ при k = 2, 3, …, пока c ≥ k; когда c < k, дальнейшие шаги
префикс не трогают. Число c убывает примерно как n / k, так что цикл
кончается примерно через 2√(n/π) шагов, около 3.6·10⁴ для 10⁹. Ответ —
f(r) − f(l − 1).

В примере f(10): 10 → 5 → 4 → 3, и спокойные дни — 1, 3 и 7.

## Оптимизированные решения

`2095_math_optimized.java`. Сохраняем точное удаление блоками одинакового частного, одновременно продвигая верхний и нижний префиксы. Если они сравнялись, ответ сразу ноль. При L=1 значение quiet(0)=0, поэтому считается лишь верхний префикс. Выбор безопасного общего скачка использует сравнение целых вместо Math.min. Каждый шаг по-прежнему удаляет floor(c/k); пока частное q постоянно, объединяем j=floor((c−qk)/(2q))+1 шагов. Время O(R^(1/3)), числовое состояние O(1). Обе границы прочитаны до переиспользования входного буфера 64 байта под ответ; вывод сбрасывается перед Runtime.getRuntime().halt(0). Все 45150 интервалов 1≤L≤R≤300 совпали с независимым пошаговым оракулом; 2000 больших — с принятым предшественником, дополнительно проверены 1000 запусков основного метода с вводом/выводом. Текущая пара 0.093 с/464 КБ и историческая 0.125 с/320 КБ разделены: ускорение здесь требует больше памяти. Наглядное пошаговое решето и остальные языковые реализации сохранены.

Accepted точного исходника Java 1.8 №11327888: 0.093 с / 464 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 5/44, память 1/44. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11309305: 0.125 с / 320 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `2095_math_optimized.java`: 0.093 s / 464 KB; сохранённая учебная база `2095_math.java`: 0.125 s / 1556 KB.

Одношаговое решето сохраняем как учебную базу. Перед шагом k размер оставшегося префикса c=qk+r. После j удалений по q частное остаётся q ровно при 2 qj<=r; верхнее неравенство лишь ослабляется. Сразу выполняем r//(2 q)+1 шагов: c-=q*j,k+=j. Следующее положительное частное строго меньше. Перед k индукция из c<-c-floor(c/k) даёт (k-1)c<=N+(k-2)(k-1)/2. При K=ceil(N^(1/3))+1 ранних шагов меньше K, а затем q<=K, значит остаётся не больше K блоков: O(N^(1/3)) времени, O(1) состояния. Ответ quiet(R)-quiet(L-1). Go использует ограниченный переносимый нативный ввод-вывод, Java использует те же точные блоки. Python вычисляет каждый префикс отдельно и получает частное и остаток одним вызовом divmod. Все вычисления целочисленные.

- `2095_math_optimized.go`: 0.015 s / 280 KB; база `2095_math.go`: 0.031 s / 1076 KB; изменение относительно базы: время -51.6%, память -74.0%.

- `2095_math_optimized.py`: 0.062 s / 368 KB; база `2095_math.py`: 0.078 s / 368 KB; изменение относительно базы: время -20.5%, память -0.0%.

`2095_math_optimized.rs`. Сохраняется точное пошаговое решето для каждого префикса: c заменяется на c-floor(c/k), k растёт от двух до условия c<k. Вычисляется quiet(R)-quiet(L-1), в том числе quiet(0)=0. На префикс нужны лишь две переменные цикла: O(√R) времени и O(1) дополнительного состояния. Rust использует среду выполнения C для ввода-вывода, без целых декодированных строк String и форматирования Rust. Простой принятый исходник сохранён без изменений.

По сравнению с `2095_math.rs`: время 0.015 s → 0.031 s; память 204 KB → 52 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2095_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
