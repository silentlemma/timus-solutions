# 2013. Значения на входе и выходе при любом маршруте

[Timus 2013](https://acm.timus.ru/problem.aspx?space=1&num=2013) · сложность 940 · graphs

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Движение по ориентированному графу начинается в вершине 1 со значением
0. При входе запоминается текущее значение. Затем параметр вершины `k`
заменяет его, если `k>0`; при `k=0` значение сохраняется. Получаем
значение на выходе и переходим по любому исходящему ребру. Вершины можно
посещать повторно. Для каждой вершины определите, одинаковы ли значения
на входе и на выходе при всех возможных маршрутах до этого посещения.
Все вершины достижимы из 1.

## Входные данные

Сначала `n`, `1 ≤ n ≤ 100 000`. Далее для каждой вершины по порядку
строка `k m` и `m` различных исходящих соседей в возрастающем порядке.
`0 ≤ k ≤ 100 000`, `0 ≤ m ≤ n`; номера соседей от 1 до `n`, возможны
петли. Всего рёбер не больше 100 000. Лимит времени 1 секунда, памяти 64
МБ.

## Выходные данные

Для каждой вершины по порядку выведите два ответа: до замены и после
неё. Если значение всегда нулевое, пишите `sober`; если всегда одно
положительное — само число; при нескольких возможных значениях —
`unknown`. Слова в нижнем регистре. Единственный набор ответов
сравнивается по токенам.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
5
0 2 2 3
6 1 4
5 2 4 5
5 1 5
0 0
```

```
sober sober
sober 6
sober 5
unknown 5
5 5
```

```
2
0 2 1 2
0 2 1 2
```

```
sober sober
sober sober
```

В первом примере на входе вершины 4 возможны 6 и 5, поэтому ответ
неизвестен; собственная замена делает выход равным 5. Оба пути в вершину
5 после этого несут 5. Во втором примере замен нет, поэтому циклы не
меняют начальный ноль.

## Решение

У каждого входа храним одно из состояний: ещё не достигнут, известно
одно значение (включая ноль), неизвестно. Два служебных отрицательных
кода должны различаться. Входу вершины 1 задаём ноль и кладём вершину в
очередь изменений. Начальный ноль остаётся возможным даже при
последующем возврате в вершину 1.

Извлекаем вершину: её выход равен положительному `k`, если оно есть,
иначе текущему состоянию входа. Предлагаем выход всем соседям. Не
достигнутый сосед принимает предложение. Совпадающие известные значения
остаются прежними, разные состояния объединяются в неизвестное.
Неизвестное поглощает последующие предложения. Соседа добавляем в
очередь только при изменении входа. После опустошения очереди тем же
правилом вычисляем все выходы.

Сводного состояния достаточно: замена полностью отбрасывает историю, а
нулевая вершина сохраняет её. Объединение разных достижимых значений или
уже неоднозначного состояния правильно выявляет несколько возможностей.
Одинаковые значения из разных вершин не конфликтуют: важны числа, а не
источник. Каждая переданная возможность получена реальным маршрутом,
поэтому ложной неоднозначности нет. После завершения каждое ребро
передало итоговый выход предшественника; индукция по длине конечного
маршрута показывает, что учтены все его возможности. Значит,
единственное значение общее для всех маршрутов, а неизвестность означает
хотя бы два. Особый порядок обхода циклов не нужен.

Вход меняется не более двух раз: из недостигнутого в известный, затем в
неизвестный, либо сразу в неизвестный. Каждое изменение даёт не больше
одного добавления в очередь. Список рёбер вершины просматривается не
более двух раз. Итого время `O(n+m)`, память `O(n+m)`. Храним соседей
плоским массивом с границами списков и используем итеративную очередь,
без рекурсии и перебора маршрутов.

## Особенности языков

Первый визит не фиксирует ответ: поздний конфликт нужно провести через
нулевые вершины. Положительная вершина сбрасывает даже неизвестное
значение. Возврат в вершину 1 может сделать её вход неизвестным. Цикл
без замен сохраняет ноль, одинаковые положительные метки не конфликтуют.
Благодаря достижимости служебное недостигнутое состояние не выводится.
Очереди Java достаточно `2n` мест; Go, C++ и Rust используют растущие
массивы. Python хранит граф и состояния компактными знаковыми массивами,
очередь — deque; разобранные токены освобождаются до построения ответа.
Используется CPython.
