# 2003. Итерации попарных НОД

[Timus 2003](https://acm.timus.ru/problem.aspx?space=1&num=2003) · сложность 366 · number_theory

Автор оригинальной задачи — Кирилл Бороздин; Уральская региональная командная олимпиада по программированию 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Массив содержит положительные целые числа. За шаг он заменяется НОД
каждой неупорядоченной пары различных позиций. Каждая пара даёт
отдельный элемент, даже при совпадении значений или результатов. Поэтому
длина `k` становится `k(k−1)/2`. Нужно найти минимальное число шагов до
массива, состоящего только из единиц.

## Входные данные

Первая строка содержит `n`, `3 ≤ n ≤ 10000`. Следующие `n` строк
содержат элементы от 1 до `10^7`. Числа разделены пробельными символами.
Время 1 секунда, память 64 МБ.

## Выходные данные

Минимальное число шагов либо строчное `infinity`, если цель недостижима
или ответ превышает `10^18`. Для исходного массива единиц ответ равен 0.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3
1
2
3
```

```
1
```

```
4
2
2
2
2
```

```
infinity
```

В первом примере НОД каждой пары равен 1, поэтому достаточно одного
шага. Во втором любой новый элемент остаётся равен 2 бесконечно.

## Решение

Зафиксируем простое `p`. Пусть `c` текущих элементов делятся на него.
Новый НОД делится на `p` тогда и только тогда, когда обе выбранные
позиции делились на `p`. Следовательно, новая кратность присутствия
равна `c(c−1)/2`. Считаются позиции, а не показатели степеней простого.

Получаем переходы `0→0`, `1→0`, `2→1→0`. Значение 3 сохраняется. При
`c≥4` выполняется `c(c−1)/2≥c`, поэтому присутствие хотя бы в трёх
элементах никогда не исчезает. Длина массива всё время не меньше 3,
поскольку начальная длина не меньше 3.

Значит, простое, делящее три исходных элемента, доказывает ответ
`infinity`. Если такого простого нет, все простые исчезнут за два шага.
Исходное присутствие в двух элементах требует ровно двух шагов; иначе
любому числу больше 1 нужен ровно один. При полном отсутствии простых
множителей ответ 0. Это доказывает достижимость и минимальность.
Конечных ответов больше 2 нет, поэтому граница `10^18` не требует
больших чисел.

Решетом строим простые до `B=floor(sqrt(A))`, где `A` — максимальный
элемент. Каждое число делим на эти простые, пока квадрат пробного
делителя не превысит остаток. Найденное простое учитываем один раз и
удаляем все его степени. Оставшийся множитель больше 1 прост и
учитывается один раз. Счётчики храним в хеш-таблице; третье появление
сразу даёт `infinity`. Иначе ответ — наибольший счётчик, изначально 0.

Пусть `P` — число простых до `B`, а `F` — сумма количеств различных
простых множителей по всем элементам. Ожидаемое время `O(B log log(B+2)
+ nP + n log(A+1))` включает деления и хеш-операции; память `O(n+B+F)`
учитывает вход. Оценка хеширования ожидаемая. Здесь `B≤3162`, `P≤446`,
`F≤8n`: произведение первых девяти простых уже больше `10^7`. Решето
размера `10^7` и разрастающийся массив НОД не нужны.

Один простой учитывается только раз на позицию: `[4,8,1]` требует двух
шагов независимо от степеней двойки. Общий НОД 1 не доказывает
завершение: `[2,2,2,3]` бесконечен. А `[6,10,15]` требует двух шагов,
хотя каждая исходная пара имеет общий делитель. Равные значения занимают
разные позиции. Единица не добавляет множителей. Слово `infinity`
выводится точно в указанном регистре.

## Особенности языков

Пять портов используют деление на небольшие простые и разреженные
счётчики. C++, Go, Java и Rust получают границу корня целочисленно,
Python использует `isqrt`. Произведения укладываются в знаковое
32-битное число. В Java ввод буферизован, Python разбирает вход целиком.
CPython выбран после измерения полной программы на максимальных входах.
