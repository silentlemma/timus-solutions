# 2044. Маски числа палиндромов для всех префиксов

[Timus 2044](https://acm.timus.ru/problem.aspx?space=1&num=2044) · сложность 2428 · strings

Автор оригинальной задачи — Михаил Рубинчик; Ural FU Dandelion contest. Petrozavodsk training camp. Summer 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано слово из `1≤n≤300000` строчных латинских букв. Для каждого
непустого префикса и каждого `j` от `1` до `31` требуется определить,
можно ли разбить префикс ровно на `j` непустых палиндромов. Части идут
подряд, покрывают все позиции и могут совпадать. Палиндром одинаково
читается в обоих направлениях.

Для одного префикса ответы кодируются целым неотрицательным числом: бит
`j-1` установлен тогда и только тогда, когда разбиение на `j` частей
существует. Число лежит в диапазоне `0..2^31-1`. Лимиты: 0,5 секунды и
64 МБ.

## Входные данные

Одна строка со словом. Его длина равна `n`; отдельного числа длины нет.

## Выходные данные

Вывести `n` десятичных целых чисел, каждое с новой строки, по
возрастанию длины префикса. Целочисленные токены сравниваются точно.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
abaa
```

```
1
2
5
14
```

Для `a` возможна только одна часть. Для `ab` подходит лишь `a|b`.
Префикс `aba` допускает целый палиндром и `a|b|a`, поэтому маска равна
`1+4=5`. У `abaa` существуют `aba|a`, `a|b|aa` и `a|b|a|a`: две, три и
четыре части дают `2+4+8=14`.

## Решение

### Динамика по префиксам и дерево палиндромов

Во внутренней маске `D[i]` бит `j` означает возможность разбить первые
`i` букв на `j` частей. Бит ноль, в отличие от формата ответа, отведён
нулю частей; `D[0]=1`. Если последний палиндром имеет длину `L`, перед
ним остаётся префикс `i-L`. Поэтому `D[i]=OR(D[i-L]<<1)` по всем
палиндромным суффиксам текущего префикса. Оставляем биты `0..31`, а
печатаем `D[i]>>1`. Большие количества частей можно отбросить:
добавление части не уменьшает их число.

Дерево палиндромов, или eertree, содержит по вершине для каждого
различного непустого палиндрома и два корня длины `-1` и `0`. Переход по
букве `c` окружает палиндром двумя буквами `c`. Суффиксная ссылка
`link[v]` ведёт в самый длинный собственный палиндромный суффикс. При
добавлении буквы поиск по ссылкам находит расширяемый суффикс, создаёт
не более одной вершины и определяет её ссылку. Перед словом стоит
символ, отсутствующий в алфавите.

Полный проход по суффиксным ссылкам для каждого префикса квадратичен на
одинаковых буквах. Введём `diff[v]=len[v]-len[link[v]]`.
Последовательные одинаковые разности образуют серию. Если
`diff[v]=diff[link[v]]`, полагаем `series[v]=series[link[v]]`; иначе
`series[v]=link[v]`. Ссылка `series` перескакивает за всю текущую серию.

### Объединение для целой серии

У каждой вершины хранится постоянная маска `cache[v]`. Для конца
префикса `i` идём от самого длинного палиндромного суффикса по `series`.
В посещённой голове `v` положим `d=diff[v]` и `B=len[series[v]]+d`: это
минимальная длина в серии. Запишем `cache[v]=D[i-B]`. Если разности `v`
и `link[v]` равны, добавим через OR значение `cache[link[v]]`. Затем
добавим `cache[v]<<1` в ответ и перейдём к следующей серии.

Используемая маска суффиксной ссылки обычно вычислена на более раннем
префиксе. Это необходимая часть алгоритма; обнулять кеши после каждого
символа нельзя.

### Почему старое значение соответствует текущим разрезам

У палиндрома любая граница тоже палиндром: суффикс является обращением
равного по длине префикса. Периоду соответствует дополнительная длина
границы, поэтому `diff[v]` — минимальный период палиндрома.

Рассмотрим нетривиальную серию, `u=link[v]`, `diff[u]=diff[v]=d`. Имеем
`|v|=|u|+d` и `|u|≥d`. Префиксная и суффиксная копии `u` покрывают `v`,
их начала сдвинуты на `d`. Между ними не может начинаться ещё одна копия
`u`: перекрытие с первой дало бы период меньше `d`. Следовательно, `u`
не встречается как суффикс при концах строго между `i-d` и `i`.

При конце `i-d` вершина `u` была головой серии. Иначе в той суффиксной
цепочке есть непосредственный предшественник `z` с `link[z]=u` и той же
разностью `d`. Тогда `|z|=|v|`; две покрывающие копии `u` однозначно
задают `z=v`. Две копии `v` с концами `i-d` и `i` образуют более длинный
палиндром `W`: отражение относительно его центра меняет местами
одинаковые палиндромные копии. Его минимальный период равен `d`,
поскольку период `d` есть, а меньший невозможен уже внутри `v`. Получаем
`link[W]=v` с той же разностью, что противоречит тому, что `v` сейчас
голова серии.

Значит, `cache[u]` последний раз обновлялся при `i-d`. По индукции в нём
объединены `D[i-d-L]` для длин старой серии `L=B,B+d,…,|v|-d`. Это ровно
разрезы для текущих более длинных суффиксов `B+d,…,|v|`. Добавление
`D[i-B]` учитывает оставшийся самый короткий суффикс. Для серии из одной
вершины хватает одного этого значения.

Итак, каждый кеш объединяет ровно разрезы своей текущей серии. Серии
разбивают множество всех палиндромных суффиксов, а сдвиг добавляет
последнюю часть. Индукция по длине префикса доказывает точность масок.
Доказательство относится к самим индексам разрезов, поэтому обосновывает
OR, а не только динамику минимального количества частей.

### Сложность

Каждые два перехода `series` уменьшают положительную длину хотя бы
вдвое. Пусть три последовательные длины — `L,A,B` и `B>L/2`. Обозначим
минимальные периоды первого и второго палиндромов через `d` и `e`.
Второй наследует период `d`, но имеет другую разность, поэтому `e<d`;
также `e≤A-B`. Две его копии покрывают первый палиндром и пересекаются в
`2A-L>2e` позициях. Объединение двух `e`-периодических строк с
перекрытием хотя бы `e` тоже `e`-периодично: каждую пару позиций на
расстоянии `e` покрывает одна из копий. Это противоречит минимальности
`d`, так что `B≤L/2`.

Один переход не обязан делить длину пополам: `aabaaabaa` даёт `9→5`.
Доказанного свойства двух переходов достаточно для `O(log n)` серий на
префикс. С учётом амортизированных поисков суффикса и фиксированного
алфавита получаем `O(n log n)` времени и `O(n)` памяти. У Python время
доступа к словарю переходов ожидаемое; остальные реализации используют
массивы с ограниченной степенью вершины.

Базовый приём серийных ссылок описан в [Rubinchik и Shur, EERTREE,
раздел 4.1](https://arxiv.org/abs/1506.04862). Доказательство
объединения разрезов выше объясняет его применение к точным маскам числа
частей.

Подводные камни:

- Части непусты; внутренний бит ноль относится только к пустому префиксу.
- Нужен OR, а не сложение: разные разрезы могут давать одинаковое число частей.
- Внутри сохраняются 32 бита, после чего ответ сдвигается вправо. В Java
  нужен беззнаковый сдвиг.
- Старые кеши сохраняются: их временной сдвиг используется в доказательстве.
- Нулевая маска может позже стать ненулевой благодаря длинному суффиксу,
  достигающему раннего разреза.
- Плотные таблицы 64-битных индексов могут превысить лимит памяти;
  переходы следует хранить компактно.

## Особенности языков

C++ и Go используют массивы из 26 переходов с 32-битными индексами. В
Rust переходы тоже 32-битные, с преобразованием при индексировании. Java
хранит исходящие рёбра списками в примитивных массивах; индекс входящего
ребра совпадает с индексом вершины, поиск просматривает не более 26
рёбер. Вывод буферизован.

Python хранит поля и маски в компактных `array`, переходы — в одном
словаре по ключу `parent*26+letter`, выводит порциями.

Решение на Python запускается под PyPy: под CPython 3.12 оно превышает
ограничение времени на 32-м тесте судьи, а под PyPy 3.10 принимается за
0.375 с.
