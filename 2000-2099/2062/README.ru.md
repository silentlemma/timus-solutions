# 2062. Накапливаем излучение по делителям

[Timus 2062](https://acm.timus.ru/problem.aspx?space=1&num=2062) · сложность 296 · fenwick

Автор оригинальной задачи — Алексей Данилюк; подготовка — Никита Сивухин. Уральская региональная командная олимпиада по программированию 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В цепочке n частиц с начальными зарядами a[i]. Направленная на частицу k
мощность d добавляет d каждой частице, номер которой кратен k. Операция
`2 l r d` направляет мощность d на каждую частицу от l до r по
отдельности, так что частица, до которой достают несколько из них,
получает несколько добавок; операция `1 i` спрашивает текущий заряд
частицы i. Ограничения: 3 секунды и 128 МБ.

## Входные данные

Сначала n, затем n зарядов a[i], затем q и q операций. 1 ≤ n, q ≤
300 000, 0 ≤ a[i], d ≤ 10⁶, 1 ≤ i ≤ n, 1 ≤ l ≤ r ≤ n.

## Выходные данные

Ответы на запросы, по одному в строке.

## Проверка

Ответы сравниваются по токенам.

## Примеры

За каждым блоком ввода приведён соответствующий вывод.

```
3
1 2 3
2
2 1 3 5
1 2
```

```
12
```

```
6
1 2 1 4 5 6
5
2 2 4 2
1 3
1 4
2 3 5 1
1 5
```

```
3
8
6
```

В первом примере излучение мощности пять на `[1,3]` достигает частицы
два от источников один и два. С учётом начального заряда получаем
`2+5+5=12`. Сами начальные заряды не являются источниками излучения.

Во втором примере после первой операции каждый источник из `[2,4]`
получает мощность два. Для частицы три действует только источник три:
`1+2=3`. Для частицы четыре действуют источники два и четыре: `4+2+2=8`.
Следующее воздействие на `[3,5]` добавляет единицу мощности источнику
пять; заряд частицы пять становится `5+1=6`.

## Решение

### Отделим мощность источника от заряда частицы

Пусть `v[k]` — суммарная мощность, направленная на источник `k`;
изначально она нулевая. Воздействие прибавляет `d` к `v[l..r]`. Источник
достигает частицы `i` тогда и только тогда, когда его номер делит `i`.
Поэтому её заряд равен `a[i]+sum(v[k] : k делит i)`. Для одного
воздействия равенство следует из правила задачи, а сложение сохраняет
его после каждого действия. Разные делители обозначают разные источники:
совпавшие по месту волны не отменяют и не объединяют прибавки.

### Прибавление на отрезке через дерево Фенвика

Храним в дереве Фенвика разности массива `v`. Прибавление `d` на
включительном отрезке требует точечной прибавки в `l` и вычитания в
`r+1`, если этот индекс существует. Сумма разностей на префиксе до `k`
равна `v[k]`: две граничные поправки дают вклад `d` ровно внутри
отрезка. Пути точечного обновления и префиксного запроса Фенвика
корректно разбивают нужные диапазоны и требуют `O(log n)` шагов. При
измерении складываем такие префиксные суммы по всем делителям номера и
добавляем только собственный начальный заряд. По доказанному инварианту
это и есть требуемый физический заряд.

### Компактное хранение пар делителей

Каждый делитель входит в пару `(d,i/d)`, меньший элемент которой
удовлетворяет `d²≤i`. Предвычисляем только меньшие элементы: для каждого
`d` с `d²≤n` посещаем `d²,d²+d,…≤n`. Это в точности кратные числа, для
которых `d` является малым делителем. Первый проход считает размеры
списков, префиксные суммы задают смещения в общем плоском массиве,
второй заполняет соответствующие срезы. При измерении перебираем срез
числа `i` и запрашиваем оба элемента каждой пары; при равенстве
элементов запрос выполняется один раз. Меньший элемент однозначно задаёт
пару, поэтому все положительные делители, включая единицу и само число,
учитываются ровно по одному разу. У квадратов необходима отдельная
проверка равенства.

Малые делители помещаются в 16 бит: `d≤floor(sqrt(300000))=547`; хватает
и знакового Java short. Количество элементов не превосходит
`n·547=164100000<2³¹`, поэтому смещения помещаются в знаковые 32 бита;
память выделяется по фактически подсчитанному размеру. Точное число
записей — `S=sum(floor(n/d)−d+1,1≤d≤floor(sqrt(n)))`. Гармоническая
оценка даёт `O(n log n)` для обоих проходов и хранения, без отдельного
списка упакованных в объекты чисел для каждой частицы.

Не складывайте начальные заряды по делителям. Обновлять надо
направленные мощности. Правая граница включена: отрицательная поправка
ставится в `r+1`, а при `r=n` остаётся за деревом и не выполняется.
Индексация начинается с единицы: обновление нулевого индекса не
сдвигается. Не считайте корень квадрата дважды, не обрезайте ответ до 32
бит, не забывайте источник один и не печатайте ответ на воздействие.
Повторные измерения и нулевая мощность допустимы.

## Оптимизированные решения

C++ и Go заполняют отрезки таблицы делителей с конца. Конечные смещения становятся начальными без второго массива указателей. Начальные заряды занимают 32 бита, а дерево Фенвика и суммы остаются 64-битными. PyPy хранит наименьшие простые делители и перечисляет делители при измерении частицы. Результат можно использовать повторно до следующего ненулевого обновления дерева.

Принятая версия G++ 13.2 x64 заняла 0.453 с при 0.437 с у базовой и использовала 8 152 KB при 10720 KB у базовой.

Принятые базовые реализации [2062_fenwick.java](2062_fenwick.java), [2062_fenwick.rs](2062_fenwick.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

Заряды и ячейки Фенвика — знаковые 64-битные числа. Безопасная грубая
оценка заряда: `1000000+q·n·1000000≤90000000001000000<2⁶³`, поскольку
одно воздействие имеет не более `n` источников. Разности могут быть
отрицательными, хотя реальные мощности неотрицательны. Индексы и
произведение `d²` укладываются в 32 бита.

Предподготовка требует `O(n log n)` времени и памяти. Для `u`
воздействий и измерений с номерами `i₁,…,iₘ` общее время равно `O(n log
n+u log n+sum(τ(iⱼ) log n))`, где `τ(i)` — число делителей. Одно
обновление стоит `O(log n)`, измерение — `O(τ(i) log n)`, а не
константу. Во всех пяти версиях одинаковые срезы пар. C++, Go, Java и
Rust используют примитивные массивы или векторы и буферизованный
ввод-вывод. Python хранит делители в 16-битном массиве, смещения — в
32-битном, заряды и Фенвик — в 64-битных; читает построчно и выводит
порциями по 1024 строки. Решение на Python работает на PyPy:
CPython слишком медленный на самых больших тестах.
