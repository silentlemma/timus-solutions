# 2009. Две очереди с секундным обслуживанием

[Timus 2009](https://acm.timus.ru/problem.aspx?space=1&num=2009) · сложность 833 · simulation

Автор оригинальной задачи — Алексей Кунгурцев; Уральская региональная командная олимпиада по программированию 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Студенты приходят в две очереди, левую и правую. Обслуживание занимает
секунду и начинается сразу, когда это возможно. Прибывший может встать в
любой хвост либо непосредственно за указанным знакомым, который сейчас
стоит в очереди. Выбирается место с наименьшим числом людей впереди; при
равенстве выбирается правая очередь. Позже менять очередь нельзя.
Студенты группы приходят одновременно, но выбирают места последовательно
в заданном порядке. Обслуживания, заканчивающиеся в момент прихода,
происходят раньше всех прибытий в обеих очередях. Найдите время выхода и
очередь каждого студента.

## Входные данные

Числа `n m`, `5 ≤ n ≤ 1000`, `1 ≤ m ≤ n`. Номера студентов 1..n. Каждая
из следующих `n` строк содержит до 100 номеров других студентов, за
которыми можно встать, и завершается 0. Разрешение направленное,
взаимность не гарантируется, собственного номера нет. Группа задаётся
строкой `t k` и строкой из `k` номеров в порядке входа. Времена групп
возрастают, целые `1 ≤ t ≤ 10^9`. Каждый студент приходит ровно один
раз. Время 1 секунда, память 64 МБ.

## Выходные данные

Выведите `n` строк по номерам студентов. В каждой время выхода и `left`
либо `right`. Единственные правильные числа и слова сравниваются по
токенам.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
5 1
0
0
0
0
1 0
1 5
1 2 3 4 5
```

```
2 right
2 left
4 right
3 left
3 right
```

После первых четырёх прибытий справа `[1,3]`, слева `[2,4]`. Студент 5
может встать сразу за 1, поэтому справа становится `[1,5,3]`. Все пришли
в момент 1, первые выходят в 2. Студент 5 выходит в 3, студент 3 — в 4.
Вывод остаётся упорядоченным по номерам.

## Решение

Храним обе очереди упорядоченными массивами. Для каждого студента
известны текущая очередь, либо −1, если студент не ждёт, и позиция с
нуля. Для непустой очереди сохраняем ближайшее время завершения
обслуживания. Старую позицию ушедшего студента игнорируем по признаку
отсутствия.

Перед группой в момент `t` продвигаем обе кассы. Если ближайшее
завершение `u≤t`, уйдут ровно `min(длина_очереди,t−u+1)` первых
студентов. Записываем времена `u,u+1,…`, отмечаем ушедших, удаляем
префикс и обновляем позиции остальных. Для непустого остатка прибавляем
число ушедших к ближайшему завершению, для пустого отмечаем простой.
Даже промежутки до `10^9` обрабатываются арифметически.

При приходе начинаем с позиций обоих хвостов. Каждый указанный знакомый,
который ещё ждёт, предлагает свою позицию плюс один в соответствующей
очереди. Берём минимумы. Левую выбираем только при строго меньшей
позиции, иначе правую. Вставляем студента и обновляем позиции сдвинутого
суффикса. Если очередь была пуста, новый первый завершит обслуживание в
`t+1`. После всех групп дописываем оставшиеся выходы от ближайшего
завершения с шагом в секунду.

Индукция по событиям прихода. Изначально массивы, присутствие и часы
описывают пустые очереди. Пока прибытий нет, первый завершает в
сохранённый момент, остальные — каждую следующую секунду в порядке
массива. Формула обслуженного префикса выполняет в точности все
завершения не позже `t`, включая равенство, и восстанавливает позиции до
новых прибытий.

Все допустимые места — это ровно хвосты и позиции непосредственно за
присутствующими указанными знакомыми. Минимумы и правило равенства
выбирают требуемое место. В непустой очереди любая такая позиция не
меньше единицы, поэтому обслуживаемого первого никто не сдвигает и его
часы сохраняются. В пустой обслуживание начинается сейчас и
заканчивается через секунду. Обновление суффикса сохраняет присутствие и
позиции для следующего студента той же группы. Финальное опустошение —
такой же промежуток без прибытий. Значит, все записи ответа правильны.

Пусть `F≤100n` — суммарное число указанных знакомых. До `n` вставок и
`2m` пакетов обслуживания сдвигают или перенумеровывают до `n` позиций,
просмотр знакомых суммарно занимает `F`. Время `O(n²+F)`, память
`O(n+F)` вместе с входом и ответом. Перебирать прошедшие секунды не
нужно. Выход не позже `max_приход+n≤1000001000`, достаточно знакового
32-битного числа.

## Особенности языков

Удаляйте обслуженных до всех прибытий в тот же момент; будущие и ушедшие
знакомые не подходят. Разрешения направленные. Новый студент встаёт
сразу за знакомым, перед прежними последователями, а не в конец
постоянной группы. Равенство выбирает правую очередь. После простоя часы
запускаются от нового прихода. Ответ хранится по номерам. Все пять
портов используют итеративные массивы или списки; Java читает
буферизованно и хранит знакомых в примитивных массивах.
