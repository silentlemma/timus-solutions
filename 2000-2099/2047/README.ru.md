# 2047. Последовательность с ограничениями на делители сумм

[Timus 2047](https://acm.timus.ru/problem.aspx?space=1&num=2047) · difficulty 483 · number_theory

Задача из фольклора; подготовка — Александр Ипатов. XIX Открытый чемпионат Урала по спортивному программированию (апрель, 2015).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Постройте n целых чисел a₁, …, aₙ, 1 ≤ aᵢ ≤ 300, так, чтобы для каждого
k от 2 до n префиксная сумма a₁ + … + aₖ имела ровно aₖ различных
положительных делителей. На первый элемент отдельного условия нет.
Ограничения: 1 секунда и 64 МБ.

## Входные данные

Одно целое число n, 2 ≤ n ≤ 100 000.

## Выходные данные

Выведите подходящую последовательность через пробел или `Impossible`,
если её нет.

## Проверка

Проверяющая программа сверяет длину и границы и считает делители каждой
префиксной суммы начиная со второй; принимается любая подходящая
последовательность, а `Impossible` — только если её нет.

## Примеры

```
3
```

```
1 3 4
```

Первая проверяемая сумма `1+3=4` имеет делители `1,2,4`, поэтому
последний элемент равен трём. Следующая сумма `8` имеет делители
`1,2,4,8`, поэтому элемент равен четырём. Другой правильный ответ — `2 4
6`: суммы `6` и `12` имеют четыре и шесть делителей.

## Решение

Обозначим число положительных делителей через `τ(s)`. Если
последовательность хотя бы из двух элементов заканчивается суммой `s`,
последний элемент однозначно равен `d=τ(s)`, а предыдущая сумма — `s-d`.
Просматриваем такие рёбра предшественников по возрастанию суммы.

`depth[s]` — максимальная длина правильной последовательности с суммой
`s`. Одноэлементная последовательность допустима ровно при `1≤s≤300`, её
базовое значение равно единице; иначе начальное значение ноль, то есть
сумма недостижима. Если `d≤300`, `s>d` и `depth[s-d]>0`, рассматриваем
также `depth[s-d]+1` и берём максимум.

Доказанная граница поиска — `M=300n`, поскольку сумма любого нужного
ответа не превосходит её. Останавливаемся при первой глубине `n`.
Проходим назад `n-1` рёбер, записывая вынужденные последние элементы;
остаток суммы становится первым элементом. Разворачиваем ответ. Если до
`M` нужная глубина не достигнута, выводим `Impossible`.

### Блочное вычисление числа делителей

Один раз строим простые до `floor(sqrt(M))`. Суммы обрабатываем блоками
по `K=65536`. Для каждого числа храним остаток, первоначально само
число, и счётчик, первоначально единицу. Для простого `p` с `p²≤right`
посещаем кратные в блоке, удаляем все `e` множителей `p` и умножаем
счётчик на `e+1`. Остаток больше единицы — простой множитель,
добавляющий множитель два. Используется формула `τ(s)=product(e+1)`.

Числа делителей дописываем в компактную историю для восстановления.
Предшественник допустимого ребра отстоит не более чем на 300, поэтому
глубины достаточно хранить в кольце размера 301. Читаем предшественника
до перезаписи текущей позиции. Рёбра с числом делителей больше 300
пропускаем.

### Доказательство

Факторизация удаляет все простые не больше квадратного корня правого
конца блока. Составной остаток имел бы один из этих делителей, что
невозможно; значит, остаётся единица или простой множитель. Произведение
количеств степеней даёт точное число делителей, включая `τ(1)=1`.

Докажем динамику индукцией по сумме. Любая правильная последовательность
либо состоит из одного допустимого элемента, либо её последний элемент
равен `τ(s)`, а предыдущие образуют последовательность с единственной
возможной меньшей суммой. Обратно, добавление этого элемента к
достижимому предшественнику обеспечивает новое условие и сохраняет
старые. Следовательно, максимум в переходе даёт точную наибольшую длину.
Кольцо хранит нужное значение: расстояние до него от одного до 300.

До первой успешной суммы все глубины меньше `n`, поэтому новая глубина в
точности `n`. Обратный проход идёт по тем же рёбрам рекуррентности и
каждый раз уменьшает глубину на единицу. Он заканчивается базовой суммой
не больше 300. Тем самым доказаны границы всех элементов и все условия
на префиксы. Если успеха до `300n` нет, любая требуемая
последовательность противоречила бы точной динамике в своей конечной
сумме. Верны и построение, и `Impossible`, без догадки о сокращённой
границе.

### Сложность и длина поиска

Консервативная верхняя оценка — `O(M log M+n)` времени и
`O(M+K+sqrt(M)+n)` памяти с ранней остановкой. При просмотре `B` сумм
история занимает `O(B)`, факторизуется не более одного лишнего блока.
Накладные проходы простых ограничены тем, что `floor(sqrt(M))≤5477<K`.
Счётчикам хватает 16 бит: `τ(s)≤2sqrt(s)≤2sqrt(30000000)<11000`;
подходит и знаковый short Java.

Независимое обычное решето построило цепочку из 100000 элементов с
конечной суммой `1568617`, затем каждый её префикс проверен перебором
делителей. Её префиксы доказывают существование для всех разрешённых
длин. Поэтому первая успешная сумма для любой длины не больше указанной;
программы всё равно используют полную границу `300n`, не вшивая
найденную цепочку или её конец.

## Особенности языков

Условие начинается с `k=2`. Считаются различные положительные делители,
а не простые множители. Ноль у предшественника означает недостижимость.
В кольце из 301 элемента текущая позиция отличается от всех 300
возможных позиций предшественника; его значение читается до записи
текущей глубины. Для восстановления нужна история чисел делителей,
одного кольца глубин недостаточно. Факторизуются положительные числа
начиная с единицы, не ноль.

Во всех реализациях одинаковый полный поиск с блочной факторизацией.
Java расширяет примитивный массив short; C++, Go и Rust также хранят
историю в 16 битах. Python использует `array("H")` и небольшие списки
блока и кольца.

Решение на Python запускается под PyPy: под CPython 3.12 оно превышает
ограничение времени на 13-м тесте судьи, а под PyPy 3.10 принимается за
0.437 с.
