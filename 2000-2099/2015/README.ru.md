# 2015. Выбор квартиры и доступного способа проживания

[Timus 2015](https://acm.timus.ru/problem.aspx?space=1&num=2015) · сложность 300 · bruteforce

Автор оригинальной задачи — Евгений Курпилянский; NEERC 2014, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Выберите квартиру и проживание без соседа либо с одним другом из списка.
В одиночку разрешено снимать одно- или двухкомнатную квартиру, вдвоём —
только двухкомнатную. При одиночном проживании оплачивается вся аренда;
при совместном каждый платит ровно половину и должен уложиться в свой
бюджет. Оценка равна преимуществу квартиры плюс преимущество одиночного
проживания с данным числом комнат либо преимущество выбранного друга.
Найдите любой доступный вариант с максимальной оценкой. Если доступных
вариантов нет, сообщите об этом.

## Входные данные

Сначала собственный бюджет и две оценки одиночного проживания: для одной
и двух комнат. Далее `n`, `0 ≤ n ≤ 256`, и `n` пар бюджета и оценки
друга. Затем `m`, `1 ≤ m ≤ 256`, и `m` троек: число комнат (1 или 2),
полная аренда и оценка квартиры. Бюджеты и аренда — целые от 1 до
100 000, оценки — от 0 до 100 000. Друзья и квартиры нумеруются с 1 в
порядке ввода. Лимит времени 1 секунда, памяти 64 МБ.

## Выходные данные

Для квартиры `i` без соседа выведите `You should rent the apartment #i
alone.`. С другом `j` — `You should rent the apartment #i with the
friend #j.`. Если доступных вариантов нет — `Forget about apartments.
Live in the dormitory.`. Вместо `i` и `j` подставьте номера, сохранив
слова, пробелы, знаки `#` и точку.

## Проверка

Проверяющая программа сверяет фразу, номера, число комнат и оба бюджета
и сравнивает счёт с оптимумом; принимается любой оптимальный выбор, а
отказ — только если ничего снять нельзя.

В первом случае доступна лишь квартира 1 с оценкой `50+200=250`: даже
половина второй слишком дорога. Во втором лучший одиночный вариант даёт
2001, а квартира 3 с другом 1 — `1001+1001=2002`. В третьем единственная
квартира недоступна.

## Решение

Перебираем квартиры по порядку. Если полная аренда не превышает
собственный бюджет, рассматриваем сумму `оценка_квартиры +
одиночная_оценка[комнаты−1]`. Для двухкомнатной квартиры дополнительно
перебираем каждого друга. Совместное проживание доступно ровно при
`аренда≤2·свой_бюджет` и `аренда≤2·бюджет_друга`; его оценка —
`оценка_квартиры + оценка_друга`. Удвоенные сравнения точны даже при
нечётной аренде, деление и вещественные числа не нужны.

Храним лучшую оценку и два номера. Начинаем с −1, что меньше любой
допустимой оценки. Обновляем только при строгом улучшении: так выбор при
равенстве определён, хотя задача этого не требует. Внутренний номер
друга ноль обозначает одиночный вариант. Если обновления не было,
выводим отказ от аренды.

Любое законное решение — одна квартира без соседа либо двухкомнатная
квартира с одним другом. Циклы рассматривают все эти варианты и
отбрасывают ровно те, где платёж превышает один из бюджетов. Для каждого
кандидата складываются именно нужные две оценки. По индукции сохранённый
выбор лучший среди уже просмотренных доступных. После полного перебора
он глобально оптимален либо доступных вариантов нет. Начальное значение
ниже нуля не даёт спутать доступный вариант с нулевой оценкой с
невозможностью аренды.

Рассматривается не больше `m(n+1) ≤ 65 792` кандидатов, время
`O(m(n+1))`, в том числе при `n=0`. Вход хранится в памяти `O(n+m)`, для
выбора нужно ещё `O(1)`. Оценки и удвоенные бюджеты не больше 200 000,
обычных знаковых целых достаточно. Альтернатива — сортировка друзей по
бюджету с поиском максимальной доступной оценки, но при данных границах
перебор уже укладывается.

## Оптимизированные решения

C++ и Rust сортируют друзей по бюджету и заранее находят самого полезного друга в каждом суффиксе. Для двухкомнатной квартиры двоичный поиск находит первого друга, способного оплатить половину аренды. Суффиксная сводка даёт лучшего допустимого соседа. C++ хранит отдельные индексы суффиксов. Rust сохраняет порядок бюджетов, а поля пользы и номера заменяет на лучший выбор соответствующего суффикса. Rust хранит друзей в фиксированном массиве с 16-битными номерами и использует фиксированные байтовые буферы ввода и десятичного вывода через библиотеку времени исполнения C.

Принятые базовые реализации [2015_bruteforce.go](2015_bruteforce.go), [2015_bruteforce.java](2015_bruteforce.java), [2015_bruteforce.py](2015_bruteforce.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

Однокомнатную квартиру делить нельзя. Проверяйте оба бюджета:
обеспеченный друг не может оплачивать чужую половину. Нельзя округлять
половину нечётной аренды вниз или добавлять одиночную оценку к
совместной. Одиночная оценка зависит от числа комнат. Отсутствие друзей
и нулевые оценки допустимы. Все пять решений используют точные
целочисленные сравнения и одинаковый порядок перебора; отсутствие
варианта отличается от одиночного варианта. Python работает в CPython,
ограниченный перебор не требует оптимизаций.
