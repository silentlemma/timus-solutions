# 2023. Переходы между тремя пунктами

[Timus 2023](https://acm.timus.ru/problem.aspx?space=1&num=2023) · сложность 40 · implementation

Автор оригинальной задачи — Алексей Самсонов; NEERC 2014, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Три пункта стоят на прямой в соседних позициях 0, 1 и 2. Каждая метка получателя
относится ровно к одному пункту согласно полной таблице:

| Позиция | Метки получателей |
| --- | --- |
| 0 | Alice, Ariel, Aurora, Phil, Peter, Olaf, Phoebus, Ralph, Robin |
| 1 | Bambi, Belle, Bolt, Mulan, Mowgli, Mickey, Silver, Simba, Stitch |
| 2 | Dumbo, Genie, Jiminy, Kuzko, Kida, Kenai, Tarzan, Tiana, Winnie |
Нужно обработать `n` меток в заданном порядке, начиная с позиции 0.
Переход к соседней позиции требует одного шага; обработка метки на
нужной позиции бесплатна. Найдите общее число шагов. После последней
метки возвращаться к позиции 0 не требуется. Метки могут повторяться.
Ограничения: `1 ≤ n ≤ 1000`, 1 секунда, 64 МБ.

## Входные данные

Первая строка содержит `n`. В следующих `n` строках дано по одной метке
из таблицы с указанными написанием и регистром. Порядок строк задаёт
порядок обработки. Метки состоят только из букв и имеют длину не более
семи.

## Выходные данные

Одно целое число — общее количество шагов от 0 до `2n` включительно.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
4
Aurora
Tiana
Ariel
Mulan
```

```
5
```

## Решение

После очередной метки достаточно знать текущую позицию. Начальные буквы
трёх групп не пересекаются: `A, P, O, R` задают позицию 0, `B, M, S` —
позицию 1, остальные допустимые буквы (`D, G, J, K, T, W`) — позицию 2.
Такое сокращение корректно, поскольку во входе гарантированы только
метки из таблицы.

Начинаем с `position = 0` и `steps = 0`. Для каждой метки определяем
`target`, прибавляем `abs(target - position)` к `steps` и присваиваем
`position = target`. После ровно `n` меток выводим `steps`. Сортировать
или переставлять метки нельзя.

Докажем корректность одного перехода из `p` в `q`. За шаг координата
меняется на единицу, поэтому требуется не менее `|q-p|` шагов. Прямое
движение к `q` достигает этой границы. Порядок обработки фиксирует все
соседние пары пунктов, включая начальную позицию 0. Сумма точных
расстояний поэтому равна требуемому пути. По индукции после каждой метки
счётчики содержат её позицию и точное число уже пройденных шагов. После
последней метки нового перехода нет.

В примере позиции равны `0 → 0 → 2 → 0 → 1`, расстояния — `0 + 2 + 2 + 1 = 5`.
Время — `O(n)`, так как длина метки ограничена. Сканирование использует `O(1)`
счётчиков; программы сохраняют входные метки, поэтому их общая дополнительная
память — `O(n)`. Потоковый ввод позволил бы сократить её до `O(1)`.

Подводные камни:

- Начальная позиция — самая левая, ещё до первой метки.
- Между крайними пунктами два шага; внутри одного пункта — ноль.
- Сохраняйте повторы и порядок; обратный путь после последней метки не нужен.
- Используйте написание `Mickey`, `Kuzko`, `Phoebus` из таблицы. Начальная буква
  определяет пункт, а не алфавитный диапазон или номер отдельного отделения.

## Особенности языков

Все пять программ выполняют одинаковый проход с обычными целыми: ответ не больше
2000. C++ проверяет принадлежность строке, Go — наличие ASCII-буквы как руны,
Rust — байта, Java применяет `indexOf`, Python — принадлежность строке.
Буферизованного ввода достаточно; CPython не требует другого интерпретатора.
