# 2039. 由完整黑行与黑列组成的正方形

[Timus 2039](https://acm.timus.ru/problem.aspx?space=1&num=2039) · 难度 5497 · two_pointers, bitmask

原题作者 Kirill  Borozdin （由 Oleg Merkurev 整理），出自 2014 年夏季彼得罗扎沃茨克集训营乌拉尔联邦大学 Dandelion 专场。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定二进制矩阵 `n × m` 和正整数 `k`，统计连续正方形区域：恰好 `k` 行完全为黑色，恰好 `k` 列完全为黑色，且这些行列的并集以外全部为白色。所选行列不要求相邻。左上角或边长不同的正方形视为不同。

## 输入

第一行是 `n,m,k`，各自在 1 到 1000 之间。随后 `n` 行，每行恰好 `m` 个二进制字符；`0` 为白色，`1` 为黑色。`k` 可以超过矩阵任一维度。时间限制 0.5 秒，内存限制 64 MB。

## 输出

输出满足条件的正方形数量。边长小于 `k` 不可能；边长等于 `k` 时只接受全黑正方形；边长更大时必须含白格。若 `k>min(n,m)`，答案为零。允许输入中全部正方形总数至多为 333833500，使用 64 位累加器方便，但此上界也能放入有符号 32 位整数。

## 评测方式

按记号逐个比较输出。

## 样例

```
5 6 2
010100
111111
010100
111111
010100
```

```
7
```

用从一开始的 `(行,列,边长)` 表示，七个正方形为 `(2,2,3)`、`(1,1,4)`、`(1,2,4)`、`(2,1,4)`、`(2,2,4)`、`(1,1,5)`、`(1,2,5)`。边长三的区域中，中间行列除了与另一个方向的两条全黑线交叉处以外均白。边长四和五的这些窗口仍各有两条完整黑行与黑列，没有全黑的边长二窗口。因此答案为 `1+4+2=7`。

## 解法

### 可遗传的正方形性质

先不限定黑线数量，称白格集合恰为笛卡尔积 `R×C` 的正方形形状正确，其中 `R` 为含白格的行，`C` 为含白格的列。全黑时两集合为空。等价地，每个非空白行拥有相同的白列模式。这恰好描述若干完整黑行列的并集。

非空白积的边长为 `s` 时，完整黑行列数分别为 `s-|R|`、`s-|C|`。性质 `P` 要求形状正确且两数都不超过 `k`。任意子正方形继承 `P`：仍含白格时，黑线只是原选线的子集；若变成全黑，其全部行或全部列必须来自原选黑线，否则一条白行与一条白列会在其中相交。于是其边长不超过 `k`，也满足数量上界。

### 每条对角线的单个移动窗口

C++、Go、Rust、Java 沿左上到右下的对角线访问右下角。起点指针表示满足 `P` 的最大后缀正方形，只向前移动。由于遗传性，无效区域不能通过扩大修复；从旧有效窗口删除顶行和左列、重试扩展，会得到新的最大窗口。总扩展与删除次数为 `O(nm)`。

窗口无需存储完整 `R,C`。保存最靠下的白行 `pr`、最靠右的白列 `pc`、两项黑线计数；全黑窗口无这两个支点。在旧列范围添加底行时，新白模式须为空或与旧支点行的限制相同；原来全黑时任意新模式都可开始一个白积。随后在包括新行的全部行范围添加右列，执行对应的支点列比较。用最后白位置更新支点。若白积原已非空，新行列在对向支点处的格值判定其是否为全黑；若从全黑首次产生白模式，则唯一新白行或白列及该线上的黑格数直接确定两项计数。只在计数都不超过 `k` 时提交扩展。

失败时仅缩小旧窗口，不保留部分扩展。如果移除的顶行等于 `pr` 或左列等于 `pc`，白积的一因子完全消失，剩下的旧窗口全黑。否则支点保持，两项计数只在被移除的线于对向支点处为黑时减少。这样形状、极端白位置和计数持续正确。

设当前右下角在对角线上的偏移为 `t`，最大窗口起点为 `a`。所有以该点结尾的答案都包含在这个窗口内。边长 `k` 的后缀若放得下，且至少一个白支点位于其边界之前，就没有白积交点，贡献一次。

对于大于 `k` 的边长，缩小不能增加选中的黑线，因此只有当前两项计数都等于 `k` 且白积非空时才有贡献。设 `fr,fc` 是最早的选中黑行列在对角线上的偏移。起点必须满足 `a≤x≤min(t-k,fr,fc,pr,pc)`，支点也转换为偏移。保留第一条选中行即保留全部选中行；保留最后白行即至少留下一个白行，列同理。此区间条件必要且充分，累加其中整数个数即可。每个正方形只有一个右下角，不会重复。

两个线数都必须恰好等于 `k`；即使线数正确，额外黑格也使区域无效。全黑边长 `k` 和更大的混色区域需分开。新增列应包括新增行；失败的半次扩展不能提交。白积任一因子消失时两个支点均清除。

### Python：先缩小棋盘，再选择算法

Python 首先排除尺寸小于 `k` 的情况。全黑棋盘只需统计边长为 `k` 的正方形，全白棋盘的答案为零。其他棋盘先裁到所有黑格的最小包围矩形。由于 `k` 为正，每个答案的每行、每列都含黑格，因此裁剪不会丢失答案。

若每行不是全黑，就是同一个固定图案，那么较大的答案可独立拆成两个窗口：行窗口恰含 `k` 个全黑行，列窗口在固定图案中恰含 `k` 个一。对每个边长，将两种窗口的数量相乘即可。一组连续 `k` 个一确定了所有包含其首尾、但不包含前后相邻一的窗口；窗口数量随长度的变化呈梯形，可用二阶差分统一累加。边长 `k` 单独按全黑行或全黑列的连续段计数，并减去两者的交集一次。

当行图案种类较少且没有全黑行时，程序还尝试按黑格划分连通分量：将行、列作为二分图顶点，黑格作为边。仅当每个分量占据连续的行和连续的列时，才递归处理这些矩形。一个有效正方形中的黑色条纹会连接其全部行、列顶点，所以它只能属于其中一个矩形，各矩形的答案可以直接相加。

另一条分支处理嵌套棋盘：必要时上下或左右翻转后，每行都是黑色前缀接白色后缀，且前缀长度不减。边长 `k` 的全黑正方形由每个行窗口内的最短前缀直接计数。更大的答案先包含若干最短且等长的行，随后恰有 `k` 个更长的行。恰含 `k` 个全黑列的要求固定了左边界。最短行的数量决定边长，其上限来自该等长组的大小、到下一个前缀长度的差，以及剩余宽度。每个可行数量对应一个正方形，无需逐个枚举边长。

剩余棋盘还可能转置：程序根据图案变化次数估算工作量，选择更有利的方向。转置保留正方形及两个方向的条纹数。求出安全的边长上界后，较短的范围用并行计数；`k > 1` 且范围较长时用离线分解；`k = 1` 则有专门的计数方法。

### Python：并行计数与安全上界

固定边长 `s`，正方形有效当且仅当它有 `k` 个全黑行、`k` 个全黑列，且每行黑格数为 `k` 或 `s`。因为每个非全黑行在这 `k` 个全黑列中已含全部 `k` 个黑格，所以不可能再有多余黑格。

整张棋盘存入一个大整数，每格占一位。移位与按位 AND 找出全黑的水平、竖直线段；通过倍增线段长度，无需逐格扫描。计数器的各个二进制位分别存入不同整数，以同时统计所有窗口中的标记。XOR 得到和的当前位，AND 得到进位；合并移位后的块，就能在每个位置独立执行精确的二进制加法。按 `k` 的各位对位平面取交，即可判断计数是否相等。全黑行数、全黑列数与上述逐行条件共同给出精确的答案掩码；边界掩码排除越界起点，最后统计置位数。

计数前，先用必要的局部条件限制边长。白格构成笛卡尔积时，相邻 `2×2` 块不能恰有三个白格，也不能只有两个对角白格。大于 `k` 的答案不能包含边长 `k+1` 的全黑正方形。`k` 较小时，还排除边长 `2k+1`、全黑行或列过多的块。二次幂边长的正方形表通过四个重叠角块检查这些禁用块是否存在。由于 `k` 为正，还要排除全白候选。剩余混色候选的存在性对边长单调：较小的角部正方形可以保留一对相邻异色格，并继承禁用块不存在的条件。因此二分查找给出安全上界，但不直接判定答案。

按边长区间处理时，裁剪保留所有可能达到区间最小边长的全黑行段、列段，并为区间最大边长留足边距。每个答案都含这样的线段，因此裁剪范围之外不可能有贡献。掩码为空或尺寸不足时可安全结束扫描，最终仍由精确计数器检查所有剩余候选。

### Python：`k > 1` 时的离线分解

边长范围较长时，程序避免对每个边长重复计数。边长 `k` 只统计全黑正方形；边长 `k+1` 必须恰有一个白格，其他行、列正好就是 `k` 条黑色条纹。这两种情况都用并行掩码处理，在合并互不相交的块时记录没有白格或至多一个白格的状态。

更大的边长先检查其中每个边长 `k+2` 的块的形状。`k` 较小时，任意两行只要都不是全黑，其白格图案就必须相同，同时禁止边长 `k+1` 的全黑块。否则，要求白格所占列的并集大小等于每个含白格行中的白格数，从而迫使这些集合一致；还要求至少两行、两列含白格。每个有效答案都会通过相应检查。相邻的合格块在重叠部分共享白格，因此各自的笛卡尔积一致，可扩展成覆盖整个正方形的白格积。正方形动态规划为每个起点求出满足这些证书的最大边长，利用打包的最小值运算和到下一个失败证书的距离计算一整行状态。

在有效正方形的前 `k+1` 行中，至少一行不是黑色条纹，所以这些行的按位交集恰好给出全黑列。类似地，前 `k+1` 列的交集给出全黑行。对每个起点，第 `k` 条选中线的位置确定边长下界，下一条选中线的位置确定边长上界，两端均包含在内；窗口必须包含第 `k` 条线，并排除下一条线。将行、列区间与形状上界及最小边长 `k+2` 相交，累加所得整数区间的长度。每个计入的边长都具有已验证的形状和准确的条纹数，每个答案也只在唯一的起点计入一次。

后继位置由连续段或打包的秩求得，重复图案复用精确的端点数组；变化较小时只更新受影响的秩。端点与边界放在大整数中相互独立、带保护位的字段内，可同时计算许多列的最小值、最大值和区间长度。字段宽度足以容纳所有允许的坐标，掩码保证跨字段进位或借位不会改变结果。所有操作都精确，不使用概率比较。若证书只留下很短的边长范围，程序改用并行计数。

### Python：一条条纹与唯一交点

当 `k = 1` 时，每个黑格贡献一个边长为一的答案。其余较小边长分段处理。在每段的最小边长上，掩码找出恰有一个全黑行和一个全黑列的正方形，边长大于二时还检查局部形状证书。这些条件已经充分：形状证书保证每个非全黑行只有全黑列上的那一个黑格。每个较大的一条条纹正方形都包含一个交点相同的较小正方形，因此这些掩码能定位本段中所有可能有贡献的区域。将候选所在的行分组并向外扩展所需边距，不同组的裁剪范围互不相交；每个范围内再用固定图案公式或并行计数，只统计本段边长。

较大边长则通过一个固定的较小边长寻找候选交点。每个通过检查的正方形都有唯一的全黑行列交点，在另一列中查看黑格即可确定全黑行。用集合去除从多个小正方形中找到的重复交点。每个较大答案都含一个交点相同的这种小正方形，所以不会漏掉所需交点。

对每个交点，穿过它的横向、纵向连续黑段限制了所有可能答案的范围。在这个范围内，将交点所在行和列擦成白色。一个包含交点的正方形有效，当且仅当剩余格子全白。打包的动态规划求出每个左上角的最大全白正方形。包含交点所需的距离给出边长下界，空白正方形的大小及待统计范围给出上界。累加整数区间长度，即得该交点的全部答案。擦除两条线是正确的，因为黑段边界已保证它们原本全黑；交点唯一，则正方形不会重复计数。

## 各语言说明

记 `L=min(n,m)`。移动窗口只有 `O(nm)` 次更新，但字节串搜索比较可读 `O(L)` 字符，故 C++/Go/Rust 保守时间 `O(nmL)`、空间 `O(nm)`。Java 用精确 64 位块、边界掩码、位计数和最后白位置前缀表，时间 `O(nmB₆₄)`、空间 `O(nm)`，其中 `B₆₄=ceil(max(n,m)/64)`；位移 64 单独处理。

Python 中，记 `D=max(n,m)`，`B` 为保存一行 `D` 个带保护位坐标字段所需的机器字数。按题目的坐标上限，这样的整数占 `O(D)` 位。将此类整数的乘除法保守计为 `O(B²)`，并采用标准的字典均摊开销，覆盖全部分支的时间上界为 `O(nm(nm+DB²))`，空间上界为 `O(nm+DB log(L+1))`。

这个有意放宽的时间估计允许至多 `nm` 个不同交点，每个交点最多扫描 `nm` 个格子和 `D` 行打包数据，每行花费 `O(B²)`。它也覆盖离线预处理、所有边长扫描，以及整张棋盘大小整数的二次算术开销。交点逐个处理，保存的掩码、端点数组、缓存和二次幂表均在上述空间范围内。棋盘化简与打包运算使许多输入的实际工作量远小于此上界。

该解答运行于 CPython，已在 Timus 的 Python 3.12 x64 下获得 Accepted，用时 0.359 秒，内存 21 964 KB，时间限制为 0.5 秒。早期版本曾在评测的第 4、26、24 个测试上超时；第 24 个测试变慢的原因是通过在大量生成的棋盘上比较两个版本的运行时间找到的。
