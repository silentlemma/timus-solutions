# 2053. Построить планарный граф с более чем тремястами тысячами циклов

[Timus 2053](https://acm.timus.ru/problem.aspx?space=1&num=2053) · difficulty 3448 · constructive

Автор оригинальной задачи — Александр Ипатов; XIX Открытый чемпионат Урала по спортивному программированию (апрель, 2015).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нарисуйте плоский граф с шестнадцатью вершинами в различных целых точках
и прямыми рёбрами, которые встречаются только в общих концах и не
проходят через другие вершины, так чтобы в нём было больше 300 000
простых циклов. Цикл считается один раз независимо от начальной вершины
и направления. Ограничения: 1 секунда и 64 МБ.

## Входные данные

Входных данных нет.

## Выходные данные

Шестнадцать строк с координатами вершин, каждая из [−1000, 1000], и
затем матрица смежности 16 × 16 из строк нулей и единиц, симметричная, с
нулевой диагональю.

## Проверка

Проверяющая программа сверяет точки, матрицу и геометрию рёбер и точно
считает простые циклы; принимается любой подходящий граф. Пример
исходной задачи лишь показывает формат и не является верным ответом,
поэтому его сохранённый вывод помечен `format_only` и не проверяется.

## Решение

### Алгоритмическое построение графа

Нумеруем вершины с нуля как `v=4r+c` на условной сетке четыре на четыре.
Добавляем горизонтальных и вертикальных соседей — 24 ребра, затем в
каждой клетке диагональ из левого верхнего угла в правый нижний — ещё
девять. Это схема имён вершин, не окончательные координаты.

Стороны границы задаются списками `(0,1,2,3)`, `(3,7,11,15)`,
`(15,14,13,12)` и `(12,8,4,0)`. Для каждой стороны `(a,b,c,d)` добавляем
`a-d` и `a-c`, затем отдельно `3-12`. Все рёбра различны, всего их 42.
Внешний треугольник образуют вершины ноль, три и двенадцать. Программы
генерируют рёбра циклами, а не хранят готовую матрицу ответа.

### Вычисление целых координат

Фиксируем вершину ноль в `(-900,-900)`, три в `(900,-900)`, двенадцать в
`(0,900)`. Каждая из остальных вершин должна совпадать со средним
арифметическим своих соседей. Для каждой координаты тринадцать
неизвестных удовлетворяют `degree(v)·p_v - sum_{внутренние соседи u} p_u
= sum_{фиксированные соседи u} p_u`. Строим расширенную матрицу с
тринадцатью строками и двумя правыми частями, решаем исключением Гаусса
с выбором ведущей строки. Координаты округляем по правилу
`floor(value+0.5)`.

Система невырождена. Продолжим вектор внутренних вершин нулями на
границу. Квадратичная форма матрицы — сумма `(x_u-x_v)²` по внутренним
рёбрам и `x_v²` по рёбрам к границе. Нулевая сумма заставляет значения
быть равными вдоль всех рёбер и нулевыми на границе; связность даёт
нулевой вектор. Значит, матрица положительно определена. Принцип
максимума ограничивает точные координаты крайними граничными значениями:
строгое внутреннее превышение не может быть средним, а плато максимума
распространяется до границы.

Округление произвольного усреднённого рисунка само по себе не сохраняет
планарность. Здесь граф фиксирован, поэтому фактические целые координаты
проверяются точно. Рациональное исключение даёт шестнадцать точек из
исполняемого сертификата ниже. Каждая точная координата удалена от
полуцелой границы округления хотя бы на `513/46262`; двойной точности
достаточно с запасом для этой малой системы. Все пять программ выдают
этот целый сертификат. Точные тесты ориентации и принадлежности отрезку
подтверждают различие точек, границы, отсутствие вершин внутри чужих
рёбер и запрещённых пересечений. Никакие три точки сертификата также не
коллинеарны.

### Доказательство числа циклов

Пусть `DP[M][v]` — число путей, посетивших ровно множество `M`,
заканчивающихся в `v` и начинающихся в наименьшей вершине `M`.
Инициализация — `DP[{v}][v]=1`. Продлеваем путь в непосещённого соседа,
большего начальной вершины, сохраняя минимальный старт. Каждый простой
по вершинам путь учитывается ровно один раз: удаление последнего ребра и
индукция по длине дают единственный предыдущий переход.

При трёх и более вершинах путь замыкается в простой цикл ровно тогда,
когда конец смежен началу. Складываем такие состояния. Каждый
неориентированный цикл учтён дважды — по направлениям; минимальная
начальная вершина уже устранила циклические сдвиги. Делим на два.
Проверенное прямолинейное вложение не имеет запрещённых пересечений и
касаний вершин, поэтому графовые циклы в точности соответствуют
допустимым многоугольникам.

Для длин от трёх до шестнадцати получаются
`28,46,116,365,1140,3174,7922,17578,33714,53732,67908,63842,39852,12426`.
Точная сумма — `301843>300000`. Полная конечная проверка ниже строит
граф, проверяет геометрию и считает циклы всех длин. Это проверяющий
сертификат, а не отправляемая программа: программа вычисляет координаты
из линейной системы.

```python
from array import array

GRID = 4
COORDINATE_BOUND = 1000
MIN_CYCLE_LENGTH = 3
points = [(-900, -900), (-275, -647), (12, -731), (900, -900),
          (-258, -48), (-239, -415), (27, -541), (310, -669),
          (-77, 241), (-74, -67), (49, -285), (301, -502),
          (0, 900), (25, 178), (56, -72), (222, -114)]
adjacency = [0] * (GRID * GRID)

def link(a, b):
    adjacency[a] |= 1 << b
    adjacency[b] |= 1 << a

for r in range(GRID):
    for c in range(GRID):
        v = GRID * r + c
        if c + 1 < GRID:
            link(v, v + 1)
        if r + 1 < GRID:
            link(v, v + GRID)
        if r + 1 < GRID and c + 1 < GRID:
            link(v, v + GRID + 1)
corners = [0, GRID - 1, GRID * GRID - 1, GRID * GRID - GRID]
for side, a in enumerate(corners):
    d = corners[(side + 1) % GRID]
    step = (d - a) // (GRID - 1)
    link(a, d)
    link(a, d - step)
link(corners[1], corners[-1])

def orientation(a, b, c):
    return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])

def on_segment(a, b, p):
    return orientation(a, b, p) == 0 and min(a[0], b[0]) <= p[0] <= max(a[0], b[0]) and (min(a[1], b[1]) <= p[1] <= max(a[1], b[1]))

def geometric(points, adjacency):
    size = len(points)
    if len(set(points)) != size or any((abs(x) > COORDINATE_BOUND for p in points for x in p)):
        return False
    edges = [(a, b) for a in range(size) for b in range(a + 1, size) if adjacency[a] & 1 << b]
    for a, b in edges:
        if any((v not in (a, b) and on_segment(points[a], points[b], p) for v, p in enumerate(points))):
            return False
    for index, (a, b) in enumerate(edges):
        for c, d in edges[index + 1:]:
            if len({a, b, c, d}) < 4:
                continue
            pa, pb, pc, pd = (points[a], points[b], points[c], points[d])
            x, y = (orientation(pa, pb, pc), orientation(pa, pb, pd))
            z, w = (orientation(pc, pd, pa), orientation(pc, pd, pb))
            if x * y < 0 and z * w < 0:
                return False
            if on_segment(pa, pb, pc) or on_segment(pa, pb, pd):
                return False
            if on_segment(pc, pd, pa) or on_segment(pc, pd, pb):
                return False
    return True

def cycle_histogram(adjacency):
    size = len(adjacency)
    full = (1 << size) - 1
    paths = array('Q', [0]) * ((1 << size) * size)
    for vertex in range(size):
        paths[(1 << vertex) * size + vertex] = 1
    totals = [0] * (size + 1)
    for mask in range(1, 1 << size):
        anchor = mask & -mask
        allowed = full ^ (anchor << 1) - 1
        length = mask.bit_count()
        endpoints = mask
        while endpoints:
            bit = endpoints & -endpoints
            endpoints ^= bit
            last = bit.bit_length() - 1
            value = paths[mask * size + last]
            if not value:
                continue
            if length >= MIN_CYCLE_LENGTH and adjacency[last] & anchor:
                totals[length] += value
            choices = adjacency[last] & ~mask & allowed
            while choices:
                new_bit = choices & -choices
                choices ^= new_bit
                end = new_bit.bit_length() - 1
                paths[(mask | new_bit) * size + end] += value
    return [value // 2 for value in totals]

assert geometric(points, adjacency)
histogram = cycle_histogram(adjacency)
assert histogram[3:] == [28, 46, 116, 365, 1140, 3174, 7922,
                        17578, 33714, 53732, 67908, 63842, 39852, 12426]
assert sum(histogram) == 301843 > 300000
```

Все утверждения выполняются. Независимый буквальный DFS по простым путям
также перечисляет ту же гистограмму; результат не выведен из случайных
тестов или одного подсчёта граней.

Шестивершинную иллюстрацию отправлять нельзя. Недостаточно считать
только треугольники, грани или гамильтоновы циклы. Неравенство строгое.
Симметричная матрица ещё не гарантирует допустимое прямолинейное
вложение: нужны проверки вершин на рёбрах, чужих пересечений и
коллинеарного перекрытия. Сетка служит только нумерацией; старые
сеточные координаты с последним добавленным ребром дали бы пересечение.
Сохраните три фиксированные граничные вершины и одинаковое правило
`floor(x+0.5)` также для отрицательных координат. Цикл учитывается один
раз с точностью до сдвига и обращения.

## Особенности языков

Отправляемые программы строят граф и решают систему размера `V-3`: время
`O(V^3)`, память `O(V^2)` при фиксированном `V=16`. Циклы во время
работы решения не считаются. Отдельный проверяющий код требует
`O(V^2·2^V)` времени и `O(V·2^V)` памяти; при шестнадцати вершинах
таблица путей занимает восемь МиБ.

Все версии используют исключение в двойной точности и целочисленный
вывод. Java и Rust используют
примитивные числовые массивы, C++ и Go — фиксированные массивы графа.
Парсера входа и таблицы готовых координат нет.
