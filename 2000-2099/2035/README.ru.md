# 2035. Разложение суммы с двумя верхними границами

[Timus 2035](https://acm.timus.ru/problem.aspx?space=1&num=2035) · сложность 78 · math

Автор оригинальной задачи — Кирилл Бороздин; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

По целым `X,Y,C`, где `0 ≤ X,Y,C ≤ 1000000000`, найти любые целые
`A,B` с условиями `0 ≤ A ≤ X`, `0 ≤ B ≤ Y` и `A+B=C`.
Лимиты: 0,5 секунды, 64 МБ.

## Входные данные

Одна строка `X Y C`. Перед единственным набором нет количества тестов.

## Выходные данные

Любая подходящая пара `A B` либо слово `Impossible`, если пары нет.
При `C=0` пара `0 0` допустима.

## Проверка

Проверяющая программа сверяет обе границы и сумму; `Impossible`
принимается, только если пары нет. Принимается любая подходящая пара.

## Примеры

```
2 7 5
```

```
2 3
```

```
9 15 100
```

```
Impossible
```

## Решение

Берём A как можно больше, A = min(X, C), и B = C − A. Если B ≤ Y, пара
подходит; иначе не подходит никакая, потому что любое другое A меньше и
только увеличивает B. `O(1)`.

Подводные камни:

- A = X без ограничения числом C может сделать B отрицательным;
- нулевые слагаемые допустимы, принимается любая подходящая пара.

## Оптимизированные решения

`2035_math_optimized.py`. Сохраняется конструкция ограниченных слагаемых A=min(X,C), B=C-A. Оба значения неотрицательны, A<=X; при B>Y допустимой пары нет, иначе она выводится. C=0 даёт 0 0. Нужны лишь три входных значения и несколько ограниченных целых, O(1) времени и состояния. Убраны обёртки solve/main, разбираются сырые байтовые токены; алгоритм допустимости прежний. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `2035_math.py`: время 0.078 s → 0.14 s; память 436 KB → 200 KB.

`2035_math_optimized.rs`. Сохраняется конструкция ограниченных слагаемых A=min(X,C), B=C-A. Оба значения неотрицательны, A<=X; при B>Y допустимой пары нет, иначе она выводится. C=0 даёт 0 0. Нужны лишь три входных значения и несколько ограниченных целых, O(1) времени и состояния. Три значения i64 читаются напрямую и выводятся числами без входной String и форматирования. Неотрицательная область условия обеспечивает безопасность вычитаний. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `2035_math.rs`: время 0.031 s → 0.046 s; память 228 KB → 68 KB.

Оптимизированное решение на C++ разбирает три числа вручную через
`getchar` вместо `iostream`: 100 КБ вместо 400 КБ при том же времени.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2035_math_optimized.py`: место по времени 47/54, по памяти 1/54 в этой сопоставимой выборке.

`2035_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
