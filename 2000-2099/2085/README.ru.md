# 2085. Путь в дереве, использующий каждую технологию один раз

[Timus 2085](https://acm.timus.ru/problem.aspx?space=1&num=2085) · сложность 1643 · hashing, trees

Автор оригинальной задачи — Александр Фетисов.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n проектов образуют дерево, и каждый проект использует набор из m
технологий. Найдите простой путь (возможно, из одного проекта), на
котором каждая технология встречается ровно в одном проекте, и выведите
его концы, или «No solution». Подходит любой правильный путь.
Ограничения: 5 секунд и 256 МБ.

## Входные данные

n и m, 1 ≤ n, m ≤ 10⁵, n − 1 рёбер, затем для каждого проекта число его
технологий и их номера; всего в наборах не больше 10⁶ элементов.

## Выходные данные

Два конца пути или `No solution`.

## Проверка

Проверяющая программа принимает «No solution», только если так в
ожидаемом выводе, а иначе проходит по выведенному пути и считает
технологии.

## Примеры

### Пример 1

Ввод:

```
5 3
1 2
1 3
3 4
3 5
1 1
1 3
0
2 1 3
1 2
```

Вывод:

```
2 5
```

### Пример 2

Ввод:

```
3 3
1 2
1 3
2 2 3
3 1 2 3
1 3
```

Вывод:

```
2 2
```

### Пример 3

Ввод:

```
2 3
1 2
2 1 2
2 1 3
```

Вывод:

```
No solution
```

## Решение

Дадим каждой технологии случайный 64-битный вес, а каждому проекту —
сумму весов его технологий. На пути, где каждая технология использована
один раз, значения проектов в сумме дают сумму G всех весов; если
какая-то технология использована дважды или пропущена, сумма — другая
линейная комбинация независимых случайных чисел и равна G лишь с
вероятностью около 2⁻⁶⁴. Задача сводится к поиску пути с суммой значений
G по модулю 2⁶⁴.

Подвесим дерево и обозначим depth(v) сумму значений от корня до v. Путь
u … v через самую высокую вершину x имеет сумму
depth(u) + depth(v) − 2 depth(x) + value(x). Для каждой x вершины её
поддерева хранятся в хеш-таблице «глубина → вершина», которая строится
слиянием меньшего в большее: x начинает с таблицы {depth(x)}, и таблица
каждого потомка вливается в неё, меньшая в большую. Перед слиянием
каждая глубина d меньшей таблицы ищет в большей
G + 2 depth(x) − value(x) − d; попадание — путь через x, ведь две
стороны лежат в разных потомках x (или один конец — сама x). Один проект
со значением G — путь сам по себе. Каждая вершина переезжает O(log n)
раз, так что работа в среднем O(n log n + Σ aᵢ).

Дерево обходится в порядке обхода в ширину, а на обратном пути потомки
идут раньше родителей, так что глубоким деревьям не нужна рекурсия. В
первом примере путь 5, 3, 4 использует технологию 2, затем ни одной,
затем 1 и 3; ответ из образца 2 … 5 ничем не хуже.
