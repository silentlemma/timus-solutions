# 2002. Тестовое задание

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Смоделировать изначально пустую базу пользователей. Запрос регистрирует
имя с паролем, выполняет вход по паролю либо выход по имени. Для каждого
запроса требуется строго заданный ответ с указанным приоритетом ошибок.
Новая запись создаётся без активного входа. Неудачные запросы не меняют
существующие пароли и сеансы.

## Входные данные

Число `1≤n≤100`, далее `n` запросов: `register name password`, `login
name password`, `logout name`. Имена и пароли непустые, длиной до 30,
состоят из ASCII 33–126 и сравниваются с учётом регистра. Пробельных
символов внутри нет; знаки пунктуации и слова команд допустимы. Лимиты:
0,5 секунды и 64 МБ.

## Выходные данные

Одна строка ответа на запрос. Английские сообщения, двоеточия и пробелы
сохраняются точно. Строки таблицы для каждой команды проверяются сверху
вниз.

| Условие | Сообщение | Изменение |
| --- | --- | --- |
| register: имя существует | `fail: user already exists` | нет |
| register: иначе | `success: new user added` | записать пароль, без входа |
| login: имя отсутствует | `fail: no such user` | нет |
| login: неверный пароль | `fail: incorrect password` | нет |
| login: уже вошёл | `fail: already logged in` | нет |
| login: иначе | `success: user logged in` | вход |
| logout: имя отсутствует | `fail: no such user` | нет |
| logout: уже вышел | `fail: already logged out` | нет |
| logout: иначе | `success: user logged out` | выход |

## Проверка

В репозитории ответ сравнивается посимвольно после удаления всех пробельных
символов в конце всего вывода. Завершающие пробелы и пустые строки
игнорируются; в остальных местах пробельные символы должны совпадать.

## Примеры

```
6
register vasya 12345
login vasya 1234
login vasya 12345
login anakin C-3PO
logout vasya
logout vasya
```

```
success: new user added
fail: incorrect password
success: user logged in
fail: no such user
success: user logged out
fail: already logged out
```

Регистрация сохраняет `12345`, оставляя запись без входа. Неправильный
пароль ничего не меняет. Правильный вход проходит, неизвестное имя даёт
ошибку, первый выход успешен, второй отвергается как повторный.

## Решение

Храним хеш-таблицу от имени к паролю и признаку «в сети». Для каждого
запроса ищем имя и проверяем условия таблицы сверху вниз; первое
выполненное условие даёт ответ и единственное изменение. `O(n·L)` для
имён длины L ≤ 30.

Подводные камни:

- при входе неверный пароль сообщается раньше, чем «уже в сети»;
- регистрация не выполняет вход;
- неудачные запросы ничего не меняют, а поиск никогда не создаёт
  учётную запись;
- имена и пароли сравниваются точно, с учётом регистра.

## Оптимизированные решения

`2002_implementation_optimized.py`. Python сохраняет словарь аккаунтов и приоритет ошибок: пароль при входе проверяется раньше состояния «уже вошёл». Не более 100 запросов один раз разбиваются на байтовые токены; все аргументы команды потребляются даже при отказе. Хранятся байтовые имена и пароли, флаги входа и список ответов, который склеивается и записывается один раз. В отличие от потоковых Java/Rust здесь намеренно хранится ввод и вывод: ожидаемая работа O(I+O), память O(I+O+A) для данных аккаунтов A. Выход внутри main пропускает очистку локальных данных. Фиксированные ответы задаются условием, а не таблицей решений. Учебные версии сохранены.

Accepted точного исходника Python 3.12 x64 №11327495: 0.078 с / 848 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 5/69, память 66/69. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11324845 (PyPy 3.10 x64): 0.109 с / 252 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `2002_implementation_optimized.py`: 0.078 s / 848 KB; сохранённая учебная база `2002_implementation.py`: 0.093 s / 576 KB.

`2002_implementation_optimized.rs`. Сохраняются HashMap аккаунтов и автомат входа, включая приоритет ошибок. Каждая команда сразу читается и выполняется; байтовые имена/пароли хранятся только для зарегистрированных аккаунтов, фиксированный ответ выводится напрямую. История команд и строки ответов не сохраняются. При стандартном случайном хешировании ожидаемое время O(I+O) для байт ввода/вывода, память O(A+T) для данных аккаунтов A и максимальной текущей команды T.

По сравнению с `2002_implementation.rs`: время 0.046 s → 0.015 s; память 460 KB → 280 KB.

`2002_implementation_optimized.java`. Сохраняются карта аккаунтов и приоритет ошибок, включая проверку пароля до проверки уже активного входа. Запрос обрабатывается и ответ выводится сразу, без хранения всех команд, ответов и объединённой строки. Java хранит один Account на зарегистрированное имя и фиксированные буферы. Память O(U) записей аккаунтов и текущий запрос ограниченной длины, U<=n. При длине имени и пароля до 30 символов ожидаемое время хеш-таблицы O(n), без гарантии худшего случая. Ошибки не меняют состояние; регистрация создаёт неактивный аккаунт.

По сравнению с `2002_implementation.java`: время 0.140 s → 0.109 s; память 664 KB → 640 KB.

Оптимизированное решение на C++ читает слова через `scanf` в буферы на
31 байт вместо `iostream` и отвечает на каждый запрос сразу, а не
сохраняет сначала все запросы и ответы: 212 КБ вместо 516 КБ при том же
времени.

Оптимизированное решение на Go разбирает запросы вручную из ввода с
буфером на 1 КБ вместо `fmt.Fscan` и сразу отвечает на каждый через
буферизованный вывод, без списка команд: 0.015 с вместо 0.046 с и 936 КБ
вместо 1124 КБ.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2002_implementation_optimized.java`: место по времени 26/249, по памяти 29/249 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
