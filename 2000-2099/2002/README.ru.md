## Задача

Смоделировать изначально пустую базу пользователей. Запрос регистрирует
имя с паролем, выполняет вход по паролю либо выход по имени. Для каждого
запроса требуется строго заданный ответ с указанным приоритетом ошибок.
Новая запись создаётся без активного входа. Неудачные запросы не меняют
существующие пароли и сеансы.

## Входные данные

Число `1≤n≤100`, далее `n` запросов: `register name password`, `login
name password`, `logout name`. Имена и пароли непустые, длиной до 30,
состоят из ASCII 33–126 и сравниваются с учётом регистра. Пробельных
символов внутри нет; знаки пунктуации и слова команд допустимы. Лимиты:
0,5 секунды и 64 МБ.

## Выходные данные

Одна строка ответа на запрос. Английские сообщения, двоеточия и пробелы
сохраняются точно. Строки таблицы для каждой команды проверяются сверху
вниз.

| Условие | Сообщение | Изменение |
| --- | --- | --- |
| register: имя существует | `fail: user already exists` | нет |
| register: иначе | `success: new user added` | записать пароль, без входа |
| login: имя отсутствует | `fail: no such user` | нет |
| login: неверный пароль | `fail: incorrect password` | нет |
| login: уже вошёл | `fail: already logged in` | нет |
| login: иначе | `success: user logged in` | вход |
| logout: имя отсутствует | `fail: no such user` | нет |
| logout: уже вышел | `fail: already logged out` | нет |
| logout: иначе | `success: user logged out` | выход |

## Проверка

Ответ сравнивается точно, посимвольно; отличаться может только последний
перевод строки.

## Примеры

```
6
register vasya 12345
login vasya 1234
login vasya 12345
login anakin C-3PO
logout vasya
logout vasya
```

```
success: new user added
fail: incorrect password
success: user logged in
fail: no such user
success: user logged out
fail: already logged out
```

Регистрация сохраняет `12345`, оставляя запись без входа. Неправильный
пароль ничего не меняет. Правильный вход проходит, неизвестное имя даёт
ошибку, первый выход успешен, второй отвергается как повторный.

## Решение

Храним хеш-таблицу: имя отображается в пароль и булев признак входа. Для
очередного запроса ищем запись без её создания. Выбираем первую
подходящую строку таблицы, добавляем ответ и выполняем только указанное
успешное изменение.

При входе сначала проверяется существование имени, затем пароль и лишь
затем активность сеанса. Поэтому неверный пароль даёт свою ошибку даже у
уже вошедшего пользователя. Повторная регистрация не перезаписывает
пароль и не сбрасывает вход. Выход меняет только активность. Неудачный
поиск не создаёт запись.

Индукция: до запросов база пуста и корректна. Если после префикса
запросов она точно описывает все записи, очередной поиск находит нужную
запись либо её отсутствие. Упорядоченные условия выбирают требуемый
ответ, а разрешённое изменение сохраняет точное состояние.
Следовательно, верны все ответы и последующие состояния.

При длине токена `L≤30` ожидаемое время хеш-таблицы `O(n L)`, память
`O(n L)` вместе со входом и ответами. Консервативная оценка при
коллизиях `O(n² L)` также невелика для 100 запросов. Во всех пяти языках
порядок переходов одинаков.

Не проверять активность раньше пароля. Регистрация не означает вход.
Ошибки входа, выхода и повторной регистрации не меняют базу. Полные
строки сравниваются с учётом регистра; кавычки, обратная косая черта и
имена-команды — обычные символы. Выводить только канонический ответ, без
имени и пароля.
