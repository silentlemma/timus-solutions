## Задача

Смоделировать изначально пустую базу пользователей. Запрос регистрирует
имя с паролем, выполняет вход по паролю либо выход по имени. Для каждого
запроса требуется строго заданный ответ с указанным приоритетом ошибок.
Новая запись создаётся без активного входа. Неудачные запросы не меняют
существующие пароли и сеансы.

## Входные данные

Число `1≤n≤100`, далее `n` запросов: `register name password`, `login
name password`, `logout name`. Имена и пароли непустые, длиной до 30,
состоят из ASCII 33–126 и сравниваются с учётом регистра. Пробельных
символов внутри нет; знаки пунктуации и слова команд допустимы. Лимиты:
0,5 секунды и 64 МБ.

## Выходные данные

Одна строка ответа на запрос. Английские сообщения, двоеточия и пробелы
сохраняются точно. Строки таблицы для каждой команды проверяются сверху
вниз.

| Условие | Сообщение | Изменение |
| --- | --- | --- |
| register: имя существует | `fail: user already exists` | нет |
| register: иначе | `success: new user added` | записать пароль, без входа |
| login: имя отсутствует | `fail: no such user` | нет |
| login: неверный пароль | `fail: incorrect password` | нет |
| login: уже вошёл | `fail: already logged in` | нет |
| login: иначе | `success: user logged in` | вход |
| logout: имя отсутствует | `fail: no such user` | нет |
| logout: уже вышел | `fail: already logged out` | нет |
| logout: иначе | `success: user logged out` | выход |

## Проверка

В репозитории ответ сравнивается посимвольно после удаления всех пробельных
символов в конце всего вывода. Завершающие пробелы и пустые строки
игнорируются; в остальных местах пробельные символы должны совпадать.

## Примеры

```
6
register vasya 12345
login vasya 1234
login vasya 12345
login anakin C-3PO
logout vasya
logout vasya
```

```
success: new user added
fail: incorrect password
success: user logged in
fail: no such user
success: user logged out
fail: already logged out
```

Регистрация сохраняет `12345`, оставляя запись без входа. Неправильный
пароль ничего не меняет. Правильный вход проходит, неизвестное имя даёт
ошибку, первый выход успешен, второй отвергается как повторный.

## Решение

Храним хеш-таблицу от имени к паролю и признаку «в сети». Для каждого
запроса ищем имя и проверяем условия таблицы сверху вниз; первое
выполненное условие даёт ответ и единственное изменение. `O(n·L)` для
имён длины L ≤ 30.

Подводные камни:

- при входе неверный пароль сообщается раньше, чем «уже в сети»;
- регистрация не выполняет вход;
- неудачные запросы ничего не меняют, а поиск никогда не создаёт
  учётную запись;
- имена и пароли сравниваются точно, с учётом регистра.

## Оптимизированные решения

Оптимизированное решение на C++ читает слова через `scanf` в буферы на
31 байт вместо `iostream` и отвечает на каждый запрос сразу, а не
сохраняет сначала все запросы и ответы: 212 КБ вместо 516 КБ при том же
времени.

Оптимизированное решение на Go разбирает запросы вручную из ввода с
буфером на 1 КБ вместо `fmt.Fscan` и сразу отвечает на каждый через
буферизованный вывод, без списка команд: 0.015 с вместо 0.046 с и 936 КБ
вместо 1124 КБ.
