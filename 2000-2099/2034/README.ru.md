# 2034. Максимальный минимум расстояния на кратчайшем пути

[Timus 2034](https://acm.timus.ru/problem.aspx?space=1&num=2034) · сложность 283 · bfs, dp

Автор оригинальной задачи — Олег Меркурьев; Уральская региональная командная олимпиада по программированию 2014.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дан связный простой неориентированный граф с единичными рёбрами и три различные
вершины `s,f,r`. Выбирается один из кратчайших путей из `s` в `f`.
Его оценка — минимум расстояния от `r` до вершины этого пути, включая оба конца.
Нужно максимизировать такую оценку по всем кратчайшим путям.
Расстояния от `r` считаются по всему графу. Более длинный путь не подходит,
даже если его оценка выше.

Ограничения: `3 ≤ n ≤ 100000`, `2 ≤ m ≤ 100000`, петель и кратных рёбер нет,
граф связен. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Сначала `n m`, затем `m` пар концов рёбер от 1 до `n`.
Последняя строка — попарно различные `s f r`.

## Выходные данные

Одно целое — максимальная оценка кратчайшего пути. Ноль допустим, если любой
кратчайший путь содержит `r`. Ближайшими могут быть и концы `s`, `f`.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
7 7
1 2
2 4
2 5
3 4
4 6
5 6
6 7
1 7 3
```

```
2
```

## Решение

BFS из `s` даёт расстояния `ds` и порядок обхода; BFS из `r` — расстояния `dr`.
Используем ориентированный переход `u→v` только при `ds[v]=ds[u]+1`.
Получается ациклический граф, упорядоченный слоями BFS.

Пусть `best[v]` — наибольший минимум `dr` на кратчайшем пути из `s` в `v`.
Изначально `best[s]=dr[s]`, остальные значения `-1`. Перебираем вершины
в порядке первого BFS и для каждого допустимого перехода обновляем
`best[v]=max(best[v],min(best[u],dr[v]))`. Ответ — `best[f]`.

### Доказательство

Любой префикс кратчайшего пути тоже кратчайший: иначе его замена
сократила бы весь путь. Поэтому каждое ребро увеличивает `ds` на
единицу. Обратно, путь из `s` в `f` с такими переходами имеет ровно
`ds[f]` рёбер и является кратчайшим.

Начальное значение учитывает `s`. Любой кратчайший путь в `v` заканчивается
предшественником `u` предыдущего слоя; его оценка равна минимуму оценки
префикса и `dr[v]`. Минимум монотонен по первой величине, поэтому достаточно
хранить лучший префикс для каждого `u`. Максимум по всем предшественникам
даёт точное `best[v]`. Порядок BFS обрабатывает предшественников раньше,
и индукция доказывает результат для `f`.

Можно обрабатывать и вершины вне всех кратчайших путей `s-f`. Если их
значение достигает `f` по возрастающим слоям, полученный полный путь
тоже кратчайший; в противном случае повлиять на `f` они не могут.

В примере путь `1-2-4-6-7` имеет минимум расстояния от вершины 3, равный
единице в вершине 4. У пути `1-2-5-6-7` минимум равен двум в вершинах 2 и 6.
Максимум этих оценок — два.

Два BFS и один просмотр рёбер требуют `O(n+m)` времени. Смежность,
расстояния, порядок и динамика занимают `O(n+m)` памяти.

Подводные камни:

- Сначала минимум по вершинам пути, затем максимум по путям.
- Переход разрешён только на следующий слой BFS.
- Расстояния от `r` считаются по всему графу, концы `s` и `f` учитываются.
- Ноль корректен, если на кратчайших путях нельзя избежать `r`.
- Более длинный безопасный обход не участвует в выборе.

## Оптимизированные решения

`2034_bfs_dp_optimized.rs`. Сохраняются два BFS и ДП max–min только по рёбрам в следующий слой кратчайшего пути. Плоские рёбра u32 заменяют вложенные векторы и сохранённый список концов; один вектор порядка BFS переиспользуется, вывод прямой. Расстояния связного графа помещаются в u32, MAX обозначает недостигнутую вершину. Время и память O(N+M), простое объяснение графа/BFS сохранено.

По сравнению с `2034_bfs_dp.rs`: время 0.078 s → 0.062 s; память 13112 KB → 3 448 KB.

`2034_bfs_dp_optimized.go`. Сохраняются два BFS и динамика узкого места по рёбрам, увеличивающим расстояние от s на единицу. В порядке BFS best[v] — наибольшее минимальное расстояние от r вдоль кратчайшего пути s→v; переносим min(best[v],clearance[u]) и максимизируем в u. Граф сразу при чтении хранится в плоских int32 first/to/next, без прежнего отдельного списка пар рёбер и вложенных срезов машинных int. Расстояния, очереди и динамика — int32, что безопасно при n,m<=100000; оба BFS по-прежнему выделяют собственные массивы. Граф связный, все нужные расстояния определены. Время и память O(n+m). Переносимые os.Stdin.Read/os.Stdout.Write и прямое преобразование целых используют фиксированные буферы ввода и вывода по 4096 байт. Частичная запись обрабатывается до повторного использования буфера. Исходный простой вариант с Accepted сохранён.

По сравнению с `2034_bfs_dp.go`: время 0.109 s → 0.031 s; память 11080 KB → 5244 KB.

После вычисления расстояний от первого начала второй BFS совмещается с DP узкого места по слоям кратчайших путей. Порядок FIFO гарантирует завершение всех предшествующих слоёв при извлечении вершины, поэтому тогда её лучшая оценка окончательна. Конечная вершина обрабатывается до остановки при извлечении, а не первом обнаружении. Плоская смежность и одна переиспользуемая очередь заменяют вложенные контейнеры; компактные расстояния и оценки сохраняют линейный графовый алгоритм.

- `2034_bfs_dp_optimized.cpp`: 0.031 s / 3228 KB; база `2034_bfs_dp.cpp`: 0.078 s / 6892 KB; изменение относительно базы: время -60.3%, память -53.2%.
- `2034_bfs_dp_optimized.py`: 0.468 s / 4072 KB; база `2034_bfs_dp.py`: 0.515 s / 28236 KB; изменение относительно базы: время -9.1%, память -85.6%.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`2034_bfs_dp_optimized.go`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
