# 2068. Чётность числа разбиений

[Timus 2068](https://acm.timus.ru/problem.aspx?space=1&num=2068) · сложность 108 · games

Автор оригинальной задачи — Алексей Данилюк; Уральская региональная командная олимпиада по программированию 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть n кучек орехов, в каждой нечётное число орехов. Двое ходят по
очереди; ход — разделить одну кучку на три непустые, в каждой из которых
снова нечётное число орехов. Кто не может сделать ход, проигрывает.
Первой ходит Дейенерис, затем Станнис. Определите победителя при
оптимальной игре. Ограничения: 1 секунда и 64 МБ.

## Входные данные

Нечётное n, 1 ≤ n ≤ 777, затем n нечётных размеров кучек от 1 до 54321.

## Выходные данные

`Daenerys`, если она выигрывает, иначе `Stannis`.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

```

```

Вывод:

```
Daenerys
```

### Пример 2

Ввод:

```

```

Вывод:

```

```

### Пример 3

Ввод:

```

```

Вывод:

```
Daenerys
```

## Решение

Стратегия здесь ничего не решает. Ход заменяет одну кучку тремя, поэтому
число кучек растёт ровно на два, а общее число орехов не меняется. Игра
заканчивается ровно тогда, когда в каждой кучке по одному ореху: кучку
из 3 и более (нечётного числа) орехов всегда можно разбить как
1 + 1 + (a − 2). В этот момент кучек столько же, сколько орехов, так что
число сделанных ходов всегда равно (S − n) / 2, то есть сумме
(aᵢ − 1) / 2 по кучкам.

Дейенерис делает ходы с нечётными номерами, поэтому она выигрывает ровно
тогда, когда это число нечётно. В третьем примере кучки дают
388 + 156 + 232 + 49 + 0 = 825 ходов — нечётное число. Работа за O(n).

## Оптимизированные решения

`2068_games_optimized.py` используется побайтово без изменений, без второго исходника и нового алгоритма. Accepted точного исходника на CPython 3.12 №11327048: 0.078 с / 696 КБ. Сохранённая выборка актуальных компиляторов семейства Python от 2026-11-20: место по времени 5/50, по памяти 37/50. Поскольку здесь меньше 1024 КБ, строгий критерий первых десяти мест или топ 15% учитывает только время; звёздочка сохраняет отдельную рейтинговую цель языка. У того же файла есть прежний Accepted на PyPy 3.10 №11325080: 0.109 с / 236 КБ. Это парные замеры разных запусков: CPython даёт выбранный результат по времени и рейтингу, PyPy расходует меньше памяти. Прежние замечания об экономии памяти в этом разделе относятся к этому замеру PyPy, а не к строке CPython. Все учебные исходники сохранены без изменений.

`2068_games_optimized.java`. Сохраняется XOR чётностей ((куча−1)/2). Чтение идёт из стандартного потока без дополнительного байтового массива; фиксированные байты победителя выводятся через System.out.write и flush. Кодирование String не требуется, используется обычный разрешённый стандартный поток без доступа к FileDescriptor. Время O(N), дополнительная память постоянна.

По сравнению с `2068_games.java`: время 0.109 s → 0.093 s; память 480 KB → 340 KB.

`2068_games_optimized.py`. Сохраняется инвариант фиксированного числа ходов: разбиение добавляет две кучи, исходная куча a даёт (a-1)//2 ходов до единичных куч. Важна только чётность суммы. Чётности вкладов складываются XOR при чтении целых вместо хранения всех текстовых токенов и суммирования полного числа ходов. Разбор блоками по 65536 байт сохраняет только блоки парсера и незаконченный токен; состояние игры — один бит. Время O(N) при ограниченных размерах куч, память ограничена независимо от N. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `2068_games.py`: время 0.093 s → 0.109 s; память 388 KB → 236 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

Прежнее сравнение PyPy: `2068_games_optimized.py`: место по времени 33/50, по памяти 1/50 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
