# 2064. Самый высокий из многих зигзагов

## Задача

n гусениц стартуют с земли в момент 0. Гусеница i ползёт вверх со
скоростью 1 см в минуту tᵢ минут, затем столько же сползает вниз с той
же скоростью до земли и повторяет это бесконечно. Для каждого из q
моментов найдите высоту самой высокой гусеницы. Ограничения: 3 секунды
и 64 МБ.

## Входные данные

Число гусениц n, 1 ≤ n ≤ 10⁶, затем n значений tᵢ, 1 ≤ tᵢ ≤ 10⁹, затем
число моментов q, 1 ≤ q ≤ 10⁶, и q моментов x по одному в строке,
1 ≤ x ≤ 10⁶.

## Выходные данные

Для каждого момента — наибольшая высота в отдельной строке.

## Проверка

Ответы сравниваются по токенам.

## Решение

В момент x гусеница с параметром t находится на высоте t − |x − c|, где
c — ближайшее к x нечётное кратное t: её график — ряд «шатров» высоты t
с вершинами в t, 3t, 5t, … и основаниями в чётных кратных. Иначе говоря,
высота — это расстояние от x до ближайшего кратного 2t. Ответ в момент
x — наивысшая точка всех шатров, то есть максимум h − |x − c| по всем
шатрам; шатёр, не накрывающий x, даёт там не больше 0 и не выигрывает.

Пусть X — наибольший момент. Гусеница с t ≥ X во все моменты ещё
ползёт вверх и находится на высоте x — ровно столько даёт шатёр высоты X
с вершиной в X. При t < X ближайшими к моменту x ≤ X могут быть только
шатры с вершинами до 2X. Поэтому разложим шатры по массиву: height[c] —
высота самого высокого шатра с вершиной в c; он заполняется проходом по
c = t, 3t, 5t, … до 2X для каждого различного t. Всего это около
X ln X шагов.

Затем best[x] = max по c от height[c] − |x − c| — это преобразование
расстояний с наклоном 1: проход слева направо берёт
best[x] = max(height[x], best[x − 1] − 1) для шатров слева, и проход
справа налево делает то же для шатров справа. Ответ на каждый момент
читается из массива. Время O(n log n + X log X + q), память
O(n + X + q).

В примере шатры имеют высоту 1 в нечётные моменты, 2 в 2, 6, 10, … и 3
в 3, 9, 15, … В момент 12 ближайшие вершины 10, 11, 13, 14 и 15 дают 0,
так что ответ 0.

Подводные камни:

- одно и то же t может встречаться много раз: важны только различные
  значения;
- гусеница выше всех моментов тоже учитывается, с высотой x;
- шатры с вершинами правее наибольшего момента важны для моментов перед
  ним.

## Особенности языков

Чтение двух миллионов чисел требует быстрого ввода во всех языках.
Решение на Python работает на PyPy с простыми циклами, которые хорошо
компилирует JIT; CPython тратит на самых больших тестах около шести
секунд. Разбиение всего ввода на слова обходится PyPy больше чем в
64 МБ, поэтому числа разбираются по цифрам из небольших кусков ввода,
хранятся в массивах array, а ответы выводятся небольшими порциями.
