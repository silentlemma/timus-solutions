# 2071. Порядок коктейлей с наименьшим числом наливаний

[Timus 2071](https://acm.timus.ru/problem.aspx?space=1&num=2071) · сложность 641 · bitmask, dp

Автор оригинальной задачи — Михаил Рубинчик; подготовка — Николай Пермяков и Алексей Данилюк. Уральская региональная командная олимпиада по программированию 2015.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый из n гостей заказывает коктейль — непустой набор соков A, B и P.
Стаканы ставят в ряд в некотором порядке, а за одно наливание отрезок
подряд идущих стаканов заполняется одним соком (сначала яблочный, затем
банановый, затем ананасовый, так что порядок наливаний не мешает). Каждый
стакан должен получить ровно соки своего коктейля. Расставьте стаканы
так, чтобы наливаний было как можно меньше. Ограничения: 1 секунда и
64 МБ.

## Входные данные

n, 1 ≤ n ≤ 10⁵, затем n строк, каждая — одно из A, B, P, AB, AP, BP,
ABP.

## Выходные данные

Наименьшее число наливаний, затем номера стаканов в порядке ряда.
Подходит любая оптимальная расстановка.

## Проверка

Проверяющая программа сравнивает число наливаний и пересчитывает,
сколько наливаний нужно для выведенной расстановки.

## Примеры

### Пример 1

Ввод:

```
3
A
B
ABP
```

Вывод:

```
3
1 3 2
```

## Решение

При фиксированном ряде каждому соку нужно по наливанию на каждый
максимальный отрезок стаканов, где он есть, так что стоимость — число
мест, где сок есть в стакане, но нет в предыдущем (первый стакан
считается со всеми соками). Удаление стакана не создаёт новых отрезков. Если поставить этот
стакан рядом с таким же, он лишь продлит уже существующие отрезки.
Поэтому можно собрать стаканы каждого типа вместе и упорядочить
не более семи групп.

Их упорядочивает DP по подмножествам: best[S][last] — наименьшее число
наливаний для ряда из коктейлей множества S, который заканчивается
коктейлем last. Добавление коктейля k стоит столько, сколько соков k нет
в last, то есть popcount(k & ~last). Ответ — минимум по last для полного
множества, а сохранённые предшественники дают порядок. При семи
коктейлях это 2⁷ · 7 · 7 шагов, так что работа — O(n) на чтение и вывод.

В примере порядок B, ABP, A требует трёх наливаний: по одному отрезку на
каждый сок.

## Оптимизированные решения

Версия C++ перебирает порядки не более семи типов коктейлей. Индексы стаканов каждого типа хранятся связным списком в одном массиве. Ввод и вывод занимают O(n), перебор k типов — O(k! · k), память — O(n). Посылка 11317118 заняла 0,046 с и 560 КБ против 0,078 с и 420 КБ у базовой версии.

Java разбирает ввод побайтово, хранит стоимости и предков динамики в байтовых массивах и связывает индексы стаканов через один целочисленный массив. Посылка 11317279 заняла 0,125 с и 832 КБ против 0,14 с и 8836 КБ у базы.

Go читает по одному токену и связывает индексы стаканов через один массив 32-битных чисел. Стоимости и предки в динамике по подмножествам хранятся в байтовых массивах. Посылка 11317277 заняла 0,031 с и 1288 КБ против 0,031 с и 8040 КБ у базы.

Python хранит стоимости и предков в байтовых массивах, читает заказы построчно и выводит упакованные индексы стаканов порциями. Посылка 11317276 заняла 0,109 с и 1408 КБ против 0,171 с и 16872 КБ у базы.

Rust хранит стоимость и предка каждого состояния динамики в одном байте каждый. Индексы стаканов одного типа связываются через общий массив 32-битных чисел. Посылка 11317274 заняла 0,046 с и 584 КБ против 0,046 с и 7676 КБ у базы.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11318364 · Java 1.8 №11318369 · Rust 1.75 x64 №11318371.

Версия C++ с динамикой по подмножествам читает и пишет блоками. Индексы стаканов каждого типа связаны в одном массиве. G++ 13.2 x64, посылка 11321988. Время 0,078 → 0,015 с, память 420 → 516 КБ.
