# 1929. Тройка с участником №1 и допустимый остаток

[Timus 1929](https://acm.timus.ru/problem.aspx?space=1&num=1929) · difficulty 385 · combinatorics

Original problem from Ural Regional School Programming Contest 2012 | by Olga Soboleva (prepared by Kirill Devyatkin).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Из n человек m являются специальными. Каждая команда состоит из трёх
человек и содержит хотя бы одного специального. Посчитать неупорядоченные
команды с участником №1, после выбора которых всех остальных можно
разбить на допустимые тройки. Каждая выбранная тройка учитывается один
раз, независимо от числа разбиений остатка. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Первая строка: n и m, 6≤n≤999, n делится на 3, 1≤m≤n.
Во второй перечислены m различных номеров специальных участников
от 1 до n в произвольном порядке. Участник №1 может быть любым.

## Выходные данные

Одно целое число — количество допустимых команд с участником №1.

## Проверка

Точное сравнение одного целочисленного токена.

## Примеры

```
6 4
2 3 4 6
```

```
10
```

## Решение

Пусть h=1, если участник №1 специальный, иначе h=0. Среди остальных
есть S=m−h специальных и U=n−m−(1−h) обычных. Переберём r=0,1,2 —
число специальных среди двух партнёров. Удалится h+r специальных;
в выбранной тройке требуется h+r≥1. Останется t=n/3−1 команд,
которые можно составить тогда и только тогда, когда m−h−r≥t.

Необходимость: каждой оставшейся команде нужен отдельный специальный
участник. Для достаточности назначим по одному различному специальному
в каждую из t команд. Останется ровно 2t человек на 2t мест; заполним
их произвольно. Лишние специальные тоже могут занять эти места.
Других ограничений нет.

Для допустимого r получаем C(S,r)·C(U,2−r) вариантов. Невозможный
выбор даёт ноль; C(a,0)=1, C(a,1)=a, C(a,2)=a(a−1)/2.
Три случая не пересекаются и охватывают каждую неупорядоченную пару
ровно один раз. Поэтому сумма равна искомому количеству.

O(m) времени на чтение, O(1) вычислений. Потоковые C++, Go и Java
используют O(1) дополнительной памяти; Python и Rust хранят O(m) входа.

В выбранной тройке тоже нужен специальный участник. Не удаляйте №1
из неверной категории, не считайте порядок партнёров или распределение
ролей. В остальных тройках нужен хотя бы один специальный, а не ровно
один. При m<n/3 ответ ноль; при m=n/3 в каждой тройке ровно один,
что формула учитывает автоматически. C(0,0) равно 1.
Даже найдя №1, дочитайте оставшиеся идентификаторы.

## Оптимизированные решения

`1929_combinatorics_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1929_combinatorics.java`: время 0.125 s → 0.093 s; память 2 368 KB → 492 KB.

Go и Rust читают номера особых участников до нахождения первого участника или конца списка. Хранится только этот признак, после чего напрямую складываются допустимые количества пар с нулём, одним или двумя особыми партнёрами. Выбранная тройка должна содержать особого участника и оставлять по одному на каждую следующую команду. Множество номеров и список троек не хранятся. Go использует фиксированные байтовые буферы и стандартные дескрипторы напрямую, повторяет прерванные вызовы и завершает частичные записи.

Принятые базовые реализации [1929_combinatorics.cpp](1929_combinatorics.cpp), [1929_combinatorics.java](1929_combinatorics.java), [1929_combinatorics.py](1929_combinatorics.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Учебные алгоритмы сохранены. Перепроверенные базовые версии используют собственные новые метрики и ID Accepted точного исходника; эти проверки не считаются оптимизациями.

`1929_combinatorics_optimized.java`: место по времени 2/25, по памяти 3/25 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
