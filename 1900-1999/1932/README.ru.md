# 1932. Пары по расстоянию между четырьмя цифрами

[Timus 1932](https://acm.timus.ru/problem.aspx?space=1&num=1932) · difficulty 963 · combinatorics

Original problem from Open Ural FU Championship 2012 | by Victor Vinogradov (prepared by Egor Shchelkonogov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны различные четырёхсимвольные шестнадцатеричные идентификаторы.
Посчитать неупорядоченные пары, различающиеся ровно в одной, двух,
трёх и четырёх позициях. Начальные нули являются полноценными позициями.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Сначала n, 2≤n≤65536, затем n различных строк длины четыре.
Символы: 0..9 и строчные a..f. Идентификатор 0000 допустим.

## Выходные данные

Четыре целых числа по возрастанию количества разных позиций.
Каждая неупорядоченная пара входит ровно в один из четырёх классов.

## Проверка

Точное сравнение четырёх целочисленных токенов.

## Примеры

```
3
dead
beef
f00d
```

```
0 0 2 1
```

## Решение

Для k=1,2,3 обозначим S_k сумму количеств пар, совпадающих на каждом
выбранном k-элементном подмножестве позиций. Пары учитываются с
кратностью: при r совпадающих позициях вклад равен C(r,k), по одному
на каждое подходящее подмножество. Совпадений всех четырёх нет,
поскольку идентификаторы различны. Пусть d_j — пары с j различиями.
Тогда S_3=d_1, S_2=3d_1+d_2, S_1=3d_1+2d_2+d_3. Поэтому
d_1=S_3, d_2=S_2−3d_1, d_3=S_1−3d_1−2d_2,
d_4=n(n−1)/2−d_1−d_2−d_3. Эти равенства доказывают восстановление.

Статистики считаются за один проход. Для каждого подмножества позиций
храним частоты проекций на него. При новом идентификаторе прибавляем
старую частоту его ключа к соответствующему S_k, затем увеличиваем
частоту. Каждая совпадающая пара учитывается один раз, при появлении
её позднего элемента; значит, получены именно требуемые статистики.

Нужны четыре таблицы по 16 для одиночных позиций, шесть по 256 для пар
и четыре по 4096 для троек — всего 17 984 счётчика. Разные подмножества
имеют отдельные таблицы. Идентификатор переводится в число, но из него
извлекаются ровно четыре полубайта, сохраняя смысл начальных нулей.
Ключ выбранных позиций упаковывается в исходном порядке.

O(14n+17984) времени, 17 984 счётчика и буфер входа. При фиксированных
четырёх цифрах и алфавите 16 это O(n) времени, O(1) рабочих частот
и O(n) общей памяти у программ с буферизованным вводом.

Различаются цифры, не биты: у 0000 и 000f одно различие. Таблицы для
разных подмножеств не объединяются. S_k имеет биномиальную кратность,
а не просто считает пары с хотя бы k совпадениями. Различность строк
необходима для S_3=d_1. Сначала прибавьте старую частоту, затем
увеличьте её. Порядок ответа 1,2,3,4; начальные нули сохраняют позиции.

## Особенности языков

Накопители знаковые 64-битные; расширьте тип ДО n(n−1). При n=65536
произведение равно 4 294 901 760, что превышает знаковые 32 бита до деления;
число пар равно 2 147 450 880. Частоты помещаются в 32 бита: максимум
4096,256,16 для одной, двух и трёх выбранных позиций. C++, Go, Java
и Rust используют широкие суммы, Python — точные целые. В Java
буферизованное десятичное/шестнадцатеричное чтение. C++ переключает
на hex только поток ввода после n; вывод остаётся десятичным.
Для Python выбран CPython.
