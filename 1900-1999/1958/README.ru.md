# 1958. Сортировка циклическими обменами по значению

[Timus 1958](https://acm.timus.ru/problem.aspx?space=1&num=1958) · difficulty 3577 · constructive

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Olga Soboleva (prepared by Denis Dublennykh).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Отсортировать перестановку p чисел 1…n следующими операциями. Выбрать
значение a, 1≤a≤n, найти его текущий индекс k с нуля и обменять p[k]
с p[(k+a) mod n]. Аргумент — значение элемента, а не его индекс.
Нужно не более 10⁶ операций либо сообщение о невозможности. Лимиты: 1 с, 64 МБ.

## Входные данные

Сначала n, 1≤n≤500. Далее n целых чисел — перестановка 1…n.

## Выходные данные

Если сортировка невозможна, `Impossible`. Иначе число операций m,
0≤m≤10⁶, затем m строк с аргументами в порядке выполнения. Подходит
любая корректная последовательность; минимизировать m не требуется.
Конструкция ниже доказывает возможность для любого входа и никогда
не выводит `Impossible`.

## Проверка

Проверяющая программа выполняет напечатанные операции и принимает любую
последовательность в пределах лимита, которая сортирует перестановку.

## Примеры

```
5
1 3 5 2 4
```

```
3
4
3
3
```

## Решение

Последнюю позицию n−1 используем как буфер. Если там a<n, операция a
обменивает её с (n−1+a) mod n=a−1 и сразу ставит a на окончательное место.
Повторяем до появления n в буфере; назовём это освобождением буфера.

Каждый такой обмен окончательно фиксирует новое значение в пределах
этого освобождения: операция b трогает другой целевой индекс b−1.
Поэтому n появится в буфере не позднее чем через n−1 вызовов. Сначала
один раз освобождаем буфер.

Теперь есть правильный суффикс, содержащий n. Если всё уже отсортировано,
заканчиваем. Иначе находим единицу и повторяем операцию 1, пока единица
не окажется последней. Это соседние обмены вправо без перехода через
границу. Снова освобождаем буфер и повторяем.

### Почему суффикс растёт

Пусть перед раундом позиции k…n−1 были правильными, k>0. Единица находится
раньше этого суффикса. При её движении вправо каждое значение суффикса
сдвигается влево: k+1 стоит в k−1, k+2 в k, …, n в n−2.

При освобождении буфера получить в нём n можно только фиксацией n−1
в позиции n−2. До этого n−1 должно попасть в буфер при фиксации n−2.
Продолжая назад, получаем обязательную цепочку k,k+1,…,n−1. Уже
зафиксированные в этом освобождении значения больше не вытесняются.
Значит, восстанавливается весь суффикс и дополнительно ставится k
в позицию k−1. Правильный суффикс увеличивается хотя бы на одну позицию.

Алгоритм всегда продвигается и завершает сортировку. Сначала не более
n−1 вызовов. В каждом из не более n−1 раундов — до n−1 движений единицы
и до n−1 вызовов освобождения. Итого:

m≤(n−1)+2(n−1)²=(n−1)(2n−1)≤498501<10⁶.

Для n=1 и уже правильной перестановки ответ ноль. Каждая записанная
операция выполняет ровно один разрешённый обмен.

Время O(n²), включая поиск единицы раз за раунд и вывод. Хранение вызовов
занимает O(n²), рабочая перестановка O(n). Нельзя путать значение a
с индексом k, считать позиции с единицы в формуле или ожидать изменения
от a=n: это разрешённая пустая операция. Освобождение использует только
a<n. Итог — именно 1…n, а не циклический сдвиг.

## Особенности языков

C++, Go и Rust хранят вызовы в векторе/срезе. Java 8 выделяет примитивный
int-массив по доказанной границе, без упаковки чисел в объекты. Python
сохраняет ссылки на целые и выводит блоками по 4096 операций, не создавая
огромный список десятичных строк. Rust использует только стандартную
библиотеку. Нативным версиям достаточно обычных целых. Выбран CPython.
