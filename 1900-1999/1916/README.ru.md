# 1916. Короткие фрагменты огромных слов

[Timus 1916](https://acm.timus.ru/problem.aspx?space=1&num=1916) · difficulty 3024 · strings

Автор оригинальной задачи — Иван Бурмистров (подготовка — Дмитрий Иванков); NEERC 2012, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый из n типов символов устойчив или имеет единственную фиксированную
замену на последовательность других типов, перечисленных снизу вверх.
Неустойчивые символы заменяются до получения только устойчивых; процесс
для любого типа гарантированно завершается. Можно начать с любого одного
типа. Посчитайте различные непрерывные фрагменты ровно из k устойчивых
символов во всех итоговых словах. Повторные вхождения считаются один раз.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

n,k от 2 до 100. Затем описания типов 1..n. Устойчивый тип записан как −1.
Иначе указаны длина 1≤kᵢ≤100 и kᵢ индексов от 1 до n; порядок сохраняется.
Сумма E всех длин замен не превышает 100.

## Выходные данные

Количество разных фрагментов длины k по модулю 1 000 000 007.
Если все слова слишком короткие, выведите ноль.

## Проверка

Точное сравнение одного целочисленного токена.

## Примеры

```
7 3
3 3 2 2
3 4 5 5
1 7
-1
-1
3 7 7 7
-1
```

```
5
```

## Решение

Граф зависимостей ацикличен: цикл непустых замен не позволил бы закончить
развёртку. Обрабатываем типы обходом в глубину с запоминанием результатов.
Итоговые слова не строим: уже 50 удвоений дают длину 2⁵⁰. Для каждого
типа достаточно префикса и суффикса длины не больше k−1. Устойчивый тип
даёт собственный односимвольный результат.

Склеиваем детей неустойчивого типа слева направо. При добавлении B
к уже обработанной части A строим короткое окно
suffix(A,k−1)+prefix(B,k−1). Каждую подстроку окна длины k добавляем
в общее множество. Обе половины короче k, поэтому каждая такая подстрока
пересекает настоящую границу. Новый префикс — первые k−1 символов
склейки двух префиксов, новый суффикс — последние k−1 символов склейки
двух суффиксов. Для обновления суффикса нужен суффикс ребёнка, не префикс.

### Корректность

Фрагмент A+B либо целиком находится внутри A, либо внутри B, либо
пересекает границу. Внутренние уже собраны при обработке предыдущих
детей или рекурсивно внутри B. Пересекающий использует не более k−1
символов с каждой стороны и находится в коротком окне. Обратно, любая
подстрока окна длины k действительно пересекает границу. Обновления
сохраняют точные краткие описания для следующего ребёнка. Индукция
по графу зависимостей и порядку склеивания доказывает полноту и отсутствие
лишних фрагментов. Обход всех типов учитывает все начала, множество
убирает повторения.

### Оценки и представление

На границе не больше k−1 кандидатов, присоединений детей не больше E.
Всего не более E(k−1)≤9900 добавлений. Копирование и хеширование слова
стоят `O(k)`, поэтому ожидаемое время `O(Ek² + nk)`, память `O(Ek² + nk)`.
Учтено содержимое ключей, а не предположение о хеше за постоянное время.
При данных ограничениях ответ меньше модуля, но требуемый остаток берётся.

Индекс устойчивого типа помещается в один байт, поскольку n≤100.
Ключи — полные байтовые или символьные строки. Коллизия хеша не склеивает
разные слова: контейнер сравнивает их содержимое. Запоминание результатов
обрабатывает прямые ссылки на ещё не прочитанные типы и общих потомков.

В примере получаются 777,455,745,554,545. Повторное вхождение 455
не добавляет нового фрагмента.

Считаются слова, а не вхождения и не пути вывода. Нужны все начальные типы.
Левая часть должна накапливаться целиком в кратком описании: один фрагмент
может пересечь несколько границ детей. Важны порядок, разные индексы
устойчивых типов, цепочки одиночных замен, слишком большое k и различие
между префиксом и суффиксом ребёнка.

## Особенности языков

Python использует `bytes`, C++/Go — байтовые строки, Java — символьные,
Rust — векторы байтов. Все контейнеры проверяют точное равенство слов.
Глубина рекурсии не больше n≤100. Ключи Go неизменяемы и могут ссылаться
на память короткого окна; Rust копирует ключи. Полные огромные развёртки
не сохраняются; скользящий хеш не используется как единственный идентификатор.
