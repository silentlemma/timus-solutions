# 1965. Две монотонные подпоследовательности

[Timus 1965](https://acm.timus.ru/problem.aspx?space=1&num=1965) · difficulty 1005 · dp

Original problem from Open Ural FU Personal Contest 2013 | by Sergey Pupyrev.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Разбить перестановку 1,…,n на две непустые строго монотонные
подпоследовательности. Каждая независимо может возрастать или убывать;
одинаковые направления тоже разрешены. Внутри групп сохраняется порядок
ввода, каждый элемент используется ровно один раз. Вывести любое
разбиение либо сообщить о невозможности. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Число n, 3≤n≤100 000, затем n различных целых чисел от 1 до n.

## Выходные данные

Если решение есть, в первой строке вывести два размера от 1 до n−1,
во второй и третьей — значения соответствующих групп в порядке ввода.
Допускается любое правильное разбиение. Если решения нет, вывести `Fail`.
Группа из одного элемента монотонна в любом направлении.

## Проверка

Проверяющая программа убеждается, что обе группы непусты, вместе
содержат каждое значение по разу, сохраняют порядок ввода и строго
монотонны; принимается любое подходящее разбиение. Ответ `Fail` должен
совпадать с сохранённым.

## Примеры

```
8
8 7 1 6 4 3 5 2
```

```
3 5
1 4 5
8 7 6 3 2
```

```
6
3 5 1 2 6 4
```

```
3 3
3 5 6
1 2 4
```

```
6
3 5 2 1 6 4
```

```
Fail
```

## Решение

В первом примере 1,4,5 возрастают, а 8,7,6,3,2 убывают. Обе группы
сохраняют порядок ввода и используют все значения. Во втором допустимы
две возрастающие группы: 3,5,6 и 1,2,4. Третий пример не допускает
разбиения: описанная ниже динамика отвергает все пары направлений.

Переберём четыре пары направлений: (+,+), (−,−), (+,−), (−,+). Для одной
пары обрабатываем числа слева направо. Последнее обработанное значение v
принадлежит одной из групп — владельцу последнего элемента. Последнее
значение этой группы уже равно v. В состоянии достаточно хранить номер
владельца и последнее значение другой группы.

Для каждого владельца оставим лучший хвост другой группы: меньший для
возрастания, больший для убывания. К лучшему хвосту можно приписать всё,
что разрешено после худшего. Хвост группы владельца в обоих состояниях
одинаков, поэтому худшее состояние не требуется. Запоминаем также номер
предыдущего владельца для восстановления.

Следующее x можно добавить к прежнему владельцу, если x следует за v
в нужном направлении; другой хвост не меняется. Либо добавляем x к
другой группе, если её сохранённый хвост подходит. Владелец меняется,
а хвост другой группы становится v. Для одного нового владельца
сохраняем только лучший хвост. Если недоступны оба состояния, выбранная
пара направлений невозможна.

Первое число изначально может принадлежать любой группе. Пустая
возрастающая группа имеет условный хвост 0, убывающая — n+1: любое
входное число можно добавить. В конце выбираем доступного владельца,
идём назад по сохранённым предкам и восстанавливаем группы в прямом
порядке ввода.

Если одна группа оказалась пустой, вся перестановка монотонна в другой.
Переносим её последний элемент в пустую группу. В прежней останется
n−1≥2 элементов, а одиночный элемент подходит под любое направление.
Поэтому разрешение временно пустых групп не нарушает доказательство
доминирования и позволяет получить непустой итог.

По индукции состояния сохраняют все возможности продолжения для
фиксированной пары: переходы перебирают обоих владельцев нового числа,
а доминирование удаляет лишь менее удобный хвост. Отказ всех четырёх
пар доказывает отсутствие разбиения.

Время `O(n)`, память `O(n)`: четыре пары направлений, два состояния
на позицию и константное число переходов. Предки занимают два массива
байтов на попытку; ввод и итоговые группы также линейны.

Обе группы могут иметь одинаковое направление. Однозначный жадный выбор
группы для текущего числа теряет варианты: нужны оба владельца.
Направление доминирования определяется другой группой. Сохраняем предка
именно выбранного перехода. Выводим значения, не индексы; порядок ввода
сохраняется. Пустую группу исправляем после восстановления. Нельзя
сравнивать ответ с образцом как фиксированную последовательность токенов.

## Особенности языков

Python 3.12 использует None для недоступного состояния и bytearray для
предков. C++/Go/Java/Rust обозначают недоступный хвост числом −1, поскольку
значения и условные хвосты неотрицательны. У C++ и Go массивы байтов,
у Java byte[][], у Rust Vec<u8>. Java читает буферизованно и собирает
вывод через StringBuilder. В Rust индексы usize, знаковые хвосты i32.
Рекурсии нет.
