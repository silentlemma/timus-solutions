# 1910. Тройка соседних значений с наибольшей суммой

[Timus 1910](https://acm.timus.ru/problem.aspx?space=1&num=1910) · difficulty 34 · implementation

Автор исходной задачи: Denis Dublennykh, NEERC 2012, Eastern subregional contest.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В последовательности положительных значений найдите три подряд идущих
элемента с наибольшей суммой. Выведите эту сумму и номер среднего элемента
при нумерации с единицы. Максимизирующая тройка гарантированно единственна.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Сначала n, 3≤n≤1000, затем n целых aᵢ, 1≤aᵢ≤10⁶.
Пробелы и переводы строк равноправны как разделители.

## Выходные данные

Максимальная сумма и номер среднего элемента с единицы.

## Проверка

Два точных целых числа; сравнение по токенам.

## Примеры

```
6
1 4 4 4 1 1
```

```
12 3
```

## Решение

Перебираем секции со второй по предпоследнюю как среднюю из трёх:
складываем её с двумя соседями и запоминаем наибольшую сумму вместе с
номером. Условие обещает, что лучшая тройка единственна, поэтому хватает
строгого сравнения. `O(n)`; сумма не больше 3·10⁶ и помещается в
32-битное целое.

Подводные камни:

- ответ — номер средней секции, считая с 1;
- при n = 3 тройка только одна.

## Оптимизированные решения

`1910_implementation_optimized.java`. Java сохраняет максимум скользящей тройки. Хранятся только два предыдущих значения; после чтения нового вычисляется сумма, а лучшая сумма и номер среднего элемента с единицы обновляются при строгом улучшении. Гарантированного единственного максимума достаточно для такого сравнения. Сумма не больше 3000000 и помещается в int. Фиксированный байтовый ввод и прямой числовой вывод обходятся без Scanner, конкатенации строк и общего форматирования целых; последовательность не хранится. Время O(N), дополнительная память O(1).

Accepted точного исходника Java 1.8 №11327450: 0.078 с / 356 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 1/532, память 2/532. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11303787: 0.125 с / 380 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1910_implementation_optimized.java`: 0.078 s / 356 KB; сохранённая учебная база `1910_implementation.java`: 0.156 s / 2372 KB.

Оптимизированное решение на C++ не хранит секции: оно читает их по одной
через `scanf` и помнит только две предыдущие, а больше для тройки ничего
не нужно: 128 КБ вместо 192 КБ при том же времени.

## Особенности языков

Ничего особенного не требуется.

При чтении последовательности держим окно из трёх значений и запоминаем первый максимум. Принятая посылка 11324269 заняла 0,140 с и использовала 240 КБ. Простая версия заняла 0,062 с и использовала 452 КБ. Зафиксированное время выше, чем у простой версии.
