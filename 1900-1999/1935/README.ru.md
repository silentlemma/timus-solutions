# 1935. Минимум листов при свободной перестановке

[Timus 1935](https://acm.timus.ru/problem.aspx?space=1&num=1935) · difficulty 80 · greedy

Original problem from Open Ural FU Championship 2012 | by Tatiana Sharypova (prepared by Oleg Dolgorukov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n тонких предметов размещаются между листами книги в произвольном
порядке. Предмет i требует хотя бы a_i листов до каждого соседнего
предмета или обложки. Общий промежуток должен удовлетворять обоим
соседям. Найдите минимальное число листов в книге.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

В первой строке n, 1≤n≤100. Во второй n целых a_i, 1≤a_i≤100.
Порядок во входных данных не ограничивает порядок размещения.

## Выходные данные

Одно целое число — минимальное достаточное количество листов.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3
5 10 3
```

```
28
```

## Решение

Обозначим сумму требований через S, максимум через M. Ответ S+M.
Достаточно найти эти две величины; сортировать массив не требуется.

Докажем нижнюю границу для любого размещения. Выберем один предмет
с требованием M. Каждый предмет слева от него сопоставим промежутку
непосредственно слева от этого предмета, каждый предмет справа —
промежутку справа. Сам выбранный максимум сопоставим обоим соседним
промежуткам. Использованы все n+1 различных промежутков, в каждом
должно быть хотя бы сопоставленное количество листов. Все требования
учтены по одному разу, выбранный максимум — дважды. Значит, листов
не меньше S+M. Рассуждение верно и для n=1, и при нескольких максимумах.

Для достижения границы расположим требования неубывающе:
b_1≤...≤b_n. Перед первым предметом положим b_1 листов, между i-м
и следующим — b_{i+1}, после последнего — b_n. Внутренний промежуток
равен большему из требований соседей, поэтому все условия выполнены.
Итого b_1+(b_2+...+b_n)+b_n=S+M, то есть нижняя граница достижима.
Сортировка нужна только для доказательства существования размещения.

Время O(n). Реализации сохраняют входные значения, поэтому общая
память O(n), дополнительное состояние для вычислений O(1).

Соседи используют общий промежуток: нужен максимум требований,
а не их сумма. Порядок входа сохранять нельзя: для 100,1,100 после
перестановки достаточно 301 листа, фиксированный порядок требует 400.
Максимум учитывается ещё один раз. Единственному предмету нужны 2a_1
листов из-за двух обложек; несколько максимумов не меняют формулу.

## Особенности языков

Ответ не превосходит 100·100+100=10100 и помещается в обычное 32-битное
целое. C++ суммирует целые и находит максимальный элемент; Go и Java
совмещают вычисления в одном цикле. Python использует sum и max,
Rust — сумму i32 и максимум непустого среза. Все программы читают
целые через произвольные пробельные разделители и завершают ответ LF.
