# 1935. Минимум листов при свободной перестановке

[Timus 1935](https://acm.timus.ru/problem.aspx?space=1&num=1935) · difficulty 80 · greedy

Original problem from Open Ural FU Championship 2012 | by Tatiana Sharypova (prepared by Oleg Dolgorukov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n тонких предметов размещаются между листами книги в произвольном
порядке. Предмет i требует хотя бы a_i листов до каждого соседнего
предмета или обложки. Общий промежуток должен удовлетворять обоим
соседям. Найдите минимальное число листов в книге.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

В первой строке n, 1≤n≤100. Во второй n целых a_i, 1≤a_i≤100.
Порядок во входных данных не ограничивает порядок размещения.

## Выходные данные

Одно целое число — минимальное достаточное количество листов.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3
5 10 3
```

```
28
```

## Решение

Ответ — сумма всех требований плюс наибольшее из них, S + M.

Меньше нельзя: возьмём предмет с наибольшим требованием M. Каждому
предмету слева от него нужен свой промежуток слева, каждому справа —
свой промежуток справа, а самому большому нужны оба его промежутка. Это
n + 1 разных промежутков, и вместе в них не меньше S + M листов.

Этого достаточно: отсортируем требования a₁ ≤ … ≤ aₙ и положим предметы
в этом порядке, оставив a₁ листов перед первым, a_(i+1) листов между
предметами i и i + 1 и aₙ после последнего. В каждом промежутке столько,
сколько нужно большему из соседей, а всего S + M. `O(n)`; программе
сортировать не нужно.

Подводные камни:

- соседи делят промежуток: нужно большее требование, а не сумма;
- порядок во вводе не важен: для 100, 1, 100 нужен 301 лист, а не 400;
- одному предмету нужно 2a₁ листов.

## Оптимизированные решения

Оптимизированное решение на C++ читает через `scanf` вместо `iostream`
и считает сумму и максимум во время чтения, не сохраняя требования:
124 КБ вместо 428 КБ.
