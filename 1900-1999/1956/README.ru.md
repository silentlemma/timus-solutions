# 1956. Прямая с минимальной суммой расстояний

[Timus 1956](https://acm.timus.ru/problem.aspx?space=1&num=1956) · difficulty 2303 · geometry

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Pavel Klimov (prepared by Olga Soboleva).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Переместить n точек плоскости на одну бесконечную прямую с минимальной
суммой евклидовых расстояний перемещения. Прямую и конечные положения
можно выбирать свободно. Совпадающие точки разрешены. Лимиты: 1 с, 64 МБ.

## Входные данные

Сначала n, 2≤n≤1000. Далее n пар целых координат x,y, каждая от −10⁶
до 10⁶ включительно.

## Выходные данные

Одно вещественное число — минимальная сумма расстояний. Абсолютная или
относительная ошибка не более 10⁻⁶. Печатаются двенадцать знаков после точки.

## Проверка

Ответ сравнивается с абсолютной или относительной погрешностью 10⁻⁶.

## Примеры

```
4
0 0
0 1
1 1
1 0
```

```
1.414214
```

## Решение

Для выбранной прямой каждая точка перемещается в ортогональную проекцию.
При фиксированном направлении спроецируем исходные точки на единичную
нормаль. Сумму модулей отклонений минимизирует медиана. Значит, оптимальную
прямую этого направления можно провести через входную точку P; при чётном
n берём конец интервала медиан.

Зафиксируем P и повернём прямую. Между направлениями на другие различные
точки знаки векторных произведений постоянны. Стоимость имеет вид
A cos θ+B sin θ≥0, а её вторая производная равна минус самой стоимости.
Если точки не коллинеарны, стоимость положительна и строго вогнута на
каждом таком интервале: минимум достигается на границе. Поэтому существует
глобально оптимальная прямая через две различные входные позиции. Если
все точки совпадают, ответ нулевой.

Прямой подсчёт для каждой пары занимает O(n³). Для каждой опорной P строим
векторы v=Q−P. Нулевые пропускаем. Если y<0 либо y=0 и x<0, меняем знак
вектора. Неориентированные направления попадают в полуплоскость y≥0,
включающую положительный горизонтальный луч. Модули произведений неизменны.

Сортируем по k=−x/(|x|+y), строго возрастающему с углом на [0,π).
Изначально R — сумма нормализованных векторов. В направлении d ещё не
пройденные векторы дают cross(d,v)≥0, пройденные — ≤0. Поэтому cross(d,R)
равно сумме модулей произведений. Стоимость — cross(d,R)/sqrt(d.x²+d.y²).
После события v вычитаем 2v из R. Коллинеарные векторы дают ноль, поэтому
группировать равные ключи не нужно. Пару оцениваем только у меньшего индекса.

Python объединяет совпавшие позиции с кратностями: вес w добавляет wv
в R и вычитает 2wv после события. Остальные языки хранят повторы явно.
Все исходные точки учтены. Время O(n² log n), рабочая память O(n).

### Точная арифметика и подводные камни

Компоненты направления по модулю не больше 2·10⁶, знаменатель ключа не
больше 4·10⁶. Различные рациональные ключи отличаются хотя бы на
1/(4·10⁶)², существенно больше ошибки binary64 на [−1,1]. Равные дроби
округляются одинаково; epsilon и atan2 не нужны.

Компоненты R по модулю меньше 2·10⁹. Каждое произведение меньше 4·10¹⁵,
разность меньше 8·10¹⁵. Нативные версии используют знаковый int64. Python
хранит целочисленные векторы в binary64: операции здесь точны, поскольку
произведения меньше 2⁵², целая разность меньше 2⁵³. Квадрат нормы не больше
8·10¹² и тоже точен. Округляются лишь корень и деление, запас для 10⁻⁶ велик.
Сумма квадратов расстояний решает другую задачу. Нельзя терять кратности,
делить на нулевой вектор или рассматривать лишь горизонтальные и вертикальные
прямые. Для коллинеарного набора ответ ноль.

## Особенности языков

C++ и Rust переиспользуют один вектор, Go 1.14 применяет sort.Slice,
Java 8 переиспользует объекты направлений вместо создания нового для
каждой пары. Python использует Counter, заранее удвоенные обновления и
itemgetter как ключ сортировки. Он запускается под PyPy: под CPython
3.12 решение превышает ограничение времени на 49-м тесте судьи, а под
PyPy 3.10 принимается за 0.843 с.
