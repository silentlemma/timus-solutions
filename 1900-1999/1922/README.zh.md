# 1922. 阻止任何单人加入的队伍

[Timus 1922](https://acm.timus.ru/problem.aspx?space=1&num=1922) · difficulty 322 · sorting

原题作者 Grigoriy Nazarov，出自 2012 年乌拉尔地区中学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n 位参与者。第 i 位只接受总人数至少为 aᵢ 的队伍，人数包括自己。
非空队伍中每位成员都接受当前人数时，队伍有效。若向有效队伍添加
任意一位外部成员都会使其无效，则队伍可靠。有效的全员队伍也可靠。
列出所有不同的可靠队伍。空队伍不计入答案。限制：1 秒，64 MB。

## 输入

第一行 n，1≤n≤1000。接下来 n 行各为 aᵢ，1≤aᵢ≤1000。
门槛可能超过 n。成员原始编号为 1 到 n。

## 输出

先输出可靠队伍数量 k。随后 k 行，每行输出人数与各成员的原始编号。
队伍顺序、成员顺序任意。若没有队伍，只输出 `0`，不附队伍描述。

## 评测方式

专用检查器验证队伍非空、编号合法且互异、有效性、每次单人加入
均失败、队伍无重复，以及答案集合完整。忽略队伍与成员顺序，
不要求某个固定的输出排列。

## 样例

```
5
1
3
3
6
6
```

```
2
1 1
3 2 1 3
```

## 解法

考虑人数为 s 的有效队伍 S。原成员均满足 aᵢ≤s，人数增至 s+1
不会破坏原成员要求。加入外部成员 j 成功恰好等价于 aⱼ≤s+1。
所以可靠性等价于所有外部成员的门槛均大于 s+1。

因此所有 aᵢ≤s 的成员必须在 S 内。门槛 s+1 的人既不能在队内
（会破坏有效性），也不能在队外（可以单独加入）。每个人数最多
对应一个可靠队伍：恰为所有门槛不超过 s 的人，且这些人必须恰好
有 s 位，同时没人门槛等于 s+1。

将 (门槛,原始编号) 排序，对 s=1..n 检查：

```text
前 s 项中的最大门槛 ≤ s；
并且 s=n，或下一项门槛 > s+1。
```

两者满足就输出前 s 个原始编号。第一条保证队伍有效，第二条阻止
所有外人。反过来，前述结论迫使每个可靠队伍都是这样的前缀，
故不遗漏、不重复。相同门槛无法被合法边界分开，因此其排序顺序
不产生额外队伍。

s=n 时仍需检查有效性；若有人门槛超过 n，全员队伍也无效。

可靠性针对一次加入一人，并非在所有有效超集中的极大性。
门槛 1,3,3 时，单人队和三人队都可靠：门槛 3 的两人不能分别
加入单人队，虽然一起加入就能成功。

令 R 为输出成员编号的总数。时间 O(n log n+R)，缓存答案时空间
O(n+R)。输出可能为二次规模：2,2,4,4,…,1000,1000 产生 500 个队伍、
250,500 个编号，列举它们本身就需要相应工作。

外部门槛必须严格大于 s+1，而不是仅大于 s；内部允许等于 s。
排除空队伍，允许零个答案，使用原始一基编号。相同门槛的人仍是
不同成员，但不会形成同人数的多个可靠子集。
不要把单人加入改成全局极大性，复杂度不能漏掉输出项 R。

## 各语言说明

人数与编号均可用普通整数。排序时保留原始编号。
C++、Go、Java、Rust 逐步扩展前缀，仅在合法人数处复制；Python
截取每个成功前缀。之后的修改不能覆盖已存队伍。缓冲输出减少长列表开销。
