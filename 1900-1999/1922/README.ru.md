# 1922. Команды, запрещающие любое одиночное добавление

[Timus 1922](https://acm.timus.ru/problem.aspx?space=1&num=1922) · difficulty 322 · sorting

Автор оригинальной задачи — Григорий Назаров; Уральская региональная командная олимпиада по программированию 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть n участников. Участник i согласен на команду общей численности
не меньше aᵢ, включая самого участника. Непустая команда эффективна,
если все её участники согласны с размером. Эффективная команда сплочённая,
если добавление любого одного постороннего делает её неэффективной.
Эффективная команда из всех участников также сплочённая.
Нужно перечислить все такие команды. Пустая команда не учитывается.
Лимиты: 1 секунда, 64 МБ.

## Входные данные

В первой строке n, 1≤n≤1000. В следующих n строках aᵢ, 1≤aᵢ≤1000.
Порог может превышать n. Исходные номера участников от 1 до n.

## Выходные данные

Вывести число k команд. Затем для каждой из k команд в отдельной строке
указать размер и исходные номера участников. Порядок команд и номеров
произвольный. Если команд нет, вывести `0` без описаний.

## Проверка

Специальная проверка контролирует непустоту, различные допустимые номера,
эффективность, невозможность каждого одиночного добавления, отсутствие
повторных команд и полноту списка. Порядок команд и их участников
не важен; единственного канонического вывода нет.

## Примеры

```
5
1
3
3
6
6
```

```
2
1 1
3 2 1 3
```

## Решение

Пусть эффективная команда S имеет размер s. Для каждого участника
внутри aᵢ≤s, поэтому увеличение размера до s+1 никому внутри не мешает.
Добавление постороннего j удаётся тогда и только тогда, когда aⱼ≤s+1.
Сплочённость равносильна тому, что у всех посторонних порог больше s+1.

Значит, каждый участник с aᵢ≤s обязательно входит в S. Порог s+1
невозможен вообще: внутри нарушается эффективность, снаружи получается
допустимое добавление. Поэтому для каждого размера существует не более
одной сплочённой команды: все участники с порогом не больше s, если
их ровно s и никто не имеет порога s+1.

Сортируем пары (порог, исходный номер). Для каждого s=1..n проверяем:

```text
максимальный порог среди первых s пар ≤ s;
и либо s=n, либо следующий порог > s+1.
```

При выполнении условий выводим первые s номеров. Первое условие
гарантирует эффективность, второе запрещает всех посторонних.
Обратно, доказанное свойство вынуждает любую сплочённую команду быть
таким префиксом, поэтому нет пропусков и повторов. Равные пороги
нельзя разделить допустимой границей, их порядок не создаёт новых команд.

При s=n остаётся проверить эффективность. Полная команда не всегда
эффективна: некоторые пороги могут превышать n.

Речь идёт об одном добавлении, а не о максимальности среди всех
эффективных надмножеств. Для порогов 1,3,3 подходят и одиночная команда,
и все трое: по одному участники с порогом 3 присоединиться не могут,
хотя вместе присоединились бы.

Пусть R — суммарное число выводимых номеров. Время O(n log n+R),
память O(n+R) при хранении ответов и буферизации. Вывод бывает
квадратичным: 2,2,4,4,…,1000,1000 дают 500 команд и 250 500 номеров.
Их перечисление неизбежно требует соответствующего времени.

Порог снаружи должен быть строго больше s+1, а не просто s.
Внутри равенство s допустимо. Не учитывайте пустую команду, допускайте
нулевой ответ и сохраняйте нумерацию с единицы. Равные пороги относятся
к разным участникам, но не создают альтернативных команд одного размера.
Не подменяйте одиночное добавление общей максимальностью и не забывайте R.

## Особенности языков

Размеры и номера помещаются в обычные целые. При сортировке сохраняются
исходные индексы. C++, Go, Java и Rust наращивают префикс и копируют
его только при подходящем размере; Python извлекает нужный префикс.
Поздние изменения не должны перезаписывать уже сохранённые команды.
Буферизация ускоряет длинный вывод.
