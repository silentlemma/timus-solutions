# 1978. Наибольшая сумма векторов для каждого размера

[Timus 1978](https://acm.timus.ru/problem.aspx?space=1&num=1978) · сложность 3234 · geometry, sorting

Автор оригинальной задачи — Александр Ипатов; XVII Открытый чемпионат Урала по спортивному программированию (май, 2013).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `n` плоских векторов. Для каждого `k=1,…,n` выберите ровно `k`
различных входных элементов так, чтобы евклидова длина их суммы была
наибольшей. Одинаковые векторы считаются отдельными элементами; нулевые
и отрицательные координаты разрешены.

Ограничения: `1≤n≤1000`, целые координаты `−10⁶≤x,y≤10⁶`. Время — 2
секунды, память — 64 МБ.

## Входные данные

Первая строка содержит `n`, следующие `n` строк — пары координат `x y`.

## Выходные данные

Выведите `n` строк. В строке `k` находится наибольшая длина суммы ровно
`k` элементов.

## Проверка

Числа сравниваются с абсолютной или относительной погрешностью 10⁻⁶.

## Примеры

Ввод:

```
3
3 -2
-3 -2
0 4
```

Вывод:

```
4.000000
4.000000
0.000000
```

## Решение

При фиксированном направлении `u` возьмём `k` наибольших скалярных
проекций. Среди таких наборов при вращении направления найдётся
оптимальный для каждого размера. Если оптимальная сумма `s` ненулевая,
набор с большей проекцией на `s/|s|` имел бы длину больше `|s|`, что
невозможно. Равенства проекций разрешаются малым поворотом: предельная
проекция остаётся оптимальной. Нулевой оптимум также учитывается.

Поддерживаем возрастающий порядок проекций на `(1,t)`, когда `t`
меняется от минус бесконечности до плюс бесконечности. Начальный порядок
— убывание `y`, затем возрастание `x`. Префикс даёт наименьшие проекции,
дополнение — наибольшие. Учёт обоих наборов покрывает и противоположную
полуокружность.

Пара с различными `y` меняет порядок при
`t=(x_low−x_high)/(y_high−y_low)`, где `high` обозначает больший `y`.
Сортируем события точным перемножением крест-накрест. При одинаковом `y`
пересечения внутри полуокружности нет; одинаковые векторы не требуют
события.

В одиночном событии элементы соседние. Меняем их местами и пересчитываем
только префикс между ними. Для каждого префикса храним суммы координат,
обновляем максимум квадрата длины и максимум для размера дополнения,
вычитая префикс из общей суммы.

Одновременные события обрабатываем вместе. Каждая группа равных проекций
занимает непрерывный блок и при переходе через событие разворачивается.
Для каждой пары отметим отрезок между текущими позициями; объединим
пересекающиеся отрезки, сохраняя просто соседние раздельными. Развернём
каждый полученный блок и заново вычислим внутренние префиксы. Суммы
префиксов вне блока не меняются. Такой порядок работает и с
повторяющимися векторами.

Между соседними направлениями событий порядок постоянен. Начальная
перестановка и все групповые развороты посещают нужные наборы
максимальных проекций. Каждый проверенный префикс или дополнение
является настоящим подмножеством и не может завысить оптимум. Вместе с
аргументом о направлении оптимальной суммы это доказывает ответы.

Событий `O(n²)`, их сортировка занимает `O(n² log n)`. Суммарная длина
разворачиваемых блоков — `O(n²)`: нетривиальный блок связан событиями,
поэтому его длина не больше удвоенного числа этих событий. Сортировки
начал внутри групп укладываются в ту же оценку. Память — `O(n²)`.

В примере вектор `(0,4)` даёт длину 4. Сумма первых двух — `(0,−4)`,
тоже длины 4. Сумма всех трёх равна нулю.

Подводные камни:

- Требуется ровно `k` элементов; ответ при увеличении `k` может уменьшаться.
- У одного направления бывает несколько разных групп равных проекций;
  соседние группы нельзя сливать.
- Пара из одновременной группы до её обработки может быть несоседней.
- Близкие направления с целыми координатами могут иметь определитель
  один; сравнение наклонов должно быть точным.
- Квадрат суммы достигает `2·10¹⁸`; нужны 64-битные произведения и нормы.

## Особенности языков

C++, Go, Java и Rust сортируют упакованные индексы пар с точными
64-битными произведениями. Java использует примитивные массивы и
сортировку слиянием.

Python не хранит O(n²) событий. Оптимальное множество отделяется от всех
остальных различных векторов прямой, и эту прямую можно поворачивать,
пока она не пройдёт через один из векторов. Поэтому для каждого
различного вектора как опорного решение сортирует остальные векторы по
наклону их прямой через опорный, поворачивает прямую вокруг него и на
каждом шаге записывает множество по одну сторону и его дополнение,
добавляя копии самого опорного вектора по одной. Границы координат
разводят различные наклоны далеко за пределы ошибки округления double, а
векторы с равным наклоном можно проходить в любом порядке, потому что
каждое промежуточное множество — настоящее подмножество. Квадраты длин
остаются точными целыми; вещественные числа нужны только для
заключительного извлечения корней. `O(n² log n)` времени и `O(n)`
памяти. Решение запускается под PyPy, у судьи 0,80 с из 2 с; прежняя
версия со всеми событиями пар превышала лимит времени на 7-м тесте судьи
под CPython и на 33-м под PyPy.

Ответы совпадают с перебором всех подмножеств на 14 139 малых тестах.
