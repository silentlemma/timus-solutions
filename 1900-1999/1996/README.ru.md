# 1996. Минимум изменений младших битов для подстроки байтов

[Timus 1996](https://acm.timus.ru/problem.aspx?space=1&num=1996) · сложность 1239 · strings

Автор оригинальной задачи — Денис Дублённых; подготовка — Олег Долгоруков.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны изображение из `n` байтов и сообщение из `m` байтов. В каждом байте
изображения разрешено изменить только самый младший бит. Нужно получить
сообщение как непрерывный фрагмент, изменив минимальное число битов. При
равной стоимости выбирается самое раннее начало. Семь старших битов
каждого байта неизменны. Ограничения: `1≤n,m≤250000`, 2 секунды, 64 МБ.

## Входные данные

Сначала записаны `n m`, затем две строки байтов: изображение и
сообщение. Каждый байт — восемь двоичных цифр от старшей к младшей;
байты разделены пробелами.

## Выходные данные

Если подходящего размещения нет, вывести `No`. Иначе вывести `Yes`, а
следующей строкой минимальное число изменений и номер первого байта
фрагмента, считая с единицы.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3 2
11110001 11110001 11110000
11110000 11110000
```

```
Yes
1 2
```

```
3 1
11110000 11110001 11110000
11110000
```

```
Yes
0 1
```

В первом примере старшие биты подходят для обоих начал. Для начала 1
нужны два изменения, а для начала 2 — одно. Во втором примере байты 1 и
3 дают стоимость ноль; по правилу равенства выбирается байт 1.

## Решение

Обозначим значения байтов через `A[i]` и `B[j]`. Алгоритмом
Кнута—Морриса—Пратта найдём все вхождения `B[j]>>1` в `A[i]>>1`. Это в
точности допустимые начала: различие старших семи битов исправить
нельзя, а при их совпадении младший бит всегда можно подогнать. После
полного совпадения возвращаем состояние к значению префикс-функции,
сохраняя перекрывающиеся вхождения. При `m>n` или отсутствии вхождений
ответ `No`.

Пусть `a[i]=A[i]&1`, `b[j]=B[j]&1`, `P` — префиксные суммы `a`, а
`q=sum(b)`. Развернём `b` и найдём свёртку `C` с `a`. Для начала `s`,
отсчитываемого от нуля, коэффициент `C[s+m−1]` равен `sum(a[s+j]·b[j])`.
Из тождества для битов `x xor y=x+y−2xy` получаем точную стоимость:

`P[s+m]−P[s]+q−2·C[s+m−1]`.

Перебираем допустимые начала по возрастанию и обновляем ответ только при
строгом уменьшении стоимости. Тогда среди минимумов сохраняется самое
раннее начало. Менять биты вне выбранного фрагмента незачем.

### Точная свёртка в C++, Go, Java и Rust

Используется NTT по простому модулю `998244353=119·2^23+1` с
первообразным корнем 3. Длина `L` — ближайшая степень двойки не меньше
`n+m−1`; она не превышает 524288, поэтому все корни существуют. Два
прямых преобразования, поэлементное произведение и обратное
преобразование дают свёртку. Её целочисленные коэффициенты лежат от нуля
до `m≤250000`, то есть ниже модуля. Поэтому остаток равен самому числу
совпавших единиц: округления и вероятность ошибки отсутствуют.
Произведения вычисляются в 64 битах, сумма двух остатков помещается в
знаковые 32 бита. Если начал не больше 32, используется непосредственное
сравнение младших битов.

### Умножение целых в Python

Берём основание `R=2^18` и упаковываем `X=sum(a[i]R^i)`,
`Y=sum(b[m−1−j]R^j)`. Цифры произведения по основанию `R` — коэффициенты
той же свёртки. Каждый не больше 250000 и строго меньше 262144, поэтому
переносов между коэффициентами нет. Таблица из 16 элементов упаковывает
четыре исходных бита в девять байтов. Произведение переводится в байты с
младшими вперёд; каждая 18-битная цифра читается из трёх байтов,
поскольку сдвиг внутри байта равен 0, 2, 4 или 6. Дополнение последней
группы нулями не меняет число.

Если начал не больше 2048, младшие биты упаковываются по одному на
двоичный разряд; стоимость даёт XOR с маской и подсчётом единиц.
Разворот помещает первый байт в младший разряд, маска отбрасывает хвост
за сообщением. Порог фиксирован, поэтому эта ветка линейна по длине
входа. Для полностью одинаковых старших частей список начал строится
сразу. Все ветки сохраняют формулу стоимости и правило равенства.

### Сложность

NTT-версии работают за `O(n+m+L log L)` времени и `O(n+m+L)` памяти, то
есть `O((n+m) log(n+m))` и `O(n+m)`. Для Python обозначим стоимость
умножения целых длиной до `u` и `v` битов через `M(u,v)`: время
`O(n+m+M(18n,18m))`, линейный объём хранимых данных плюс рабочая память
умножения. Оценка Python относится к целочисленному умножению, а не к
реализации FFT.

Нужно проверять все семь неизменных битов. В свёртке сообщение
разворачивается, ответ читается из коэффициента `s+m−1`. Недопустимые
начала не участвуют в минимизации. Равная стоимость не заменяет уже
найденный ответ. Ведущие нули входят в восьмизначную запись байта.
Нулевое произведение, максимальный коэффициент, перекрытия, `m>n` и
единственное окно обработаны отдельно в тестах.
