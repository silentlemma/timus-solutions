# 1994. Оптимальные случайные исключения между ночными потерями

[Timus 1994](https://acm.timus.ru/problem.aspx?space=1&num=1994) · сложность 1050 · dp, probability, combinatorics

Автор оригинальной задачи — Денис Дублённых; подготовка — Евгений Курпилянский.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Из `n` действующих участников `k` враждебны, остальные обычные. Ночью
каждый враждебный участник может устранить одного обычного; назначения
максимизируют число потерь, поэтому погибает минимум из двух
численностей. Каждый следующий день выбирается положительное число
исключаемых участников, а их личности определяются равномерно случайно.
Исключённые больше не действуют и не учитываются в ответе. Нужно
оптимально выбирать ежедневные количества, максимизируя ожидаемое число
обычных участников, оставшихся действующими, когда потери прекратятся
или обычных участников не останется.

Начальный момент — вечер: первая ночь проходит до первого исключения.
Выбирать конкретные личности нельзя. Ограничения: `1≤k≤min(n,20)`,
`n≤200`. Лимит времени — 1 секунда, памяти — 64 МБ.

## Входные данные

Два целых числа `n k`.

## Выходные данные

Одно вещественное число — оптимальное математическое ожидание оставшейся
обычной численности, а не вероятность выживания.

## Проверка

Числа сравниваются с абсолютной или относительной погрешностью 10⁻⁶.

## Примеры

Ввод:

```
4 1
```

Вывод:

```
0.6666666667
```

Первая ночь переводит `(4,1)` в дневное состояние с тремя участниками и
одним враждебным. Исключение одного с вероятностью `1/3` сохраняет двух
обычных, иначе следующая ночь устраняет последнего. Ожидание равно
`2/3`.

## Решение

### Динамика дневных состояний

Пусть `V(N,K)` — оптимум в начале дня, до исключения. Базы: `V(N,0)=N`,
`V(N,N)=0`. Численностей достаточно, хотя личности скрыты: если после
ночи остались обычные участники, число погибших равно оставшемуся числу
враждебных. Если обычные погибли все, результат уже нулевой и дальнейших
решений нет.

Переберём количество оставляемых `t<N`. Это равномерное подмножество,
поэтому число `j` враждебных имеет гипергеометрическую вероятность. При
`j=0` результат `t`; при `t≤2j` следующая ночь устраняет всех обычных.
Иначе следующий день начинается с `t−j` участников и `j` враждебных.
Получаем:

`P(j)=C(K,j)·C(N−K,t−j)/C(N,t)`

`V(N,K)=max[1≤t<N] Σ[max(0,t−(N−K))≤j≤min(K,⌊(t−1)/2⌋)] P(j)·V(t−j,j)`

При `j=0` используется `V(t,0)=t`, пропущенные слагаемые дают ноль.
Оставить ноль тоже означает результат ноль, этот вариант можно не
вычислять. Заполняем по возрастанию `N`: `t−j<N`. Сочетания получаем
треугольником Паскаля. В программе сначала суммируются взвешенные
количества, затем один раз делятся на общий `C(N,t)`.

Ответ равен нулю при `n≤2k`, иначе `V(n−k,k)` после обязательной первой
ночи. Нельзя обнулять внутреннее дневное состояние только из-за
большинства враждебных: `V(2,1)=1/2`, поскольку можно случайно исключить
нужного участника. Нельзя ограничиваться одним исключением: в дневном
состоянии `(5,2)` оставление трёх даёт `0,6`, а четырёх — только `4/15`.

Равномерный выбор оставшихся даёт указанную вероятность. Каждому составу
соответствует описанный исход следующей ночи. Меньшие состояния уже
содержат оптимальное дальнейшее ожидание, поэтому условное усреднение
даёт ценность каждого допустимого действия. Максимум по всем
положительным размерам исключения выбирает оптимальное. Индукция по
численности доказывает таблицу; отдельный переход первой ночи даёт
ответ. Случайный выбор самого размера исключения не превосходит
максимума его вариантов.

При `M=n−k` достаточно состояний до `M` и до `k` враждебных. Время
`O(M²k²)`, память `O(M²+Mk)`. Нулевые начальные случаи пропускают
таблицу. Максимальный вход требует нескольких миллионов слагаемых.

Сочетания до 200 меньше `10⁶⁰`, суммы числителя меньше `10⁶²`; double не
переполняется. Все суммы неотрицательны. При стандартном округлении
double относительная ошибка Паскаля ограничена `γ₂₀₀<2,3·10⁻¹⁴`. Два
коэффициента, не более 21 слагаемого и деление дают консервативную
относительную ошибку действия меньше `10⁻¹³`, не считая ошибки
предыдущей таблицы. Веса ожидания неотрицательны с суммой не больше
единицы, максимум имеет константу Липшица 1. За менее чем 200 переходов
абсолютная ошибка меньше `200((1+10⁻¹³)²⁰⁰−1)<5·10⁻⁹`. Положительные
слагаемые при этих границах не исчезают из-за потери порядка. Вывод 12
знаков добавляет не больше `5·10⁻¹³`.

## Особенности языков

Все пять версий используют ту же динамику и double. Java фиксирует
локаль вывода, Go совместим с 1.14. Python выносит общий знаменатель за
внутренний цикл. Различайте день и первую ночь, допускайте групповые
исключения и начинайте `j` с `max(0,t−(N−K))`, когда оставляется больше
людей, чем обычных.
