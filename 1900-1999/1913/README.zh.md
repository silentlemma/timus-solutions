# 1913. 连接三个终端的两个中继点

[Timus 1913](https://acm.timus.ru/problem.aspx?space=1&num=1913) · difficulty 1863 · geometry

原题作者 Alexey Samsonov（由 Denis Mukhametianov 准备），出自 NEERC 2012 东部分区赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

平面上有两个能源 G₁,G₂ 和接收点 C。放置两个中继点。
能源只能向距离不超过 R 的中继点发送能量；中继点可以向
另一个中继点或 C 发送，距离同样不超过 R。两个能源都必须
能沿允许的有向传输到达 C。能源不能直接向 C 或另一个能源发送。
求任意可行位置，或判断无解。中继点可以与终端或彼此重合。
限制：1 秒，64 MB。

## 输入

整数 R，1≤R≤10 000，然后依次是 C,G₁,G₂ 的整数坐标。
每个坐标在 [−10 000,10 000] 内，三个终端两两不同。

## 输出

无解时输出 `Death`。否则输出 `Now we have enough power`，
然后两行分别输出中继点坐标。任意可行答案均可；坐标的绝对
或相对误差不得超过 10⁻⁵。

## 评测方式

检查器验证成功短语、四个有限坐标，以及两个能源在
允许的有向图中能否到达 C。边长只允许 10⁻⁷ 的绝对舍入误差。
`Death` 必须与预期的可行性一致。

## 解法

先检查两条独立路径。若 |C−G₁|≤2R 且 |C−G₂|≤2R，
把两个中继点分别放在 C 与两个能源的中点即可。两个中继点
无需互相连通；能源位于 C 的两侧时也适用。

否则，可行网络中有一个靠近 C 的中继点，另一个与它相连。
两个能源要么都连接远端中继点，要么各连接一个。统一处理方式是：
从 C,G₁,G₂ 中选择终端 T，寻找距另外两个终端均不超过 R、
距 T 不超过 2R 的点 H。另一个中继点取 H 与 T 的中点。
T=C 时 H 汇集两个能源；T 是能源时 H 连接 C 与另一个能源。

因此枚举三种半径分配，检查半径为 R,R,2R 的三个闭圆盘是否
有交集。候选点是三个圆心与各对圆周交点。若交集边界包含
不同圆周的圆弧，圆弧切换处就是候选顶点；若没有切换，
交集是一个包含于其他圆盘的完整圆盘，其圆心可用。相切也包含在内。

### 精确判断与坐标构造

两个圆心 P,Q、半径 a,b，令 u=Q−P，d=u·u>0，
A=d+a²−b²，F=4a²d−A²。F<0 表示无交点，否则交点为
P+(Au±√F·rot90(u))/(2d)，其中 rot90(x,y)=(−y,x)。
对第三个圆心 S、半径 c，令 w=P−S，
T=d(c²−a²−w·w)−A(w·u)。交点在第三圆盘内当且仅当
T≥B√F，其中 B=±w·rot90(u)，符号与交点一致。

B=0 或 F=0 时检查 T≥0；B>0 时要求 T≥0 且 T²≥B²F；
B<0 时要求 T≥0 或 T²≤B²F。先处理符号再平方，整个可行性
判断只用整数，不使用浮点容差。只在确认候选可行后计算浮点坐标，
输出小数点后 12 位，并构造 H 与 T 的中点。

### 正确性

若两个中继点均连接 C，由三角不等式可得两个 2R 条件。
若只有一个连接 C，另一个必须连接它。两个能源都使用远端时，
远端点落在 T=C 的交集中；能源分别连接两个中继点时，
近端点落在 T 为远端能源的交集中。若两个能源都连接近端点，
独立路径条件已满足。因此所有可行拓扑均被覆盖。反过来，
中点把长度 ≤2R 的线段分成两条允许的边，H 又连接另外两个
终端，故所有构造都合法。候选点集合完备且比较精确，所以无解判断也正确。

时间与额外空间均为 `O(1)`，终端、半径分配和候选点数量都是常数。

第一例中 H=(2,0) 汇集能源，(1,0) 连接 C；第二例允许中继点
与终端重合；第三例有能源距 C 超过 3R，两个中继点无法跨越此距离。

不要强制两个独立中继点相连，不要允许能源直接连接 C。
重合位置合法。必须枚举三种扩大半径，处理内切、外切、
负的 B 和 T，并防止平方比较发生 64 位溢出。

## 各语言说明

距离平方至多 8·10⁸。由 |T|≤1.76·10¹⁸ 可知 T 可用有符号 64 位整数保存，
而 T²≤3.0976·10³⁶ 是保守的上界。C++ 与 Rust 用 128 位整数比较平方；
Go 与 Java 在这一比较中使用大整数，Python 使用任意精度整数。
Double 足以输出坐标，但不用于可行性决策。
