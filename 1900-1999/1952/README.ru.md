# 1952. Выживание при смене зон атаки

[Timus 1952](https://acm.timus.ru/problem.aspx?space=1&num=1952) · difficulty 8217 · dp

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Denis Dublennykh.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть n атакующих и m лечащих участников, N=n+m. Все начинают в (0,0),
имеют здоровье H и скорость v. У ауры есть максимум c, скорость роста r
при поддержании и скорость спада f при беге. Мощность непрерывна,
ограничена [0,c] и продолжает действовать при движении. Атакующая аура
снимает свою мощность со здоровья цели за секунду; каждая лечащая
восстанавливает столько же КАЖДОМУ участнику с ограничением H. Вначале
атакующие ауры нулевые, лечащие имеют максимальную мощность.

При Storm все немедленно бегут по прямой в заданный центр и поддерживают
там ауры. Урон D в секунду действует на каждого лишь до его прибытия.
При Breath выбирается биекция участников на N различных мест. Каждый
бежит прямо к своему месту и затем поддерживает ауру; урон D действует
в течение всего Breath, включая время на месте. Прохождение чужого места
не разрешает колдовать. Tail мгновенно убивает всех, встречается ровно
один раз в конце списка. Трёх Breath подряд не бывает. Времени каждого
заклинания хватает для любого возможного перехода. Storm дополнительно
хватает для полного восстановления здоровья выживших и максимумов всех
аур. Любое D строго больше суммы максимумов лечащих аур.

Нулевое здоровье участника немедленно убивает всю группу. Нулевое здоровье
цели само по себе не останавливает атаки: требуется мгновенное добивание,
когда ВСЕ живы и находятся вместе в центре действующего Storm. На границе
атак ещё действует предыдущая. Найдите самый ранний номер атаки,
допускающий добивание. Ограничения: 1 секунда, 64 МБ.

## Входные данные

Сначала n,m,k: 1≤n,m≤9, N≤10, 1≤k≤10. Затем H,v,G, где G — здоровье
цели: 1≤H,G≤10⁹, 1≤v≤10⁶. Далее n атакующих и m лечащих троек c,r,f,
все значения от 1 до 10⁶. Каждый из k блоков начинается именем атаки с
учётом регистра. Storm: строка D,T и строка x,y центра. Breath: D,T и N
строк x,y мест. У Tail параметров нет. Для заклинаний 1≤D,T≤10⁶,
−1000≤x,y≤1000. Выполняются все перечисленные гарантии. Время движения —
евклидово расстояние, делённое на v, и может быть иррациональным.

## Выходные данные

Если победа невозможна, `You are not prepared`. Иначе `No useful loot again`
и на следующей строке самый ранний номер атаки, начиная с 1.

## Решение

Конец Storm восстанавливает позиции, здоровье и мощности. Делим список
на блоки из нуля, одного или двух Breath и следующего Storm; начальное
состояние считаем виртуальной границей. Хвост из Breath перед Tail можно
игнорировать. Только первый блок имеет нулевые атакующие ауры. Максимальный
урон каждого проходимого блока суммируется независимо: следующая граница
полностью сбрасывает состояние группы.

Пусть L — максимальное время пути от мест последнего Breath до центра.
Все места заняты, поэтому L не зависит от назначения. Последний прибывший
получает урон во всех Breath и до L. Поскольку D больше любого суммарного
лечения, его здоровье строго убывает. Прибывшие раньше избегают части урона
и имеют не меньше здоровья. Достаточно строгой проверки выживания при L;
после этого все в безопасности и могут добить цель до конца Storm.

Пусть B — сумма максимумов лечения. Неизбежная потеря равна
ΣBreath (D−B)T+(Dstorm−B)L. Вычтем её из H, получим запас K. Для каждого
лекаря стоимость назначения — интеграл c−power по Breath и первым L
секундам Storm. Сумма этих неотрицательных дефицитов должна быть СТРОГО
меньше K. Вес атакующего — интеграл мощности по всему блоку, включая
весь конечный Storm. Падающие и растущие линейные участки интегрируем с
ограничениями 0 и c. Прямой расчёт дефицита не вычитает близкие огромные
полные интегралы лечения.

Для одной группы обрабатываем участников по порядку. При одном Breath
dp[S] — оптимум назначения первых |S| участников на S. При двух dp[S,U]
хранит два использованных подмножества. Добавляем незанятое место в каждом
слое и вес пары для текущего участника. Минимизируем дефицит лекарей и
максимизируем урон атакующих отдельно. Для выживающей маски или пары масок
лекарей берём дополнительные маски атакующих. Переходы перебирают все
инъекции, сохраняя оптимум, а дополнения заполняют оставшиеся места без
конфликтов. Это доказывает допустимость и максимальность урона. Без Breath
назначений нет, выживание проверяется прямым сравнением радикалов. Ответ —
первый Storm, где накопленный максимум урона не меньше G.

### Точные сравнения

Эпсилон не отличает смерть при точном нуле здоровья. В общей геометрии
время, интегралы и ошибки назначений заключены в интервалы с округлением
наружу. Неравенство принимается лишь при доказательстве всем интервалом.
При пересечении границы нужное ограниченное назначение уточняется точно.
Число представляется канонической суммой Σ q_d√d с рациональными q_d и
бесквадратными d. Различные такие радикалы линейно независимы над Q:
точный ноль имеет только нулевые коэффициенты. Для ненулевого числа
целочисленные корни дают всё более точные десятичные границы, пока интервал
не исключит ноль. Так выбираются спорные назначения и проверяются точные
совпадения суммарного урона. Фиксированного допуска нет.

Python использует Fraction для рационального времени пути и точного
интегрирования, а Surd — для иррационального времени и сумм радикалов.
Перед построением точного тензора c,r,f каждой ауры делятся на их НОД,
затем стоимости умножаются на него обратно. Точное назначение одного
слоя решается паросочетанием. При двух слоях одинаковые тензоры всех
участников также сводятся к паросочетанию между наборами мест; иначе
используется ограниченная точная динамика по подмножествам.

В обычной динамике двух Breath обе группы вместе выполняют ровно
N²·C(2N−2,N−1) переходов, до 4 862 000 при N=10. Один слой: O(N·2ᴺ).
Обычная динамика нативных версий компактно хранит пары масок одинаковой
мощности: O(C(2N,N)) состояний, до 184 756. Python адресует O(4ᴺ) ячеек.
Для точного ограниченного назначения q участников C++ и Java также
хранят компактные O(C(2q,q)) состояния, а Go, Rust и Python выделяют
O(4^q) ячеек. Веса требуют O(N³) времени и памяти. Всё умножается на число
блоков. Спорные
точные сравнения добавляют ограниченные назначения и длинную арифметику;
число обычных переходов не ограничивает их битовую сложность. Завершение
уточнений следует из доказательства знака суммы радикалов.

Прибытие не снимает урон Breath; бег не отключает ауру; лечение действует
на всех. Места нельзя разделять, старый центр во время Breath не разрешает
добивание. Начальные Breath допустимы. Здоровье участника строго >0, цели
может быть нулём. Начальная атакующая мощность нулевая. Гарантия полного
восстановления Storm нужна для разбиения; стресс-тесты тоже обязаны ей
удовлетворять. Квадраты координат, скорости и точные числители требуют
достаточного диапазона целых. Рациональное время пути всё равно даёт
дробные стоимости: тесты case_049–case_056 проверяют строгую границу
здоровья и порог урона цели. Нельзя округлять эти стоимости до целых
или предполагать наличие отдельного пути с целочисленным масштабированием.

## Особенности языков

Go и Java используют свои целые произвольной точности, Python — свои
целые и Fraction, C++ — собственную длинную арифметику с дробями,
длинным делением и целочисленным квадратным корнем, а Rust — собственные
числа из 32-битных разрядов. Java разделяет тензоры одинаковых аур и
время от времени освобождает временные точные объекты, чтобы куча
оставалась маленькой. Точное уточнение восстанавливает выбор по ссылкам
на родителей, а не хранит символьное число в каждом состоянии
подмножества.

Python сначала решает в double с гарантированными оценками ошибки:
релаксация через паросочетание и однослойные дополняющие ДП дают оценки,
которые решают большинство боёв, а полная ДП и точная арифметика
запускаются, только когда оценки не позволяют решить. Решение
запускается под PyPy, у судьи 0,83 с из 1 с; прежняя версия, которая
всегда выполняла полную ДП, превышала лимит времени на тесте 21 жюри.
Rust повторяет решение на Go простыми циклами и почти без обобщённых
функций: прежняя версия на Rust не уложилась у судьи во время
компиляции.
