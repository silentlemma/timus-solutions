# 1952. 在交替区域攻击中生存

[Timus 1952](https://acm.timus.ru/problem.aspx?space=1&num=1952) · difficulty 8217 · dp

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Denis Dublennykh.

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n 个攻击者和 m 个治疗者，N=n+m。全员从 (0,0) 出发，生命上限 H，
移动速度 v。每个光环有上限 c、施法时增长速度 r、奔跑时衰减速度 f。
功率连续且限制在 [0,c]，移动时仍有效。攻击光环每秒扣除目标相应生命；
每个治疗光环每秒给所有队员恢复相应生命，不能超过 H。初始攻击功率为
零，治疗功率为上限。

Storm 开始时全员立即直线跑向中心，到达后施法。每人只在到达前承受
每秒 D 点伤害。Breath 中必须将全员与 N 个不同地点一一对应；每人
直线跑到自己的地点后施法，整个 Breath 都承受每秒 D 点伤害，包括
到达之后。经过别人的地点不能施法。Tail 立即杀死全员，恰好出现一次
且在最后。不会连续出现三个 Breath。任何攻击的时长都足够完成任意
可能的移动。每个 Storm 还足够让幸存者恢复满生命及所有光环上限。
每个 D 严格大于全部治疗光环的上限之和。

任何队员生命降到零时全队立即死亡。目标生命到零不会终止攻击，还须
在所有队员存活且同时位于当前 Storm 中心时施放瞬时终结技能。攻击
交界时仍按前一个攻击处理。求能结束战斗的最早攻击编号。1 秒，64 MB。

## 输入

首行 n,m,k：1≤n,m≤9，N≤10，1≤k≤10。下一行 H,v,G，G 为目标生命：
1≤H,G≤10⁹，1≤v≤10⁶。随后 n 行攻击光环和 m 行治疗光环，每行为
c,r,f，各在 [1,10⁶]。接着 k 块，每块先给大小写敏感的攻击名称。
Storm 后为 D,T 和一个中心 x,y；Breath 后为 D,T 和 N 行地点 x,y；
Tail 没有参数。1≤D,T≤10⁶，−1000≤x,y≤1000。满足上述全部保证。
移动时间为欧氏距离除以 v，可能是无理数。

## 输出

不能成功则输出 `You are not prepared`。否则输出 `No useful loot again`，
下一行输出从 1 开始的最早攻击编号。

## 评测方式

按记号逐个比较输出。

## 解法

每个 Storm 结束后位置、生命和功率完全重置。将序列分为零、一或两个
Breath 加一个 Storm 的块，初始状态视为虚拟边界。Tail 前没有 Storm
的 Breath 后缀无法结束战斗。仅第一块攻击光环从零开始。各可生存块
独立最大化伤害再相加，因为下一块状态与本块选择无关。

设 L 为最后一个 Breath 的所有地点到下个中心的最大移动时间。每个
地点均被使用，因此 L 与分配无关。最后到达者在各 Breath 及 Storm
前 L 秒一直受伤；D 大于任何可能的总治疗，其生命严格下降。早到者
少受部分伤害，生命不会更低。因此只需严格检查 L 时刻存活；之后
全员安全，可在 Storm 结束前完成终结。

设 B 为治疗上限总和。不可避免的生命损失为
ΣBreath (D−B)T+(Dstorm−B)L，从 H 减去它得预算 K。每个治疗者的
分配代价为各 Breath 及 Storm 前 L 秒的 c−power 积分；总代价必须
严格小于 K。攻击者权重为整个块内功率的积分，包括全部末尾 Storm。
下降和上升均为分段线性，在零与 c 处截断。直接积分治疗缺口避免
两个巨大而接近的总治疗积分相减。

按固定顺序处理某一类队员。一个 Breath 时 dp[S] 为前 |S| 人分配到
S 的最优权重；两个时 dp[S,U] 记录两次已用的地点集合。每层加一个
未用地点及当前队员对应权重。分别最小化治疗缺口、最大化攻击伤害。
枚举可生存的治疗掩码或掩码对，攻击者使用补集。转移枚举每个单射
并保留最优值，补集正好无冲突地填满其余地点，故可行性与伤害最大值
均正确。没有 Breath 时无需分配，直接比较根式判断生命。第一个累计
最大伤害 ≥G 的 Storm 即答案。

### 精确比较

固定 epsilon 无法区分生命恰为零的死亡。一般几何先用向外舍入区间
包含移动、积分及分配误差；仅在整个区间证明不等式时作出决定。
否则精确细化有关的受限分配。数值用标准形式 Σ q_d√d 表示，q_d 为
有理数，d 为无平方因子的整数。不同这些根式在 Q 上线性独立，故
精确零恰好为全部系数零。非零时以整数平方根求逐步加密的十进制界，
最终区间排除零。重叠的分配候选及累计伤害相等也如此处理。不使用
固定误差或未经证明的浮点平局规则。

Python 用 Fraction 表示有理移动时间并精确积分，用 Surd 表示无理
移动时间及其产生的根式和。构造精确张量前，将每个光环的 c,r,f
除以它们的最大公因数，再将代价乘回该因数。单层精确分配使用匹配。
两层中，若所有队员的张量相同，也可化为两组地点之间的匹配；否则
使用受限的精确子集 DP。

每个双 Breath 块两类普通 DP 合计恰有 N²·C(2N−2,N−1) 次转移，
N=10 时最多 4,862,000。单层 O(N·2ᴺ)。原生版本的普通 DP 紧凑保存
等大小掩码对，O(C(2N,N)) 状态，最多 184,756；Python 使用 O(4ᴺ)
寻址槽。对 q 人的受限精确分配，C++ 和 Java 也使用紧凑的
O(C(2q,q)) 状态，而 Go、Rust 和 Python 分配 O(4^q) 个槽。
权重计算及存储 O(N³)，再乘块数。精确歧义处理额外需要受限分配和
任意精度运算，普通转移数不能单独界定其位复杂度。根式符号论证保证
细化终止。

Breath 到达后仍受伤，奔跑光环不停，治疗作用于全员。地点不能共享，
Breath 中经过旧中心不能结束。初始可以是 Breath。队员生命必须 >0，
目标生命允许零，初始攻击功率为零。Storm 完全恢复的输入保证是分块
的必要依据，压力测试同样必须满足。坐标平方、速率及精确分子须有
足够的整数范围。有理移动时间仍可能产生分数代价：case_049–case_056
检查严格生命边界及目标伤害阈值。不能将这些代价取整，也不能假定
实现中存在单独的整数缩放路径。

## 各语言说明

Go 和 Java 使用各自的任意精度整数，Python 使用其整数和 Fraction，C++ 使用自己实现的带分数、长除法和整数平方根的高精度运算，Rust 使用自己的 32 位分段整数。Java 让相同光环共享张量，并不时释放临时的精确对象以保持堆较小。精确细化通过父链接恢复选择，而不在每个子集状态中保存符号数。

Python 先用带有可靠误差界的 double 进行判断：匹配松弛和单层补全 DP 给出的界能解决大多数战斗，只有在界无法判定时才运行完整 DP 和精确运算。它在 PyPy 下运行，评测用时 0.83 秒（限制 1 秒）；总是运行完整 DP 的早期版本在评测的第 21 个测试上超时。Rust 以简单的循环、很少的泛型函数照搬 Go 解答：早期的 Rust 版本在评测时超出了编译时间。
