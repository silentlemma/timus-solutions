# 1985. Столбец с простыми числами в гамильтоновой нумерации

[Timus 1985](https://acm.timus.ru/problem.aspx?space=1&num=1985) · сложность 1970 · constructive

Автор оригинальной задачи — Михаил Рубинчик, отдельная благодарность Александру Ипатову; Открытый командный чемпионат УрФУ по программированию — 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Заполните таблицу `n×n` целыми числами от 1 до `n²`, каждое ровно один
раз. Клетки с последовательными числами должны иметь общую сторону.
Оценка столбца — число простых значений в нём. Максимизируйте наибольшую
оценку столбца и выведите любую оптимальную таблицу. Дано `1≤n≤256`.
Ограничения: 1 секунда и 64 МБ.

## Входные данные

Одно целое число `n`.

## Выходные данные

Оптимальная таблица: `n` строк по `n` целых чисел.

## Проверка

Проверяющая программа сверяет перестановку, соседство по стороне для
последовательных чисел и то, что в лучшем столбце оптимальное число
простых; принимается любая оптимальная таблица.

## Примеры

Ввод:

```
4
```

Вывод:

```
2 1 12 11
3 16 13 10
4 15 14 9
5 6 7 8
```

## Решение

Рассматриваем числа как порядок посещения клеток гамильтоновым путём.
Каждое посещение записывает следующее число. Координаты далее нумеруются
с нуля.

### Оптимальная оценка

Цвета шахматной раскраски чередуются вдоль пути. Все нечётные числа
имеют один цвет, а все простые, кроме 2, нечётны. Поэтому в столбце не
больше `ceil(n/2)` нечётных простых и, возможно, число 2: верхняя
граница — `ceil(n/2)+1`.

При `n=1` оценка нулевая, при `n=3` — два. В последнем случае путь
начинается на преобладающем цвете раскраски, поэтому в среднем столбце
только одно нечётное число. Три простых в крайнем столбце потребовали бы
2 в его средней клетке. Тогда 1 находится в горизонтальной соседней
клетке, 3 — в одной из вертикальных. Из этого угла числа 4–9 вынужденно
идут по оставшемуся периметру, а другой конец крайнего столбца получает
составное число 9. Отражения покрывают остальные положения. Змейка по
строкам достигает оценки два. Для этих двух малых нечётных размеров
используем такую змейку, для остальных достигаем общей границы.

### Подготовка и обход

Решетом находим простые до `n²`. Таблица `next[x]` хранит минимальное
простое строго больше `x` либо ноль. Разность нечётных простых `g`
чётна. Обход ширины `t=(g−2)/2`: `t` шагов по горизонтали, шаг по
вертикали, `t` шагов обратно и ещё шаг по вертикали — увеличивает метку
на `g` и меняет строку на две. Запоминаем ширины для заполнения
оставшихся частей.

### Чётный размер

Ставим 1 в `(0,1)`, 2 в `(0,0)`, 3 в `(1,0)`. Обходами
вправо/вниз/влево/вниз помещаем следующие нечётные простые в столбец 0,
строки `1,3,…,n−1`. Каждый обход занимает равные левые префиксы двух
строк. Требуем `t<n−1`, оставляя справа хотя бы один столбец.

От нижнего простого идём по нижней строке вправо. Затем заполняем
остатки пар строк снизу вверх: нижнюю справа до первой свободной клетки,
верхнюю оттуда вправо. Наконец идём по свободной части верхней строки
справа до столбца 2. Каждая клетка посещается ровно один раз. В столбце
0 находятся `n/2` нечётных простых и 2, оценка — `n/2+1`.

### Нечётный размер не меньше пяти

Целевой столбец — 2; слева полоса ширины два, справа — `w=n−3`.
Перебираем `a` от 0 до `w`, исключая `w−1`. Нужны простые `p=3+2a` и
`q=p+2n`. Начиная с `q`, проверяем также следующие `(n−3)/2` промежутков
между простыми: их ширины должны удовлетворять `0≤t<w`, а сами простые
не превосходить `n²`. Неподходящий вариант отбрасываем.

1. Записываем 1 в `(1,1)`, 2 в `(1,2)`. Идём вправо на `a` клеток по
   строке 1, вверх в строку 0 и влево на `a` клеток. В `(0,2)`
   оказывается простое `p`.
2. Полностью заполняем левую полосу, кроме уже занятой единицы:
   `(0,1),(0,0),(1,0),(2,0),(2,1)`, затем для нечётных `r=3,5,…,n−2`
   посещаем `(r,1),(r,0),(r+1,0),(r+1,1)`. Входим в `(n−1,2)` с меткой
   `q=p+2n`.
3. Поднимаемся по целевому столбцу обходами вправо/вверх/влево/вверх. В
   чётных строках `n−3,n−5,…,2` оказываются следующие простые. У каждой
   пары строк правой полосы остаются равные свободные суффиксы.
4. Пусть `L=3+a`. При `L=n` верхние две правые полосы уже заполнены:
   просто идём по строке 2 вправо. Иначе `m=n−L≥2`: идём по строке 2 до
   `L`, в `(1,L)`, затем `(0,L)`, по строке 0 до правого края, по строке
   1 обратно до `L+1` и по строке 2 от `L+1` до правого края. Так
   заполняется верхний правый прямоугольник. Исключение `a=w−1`
   устраняет невозможный одностолбцовый случай этого шага.
5. Заполняем нижние пары правой полосы сверху вниз, начиная со строк 3
   и 4: верхнюю справа налево до свободной границы, нижнюю оттуда
   направо. Границы определяются сохранёнными ширинами.

Левая полоса и оставшиеся правые суффиксы не пересекаются. Все переходы,
включая стыки пар, идут в соседние клетки. Получается гамильтонов путь.
В каждой чётной строке столбца 2 стоит нечётное простое, а в строке 1 —
число 2, поэтому оценка равна `(n+1)/2+1`.

### Конечные условия на простые и сложность

Условия ширины проверены на всей допустимой области, без предположений о
недоказанных свойствах простых. Независимая проверка делением охватывает
все 128 чётных и все 126 нечётных размеров не меньше пяти. Для каждого
нечётного размера найден допустимый префикс. Максимальные найденные
ширины: 8 для чётного обхода, 14 для начального нечётного и 16 для
восходящего. Проверены также неравенства свободной ширины для каждого
размера. Проверку можно воспроизвести, выполнив описанный поиск для всех
допустимых `n`. Все 256 полных построений дополнительно проверены на
перестановку, соседство и оптимальность.

В примере первый столбец равен `2,3,4,5` и содержит три простых —
верхнюю границу для `n=4`.

Решето требует `O(n² log log n)` времени. Таблица следующего простого,
обход и проверка кандидатов требуют `O(n²)`: `O(n)` кандидатов по `O(n)`
переходов с запросом за постоянное время. Память — `O(n²)`; сам вывод
содержит `n²` значений.

Подводные камни:

- 1 не является простым, а 2 — единственное чётное простое.
- При `n=3` оптимум равен двум, а не трём.
- Корректный гамильтонов путь может давать неоптимальный столбец.
- Следующее простое должно быть строго больше текущей метки.
- При заполнении остатков нужны сохранённые ширины обходов.
- Конечная проверка свойств простых относится к `n≤256`, а не ко всем
  большим размерам.

## Особенности языков

Все пять версий используют одинаковое построение, решето и запрос
следующего простого за постоянное время. В Python простота хранится в
байтовом массиве. C++, Go и Java используют целые метки, Rust — индексы
`usize`. Максимальная метка — 65 536. Вывод буферизуется или собирается
в памяти.
