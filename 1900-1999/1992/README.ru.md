# 1992. Общие неизменяемые истории обучения и откатов

[Timus 1992](https://acm.timus.ru/problem.aspx?space=1&num=1992) · сложность 372 · trees, simulation

Автор оригинальной задачи — Егор Щелконогов.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Изначально объект 1 не знает программ и не имеет истории откатов.
Требуется обработать `n` команд над упорядоченными историями обучения;
номера программ от 1 до `m`. Обучение добавляет программу и очищает
историю откатов этого объекта. Откат удаляет последнюю изученную
программу и сохраняет её для восстановления. Восстановление возвращает
последний откат. Копирование создаёт новый объект с обеими текущими
историями. Запрос возвращает последнюю изученную программу либо `basic`,
если история обучения пуста.

Ограничения: `1≤n,m≤500000`. Все команды корректны: объект уже
существует, новая программа сейчас им не изучена, для отката есть
изученная программа, для восстановления есть запись. Программу после
отката можно изучить снова. Лимит времени — 2 секунды, памяти — 64 МБ.

## Входные данные

Первая строка содержит `n m`, далее идут `n` команд:

- `learn c p`: изучить программу `p`, `1≤p≤m`, и очистить историю
  откатов объекта `c`.
- `rollback c`: откатить последнюю изученную программу.
- `relearn c`: восстановить последний откат.
- `clone c`: скопировать обе истории в новый объект.
- `check c`: запросить последнюю изученную программу.

Новые номера выдаются по порядку создания после исходного номера 1.
Копирование не изменяет исходный объект.

## Выходные данные

На каждый `check` по порядку выведите номер программы либо слово `basic`
строчными буквами, по ответу на строку. Если запросов нет, вывод пустой.

## Проверка

Ответы сравниваются по токенам.

## Примеры

Ввод:

```
9 10
learn 1 5
learn 1 7
rollback 1
check 1
clone 1
relearn 2
check 2
rollback 1
check 1
```

Вывод:

```
5
7
basic
```

После первого отката объект 1 знает программу 5 и может восстановить 7.
Копия сохраняет оба состояния. Объект 2 восстанавливает 7, не меняя
объект 1; последний откат оставляет объект 1 без изученных программ.

## Решение

У каждого объекта храним две вершины стеков: `A` изученных программ,
последняя сверху, и `R` откатов, последний откат сверху. Все стеки
используют общий пул узлов. Узел содержит `(программа, предыдущий)` и
после создания не меняется; индекс 0 означает пустоту. Добавление `p` к
вершине `h` создаёт новый узел `(p,h)` и возвращает его индекс. Удаление
вершины читает её индекс `previous`.

Операции:

- Обучение: `A=push(p,A)`, `R=0`.
- Откат: запомнить `t=A`, затем `A=previous[t]`, `R=push(value[t],R)`.
- Восстановление: запомнить `t=R`, затем `R=previous[t]`, `A=push(value[t],A)`.
- Копирование: скопировать два целочисленных индекса вершин.
- Запрос: вывести `value[A]` при непустом `A`, иначе `basic`.

Очистка откатов только обнуляет вершину: удалять общие узлы нельзя, они
могут оставаться достижимыми у других объектов. Копии разделяют
неизменяемые хвосты; дальнейшая команда меняет только вершины выбранного
объекта. Обходы, копирование списков и множество изученных программ не
нужны, поскольку вход корректен.

Ненулевая вершина `h` представляет последовательность из `value[h]` и
последовательности по `previous[h]`; ноль представляет пустую
последовательность. Новый узел добавляет ровно один элемент к прежнему
стеку. Существующие узлы неизменяемы, поэтому копия вершины сохраняет
всю последовательность независимо от дальнейших изменений других вершин.

Индукция по командам: в начале обе истории пусты. Обучение добавляет
нужную программу и удаляет историю восстановления. Откат перемещает
ровно верхнюю изученную программу в откаты; восстановление делает
обратное. Копирование сохраняет обе последовательности, а запрос читает
правильную верхнюю программу. Значит представленные стеки всегда
совпадают с требуемыми историями и все ответы верны.

Обучение, откат и восстановление создают по одному узлу; копирование и
запрос узлов не создают. Узлов не больше `n`, объектов не больше `n+1`.
Четыре массива длины `n+2` хранят программы, предшественников и две
таблицы вершин. Все значения помещаются в 32 бита. Максимальная память
элементов — `4·4·(500000+2)=8000032` байта, около 7,63 МиБ.

Работа со стеками — `O(1)` на команду, суммарное время `O(n)` при
ограниченной длине токенов, память `O(n)`. Пусть `I` — число байтов
ввода, `B` — вывода. Go и Rust также сохраняют `I`; C++, Go, Python и
Rust накапливают `B`. Java выводит через буферизованный поток и
переиспользует массив цифр без создания строки на каждый числовой ответ.
Здесь `B≤7n`, поэтому общая память остаётся линейной.

Python читает команды построчно и использует компактные `array('i')`:
отдельные кортежи или копии списков на каждый узел слишком затратны. Go
использует 32-битные массивы и байтовый разбор, совместимый с 1.14. Java
использует `int` и байтовый ввод. В Rust индексы `u32` преобразуются при
обращении к векторам. Полное копирование списков может дать квадратичные
затраты при множестве копий глубокой истории.
