# 1975. Число поворотов сферы с отмеченными точками

[Timus 1975](https://acm.timus.ru/problem.aspx?space=1&num=1975) · сложность 4177 · geometry

Автор оригинальной задачи — Денис Дублённых; XVII Открытый чемпионат Урала по спортивному программированию (май, 2013).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На единичной сфере с центром в начале координат отмечено n точек. Нужно
посчитать собственные пространственные повороты вокруг центра, после
которых каждая отметка находится не далее 10⁻⁶ от некоторой отметки.
Тождественный поворот учитывается. Повороты, задающие одну перестановку
точек, считаются один раз; отражения запрещены. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Первая строка содержит n, 3≤n≤200. Следующие n строк содержат координаты
x, y, z точек единичной сферы, не более девяти знаков после запятой.
Расстояние между любыми различными точками не меньше 10⁻⁵. Для невязок
используются исходные координаты; нормализация нужна лишь для направлений
и ортонормированных базисов.

## Выходные данные

Одно целое число — количество реализуемых перестановок точек.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3
0 1 0
1 0 0
0 0 1
```

```
3
```

## Решение

### Перебор образов устойчивой пары

Обозначим ε=10⁻⁶. Первое нормированное направление назовём a, а b выберем
по максимальному s=|a×b|. Три разделённые точки гарантируют s>0, даже
вблизи одной оси. Построим правый базис z=a, y=(a×b)/s, x=y×z и выразим
в нём исходные, ненормированные точки.

Переберём упорядоченные различные образы P,Q. Пусть e=ε/min|point|,
η=2 asin(e/2). Необходимое условие: угол β между P,Q отличается от
α=angle(a,b) не более чем на 2η. Сначала проверяем дешёвые ограничения
на синус и косинус. Добавка 10⁻¹² расширяет только этот фильтр и никогда
не служит допуском для принятия поворота.

Базис целей задаёт собственный канонический поворот R₀, переводящий a
точно в P, а b — на азимут Q. Допустимый поворот имеет вид T H R₀:
T наклоняет P не более чем на η, H поворачивает вокруг P на θ. Если
t=sin β, то |sin(θ/2)|≤e/√(st). Поперечный радиус любой исходной точки
не превосходит s. Поэтому расстояние её канонического образа до истинной
цели не больше ε+rmax·e·(1+2√(s/t)). Из разделения точек следуют
s≥примерно 5·10⁻⁶ и t≥s−2e; итоговая граница строго меньше 5ε, в том
числе при округлении координат до девяти знаков.

Ближайшая отметка в пределах 5ε и есть нужный образ: другая отметка
удалена от неё хотя бы на 10ε. Храним точки в пространственном хеше с
ребром ячейки 10ε, добавляя каждую в 27 соседних корзин. Для образа
достаточно одной корзины. Отсутствующая или повторная цель отменяет
кандидата. Множество принятых перестановок исключает повторный подсчёт.

### Нужен допустимый поворот, а не только точный базис

У точек (1,0,0), (−δ,1,0), (−1,0,0), (δ,−1,0) при δ=0.9ε есть
допустимый четвертьоборот, но точная привязка базиса даёт невязку до
1.8ε. Проверка лишь R₀ теряет ответы. Минимум суммы квадратов тоже
недостаточен: он может не минимизировать наибольшее расстояние.

Сначала пробуем один шаг по трём параметрам вращения, затем взвешенные
итерации наименьших квадратов. Масштабирование осевого параметра через s
устраняет плохую обусловленность полярных облаков. Обновления объединяем
одним нормированным кватернионом и применяем к исходным точкам. Принятие
возможно только по явному собственному повороту, у которого все невязки
не больше ε с указанной защитой от округления.

Перед подразделением сохраняем накопленные веса: умножаем каждый вес на
exp((dᵢ/max d−1)/2), нормируем и повторяем подгонку. Это выравнивает
наибольшие квадраты невязок без колебаний независимого перевзвешивания.
Для отказа используем ε² с запасом сертификата; больший запас свидетеля
относится только к принятию. Ловушка теста **02** — почти антиподальная
тройка с допустимым полуповоротом на границе точности: обычная подгонка
и независимые веса приводят к чрезмерному подразделению.

Неудача подгонки не означает отказ. Кандидата могут исключить попарные
углы. Ещё один сертификат использует веса wᵢ≥0, текущие образы pᵢ и
цели qᵢ. Положим F=Σwᵢ|pᵢ−qᵢ|², g=Σwᵢ pᵢ×(qᵢ−pᵢ),
H=Σwᵢ[(pᵢ·qᵢ)I−(pᵢqᵢᵀ+qᵢpᵢᵀ)/2]. Если λ>0 — консервативная
нижняя граница собственного значения H, то глобальная ошибка не меньше
F−|g|²/λ. Отказ допустим только при превышении ε²Σwᵢ с запасом на
округление. Вращения Якоби и границы Гершгорина дают оценку λ.

### Полный поиск в оставшемся диапазоне

В базисе цели наклон задаётся новым направлением оси
(u,v,1)/√(1+u²+v²). Все подходящие повороты находятся внутри
|u|,|v|≤tan η и |θ|≤2 asin(min(1,e/√(st))). После поворота вокруг оси
получим (x,y,z); вычислим c=1/√(1+u²+v²), d=ux+vy, h=cz−c²d/(1+c).
Наклон даёт (x+uh,y+vh,c(z−d)), сохраняя собственное вращение.

Для полуширин ячейки hu,hv,hθ точка нормы r и поперечного радиуса ρ
отходит от образа центра не больше чем на 2r√(hu²+hv²)+ρhθ. Если хоть
одна невязка центра за вычетом этой границы больше ε+10⁻¹⁶, ячейка
исключается. Иначе проверяем центр явно либо делим параметр с наибольшей
масштабированной полушириной. Приоритетная очередь выбирает наименьшую
нижнюю оценку невязки. Ограничения числа узлов и принятия неразрешённой
ячейки нет. Когда граница движения меньше четверти защиты от округления,
неисключённый центр уже обязан пройти проверку свидетеля.

Каждая допустимая перестановка задаёт перебираемую пару образов. Граница
5ε восстанавливает её цели, а параметрический ящик содержит её поворот.
Каждый принятый кандидат имеет явный собственный свидетель. Необходимые
условия и нижние оценки отбрасывают лишь невозможные варианты. Это даёт
полноту и корректность с оговорённой полосой округления binary64.

В примере подходят тождественное преобразование и два циклических
переставления положительных координатных осей. Остальные три перестановки
меняют ориентацию. Поэтому ответ равен 3.

При суммарном числе B посещённых ячеек время равно
`O(n³+nB+B log(B+1))`: до подразделения каждый из не более n(n−1)
кандидатов требует линейной работы. Для A принятых перестановок и H
живых ячеек память составляет `O(n²+nA+H)`. Подразделение адаптивно и
может быть экспоненциальным; полиномиальная худшая оценка не заявляется.

Исключайте отражения. Приближённые симметрии могут не образовывать группу.
Не подменяйте допустимость точным базисом или неудачей оптимизации.
Используйте векторное произведение для почти параллельных осей, исходные
точки для невязок и ε для конечной проверки. Исчерпание быстрых итераций
должно вести к сертифицированному поиску, а не к отказу.

Для C++ упорядоченные map и set дают оценку
`O(n³ log(n+1)+nB+B log(B+1))`; для остальных версий сохраняется оценка выше.

## Особенности языков

Все пять версий используют стандартные библиотеки и одинаковый полный
поиск. Все обновления используют нормированные кватернионы.
C++ суммирует сертификаты в long double, Go, Java и Rust используют
компенсированное суммирование, Python — math.fsum. Это уменьшает ошибки
округления, не расширяя ε.
