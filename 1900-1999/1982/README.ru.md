# 1982. Минимальный лес с выходом к снабжающим вершинам

[Timus 1982](https://acm.timus.ru/problem.aspx?space=1&num=1982) · сложность 128 · graphs, greedy

Автор оригинальной задачи — Михаил Рубинчик; Открытый командный чемпионат УрФУ по программированию — 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дан полный неориентированный граф из `n` вершин и непустое множество из
`k` уже снабжающих вершин. Выберите рёбра минимальной суммарной
стоимости так, чтобы из каждой вершины можно было попасть хотя бы в одну
снабжающую. Сами снабжающие вершины могут оставаться в разных
компонентах.

Все входные значения целые, `1≤k≤n≤100`. Матрица стоимости симметрична,
её диагональ нулевая, остальные элементы лежат от 1 до `10⁵`.
Ограничения: 0,5 секунды и 64 МБ.

## Входные данные

Даны `n k`, затем `k` различных номеров снабжающих вершин от 1 до `n` и
матрица стоимости размера `n×n`.

## Выходные данные

Минимальная общая стоимость, одно целое число.

## Проверка

Ответы сравниваются по токенам.

## Примеры

Ввод:

```
4 2
1 4
0 2 4 3
2 0 5 2
4 5 0 1
3 2 1 0
```

Вывод:

```
3
```

## Решение

Добавим воображаемую вершину с нулевыми рёбрами ко всем снабжающим.
Минимальное остовное дерево дополненного графа решает задачу. Любая
допустимая исходная сеть становится связной после добавления нулевых
рёбер, поэтому остовное дерево дополненного графа стоит не больше неё.
Обратно, удаление воображаемой вершины из такого дерева оставляет
компоненты, в каждой из которых есть снабжающая вершина, сохраняя
стоимость платных рёбер. Значит, оптимумы совпадают.

Используем плотный алгоритм Прима без явной дополнительной вершины.
Начальные ключи всех снабжающих вершин равны нулю, остальных —
бесконечности. Это состояние после обработки воображаемой вершины.
Каждый раз выбираем неиспользованную вершину с минимальным ключом,
прибавляем ключ к ответу и улучшаем ключи остальных неиспользованных
вершин по её строке матрицы.

Ключ хранит самое дешёвое ребро к уже обработанной части дополненного
дерева. По свойству разреза Прим каждый раз выбирает безопасное ребро.
Инициализация учитывает все существующие источники снабжения. После
обработки всех вершин сумма равна стоимости остовного дерева
дополненного графа и, следовательно, искомому оптимуму.

Полезен и взгляд через лес с корнями. Циклы положительной стоимости
можно удалить. Если дерево содержит несколько снабжающих вершин, удалим
ребро между ними так, чтобы обе части сохранили источник. Поэтому
оптимум может состоять ровно из `k` компонент и `n−k` платных рёбер. При
`k=n` стоимость нулевая.

В примере выбираем ребро 1–2 стоимости 2 и ребро 3–4 стоимости 1. В
каждой компоненте есть снабжающая вершина, сумма равна 3.

Выполняются `n` поисков минимального ключа и `n` просмотров строк по
`O(n)` каждый. Время — `O(n²)`, память под матрицу — `O(n²)`, под ключи
и отметки — ещё `O(n)`. Ответ не больше `(n−k)·10⁵≤9 900 000`.

Подводные камни:

- Нулевые ключи получают все снабжающие вершины независимо от порядка во входе.
- Неснабжающей вершине нельзя заранее присваивать нулевой ключ.
- Новые рёбра между неснабжающими вершинами могут уменьшить стоимость.
- Нулевой диагональный элемент не является бесплатным соединением разных вершин.
- Если все вершины уже снабжающие, платные рёбра не нужны.

## Особенности языков

Все пять версий используют плотный алгоритм Прима с целыми стоимостями.
Матрица хранится полностью. C++, Go, Java и Rust используют широкие
целые типы для ключей и суммы, Python — точные целые.
