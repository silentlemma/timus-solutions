# 1959. Восстановление символов по модам пересекающихся окон

[Timus 1959](https://acm.timus.ru/problem.aspx?space=1&num=1959) · difficulty 1062 · two_pointers

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Mikhail Rubinchik (prepared by Bulat Zaynullin).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для текста s длины n и шаблона p длины m<n суммируются расстояния Хэмминга
между p и всеми подстроками s длины m. Расстояние Хэмминга — число
неравных позиций. В одной из последовательностей могут быть неизвестные
символы; другая целиком известна. Обе могут быть неповреждёнными. Нужно
минимизировать сумму, сохранив известные символы. Лимиты: 1 с, 64 МБ.

## Входные данные

Сначала n, 1≤n≤100000, затем n чисел текста. Далее m, 1≤m<n, и m чисел
шаблона. Совместно условия означают n≥2. Значения 0…100000: положительные
числа — идентификаторы символов, ноль — неизвестный. Нули не встречаются
сразу в обеих последовательностях.

## Выходные данные

Восстановленный текст в первой строке, шаблон во второй. Все значения
1…100000, известные позиции неизменны. При нескольких минимумах подходит
любой. Само расстояние выводить не нужно.

## Проверка

Проверяющая программа убеждается, что известные символы сохранены, а
каждый восстановленный символ — один из самых частых противников в своих
сравнениях; по рассуждению ниже любой такой выбор оптимален, так что при
равенстве годится любой.

## Примеры

```
5
1 2 3 1 2
3
1 2 0
```

```
1 2 3 1 2
1 2 1
```

## Решение

### Независимые подстановки

Поскольку неизвестна только одна сторона, каждый неизвестный символ
сравнивается с фиксированными символами другой. Сравнения двух известных
позиций дают константу. Если неизвестная позиция участвует в t сравнениях,
выбор v даёт t−frequency(v) несовпадений. Берём любую моду — самый частый
символ среди её соперников. Неизвестные позиции не взаимодействуют,
поэтому сумма локальных минимумов глобально оптимальна. Окна непусты,
а их символы положительны: допустимая оптимальная подстановка существует.

Положим g=n−m, индексы с нуля. Позиция j шаблона сравнивается с
s[j…j+g], то есть окном ширины g+1. При движении j вправо удаляем старый
левый элемент и добавляем новый правый.

Позиция i текста сравнивается с j шаблона, где i=j+offset,
0≤offset≤g и 0≤j<m. Получаем окно
p[max(0,i−g)…min(m−1,i)]. Обе границы не убывают. Для каждого i добавляем
p[i], если i<m; удаляем p[i−g−1], если i>g; затем при s[i]=0 берём моду.
Окно сначала растёт, затем сдвигается или стоит на месте, потом сжимается.
Известная противоположная последовательность не изменяется.

### Мода за постоянное время

Храним frequency[v]. Символы с положительной частотой f связаны в двусвязный
список: previous[v], following[v], голова head[f]. Ноль — только пустая
ссылка; символы нулевой частоты в списки не входят. Ещё храним максимальную
непустую частоту maximum.

Обновление удаляет символ из старого списка, меняет частоту на единицу
и вставляет в голову нового списка, если частота положительна. Если
она больше maximum, повышаем maximum; иначе уменьшаем его, пока голова
пуста. При одном корректном обновлении максимум падает не более чем на
один: после удаления остаётся тот же символ с частотой f−1, кроме f=1.
Поэтому обновление и запрос O(1). Значение head[maximum] — допустимая мода.

Для неизвестного шаблона достаточно голов до g+1. Для неизвестного текста
выделяем до m: добавление правой границы до удаления левой может временно
увеличить окно на один относительно его окончательной ширины.

Время и память O(n+m+σ), где σ — максимальный входной ID, σ≤100000.
Изменений границ O(n+m), обращения к массивам прямые. Нельзя брать
глобальную моду вместо оконной, забывать включённые концы и ширину g+1,
учитывать нули в частотах или менять известные позиции. Суммируются все
наложения, а не выбирается лучшее. Независимость опирается на повреждение
только одной стороны.

Программы не вычисляют численную сумму. Частоты помещаются в int32, но
полная сумма может превысить 2³¹−1: число сравниваемых пар достигает
2 500 050 000. Проверяющий расчёт использует широкие целые.

## Особенности языков

C++, Go 1.14, Java 8 и Rust 1.75 используют примитивные массивы/векторы,
Java без объектов для каждого символа. Rust только со стандартной
библиотекой. Python хранит индексируемые списки; CPython проходит с
запасом. Если нулей нет нигде, все версии возвращают исходные данные
без построения частотных списков.
