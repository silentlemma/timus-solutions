# 1944. Карта из символов с приоритетом точек

[Timus 1944](https://acm.timus.ru/problem.aspx?space=1&num=1944) · difficulty 238 · implementation

Original problem from Open Ural FU Personal Contest 2012 | by Andrey Demidov.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Изобразить различные целочисленные точки на декартовой сетке: x растёт
вправо, y вверх, одна ячейка соответствует одной паре координат.
Точка обозначается *, начало +, ось x знаком -, ось y знаком |,
остальные ячейки точкой. Звёздочка имеет приоритет над осями и началом;
оси могут полностью скрыться под точками. Нужен минимальный прямоугольник,
содержащий все точки и начало. Ограничения: 1 секунда, 64 МБ.

## Входные данные

n, 1≤n≤250, затем n различных целых пар (x,y), −100≤x,y≤100.
Совпадающих точек нет.

## Выходные данные

Строки идут от U=max(0,max y) до D=min(0,min y) включительно, вниз.
Столбцы — от L=min(0,min x) до R=max(0,max x). В каждой строке
W=R−L+1 символов, всего H=U−D+1 строк. Вывести только рисунок.

## Проверка

Сравниваем каждый символ и перевод строки всего рисунка, а не только
токены. Оба новых публикуемых исходника прошли все 26 входов репозитория
и 69 независимых дополнительных входов в Docker на целевых компиляторах.
Фактический вывод и код завершения каждой дополнительной проверки заново
сверены с независимым поклеточным эталоном: сначала занятые точки, затем
начало координат, оси и фон. Проверены начало, одна строка или столбец,
закрытые оси, все четверти, ±100, 250 точек, явный плюс, CRLF и EOF.
Отдельный Python-кандидат также прошёл эти 69 целевых запусков и 2048
запусков на хосте, включая все непустые подмножества сетки 3×3. Эти 2048
запусков не выдаются за проверки C++ или Java. У всех трёх кандидатов
есть собственный Accepted точных байтов, но критерий допуска отдельный.

## Решение

Изначально все четыре границы равны нулю, затем расширяются по точкам.
Координата (x,y) отображается в row=U−y, column=x−L. Это биекция
прямоугольника на индексы 0..H−1 и 0..W−1 с нужной ориентацией.

Заполняем сетку H×W точками. В столбце −L каждой строки ставим |.
Строку U заполняем -, затем её столбец −L заменяем на +. В конце
каждую заданную точку отмечаем * по вычисленным индексам. Выводим
строки по порядку индексов.

Начальные точки обозначают фон. Вертикальный и горизонтальный проходы
попадают ровно на x=0 и y=0. В пересечении ставится +, а последний
проход обеспечивает приоритет всех заданных точек. Различные точки
не накладываются. Нулевые исходные границы включают начало даже при
точках в одной четверти, и меньшая рамка не содержит все необходимые
координаты. Поэтому верны размеры, символы и направление, в том числе
при одной строке или одном столбце.

Время и память O(n+WH), с хранением входа и результата. W,H≤201,
максимальный вывод H(W+1)≤40602 ASCII-байта с LF — меньше 64 КиБ.
Границам и индексам достаточно обычного знакового целого.

Ноль входит в оба диапазона. При увеличении номера строки y уменьшается.
Не перепутать смещения строк и столбцов. В начале стоит +, только если
там нет точки; на оси точка тоже остаётся *. Не добавлять подписи,
пробелы, рамки или поля.

## Оптимизированные решения

`1944_implementation_bitmask.java`. Вместо сортировки упакованных точек используется фиксированная сетка масок: четыре long на каждую из 201 строки. Точки отмечаются напрямую, рамка включает начало координат, установленные биты рисуются поверх осей, поэтому звёздочки приоритетнее. Маски занимают 6432 байта; полный вывод до 40602 байт сохраняется ради одного вызова записи. При K отмеченных клетках и размерах вывода W/H время O(N+WH+4H+K), память O(201*4+WH). Повторные точки безвредны. Метод implementation_bitmask обменивает фиксированную сетку и полный вывод на прежнюю разреженную сортировку с повторным использованием строк; обе версии и учебный исходник сохранены.

Точный исходник: Java 1.8 Accepted #11327417: 0.109 s / 440 KB. Сохранённые места в группе компилятора от 2026-11-20, время затем память: 8/48; 1/48. Строгий допуск учитывает только время при памяти меньше 1024 КБ: первые десять или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка — первого места по обеим метрикам. Сохранённый прежний вариант имеет собственную парную посылку #11308715 (Java 1.8): 0.125 s / 476 KB; замеры и рантаймы не смешиваются. Все учебные исходники сохранены без изменений.

- `1944_implementation_bitmask.java`: 0.109 s / 440 KB; сохранённая учебная база `1944_implementation.java` (Java 1.8): 0.125 s / 844 KB.

`1944_implementation_sorting.rs`. Массив рисунка W×H и полный буфер вывода заменены сортировкой различных точек по убыванию y, затем возрастанию x. Координаты вывода обходятся вместе с указателем на точку; звёздочка имеет приоритет над началом и осями. Точки хранятся двумя i16, что безопасно при обещанных [-100,100], границы включают начало координат. Время O(n log n+WH), память O(n): сортировка заменяет выделение поля и вывода. Другая реализация через сортировку имеет отдельное имя; простой исходник с сеткой сохранён.

По сравнению с `1944_implementation.rs`: время 0.031 s → 0.015 s; память 348 KB → 68 KB.

Рисунок выводится по строкам вместо выделения полной сетки. Упакованные координаты точек сортируются так, чтобы точки одной строки шли подряд. Строка заполняется фоном и видимой осью; при необходимости строятся горизонтальная ось и начало координат, после чего последними накладываются точки. Сохраняются точный приоритет символов и убывающий порядок вертикали. Буфер строки переиспользуется: память зависит от точек и ширины, а не площади рисунка. Сортировка не устраняет время вывода каждой клетки.

- `1944_implementation_optimized.cpp`: 0.015 s / 116 KB; база `1944_implementation.cpp`: 0.015 s / 472 KB; изменение относительно базы: время -0.0%, память -75.4%.
- `1944_implementation_optimized.java`: 0.125 s / 476 KB; база `1944_implementation.java`: 0.125 s / 844 KB; изменение относительно базы: время -0.0%, память -43.6%.
- `1944_implementation_optimized.py`: 0.140 s / 332 KB; база `1944_implementation.py`: 0.093 s / 636 KB; изменение относительно базы: время +50.5%, память -47.8%.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1944_implementation_sorting.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
