# 1957. Все возможные итоговые таблицы

[Timus 1957](https://acm.timus.ru/problem.aspx?space=1&num=1957) · difficulty 4747 · math

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Mikhail Rubinchik (prepared by Denis Dublennykh).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Четыре команды проводят по одному матчу с каждой другой: всего шесть игр.
Результаты части игр известны; в оставшихся число голов не ограничено.
Победа даёт 3 очка, ничья по 1, поражение 0. Сначала сравниваются очки,
затем разность забитых и пропущенных голов. При равенстве обоих показателей
порядок может быть любым по жребию. Перечислить все итоговые таблицы.
Ограничения: 1 с, 64 МБ.

## Входные данные

Сначала число завершённых игр n, 0≤n≤6. Далее n строк a,b,c,d:
1≤a<b≤4, 0≤c,d≤10, где a забила c голов, b — d. Пары не повторяются.
Ограничение 10 относится только к уже сыгранным матчам.

## Выходные данные

Число различных порядков m, 1≤m≤24, затем m перестановок 1,2,3,4:
номера команд от первого места до четвёртого. Каждую вывести один раз,
в лексикографическом порядке. Исходы различаются местами, а не счетами.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
5
1 2 1 0
1 3 2 1
1 4 3 2
2 3 1 0
2 4 5 4
```

```
2
1 2 3 4
1 2 4 3
```

## Решение

Перебираем три результата каждой оставшейся игры: ничья, победа первой,
победа второй. Очки полностью определены. Ничья не меняет разности голов.
Для решающего матча задаём преимущество победителя 1+x, где x — целое
неотрицательное; подходит счёт (1+x):0. Единицу добавляем к базовым разностям
g, а величины x оставляем неизвестными.

Перебираем все 24 порядка. Если у соседней нижней команды больше очков,
порядок невозможен. Для соседей a перед b с равными очками требуем
final_g[a]≥final_g[b]. Это не более трёх неравенств, вместе с x≥0 — система
A·x≤b максимум с шестью целыми переменными. Равенство допускается жребием.
Соседних сравнений достаточно по транзитивности в каждом блоке равных очков.

### Точная целочисленная проверка

Каждое неравенство делим на положительный НОД h коэффициентов, правую часть
b заменяем floor(b/h). Для целых переменных это эквивалентно, в том числе
при отрицательном b. Нулевая левая часть с отрицательной правой невозможна,
иначе строка лишняя. Среди одинаковых векторов оставляем наименьшую границу.

Выбираем переменную x, у которой все положительные коэффициенты равны 1
либо все отрицательные равны −1. Нижнюю и верхнюю строки запишем как
−p·x+L≤bL и q·x+U≤bU, p,q>0. Удаляем x, добавляя для каждой пары
q·L+p·U≤q·bL+p·bU и сохраняя строки без x.

Необходимость следует сложением. Для достаточности: если все нижние
коэффициенты −1, нижние границы целые при целых остальных переменных.
Выбираем максимальную из них; комбинированные строки гарантируют выполнение
всех верхних. Если единичны верхние коэффициенты, выбираем минимальную
целую верхнюю границу. Отсутствующая сторона не ограничена. Поэтому
каждое исключение сохраняет именно целочисленную разрешимость. Обычное
исключение Фурье—Моцкина над вещественными числами этого не гарантирует.
Снова нормализуем и повторяем; непротиворечивые константы означают успех.

Наличие подходящей переменной — конечное свойство коэффициентов задачи.
Перенумеруем команды в порядке кандидата. Каждая из шести пар либо не
даёт переменной, либо даёт одно из двух направлений преимущества: 3⁶
вариантов. Три соседних сравнения выбираются маской равных очков: 2³
варианта. Скрипт [tests/gen.py](tests/gen.py) исчерпывающе проверяет все
5832 семейства и каждый допустимый путь исключений: 13 286 различных
промежуточных систем, 44 054 шага, ни одного тупика. Это охватывает любой
порядок переменных и выбор при равной стоимости шага. Константы не влияют
на путь коэффициентов: НОД, объединение параллельных строк и проекция
определяются коэффициентами; противоречие лишь раньше завершает проверку.
Это исполняемое конечное доказательство специального свойства системы.

Итак, сохраняется ровно та перестановка, которую реализуют целые будущие
счета. Печатаем сохранённые в лексикографическом порядке.

Для r=6−n неизвестных матчей не более 3ʳ вариантов результатов и 24 порядков.
Исключений максимум шесть, нормализованных строк максимум 14, коэффициенты
по модулю не больше 31. Для четырёх команд работа исключения E постоянна:
время O(3ʳ·24·E), память O(1). До деления коэффициенты не больше 2·31².
Из начальных правых частей |b|≤66 после шести шагов получаем
66·62⁶<2⁴²; хватает знакового int64. Делить отрицательные границы нужно
с округлением вниз. Нельзя ограничивать будущие голы десятью, забывать
разность мячей и жребий или заменять целые преимущества вещественными.

## Особенности языков

Во всех версиях точное целочисленное исключение. Python использует длинные
целые, остальные — int64. Go 1.14 и Java 8 сами строят перестановки.
Java применяет Math.floorDiv, Rust — div_euclid с положительным делителем,
C++ и Go поправляют деление при отрицательном остатке. Rust использует
только стандартную библиотеку. Выбор CPython подтверждается замерами.
