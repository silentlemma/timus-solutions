# 1905. Routes Through Space-Time Events

[Timus 1905](https://acm.timus.ru/problem.aspx?space=1&num=1905) · difficulty 1131 · bfs

Original problem by Dmitry Ivankov, from Ural Championship 2012.

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

航班连接指定地点及出发、到达时刻，到达可以早于出发。从给定地点和时刻
出发，在指定目标时刻到达目标地点，可以向未来等待。任务完成前，同一地点
的两次独立访问不能占据相同瞬间，等待期间也算。输出任意合法航班序列。
时限 3 秒，内存限制 64 MB。

## 输入

首先 n、m，1 ≤ n ≤ 100 000、0 ≤ m ≤ 100 000。接着 m 行分别给出
出发地点、到达地点、出发时间、到达时间。地点编号 1,…,n，所有时间为
0 到 10⁶ 的整数。最后给出起点、目标地点、当前时间、目标时间。
航班按输入顺序从 1 编号。

## 输出

无解输出 `Impossible`。否则输出 k，再输出依次使用的 k 个航班编号。
允许零航班：输出 0 和空的第二行。任意合法路线均可。

## 评测方式

构造检查器验证编号、地点、可登机时间和不晚于目标的到达时间，再等待到
目标事件。它收集全部闭访问区间，按地点和时间排序，拒绝任何相交，包括
公共端点。任何合法路线都被接受。

## 样例

```
4 3
1 2 10 20
2 4 50 20
4 3 20 30
1 3 10 30
```

```
3
1 2 3
```

## 解法

把所有航班端点及起点、终点的不同 (地点,时间) 建为顶点，相同事件必须合并。
每个地点内按时间排序，从事件连向下一个事件作为等待边。
每条航班从出发事件连向到达事件，即使它使时间倒退。

从起点 BFS，首次访问时记录父顶点及航班编号，等待边记为 0。
目标不可达则输出 `Impossible`；否则逆向追踪父链，只保留正航班编号，
再反转即可。

为什么不需要把全部历史加入状态？每条真实路线都对应图上的游走，因为
等待经过所有中间事件，所以不可达时一定无解。反之，可达目标有一条简单
顶点路径，BFS 父树正好提供它。假如同一地点的两次独立访问区间重叠，
某次访问的端点必在另一区间内。这个端点是航班、起点或终点事件，另一次
等待链也必须经过该顶点，导致顶点重复，与简单路径矛盾。因此输出不会
自相撞。连续等待边属于同一次访问，同一时刻的换乘只使用公共顶点一次。

用 `地点·B+时间` 编码，B=1 000 001。排序并原地去重，以二分查找映射
航班端点。排序后各地点形成连续组，若键除以 B 的商相同，则 i→i+1
是等待边，不必显式保存。航班邻接表用 head/next 数组表示。

顶点最多 2m+2，边最多 3m+1。排序和二分总时间
`O((m+1) log(m+2))`，BFS 和恢复为线性；空间 `O(m+1)`。
无事件地点不需要单独分配存储。

示例在地点 2 等待到 50，再倒退到地点 4 的时刻 20，立即换乘最后的航班。

## 各语言说明

编码键最大超过 10¹¹，必须使用 64 位整数；顶点下标用 32 位即可。
C++、Go、Java、Rust 使用基本类型数组或向量。Python 用紧凑 `array`
存放图下标和队列，仅保留一个整数键列表；原地去重，并在 BFS 前释放
输入词元生成器以控制峰值内存。Python 使用 CPython 3.12。

不要要求到达不早于出发。即使没有对应航班，也要加入起点和终点事件。
等待只能向未来，相同事件要合并，等待期间的重叠同样不允许。

在 3048 个小测试上，答案与直接检查碰撞的航班序列搜索一致；检查器接受五条合法路线并拒绝 16 条错误路线。
