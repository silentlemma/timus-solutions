# 1905. Routes Through Space-Time Events

[Timus 1905](https://acm.timus.ru/problem.aspx?space=1&num=1905) · difficulty 1131 · bfs

Original problem by Dmitry Ivankov, from Ural Championship 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Рейсы соединяют пункты в заданные моменты вылета и прилёта; прилёт
может предшествовать вылету. Из заданного пункта и момента нужно попасть
в целевой пункт к его точному моменту, при необходимости ожидая вперёд.
До завершения два разных посещения одного пункта не должны содержать
один и тот же момент, в том числе при ожидании. Выведите любой маршрут.
Ограничения: 3 секунды и 64 МБ.

## Входные данные

Сначала n и m: 1 ≤ n ≤ 100 000, 0 ≤ m ≤ 100 000. Далее m четвёрок:
пункт вылета, пункт прилёта, время вылета, время прилёта. Пункты имеют
номера 1,…,n, все времена целые от 0 до 10⁶. Последняя строка задаёт
начальный пункт, целевой пункт, текущее и целевое время. Номер рейса —
его индекс во входном списке, начиная с 1.

## Выходные данные

`Impossible`, если маршрута нет. Иначе k и k номеров рейсов в порядке
использования. Нулевой маршрут допустим: 0 и пустая вторая строка.
Подходит любой допустимый ответ.

## Проверка

Проверяются номера, пункты, возможность посадки и прилёт не позже цели.
Ожидание доводит до точного целевого момента. Проверяющая программа собирает
замкнутые интервалы всех посещений, сортирует по пункту и времени и
отклоняет пересечения, включая общий конец.
Принимается любой допустимый маршрут.

## Примеры

```
4 3
1 2 10 20
2 4 50 20
4 3 20 30
1 3 10 30
```

```
3
1 2 3
```

## Решение

Создадим вершину для каждой различной пары (пункт,время) среди концов
рейсов, начального и целевого событий. Совпадающие события объединяются.
В каждом пункте отсортируем события и проведём ребро ожидания к следующему
по времени. Добавим направленные рёбра рейсов, включая перемещения назад.

Запустим BFS из начального события. При первом посещении запомним предка
и номер использованного рейса либо 0 для ожидания. Если цель недостижима,
выведем `Impossible`. Иначе идём по предкам назад, оставляем положительные
номера рейсов и разворачиваем их.

Почему достаточно обычной достижимости? Любой физический маршрут задаёт
путь с возможными повторениями в графе: ожидание проходит все промежуточные
события. Если граф недостижим, реального маршрута нет. Обратно, для
достижимой цели BFS даёт простой путь по дереву предков. Если два разных
посещения пункта пересекались во времени, конец одного замкнутого интервала
лежал бы в другом. Этот конец — событие вылета, прилёта, старта или цели;
цепочка ожидания другого посещения тоже проходит его вершину. Получилось
бы повторение вершины, противоречащее простоте пути. Поэтому столкновения
нет. Последовательные рёбра ожидания — одно непрерывное посещение;
пересадка в тот же момент использует общую вершину один раз.

Кодируем событие числом `пункт·B+время`, B=1 000 001. Сортируем ключи,
удаляем повторы, индексы концов рейса находим бинарным поиском. В общем
порядке события сгруппированы по пунктам: ребро ожидания i→i+1 существует,
если частные обоих ключей при делении на B совпадают. Храним только
рёбра рейсов через массивы головы списка и следующего ребра.

Вершин не больше 2m+2, рёбер не больше 3m+1. Сортировка и поиски требуют
`O((m+1) log(m+2))` времени, BFS и восстановление линейны. Память `O(m+1)`;
для пунктов без событий ничего выделять не нужно.

В примере ждём в пункте 2 до времени 50, перемещаемся назад в пункт 4
ко времени 20, затем сразу пересаживаемся на последний рейс.

## Особенности языков

Ключам нужен 64-битный тип: максимум превышает 10¹¹. Индексам хватает
32 бит. C++, Go, Java и Rust используют массивы/векторы простых типов.
Python хранит индексы и очередь в компактных `array`, оставляя один
список ключей; удаляет повторы на месте и освобождает генератор токенов
до BFS, снижая пик памяти. Используется CPython 3.12.

Нельзя запрещать прилёт раньше вылета. Старт и цель добавляются даже
без соответствующих рейсов. Ожидание идёт только вперёд, одинаковые
события объединяются, пересечения во время ожидания тоже запрещены.

Ответы совпадают с перебором последовательностей рейсов с прямой
проверкой столкновений на 3048 малых тестах; проверяющая программа
принимает пять верных маршрутов и отклоняет 16 ошибочных.
