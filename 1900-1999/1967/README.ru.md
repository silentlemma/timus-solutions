# 1967. Минимальная десятичная склейка двоичных блоков

[Timus 1967](https://acm.timus.ru/problem.aspx?space=1&num=1967) · difficulty 5141 · greedy

Автор оригинальной задачи — Илья Звигинцев; Открытое личное первенство УрФУ по программированию 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Склеим двоичные записи чисел 1,2,…,n в строку S. Разобьём её на непустые
блоки, разрешая разрез только перед единицей: ведущих нулей быть не может.
Каждый блок переводится в положительное десятичное число, затем записи
склеиваются в прежнем порядке. Минимизировать полученное целое число и
вывести любое оптимальное разбиение длинами блоков в битах. Начальная
запись числа 1 включена в S. Ограничения: 1 секунда, 64 МБ.

## Входные данные

Одно число n, 2≤n≤100 000.

## Выходные данные

Две строки: количество блоков, затем их положительные длины в битах
слева направо. Блоки должны полностью покрыть S. Принимается любое
разбиение с минимальной десятичной склейкой.

## Проверка

Проверяющая программа сверяет число блоков, общую длину и допустимость
начал, а оптимальность проверяет по критерию обмена, доказанному ниже;
принимается любое оптимальное разбиение.

## Примеры

```
5
```

```
2
1 10
```

## Решение

Для n=5 имеем S=11011100101. Суффикс из четырёх бит 0101 начинается
с нуля и недопустим. Семибитный 1100101 равен 101, что не меньше 100.
Десятибитный 1011100101 равен 741<1000. Правило ниже выбирает эти
последние десять бит, оставляя первую единицу отдельно. Результат
1||741=1741, тогда как весь блок дал бы 1765.

### Строгое правило обмена

Пусть соседние двоичные блоки A,B задают положительные числа a,b.
У B длина q бит, у b — d десятичных цифр. Отдельные блоки дают
a·10^d+b, объединённый — a·2^q+b. Поэтому разрез строго улучшает
результат ровно при 10^d<2^q. Назовём такой B выгодным. Иначе строго
выгоднее объединение. Равенства нет: положительная степень десяти
содержит множитель пять.

Замена локального положительного десятичного числа меньшим уменьшает
и всю склейку с фиксированными внешними блоками. Более короткая запись
уменьшает общее число цифр, равная по длине меньшая выигрывает
лексикографически после того же префикса. Правило действует внутри
произвольного разбиения.

### Последний блок вынужден

В оптимальном ответе из нескольких блоков последний обязан быть выгодным,
иначе слияние последних двух уменьшит число. В нём не может быть более
короткого выгодного суффикса: разрез перед ним тоже уменьшил бы результат.
Значит, последний блок — кратчайший собственный выгодный суффикс всей
оставшейся строки. Ответ из одного блока также улучшается разрезом,
если такой суффикс существует.

Выбираем этот суффикс и решаем ту же задачу для префикса. Сам префикс
должен быть оптимален: приписывание фиксированного последнего числа
сохраняет числовой порядок. Если собственного выгодного суффикса нет,
у любого многоблочного ответа последний блок был бы невыгодным.
Весь префикс оставляем одним блоком. Так доказана жадность для любой
двоичной строки, начинающейся с единицы.

### Поиск без погрешностей

Для q-битного b выполняется 2^(q−1)≤b<2^q. Если блок выгоден, порог
T=10^d лежит между b и 2^q, то есть двоичная длина T равна q.
Обратно, если 10^d имеет q бит и q-битный суффикс меньше него, то
b≥2^(q−1)>10^(d−1): у b действительно d десятичных цифр и он выгоден.

Перебираем T=10,100,1000,… по возрастанию двоичной длины. Суффикс должен
начинаться с единицы и быть лексикографически строго меньше двоичной
записи T той же длины. Первое совпадение условия даёт кратчайший
выгодный суффикс. Если длина порога достигла длины всего остатка,
собственного подходящего суффикса нет. Снимаем блоки справа налево,
в конце разворачиваем список длин.

Степени наращиваются и сохраняются по мере надобности. Нативные версии
умножают двоичную строку на десять переносами справа налево; Python
использует целые числа и bin. Ограничения длины блока, машинной разрядности,
приближённые логарифмы и перевод итогового гигантского числа не нужны.

Пусть L=|S|, K — наибольшая проверенная двоичная длина порога. Грубая
верхняя оценка: время `O(n log n + L K²)`, память `O(L+K²)`, включая
кеш степеней и вывод. Один поиск перебирает `O(K)` порогов и сравнивает
до `O(K²)` бит. Построение S занимает `O(n log n)`.

Для всего диапазона `python tests/gen.py 100000 certify` перебирает все
1 568 946 концов префиксов строки при n=100 000 и суммирует работу пути
для каждого допустимого n. Получено K≤226, не более 461 145 проверок
порогов, 2 780 158 сравниваемых символов по верхней оценке и 131 447
блоков. Программа не использует эти числа как предел и не обрезает
поиск. Корректность следует из обмена, а воспроизводимая проверка
оценивает объём работы на всём диапазоне входов.

Сначала сравнивается количество десятичных цифр, затем лексикографический
порядок. Не забываем исходную единицу. Разрез перед нулём запрещён,
сравнение с 10^d строгое. Суффиксы проверяем от коротких к длинным,
ответ разворачиваем. Для порогов не хватает ни 64, ни 128 бит; длинные
блоки встречаются уже на небольших n. Нельзя вводить угаданный предел
длины или использовать неточные логарифмы.

## Особенности языков

C++, Go 1.14, Java 8 и Rust 1.75 хранят степени двоичными строками или
массивами байтов и умножают на десять с небольшим переносом. Python 3.12
использует точные целые и bin, не переводя гигантский результат в десятичный
вид. Java сравнивает символы на месте без создания подстрок. Во всех
версиях стандартная библиотека и отсутствие рекурсии.
