# 1977. Накопление энергии и треугольное распределение

[Timus 1977](https://acm.timus.ru/problem.aspx?space=1&num=1977) · сложность 2366 · segment_tree, simulation

Автор оригинальной задачи — Денис Дублённых; XVII Открытый чемпионат Урала по спортивному программированию (май, 2013).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `n` пронумерованных секций и хранилище. В начальный момент вся
энергия равна нулю. Каждая секция получает `p` единиц энергии за единицу
времени. События происходят в различные целочисленные моменты в
возрастающем порядке. Операция `save l r` переносит всю энергию
включительного отрезка `[l,r]` в хранилище и выводит новый запас
хранилища. Операция `enforce i d` расходует весь запас: секция `j`
получает `x(d−|j−i|)` при `|j−i|<d`, где `x=запас/d²`. Эта добавка
суммируется с уже имеющейся энергией; хранилище становится пустым.

Ограничения: `1≤n≤10⁹`, `1≤p≤100`, `1≤q≤10⁵`, `0≤t≤10⁹`. Для сохранения
`1≤l≤r≤n`; для распределения `1≤d≤min(i,n+1−i)`. Лимиты: 2 секунды и 64
МБ.

## Входные данные

Первая строка содержит `n p`, следующая — `q`. Далее идут `q` строк вида
`t save l r` или `t enforce i d`, упорядоченных по времени.

## Выходные данные

После каждого сохранения выведите запас хранилища. Операции
распределения ничего не выводят.

## Проверка

Числа сравниваются с абсолютной или относительной погрешностью 10⁻⁶.

## Примеры

Ввод:

```
5 1
4
2 save 4 5
3 enforce 2 2
4 save 3 5
5 enforce 3 3
```

Вывод:

```
4.000000
9.000000
```

## Решение

Сначала прочитаем события и сожмём координаты границ, на которых
меняется формула обновления. Добавим `1,n+1`; сохранение добавляет
`l,r+1`, распределение — `i−d+1,i+1,i+d`. Лист представляет все целые
секции между соседними границами и сохраняет их настоящую суммарную
длину.

В дереве отрезков храним суммы энергии. Отложенное обновление узла
состоит из флага очистки и добавляемой линейной функции, заданной
значениями на первой и последней секциях. Если эти значения равны `a,b`,
а длина узла равна `L`, сумма увеличивается на `(a+b)L/2`. Между
событиями в моменты `s,t` добавляем корню постоянную `p(t−s)`.

Пусть длины детей равны `A,B`. При спуске линейной добавки последнее
значение левого ребёнка равно `(aB+b(A−1))/(A+B−1)`, а первое значение
правого — `(a(B−1)+bA)/(A+B−1)`. Здесь используются суммы
неотрицательных величин. Постоянная добавка обрабатывается отдельно.
Очистку спускаем раньше добавок. Хранение значений на концах позволяет
избежать вычитания больших близких слагаемых вида «наклон × координата»
и «свободный член».

Сохранение собирает суммы полностью покрытых узлов и очищает их. После
частичного обхода сумма родителя заново складывается из сумм детей.
Распределение разбивается на возрастающую прогрессию на `[i−d+1,i]` и
убывающую на `[i+1,i+d−1]`. Целые веса вычисляем до умножения на
`запас/d²`, после чего обнуляем запас.

Сумма весов равна `1+…+d+(d−1)+…+1=d²`, поэтому распределяется ровно
весь запас. Инвариант дерева: сумма узла уже учитывает его отложенную
добавку, которую дети получают при посещении. Рост, добавление
прогрессии и сбор с очисткой сохраняют инвариант. Следовательно, все
выводимые запасы верны.

В примере первое сохранение собирает две секции с энергией 2 и даёт 4.
После единицы роста и распределения с радиусом два энергии равны
`(4,5,4,1,1)`. Ещё через единицу времени секции 3–5 дают `5+2+2=9`.
Последнее событие ничего не выводит.

Для `m=O(q)` сжатых интервалов четыре версии на компилируемых языках
требуют `O(q log q)` времени и `O(q)` памяти. Обход в прямом порядке
позволяет хранить ровно `2m−1` узлов: левый ребёнок следует за
родителем, правый расположен после всего левого поддерева.

### Python: передача энергии будущим сохранениям

Файл Python `1977_segment_tree_simulation.py` учитывает естественный
рост отдельно от распределённой энергии. Для сжатия нужны только `1,n+1`
и границы сохранений `l,r+1`. Любое сохранение забирает ячейку целиком
или не затрагивает её. Распределение может пересекать лишь часть ячейки:
достаточно сложить соответствующий участок арифметической прогрессии,
поскольку последующие сохранения не различают секции внутри ячейки.

Для распределённой энергии пройдём события в обратном порядке и пометим
каждую секцию первым будущим сохранением либо отсутствием получателя,
если секция больше не сохраняется. При сохранении заменим метки на его
отрезке меткой этого события. Это верно: для любого более раннего
события данное сохранение наступит раньше всех уже записанных
получателей на отрезке. В персистентном дереве отрезков версии совместно
используют неизменившиеся маршруты; узел сворачивается, если у всего его
отрезка один получатель. Для каждого распределения запоминаем нужную
версию.

Теперь обрабатываем события по времени с настоящим запасом хранилища.
Две линейные половины распределения направляем по сохранённой версии.
Если получатель единственный, сразу прибавляем ему сумму прогрессии;
иначе в полностью покрытом узле накапливаем значения на концах. При
сохранении, завершающем действие маршрута, передаём накопленную функцию
записанным детям с помощью описанной выше интерполяции неотрицательных
значений, затем обрабатываем детей. Каждая добавка попадает ровно в
первое сохранение; добавки без получателя можно отбросить. Числовые
буферы последовательных версий одного пространственного узла можно
совмещать: старая версия опустошается до поступления энергии в новую.

Для естественного роста достаточно карты интервалов с одинаковым
временем последнего сохранения, изначально нулевым. Участок длины `L`,
последний раз сохранённый в момент `s`, в момент `t` отдаёт `pL(t−s)`;
затем его время меняется на `t`. Разбиваем интервалы на границах
сохранения и удаляем перезаписанные внутренние границы. Так учитывается
ровно рост со времени предыдущего сохранения. Иерархические битовые
множества находят действующие границы. Каждое сохранение создаёт не
более двух границ, а удаление границы относится к её вставке. Если
распределений с ненулевым запасом нет, достаточно только этой карты.

Перед построением персистентных маршрутов программа пытается составить
явный список переносов по заранее известным событиям. Обратный проход по
карте интервалов находит первое будущее сохранение для каждого участка
распределения. Ребро к этому сохранению получает вес, равный
целочисленной сумме треугольных весов участка. Тот же проход учитывает
естественный рост между последовательными сохранениями или от нулевого
момента до первого сохранения. В прямом проходе вес ребра умножается на
текущий запас хранилища, делённый на `d²`. Получаются те же переносы
энергии к тем же сохранениям, что и в дереве маршрутов. Время и память
этой попытки ограничены; если карта слишком раздроблена, результат
отбрасывается и используется общий метод.

Небольшие части стены выгоднее моделировать напрямую. Исключив
сохранения всей стены, объединим пересекающиеся отрезки операций в
компоненты. Если в каждой компоненте мало сжатых ячеек, храним для
каждой ячейки сумму распределённой энергии и время последнего
сохранения. Все события обрабатываем по порядку с общим хранилищем. Для
распределения суммируем веса на пересечении с ячейкой. Суммы достаточно,
поскольку сохранение не делит ячейку; между сохранениями всей стены
пространственного взаимодействия компонент нет.

Ещё один быстрый вариант предназначен для сохранений, охватывающих мало
сжатых ячеек. Дерево со значениями на концах накапливает добавки без
сумм поддеревьев. Сохранение спускает отложенные добавки, обходит и
очищает свой короткий отрезок, а рост вычисляет по временам посещённых
ячеек. Результат совпадает с запросом суммы и очистки. Сохранение всей
стены по закону сохранения энергии устанавливает запас равным `npt`, то
есть всей энергии, возникшей к этому моменту, и сбрасывает состояние
стены. При моделировании компонент сброс можно отложить до следующего
обращения к компоненте. Вариант для узких сохранений выбирается только
при ограниченной суммарной стоимости полных сбросов.

При `m=O(q)` сжатых ячейках общий метод требует `O(q log q)` времени и
`O(q log q)` памяти. Сохранение создаёт не более `O(log m)` узлов
маршрутов, распределение добавляет два линейных отрезка за `O(log m)`, а
каждый узел маршрута передаёт накопленную энергию один раз. Числовые
буферы занимают `O(q)` памяти. Ограничение попытки с явными переносами и
проверки размеров и объёма работы прямого моделирования сохраняют эти
оценки в худшем случае при данных ограничениях. Суммы энергии
объединяются сложением неотрицательных величин, а линейные функции
делятся с помощью интерполяции значений на концах. Это позволяет не
вычитать близкие большие количества энергии.

Подводные камни:

- Хранилище накапливает результаты сохранений и очищается только распределением.
- Рост происходит до события с соответствующей меткой времени; время
  ноль допустимо.
- Радиус один затрагивает только центр; убывающая половина может быть пустой.
- Сжатие не должно заменять физическую длину каждого интервала единицей.
- После очистки пересчитывайте родителя сложением детей: вычитание
  близких больших сумм может уничтожить малый остаток.
- Глобальные вещественные коэффициенты прямой могут приводить к потере
  точности на больших координатах.

## Особенности языков

C++, Go, Java и Rust используют дерево с вещественными значениями на
концах. Java обходит дерево явным переиспользуемым стеком и выводит
научную запись с десятью значащими цифрами без создания строки для
каждого вещественного числа.

Python использует двойную точность и описанные выше маршруты и
моделирование. Текущее решение принято на PyPy 3.10 x64 за 1.484 с с
расходом памяти 37 252 КБ при лимитах 2 секунды и 64 МБ. Предыдущие
версии превышали ограничение времени на 7-м тесте судьи под CPython и на
12-м под PyPy.
