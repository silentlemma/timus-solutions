# 1991. Неиспользованные запасы и оставшиеся цели

[Timus 1991](https://acm.timus.ru/problem.aspx?space=1&num=1991) · сложность 48 · implementation

Автор оригинальной задачи — Денис Дублённых; подготовка — Егор Щелконогов.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `n` независимых групп, в каждой ровно `k` целей. Группа `i`
получает `a_i` единиц запаса; каждая единица однократно устраняет одну
цель только своей группы. Действие всегда успешно. Передавать запасы
между группами нельзя. После максимального использования посчитайте
суммарный неиспользованный запас и число оставшихся целей.

Ограничения: `1≤n,k≤10000`, `0≤a_i≤100000`. Лимит времени — 1 секунда,
памяти — 64 МБ.

## Входные данные

В первой строке `n k`, во второй — `n` количеств запаса.

## Выходные данные

Два целых числа: сначала общий неиспользованный запас, затем общее число
оставшихся целей.

## Проверка

Ответы сравниваются по токенам.

## Примеры

Ввод:

```
4 5
2 7 5 0
```

Вывод:

```
2 8
```

По группам остаются пары `(запас,цели)`: `(0,3)`, `(2,0)`, `(0,0)`,
`(0,5)`. Их сумма — `(2,8)`.

## Решение

В одной группе нельзя использовать больше `a_i` единиц запаса или больше
`k` целей. Поштучное сопоставление использует ровно `b_i=min(a_i,k)`
пар: после этого одна сторона пуста. Поэтому остаются
`a_i−b_i=max(a_i−k,0)` единиц запаса и `k−b_i=max(k−a_i,0)` целей.

Поддерживаем две суммы с начальным значением ноль. При `a_i>k` добавляем
`a_i−k` к запасу, иначе `k−a_i` к оставшимся целям. После обработки
первых `j` групп суммы равны их действительным остаткам: формула верна
для отдельной группы, а обмена между группами нет. Этот инвариант
доказывает правильность после всех `n` групп.

Нельзя сначала объединить все запасы: в одной группе может быть избыток,
а в другой одновременно недостаток. При `a_i=k` оба вклада нулевые; при
`a_i=0` остаются все `k` целей. Контрольное равенство
`запас−цели=Σa_i−nk` выполняется, но само по себе не определяет два
ответа.

## Особенности языков

Время `O(n)`, дополнительное состояние двух сумм — `O(1)`. C++, Go и
Java читают числа из буферизованного потока. Python сохраняет `O(n)`
разобранных значений, Rust — `I` байтов ввода; фактическая память ввода
соответственно `O(n)` и `O(I)`. Срез Python создаёт ещё один временный
массив `O(n)`, не меняя оценки времени.

Максимальный неиспользованный запас — `10000·(100000−1)=999990000`,
оставшихся целей — `10000²=100000000`. Оба результата помещаются в
знаковые 32 бита, скомпилированные версии используют более широкие
суммы. Rust вычитает только после сравнения, поэтому переполнения
беззнакового типа вниз нет. Токенизатор Java точно читает целые данного
диапазона. Сортировка, перераспределение и вещественный вывод не нужны.
