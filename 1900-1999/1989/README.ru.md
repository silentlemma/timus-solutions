# 1989. Палиндромы при заменах букв

[Timus 1989](https://acm.timus.ru/problem.aspx?space=1&num=1989) · сложность 338 · strings, fenwick, hashing

Автор оригинальной задачи — Михаил Рубинчик; Открытый командный чемпионат УрФУ по программированию — 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Поддерживайте слово из `n` строчных латинских букв. Операция либо
заменяет одну букву, либо спрашивает, одинаково ли читается указанный
подотрезок слева направо и справа налево. Всего `m` операций,
`5≤n,m≤100000`. Нумерация начинается с 1. Лимит времени: 0,5 секунды,
памяти: 64 МБ.

## Входные данные

Слово, число `m`, затем `m` операций. `change i a` присваивает позиции
`i` букву `a`, `1≤i≤n`. Запрос `palindrome? l r` относится к
включительному отрезку от `l` до `r`, `1≤l≤r≤n`. Разрешено присвоить уже
имеющуюся букву.

## Выходные данные

На каждый запрос в исходном порядке выведите `Yes`, если подстрока
является палиндромом, иначе `No`. Замены ничего не выводят.

## Проверка

Ответы сравниваются по токенам.

## Примеры

Ввод:

```
abcda
5
palindrome? 1 5
palindrome? 1 1
change 4 b
palindrome? 1 5
palindrome? 2 4
```

Вывод:

```
No
Yes
Yes
Yes
```

Исходное слово целиком не является палиндромом, а одна буква является
всегда. После замены четвёртой буквы на `b` получается `abcba`; и всё
слово, и внутренняя подстрока `bcb` симметричны.

## Решение

### Точные зеркальные буферы: C++, Go, Python, Rust

Храним слово `s` и развёрнутое слово `t` с инвариантом `t[n−1−i]=s[i]`.
Замена записывает новую букву в обе соответствующие позиции. Запрос
переводим в полуинтервал `[l,r)` с нулевой нумерацией. Обращение этой
подстроки находится в `t[n−r:n−l]`, поэтому сравниваем его с `s[l:r]`.

Инвариант верен после построения и сохраняется при каждой замене, в том
числе без изменения значения. Для любого смещения `j` имеем
`t[n−r+j]=s[r−1−j]`. Равенство сравниваемых участков эквивалентно
равенству всех зеркальных пар букв подстроки. Это доказывает точность
ответа без вероятностных коллизий. Отрезок длины 1 и границы слова
обрабатываются теми же формулами.

Пусть `L` — сумма длин всех запрошенных подстрок. Построение занимает
`O(n)`, замена — `O(1)`, запрос — не более времени своей длины. Итого
`O(n+m+L)`, в худшем случае `O(nm)`, а не логарифмическое время.
Последовательные сравнения выполняются средствами языка: C++ `memcmp`,
Go `bytes.Equal`, равенство срезов Rust и CPython `bytearray.startswith`
с `memoryview` зеркального буфера. Представление Python видит точечные
изменения; при запросе данные участка не копируются, размеры буферов не
меняются.

В программе достаточно сравнить только `h=floor((r−l)/2)` букв:
`s[l:l+h]` и `t[n−r:n−r+h]`. Так каждая зеркальная пара проверяется
ровно один раз, а средняя буква нечётной подстроки совпадает сама с
собой. Для одной буквы оба участка пусты, поэтому ответ положительный.

### Четыре поля и деревья Фенвика: Java

Для каждого простого `p=1000000007,1000000009,998244353,1000000033`
независимо выбираем равномерное основание `B` из `2..p−2`. Предвычисляем
степени и строим два дерева Фенвика с весами `s[i]Bⁱ` и `s[i]Bⁿ⁻¹⁻ⁱ` по
модулю `p`. Линейное построение передаёт значение каждой вершины её
родителю. Разность старой и новой букв меняет только два веса;
обновление занимает `O(log n)`.

Для `[l,r)` получаем суммы `F,G` вычитанием префиксов и во всех полях
проверяем `F·Bⁿ⁻ʳ ≡ G·Bˡ (mod p)`. Множители выравнивают степени
зеркальных букв. Палиндром проходит всегда. Если подстрока
несимметрична, разность выровненных многочленов после удаления общего
множителя имеет степень не более `n−1` и ненулевой коэффициент из
диапазона −25..25. Он ненулевой в каждом используемом поле.

Ненулевой многочлен над полем имеет не больше корней, чем его степень.
Для фиксированного входа, независимого от случайных оснований,
вероятность хотя бы одного ложного `Yes` ограничена `m·∏((n−1)/(p−3)) <
1,1·10⁻¹¹`. Основания выбираются через `java.util.Random`. Это алгоритм
Монте-Карло, а не доказательство точного равенства; оценка предполагает
независимые равномерные выборы и не относится к адаптивным запросам по
скрытым основаниям. Четыре поля требуют `O(n+m log n)` времени и
`O(n+m)` памяти с накопленными ответами. Неравенства уже в одном поле
достаточно для `No`.

### Реализация и ограничения

Используются ASCII-коды букв. В Java произведения меньше `p²<1,01·10¹⁸`
помещаются в `long`; знаковые разности нормализуются до умножения. Узел
дерева меньше `p`, сумма двух узлов помещается в `int`, а сумма не более
17 узлов префикса — в `long`. Обратные элементы не нужны. Java читает
вход через байтовый буфер; Go совместим с 1.14.

Точные реализации хранят `O(n)` букв и до `O(m)` ответов. Go и Rust
также удерживают `I` байтов исходного ввода: фактическая память
`O(n+m+I)`. Для Python выбран CPython 3.12: измеренный PyPy 3.10
превысил время и память на длинных симметричных запросах. Худшая оценка
точного сравнения квадратична, так что лимит 0,5 секунды для него
жёсткий. Статические радиусы Манакера сами по себе не
поддерживают замены, а их перестроение после каждой замены также даёт
квадратичную оценку.

Ловушка генерации тестов: случаи генератора № 26–29
(`generated_exhaustive5` — `generated_exhaustive8`) используют только
размеры `5..8`. Двоичный режим `exhaustiveN` создаёт
`m=N·2^N·(1+N(N+1)/2)` операций. Поэтому `exhaustive4` нарушает `n≥5`,
а `exhaustive9` создаёт 211968 операций, превышая `m≤100000`.
Генератор отклоняет размеры вне `5..8` до построения последовательности.

## Оптимизированные решения

C++ и Go хранят строку и её разворот и точно сравнивают зеркальные половины. Они считают пары разных соседних букв. Замена меняет не более двух пар, а при нуле любая подстрока сразу проходит проверку. PyPy хранит прямые и обратные полиномиальные суммы в деревьях Фенвика по двум простым модулям с независимо выбранными случайными основаниями. Замена обновляет четыре суммы. Запрос вычитает префиксы и сдвигает суммы двух направлений к одинаковым степеням. Сравнение вероятностное из-за возможных коллизий хешей. PyPy хранит входные команды в виде байтов и выводит ответы пакетами ограниченного размера.

Принятая версия Go 1.14 x64 заняла 0.281 с при 0.265 с у базовой и использовала 1 364 KB при 10216 KB у базовой.

Принятая версия PyPy 3.10 x64 заняла 0.234 с при 0.500 с у базовой и использовала 11 204 KB при 9896 KB у базовой.

Принятые базовые реализации [1989_strings.java](1989_strings.java), [1989_strings.rs](1989_strings.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
