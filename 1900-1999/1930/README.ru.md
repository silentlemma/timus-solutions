# 1930. Маршрут с минимумом смен передачи

[Timus 1930](https://acm.timus.ru/problem.aspx?space=1&num=1930) · difficulty 162 · shortest_paths

Original problem from Ural Regional School Programming Contest 2012 | by Grigoriy Nazarov (prepared by Bulat Zaynullin).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

По дороге можно ехать в обе стороны. В записи a,b направление от первого
города ко второму требует передачи для подъёма, обратное — для спуска.
Найти путь между заданными различными началом и концом с минимумом смен
двух передач. Первую передачу разрешено выбрать бесплатно. Путь существует.
Ограничения: 1,5 секунды, 64 МБ.

## Входные данные

Сначала n,m: 2≤n≤10000, 1≤m≤100000. Далее m строк с различными
концами дороги a,b в 1..n, подъём направлен a→b. Петель нет, между
неупорядоченной парой городов не больше одной дороги. Последняя строка —
различные начальный и конечный города, между которыми есть путь.
Другие компоненты могут быть несвязными. Номера не определяют направление.

## Выходные данные

Одно целое число — минимальное количество смен передачи.

## Проверка

Точное сравнение одного целочисленного токена.

## Примеры

```
3 2
1 2
3 2
1 3
```

```
1
```

```
3 3
1 2
2 3
3 1
1 3
```

```
0
```

## Решение

Создадим два состояния для города: сам город и текущая передача.
При проезде дороги с требуемой передачей d переходим из (город,g)
в (сосед,d) за 0 при g=d и за 1 иначе. Обе начальные передачи имеют
расстояние 0 — это бесплатный первый выбор. Подходит любое состояние цели.

Запустим 0–1 BFS. Улучшение по ребру нулевого веса кладём в начало дека,
по единичному — в конец. При первом извлечении фиксируем состояние,
последующие копии пропускаем. Возвращаем ответ при фиксации цели.
Дек обрабатывает незафиксированные расстояния в порядке алгоритма
Дейкстры: нулевые переходы остаются на текущем расстоянии, единичные
идут следом. Поэтому первое зафиксированное расстояние оптимально.

Каждый реальный маршрут соответствует пути состояний ровно с тем же
числом переключений. Каждый переход обратно соответствует допустимому
проезду дороги с возможной предварительной сменой передачи. Два нулевых
начальных состояния учитывают оба бесплатных первых выбора. Следовательно,
кратчайшее расстояние состояний равно ответу, а первая зафиксированная
цель его достигает.

O(n+m) времени и памяти. Состояний 2n, возможных переходов 4m.
Каждое зафиксированное состояние просматривает соседей своего города
один раз; дубликаты пропускаются, каждое улучшение связано с переходом.

Минимум дорог не означает минимум переключений. Нужны два состояния
города: равные по цене прибытия на разных передачах не взаимозаменяемы.
Не учитывайте первую передачу как переключение и не требуйте начинать
подъёмом. Направления дорог заданы независимо: второй пример содержит
направленный цикл. Номера городов не задают порядок высот.
Связность гарантирована только для начала и конца, а не всего графа.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает до 200 004 чисел вручную из
буфера на 4 КБ, который пополняется через `fread`, и печатает через
`printf` вместо `iostream`; граф и 0–1 BFS те же:
{1930_shortest_paths_optimized.cpp}.

Оптимизированное решение на Go разбирает числа вручную из буфера на
4 КБ, читаемого из стандартного ввода, вместо вызова `fmt.Fscan` на
каждое из не более чем 200 004 чисел; граф и 0–1 BFS те же:
{1930_shortest_paths_optimized.go}.

Оптимизированное решение на Java разбирает числа вручную из
`BufferedInputStream` вместо `StreamTokenizer` и держит дек кольцевым
буфером в массиве `int` вместо `ArrayDeque` упакованных `Integer`. При
`A = 2m` записях смежности в дек попадает не больше `2 + 2A` состояний,
поэтому ёмкость `2A + 3` никогда не переполняется и оставляет одну
свободную ячейку: {1930_shortest_paths_optimized.java}.

Оптимизированное решение на Python читает ввод кусками по 4 КБ, а не
разбивает его весь сразу, и хранит каждый список смежности в
`array("H")` из беззнаковых 16-битных чисел вместо списка целых
объектов: номер состояния 2·город+передача не больше 19 999, ведь
n ≤ 10000: {1930_shortest_paths_optimized.py}.

Оптимизированное решение на Rust хранит списки смежности как `Vec<u16>`
вместо `Vec<usize>`, по 2 байта вместо 8 на запись: номер состояния
2·город+передача не больше 19 999, ведь n ≤ 10000. Числа разбираются
вручную из буфера на 4 КБ вместо чтения всего ввода в `String`:
{1930_shortest_paths_optimized.rs}.

## Особенности языков

В списке смежности хранится 2·сосед+требуемаяПередача — две записи на
дорогу. Расстояния помещаются в знаковые 32 бита. Число 2n подходит для
бесконечности: простой путь графа состояний короче 2n рёбер веса ≤1. В
Java — чтение через `StreamTokenizer`, массив `int` соседей на каждый
город и `ArrayDeque`. В Go дек представлен двумя стеками: отложенный
задний переворачивается только при пустом переднем. Каждый такой элемент
переносится один раз, суммарно линейно. C++ и Rust используют
стандартные деки, Python — deque и bytearray для отметок фиксации. Общие
буферы и граф занимают O(n+m).
