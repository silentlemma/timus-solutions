# 1933. Матрица пар для нечётного кругового турнира

[Timus 1933](https://acm.timus.ru/problem.aspx?space=1&num=1933) · difficulty 408 · constructive

Original problem from Open Ural FU Championship 2012 | by Alexander Ipatov (prepared by Oleg Dolgorukov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть R=2n+1 участников и R раундов. В каждом нужно составить n
непересекающихся пар и оставить одного руководителя. Пары не повторяются,
каждый участник руководит ровно один раз. Построить симметричную матрицу,
в которой для каждой пары указан раунд её совместной работы.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Одно целое n, 1≤n≤100.

## Выходные данные

R строк по R целых от 0 до R. На диагонали нули. Вне диагонали
элемент (i,j) — номер раунда 1..R, где участники i и j образуют пару.
Всего nR=C(R,2) парных мест; без повторов каждая пара используется
ровно один раз. Подходит любое расписание со всеми указанными свойствами.

## Проверка

checker.py читает R² целых и проверяет диагональ, диапазоны, симметрию,
n непересекающихся пар в каждом раунде, единственного руководителя
каждого раунда и различность руководителей. Принимаются иные допустимые
расписания, в том числе с другими номерами раундов и перестановкой людей.

## Примеры

```
1
```

```
0 1 2
1 0 3
2 3 0
```

## Решение

Используем индексы i,j от нуля. На диагонали ставим 0, иначе
A[i][j]=((i+j+R−1) mod R)+1. Слагаемое R сохраняет неотрицательность
во всех языках. Симметрия и диапазон номеров следуют сразу.

Зафиксируем участника i. При переборе всех R значений j формула
выдаёт каждый номер раунда один раз. Исключение j=i оставляет разные
номера для всех настоящих партнёров; пропущен только
L_i=((2i+R−1) mod R)+1. Число R нечётное, поэтому умножение на 2
обратимо по модулю R. Значит, пропущенные номера L_i попарно различны,
даже если R составное. В каждом раунде отсутствует ровно один человек,
а остальные участвуют по одному разу; симметрия объединяет их в n пар.
Отсутствующий руководит. Каждый пропускает один раунд, и эти раунды
различны, значит, руководителем становится ровно по одному разу.
Неупорядоченная пара получает один номер в матрице и не повторяется.
Тем самым доказаны все свойства конструкции.

O(n²) времени — столько же, сколько элементов нужно вывести.
Реализации хранят матрицу целиком, используя O(n²) памяти вместе
с возможным буфером вывода.

Нечётности достаточно, простота R не нужна. Нули должны быть только
на диагонали. Метка пары одинакова с обеих сторон матрицы. Единственный
руководитель в раунде ещё не гарантирует, что все руководят по разу.
Перенумерация раундов и участников меняет матрицу, сохраняя допустимость,
поэтому проверять нужно свойства расписания, а не совпадение текста.

## Оптимизированные решения

C++, Go и Rust выводят то же расписание через буфер сразу по мере построения. В строке i метки раундов начинаются с i, а вместо нулевой метки берём R. Дальше метка увеличивается на один с переходом через границу. На диагонали печатаем ноль, но увеличиваем метку как обычно. Так исходная формула по модулю вычисляется без хранения матрицы.

Принятые базовые реализации [1933_constructive.java](1933_constructive.java), [1933_constructive.py](1933_constructive.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

R≤201, номера≤201, i+j+R−1≤600, обычных целых достаточно.
C++ использует векторную матрицу и отключённую синхронизацию потоков.
В Go буферизованная запись; Java и Rust собирают строку вывода,
Python соединяет значения каждой строки. Все программы печатают
R строк без пробелов в конце.
