# 1987. Кратчайший содержащий отрезок в ламинарном семействе

[Timus 1987](https://acm.timus.ru/problem.aspx?space=1&num=1987) · сложность 168 · greedy

Автор оригинальной задачи — Михаил Рубинчик (идея — Никита Первухин); Открытый командный чемпионат УрФУ по программированию — 2013.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `n` различных замкнутых отрезков. Любые два либо не имеют общих
точек, либо один содержит другой. Для каждой из `m` точек найдите
кратчайший содержащий её отрезок. Выведите исходный номер отрезка от 1
или −1, если подходящего нет.

Ограничения: `1≤n,m≤10⁵`, `1≤aᵢ<bᵢ≤10⁹`, `1≤cⱼ≤10⁹`. Отрезки перечислены
по неубыванию левого конца, при равенстве — по убыванию длины. Запросы
также не убывают. Лимиты: 1 секунда и 64 МБ.

## Входные данные

Число `n`, далее `n` пар `aᵢ bᵢ`, затем `m` и координаты `m` запросов.
Номер отрезка определяется его положением во входном списке.

## Выходные данные

Для каждого запроса одна строка с номером кратчайшего покрывающего
отрезка либо −1.

## Проверка

Ответы сравниваются по токенам.

## Решение

Двигаемся по запросам слева направо и продвигаем указатель по уже
отсортированным отрезкам. В стеке храним их индексы: от внешнего отрезка
к внутреннему.

Для запроса `c` обрабатываем все ещё не просмотренные отрезки с началом
`a≤c`. Перед добавлением очередного удаляем из стека отрезки, правый
конец которых строго меньше `a`: они уже закончились и не пересекают
новый. Если стек остался непустым, его вершина содержит новый отрезок.
Они пересекаются в точке `a`, частичное пересечение запрещено, а внешний
отрезок не может прийти позже внутреннего благодаря порядку входа. При
равных началах внешний явно перечислен раньше. Добавление сохраняет
цепочку вложенности.

Когда просмотрены все начала не больше `c`, удаляем отрезки с правым
концом строго меньше `c`. Все оставшиеся содержат точку: их начало уже
достигнуто, а конец ещё не пройден. Вершина — самый внутренний и потому
кратчайший отрезок. Пустому стеку соответствует −1.

Удалённый отрезок не сможет покрыть последующие запросы: он закончился
раньше уже достигнутой координаты, а запросы не движутся влево.
Непросмотренный отрезок начинается правее `c` и её не содержит. Каждый
ранее обработанный содержащий отрезок сохраняется в цепочке, поэтому
вершина оптимальна среди всех отрезков. Различные вложенные отрезки
имеют строго разные длины, так что кратчайший ответ единственен.

В примере точки 2 и 3 покрывает отрезок 2. Для точки 4 он уже
закончился, но остаётся внешний отрезок 1. Точки 5–7 покрывает отрезок
3, точки 8–10 — снова отрезок 1. Точки 1 и 11 не покрыты. Это и даёт
одиннадцать строк ответа.

Каждый отрезок добавляется в стек не больше одного раза и удаляется не
больше одного раза суммарно в обоих циклах. Указатель только растёт,
поэтому время — `O(n+m)`, несмотря на вложенные циклы. Дополнительная
память стека — `O(n)`. Полные программы буферизуют ввод или ответы,
поэтому общий объём хранения — `O(n+m)`. Сортировка, рекурсия, куча и
двоичный поиск не нужны.

Подводные камни:

- Оба условия удаления используют строгое `<`: правый конец принадлежит отрезку.
- Все отрезки с началом в точке запроса должны быть добавлены до ответа.
- При равных началах сохраняйте заданный порядок от внешнего к внутреннему.
- Выводите исходный номер от 1, а не глубину стека.
- Удаляйте закончившихся потомков, прежде чем возвращаться к предку.
- Линейный алгоритм опирается на вложенность и отсортированность входа.

## Особенности языков

Все пять версий реализуют один проход. Координаты и номера помещаются в
знаковые 32-битные целые. C++ и Rust используют векторы, Java — массивы
примитивов, Go — срезы. В Go и Java есть быстрый разбор целых чисел.
Python хранит массивы концов, получает запросы через итератор токенов и
буферизует ответы.
