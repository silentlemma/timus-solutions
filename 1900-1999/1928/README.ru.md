# 1928. Поочерёдные выплаты и завершающий подарок

[Timus 1928](https://acm.timus.ru/problem.aspx?space=1&num=1928) · difficulty 771 · games, dp

Original problem: folklore, prepared by Maria Zyryanova; from Ural Regional School Programming Contest 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Два участника по очереди запрашивают целую сумму от 1 до k; начинает
первый, общий начальный бюджет равен n. Если бюджет нулевой, игра
заканчивается до следующей заявки. Посильную заявку полностью оплачивают
из бюджета. Если денег не хватает, текущий участник получает только
отдельный подарок m, бюджет не расходуется, игра сразу завершается.
Каждый прежде всего максимизирует свою итоговую сумму, а при её равенстве
минимизирует сумму соперника. Найти обе суммы при оптимальной игре.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Одна строка n m k: 0≤n≤10000, 0≤m≤1000, 1≤k≤100.

## Выходные данные

Два целых числа: сумма первого участника, затем второго.

## Проверка

Точное сравнение двух целочисленных токенов.

## Примеры

```
12 30 10
```

```
31 10
```

## Решение

Для остатка бюджета b храним F[b] — будущий доход участника, который
сейчас ходит, и G[b] — будущий доход другого. Уже полученные суммы
одинаковы при сравнении всех следующих вариантов, поэтому не влияют на
выбор. При b=0 обе величины нулевые: нового хода нет.

Посильная заявка x, 1≤x≤min(b,k), оставляет бюджет b−x и меняет роли
участников. Получаем пару (x+G[b−x], F[b−x]). Непосильная заявка
существует ровно при 0<b<k; все такие заявки дают один завершающий
вариант (m,0). Ни x, ни остаток b в этой ветви не выплачиваются.
Выбираем наибольшую первую компоненту, при равенстве — наименьшую вторую.
Заполняем b=1..n и выводим F[n],G[n].

Докажем корректность по возрастанию b. Для меньших бюджетов уже известны
результаты оптимальной игры. Любая легальная заявка либо завершает игру
подарком, либо переходит в меньший бюджет с обменом ролей. Формула пары
точно учитывает этот исход. Выбор по заданным предпочтениям оптимален
в текущем состоянии. База и переход доказывают алгоритм.

O(nk) времени и O(n) памяти: два массива, не более 1 000 000 посильных
вариантов на полных ограничениях. Рекурсивного перебора в решениях нет.

Максимизация разности сумм не заменяет первичную максимизацию своей.
Правило равенства существенно: n=5,m=2,k=3 даёт (3,2), а игнорирование
равенств меняет результат. При нулевом бюджете ответ (0,0), независимо
от подарка. При b=k непосильной легальной заявки нет. В непосильной
ветви выплачивается только m, не запрос и не весь остаток бюджета;
игра сразу завершается. После посильной заявки обязательно поменять роли.

## Особенности языков

Доходы неотрицательны, их общая сумма не больше n+m≤11000, поэтому
хватает знаковых 32-битных чисел. В Go используется int, в Rust индексы
usize отделены от доходов i32, в C++ и Java — int, в Python — списки.
Служебное значение лучшего дохода −1 означает отсутствие варианта;
в ответ оно не попадает. CPython достаточно для этого ограниченного DP.
