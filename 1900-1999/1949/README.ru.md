# 1949. Расписание с приоритетами

[Timus 1949](https://acm.timus.ru/problem.aspx?space=1&num=1949) · difficulty 1400 · matching

Original problem from Open Ural FU Personal Contest 2012 | by Vitaliy Belokobilskiy, Sergey Madzhuga.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть n фильмов и k зрителей. Фильм i занимает [a_i,b_i), ему соответствует
число c_i. Зритель смотрит фильм целиком, не может смотреть пересекающиеся
сеансы, а следующий фильм должен иметь c не меньше предыдущего. Конец
ровно в момент следующего начала допустим, равные c тоже. Перерывы и
неиспользованные зрители разрешены, время перехода не учитывается.

Выбрать допустимое множество с лексикографически наибольшей двоичной строкой
длины n в порядке входа: 1 предпочтительнее 0. Любой ранний фильм важнее
всех последующих вместе. Ограничения: 1 секунда, 64 МБ.

## Входные данные

n и k, 1≤k≤n≤100. Затем n троек a_i,b_i,c_i в порядке приоритета:
0≤a_i<b_i≤86399, 1≤c_i≤10000. Порядок не обязан совпадать со временем.

## Выходные данные

Строка из n цифр: 1 на позиции i означает включение фильма i в лучшее
допустимое множество. Распределение по зрителям выводить не нужно.

## Проверка

Ответы сравниваются по токенам; оптимальная строка единственна.

## Решение

Проведём ребро i→j, если b_i≤a_j и c_i≤c_j. Время по ребру строго
увеличивается, поэтому граф ацикличен. Расписание зрителя — путь.
Для выбранных s фильмов создадим левые и правые копии вершин с теми же
рёбрами между долями. Если максимальное паросочетание имеет M рёбер,
минимальное число зрителей равно s−M.

Доказательство: p путей расписания дают паросочетание из последовательных
рёбер, всего s−p. Обратно, рёбра паросочетания дают каждой вершине не
больше одного предшественника и продолжения. Циклов нет, значит получаются
s−M непересекающихся путей, каждый — допустимое расписание. Поэтому
множество допустимо тогда и только тогда, когда s−M≤k.

Перебираем фильмы по приоритету и пробуем включать очередной. Допустимое
множество сохраняем: все оставшиеся биты можно сделать нулевыми. Недопустимое
отклоняем. Допустимость наследуется подмножествами: удаление фильмов из
расписания сохраняет порядок времени и неубывание c. Поэтому добавления
позже не исправят недопустимое подмножество. На каждом шаге фиксируем
лучший возможный первый различающийся бит; это доказывает жадный выбор.

Максимальное паросочетание поддерживаем двумя последовательными поисками:

1. Добавляем только левую копию кандидата. Из неё ищем увеличивающий путь
   вперёд к старым активным правым вершинам, обновляя обе таблицы партнёров.
2. Активируем правую копию. Из неё ищем увеличивающий путь в обратном
   направлении по рёбрам предшественников к свободной левой вершине.

В первой фазе новый увеличивающий путь обязан начинаться в новой свободной
левой вершине, а размер максимума может вырасти не больше чем на один.
Успешный поиск достигает этой границы, неуспешный подтверждает старый
максимум. Для второй фазы рассуждение симметрично. После обеих фаз
паросочетание максимально. Только поиск из новой левой вершины не заметит
улучшение через новую правую.

Метки посещения для фаз сбрасываем. До попытки сохраняем обе таблицы и M;
если s+1−M>k, отключаем кандидата и восстанавливаем всё состояние.
Принятые фильмы остаются активными. Выводим биты принятых решений.

O(n³) времени и O(n²) памяти. Построение графа O(n²), у каждого из n
кандидатов два поиска по O(n²) и снимки по O(n). В одном поиске каждая
вершина противоположной доли посещается не более раза. Глубина рекурсии
не больше n≤100.

Нельзя максимизировать количество фильмов или сумму c_i, терять приоритет
сортировкой. Условия по времени и c нестрогие. У кандидата есть обе копии,
улучшение возможно в любом направлении. Новая правая копия в первой фазе
ещё неактивна. Отклонённые фильмы не должны попадать в будущий граф.

## Особенности языков

В нативных версиях булевы матрицы смежности, массивы активности и посещения,
целые таблицы партнёров. Общий поиск обслуживает оба направления сменой
графа и порядка таблиц. Python хранит соседей целочисленными масками
до 100 бит; одного 64-битного числа для всех фильмов недостаточно.
Между фазами очищать метки, при отказе восстанавливать обе таблицы.
Достаточно стандартной библиотеки.
