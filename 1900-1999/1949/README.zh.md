# 1949. 按优先级安排观影

[Timus 1949](https://acm.timus.ru/problem.aspx?space=1&num=1949) · difficulty 1401 · matching

Original problem from Open Ural FU Personal Contest 2012 | by Vitaliy Belokobilskiy, Sergey Madzhuga.

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 n 部电影和 k 名观众。电影 i 占用区间 [a_i,b_i)，带有数值 c_i。
每部必须完整观看，同一观众不能观看重叠电影，下一部的 c 不得小于
上一部。结束等于下一场开始、c 相等都允许，可以有空档或不用某些
观众，不考虑转场时间。

按输入顺序输出所选集合的 n 位成员串，要求字典序最大，1 优于 0。
因此较早的一部优先于所有后续电影的组合。限制：1 秒、64 MB。

## 输入

n、k，1≤k≤n≤100。接着 n 组三元组 a_i,b_i,c_i，顺序表示优先级。
0≤a_i<b_i≤86399，1≤c_i≤10000。输入顺序不一定是时间顺序。

## 输出

n 位二进制串，第 i 位为 1 当且仅当选择电影 i，且整体为最优可行集合。
不需要输出观众分配。

## 评测方式

按记号逐个比较输出；最优字符串是唯一的。

## 解法

若 b_i≤a_j 且 c_i≤c_j，建立边 i→j。每条边使时间严格增加，所以
图无环，每名观众的观看安排是一条路径。对选中的 s 部电影建立左右
两份顶点，按原边连接。若最大二分匹配大小为 M，则最少观众数为 s−M。

证明：p 条观看路径的相邻边构成大小 s−p 的匹配。反之，匹配边令每个
顶点至多有一个前驱、一个后继；无环性排除循环，故形成 s−M 条互不
相交的合法观看路径。因此可行当且仅当 s−M≤k。

按优先级逐个尝试加入电影。若仍可行就保留，因为后续全选零即可形成
完整方案；否则拒绝。可行性对子集封闭：从实际观看安排中删除电影，
时间顺序及 c 不降仍成立，因此未来加入电影不能修复一个不可行子集。
每一步都固定最早位置上可实现的最大位，证明贪心的字典序最优性。

每次插入用两个有序步骤维护最大匹配：

1. 只加入候选的左副本，从它向旧的活跃右顶点寻找增广路，并更新双方
   的匹配伙伴数组。
2. 激活新的右副本，从它沿前驱边反向寻找通向未匹配左顶点的增广路。

第一阶段新增的增广路必从新加入的未匹配左顶点开始，最大匹配至多
增加一条边。找到即达到上界，找不到则原匹配仍最大。第二阶段交换
左右角色后同理。所以两步结束后仍是最大匹配。只从新左顶点搜索会
漏掉通过新右顶点的改善。

两次搜索之间清空访问标记。尝试前保存双方匹配数组和 M；若
s+1−M>k，取消候选激活并恢复全部匹配状态。保留的电影持续活跃，
最终输出保留位串。

O(n³) 时间、O(n²) 空间。建图 O(n²)，每个候选有两次 O(n²) 搜索及
O(n) 快照。一次搜索至多访问每个对侧顶点一次，递归深度不超过 n≤100。

目标不是电影数量或 c_i 总和，不要排序后丢失优先级。时间和数值条件
都含等号。新增电影的左右副本都重要；第一阶段新右副本尚未激活。
被拒电影必须一直保持不活跃。

## 各语言说明

原生版本使用布尔邻接矩阵、活跃与访问数组、整数伙伴数组。共用的
增广函数通过交换图及伙伴数组处理两个方向。Python 使用至多 100 位
整数存储邻居；不能用一个 64 位掩码表示全部电影。两阶段之间重置
访问标记，拒绝时恢复双方伙伴，只需标准库。
