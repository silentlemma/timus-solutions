# 1980. Минимальное превышение скорости с маршрутом

[Timus 1980](https://acm.timus.ru/problem.aspx?space=1&num=1980) · сложность 639 · binary_search, dijkstra

Автор оригинальной задачи — Денис Дублённых; XVII Открытый чемпионат Урала по спортивному программированию (май, 2013).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У каждой двусторонней дороги есть длина `l` километров и разрешённая
скорость `s` километров в час. Общее неотрицательное превышение `S`
позволяет ехать по дороге со скоростью до `s+S`. Найдите минимальное
превышение, при котором можно добраться из вершины 1 в вершину `n` не
более чем за `T` часов, и выведите последовательность исходных номеров
дорог.

Ограничения: `2≤n≤10000`, `1≤m≤10000`, `1≤s≤300`, `1≤l≤1000`, целое
`1≤T≤10⁶`. Концы дороги удовлетворяют `1≤a<b≤n`. Путь до цели
существует; алгоритм учитывает параллельные дороги и несущественные
компоненты. Время — 1 секунда, память — 64 МБ.

## Входные данные

Все входные значения целые. Даны `n m`, затем `m` строк `a b s l` и
число `T`. Дороги пронумерованы от 1 до `m` в порядке ввода.

## Выходные данные

В первой строке выведите `S k`, во второй — `k` номеров дорог в порядке
проезда. Подходит любой правильный оптимальный маршрут.

## Проверка

Проверяющая программа убеждается, что напечатанные дороги образуют путь
из 1 в n, укладывающийся в срок при напечатанной надбавке, и что
надбавка оптимальна с абсолютной или относительной погрешностью 10⁻⁶;
принимается любой такой маршрут.

## Примеры

Ввод:

```
3 3
1 3 50 150
1 2 80 100
2 3 80 100
2
```

Вывод:

```
20.000000 2
2 3
```

Ввод:

```
2 1
1 2 60 60
1
```

Вывод:

```
0.000000 1
1
```

## Решение

При фиксированном `S` минимальное время на дороге равно `l/(s+S)`. Веса
положительные, поэтому достижимость цели за время `T` проверяется
алгоритмом Дейкстры. Устаревшие записи очереди пропускаем; при
извлечении цели с актуальной меткой проверку можно закончить. Время
больше `T` не добавляем в очередь, поскольку следующие дороги только
увеличат его.

При увеличении `S` все времена уменьшаются: проверка монотонна. Сначала
проверим ноль. Если путь уже укладывается в срок, оптимум равен нулю.
Иначе выполним двоичный поиск между невозможным нулём и возможной
границей `U=Σl/T`. Она достаточна: длина простого пути не больше `Σl`, а
при превышении `U` его время строго меньше `Σl/U=T`.

Правая граница всегда остаётся возможной. Делаем не более 60 делений
пополам; Python также останавливается, когда ширина интервала не больше
`10⁻⁹ max(1,upper)`. В конце заново запускаем Дейкстру на правой
границе. В предке сохраняем номер исходной дороги, что различает
параллельные рёбра. От вершины `n` идём к предыдущему концу каждой такой
дороги и разворачиваем список.

Каждая проверка правильна по инварианту Дейкстры для положительных
весов. Монотонность сохраняет оптимум внутри поискового интервала.
Последняя цепочка предков подтверждает достижимость для правой границы,
что доказывает и численный ответ, и маршрут.

Перед выводом увеличиваем границу на `10⁻⁸ max(1,upper)`. Этот небольшой
запас сохраняет выполнимость напечатанного маршрута при ошибках
суммирования и форматирования и остаётся внутри разрешённой погрешности.
Поэтому нулевой оптимум может выводиться как очень малое положительное
число. Простой путь содержит не больше `n−1` положительных слагаемых;
ошибка их суммирования в binary64 намного меньше запаса. Условие
остановки Python также точнее этого запаса. С учётом делений
относительная ошибка не более 9999 положительных слагаемых меньше
`1,2·10⁻¹²`. При `s≤300` запас уменьшает время каждой дороги как минимум
на `3,3·10⁻¹¹` относительно, перекрывая эту ошибку и округление вывода.

При общем числе запусков Дейкстры `B≤62`, включая начальную и
заключительную проверки, время с ленивыми записями кучи равно `O(B(n+m)
log(n+m))`, память — `O(n+m)`. При параллельных дорогах размер кучи
может превышать `n`.

В первом примере дороги 2 и 3 требуют `200/(80+20)=2` часа, а прямая
дорога — `150/(50+20)>2`. Минимальное превышение равно 20. Во втором
примере исходная разрешённая скорость уже позволяет доехать за час,
поэтому оптимум нулевой.

Подводные камни:

- Время равно длине, делённой на скорость; прибавка скорости не вычитает
  постоянное время.
- До поиска проверьте нулевое превышение.
- Сохраняйте номера дорог, включая параллельные, и выводите их от старта к цели.
- Последняя середина могла быть невозможной, поэтому возможную границу
  нужно проверить заново.
- Используйте возможную правую границу и достаточно знаков: округление
  вниз может нарушить срок.

## Особенности языков

C++, Go, Python и Rust используют стандартные двоичные кучи. Java хранит
списки смежности и кучу в примитивных массивах, повторно используя их
между проверками. Стоимость каждой дороги вычисляется один раз на
проверку. Python прекращает лишние итерации по ширине интервала. Все
версии сохраняют номера дорог-предков и добавляют небольшой численный
запас вверх.
