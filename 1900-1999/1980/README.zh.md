# 1980. 最小超速额度与对应路线

[Timus 1980](https://acm.timus.ru/problem.aspx?space=1&num=1980) · 难度 638 · binary_search, dijkstra

原题作者 Denis Dublennykh，出自 2013 年乌拉尔体育编程锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

每条无向道路有长度 `l` 千米和限速 `s` 千米每小时。给定统一的非负超速额度 `S`，该道路可使用至多 `s+S` 的速度。求能在 `T` 小时内从顶点 1 到达顶点 `n` 的最小额度，并输出对应路线的原始道路编号。

`2≤n≤10000`、`1≤m≤10000`、`1≤s≤300`、`1≤l≤1000`，整数 `1≤T≤10⁶`。道路端点满足 `1≤a<b≤n`。保证目的地可达；算法允许平行道路及无关连通分量。时间限制 1 秒，内存限制 64 MB。

## 输入

所有输入值均为整数。先读入 `n m`，再读入 `m` 行 `a b s l`，最后是 `T`。道路按输入顺序编号为 1 到 `m`。

## 输出

第一行输出 `S k`，第二行按通行顺序输出 `k` 个道路编号。可以输出任意合法最优路线。

## 评测方式

检查器确认输出的道路构成从 1 到 n 的路线，并以 10⁻⁶ 的绝对或相对误差检查额度的最优性。检查路线能否按时到达时，会在输出额度上增加允许的数值误差；任何这样的路线都被接受。

## 样例

输入:

```
3 3
1 3 50 150
1 2 80 100
2 3 80 100
2
```

输出:

```
20.000000 2
2 3
```

输入:

```
2 1
1 2 60 60
1
```

输出:

```
0.000000 1
1
```

## 解法

固定 `S` 后，道路的最短通行时间为 `l/(s+S)`。权值均为正，因此用 Dijkstra 判断能否在 `T` 内到达目的地。跳过堆中过期的距离；目的地以当前最短距离弹出时即可结束。超过 `T` 的候选距离可以直接丢弃，因为后续道路只会增加时间。

增大 `S` 会减小所有道路时间，可行性具有单调性。先检查 `S=0`，若可行则最优值为零；否则在不可行的零与可行上界 `U=Σl/T` 之间二分。上界成立，因为一条简单路线的总长度至多为 `Σl`，在额度 `U` 下其时间严格小于 `Σl/U=T`。

保持右端点可行，最多二分 60 次。Python 还会在区间宽度不超过 `10⁻⁹ max(1,upper)` 时停止。最后在可行右端点重新执行 Dijkstra。前驱记录原始道路编号，从而区分平行边；从 `n` 沿前驱道路走向另一个端点，再反转所得编号序列。

每次检查由正权图上的 Dijkstra 不变量保证正确。单调性保证最优值始终位于搜索区间中。最后的前驱链证明右端点可行，因此数值答案和路线均正确。

输出前再增加 `10⁻⁸ max(1,upper)` 的小余量，抵消求和和格式化误差，同时远小于允许误差。因此零最优值也可能输出为一个很小的正数。简单路线最多包含 `n−1` 个正项，binary64 的累计误差远小于该余量；Python 的停止误差也更小。计入除法后，至多 9999 个正项的相对舍入误差小于 `1.2·10⁻¹²`；由 `s≤300` 可知速度余量使每条道路时间至少相对减少 `3.3·10⁻¹¹`，足以覆盖舍入和输出格式化误差。

设包括初始零额度检查和最终重建在内的 Dijkstra 总运行次数为 `B≤62`，使用保留过期项的堆时，时间为 `O(B(n+m) log(n+m))`，空间为 `O(n+m)`。平行道路可能使堆中的项数超过 `n`。

第一个样例中，道路 2、3 的时间为 `200/(80+20)=2`，直达道路却需要 `150/(50+20)>2`，故最小额度为 20。第二个样例按原限速即可一小时到达，最优值为零。

注意事项：

- 时间为长度除以速度，增加速度并非减去固定时间。
- 二分前先检查零额度。
- 保留道路编号以区分平行边，并按起点到终点的顺序输出。
- 最后一个中点可能不可行，必须重新检查可行右端点。
- 使用可行上界并输出足够小数位，向下舍入可能破坏紧约束路线。
- 对于 `case_010` 这类恰好到达截止时间的测试，应区分路线的精确可行性与检查器的接受条件：检查路线时也应用额度误差。设输出为 `P`，`ε=10⁻⁶`，则检查器在 `P≤1−ε` 时使用 `P+ε`，否则使用 `P/(1−ε)`。

## 各语言说明

C++、Go、Python 和 Rust 使用标准二叉堆。Java 使用基本类型数组存储邻接表与堆，并在多次检查之间复用。每次检查只计算一次每条道路的代价。Python 根据区间宽度提前停止无用迭代。所有版本均保留前驱道路编号，并加入小的向上数值余量。
