# 1908. Цена нажатий в сокращаемом дереве выбора

[Timus 1908](https://acm.timus.ru/problem.aspx?space=1&num=1908) · difficulty 2071 · dp, trees

Автор исходной задачи: Denis Dublennykh, подготовка Alexander Fetisov, Ural Championship 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждая строка задаёт последовательность выборов от корня дерева до концовки.
Нужно исследовать все концовки; после каждой возврат к корню бесплатен.
Вариант перехода исчезает, когда исследованы все концовки под ним.
Выбор доступного ребра стоит одно нажатие. Ещё одна кнопка за одно нажатие
проходит текущую однозначную цепочку до ближайшего ветвления или концовки;
в самом ветвлении она ничего не делает. Минимизируйте общее число нажатий.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Сначала n, 1≤n≤100 000, затем n непустых строк из строчных латинских букв.
Ни одна не является префиксом другой. Сумма длин S не превышает 100 000.

## Выходные данные

Минимальное число нажатий для исследования всех концовок.

## Проверка

Одно точное целое число; сравнение по токенам.

## Примеры

```
3
aza
azc
b
```

```
4
```

## Решение

Построим префиксное дерево. Для вершины v храним число листьев N[v] и две
стоимости: A[v] — обычный вход при каждом чтении, B[v] — бесплатный начальный
пропуск при каждом входе, включая возвраты после концовок. Этот пропуск
доходит до первого текущего ветвления или листа; после дальнейших выборов
он повторно не предоставляется. В листе N=1,A=B=0.

Можно считать, что оптимальный порядок полностью исследует поддеревья детей
по одному. Возьмём ребёнка с последней концовкой и перенесём все его ранние
чтения после остальных детей, сохраняя внутренний порядок. Остальные дети
по-прежнему видят последний вариант доступным, их цена входа не растёт.
Перенесённые чтения лишь раньше получают возможность пропускать однозначные
участки. Оставшихся детей можно так же сгруппировать рекурсивно.

При входе в непоследнего ребёнка c вершина остаётся ветвлением: каждое
из N[c] чтений требует один выбор и обычную стоимость A[c] внутри.
Для последнего ребёнка при обычном входе платим один пропуск на чтение,
который одновременно обеспечивает начальный пропуск в ребёнке: N[c]+B[c].
При уже предоставленном пропуске остаётся только B[c]. Поэтому при
T=Σc(A[c]+N[c]) получаем:

```text
N[v] = sum N[c]
A[v] = T - max (A[c] - B[c])
B[v] = T - max (N[c] + A[c] - B[c])
```

Максимумы выбираются независимо. Для aa,ab,ac,ad,bxa,bxb имеем A[root]=11,
B[root]=8, причём последние дети различаются. Общая начальная z меняет
ответ на 6+8=14. Те же формулы работают для одного ребёнка и сжимают
сколь угодно длинную однозначную цепочку в одно нажатие. Ответ — A корня.

При создании вершины её номер больше номера родителя. Обратный проход по
номерам заменяет рекурсивный обход и безопасен для слова длины 100 000.
Детей храним связным списком соседей: при поиске проверяем не больше 26 букв.
Время построения и динамики O(S), память O(S), так как алфавит фиксирован.
Явное нажатие всех исходных выборов требует не больше S действий, поэтому
счётчики и промежуточные суммы помещаются в 32 бита.

В примере выбираем b, пропускаем до оставшегося ветвления a/z, выбираем c
и одним пропуском проходим последний путь. Всего четыре нажатия.

## Особенности языков

Во всех реализациях вставка и динамика итеративны. C++, Go 1.14 и Rust 1.75
используют записи вершин, Java 8 — примитивные массивы и буферизованный ввод.
Python 3.12 хранит целые в компактных массивах, а метки рёбер — в байтах,
без словаря или списка из 26 элементов для каждой вершины. Входные строки
занимают O(S). Рекурсии, глубина которой зависит от длины слова, нет.

Ответы совпадают с поиском в ширину по состояниям интерфейса на 978
тестах, среди них все беспрефиксные наборы двоичных строк длины не
больше трёх.
