# 1942. Ближайший сдвиг для самой большой группы

[Timus 1942](https://acm.timus.ru/problem.aspx?space=1&num=1942) · difficulty 646 · geometry

Original problem from Open Ural FU Personal Contest 2012 | by Vitaliy Belokobilskiy, Sergey Madzhuga.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны n точек на плоскости. Один раз переносится начало координат,
без поворота осей. Точка учитывается, если обе её новые координаты целые.
Максимизировать число учтённых точек, затем среди таких переносов
минимизировать евклидово расстояние от старого начала до нового.
Совпадающие точки — отдельные записи, каждая учитывается.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Число n, 1≤n≤50000, затем n пар вещественных координат. Модуль каждой
не больше 100, после десятичной точки не больше трёх цифр. Допустимы
знаки и более короткая дробная часть.

## Выходные данные

Максимальное количество точек целым числом и минимальное расстояние.
Абсолютная погрешность расстояния не больше 10⁻⁵.

## Проверка

Проверяющая программа сверяет число точек точно, а длину сдвига — с
абсолютной погрешностью 10⁻⁵.

## Решение

Пусть S=1000. Пропускаем целую часть координаты и разбираем только
дробную часть со знаком как целые тысячные X,Y, дополняя нулями.
Остаток сохраняется без преобразования неограниченного числа ведущих
нулей. Умножать двоичное вещественное число
и отбрасывать дробь не нужно. Две точки становятся целочисленными
одновременно тогда и только тогда, когда обе разности координат целые.
Значит, совпадают нормализованные остатки rx=X mod S, ry=Y mod S
в диапазоне 0..999.

Частоту каждой пары считаем в массиве S² с индексом rx·S+ry. Каждый
полезный перенос относится к одному классу и делает целыми ровно его
точки. Поэтому максимальная частота даёт максимальное количество.

Для класса допустимые начала: (rx/S+i,ry/S+j), где i,j целые. Ближайший
перенос выбирается отдельно по осям. Модули компонент в тысячных равны
dx=min(rx,S−rx), dy=min(ry,S−ry). Обозначим q=dx²+dy². Из классов
максимальной частоты берём минимальный q, затем находим sqrt(q)/S.

Частоты при чтении только растут. После увеличения частоты сравниваем
её с лучшей: большее количество важнее, при равенстве меньшее q.
Каждый новый претендент на равенство рассматривается, поэтому лучший
ответ среди уже обработанных точек сохраняется по индукции. Классы
доказывают оптимальность количества, независимый выбор ближайших
компонент — минимальность расстояния. Для половинных координат два
ближайших начала могут различаться, но квадрат расстояния одинаков.

Время O(S²+L), S=1000, L — длина входа; массив частот занимает O(S²).
С учётом сохранённых точек, входа и токенов общая память O(S²+L).
При ограниченной длине токенов получаем O(S²+n).
Количество≤50000, дробные тысячные со знаком в пределах ±999,
q≤500000, хватает знаковых 32 бит. Таблица занимает около 4 МБ.

Не поворачивать оси, не сливать совпадающие записи, не брать модуль
дробной части отрицательных координат. Близость вторична относительно
количества. Целая часть не меняет класс. Остаток около 1 допускает
маленький отрицательный перенос. Для группировки и сравнения q допуск
не нужен.
В тесте 34 ноль записан 4301 цифрой: ведущие нули допустимы, но
преобразование всей строки превышает стандартный лимит int в Python.
Перед преобразованием n также убираем ведущие нули.
В тесте 35 n=0008: количество читаем в десятичной системе, а не восьмеричной.

## Особенности языков

В C++, Go, Java отрицательные остатки нормализуются явно; Python
при положительном модуле и Rust rem_euclid уже дают нужный диапазон.
Все парсеры точно сохраняют остатки, в том числе для отрицательной дроби с нулевой
целой частью. Python и Go хранят упакованные знаковые 32-битные частоты.
В Java фиксируется локаль. Выводится девять дробных цифр: погрешность
округления ≤5·10⁻¹⁰. Вещественный только конечный корень, решения о
группах и равенствах полностью целочисленные.
