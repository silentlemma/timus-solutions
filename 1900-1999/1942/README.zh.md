# 1942. 最大格点同余类的最近平移

[Timus 1942](https://acm.timus.ru/problem.aspx?space=1&num=1942) · difficulty 646 · geometry

Original problem from Open Ural FU Personal Contest 2012 | by Vitaliy Belokobilskiy, Sergey Madzhuga.

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定平面上n个点，只能平移一次坐标原点，不能旋转坐标轴。新坐标
两分量均为整数的点被计数。先最大化计数，再在实现最大计数的
平移中最小化欧氏长度。重合点也作为不同记录分别计数。
时限1秒，内存64 MB。

## 输入

n满足1≤n≤50000，随后n对实数坐标。每个绝对值≤100，小数点后
至多三位。允许符号及较短小数部分。

## 输出

最大计数的整数，以及最小平移距离。距离绝对误差≤10⁻⁵。

## 评测方式

检查器精确核对点数，并按 10⁻⁵ 的绝对误差检查平移距离。

## 解法

令S=1000，跳过坐标整数部分，只将带原符号的小数部分补零后解析
成整数千分值X,Y。余数不变，也无需转换任意多个前导零。
不经二进制浮点乘法截断。两点能同时成为整数坐标，当且仅当
两个坐标差都是整数，因此归一化余数rx=X mod S、ry=Y mod S
必须相同，均在0..999。

用S²项数组统计每个余数对，键为rx·S+ry。每个有用平移属于一个
类，并恰好使该类全部点整数化，最大频率就是最大计数。

该类可选原点为(rx/S+i,ry/S+j)，i,j为整数。距离平方分量独立，
各取最近整数平移。千分值分量大小dx=min(rx,S−rx)，dy同理，
定义q=dx²+dy²。在最大频率类中选最小q，最后才求sqrt(q)/S。

频率只增不减。每次更新类后，按计数更大、同计数时q更小维护
当前最优。每个新达到并列频率的类都会比较，归纳保持已处理点的
最优解。类划分证明计数最优，逐轴最近整数选择证明距离最小。
半整数可能对应两个最近平移，但平方距离相同。

时间O(S²+L)，S=1000，L为输入长度；频率辅助空间O(S²)。计入
保留的点、输入和词元后，总空间O(S²+L)。词元长度有界时为O(S²+n)。
计数≤50000，带符号的小数千分值在±999，
q≤500000，有符号32位足够。频率表约4 MB。

不能旋转、合并重合记录、把负小数部分直接取绝对值，也不能先
选最近类再考虑计数。整数部分不影响分类。接近1的余数对应很小
的负平移。分组和比较q不需epsilon。
测试34把零写成4301位数字：前导零合法，但整串转换会触发Python
默认的int位数限制。转换n之前也要去掉前导零。
测试35使用n=0008：点数必须按十进制读取，不能推断为八进制。

## 各语言说明

C++、Go、Java显式归一化负余数；Python正模及Rust rem_euclid
已给正确范围。解析器精确保留余数，包括负小于1的数的符号。Python、Go用
紧凑32位频率数组；Java固定输出区域设置。输出九位小数，舍入
误差≤5·10⁻¹⁰。只有最终平方根使用浮点，分组和并列决策都精确。

## 优化解法

C++ 版本把每一对余数编码为一个整数。将这些键排序后统计相同键的连续段，频次相同则比较距离的平方。只有输出距离时才开平方。输入长度为 L、点数为 N 时，时间复杂度为 O(L + N log N)，额外空间为 O(N)。评测数据来自提交 11316985。

Java 1.8 版本也将每对余数编码为一个整数，排序后统计连续段。提交 11317110 耗时 0.109 秒，使用 804 KB；基础版耗时 0.125 秒，使用 6036 KB。

Python 3.12 x64 版本也将每对余数编码为一个整数，排序后统计连续段。提交 11317108 耗时 0.203 秒，使用 3384 KB；基础版耗时 0.281 秒，使用 11584 KB。

Rust 1.75 x64 版本也将每对余数编码为一个整数，排序后统计连续段。提交 11317104 耗时 0.015 秒，使用 412 KB；基础版耗时 0.031 秒，使用 6016 KB。

Go 1.14 x64 版本也将每对余数编码为一个整数，排序后统计连续段。提交 11317099 耗时 0.031 秒，使用 1260 KB；基础版耗时 0.078 秒，使用 8908 KB。
