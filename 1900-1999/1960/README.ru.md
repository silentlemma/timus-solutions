# 1960. Различные палиндромы каждого префикса

[Timus 1960](https://acm.timus.ru/problem.aspx?space=1&num=1960) · difficulty 434 · strings

Original problem from Ural FU contest. Kontur Cup. Petrozavodsk training camp. Winter 2013 | by Mikhail Rubinchik (prepared by Grigory Nazarov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для каждого непустого префикса слова найти число различных непустых
непрерывных подстрок-палиндромов. Одинаковые строки учитываются один раз,
даже при нескольких вхождениях. Палиндром совпадает со своим обращением.
Ограничения: 1 с, 64 МБ.

## Входные данные

Одно слово из n строчных латинских букв, 1≤n≤100000. Отдельного числа
длины во вводе нет.

## Выходные данные

n чисел через пробел: ответы для длин префикса от 1 до n. Пустой
палиндром не учитывается. Считаются различные строки, а не вхождения
и не длина самого длинного палиндрома.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
aba
```

```
1 2 3
```

## Решение

В примере префикс `a` содержит только `a`, префикс `ab` — `a,b`, а `aba` добавляет строку `aba`. Поэтому ответы 1,2,3.

### Не более одного нового палиндрома

После добавления c любая новая подстрока заканчивается на c. Пусть P —
самый длинный палиндромный суффикс нового префикса. Любой более короткий
палиндромный суффикс Q также является собственным префиксом P, а значит,
уже встречался с концом раньше c. Новым может быть только P. За один
шаг появляется ноль или один различный палиндром, всего их не больше n.

### Дерево палиндромов

Используем стандартный eertree, см. [Rubinchik–Shur, 2015](https://arxiv.org/abs/1506.04862).
Ниже самостоятельное описание. Реальная вершина представляет палиндром,
хранит длину, ссылку на самый длинный собственный палиндромный суффикс
и переходы обрамления Q→cQc. Два служебных корня имеют длины −1 и 0,
индексы 0 и 1. Ссылки обоих ведут в индекс 0. Однобуквенная вершина
ссылается на пустой корень. Внутренний палиндром и буква обрамления
однозначно задают непустой палиндром, поэтому входящий переход единственен.

Храним last — самый длинный палиндромный суффикс перед добавлением.
Идём по суффиксным ссылкам, пока перед кандидатом не окажется буква c.
У корня длины −1 проверяется сама новая буква, поэтому поиск завершается.
Самый длинный расширяемый Q даёт новый максимальный суффикс P=cQc.
Если переход c существует, переиспользуем вершину, иначе создаём длину |Q|+2.

Для новой длины 1 ссылка ведёт к пустому корню. Иначе начинаем с link[Q],
так же находим следующий расширяемый суффикс и берём его существующий
переход c. Это максимальный собственный палиндромный суффикс P. Вершина
уже есть: этот палиндром — собственный префикс P и встречался раньше.
Переносим last в P, выводим число реальных вершин total_nodes−2.

### Корректность и сложность

Ссылки перебирают палиндромные суффиксы по убыванию длины. Первый
расширяемый даёт максимальный новый суффикс. Пара «внутренний палиндром,
буква» однозначно определяет строку: отсутствие перехода означает новое
значение. Остальные суффиксы уже были по первой лемме. По индукции дерево
содержит ровно различные палиндромы каждого префикса.

Суммарная работа обоих поисков линейна. Пусть ℓ_old,ℓ_new — длины старого
и нового last. Каждая неудачная ссылка уменьшает длину, обрамление
увеличивает на два: число переходов не больше ℓ_old−ℓ_new+2. Сумма
телескопируется. Для второго поиска аналогично используем q_old,q_new —
длины максимальных собственных суффиксов last. Начальная длина ≤q_old,
конечная q_new−2, граница q_old−q_new+2 тоже телескопируется. Если вершина
не создаётся, второго поиска нет, а q_new≤q_old+2 сохраняется.

Нативные версии выделяют переходы по 26 буквам: `O(26n)` инициализации
и памяти, то есть `O(n)` при фиксированном алфавите. Python хранит разреженный
словарь точных ключей parent*26+letter_code: ожидаемое время `O(n)`, память
`O(n)`. Представление ключа однозначно, это не вероятностный хеш подстроки.
Вершин максимум n+2.

Нельзя учитывать корни, суммировать вхождения, забывать чётные палиндромы
или считать каждый шаг новым: для `abca` последний ответ 3. До обращения
к символу проверяйте левую границу: отрицательный индекс Python не вызовет
ошибку, но прочитает другой символ. Перебор всех вхождений квадратичен.

## Особенности языков

C++ хранит массивы внутри вершин. Go 1.14 и Rust 1.75 используют машинные
целые индексы. Java 8 — один плоский int-массив переходов, без объектов
на вершину. Python работает с bytes и разреженными целыми ключами.
Rust использует только стандартную библиотеку. Выбор CPython проверяется
замерами ресурсов.
