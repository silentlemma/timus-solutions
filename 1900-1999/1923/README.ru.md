# 1923. Две области с поочерёдным расширением по цветам

[Timus 1923](https://acm.timus.ru/problem.aspx?space=1&num=1923) · difficulty 545 · bfs

Оригинальная задача — фольклор, подготовка — Дмитрий Карпенко; Уральская региональная олимпиада по программированию 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В таблице n×m каждая клетка имеет цвет 0..9. Связные по сторонам
клетки одного цвета образуют страну. Первая сторона изначально владеет
всей страной левой нижней клетки, вторая — правой верхней.
Начальные цвета различны. Стороны ходят по очереди, первой ходит первая.
На ходу сторона меняет союз на заданный цвет, сохраняет прежние владения
и присоединяет соседние страны нового цвета. Выбирать собственный текущий
цвет или цвет соперника нельзя. По допустимой последовательности ходов
найти итоговые площади. Площадь клетки равна 1. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Числа n,m, 2≤n,m≤50, затем n строк по m цифр.
Далее l, 2≤l≤100, и ровно l выбранных цветов 0..9 в порядке ходов.
Числа могут разделяться произвольными пробельными символами.

## Выходные данные

В первой строке площадь первой стороны, во второй — второй.
Порядок соответствует левой нижней и правой верхней исходным странам.

## Проверка

Точное сравнение двух целых токенов в указанном порядке.

## Решение

Для каждой клетки храним владельца: нейтральная, первая или вторая
сторона. Для каждой стороны — список её клеток. Заранее построим
четырёх соседей по сторонам с проверкой границ. Исходный цвет нейтральной
клетки не меняется; у занятой клетки прежний цвет уже не определяет владельца.

Сначала пометим обе начальные клетки и расширим каждую область по её
исходному цвету через нейтральные клетки. Получатся целые начальные
страны, а не только угловые клетки.

На ходу с новым цветом c просматриваем все клетки текущей области как
очередь. Нейтрального соседа исходного цвета c сразу помечаем своим
и добавляем в ту же очередь. Добавленные клетки тоже обрабатываются
на этом ходу. Так присоединяется вся соседняя страна, а не только граница.
Все прежние клетки остаются в списке при любой последующей смене цвета.

Перекрашивать сохранённые цифры и запоминать текущие союзы для самой
симуляции не требуется: допустимость ходов гарантирована входом.
Нейтральные цвета остаются исходными, занятые клетки распознаются
по владельцу. Клетка соперника всегда недоступна независимо от её старой цифры.

Докажем инвариант: каждый список в точности содержит связную область
своей стороны. После начальных обходов это верно. Любая добавленная
на ходу клетка нейтральна, имеет нужный цвет и примыкает к прежней
или только что присоединённой клетке, поэтому её страна должна войти
в область. Обратно, очередь пройдёт весь путь внутри каждой соседней
страны нужного цвета, значит ничего не пропустит. Пометка до добавления
устраняет повторы, проверка владельца защищает соперника.
Старые клетки не удаляются, инвариант сохраняется. Длины итоговых
списков и есть требуемые площади.

Каждое расширение просматривает до nm клеток и до четырёх соседей.
Время O((l+1)nm). Владельцы, соседи и списки требуют O(nm) памяти;
с учётом сохранённой последовательности ходов — O(nm+l).

Начальные углы — левый нижний и правый верхний. Нужно взять начальные
страны целиком. Сохраняйте прежние владения и завершайте обработку
новых клеток в тот же ход. Диагональное касание не считается соседством;
соседи по горизонтали не переходят на другую строку. Старый цвет клетки
не может отменить её владельца. При нечётном l не добавляйте лишний ход.
Генерируемые ходы должны исключать оба текущих цвета.

## Особенности языков

Клетка (r,c) кодируется как r·m+c при нумерации с нуля.
В C++, Go, Java и Rust курсор сравнивается с текущей растущей длиной
списка. Python обрабатывает добавленные в список элементы в том же
проходе. В Java две очереди — плоские массивы достаточной длины,
в остальных версиях используются динамические списки или векторы.
Все обходы итеративные.
