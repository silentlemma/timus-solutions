# 1931. Кого сравнивают чаще всего

[Timus 1931](https://acm.timus.ru/problem.aspx?space=1&num=1931) · difficulty 169 · simulation

Original problem from Open Ural FU Championship 2012 | by Olga Soboleva.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Люди стоят в заданном порядке и имеют различные положительные оценки.
Сначала текущим кандидатом является участник №1. Каждого следующего
сравнивают с кандидатом; меньшая оценка нового участника заменяет кандидата.
Сравнение учитывается у ОБОИХ, в том числе при замене. Найти участника,
которого сравнивали наибольшее число раз. При равенстве подходит любой.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Сначала n, 1≤n≤100000. Далее n попарно различных целых a1..an,
1≤ai≤1000000000. Номера 1..n соответствуют порядку ввода.

## Выходные данные

Один номер участника с максимальным количеством сравнений.
При n=1 вывести 1: единственного человека не сравнивали ни разу.

## Проверка

Любой допустимый ответ: checker.py требует ровно одно целое в 1..n,
буквально моделирует процесс с отдельным счётчиком каждого участника
и проверяет максимальность выбранного. Сохранённый номер не канонический,
другой участник с тем же максимумом принимается.

## Примеры

```
6
2 5 3 4 1 9
```

```
1
```

## Решение

Храним оценку, номер и число сравнений текущего кандидата, а также
наибольшее замеченное число и его номер. Сначала текущий счётчик нулевой.
При появлении следующего сначала увеличиваем счётчик СТАРОГО кандидата
и обновляем лучший ответ, если значение больше. Лишь затем сравниваем
оценки. Если новый лучше, заменяем кандидата и ставим его счётчик равным
1: он уже участвовал в выборе. Если кандидат остаётся, всё количество
сравнений непринятого участника равно 1.

Кандидат всегда является минимумом обработанного префикса; его счётчик
учитывает все участия, включая входящее и проигранное сравнение, если они
были. Не ставший кандидатом новичок не побьёт максимум: его единственное
сравнение проходит с кандидатом, чей увеличенный счётчик уже не меньше 1.
То же верно для первого сравнения нового кандидата. Каждое дальнейшее
увеличение происходит во время его кандидатства и явно проверяется.
Сменённые кандидаты не возвращаются, их суммы фиксированы. По индукции
сохранённый ответ достигает общего максимума. Начальный номер 1 покрывает
случай полного отсутствия сравнений.

O(n) времени и O(1) рабочих счётчиков. Программы буферизуют вход
в массиве, векторе или токенах, поэтому общая память O(n).

Минимальная оценка не гарантирует наибольшее количество сравнений.
Проигрыш старого кандидата учитывается ДО замены. Счётчик нового
начинается с 1, не с 0. Выведите номер, а не число сравнений.
Не отвергайте иной ответ только из-за равенства максимумов:
например, для [3,2,1,4] подходят и 2, и 3.

## Особенности языков

Оценки помещаются в знаковые 32 бита, счётчики не больше n−1≤99999.
Оценки только сравниваются. В Java — буферизованное чтение целых;
C++, Go и Rust хранят массив значений, Python использует генератор
разобранных токенов. Массив счётчиков участников в решениях не нужен;
он используется в независимом проверяющем скрипте.
