# 1931. 谁参加的比较次数最多

[Timus 1931](https://acm.timus.ru/problem.aspx?space=1&num=1931) · difficulty 168 · simulation

Original problem from Open Ural FU Championship 2012 | by Olga Soboleva.

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

按固定顺序排列的人各有互不相同的正整数分数。最初 1 号为当前候选人。
依次将后面的人与当前候选比较，只有新人分数更小时才替换候选。
一次比较同时计入双方，即使这次比较更换了候选。输出参加比较次数
最多的成员编号；并列最大时任意一个均可。限制：1 秒，64 MB。

## 输入

首先 n，1≤n≤100000；随后 n 个互不相同整数 a1..an，
1≤ai≤1000000000。编号 1..n 为原输入次序。

## 输出

一个比较次数最大的成员编号。n=1 时输出 1，唯一成员比较次数为零。

## 评测方式

允许任意合法答案。checker.py 要求恰好一个 1..n 内整数，逐次模拟
比较并给每人维护单独计数，检查被选计数是否全局最大。保存的编号
只是其中之一，其他并列赢家同样接受。

## 样例

```
6
2 5 3 4 1 9
```

```
1
```

## 解法

维护当前候选的分数、编号和比较次数，以及已见最大次数及编号。
初始当前次数为零。每来一个新人，先增加旧候选的次数，若超过
最好记录则更新答案。之后才比较分数；若新人更小，替换候选并将
当前次数置为 1，因为新人已经参加了选中它的那次比较。否则，
未成为候选的新人成员终生只参加这一次比较。

当前候选始终是已处理前缀中的最小分数者，计数包含其全部参与，
包括适用的入选与落选比较。未入选新人不会超过已记录最大值：
它唯一的比较对应旧候选已增加到至少 1 的计数。新候选的初始
一次比较同理。此人后来的每次增加都发生在候选阶段，会被显式
检查。被替换者不再回来，次数固定。因此归纳可证记录答案达到
全局最大。初始答案 1 也覆盖没有任何比较的情形。

时间 O(n)，工作计数器空间 O(1)。这些程序以数组、向量或记号
缓冲输入，因此总空间 O(n)。

分数最小者不一定比较最多。旧候选落选的比较必须在替换之前计入。
新候选次数从 1 开始，不是 0。输出编号，不是次数。并列最大时
不同编号仍然正确，例如 [3,2,1,4] 的答案既可为 2，也可为 3。

## 各语言说明

分数在有符号 32 位范围内，计数至多 n−1≤99999；对分数只比较。
Java 使用缓冲整数读取，C++、Go、Rust 保存基本类型值数组，Python
以生成器遍历解析的记号。提交算法不需要每人一个计数器数组，
独立检查器才使用这种完整计数方式。
