# 1920. Все чётные длины циклов квадратной решётки

[Timus 1920](https://acm.timus.ru/problem.aspx?space=1&num=1920) · difficulty 728 · constructive

Автор оригинальной задачи — Алексей Самсонов, подготовка — Дмитрий Иванков; NEERC 2012, Восточный подрегион.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно построить простой цикл из ровно L узлов квадратной решётки n×n.
Соседние узлы, включая последний и первый, находятся на расстоянии 1.
Каждый узел разрешено использовать не более одного раза. Координаты
целые от 1 до n. Вывести любой подходящий цикл либо сообщить,
что такого цикла нет. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Два целых числа n,L: 2≤n≤100 и 4≤L≤20 000.

## Выходные данные

Если цикл невозможен, вывести `Unsuitable device`. Иначе вывести
`Overwhelming power of magic`, а затем L пар координат по одной
на строке в порядке обхода. Первую вершину в конце повторять не нужно.
Допустимы любой правильный цикл, начальная вершина и направление.

## Проверка

Специальный проверяющий код контролирует заголовок, число координат,
целочисленность, границы, различные вершины и единичное манхэттенское
расстояние каждого ребра, включая замыкающее. Ложное заявление
о невозможности отклоняется. Маршрут из ожидаемого файла не является
единственным ответом и не сравнивается по токенам.

## Решение

Раскрасим вершину (r,c) по чётности r+c. Каждое ребро меняет цвет,
поэтому любой цикл имеет чётную длину. Различность вершин требует L≤n².
Докажем достаточность этих условий, построив все чётные длины от 4
до M=n²−(n mod 2).

Начнём с границы квадрата 2×2: её длина 4. Расширение заменяет ребро
u—v обходом u—a—b—v через две новые соседние вершины по другую сторону
ребра. Добавляются две вершины; сохраняются единичные рёбра и один
простой цикл.

Положим W=n−(n mod 2), это чётное число. Порядок расширений фиксирован:

1. Достроим прямоугольник высоты 2 до ширины W по одному столбцу.
   Правое вертикальное ребро заменяем обходом через новый столбец.
2. Добавим строки с 3 до n. В каждой строке обрабатываем пары столбцов
   (1,2), (3,4), …, (W−1,W), заменяя горизонтальное ребро сверху обходом
   через две новые вершины пары.
3. При нечётном n добавим последний столбец парами строк (1,2), (3,4),
   …, (n−2,n−1), используя вертикальные рёбра слева от этих пар.

Нужные рёбра всегда существуют. Первый этап оставляет всю нижнюю
границу. Каждый обход второго этапа создаёт горизонтальное ребро пары
для следующей строки и сохраняет правую вертикальную границу.
Третий этап использует непересекающиеся рёбра этой границы. Все новые
вершины ещё не использованы. Остановка посреди строки также корректна.

При чётном n второй этап охватывает все n² узлов. При нечётном третий
охватывает все, кроме правого нижнего угла, то есть n²−1 узлов.
Каждый шаг добавляет ровно две вершины, поэтому после (L−4)/2 шагов
получается любая нужная чётная длина до M. Это доказывает построение
и точное условие отказа.

Храним ориентированные рёбра цикла массивом следующей вершины по
индексу r·n+c, координаты с нуля. Если выбранное ребро ориентировано
в обратную сторону, меняем местами обе старые и обе новые вершины.
Меняем три ссылки. Затем обходим ровно L вершин из верхнего левого
угла и переводим координаты к нумерации с единицы.

O(n²+L) времени и памяти с учётом инициализации массива ссылок
и буферизации вывода. Изменение ссылок занимает O(1) на две вершины.
Невозможный вход отклоняется за O(1).

В нечётной решётке нельзя включить все вершины, но можно n²−1,
а не только n(n−1). Не забывайте последний столбец. При развороте
ребра переставляются обе пары концов. Останавливайтесь после точного
числа расширений, разрешайте незавершённую строку и учитывайте
замыкающее ребро без повторной печати первой вершины.

## Особенности языков

Индексы и длины помещаются в обычные целые. C++, Go, Java и Rust
используют плоские массивы и явные циклы. Python лениво генерирует
тот же порядок расширений. Java, Python и Rust буферизуют вывод,
Go использует буферизованный ввод-вывод, C++ отключает синхронизацию
потоков. Ссылки позволяют обойтись без сдвигов элементов списка.
