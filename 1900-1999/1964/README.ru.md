# 1964. Китайский язык

[Timus 1964](https://acm.timus.ru/problem.aspx?space=1&num=1964) · difficulty 172 · math

Original problem from Open Ural FU Personal Contest 2013 | by Alexander Ipatov.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть множество из n различных элементов и k его подмножеств. Известно
лишь, что в подмножестве i находится не менее a_i элементов. Найти
минимальное возможное число элементов, принадлежащих одновременно всем
k подмножествам. Перекрытия произвольны. Лимиты: 1 секунда, 64 МБ.

## Входные данные

Первая строка содержит n,k: 1≤n≤10⁹, 2≤k≤20. Во второй строке k целых
чисел a_i, для каждого 1≤a_i≤n.

## Выходные данные

Одно целое число — минимальный размер пересечения всех k множеств.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
1000000000 2
800000000 800000000
```

```
600000000
```

```
1000000000 2
500000000 500000000
```

```
0
```

## Решение

В первом примере в каждом множестве может отсутствовать не более
200 000 000 элементов. Даже непересекающиеся пропуски покроют лишь
400 000 000 из миллиарда. Остальные 600 000 000 обязательно общие;
непересекающиеся пропуски достигают этой границы. Во втором два
множества можно выбрать как разные половины общей совокупности,
поэтому пересечение пусто.

Рассмотрим дополнения. Пусть b_i=n−a_i — максимальное число элементов,
отсутствующих в множестве i. Чтобы элемент не попал в общее пересечение,
он должен отсутствовать хотя бы в одном множестве. Объединение дополнений
содержит не больше min(n,Σb_i) элементов. Поэтому пересечение не меньше

max(0,n−Σb_i) = max(0,Σa_i−(k−1)n).

Докажем достижимость. Пронумеруем элементы циклически от 0 до n−1.
Первому дополнению отдадим первые b_1 последовательных номеров,
следующему — следующие b_2 и так далее, переходя через n−1 к нулю.
Каждое b_i<n, поэтому внутри одного дополнения номера не повторяются,
и его размер ровно b_i. Исходное множество имеет ровно a_i элементов,
что удовлетворяет и условию «не менее».

При Σb_i<n все дополнения непересекающиеся, их объединение имеет размер
Σb_i. При Σb_i≥n последовательный обход посетит все n номеров, то есть
объединение покроет всю совокупность. В обоих случаях размер объединения
равен min(n,Σb_i), и нижняя граница пересечения достигается.

Строить множества в программе не нужно. Начинаем с n, вычитаем все
n−a_i, затем заменяем отрицательный итог нулём.

Время `O(k)`, память `O(k)`: реализации сохраняют k входных значений.
Сам аккумулятор требует `O(1)` дополнительной памяти.

Заданы нижние границы размеров, а не вероятности или независимые
события. Попарные пересечения и размер наименьшего множества не дают
искомый минимум. Отрицательный результат заменяем нулём. Итог не больше
n, но промежуточные суммы близки к 20·10⁹, а аккумулятор может опуститься
ниже −2³¹: нужны знаковые 64-битные числа. Если все a_i=n, ответ равен n.

## Оптимизированные решения

`1964_math_optimized.py`. Сохраняется граница max(0,N-sum(N-a[i])) для минимального пересечения. Накапливается знаковое значение, ограничение нулём применяется в конце; при K<=20,N<=10^9 промежуточное значение может выйти ниже знаковых32 бит, поэтому Rust сохраняет i64. Рассуждение о множествах и ответ прежние. Время O(K). Разбор блоками65536байт потребляет каждую нижнюю границу напрямую, без старого lower_bounds. Остаются блоки парсера и незаконченный токен; состояние арифметики O(1). Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1964_math.py`: время 0.078 s → 0.156 s; память 476 KB → 256 KB.

`1964_math_optimized.rs`. Сохраняется граница max(0,N-sum(N-a[i])) для минимального пересечения. Накапливается знаковое значение, ограничение нулём применяется в конце; при K<=20,N<=10^9 промежуточное значение может выйти ниже знаковых32 бит, поэтому Rust сохраняет i64. Рассуждение о множествах и ответ прежние. Время O(K). K границ читаются сразу в накопитель, без вектора границ и входной String. Дополнительное состояние O(1). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1964_math.rs`: время 0.031 s → 0.046 s; память 236 KB → 64 KB.

Оптимизированное решение на C++ читает через `scanf` вместо `iostream` и
вычитает каждое `n − a_i` из накопителя сразу после чтения, а не хранит
k значений в векторе, поэтому ему нужна память `O(1)`; накопитель
по-прежнему знаковое 64-битное целое (`long long`), ведь вычитается до
20 недостач величиной до 10⁹ каждая: {1964_math_optimized.cpp}.

Оптимизированное решение на Java считает то же число, но читает ввод
через `BufferedReader` и `StringTokenizer` вместо `Scanner`, регулярные
выражения которого требуют времени и памяти на подготовку:
{1964_math_optimized.java}.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1964_math_optimized.cpp`: сокращение времени +51.61%; сокращение
  памяти +73.53%; база: `1964_math.cpp`.

- `1964_math_optimized.java`: сокращение времени +25.60%; сокращение
  памяти +68.20%; база: `1964_math.java`.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1964_math_optimized.py`: место по времени 27/27, по памяти 2/27 в этой сопоставимой выборке.

`1964_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
