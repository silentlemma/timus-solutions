# 1974. Максимум совпадений при сдвиге последовательностей нот

[Timus 1974](https://acm.timus.ru/problem.aspx?space=1&num=1974) · difficulty 1157 · bitmask, bruteforce

Автор оригинальной задачи — Денис Дублённых; XVII Открытый чемпионат Урала по спортивному программированию (май, 2013).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дана исходная мелодия и m сравниваемых. Для двух непрерывных подстрок
одинаковой длины считаем позиции с одинаковой абсолютной высотой звука.
Абсолютная похожесть — максимальное такое число по всем парам подстрок.
Несовпадения разрешены и не штрафуются. Относительная похожесть делит
этот максимум на длину сравниваемой мелодии. Ограничения: 1 секунда, 64 МБ.

## Входные данные

Первая строка: длина n и n звуков исходной мелодии. Затем m, 1≤m≤100,
и m строк с длиной и звуками очередной мелодии. Все длины от 1 до 1000.

Звук записан dN, dN+ или dN-, октава d от 1 до 8, буква N от A до G.
Смещения натуральных нот: C=0, D=2, E=4, F=5, G=7, A=9, B=11;
+ и - меняют их на полтона. Равны C+=D-, D+=E-, E=F-, F=E+, F+=G-,
G+=A-, A+=B-. B+ — это C следующей октавы, C- — B предыдущей.
Несуществующие 1C- и 8B+ во входе отсутствуют.

## Выходные данные

m вещественных чисел, по одному на мелодию в исходном порядке.
Абсолютная или относительная ошибка до 10⁻⁶. Значения лежат в [0,1].

## Проверка

Проверяющая программа сравнивает каждое число с погрешностью не больше
10⁻⁶ · max(1, |ответ|).

## Примеры

```
4 5C+ 5D 5C 5G
3
2 5D- 5D
2 5D 4B+
4 5D 5C+ 5D 5F-
```

```
1.000000
1.000000
0.500000
```

## Решение

### Общая высота и полное перекрытие

Звук преобразуется в 12(d−1)+смещение+знак, число от 0 до 95. Так
автоматически учитываются и записи через границу октав. Октава важна;
транспонировать целую мелодию не разрешается.

Зафиксируем сдвиг индексов i−j. Любую пару подстрок с этим сдвигом можно
расширить до полного перекрытия последовательностей. Совпадения не
исчезнут, поскольку несовпадающая позиция не даёт штрафа. Достаточно
посчитать равные звуки для n+L−1 непустых перекрытий, L — длина цели.
Максимум в точности совпадает с исходным определением.

### Пары позиций в компилируемых версиях

Для каждой высоты храним список её позиций в исходной мелодии. Совпавшая
пара (i,j) принадлежит ровно сдвигу i−j: увеличиваем счётчик i−j+L−1.
Максимум счётчиков — ответ. Каждое совпадение перекрытия учтено один раз,
несовпадения не учитываются, что доказывает корректность. Списки позиций
переиспользуются, а счётчики для новой цели создаются заново.

При K совпавших парах время — `O(n+L+K)`, в худшем случае `O(nL)`.
Рабочая память — `O(n+L+96)` без буферов. Так работают C++, Go, Java и Rust.

### Python: независимые счётчики внутри одного целого

Возьмём основание 2¹⁰=1024. Для высоты p построим
M[p]=Σᵢ:звук(i)=p 2^(10i). Для цели суммируем

T = Σⱼ M[цель[j]] · 2^(10(L−1−j)).

Цифра в позиции i−j+L−1 равна числу совпавших пар этого сдвига. Каждая
цифра не больше min(n,L)≤1000, поэтому переносов между полями нет.
Извлекаем десятибитные поля и выбираем максимум. При достижении min(n,L)
можно завершить поиск: больше быть не может. Делим на L, а не на n.

Упакованное число содержит B=10(n+L−1) бит. Выполняются L сложений со
сдвигами и не больше n+L−1 извлечений поля. В модели w-битных слов
консервативная оценка сравнения — `O((n+L)·ceil(B/w))`, масок высот —
`O(96·ceil(10n/w))` слов. Арифметика больших целых выполняет плотные
операции внутри реализации, без Python-цикла по nL парам.

В примере 5C+=5D-, поэтому первая цель совпадает с началом исходной
мелодии: 2/2=1. Вторая совпадает с позициями 2 и 3, поскольку 4B+=5C:
снова 2/2=1. У последней цели вторую и третью ноты совмещаем с первыми
двумя исходными, получаем два совпадения и 2/4=0,5.

Это не общая подстрока и не подпоследовательность: несовпадения можно
оставлять, но сдвиг один для всех позиций. Нормализуйте одинаковые
записи звука, включая B+ и C- между октавами. Делитель — длина цели.
Ноль допустим. Для счётчика до 1000 нужны десять бит, не девять.
Рассматривайте все сдвиги, обнуляйте счётчики между целями.

## Особенности языков

Python использует точные большие целые и поля счётчиков. Компилируемые
версии перечисляют совпадающие пары позиций. Java читает звуки прямо
из байтового буфера без выделения 100 000 временных строк. Структура
позиций источника не меняется при сравнении.
