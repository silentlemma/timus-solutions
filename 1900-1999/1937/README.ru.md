# 1937. Палиндром из двух циклических строк

[Timus 1937](https://acm.timus.ru/problem.aspx?space=1&num=1937) · difficulty 1217 · suffix_structures

Original problem from Open Ural FU Championship 2012 | by Olga Soboleva (prepared by Egor Shchelkonogov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Для двух строк A,B независимо выберите циклические сдвиги. Их склейка,
сначала сдвинутая A, затем сдвинутая B, должна совпасть со своим
разворотом. Найдите любые два начала или установите невозможность.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Две строки из строчных латинских букв: A длины n и B длины m,
1≤m<n≤100000. После выбранного начального символа чтение продолжается
циклически с сохранением порядка букв.

## Выходные данные

Если решения нет, выведите No. Иначе Yes и на следующей строке два
начала в A и B: нумерация от 1, границы n и m соответственно.
Подходит любая пара, дающая палиндромную склейку.

## Проверка

Проверяющая программа убеждается, что напечатанные сдвиги действительно
дают палиндром, а для `No` сама проверяет, что подходящей пары нет.
Принимается любая подходящая пара.

## Примеры

```
cdedab
bac
```

```
Yes
5 3
```

```
aaaa
bbb
```

```
No
```

## Решение

Перейдём к нумерации с нуля. Разделим сдвинутую A на U V, где |U|=m,
|V|=L=n−m. Склейка U V Brot является палиндромом тогда и только тогда,
когда V — палиндром, а Brot=reverse(U). Так разделяются проверка
середины и принадлежность циклическим сдвигам без перебора n·m пар.

Пусть C=reverse(B), P=C+C[:-1]. Все окна длины m в P — ровно сдвиги C.
Построим суффиксный автомат P. Просматриваем первые n+m−1 символов
A+A, поддерживая наибольший суффикс, встречающийся в P. При наличии
перехода продолжаем его; иначе идём по суффиксным ссылкам до нужного
перехода и сокращаем длину до максимальной длины достигнутого состояния.
Совпадение длины хотя бы m подтверждает внешний фрагмент U с началом
a=position−m+1. Так проверяются все n возможных начал.

Состояние хранит максимальную длину, суффиксную ссылку, переходы и
конец одного вхождения f. При добавлении символа создаём состояние
и добавляем отсутствующие переходы вдоль суффиксных ссылок. Первый
имеющийся переход p→q даёт ссылку на q, если len(q)=len(p)+1.
Иначе клонируем q с длиной len(p)+1, копируя переходы, ссылку и конец
вхождения; перенаправляем затронутые переходы вдоль ссылок на клон,
затем связываем с ним q и новое состояние. Множество подстрок P
сохраняется. Последние m символов совпадения встречаются с концом f,
поэтому j=f−m+1 — начало нужного сдвига C, 0≤j<m. После разворота
это сдвиг B с началом (−j mod m). Возвращаем a+1 и второе начало+1.

Для середины вычислим радиусы Манакера на A+A только нужной чётности.
Нечётный радиус считает пары без центрального символа, чётный — пары
вокруг промежутка перед центром. Условие для V с началом a+m:
radius[a+m+floor(L/2)]≥floor(L/2). Манакер использует зеркальный радиус
внутри самого правого палиндрома и расширяет его за правую границу,
поэтому суммарное время линейно. Если подходящей середины вообще нет,
автомат строить не нужно. Каждая найденная пара удовлетворяет двум
необходимым и достаточным условиям; отсутствие пары после полного
просмотра исключает все возможные сдвиги A.

Время и память O(n+m) при фиксированном алфавите из 26 букв. Плотные
переходы занимают O(26m) целых; состояний меньше 2|P|. Проходы по
суффиксным ссылкам амортизируются успешными шагами. Java просматривает
не больше 26 разреженных переходов, так что оценка не меняется.

Перед поиском сдвигов разверните B, затем поменяйте знак её найденного
начала. Достаточно совпадения хотя бы m символов, даже если автомат
знает более длинный суффикс. Включите последнее начало n−1. У повторной
строки бывает несколько правильных вторых индексов. Середина и внешний
фрагмент должны подходить при одном и том же начале. Из m<n следует,
что середина непустая; её чётность задаёт смысл радиуса.

## Особенности языков

C++, Go, Rust и Python хранят плотные таблицы и состояния в 32 битах.
Go int32 и Rust i32 сохраняют размер главного массива. У Python при
m=99999 данные автомата занимают 46 399 304 байта, один массив радиусов
ещё 800 000 байт. Java использует примитивные head/next/destination/letter,
не больше 3|P|+1 ячеек переходов и байтовые буквы, оставляя место JVM.
Все индексы и смещения в таблице помещаются в 32 бита.
