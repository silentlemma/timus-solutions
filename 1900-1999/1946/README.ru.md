# 1946. Подсчёт отсортированных таблиц голов

[Timus 1946](https://acm.timus.ru/problem.aspx?space=1&num=1946) · difficulty 1831 · dp

Original problem from Open Ural FU Personal Contest 2012 | by Alexander Ipatov.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

n игроков встречаются попарно по разу. В матче ровно три гола:
3:0, 2:1, 1:2 или 0:3. Суммы голов игроков сортируются по невозрастанию.
Посчитать различные итоговые списки, без имён и без учёта разных
результатов матчей, дающих тот же список. Ограничения: 1 секунда, 64 МБ.

## Входные данные

Одно целое n, 2≤n≤50.

## Выходные данные

Количество различных списков по модулю 1000000007.

## Проверка

Ответы сравниваются по токенам.

## Примеры

```
3
```

```
8
```

## Решение

Считаем обратные списки a₁≤…≤a_n. Пусть T=3n(n−1)/2,
L(k)=3k(k−1)/2. Неотрицательный целый список реализуем тогда и только
тогда, когда сумма T и сумма каждого префикса длины k не меньше L(k).
Каждый результат не больше M=3(n−1).

Необходимость: у любых k игроков есть k(k−1)/2 внутренних матчей,
все три гола которых остаются в группе; внешние добавляют неотрицательные
голы. У k наименьших результатов тоже выполняется неравенство.

Достаточность доказывается потоком: исток→узел матча с ёмкостью 3,
матч→два участника с ёмкостью T+1, участник j→сток с ёмкостью a_j.
В разрезе стоимости не больше T обозначим через S игроков со стороны
истока. Матч там возможен только с обоими концами в S, иначе пересечёт
дугу T+1. Для фиксированного S дешевле включить все внутренние матчи.
Стоимость 3·(C(n,2)−C(|S|,2))+Σ_{j∈S}a_j не меньше T по условию для
наименьшего префикса. Поэтому поток T существует; целочисленность
ёмкостей даёт целые голы, каждый матч распределяет ровно три, каждый
игрок получает заданную сумму. Условие достаточно.

dp_i[P][v] — число неубывающих префиксов из i результатов с суммой P
и последним v, выполняющих нижние границы. База dp₀[0][0]=1.
Среднее префикса не превосходит среднего всего списка, поэтому
достаточно L(i)≤P≤U(i)=floor(Ti/n). Добавление x даёт

dp_(i+1)[P+x][x] = Σ_{v≤x} dp_i[P][v].

Для одной старой суммы накапливаем префикс по x. Старая сумма
однозначна по новой сумме и x, поэтому ячейку присваиваем, а не
складываем с переходами от другой суммы. Два слоя обнуляются и
чередуются; последний результат лежит в 0..M.

Точные границы перебора:

first=max(0,L(i+1)−P,ceil(P/i) при i>0),
last=min(M,U(i+1)−P,floor((T−P)/(n−i))).

Последний старый результат не меньше среднего префикса, а все n−i
оставшихся, включая x, будут не меньше x. Отсекаются только
непродолжаемые префиксы. Сначала суммируем позиции меньше first,
потом добавляем dp_i[P][x] перед записью. В конце складываем все
последние результаты dp_n[T]. У каждого отсортированного списка один
путь, множителя по именам или числу реализаций матчей нет.

Время O(n⁴), память O(n³): n слоёв, O(n²) сумм и O(n) последних
результатов. Префиксные суммы убирают дополнительный множитель n.
При n=50 максимум 938 строк сумм и 148 столбцов, 138824 ячейки на слой.

Нужны таблицы, а не 4^(число матчей), векторы с именами или только
разбиения суммы. Префиксные ограничения обязательны, равные результаты
и нули допустимы. Целые floor/ceil, включение x=v в сумму, очистка
буферов и 64-битные накопители важны.

## Особенности языков

Нативные версии переиспользуют два плоских 32-битных буфера, очищая
следующий; Python использует списки. Префикс и итоговая сумма строки
64-битные: до 148·(MOD−1)=148000000888. Модуль берётся при записи
ячейки; Python хранит промежуточные суммы без переполнения. Индексы
и их произведения помещаются в 32 бита.
