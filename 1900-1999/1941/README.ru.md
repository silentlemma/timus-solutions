# 1941. Окна с заданным мультимножеством букв

[Timus 1941](https://acm.timus.ru/problem.aspx?space=1&num=1941) · difficulty 432 · two_pointers

Original problem from Open Ural FU Personal Contest 2012 | by Andrey Demidov (prepared by Alex Samsonov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Буква — упорядоченная тройка ASCII-символов с кодами от 33 до 122
включительно; алфавит содержит 90³=729000 букв. Даны непустой образец
длины m≤8000 и непустой текст длины n≤500000 букв. Посчитать непрерывные
окна текста, являющиеся перестановкой образца. Кратности важны,
порядок символов внутри буквы важен, окна могут пересекаться.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Первая строка — образец, вторая — текст. Буква содержит ровно три
соседних символа, буквы разделяются пробелами. Граница первой строки
определяет длину образца. Числа m и n отдельно не передаются.

## Выходные данные

Одно целое — число подходящих окон. При m>n ответ 0.

## Проверка

Сравнивается один целочисленный токен; пробелы несущественны.

## Примеры

```
aaa bbb ccc
aaa aaa bbb ccc aaa zzz aaa bbb ccc
```

```
3
```

## Решение

Код буквы (a,b,c): ((a−33)·90+(b−33))·90+(c−33). Цифры от 0 до 89,
поэтому это взаимно однозначное кодирование в 0..728999, а не хеш.
Заводим знаковую таблицу дефицитов D на 729000 элементов, изначально
частоты образца, кольцевой буфер на m кодов и missing=m.

Перед добавлением очередной буквы удаляем старейшую, если буфер полон.
При удалении x увеличиваем missing, если D[x]≥0, затем увеличиваем
D[x]. При вставке y уменьшаем missing, если D[y]>0, затем уменьшаем
D[y]. Записываем y в освободившееся место и циклически сдвигаем позицию.
При missing=0 увеличиваем ответ. До заполнения окна missing положителен:
меньше m букв не способны покрыть m требуемых вхождений.

Инвариант: D[x]=частота_в_образце[x]−частота_в_окне[x], а missing
равен сумме положительных D[x]. Удаление создаёт недостаток ровно
при D[x]≥0, вставка закрывает недостаток ровно при D[y]>0. Для полного
окна суммы кратностей равны, поэтому missing=0 означает нулевые
дефициты всех букв, и наоборот. Каждое окно длины m рассматривается
ровно один раз, включая пересечения и последнее окно.

При U=729000 время O(U+m+n), память ядра O(U+m). C++ и Java обрабатывают
текст потоком; Python, Go и Rust сохраняют вход, поэтому полные программы
используют O(U+m+n) памяти. Ответ не больше max(0, n−m+1)≤500000, хватает
знакового 32-битного целого.

Буква — тройка, а не один символ; перестановка символов внутри тройки
меняет букву. Множества без кратностей недостаточно. При удалении
проверяется ≥0, при вставке >0, до изменения D. Нельзя пропускать
перекрытия и последнее окно, сдвигать весь буфер или сравнивать весь
алфавит на каждом шаге. При m>n окон нет (тест 03), поэтому верхнюю
границу нужно ограничить снизу нулём.

## Оптимизированные решения

`1941_two_pointers_optimized.py`. Сохраняются точные коды троек по основанию 90 и тот же инвариант недостающих вхождений в скользящем окне. Таблица 729000 дефицитов и кольцо хранятся в списках Python вместо упакованных array: при каждом обновлении не требуется преобразование ячейки. Токены текста поступают через буфер split 16 КиБ вместо хранения всего текста. До обновления удаление проверяет deficit>=0, добавление — deficit>0. Время O(U+m+n), состояние O(U+m) и ограниченный буфер токенов, U=90^3. Это точный компромисс представления и ввода-вывода, не хеширование и не новый алгоритм окна; учебные версии сохранены.

Accepted точного исходника PyPy 3.10 x64 №11326701: 0.234 с / 17756 КБ. Сохранённое сравнение актуальных компиляторов семейства Python от 2026-11-20: время 2/16, память 2/16; оба строгих критерия первой десятки пройдены. Память не меньше 1024 КБ: требуются и время, и память. Отдельная цель первого места по обеим метрикам не достигнута, звёздочка остаётся. Прежний документированный оптимизированный запуск CPython 3.12 №11314998: 0.89 с / 8604 КБ. У выбранного PyPy меньше зафиксированное время, но больше память; это независимые парные замеры разных интерпретаторов, не чистый эффект алгоритма и не смешанные минимумы. Текущий Accepted сохранённой простой версии CPython №11327563: 0.781 с / 33640 КБ. Дополнительная копия исходника и повторная отправка не нужны.

Собственные Accepted после изменения только форматирования: `1941_two_pointers.py` #11327563. Алгоритмы простых версий и все остальные исходники сохранены.

Новые Go, Python и Rust сохраняют точное кодирование троек по основанию 90 и инвариант недостающих вхождений. В Go и Rust частоты шаблона и окна лежат в 0..m, m≤8000: упакованный знаковый 16-битный дефицит уменьшает таблицу 729000 элементов до 1458000 байт; их кольца хранят точные коды в 32 битах. Go и Rust читают тройки потоково с ограниченными буферами, всего O(U+m) памяти. Python использует списки целых для дефицитов и кольца, расходуя больше памяти ради быстрых обновлений; текст поступает токенами через ограниченный буфер 16 КиБ: O(U+m) состояния и ограниченная память ввода. До изменения дефицита удаление проверяет ≥0, добавление — >0. Первая новая строка по-прежнему отделяет шаблон от текста, включая CRLF. Простые версии сохранены; C++ и Java закрывают быстрый набор уже подходящими базами.

Сохранённые принятые базы [1941_two_pointers.cpp](1941_two_pointers.cpp), [1941_two_pointers.java](1941_two_pointers.java) также проходят строгий допуск первых десяти мест или топ 15% по требуемым метрикам в сохранённом сравнении. Они используются без одинаковых оптимизированных копий. Текущие точные парные замеры приведены в таблице, звёздочка означает отдельную цель языка. Форматирование не меняет алгоритм, ему не приписывается ускорение.

## Особенности языков

Эти замечания относятся к базовым реализациям.

Дефициты знаковые: избыток буквы даёт отрицательное значение. В Python
используется упакованный массив signed int. Go хранит int32 и разбирает
поля байтов. Java читает тройки напрямую без String на каждую букву.
Rust сохраняет вход один раз и перебирает срезы. Вероятностного отпечатка
или словаря нет, сравнение точное.
