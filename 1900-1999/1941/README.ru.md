# 1941. Окна с заданным мультимножеством букв

[Timus 1941](https://acm.timus.ru/problem.aspx?space=1&num=1941) · difficulty 432 · two_pointers

Original problem from Open Ural FU Personal Contest 2012 | by Andrey Demidov (prepared by Alex Samsonov).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Буква — упорядоченная тройка ASCII-символов с кодами от 33 до 122
включительно; алфавит содержит 90³=729000 букв. Даны непустой образец
длины m≤8000 и непустой текст длины n≤500000 букв. Посчитать непрерывные
окна текста, являющиеся перестановкой образца. Кратности важны,
порядок символов внутри буквы важен, окна могут пересекаться.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

Первая строка — образец, вторая — текст. Буква содержит ровно три
соседних символа, буквы разделяются пробелами. Граница первой строки
определяет длину образца. Числа m и n отдельно не передаются.

## Выходные данные

Одно целое — число подходящих окон. При m>n ответ 0.

## Проверка

Сравнивается один целочисленный токен; пробелы несущественны.

## Примеры

```
aaa bbb ccc
aaa aaa bbb ccc aaa zzz aaa bbb ccc
```

```
3
```

## Решение

Код буквы (a,b,c): ((a−33)·90+(b−33))·90+(c−33). Цифры от 0 до 89,
поэтому это взаимно однозначное кодирование в 0..728999, а не хеш.
Заводим знаковую таблицу дефицитов D на 729000 элементов, изначально
частоты образца, кольцевой буфер на m кодов и missing=m.

Перед добавлением очередной буквы удаляем старейшую, если буфер полон.
При удалении x увеличиваем missing, если D[x]≥0, затем увеличиваем
D[x]. При вставке y уменьшаем missing, если D[y]>0, затем уменьшаем
D[y]. Записываем y в освободившееся место и циклически сдвигаем позицию.
При missing=0 увеличиваем ответ. До заполнения окна missing положителен:
меньше m букв не способны покрыть m требуемых вхождений.

Инвариант: D[x]=частота_в_образце[x]−частота_в_окне[x], а missing
равен сумме положительных D[x]. Удаление создаёт недостаток ровно
при D[x]≥0, вставка закрывает недостаток ровно при D[y]>0. Для полного
окна суммы кратностей равны, поэтому missing=0 означает нулевые
дефициты всех букв, и наоборот. Каждое окно длины m рассматривается
ровно один раз, включая пересечения и последнее окно.

При U=729000 время O(U+m+n), память ядра O(U+m). C++ и Java обрабатывают
текст потоком; Python, Go и Rust сохраняют вход, поэтому полные программы
используют O(U+m+n) памяти. Ответ не больше max(0, n−m+1)≤500000, хватает
знакового 32-битного целого.

Буква — тройка, а не один символ; перестановка символов внутри тройки
меняет букву. Множества без кратностей недостаточно. При удалении
проверяется ≥0, при вставке >0, до изменения D. Нельзя пропускать
перекрытия и последнее окно, сдвигать весь буфер или сравнивать весь
алфавит на каждом шаге. При m>n окон нет (тест 03), поэтому верхнюю
границу нужно ограничить снизу нулём.

## Особенности языков

Дефициты знаковые: избыток буквы даёт отрицательное значение. В Python
используется упакованный массив signed int. Go хранит int32 и разбирает
поля байтов. Java читает тройки напрямую без String на каждую букву.
Rust сохраняет вход один раз и перебирает срезы. Вероятностного отпечатка
или словаря нет, сравнение точное.
