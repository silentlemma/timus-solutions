# 1925. Последнее число для совпадения общей суммы

[Timus 1925](https://acm.timus.ru/problem.aspx?space=1&num=1925) · difficulty 70 · math

Автор оригинальной задачи — Павел Агеев; Уральская региональная командная олимпиада по программированию 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Известны n прошлых раундов. В раунде i показано bᵢ, требуемый ввод
равнялся bᵢ−2, а фактически введено gᵢ. Сейчас показано k.
Проверяется только общая сумма за все n+1 раундов: сумма фактических
вводов должна совпасть с суммой требуемых. Найти неотрицательное
целое число для текущего ввода либо сообщить о невозможности.
Прошлые раунды не обязаны быть правильными по отдельности.
Лимиты: 1 секунда, 64 МБ.

## Входные данные

n,k, 1≤n,k≤100, затем n пар bᵢ,gᵢ, каждое число от 0 до 100.

## Выходные данные

Нужное неотрицательное целое, включая ноль. Вывод не ограничен числом
100. Если подходящего числа нет, вывести точно `Big Bang!` с пробелом,
указанным регистром и восклицательным знаком.

## Проверка

Точное сравнение токенов: одно число либо слова `Big` и `Bang!`.

## Примеры

```
6 5
3 1
3 1
5 3
6 5
5 5
7 2
```

```
3
```

```
1 3
4 6
```

```
Big Bang!
```

## Решение

Обозначим сегодняшний ввод x. Проверка требует

```text
sum(gᵢ) + x = sum(bᵢ−2) + (k−2).
```

Отсюда x=k−2+sum(bᵢ−gᵢ−2). Начинаем знаковый баланс с k−2 и для
каждой пары прибавляем bᵢ−gᵢ−2. Знак проверяется только после всех
пар: неотрицательный баланс выводим, отрицательный означает отказ.

Коэффициент при x равен единице, поэтому кандидат единственный.
При неотрицательном значении подстановка даёт нужное равенство.
При отрицательном никакое другое неотрицательное число ему не удовлетворяет.
Так доказаны оба варианта ответа.

Отдельное требуемое число и промежуточный баланс могут быть отрицательными.
Важен только итог. Например, k=100 и пары (0,100),(100,0) дают 94,
хотя после первой пары баланс отрицателен. При k=1 и паре (3,0)
правильный ответ — ноль.

O(n) времени. Аккумулятор использует O(1) рабочей памяти; программы
хранят историю или полностью считывают ввод, поэтому общая память O(n).

Раундов n+1, сегодняшний тоже учитывается. Двойка вычитается за каждый.
Нельзя отклонять ответ раньше времени, проверять прошлые раунды отдельно,
обнулять отрицательные промежуточные суммы или требовать k≥2.
Ноль допустим, вывод может превышать 100. Фразу отказа нужно сохранить точно.

## Особенности языков

Нужна знаковая арифметика, в том числе в Rust. Промежуточные балансы
помещаются в 32-битное знаковое целое: диапазон −10201..9898.
Верхняя граница достигается при n=100,k=100 и всех парах (100,0).
Все версии возвращают знаковый баланс и выбирают формат вывода в конце.
Python лениво передаёт пары из буферизованного ввода.
