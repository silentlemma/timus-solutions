# 1925. Последнее число для совпадения общей суммы

[Timus 1925](https://acm.timus.ru/problem.aspx?space=1&num=1925) · difficulty 70 · math

Автор оригинальной задачи — Павел Агеев; Уральская региональная командная олимпиада по программированию 2012.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Известны n прошлых раундов. В раунде i показано bᵢ, требуемый ввод
равнялся bᵢ−2, а фактически введено gᵢ. Сейчас показано k.
Проверяется только общая сумма за все n+1 раундов: сумма фактических
вводов должна совпасть с суммой требуемых. Найти неотрицательное
целое число для текущего ввода либо сообщить о невозможности.
Прошлые раунды не обязаны быть правильными по отдельности.
Лимиты: 1 секунда, 64 МБ.

## Входные данные

n,k, 1≤n,k≤100, затем n пар bᵢ,gᵢ, каждое число от 0 до 100.

## Выходные данные

Нужное неотрицательное целое, включая ноль. Вывод не ограничен числом
100. Если подходящего числа нет, вывести точно `Big Bang!` с пробелом,
указанным регистром и восклицательным знаком.

## Проверка

Точное сравнение токенов: одно число либо слова `Big` и `Bang!`.

## Примеры

```
6 5
3 1
3 1
5 3
6 5
5 5
7 2
```

```
3
```

```
1 3
4 6
```

```
Big Bang!
```

## Решение

Пусть x — сегодняшний ввод. Проверка сравнивает суммы по всем n + 1
раундам: g₁ + … + gₙ + x = (b₁ − 2) + … + (bₙ − 2) + (k − 2). Значит,
x = k − 2 + Σ(bᵢ − gᵢ − 2); если это число отрицательно, подходящего
ввода нет и ответ `Big Bang!`. `O(n)`.

Подводные камни:

- промежуточная сумма может уйти в минус и всё же закончиться
  неотрицательной, поэтому решать надо только в конце;
- ноль — допустимый ответ;
- каждый раунд, включая сегодняшний, вычитает 2.

## Оптимизированные решения

`1925_math_optimized.py`. Сохраняется уравнение current-2+sum(displayed-entered-2). До решения обрабатываются все пары: промежуточный отрицательный баланс может восстановиться. Выводится итоговое целое, включая ноль, либо точно Big Bang! только при отрицательном результате. Время O(N), постоянное состояние арифметики при заданных пределах. Накопитель встроен вместо вызова required_input через генератор пар. Байтовые токены ввода по-прежнему требуют O(N) памяти; это не потоковый парсер с постоянной памятью. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1925_math.py`: время 0.093 s → 0.156 s; память 504 KB → 232 KB.

`1925_math_optimized.rs`. Сохраняется уравнение current-2+sum(displayed-entered-2). До решения обрабатываются все пары: промежуточный отрицательный баланс может восстановиться. Выводится итоговое целое, включая ноль, либо точно Big Bang! только при отрицательном результате. Время O(N), постоянное состояние арифметики при заданных пределах. Каждая пара сразу читается и прибавляется, вектор истории и декодированный ввод исключены. Дополнительное состояние O(1). Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1925_math.rs`: время 0.031 s → 0.062 s; память 236 KB → 56 KB.

Оптимизированное решение на C++ читает пары через `scanf` вместо
`iostream` и сразу складывает их, не сохраняя историю: 124 КБ вместо
428 КБ.

Оптимизированное решение на Java читает ввод блоками по 1 КБ и разбирает
его вручную вместо `Scanner`, а показания складывает сразу при чтении,
не храня их: 0.078 с вместо 0.140 с и 364 КБ вместо 1796 КБ.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1925_math_optimized.py`: место по времени 57/59, по памяти 1/59 в этой сопоставимой выборке.

`1925_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
