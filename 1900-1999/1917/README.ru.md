# 1917. Безопасное удаление групп по порогу

[Timus 1917](https://acm.timus.ru/problem.aspx?space=1&num=1917) · difficulty 242 · greedy

Автор оригинальной задачи — Денис Дублённых; NEERC 2012, четвертьфинал Восточного подрегиона.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У каждой монеты есть положительный порог устойчивости. Заклинание силы s
уничтожает все оставшиеся монеты с порогом не больше s. Энергия всплеска
равна s, умноженному на число уничтоженных этим заклинанием монет,
и не должна превышать p. Сначала максимизируйте число уничтоженных
монет, затем минимизируйте число заклинаний для этого максимума.
Ограничения: 1 секунда, 64 МБ.

## Входные данные

n,p: 1≤n≤1000, 1≤p≤1 000 000 000. Затем n порогов
1≤aᵢ≤1 000 000 в произвольном порядке.

## Выходные данные

Максимальное число уничтожаемых монет и минимальное число заклинаний.
Если нельзя уничтожить ничего, выведите `0 0`.

## Проверка

Точное сравнение двух целых токенов в указанном порядке.

## Примеры

```
5 4
4 1 4 1 2
```

```
3 2
```

## Решение

Сортируем пороги и объединяем одинаковые. Группу из c монет с порогом t
невозможно разделить: слабое заклинание не уберёт ни одной, первое
заклинание силы хотя бы t уничтожит все c сразу.

Если ct>p, такую группу не убрать даже отдельно. Большая сила или
добавочные монеты только увеличат энергию. Она блокирует и все более
высокие пороги, поскольку достаточно сильное заклинание затронет её тоже.
Максимум — префикс до первой такой группы. Все предыдущие группы можно
убрать по отдельности, значит, эта граница достижима.

Допустимый префикс разбиваем жадно. Пусть active — число монет текущего
заклинания. Добавляем целиком очередную группу, пока (active+c)t≤p.
Иначе завершаем предыдущее непустое заклинание и начинаем новое с этой
группы. В конце учитываем непустой остаток. Минимальная сила каждого
заклинания равна максимальному порогу его группы. Проверку ct>p делаем
до открытия нового заклинания; пустые заклинания не считаем.

### Оптимальность длиннейшей группы

Первая жадная порция — самый длинный допустимый префикс: при добавлении
групп растут и число монет, и максимальный порог. В оптимальном разбиении
заменим первую порцию жадной. Монеты, захваченные дополнительно, удалим
из последующих порций, опустевшие порции отбросим. Число монет и порог
в каждой оставшейся не увеличатся, поэтому безопасность сохранится,
а число заклинаний не вырастет. Повторение аргумента для остатка
доказывает минимум заклинаний.

Время `O(n log n)` на сортировку, остальной проход линейный.
Память `O(n)`, включая вход и отсортированную копию.

В примере две единицы уничтожаются силой 1, двойка — силой 2.
Две четвёрки вместе дали бы энергию 8>4 и блокируют дальнейшие действия.
Итог — три монеты за два заклинания.

Нельзя делить одинаковые пороги и перескакивать через опасную слабую группу.
Граница энергии включительная. Учитывайте все одновременно уничтожаемые
монеты; сбрасывайте накопление после учёта непустого заклинания.
Опасная следующая группа не отменяет уже набранную допустимую.
Сначала максимизируется число монет, затем минимизируется число заклинаний.

## Оптимизированные решения

Групповый жадный алгоритм не меняется: равные значения образуют неразделимую группу, первую небезопасную группу нельзя пропустить. Java сортирует примитивный массив на месте итеративной пирамидальной сортировкой, без вспомогательных классов, копий и рабочего массива сортировки. Ограниченный байтовый ввод и ASCII-вывод заменяют объекты токенов и форматирования. Произведения при проверке группы вычисляются в широком целочисленном типе; дополнительная память сортировки постоянна.

- `1917_greedy_optimized.java`: 0.109 s / 380 KB; база `1917_greedy.java`: 0.125 s / 648 KB; изменение относительно базы: время -12.8%, память -41.4%.
