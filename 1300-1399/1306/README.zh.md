# 1306. 序列的中位数

[Timus 1306](https://acm.timus.ru/problem.aspx?space=1&num=1306) · 难度 145 · sorting

原题出自 1998 年 4 月 3–4 日在叶卡捷琳堡举行的第二届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

求 1 ≤ N ≤ 250 000 个 0 到 2³¹ − 1 之间整数的中位数：N 为奇数时是排序后正中
间的元素，N 为偶数时是中间两个元素的平均值。保留一位小数输出。

时间限制：1 秒。内存限制：1 MB。题面只允许 C、C++ 和 Pascal，提交表单还提供 Rust。

## 输入

N，然后是 N 个数，每行一个。

## 输出

中位数，保留一位小数。

## 评测方式

精确比较（`tests/tests.json` 的 `judging: exact`）：一行精确的中位数，
保留一位小数（`.0` 或 `.5`），末尾换行。

## 样例

### 样例 1

输入：

```
6
12
1
9
4
2
7
```

输出：

```
5.5
```

## 解法

整个序列要占 250 000 · 4 字节，约 1 MB，正是全部内存限制。但只有较小的一半有用：中位数就是最小的
⌊N/2⌋ + 1 个数中最大的那个，或最大两个的平均值。

所以用一个大根堆保存目前读到的最小的 ⌊N/2⌋ + 1 个数，约 500 KB。每个新数在堆未满时加入；堆满后
若比堆顶小，就替换堆顶。最后：

- N 为奇数时，堆顶就是中位数；
- N 为偶数时，堆顶以及弹出一次后的新堆顶就是中间的两个元素。

堆的最坏工作量为 `O(N log N)`，包含 I 个输入字节时为 `O(I+N log N)`。
有效堆含 `⌊N/2⌋+1` 个元素。两个 C++ 版本均预留固定的 125001 元素数组
（32 位元素共 500004 字节），因此分配空间为 `O(C+B)`，C 为最大容量，B 为
有界缓冲区，并非随每个小 N 缩小。Rust 仅预留 `⌊N/2⌋+1` 个 i32 元素，
但还保存最长输入行 H，空间为 `O(N/2+H+B)`。通常行长度有界时可变空间
为 `O(N)`。求和使用扩展类型。

注意事项：

- 两个接近 2³¹ − 1 的数相加可能溢出 32 位有符号整数（测试 04），但和仍在 32 位无符号整数的范围内；代码用 64 位计算；
- 平均值要么是整数，要么以 .5 结尾，因此不用浮点数就能精确输出（测试 01 和 08）；
- 这里 C++ 流太占内存，所以程序用 `scanf` 读入。

## 优化解法

优化的 C++ 解法从 4 KB 缓冲区中手工解析数字，而不是用 `scanf`。它用
`std::make_heap` 在线性时间内一次建好前 ⌊N/2⌋ + 1 个数的堆，而不是逐个插入；替
换堆顶时只做一次向下调整，而不是先 `pop_heap` 再 `push_heap`：
