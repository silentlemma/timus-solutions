# 1306. Медиана последовательности

[Timus 1306](https://acm.timus.ru/problem.aspx?space=1&num=1306) · сложность 145 · sorting

Оригинальная задача — II командный студенческий чемпионат Урала по программированию, Екатеринбург, 3–4 апреля 1998 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Нужно найти медиану 1 ≤ N ≤ 250 000 целых чисел от 0 до 2³¹ − 1: средний
элемент отсортированной последовательности при нечётном N и среднее двух
средних элементов при чётном. Вывести её с одним знаком после точки.

Ограничение времени: 1 секунда. Ограничение памяти: 1 МБ. В условии
разрешены C, C++ и Pascal, форма отправки предлагает ещё Rust.

## Входные данные

N, затем N чисел по одному в строке.

## Выходные данные

Медиана с одним знаком после точки.

## Проверка

Точное сравнение (`judging: exact` в `tests/tests.json`): одна строка
с точной медианой, одной цифрой после точки (`.0` или `.5`) и переводом строки.

## Примеры

### Пример 1

Ввод:

```
6
12
1
9
4
2
7
```

Вывод:

```
5.5
```

## Решение

Вся последовательность занимает 250 000 · 4 байта, около 1 МБ, то есть
весь лимит памяти. Но важна только меньшая половина: медиана — это
наибольшее или среднее двух наибольших из ⌊N/2⌋ + 1 наименьших чисел.

Поэтому куча с максимумом наверху хранит ⌊N/2⌋ + 1 наименьших из уже
прочитанных чисел, около 500 КБ. Каждое новое число либо добавляется,
пока куча не заполнена, либо заменяет вершину, если оно меньше
вершины. В конце:

- при нечётном N вершина и есть медиана;
- при чётном N вершина и, после одного извлечения, новая вершина — два
  средних элемента.

Худшее время работы кучи — `O(N log N)`, с I байтами ввода —
`O(I+N log N)`. В активной куче `⌊N/2⌋+1` элементов. Обе версии C++
резервируют фиксированный массив из 125001 элемента (500004 байта
для 32-битных чисел): выделенная память `O(C+B)`, где C — максимальная
ёмкость, B — ограниченные буферы, а не размер конкретного малого N.
Rust резервирует только `⌊N/2⌋+1` элементов i32, но также хранит
самую длинную входную строку H: `O(N/2+H+B)`. При обычных строках
ограниченной длины переменная память `O(N)`. Суммы вычисляются
в расширенном типе.

Тонкие места:

- сумма двух чисел около 2³¹ − 1 может переполнить 32-битный знаковый
  тип (тест 04), но помещается в беззнаковый; код использует 64 бита;
- среднее либо целое, либо оканчивается на .5, поэтому печатается
  точно, без вещественных чисел (тесты 01 и 08);
- потоки C++ здесь слишком дороги по памяти, поэтому программа читает
  через `scanf`.

## Оптимизированные решения

Оптимизированное решение на C++ разбирает числа вручную из буфера на
4 КБ вместо `scanf`. Кучу из первых ⌊N/2⌋ + 1 чисел оно строит сразу
через `std::make_heap`, за линейное время, а не добавляет их по одному,
а вершину заменяет одним просеиванием вниз вместо `pop_heap` и
следующего за ним `push_heap`: {1306_sorting_optimized.cpp}.

### Измеренный выигрыш

Проценты ниже сравнивают сохранённые Accepted, а не задают порог
допуска. Действуют [критерии рейтинга](../../RATING_CRITERIA.md):
топ-10/топ-15%, заменяемые при 1–10 соперниках той же версии
сравнением с выбранным эталоном и допуском 15% или одного тика.
При памяти меньше 1024 КБ сравнивается только время. Содержательные
простые версии сохраняются. Быстрый C++ проходит сохранённый порог
времени, базовый Rust — сохранённое сравнение времени малой группы.
Соответствие исходника посылке проверяется отдельно от метрик.

В простых C++ и Rust изменены только комментарии. Алгоритмы и остальные полезные комментарии сохранены.

- `1306_sorting_optimized.cpp`: сокращение времени +84.73%; сокращение
  памяти +8.97%; база: `1306_sorting.cpp`.
