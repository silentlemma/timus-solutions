# 1309. 争论的艺术

[Timus 1309](https://acm.timus.ru/problem.aspx?space=1&num=1309) · 难度 603 · math

原题创意来自 Alexander Klepinin，由 Alexander Klepinin 和 Stanislav Vasiliev 准备，出自 2004 年 3 月 11–16 日在叶卡捷琳堡举行的第八届乌拉尔大学生团体程序设计锦标赛。

## 任务

f(0) = 0，f(n) = g(n, f(n − 1))，其中

g(x, y) = ((y − 1)x⁵ + x³ − xy + 3x + 7y) mod 9973。

要求在半秒内对 0 ≤ n ≤ 10⁸ 计算 f(n)。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

数 n。

## 输出

f(n)。

## 样例

### 样例 1

输入：

```
50
```

输出：

```
6300
```

## 解法

把含 y 的项合并：

g(x, y) = y · (x⁵ − x + 7) + (x³ + 3x − x⁵) mod 9973，

所以每一步都是模 9973 的仿射变换 y → a(x) · y + b(x)，其系数只取决于 x mod 9973。因此 x = 1, …, 9973
这些步骤会按同样的顺序在每一段连续 9973 个 x 中重复出现。

- 把一段中的 9973 个变换复合成一个变换 y → A · y + B。
- 写 n = q · 9973 + r。先应用 y → A · y + B 共 q 次（q ≤ 10 028），再逐个应用 x = 1, …, r 的步骤。

三个各约 10 000 步的短循环代替了 10⁸ 步。`O(9973 + n / 9973)`。

注意事项：

- y = 0 时，x ≥ 2 的表达式为负，所以要取数学意义上的余数（0 到 9972）。若像 C 那样用截断的 `%`，
  答案首次出现差别是在 n = 1893（测试 04）；
- 即使 x 接近 9973，x⁵ 也超出 64 位，所以每次乘法之后都对 9973 取模；
- n = 0 时结果为 0（测试 02），n 略小于、等于和略大于 9973 的倍数时检查衔接处（测试 05–07）。

对 60 000 以内的每个 n 与直接递推比较过；对较大的 n 与另一种方法比较过，该方法用反复平方求出段变换的
q 次幂。

## 各语言说明

- Java 用 `Math.floorMod`，Rust 用 `rem_euclid` 求非负余数；C++ 和 Go 在最后一次 `%` 之前加上 9973。
