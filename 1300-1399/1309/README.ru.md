# 1309. Искусство спора

[Timus 1309](https://acm.timus.ru/problem.aspx?space=1&num=1309) · сложность 603 · math

Идея оригинальной задачи — Александр Клепинин, подготовили Александр Клепинин и Станислав Васильев; VIII командный студенческий чемпионат Урала по программированию, Екатеринбург, 11–16 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

f(0) = 0 и f(n) = g(n, f(n − 1)), где

g(x, y) = ((y − 1)x⁵ + x³ − xy + 3x + 7y) mod 9973.

Нужно вычислить f(n) для 0 ≤ n ≤ 10⁸ за полсекунды.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Число n.

## Выходные данные

f(n).

## Примеры

### Пример 1

Ввод:

```
50
```

Вывод:

```
6300
```

## Решение

Соберём слагаемые с y:

g(x, y) = y · (x⁵ − x + 7) + (x³ + 3x − x⁵) mod 9973,

так что каждый шаг — аффинное отображение y → a(x) · y + b(x) по
модулю 9973, и его коэффициенты зависят только от x mod 9973. Поэтому
шаги x = 1, …, 9973 повторяются в том же порядке в каждом блоке из 9973
подряд идущих x.

- Составим из 9973 отображений одного блока одно отображение
  y → A · y + B.
- Запишем n = q · 9973 + r. Применим y → A · y + B q раз (q ≤ 10 028),
  затем отдельные шаги x = 1, …, r.

Три коротких цикла примерно по 10 000 шагов вместо 10⁸.
`O(9973 + n / 9973)`.

Тонкие места:

- при y = 0 выражение отрицательно для x ≥ 2, поэтому остаток нужно
  брать математический, от 0 до 9972. Отсекающий `%`, как в C, впервые
  дал бы другой ответ при n = 1893 (тест 04);
- x⁵ не помещается в 64 бита даже при x около 9973, поэтому степени
  берутся по модулю 9973 после каждого умножения;
- n = 0 даёт 0 (тест 02), а n чуть меньше, равное и чуть больше
  кратного 9973 проверяет стыки (тесты 05–07).

Результаты сравнивались с прямым вычислением рекуррентности для всех n
до 60 000, а для больших n — со вторым способом, возводящим отображение
блока в степень q повторным возведением в квадрат.

## Особенности языков

- Java использует `Math.floorMod`, Rust — `rem_euclid` для
  неотрицательного остатка; C++ и Go прибавляют 9973 перед последним
  `%`.
