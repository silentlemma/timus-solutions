# 1330. Интервалы

[Timus 1330](https://acm.timus.ru/problem.aspx?space=1&num=1330) · сложность 95 · prefix_sums

Автор оригинальной задачи — Ден Расковалов; X командный чемпионат школьников Свердловской области по программированию, 16 октября 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N ≤ 10 000 датчиков дают целые показания от −10 000 до 10 000. Нужно
ответить не более чем на 100 000 вопросов: сумма показаний датчиков с i-го по j-й,
i ≤ j.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N показаний, затем Q и Q пар i, j.

## Выходные данные

По одной сумме в строке.

## Примеры

### Пример 1

Ввод:

```
5
1
2
3
-1
4
3
1 5
4 4
1 4
```

Вывод:

```
9
-1
5
```

## Решение

Храним before[i] — сумму первых i показаний, before[0] = 0. Сумма с i
по j — это before[j] − before[i − 1], одно вычитание на вопрос.
`O(N + Q)`.

Тонкие места:

- суммы лежат между −10⁸ и 10⁸, что помещается в 32-битное целое;
- вопросов может не быть вовсе (тест 03);
- при 100 000 вопросах ввод и вывод нужно читать и писать большими
  кусками, чтобы уложиться в 0.5 секунды.

## Оптимизированные решения

Оптимизированные решения на C++ и Java хранят префиксные суммы
32-битными целыми, чего хватает для сумм от −10⁸ до 10⁸. C++ разбирает
числа и записывает ответы вручную через буферы по 4 КБ и хранит суммы в
статическом массиве: 0.015 с вместо 0.125 с и 132 КБ вместо 2784 КБ.

Оптимизированное решение на Java читает ввод блоками по 4 КБ и разбирает
его вручную вместо `StreamTokenizer`, а ответы пишет в байтовый буфер на
4 КБ вместо строк: 0.125 с вместо 0.156 с и 452 КБ вместо 7324 КБ.
Оптимизированное решение на Python разбирает ввод построчно вместо
разбиения всего ввода сразу и выводит ответы пачками по 1024 строки:
1440 КБ вместо 27608 КБ, хотя время растёт с 0.125 с до 0.203 с.

## Особенности языков

- Простое решение на Java читает через `StreamTokenizer`, который
  понимает отрицательные показания, и собирает ответы в одну строку.
