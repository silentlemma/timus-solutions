# 1335. Белый тезис

[Timus 1335](https://acm.timus.ru/problem.aspx?space=1&num=1335) · сложность 182 · math

Автор оригинальной задачи — Ден Расковалов; X командный чемпионат школьников Свердловской области по программированию, 16 октября 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано N, 2 ≤ N ≤ 30 000. Нужно найти три различных целых числа A, B и C
от N² до (N + 1)² включительно, для которых A² + B² делится на C, или
вывести `No solution`, если таких нет. Принимается любая такая тройка.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

A, B и C или `No solution`.

## Проверка

Чекер принимает любые три различных числа из отрезка, у которых A² + B²
делится на C. Тройка существует всегда, поэтому `No solution` не
принимается никогда.

## Примеры

### Пример 1

Ввод:

```
2
```

Вывод:

```
8 6 4
```

### Пример 2

Ввод:

```
1000
```

Вывод:

```
1000000 1000756 1000976
```

## Решение

Возьмём C = N² + 1, A = N² и B = N² + N + 1. По модулю C первое число
равно −1, а второе — N, так что A² + B² ≡ 1 + N², а это и есть C, и
сумма делится на C. Все три лежат между N² и (N + 1)², поскольку
N² + N + 1 < N² + 2N + 1, и различны при любом N ≥ 1. Значит, ответ
существует всегда и `No solution` не бывает. `O(1)`.

Тройка найдена так: для небольших N были выписаны все решения с
A = N², и среди них каждый раз встречалась пара (N² + N + 1, N² + 1).

Тонкие места:

- числа доходят примерно до 9 · 10⁸, а их квадраты, нужные только
  чекеру, — до 8 · 10¹⁷, больше, чем вмещают 32 бита;
- в примерах показаны другие тройки; принимается любая верная.

## Оптимизированные решения

`1335_math_optimized.java`. Сохраняется тройка A=N², B=N²+N+1, C=N²+1. Квадрат вычисляется один раз в int: при N<=30000 максимальное выводимое число 900030001. Буферы ввода/вывода по 1024 байта и массив цифр заменяют конкатенацию строк и общее форматирование long. Доказательства сравнимости и различия чисел прежние; ограниченная арифметика и память O(1). Все допустимые N от 2 до 30000 проверены независимым 64-битным тождеством.

Accepted точного исходника Java 1.8 №11327452: 0.093 с / 356 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 4/41, память 1/41. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. ### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

`1335_math_optimized.py`. Сохраняется конструкция A=N², B=N²+N+1, C=N²+1, квадрат N считается один раз. По модулю C первые два значения равны -1 и N, поэтому A²+B² делится на C; при N>=2 все три числа различны и в нужном интервале. O(1) ограниченной арифметики и памяти. Один вычисленный квадрат используется повторно, три целых выводятся одним вызовом. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1335_math.py`: время 0.078 s → 0.125 s; память 392 KB → 168 KB.

`1335_math_optimized.rs`. Сохраняется конструкция A=N², B=N²+N+1, C=N²+1, квадрат N считается один раз. По модулю C первые два значения равны -1 и N, поэтому A²+B² делится на C; при N>=2 все три числа различны и в нужном интервале. O(1) ограниченной арифметики и памяти. Используются знаковая арифметика i64 и прямой числовой вывод; при N<=30000 все построенные значения заведомо помещаются в i64. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1335_math.rs`: время 0.046 s → 0.015 s; память 244 KB → 56 KB.
