# 1320. Разбиение графа

[Timus 1320](https://acm.timus.ru/problem.aspx?space=1&num=1320) · сложность 283 · dsu

Идея оригинальной задачи — Александр Петров, подготовили Александр Петров и Леонид Волков; VIII командный студенческий чемпионат Урала по программированию, Екатеринбург, 11–16 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У простого графа чётное число рёбер, от 2 до 1050, вершины пронумерованы
от 1 до 1000. Нужно определить, можно ли разбить его рёбра на пары
смежных, то есть имеющих общую вершину.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Рёбра, каждое парой номеров вершин, до конца ввода. Петель и кратных
рёбер нет.

## Выходные данные

1, если такое разбиение существует, иначе 0.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Примеры

### Пример 1

Ввод:

```
1 2
2 3
3 1
1 10
```

Вывод:

```
1
```

### Пример 2

Ввод:

```
1 2
2 3
3 1
4 10
```

Вывод:

```
0
```

## Решение

Два смежных ребра всегда лежат в одной компоненте связности, поэтому в
каждой компоненте должно быть чётное число рёбер. Этого и достаточно:
связный граф с чётным числом рёбер всегда можно разбить. Возьмём дерево
обхода в глубину и будем обрабатывать вершины от самых глубоких вверх.
В вершине v свободные рёбра при v, кроме ребра к родителю, разбиваются
на пары; если одно осталось, оно образует пару с ребром к родителю,
иначе ребро к родителю остаётся свободным для родителя. Каждая вершина,
кроме корня, не оставляет свободных рёбер ниже себя, а в корне
свободные рёбра разбиваются на пары между собой, что возможно, потому
что всего рёбер чётное число.

Значит, для ответа нужно только число рёбер в каждой компоненте. Система
непересекающихся множеств по вершинам хранит его в корне: при
объединении двух компонент числа складываются, и каждое ребро добавляет
единицу. В конце проверяем, что счётчик в каждом корне чётный. Здесь V —
диапазон номеров вершин, M — число рёбер. Корни объединяются без
балансировки по рангу или размеру, поэтому укорачивание путей даёт
безопасную общую оценку `O(V + M log V)`, включая инициализацию и
финальную проверку корней.

Тонкие места:

- во всём графе рёбер всегда чётное число, а в компоненте может быть
  нечётное: треугольник и отдельное ребро дают 0 (тест 02, а также два
  отдельных треугольника в тесте 06);
- число рёбер не задано, ввод просто заканчивается;
- два треугольника с общей вершиной — одна компонента из шести рёбер, и
  её можно разбить (тест 07).

Правило сравнивалось с перебором всех разбиений на пары на 487
случайных графах до 14 рёбер.

## Оптимизированные решения

`1320_dsu_optimized.py`. Алгоритм DSU с чётностью сохранён: в каждой компоненте должно быть чётное число рёбер. Отрицательный корень хранит -(2*size+parity); сжатие пути через одну вершину и объединение по размеру дают O((V+E)*alpha(V)) амортизированного времени. Число нечётных компонент обновляется при объединении корней или смене чётности внутри компоненты. Текущая версия целиком читает и разбивает ограниченный ввод, передавая итератор целых в decomposable: память O(V+I), а не потоковая O(V). Настройка pypyjit не нужна, замер сделан на CPython. Прямой вывод и os._exit(0) вызываются на верхнем уровне после возврата функции; массив parent не обязательно доживает до выхода.

Accepted точного исходника Python 3.12 x64 №11327483: 0.078 с / 808 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 6/42, память 13/42. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11309751 (PyPy 3.10 x64): 0.156 с / 436 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1320_dsu_optimized.py`: 0.078 s / 808 KB; сохранённая учебная база `1320_dsu.py`: 0.093 s / 656 KB.

`1320_dsu_optimized.go`. Рёбра сразу поступают в DSU со сжатием пути через одну вершину. Фиксированные массивы из 1001 родителя uint16 и чётностей рёбер компонент заменяют сохранённые концы и целые счётчики. При объединении чётности складываются XOR, каждое ребро, включая петли и повторы, меняет чётность. V=1000 помещается в uint16. Объединение по рангу не вводится: консервативная оценка O(EV+V), память O(V). Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1320_dsu.go`: время 0.015 s → 0.015 s; память 1112 KB → 336 KB.

`1320_dsu_optimized.rs`. Сохраняются DSU со сжатием пути через одну вершину и чётность рёбер компонент. Рёбра читаются потоком, родители u16 и байт чётности на вершину; объединение через XOR, каждое ребро, включая петли, меняет чётность. Балансировка по рангу не добавляется: консервативно O(EV+V) времени, O(V) памяти, V=1000. Наглядная версия со списком концов сохранена.

По сравнению с `1320_dsu.rs`: время 0.015 s → 0.015 s; память 264 KB → 68 KB.

Исходные понятные DSU сохраняются. Попарное объединение рёбер возможно ровно тогда, когда в каждой компоненте чётное число рёбер. Java хранит положительные ссылки на родителя и чётность корня 0/-1 в одном исходно нулевом short-массиве. Внутреннее ребро меняет чётность; слияние даёт XOR двух чётностей и единицы. Укорочение путей сохраняет компоненты, метки 1..1000 помещаются в short. Буфер стандартного ввода на 512 байт корректно пополняется даже внутри четырёхзначной метки, поддерживает пробелы и EOF, выводит байты напрямую. Python отдельно кодирует размер и чётность отрицательным корнем -(2*size+parity), сливает по размеру и поддерживает число нечётных компонент. Сравниваем с базой того же языка. Java: амортизированно O((V+M)log V), память O(V); Python: O((V+M)alpha(V)), O(V+M) с токенами ввода.

Исторические замеры прежних ревизий: PyPy также отключает JIT-компиляцию ради памяти кеша кода; время может увеличиться.

- `1320_dsu_optimized.java`: 0.093 s / 408 KB; база `1320_dsu.java`: 0.109 s / 420 KB; изменение относительно базы: время -14.7%, память -2.9%.

## Особенности языков

Срезы рейтинга сохранены 1 и 4 ноября 2026 года. Цель C++ — топ 15% либо первые 10 мест одновременно по времени и памяти; других семейств — первое место по обеим метрикам. Ничьи делят место. Пустые выборки дают только формальное покрытие.

Используется сохранённый профиль текущих компиляторов; исключены собственный автор и старые строки со временем меньше 0,015 с. Для семейств кроме C++ дополнительно требуется ID посылки ≥10770000; память C++ сравнивается по первым 1000 подходящим строкам. Собственные времена меньше 0,015 с считаются 0,015 с. Порог ID — фиксированное правило сравнения, а не точный календарный фильтр.
