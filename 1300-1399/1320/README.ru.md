# 1320. Разбиение графа

[Timus 1320](https://acm.timus.ru/problem.aspx?space=1&num=1320) · сложность 283 · dsu

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У простого графа чётное число рёбер, от 2 до 1050, вершины пронумерованы
от 1 до 1000. Нужно определить, можно ли разбить его рёбра на пары
смежных, то есть имеющих общую вершину.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Рёбра, каждое парой номеров вершин, до конца ввода. Петель и кратных
рёбер нет.

## Выходные данные

1, если такое разбиение существует, иначе 0.

## Проверка

Точные токены ответа. Каждый новый исходник прошёл полные проверки целевой среды, независимые математические сравнения и имеет собственный Accepted с хешем; простые версии сохраняют свои метрики.

## Примеры

### Пример 1

Ввод:

```
1 2
2 3
3 1
1 10
```

Вывод:

```
1
```

### Пример 2

Ввод:

```
1 2
2 3
3 1
4 10
```

Вывод:

```
0
```

## Решение

Два смежных ребра всегда лежат в одной компоненте связности, поэтому в
каждой компоненте должно быть чётное число рёбер. Этого и достаточно:
связный граф с чётным числом рёбер всегда можно разбить. Возьмём дерево
обхода в глубину и будем обрабатывать вершины от самых глубоких вверх.
В вершине v свободные рёбра при v, кроме ребра к родителю, разбиваются
на пары; если одно осталось, оно образует пару с ребром к родителю,
иначе ребро к родителю остаётся свободным для родителя. Каждая вершина,
кроме корня, не оставляет свободных рёбер ниже себя, а в корне
свободные рёбра разбиваются на пары между собой, что возможно, потому
что всего рёбер чётное число.

Значит, для ответа нужно только число рёбер в каждой компоненте. Система
непересекающихся множеств по вершинам хранит его в корне: при
объединении двух компонент числа складываются, и каждое ребро добавляет
единицу. В конце проверяем, что счётчик в каждом корне чётный. Здесь V —
диапазон номеров вершин, M — число рёбер. Корни объединяются без
балансировки по рангу или размеру, поэтому укорачивание путей даёт
безопасную общую оценку `O(V + M log V)`, включая инициализацию и
финальную проверку корней.

Тонкие места:

- во всём графе рёбер всегда чётное число, а в компоненте может быть
  нечётное: треугольник и отдельное ребро дают 0 (тест 02, а также два
  отдельных треугольника в тесте 06);
- число рёбер не задано, ввод просто заканчивается;
- два треугольника с общей вершиной — одна компонента из шести рёбер, и
  её можно разбить (тест 07).

Правило сравнивалось с перебором всех разбиений на пары на 487
случайных графах до 14 рёбер.

## Оптимизированные решения

Исходные понятные DSU сохраняются. Попарное объединение рёбер возможно ровно тогда, когда в каждой компоненте чётное число рёбер. Java хранит положительные ссылки на родителя и чётность корня 0/-1 в одном исходно нулевом short-массиве. Внутреннее ребро меняет чётность; слияние даёт XOR двух чётностей и единицы. Укорочение путей сохраняет компоненты, метки 1..1000 помещаются в short. Буфер стандартного ввода на 512 байт корректно пополняется даже внутри четырёхзначной метки, поддерживает пробелы и EOF, выводит байты напрямую. Python отдельно кодирует размер и чётность отрицательным корнем -(2*size+parity), сливает по размеру и поддерживает число нечётных компонент. Сравниваем с базой того же языка. Java: амортизированно O((V+M)log V), память O(V); Python: O((V+M)alpha(V)), O(V+M) с токенами ввода.

PyPy также отключает JIT-компиляцию ради памяти кеша кода; время может увеличиться.

- `1320_dsu_optimized.java`: 0.093 s / 408 KB; база `1320_dsu.java`: 0.109 s / 420 KB; изменение относительно базы: время -14.7%, память -2.9%.
- `1320_dsu_optimized.py`: 0.156 s / 436 KB; база `1320_dsu.py`: 0.093 s / 656 KB; изменение относительно базы: время +67.7%, память -33.5%.
