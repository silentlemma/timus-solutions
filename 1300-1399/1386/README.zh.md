# 1386. 又是迷宫

[Timus 1386](https://acm.timus.ru/problem.aspx?space=1&num=1386) · 难度 1143 · simulation

原题作者 Andrew Khalyavin，出自 2005 年 8 月彼得罗扎沃茨克夏季集训。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

迷宫是一个 N × M 的方格场地，1 ≤ N, M ≤ 100，有四种指令。对每个格子和每
种指令，地图给出玩家将移动到的格子。玩家的起点未知，但游戏中的全部
S ≤ 4000 条指令已知。输出玩家现在可能所在的所有格子。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

N 和 M，然后是四个块，每种指令一个，每块 N 行，每行 M 对：第 k 块第 j 行
第 i 对是从格子 (j, i) 执行指令 k 后到达的格子。然后是 S 和 S 条指令。

## 输出

格子数，然后按行、再按列排序输出这些格子。

## 样例

### 样例 1

输入:

```
2 3
1 2  1 3  1 3
2 2  2 3  2 3
2 1  2 2  2 3
2 1  2 2  2 3
1 1  1 1  1 2
2 1  2 1  2 2
1 1  1 2  1 3
1 1  1 2  1 3
4
1 2 3 4
```

输出:

```
2
1 1
1 2
```

## 解法

维护玩家可能所在的格子集合，开始时为整个场地，并让它依次经过每条指令。
多个格子可能到达同一个格子，所以要去重：C++、Go、Java 和 Rust 只有当某格
的标记还不等于当前步数时才加入。集合从不变大，因此每一步最多 N·M 次查
表，总计最多 4·10⁷ 次。计入最终排序，时间为 `O(N·M·(S + log(N·M)))`。

注意事项：

- 地图可能是排列，比如在环面上，此时永远不会合并：每一步都要处理全部
  10 000 个格子（生成测试 1 和 3）；
- 时间限制只有半秒，所以格子用一个下标编号，每一步都是一个紧凑的循环；
- 输出先按行、再按列排序。

在 400 个小型随机场地上，与从每个起点分别模拟的结果做了比较。

## 各语言说明

- Python 在 PyPy 下运行，并且每次同时执行四条命令：为 16 种命令对各建一张表，某个四条命令的块第一次出现时用两张对表拼成它的表，于是格子只需走大约四分之一的步数，并定期用 set 去重。一次执行一条命令时，它在评测的第 46 个测试上超过 0.5 秒的限制，现在用 0.33 秒。
