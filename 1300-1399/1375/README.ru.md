# 1375. Нонконформизм

[Timus 1375](https://acm.timus.ru/problem.aspx?space=1&num=1375) · сложность 541 · number_theory

Автор оригинальной задачи — Ден Расковалов; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано простое p ≤ 10⁶ и 0 ≤ k ≤ p − 1. Нужно вывести любые x и y от 0
до p − 1 с x² + y² ≡ k (mod p) или `NO SOLUTION`, если таких нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

k и p.

## Выходные данные

x и y или `NO SOLUTION`.

## Проверка

В репозитории используется проверяющая программа, принимающая любой вывод с указанными свойствами. Проверка репозитория требует ровно два неотрицательных целых токена x,y при x,y<p и проверяет (x*x+y*y) mod p=k. Принимается любая подходящая пара. При простом p пара существует всегда, NO SOLUTION отклоняется.

## Примеры

### Пример 1

Ввод:

```
1 3
```

Вывод:

```
0 2
```

## Решение

Для нечётного простого p квадраты принимают (p + 1) / 2 различных
значений по модулю p, и столько же значений у k − x². Два множества по
(p + 1) / 2 значений среди p обязаны пересечься, так что какие-то x² и
y² дают в сумме k: ответ есть всегда, и `NO SOLUTION` не бывает. При
p = 2 любое k равно 0² + 0² или 1² + 0².

Чтобы его найти, запишем по одному корню для каждого квадрата: для y от
0 до p − 1 запоминаем y как корень из y² mod p. Затем пробуем
x = 0, 1, 2, …, пока у k − x² mod p не найдётся корень. Квадратами
является примерно половина всех значений, так что это заканчивается
почти сразу. `O(p)`.

Тонкие места:

- при k = 0 ответ 0 0 (тест 07);
- k − x² нужно брать по модулю p неотрицательным;
- y² может быть почти 10¹², что не помещается в 32 бита.

Ответ проверялся для всех k и всех простых меньше 300, а тесты
проверяются чекером, принимающим любую пару.

## Оптимизированные решения

`1375_math.py`. Таблица квадратных корней O(p) заменена скалярной модульной арифметикой. Перебирается x до нулевого r=(k-x*x) mod p либо прохождения критерия Эйлера. При p=2 выводится(0,k); для остальных простых корень вычисляется напрямую при p mod4=3, иначе применяется Тонелли–Шенкс. Пересечение множеств квадратов гарантирует успех некоторого x; поиск невычета и x конечен и не является случайными повторными попытками. Худшее время O(p log p), асимптотического превосходства над таблицей не обещаем; этап Тонелли–Шенкса требует не более O(log²p) модульных умножений. Память O(1) модульных слов при p<=10^6. Допуск подтверждают собственный Accepted и первые места по обеим метрикам. Учебная таблица сохраняется, другой алгоритм получает имя math.

Новые C++, Go и Rust заменяют таблицу корней O(p) арифметикой поля с постоянной памятью. При p=2 или k=0 достаточно(k,0). Для p≡1 mod4 критерием Эйлера находим квадратичный невычет z и берём i=z^((p−1)/4), тогда i²=−1. Выбираем нечётное t, равное k или k+p. При a=(t+1)/2, b=(t−1)/2 имеем a²−b²=t, поэтому ответ — (a mod p, ib mod p). При p≡3 mod4 перебираем x от0 до(p−1)/2, для r=k−x² mod p считаем y=r^((p+1)/4) и проверяем y²=r. Для ненулевого квадратичного вычета y²=r·r^((p−1)/2)=r по критерию Эйлера. При r=0 корень нулевой. Перебор x покрывает каждый квадрат один раз. Множество квадратов S и k−S имеют по (p+1)/2 элементов, поэтому пересекаются и перебор найдёт пару. 64-битные произведения меньше10^12. Для T попыток модульной степени время O(1+T log p), в худшем O(p log p), дополнительная память O(1); лучшего асимптотического времени относительно таблицы не обещаем. Допуск определяют экономия памяти и реальные посылки. Rust использует C runtime. Простые таблицы сохранены, Простые таблицы сохранены; Python теперь имеет отдельный вариант с модульным корнем.

Принятая Java-таблица и все учебные версии сохраняются. У Python теперь собственный другой алгоритм модульного корня, без копирования неизменённой базы. Звёздочки по-прежнему отмечают недостигнутую рейтинговую цель языка.
