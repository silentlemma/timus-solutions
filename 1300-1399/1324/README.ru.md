# 1324. Лишние пробелы

[Timus 1324](https://acm.timus.ru/problem.aspx?space=1&num=1324) · сложность 929 · greedy

Идея оригинальной задачи — Станислав Васильев, подготовили Станислав Васильев и Игорь Гольдберг; VIII командный студенческий чемпионат Урала по программированию, Екатеринбург, 11–16 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В тексте встречаются группы от 1 до L пробелов, L < 2 000 000. Команда
редактора заменяет каждую группу ровно из k пробелов одним пробелом за
один проход слева направо, не просматривая заново то, что уже заменила.
Поэтому при k = 2 шесть пробелов превращаются в три, а не в один.

Нужно найти наименьшее число команд с выбранными длинами k, которые
превращают любую группу до L пробелов в один пробел. Среди таких планов
надо выбрать тот, что справляется со всеми группами до K пробелов при
наибольшем возможном K. Принимается любой такой план.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Число L.

## Выходные данные

Число команд R, затем R строк с длиной, которую заменяет каждая
команда, в порядке выполнения.

## Проверка

Чекер требует столько же команд, сколько в ожидаемом плане, и для обоих
планов вычисляет наибольшее K, при котором любая группа от 1 до K
пробелов становится одним пробелом. План должен доставать до L и давать
то же K, что и ожидаемый.

## Примеры

### Пример 1

Ввод:

```
22
```

Вывод:

```
4
6
3
2
2
```

## Решение

Одна команда с длиной k превращает группу из n пробелов в
n div k + n mod k пробелов. Пойдём от конца, где должен остаться один
пробел, и пусть M — длина самой длинной группы, которую уже выбранные
команды превращают в один пробел. Группа из n = q · k + r пробелов
становится группой из q + r, и первая группа, которая становится длиннее
M, — это (M − k + 2) · k + (k − 1). Значит, команда с 2 ≤ k ≤ M + 1
справляется со всеми группами до (M + 3 − k) · k − 2 пробелов, а более
длинное k ничего не даёт: группа из k − 1 пробела остаётся как есть.

Эта граница растёт вместе с M, поэтому на каждом шаге назад лучше всего
брать k с наибольшей границей, k = ⌊(M + 3) / 2⌋ — вершину параболы.
Тогда каждый шаг даёт наибольшее возможное M, и первое R с M ≥ L —
наименьшее число команд. Начиная с M = 1, границы равны 2, 4, 10, 40,
460, 53 590 и 718 052 410, так что больше семи команд не нужно никогда.
План выводится от первой команды к последней, то есть в порядке,
обратном тому, в котором он найден. `O(R)`.

Тонкие места:

- при L = 1 заменять ничего не нужно, и ответ — один 0 (тест 02);
- при чётном M два значения k одинаково хороши, поэтому оптимальных
  планов несколько и нужен чекер: для 22 до 40 достают и 6, 3, 2, 2, и
  7, 4, 3, 2;
- граница после семи команд, 718 052 410, ещё помещается в 32-битное
  целое, но решения всё равно используют 64-битные числа.

Формула для одной команды сравнивалась с прямым прогоном для всех M до
79 и k до 89, а планы — со всеми списками до четырёх длин не больше 23
для каждого L до 40.
