# 1352. Простые числа Мерсенна

[Timus 1352](https://acm.timus.ru/problem.aspx?space=1&num=1352) · сложность 132 · number_theory

Автор оригинальной задачи — Владимир Яковлев; чемпионат школьников, март 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Простое число Мерсенна — простое число вида 2^p − 1. Дано T запросов,
в каждом число N ≤ 38; нужно вывести показатель p N-го по возрастанию
простого числа Мерсенна.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

T, затем T строк с N.

## Выходные данные

T строк с показателями.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
13
18
32
24
21
19
34
27
33
20
30
28
29
22
```

Вывод:

```
3217
756839
19937
9689
4253
1257787
44497
859433
4423
132049
86243
110503
9941
```

## Решение

Никакая программа не найдёт эти числа за секунду: 38-й показатель равен
6 972 593, и проверка даже одного числа такого размера требует огромных
вычислений. Порядок первых 38 простых чисел Мерсенна давно установлен,
поэтому решения хранят список их показателей как константную таблицу и
отвечают на запрос обращением по индексу. `O(T)`.

Тонкие места:

- N считается с 1: первое простое число Мерсенна — 2² − 1 = 3,
  показатель 2 (тест 03);
- все показатели помещаются в 32-битные целые.

Первые 22 значения проверены тестом Люка — Лемера для всех простых
показателей до 10 000; остальные взяты из опубликованного списка и
совпадают с примером и значениями, названными в условии.

## Оптимизированные решения

`1352_number_theory_optimized.rs`. Сохраняется точная таблица первых 38 показателей простых Мерсенна из условия. Q индексов читаются потоком, каждый ответ сразу выводится через среду C без строк полного входа и вывода и выделений to_string на ответ. Время O(Q), дополнительная память O(1) при фиксированной таблице; новый тест простоты или новая таблица ответов не вводятся.

По сравнению с `1352_number_theory.rs`: время 0.001 s → 0.001 s; память 216 KB → 56 KB.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1352_parsing_optimized.go`. Используются прямой типизированный разбор с пополняемым буфером на 256 байт и компактный вывод с полной записью. Отрицательные целые накапливаются сразу со знаком, включая минимальное значение; отражение при вводе и универсальный выбор формата вывода не нужны. Разбор токенов и числовой вывод специализированы по реально используемым типам; неиспользуемые универсальные ветви удалены, алгоритм и комментарии сохранены. Цифровые серии преобразуются внутри текущего блока с локальной позицией до границы токена или блока. Отрицательное накопление поддерживает минимальное знаковое число и устраняет выбор знака либо вызов читателя на каждой цифре; EOF и необязательные знаки сохранены.

Accepted #11329135 (Go 1.14 x64): **0.015 s / 796 KB**. Архивное сравнение: `1352_number_theory.go` (Go 1.14 x64) — 0.031 s / 1084 KB (#11285182).


`1352_number_theory_parsing_optimized.java`. Сохранены те же 38 показателей простых Мерсенна и ссылка на OEIS. Запросы и ответы обрабатываются повторно используемыми байтовыми буферами по 1 КиБ без StreamTokenizer, декодирования символов и временных десятичных строк. Перед Runtime.halt(0) записываются все оставшиеся байты. Число запросов не ограничивается размером буфера: обработка потоковая. Простая реализация сохранена.

Для этого точного исходника получен собственный Accepted и выполнены единые [рейтинговые критерии](../../RATING_CRITERIA.md). Время и память ниже взяты из одной посылки; повторные измерения судьи могут различаться. Существующие простые и отличающиеся оптимизированные версии сохранены.

Accepted #11329348 (Java 1.8): **0.046 s / 480 KB**.

## Особенности языков

Неизменённый исходник CPython измерен ещё три раза: (0.078 s, 468 KB), (0.093 s, 400 KB) и (0.046 s, 312 KB). В таблице указана последняя реальная пара Accepted; повторные измерения не являются алгоритмическим ускорением. В сохранённой сопоставимой выборке текущих интерпретаторов эта посылка делит первое место по времени (1/30), место по памяти — 11/30. При памяти менее 1 МиБ для допуска учитывается место по времени. Наглядная базовая версия уже выполняет критерий, поэтому отдельная копия Python с именем optimized не добавляется.

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1352_number_theory_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
