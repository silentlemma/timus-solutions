# 1303. Минимальное покрытие

[Timus 1303](https://acm.timus.ru/problem.aspx?space=1&num=1303) · сложность 174 · greedy

Оригинальная задача — II командный студенческий чемпионат Урала по программированию, Екатеринбург, 3–4 апреля 1998 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны от 1 до 99 999 отрезков [Li, Ri] с целыми концами
(−50 000 ≤ Li < Ri ≤ 50 000). Нужно выбрать как можно меньше из них
так, чтобы вместе они покрывали [0, M], 1 ≤ M ≤ 5000. Вывести их
количество и выбранные отрезки по возрастанию левых концов или
`No solution`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

M, затем отрезки по паре в строке, завершённые парой `0 0`.

## Выходные данные

Количество, затем отрезки по одному в строке, или `No solution`.

## Проверка

Принимается любое минимальное покрытие. Проверяющая программа
убеждается, что количество минимально, что каждый выведенный отрезок
есть во входных данных (и встречается не чаще, чем там), что левые
концы не убывают и что отрезки не оставляют непокрытых точек на
[0, M]. Если покрытия нет, вывод должен быть `No solution`.

## Примеры

### Пример 1

Ввод:

```
1
-1 0
-5 -3
2 5
0 0
```

Вывод:

```
No solution
```

### Пример 2

Ввод:

```
1
-1 0
0 1
0 0
```

Вывод:

```
1
0 1
```

## Решение

Классический жадный алгоритм. Храним правый конец c уже покрытой части
[0, c], вначале c = 0. Среди отрезков с L ≤ c берём отрезок с
наибольшим R. Если даже этот R не дальше c, точку сразу правее c
покрыть нельзя: `No solution`. Иначе берём его и полагаем c = R.
Останавливаемся, когда c ≥ M.

Брать самый дальний отрезок безопасно: какой бы отрезок ни
использовало в этом месте оптимальное покрытие, он заканчивается не
дальше, поэтому замена его нашим сохраняет покрытие и количество.

Если отрезки отсортированы по левым концам, один указатель проходит по
ним один раз: пропущенный однажды отрезок позже помочь не может (его R
не больше текущего c). Выбранные отрезки сами собой идут по
возрастанию левых концов. `O(N log N)` из-за сортировки.

Тонкие места:

- покрытие означает отсутствие дыр внутри [0, M]: отрезки, касающиеся
  в точке, вроде [0, 2] и [2, 5], подходят (тест 04), а [0, 4] и
  [5, 10] оставляют дыру (тест 06);
- отрезок, заканчивающийся в 0, не помогает (тесты 02 и 09);
- пара `0 0` — только признак конца, ведь у настоящего отрезка L < R.

Количества, найденные жадным алгоритмом, сравнивались с поиском в
ширину по достижимым правым концам на 400 небольших случайных входах.

## Оптимизированные решения

Оптимизированное решение на C++ не хранит и не сортирует отрезки.
Поскольку концы целые и M ≤ 5000, оно заводит по корзине на каждый левый
конец от 0 до M − 1 и держит в ней отрезок, дальше всех достающий
вправо; отрезки, начинающиеся левее 0, делят корзину 0, а отрезки,
начинающиеся в M или правее либо кончающиеся в 0 или левее,
отбрасываются: они никогда не помогают. При равной правой границе
корзина хранит меньший левый конец, так что печатается то же покрытие.
Затем жадный алгоритм один раз проходит M корзин: время `O(N + M)` и
память `O(M)`. Числа разбираются вручную из блоков по 4 КБ вместо
`scanf`: {1303_greedy_optimized.cpp}.

## Особенности языков

  отсортированном порядке, — поэтому печатают одно и то же покрытие.
