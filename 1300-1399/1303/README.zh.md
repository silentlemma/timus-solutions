# 1303. 最小覆盖

[Timus 1303](https://acm.timus.ru/problem.aspx?space=1&num=1303) · 难度 174 · greedy

原题出自 1998 年 4 月 3–4 日在叶卡捷琳堡举行的第二届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定 1 到 99 999 条端点为整数的线段 [Li, Ri]（−50 000 ≤ Li < Ri ≤ 50 000），从中选出尽可能少的
线段，使它们一起覆盖 [0, M]，1 ≤ M ≤ 5000。输出数量以及按左端点递增排列的所选线段，或
`No solution`。

时间限制：1 秒。内存限制：64 MB。

## 输入

M，然后是各线段，每行一对，以 `0 0` 结束。

## 输出

数量，然后每行一条线段；或 `No solution`。

## 评测方式

任何最小覆盖都会被接受。检查程序确认数量是最小值，每条输出的线段都在输入中出现（次数不超过输入中的
次数），左端点不递减，并且这些线段没有在 [0, M] 中留下未覆盖的点。不存在覆盖时，输出必须是
`No solution`。

## 样例

### 样例 1

输入：

```
1
-1 0
-5 -3
2 5
0 0
```

输出：

```
No solution
```

### 样例 2

输入：

```
1
-1 0
0 1
0 0
```

输出：

```
1
0 1
```

## 解法

经典的贪心。维护已覆盖部分 [0, c] 的右端 c，初始 c = 0。在 L ≤ c 的线段中取 R 最大的一条。如果
这个 R 都不超过 c，那么 c 右边紧挨着的点永远无法覆盖：`No solution`。否则选它，并令 c = R。
当 c ≥ M 时停止。

取伸得最远的线段是安全的：最优覆盖在此处使用的任何线段都不会更远，所以把它换成我们的线段，覆盖依然
成立，数量也不变。

线段按左端点排序后，一个指针只需扫描一遍：被跳过的线段以后也帮不上忙（其 R 不超过当前的 c）。所选
线段自然按左端点递增排列。排序决定复杂度为 `O(N log N)`。

注意事项：

- 覆盖意味着 [0, M] 内没有缺口：只在一点相接的线段（如 [0, 2] 和 [2, 5]）没问题（测试 04），而
  [0, 4] 和 [5, 10] 之间有缺口（测试 06）；
- 止于 0 的线段没有帮助（测试 02 和 09）；
- `0 0` 这对数只是结束标记，因为真正的线段都满足 L < R。

在 400 个小型随机输入上，用对可达右端点的广度优先搜索验证了贪心得到的数量。

## 优化解法

优化的 C++ 解法既不保存也不排序线段。由于端点是整数且 M ≤ 5000，它为从 0 到
M − 1 的每个左端点设一个桶，只保留从该处向右延伸最远的线段；左端点小于 0 的线段
共用桶 0，左端点不小于 M 或右端点不大于 0 的线段直接丢弃，因为它们永远没有用。右
端点相同时桶里保留左端点较小的线段，所以输出的覆盖相同。然后贪心把 M 个桶扫一
遍：时间 `O(N + M)`，内存 `O(M)`。数从 4 KB 的块中手工解析，而不是用 `scanf`：
{1303_greedy_optimized.cpp}。
