# 1371. Грузоперевозки

[Timus 1371](https://acm.timus.ru/problem.aspx?space=1&num=1371) · сложность 516 · dp

Идея оригинальной задачи — Ден Расковалов, подготовка — Александр Клепинин; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N ≤ 50 000 филиалов соединены N − 1 дорогами в дерево, у каждой дороги
время доставки от 0 до 1000. Нужно вывести среднее время доставки по
всем упорядоченным парам различных филиалов — сумму всех расстояний,
делённую на N(N − 1), — с 4 знаками после точки.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N − 1 строк с концами дороги и её временем.

## Выходные данные

Среднее время.

## Примеры

### Пример 1

Ввод:

```
4
1 2 1
2 3 1
2 4 1
```

Вывод:

```
1.5
```

## Решение

Посчитаем каждую дорогу по разу на каждую пару, которая по ней идёт.
Удаление дороги делит дерево на части из s и N − s филиалов, и ровно
s · (N − s) пар с концами в разных частях идут по ней. Значит, сумма по
упорядоченным парам равна 2 · Σ c · s · (N − s).

Подвесим дерево за филиал 1 и выпишем филиалы так, чтобы родители шли
раньше детей, обходом в ширину. Прочитанный с конца, этот список даёт
размеры поддеревьев: каждый филиал прибавляет свой размер к родителю.
`O(N)`.

Тонкие места:

- на пути из самых дорогих дорог сумма доходит до 4·10¹⁶, так что нужны
  64-битные целые (сгенерированный тест 2);
- путь из 50 000 филиалов слишком глубок для рекурсии, отсюда обход в
  ширину;
- бесплатные дороги со временем 0 допустимы (тест 03).

Ответы сравнивались с суммой всех расстояний, найденных поиском из
каждого филиала, на 300 случайных деревьях до 30 филиалов.

## Оптимизированные решения

C++ сохраняет сумму по разрезам рёбер, храня дерево плоскими списками. Направленное ребро содержит 32-битный следующий индекс, 16-битные вершину и вес. Родители, веса родительских рёбер, порядок обхода и размеры поддеревьев тоже помещаются в 16 бит: N≤50000, веса≤1000. Итеративный порядок от родителей к детям читается назад; вклад weight·s·(N−s) переводится в 64 бита до умножения. Удвоенная сумма и N(N−1) помещаются в знаковые 64 бита. Сначала делим числитель на знаменатель d и получаем целую часть и остаток r. Четыре цифры после точки равны floor((10000r+floor(d/2))/d). Значение 10000 даёт перенос в целую часть. Масштабированный остаток меньше 2.5·10¹³, ошибка округления не больше 0.00005. Время и память O(N), без рекурсии и отдельных контейнеров рёбер у вершин. Простые версии сохранены; остальные семейства используют базы.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- Java хранит дерево в плоских массивах; все языки печатают точку как
  десятичный разделитель.

Последовательно удаляем листья дерева. Для листа XOR-накопители дают единственного оставшегося соседа и вес ребра, поэтому списки смежности не нужны. Принятая посылка 11324213 заняла 0,156 с и использовала 5 856 КБ. Простая версия заняла 0,218 с и использовала 29648 КБ.
