# 1371. 货运公司

[Timus 1371](https://acm.timus.ru/problem.aspx?space=1&num=1371) · 难度 516 · dp

原题创意来自 Den Raskovalov，由 Alexander Klepinin 准备，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

N ≤ 50 000 个分部由 N − 1 条道路连成一棵树，每条路的运送时间在 0 到 1000 之间。输出所有不同分部有序对的平均运送
时间，即所有距离之和除以 N(N − 1)，保留 4 位小数。

时间限制：1 秒。内存限制：64 MB。

## 输入

2 ≤ N ≤ 50000，随后 N−1 个三元组 a,b,c。端点编号 1 至 N，路程时间 c 是 0 至 1000 的整数。道路构成连通树。

## 输出

平均时间。

## 评测方式

数值词元比较（`judging: float:0.0001`）：唯一输出须为有限数，且 abs(actual−expected) ≤ 0.0001·max(1,abs(expected))。题面要求小数点后四位；仓库比较也接受容差内的其他数值写法。

## 样例

### 样例 1

输入：

```
4
1 2 2
2 3 0
3 4 4
```

输出：

```
3.0000
```

## 解法

按经过每条路的分部对来计数。删去一条路会把树分成 s 和 N − s 个分部两部分，恰好有 s · (N − s) 对分部的两端分在两边、
要经过这条路。所以有序对的总和为 2 · Σ c · s · (N − s)。

以分部 1 为根，用广度优先遍历按父先子后的顺序列出分部。倒着读这个列表就能得到子树大小：每个分部把自己的大小加到
父分部上。`O(N)`。

注意事项：

- 在全是最贵道路的路径上，总和可达 4·10¹⁶，需要 64 位整数（生成测试 2）；
- 50 000 个分部的路径对递归来说太深，所以用广度优先顺序；
- 允许时间为 0 的免费道路（测试 03）。

在 300 棵最多 30 个分部的随机树上，与从每个分部出发搜索并累加所有距离的结果比较过。

## 优化解法

C++ 保持边割求和，改为平坦前向星。每有向边含 32 位下一索引、16 位目标与权重；N≤50000、权≤1000，父节点、父边权、遍历顺序及子树大小也适合 16 位。迭代父优先顺序逆序计算，每边贡献 weight·s·(N−s)，乘前提升到 64 位。双倍总和及 N(N−1) 适合有符号 64 位。先用分母 d 除出整数与余数 r，再用 floor((10000r+floor(d/2))/d) 得到四位小数。若结果为 10000 则向整数进位。放大后的余数小于 2.5·10¹³，舍入误差至多 0.00005。时间空间 O(N)，无递归、无逐点边容器。保留简单版，Java/Rust 复用达标基础版，Go/Python 使用各自独立优化源代码。
