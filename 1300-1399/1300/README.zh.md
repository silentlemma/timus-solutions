# 1300. 税收

[Timus 1300](https://acm.timus.ru/problem.aspx?space=1&num=1300) · 难度 2829 · binary_search

原题出自 1998 年 4 月 3–4 日在叶卡捷琳堡举行的第二届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

税率表由界限 N1 < … < Nm 和税率 S1, …, Sm+1（百分比）给出：收入 K 中不超过 N1 的部分缴 S1 %，
N1 与 N2 之间的部分缴 S2 %，依此类推，超过 Nm 的部分缴 Sm+1 %。记为 T(K)。

除工资 R 外，每个单位还发放 R 的 L % 作为地区补贴，补贴单独计税：单位代扣 T(R) + T(L % · R)，
实发 R − T(R) + L % · R − T(L % · R)。所有这些金额都四舍五入到分。

某公民在不超过 30 个单位工作过，只知道各单位的实发金额。输出全年还需补缴多少税：按总工资及据此重算的补贴
计算的税减去各单位已代扣的税。

时间限制：1 秒。内存限制：64 MB。

## 输入

L；然后是若干行 `N S`，以给出最后一档税率的一行 `0 S` 结束；然后是各实发金额，每行一个，以 −1 结束。
L 和税率是 0 到 99 的整数百分比；金额和界限为正数，最多两位小数，不超过 10⁹。界限最多 20 个。

## 输出

差额，保留两位小数。

## 样例

### 样例 1

输入：

```
15         
12000000 12
24000000 20
36000000 25
48000000 30
0        35
12000000   
12000000   
-1
```

输出：

```
937233.19
```

## 解法

所有计算都以整数分进行，因此不会积累舍入误差。金额的百分比按四舍五入取到分，T(K) 先精确累加各档，
再只舍入一次。B(R) 为舍入后的补贴。

难点在于从实发金额反推工资。记 net(R) 为工资 R 对应的实发金额。工资多一分，税最多多一分（所有税率
都低于 100 %），补贴及其税也是如此，所以 net(R) 随 R 增大而不减。因此可以用二分查找由金额求工资：
先把上界不断加倍直到其 net 超过该金额，再把区间折半至一分宽。

几个不同的工资可能对应同一实发金额，因为多出的一分工资可能正好被一分税吃掉。解法取 net 不超过实发
金额的最大工资。求出各工资 Ri 后：

答案 = T(ΣRi) + T(B(ΣRi)) − Σ(T(Ri) + T(B(Ri)))。

J 个单位、m 个界限、工资不超过 V 分时为 `O(J · (m + 1) · log V)`。

注意事项：

- 答案可能为负：税率表不一定递增，税率递减时公民会拿回钱（测试 08）；仅舍入就可能得到 −0.02
  （测试 07）；
- L = 99、统一税率为 99 % 时，实发 10⁹ 对应的工资约大 50 倍，所以需要 64 位的分（测试 07）；
- 金额可能只有一位小数或没有小数，行尾可能有空格（测试 01 和 06）；
- 补贴单独计税，税率表相同（测试 04）。

在 150 个小型随机输入上与逐一枚举所有工资的做法比较过。
