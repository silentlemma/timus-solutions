# 1362. 同学 2

[Timus 1362](https://acm.timus.ru/problem.aspx?space=1&num=1362) · 难度 442 · dp

原题作者 Evgeny Krokhalev，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一家有 N ≤ 100 000 名员工的公司是一棵树：除总经理外，每人恰有一位上司。Tanya 有一个消息，知道消息的人可以给
自己的上司或某个直接下属打电话；每次通话一分钟，一个人同一时间只能打一个电话。输出全公司都知道消息所需的最少
分钟数。这是 [1323](../1323/README.zh.md) 的树上版本。

时间限制：2 秒。内存限制：64 MB。

## 输入

N，然后是 N 行：第 K 行列出员工 K 的下属，以 0 结尾。最后一行为 Tanya 的编号。

## 输出

最少的分钟数。

## 样例

### 样例 1

输入：

```
10
2 3 0
4 5 7 0
6 9 0
0
0
8 10 0
0
0
0
0
2
```

输出：

```
5
```

## 解法

电话既可以往上打也可以往下打，所以上司只是又一个邻居。以 Tanya 为根；这样消息进入每棵子树恰好一次，经由子树的根。

设 time(v) 为 v 得知消息后通知整棵子树所需的分钟数。若 v 按某种顺序给孩子打电话，第 i 个孩子在第 i 分钟得知，在
i + time(孩子) 时完成。最优顺序是先打给最慢的子树：把孩子的时间按降序排为 t₁ ≥ t₂ ≥ …，则 time(v) = max(tᵢ + i)。
交换两个不符合这一顺序的相邻孩子永远不会更差，由此可证。

按广度优先顺序遍历树，再从叶子向上计算时间，所以即使是 100 000 长的链也不需要递归。`O(N log N)`。

注意事项：

- 根不一定是总经理：若 Tanya 是下属，消息先往上再沿其他分支往下（测试 03 和 04）；
- 100 000 长的链对大多数语言的递归来说太深（生成测试 2）；
- 100 000 个点的星形需要 99 999 分钟，每次只能打一个电话（生成测试 3）。

在 400 棵最多 8 名员工的随机树上，与逐分钟枚举所有打电话方式的搜索结果比较过。
