# 1362. Одноклассники 2

[Timus 1362](https://acm.timus.ru/problem.aspx?space=1&num=1362) · сложность 442 · dp

Автор оригинальной задачи — Евгений Крохалев; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Агентство из N ≤ 100 000 сотрудников устроено как дерево: у каждого,
кроме генерального директора, ровно один начальник. У Тани есть
новость, и каждый, кто её знает, может позвонить своему начальнику или
одному из непосредственных подчинённых; разговор длится минуту, и
одновременно человек ведёт только один разговор. Нужно вывести
наименьшее число минут, за которое новость узнает всё агентство. Это
версия задачи [1323](../1323/README.ru.md) для дерева.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

1 ≤ N ≤ 100000 сотрудников имеют уникальные ID от 1 до N. Следующие N строк перечисляют непосредственных подчинённых сотрудника K в строке K, каждый список заканчивается 0. Последняя строка — ID Тани из того же диапазона; иерархия является деревом.

## Выходные данные

Наименьшее число минут.

## Проверка

Сравнение токенов (`judging: tokens`): одно целое — минимальное прошедшее время в минутах; пробельные разделители игнорируются.

## Примеры

### Пример 1

Ввод:

```
6
2 3 0
4 5 0
6 0
0
0
0
4
```

Вывод:

```
4
```

## Решение

Звонить можно и вверх, и вниз, так что начальник — просто ещё один
сосед. Подвесим дерево за Таню; тогда новость попадает в каждое
поддерево один раз, через его корень.

Пусть time(v) — сколько минут нужно v, чтобы оповестить всё своё
поддерево после того, как новость дошла до v. Если v звонит детям в
каком-то порядке, i-й ребёнок узнаёт новость на минуте i и заканчивает
на i + time(ребёнка). Лучший порядок — начинать с самого медленного
поддерева: сортируем времена детей по убыванию t₁ ≥ t₂ ≥ …, и
time(v) = max(tᵢ + i). Обмен двух соседей, стоящих не в этом порядке,
никогда не ухудшает результат, что и доказывает правило.

Дерево обходится в ширину, а времена считаются от листьев вверх, так
что даже цепочке из 100 000 рекурсия не нужна. `O(N log N)`.

Все простые реализации хранят O(N) данных дерева, обхода, ДП и времён детей. Потоковые C++/Go/Java добавляют ограниченные буферы парсера; Python/Rust сохраняют весь ввод: всего O(N+I) для I байтов ввода. Списки детей и наибольшая временная сортируемая строка вместе требуют O(N); рекурсивного стека нет.

Тонкие места:

- корень — не обязательно директор: если Таня подчинённая, новость идёт вверх и
  потом вниз по другим ветвям (тесты 03 и 04);
- цепочка из 100 000 слишком глубока для рекурсии в большинстве языков
  (сгенерированный тест 2);
- звезде из 100 000 нужно 99 999 минут, по одному звонку за раз
  (сгенерированный тест 3).

Ответы сравнивались с перебором всех способов звонить, минута за
минутой, на 400 случайных деревьях до 8 сотрудников.

## Оптимизированные решения

Новые C++, Go и Rust сохраняют порядок звонков по убыванию времени поддеревьев. Дерево хранится тремя индексами на сотрудника: исходный начальник, первый подчинённый и следующий сосед в списке подчинённых. Они перечисляют всех неориентированных соседей без отдельных контейнеров и двойных объектов рёбер. От источника строятся плоский порядок BFS и массив родителей; исходный начальник становится обычным соседом, а директор может быть другим. Идём по порядку назад, собираем времена детей в переиспользуемый префикс рабочего массива, сортируем по убыванию и берём max(time[i]+i+1). Листу нужно ноль минут. Номера и времена помещаются в 32 бита: последовательные звонки всегда завершаются за N−1 минут. Время O(N log N), дерево занимает O(N), рекурсивного обхода нет. C++ и Go читают потоково, Rust хранит строку входа: всего O(N+байты входа). Простые файлы сохранены; Java использует подходящую базу, Python — отдельный быстрый исходник.

Принятая версия Rust 1.75 x64 заняла 0.046 с при 0.031 с у базовой и использовала 3 948 KB при 15320 KB у базовой.

Java использует базу: обе обязательные метрики занимают 1/22. Python использует [1362_dp_optimized.py](1362_dp_optimized.py), предыдущий точный Accepted #11328667, 0.312 с / 29520 КБ. Семь соперников того же CPython дают третий эталон с пределами 0.34040 с / 39495.60 КБ; обе метрики обязательны и проходят. Учебная база 0.468 с / 33988 КБ не проходит время. Общие [критерии](../../RATING_CRITERIA.md): память исключается только строго меньше 1024 КБ, ровно 1024 КБ требует обе метрики; чужие времена быстрее 0.015 с исключаются, снизу ограничивается только наше время. Быстрая C++ проходит обе метрики 1/58; Go/Rust проходят резервную выборку старых компиляторов того же языка. Простые версии сохранены без одинаковых быстрых копий.

В семи файлах исправлены только поясняющие комментарии: пять простых и быстрая Python уточняют, что звонок i при нумерации с единицы завершается в прошедшую минуту i; комментарий рабочего массива быстрой Go перенесён к обратному циклу сбора и сортировки. Алгоритмы и содержательные комментарии сохранены.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1362_dp_optimized.py`. Списки времени детей создаются только для нелистовых вершин, сортируются на месте; задержка родителя находится прямым циклом максимума. Для листьев пустые списки не выделяются. Самостоятельная программа сбрасывает оба выходных потока перед os._exit(0), чтобы после записи полного ответа не выполнять завершение интерпретатора. Это изменение завершения процесса, а не математического алгоритма; простая версия сохранена.

Accepted #11328667 (Python 3.12 x64): **0.312 s / 29520 KB**. Архивное сравнение: `1362_dp.py` (Python 3.12 x64) — 0.468 s / 33988 KB (#11285503).
