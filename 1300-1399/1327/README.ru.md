# 1327. Предохранители

## Задача

ЭВМ теряет предохранитель в каждый нечётный рабочий день: в день 1,
затем в день 3, в день 5 и так далее. Нужно посчитать, сколько
предохранителей сгорит с дня A по день B включительно,
1 ≤ A ≤ B ≤ 10 000.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

A в первой строке и B во второй.

## Выходные данные

Число предохранителей.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
1
5
```

Вывод:

```
3
```

### Пример 2

Ввод:

```
100
200
```

Вывод:

```
50
```

## Решение

Среди дней с 1 по x ровно ⌊(x + 1) / 2⌋ нечётных. Нечётные дни с A по B
— это нечётные дни до B без нечётных дней до A − 1, что даёт
⌊(B + 1) / 2⌋ − ⌊A / 2⌋. `O(1)`.

Тонкие места:

- промежуток из одного дня даёт 1 для нечётного дня и 0 для чётного
  (тесты 03 и 04);
- оба конца учитываются, если они нечётные (тесты 01 и 07).

## Оптимизированные решения

Оптимизированное решение на Java разбирает два числа побайтно из
`System.in` вместо `Scanner`: 0.078 с вместо 0.109 с и 304 КБ вместо
1624 КБ.

`1327_math_optimized.py`. Сохраняется разность префиксных количеств нечётных дней (B+1)//2-A//2. Обе ограниченные границы разбираются из байтовых токенов вместо двух текстовых вызовов input. Арифметика требует O(1) времени и дополнительной памяти. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1327_math.py`: время 0.062 s → 0.125 s; память 404 KB → 208 KB.
