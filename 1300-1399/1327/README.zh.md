## 任务

一台计算机在每个奇数工作日烧掉一根保险丝：第 1 天，然后第 3 天、第 5 天，依此类推。求从第 A 天到第 B 天
（含两端）烧掉的保险丝数，1 ≤ A ≤ B ≤ 10 000。

时间限制：1 秒。内存限制：64 MB。

## 输入

第一行是 A，第二行是 B。

## 输出

保险丝的数量。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
1
5
```

输出：

```
3
```

### 样例 2

输入：

```
100
200
```

输出：

```
50
```

## 解法

第 1 天到第 x 天中有 ⌊(x + 1) / 2⌋ 个奇数日。从 A 到 B 的奇数日等于到 B 为止的奇数日减去到 A − 1 为止的
奇数日，即 ⌊(B + 1) / 2⌋ − ⌊A / 2⌋。`O(1)`。

注意事项：

- 只有一天的区间，奇数日得 1，偶数日得 0（测试 03 和 04）；
- 两端为奇数时都要计入（测试 01 和 07）。

## 优化解法

优化的 Java 解法直接从 `System.in` 逐字节解析两个数，而不是使用 `Scanner`：
0.078 s，而不是 0.109 s；304 KB，而不是 1624 KB。

`1327_math_optimized.py`. 保留奇数天前缀计数之差 (B+1)//2-A//2。从字节记号读取两个有界端点，代替两次文本 input。算术时间及额外空间均为 O(1)。 独立评测程序在 os._exit(0) 前显式刷新 stdout，跳过常规解释器清理。其自身 Accepted 记录证明内存收益。单独改变退出方式不改进渐近复杂度，运行环境收益也不保证跨平台成立。简单版本保持不变。
