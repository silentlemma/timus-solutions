# 1315. MDPAR 与 MIIAR

[Timus 1315](https://acm.timus.ru/problem.aspx?space=1&num=1315) · 难度 1761 · bfs

原题创意来自 Alexander Klepinin，由 Alexander Klepinin 和 Ivan Dashkevich 准备，出自 2004 年 3 月 11–16 日在叶卡捷琳堡举行的第八届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

洞穴是一个 W × H 的网格，由岩石（`#`）和空格（`.`）组成，W, H ≤ 500，顶行之上是地面。若某个空格
经由有公共边的空格存在一条从不向下走的通往地面的路径，水就会灌满它。探洞者站在格子 (X, Y)（从左
和从下数起），在水下最多能游 D ≤ 1000 格，之后必须换气。水到不了的空格里留有空气。探洞者能自己
出来吗？洞穴干燥时保证有出路。

时间限制：1 秒。内存限制：64 MB。

## 输入

W、H、X、Y 和 D，然后是从上到下的 H 行洞穴。

## 输出

`Can be rescued by himself` 或 `Rescue operation required`。

## 样例

### 样例 1

输入：

```
9 4 8 2 5
##..##..#
##.#.####
##......#
#########
```

输出：

```
Rescue operation required
```

### 样例 2

输入：

```
9 4 8 2 6
##..##..#
##.#.####
##......#
#########
```

输出：

```
Can be rescued by himself
```

## 解法

先求出水。若从某格只向上、左、右移动就能到达地面，该格就被淹没，所以从顶行的空格出发反向搜索，
向下、左、右扩展。

再看探洞者。两个样例确定了游泳的计数方式：一段水下行程从上一次呼吸持续到下一次呼吸，其中每一步都
计数，包括进入空气格或从顶行出去的那一步。样例中从空气囊到地面的一段需要 6 步，所以 D = 5 不够，
D = 6 足够。

给每个格子一个标签：在所有到达方式中，站在该格时距上一次呼吸在水下走过的最少步数。

- 进入有水的格子，标签加 1；
- 进入空气格把标签重置为 0，但游泳者只有还剩一步时才能这样做，即标签 + 1 ≤ D（从空气到空气不计）；
- 从顶行出去需要标签 + 1 ≤ D。

标签越小越好，所以每个格子只需保留最小标签。标签在 0 到 D 之间，按标签分桶就能当作优先队列。当在
处理较大标签时，某个空气囊出现了标签 0，扫描就回到 0 号桶。最坏情况为 `O(W · H · D)`。

注意事项：

- 空气囊没有不向下走就能到地面的路径，比如样例中走廊上方的那一格，探洞者可以在里面呼吸（测试
  01–04）；
- 探洞者可能从空气囊或水中出发，两种情况标签都从 0 开始（测试 03 和 01）；
- 出到地面的那一步也计数：k 格长的淹没竖井需要 D ≥ k（测试 08 和 09）。

在 700 个小型随机洞穴上与对所有状态（格子，距上次呼吸的步数）做广度优先搜索的结果比较过。

## 各语言说明

- Python 在洞穴外围加一圈岩石，这样每一步都不用检查边界，并用 `bytes.translate` 构造网格。
- Python 在 PyPy 下运行：评测系统的一个测试用 CPython 略超 1 秒，而我们的测试都在 0.2 秒以内。
