# 1376. Пирамида декана 2

[Timus 1376](https://acm.timus.ru/problem.aspx?space=1&num=1376) · сложность 12875 · backtracking

Автор оригинальной задачи — Александр Мироненко; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Пирамида с квадратным основанием со стороной A1 и четырьмя равными
равнобедренными боковыми гранями с боковым ребром A2 (оба от 0,1 до 10,
A2/A1 от 0,9 до 1,9) стоит на основании, центр в начале координат,
рёбра основания вдоль осей. Её перекатывают через ребро с грани на
соседнюю грань, ребро при этом остаётся на месте. Не более чем за N
перекатываний (2 ≤ N ≤ 32) верните её на основание так, чтобы центр
основания был как можно ближе к (X, Y), которая не ближе 20,05·A1; при
равных расстояниях — за наименьшее число перекатываний. Выведите
расстояние с 3 знаками, число перекатываний M и M + 1 граней, на
которых она стоит: 0 — основание, 1–4 — боковые грани по часовой
стрелке, начиная с обращённой к +y.

Ограничение времени: 2,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

A1, A2, X, Y и N.

## Выходные данные

Расстояние, M и грани, начиная с исходной 0.

## Примеры

### Пример 1

Ввод:

```
10.0 10.0 1000.0 0.0 5
```

Вывод:

```
972.679
5
0 2 3 4 1 0
```

## Решение

Состояние — грань на столе и вершины этой грани; перекатывание отражает
или разворачивает их через общее ребро. Все перекатывания покрывают
четыре правила: с основания на боковую грань k через ребро вершин k и
k + 1; с боковой грани на основание, что разворачивает квадрат; и с
боковой грани на соседнюю по или против часовой стрелки через боковое
ребро, что отражает третью вершину.

Поиск точный. Одно перекатывание сдвигает центр грани на столе на
постоянную величину: A1/2 + h/3 между основанием и боковой гранью (h —
высота боковой грани) и 2·A1·h/(3·A2) между двумя боковыми, поэтому
таблица даёт для каждого состояния и числа оставшихся перекатываний,
насколько далеко ещё может уйти центр, закончив на основании. Поиск в
глубину по перекатываниям (никогда не катя сразу обратно) отсекает по
неравенству треугольника каждую ветку, которая не может улучшить лучшее
расстояние, и пробует сначала ближайшие положения. Поиск с лучом в
4 000 состояний на глубину даёт хороший первый ответ, так что отсечения
работают сразу. `O(3^N)` в худшем случае, на деле гораздо меньше.

Подводные камни:

- ответ не единственный: перекатывания из примера можно сделать в другом
  порядке (тест 01), поэтому программа проверки повторяет их;
- при N = 2 ближе не подойти, и ответ — 0 перекатываний (тест 02);
- при равных расстояниях решает число перекатываний.

Ответы совпадают с независимой принятой реализацией на всех здешних
тестах и на 150 сгенерированных, а с полным перебором всех
последовательностей — на 240 случаях с N до 8.

## Особенности языков

- Python считает оценку для первых 8 перекатываний точно: из одного
  состояния каждого из 17 видов он проигрывает все последовательности до
  8 перекатываний и берёт самый дальний конец на основании; дальше, как
  в остальных языках, прибавляются постоянные шаги. Основание — грань —
  основание всегда возвращает пирамиду на место, так что прежняя оценка
  была слишком грубой: поиск обходит в 11–25 раз меньше узлов, и хватает
  луча в 200 состояний. Самые большие тесты занимают 0,25 с в CPython;
  первая версия без точной оценки даже под PyPy превышала 2,5 с на тесте
  5 жюри.
