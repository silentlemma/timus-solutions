# 1334. Шашки

[Timus 1334](https://acm.timus.ru/problem.aspx?space=1&num=1334) · сложность 541 · simulation

Автор оригинальной задачи — Ден Расковалов; X командный чемпионат школьников Свердловской области по программированию, 16 октября 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Двое по очереди ставят шашки своего цвета на чёрные поля шахматной
доски, белые первыми; ходов 32. Проигрывает тот, после чьего хода
какую-нибудь шашку можно срубить: шашку A может срубить шашка B другого
цвета, стоящая рядом с ней по диагонали, если поле сразу за A на этой
диагонали свободно. Нужно вывести номер проигрышного хода или `Draw`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

32 строки с полями в шахматной нотации, например `a1`: ходы белых в
нечётных строках, ходы чёрных в чётных.

## Выходные данные

Номер проигрышного хода или `Draw`.

## Решение

Ставим шашки на доску по одной. После каждого хода смотрим на каждую
шашку и каждую из четырёх диагоналей: если сосед там другого цвета, а
поле за ним есть на доске и свободно, рубить можно, и только что
сделанный ход проигрывает. Считается взятие любым игроком, в том числе
тем, кто только что сходил, и взятие назад тоже. O(1): не больше 32 · 32 · 4
проверок.

Тонкие места:

- прыжок, который уводит за край доски, — не взятие, как у шашки в углу
  (тест 03);
- ходящий может проиграть, дав возможность рубить самому себе (тест 05);
- ход 32 никогда не проигрывает: к этому времени все чёрные поля заняты
  и приземлиться некуда, так что последний ход, который может
  проиграть, — 31-й (тест 07).

## Оптимизированные решения

Go и Rust проверяют только тройки, затронутые новой шашкой. До непроигрышного хода взятия нигде нет. Неизменённая тройка не может стать взятием, а занятая новым ходом клетка уже не может быть пустой посадочной. Значит новая шашка — либо атакующая, либо срубаемая средняя. Для каждого из четырёх диагональных смещений d ищем противника в cell+d и пустоту в cell+2d (новая атакующая) либо cell−d (новая средняя). Учитывается возможность любого игрока и все направления. Двухклеточная рамка превращает поле8×8 в 144 байта: стена255 не равна ни цвету, ни пустоте, обращения на два шага остаются внутри. Цвета чередуются, регистр буквы клетки неважен; выводится первый проигрышный ход или Draw. Для M ходов время O(M), без сканирования всего поля, память постоянна. Go читает через стандартные дескрипторы в буфер на 64 байта и печатает номер хода из трёхбайтового массива. Rust использует C runtime. Простые полные проверки сохранены; C++/Java/Python используют подходящие базы.

Принятая версия Rust 1.75 x64 заняла 0.062 с при 0.046 с у базовой и использовала 60 KB при 208 KB у базовой.

Принятая версия Go 1.14 x64 заняла 0.031 с при 0.015 с у базовой и использовала 276 KB при 1036 KB у базовой.

Принятые базовые реализации [1334_simulation.cpp](1334_simulation.cpp), [1334_simulation.java](1334_simulation.java), [1334_simulation.py](1334_simulation.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Исходные файлы проверяют всю доску после каждого хода. Оптимизированные Go и Rust проверяют четыре диагональных направления от новой шашки.
