# 1370. Волшебник

[Timus 1370](https://acm.timus.ru/problem.aspx?space=1&num=1370) · сложность 89 · implementation

Автор оригинальной задачи — Станислав Васильев; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На ободе колеса написаны N цифр, 11 ≤ N ≤ 1000, а в окошке видны 10
подряд идущих, сначала цифры с 1-й по 10-ю. Каждый щелчок поворачивает
колесо на одну цифру, так что после одного щелчка в окошке цифры со 2-й
по 11-ю. По числу щелчков M (1 ≤ M ≤ 32 767) нужно вывести 10 цифр в окошке.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и M, затем N цифр по одной в строке.

## Выходные данные

10 цифр в окошке, включая ведущие нули.

## Проверка

Тесты репозитория сравнивают полный текст вывода, игнорируя только конечные пробельные символы. Значимые пробелы, переводы строк, регистр и пунктуация сохраняются.

## Примеры

### Пример 1

Ввод:

```
12 7
1
2
3
4
5
6
7
8
9
0
7
7
```

Вывод:

```
8907712345
```

## Решение

После M щелчков окошко начинается с цифры M (считая с 0), а колесо
замкнуто, поэтому ответ — цифры (M + i) mod N для i = 0 … 9. `O(1)`
после чтения ввода.

Тонкие места:

- M может быть во много раз больше N (тест 05);
- окошко может переходить через последнюю цифру (пример);
- ответ выводится цифрами, с ведущими нулями (тест 03).

## Оптимизированные решения

Оптимизированное решение на Java разбирает числа вручную вместо
`Scanner`, хранит цифры байтами и выводит десять цифр окошка одним
массивом байтов: 0.093 с вместо 0.125 с и 340 КБ вместо 1892 КБ.

Оптимизированное решение на C++ читает цифры как символы в массив
фиксированного размера и печатает десять из них через `putchar`, без
перевода в числа и без `std::string`: 120 КБ вместо 196 КБ при том же
времени.

`1370_implementation_optimized.py`. Поворот сводится к start=M mod N. При чтении цифры i она сохраняется только при offset=(i-start) mod N меньше десяти, на этой позиции ответа. При N>=11 десять смещений различны и каждое заполняется ровно раз. Переход через конец и ведущие нули сохраняются, всё колесо хранить не нужно. Время O(N), десять байт ответа. Используются bytearray на десять позиций и разбор блоками по 65536 байт. Память токенов и блока парсера остаётся, но списка N цифр нет; декодируются только десять байт ответа. Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1370_implementation.py`: время 0.062 s → 0.14 s; память 404 KB → 244 KB.

`1370_implementation_optimized.rs`. Поворот сводится к start=M mod N. При чтении цифры i она сохраняется только при offset=(i-start) mod N меньше десяти, на этой позиции ответа. При N>=11 десять смещений различны и каждое заполняется ровно раз. Переход через конец и ведущие нули сохраняются, всё колесо хранить не нужно. Время O(N), десять байт ответа. Используются фиксированный массив десяти байт и O(1) числового состояния; цифры выводятся байтами ASCII без строки ответа. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1370_implementation.rs`: время 0.015 s → 0.015 s; память 244 KB → 52 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1370_implementation_optimized.py`: место по времени 170/179, по памяти 1/179 в этой сопоставимой выборке.

`1370_implementation_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
