# 1353. Миллиардная Функция Васи

[Timus 1353](https://acm.timus.ru/problem.aspx?space=1&num=1353) · сложность 103 · dp

Автор оригинальной задачи — Денис Мусин; чемпионат школьников, март 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано S, 1 ≤ S ≤ 81. Нужно посчитать целые числа от 1 до 10⁹ с суммой
цифр S.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число S.

## Выходные данные

Количество.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
1
```

Вывод:

```
10
```

## Решение

Любое число меньше 10⁹, дополненное ведущими нулями, — строка из девяти
цифр, а ведущие нули сумму цифр не меняют. Поэтому считаем строки
цифр: ways[s] после k цифр — число k-значных строк с суммой s, и каждая
новая цифра d от 0 до 9 переносит ways[s] в s + d. После девяти цифр
ways[S] — количество чисел от 0 до 999 999 999 с суммой S. У нуля сумма
0, он никогда не учитывается, а само 10⁹ с суммой цифр 1 добавляет
единицу при S = 1. `O(9 · 81 · 10)`.

Тонкие места:

- 10⁹ входит в диапазон: при S = 1 ответ 10, а не 9 (тест 01);
- начиная с S = 10 одна цифра уже не может взять всю сумму, и простой
  подсчёт «шаров и перегородок» даёт лишнее (тест 07);
- значения симметричны, ways[s] = ways[81 − s], а наибольшее —
  45 433 800 при S = 40 и 41, оно помещается в 32 бита.

Та же таблица для 10⁶ вместо 10⁹ сравнивалась с подсчётом сумм цифр
всех чисел до 10⁶.

## Оптимизированные решения

`1353_combinatorics.py`. DP суммы цифр заменена включением-исключением по девяти десятичным цифрам. Дополнение цифр сводит S к min(S,81−S). Для каждого набора исключений C(r+8,8) равно (a+8)(a+14)(a+18)(a+20)/8!, где a=r(r+9); C(9,j) обновляется точно. Отдельное число 10^9 добавляется только при S=1. Для фиксированных девяти цифр не больше пяти слагаемых, целая арифметика без таблицы ответов. Другой алгоритм назван combinatorics; обе DP-версии сохранены.

Точный исходник: Python 3.12 x64 Accepted #11327779: 0.078 s / 748 KB. Сохранённые места в группе компилятора от 2026-11-20, время затем память: 1/97; 57/97. Строгий допуск учитывает только время при памяти меньше 1024 КБ: первые десять или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка — первого места по обеим метрикам. Сохранённый прежний вариант имеет собственную парную посылку #11325475 (PyPy 3.10 x64): 0.125 s / 228 KB; замеры и рантаймы не смешиваются. Все учебные исходники сохранены без изменений.

- `1353_combinatorics.py`: 0.078 s / 748 KB; сохранённая учебная база `1353_dp.py` (Python 3.12 x64): 0.093 s / 496 KB.

`1353_dp_optimized.java`. Сохраняются ДП по девяти цифрам и добавление числа 10^9 при S=1. Вместо десяти переходов для каждой суммы используется скользящая сумма десяти предыдущих состояний; два массива long по S+1 ячейке переиспользуются. Единственное число читается через буфер 1024 байта вместо Scanner. Время O(9S), дополнительная память O(S); простое ДП с десятью переходами сохранено без изменений. Допуск обеспечен собственными измерениями памяти Accepted, первое место не заявляется.

По сравнению с `1353_dp.java`: время 0.125 s → 0.093 s; память 1 576 KB → 476 KB.

`1353_dp_optimized.py`. ДП сохраняется, но очередная строка считается скользящей суммой вместо десяти прибавлений на состояние. После k цифр хранятся только суммы до min(S,9k), одновременно нужны две строки: время O(9S), дополнительная память O(S). Во входе одно ограниченное число. Полный ответ сбрасывается до os._exit(0), пропускающего завершение интерпретатора; само по себе это не гарантия алгоритмического ускорения. Судья использовал PyPy 3.10, а сохранённая простая версия перепроверена на CPython 3.12: метрики относятся к этим парам исходник/среда. Память снижается с 496 до 228 КБ, время растёт с 0.093 до 0.125 с. Простая версия сохранена, недостигнутая рейтинговая цель отмечена звёздочкой.

По сравнению с `1353_dp.py`: время 0.093 s → 0.125 s; память 496 KB → 228 KB.

`1353_dp_optimized.rs`. В том же ДП десять переходов по цифрам заменены скользящей суммой десяти предыдущих состояний. Два фиксированных массива по 82 ячейки u32 покрывают суммы до 81; после каждой цифры перебираются только достижимые суммы. При D=9 цифрах и M=9D время O(DM), дополнительная память O(M), обе величины ограничены константой для этой задачи. Число строк не больше 10^9 и помещается в u32. Побайтовые ввод и вывод через среду C исключают выделения для стандартных текстовых средств Rust. Добавление 10^9 при S=1 и простая версия сохранены. Измеренный выигрыш относится к памяти; ускорение по старому запуску не обещаем.

По сравнению с `1353_dp.rs`: время 0.062 s → 0.062 s; память 216 KB → 60 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Все пять простых исходников сохранены без изменений. Их строки таблицы теперь содержат новые Accepted для точных исходников: обе метрики и ID одной посылки; исходные таблицы README сохранены в резервной копии интеграции. Эти перепроверки не считаются оптимизациями.

`1353_dp_optimized.java`: место по времени 4/94, по памяти 10/94 в этой сопоставимой выборке.

`1353_dp_optimized.py`: место по времени 71/97, по памяти 1/97 в этой сопоставимой выборке.

`1353_dp_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
