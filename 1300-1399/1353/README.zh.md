# 1353. Vasya 的十亿函数

[Timus 1353](https://acm.timus.ru/problem.aspx?space=1&num=1353) · 难度 103 · dp

原题作者 Denis Musin，出自 2005 年 3 月中学生锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定 S，1 ≤ S ≤ 81，统计 1 到 10⁹ 之间数字和为 S 的整数个数。

时间限制：1 秒。内存限制：64 MB。

## 输入

一个数 S。

## 输出

个数。

## 评测方式

仓库测试精确比较输出记号，记号之间的空白分隔不影响结果。

## 样例

### 样例 1

输入：

```
1
```

输出：

```
10
```

## 解法

每个小于 10⁹ 的数补上前导零后都是一个九位数字串，而前导零不改变数字和。所以改为统计数字串：k 位之后的
ways[s] 是数字和为 s 的 k 位串个数，每加一位数字 d（0 到 9）就把 ways[s] 加到 s + d 上。九位之后，ways[S]
就是 0 到 999 999 999 中数字和为 S 的数的个数。0 的数字和为 0，永远不会被计入；而 10⁹ 本身的数字和为 1，
在 S = 1 时再加一。`O(9 · 81 · 10)`。

注意事项：

- 10⁹ 在范围之内：S = 1 时答案是 10 而不是 9（测试 01）；
- 从 S = 10 开始，单个数字已无法承担全部的和，直接用隔板法会多算（测试 07）；
- 结果是对称的，ways[s] = ways[81 − s]，最大值为 S = 40 和 41 时的 45 433 800，可以放进 32 位整数。

把 10⁹ 换成 10⁶ 得到的同样的表，与逐个统计 10⁶ 以内所有数的数字和的结果比较过。

## 优化解法

`1353_combinatorics.py`. 以九位十进制数字的容斥替代数位和 DP。补数字把 S 缩为 min(S,81−S)。每项 C(r+8,8) 用 a=r(r+9) 写成 (a+8)(a+14)(a+18)(a+20)/8!，精确更新 C(9,j)。仅 S=1 时另加 10^9。固定九位至多五项，整数精确计算，无答案表。不同算法命名 combinatorics，保留两种 DP。

`1353_dp_optimized.java`. 保留九位数位 DP，以及 S=1 时补上 10^9。用前十个状态的滑动和替代每个和的十次转移，复用两个各 S+1 格的 long 数组。单个输入整数通过 1024 字节缓冲解析，不用 Scanner。时间 O(9S)，辅助空间 O(S)；原有十次转移的简单 DP 保持不变。按自身 Accepted 的内存改进收录，不声称排名第一。

与 `1353_dp.java` 相比：时间 0.125 s → 0.093 s；内存 1 576 KB → 476 KB。

`1353_dp_optimized.py`. 保留数位 DP，但每行用滑动和计算，不再每状态做十次加法。处理 k 位后仅存到 min(S,9k) 的和，同时保留两行：时间 O(9S)，辅助空间 O(S)。输入仅一个有界整数。完整答案先 flush，再 os._exit(0) 跳过解释器清理；这本身不保证算法加速。评测用 PyPy 3.10，保留的简单版在 CPython 3.12 重新 Accepted，指标属于各自代码/运行时。内存由 496 降至 228 KB，时间从 0.093 增至 0.125 s。保留简单版，未达排名目标标星。

与 `1353_dp.py` 相比：时间 0.093 s → 0.125 s；内存 496 KB → 228 KB。

`1353_dp_optimized.rs`. 同一数位 DP 的十次转移改为前十状态滑动和。两个各 82 格的固定 u32 数组覆盖和至 81，每位只遍历可达的和。令 D=9、M=9D，时间 O(DM)、辅助空间 O(M)，本题均为有界常量。计数不超过 10^9 个数串，u32 足够。C 运行时字节输入/输出避免 Rust 标准文本与格式化分配。保留 S=1 时补 10^9 和简单版。实测收益为内存，不从不同历史运行推断加速。

与 `1353_dp.rs` 相比：时间 0.062 s → 0.062 s；内存 216 KB → 60 KB。
