# 1366. Подарки

[Timus 1366](https://acm.timus.ru/problem.aspx?space=1&num=1366) · сложность 523 · math

Идея оригинальной задачи — Станислав Васильев, подготовка — Павел Егоров; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждый из n ≤ 1000 детей приносит подарок, и подарками меняются так,
чтобы каждый ребёнок получил ровно один подарок и никто не остался со
своим. Нужно посчитать число способов.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число n.

## Выходные данные

Число схем обмена.

## Примеры

### Пример 1

Ввод:

```
3
```

Вывод:

```
2
```

## Решение

Схема обмена — перестановка без неподвижных точек, беспорядок. По
формуле включений-исключений их число d(k) = Σ (−1)ⁱ · k! / i! по
i = 0 … k, и умножение d(k − 1) на k даёт все слагаемые d(k), кроме
последнего, (−1)ᵏ. Значит, d(1) = 0 и d(k) = k · d(k − 1) + (−1)ᵏ:
начинаем с 0 и применяем это для k = 2 … n.

Ответ при n = 1000 содержит 2 568 цифр, так что нужна длинная
арифметика: каждый шаг умножает на небольшое число и прибавляет или
вычитает 1. `O(n² log n)` действий с цифрами.

Тонкие места:

- один ребёнок поменяться не может: ответ 0 (тест 02);
- d(21) — первое значение, которое не помещается в 64 бита (тест 06);
- после умножения число при k ≥ 3 не меньше 3, так что вычитание 1
  никогда не уводит ниже нуля.

Рекуррентность сравнивалась с подсчётом всех перестановок при n ≤ 8 и
с суммой включений-исключений при n = 50.

Учебная версия C++ хранит десятичные цифры по одной, начиная с младшей. На шаге k перенос начинается с +1 для чётного k и с −1 для нечётного. Умножаем очередную цифру на k и прибавляем перенос, записываем цифру единиц и передаём частное как новый перенос. Так за один проход вычисляется k·D(k−1)+(−1)^k. При нечётном k предыдущий индекс чётный и D(k−1) нечётно. Значит, младшая цифра положительна и первое вычитание безопасно. Печатаем цифры от старшей к младшей. Время O(n² log n), память O(n log n).

## Оптимизированные решения

Go, Java и Rust считают перестановки без неподвижных точек, объединяя два шага. Из D(k)=kD(k−1)+(−1)^k для чётного k получаем D(k)=k(k−1)D(k−2)−(k−1). Начинаем с D(2)=1, n=1 обрабатываем отдельно; для нечётного n завершаем формулой nD(n−1)−1, если n>1. Один проход по блокам в основании 10⁹ обслуживает два шага. По рекуррентной формуле D с чётным индексом нечётно, поэтому младший блок положителен. Начальное вычитание меньше множителя f, а первый продукт не меньше f. Дальнейшие переносы лежат в [0,f−1], промежуточные значения меньше f·10⁹. При f≤999 000 достаточно знаковых 64 бит, а конечный перенос помещается в один блок. Из D(n)<n!≤10³⁰⁰⁰ следует, что достаточно 334 блоков, а весь вывод Go и Java помещается в 3001 байт. Фиксированные массивы заменяют временные длинные числа Go и Java. Go читает и пишет через стандартные дескрипторы и заполняет буфер с конца. Java обходится без Scanner. В Rust используется точка входа C и посимвольный ввод и вывод через библиотеку C. Для записи блока достаточно буфера на девять байтов. Время O(n² log n) машинных операций, O(n log n) цифр. Простые версии сохранены, C++/Python используют подходящие базы.

Принятые базовые реализации [1366_math.cpp](1366_math.cpp), [1366_math.py](1366_math.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Исходные Python, Go и Java используют длинные целые своих языков. Исходные C++ и Rust хранят блоки в основании 10⁹. Оптимизированные Go, Java и Rust используют фиксированные массивы таких блоков и объединяют два шага.
