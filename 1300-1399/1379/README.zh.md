# 1379. 运送杯子

[Timus 1379](https://acm.timus.ru/problem.aspx?space=1&num=1379) · 难度 581 · graphs

原题作者 Pavel Egorov，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一辆 3000 kg 的卡车要在 24 小时内把尽可能多的杯子从路口 1 运到路口 N（N ≤ 500），每个杯子重 100 g，最多为订购的
10 000 000 个。每条双向道路有以分钟计的行驶时间和以克计的卡车最大允许质量。输出最多能运的杯子数。

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 M，然后是 M 行：道路的两端、时间和质量限制。

## 输出

杯子的数目。

## 样例

### 样例 1

输入：

```
3 3
1 2 10 3000220
2 3 20 3000201
1 3 1 3000099
```

输出：

```
2
```

### 样例 2

输入：

```
1 0
```

输出：

```
10000000
```

## 解法

卡车越重，能走的路就越少，所以随着载重增加，按时到达只会更难。一条路线的最大允许质量等于其中某条道路的限制，于是在不小于
3 000 000 g 的道路限制中二分查找。对每个候选值，Dijkstra 算法只使用能承受该质量的道路，且不保留超过 1440
分钟的时间。设能按时到达的最大质量为 W，答案为 min(10 000 000, ⌊(W − 3 000 000) / 100⌋)。`O((N + M log M) · log M)`。

注意事项：

- N = 1 时杯子已经在会场：全部 10 000 000 个（样例 2）；
- 恰好 24 小时即 1440 分钟仍然来得及（测试 03）；
- 最快的路可能比慢的路承重小（测试 05）；
- 恰好只能承受空卡车的道路一个杯子也运不了（测试 06）；
- 道路可能不花时间（测试 07）。

在 400 个最多 6 个路口的随机图上，与枚举所有简单路径的结果比较过。

## 优化解法

优化后的 C++ 版本二分搜索不同的整杯载量。每次运行 Dijkstra 时，为 0 到 1440
的每一分钟设一个桶。若到达时间缩短，就把该结点移到更早的桶。零分钟的道路可能向当前桶添加结点，因此必须处理到桶为空。D = 1440 时，每次搜索耗时 O(N + M + D)，空间为
O(N + M + D)。提交 11316958 耗时 0.031 秒、使用 3464 KB；基础版本为 0.281 秒和 7564 KB。

## 各语言说明

- Python 需要 PyPy：在由一天长的道路组成的完全图中藏一条短路链，会让搜索扫描大量道路，CPython 约需 0.5 秒，
  PyPy 约 0.25 秒。
- Java 把堆存成普通 long 的数组，时间和顶点打包在一个数里：用小数组组成的优先队列在评测的第 46 个测试上超时。

PyPy 版本把终点、行驶时间和载重上限编码到每条边的一个整数中。邻接表按载重上限排序，遇到无法通行的边时即可停止扫描。按分钟分桶时跳过已经被更短路径替代的记录。评测数据来自提交 11317003。

Java 版本也将每条边编码为一个整数，并按载重上限排序邻接表。找到更早的到达时间时，将原有记录移到相应的分钟桶，每个路口最多保留一条记录。评测数据来自提交 11317007。

Rust 版本按载重上限排序压缩后的边，遇到第一条载重不足的边时停止扫描。移动分钟桶中的记录可以让每个路口只保留一条记录。评测数据来自提交 11317009。

Go 版本将每条边压缩为一个整数，并按载重对邻接表排序。搜索路径时，一旦遇到载重不足的边，就停止扫描当前邻接表。提交 11317150 耗时 0.093 秒，使用 5748 KB；基础版耗时 0.562 秒，使用 24828 KB。
