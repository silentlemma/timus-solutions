# 1316. Биржа

[Timus 1316](https://acm.timus.ru/problem.aspx?space=1&num=1316) · сложность 427 · fenwick

Идея оригинальной задачи — Павел Атнашев, подготовили Павел Атнашев и Павел Егоров; VIII командный студенческий чемпионат Урала по программированию, Екатеринбург, 11–16 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Журнал биржи содержит до 100 000 операций:

- `BID X`: покупатель готов купить одну болванку по цене X;
- `DEL X`: заявка по цене X снимается;
- `SALE X K`: выставлено K болванок по цене X, и первые K заявок с ценой
  X или больше получают по одной; остальные идут на переплавку.

Заявка остаётся в силе и после покупки, пока её не снимут. Цены от
0.01 до 10 000.00, не больше двух знаков после точки, K ≤ 100 000,
журнал заканчивается словом `QUIT`. Биржа получает 0.01 с каждой
проданной болванки. Нужно вывести её итоговую прибыль.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Журнал по операции в строке, заканчивающийся `QUIT`.

## Выходные данные

Прибыль биржи с двумя знаками после точки.

## Примеры

### Пример 1

Ввод:

```
BID 0.01
BID 10000
BID 5000
BID 5000
SALE 7945.14 3
DEL 5000
SALE 3487.45 3
SALE 0.01 3
QUIT
```

Вывод:

```
0.06
```

## Решение

Продажа продаёт min(K, число действующих заявок по X или дороже)
болванок, так что нужен лишь счётчик действующих заявок по ценам с
запросом «сколько по X или дороже».

Цены читаются точно, как целые копейки, от 1 до 1 000 000. Если
нумеровать копейки от самой высокой цены вниз, «X или дороже»
становится префиксом, и счётчики хранит дерево Фенвика. Заявка
прибавляет 1 к своей цене, снятие вычитает 1, а продажа читает
префиксную сумму. `O(P + N log P)` для N операций и P индексов цен.

Проданные болванки считаются в целом числе, и, поскольку каждая
приносит одну копейку, это число, делённое на 100 и записанное с двумя
знаками после точки, и есть ответ.

Тонкие места:

- заявка ровно по X покупает (тест 04), и заявка действует для следующих
  продаж, пока её не снимут (тест 07);
- 50 000 заявок и 49 999 продаж по 100 000 болванок дают 2.49995 · 10⁹
  проданных болванок, больше 2³¹, так что знаковые 32-битные счётчики
  переполняются (тест gen5);
- цены могут иметь один знак после точки или ни одного, например `5.5`
  или `10000` (тесты 04 и 05);
- вещественная прибыль вроде 0.01 · count может выйти на копейку
  меньше, чего целые копейки избегают.

Итоги сравнивались с прямым подсчётом по всем действующим заявкам на
300 случайных журналах.

## Оптимизированные решения

Обновлённая версия C++ сохраняет сжатие цен BID и повторное выполнение журнала с деревом Фенвика. Фиксированный байтовый буфер на 16 КБ разбирает команды, десятичные цены и объёмы продаж без scanf. Точное преобразование в целые центы и допустимость ставок, равных цене продажи, не изменились.

Accepted точного исходника (G++ 13.2 x64, #11326642: 0.015 s / 1320 KB); учебная база `1316_fenwick.cpp`: 0.171 s / 3652 KB. Прежнее измерение оптимизированной версии: 0.156 s / 1344 KB. В сохранённом сравнении от 20 ноября 2026 года место по времени — 1/85, по памяти — 1/85; при памяти менее 1 МиБ правило учитывает только рейтинг времени.

Новые реализации C++, Go и Rust сжимают только цены из операций BID. Сохраняем журнал, сортируем и удаляем повторы этих цен, затем выполняем операции с деревом Фенвика. При продаже по X вычитаем из общего числа активных заявок число строго более дешёвых: заявки ровно по X участвуют, а сама продажа их не удаляет. Цены разбираются в целые центы, прибыль хранится в 64-битном или Python-числе. Для не более N операций нужны O(N log N) времени и O(N) памяти вместо миллиона ценовых ячеек. C++, Go и Rust резервируют ёмкость под предел 100000 операций. Python обрабатывает операции сразу в плотном Fenwick-списке на P=1000000 центов с обратным индексом P−цена+1. Более простой онлайн-вариант не хранит журнал, не сортирует цены, не строит словарь и не делает двоичных поисков. Его O(P+N log P) времени и O(P) ячеек меняют фиксированную таблицу на отсутствие сохранённого входа, доступ к списку быстрее типизированной упаковки. Go использует стандартные дескрипторы, Rust — ограниченные буферы C runtime и точку входа C. Обычные реализации и уже подходящая базовая Java-версия сохранены.

Принятая версия Python 3.12 x64 заняла 0.5 с при 0.437 с у базовой и использовала 8 324 KB при 32560 KB у базовой.

Принятые базовые реализации [1316_fenwick.java](1316_fenwick.java) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- Python нумерует только встречающиеся в журнале цены, что делает
  дерево маленьким; остальные языки индексируют все миллион цен
  напрямую.
