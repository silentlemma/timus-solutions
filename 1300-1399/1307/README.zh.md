# 1307. 压缩程序

[Timus 1307](https://acm.timus.ru/problem.aspx?space=1&num=1307) · 难度 1275 · strings

原题创意来自 Leonid Volkov，由 Pavel Egorov 和 Leonid Volkov 准备，出自 2004 年 3 月 11–16 日在叶卡捷琳堡举行的第八届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

输入是一段英文文学作品，长 20 000 到 200 000 个字符。输出它的“压缩包”：一个 Pascal、C 或 C++
程序，第一行为 `{PAS}`、`/*C*/` 或 `//CPP` 以指明语言；编译运行后恰好输出原文，并且严格短于原文。

时间限制：1 秒。内存限制：4 MB。

## 输入

一段文本。

## 输出

压缩包。

## 评测方式

Timus 会编译压缩包，并把它的输出与原文比较。我们的检查程序无法编译 C++，所以只接受这些解法输出的
那一种格式（见下文），并自行执行这种格式：检查固定的行，解码字符串和代码表，再与输入比较。对于至少
20 000 个字符的输入，还要检查压缩包更短。较短的样例仅免除长度检查。

## 样例

### 样例 1

输入：

```
123456789101112131415161718192021222324252627282930313233343536373839404142434445464748495051525354555657
```

输出：

```
//CPP
#include <cstdio>
const char *d[] = {
"123456789101112131415161718192021222324252627282930313233343536373839404142434445464748495051525354555657\n",
0};
int main() {
    const char *t[256] = {0};
    for (int k = 0; d[k]; k++)
        for (const char *p = d[k]; *p; p++)
            if (t[(unsigned char)*p]) fputs(t[(unsigned char)*p], stdout);
            else putchar(*p);
    return 0;
}
```

## 解法

压缩包是一个包裹着文本的小 C++ 程序，文本存放在字符串字面量中，节省的长度必须超过程序本身的开销
（几百个字符，外加每个代码一行）。

英文会重复“ the ”、“and”、“th”、“e ”等短片段，也会重复整个单词。文学文本通常会留下一些未使用的
可打印字符，比如 `#`、`$`、`@`、`~`。编码器将常见片段和至多 300 个单词变体（带前导空格和不带两种）
按预计节省排序。若替换某片段的不重叠出现所节省的长度超过其代码表一行开销的保守估计，就分配下一个
未使用的可打印字符。

候选只含文本中出现过的字符，而代码在文本中没有出现，所以后续替换不会吞掉先前的代码，解码只需一遍，
没有嵌套。

于是压缩包包含：

- 存放编码后文本的字符串字面量，每个至多 1000 个编码后的字符，这样不会碰到编译器对字面量长度的限制；
- 已用代码的表 `t[code] = "piece";`；
- 一个循环：遇到代码就输出 `t[c]`，否则输出 `c` 本身。

字面量中要转义 `"`、`\` 和 `?`（后者是为了不出现 `??` 三字符组），没有代码的换行符写成 `\n`。输入中的
回车符被丢弃，将 CRLF 转为 LF。

在我们的非样例测试文本上，压缩包约为输入的 26.3–61.3 %。

注意事项：

- 4 MB 并不多：每个字符一个字符串对象可能超限。C++、Go、Java 和 Rust 在原地编码，Python 替换字符串。
  五种解答都分块写出输出；
- 这些压缩包用 g++ 编译运行过，准确地还原了测试文本，包括反斜杠和问号。

## 各语言说明

- 五种语言输出逐字节相同的压缩包，无论编码器用什么语言写成，压缩包的第一行都是 `//CPP`。
- 内存限制是 4 MB。Go 和 Java 只把单词的起点存进数组（单词一直延伸到字母结束），数组大小由先行的计数遍历确定，
  只有选中的 300 个单词才变成字符串。Go 还调低了垃圾回收的阈值；Java 用自己写的堆排序和匿名类排序，因为
  对象形式的二元组、`TimSort` 的缓冲区和 lambda 机制都会让它超出限制。
