# 1307. Архиватор

[Timus 1307](https://acm.timus.ru/problem.aspx?space=1&num=1307) · сложность 1275 · strings

## Задача

На вход подаётся отрывок английской литературы длиной от 20 000 до
200 000 символов. Нужно вывести его «архив»: программу на Pascal, C
или C++, первая строка которой — `{PAS}`, `/*C*/` или `//CPP` — задаёт
язык, которая после компиляции и запуска печатает в точности исходный
текст и которая строго короче этого текста.

Ограничение времени: 1 секунда. Ограничение памяти: 4 МБ.

## Входные данные

Текст.

## Выходные данные

Архив.

## Проверка

Timus компилирует архив и сравнивает напечатанное с текстом. Наша
проверяющая программа не умеет компилировать C++, поэтому принимает
только архивы того единственного вида, который печатают эти решения
(показан ниже), и исполняет этот вид сама: проверяет неизменные строки,
расшифровывает строки и таблицу и сравнивает результат с входом. Для
входов длиной не меньше 20 000 символов она проверяет и то, что архив
короче. Для более короткого примера отменена только проверка размера.

## Примеры

### Пример 1

Ввод:

```
123456789101112131415161718192021222324252627282930313233343536373839404142434445464748495051525354555657
```

Вывод:

```
//CPP
#include <cstdio>
const char *d[] = {
"123456789101112131415161718192021222324252627282930313233343536373839404142434445464748495051525354555657\n",
0};
int main() {
    const char *t[256] = {0};
    for (int k = 0; d[k]; k++)
        for (const char *p = d[k]; *p; p++)
            if (t[(unsigned char)*p]) fputs(t[(unsigned char)*p], stdout);
            else putchar(*p);
    return 0;
}
```

## Решение

Архив — это небольшая программа на C++ вокруг текста, записанного в
строковые литералы, и экономия должна превысить стоимость программы
(несколько сотен символов плюс строка на каждый код).

В английском повторяются короткие куски вроде « the », «and», «th»,
«e », а также целые слова. Литературный текст обычно оставляет некоторые
печатные символы неиспользованными, например `#`, `$`, `@` или `~`.
Кодировщик упорядочивает частые куски и до 300 вариантов слов, с пробелом
перед ними и без него, по ожидаемой экономии. Кусок получает следующий
неиспользованный печатный символ, если замена неперекрывающихся вхождений
экономит больше консервативной оценки стоимости строки таблицы.

Кандидаты содержат только символы из текста, а коды в нём отсутствуют,
поэтому поздние замены не поглощают ранее выданные коды, и расшифровка —
один проход без вложенности.

Архив содержит:

- закодированный текст в строковых литералах не более чем по 1000
  кодированных символов, чтобы не упереться в ограничение компилятора
  на длину литерала;
- таблицу `t[code] = "piece";` для использованных кодов;
- цикл, который печатает `t[c]` для кода и сам `c` иначе.

`"`, `\` и `?` экранируются в литералах (последний — чтобы не возникло
триграфа `??`), а переводы строк без кода записываются как `\n`.
Возвраты каретки из входа выбрасываются, превращая CRLF в LF.

На наших тестовых текстах, кроме примера, архив занимает примерно
26,3–61,3 % входа.

Тонкие места:

- 4 МБ — это немного: строка-объект на каждый символ может превысить лимит.
  C++, Go, Java и Rust кодируют текст на месте, Python заменяет строки.
  Все пять решений записывают вывод кусками;
- архивы компилировались g++ и запускались, и они в точности
  воспроизвели тестовые тексты, включая обратные косые черты и
  вопросительные знаки.

## Особенности языков

- Все пять языков печатают байт в байт один и тот же архив, и его
  первая строка — `//CPP`, на каком бы языке ни был кодировщик.
- Лимит памяти 4 МБ. Go и Java хранят слово только как его начало (оно
  тянется до конца букв) в массиве, размер которого известен после
  первого прохода-подсчёта, и превращают в строки только 300 выбранных
  слов. Go вдобавок снижает порог сборщика мусора, а Java сортирует своей
  пирамидальной сортировкой с анонимными классами: пары-объекты, буфер
  `TimSort` и механизм лямбд выводили её за лимит.
