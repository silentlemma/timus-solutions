# 1318. Логарифм

[Timus 1318](https://acm.timus.ru/problem.aspx?space=1&num=1318) · сложность 1394 · bitmask

Идея оригинальной задачи — Никита Шамгунов, подготовили Никита Шамгунов и Антон Ботов; VIII командный студенческий чемпионат Урала по программированию, Екатеринбург, 11–16 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны N ≤ 5000 чисел A₀, …, A_{N−1} по 128 бит. Нужно вычислить сумму
⌊log₁₀(A_k xor A_j)⌋ по всем упорядоченным парам k, j от 0 до N − 1,
считая логарифм нуля равным 0.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

В первой строке N. В каждой из следующих N строк четыре числа от 0 до
2³² − 1 — 32-битные слова A_k от старшего к младшему:
A_k = 2⁹⁶ · a₁ + 2⁶⁴ · a₂ + 2³² · a₃ + a₄.

## Выходные данные

Сумма.

## Примеры

### Пример 1

Ввод:

```
2
0 0 0 2324
0 2332 0 0
```

Вывод:

```
44
```

## Решение

⌊log₁₀ x⌋ — это количество степеней 10¹, 10², …, не превосходящих x.
Степень десяти, в которой меньше битов, чем в x, всегда меньше x, а
поскольку 10 > 2, ровно столько же битов, сколько в x, имеет не больше
одной степени. Поэтому таблица по длине в битах L даёт число более
коротких степеней, а единственная степень длины L, если она есть,
требует одного сравнения. Каждая пара k < j стоит одного xor, одной
длины в битах и не более одного сравнения, а сумма по упорядоченным
парам вдвое больше суммы по k < j, поскольку диагональ даёт 0.
`O(N²)`, около 12.5 миллиона пар.

Тонкие места:

- пары упорядоченные, поэтому в примере 22 считается дважды (тест 01);
- у xor, равного ровно 10³⁸, логарифм 38, а у 10³⁸ − 1 — 37 (тест 06),
  и у наибольшего xor 2¹²⁸ − 1 он всё ещё 38 (тест 05);
- слова нужно читать как беззнаковые: 4 294 967 295 не помещается в
  знаковое 32-битное целое;
- сумма может дойти до 5000 · 4999 · 38 ≈ 9.5 · 10⁸, что ещё
  помещается в 32 бита, но 64-битный счётчик ничего не стоит.

## Особенности языков

- C++ и Rust используют встроенное 128-битное целое; Go и Java хранят
  число как две 64-битные половины и сравнивают их как беззнаковые.
- В Python 12.5 миллиона пар заняли бы несколько секунд, поэтому он
  работает с отсортированными числами. В диапазоне с общими битами
  выше некоторого бита t у всех пар через разрез по t старший бит xor —
  это t, так что более короткие степени у них общие. Если у степени
  десяти старший бит t, пары, которые до неё дотягиваются, считаются
  спуском по обеим половинам бит за битом, как по двоичному бору, а
  совсем маленькие группы проверяются попарно. Это занимает около
  0.2 секунды, и результаты сравнивались с прямой суммой по всем парам
  на 800 небольших случайных наборах.
