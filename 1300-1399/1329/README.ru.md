# 1329. Галактическая история

[Timus 1329](https://acm.timus.ru/problem.aspx?space=1&num=1329) · сложность 453 · dfs

Автор оригинальной задачи — Евгений Крохалев; X командный чемпионат школьников Свердловской области по программированию, 16 октября 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

До 40 000 вех истории образуют корневое дерево; у каждой есть номер от
0 до 40 000 и номер её отца, −1 у корня. Нужно ответить не более чем на 40 000
вопросов о двух различных вехах A и B: 1, если A — предок B, 2, если B
— предок A, и 0 иначе.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N, затем N строк с вехой и её отцом, затем L и L строк с A и B.

## Выходные данные

По одному ответу в строке.

## Примеры

### Пример 1

Ввод:

```
10
234 -1
12 234
13 234
14 234
15 234
16 234
17 234
18 234
19 234
233 19
5
234 233
233 12
233 13
233 15
233 19
```

Вывод:

```
1
0
0
0
2
```

## Решение

Обойдём дерево в глубину и отметим у каждой вехи время входа в неё и
время выхода из всего её поддерева. A — предок B ровно тогда, когда в B
входят, пока A ещё открыта: enter[A] ≤ enter[B] < leave[A]. Каждый
вопрос — это до двух проверок интервалов. `O(N + L)`.

Обход идёт с явным стеком. После извлечения вехи в стек кладётся её
дополнение ~v, а затем дети; дополнение отмечает конец обхода поддерева.
Это важно, потому что дерево может быть цепочкой из 40 000 вех, слишком
глубокой для рекурсии в некоторых языках.

Тонкие места:

- вехи идут в любом порядке, дети раньше отцов (тест 03);
- веха 0 существует, поэтому отметка выхода не может быть −v; ~v = −v − 1
  годится и для 0 (тест 03);
- цепочка из 40 000 (тест gen2);
- вехи с общим отцом и вехи из соседних ветвей не являются предками
  друг друга (тест 05).

Ответы сравнивались с подъёмом по отцам на 300 случайных деревьях до 12
вех.

## Оптимизированные решения

Новые C++, Go и Rust сохраняют DFS-интервалы входа/выхода, но хранят по пять 16-битных полей на возможный номер: родителя, первого ребёнка, следующего брата, вход и выход. Номера и часы не превышают 40000, поэтому 65535 — отдельный маркер, не конфликтующий с вершиной 0. Таблица из U=40001 записей занимает 400010 байтов полей. После входа спускаемся к первому ребёнку; завершив поддерево, идём к брату либо поднимаемся по родителям до доступного брата. Каждое ребро проходится не более двух раз, без рекурсии и стека событий. Сначала читаем все рёбра: дети могут идти раньше родителей. Инициализация занимает O(U), обход и запросы — O(N+L). C++ использует ограниченный C stdio ввод, Go — буферы стандартных дескрипторов; Rust дополнительно сохраняет текст ввода. Простые файлы сохранены; Java/Python повторно используют подходящие базы.

Принятая версия Rust 1.75 x64 заняла 0.062 с при 0.046 с у базовой и использовала 2 116 KB при 5376 KB у базовой.

Принятые базовые реализации [1329_dfs.java](1329_dfs.java), [1329_dfs.py](1329_dfs.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

Эти замечания относятся к базовым реализациям.

- Java читает ввод через собственный байтовый буфер, потому что

  заметно медленнее.
