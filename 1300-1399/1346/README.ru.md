# 1346. Интервалы монотонности

[Timus 1346](https://acm.timus.ru/problem.aspx?space=1&num=1346) · сложность 297 · greedy

Автор оригинальной задачи — Александр Клепинин; USU Championship 2004.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Функция F задана на целочисленной сетке A, A + 1, …, B, где
0 ≤ A < B ≤ 100 000, а целые значения от −100 000 до 100 000. Нужно разбить
сетку на наименьшее число интервалов, на каждом из которых F не убывает
или не возрастает, и вывести их количество.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

A и B, затем целые значения F(A), …, F(B) через пробелы или переводы строк.

## Выходные данные

Наименьшее число интервалов.

## Проверка

Сравнение токенов (`judging: tokens`): одно целое — минимальное число
непересекающихся монотонных интервалов точек сетки. Границы и само
разбиение не требуются; пробельные разделители несущественны.

## Примеры

### Пример 1

Ввод:

```
1 10
1 2 3 4 2 1 -1 3 6 7
```

Вывод:

```
3
```

## Решение

Интервалы разбивают точки сетки, так что шаг между последней точкой
одного интервала и первой точкой следующего свободен. Любая часть
монотонного интервала снова монотонна. Поэтому делать первый интервал
как можно длиннее никогда не вредно, и то же верно для каждого
следующего: жадный подсчёт даёт наименьшее число.

Интервал растягивается, пока остаётся монотонным. Его направление
задаёт первый неплоский шаг, а плоские шаги подходят к любому
направлению. Первый шаг против этого направления заканчивает интервал,
и следующий начинается со следующей точки. `O(B − A)`.

Тонкие места:

- шаг между двумя интервалами свободен: для 1 3 2 4 хватает 2
  интервалов, 1 3 и 2 4 (тест 02);
- плоские шаги входят в интервал, куда бы он ни шёл, а постоянная
  функция — это один интервал (тесты 03, 05 и 06);
- значения могут идти в нескольких строках.

Ответы сравнивались с динамическим программированием по всем
разбиениям на 500 случайных функциях до 12 точек.

## Оптимизированные решения

`1346_greedy_optimized.cpp`. Сохраняется жадный проход по монотонности. При смене ненулевого направления начинается новый интервал с неизвестным направлением: переходный шаг не принадлежит ни одному интервалу. Равные значения направления не задают. Хранятся лишь предыдущее значение, направление и счётчик: O(B-A+1) времени и O(1) дополнительной памяти. Форматированный ввод заменён fread-буфером 16384 байта с одним сторожевым байтом; знак и незаконченные цифры переносятся между заполнениями, EOF не вызывает зацикливания на пустом вводе. Счётчик выводится десятичными байтами. Общий сканер проверен с обоими размерами буфера, AddressSanitizer/UndefinedBehaviorSanitizer и 100019 значениями на размер. Понятный учебный исходник сохранён.

C++ #11327408 `0.015 с / 92 КБ` проходит с местом 1/71 по времени
по общим [критериям](../../RATING_CRITERIA.md): при памяти меньше
1024 КБ учитывается только время, отдельной цели C++ нет. Прежний
#11310334 `0.031 с / 84 КБ` остаётся отдельной исторической парой.

- `1346_greedy_optimized.cpp`: 0.015 s / 92 KB; сохранённая учебная база `1346_greedy.cpp`: 0.062 s / 588 KB.

Историческое сравнение прежней ревизии: Версии на C++ и Go сохраняют жадный проход и обрабатывают каждое значение сразу при чтении. В памяти остаются предыдущее значение, направление текущего интервала и число интервалов. Буфер ввода фиксированного размера, поэтому время составляет O(B − A + 1), а дополнительная память — O(1). Принятая версия C++ заняла 0,031 с и 84 КБ, базовая — 0,062 с и 588 КБ. Go использовал 1588 КБ вместо 2512 КБ при тех же 0,031 с.

Java использует базу: при 900 КБ сравнивается только время, место
2/28. Python проходит потоковым файлом `0.109 с / 724 КБ`, а не
базой `0.140 с / 11140 КБ`: шесть точных соперников CPython дают
третий эталон с пределом времени 0.12535 с. Rust проходит нативным
файлом `0.015 с / 56 КБ`, а не базой с 2632 КБ, которая превышает
предел памяти 2047 КБ. Один точный соперник Rust даёт предел времени
0.031 с. Подходящие базы не копируются; учебные версии сохраняются.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1346_greedy_optimized.py`. Последовательность обрабатывается поточно: хранятся только предыдущее значение, направление и число интервалов. Равные значения не задают направление, смена направления начинает новый интервал. Время линейное, состояние алгоритма постоянное. Самостоятельная программа сбрасывает оба выходных потока перед os._exit(0), чтобы после записи полного ответа не выполнять завершение интерпретатора. Это изменение завершения процесса, а не математического алгоритма; простая версия сохранена.

Accepted #11328773 (Python 3.12 x64): **0.109 s / 724 KB**. Архивное сравнение: `1346_greedy.py` (Python 3.12 x64) — 0.14 s / 11140 KB (#11285126).

`1346_implementation_parsing_optimized.rs` сохраняет потоковый
жадный проход. NativeNumbers разбирает знаковые i64 через пополняемый
буфер 4096 байтов. NativeOutput пишет беззнаковое число интервалов
через массив цифр на 20 байтов и буфер 256 байтов, затем полностью
сбрасывает вывод с переводом строки. В Windows используются _read/
_write среды C и двоичный режим, на других платформах — read/write.
Знакового числового вывода и универсального форматирования нет.
Время O(B-A+1), постоянное состояние и ограниченные буферы.

Для этого точного исходника получен собственный Accepted и выполнены единые [рейтинговые критерии](../../RATING_CRITERIA.md). Время и память ниже взяты из одной посылки; повторные измерения судьи могут различаться. Существующие простые и отличающиеся оптимизированные версии сохранены.

Accepted #11329367 (Rust 1.75 x64): **0.015 s / 56 KB**.
