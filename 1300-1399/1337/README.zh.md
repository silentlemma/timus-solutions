# 1337. 官僚主义

[Timus 1337](https://acm.timus.ru/problem.aspx?space=1&num=1337) · 难度 1532 · graphs

原题作者 Anatoly Uglov 和 Evgeny Krokhalev，出自 2004 年 10 月 16 日第十届斯维尔德洛夫斯克州中学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

N ≤ 100 名官员各自签发一种文件，每人在一周（共 L ≤ 100 天）中的某一天接待；几名官员可以在同一天接待。办一份文件要花一整天，
所以每天最多办一份，而且只发给已持有某些其他文件的人。今天是一周中的第 K 天，今天也可以用。已知手头的文件和需要的文件，
求今天之后办齐所需的最少天数，以及按办理顺序列出的文件；若办不到，输出 `No Solution`。若有多个同样快的顺序，输出任意一个即可。

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 L；每名官员的接待日；N 个列表，给出办每种文件需要的文件，各以 0 结尾；K；手头文件的列表，以 0 结尾；
需要文件的列表，以 0 结尾。

## 输出

天数，然后是按办理顺序排列的文件，或 `No Solution`。

## 样例

### 样例 1

输入：

```
2 7
1 2
0
1 0
1
1 0
2 0
```

输出：

```
1
2
```

## 解法

先找出必须办的文件：手头没有的需要文件，以及它们各自需要而手头也没有的文件，依此类推。手头已有的文件会截断
搜索，因为它当初需要什么已经无关紧要。若这些文件互相需要构成环，环上没有一份能先办，答案就是
`No Solution`；用拓扑排序即可判断。

把今天记为第 0 天。一个方案就是文件的一个顺序：每份文件在其所需文件办完之后、其官员的第一个空闲接待日办理。
在某天能办某份文件时，办理总没有坏处，因为把该文件之后的办理提前到这一天只会空出一天。所以唯一的选择是：
在第一个可用的日子里，从已就绪的文件中办哪一份，而它们都属于在这一天接待的官员。若没有两名官员同一天接待，
方案是确定的；否则优先办其后等待链最长的文件是个好的猜测，但并不总是对的（测试 11）。

答案用分支限界在这个选择上搜索：

- 最长链规则给出第一个方案，并在搜索的每个节点重新运行，以改进已找到的最好方案；
- 用下界剪枝：每份剩余文件的最早日期由其所需文件推出；对每个星期几，不能早于第 r 天的 k 份文件要占用从 r
  起的 k 个这样的日子，而其中最后一份之后还有最短的等待链；
- 手头文件的集合若已在相同或更早的日子到达过，就不再搜索。

最坏情况下搜索是指数级的。在 100 名官员共用只有几天的一周的随机例子上，通常不到一秒就结束，但个别例子要久得多。
结果已在 1000 个最多 14 份文件、有共用接待日的随机例子上与对所有待办文件子集的动态规划对照。

注意事项：

- 几名官员可以同一天接待，而一天只能办一份文件，所以顺序很重要（测试 09）；
- 今天是第 0 天且可以使用：官员今天接待的文件只需 0 天（测试 04）；
- 若需要的都已在手，答案是 0 和一个空行（测试 02 和 06）；
- 所需文件中的环可能被手头已有的文件打断（测试 07），只有尚未办理的文件之间的环才会使任务无法完成（测试 03）。
