# 1337. Бюрократия

[Timus 1337](https://acm.timus.ru/problem.aspx?space=1&num=1337) · сложность 1532 · graphs

Авторы оригинальной задачи — Анатолий Углов и Евгений Крохалев; X командный чемпионат школьников Свердловской области по программированию, 16 октября 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N ≤ 100 чиновников выдают каждый свой вид документов и принимают в
один день недели из L ≤ 100 дней; несколько чиновников могут принимать
в один день. Получение документа занимает весь день, так что за день
получается не больше одного документа, и выдают его только тому, у кого
уже есть определённый набор других документов. Сегодня K-й день недели,
и сегодняшний день тоже можно использовать. По документам на руках и
нужным документам требуется найти наименьшее число дней после
сегодняшнего, за которое можно получить их все, и документы в порядке
получения, или вывести `No Solution`. Если одинаково быстрых порядков
несколько, подходит любой.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и L; приёмный день каждого чиновника; N списков документов, нужных
для каждого, каждый заканчивается 0; K; список документов на руках,
заканчивается 0; список нужных документов, заканчивается 0.

## Выходные данные

Число дней, затем документы в порядке получения, или `No Solution`.

## Примеры

### Пример 1

Ввод:

```
2 7
1 2
0
1 0
1
1 0
2 0
```

Вывод:

```
1
2
```

## Решение

Сначала найдём, что придётся получить: нужные документы, которых нет на
руках, а за каждым из них — требуемые для него бумаги, которых тоже нет
на руках, и так далее. Бумага на руках обрывает поиск, потому что то,
что было нужно для неё, больше не важно. Если эти документы требуют друг
друга по циклу, ни один из цикла не может быть получен первым, и ответ
`No Solution`; это выясняет топологическая сортировка.

Пронумеруем дни от сегодняшнего, это день 0. План — это порядок
документов: каждый получается в первый свободный приёмный день своего
чиновника после нужных ему бумаг. В день, когда какой-то документ можно
получить, получить его никогда не вредно: перенос его более позднего
получения на этот день только освобождает день. Поэтому выбор один —
какой из документов, готовых к первому подходящему дню, взять, и все
они принадлежат чиновникам этого дня недели. Если никакие два чиновника
не принимают в один день, план вынужден; иначе брать документ с самой
длинной цепочкой ожидания за ним — хорошая догадка, но не всегда верная (тест 11).

Ответ находит метод ветвей и границ по этому выбору:

- правило самой длинной цепочки даёт первый план и перезапускается из
  каждого узла поиска, улучшая лучший найденный план;
- узел отсекается нижней оценкой: самый ранний день каждого оставшегося
  документа следует из нужных ему бумаг, а для каждого дня недели k
  документов, которые не могут прийтись раньше дня r, занимают k таких
  дней начиная с r, и у последнего из них впереди ещё самая короткая
  цепочка ожидания;
- набор документов на руках, к которому уже приходили в тот же или
  более ранний день, повторно не перебирается.

В худшем случае перебор экспоненциальный. На случайных примерах со 100
чиновниками, делящими неделю из нескольких дней, он обычно заканчивается
за доли секунды, но редкие примеры идут гораздо дольше. Результаты
сверены с динамикой по всем подмножествам документов, которые надо
получить, на 1000 случайных примерах до 14 документов с общими днями.

Тонкие места:

- несколько чиновников могут принимать в один день, а получить можно
  только один документ, так что порядок важен (тест 09);
- сегодня — день 0, и его можно использовать: документ, чиновник
  которого принимает сегодня, занимает 0 дней (тест 04);
- если всё нужное уже на руках, ответ 0 и пустая строка (тесты 02 и 06);
- цикл среди нужных бумаг может разорвать бумага на руках (тест 07), и
  задачу делает невыполнимой только цикл среди ещё не полученных
  документов (тест 03).

## Особенности языков

- Набор документов на руках — целое число в Python, два 64-битных слова
  в C++, Go и Rust и список из двух long в Java; он служит ключом
  словаря.
