# 1394. 舰船（第二版）

[Timus 1394](https://acm.timus.ru/problem.aspx?space=1&num=1394) · 难度 14802 · backtracking

原题由 Vladimir Yakovlev 准备。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

与[题目 1115](../../1100-1199/1115/README.zh.md) 相同，但测试难得多：N < 100
艘舰船（长度为 1 到 100 的整数）要恰好填满 1 < M < 10 个给定长度的行，每行至少一艘。
保证存在排法，输出任意一种。评测最多保留 20 个测试，每个都针对某类启发式，
但没有一个测试是为了击败所有启发式。

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 M，然后 N 行舰船长度，再 M 行各行长度。

## 输出

按输入顺序对每一行输出两行：该行舰船数和它们的长度。

## 样例

### 样例 1

输入:

```
5 2
4
10
2
5
3
11
13
```

输出:

```
3
5 4 2
2
10 3
```

## 解法

一般情况下的精确多路划分很难，而评测的测试专门挑来击败单一启发式。

回溯按五个时段轮流运行三种精确搜索：B、行按长度升序的 B、C、D，再一次 B。
时间片按 1.6 倍增长至上限，后面几轮稍微打乱顺序，直到某个搜索放好所有船或耗尽内部预算。

- B，逐行填充。船按长度从大到小；在一行内每艘船或取或跳过，被跳过长度
  的所有副本一起跳过。每个未完成的行必须仍是未用船的子集和（后缀和的
  位集，在开新行时重算）。失败的状态——未用的船加上未完成的行——放进一个
  在重启之间保留的哈希表，因为它与顺序无关。每隔一个 B 时段还会对 D 的
  模数及小模数做余数检查。
- C，只对稀有长度（一到三个副本）做 B：这时一行只需要一个常见船能凑出的
  余量，常见船最后由嵌套的 B 放置。这样就不必枚举用常见船填行的大量等价
  方式。
- D，即 C，但“稀有”指不能被模数 K 整除，K 能整除很多船；再加上精确的
  余数检查：每个余数类剩下的非倍数船必须分给剩下的行，使每行得到自己长度
  模 K 的余数。由对行和计数向量（混合进制）的 DP 回答，每次查询有预算，
  缓存在重启之间保留。

三种都需要：没有 C 时评测第 8 个测试超时，没有 D 时第 10 个测试超时，B 若占四个时段中的两个
而不是五个中的三个，第 7 个测试超时。第四种搜索（逐艘船放进行里）不需要。

S 为舰船总长度。

易错点：

- 论坛测试 70 中的舰队有一行长 820，简单的重启 20 秒内什么也找不到
  （测试 03）；论坛测试 80 对其他顺序很难（测试 04）；
- 余数谜题：几乎所有船都是某个 k 的倍数，每行一艘特殊船，其余数限制行的
  分配（生成测试 7 和 8）；
- 只有逐行搜索 B 能解、且只在幸运的顺序下才能解，而 C 和 D 都失败的舰队
  （测试 14 和 15）；
- 各行必须按输入顺序输出。

排法在这里的所有测试、130 个困难舰队和 11 000 个生成的舰队（其中 6 000 个各行等长）上
都通过了检查器：回溯分别不超过 0.55 秒和 0.08 秒，
分别对应困难舰队和生成的舰队。

## 各语言说明

- Python 的回溯在评测第 7 个测试上超时，四个版本各有不同的主搜索，都是如此，因此这里没有 Python 解法。
- 回溯的 Java 需要更贴近的移植才能在 1 秒内通过评测第 8 个测试：行内跳过的分支用循环而不是尾调用，下标用移位和掩码。
