# 1397. 点的游戏

[Timus 1397](https://acm.timus.ru/problem.aspx?space=1&num=1397) · 难度 1642 · geometry, games, greedy

原题作者 Michael Medvedev，出自 2006 年全乌克兰大学生程序设计公开赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

平面上有 2n 个点，n ≤ 500。两名玩家轮流给点染色，先手染白、后手染黑，直到
各染 n 个点。玩家的得分是其颜色的所有点对之间距离之和。双方都采取最优策略
时，输出胜者与败者得分之差，保留小数点后三位。输入包含多局游戏。

时间限制：1 秒。内存限制：64 MB。

## 输入

各局依次给出：n，然后 2n 行点的坐标。

## 输出

每局的得分差。

## 样例

### 样例 1

输入:

```
2
0 0
0 1
1 0
1 1
2
0 0
1 0
0 3
1 5
```

输出:

```
0.000
1.937
```

## 解法

设 Dᵢ 为点 i 到其他所有点的距离之和。对白点求和时，每对白点算两次，每对异
色点算一次：ΣW Dᵢ = 2·WW + WB，同理 ΣB Dᵢ = 2·BB + WB。因此得分差为

WW − BB = (ΣW Dᵢ − ΣB Dᵢ) / 2，

游戏只是把每个点的固定值加起来。于是每位玩家都应取剩余 Dᵢ 最大的点：把 Dᵢ
降序排序，先手得到下标 0、2、4、… 上的值，答案是交替和的一半。每局计算距离 `O(n²)`。

注意事项：

- 输入有多局，一直到文件结束；
- 答案非负；代码输出其绝对值；
- 在 Java 中，每局至多 499 500 对距离时 Math.hypot 比 Math.sqrt 慢得多。

在 200 局至多 8 个点的随机游戏上，与对所有染色方式的完整极小极大搜索做了比
较。
