# 1348. Пусти козла в огород 2

[Timus 1348](https://acm.timus.ru/problem.aspx?space=1&num=1348) · сложность 177 · geometry

Автор оригинальной задачи — Павел Егоров; чемпионат школьников, март 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Козёл привязан к точке C верёвкой длины L, так что достаёт всё, что не
дальше L от C. Грядка ананасов — отрезок AB. Нужно найти, на сколько
нужно удлинить верёвку, чтобы достать хотя бы один ананас, и на сколько
— чтобы достать все, с двумя знаками после точки. Все числа целые,
L ≥ 0, а координаты по модулю не больше 10 000.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Координаты A, B и C и длина L.

## Выходные данные

Два удлинения, по одному в строке.

## Проверка

Тесты репозитория сравнивают числовые токены по условию |ответ-эталон| <= 0.01·max(1,|эталон|), отклоняют бесконечности и NaN, а нечисловые токены сравнивают точно.

## Примеры

### Пример 1

Ввод:

```
8 -6 8 6
0 0 7
```

Вывод:

```
1.00
3.00
```

## Решение

Ближайшая точка грядки — проекция C на прямую AB, перенесённая в A или
B, если она выпала за отрезок. Самая дальняя точка отрезка от любой
точки — один из его концов. Значит, ответы — max(0, d_ближ − L) и
max(0, max(|CA|, |CB|) − L). Проекция использует
t = (C − A) · (B − A) / |B − A|², ограниченное отрезком от 0 до 1, а для
грядки из одной точки, A = B, берётся t = 0.

Верхней границы для L нет, поэтому L читается как вещественное число, а
не как целое, которое переполнилось бы. Огромное L превращается в
огромное число или в бесконечность, и тогда оба ответа равны 0, что
верно: любое расстояние не больше 20000√2 < 30000. Геометрия занимает
`O(1)` времени; с учётом ввода время и память — `O(k)`, где k — число
символов ввода.

Тонкие места:

- грядка может быть одной точкой (тесты 02 и 08);
- если C лежит на прямой грядки за концом, ближайшая точка — этот конец,
  а не проекция (тест 04);
- если верёвки уже хватает, нужно 0, а не отрицательное число
  (тест 05);
- L может выходить за диапазоны целых и вещественных типов (тесты
  09–11): как вещественное число оно становится бесконечностью, и оба
  ответа равны 0, а целый тип переполнился бы.

## Оптимизированные решения

`1348_geometry_optimized.rs`. Сохраняются ограниченная проекция на отрезок, дальний конец и max(distance-rope,0). Текстовый разбор входа и форматирование Rust заменены scanf семи f64 и printf двух ответов с двумя знаками. Вырожденный отрезок использует свой конец, бесконечная разобранная длина верёвки даёт нулевые удлинения. Геометрия требует O(1) операций и явно хранимых данных; чтение токена длины верёвки из k символов занимает O(k) времени. Выигрыш памяти подтверждён собственным Accepted.

По сравнению с `1348_geometry.rs`: время 0.031 s → 0.031 s; память 244 KB → 116 KB.

`1348_geometry_optimized.cpp`. Сохраняются проекция на отрезок с ограничением параметра [0,1] и выбор более далёкого конца для максимального расстояния. C scanf/printf заменяют потоки C++ и явную строку токена длины верёвки. Геометрия остаётся в f64; если верёвка разобрана как положительная бесконечность, обе требуемые добавки нулевые. Чтение записи длины k требует O(k), явное состояние геометрии постоянно.

По сравнению с `1348_geometry.cpp`: время 0.015 s → 0.015 s; память 396 KB → 144 KB.

`1348_geometry_optimized.java`. Сохраняется та же геометрия проекции с ограничением и расстояний до концов. Ограниченный байтовый буфер заменяет Scanner; неограниченный токен длины верёвки по-прежнему декодируется и передаётся в Double.parseDouble. Бесконечность правильно даёт две нулевые добавки. Убираются расходы Scanner, но для записи верёвки произвольной длины не заявляется постоянная память: время и хранение токена O(k).

По сравнению с `1348_geometry.java`: время 0.140 s → 0.109 s; память 1856 KB → 1 072 KB.
