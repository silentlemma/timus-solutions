# 1314. Погоня в метро

[Timus 1314](https://acm.timus.ru/problem.aspx?space=1&num=1314) · сложность 561 · bfs

Идея оригинальной задачи — Леонид Волков, подготовили Александр Сомов, Леонид Волков и Игорь Гольдберг; VIII командный студенческий чемпионат Урала по программированию, Екатеринбург, 11–16 марта 2004 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В метро до 50 линий по 2–50 станций; станция — число до 32 767, и
станция, встречающаяся на нескольких линиях (или несколько раз на
одной), — это одно место, где они пересекаются. Беглец входит на первой
из M станций, записанных маяком, и едет к выбранной цели по кратчайшему
маршруту, считая только перегоны. Маяк записывает по порядку все
станции на пути. Нужно вывести по возрастанию все станции, которые
могут быть целью.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N; N строк, в каждой K и затем K станций; затем M и M записанных
станций.

## Выходные данные

Возможные цели по одной в строке.

## Примеры

### Пример 1

Ввод:

```
3
2 61 62
5 75 20 85 50 61
3 10 20 30
3 30 20 85
```

Вывод:

```
50
61
62
85
```

## Решение

Соединим соседние станции каждой линии ребром. Пусть s — первая
записанная станция, e — последняя, а d — расстояние в перегонах.
Беглец едет по кратчайшему маршруту из s в цель t, и запись — его
начало, поэтому:

- запись должна быть путём по рёбрам и сама кратчайшим маршрутом,
  d(s, e) = M − 1;
- t может быть целью ровно тогда, когда кратчайший маршрут из s в t
  проходит через e, то есть d(s, t) = d(s, e) + d(e, t).

Два поиска в ширину, из s и из e, дают все расстояния. `O(V + E)` для
станций и рёбер, каждых не больше 2500; Python тратит `O(V log V + E)`
из-за сортировки целей.

Условие обещает согласованную запись. Если это не так (неизвестная
станция, две несоседние станции или крюк), ни одна цель не подходит, и
ничего не выводится.

Тонкие места:

- сама e тоже цель, ведь поездка может закончиться прямо здесь
  (тест 01);
- при одной записанной станции подходит каждая достижимая из неё
  станция (тесты 02 и 07);
- запись из двух несоседних станций не подходит ни к чему (тест 04);
- станция дальше по линии не подходит, если до неё быстрее добраться
  по короткому пути (тест 05).

Ответы сравнивались с перечислением всех кратчайших маршрутов из s на
400 небольших случайных сетях.

## Оптимизированные решения

Сжимаем номера станций в отсортированном порядке и храним списки смежности в одном массиве.
Один BFS от первой записанной станции строит слои расстояний. Проверив записанный маршрут,
отмечаем последнюю станцию и в порядке BFS переносим отметки по рёбрам в следующий слой.
Именно из этих станций может состоять кратчайшее продолжение. Сжатие занимает O((V + E)
log(V + E)) времени, массивы занимают O(V + E) памяти. Посылка 11316949 заняла 0,015 с и использовала 224 КБ. Простая версия заняла 0,015 с и использовала 1256 КБ.

Go сжимает номера станций через битовый набор и хранит смежность и очередь BFS в массивах фиксированного размера. Старший бит каждого расстояния отмечает станции, продолжающие записанный кратчайший путь. Go 1.14 x64, посылка 11322926. Время 0,015 → 0,015 с, память 1844 → 376 КБ.

Rust переводит номера станций в компактные индексы и хранит списки соседей в одном непрерывном массиве. Посылка 11317248 заняла 0,062 с и 320 КБ против 0,046 с и 1532 КБ у базы.

Java хранит компактные индексы станций и ссылки на соседей в массивах коротких целых. Посылка 11317252 заняла 0,109 с и 636 КБ против 0,093 с и 2864 КБ у базы.

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. `1314_bfs_implementation_optimized.rs`. Смежность представлена связанными массивами с 16-битными номерами вершин и знаковыми указателями next/head вместо тысяч отдельных векторов. Расстояния BFS сохранены. Токены читаются через ограниченный нативный байтовый буфер; короткие хранятся внутри объекта, дополнительная память выделяется только длинным. Десятичный разбор сохраняет знаковые границы без хранения всего командного ввода. Точка входа C напрямую вызывает решение и сбрасывает вывод Rust перед возвратом; архивная реализация с обычной точкой входа сохранена.
