# 1314. 地铁追捕

[Timus 1314](https://acm.timus.ru/problem.aspx?space=1&num=1314) · 难度 561 · bfs

原题创意来自 Leonid Volkov，由 Alexander Somov、Leonid Volkov 和 Igor Goldberg 准备，出自 2004 年 3 月 11–16 日在叶卡捷琳堡举行的第八届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

地铁至多有 50 条线路，每条 2 到 50 个站；车站是不超过 32 767 的编号，出现在多条线路上（或在同一条线路
上出现多次）的车站是它们交汇的同一个地点。逃犯从信标记录的 M 个车站中的第一个进站，沿最短路线前往
选定的目的地，路线长度只按经过的区间数计算。信标按顺序记录途经的每个车站。按递增顺序输出所有可能是
目的地的车站。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

N；N 行，每行先是 K，再是 K 个车站；然后是 M 和记录到的 M 个车站。

## 输出

可能的目的地，每行一个。

## 样例

### 样例 1

输入：

```
3
2 61 62
5 75 20 85 50 61
3 10 20 30
3 30 20 85
```

输出：

```
50
61
62
85
```

## 解法

把每条线路上相邻的车站连边。设 s 为第一个记录的车站，e 为最后一个，d 为以区间数计的距离。逃犯沿
最短路线从 s 去目的地 t，而记录是这条路线的开头，因此：

- 记录必须是沿边的路径，并且本身是最短路线，即 d(s, e) = M − 1；
- t 能成为目的地，当且仅当某条从 s 到 t 的最短路线经过 e，即 d(s, t) = d(s, e) + d(e, t)。

从 s 和从 e 各做一次广度优先搜索就得到所有距离。车站和边各不超过 2500 个，复杂度 `O(V + E)`；Python 因排序目的地而需 `O(V log V + E)`。

题目保证记录是一致的。若不一致（未知车站、两个不相邻的车站或绕路），没有目的地符合，什么也不输出。

注意事项：

- e 本身也是目的地，因为行程可能就在这里结束（测试 01）；
- 只记录到一个车站时，从它可达的每个车站都符合（测试 02 和 07）；
- 由两个不相邻车站组成的记录什么也不符合（测试 04）；
- 如果有近路更快到达，线路更远处的车站就不符合（测试 05）。

在 400 个小型随机网络上与列出从 s 出发的全部最短路线的结果比较过。

## 优化解法

按编号排序并压缩站点，将邻接表存入一个连续数组。从记录的第一站执行一次 BFS，得到距离分层。验证记录后，标记最后一站，再按 BFS
顺序沿边把标记传到下一层。恰好只有被标记的站点可作为最短路线的终点。压缩耗时 O((V + E) log(V + E))，数组占用 O(V + E) 空间。提交 11316949 耗时 0.015 秒，使用 224 KB。简单版本耗时 0.015 秒，使用 1256 KB。

Go 用位集合压缩站号，并用定长数组存放邻接表和广搜队列。距离的最高位标记能从已有记录继续沿最短路到达的站点。 Go 1.14 x64（提交 11322926）的运行时间从 0.015 秒变为 0.015 秒，内存从 1844 KB 变为 376 KB。

Rust 版本将车站编号映射为紧凑索引，并用一个连续数组保存邻接站点。提交 11317248 耗时 0.062 秒，使用 320 KB；基础版耗时 0.046 秒，使用 1532 KB。

Java 版本用短整数数组保存紧凑的车站索引和邻接链接。提交 11317252 耗时 0.109 秒，使用 636 KB；基础版耗时 0.093 秒，使用 2864 KB。
