# 1363. 半色调

[Timus 1363](https://acm.timus.ru/problem.aspx?space=1&num=1363) · 难度 4703 · greedy

原题创意来自 Pavel Atnashev，由 Evgeny Krokhalev 准备，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一幅 N × M 像素（75 ≤ N, M ≤ 300）、亮度在 0 到 255 之间的灰度图 A，要打印成黑白图：B 的每个像素为 0 或 255。
对每个像素 (i, j)，取图内满足 |k − i| ≤ 10、|l − j| ≤ 10 的像素 (k, l) 组成的窗口。B − A 在该窗口上的平均值的
绝对值不得超过 20。输出任意一个这样的 B。

时间限制：1 秒。内存限制：64 MB。

## 输入

N 和 M，然后是 N 行，每行 M 个亮度值。

## 输出

N 行，每行 M 个数，每个数为 0 或 255。

## 样例

### 样例 1

输入：

```
3 3
255 255 0
0 0 255
254 0 253
```

输出：

```
255 255 0
0 0 255
255 0 255
```

## 解法

每一行单独取整，沿着这一行传递误差。记 e 为该行已处理像素上 B − A 的和。处理下一个像素时，从 e 中减去它的亮度；
若 e 小于 −127，则输出白色并加上 255。这样每一步 e 都保持在 [−127, 127] 内。行中任意一段的误差是两个这样的和之差：
至多 254；若这一段从该行扫描的起点开始，则至多 127。

窗口有 r ≥ 11 行、c ≥ 11 列，它的误差是各行中对应段的误差之和：

- 远离左右边界的窗口宽 21，每行段误差 254 远小于允许的 20 · 21 = 420；
- 靠近左右边界的窗口可能只有 11 宽，每行只允许 220，小于 254。所以各行按交替方向扫描；这样每隔一行，窗口中的
  段就接触扫描起点，误差至多 127。行数 r ≥ 11 时，⌈r/2⌉ · 254 + ⌊r/2⌋ · 127 ≤ 220 · r。

`O(N · M)`。

注意事项：

- 所有行都从左往右扫描是不够的：宽 97、全为灰度 46 的图在右边界处的窗口平均误差达 22.8（生成测试 2）；
- 样例故意违反尺寸限制，只用来展示格式。

测试由检查程序评判，它用二维前缀和检查每个窗口；同一个检查程序在生成测试 2 上会拒绝单方向取整。
