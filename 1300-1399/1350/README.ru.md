# 1350. Столовая

[Timus 1350](https://acm.timus.ru/problem.aspx?space=1&num=1350) · сложность 384 · implementation

Автор оригинальной задачи — Павел Егоров; чемпионат школьников, март 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В меню N ≤ 100 продуктов, а обед дня приготовлен из M различных из них,
неизвестно каких. Его едят K + 1 ≤ 101 студентов; для каждого известен
список опасных продуктов. Первый студент поел и не отравился. Для
каждого из остальных K студентов нужно вывести `YES`, если обед точно
безвреден для этого студента, `NO`, если в обеде точно есть опасный
продукт, и `MAYBE`, если возможно и то и другое.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и N названий продуктов, затем K, затем K + 1 блоков: количество и
столько опасных продуктов, первый блок — для первого студента. Ввод
заканчивается числом M.

## Выходные данные

K строк с `YES`, `NO` или `MAYBE`.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
7
Rafinad
Kefir
Pastila
Smetana
Chokolade
Kljukva
Imbir
3
3
Rafinad
Kefir
Imbir
1
Rafinad
3
Kefir
Kljukva
Smetana
2
Imbir
Smetana
3
```

Вывод:

```
YES
NO
MAYBE
```

## Решение

Раз первый студент не отравился, ни одного из продуктов, опасных для
первого студента, в обеде нет: обед — это какие-то M продуктов из остальных,
безопасного множества S. Для другого студента с опасными продуктами D:

- если M = 0 или ни один продукт из S не входит в D, любой возможный обед
  безвреден: `YES`;
- если вне D меньше M продуктов из S, любой обед из M продуктов обязан
  взять что-то из D: `NO`;
- иначе один обед может обойти D, а другой — включить: `MAYBE`.

В среднем `O(N · K)`; в C++ — `O(N · K · log N)`.

Тонкие места:

- при M = 0 ничего не съедено, и все в порядке (тест 02);
- названия регистрозависимы: `Milk` и `milk` — два продукта (тест 04);
- опасные продукты вне S не важны, ведь в обеде их быть не может.

Ответы сравнивались с перебором всех возможных обедов на 400 случайных
столовых до 6 продуктов.

## Оптимизированные решения

`1350_bitmask_implementation.java`. Отдельный битовый вариант хранит опасные продукты меню словами по 64 бита на студента. Открытая адресация разрешает коллизии полным сравнением символов; один буфер имени на 40 символов избегает String для каждого вхождения, сохраняются только имена меню. Неизвестные имена игнорируются, OR убирает повторы. Long.bitCount считает опасные продукты каждого студента вне опасностей студента ноль; условия YES/NO/MAYBE прежние. Для P различных продуктов меню, K остальных студентов, W=ceil(P/64) и I байтов ввода ожидаемое время O(I+KW+P), состояние O(P+KW+K) при ограниченных именах. Коллизии могут замедлить поиск, но не меняют ответ. Обе прежние реализации сохранены.

Accepted точного исходника Java 1.8 №11326945: 0.109 с / 448 КБ. Сохранённое сравнение актуального Java от 2026-11-20: место по времени 6/29, по памяти 1/29. При памяти меньше 1024 КБ строгий критерий учитывает только время.

- `1350_bitmask_implementation.java`: 0.109 s / 448 KB; сохранённая учебная база `1350_implementation.java`: 0.14 s / 6524 KB; изменение времени -22.1%; изменение памяти -93.1%.

Компактные версии присваивают каждому продукту из меню индекс. C++ и Rust ищут индекс в отсортированном массиве, Go — в хеш-таблице. Rust читает каждый токен в один и тот же буфер. В массиве храним номер последнего студента, упомянувшего продукт, чтобы повторы в одном списке учитывались один раз. После исключения опасных продуктов первого студента для каждого следующего храним только число опасных продуктов, которые могли попасть в обед. Этого достаточно, когда станет известен размер обеда.

Сохранённые принятые базы [1350_implementation.go](1350_implementation.go) и [1350_implementation.py](1350_implementation.py) также проходят строгий критерий первых десяти мест или топ 15% в сохранённом сравнении. Их места по времени/памяти — 2/2 и 3/15 соответственно. Учебная Java-база занимает 16/29 по времени и 27/29 по памяти и не закрывает строгий быстрый набор; его закрывает отдельная битовая Java-версия выше. Базы используются без одинаковых копий; звёздочка относится к отдельной рейтинговой цели языка.

`1350_implementation_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1350_implementation.java`: время 0.140 s → 0.125 s; память 6524 KB → 3 484 KB.
