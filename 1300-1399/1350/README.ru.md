# 1350. Столовая

[Timus 1350](https://acm.timus.ru/problem.aspx?space=1&num=1350) · сложность 384 · implementation

Автор оригинальной задачи — Павел Егоров; чемпионат школьников, март 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В меню N ≤ 100 продуктов, а обед дня приготовлен из M различных из них,
неизвестно каких. Его едят K + 1 ≤ 101 студентов; для каждого известен
список опасных продуктов. Первый студент поел и не отравился. Для
каждого из остальных K студентов нужно вывести `YES`, если обед точно
безвреден для этого студента, `NO`, если в обеде точно есть опасный
продукт, и `MAYBE`, если возможно и то и другое.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и N названий продуктов, затем K, затем K + 1 блоков: количество и
столько опасных продуктов, первый блок — для первого студента. Ввод
заканчивается числом M.

## Выходные данные

K строк с `YES`, `NO` или `MAYBE`.

## Решение

Раз первый студент не отравился, ни одного из продуктов, опасных для
первого студента, в обеде нет: обед — это какие-то M продуктов из остальных,
безопасного множества S. Для другого студента с опасными продуктами D:

- если M = 0 или ни один продукт из S не входит в D, любой возможный обед
  безвреден: `YES`;
- если вне D меньше M продуктов из S, любой обед из M продуктов обязан
  взять что-то из D: `NO`;
- иначе один обед может обойти D, а другой — включить: `MAYBE`.

В среднем `O(N · K)`; в C++ — `O(N · K · log N)`.

Тонкие места:

- при M = 0 ничего не съедено, и все в порядке (тест 02);
- названия регистрозависимы: `Milk` и `milk` — два продукта (тест 04);
- опасные продукты вне S не важны, ведь в обеде их быть не может.

Ответы сравнивались с перебором всех возможных обедов на 400 случайных
столовых до 6 продуктов.

## Оптимизированные решения

Компактные версии присваивают каждому продукту из меню индекс. C++ и Rust ищут индекс в отсортированном массиве, Go — в хеш-таблице. Rust читает каждый токен в один и тот же буфер. В массиве храним номер последнего студента, упомянувшего продукт, чтобы повторы в одном списке учитывались один раз. После исключения опасных продуктов первого студента для каждого следующего храним только число опасных продуктов, которые могли попасть в обед. Этого достаточно, когда станет известен размер обеда.

Принятые базовые реализации [1350_implementation.java](1350_implementation.java), [1350_implementation.py](1350_implementation.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
