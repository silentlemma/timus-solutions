# 1374. 米赛尔

[Timus 1374](https://acm.timus.ru/problem.aspx?space=1&num=1374) · 难度 9959 · games

原题作者 Den Raskovalov，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

三名玩家各持 32 张牌中的 10 张，所有牌公开。共打十墩：领出者出任意一张牌，然后下一名玩家和第三名玩家依次出牌，有
首张牌的花色就必须跟同花色。该花色最大的牌赢得这一墩，并领出下一墩。没有将牌。玩家 1 宣布了米赛尔（不赢任何一墩），
一墩都不能赢。若无论另外两人怎么打，玩家 1 都能做到，输出 `;)`，否则输出 `;(`。

时间限制：1 秒。内存限制：16 MB。

## 输入

玩家 1、2、3 的手牌，每行一手，牌的写法如 `10S` 或 `QH`，然后是首先领出的玩家编号。

## 输出

`;)` 或 `;(`。

## 样例

### 样例 1

输入：

```
7S 8S 9S 10S JS QS KS AS 7C 8C
9C 10C JC QC KC AC 7D 8D 9D 10D
JD QD KD AD 7H 8H 9H 10H JH QH
1
```

输出：

```
;)
```

## 解法

这是结果为“是或否”的完全信息博弈，所以直接搜索：轮到玩家 1 出牌时，需要存在一张能保住米赛尔的牌；轮到另外两人时，
每一张牌都必须保住。有三点让搜索保持很小：

- 相邻的牌等同于同一张牌：同一玩家同一花色、中间没有其他玩家牌的两张牌，结果相同，所以每串只试一张；
- 四种花色地位相同，花色内只有牌的相对顺序重要。所以墩与墩之间的局面用每个花色持有者序列排序后的结果加上领出者来
  记忆，只差花色或点数改名的局面只算一次；
- 记忆的局面存放在以该序列为键的固定大小的表中。冲突只意味着要重新计算某个局面，内存因此远低于 16 MB。

在找到的最难的牌局上，大约存储 30 000 个局面。最坏情况是指数级的，但在所有试过的牌局上都很快。

注意事项：

- 出牌顺序是绕桌 1 → 2 → 3，从领出者开始；
- 没有首张花色的玩家可以出任何牌，而这样的牌永远赢不了这一墩；
- 玩家 1 只要赢下一墩，米赛尔就失败了。

在 300 个牌局上与不做花色和点数改名的普通搜索比较过答案；相邻牌的等价性在其他牌局上与逐张尝试所有牌的搜索核对过。
测试 02 到 05 是该题讨论区里贴出的难题牌局。

## 各语言说明

- Go 用固定大小的数组构造键和出牌列表：每一步都新建切片会留下垃圾，回收器会让堆长到 8 MB 表的约两倍，超过 16 MB。
- Python 按三名玩家的牌缓存一门花色的归属串，并只遍历手牌中置位的比特；它的局面表是至多 100 000 项的字典。在 PyPy 下它仍在评测的第 62 个测试上超时（1.05 秒），因此保留并标为 TLE：它通过了这里的全部测试，但不保证在评测的每个测试上都足够快。
- Java 的表用 2¹⁹ 项而不是 2²⁰ 项，给 16 MB 内的 JVM 留出空间。
