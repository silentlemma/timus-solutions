# 1389. Дорожные работы

[Timus 1389](https://acm.timus.ru/problem.aspx?space=1&num=1389) · сложность 552 · dp

Авторы оригинальной задачи — Дмитрий Иванков и Александр Ипатов; Петрозаводские летние сборы, август 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

N ≤ 100 000 городов соединены N − 1 двусторонними дорогами так, что из
любого города можно доехать до любого другого: дороги образуют дерево.
Нужно закрыть на ремонт как можно больше дорог, но у каждого города не
больше одной закрытой.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

N и M = N − 1, затем M дорог парами городов.

## Выходные данные

Число K закрытых дорог, затем K дорог в том виде, в каком они были во
входных данных.

## Примеры

### Пример 1

Ввод:

```
4 3
1 2
2 3
3 4
```

Вывод:

```
2
1 2
3 4
```

## Решение

Закрытые дороги образуют паросочетание, а наибольшее паросочетание в
дереве находится жадно от листьев. Возьмём лист и его единственного
соседа: какое-то наибольшее паросочетание содержит дорогу между ними,
потому что паросочетание с другой дорогой у этого соседа можно обменять
на эту. Поэтому обходим города в обратном порядке поиска в ширину от
города 1 и закрываем дорогу к родителю, если оба её конца ещё свободны.
Порядок поиска в ширину заменяет рекурсию, которая может переполнить стек
на пути из 100 000 городов. `O(N)`.

Подводные камни:

- дороги выводятся так, как записаны во входных данных, и в порядке
  ввода; другой порядок верного ответа, судя по всему, не принимается,
  поэтому решения отмечают выбранные дороги и выводят их за один проход;
- путь из 100 000 городов может быть слишком глубок для рекурсии
  (сгенерированный тест 1);
- в звезде можно закрыть только одну дорогу (тест 03 и сгенерированный
  тест 3).

Ответы сравнивались на 300 случайных деревьях до 11 городов с перебором
всех наборов дорог. Тесты проверяются программой, которая требует
ожидаемое число дорог, каждая записана как во входных данных, в порядке
ввода, и ни у одного города нет двух таких дорог.

## Оптимизированные решения

C++/Go/Rust сохраняют паросочетание в обратном порядке BFS: свободную наиболее глубокую вершину безопасно соединить со свободным родителем по обычному обменному доказательству. Вместо динамических списков и дублирующих концов дорог — плоские uint32 head/to/next. Дорога i имеет направленные рёбра2i (входное a→b) и2i+1 (b→a); xor1 обращает ребро, те же записи восстанавливают исходное направление вывода. Номер родительского ребра+1 с нулевой меткой позволяет пропускать обратное ребро без отдельного массива родителей/посещений. Порядок BFS выделен заранее, занятость вершины занимает байт. После BFS ссылки больше не обходятся: их свободные старшие биты отмечают выбранные дороги без нового массива. Финальный проход печатает их в порядке и ориентации ввода. Ссылки меньше200000 и не достигают бита31; путь100000 обходится без рекурсии. Время и память O(N), потоковый ограниченный ввод-вывод без полного текста и списка ответа. Простые версии сохранены; Java/Python используют подходящие базы.

Принятая версия Rust 1.75 x64 заняла 0.078 с при 0.031 с у базовой и использовала 2 768 KB при 16272 KB у базовой.

Принятые базовые реализации [1389_dp.java](1389_dp.java), [1389_dp.py](1389_dp.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
