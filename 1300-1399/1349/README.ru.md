# 1349. Ферма

[Timus 1349](https://acm.timus.ru/problem.aspx?space=1&num=1349) · сложность 51 · math

Автором оригинальной задачи назван Пьер Ферма; чемпионат школьников, март 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано n, 0 ≤ n ≤ 100. Нужно найти три различных целых числа a, b, c от 1
до 100, для которых aⁿ + bⁿ = cⁿ, — то, где a наименьшее, затем
наименьшее b, затем наименьшее c, — или вывести −1, если их нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число n.

## Выходные данные

a, b и c или −1.

## Проверка

Тесты репозитория точно сравнивают токены вывода; пробельные разделители между ними несущественны.

## Примеры

### Пример 1

Ввод:

```
0
```

Вывод:

```
-1
```

### Пример 2

Ввод:

```
1
```

Вывод:

```
1 2 3
```

## Решение

- n = 0: любая степень равна 1, а 1 + 1 никогда не 1, так что ответа нет.
- n = 1: a + b = c, и наименьший вариант с тремя различными числами —
  1 2 3.
- n = 2: наименьшая пифагорова тройка, 3 4 5, первая в нужном порядке.
- n ≥ 3: по великой теореме Ферма у aⁿ + bⁿ = cⁿ нет решений в
  натуральных числах.

`O(1)`.

Тонкие места:

- при n = 0 ответа нет, хотя все степени равны (тест 01);
- числа должны быть различны, что исключает ответы вроде 1 1 2 при
  n = 1.

Перебор всех троек до 100 для n от 0 до 5 дал те же ответы.

## Оптимизированные решения

Оптимизированные решения печатают те же три ответа. Java разбирает
показатель степени вручную через `System.in.read` вместо `Scanner`:
0.062 с вместо 0.125 с и 316 КБ вместо 1612 КБ. Rust выводит ответ
байтовой строкой через `write_all` вместо `println!`: 0.031 с вместо
0.062 с и 212 КБ вместо 232 КБ.

`1349_math_optimized.py`. Используется тот же полный разбор случаев, что в базовом словаре: n=1 даёт 1 2 3, n=2 — 3 4 5, остальные допустимые n — -1. Прямые ветви исключают создание небольшого словаря ответов, но не являются новым теоретико-числовым алгоритмом. Время и дополнительная память O(1). Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1349_math.py`: время 0.093 s → 0.109 s; память 336 KB → 172 KB.

Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
