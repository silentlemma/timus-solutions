# 1319. Отель

[Timus 1319](https://acm.timus.ru/problem.aspx?space=1&num=1319) · сложность 39 · implementation, math

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Стеллаж для почты в гостинице — блок N × N ячеек (1 ≤ N ≤ 100),
пронумерованных по диагоналям: номер 1 в правом верхнем углу, каждая
диагональ идёт сверху вниз, а диагонали следуют одна за другой к левому
нижнему углу, где стоит N². Нужно вывести пронумерованную таблицу.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

N строк по N чисел через пробел.

## Примеры

### Пример 1

Ввод:

```
3
```

Вывод:

```
4 2 1
7 5 3
9 8 6
```

## Решение

У клеток одной диагонали одинакова разность столбец − строка. Если
перебирать эту разность от N − 1 до −(N − 1), а строки каждой диагонали
сверху вниз, клетки идут в порядке нумерации. `O(N²)`.

Тонкие места:

- первая диагональ — одна правая верхняя клетка, а не главная диагональ
  (тест 01);
- N = 1 — одна клетка с числом 1 (тест 02).

## Оптимизированные решения

**Формула** (C++, Java, Rust). Таблица не хранится: число в каждой
клетке вычисляется по её положению, а строки печатаются по мере
вычисления. Диагональ клетки в строке `r` и столбце `c` содержит
`len = N − |c − r|` клеток. На главной диагонали и выше (`c ≥ r`)
диагонали перед ней содержат `1 + 2 + … + (len − 1) = len·(len − 1)/2`
чисел, а клетка стоит на своей диагонали под номером `r + 1`, поэтому в
ней `len·(len − 1)/2 + r + 1`. Ниже главной диагонали клетка считается с
конца: последующие диагонали и остаток её собственной оставляют
`N² − len·(len + 1)/2 + c + 1`. Java и Rust к тому же читают `N`
побайтно. Java укладывается в 0.062 с вместо 0.093 с и 508 КБ вместо
2008 КБ; C++ и Rust занимают меньше памяти при том же времени: 124 КБ
вместо 244 КБ и 200 КБ вместо 364 КБ.

Формула записана и на Python, каждая строка выводится сразу после
вычисления: 296 КБ вместо 888 КБ, хотя время растёт с 0.046 с до
0.078 с.
