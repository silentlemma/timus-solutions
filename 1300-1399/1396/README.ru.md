## Задача

Та же последовательность, что в [задаче 1079](../../1000-1099/1079/README.ru.md):
a₀ = 0, a₁ = 1, a₂ᵢ = aᵢ, a₂ᵢ₊₁ = aᵢ + aᵢ₊₁. Для до 10 000 чисел
n < 10¹⁸ нужно вывести наибольшее aᵢ при 0 ≤ i ≤ n.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

По одному n в строке, в конце 0.

## Выходные данные

Наибольший член до каждого n.

## Примеры

### Пример 1

Ввод:

```
5
10
0
```

Вывод:

```
3
4
```

## Решение

Член читается по двоичным цифрам индекса. Для префикса m цифр храним
пару (aₘ, aₘ₊₁): цифра 0 превращает её в (aₘ, aₘ + aₘ₊₁), цифра 1 — в
(aₘ + aₘ₊₁, aₘ₊₁). Оба отображения линейны, поэтому ещё r цифр
превращают пару в p·aₘ + q·aₘ₊₁ с постоянными p и q.

Любое i ≤ n — либо само n, либо совпадает с n до некоторой цифры 1,
которую понижает до 0, а ниже идут любые r цифр. Поэтому идём по цифрам
n сверху и в каждой цифре 1 берём лучшее из всех окончаний длины r после
пониженного префикса. Лучшее окончание всегда одно из восьми:
чередующиеся цифры, начиная с 0 или с 1, как есть, с последней цифрой 1
или с двумя последними 11 или 01. Их (p, q) считаются один раз для
каждого r до 60, так что запрос стоит `O(log n)`. Члены с индексами
меньше 2⁶⁰ меньше 3·10¹², в 64 бита они помещаются.

Подводные камни:

- одних чередующихся цифр мало: от a₀, a₁ две свободные цифры дают
  больше всего при 11, а не при 01 или 10;
- рекорды растут как числа Фибоначчи и при больших n выходят за 32 бита
  (тест 04).

Восемь окончаний проверены на настоящем максимуме каждого блока из 2ʳ
индексов ниже 2²² при r от 12 до 20, а все малые случаи — перебором
всех окончаний; ответы сравнивались с прямым просмотром для каждого n
до 65 536.
