# 1396. 最大值（第二版）

[Timus 1396](https://acm.timus.ru/problem.aspx?space=1&num=1396) · 难度 1980 · math

原题由 Vladimir Yakovlev 准备。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

与[题目 1079](../../1000-1099/1079/README.zh.md) 相同的数列：a₀ = 0，a₁ = 1，
a₂ᵢ = aᵢ，a₂ᵢ₊₁ = aᵢ + aᵢ₊₁。对至多 10 000 个 n < 10¹⁸，输出 0 ≤ i ≤ n 中最
大的 aᵢ。

时间限制：1 秒。内存限制：64 MB。

## 输入

每行一个 n，以 0 结束。

## 输出

每个 n 之前的最大项。

## 样例

### 样例 1

输入:

```
5
10
0
```

输出:

```
3
4
```

## 解法

一项可以由其下标的二进制位读出。对位的前缀 m 保存数对 (aₘ, aₘ₊₁)：位 0 把它
变为 (aₘ, aₘ + aₘ₊₁)，位 1 变为 (aₘ + aₘ₊₁, aₘ₊₁)。两个映射都是线性的，所以
再加 r 位就把数对变成 p·aₘ + q·aₘ₊₁，其中 p、q 固定。

每个 i ≤ n 要么就是 n，要么与 n 一直相同到某个 1 位，把它降为 0，其下是任意
r 位。因此从高位遍历 n，在每个 1 位处取降低后的前缀接上所有 r 位结尾中的最
大值。最佳结尾总是八种之一：以 0 或 1 开头的交替位，保持不变，或把最后一位
设为 1，或把最后两位设为 11 或 01。它们的 (p, q) 对每个不超过 60 的 r 预先算
好，所以每次查询 `O(log n)`。下标小于 2⁶⁰ 的项都小于 3·10¹²，64 位足够。

注意事项：

- 只用交替位不够：从 a₀、a₁ 出发，两位自由位时 11 最大，而不是 01 或 10；
- 纪录值按斐波那契数增长，n 较大时超过 32 位（测试 04）。

这八种结尾在 2²² 以下每个长 2ʳ 的下标块上（r 从 12 到 20）与真实最大值做了
核对，小情形则枚举所有结尾验证；答案与直接扫描在 n 不超过 65 536 的所有值上
做了比较。
