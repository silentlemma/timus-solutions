# 1369. 蟑螂赛跑

[Timus 1369](https://acm.timus.ru/problem.aspx?space=1&num=1369) · 难度 10221 · geometry

原题作者 Den Raskovalov，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

平面上有 M 只蟑螂（1 ≤ M ≤ 100 000）和 N 块糖（0 ≤ N ≤ 10 000），坐标是
−10 000 到 10 000 之间的实数；任意两只蟑螂、任意两块糖之间的距离都不
小于 0.001。对每块糖，按升序输出离它最近的蟑螂编号。

时间限制：2 秒。内存限制：64 MB。

## 输入

M 和蟑螂，接着 N 和糖，每行一个点。

## 输出

N 行，每块糖最近的蟑螂。

## 样例

### 样例 1

输入:

```
4
0 0
1 0
0 1
1 2
2
0 0
0 2
```

输出:

```
1
3 4
```

## 解法

这些实现使用题面没提到的容差：若某只蟑螂距离的平方小于最小值加
2⁻²⁴，它就算在内。坐标的小数点后可能超过 20 位，double 可能丢失这一
边界附近的差异。精确比较使用放大 10³⁰ 倍的整数，截去小数点后第 30 位
以后的数字。

C++、Go、Java 和 Rust 将蟑螂连成一张图：用分治法在 quad-edge 上构建的
Delaunay 三角剖分，再加上每只蟑螂在按 x 排序和按 y 排序中的邻居。方向测试和圆内测试先用
double 计算并给出舍入误差界，结果落在误差界内时再精确重算。若所有蟑螂
共线，图就是沿这条直线的路径。

对一块糖，行走从上一个答案和按 x 顺序均匀选出的至多 1 024 只蟑螂中
最近的一只出发，只要有更近的邻居就移过去：先用 double，再精确地走。在
Delaunay 三角剖分上这样的行走终止于最近的蟑螂。再从那里在图上搜索，
只扩展容差内的顶点，收集所有这样的蟑螂。W 为检查的顶点数与邻接表项数
之和，K 为每次查询输出的蟑螂数（均取各次查询的最大值）。

易错点：

- 平方距离上的容差 2⁻²⁴：测试 06 中有小于和大于该容差的平方距离差；
- 最近的蟑螂可以有十二只（测试 04）；
- 共线的蟑螂会使三角剖分退化（测试 05）；
- N 可以为 0（测试 03）。

答案在所有小测试和大测试的抽样上与精确暴力一致。一份独立的已通过实现
除了生成的环形和圆形测试中的五行之外全部一致，而在这五行上暴力结果站在
这里的解法一边。

## 各语言说明

- C++ 和 Rust 用 128 位整数存坐标，用十六个 32 位分段组成的 512 位整数存乘积。Go 也用 128 位存坐标，只在精确计算时扩展，边数组用 32 位：最初存 512 位坐标的版本在评测第 9 个测试上用了 88 MB。
- Java 先用 double 比较距离，只有差值在舍入误差之内时才精确计算，乘法也只处理用到的分段：否则在评测第 9 个测试上超过 2 秒。
- Python 在 PyPy 下运行，不构建三角剖分：它在存于扁平数组中的包围盒 k-d 树里查找最近的蟑螂，点云细长时树沿主轴旋转。蟑螂靠近同一个圆时改按角度排序，树结点用其角度区间和到圆心的最小距离来估计；也可以直接扫描狭窄的角度窗口或整个圆。除可能相等的情况精确比较外，其余都用 double 判断。早先带三角剖分的版本在评测第 15 个测试上用时略超 2 秒，或在第 9 个测试上用了 70 MB。V 为每次查询检查的树结点数和点数（取各次查询的最大值）。
