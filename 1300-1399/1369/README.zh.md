# 1369. 蟑螂赛跑

[Timus 1369](https://acm.timus.ru/problem.aspx?space=1&num=1369) · 难度 11966 · geometry

原题作者 Den Raskovalov，出自 2005 年 4 月 19–24 日在叶卡捷琳堡举行的第九届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

平面上有 M 只蟑螂（M ≤ 100 000）和 N 块糖（N ≤ 10 000），坐标是
−10 000 到 10 000 之间的实数；任意两只蟑螂、任意两块糖之间的距离都不
小于 0.001。对每块糖，按升序输出离它最近的蟑螂编号。

时间限制：2 秒。内存限制：64 MB。

## 输入

M 和各只蟑螂，然后是 N 和各块糖，每行一个点。

## 输出

N 行，每块糖最近的蟑螂。

## 样例

### 样例 1

输入:

```
4
0 0
1 0
0 1
1 2
2
0 0
0 2
```

输出:

```
1
3 4
```

## 解法

“最近”带有题面没提到的容差：若某只蟑螂距离的平方小于最小值加
2⁻²⁴，它就算在内。坐标小数点后可能超过 20 位，double 无法区分这样的
距离。因此每个坐标还会精确地保存为整数——十进制值乘以 10³⁰，所有最终
比较都在这些整数上进行。

蟑螂被连成一张图：用分治法在 quad-edge 上构建的 Delaunay 三角剖分，
再加上每只蟑螂在按 x 排序和按 y 排序中的邻居。方向测试和圆内测试先用
double 计算并给出舍入误差界，结果落在误差界内时再精确重算。若所有蟑螂
共线，图就是沿这条直线的路径。

对一块糖，行走从按 x 顺序均匀选出的 1 024 只蟑螂中最近的一只（或上一个
答案）出发，只要有更近的邻居就移过去：先用 double，再精确地走。在
Delaunay 三角剖分上这样的行走终止于最近的蟑螂。再从那里在图上搜索，
只经过容差内的蟑螂，收集所有这样的蟑螂。`O(M log M + N · W)`，W 为行走
步数。

易错点：

- 平方距离上的容差 2⁻²⁴：测试 06 中有在容差内相等和刚好超出的距离；
- 最近的蟑螂可以有十二只（测试 04）；
- 共线的蟑螂会使三角剖分退化（测试 05）；
- N 可以为 0（测试 03）。

答案在所有小测试和大测试的抽样上与精确暴力一致。一份独立的已通过实现
除了生成的环形和圆形测试中的五行之外全部一致，而在这五行上暴力结果站在
这里的解法一边。

## 各语言说明

- C++ 和 Rust 用 128 位整数存坐标，用十六个 32 位分段组成的 512 位整数存乘积。Go 也用 128 位存坐标，只在精确计算时扩展，边数组用 32 位：最初存 512 位坐标的版本在评测第 9 个测试上用了 88 MB。
- Java 先用 double 比较距离，只有差值在舍入误差之内时才精确计算，乘法也只处理用到的分段：否则在评测第 9 个测试上超过 2 秒。
- Python 在 PyPy 下运行，不构建三角剖分：它在存于扁平数组中的包围盒 k-d 树里查找最近的蟑螂，点云细长时树沿主轴旋转。蟑螂靠近同一个圆时改按角度排序，树结点用其角度区间和到圆心的最小距离来估计。除可能相等的情况精确比较外，其余都用 double 判断。早先带三角剖分的版本在评测第 15 个测试上用时略超 2 秒，或在第 9 个测试上用了 70 MB。复杂度为 `O(M log M + N · V)`，V 为一次查询访问的树结点数。
