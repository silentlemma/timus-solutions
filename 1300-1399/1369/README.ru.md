# 1369. Тараканьи бега

[Timus 1369](https://acm.timus.ru/problem.aspx?space=1&num=1369) · сложность 11966 · geometry

Автор оригинальной задачи — Ден Расковалов; IX командный студенческий чемпионат Урала по программированию, Екатеринбург, 19–24 апреля 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На плоскости стоят M тараканов (M ≤ 100 000) и N кусочков сладости
(N ≤ 10 000), координаты вещественные от −10 000 до 10 000; любые два
таракана и любые два кусочка находятся на расстоянии не меньше 0,001.
Для каждого кусочка выведите номера ближайших к нему тараканов по
возрастанию.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

M и тараканы, затем N и кусочки, по точке в строке.

## Выходные данные

N строк — ближайшие тараканы каждого кусочка.

## Примеры

### Пример 1

Ввод:

```
4
0 0
1 0
0 1
1 2
2
0 0
0 2
```

Вывод:

```
1
3 4
```

## Решение

У «ближайшего» есть допуск, о котором условие молчит: таракан
считается, если квадрат расстояния до него меньше наименьшего плюс
2⁻²⁴. У координат бывает больше 20 знаков после точки, и double такие
расстояния не различает. Поэтому каждая координата хранится ещё и
точно, как целое — десятичная запись, умноженная на 10³⁰, и все
окончательные сравнения делаются на этих целых.

Тараканы связываются в граф: триангуляция Делоне, построенная методом
«разделяй и властвуй» на quad-edge, плюс соседи каждого таракана в
порядке по x и в порядке по y. Проверки ориентации и попадания в круг
считаются в double с оценкой ошибки округления и пересчитываются точно,
если результат попал внутрь этой оценки. Если все тараканы на одной
прямой, граф — путь вдоль неё.

Для кусочка обход начинается с ближайшего из 1 024 тараканов, равномерно
взятых в порядке по x (или с прошлого ответа), и переходит к более
близкому соседу, пока такой есть: сначала в double, затем точно. На
триангуляции Делоне такой обход заканчивается в ближайшем таракане.
Поиск по графу оттуда собирает всех тараканов в пределах допуска,
проходя только через таких тараканов. `O(M log M + N · W)` для обходов
из W шагов.

Подводные камни:

- допуск 2⁻²⁴ на квадраты расстояний: в тесте 06 есть расстояния,
  равные в его пределах и чуть за ним;
- ближайших тараканов может быть двенадцать (тест 04);
- тараканы на одной прямой вырождают триангуляцию (тест 05);
- N может быть 0 (тест 03).

Ответы совпадают с точным перебором на всех маленьких тестах и на
выборках из больших. Независимая принятая реализация согласна везде,
кроме пяти строк сгенерированных тестов с кольцами и окружностью, где
перебор на стороне здешних решений.

## Особенности языков

- C++ и Rust держат координаты в 128-битных целых, а произведения — в
  512-битном целом из шестнадцати 32-битных разрядов. Go тоже хранит
  координаты в 128 битах и расширяет их только для точных шагов, а
  массивы рёбер у него 32-битные: первая версия с 512-битными
  координатами заняла 88 МБ на тесте 9 жюри.
- Java сначала сравнивает расстояния в double и точно — только когда
  разница в пределах ошибки округления, а умножает лишь занятые разряды:
  без этого на тесте 9 жюри она работала больше 2 с.
- Python запускается под PyPy и триангуляцию не строит: ближайших
  тараканов он ищет в k-d дереве ограничивающих прямоугольников в
  плоских массивах, повёрнутом вдоль главной оси вытянутого облака.
  Когда тараканы лежат около одной окружности, они упорядочены по углу,
  а вершина дерева оценивается своим угловым интервалом и наименьшим
  расстоянием до центра. Всё решают числа double, кроме возможных
  равенств, которые сравниваются точно. Прежние версии с триангуляцией
  работали чуть больше 2 с на тесте 15 жюри или занимали 70 МБ на тесте 9.
  `O(M log M + N · V)`, где V — число вершин дерева, просмотренных запросом.
