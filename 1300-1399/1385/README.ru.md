# 1385. Интересное число

[Timus 1385](https://acm.timus.ru/problem.aspx?space=1&num=1385) · сложность 247 · math

Автор оригинальной задачи — Александр Ипатов; Петрозаводские летние сборы, август 2005 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Число из 2N цифр без ведущего нуля называется интересным, если оно
делится и на число из своих первых N цифр, и на число из последних N
цифр. Нужно посчитать интересные числа из 2N цифр, 1 ≤ N ≤ 10 000.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

Количество.

## Проверка

Сравнивается один целочисленный токен. У пяти добавленных исходников по 13 тестов репозитория и 67 дополнительных целевых запусков, включая N=1,2,3,4,4300,4301,9999,10000. Только Python дополнительно исполнен для всех N=1..10000. Малые количества проверены буквальной делимостью при N≤3 и перебором кратных при N=4. Это разные проверки, не 10000 запусков каждого языка.

## Примеры

### Пример 1

Ввод:

```
1
```

Вывод:

```
14
```

Эти четырнадцать чисел: 11, 12, 15, 22, 24, 33, 36, 44, 48, 55, 66, 77,
88 и 99.

## Решение

Запишем число как `A*M+B`, где `M=10^N`, `M/10≤A<M`, `0≤B<M`.
У второго блока могут быть ведущие нули, но сам он должен быть ненулевым
делителем. Делимость на A означает `B=k*A`, `1≤k≤9`. Тогда условие
`k*A | A*M+B` равносильно `k | M`. Для каждого такого k значения A идут
от `M/10` до `M/k−1`, всего `M/k−M/10`. Разные k задают непересекающиеся
варианты, поэтому эти количества складываются.

Учебные Go, Java и Python напрямую вычисляют M стандартными длинными целыми,
проверяют k=1..9 и выполняют точные деления. Требуется `O(N)` десятичных
цифр памяти; консервативная оценка арифметики и перевода в десятичный вид —
`O(N²)`. Python отключает стандартный предел числа цифр при конвертации,
иначе допустимые большие N не пройдут. Обычного машинного целого недостаточно.
Все прежние версии с формулой сохранены; C++ и Rust используют доказанную
замкнутую формулу, поскольку в их стандартных библиотеках нет соответствующих
целых произвольной точности.

## Оптимизированные решения

`1385_math_optimized.go`. Сохраняется вывод коэффициента из делимости только через 10^min(N,3), затем потоковый вывод нулевого хвоста. syscall.Read/Write из Go1.14 с фиксированными буферами 256 байт заменяют инициализацию os.File и прежние буферы 4096 байт; учитываются EINTR, частичные записи и EOF с нулём байт. Таблица ответов и длинные числа не вводятся. Вывод O(N), дополнительная память O(1). Собственный Accepted использует 312КБ, на72,0% меньше короткой формульной базы1116КБ; обе простые версии — формула и длинная арифметика — сохранены.

По сравнению с `1385_math.go`: время 0.031 s → 0.015 s; память 1116 KB → 312 KB.

`1385_math_optimized.rs`. Сохраняется доказанный подсчёт Σ(10^N/d-10^(N-1)) по делителям d=1..9 числа10^N, но коэффициент вычисляется только для10^min(N,3). С N=3 допустимые d стабилизируются на1,2,4,5,8: получаем14,155 либо1575 и при необходимости ровно N-3 нулевых байт. Значения выводятся из короткого цикла делителей, а не хранятся как ответы. Обе версии непосредственно выводят нулевой хвост без Repeat/repeat и склейки всего ответа. Ответ содержит N+1 цифру: O(N) времени, O(1) дополнительного состояния плюс ограниченный ввод-вывод, без длинного целого или буфера размера N. Rust-версия читает и пишет через среду выполнения C, без сохранения декодированной входной String и построения форматированной строки ответа. Простой исходник с Accepted сохранён.

По сравнению с `1385_math.rs`: время 0.015 s → 0.015 s; память 224 KB → 56 KB.

Среди k=1..9 делить `10^N` могут лишь числа с простыми множителями 2 и 5.
При N=1 подходят 1,2,5:9+4+1=14. При N=2 подходят 1,2,4,5:
90+40+15+10=155. Начиная с N=3 набор постоянен:1,2,4,5,8.
Вынося `10^(N−3)`, получаем
`(1000−100)+(500−100)+(250−100)+(200−100)+(125−100)=1575`.
Поэтому выводим `1575` и N−3 нулей. Константы выведены из подсчёта
делимости, а не являются сохранёнными ответами на отдельные входы.
Ответ содержит N+1 цифр, время вывода `O(N)`. Прежние формулы строят строку
ответа с памятью `O(N)`; новые C++/Java выводят нули ограниченными блоками,
используя `O(1)` дополнительной памяти относительно N.

Прежняя формула Python экономит 35,5% памяти против прямой учебной версии
с длинными целыми при том же времени 0,078 с. Новый Java медленнее своей
длинноцелой базы, но экономит память; указаны обе стороны. Недобор рейтинга
не отменяет реальную экономию памяти: такая формула помечена звёздочкой.

- `1385_math.py`: 0.078 s / 392 KB; база `1385_math_number_theory.py`: 0.078 s / 608 KB; изменение относительно базы: время -0.0%, память -35.5%.
- `1385_math_optimized.cpp`: 0.015 s / 120 KB; база `1385_math.cpp`: 0.015 s / 372 KB; изменение относительно базы: время -0.0%, память -67.7%.
- `1385_math_optimized.java`: 0.093 s / 432 KB; база `1385_math_number_theory.java`: 0.078 s / 1388 KB; изменение относительно базы: время +19.2%, память -68.9%.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1385_math_optimized.go`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

`1385_math_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
