## Задача

Число из 2N цифр без ведущего нуля называется интересным, если оно
делится и на число из своих первых N цифр, и на число из последних N
цифр. Нужно посчитать интересные числа из 2N цифр, 1 ≤ N ≤ 10 000.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число N.

## Выходные данные

Количество.

## Проверка

Сравнивается один целочисленный токен. У пяти добавленных исходников по 13 тестов репозитория и 67 дополнительных целевых запусков, включая N=1,2,3,4,4300,4301,9999,10000. Только Python дополнительно исполнен для всех N=1..10000. Малые количества проверены буквальной делимостью при N≤3 и перебором кратных при N=4. Это разные проверки, не 10000 запусков каждого языка.

## Примеры

### Пример 1

Ввод:

```
1
```

Вывод:

```
14
```

Эти четырнадцать чисел: 11, 12, 15, 22, 24, 33, 36, 44, 48, 55, 66, 77,
88 и 99.

## Решение

Запишем число как `A*M+B`, где `M=10^N`, `M/10≤A<M`, `0≤B<M`.
У второго блока могут быть ведущие нули, но сам он должен быть ненулевым
делителем. Делимость на A означает `B=k*A`, `1≤k≤9`. Тогда условие
`k*A | A*M+B` равносильно `k | M`. Для каждого такого k значения A идут
от `M/10` до `M/k−1`, всего `M/k−M/10`. Разные k задают непересекающиеся
варианты, поэтому эти количества складываются.

Учебные Go, Java и Python напрямую вычисляют M стандартными длинными целыми,
проверяют k=1..9 и выполняют точные деления. Требуется `O(N)` десятичных
цифр памяти; консервативная оценка арифметики и перевода в десятичный вид —
`O(N²)`. Python отключает стандартный предел числа цифр при конвертации,
иначе допустимые большие N не пройдут. Обычного машинного целого недостаточно.
Все прежние версии с формулой сохранены; C++ и Rust используют доказанную
замкнутую формулу, поскольку в их стандартных библиотеках нет соответствующих
целых произвольной точности.

## Оптимизированные решения

Среди k=1..9 делить `10^N` могут лишь числа с простыми множителями 2 и 5.
При N=1 подходят 1,2,5:9+4+1=14. При N=2 подходят 1,2,4,5:
90+40+15+10=155. Начиная с N=3 набор постоянен:1,2,4,5,8.
Вынося `10^(N−3)`, получаем
`(1000−100)+(500−100)+(250−100)+(200−100)+(125−100)=1575`.
Поэтому выводим `1575` и N−3 нулей. Константы выведены из подсчёта
делимости, а не являются сохранёнными ответами на отдельные входы.
Ответ содержит N+1 цифр, время вывода `O(N)`. Прежние формулы строят строку
ответа с памятью `O(N)`; новые C++/Java выводят нули ограниченными блоками,
используя `O(1)` дополнительной памяти относительно N.

Прежняя формула Python экономит 35,5% памяти против прямой учебной версии
с длинными целыми при том же времени 0,078 с. Новый Java медленнее своей
длинноцелой базы, но экономит память; указаны обе стороны. Недобор рейтинга
не отменяет реальную экономию памяти: такая формула помечена звёздочкой.
