# 1342. 企业

[Timus 1342](https://acm.timus.ru/problem.aspx?space=1&num=1342) · 难度 735 · dp

原题作者 Magaz Asanov 和 Pavel Egorov，出自 USU Championship 2004。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一家公司有 N ≤ 1000 个工厂，需要 M ≤ 1000 把扫帚。工厂 i 每天能做 0 到 K_i ≤ 100 把；第一把的成本是 P_i，
第 K_i 把是 Q_i，中间第 j 把的价格线性变化。求 M 把扫帚的最小总成本，保留小数点后两位。若所有工厂加起来做不出
M 把，先输出它们最多能做的数量 V，再输出 V 把扫帚的最小成本。

时间限制：2.5 秒。内存限制：64 MB。

## 输入

N 和 M，然后 N 行 K_i、P_i 和 Q_i。

## 输出

若达不到 M，先输出 `Maximum possible amount: V`，然后输出 `Minimum possible cost: C`。

## 样例

### 样例 1

输入：

```
2 10
6 20 15
100 100 100
```

输出：

```
Minimum possible cost: 505.00
```

### 样例 2

输入：

```
2 10
5 30 14
1 20 20
```

输出：

```
Maximum possible amount: 6
Minimum possible cost: 130.00
```

## 解法

工厂的第 j 把扫帚成本为 P + (j − 1) · (Q − P) / (K − 1)，所以做 x 把的成本是
x · P + (Q − P) / (K − 1) · x (x − 1) / 2。目标是 T = min(M, ΣK)。价格下降时，工厂只有做很多把才划算；价格
上升时，只有前几把便宜。两种情况混在一起时，任何贪心顺序都不行，所以这是背包问题：best[j] 表示用已考虑的
工厂恰好做 j 把的最小成本。加入新工厂时，对每个不超过 T 的 j 尝试从 0 到 K 的每个数量 x。这最多是
N · T · K = 10⁸ 个简单步骤。`O(N · M · K)`。

注意事项：

- 价格下降的工厂可能只有满负荷运转时，才能胜过一家看起来更便宜的工厂（测试 04）；
- 总产能不足时要输出两行，成本按 V 把计算（测试 02 和 06）；
- K = 1 的工厂只有一把扫帚，价格为 P。

在 400 个最多 3 个工厂的随机例子上，与枚举订单在工厂间所有分配方式的结果比较过成本。

## 各语言说明

- CPython 在最大的例子上约需 4 秒，超过 2.5 秒的限制，所以 Python 解法以 PyPy 3.10 提交，约需 0.1 秒。
- Java 在内层循环中直接比较 double：对 double 使用 `Math.min` 还要处理 NaN 和 −0，会让解法慢好几倍。
