# 1342. Фирма веников не вяжет

[Timus 1342](https://acm.timus.ru/problem.aspx?space=1&num=1342) · сложность 729 · dp

Авторы оригинальной задачи — Магаз Асанов и Павел Егоров; USU Championship 2004.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У фирмы N ≤ 1000 фабрик, и ей нужно M ≤ 1000 веников. Фабрика i может
связать за день от 0 до K_i ≤ 100 веников; первый веник стоит P_i,
K_i-й — Q_i, а цена j-го веника между ними меняется линейно. Нужно найти
наименьшую общую стоимость M веников с двумя знаками после точки. Если
фабрики вместе не могут сделать M веников, сначала выводится наибольшее
количество V, которое они могут сделать, а затем наименьшая стоимость V
веников.

Ограничение времени: 2.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

N и M, затем N строк с K_i, P_i и Q_i.

## Выходные данные

`Maximum possible amount: V`, если M недостижимо, затем
`Minimum possible cost: C`.

## Примеры

### Пример 1

Ввод:

```
2 10
6 20 15
100 100 100
```

Вывод:

```
Minimum possible cost: 505.00
```

### Пример 2

Ввод:

```
2 10
5 30 14
1 20 20
```

Вывод:

```
Maximum possible amount: 6
Minimum possible cost: 130.00
```

## Решение

j-й веник фабрики стоит P + (j − 1) · (Q − P) / (K − 1), так что x
веников стоят x · P + (Q − P) / (K − 1) · x (x − 1) / 2. Цель —
T = min(M, ΣK). Когда цены падают, фабрика выгодна только при большом
числе веников, а когда растут — дёшевы только её первые веники. При
смеси обоих видов никакой жадный порядок не работает, поэтому это
рюкзак: best[j] — наименьшая стоимость ровно j веников с уже
рассмотренных фабрик. Новая фабрика обновляет его, перебирая каждое
количество x от 0 до K для каждого j до T. Это не больше
N · T · K = 10⁸ простых шагов. `O(N · M · K)`.

Тонкие места:

- фабрика с падающими ценами может обогнать на вид более дешёвую только
  при полной загрузке (тест 04);
- когда общей мощности не хватает, выводятся обе строки, и стоимость
  считается для V веников (тесты 02 и 06);
- у фабрики с K = 1 единственный веник стоит P.

Стоимости сравнивались с перебором всех разбиений заказа между не более
чем 3 фабриками на 400 случайных примерах.

## Особенности языков

- CPython тратит около 4 секунд на самый большой пример, больше предела
  в 2.5 секунды, поэтому решение на Python отправляется под PyPy 3.10,
  где оно занимает около 0.1 секунды.
- Java сравнивает числа типа double во внутреннем цикле напрямую:
  `Math.min` для double учитывает ещё NaN и −0 и замедлял решение в
  несколько раз.
