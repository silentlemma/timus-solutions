# 1028. 统计每个点左下方的点数

[Timus 1028](https://acm.timus.ru/problem.aspx?space=1&num=1028) · 难度 265 · fenwick, segment_tree

原题出自 1999 年第三届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定 `N` 个不同的整数点，`1 ≤ N ≤ 15000`、`0 ≤ x, y ≤ 32000`。输入按 `y` 递增，同一 `y` 时按 `x` 递增。一个点的等级是满足 `x' ≤ x` 且 `y' ≤ y` 的其他点数。输出等级 0 到 `N − 1` 各有多少点。时间限制：0.25 秒；内存限制：64 MB。

## 输入

先给出 `N`，随后 `N` 行 `x y`，满足上述顺序，且没有重合点。

## 输出

输出 `N` 行，依次为等级 0、1、…、`N − 1` 的点数。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 样例

### 样例 1

输入：

```
6
2 0
6 0
0 2
4 2
4 4
1 6
```

输出：

```
2
2
1
1
0
0
```

### 样例 2

输入：

```
1
32000 32000
```

输出：

```
1
```

## 解法

处理当前点时，所有之前的点已满足 `y′ ≤ y`；之后的点要么 `y` 更大，
要么同一 `y` 下 `x` 更大，因此都不能贡献。等级就是已处理点中 `x′ ≤ x` 的数量。

在 `x = 0..32000` 上维护频率 Fenwick 树，先将 `x` 加一以使用从 1 开始的索引。
查询截至 `x + 1` 的前缀，增加该等级的直方图计数，随后插入当前点。
每个 Fenwick 单元保存其索引前缀的一个后缀；不断清除最低有效位，
可把查询前缀划分为互不相交的区间。插入更新的恰是包含该索引的区间。
因此查询恰好计入所需的之前点；先查询再插入可排除当前点。
同一 `y` 下也要立即插入，不能延迟到整组末尾，因为同一行之前的点同样应被计入。

时间为 `O(N log C)`，`C = 32001`，树与直方图占 `O(C + N)` 个单元。
还保留原 C++ 线段树：查询 `[0, x + 1)` 并插入 `x`，使用相同的顺序证明，
渐近界相同但树更大。六份原始 Accepted 源码均逐字节保留。

## 优化解法

树或直方图中的计数最多为 `N ≤ 15000`，故无符号 16 位单元足够，
查询求和则使用更宽的类型。紧凑 Fenwick 用 16 位数组取代完整原生整数或 Python 对象列表。
最大规模下，两组计数数组共 `2 × (32002 + 15000) = 94004` 字节，
不含输入、输出和运行时。

C++ 采用小块输入缓冲与标准缓冲输出。Python 流式处理输入标记，处理后删除生成器，
但仍构造最终输出字符串。Rust 保留输入文本，但惰性解析，不再保存全部数值标记向量，
并通过缓冲写出。时间仍为 `O(N log C)`，计数存储仍为 `O(C + N)`，是实现和内存优化。

相对同语言原 Fenwick，实测内存：C++ 348 → 224 KB（减少 35.6%），
Python 3644 → 1576 KB（减少 56.8%），Rust 1076 → 580 KB（减少 46.1%）。
三份均有各自 Accepted，并按内存改善准入。Python 较慢，为 0.156 秒对 0.109 秒；
Rust 均为 0.031 秒。C++ 记录为 0.015 秒对 0.031 秒，但单个计时刻度不作为可靠加速证据。
C++ 比较基线明确为原 Fenwick，而非内存更多的线段树。

## 各语言说明

Python 与直接二维支配计数比较了 811 组小点集，包括 3 × 3 坐标网格的所有非空子集
和随机边界坐标。另外两组 15000 点极端输入用公式推出的期望直方图检查，
覆盖直方图计数 15000 与最大 Fenwick 计数。
三份实际候选程序还各自在 Docker 中通过仓库的 14 组输入。

排名快照为 2026 年 11 月 2 日。C++ 在 235 个筛选后的其他作者记录中，时间第 1、
内存第 2，达到目标。Rust 对两个记录两项均第 1。Python 对 19 个记录为时间第 5、
内存第 3，因此保留星号。原 Java 对五个记录两项均第 1。Go 比较样本为空，
其形式覆盖不证明竞争优势。
