# 1028. Подсчёт точек ниже и левее каждой точки

[Timus 1028](https://acm.timus.ru/problem.aspx?space=1&num=1028) · сложность 265 · fenwick, segment_tree

Оригинальная задача — III командный студенческий чемпионат Урала по программированию, 1999 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `N` различных точек, `1 ≤ N ≤ 15000`, с целыми координатами `0 ≤ x, y ≤ 32000`. Они перечислены по возрастанию `y`, а при одинаковом `y` — по возрастанию `x`. Уровень точки — число других точек с `x' ≤ x` и `y' ≤ y`. Найдите количество точек каждого уровня от 0 до `N − 1`. Лимит времени: 0,25 секунды. Память: 64 МБ.

## Входные данные

`N`, затем `N` строк `x y` в указанном порядке; совпадающих точек нет.

## Выходные данные

`N` строк с количествами точек уровней 0, 1, …, `N − 1`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
2 0
6 0
0 2
4 2
4 4
1 6
```

Вывод:

```
2
2
1
1
0
0
```

### Пример 2

Ввод:

```
1
32000 32000
```

Вывод:

```
1
```

## Решение

У текущей точки все предыдущие уже имеют `y′ ≤ y`. У более поздней
точки либо больше `y`, либо тот же `y` и больше `x`, поэтому она не может
внести вклад. Уровень равен числу уже прочитанных точек с `x′ ≤ x`.

Храним частоты `x = 0..32000` в дереве Фенвика. Сдвигаем `x` на единицу:
запрашиваем префикс до `x + 1`, увеличиваем счётчик полученного уровня,
затем вставляем точку. Ячейка дерева хранит суффикс префикса своего индекса;
последовательное удаление младшего установленного бита разбивает префикс
на непересекающиеся интервалы. Вставка посещает ровно те ячейки, интервалы
которых содержат её индекс. Поэтому запрос считает ровно нужные предыдущие
точки. Запрос до вставки исключает саму точку. Точки с одинаковым `y`
обрабатываем сразу, не откладывая вставки до конца группы: более ранние
точки на той же строке тоже должны учитываться.

Время — `O(N log C)`, `C = 32001`, дерево и гистограмма занимают `O(C + N)`
ячеек. Сохранено и исходное дерево отрезков C++: запрос `[0, x + 1)`
и вставка `x` используют то же обоснование порядка. Асимптотика такая же,
но дерево больше. Все шесть исходных Accepted-файлов сохранены побайтово.

## Оптимизированные решения

Каждый счётчик дерева или гистограммы не превосходит `N ≤ 15000`,
поэтому достаточно беззнаковой 16-битной ячейки; сумма запроса вычисляется
в более широком типе. Компактные версии заменяют полные нативные целые
или списки объектов Python 16-битными массивами. При максимальном размере
два массива счётчиков занимают `2 × (32002 + 15000) = 94004` байта
без учёта ввода, вывода и среды выполнения.

C++ использует небольшой буфер чтения и стандартный буферизованный вывод.
Python читает токены потоком и удаляет генератор после обработки, но
по-прежнему собирает итоговую строку вывода. Rust хранит текст входа,
но разбирает его лениво без вектора всех числовых токенов и пишет через
буфер. Время остаётся `O(N log C)`, хранение счётчиков — `O(C + N)`;
это оптимизация реализации и памяти.

Измеренная память относительно исходного Фенвика на том же языке:
C++ 348 → 224 КБ (35,6%), Python 3644 → 1576 КБ (56,8%), Rust 1076 → 580 КБ
(46,1%). У всех трёх есть собственный Accepted; критерий выполнен по памяти.
Python медленнее: 0,156 с против 0,109 с; Rust остаётся на 0,031 с. У C++
записано 0,015 с против 0,031 с, но один тик таймера не используется
как подтверждение ускорения. C++ сравнивается с исходным Фенвиком,
а не с более затратным по памяти деревом отрезков.

## Особенности языков

Python проверен на 811 малых наборах против прямого подсчёта двумерного
доминирования: все непустые подмножества сетки координат 3 × 3 и случайные
граничные координаты. Ещё два предельных набора по 15000 точек проверены
по ожидаемым гистограммам, выведенным формулами: счётчик 15000 и максимальные счётчики Фенвика.
Каждая из трёх реальных программ также прошла 14 входов репозитория в Docker.

Рейтинговый срез — 2 ноября 2026 года. C++ занимает места 1 по времени
и 2 по памяти среди 235 отфильтрованных посылок других авторов и достиг
цели. Rust первый по обеим метрикам против двух посылок. У Python места
5 и 3 против 19 посылок, поэтому его оптимизированная строка со звёздочкой.
Исходная Java первая по обеим метрикам против пяти посылок. Выборка Go
пуста: формальное покрытие не доказывает конкурентного превосходства.
