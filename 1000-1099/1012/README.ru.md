# 1012. Подсчёт K-ичных чисел без двух нулей подряд, с длинной арифметикой

[Timus 1012](https://acm.timus.ru/problem.aspx?space=1&num=1012) · сложность 181 · dp

Оригинальная задача — усложнённая версия [задачи 1009](../1009/README.ru.md).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Посчитайте `N`-значные числа в системе счисления с основанием `K` (первая
цифра не ноль), в записи которых нет двух нулей подряд. `2 ≤ K ≤ 10`,
`N ≥ 2`, `N + K ≤ 1800`.

Ограничение времени: 0.5 секунды. Ограничение памяти: 16 МБ.

## Входные данные

`N` и `K`, каждое на своей строке.

## Выходные данные

Количество целиком.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4
2
```

Вывод:

```
5
```

### Пример 2

Ввод:

```
3
10
```

Вывод:

```
891
```

## Решение

Рекуррентность та же, что в [задаче 1009](../1009/README.ru.md): считаем
правильные префиксы по последней цифре, `zero` оканчиваются на `0`,
`other` — на ненулевую цифру:

- `zero' = other`;
- `other' = (zero + other) · (K - 1)`;

начиная с `zero = 0`, `other = K - 1`; ответ — `zero + other` после `N`
цифр.

Меняется размер: ответ содержит до примерно 1 800
десятичных цифр, поэтому нужна длинная арифметика. Используются всего две
операции — сумма двух длинных чисел и произведение длинного на короткое, —
обе линейны по длине. Храним длинное число массивом «цифр» по основанию
`10^9`, младшие впереди: цифра, умноженная на `K - 1`, плюс перенос
помещается в 64 бита. `N` шагов по `O(L)`, где `L` — длина ответа в
разрядах: около `1800 · 200` операций.

Хранятся только два текущих значения, так что память — `O(L)`; таблица из
`N` длинных чисел тоже поместилась бы, но она не нужна.

Подводные камни:

- 64-битные целые переполняются примерно после 20 цифр: решение лёгкой
  версии здесь неверно;
- при печати разрядов по основанию `10^9` каждый разряд, кроме старшего,
  нужно дополнять ведущими нулями до 9 цифр.

## Оптимизированные решения

Оптимизированное решение на C++ хранит `zero` и `other` в двух
статических массивах из 201 разряда по основанию `10^9`; этого хватает,
ведь ответ меньше `K^N ≤ 10^N`, а `N < 1800`. Шаг рекуррентности
делается за один проход по разрядам на месте: разряд `zero` получает
разряд `other`, а разряд `other` становится равен остатку от деления на
`10^9` суммы `(zero + other) · (K - 1)` и переноса; сама сумма меньше
`18 · 10^9` и помещается в 64 бита. На каждом шаге не выделяются и не
растут временные векторы: {1012_dp_optimized.cpp}.

Оптимизированное решение на Go заменяет `math/big` двумя массивами
фиксированного размера из 201 разряда по основанию `10^9`; этого
хватает, ведь ответ меньше `K^N ≤ 10^N`, а `N < 1800`. Шаг
рекуррентности делается за один проход по разрядам на месте, сумма и
умножение на `K - 1` совмещены: промежуточное значение меньше
`18 · 10^9` и помещается в 64 бита. На каждом шаге не создаются новые
длинные числа, а разряды печатаются с дополнением нулями через
буферизованный вывод: {1012_dp_optimized.go}.

Оптимизированное решение на Java заменяет `BigInteger` двумя массивами
`long` из 201 разряда по основанию `10^9`; этого хватает, ведь ответ
меньше `K^N ≤ 10^N`, а `N < 1800`. Шаг рекуррентности делается за один
проход по разрядам на месте, сумма и умножение на `K - 1` совмещены:
промежуточное значение меньше `18 · 10^9` и помещается в `long`. Кроме
того, два числа читаются побайтно вместо `Scanner`, а разряды
дополняются нулями вручную: {1012_dp_optimized.java}.

Оптимизированное решение на Rust хранит `zero` и `other` в двух массивах
фиксированного размера из 201 разряда по основанию `10^9`; этого
хватает, ведь ответ меньше `K^N ≤ 10^N`, а `N < 1800`. Шаг
рекуррентности делается за один проход по разрядам на месте:
промежуточное значение `(zero + other) · (K - 1)` плюс перенос меньше
`18 · 10^9` и помещается в `u64`. Для каждой суммы и произведения не
выделяются новые векторы, а разряды пишутся сразу в `BufWriter`, без ещё
одной строки: {1012_dp_optimized.rs}.

## Особенности языков

- **Python**, **Go** (`math/big`) и **Java** (`BigInteger`) поддерживают
  длинные целые.
- **C++** и **Rust** реализуют обе операции на разрядах по основанию `10^9`.
