# 1001. Квадратные корни в обратном порядке

[Timus 1001](https://acm.timus.ru/problem.aspx?space=1&num=1001) · сложность 14 · math

Оригинальную задачу подготовил Дмитрий Ковалёв.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На вход подаётся последовательность целых чисел `A1, A2, ..., An`, где
`0 ≤ Ai ≤ 10^18`. Выведите их квадратные корни в обратном порядке: сначала
`√An`, последним `√A1`.

Количество `n` не задаётся: числа идут до конца ввода, общий размер которого
не больше 256 КБ (значит, `n` не больше примерно 131 000).

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Целые числа `Ai`, разделённые любым количеством пробелов и переводов строки
(в том числе пустыми строками).

## Выходные данные

`n` строк: `√An, √An-1, ..., √A1`, по одному числу в строке, каждое не менее
чем с четырьмя знаками после десятичной точки.

## Проверка

Каждый квадратный корень нужно вывести не менее чем с четырьмя знаками
после десятичной точки.

## Примеры

### Пример 1

Ввод:

```
  16   2

 1000000000000000000   
0
```

Вывод:

```
0.0000
1000000000.0000
1.4142
4.0000
```

### Пример 2

Ввод:

```
7
```

Вывод:

```
2.6458
```

## Решение

Прочитать все числа до конца ввода в массив, затем пройти его с конца и
вывести `sqrt(Ai)` с четырьмя знаками. Время и память — `O(n)`.

Точности `sqrt` в двойной точности хватает: при переводе значения до `10^18` в
double относительная погрешность не больше `2^-53`, поэтому корень (не больше
`10^9`) отличается от точного меньше чем на `10^-6` — намного меньше
`10^-4` (четыре знака после точки).

Подводные камни:

- количество чисел не задано, поэтому читать нужно до конца ввода;
- разделители произвольные: несколько пробелов, переводы строк, пустые строки;
- значения не помещаются в 32 бита: нужны 64-битные целые;
- до примерно 131 000 строк вывода: вывод нужно буферизовать.

## Оптимизированные решения

Оптимизированные решения (C++, Go, Java, Rust) хранят ввод как текст, а
не как массив чисел. C++, Go и Java читают его в один буфер и разбирают
числа с конца назад — ровно в порядке вывода; Rust проходит лексемы текста
в обратном порядке. Корень печатается вручную: умножается на `10^4`,
округляется и выводится как целая часть и четыре цифры дробной, без
медленного форматирования чисел с плавающей точкой. Вместо массива до
131 000 чисел в памяти остаются только 256 КБ ввода. C++: 0.031 с вместо
0.125 с и 356 КБ вместо 1576 КБ; Go: 0.015 с вместо 0.125 с и 1180 КБ
вместо 6588 КБ; Java: 0.125 с вместо 0.593 с и 872 КБ вместо 11728 КБ;
Rust: 0.015 с вместо 0.046 с и 464 КБ вместо 3072 КБ.

Оптимизированное решение на Python выводит ответы блоками с конца ввода:
оно отрезает примерно по 4 КБ чисел, по границе между числами, поэтому
список всех корней целиком не строится: 2052 КБ вместо 11492 КБ, хотя
время растёт с 0.125 с до 0.156 с.

## Особенности языков

- **C++**: простое решение использует `scanf("%llu")` в цикле и
  `printf("%.4f\n")`.
- **Go**: простое решение читает через `fmt.Fscan` поверх `bufio.Reader`
  и пишет через `fmt.Fprintf` в `bufio.Writer`; вызывать `fmt.Printf` на
  небуферизованный вывод для каждой строки медленно.
- **Python**: простое решение читает весь ввод через
  `sys.stdin.buffer.read().split()`, собирает все строки и выводит их одним
  `join`.
- **Java**: простое решение читает через `BufferedReader` со
  `StringTokenizer` и собирает вывод в `StringBuilder`; форматирует с
  `Locale.US`, иначе разделителем дробной части может оказаться запятая.
- **Rust**: простое решение читает весь ввод в `String`, разбирает `u64`
  и форматирует через `{:.4}` в одну строку вывода.
