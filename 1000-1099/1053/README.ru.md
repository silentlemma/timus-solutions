# 1053. Распил заготовок, пока не останется одна

[Timus 1053](https://acm.timus.ru/problem.aspx?space=1&num=1053) · сложность 344 · number_theory

Оригинальная задача — Рыбинская государственная авиационная академия.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `N` заготовок (`1 ≤ N ≤ 1000`) с целыми длинами от 1 до `2^31 − 1`.
Пока заготовок больше одной, берём любые две: если они равны, одну
выбрасываем; иначе отпиливаем от длинной кусок длиной в короткую и
выбрасываем его. Выведите длину последней заготовки или `IMPOSSIBLE`, если
она зависит от выбора.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` длин, по одной в строке.

## Выходные данные

Длина последней заготовки.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3
2
3
4
```

Вывод:

```
1
```

### Пример 2

Ввод:

```
4
12
18
30
42
```

Вывод:

```
6
```

## Решение

Оба шага сохраняют наибольший общий делитель всех длин:
`gcd(a, b) = gcd(a − b, b)`, а выбрасывание одной из двух равных заготовок
не меняет множества делителей. Процесс заканчивается одной заготовкой, а
НОД одного числа — само число, поэтому последняя заготовка всегда равна
НОД исходных длин, как бы мы ни выбирали. `IMPOSSIBLE` не бывает ответом
никогда. `O(N log L)`.

Это вычитательная форма алгоритма Евклида, запущенная сразу на многих
числах.

Подводные камни:

- длины доходят до `2^31 − 1`, что ещё помещается в знаковое 32-битное
  целое;
- одна заготовка сама по себе и есть ответ;
- моделировать распилы по одному слишком долго для длин вроде
  `2^31 − 1` и 1.

## Оптимизированные решения

Go и Rust обновляют один текущий НОД при чтении длин. Как только он становится единицей, ответ больше не изменится, поэтому программа завершается без чтения остальных длин. Ввод буферизован, НОД выводится напрямую. Дополнительная память постоянна. Go обращается к стандартным дескрипторам напрямую и завершает частичные записи. Rust читает и пишет через библиотеку времени исполнения C.

Принятая версия Rust 1.75 x64 заняла 0.031 с при 0.015 с у базовой и использовала 68 KB при 244 KB у базовой.

Принятые базовые реализации [1053_number_theory.cpp](1053_number_theory.cpp), [1053_number_theory.java](1053_number_theory.java), [1053_number_theory.py](1053_number_theory.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
