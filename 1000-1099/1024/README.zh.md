# 1024. 置换的阶

[Timus 1024](https://acm.timus.ru/problem.aspx?space=1&num=1024) · 难度 323 · math

原题作者 Nikita Shamgunov，出自 2000 年 10 月 7 日斯维尔德洛夫斯克州第二届中学生团体程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`1..N`（`1 ≤ N ≤ 1000`）上的置换 `P` 由 `P(1), ..., P(N)` 给出。其幂为 `P^1 = P`，
`P^k(n) = P(P^(k-1)(n))`。求使 `P^k` 为恒等置换的最小 `k ≥ 1`。答案不超过 `10^9`。

时间限制：2 秒。内存限制：64 MB。

## 输入

`N`，然后是 `N` 个数 `P(1), ..., P(N)`。

## 输出

最小的这样的 `k`。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 样例

### 样例 1

输入：

```
5
2 3 1 5 4
```

输出：

```
6
```

### 样例 2

输入：

```
1
1
```

输出：

```
1
```

## 题解

每个置换都可分解为互不相交的 **循环**：从某个元素出发不断应用 `P`，直到回到起点。在长度为 `c` 的循环上
置换就是一次轮转，所以 `P^k` 在其上为恒等当且仅当 `c` 整除 `k`。当所有循环都满足时 `P^k` 处处为恒等，
最小的这样的 `k` 就是各循环长度的 **最小公倍数**。

用 `seen` 数组遍历各循环（每个元素访问一次，`O(N)`），并用 `lcm(a, b) = a / gcd(a, b) · b` 累积长度——
先做除法可使中间值保持较小。

注意事项：

- 循环长度之积不是答案：长度 4 和 6 得 12，而不是 24；
- 逐次计算 `P` 的幂可能需要多达 `10^9` 步；
- 按题意最小公倍数不超过 `10^9`，但除法前的 `a · b` 可能超出 32 位——请用 64 位整数。

## 优化解法

Go 用固定的 16 位编号数组保存排列。访问过的项置零，零不属于排列，因此无需额外的访问标记数组。各环长度通过最小公倍数合并，先除以最大公约数再相乘。通过标准句柄直接读写固定字节缓冲区。

已通过评测的基础实现 [1024_math.cpp](1024_math.cpp), [1024_math.java](1024_math.java), [1024_math.py](1024_math.py), [1024_math.rs](1024_math.rs) 也满足快速版本的要求：在保存的比较快照中，时间和内存均符合前 15% 或前十名的排名收录规则。直接复用这些源文件，不创建相同副本。星号标记尚未达到该语言目标排名的版本。

`1024_math_optimized.java`. Java 保留简单版本所述的算法和数据结构。固定字节缓冲区与 FastInput 替代 Scanner 及其正则表达式、区域设置处理。整数记号直接解析；需要字符串时仍进行 UTF-8 解码，十进制记号仍显式转换为数值。仅在需要前瞻时保存一个记号，输出算法不变。这样减少通用解析开销；表中列出算法工作量，输入扫描与字节数成正比，并使用有界输入缓冲区。

与 `1024_math.java` 相比：时间 0.140 s → 0.093 s；内存 2400 KB → 468 KB。
