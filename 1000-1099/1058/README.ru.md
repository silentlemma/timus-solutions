# 1058. Кратчайший разрез, делящий выпуклый многоугольник пополам

[Timus 1058](https://acm.timus.ru/problem.aspx?space=1&num=1058) · сложность 2756 · geometry

Оригинальная задача — Рыбинская государственная авиационная академия.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Выпуклый многоугольник с `N` вершинами (`4 ≤ N ≤ 50`, против часовой
стрелки, координаты от −100 до 100 не более чем с тремя знаками после
запятой) разрезается прямой линией на две части равной площади. Найдите
наименьшую возможную длину разреза с погрешностью не больше `10^-4`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк с координатами вершин.

## Выходные данные

Наименьшая длина делящего пополам разреза.

## Проверка

Числа сравниваются с абсолютной или относительной погрешностью `10^-4`.

## Примеры

### Пример 1

Ввод:

```
4
0 0
4 0
4 3
0 3
```

Вывод:

```
3.000000
```

### Пример 2

Ввод:

```
4
0 -5
5 0
0 5
-5 0
```

Вывод:

```
7.071068
```

## Решение

Будем задавать разрез его первым концом `P` на границе, записанным как
позиция `u ∈ [0, N)`: `u = i + t` — точка на доле `t` ребра `i`. Через
каждую точку `P` проходит ровно один делящий пополам разрез, и его второй
конец `Q` находится из площадей:

- с префиксными суммами слагаемых формулы шнурков удвоенная площадь
  многоугольника `P, V[i+1], …, V[j]` считается за `O(1)`; она растёт с
  `j`, поэтому двоичный поиск находит ребро `j`, на котором лежит `Q`;
- на этом ребре площадь растёт линейно с положением `Q`, что даёт `Q`
  точно.

Так длина разреза `L(u)` вычисляется за `O(log N)`. При движении `u`
функция `L(u)` гладкая везде, кроме моментов, когда `P` или `Q` проходит
вершину. Точки излома — целые числа и партнёры вершин (отношение
«партнёр» симметрично), всего не больше `2N`. На каждом гладком куске
решения берут 64 точки и уточняют каждый локальный минимум выборки, в
том числе на концах куска, поиском золотого сечения; наименьшее
найденное значение и есть ответ.

Это численный поиск, а не формула: он рассчитывает на то, что внутри
одного куска у длины нет двух минимумов ближе шага выборки. Он сравнивался
с совершенно другим методом (перебор направления разреза, где каждая
делящая прямая находится бисекцией по её сдвигу) примерно на семидесяти случайных,
правильных, тонких и почти круглых многоугольников и примерно на сотне
случайных многоугольников с вершинами на сторонах, повторённой вершиной
или обходом по часовой стрелке — всегда в пределах `10^-6`.

Подводные камни:

- разрез не обязан проходить через вершину или быть перпендикулярным
  ребру;
- у очень тонких многоугольников очень короткие разрезы; важна
  относительная точность;
- обход границы требует порядка против часовой стрелки; решения берут
  знак площади и переворачивают список по часовой стрелке, а не верят
  порядку (первая версия, которая верила, не прошла на сервере);
- каждый разрез находится дважды (с любого конца), что не мешает.

## Особенности языков

- Во всех языках один и тот же поиск; размеры маленькие, поэтому даже в
  Python он занимает несколько миллисекунд.
