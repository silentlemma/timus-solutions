# 1026. K-й по величине элемент базы данных

[Timus 1026](https://acm.timus.ru/problem.aspx?space=1&num=1026) · сложность 156 · sorting, prefix_sums

Автор оригинальной задачи — Леонид Волков; второе командное соревнование школьников Свердловской области по программированию, 7 октября 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В базе данных `N` целых чисел (`N ≤ 100 000`, каждое от 1 до 5000, в
произвольном порядке, с повторами). Ответьте на `K` запросов
(`1 ≤ K ≤ 100`): по данному `i` (`1 ≤ i ≤ N`) выведите `i`-й по величине
элемент, считая повторы.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` чисел по одному в строке; затем строка `###`; затем `K` и
`K` запросов по одному в строке.

## Выходные данные

`K` строк — ответы на запросы по порядку.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
42
7
5000
7
1
300
###
5
1
2
3
6
4
```

Вывод:

```
1
7
7
5000
42
```

### Пример 2

Ввод:

```
1
3000
###
1
1
```

Вывод:

```
3000
```

## Решение

**Сортировка.** Сортируем базу один раз; ответ на запрос `i` — элемент на
позиции `i` (считая с 1). `O(N log N + K)`.

**Подсчёт.** Значения маленькие, поэтому считаем, сколько раз встречается
каждое значение `v ≤ 5000`, и берём префиксные суммы: `atMost[v]` — число
элементов, не больших `v`. `i`-й по величине элемент — наименьшее `v` с
`atMost[v] ≥ i`; его находит двоичный поиск по неубывающему массиву.
`O(N + V + K log V)` при `V = 5000`.

Подводные камни:

- повторяющиеся значения занимают несколько позиций: если 7 встречается
  дважды, на позициях 2 и 3 стоит 7;
- строку-разделитель `###` нужно пропустить, а не разбирать как число;
- читайте вход быстро: `10^5` строк.

## Оптимизированные решения

Оптимизированное решение на C++ считает значения так же, как простое
решение подсчётом, но хранит счётчики в глобальном массиве из 5001
`int`, разбирает числа вручную из буфера на 4 КБ, который пополняется
через `fread` (строка `###` пропускается вместе с прочими нецифровыми
символами), и печатает через `printf` вместо `iostream`:
{1026_prefix_sums_optimized.cpp}.

Оптимизированное решение на Go считает вместо сортировки: оно хранит
только число вхождений каждого значения от 1 до 5000, берёт префиксные
суммы и отвечает на каждый запрос двоичным поиском через
`sort.SearchInts`, так что база не хранится и не сортируется. Кроме
того, цифры разбираются вручную из читателя `bufio` вместо `fmt.Fscan`:
{1026_prefix_sums.go}.

Оптимизированное решение на Java тоже считает вместо сортировки: частоты
значений до 5000, их префиксные суммы и двоичный поиск на каждый запрос.
Оно читает ввод блоками по 4 КБ и разбирает цифры вручную, пропуская
строку `###`, вместо того чтобы делать `String` из каждой строки:
{1026_prefix_sums.java}.

Оптимизированное решение на Python тоже считает вместо сортировки. Оно
читает базу построчно, ведь каждое значение стоит на своей строке,
считает частоты значений в списке из 5001 элемента, берёт префиксные
суммы и отвечает на каждый запрос через `bisect_left`; ни список всех
токенов, ни отсортированный список из `N` чисел не хранится:
{1026_prefix_sums.py}.

Оптимизированное решение на Rust считает значения в массиве
фиксированного размера из 5001 `u32`, читая ввод построчно в одну и ту
же `String`, а затем отвечает на каждый запрос двоичным поиском по
префиксным суммам вместо сортировки; ни весь ввод, ни база не хранятся:
{1026_prefix_sums.rs}.
