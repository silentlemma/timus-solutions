# 1026. K-й по величине элемент базы данных

[Timus 1026](https://acm.timus.ru/problem.aspx?space=1&num=1026) · сложность 156 · sorting, prefix_sums

Автор оригинальной задачи — Леонид Волков; второе командное соревнование школьников Свердловской области по программированию, 7 октября 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В базе данных `N` целых чисел (`N ≤ 100 000`, каждое от 1 до 5000, в
произвольном порядке, с повторами). Ответьте на `K` запросов
(`1 ≤ K ≤ 100`): по данному `i` (`1 ≤ i ≤ N`) выведите `i`-й по величине
элемент, считая повторы.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` чисел по одному в строке; затем строка `###`; затем `K` и
`K` запросов по одному в строке.

## Выходные данные

`K` строк — ответы на запросы по порядку.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
42
7
5000
7
1
300
###
5
1
2
3
6
4
```

Вывод:

```
1
7
7
5000
42
```

### Пример 2

Ввод:

```
1
3000
###
1
1
```

Вывод:

```
3000
```

## Решение

**Сортировка.** Сортируем базу один раз; ответ на запрос `i` — элемент на
позиции `i` (считая с 1). `O(N log N + K)`.

**Подсчёт.** Значения маленькие, поэтому считаем, сколько раз встречается
каждое значение `v ≤ 5000`, и берём префиксные суммы: `atMost[v]` — число
элементов, не больших `v`. `i`-й по величине элемент — наименьшее `v` с
`atMost[v] ≥ i`; его находит двоичный поиск по неубывающему массиву.
`O(N + V + K log V)` при `V = 5000`.

Подводные камни:

- повторяющиеся значения занимают несколько позиций: если 7 встречается
  дважды, на позициях 2 и 3 стоит 7;
- строку-разделитель `###` нужно пропустить, а не разбирать как число;
- читайте вход быстро: `10^5` строк.

## Особенности языков

- **C++**: и сортировка, и сортировка подсчётом с двоичным поиском.
- **Go**, **Python**, **Java**, **Rust**: сортировка; Python читает все
  токены разом.
