# 1038. Подсчёт ошибок в заглавных буквах

[Timus 1038](https://acm.timus.ru/problem.aspx?space=1&num=1038) · сложность 489 · implementation

Автор оригинальной задачи — Александр Гальперин; Пятый командный чемпионат УрГУ по программированию, октябрь 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Текст длиной не более 10000 символов состоит из латинских букв, цифр,
знаков препинания `. , ; : - ! ?` и пробельных символов. Слово — это
максимальная последовательность букв; любой другой символ, включая
перевод строки, его завершает. Предложение заканчивается на `.`, `?` или
`!`; начало текста тоже начинает предложение. Посчитайте ошибки двух
видов:

- первая буква предложения строчная;
- заглавная буква не является первой буквой своего слова (каждая такая
  буква — отдельная ошибка).

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Текст, возможно, на нескольких строках.

## Выходные данные

Число ошибок.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
This sentence iz correkt! -It Has,No mista;.Kes et oll.
But there are two BIG mistakes in this one!
and here is one more.
```

Вывод:

```
3
```

### Пример 2

Ввод:

```
hello. World? yes!
OK, fine.
```

Вывод:

```
3
```

## Решение

Один проход по символам с двумя флагами:

- `new_sentence` — с начала текста или с последнего `.`, `?`, `!` ещё не
  было ни одной буквы;
- `in_word` — предыдущий символ был буквой.

Для буквы: если она строчная и `new_sentence` установлен — ошибка первого
вида; если заглавная и установлен `in_word` — ошибка второго вида. Затем
`new_sentence` сбрасывается, а `in_word` устанавливается. Любой другой
символ сбрасывает `in_word`, а конец предложения устанавливает
`new_sentence`. `O(L)` для текста длины `L`.

Подводные камни:

- первая буква предложения не обязана его начинать: перед ней могут быть
  цифры, пробелы или другие знаки (`2nd place.` — ошибка на `n`);
- цифра не буква, поэтому `3Rd` — это слово `Rd`, начинающееся с
  заглавной, ошибки нет;
- весь ввод — это текст: читайте его до конца вместе с переводами строк.

## Оптимизированные решения

Go/Python сохраняют автомат с двумя флагами, но читают блоки 4096 байт. Флаги переносятся между блоками, разрыв слова или ожидание первой буквы предложения обрабатываются точно. Go проверяет ASCII-диапазоны, Python переводит блок таблицей классов из 256 байтов и сканирует малые целые классы. Таблица описывает алфавит ASCII, не ответы. Цифры и пробельные символы заканчивают слово, новое предложение дают только .?!. Время O(L), дополнительная память фиксирована. Допуск определяется реальными метриками судьи, особенно для Python с заметным временем запуска. Базы сохранены; C++, Java и Rust используют подходящие базы.

Принятая версия Python 3.12 x64 заняла 0.078 с при 0.109 с у базовой и использовала 496 KB при 364 KB у базовой.

Принятые базовые реализации [1038_implementation.cpp](1038_implementation.cpp), [1038_implementation.java](1038_implementation.java), [1038_implementation.rs](1038_implementation.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

`1038_implementation_parsing_optimized.rs`. Ошибки регистра считаются при чтении нативных блоков; между пополнениями хранятся только состояния предложения и слова. Исходные правила ASCII-букв и пунктуации сохранены; полный текст не хранится. Прямой вывод специализирован по реальным типам ответа без универсального выбора формата и временных строк. Фиксированный текст записывается нативно; числовой вывод точно обрабатывает нужные знаковые или беззнаковые значения. Математические решения и архивные простые версии сохранены.

Accepted #11329194 (Rust 1.75 x64): **0.015 s / 60 KB**. Архивное сравнение: `1038_implementation.rs` (Rust 1.75 x64) — 0.031 s / 252 KB (#11278496).

## Особенности языков

Эти замечания относятся к базовым реализациям.

- Во всех языках ввод читается целиком (побайтово или одной строкой), и
  выполняется один и тот же проход с двумя флагами.
