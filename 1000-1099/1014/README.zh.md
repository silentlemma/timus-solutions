# 1014. 各位数字之积为给定值的最小数

[Timus 1014](https://acm.timus.ru/problem.aspx?space=1&num=1014) · 难度 94 · greedy

原题出自 Ural State University Internal Contest '99 #2。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

给定 `N`（`0 ≤ N ≤ 10^9`），求各位十进制数字之积恰好等于 `N` 的最小正整数 `Q`；若不存在则说明。

时间限制：1 秒。内存限制：64 MB。

## 输入

整数 `N`。

## 输出

`Q`；若不存在这样的数，输出 `-1`。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 样例

### 样例 1

输入：

```
36
```

输出：

```
49
```

### 样例 2

输入：

```
0
```

输出：

```
10
```

## 题解

先处理两种特殊情况：

- `N = 0`：数字之积为 0 当且仅当含有数字 0，最小的这样的正整数是 `10`；
- `N = 1`：答案是 `1`（而不是空数）。

其余情况下没有数字是 0 或 1（1 只会让数变长），所以 `Q` 由数字 2–9 组成。位数少的数更小，而位数相同时，
数字按递增顺序排列的那个最小。因此问题变为：把 `N` 写成尽可能少的数字之积。

**贪心：** 先尽可能用 9 去除 `N`，然后依次用 8、7、……、2，并收集这些数字。若最后剩下的不是 1，说明 `N`
有大于 7 的质因子，答案为 `-1`。把收集到的数字按递增顺序输出。

为什么先用大数字：3 的幂最好装进 9（一个数字装两个 3），2 的幂装进 8，剩下的一个 3 和一个 2 合成 6 而不是
两个数字；按 9、8、……、2 的顺序去除恰好得到这种装法。共 `O(log N)` 次除法。

注意事项：

- `N = 0` 和 `N = 1`；
- 答案可能有 12 位（`10^9 = 2^9 · 5^9` 得到 `555555555888`）：不要存进 32 位整数——按字符串输出数字。
- 只统计除法会漏掉在开头插入数字的开销：[测试 05](tests/05.in) 就会构造一个 12 位的答案。

## 优化解法

优化的 Java 解法直接从 `System.in` 逐字节解析数字，而不是使用 `Scanner`；数字追
加到末尾，最后把字符串反转一次，而不是每次插到开头：380 KB，而不是 1604 KB，时间
不变。

## 各语言说明

各语言使用相同的贪心；数字收集到字符串中。设收集了 `k = O(log N)` 个数字，简单的
C++、Go 和 Java 解法每次都在开头插入，需要移动或复制已有数字，总时间为
`O(k^2) = O((log N)^2)`。Python、Rust 和优化的 Java 解法在末尾追加，再逆序输出，
总时间为 `O(log N)`。所有解法的额外空间均为 `O(log N)`。
