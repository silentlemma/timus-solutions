# 1014. Наименьшее число с заданным произведением цифр

[Timus 1014](https://acm.timus.ru/problem.aspx?space=1&num=1014) · сложность 94 · greedy

Оригинальная задача — Ural State University Internal Contest '99 #2.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано `N` (`0 ≤ N ≤ 10^9`). Найдите наименьшее натуральное `Q`, произведение
десятичных цифр которого равно ровно `N`, или сообщите, что такого нет.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Целое число `N`.

## Выходные данные

`Q` или `-1`, если такого числа не существует.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
36
```

Вывод:

```
49
```

### Пример 2

Ввод:

```
0
```

Вывод:

```
10
```

## Решение

Сначала два особых случая:

- `N = 0`: произведение цифр равно 0 ровно тогда, когда в числе есть ноль,
  и наименьшее такое натуральное число — `10`;
- `N = 1`: ответ `1` (а не пустое число).

Иначе ни одна цифра не равна 0 или 1 (единица только удлиняет число), так
что `Q` состоит из цифр 2–9. Меньшее число короче, а среди чисел одной
длины наименьшее то, у которого цифры идут по возрастанию. Значит, задача —
записать `N` произведением наименьшего числа цифр.

**Жадность:** делим `N` на 9, пока делится, затем на 8, 7, ..., 2 и
собираем цифры. Если в остатке не 1, у `N` есть простой делитель больше 7, и
ответ `-1`. Выводим собранные цифры по возрастанию.

Почему сначала большие цифры: степени тройки выгоднее всего упаковать в
девятки (две тройки в одной цифре), степени двойки — в восьмёрки, а
оставшиеся тройка и двойка образуют шестёрку, а не две цифры; деление на 9,
8, ..., 2 в таком порядке даёт именно эту упаковку. `O(log N)` шагов деления.

Подводные камни:

- `N = 0` и `N = 1`;
- в ответе может быть 12 цифр (`10^9 = 2^9 · 5^9` даёт `555555555888`): не
  храните его в 32-битном целом — печатайте цифры строкой.
- подсчёт только делений не учитывает стоимость вставки цифр в начало:
  уже [тест 05](tests/05.in) строит ответ из 12 цифр.

## Оптимизированные решения

`1014_greedy_optimized.py` используется побайтово без изменений, без второго исходника и нового алгоритма. Accepted точного исходника на CPython 3.12 №11327014: 0.078 с / 724 КБ. Сохранённая выборка актуальных компиляторов семейства Python от 2026-11-20: место по времени 6/482, по памяти 448/482. Поскольку здесь меньше 1024 КБ, строгий критерий первых десяти мест или топ 15% учитывает только время; звёздочка сохраняет отдельную рейтинговую цель языка. У того же файла есть прежний Accepted на PyPy 3.10 №11325471: 0.125 с / 240 КБ. Это парные замеры разных запусков: CPython даёт выбранный результат по времени и рейтингу, PyPy расходует меньше памяти. Прежние замечания об экономии памяти в этом разделе относятся к этому замеру PyPy, а не к строке CPython. Все учебные исходники сохранены без изменений.

`1014_greedy_optimized.py`. Сохраняются жадное разложение по цифрам от 9 до 2 и разворот найденных цифр. Для нуля ответ 10, для единицы 1, остаточный множитель означает -1. Байтовый ввод и прямой ход программы заменяют input() и функцию-обёртку. Время и память для цифр остаются O(log(N+2)); асимптотическое ускорение не заявляется. В строке Accepted указаны фактическая среда судьи и парные время/память. Вывод сбрасывается до os._exit(0), пропускающего завершение интерпретатора; измеренный выигрыш памяти относится к этой среде и не означает асимптотического ускорения.

По сравнению с `1014_greedy.py`: время 0.093 s → 0.125 s; память 444 KB → 240 KB.

`1014_greedy_optimized.go`. Сохраняются разложение на цифры по убыванию и особые ответы10 для нуля,1 для единицы. Вместо добавления форматированной строки в начало при каждом множителе байты цифр пишутся в фиксированный массив из32ячеек и выводятся обратно. Каждый множитель не меньше двух, при N<=10^9 места достаточно. Исключены квадратичные копирования по числу множителей и повторное форматирование; буферы ввода256байт и вывода64байта заменяют fmt/строковые средства. Время O(log(N+2)), дополнительная память O(1) при заданной границе. Допуск обеспечен рейтингом, выигрыш30% не заявляется.

По сравнению с `1014_greedy.go`: время 0.031 s → 0.031 s; память 1096 KB → 788 KB.

Оптимизированное решение на Java разбирает число побайтно из `System.in`
вместо `Scanner`, а цифры дописывает в конец и разворачивает строку один
раз вместо вставки каждой цифры в начало: 380 КБ вместо 1604 КБ при том
же времени.
