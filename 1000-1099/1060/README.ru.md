# 1060. Наименьшее число переворотов, чтобы доска 4 × 4 стала одного цвета

[Timus 1060](https://acm.timus.ru/problem.aspx?space=1&num=1060) · сложность 378 · bruteforce, bitmask

Оригинальная задача — полуфинал ACM ICPC Северо-Восточной Европы 2000–2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

На доске 4 × 4 лежат фишки чёрной (`b`) или белой (`w`) стороной вверх.
Ход выбирает клетку и переворачивает фишку на ней и её соседей сверху,
снизу, слева и справа (те, что есть). Найдите наименьшее число ходов,
после которых все фишки показывают один цвет (любой), `0`, если это уже
так, или `Impossible`.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Четыре строки по четыре символа `b` и `w`.

## Выходные данные

Наименьшее число ходов или `Impossible`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
bwbw
wwww
bbwb
bwwb
```

Вывод:

```
Impossible
```

### Пример 2

Ввод:

```
bwwb
bbwb
bwwb
bwww
```

Вывод:

```
4
```

## Решение

Запишем доску как 16 бит; ход на клетке делает XOR доски с фиксированной
маской не более чем из пяти бит. XOR коммутативен, а маска, применённая
дважды, сокращается, поэтому порядок ходов не важен и ни на одной клетке
не нужно больше одного хода: решение — это просто множество клеток.

Множеств `2^16 = 65536`. Для каждого применяем XOR масок его клеток к
доске и запоминаем наименьшее множество, дающее все нули или все единицы.
`O(2^16 · 16)`.

Решаемы лишь 4096 из 65536 позиций, и ни одной не нужно больше шести
ходов (это показывает поиск в ширину по всем позициям, которым проверены
тесты).

Подводные камни:

- цель — и все белые, и все чёрные;
- клетки на краю и в углах переворачивают меньше фишек;
- позиции, уже одноцветной, нужно 0 ходов.

## Оптимизированные решения

Go перебирает 16 масок нажатий первой строки для каждого из двух целевых цветов. Каждое оставшееся несовпадение в строке вынуждает нажатие прямо под ним, поэтому остальные строки определяются однозначно. Считаются установленные биты нажатий. Вариант допустим, только если после последней строки нет несовпадений. Каждая строка поля занимает один байт. Python делит 16 клеток пополам и перебирает XOR-эффекты подмножеств нажатий каждой половины, сохраняя минимальное число нажатий для эффекта. Для каждого одноцветного результата и эффекта левой половины один поиск даёт нужный эффект правой половины. Время и память O(2^(C/2)), где C = 16 клеток. Go использует малые фиксированные байтовые буферы и стандартные дескрипторы напрямую, повторяет прерванные вызовы и завершает частичные записи.

Принятые базовые реализации [1060_bruteforce_bitmask.cpp](1060_bruteforce_bitmask.cpp), [1060_bruteforce_bitmask.java](1060_bruteforce_bitmask.java), [1060_bruteforce_bitmask.rs](1060_bruteforce_bitmask.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- **C++**, **Go**, **Java**, **Rust**: цикл по всем 65536 множествам.
- **Python**: доски всех множеств строятся по клетке, удваивая список
  (каждая новая клетка добавляет свою маску ко всем доскам), что избавляет
  от питоновского цикла по 16 битам каждого множества.
