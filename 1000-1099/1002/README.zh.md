# 1002. 用最少的单词拼出号码

[Timus 1002](https://acm.timus.ru/problem.aspx?space=1&num=1002) · 难度 225 · dp, hashing, strings

原题出自 1999 年中欧信息学奥林匹克竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

每个小写拉丁字母按下表编码为一位数字。给定最多 100 位的数字串和最多 50000 个单词，每词 1–50 个字母，选取可重复使用的词串联成该数字串，使词数最少。输入含多个测试，总大小不超过 300 KB。保留前导零。时间限制：2 秒；内存限制：64 MB。

| 数字 | 字母 |
|---|---|
| 0 | o q z |
| 1 | i j |
| 2 | a b c |
| 3 | d e f |
| 4 | g h |
| 5 | k l |
| 6 | m n |
| 7 | p r s |
| 8 | t u v |
| 9 | w x y |

## 输入

每例依次为数字串、字典词数、每行一个单词；单独一行 `-1` 结束输入。

## 输出

每例输出一个词数最少的序列，词间一个空格；无解时输出准确的 `No solution.`。

## 评测方式

接受任意一个最短序列：检查器会验证这些单词都在词典中、它们能拼出号码，并且不存在更短的
序列。

## 解法

令 `best[i]` 为拼出前 `i` 位的最少词数，起初仅 `best[0] = 0` 可达。
从每个可达位置出发，每个匹配后续子串的字典编码都给出一条到该子串末尾、代价为一的边。
位置严格递增，按前缀顺序即可求此 DAG 的最短路。记录最后选用的词并逆向恢复答案；
并列最优解均有效。

简单版本用哈希表保存“单词编码 → 一个代表词”。相同编码只需保留任意一个词。
每个可达位置只查长度 1 到 `W = 50` 的子串。设号码长为 `P`、字典总字符数为 `T`，
计入子串构造与哈希后，期望时间为 `O(T + P W²)`；空间取决于字典数据。
五份 Accepted 哈希版本全部原样保留。

## 优化解法

读字典之前，先对号码本身所有长度不超过 `W` 的子串建立 trie，
节点数至多 `1 + P W`。把字典词的编码沿此 trie 行走，缺少边就丢弃该词，
到达终点时仅保存一个代表词。无用单词不创建节点，也不保留字典记录；
大字典与短号码重合很少时尤其节省内存。

DP 从每个可达位置沿号码数字走 trie，无须分配和哈希子串。
所有可用词均在其中，因为其编码必须是号码子串；每个保留终点也确实对应字典词，
所以 DP 的边集合与最少词数不变。逆向恢复时，所选词长度给出前驱位置。

固定十数字字母表下，时间为 `O(T + P W)`，工作空间为 `O(P W + R)`，
其中 `R` 是保留代表词的字符量，另计输入输出缓冲。C++ 使用有界静态池并清理上一例的节点，
清理成本按所有测试合计。Go、Rust 流式读词；Java 重用词缓冲但累积输出行；
Python 用平坦整数转移数组。这是不同算法，标签为 `dp, strings`，不使用 `_optimized` 后缀。

五种版本都因相对同语言原哈希代码的实测内存改善超过阈值而准入。
接近单个计时刻度的差异不作为可靠加速证据。

实测内存减少：C++ 83.1%、Go 57.0%、Java 89.9%、Python 82.5%、Rust 76.7%。每份源码均有各自的 Accepted，提交 ID 见表。

## 各语言说明

Python 候选在 1802 例上与独立的位置 BFS 比较，该 BFS 枚举每个完整字典词。
另验证词属于字典、编码正确且词数最少，允许并列答案。覆盖编码碰撞、复用、无解、
前导零、50 字母单词、大量无关词以及大小测试交替。拼接的模糊测试流有意超过普通总文件限制，
仅作为状态清理与语义附加测试，不宣称是合法的 300 KB 输入。
五种实际程序还各自在 Docker 中通过仓库的 14 组输入。
