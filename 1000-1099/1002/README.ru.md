# 1002. Запись номера наименьшим числом слов

[Timus 1002](https://acm.timus.ru/problem.aspx?space=1&num=1002) · сложность 225 · dp, hashing, strings

Оригинальная задача — Центральноевропейская олимпиада по информатике 1999 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Каждая строчная латинская буква кодирует цифру по таблице ниже. Для строки не более чем из 100 цифр и словаря не более 50000 слов длиной 1–50 букв подберите конкатенацию слов с минимальным числом слов. Повторное использование разрешено. Во входе несколько случаев, общий размер не более 300 КБ. Начальные нули сохраняются. Лимит времени: 2 секунды. Память: 64 МБ.

| Цифра | Буквы |
|---|---|
| 0 | o q z |
| 1 | i j |
| 2 | a b c |
| 3 | d e f |
| 4 | g h |
| 5 | k l |
| 6 | m n |
| 7 | p r s |
| 8 | t u v |
| 9 | w x y |

## Входные данные

В каждом случае: строка цифр, строка с числом слов, затем по одному слову в строке. Строка `-1` завершает ввод.

## Выходные данные

Для каждого случая выведите минимальную последовательность слов через одиночные пробелы либо точно `No solution.`, если решения нет.

## Проверка

Принимается любая кратчайшая последовательность: чекер проверяет, что слова
есть в словаре, что они записывают номер и что более короткой
последовательности не существует.

## Примеры

### Пример 1

Ввод:

```
8733
3
use

tree

2

-1
```

Вывод:


### Пример 2

Ввод:

```

```

Вывод:

```

```

## Решение

Пусть `best[i]` — минимальное число слов для первых `i` цифр.
Изначально достижимо только `best[0] = 0`. Из каждой достижимой позиции
совпавшее с дальнейшей подстрокой словарное кодирование задаёт переход
к её концу со стоимостью один. Позиции строго растут, поэтому порядок
префиксов вычисляет кратчайшие пути в этом DAG. Последнее выбранное слово
позволяет восстановить минимум назад. При равенстве подходит любой вариант.

Простые версии хранят хеш-таблицу: кодирование слова → один представитель.
Для нескольких слов с одинаковым кодированием достаточно любого одного.
В каждой достижимой позиции проверяются подстроки длины от 1 до `W = 50`.
При длине номера `P` и суммарной длине словаря `T` ожидаемое время
`O(T + P W²)` учитывает построение и хеширование подстрок; память зависит
от словарных данных. Все пять Accepted-версий с хешированием сохранены
без изменений.

## Оптимизированные решения

До чтения словаря строим trie всех подстрок самого НОМЕРА длиной
не более `W`. В нём не более `1 + P W` вершин. Кодирование каждого слова
проводим по этому trie: если перехода нет, слово отбрасывается. В конечной
вершине сохраняем одного представителя. Бесполезное слово не создаёт
ни вершины, ни сохраняемой словарной записи. Это особенно полезно при
большом словаре и малом числе совпадений с коротким номером.

В DP из каждой достижимой позиции идём по цифрам номера через переходы,
не выделяя и не хешируя подстроки. Любое пригодное слово присутствует,
поскольку его кодирование — подстрока номера; каждая сохранённая конечная
вершина соответствует реальному слову. Значит, набор переходов DP и
минимальный ответ сохраняются. При восстановлении длина слова задаёт
предыдущую позицию.

При фиксированном алфавите из десяти цифр время — `O(T + P W)`, рабочая
память — `O(P W + R)`, где `R` — объём сохранённых слов-представителей,
плюс буферы ввода-вывода. C++ выделяет ограниченный статический пул и
очищает вершины предыдущего случая; затраты очистки учитываются суммарно
по случаям. Go и Rust читают слова потоком; Java переиспользует буфер
токена, но накапливает строки вывода. Python хранит переходы плоским
целочисленным массивом. Это другой алгоритм с тегами `dp, strings`,
а не файл с суффиксом `_optimized`.

Все пять версий проходят порог по измеренному сокращению памяти
относительно неизменённого хеширования на том же языке. Разницы времени
около одного тика таймера не считаются надёжным подтверждением ускорения.

Измеренное сокращение памяти: C++ 83.1%, Go 57.0%, Java 89.9%, Python 82.5%, Rust 76.7%. У каждого файла есть собственный Accepted с ID в таблице.

## Особенности языков

Python-кандидат проверен на 1802 случаях независимым BFS по позициям
с перебором всех полных слов. Проверяются принадлежность словарю,
кодирование и минимальность числа слов, допускаются равные ответы.
Есть коллизии кодирований, повторное использование, невозможные строки,
начальные нули, слова длины 50, большие бесполезные словари и чередование
больших и малых случаев. Объединённый fuzz-поток намеренно превышает
обычный лимит всего файла: это дополнительная проверка сброса состояния
и семантики, а не заявленный корректный вход размером 300 КБ. Все пять
реальных программ также прошли 14 входов репозитория в Docker.
