# 1091. Подсчёт наборов чисел с общим делителем

[Timus 1091](https://acm.timus.ru/problem.aspx?space=1&num=1091) · сложность 529 · number_theory

Автор оригинальной задачи — Станислав Васильев; USU Open Collegiate Programming Contest, март 2001 года, Senior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Посчитайте наборы из `K` различных натуральных чисел, не больших `S`
(`2 ≤ K ≤ S ≤ 50`), наибольший общий делитель которых больше 1.
Выведите их количество или 10000, если оно больше.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`K` и `S`.

## Выходные данные

Число наборов, не больше 10000.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3 10
```

Вывод:

```
11
```

## Решение

Предпочтительная учебная Go-версия считает наборы по точному НОД без функции Мёбиуса. При K>floor(S/2) ни у одного делителя≥2 нет K кратных. Иначе нужны только C(m,K) при K≤m≤floor(S/2): начинаем с1 и используем C(m,K)=C(m−1,K)·m/(m−K). Для d от D=floor(S/K) до2 берём C(floor(S/d),K) наборов кратных d и вычитаем уже найденные количества с точными НОД2d,3d,… . У набора ровно один НОД, поэтому классы не пересекаются, а сумма для d≥2 даёт ответ. При K=3 и S=10 точный НОД 3 даёт C(3,3)=1 набор, точный НОД 2 — C(5,3)=10 наборов, всего 11. Если C(m,K) достиг 10 000, выбор K из первых m чётных чисел уже даёт достаточно допустимых наборов для ответа 10 000. До этого умножаем число меньше 10 000 на m ≤ 25. Количество наборов с точным НОД ограничено своим биномиальным коэффициентом, поэтому прибавление к сумме меньше 10 000 даёт значение меньше 20 000. Ответ ограничен 10 000. Время O(S + D log D), память O(S). Исходные версии считают знакопеременную сумму Σ−μ(d)C(floor(S/d),K) по полной таблице Паскаля и ограничивают окончательный результат.

## Оптимизированные решения

Оптимизированная версия Go сохраняет подсчёт по точному НОД, читает и пишет через стандартные дескрипторы и хранит ответ в буфере на шесть байтов. Rust использует тот же алгоритм точного НОД в отдельном быстром порте с фиксированными32-битными массивами, символьным C runtime и точкой входа C. C++/Java/Python используют подходящие исходные программы. D=floor(S/K)≤25, готовых таблиц ответов нет. Прежний Go сохранён в других подходах, прежний Rust — как обычная версия со стандартной библиотекой. Звёздочки относятся к рейтинговым целям языка.

Принятые базовые реализации [1091_number_theory.cpp](1091_number_theory.cpp), [1091_number_theory.java](1091_number_theory.java), [1091_number_theory.py](1091_number_theory.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

`1091_number_theory_optimized.java`. Java сохраняет алгоритм и структуры данных, описанные для простой версии. Фиксированный байтовый буфер и FastInput заменяют Scanner с его регулярными выражениями и обработкой локали. Целые числа разбираются напрямую; строки при необходимости по-прежнему декодируются из UTF-8, десятичные токены явно преобразуются в числа. Предварительный просмотр хранит токен только при необходимости. Алгоритм вывода не меняется. Убираются накладные расходы универсального разбора; в таблице указана работа алгоритма, а чтение линейно по числу байтов с ограниченным буфером.

По сравнению с `1091_number_theory.java`: время 0.109 s → 0.093 s; память 1640 KB → 492 KB.

## Особенности языков

Учебный Go-порт использует обычный буферизированный ввод и два массива по26 целых. Rust — два массива u32 по26 и C runtime без указателей в getchar/putchar. Для ответа до10000 достаточно пяти цифр. Все исходные программы сохраняют собственные точные Accepted и метрики, Python — фактический принятый интерпретатор.
