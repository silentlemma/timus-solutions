# 1048. Сложение двух чисел из миллиона цифр

[Timus 1048](https://acm.timus.ru/problem.aspx?space=1&num=1048) · сложность 201 · implementation

Авторы оригинальной задачи — Станислав Васильев и Александр Клепинин; студенческое соревнование по программированию УрГУ, 25 марта 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Два положительных целых числа имеют по `N` цифр (`1 ≤ N ≤ 10^6`, ведущие
нули допускаются), и их сумма тоже помещается в `N` цифр. Числа заданы
столбиком: в строке `i` записаны `i`-е цифры обоих чисел. Выведите сумму
ровно из `N` цифр.

Ограничение времени: 2 секунды. Ограничение памяти: 16 МБ.

## Входные данные

`N`, затем `N` строк с двумя цифрами через пробел.

## Выходные данные

`N` цифр суммы в одной строке.

## Проверка

Вывод сравнивается по токенам и содержит ровно `N` цифр.
Реальный кандидат Python проверен на 610 сложениях: 600 случайных
положительных операндов до 300 цифр против целочисленного сложения
произвольной точности и десять аналитических случаев переноса/ведущих
нулей длиной 2, 3, 31, 1000 и 1000000. Длинная цепочка переноса проходит
через всё число, другая крайность сохраняет много ведущих нулей.
Все входы соблюдают отсутствие переполнения, миллионные ожидаемые ответы
не получены преобразованием операндов в целые. Реальные Python и Rust
также прошли по 14 входов репозитория в Docker и получили собственные
Accepted точных исходников. 610 проверок эталоном — запуски Python,
а не по 610 запусков каждого компилируемого языка.

## Примеры

### Пример 1

Ввод:

```
4
0 4
4 2
6 8
3 7
```

Вывод:

```
4750
```

### Пример 2

Ввод:

```
3
0 0
4 5
5 5
```

Вывод:

```
100
```

## Решение

Складываем столбцы справа налево. Для суммы цифр `s` и входящего
переноса `c` записываем `(s + c) mod 10`, а влево передаём
`(s + c) div 10`. Начальный перенос — ноль. При `0 ≤ s ≤ 18` перенос
всегда равен 0 или 1, промежуточное значение не больше 19. По индукции
обработанный суффикс содержит младшие цифры его суммы, а оставшийся
перенос передаётся влево. Гарантия длины суммы не больше `N` даёт нулевой
последний перенос. Сохраняем все `N` цифр, включая ведущие нули;
лишнюю цифру переноса не выводим.

Нативные базы хранят суммы столбцов в байтах и переиспользуют массив
под ответ. Последний байт буфера `N + 1` — перевод строки, а не новая
старшая цифра. Понятная база Python читает вход целиком, удаляет пробелы,
выделяет две байтовые строки операндов и выполняет тот же обратный проход.
База Rust хранит весь вход помимо массива столбцов/ответа. Время и память
всех версий — `O(N)`. Все пять исходных Accepted-баз сохранены побайтово.

## Оптимизированные решения

Новые Python и Rust отбрасывают прочитанный вход, сохраняя только
суммы столбцов `0..18` в одном байтовом буфере `N + 1`. Обратный проход
заменяет их на ASCII-цифры ответа; последний байт остаётся переводом
строки. Отдельные операнды и весь вход не нужны: от каждой пары цифр
сложению требуется только сумма. Сам буфер занимает `N + 1` байт
без среды выполнения и буферов ввода-вывода. Время и память остаются
`O(N)`; меняются хранение и ввод-вывод того же сложения в столбик,
поэтому суффикс — `_optimized`.

Python читает указанные строки пар цифр по одной, Rust после `N`
отбирает ASCII-цифры из заблокированного входного потока. Оба пишут
готовый байтовый буфер напрямую, не превращая миллион цифр каждого
операнда в одно целое число.

Accepted точного Python: 0,593 с / 1392 КБ против базовых 0,406 с /
10360 КБ — памяти меньше на 86,6%, записанное время больше на 46,1%.
Rust: 0,046 с / 1144 КБ против 0,015 с / 10248 КБ — памяти меньше
на 88,8%, но записанное время выше. Обе версии проходят по памяти,
не по ускорению. Более простые базы с меньшим записанным временем остаются.

## Особенности языков

Срез — 2 ноября 2026 года. У исходного C++ места 1 по времени
и 5 по памяти против 234 отфильтрованных посылок других авторов;
Java первая по обеим метрикам против шести. Выборка Go пуста:
формальное покрытие не доказывает конкурентного превосходства.
Оптимизированный Rust первый по обеим против одной посылки. У нового
Python места 7 и 1 против восьми, звёздочка остаётся: согласованный
профиль требует для C++ топ 15% или первые 10 мест по обеим метрикам,
для остальных семейств — первое место по обеим. Выигрыш памяти Python
всё равно удовлетворяет допуску независимо от рейтинга.
