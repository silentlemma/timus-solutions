# 1099. 给夜班警卫配对：一般图的最大匹配

[Timus 1099](https://acm.timus.ru/problem.aspx?space=1&num=1099) · 难度 1144 · matching, graphs

原题作者：Jivko Ganev。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

有 `N ≤ 222` 名警卫，以及一串可以一起值班的警卫对（直到输入结束）。每名警卫至多与一名搭档一起工作，没有人单独值班。
安排尽可能多的警卫：输出人数以及各对。

时间限制：0.5 秒。内存限制：64 MB。

## 输入

`N`，然后是若干对 `i j`，直到输入结束。

## 输出

安排的警卫人数 `C`，然后 `C/2` 对。

## 评测方式

接受任何一个最大的配对集合。检查程序验证人数等于最大值，并且每一对都是允许的，每名警卫至多用一次。

## 样例

### 样例 1

输入：

```
3
1 2
2 3
1 3
```

输出：

```
2
1 2
```

## 题解

这是一般图的最大匹配。与二分图不同，一般图有奇环，所以普通的增广路不够用。Edmonds 的带花树算法可以处理它们。
先求一个贪心匹配。然后从每个未匹配的警卫出发，用广度优先搜索生长交错树：从外点 `v` 出发，未匹配的邻居 `to`
结束一条增广路；已匹配的邻居与它的搭档一起进入树中。当 `v` 遇到另一个外点时，两条树上的路径和它们之间的边
构成一个奇环（花）。花上的顶点获得花的基点（最近公共祖先），变成外点并进入队列，环上的父指针被设置成仍然可以
沿着穿过花的路径走下去。找到增广路后，沿路交换匹配边与非匹配边，匹配数加一。`O(N³)`。

注意事项：

- 没有给出配对的数量，所以要一直读到输入结束；
- 一对可能重复出现或以两种顺序出现，而警卫不能和自己配对，所以这样的行要忽略；
- 没有任何配对的图输出 `0`，此外什么都不输出。

检查程序依赖期望的人数；这些人数用随机 Tutte 矩阵模大素数的秩（等于最大匹配大小的两倍）在所有测试以及数百个
随机小图上做了核对。

## 各语言说明

- Rust 把搜索用到的数组放在 `Matcher` 结构体里，因为辅助函数会修改它们。
- Java 和 C++ 用集合构造有序的邻接表，从而去掉重复的配对。
