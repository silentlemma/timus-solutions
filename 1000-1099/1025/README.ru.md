# 1025. Наименьшее число сторонников для двухуровневого большинства

[Timus 1025](https://acm.timus.ru/problem.aspx?space=1&num=1025) · сложность 67 · greedy, sorting

Оригинальная задача — второе командное соревнование школьников Свердловской области по программированию, 7 октября 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Избиратели разделены на `K` групп (`K` нечётно, `1 ≤ K ≤ 101`), каждая
нечётного размера; всего не больше 9999 человек. Группа говорит «за», если
«за» голосует больше половины её членов, а решение принимается, если «за»
высказывается больше половины групп. Найдите наименьшее число сторонников,
которые при правильном распределении по группам проведут любое решение.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`K`, затем `K` размеров групп.

## Выходные данные

Наименьшее число сторонников.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
5
9 3 11 1 7
```

Вывод:

```
7
```

### Пример 2

Ввод:

```
1
9999
```

Вывод:

```
5000
```

## Решение

Чтобы провести решение, сторонники должны выиграть `K / 2 + 1` групп
(целочисленное деление, `K` нечётно), а чтобы выиграть группу из `s`
человек (`s` нечётно), нужно `s / 2 + 1` сторонников; лишние в этой группе
пропадают зря, как и сторонники в проигранных группах.

Значит, нужно выбрать `K / 2 + 1` групп с наименьшей суммарной стоимостью
`s / 2 + 1`. Стоимость растёт с размером, поэтому лучшие группы — просто
самые маленькие: сортируем размеры и складываем стоимости первых
`K / 2 + 1`. `O(K log K)`.

Подводные камни:

- большинство групп — это `K / 2 + 1`, а большинство в группе из `s` —
  `s / 2 + 1`, а не `s / 2`;
- во входе размеры не упорядочены.

## Оптимизированные решения

`1025_greedy_sorting_optimized.py`. Python по-прежнему сортирует размеры групп и выбирает floor(K/2)+1 наименьших. Все размеры нечётны, поэтому число сторонников равно (sum(selected_sizes)+needed)//2: одна сумма на уровне C и одно деление заменяют Python-генератор с делением для каждой группы. Читаются двоичные токены целых, ответ записывается один раз, выход происходит внутри main до очистки локальных данных. Время O(K log K), отсортированные данные O(K), в процессе также хранится прочитанный ввод. Это тот же жадный выбор большинства. Наглядная база с ценой каждой группы сохранена.

`1025_greedy_sorting_optimized.java`. Java сохраняет жадный выбор наименьшего большинства: выиграть floor(K/2)+1 самых маленьких групп, затратив floor(size/2)+1 сторонников на каждую. При K<=101 очередной размер вставляется на своё место в отсортированном массиве int без загрузки Arrays.sort. Это намеренная замена сортировки O(K log K) ограниченным перебором O(K^2), чтобы уменьшить накладные расходы запуска библиотеки, а не асимптотическое улучшение. Буфер ввода на 1024 байта и прямой десятичный вывод обходятся без Scanner и строк чисел. Дополнительная память O(K); простая учебная версия с библиотечной сортировкой сохранена.

`1025_greedy_sorting_optimized.go`. Go сохраняет жадный выбор большинства самых малых групп. Оптимизированный исходник читает байты напрямую и вставляет каждую группу в один фиксированный массив максимум из 101 элемента. Здесь намеренно используется сортировка вставками: O(K²) вместо O(K log K) у базовой сортировки, зато при малом ограничении нет её динамических контейнеров и накладных расходов fmt. Для первых floor(K/2)+1 групп суммируем floor(size/2)+1. Исходник с библиотечной сортировкой сохранён.

По сравнению с `1025_greedy_sorting.go`: время 0.031 s → 0.015 s; память 1076 KB → 796 KB.
