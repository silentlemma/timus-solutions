# 1000. Сумма двух целых чисел

[Timus 1000](https://acm.timus.ru/problem.aspx?space=1&num=1000) · сложность 16 · math

Автор оригинальной задачи: Павел Атнашев.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны два целых числа `a` и `b`. Выведите их сумму `a + b`.

В оригинальной задаче ограничения на `a` и `b` не указаны; в решениях с
фиксированной разрядностью оба слагаемых и их сумма должны помещаться
в знаковое 64-битное целое.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Два целых числа `a` и `b`, разделённые пробельными символами (пробелом или
переводом строки).

## Выходные данные

Одно целое число: `a + b`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
2 3
```

Вывод:

```
5
```

### Пример 2

Ввод:

```
2000000000 2000000000
```

Вывод:

```
4000000000
```

## Решение

Считать два числа и вывести их сумму. Время и память — `O(1)`.

Подводные камни:

- сумма двух чисел, каждое из которых помещается в 32 бита, может в 32 бита не
  поместиться, поэтому для слагаемых и результата используется 64-битный тип;
- числа читаются как токены, разделённые пробельными символами, поэтому неважно,
  стоят они в одной строке или в двух.

## Оптимизированные решения

`1000_math_optimized.go`. Сумма по-прежнему вычисляется для двух int64 с постоянной памятью. Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1000_math.go`: время 0.015 s → 0.001 s; память 1060 KB → 256 KB.

Оптимизированное решение на Java разбирает два числа побайтно из
`System.in` вместо `Scanner`: 0.046 с вместо 0.078 с и 336 КБ вместо
1548 КБ.

Новая версия Python читает байты без декодирования всего ввода, явно
сбрасывает вывод и завершает процесс без обычного завершения интерпретатора.
Её собственная Accepted-посылка занимает 0.046 с вместо 0.078 с у простой
версии: выигрыш времени 41.0%, но память выросла со 132 КБ до 656 КБ.
Короткую простую версию сохраняем. Вариант Rust разбирает и выводит знаковые
целые через среду выполнения C, без строк ввода-вывода Rust и форматирования:
память уменьшилась с 228 КБ до 52 КБ, на 77.2%. В обоих случаях алгоритм
сложения и постоянная дополнительная память сохраняются. Звёздочка у новой
строки Python означает, что строгая рейтинговая цель языка не достигнута;
версия допущена благодаря выигрышу времени.

## Особенности языков

- **C++**: `long long` и `scanf("%lld %lld")`.
- **Go**: `int64` и `fmt.Scan`, который пропускает любые пробельные символы.
- **Python**: целые числа произвольной точности; чтение всех токенов через
  `sys.stdin.read().split()` работает при любом расположении по строкам.
- **Java**: простое решение использует `long` и `Scanner`.
- **Rust**: прочитать весь ввод в `String`, разбить по пробельным символам и
  разобрать `i64`.
