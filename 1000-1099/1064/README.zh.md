# 1064. 二分查找恰在指定步数结束的数组长度

[Timus 1064](https://acm.timus.ru/problem.aspx?space=1&num=1064) · 难度 656 · simulation

原题出自 2000–2001 年 ACM ICPC 东北欧区域赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

在非降数组 `A[0 … N−1]` 上的经典二分查找维护边界 `p = 0`、`q = N − 1`；当 `p ≤ q` 时取 `i = ⌊(p + q)/2⌋`，
计一次比较，若 `A[i] = x` 则停止，否则把 `q` 移到 `i − 1`（当 `x < A[i]`）或把 `p` 移到 `i + 1`。已知它恰在第
`L` 次比较时停在下标 `i`（`0 ≤ i ≤ 9999`，`1 ≤ L ≤ 14`）。求 1 到 10000 中所有可能的长度 `N`，并把连续的值
合并成区间。

时间限制：1 秒。内存限制：64 MB。

## 输入

`i` 和 `L`。

## 输出

区间个数 `K`，然后 `K` 行，按升序给出每个区间的首尾长度；若没有则输出 `0`。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 样例

### 样例 1

输入：

```
9000 2
```

输出：

```
0
```

### 样例 2

输入：

```
10 3
```

输出：

```
4
12 12
17 18
29 30
87 94
```

## 题解

长度 `N` 固定时，比较过程不取决于具体的值，只取决于查找往哪边走。要停在下标 `i`，`i` 之前被查看的元素都必须
让查找往右走，`i` 之后的都必须让它往左走——在 `i` 之前放较小的值、之后放较大的值的数组正好如此。因此查找路径
是确定的：从 `[0, N − 1]` 开始，取中点，若是 `i` 就停止，否则保留包含 `i` 的那一半。若这条路径恰好在第 `L`
次比较时遇到 `i`（且 `i < N`），`N` 就符合要求。

枚举所有 `N`：每个最多 14 步，`O(10000 · log 10000)`，再把连续的合格长度合并成区间。

注意事项：

- `i` 必须是数组的下标：`N > i`；
- 查找可能比 `L` 更早或更晚到达 `i`；只有恰好 `L` 次才算；
- 答案可能为空：只输出 `0`。

## 各语言说明

- 各语言对每个长度模拟同样的路径。
