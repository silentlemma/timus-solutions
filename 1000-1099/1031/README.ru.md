# 1031. Самый дешёвый набор железнодорожных билетов с тремя тарифами

[Timus 1031](https://acm.timus.ru/problem.aspx?space=1&num=1031) · сложность 390 · dp, two_pointers

Оригинальная задача — III командный студенческий чемпионат Урала по программированию, 1999 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` станций (`2 ≤ N ≤ 10 000`) лежат на прямой; станция 1 на расстоянии 0,
остальные — на заданных возрастающих расстояниях (не больше `10^9`, соседние
станции не дальше `L3` друг от друга). Билет оплачивает одну поездку между
двумя станциями на расстоянии `X`: стоит `C1`, если `X ≤ L1`, `C2`, если
`L1 < X ≤ L2`, `C3`, если `L2 < X ≤ L3`, а для более длинных поездок нужно
несколько билетов с пересадками на станциях (`1 ≤ L1 < L2 < L3 ≤ 10^9`,
`1 ≤ C1 < C2 < C3 ≤ 10^9`). Найдите самый дешёвый способ проехать между
двумя данными станциями; ответ не превосходит `10^9`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`L1 L2 L3 C1 C2 C3`, затем `N`, затем две станции (в любом порядке), затем
`N - 1` расстояний станций 2..`N` от станции 1.

## Выходные данные

Наименьшая суммарная стоимость.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3 6 8 20 30 40
7
2 6
3
5
9
12
17
19
```

Вывод:

```
70
```

### Пример 2

Ввод:

```
1 2 3 1 2 3
2
2 1
1
```

Вывод:

```
1
```

## Решение

Меняем станции местами так, чтобы `a < b`; ехать назад никогда не выгодно.
Пусть `cost[i]` — самый дешёвый путь от `a` до станции `i`, `cost[a] = 0`;
последний билет идёт от некоторой станции `j` до `i` и стоит по тарифу
расстояния `x[i] - x[j]`.

**Квадратичная динамика.** Перебираем все `j` с `x[i] - x[j] ≤ L3`. Это до
`N^2 / 2 = 5·10^7` шагов, когда билет достаёт далеко, — хватает на C++, но
не на Python.

**Три указателя.** `cost` не убывает вдоль линии: путь до станции `i + 1`
заканчивается билетом от некоторой `j`, а билет от `j` до `i` не длиннее, а
значит, не дороже. Поэтому для билета тарифа `k` лучшее начало — **самая
дальняя** станция `j` с `x[i] - x[j] ≤ Lk`: у неё наименьший `cost` среди
всех начал, достижимых этим тарифом. С ростом `i` эти самые дальние начала
только двигаются вперёд, так что держим по указателю на тариф и сдвигаем
его, пока расстояние больше `Lk`. На каждом шаге три кандидата: всего
`O(N)`.

Подводные камни:

- станции могут быть даны в убывающем порядке;
- билет дешёвого тарифа годится для любой более короткой поездки, так что
  поездка длины `X ≤ L1` стоит `C1`, а не `C3`;
- ответ помещается в 32 бита, но для сумм всё равно используйте 64-битные
  целые.

## Особенности языков

- **C++**, **Go**, **Python**, **Java**, **Rust**: три указателя.
- **C++** — ещё и квадратичная динамика.
