# 1031. 三档票价下最便宜的火车票组合

[Timus 1031](https://acm.timus.ru/problem.aspx?space=1&num=1031) · 难度 392 · dp, two_pointers

原题出自 1999 年第三届乌拉尔大学生团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

`N` 个车站（`2 ≤ N ≤ 10 000`）位于一条直线上；1 号站在距离 0 处，其余站在给定的递增距离处（不超过
`10^9`，相邻车站相距不超过 `L3`）。一张票覆盖两站之间距离为 `X` 的一次乘车：若 `X ≤ L1` 票价为 `C1`，
`L1 < X ≤ L2` 为 `C2`，`L2 < X ≤ L3` 为 `C3`；更长的行程需要在车站换乘、买多张票
（`1 ≤ L1 < L2 < L3 ≤ 10^9`，`1 ≤ C1 < C2 < C3 ≤ 10^9`）。求两个给定车站之间最便宜的走法；答案不超过 `10^9`。

时间限制：1 秒。内存限制：64 MB。

## 输入

`L1 L2 L3 C1 C2 C3`，然后是 `N`，再是 `1..N` 内两个不同的站号
（顺序任意）。接下来 `N - 1` 行给出 2..`N` 号站距 1 号站的距离：
互不相同的正整数，按递增顺序排列。

## 输出

最小的总票价。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 题解

交换两站使 `a < b`；往回坐从来没有好处。设 `cost[i]` 为从 `a` 到 `i` 号站的最低花费，`cost[a] = 0`；
最后一张票从某站 `j` 到 `i`，票价按距离 `x[i] - x[j]` 所在档位计算。

**平方级 DP。** 枚举所有满足 `x[i] - x[j] ≤ L3` 的 `j`。当一张票能覆盖很远时，最多 `N^2 / 2 = 5·10^7` 步——
C++ 足够，Python 不行。

**三个指针。** `cost` 沿线路不减：到 `i + 1` 站的走法以从某站 `j` 出发的票结束，而从 `j` 到 `i` 的票不更长，
因此不更贵。所以对第 `k` 档的票，最好的起点是满足 `x[i] - x[j] ≤ Lk` 的 **最远** 车站 `j`——在该档能到达的
所有起点中它的 `cost` 最小。随着 `i` 增大，这些最远起点只会向前移动，因此每档维护一个指针，距离超过 `Lk`
时就前移。每一步只比较三个候选：总计 `O(N)`。

两种 DP 都存储 `O(N)` 个位置和费用，三个指针只增加常数状态。简单
Python、Rust 另存全部输入 `O(I)`，`I` 为输入长度。优化 Python 使用
`O(N)` 紧凑数组及有界输入块。优化 Rust 只存区间内
`K = b - a + 1` 个位置和费用，占 `O(K)`。优化 Go 为上限 10000
个站预留固定数组；容量随站数上限线性增长，并非与该上限无关的常数空间。

注意事项：

- 两个车站可能按递减顺序给出；
- 便宜档的票适用于任何更短的行程，所以长度 `X ≤ L1` 的行程花 `C1`，而不是 `C3`；
- 答案在 32 位以内，但求和时仍建议用 64 位整数。

## 优化解法

Go 和 Rust 为每种票价维护一个向前移动的指针，指向该票可覆盖的最早车站。到达各站的最低费用单调不减，因此这个指针给出了该票价下最便宜的前驱站。两个版本按顺序读取位置，只保留起终点之间的区间，位置和费用均用 32 位整数保存。Go 使用最多容纳 10000 个站点的固定数组，并直接进行字节输入输出。

三指针 C++ 和 Java 基础程序也覆盖快速版本，无需复制文件。统一
[排名标准](../../RATING_CRITERIA.md) 对其低于 1 MiB 的测量只比较时间。
简单 Python 保留为教学版：1684 KB 超过缓存中的小样本内存阈值；
优化 Python 为 896 KB，只比较时间即可通过，因此由该独立源文件
覆盖 Python 快速版本。
