# 1019. Самый длинный белый интервал после перекрашиваний прямой

[Timus 1019](https://acm.timus.ru/problem.aspx?space=1&num=1019) · сложность 465 · sorting, dsu

Оригинальная задача — Ural State University Internal Contest '99 #2.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Отрезок `[0, 10^9]` числовой прямой белый. Затем по порядку выполняются `N`
перекрашиваний (`1 ≤ N ≤ 5000`): `i`-е красит отрезок от `a_i` до `b_i`
(`0 < a_i < b_i < 10^9`, целые) в белый или чёрный цвет. Найдите самый
длинный белый интервал результата; среди интервалов одной длины возьмите
самый левый.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк `a b c`, где `c` — `w` (белый) или `b` (чёрный).

## Выходные данные

Концы `x y` (`x < y`) самого длинного белого интервала.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4
2 999999998 b
100 500 w
500 900 w
300 310 b
```

Вывод:

```
310 900
```

### Пример 2

Ввод:

```
1
1 999999999 w
```

Вывод:

```
0 1000000000
```

## Решение

Соберём 0, 10⁹ и все концы перекрашиваемых отрезков, отсортируем и удалим повторы. Между соседними координатами цвет постоянен. Перекрашиваем эти части в порядке ввода, затем просматриваем слева направо, объединяя соседние белые части. Сравниваем физическую длину, а не число частей, и обновляем ответ только при строгом увеличении: так сохраняется самый левый из равных интервалов. Частей не больше 2N+1, поэтому после сортировки O(N log N) прямое перекрашивание занимает O(N²) времени и O(N) памяти. При N ≤ 5000 это не более 50005000 присваиваний. Python перекрашивает срез bytearray, внутреннее копирование которого выполняется нативным кодом; теперь этот простой алгоритм проходит на всех пяти языках. Касающиеся белые части объединяются. Границы 0 и 10⁹ обязательны, а нетронутый префикс [0,min a) гарантирует наличие белого ответа.

## Оптимизированные решения

DSU-версии выполняют перекрашивания в обратном порядке. Структура преемников находит первую часть, ещё не окрашенную более поздним действием; после присваивания связываем её со следующей. Каждая часть окрашивается не больше одного раза. Сортировка и поиск концов дают O(N log N) времени и O(N) памяти. Принятый Go-исходник использует 592 KB при 0.031 с вместо 1784 KB при 0.031 с у прямого перекрашивания: памяти меньше на 66.8%. Исходные принятые DSU-версии C++ и Python сохранены. Python DSU использует 3560 KB при 0.078 с, новая простая Python-версия — 5 464 KB при 0.093 с. Более простой алгоритм сохранён для обучения, хотя обе метрики хуже. C++ DSU использует 212 КБ вместо 208 КБ у прямой версии; разница 0.031–0.015 с составляет один тик, поэтому в быстрый набор он включён по сохранённому рейтингу, а не по заявленному ускорению на 30%. Java и Rust закрывают быстрые семейства теми же прямыми файлами из таблицы простых решений, без одинаковых копий.

## Особенности языков

Прямое простое перекрашивание теперь имеет Accepted на всех пяти языках. DSU — другой алгоритм с отдельными именами файлов. Новый Go DSU использует стандартные дескрипторы и компактные массивы примитивных значений. Все прежние файлы и исторические метрики Accepted сохранены. Звёздочки относятся к выбранным быстрым версиям, пока не достигшим рейтинговой цели своего языка.
