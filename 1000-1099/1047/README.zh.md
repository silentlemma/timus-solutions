# 1047. 二阶递推的第一个未知项

[Timus 1047](https://acm.timus.ru/problem.aspx?space=1&num=1047) · 难度 305 · math

原题作者 Dmitry Filimonenkov，出自 2000 年 3 月 25 日乌拉尔国立大学大学生程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

序列 `a0, a1, …, aN+1`（`1 ≤ N ≤ 3000`，`−2000 ≤ ai ≤ 2000`）对每个 `i = 1 … N` 满足
`ai = (ai−1 + ai+1) / 2 − ci`。给定都带两位小数的 `a0`、`aN+1` 和 `c1 … cN`，求 `a1`。

时间限制：1 秒。内存限制：64 MB。

## 输入

`N`，然后是 `a0`、`aN+1`，再然后是 `c1 … cN`，每行一个数。

## 输出

带两位小数的 `a1`。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 样例

### 样例 1

输入：

```
1
50.50
25.50
10.15
```

输出：

```
27.85
```

### 样例 2

输入：

```
2
0.00
9.00
1.00
1.00
```

输出：

```
1.00
```

## 题解

用差分 `d[i] = a[i] − a[i−1]` 改写关系式：

```text
a[i+1] − 2·a[i] + a[i−1] = 2·c[i]   →   d[i+1] = d[i] + 2·c[i]
```

所以 `d[k] = d[1] + 2·(c[1] + … + c[k−1])`；把 `d[1]` 到 `d[N+1]` 的所有差分加起来，每个 `c[i]` 出现
`N + 1 − i` 次：

```text
a[N+1] − a[0] = (N + 1)·d[1] + 2 · Σ (N + 1 − i)·c[i]
a[1] = a[0] + d[1] = (N·a[0] + a[N+1] − 2 · Σ (N + 1 − i)·c[i]) / (N + 1)
```

`O(N)`。为避免舍入问题，C++、Go、Java 和 Rust 以百分之一为单位计算：所有输入都变成整数，分子不超过约 `10^12`，
除以 `N + 1` 的结果舍入到最近的百分之一。

公式只有常数个累加器。简单 C++/Go/Java 逐步读取，使用有界缓冲或
当前词元/行。简单 Rust 保存 O(I) 输入字节；Python 另存 O(N) 个分数，
共 O(I+N)。I 为输入长度。优化 Go/Rust 使用固定缓冲；精确算术的位成本
还取决于整数长度。

注意事项：

- 3000 个浮点数相加可能产生累积误差，而输出必须恰好两位小数；用以百分之一为单位的整数可以同时避免这两个问题；
- −1 到 0 之间的负数答案要输出为 `-0.35`，而不是 `0.35` 或 `-0.-35`。

## 优化解法

Go 和 Rust 将两位小数输入解析为有符号整数分。读取时累加系数的加权和，再将 N·a₀ + aₙ₊₁ − 2Σ(N+1−i)cᵢ 除以 N+1。先把绝对值四舍五入到最近的一分，恰好居中时远离零，再恢复符号。舍入后的零不带负号。两个版本均使用固定字节缓冲区读取和格式化数值，不进行字符串转换。

配对 Accepted：Go 仍为 0.015 s，内存从 1140 降至 788 KB（减少
30.9%）。Rust 从 0.031 s / 264 KB 变为 0.015 s / 176 KB（内存减少
33.3%）。一个时钟刻度的时间差不能证明计算本身稳定加速。

缓存审计按统一[排名标准](../../RATING_CRITERIA.md)确认 C++、Java、
Python 基础版，无需副本。低于 1 MiB 的 C++ 只检查时间；Java/Python
检查两项，均不加星号。Go 使用精确编译器小样本参考，其低于 1 MiB
的优化版只比较时间。Rust 也只比较时间，采用普通名次。

五个简单 1047_math 文件的当前修订只修正舍入注释：合法输入的精确
答案可以不落在百分之一网格上。简单算法及有意义
的说明注释均保留。
