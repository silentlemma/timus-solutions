# 1016. 立方体在棋盘上滚动的最省路线

[Timus 1016](https://acm.timus.ru/problem.aspx?space=1&num=1016) · 难度 823 · dijkstra, graphs

原题出自 Ural State University Internal Contest '99 #2。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一个每个面上写有 0 到 1000 之间整数的立方体放在 8×8 棋盘的某一格上，棱长等于格子边长。一步是让它绕底面
的一条棱滚到相邻（有公共边）的格子。路线的代价是它所停过的所有格子上底面数字之和，包括第一格和最后一格
（某个面每次在底部都计入一次）。求两个不同的给定格子之间代价最小的路线。

时间限制：2 秒。内存限制：64 MB。

## 输入

一行：起点格和终点格的国际象棋记法（`a`–`h` 与 `1`–`8`），然后是开始时近面、远面、顶面、右面、底面、
左面上的数。“近面”朝向第 1 横排，“右面”朝向 `h` 列。

## 输出

一行：最小代价，然后是从起点到终点的路线上各格，以空格分隔。

## 评测方式

接受任何最优路线。检查器沿输出的路线滚动立方体：每一步都必须走到棋盘上的相邻格，路线必须从给定起点开始、
在给定终点结束，且其代价必须同时等于输出的和与最小值。

## 样例

### 样例 1

输入：

```
b2 b3 0 9 1 3 1 1
```

输出：

```
5 b2 a2 a1 b1 b2 b3
```

### 样例 2

输入：

```
a1 h8 1 1 1 1 1 1
```

输出：

```
15 a1 a2 a3 a4 a5 a6 b6 b7 c7 c8 d8 e8 f8 g8 h8
```

## 题解

下一格的代价取决于哪个面翻到底部，所以只有格子还不够：**状态** 是格子加上立方体的朝向。立方体有 24 种
朝向，所以共有 `64 · 24 = 1536` 个状态，每个状态至多 4 种走法。

**朝向。** 对每个位置（近、远、顶、右、底、左）记录处在那里的原始面的编号。一次滚动是位置的一个固定
置换，例如向远面方向滚动时，顶 → 远 → 底 → 近 → 顶。从恒等朝向出发，反复施加四种滚动直到不再出现新的
朝向，就得到 24 种朝向以及转移表 `next[朝向][方向]`。

**最短路。** 进入一个状态的代价是其底面上的数，起始状态的代价是它自己的底面。所有代价非负，因此用
Dijkstra 算法求最省路线；记录每个状态的前驱，最后在终点格的 24 个状态中取代价最小者，沿前驱回溯。
`O(S log S)`，`S = 1536`——瞬间完成。

注意事项：

- 格子数最少的路线往往不是最省的：立方体可能需要绕一圈把便宜的面翻到底部；
- 不同的面上可能有相同的数：按面在输入中的位置追踪，而不是按数值；
- 起点格的底面也要计入。

## 各语言说明

各语言都使用同样的 Dijkstra 和各自标准的优先队列（Go 用 `container/heap`，Rust 用带 `Reverse` 的
`BinaryHeap`）。
