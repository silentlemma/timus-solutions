# 1013. Подсчёт K-ичных чисел без двух нулей подряд по модулю M

[Timus 1013](https://acm.timus.ru/problem.aspx?space=1&num=1013) · сложность 198 · matrix

Оригинальная задача — самая сложная версия [задач 1009](../1009/README.ru.md) и [1012](../1012/README.ru.md).

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Посчитайте по модулю `M` количество `N`-значных чисел в системе счисления с
основанием `K` (первая цифра не ноль), в записи которых нет двух нулей
подряд. `2 ≤ N, K, M ≤ 10^18`.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`, `K` и `M`, каждое на своей строке.

## Выходные данные

Количество по модулю `M`.

## Проверка

Сравниваются точные целые токены. Новые исходники имеют собственные полные проверки целевой среды и Accepted; прежние опубликованные базы сохраняют свои собственные Accepted, а не старые архивные метрики.

## Примеры

### Пример 1

Ввод:

```
5
2

```

Вывод:

```
8
```

### Пример 2

Ввод:

```
3
10
7
```

Вывод:

```
2
```

## Решение

Пять простых версий сохраняют матричный алгоритм с двумя состояниями.
После первой ненулевой цифры `(zero,other)=(0,K−1)`. Приписывание цифры:
`zero'=other`, `other'=(K−1)(zero+other)`: ноль допустим после ненулевой,
а любую из `K−1` ненулевых цифр можно дописать к любому верному префиксу.
Значит, возводим `A=[[0,1],[c,c]]`, `c=(K−1) mod M`, в степень `N−1`
двоичным методом и применяем к `(0,c)`. Ответ — сумма состояний по модулю.
Модульного деления нет: доказательство верно и при составном `M`.

У показателя не более 60 бит: `O(log N)` матричных шагов и постоянное
число остатков. C++/Rust расширяют произведения до 128 бит: сумма двух
произведений меньше `2M²≤2·10³⁶<2¹²¹`. Go получает два слова через
`bits.Mul64`, затем остаток через `bits.Div64`; старшее слово меньше `M`,
поэтому предусловие деления соблюдено. Java/Python используют длинные
целые; стоимость их арифметики зависит от `log M`. Постоянное число
остатков не означает постоянное число бит. Ввод и представление
показателя также учитываются отдельно от матричного состояния.

Только подготовка ввода Rust стала проще: три `u64` берутся из итератора,
без сбора вектора и индексации. Матричные вычисления и вывод идентичны.
Это принятое упрощение, а не оптимизация от 30%; используются собственные
новые метрики. Остальные четыре базы побайтово сохранены, старый Rust
также сохранён в резервной копии.

## Оптимизированные решения

Сохраняются пять учебных матричных алгоритмов, включая уже принятую упрощённую подготовку Rust-ввода. При c=(K-1) mod M представим многочлен парой aX+b по модулю X²-cX-c. Квадрат даёт a'=c*a²+2ab,b'=c*a²+b², умножение на X — a'=ca+b,b'=ca. Просмотр битов N от старших к младшим с начальным 1 даёт X^N. Ответ a*c+b по модулю M совпадает с двухсостояниевой рекуррентностью и ненулевой первой цифрой. Деления по модулю нет, составные M и общие множители допустимы. Rust расширяет произведения до 128 бит: любая сумма до сокращения меньше 3M²<2^122. Python использует длинные целые и целую битовую маску вместо двоичной строки. Получаем O(log N) модульных шагов и постоянное число остатков с разрядностью O(log M). Ограниченный Rust-ввод-вывод через C ABI убирает кучу и запуск. База сравнения — текущая принятая Rust-матрица 200 КБ, а не её старые 220 КБ.
