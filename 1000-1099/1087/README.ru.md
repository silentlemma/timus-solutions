# 1087. Игра с камнями, где взявший последний камень проигрывает

[Timus 1087](https://acm.timus.ru/problem.aspx?space=1&num=1087) · сложность 278 · games

Автор оригинальной задачи — Антон Ботов; третье командное соревнование школьников Свердловской области по программированию, 4 марта 2001 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В кучке `n` камней (`1 ≤ n ≤ 10000`). Два игрока по очереди берут
`k₁`, `k₂`, … или `kₘ` камней (`1 ≤ m ≤ 50`, `1 ≤ kᵢ ≤ n`); ход всегда
возможен. Тот, кто берёт последний камень, проигрывает. Выведите 1, если
при правильной игре выигрывает первый игрок, иначе 2.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` и `m`, затем `k₁ … kₘ`.

## Выходные данные

1 или 2.

## Проверка

Вывод сравнивается по токенам. Реальный кандидат Python совпал
с независимым рекурсивным минимаксом на 3711 играх: кучи от 1 до 35,
ход 1 и подмножества ходов от 2 до 8, с повторениями и перестановками
ходов. Эталон хранит настоящего игрока и при взятии последнего камня
отдаёт победу сопернику, без условного пустого состояния DP.
Все три реальные программы также прошли по 12 входов репозитория
в Docker и получили собственные Accepted точных исходников.
3711 эталонных проверок запускались на Python, а не по 3711 раз на C++ и Java.

## Решение

Пусть `win[x]` означает, что игрок с `x` камнями гарантирует победу.
Победный ход берёт `k < x` камней и оставляет проигрышную позицию:
`win[x]` истинно ровно тогда, когда для какого-то такого `k`
`win[x − k] = false`. Взять ровно `x` камней — немедленно проиграть,
поэтому такой ход не победный. Заполняем таблицу по возрастанию `x`;
все зависимости меньше, индукция доказывает рекуррентность и ответ.

В простых версиях эквивалентное соглашение `win[0] = true`: предыдущий
игрок только что взял последний камень и проиграл. Можно проверять
`k ≤ x`, поскольку последний ход даёт `not win[0] = false`.
Гарантия допустимого хода действует до окончания игры и не требует
буквального наличия хода 1 во входе. Повторения размеров ходов не меняют
ответ. Время — `O(n m)`, логическая память — `O(n + m)`.
Все пять исходных Accepted-баз сохранены побайтово.

## Оптимизированные решения

Вместо отдельного перебора ходов в каждом состоянии Python с битовыми множествами посещает проигрышные позиции по возрастанию. Один сдвиг длинного целого отмечает все позиции, из которых допустимый ход ведёт в проигрышную, как выигрышные. Меньшие позиции уже классифицированы — сохраняется инвариант обратной индукции обычной игровой DP. Пустая позиция исключена из выигрышных переходов: взявший последний камень проигрывает. Нормализация по минимальному ходу использует доказательство простой версии.

Здесь N' — нормализованное число камней, M — число ходов, L — число проигрышных позиций, w — ширина машинного разряда длинного целого.

- `1087_games_optimized.cpp`: 0.015 s / 132 KB; база `1087_games.cpp`: 0.015 s / 204 KB; изменение относительно базы: время -0.0%, память -35.3%.
- `1087_games_optimized.java`: 0.125 s / 440 KB; база `1087_games.java`: 0.109 s / 1652 KB; изменение относительно базы: время +14.7%, память -73.4%.
