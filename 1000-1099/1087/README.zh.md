# 1087. 拿走最后一颗石子者输的取石子游戏

[Timus 1087](https://acm.timus.ru/problem.aspx?space=1&num=1087) · 难度 278 · games

原题作者 Anton Botov，出自 2001 年 3 月 4 日斯维尔德洛夫斯克州第三届中学生团体程序设计竞赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一堆石子有 `n` 颗（`1 ≤ n ≤ 10000`）。两名玩家轮流拿走 `k₁`、`k₂`、… 或 `kₘ` 颗（`1 ≤ m ≤ 50`，`1 ≤ kᵢ ≤ n`）；
总是可以走一步。拿走最后一颗石子的玩家输。若双方都采取最优策略时先手获胜，输出 1，否则输出 2。

时间限制：1 秒。内存限制：64 MB。

## 输入

`n` 和 `m`，然后是 `k₁ … kₘ`。

## 输出

1 或 2。

## 评测方式

输出按标记比较。实际 Python 候选在 3711 局上与独立递归极小极大
相符：石头数 1 到 35，操作 1 加操作 2 到 8 的子集，并打乱、重复操作项。
参考程序跟踪实际玩家，取最后一块时将胜利交给对手，不用 DP 人为空堆约定。
三份实际候选还分别在 Docker 中通过仓库 12 个输入，取得精确源码各自的 Accepted。
3711 次参考检查是 Python 执行，不是 C++、Java 各执行 3711 次。

## 样例

### 样例 1

输入：

```
17 3
1 3 4
```

输出：

```
2
```

## 解法

设 `win[x]` 表示轮到行动者剩 `x` 块时能保证获胜。获胜操作必须取
`k < x` 块并留下必败状态：恰在存在这样的 `k` 且 `win[x − k] = false`
时 `win[x]` 为真。取完 `x` 块会立即输，不能成为获胜操作。
按 `x` 递增填表，所有依赖均更小，归纳证明递推与答案正确。

简单版本用等价边界 `win[0] = true`：前一人已取最后一块并输掉。
可枚举 `k ≤ x`，因为取完仅贡献 `not win[0] = false`。
始终有合法操作的保证针对游戏结束前，并不要求原输入必须含字面上的操作 1。
重复操作大小不改变结果。时间 `O(n m)`，逻辑存储 `O(n + m)`。
五份原 Accepted 基线逐字节保留。

## 优化解法

Python 位集算法不在每个状态逐一枚举所有步长，而是按递增顺序处理必败状态。一次大整数移位把可一步到达该必败状态的位置标为必胜。更小的位置均已确定，因此保持普通博弈 DP 的逆推不变量。不能把空局面加入必胜转移：取走最后石子者输。最小步长归一化沿用基础解的证明。

N' 为归一化石子数，M 为步长数，L 为必败位置数，w 为大整数机器字宽度。
