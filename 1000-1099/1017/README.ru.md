# 1017. Подсчёт лестниц: разбиения на различные слагаемые

[Timus 1017](https://acm.timus.ru/problem.aspx?space=1&num=1017) · сложность 158 · dp

Оригинальная задача — Ural State University Internal Contest '99 #2.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Лестница из `N` одинаковых кубиков (`5 ≤ N ≤ 500`) — это последовательность
не менее чем из двух столбиков (ступеней) строго возрастающей высоты, каждый
высотой не меньше 1, использующая все `N` кубиков. Посчитайте различные
лестницы.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Количество лестниц.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
```

Вывод:

```
3
```

### Пример 2

Ввод:

```
11
```

Вывод:

```
11
```

## Решение

Лестница определяется множеством высот ступеней: они различны, а их порядок
задан (по возрастанию). Значит, ответ — число способов записать `N` суммой
**различных** натуральных чисел минус один: «лестница» из одной ступени в
`N` кубиков не допускается.

**Подсчёт рюкзаком 0/1.** `ways[s]` — число множеств различных размеров с
суммой `s`. Начинаем с `ways[0] = 1` и добавляем размеры `1, 2, ..., N` по
одному: для размера `k` делаем `ways[s] += ways[s - k]` при `s`, идущем
**вниз** от `N` до `k`, чтобы каждый размер использовался не больше одного
раза (проход вверх допустил бы повторы). После всех размеров ответ —
`ways[N] - 1`.

`O(N^2)` времени, не более 125 250 обновлений. Числа растут быстро: при
`N = 500` ответ около `7.3 · 10^14`, поэтому нужны 64-битные целые.

Другой путь: `f(n, k)` — разбиения `n` на различные слагаемые не меньше `k` —
удовлетворяет `f(n, k) = f(n, k + 1) + f(n - k, k + 1)`, что с мемоизацией
даёт те же числа.

Подводные камни:

- проход по `s` вверх считает разбиения с повторяющимися слагаемыми;
- забыть вычесть разбиение из одного слагаемого;
- знаковые 32-битные целые переполняются начиная с `N = 226`.

## Оптимизированные решения

Оптимизированное решение на C++ хранит таблицу в массиве фиксированного
размера из 501 значения `long long` на стеке вместо `vector`, ведь
`N ≤ 500`, и потому обходится без выделения памяти в куче:
{1017_dp_optimized.cpp}.

Оптимизированное решение на Java читает единственное число через
`StreamTokenizer` поверх `BufferedReader` вместо `Scanner`, чей механизм
регулярных выражений долго загружается и занимает память:
{1017_dp_optimized.java}.
