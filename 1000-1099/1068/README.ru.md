# 1068. Сумма всех целых чисел между 1 и N

[Timus 1068](https://acm.timus.ru/problem.aspx?space=1&num=1068) · сложность 37 · math

Оригинальная задача — пробный тур полуфинала ACM ICPC Северо-Восточной Европы 2000–2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дано целое число `N`, `|N| ≤ 10000`. Выведите сумму всех целых чисел
между 1 и `N` включительно.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Сумма.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
-3
```

Вывод:

```
-5
```

## Решение

Числа между 1 и `N` образуют один отрезок из `|N − 1| + 1` чисел, по какую
бы сторону от 1 ни лежало `N`. Сумма отрезка равна его длине, умноженной
на среднее концов `(1 + N) / 2`. Произведение `(1 + N) · (|N − 1| + 1)`
всегда чётно: при `N ≤ 0` сумма двух сомножителей нечётна, а иначе они
равны `N + 1` и `N`, поэтому деление точное. `O(1)`.

Подводные камни:

- `N` может быть нулём или отрицательным: тогда отрезок идёт от `N` до 1,
  и `N(N + 1)/2` даёт неверный ответ, например 0 вместо 1 при `N = 0`;
- сумма доходит примерно до `5 · 10^7` по модулю и помещается в 32-битные
  целые; решения всё равно умножают в 64 битах (Python — в своих
  неограниченных целых).

Ответы сверены с поочерёдным сложением чисел.

## Оптимизированные решения

`1068_math_optimized.go`. Сохраняется включительная арифметическая прогрессия от 1 до N: (abs(N−1)+1)(N+1)/2 в int64 учитывает положительное, нулевое и отрицательное N без цикла. Ограниченные буферы ввода 256 байт и вывода 64 байта используют syscall.Read/Write из Go 1.14, повторяют EINTR и частичные записи, учитывают EOF с нулём байт. Убираются накладные расходы инициализации fmt/bufio/os.File. Linux-тесты и кросс-сборка Windows проверяют работу и сборку; парные показатели памяти ниже взяты из собственного Accepted точного исходника на Windows-судье. Наглядный учебный исходник сохранён.

По сравнению с `1068_math.go`: время 0.031 s → 0.015 s; память 1072 KB → 260 KB.

Оптимизированное решение на Java разбирает число побайтно из `System.in`
вместо `Scanner`: 368 КБ вместо 1568 КБ при том же времени.

`1068_math_optimized.py`. Сохраняется формула прогрессии (1+N)*(abs(N-1)+1)//2, учитывающая ноль и отрицательные N. Ограниченное целое читается из сырых байтов вместо input(), без вызова обёртки. При |N|<=10000 время и память арифметики остаются O(1). Самостоятельная программа для судьи явно сбрасывает stdout перед os._exit(0), пропуская обычное завершение интерпретатора. Выигрыш памяти подтверждён её собственным Accepted. Сама смена способа завершения не улучшает асимптотику, а её эффект в среде выполнения не гарантируется на других платформах. Простая версия сохранена без изменений.

По сравнению с `1068_math.py`: время 0.078 s → 0.109 s; память 448 KB → 196 KB.

## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1068_math_optimized.py`: место по времени 644/739, по памяти 1/739 в этой сопоставимой выборке.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
