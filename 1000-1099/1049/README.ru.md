## Задача

Даны десять целых чисел `a1 … a10`, каждое от 1 до 10000. Найдите
последнюю цифру количества положительных делителей произведения
`a1 · … · a10`.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Десять целых чисел, по одному в строке.

## Выходные данные

Одна цифра — последняя цифра числа делителей.

## Проверка

## Решение

Если `P = p1^e1 · p2^e2 · … · pk^ek`, то делитель `P` выбирает каждый
показатель независимо от `0` до `ei`, поэтому у `P` ровно
`(e1 + 1)(e2 + 1)…(ek + 1)` делителей.

Само произведение может иметь 40 цифр, но оно и не нужно: раскладываем
каждое число пробным делением до его квадратного корня (не больше 100
шагов), складываем показатели одинаковых простых и перемножаем `(e + 1)`
по модулю 10. `O(10 · √10000)`.

Подводные камни:

- показатели нужно сложить по всем десяти числам до прибавления `1`:
  у `2 · 2` три делителя, а не `2 · 2`;
- простой множитель больше квадратного корня остаётся после пробного
  деления и тоже учитывается;
- последняя цифра может быть 0 (у 48 = `2^4 · 3` десять делителей).

## Оптимизированные решения

`1049_number_theory_optimized.java`. Десять чисел храним как остатки разложения. Для каждого пробного делителя снимаем все его степени со всех десяти остатков, затем умножаем окончательную степень+1 по модулю десять. В том же проходе пересчитываем наибольший оставшийся остаток; когда квадрат следующего делителя больше него, остатки больше единицы простые, одинаковые остатки объединяются. Составные пробные делители уже не делят остатки: их меньшие простые факторы удалены. Если после полного прохода произведение по модулю десять стало нулём, дальнейшие независимые множители его не изменят, и разложение можно закончить. Это безопасно только после подсчёта всей степени по всем входам. Таблица степеней на 10001 элемент не выделяется. При C=10 и исходном максимуме V≤10000: время O(C sqrt(V)+C²), состояние O(C), число проходов уменьшается вместе с остатками. Короткий ввод разбирается напрямую, два байта ответа выводятся и сбрасываются обычным образом. Точный исходник прошёл 59 процессных тестов и 11007 независимых проверок основного метода, включая все 10000 одиночных значений и граничные случаи повторяющихся простых. Учебное разложение и остальные языки сохранены.

Формула числа делителей прежняя: раскладываем десять чисел, складываем степени одинаковых простых и перемножаем степень+1 по модулю десять. Степень двойки снимается целиком, далее проверяются нечётные делители; остаток больше единицы прост. Go использует байтовые степени и список затронутых простых, Java хранит десять остатков и использует описанный выше общий проход по делителям. Максимальная степень 10*floor(log2(10000))=130 помещается в Go uint8; Java накапливает степень в int. Произведение шести различных простых уже 30030, поэтому одно число добавляет не больше пяти. Индексные массивы Go требуют O(V) инициализации и памяти, его десять разложений — O(C sqrt(V)). Python сохраняет небольшой словарь и битовые операции; обмен времени на память указан отдельно.

- `1049_number_theory_optimized.go`: 0.015 s / 292 KB; база `1049_number_theory.go`: 0.031 s / 1108 KB; изменение относительно базы: время -51.6%, память -73.6%.

`1049_number_theory_optimized.rs`. Десять чисел раскладываются на множители по мере чтения, показатели простых множителей суммируются в фиксированном массиве байтов. Каждый показатель не больше 130 при значениях до 10000, поэтому байта достаточно. По массиву перемножаются величины показатель+1 по модулю десять. Разложение требует O(10√M), итоговый проход — O(M), M=10000; память — M+1 байт плюс постоянное состояние. Rust использует среду выполнения C для ввода-вывода, без целых декодированных строк String и форматирования Rust. Простой принятый исходник сохранён без изменений.
