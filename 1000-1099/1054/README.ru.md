# 1054. Номер хода позиции в Ханойской башне

[Timus 1054](https://acm.timus.ru/problem.aspx?space=1&num=1054) · сложность 643 · math

Оригинальная задача — Рыбинская государственная авиационная академия.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` дисков (`1 ≤ N ≤ 31`, диск 1 — самый маленький) стоят на стержне 1 и
переносятся на стержень 2 классической оптимальной рекурсией

```text
Hanoi(n, from, to, via):
    если n > 0:
        Hanoi(n − 1, from, via, to)
        перенести диск n с `from` на `to`
        Hanoi(n − 1, via, to, from)
```

вызванной как `Hanoi(N, 1, 2, 3)`. Позиция задаёт стержень каждого диска.
Найдите, после скольких ходов появляется данная позиция, или `-1`, если
она не появляется никогда.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем стержни `D1 … DN` дисков `1 … N`, по одному в строке.

## Выходные данные

Число ходов или `-1`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3
3
3
1
```

Вывод:

```
3
```

### Пример 2

Ввод:

```
1
3
```

Вывод:

```
-1
```

## Решение

Пройдём рекурсию от самого большого диска вниз. Пока диски `1 … k`
переносятся с `a` на `b` через `c`, диск `k` перемещается ровно один раз —
после первых `2^(k−1) − 1` ходов (они переносят диски `1 … k − 1` на `c`).
Значит:

- диск `k` ещё на `a`: мы в первой половине; продолжаем с дисками
  `1 … k − 1`, которые переносятся с `a` на `c` через `b`;
- диск `k` на `b`: первая половина и ход диска `k` сделаны, это
  `2^(k−1)` ходов; продолжаем с дисками `1 … k − 1`, которые переносятся
  с `c` на `b` через `a`;
- диск `k` на `c`: так не бывает, ответ `-1`.

Сумма `2^(k−1)` по всем дискам, найденным на целевом стержне, и есть номер
хода. `O(N)`.

Подводные камни:

- стержни меняются ролями на каждом уровне; куда сначала идёт самый
  маленький диск — на стержень 2 или 3, — зависит от чётности `N`;
- конечная позиция 31 диска достигается за `2^31 − 1` ходов — это
  максимум знакового 32-битного целого;
- хотя бы один диск «не на том» стержне делает всю позицию
  недостижимой.

## Особенности языков

- Во всех языках один и тот же цикл по дискам с тремя переменными для
  ролей стержней.

## Оптимизированные решения

Версия C++ хранит не более 31 диска в буфере фиксированного размера. При обходе от большего диска к меньшему она дописывает по одному биту номера хода. На исходном стержне бит равен нулю, на целевом — единице. Диск на запасном стержне означает, что положение недостижимо. Время O(N), кроме входного буфера требуется O(1) памяти. Метрики взяты из посылки 11316991.

Версия с меньшим расходом памяти удаляет пробелы из входных байтов и просматривает номера стержней в обратном порядке, добавляя по одному двоичному разряду на диск. Принятая посылка 11322407 на PyPy 3.10 x64 использовала 280 КБ против 400 КБ у простой версии на Python 3.12 x64, то есть на 30% меньше. Время выросло с 0,078 до 0,140 с.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11322200 · Go 1.14 x64 №11322203 · Python 3.12 x64 №11321923 · Rust 1.75 x64 №11322205 · Java 1.8 №11321869.

Посылка Rust №11317962 заняла 0.015 с и использовала 204 КБ. У простого решения — 0.046 s и 204 KB.

Читаем номера стержней как цифры ASCII и обходим диски от больших к малым. Каждый диск добавляет один бит к номеру хода. Диск на запасном стержне означает, что позиция недостижима.

Go читает положения дисков в фиксированный массив и идёт от большего диска к меньшему. Каждый диск определяет очередной бит числа ходов либо показывает, что конфигурация недостижима. Go 1.14 x64, посылка 11322837. Время 0,031 → 0,015 с, память 1076 → 276 КБ.

Java хранит номера стержней в массиве байтов и перебирает диски от большого к малому, добавляя по одному биту в номер хода. Запасной стержень вычисляется по сумме номеров всех трёх. Посылка 11323975 заняла 0,109 с и использовала 356 КБ против 0,125 с и 1608 КБ у простой версии.
