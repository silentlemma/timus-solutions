# 1052. Больше всего точек на одной прямой

[Timus 1052](https://acm.timus.ru/problem.aspx?space=1&num=1052) · сложность 239 · geometry, sorting

Автор оригинальной задачи — Станислав Васильев; студенческое соревнование по программированию УрГУ, 25 марта 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `N` различных точек (`3 ≤ N ≤ 200`) с целыми координатами от −2000 до
2000. Найдите наибольшее число из них, лежащих на одной прямой.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк с `x` и `y`.

## Выходные данные

Наибольшее число точек на одной прямой.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
7 122
8 139
9 156
10 173
11 190
-100 1
```

Вывод:

```
5
```

### Пример 2

Ввод:

```
3
0 0
1 0
0 1
```

Вывод:

```
2
```

## Решение

Переберём каждую пару различных входных точек `i,j`. Она задаёт прямую.
Посчитаем все точки `k` на ней по точному равенству
`(x[k]−x[i])·(y[j]−y[i]) = (y[k]−y[i])·(x[j]−x[i])`.
Ответ — максимальный счётчик. На искомой прямой есть хотя бы две входные
точки, поэтому какая-то перебранная пара задаёт её. Обратно, каждый
засчитанный элемент действительно лежит на выбранной прямой. Значит,
максимум в точности равен ответу.

Этот прямой `geometry_bruteforce` — основная простая версия на всех пяти
языках. Время — `O(N³)`: при `N=200` не больше 3 980 000 проверок точек.
Хранение входа занимает `O(N)` памяти. Если уже найдена прямая со всеми
`N` точками, ответ оптимален и можно закончить. Разности координат по
модулю не больше 4000, а каждое произведение — 16 000 000, что помещается
в знаковые 32 бита. Не нужны вещественные наклоны, деление и нормализация
через НОД.

Для вертикальных и горизонтальных прямых, противоположных направлений
и почти одинаковых наклонов работает одно равенство. Точки различны,
поэтому пара не задаёт нулевой вектор; ответ всегда хотя бы два.
Прямые версии прошли все тесты судьи; локально они также сверены
с независимым эталоном канонических уравнений прямых.

## Оптимизированные решения

Сохранённый алгоритм подсчёта направлений фиксирует опорную точку
и сокращает каждый вектор `(dx,dy)` на `gcd(|dx|,|dy|)`. Меняем знак,
чтобы `dx>0` либо `dx=0,dy>0`: противоположные направления становятся
одинаковыми. Равные сокращённые векторы лежат на одной прямой с опорой.
Достаточно считать следующие по вводу точки: первая точка любой
максимальной прямой увидит все остальные.

Для хеш-таблиц ожидаемое время — `O(N² log C)`, рабочая память — `O(N)`,
где `C=4000` ограничивает разности координат. В C++ используется
упорядоченный `std::map`, поэтому оценка с его операциями составляет
`O(N²(log N+log C))`. Худший случай хеш-таблицы не объявляется константным.

Относительно новой простой базы оптимизированной считается
неизменённая Python-версия с направлениями: её Accepted на CPython —
0,078 с и 508 КБ, у простого PyPy — 0,250 с и 2840 КБ. Это на 68,8%
меньше времени и на 82,1% меньше памяти. Сравнение включает алгоритм
и интерпретатор; принятая среда указана в таблице. Прежние нативные
версии с таблицами направлений сохранены как дополнительные принятые
алгоритмы, но не имеют измеренного выигрыша 30% относительно новой
простой версии на том же языке. Разница в один тик для допуска не годится.

Новый Rust `geometry_sorting` так же точно сокращает направления, затем
сортирует фиксированный массив и считает длины одинаковых серий. Вместо
хеш-таблицы получаем гарантированные `O(N²(log N+log C))` времени и `O(N)` памяти.
Первая по вводу точка оптимальной прямой видит все остальные; если вместе
с опорой осталось не больше `best` точек, улучшить ответ уже нельзя.
Два массива по 200 пар координат/направлений и ограниченные буферы ввода-вывода
не используют кучу. Вход через C ABI исключает ненужный запуск Rust и форматирование.
Собственный Accepted: 0,015 с / 52 КБ против 0,031 с / 212 КБ у основной
кубической Rust-версии, экономия памяти 75,5%. Разница времени — один тик
судьи и для допуска не используется. Помимо тестов репозитория, все 466
подмножеств минимум из двух точек знаковой сетки 3×3 сверены с независимым
эталоном на попарных векторных произведениях.

## Особенности языков

Кубический Python принят на PyPy 3.10, подсчёт направлений — на CPython
3.12. Остальные простые версии используют обычные компиляторы судьи
и стандартный ввод. Для направлений C++ использует `std::map`, Go/Rust —
хеш-таблицы, Python — `Counter`, Java — `HashMap` с ключом `dx·8192+dy`
без коллизий между разными направлениями (`|dy|≤4000`).
