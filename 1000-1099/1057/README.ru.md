# 1057. Суммы K различных степеней B на отрезке

[Timus 1057](https://acm.timus.ru/problem.aspx?space=1&num=1057) · сложность 718 · combinatorics

Оригинальная задача — Рыбинская государственная авиационная академия.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Посчитайте целые числа на отрезке `[X, Y]` (`1 ≤ X ≤ Y ≤ 2^31 − 1`),
которые являются суммой ровно `K` различных степеней числа `B` с целыми
показателями (`1 ≤ K ≤ 20`, `2 ≤ B ≤ 10`).

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`X` и `Y`, затем `K`, затем `B`.

## Выходные данные

Количество таких чисел.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
15 20
2
2
```

Вывод:

```
3
```

### Пример 2

Ввод:

```
1 100
1
10
```

Вывод:

```
3
```

## Решение

Различные отрицательные степени `B` в сумме дают меньше 1, поэтому целая
сумма использует только неотрицательные показатели. Такое число — ровно
то, у которого все цифры в системе по основанию `B` равны 0 или 1, а
единиц `K`. Посчитаем их на `[0, n]` функцией `f(n)`; ответ —
`f(Y) − f(X − 1)`.

Для `f(n)` запишем `n` по основанию `B` (не больше 31 цифры):

1. возьмём старшую из цифр больше 1, если такие есть: любая строка из 0 и 1,
   совпадающая с `n` выше неё, меньше `n` независимо от продолжения, поэтому
   эту цифру и все младшие можно заменить на 1, не меняя ответа;
2. теперь все цифры 0 или 1: идём сверху, считая взятые единицы; на
   цифре 1 выбор 0 оставляет `i` младших позиций свободными, что даёт
   `C(i, K − ones)` чисел; выбор 1 продолжает проход;
3. в конце полученная граница учитывается, если в ней ровно `K` единиц.

`O(log_B Y)` с небольшой таблицей биномиальных коэффициентов.

Подводные камни:

- цифры по основанию `B` должны быть 0 или 1; цифра 2 и больше — это уже
  не сумма *различных* степеней;
- `f(X − 1)` при `X = 1` — это `f(0) = 0`;
- при `B = 10` ниже `2^31` всего 10 позиций, поэтому `K > 10` даёт 0.

## Особенности языков

- **C++**, **Go**, **Java**, **Rust**: треугольник Паскаля до 32.
  **Python**: `math.comb`, который возвращает 0 при `k > n`.

## Оптимизированные решения

Rust перебирает цифры в основании B и использует заранее вычисленную таблицу Паскаля для оставшихся вариантов. Rust 1.75 x64, посылка 11323261. Время 0,015 → 0,015 с, память 236 → 44 КБ.

Версия PyPy перебирает разряды границы по убывающим степеням основания и вычисляет биномиальные коэффициенты по мере надобности, без хранения разрядов. Посылка 11323987 заняла 0,125 с и использовала 268 КБ против 0,078 с и 500 КБ у простой версии.

Python обходит цифры границы от старших к младшим и вычисляет биномиальные коэффициенты по мере необходимости. На цифре больше единицы обход заканчивается, поскольку все оставшиеся комбинации нулей и единиц меньше границы.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11321895 · Java 1.8 №11321896 · Go 1.14 x64 №11322186 · Python 3.12 x64 №11322187 · Rust 1.75 x64 №11322188.

Go просматривает цифры от старших к младшим и по ходу обновляет биномиальный коэффициент для оставшихся разрядов. Go 1.14 x64, посылка 11322843. Время 0,031 → 0,015 с, память 1072 → 276 КБ.

Java читает четыре числа прямо из входного потока и перебирает разряды границы, последовательно уменьшая степень основания. Биномиальные коэффициенты вычисляются по мере надобности, с постоянной дополнительной памятью. Посылка 11323981 заняла 0,093 с и использовала 384 КБ против 0,109 с и 1624 КБ у простой версии.
