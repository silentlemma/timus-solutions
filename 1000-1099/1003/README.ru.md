# 1003. Первый противоречивый ответ о чётности

[Timus 1003](https://acm.timus.ru/problem.aspx?space=1&num=1003) · сложность 385 · dsu, hashing

Оригинальная задача — Центральноевропейская олимпиада по информатике 1999 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть неизвестная последовательность из `L` битов (`L ≤ 10^9`). По порядку
приходят `q ≤ 5000` утверждений; утверждение `i` говорит, что количество
единиц среди битов `l..r` (нумерация с 1, `l ≤ r`) чётно или нечётно.

Найдите наибольшее `X`, при котором какая-нибудь последовательность битов
удовлетворяет первым `X` утверждениям. Если все утверждения могут
выполняться одновременно, `X = q`.

Во входных данных несколько таких тестов.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

Тесты идут друг за другом. Тест — это строка с `L`, строка с `q` и `q` строк
вида `l r even` или `l r odd`. Строка `-1` завершает ввод.

## Выходные данные

Для каждого теста — одна строка с числом `X`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
6
3
1 2 odd
3 4 even
1 4 even
-1
```

Вывод:

```
2
```

### Пример 2

Ввод:

```
8
4
1 8 even
1 4 odd
5 8 odd
2 3 even
3
2
1 3 odd
1 3 even
-1
```

Вывод:

```
4
1
```

## Решение

Пусть `P(k)` — чётность количества единиц среди первых `k` битов, `P(0) = 0`.
Утверждение об отрезке `l..r` означает `P(l-1) xor P(r) = 0` (чётно) или `1`
(нечётно). И наоборот, любые значения `P` с `P(0) = 0` получаются ровно из
одной последовательности битов. Поэтому утверждения совместны тогда и только
тогда, когда система уравнений `P(a) xor P(b) = w` имеет решение.

Обрабатываем утверждения по порядку системой непересекающихся множеств на
позициях префиксов, которая для каждой вершины хранит ещё и чётность
относительно родителя. `find` возвращает корень и чётность вершины
относительно него. Для нового уравнения: если оба конца в одном множестве,
уравнение должно согласоваться с уже известными чётностями; иначе множества
объединяются с нужной чётностью на новом ребре. Первое несогласное уравнение
даёт `X`.

Позиции доходят до `10^9`, но встречается не больше `2q` из них: они
отображаются в последовательные номера хеш-таблицей. Со сжатием путей и
объединением по рангу работа занимает `O(q · α(q))` на тест; в Python без
рангов — `O(q log q)`.

Подводные камни:

- уравнения связывают префиксы `l-1` и `r`, а не `l` и `r`;
- после первого противоречия остаток теста всё равно нужно дочитать;
- в тесте может не быть ни одного утверждения.

## Оптимизированные решения

Обе версии упаковывают индекс родителя и чётность ребра в одно 16-битное число. Чётность хранится в младшем бите. C++ сначала сортирует и объединяет повторяющиеся позиции префиксов, затем находит их индексы двоичным поиском. Python назначает индексы по мере чтения через хеш-таблицу и при обходе переподключает каждую вершину к деду с учётом суммарной чётности. Уравнения проверяются в порядке входа.

Принятая версия Python 3.12 x64 заняла 0.109 с при 0.093 с у базовой и использовала 1 216 KB при 4388 KB у базовой.

Принятые базовые реализации [1003_dsu_hashing.go](1003_dsu_hashing.go), [1003_dsu_hashing.java](1003_dsu_hashing.java), [1003_dsu_hashing.rs](1003_dsu_hashing.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Эти замечания относятся к базовым реализациям.

- **C++**: `std::unordered_map<int, int>` для номеров; рекурсивный `find`
  допустим, деревья неглубокие благодаря объединению по рангу.
- **Go**: `map[int]int` и рекурсивный `find` со сжатием путей.
- **Python**: итеративный `find`, который сжимает путь и пересчитывает
  чётности вершин на нём.
- **Java**: массивы размера `2q` на тест, `HashMap<Integer, Integer>` для
  номеров, итеративный `find`.
- **Rust**: `HashMap<i64, usize>` и `entry().or_insert_with()` для создания
  вершин; итеративный `find`.
