# 1072. Кратчайший маршрут между двумя компьютерами через IP-подсети

[Timus 1072](https://acm.timus.ru/problem.aspx?space=1&num=1072) · сложность 502 · bfs, graphs

Автор оригинальной задачи — Евгений Кобзев; Ural State University Personal Contest Online, февраль 2001 года, Students Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

У каждого из `N` компьютеров (`2 ≤ N ≤ 90`) до 5 сетевых интерфейсов;
интерфейс — это IP-адрес и маска подсети (сначала единицы, потом нули).
Два интерфейса лежат в одной подсети, если `IP1 AND mask1` равно
`IP2 AND mask2`. Пакет идёт напрямую между компьютерами с общей подсетью,
а из подсети в подсеть — только через компьютер с интерфейсами в обеих.
Найдите путь через наименьшее число компьютеров между двумя заданными
компьютерами.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`; затем для каждого компьютера число интерфейсов `K` и `K` строк с
IP-адресом и маской в записи с точками; затем номера двух компьютеров.

## Выходные данные

`Yes` и компьютеры пути по порядку или `No`, если пути нет.

## Проверка

Подходит любой кратчайший путь. Проверяющая программа убеждается, что
путь идёт от первого компьютера ко второму, что каждые два соседа на нём
имеют общую подсеть и что компьютеров в нём наименьшее возможное число.

## Примеры

### Пример 1

Ввод:

```
6
2
10.0.0.1 255.0.0.0
192.168.0.1 255.255.255.0
1
10.0.0.2 255.0.0.0
3
192.168.0.2 255.255.255.0
212.220.31.1 255.255.255.0
212.220.35.1 255.255.255.0
1
212.220.31.2 255.255.255.0
2
212.220.35.2 255.255.255.0
195.38.54.65 255.255.255.224
1 
195.38.54.94 255.255.255.224
1 6
```

Вывод:

```
Yes
1 3 5 6
```

## Решение

Сведём каждый интерфейс к числу `IP AND mask`. Два компьютера соединены,
если среди их интерфейсов есть одинаковое число; переход между
соединёнными компьютерами — это ровно одна прямая передача, а компьютер в
середине пути имеет интерфейсы в подсетях по обе стороны от него. Значит,
задача — кратчайший путь в этом графе компьютеров, и его находит поиск в
ширину от первого компьютера. Путь получается, если идти по запомненным
предкам назад от второго компьютера. `O(N^2 · K^2)`.

Подводные камни:

- проверка подсети использует собственную маску каждого интерфейса:
  `10.0.0.77/255.0.0.0` и `10.0.0.5/255.255.255.0` лежат в одной подсети,
  потому что оба дают `10.0.0.0`, а `10.1.0.1/255.0.0.0` и
  `10.1.0.2/255.255.0.0` — нет, хотя каждый адрес лежит в диапазоне
  другого;
- маски `0.0.0.0` и `255.255.255.255` допустимы и не требуют особого
  случая;
- адреса — 32-битные беззнаковые числа; знаковый тип тоже подойдёт, пока
  сравнивается только равенство.

Длины путей сверены с алгоритмом Флойда — Уоршелла на том же графе,
построенном отдельно, с проверкой, что маски имеют вид «единицы, затем
нули».

## Особенности языков

- C++ читает адрес через `scanf("%u")` и `".%u"` для четырёх частей;
  остальные языки делят токен по точкам.
- Java хранит адреса в `int`, который для старших адресов переполняется в
  отрицательные значения, но `AND` и равенству это не мешает.
- Python хранит подсети компьютера во множестве и проверяет
  `isdisjoint`.
