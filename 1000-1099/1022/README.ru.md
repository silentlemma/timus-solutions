# 1022. Упорядочение семьи так, чтобы предки шли первыми

[Timus 1022](https://acm.timus.ru/problem.aspx?space=1&num=1022) · сложность 142 · graphs, bfs, dfs

Оригинальная задача — второе командное соревнование школьников Свердловской области по программированию, 7 октября 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` членов семьи (`1 ≤ N ≤ 100`), пронумерованных `1..N`, связаны
отношениями «родитель — ребёнок»: у члена может быть сколько угодно
родителей и детей, циклов нет. Выведите порядок всех членов, в котором
каждый идёт раньше всех своих потомков. Принимается любой такой порядок.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк: `i`-я перечисляет детей члена `i` в любом порядке и
заканчивается `0` (строка из одного `0` — детей нет).

## Выходные данные

`N` номеров в выбранном порядке через пробел.

## Проверка

Принимается любой правильный порядок. Чекер проверяет, что вывод —
перестановка `1..N` и что каждый член идёт раньше каждого своего ребёнка
(отсюда по индукции — раньше всех потомков).

## Примеры

### Пример 1

Ввод:

```
4
0
1 0
1 4 0
1 0
```

Вывод:

```
2 3 4 1
```

### Пример 2

Ввод:

```
1
0
```

Вывод:

```
1
```

## Решение

Члены семьи и связи образуют ориентированный ациклический граф, а нужный
порядок — его **топологическая сортировка**.

**Алгоритм Кана (BFS).** Считаем число родителей каждого члена. Члены без
родителей могут выступать первыми — кладём их в очередь. Берём членов из
очереди по одному; у каждого их ребёнка уменьшаем счётчик родителей, и
ребёнок, у которого он стал нулём, встаёт в очередь — все его родители уже
выступили. Очередь в порядке добавления и есть ответ.

**Обход в глубину.** Запускаем DFS из каждого непосещённого члена и
добавляем член в список, когда его обход заканчивается, то есть после всех
его потомков. Перевёрнутый список ставит каждого перед его потомками.

Оба способа работают за `O(N + E)`, где `E` — число связей, здесь не больше
примерно 5 000.

Подводные камни:

- во входе перечислены дети, а не родители: входящие степени считайте по
  спискам;
- строка из одного `0` — пустой список, а не конец входа.

## Оптимизированные решения

Оптимизированное решение на C++ по алгоритму Кана хранит связи в
статической матрице `bool` из 101 × 101 клеток, около 10 КБ, так как
`N ≤ 100`, а очередь — в массиве фиксированного размера, вместо
`vector` из `vector`, который растёт с каждой связью. Взяв члена семьи
из очереди, оно просматривает всю его строку матрицы, всего `O(N²)`, что
для 100 членов семьи ничего не стоит: {1022_bfs_graphs_optimized.cpp}.

Оптимизированное решение на Java по алгоритму Кана разбирает числа
вручную из буфера на 4 КБ вместо `Scanner`, хранит связи в матрице
`boolean` из (N + 1) × (N + 1) клеток, небольшой при `N ≤ 100`, а
очередь — в массиве `int`, вместо списков упакованных объектов
`Integer`. Взяв члена семьи из очереди, оно просматривает всю его строку
матрицы, всего `O(N²)`: {1022_bfs_graphs_optimized.java}.
