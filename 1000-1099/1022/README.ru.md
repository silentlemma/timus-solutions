# 1022. Упорядочение семьи так, чтобы предки шли первыми

[Timus 1022](https://acm.timus.ru/problem.aspx?space=1&num=1022) · сложность 142 · graphs, bfs, dfs

Оригинальная задача — второе командное соревнование школьников Свердловской области по программированию, 7 октября 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

`N` членов семьи (`1 ≤ N ≤ 100`), пронумерованных `1..N`, связаны
отношениями «родитель — ребёнок»: у члена может быть сколько угодно
родителей и детей, циклов нет. Выведите порядок всех членов, в котором
каждый идёт раньше всех своих потомков. Принимается любой такой порядок.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк: `i`-я перечисляет детей члена `i` в любом порядке и
заканчивается `0` (строка из одного `0` — детей нет).

## Выходные данные

`N` номеров в выбранном порядке через пробел.

## Проверка

Принимается любой правильный порядок. Чекер проверяет, что вывод —
перестановка `1..N` и что каждый член идёт раньше каждого своего ребёнка
(отсюда по индукции — раньше всех потомков).

## Примеры

### Пример 1

Ввод:

```
4
0
1 0
1 4 0
1 0
```

Вывод:

```
2 3 4 1
```

### Пример 2

Ввод:

```
1
0
```

Вывод:

```
1
```

## Решение

Члены семьи и связи образуют ориентированный ациклический граф, а нужный
порядок — его **топологическая сортировка**.

**Алгоритм Кана (BFS).** Считаем число родителей каждого члена. Члены без
родителей могут выступать первыми — кладём их в очередь. Берём членов из
очереди по одному; у каждого их ребёнка уменьшаем счётчик родителей, и
ребёнок, у которого он стал нулём, встаёт в очередь — все его родители уже
выступили. Очередь в порядке добавления и есть ответ.

**Обход в глубину.** Запускаем DFS из каждого непосещённого члена и
добавляем член в список, когда его обход заканчивается, то есть после всех
его потомков. Перевёрнутый список ставит каждого перед его потомками.

Оба способа работают за `O(N + E)`, где `E` — число связей, здесь не больше
примерно 5 000.

Подводные камни:

- во входе перечислены дети, а не родители: входящие степени считайте по
  спискам;
- строка из одного `0` — пустой список, а не конец входа.

## Оптимизированные решения

`1022_bfs_graphs_optimized.java`. Java сохраняет топологическую сортировку Кана, но упаковывает строку смежности в слова long вместо ячеек boolean. Повторный потомок не увеличивает входящую степень. Для вершины с нулевой степенью просматриваются только установленные биты слов потомков через numberOfTrailingZeros и bits&=bits-1; потомок добавляется при обнулении степени. Массив int служит очередью и ответом; списков упакованных вершин и StringBuilder нет. Раздельные буферы ввода и вывода по 4096 байт читают и выводят числа через обычные потоки. Для E перечисленных рёбер время O(N*ceil(N/64)+E), память O(N*ceil(N/64)+N) плюс фиксированные байтовые буферы. Учебные версии Кана и DFS сохранены.

Accepted точного исходника Java 1.8 №11327520: 0.078 с / 380 КБ. Сохранённое сравнение компиляторов от 2026-11-20: время 5/179, память 2/179. При памяти меньше 1024 КБ строгий допуск учитывает только время: первые десять мест или топ 15%, равенства делят место, процентный порог округляется вверх. Звёздочка остаётся для отдельной цели языка: первого места по обеим метрикам. Прежний документированный оптимизированный запуск №11304481: 0.093 с / 360 КБ; это отдельная историческая пара, не текущий замер данного исходника. Учебные версии сохранены без изменений.

- `1022_bfs_graphs_optimized.java`: 0.078 s / 380 KB; сохранённая учебная база `1022_bfs_graphs.java`: 0.125 s / 1828 KB.

`1022_bfs_graphs.py`. Сохраняются топологическая сортировка Кана, входные степени и растущий список одновременно как FIFO и ответ. При не более 100 вершинах весь ограниченный байтовый ввод разбивается один раз вместо генераторов блоков и токенов Python. Каждое ребро и вершина обрабатываются один раз: O(V+E) времени и памяти с вводом. Вывод сбрасывается перед прямым завершением. Другой учебный алгоритм DFS сохранён.

Accepted точного исходника CPython 3.12 №11327003: 0.062 с / 724 КБ. Сравнение, сохранённое 2026-11-20 для актуальных компиляторов семейства: место по времени 4/54, по памяти 44/54. При памяти меньше 1024 КБ строгий критерий учитывает только время.

- `1022_bfs_graphs.py`: 0.062 s / 724 KB; сохранённая учебная база `1022_dfs_graphs.py` (Python 3.12 x64): 0.078 s / 512 KB; изменение времени -20.5%; изменение памяти +41.4%.

По сравнению с `1022_dfs_graphs.py`: время 0.078 s → 0.093 s; память 512 KB → 256 KB.

Оптимизированное решение на C++ по алгоритму Кана хранит связи в
статической матрице `bool` из 101 × 101 клеток, около 10 КБ, так как
`N ≤ 100`, а очередь — в массиве фиксированного размера, вместо
`vector` из `vector`, который растёт с каждой связью. Взяв члена семьи
из очереди, оно просматривает всю его строку матрицы, всего `O(N²)`, что
для 100 членов семьи ничего не стоит: {1022_bfs_graphs_optimized.cpp}.
