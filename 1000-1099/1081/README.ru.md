# 1081. K-я двоичная строка без двух соседних единиц

[Timus 1081](https://acm.timus.ru/problem.aspx?space=1&num=1081) · сложность 271 · dp

Автор оригинальной задачи — Emil Kelevedzhiev; турнир по информатике Зимнего математического фестиваля, Варна, 2001 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Рассмотрим все строки длины `N` (`0 < N < 44`) из 0 и 1 без двух соседних
единиц, упорядоченные лексикографически. Выведите `K`-ю из них
(`0 < K < 10^9`) или `-1`, если их меньше `K`.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `K`.

## Выходные данные

Строка или `-1`.

## Проверка

Сравнивается двоичная строка длины N либо -1 при недопустимом ранге. Новый точный исходник Python прошёл 15 тестов репозитория на PyPy 3.10. Также 239 исчерпывающих проверок коротких строк и рангов. Остальные сохранённые варианты имеют собственные проверки целевой среды и точные Accepted. Вывод сравнивается по правилам проверяющего модуля задачи.

## Примеры

### Пример 1

Ввод:

```
3 1
```

Вывод:

```
000
```

## Решение

Пусть `count[r]` — число допустимых строк длины `r`: строка начинается
либо с 0 и любого допустимого продолжения, либо с `10` и любого
допустимого продолжения, так что `count[r] = count[r − 1] + count[r − 2]`
при `count[0] = 1` и `count[1] = 2` — это числа Фибоначчи.

Строим ответ слева направо. Если предыдущий символ — 1, этот обязан быть
0. Иначе строки с 0 на этом месте идут в порядке первыми, и их
`count[rest]`, где `rest` — число позиций после текущей (0 не
ограничивает следующий символ). Если `K ≤ count[rest]`, пишем 0; иначе
вычитаем `count[rest]` из `K` и пишем 1. Если с самого начала
`K > count[N]`, выводим `-1`. `O(N)`.

Подводные камни:

- `count[43] = 1 134 903 170` больше любого `K`, так что при `N = 43`
  ответ есть всегда; количества всё равно хранятся в 64-битных целых;
- после 1 следующий символ вынужден, и `K` не меняется;
- строки считаются с `K = 1` — строки из одних нулей.

Ответы сверены с отсортированным списком всех допустимых строк при
`N ≤ 20`, а для более длинных строк — вычислением номера ответа обратно
через подсчёт с запоминанием.

## Оптимизированные решения

`1081_dp_optimized.py`. Сохраняется точная динамика подсчёта двоичных строк и восстановления по рангу, включая отказ для слишком большого ранга. Меняются лишь байтовый ввод и прямое завершение после сброса вывода; рекуррентность, вычитание ранга и биты прежние. Это изменение накладных расходов, не новый асимптотический алгоритм. Читаемая DP сохранена.

Accepted точного исходника CPython 3.12 №11327009: 0.078 с / 660 КБ. Сравнение, сохранённое 2026-11-20 для актуальных компиляторов семейства: место по времени 3/31, по памяти 21/31. При памяти меньше 1024 КБ строгий критерий учитывает только время.

- `1081_dp_optimized.py`: 0.078 s / 660 KB; сохранённая учебная база `1081_dp.py` (Python 3.12 x64): 0.093 s / 476 KB; изменение времени -16.1%; изменение памяти +38.7%.

`1081_dp_optimized.rs`. Сохраняются числа Фибоначчи и восстановление двоичной строки по рангу без соседних единиц. При n<=43 все количества помещаются в u32, поэтому растущий вектор u64 заменён фиксированным массивом из 44 u32. Биты выводятся сразу без строки ответа, два числа разбираются напрямую. Время O(n), память счётчиков O(n), здесь не больше 44 ячеек. Ранг k больше общего числа по-прежнему отклоняется.

По сравнению с `1081_dp.rs`: время 0.046 s → 0.031 s; память 216 KB → 64 KB.

Понятная таблица количеств Фибоначчи сохранена. Компактные версии держат два соседних количества и при восстановлении обращают рекуррентное соотношение. Если остаточный ранг с нуля не меньше числа строк с нулевым префиксом, вычитается это число и выводится единица; иначе ноль. После единицы оставшийся интервал рангов меньше следующего количества с нулевым префиксом, поэтому следующий бит автоматически нулевой. Полное количество проверяет допустимость ранга. Python собирает ответ в одном целом и форматирует ровно N бит: сохраняется O(N)-битный ответ, а не таблица количеств.

- `1081_dp_optimized.java`: 0.078 s / 372 KB; база `1081_dp.java`: 0.125 s / 1640 KB; изменение относительно базы: время -37.6%, память -77.3%.


## Особенности языков

Новые исходники сравниваются по срезу от 18 ноября 2026 года с другими авторами на текущих компиляторах судьи. Порогов по ID посылки или дате нет. Ничьи делят место, времена меньше 0.015 с при сравнении считаются 0.015 с. Приведённые ниже места относятся к новым версиям; прежние исходники сохраняют собственные исторические метрики Accepted.

`1081_dp_optimized.rs`: сопоставимых чужих результатов недостаточно для рейтингового вывода; допуск основан на измеренном улучшении относительно простой версии.

Звёздочка означает недостигнутую рейтинговую цель: для C++ нужны первые десять мест либо топ 15% одновременно по обеим метрикам; для остальных семейств — первое место по обеим. Отдельный критерий допуска может выполняться по рейтингу или улучшению, в том числе при снижении времени либо памяти минимум на 30%.
