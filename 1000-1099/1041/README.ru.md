# 1041. Самый дешёвый базис из набора векторов

[Timus 1041](https://acm.timus.ru/problem.aspx?space=1&num=1041) · сложность 4654 · math, greedy

Автор оригинальной задачи — Дмитрий Филимоненков; Пятый командный чемпионат УрГУ по программированию, октябрь 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `M` целочисленных векторов размерности `N` (`3 ≤ N ≤ 50`,
`N ≤ M ≤ 2000`, координаты по модулю не больше 2000), у каждого цена от 1
до 15000. Выберите `N` линейно независимых векторов с наименьшей
суммарной ценой. Среди всех самых дешёвых вариантов выведите
лексикографически наименьший список их номеров по возрастанию. Если
никакие `N` векторов не независимы, выведите `0`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`M` и `N`, затем `M` строк с координатами векторов, затем `M` строк с их
ценами.

## Выходные данные

Наименьшая суммарная цена, затем `N` номеров выбранных векторов по
возрастанию, по одному в строке; или `0`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
5 3
1 0 0
0 1 0
0 0 1
0 0 2
0 0 3
10
20
30
10
10
```

Вывод:

```
40
1
2
4
```

### Пример 2

Ввод:

```
4 3
1 2 3
2 4 6
0 1 1
1 3 4
1
1
1
1
```

Вывод:

```
0
```

## Решение

Линейно независимые множества векторов образуют матроид, а для матроида
жадный алгоритм оптимален: идём по векторам от самых дешёвых и оставляем
вектор, если он независим от уже оставленных. При равных ценах идём по
возрастанию номеров. Это даёт и лексикографически наименьший список. Все
самые дешёвые базисы содержат базис каждого уровня цены `c`, взятый над
линейной оболочкой более дешёвых векторов. Выборы на разных уровнях
независимы друг от друга, а на каждом уровне жадный проход по возрастанию
номеров даёт базис, у которого `k`-й по величине номер наименьший
возможный для каждого `k`.

Проверка независимости — метод Гаусса: оставленные векторы хранятся в
ступенчатом виде (у каждой строки ведущая координата равна 1, а в ведущих
координатах предыдущих строк стоят нули). Кандидат сокращается каждой
строкой; если что-то ненулевое осталось, он независим и становится новой
строкой. Всего `O(M · N^2)` операций.

Точная арифметика важна: в плавающей точке почти параллельные
целочисленные векторы могут быть оценены неверно. Решения считают по
модулю простого числа `2^31 − 1`. Множество, независимое по модулю
простого, независимо и над рациональными числами (некоторый минор не
равен нулю по модулю простого, значит, не равен нулю). Обратное нарушается,
только если простое делит все ненулевые миноры `N × N`, что при таких
размерах и данных практически невозможно. Тесты проверены точными
дробями.

Подводные камни:

- жадности только по цене недостаточно: при равных ценах нужно идти по
  возрастанию номеров, чтобы список был наименьшим;
- векторы выводятся по возрастанию номеров, а не в порядке выбора;
- если даже все `M` векторов натягивают меньше `N` измерений, ответ `0`.

## Особенности языков

- **C++**, **Go**, **Java**, **Rust**: 64-битные целые; произведения двух
  вычетов меньше `2^31` помещаются с запасом.
- **Python**: базис хранится полностью приведённым (каждая строка равна
  нулю в ведущих координатах всех остальных строк). Тогда остаток
  кандидата в свободной координате — одно скалярное произведение с его
  ведущими координатами, которое считается через `sum(map(mul, ...))`; это
  достаточно быстро для CPython.
