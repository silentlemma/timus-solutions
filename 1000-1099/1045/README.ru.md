# 1045. Игра с фишкой на дереве со сгорающими вершинами

[Timus 1045](https://acm.timus.ru/problem.aspx?space=1&num=1045) · сложность 523 · games, trees

Автор оригинальной задачи — Дмитрий Филимоненков; студенческое соревнование по программированию УрГУ, 25 марта 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Дерево имеет `n` вершин (`n ≤ 1000`, у каждой вершины не больше 20
соседей). Фишка стоит в вершине `k`. Два игрока ходят по очереди: ход
переводит фишку по ребру в соседнюю вершину, а покинутая вершина
уничтожается навсегда. Проигрывает тот, кто не может сделать ход.
Определите победителя при оптимальной игре; если выигрывает первый
игрок, укажите выигрывающий первый ход — наименьшую такую вершину, если
их несколько.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`n` и `k`, затем `n − 1` строк с рёбрами.

## Выходные данные

`First player wins flying to airport L` с вершиной `L` первого хода или
`First player loses`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4 3
3 2
3 1
1 4
```

Вывод:

```
First player wins flying to airport 2
```

### Пример 2

Ввод:

```
3 1
1 2
2 3
```

Вывод:

```
First player loses
```

## Решение

Все уничтоженные вершины лежат на пути от `k` до фишки, поэтому
единственный сосед, куда фишка пойти не может, — тот, откуда она пришла.
Любая партия — это спуск по дереву с корнем `k`, и позиция зависит только
от текущей вершины.

Значит, это классический анализ выигрышных и проигрышных позиций: вершина
выигрышна для ходящего, если хотя бы один её ребёнок проигрышный; лист
проигрышный. Первый игрок выигрывает, если у `k` есть проигрышный
ребёнок, и ответ — наименьший такой ребёнок.

Дерево может быть путём из 1000 вершин, поэтому решения обходятся без
глубокой рекурсии: порядок обхода в ширину от `k` ставит родителей раньше
детей, а проход по нему с конца помечает родителя выигрышным, как только
найден проигрышный ребёнок. `O(n)`.

Подводные камни:

- нужен наименьший выигрывающий ход, а не первый во входных данных;
- `n = 1`: нет рёбер и нет хода, первый игрок проигрывает;
- первый игрок выигрывает, только переходя в *проигрышного* ребёнка;
  ребёнок, выигрышный для следующего игрока, — плохой ход.

Учебная версия C++ записывает рекуррентное правило напрямую через обход в глубину. В дереве предыдущий аэропорт — единственный разрушенный сосед. Вызов возвращает победу, как только находит ход в проигрышную для соперника позицию. Если такого хода нет, позиция проигрышная. В стартовом аэропорту выбираем наименьший номер среди выигрышных ходов. Проверяемые поддеревья не пересекаются, поэтому время O(n). Стек хранит один путь глубиной до n ≤ 1000.

## Оптимизированные решения

Go сохраняет ту же динамику выигрышных и проигрышных позиций дерева, но удаляет листья кроме корня вместо построения списков смежности и обхода с массивами родителей и порядка. В вершине хранятся XOR номеров оставшихся соседей, 8-битная степень и флаг выигрыша. 16-битная очередь содержит каждую удаляемую вершину один раз. При степени один XOR равен единственному родителю. Проигрышный ребёнок делает родителя выигрышным; исключаем его XOR и уменьшаем степень, добавляя нового листа кроме корня. Корень никогда не добавляется в очередь, а остальные вершины обрабатываются после всех своих детей. Если родитель — начальный аэропорт, выбираем минимальный номер проигрышного ребёнка. Для единственной вершины ответ — проигрыш. Номера≤1000 помещаются в 16 бит, степень≤20 — в 8. Статические массивы и прямое обращение к стандартным дескрипторам сокращают расход памяти. Короткий ответ записывается в фиксированный байтовый буфер. Время и память O(n). Простые программы сохранены, остальные четыре семейства используют подходящие базы.

Принятая версия Go 1.14 x64 заняла 0.062 с при 0.031 с у базовой и использовала 348 KB при 1216 KB у базовой.

Принятые базовые реализации [1045_games.cpp](1045_games.cpp), [1045_games.java](1045_games.java), [1045_games.py](1045_games.py), [1045_games.rs](1045_games.rs) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.

## Особенности языков

Исходные файлы строят порядок обхода в ширину и обрабатывают его с конца. Оптимизированный Go вычисляет ту же динамику, удаляя листья кроме корня.
