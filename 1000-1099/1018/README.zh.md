# 1018. 保留二叉树中最有价值的连通树枝

[Timus 1018](https://acm.timus.ru/problem.aspx?space=1&num=1018) · 难度 280 · dp, trees

原题出自 Ural State University Internal Contest '99 #2。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

一棵树有 `N` 个顶点（`2 ≤ N ≤ 100`），编号 `1..N`，根为 `1`；每个顶点有零个或两个孩子。`N - 1` 条边
（树枝）上各有 0 到 30 000 个苹果。恰好保留 `Q` 条树枝（`1 ≤ Q ≤ N - 1`），使它们仍与根相连——即删去一
根树枝会连带去掉它上方的一切——并使保留树枝上的苹果总数最大。输出这个数。

时间限制：1 秒。内存限制：64 MB。

## 输入

先是 `N` 和 `Q`，然后 `N - 1` 行 `a b c`：顶点 `a` 与 `b` 之间（顺序任意）有一根带 `c` 个苹果的树枝。

## 输出

最大的苹果数。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 样例

### 样例 1

输入：

```
7 3
1 2 1
1 3 5
2 4 9
2 5 9
3 6 2
3 7 3
```

输出：

```
19
```

### 样例 2

输入：

```
2 1
2 1 30000
```

输出：

```
30000
```

## 题解

保留的树枝构成一棵包含根的子树。以 1 为根（输入中边的方向任意），对每个顶点 `v` 计算表 `best_v[k]`：
在 `v` 的子树中保留 `k` 根且都与 `v` 相连的树枝时，苹果数的最大值。

**树上背包。** 从 `best = [0]`（什么都不保留）开始。对 `v` 的每个孩子 `c`，边 `v–c` 上有 `w` 个苹果：在
这一侧保留 `j ≥ 1` 根树枝，意味着保留这条边本身以及 `c` 下方的 `j - 1` 根，价值为 `w + best_c[j - 1]`。
像背包一样把它合并进当前表：

`new[i + j] = max(new[i + j], best[i] + (j = 0 ? 0 : w + best_c[j - 1]))`。

答案为 `best_1[Q]`。把每张表截断到 `Q + 1` 项，所有合并共 `O(N · Q^2)`——至多约 `10^6` 步；若表长限制为
子树大小，甚至是 `O(N^2)`。

为何保持连通：`c` 下方的树枝只会与边 `v–c` 一起被计入（`j ≥ 1` 的情形），因此没有保留的树枝悬空。

注意事项：

- 边可能以“孩子 父亲”的顺序给出：先建无向邻接表，再从 1 出发深度优先遍历定根；
- 每次贪心选可用的最重树枝是错的：一根轻的树枝可能通向很重的树枝。

各语言都使用同样的递归深度优先遍历；深度至多 100。
