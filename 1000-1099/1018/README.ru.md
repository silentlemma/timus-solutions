# 1018. Сохранение самых ценных связных ветвей двоичного дерева

[Timus 1018](https://acm.timus.ru/problem.aspx?space=1&num=1018) · сложность 281 · dp, graphs, trees

Оригинальная задача — Ural State University Internal Contest '99 #2.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В дереве `N` вершин (`2 ≤ N ≤ 100`), пронумерованных `1..N`, корень — `1`;
у каждой вершины ноль или два ребёнка. На каждом из `N - 1` рёбер (ветвей)
от 0 до 30 000 яблок. Оставьте ровно `Q` ветвей (`1 ≤ Q ≤ N - 1`) так,
чтобы они оставались связаны с корнем, то есть удалённая ветвь уносит всё,
что выше неё, а число яблок на оставленных ветвях было наибольшим. Выведите
это число.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `Q`, затем `N - 1` строк `a b c`: ветвь между вершинами `a` и `b` (в
любом порядке) с `c` яблоками.

## Выходные данные

Наибольшее число яблок.

## Решение

Оставленные ветви образуют поддерево, содержащее корень. Подвесим дерево за
вершину 1 (во входе рёбра даны в произвольном направлении) и посчитаем для
каждой вершины `v` таблицу `best_v[k]`: наибольшее число яблок на `k`
ветвях, оставленных в поддереве `v` и связанных с `v`.

**Рюкзак на дереве.** Начинаем с `best = [0]` (ничего не оставлено). Для
каждого ребёнка `c` вершины `v` с `w` яблоками на ребре `v–c`: оставить
`j ≥ 1` ветвей с этой стороны — значит оставить само ребро и `j - 1` ветвей
ниже `c`, что даёт `w + best_c[j - 1]`. Сливаем это с текущей таблицей как
рюкзак:

`new[i + j] = max(new[i + j], best[i] + (j = 0 ? 0 : w + best_c[j - 1]))`.

Ответ — `best_1[Q]`. Если обрезать каждую таблицу до `Q + 1` элементов,
слияния стоят в сумме `O(N · Q^2)` — не больше примерно `10^6` шагов; при
таблицах размером с поддерево это даже `O(N^2)`.

Почему связность сохраняется: ветвь ниже `c` учитывается только вместе с
ребром `v–c` (случай `j ≥ 1`), так что ни одна оставленная ветвь не висит в
воздухе.

Подводные камни:

- во входном дереве у каждой вершины ноль или два ребёнка, поэтому в нём
  минимум три вершины; при этом оставить одну ветвь допустимо (тест 02);
- ребро может быть дано как «ребёнок родитель»: стройте неориентированный
  список смежности и подвешивайте его обходом в глубину от 1;
- жадный выбор самой тяжёлой доступной ветви неверен: лёгкая ветвь может
  вести к тяжёлым.

## Оптимизированные решения

Учебная динамика слияния поддеревьев сохранена. Развернём укоренённое дерево в preorder: некорневая вершина с потомками занимает интервал [pos,end), веса входящих рёбер соответствуют тому же интервалу. В режиме максимума оставленных рёбер берём текущее и идём на следующую позицию либо пропускаем всё поддерево. В режиме минимума удалённых рёбер сохраняем текущее без удаления либо удаляем весь интервал с весом по префиксной сумме. Пропуск предка перескакивает через потомков, значит, у достигнутой позиции все предки уже оставлены и отдельного состояния для них не нужно. При K=min(Q,N-1-Q) максимизируем Q оставленных либо минимизируем потерю дополнения и вычитаем её из общего веса. На ячейку два перехода: O(N(1+K)) времени и памяти с подготовкой. Если нужны все рёбра, сразу возвращается сумма. Python использует собственные списки целых PyPy.

- `1018_dp_graphs.java`: 0.125 s / 368 KB; база `1018_dp_trees.java`: 0.140 s / 1912 KB; изменение относительно базы: время -10.7%, память -80.8%.
- `1018_dp_graphs.py`: 0.125 s / 408 KB; база `1018_dp_trees.py`: 0.078 s / 596 KB; изменение относительно базы: время +60.3%, память -31.5%.
