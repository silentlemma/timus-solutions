# 1005. Разбиение весов на две кучи

[Timus 1005](https://acm.timus.ru/problem.aspx?space=1&num=1005) · сложность 78 · dp, bitmask, bruteforce, meet_in_middle

Оригинальная задача — чемпионат Уральского государственного университета 1997 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Даны `n` положительных целых чисел `w1, ..., wn` (`1 ≤ n ≤ 20`,
`1 ≤ wi ≤ 100 000`). Разбейте их на две группы так, чтобы разность сумм групп
была как можно меньше. Выведите эту разность. Группа может быть пустой.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Число `n`, затем `n` весов через пробельные символы.

## Выходные данные

Одно целое число — наименьшая возможная разность.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
5
5 8 13 27 14
```

Вывод:

```
3
```

### Пример 2

Ввод:

```
1
100000
```

Вывод:

```
100000
```

## Решение

Если одна группа весит `s`, другая весит `total - s`, а разность равна
`|total - 2s|`. Значит, нужно найти сумму подмножества `s ≤ total / 2`,
ближайшую к `total / 2`.

**Суммы подмножеств (dp).** `reach[s]` показывает, можно ли набрать ровно `s`;
начинаем с `reach[0]` и добавляем веса по одному, проходя `s` сверху вниз,
чтобы каждый вес использовался не больше одного раза. Важны только суммы до
`total / 2 ≤ 1 000 000`, поэтому это не больше `20 · 10^6` шагов и `O(total)`
памяти. Ответ даёт наибольшая достижимая `s ≤ total / 2`.

**Битсет (dp, bitmask).** Та же таблица помещается в одно целое число, бит `s`
которого — `reach[s]`: добавление веса `x` — это `reach |= reach << x`. В
Python с его целыми произвольной точности это работает сразу целыми машинными
словами и намного быстрее цикла по `s`.

Подводные камни:

- сумма до `2 · 10^6`: `int` хватает, но таблица по всем суммам до `total`
  тратит лишнюю память — достаточно `total / 2`;
- `n = 1`: ответ равен единственному весу.

## Оптимизированные решения

**Все подмножества** (C++). При `n ≤ 20` можно перебрать все `2^20`
подмножеств. В порядке кода Грея каждое следующее подмножество отличается
от предыдущего одним весом, поэтому сумма обновляется за `O(1)`; последний
вес можно оставить во второй группе, это вдвое сокращает работу. Время
`O(2^(n-1))` и никакой таблицы, поэтому памяти нужно намного меньше, чем
ДП: 200 КБ вместо 1124 КБ при том же времени.

**Встреча посередине** (Go, Java, Rust). Разделим веса на две половины не
больше чем по 10 и выпишем суммы всех подмножеств каждой половины, не
больше 1024, в отсортированном виде. Куча — это подмножество одной
половины плюс подмножество другой, поэтому идём по суммам левой половины
вверх, а по суммам правой — вниз, сдвигая ту сторону, которая приближает
кучу к `total / 2`; каждая пропущенная так пара не лучше уже
просмотренной. Проход останавливается раньше, когда разность становится
равной `total mod 2`: лучше не бывает. Время `O(n·2^(n/2))` и несколько
килобайт памяти вместо таблицы из `total / 2` элементов. Go и Java к тому
же разбирают ввод вручную из небольшого буфера. При том же времени
решению на Go нужно 920 КБ вместо 2000 КБ, на Java — 472 КБ вместо
1388 КБ, на Rust — 244 КБ вместо 1144 КБ.

## Особенности языков

- **C++**, **Go**, **Java**, **Rust**: простые решения заполняют булеву
  таблицу сумм подмножеств, около `2 · 10^7` простых шагов.
- **Python**: битсет на длинном целом; обычный двойной цикл по весам и суммам
  был бы слишком медленным.
