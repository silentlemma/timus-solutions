# 1098. 每数到第 1999 个就删去，最后剩下的字符

[Timus 1098](https://acm.timus.ru/problem.aspx?space=1&num=1098) · 难度 557 · math

原题作者 Stanislav Vasiliev，出自 1999 年第三届乌拉尔大学生团体程序设计锦标赛的练习赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

问题是去掉换行后的全部输入（1 到 30000 个字符；空格和标点都算）。从第一个字符开始数 `N − 1` 个字符，删去第 `N`
个，到结尾时回到开头继续数；然后从被删字符的下一个字符重新开始数，直到只剩一个字符，`N = 1999`。若剩下的是
`?`，输出 `Yes`；若是空格，输出 `No`；否则输出 `No comments`。

时间限制：1 秒。内存限制：64 MB。

## 输入

问题，可能分成多行。

## 输出

`Yes`、`No` 或 `No comments`。

## 评测方式

按行比较输出；行内按记号逐个比较。

## 样例

### 样例 1

输入：

```
Does the jury of this programming contest use the
algorithm described in this problem to answer my questions?
```

输出：

```
Yes
```

### 样例 2

输入：

```
At least, will anybody READ my question?
```

输出：

```
No
```

### 样例 3

输入：

```
This is
UNFAIR!
```

输出：

```
No comments
```

## 题解

这是约瑟夫问题。设 `J(m)` 为 `m` 个字符中最后剩下的那个相对于计数起点的位置。第一次删除后剩下 `m − 1` 个字符，
计数从往后 `N` 个位置处开始，所以 `J(m) = (J(m − 1) + N) mod m`，`J(1) = 0`。递推到问题的长度就得到这个位置，
只有那里的字符才重要。`O(L)`。

设 L 为去掉换行后的长度，I 为包括换行的原始读取字节数。递推算术
用 O(1) 状态、O(L) 时间。简单 C++/Java 存 O(L) 文本，
Go/Python/Rust 可保留 O(I+L) 原始与过滤数据。读完再递推共
O(I+L)，即使换行很多也如此。优化 Python 的临时字节串占
O(I+L)。Go/Rust 位集固定保留两个各 ceil(MAX_LENGTH/8) 字节
的数组，MAX_LENGTH=30000，另加有界输入输出缓冲。

五个简单 1098_math 源码仅澄清 Josephus 下标原点：从原始计数
起点零起编号，删除后作模平移。表中 ID 和配对测量属于前一注释
修订：C++ #11321759、Go #11322213、Java #11321761、Python
#11322214、Rust #11322215。算法、有意义的简单实现和注释均保留。

从字符串中一个一个地删除字符需要 `O(L²)`（`L = 30000`）：在编译型语言中也够快，但递推式完全避免了这一点。

注意事项：

- 除换行外的每个字符都要算，包括行尾和单词之间的空格，所以按原始字节读取输入，只去掉 `\n` 和 `\r`；
- 问题可能只有一个字符，这时答案就由它决定。

答案与一个从列表中逐个删去每第 1999 个字符的直接模拟做了核对。

## 各语言说明

- Rust 在 `2..=L` 上用折叠计算递推式。
- Java 和 C++ 逐字节读取输入，从而保留每一个空格。

## 优化解法

Python 版本通过两次字节串操作去掉回车符和换行符。过滤后的字节串既提供约瑟夫递推所需的长度，也可直接取出最后留下的字节。提交 11316943 使用 348 KB，基础版使用
500 KB，显示运行时间保持 0.078 秒。

Go 用两个位集合分别保存问号和空格的位置，读入时跳过换行符。约瑟夫递推得到最后保留的位置，再根据该位置的两个比特确定答案。 提交 11317592 用时 0.015 秒、使用 900 KB，基础版用时 0.015 秒、使用 1304 KB。

**简单版本的 Timus 提交记录**

G++ 13.2 x64 №11321759 · Go 1.14 x64 №11322213 · Java 1.8 №11321761 · Python 3.12 x64 №11322214 · Rust 1.75 x64 №11322215.

Rust 用两个位集记录问号和空格，并从预计算的检查点继续约瑟夫递推。 Rust 1.75 x64（提交 11323266）的运行时间从 0.015 秒变为 0.015 秒，内存从 224 KB 变为 56 KB。

Rust 仍扫描所有 I 个原始字节。STRIDE=128 检查点只把递推尾部
减到至多 127 次更新，总运行时间为 O(I+STRIDE)，不是按固定
删除步 N=1999 的 O(N)。编译时检查点构造用 O(MAX_LENGTH) 工作
并存 O(MAX_LENGTH/STRIDE) 个 u16，与两个分类位集分开计算。
这项递推捷径并不改变线性输入扫描。
