# 1098. Последний символ после вычёркивания каждого 1999-го

[Timus 1098](https://acm.timus.ru/problem.aspx?space=1&num=1098) · сложность 557 · math

Автор оригинальной задачи — Станислав Васильев; пробный тур III командного студенческого чемпионата Урала по программированию, 1999 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Вопрос — это весь ввод без переводов строк (от одного до 30000 символов;
пробелы и знаки препинания считаются). Начиная с первого символа,
отсчитываем `N − 1` символов и удаляем `N`-й, переходя к началу при
достижении конца; затем считаем снова с символа после удалённого, пока не
останется один символ, при `N = 1999`. Выведите `Yes`, если это `?`,
`No`, если это пробел, и `No comments` иначе.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

Вопрос, возможно, на нескольких строках.

## Выходные данные

`Yes`, `No` или `No comments`.

## Проверка

Вывод сравнивается построчно; внутри строки — по токенам.

## Примеры

### Пример 1

Ввод:

```
Does the jury of this programming contest use the
algorithm described in this problem to answer my questions?
```

Вывод:

```
Yes
```

### Пример 2

Ввод:

```
At least, will anybody READ my question?
```

Вывод:

```
No
```

### Пример 3

Ввод:

```
This is
UNFAIR!
```

Вывод:

```
No comments
```

## Решение

Это задача Иосифа Флавия. Пусть `J(m)` — позиция, считая от начала
отсчёта, последнего оставшегося из `m` символов. После первого удаления
остаётся `m − 1` символ, а отсчёт начинается на `N` мест дальше, так что
`J(m) = (J(m − 1) + N) mod m` при `J(1) = 0`. Один проход до длины вопроса
даёт позицию, и важен только символ в ней. `O(L)`.

Пусть L — длина после удаления переводов строк, I — число прочитанных
байтов вместе с ними. Арифметика рекурсии использует O(1) состояния
и O(L) времени. Простые C++/Java хранят O(L) текста; Go/Python/Rust
могут хранить O(I+L) исходных и отфильтрованных данных. Полное чтение
с рекурсией занимает O(I+L), даже при множестве переводов строк.
Быстрый Python временно хранит O(I+L) байтовых строк. Битовые версии
Go/Rust резервируют два массива по ceil(MAX_LENGTH/8) байтов,
MAX_LENGTH=30000, плюс ограниченные буферы ввода/вывода.

Пять простых исходников 1098_math теперь уточняют только начало
отсчёта индекса Иосифа: с нуля от исходного начала счёта с переводом
по модулю после удаления. Табличные номера и парные замеры относятся
к предыдущим комментариям: C++ #11321759, Go #11322213, Java #11321761,
Python #11322214 и Rust #11322215. Алгоритмы, содержательные
простые реализации и комментарии сохранены.

Удаление символов по одному из строки стоило бы `O(L²)` при `L = 30000`:
в компилируемом языке это достаточно быстро, но рекуррентность обходится
вообще без этого.

Подводные камни:

- считается каждый символ, кроме переводов строк, в том числе пробелы в
  концах строк и между словами, поэтому ввод читается как сырые байты и
  отбрасываются только `\n` и `\r`;
- вопрос может состоять из одного символа, и тогда ответ определяет он.

Ответы сверены с прямой моделью, удаляющей каждый 1999-й символ из
списка.

## Особенности языков

- Rust сворачивает рекуррентность по `2..=L`.
- Java и C++ читают ввод побайтно, что сохраняет каждый пробел.

## Оптимизированные решения

Версия Python удаляет возвраты каретки и переводы строк двумя операциями над байтовой
строкой. Отфильтрованная строка даёт и длину для формулы Иосифа, и итоговый байт. Повторный
посимвольный проход на Python больше не нужен. Посылка 11316943 заняла 348 КБ вместо 500 КБ,
а показанное время осталось тем же: 0,078 с.

Go хранит позиции вопросительных знаков и пробелов в двух битовых массивах и пропускает переводы строк при чтении. Формула Иосифа находит оставшуюся позицию, а два её бита определяют ответ. Посылка 11317592 заняла 0,015 с и использовала 900 КБ, у простой версии 0,015 с и 1304 КБ.

**Посылки Timus для простых версий**

G++ 13.2 x64 №11321759 · Go 1.14 x64 №11322213 · Java 1.8 №11321761 · Python 3.12 x64 №11322214 · Rust 1.75 x64 №11322215.

Rust хранит два битовых массива для вопросительных знаков и пробелов и продолжает рекурсию Иосифа с заранее вычисленной контрольной позиции. Rust 1.75 x64, посылка 11323266. Время 0,015 → 0,015 с, память 224 → 56 КБ.

Rust всё равно сканирует все I байтов. Контрольные точки STRIDE=128
сокращают только хвост рекурсии до 127 обновлений, поэтому всё время
O(I+STRIDE), а не O(N) по постоянному шагу удаления N=1999. Построение
контрольных точек при компиляции требует O(MAX_LENGTH) работы и хранит
O(MAX_LENGTH/STRIDE) значений u16, отдельно от двух битовых массивов.
Чтение остаётся линейным, несмотря на сокращение вычислений рекурсии.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
