# 1061. Самое дешёвое окно незаблокированных буферов

[Timus 1061](https://acm.timus.ru/problem.aspx?space=1&num=1061) · сложность 670 · prefix_sums

Оригинальная задача — полуфинал ACM ICPC Северо-Восточной Европы 2000–2001.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `N` буферов (`1 ≤ N ≤ 100000`), каждый заблокирован (`*`) или хранит
ценность от 0 до 9. Выберите `K` подряд идущих буферов (`1 ≤ K ≤ 10000`),
среди которых нет заблокированных, с наименьшей суммарной ценностью, и
выведите номер `L` первого из них; при равных суммах — наименьший `L`.
Выведите `0`, если такого окна нет.

Ограничение времени: 0,5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `K`, затем `N` состояний по 80 символов в строке (последняя строка
может быть короче).

## Выходные данные

`L` или `0`.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
100 53
2165745216091853477755800393859785807207523169954341**7363*9*94664808*4777717089
09825185827659480548
```

Вывод:

```
0
```

### Пример 2

Ввод:

```
100 10
2165745216091853477755800393859785807207523169954341**7363*9*94664808*4777717089
09825185827659480548
```

Вывод:

```
36
```

## Решение

Две префиксные суммы по буферам: суммарная ценность и число
заблокированных среди первых `i`. Окно `[L, L + K − 1]` допустимо, если
число блокировок на нём не меняется, а его ценность — разность сумм
ценностей. Проверка всех `N − K + 1` окон слева направо с заменой лучшего
только при строго меньшей ценности даёт наименьший `L` среди самых
дешёвых. `O(N)`.

Подводные камни:

- `K > N`: окон нет вовсе, ответ `0`;
- равенство: оставляем первое окно, поэтому лучшее заменяется только при
  строго меньшей ценности;
- состояния разбиты на строки по 80 символов: читаем символы и
  пропускаем переводы строк;
- у заблокированных буферов нет ценности; они только запрещают окна.

## Особенности языков

- **C++**, **Go**, **Java**: состояния читаются посимвольно после двух
  чисел.
- **Python**, **Rust**: весь ввод разбивается на слова, и строки
  склеиваются.

## Оптимизированные решения

Версия Python делит вход на участки незаблокированных буферов. В каждом участке скользящее окно из K буферов вычитает ушедшее значение и прибавляет вошедшее. Ответ обновляется только при строго меньшей сумме, поэтому при равенстве остаётся первая позиция. Время O(N), память с учётом входа и участков O(N). Посылка 11317122 заняла 0,093 с и 1048 КБ против 0,125 с и 9992 КБ у базы.

Go читает состояния потоком и хранит последние K значений в кольцевом буфере байтов. Заблокированный буфер сбрасывает окно. Время O(N), память O(K). Посылка 11317123 заняла 0,015 с и 1088 КБ против 0,031 с и 2704 КБ у базы.

Rust читает состояния потоком и хранит последние K значений в кольцевом буфере байтов. Заблокированный буфер сбрасывает окно. Время O(N), память O(K). Посылка 11317124 заняла 0,015 с и 204 КБ против 0,015 с и 2196 КБ у базы.

C++ читает состояния потоком и хранит последние K значений в кольцевом буфере байтов. Заблокированный буфер сбрасывает окно. Время O(N), память O(K). Посылка 11317125 заняла 0,015 с и 184 КБ против 0,015 с и 1356 КБ у базы.

Java читает состояния потоком и хранит последние K значений в кольцевом буфере байтов. Заблокированный буфер сбрасывает окно. Время O(N), память O(K). Посылка 11317126 заняла 0,093 с и 408 КБ против 0,109 с и 1592 КБ у базы.
