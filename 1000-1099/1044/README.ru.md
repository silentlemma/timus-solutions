# 1044. Подсчёт сбалансированных билетов из N цифр

[Timus 1044](https://acm.timus.ru/problem.aspx?space=1&num=1044) · сложность 123 · bruteforce

Автор оригинальной задачи — Станислав Васильев; Пятый командный чемпионат УрГУ по программированию, октябрь 2000 года.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Номер билета состоит из `N` цифр (`N` чётно, `2 ≤ N ≤ 8`; ведущие нули
допускаются). Билет сбалансирован, если суммы первой и второй половины
цифр равны. Посчитайте сбалансированные билеты.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Число сбалансированных билетов.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
670
```

### Пример 2

Ввод:

```
2
```

Вывод:

```
10
```

## Решение

Половины независимы. Для каждой суммы `s` посчитаем, сколько чисел меньше
`10^(N/2)` имеют сумму цифр `s`: нужно перебрать не больше 10000 чисел.
Сбалансированный билет — это пара половин с одинаковой суммой, поэтому
ответ — сумма `ways[s]^2` по всем `s`. `O(10^(N/2) · N)`.

При `N = 8` ответ 4816030, он помещается в 32 бита, но вне Python квадраты
всё равно суммируются в 64-битных целых.

Подводные камни:

- ведущие нули учитываются: `0000` — тоже билет;
- в каждой половине `N / 2` цифр, а не `N`.

[Задача 1036](../1036/README.ru.md) спрашивает то же для номеров до
100 цифр и фиксированной общей суммы; там количества считаются
динамикой и требуют длинной арифметики.

## Оптимизированные решения

Оптимизированное решение на C++ хранит счётчики в массиве на
37 элементов на стеке вместо `std::vector`: при `N ≤ 8` в половине не
больше четырёх цифр, и её сумма цифр не больше 36. Библиотека
контейнеров программе тогда вообще не нужна:
{1044_bruteforce_optimized.cpp}.

Оптимизированное решение на Java читает `N` побайтно из `System.in`
вместо того, чтобы создавать `Scanner`, чьи регулярные выражения и
данные локали обходятся дороже самого подсчёта; подсчёт тот же:
{1044_bruteforce_optimized.java}.

Быстрая версия Go использует динамику по сумме цифр вместо перебора всех половин. Добавление цифры сворачивает текущие количества с десятью единицами; скользящая сумма вычисляет каждое новое количество за постоянное время. После `N/2` шагов сумма квадратов количеств даёт ответ. Время — `O(N²)`, дополнительная память — `O(N)`. Перебор сохраняется как базовая реализация.

{1044_dp.go}.

Accepted для соответствующих исходников: базовая версия 0.046 с / 1080 КБ; эта версия 0.015 с / 804 КБ (посылка 11307438). В срезе от 2026-10-31 рейтинговая цель достигнута.

### Измеренный выигрыш

Каждая оптимизированная версия имеет Accepted и сокращает время или
память минимум на 30% относительно базовой версии на том же языке.
Базовые исходники сохранены. Отрицательное сокращение означает рост
расхода. Звёздочка относится только к рейтинговой цели.

- `1044_bruteforce_optimized.cpp`: сокращение времени +0.00%; сокращение
  памяти +36.73%; база: `1044_bruteforce.cpp`.

- `1044_dp.go`: сокращение времени +67.39%; сокращение памяти +25.56%;
  база: `1044_bruteforce.go`.

- `1044_bruteforce_optimized.java`: сокращение времени +16.13%;
  сокращение памяти +79.64%; база: `1044_bruteforce.java`.
