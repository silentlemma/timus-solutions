# 1044. Подсчёт сбалансированных билетов из N цифр

[Timus 1044](https://acm.timus.ru/problem.aspx?space=1&num=1044) · сложность 122 · bruteforce

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Номер билета состоит из `N` цифр (`N` чётно, `2 ≤ N ≤ 8`; ведущие нули
допускаются). Билет сбалансирован, если суммы первой и второй половины
цифр равны. Посчитайте сбалансированные билеты.

Ограничение времени: 2 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N`.

## Выходные данные

Число сбалансированных билетов.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
4
```

Вывод:

```
670
```

### Пример 2

Ввод:

```
2
```

Вывод:

```
10
```

## Решение

Половины независимы. Для каждой суммы `s` посчитаем, сколько чисел меньше
`10^(N/2)` имеют сумму цифр `s`: нужно перебрать не больше 10000 чисел.
Сбалансированный билет — это пара половин с одинаковой суммой, поэтому
ответ — сумма `ways[s]^2` по всем `s`. `O(10^(N/2) · N)`.

При `N = 8` ответ 4816030, он помещается в 32 бита, но квадраты всё равно
суммируются в 64-битных целых.

Подводные камни:

- ведущие нули учитываются: `0000` — тоже билет;
- в каждой половине `N / 2` цифр, а не `N`.

[Задача 1036](../1036/README.ru.md) спрашивает то же для номеров до 100
цифр и фиксированной общей суммы; там количества считаются динамикой и
требуют длинной арифметики.

## Особенности языков

- Во всех языках один и тот же подсчёт; Python берёт сумму цифр
  `str(x)`.
