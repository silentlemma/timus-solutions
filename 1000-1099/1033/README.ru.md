## Задача

Лабиринт — сетка `N × N` (`3 ≤ N ≤ 33`) клеток 3 × 3 метра: `.` — пустая
клетка, `#` — сплошной блок. Лабиринт окружён внешней стеной, кроме левой
верхней и правой нижней клеток, которые служат входами (они всегда пустые).
Высота стен 3 метра. Посетитель ходит между пустыми клетками с общей
стороной; блоки, касающиеся углами, щели не оставляют. Найдите суммарную
площадь стен, которые посетитель может увидеть из частей лабиринта,
достижимых от входов.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`N`, затем `N` строк по `N` символов `.` и `#`.

## Выходные данные

Видимая площадь стен в квадратных метрах.

## Проверка

Сравнивается один целочисленный токен. Новый Rust прошёл 569 исполнений против отдельного клеточного BFS: все 128 лабиринтов 3x3 со свободными углами, случайные поля, стороны 31/32/33, разные и общая компоненты входов, пробелы/границы блоков и 11 тестов репозитория.

## Решение

Видимая грань — сторона достижимой из входа пустой клетки, обращённая
к каменному блоку или внешней границе. Запускаем обход по четырём соседям
из обеих входных клеток. Отмечаем при добавлении, чтобы общая компонента
двух входов не обходилась дважды. Для каждой достигнутой клетки считаем
стороны к `#` или за границу; сторону к другой пустой клетке не считаем.

Это перечисляет ровно видимые грани: у каждой есть единственная смежная
пустая клетка, и она должна быть достижима. Разные стороны одного блока
считать отдельно правильно. Закрытые комнаты исключены. Вычитаем четыре
внешние стороны двух входных углов — там проёмы. Умножаем на 9: ширина
грани 3 м, высота 3 м.

Базы C++, Go, Java и Rust используют очередь клеток, Python — стек.
Порядок не меняет достижимое множество и число граней. Каждая пустая
клетка добавляется не более раза, соседей четыре: `O(N²)` времени
и памяти. Перемещаться можно только через общую сторону, касание по
диагонали не даёт прохода. Входы могут принадлежать разным компонентам.

## Оптимизированные решения

Сохранённые масочные C++/Java/Python объединяют горизонтальные действия над клетками в операции над ограниченными словами; хранение всех входных токенов в старом Python по-прежнему даёт квадратичную память. Первоначальные клеточные BFS/DFS остаются учебными версиями.

Rust обходит маски строк без динамических выделений. Отмечаются оба входа. В изменившейся строке достижимость замыкается по горизонтали внутри пустых клеток, затем новые биты передаются соседним строкам. Маска строк в очереди исключает дубли; фиксированное кольцо с отдельным счётчиком допускает одновременное присутствие всех N строк. Каждое назначение строки и расширение по горизонтали связано с новой клеткой: всего `O(N²)` операций над словами. При N≤33 строка помещается в 64 бита. Четыре направления стен считаются популяционным подсчётом, внешняя граница включается; до умножения на девять вычитаются четыре входные грани. Объединение достижимых компонент учитывается один раз. Хранятся только маски, номера строк и 128-байтовый ввод. POSIX read/write работают прямо с ограниченными буферами, без буферов stdio и форматтера; число переводится в фиксированный байтовый массив. Чтения, сдвиги и индексы соблюдают границу стороны.
