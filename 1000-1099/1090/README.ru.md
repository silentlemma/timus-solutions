# 1090. Шеренга новобранцев, которая прыгает больше всех: подсчёт инверсий

[Timus 1090](https://acm.timus.ru/problem.aspx?space=1&num=1090) · сложность 366 · fenwick, binary_search

Автор оригинальной задачи — Никита Шамгунов; USU Open Collegiate Programming Contest, март 2001 года, Senior Session.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

Есть `K` шеренг (`1 ≤ K ≤ 20`) по `N` новобранцев (`2 ≤ N ≤ 10000`),
занумерованных по росту от 1 (самый высокий) до `N`; каждая шеренга —
перестановка чисел `1 … N`. Каждый новобранец подпрыгивает по разу за
каждого стоящего перед ним в шеренге с большим номером. Выведите
шеренгу с наибольшим общим числом прыжков, при равенстве — с наименьшим
номером.

Ограничение времени: 0.5 секунды. Ограничение памяти: 64 МБ.

## Входные данные

`N` и `K`, затем `K` строк по `N` чисел.

## Выходные данные

Номер шеренги.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Примеры

### Пример 1

Ввод:

```
3 3
1 2 3
2 1 3
3 2 1
```

Вывод:

```
3
```

## Решение

Общее число прыжков в шеренге — это число инверсий перестановки: пар
позиций `i < j` с `a[i] > a[j]`. При `N = 10000` двойной цикл слишком
медленный, поэтому считаем их по ходу чтения шеренги. Перед новобранцем
`x` на позиции `i` стоят `i` новобранцев, а число тех из них, у кого
номер меньше, — это префиксная сумма в дереве Фенвика по номерам
`1 … N`; прыжки `x` равны `i` минус эта сумма. Затем добавляем `x` в
дерево. `O(K · N log N)`.

Учебный Python хранит предыдущие значения в отсортированном порядке.
bisect даёт индекс вставки: i-index предыдущих значений больше текущего
и дают столько инверсий. Затем list.insert сдвигает суффикс, сохраняя
сортировку; в строке все значения различны. Поиск занимает O(log N),
но сдвиг O(N) на вставку, всего O(K N^2) времени. Список и срез текущей
строки требуют O(N) рабочих слов; именно этот исходник также хранит
O(KN) разобранных входных целых отдельно от рабочего состояния.

Подводные камни:

- максимум N(N-1)/2=49 995 000 помещается в знаковые 32 бита.
  Учебные C++/Go/Java/Rust используют 64-битные суммы, быстрый C++ —
  int, быстрый Go — машинный int, безопасные при этой границе.
  Целые Python не ограничены.
- при равенстве побеждает первая шеренга, поэтому лучшую заменяет только
  строго большая сумма;
- дерево нужно очищать для каждой шеренги.

Ответы сверены с подсчётом инверсий сортировкой слиянием, а при
`N ≤ 300` — ещё и двойным циклом.

## Оптимизированные решения

Версии на C++ и Go сохраняют дерево Фенвика и читают вход через буфер фиксированного размера. В ячейке дерева хранится счётчик до N, который помещается в 16 бит. В версии для PyPy отсортированный список заменён деревом Фенвика, поэтому запрос суммы и добавление занимают O(log N). Все три версии работают за O(K·N log N) и используют O(N) дополнительной памяти.

Текущий кэшированный аудит подтверждает простую Java только по месту
времени ниже 1 МиБ. Простой Rust не проходит обе метрики эталона малой
выборки точного компилятора; отдельный быстрый Rust теперь проходит
по эталону времени ниже 1 МиБ. Быстрый C++ использует место времени,
Go — эталон времени малой выборки, PyPy требует и проходит оба обычных
места. Действуют общие [рейтинговые критерии](../../RATING_CRITERIA.md).
Все учебные исходники сохранены, проходящие файлы используются без копий.

### Новые принятые версии

Для версий ниже применяются единые [рейтинговые критерии](../../RATING_CRITERIA.md) и Accepted точного исходника. Более ранние обсуждения производительности описывают исторические посылки и срезы, а не отдельное действующее правило допуска. Содержательные простые и прежние отличающиеся реализации сохранены.

Десятичный разбор сохраняет знаковые границы без хранения всего командного ввода. Точка входа C напрямую вызывает решение и сбрасывает вывод Rust перед возвратом; архивная реализация с обычной точкой входа сохранена.

исходник и содержательные комментарии сохранены.

## Особенности языков

Учебная версия Python использует отсортированный список с двоичным поиском и принята под PyPy 3.10. Тот же исходник под CPython 3.12 превысил лимит времени на тесте 9 (0,515 с). Оптимизированная версия Python использует дерево Фенвика и также принята под PyPy 3.10. В таблице указан фактический интерпретатор каждой принятой посылки.

Описанные выше ревизии исходников уже получили собственные Accepted. В таблицах решений указаны итоговые номера посылок и парные измерения времени и памяти для соответствующих файлов; прежние наблюдения относятся к предыдущим ревизиям. Все содержательные простые реализации сохранены.
