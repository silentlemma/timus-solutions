# 1029. Самый дешёвый путь наверх по зданию с кабинетами

[Timus 1029](https://acm.timus.ru/problem.aspx?space=1&num=1029) · сложность 356 · dp, dijkstra

Оригинальная задача — III командный студенческий чемпионат Урала по программированию, 1999 год.

[English](README.md) · **Русский** · [中文](README.zh.md) · [Español](README.es.md)

## Задача

В здании `M` этажей (`1 ≤ M ≤ 100`) по `N` кабинетов (`1 ≤ N ≤ 500`);
каждый кабинет берёт положительную плату. Путь начинается в любом кабинете
первого этажа; каждый шаг ведёт либо на этаж выше в кабинет с тем же
номером, либо в соседний кабинет на том же этаже. Найдите путь, который
заканчивается на верхнем этаже и платит наименьшую сумму за посещённые
кабинеты. До любого кабинета можно добраться не дороже `10^9`.

Ограничение времени: 1 секунда. Ограничение памяти: 64 МБ.

## Входные данные

`M` и `N`, затем `M` строк по `N` плат: строка `i` — этаж `i`.

## Выходные данные

Номера кабинетов в порядке пути. Принимается любой самый дешёвый путь.

## Проверка

Чекер восстанавливает этажи по номерам кабинетов — тот же номер ещё раз
означает этаж выше, номер, отличающийся на единицу, — шаг по этажу — и
проверяет, что путь начинается на первом этаже, заканчивается на верхнем и
стоит ровно минимум.

## Примеры

### Пример 1

Ввод:

```
3 3
5 1 9
9 1 1
1 9 1
```

Вывод:

```
2 2 3 3
```

### Пример 2

Ввод:

```
1 1
7
```

Вывод:

```
1
```

## Решение

**Динамика по этажам.** Пусть `best[i][j]` — самый дешёвый путь,
заканчивающийся в кабинете `j` этажа `i`. На этаже самый дешёвый путь в
кабинет приходит либо снизу, либо от левого соседа, либо от правого — и на
одном этаже самый дешёвый путь никогда не разворачивается, потому что платы
положительны. Поэтому каждый этаж — это три прохода:

1. снизу: `best[i][j] = fee[i][j] + best[i - 1][j]` (на первом этаже
   просто `fee[0][j]`);
2. слева направо: `best[i][j] = min(best[i][j], best[i][j - 1] + fee[i][j])`;
3. справа налево: `best[i][j] = min(best[i][j], best[i][j + 1] + fee[i][j])`.

Для каждого кабинета запоминаем, какой из трёх вариантов дал значение; от
самого дешёвого кабинета верхнего этажа идём по этим выборам назад до
первого этажа и печатаем кабинеты в обратном порядке. `O(M·N)`.

**Кратчайший путь.** Кабинеты с ходами вверх, влево и вправо образуют граф
с положительными весами в вершинах: алгоритм Дейкстры сразу из всех
кабинетов первого этажа даёт тот же ответ за `O(M·N log(M·N))`.

Подводные камни:

- по первому этажу самый дешёвый путь никогда не идёт: начать можно в любом его
  кабинете, а каждый шаг стоит положительную плату, поэтому горизонтальные
  проходы на этом этаже ничего не меняют;
- в выводе перечислены все посещённые кабинеты, включая шаги по этажу;
- гарантия достижимости за `10^9` удерживает промежуточные суммы в пределах
  32-битных знаковых целых; решения используют более широкие типы.

## Оптимизированные решения

Версии C++ и Rust выполняют те же три прохода на каждом этаже. Массив стоимостей обновляется на месте, а цены текущего этажа используются повторно в обоих горизонтальных проходах. Для каждого кабинета хранится один байт с направлением к предыдущему кабинету. Из самого дешёвого кабинета верхнего этажа идём по направлениям назад и выводим записанные номера в обратном порядке. Время O(M·N).

Принятые базовые реализации [1029_dp.go](1029_dp.go), [1029_dp.java](1029_dp.java), [1029_dp.py](1029_dp.py) также закрывают быстрый набор: в сохранённом срезе сравнения они уже удовлетворяют рейтинговому критерию включения — топ 15% или первые десять мест одновременно по времени и памяти. Используются те же исходники без одинаковых копий. Звёздочка отмечает версию, которая пока не достигла целевого рейтинга своего языка.
