# 1037. 会过期的内存块

[Timus 1037](https://acm.timus.ru/problem.aspx?space=1&num=1037) · 难度 1170 · simulation

原题作者 Alexander Klepinin，出自 2000 年 10 月第五届乌拉尔国立大学团体程序设计锦标赛。

[English](README.md) · [Русский](README.ru.md) · **中文** · [Español](README.es.md)

## 任务

模拟一个有 `30000` 个内存块（从 1 开始编号）的内存管理器。开始时所有块都空闲。请求按时间不减的顺序到来：

- **分配**：占用编号最小的空闲块；
- **访问**块 `b`：若 `b` 被占用则成功，否则失败。

在时刻 `t` 的成功访问或分配使该块保持占用到时刻 `t + 600`：到那时，如果期间没有其他成功的请求，它就重新
变为空闲。请求最多 80000 个，时间是 0 到 65000 的整数，分配时总有空闲块。

时间限制：0.4 秒。内存限制：64 MB。

## 输入

每行一个请求：`T +` 表示时刻 `T` 的分配，`T . B` 表示时刻 `T` 对块 `B`（`1 ≤ B ≤ 30000`）的访问。

## 输出

按顺序对每个请求输出：分配到的块号，或访问成功 / 失败时的 `+` / `-`。

## 评测方式

按记号逐一比较输出，多余的空白字符不影响结果。

## 题解

对每个块记录是否被占用以及过期时刻。处理时刻 `t` 的请求之前，先释放所有过期时刻 `≤ t` 的块。

由于时间不减，每个新的过期时刻 `t + 600` 都不小于之前所有的过期时刻，所以过期时刻可以按设置的顺序放在普通的
先进先出队列里。访问不删除该块的旧记录；这种记录已经过时，到达队首时就能识别出来：块当前的过期时刻不同，或者
块已经空闲。被释放的块放进空闲块的小根堆。

分配时取堆顶；若堆为空，就取下一个从未用过的块（`1, 2, 3, ...`）——它们都比任何被释放的块大。访问时若块被
占用则输出 `+` 并更新它的过期时刻。每个请求最多向队列和堆各加入一条记录，`Q` 个请求总计 `O(Q log Q)`。

注意事项：

- 块恰好在 `t + 600` 时刻释放：该时刻的请求已经看到它是空闲的；
- 失败的访问不占用块，也不改变任何东西；
- 同一时刻的多个请求按输入顺序处理，同时释放的块从最小的开始复用；
- 在同一时刻被访问两次的块，在队列中有两条相同的记录：只能释放一次。

另一种做法是在块上建立维护过期时刻最小值的线段树：第一个过期时刻 `≤ t` 的块就是编号最小的空闲块。测试用它
核对过。

## 各语言说明

- **C++**、**Rust**：标准的优先队列和队列。
- **Go**：一个手写的小堆，用切片作队列；用 `bufio.Scanner` 按单词读入。
- **Java**：逐字节读入，因为 `StreamTokenizer` 会把 `.` 当作数字；`PriorityQueue` 和两个数组作队列。
- **Python**：`heapq` 和 `deque`；一次读入全部输入。
