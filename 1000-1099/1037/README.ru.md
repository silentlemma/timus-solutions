# 1037. Блоки памяти с истекающим сроком

[Timus 1037](https://acm.timus.ru/problem.aspx?space=1&num=1037) · сложность 1170 · simulation

## Задача

Смоделируйте менеджер памяти с `30000` блоками, пронумерованными с 1.
Вначале все блоки свободны. Запросы идут в порядке неубывания времени:

- **выделение** занимает свободный блок с наименьшим номером;
- **доступ** к блоку `b` успешен, если `b` занят, и отклоняется иначе.

Успешный доступ или выделение в момент `t` держит блок занятым до момента
`t + 600`: в этот момент, если к нему не было других успешных запросов, он
снова становится свободным. Запросов не больше 80000, времена — целые от 0
до 65000, и для выделения всегда есть свободный блок.

Ограничение времени: 0,4 секунды. Ограничение памяти: 64 МБ.

## Входные данные

По одному запросу в строке: `T +` — выделение в момент `T`, `T . B` —
доступ к блоку `B` (`1 ≤ B ≤ 30000`) в момент `T`.

## Выходные данные

Для каждого запроса по порядку: номер выделенного блока или `+` / `-` для
успешного / отклонённого доступа.

## Проверка

Вывод сравнивается по токенам; лишние пробельные символы не важны.

## Решение

Для каждого блока храним, занят ли он, и момент истечения. Перед
обработкой запроса в момент `t` освобождаем все блоки, срок которых
`≤ t`.

Так как время не убывает, каждый новый срок `t + 600` не меньше всех
прежних, поэтому сроки можно хранить в обычной очереди FIFO в порядке
установки. Доступ не удаляет старую запись своего блока; такая запись
устарела и распознаётся, когда доходит до начала очереди: текущий срок
блока другой или блок уже свободен. Освобождённый блок попадает в
min-кучу свободных блоков.

Выделение берёт вершину кучи; если куча пуста — следующий ещё не
использованный блок (`1, 2, 3, ...`), все они больше любого
освобождённого. Доступ отвечает `+`, если блок занят, и сдвигает его срок.
Каждый запрос добавляет не больше одной записи в очередь и одной в кучу,
итого `O(Q log Q)` для `Q` запросов.

Подводные камни:

- блок освобождается ровно в момент `t + 600`: запрос в этот момент уже
  видит его свободным;
- отклонённый доступ не занимает блок и ничего не меняет;
- запросы в один и тот же момент обрабатываются в порядке ввода, а блоки,
  освобождённые одновременно, выдаются начиная с наименьшего;
- у блока, к которому дважды обратились в один момент, в очереди две
  одинаковые записи: освобождать его нужно один раз.

Альтернатива — дерево отрезков по блокам с минимумом сроков: первый блок
со сроком `≤ t` и есть наименьший свободный. Тесты проверены им.

## Особенности языков

- **C++**, **Rust**: стандартные очереди с приоритетом и очереди.
- **Go**: небольшая самописная куча и срез в роли очереди; ввод читается
  через `bufio.Scanner` по словам.
- **Java**: побайтовое чтение ввода, потому что `StreamTokenizer` прочитал
  бы `.` как число; `PriorityQueue` и два массива в роли очереди.
- **Python**: `heapq` и `deque`; весь ввод читается сразу.
